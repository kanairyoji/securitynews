Andariel

公開されている脅威インテリジェンスと一次資料から整理したもの。 事実と評価を分けて書いています。

一言でいうと

Andariel（別名 Silent Chollima、Onyx Sleet／PLUTONIUM、APT45、Stonefly）は、北朝鮮の偵察総局（RGB）に帰属されるサイバー攻撃集団で、複数の調査機関が Lazarus の下位系統として扱っている [20][11][8][18]。2009年前後から韓国の政府・軍・国内企業に対する諜報と破壊的攻撃を重ね [17][8][16]、2021年以降は DTrack と Maui ランサムウェアによる金銭獲得にも踏み込んだ [10][4]。標的は韓国に限られない。2022年から2023年にかけては Log4j や ManageEngine の脆弱性を突いて欧州・北米・南米の重要インフラと製造業に入っており [13][15][12]、Kaspersky が把握する最も早い Maui 事案の標的は日本にあった [10]。

素性

国は北朝鮮（KP）。CrowdStrike は SILENT CHOLLIMA を少なくとも2007年から活動する DPRK 系の実体とし、「国連は Andariel／SILENT CHOLLIMA の作戦を偵察総局（RGB）第970室が実施していると主張しており、米政府と業界の情報源もこの活動を RGB に帰属させている」と書いている。CrowdStrike 自身がさらに絞り込もうとしている記述は、取得できたページでは「Bureau 1…」の途中で切れており、どの部署を指すか読み取れない [20]。基礎層の MITRE ATT&CK も Andariel（G0138）を Lazarus Group の一部分とみなし、北朝鮮の偵察総局に帰属させている〔ATT&CK G0138〕。台帳（MISP galaxy 由来）の帰属確度は 0-100 の 50 である。

呼び名は機関ごとに割れており、同じ実体を指しているかどうかも一致していない。

別名の扱いには注意が要る。 CrowdStrike が挙げる同義名は Lazarus Group・New Romanic Cyber Army・PLUTONIUM・Onyx Sleet・APT45・Jumpy Pisces・WASSONITE・Andariel の8つで、APT38 や BlueNoroff は含まれていない [20]。一方、本記録の台帳が持つ別名59件には APT38・BlueNoroff・Sapphire Sleet・AppleJeus・Citrine Sleet・Gleaming Pisces といった資金獲得系統の名前が混ざっている。台帳の別名一覧をそのまま検索語や帰属の根拠に使うと、別の系統の事案を Andariel の活動として数えることになる。

固有マルウェアは Malpedia が23ファミリを Andariel 帰属として挙げている。読んだ資料に登場するのは Dtrack（別名 Preft／Valefor）[17][10][12]、Maui [10][4][5]、VSingle [1][2]、YamaBot（別名 Kaos）[3]、MagicRAT・QuiteRAT・CollectionRAT [14][15]、NineRAT [13]、Jupiter／EarlyRAT [14][12]、Andardoor [9]、TigerRAT・Rifdoor・Phandoor [8]、BISTROMATH [7]、SHATTEREDGLASS [16] である。

    韓国の金融機関を標的に RIFLE を使ったとみられる [16]。
  8. 2017年
    政府機関と防衛産業への注力が観測され始めた [16]。

    ActiveX のゼロデイを使い韓国のウェブサイトで水飲み場攻撃を行った。韓国の IssueMakersLab はこれを「Operation GoldenAxe」と呼んでいる [18]。
  10. 2018年6月21日〜27日
    侵害した韓国のウェブサイト4件（非営利団体1件と地方自治体の労働組合3件）に偵察用スクリプトを埋め込み、訪問者のブラウザ種別・システム言語・Flash と Silverlight のバージョン・複数の ActiveX オブジェクトの有無を収集した。次の水飲み場攻撃の下見とみられ、Trend Micro は攻撃が実行される前に公表に踏み切った [18]。
  11. 2019年
    原子力研究施設と原子力発電所（インドのクダンクラム原子力発電所など）を直接標的にした。北朝鮮による重要インフラ攻撃として公に知られる数少ない例である [16]。同年以降、Symantec は活動が高価値標的への諜報一本に絞られたとみている [17]。
  12. 2020年9月
    多国籍企業の作物科学部門を標的にした。国境閉鎖による農業生産の悪化が背景にある可能性が指摘されている [16]。
  13. 2020年半ば以降
    不正な Word 文書と PDF を装ったファイルを感染経路として、第3段ペイロードの配布を始めた [11]。
  14. 2020年12月25日
    のちに Maui ランサムウェアが展開されることになる標的システム上で、不審な 3proxy が検知された [10]。
  15. 2021年3月31日〜4月
    韓国の展示会の参加申込書を装った Word 文書（참가신청서양식.doc）が使われた。マクロが PNG 内の圧縮された悪性 zlib オブジェクトを BMP へ変換して展開し、静的検知を回避したうえで mshta から実行する手口だった [19]。Kaspersky は同じ一連の攻撃を Andariel に帰属させ、被害者の1台に独自のランサムウェアが投下されていたことを確認した [11]。
  16. 2021年4月15日
    DTrack の亜種を投下した約10時間後に Maui ランサムウェアが展開された。この標的の所在地は日本であり、Kaspersky はこれが Maui を使った最初の事案である可能性があるとしている [10]。
  17. 2021年5月以降
    米 FBI は医療・公衆衛生（HPH）分野の組織で複数の Maui 事案に対応した。電子カルテ・診断・画像・イントラネットを担うサーバーが暗号化され、サービスが長期間止まった例もある。初期侵入の経路は不明とされている [4][5]。
  18. 2021年
    南アジアの銀行に対するスピアフィッシングが確認された [16]。北朝鮮国内で新型コロナの流行が疑われた時期に医療・製薬分野を標的にし、他の北朝鮮系グループより長くこの分野を追い続けた [16]。Kaspersky はこの年、Mandiant が SHATTEREDGLASS と呼ぶランサムウェアを報告している [16]。
  19. 2022年2月
    エネルギーと軍需に関わる技術系企業が侵害された。公開されていた VMware View サーバーの Log4j 脆弱性（CVE-2021-44228）が入り口とみられ、そこから18台へ横展開した。17時間後に Preft（Dtrack）を導入し、PuTTY の PSCP を装った pvhost.exe で持ち出し、pl.exe に偽装した Mimikatz で資格情報を採取。翌日以降は 3proxy（svhost.exe）を4日間使い続け、WinSCP、Invoke-TheHash（rev.ps1）、Impacket の wmiexec（notepad.exe）で移動した [17]。
  20. 2022年7月6日
    FBI・CISA・米財務省が Maui ランサムウェアに関する共同勧告（AA22-187A）を出した [4][5]。米司法省はこの集団への身代金支払いのうち50万ドルを取り戻したと発表している [10]。
  21. 2022年7月
    JPCERT/CC が、VSingle が固定 C2 に接続できないときに GitHub から新しい C2 を取得するよう更新されていること [2]、および Go 言語で書かれた YamaBot に Windows 版が現れたこと [3] を公表した。
  22. 2022年9月
    Talos が、Log4j 脆弱性の悪用によって米国・カナダ・日本のエネルギー事業者を標的にしたキャンペーンを公表した。MagicRAT のほか VSingle・YamaBot・TigerRAT が使われており、これらは日本と韓国の政府機関が以前からこの実行主体に帰属させていたマルウェアである [14]。
  23. 2022年後半
    未修正の Zimbra を悪用し、MagicRAT に似た RAT を展開する活動が WithSecure により報告された [14]。
  24. 2023年2月
    脆弱なバージョンのファイル転送クライアント Innorix Agent（9.2.18.450 以前）を経由してバックドア Andardoor が配布された。韓国インターネット振興院（KISA）が更新を勧告した製品である。検体には C/C++ 版と .NET 版があり、タスクスケジューラへの登録名にセキュリティ企業名（AhnLab）を使って隠れようとするものもあった。通信の符号化に使う鍵は2017年の CISA 報告書にある XOR 鍵と同一だった [9]。この経路で韓国の複数の大学が感染していた [8]。
  25. 2023年初頭
    欧州のインターネットバックボーン事業者が侵害された。ManageEngine ServiceDesk の脆弱性（CVE-2022-47966）が使われ、PoC 公開の5日後には悪用が始まっていた。Java プロセスから curl で QuiteRAT が落とされ、sc create でサービスとして常駐した。欧州と米国の医療機関も同じキャンペーンの標的だった [15]。
  26. 2023年2月9日
    米 NSA・FBI・CISA・HHS と韓国 NIS・韓国 DSA（Defense Security Agency）が共同勧告（AA23-040A）を出し、重要インフラへのランサムウェア攻撃が北朝鮮のサイバー活動の資金源になっていると指摘した。得られた資金は米韓政府（国防総省の情報ネットワークや防衛産業基盤を含む）を狙うサイバー作戦を支えていると評価している [6]。
  27. 2023年3月
    DLang で書かれた NineRAT が南米の農業関連組織に対して初めて使われた。Telegram のボットとチャンネルを C2 に使う RAT である（検体自体は2022年5月ごろに作られていた）[13]。
  28. 2023年5月
    独自のプロキシツール HazyLoad が、欧州の企業と、韓国の物理セキュリティ・監視企業の米国子会社に対して使われた [13]。
  29. 2023年6月
    Kaspersky が Log4j 経由の侵入で新種 EarlyRat を確認。操作者が打ったコマンドには誤字（Program を Prorgam）が多く、侵入先がポルトガル語環境であることに気づくまで時間がかかっていた。Supremo・3Proxy・Powerline・PuTTY・Dumpert・NTDSDumpEx・ForkDump といった既製ツールも併用されていた [12]。
  30. 2023年8月
    Talos が CollectionRAT を公表。2021年の検体が Jupiter／EarlyRAT と同じコード署名証明書で署名されており、QuiteRAT・DeimosC2・CollectionRAT が2022年の MagicRAT キャンペーンと同じインフラ上に置かれていた [14]。
  31. 2023年9月
    NineRAT が欧州の製造業に対して再び使われた [13]。
  32. 2023年10月
    Microsoft が Onyx Sleet に帰属する活動を公表し、Talos の観測と重なった [13]。
  33. 2023年
    Go 言語で書かれたマルウェアが目立つ年になった。Black RAT、Goat RAT、AndarLoader、DurianBeacon（Go 版と Rust 版）が確認されている [8]。健康関連の研究への関心も続いていた [16]。

手口

入り口。 経路は3系統ある。第1に標的型メール（T1566 / T1566.001 / T1566.002）。韓国語の囮文書を添えた Word ファイルが典型で [19][11]、EarlyRat も同様にフィッシング文書から落ちる [12]。第2に水飲み場（T1189）。侵害した韓国のサイトに偵察スクリプトを仕込み、ActiveX のゼロデイで実行に持ち込む（T1203）[18]。第3に外部公開資産の n-day 悪用。Log4j（CVE-2021-44228）[17][12][13]、ManageEngine ServiceDesk（CVE-2022-47966）[15]、Zimbra [14]、そして脆弱な Innorix Agent [9] が使われている。AhnLab は初期侵入としてスピアフィッシング・水飲み場・サプライチェーン攻撃（T1195.002）を挙げ、マルウェア導入時に中央管理ソリューションを悪用する例があるとしている [8]。なお骨格の ATT&CK 一覧には「公開アプリケーションの悪用」に対応する ID が無いため、この第3系統に付ける技術 ID はここでは示さない。

実行と常駐。 マクロ（T1059.005）から WMI（T1047）経由で mshta を呼ぶ [19]。侵入後は cmd（T1059.003）と PowerShell（T1059.001）を素直に使う [15][17]。常駐はサービス作成（T1543.003 / T1569.002）が多く、QuiteRAT は sc create WindowsNotification、NineRAT は sc create Aarsvc_XXXXXX ... DisplayName=Agent Activation Runtime と、いずれも Windows 標準サービスに紛れる名前を選ぶ [15][13]。Andardoor はタスクスケジューラ（T1053.005）に登録され、タスク名にセキュリティ製品ベンダー名を使った [9]。Preft は Startup_LNK（T1547.009）・サービス・レジストリ（T1547.001）・タスクスケジューラの4通りを持つ [17]。設定をレジストリに置く実装もある（T1112。Volgmer は HKLM\SYSTEM\CurrentControlSet\Control\WMI\Security から読む [8]）。

隠す技術。 画像への埋め込み（T1027.003）はこの集団の癖である。2021年の Word 文書は PNG に圧縮した zlib オブジェクトを埋め、BMP へ変換することで展開と同時に静的検知を外した [19]。2020年に米政府が公表した BISTROMATH も、偽のビットマップを含むトロイの木馬化した実行ファイルがシェルコードにデコードされる構造だった [7]。ほかに MFC でラップしたパッキング（T1027.002。CollectionRAT [14]）、正規名への偽装（T1036.003 / T1036.005。svchost.exe・notepad.exe・pl.exe・tapi.exe [17]、小文字の l を大文字の I に替えた nsIookup.exe [13]）、正規プロセスへの注入（T1055 / T1055.001。Preft は iexplore.exe か explorer.exe に第3段を注入し名前付きパイプで繋ぐ [17]。VSingle は Explorer に DLL 注入する [1]）、文字列の XOR 難読化（T1140。VSingle の固定鍵 o2pq0qy4ymcrbe4s [1]、QuiteRAT の 0x78 [15]）がある。Preft の第2段は19,999秒スリープしてサンドボックスをやり過ごす [17]。署名（T1553.002 / T1588.004）も使い、2021年の CollectionRAT は EarlyRAT と同じ証明書で署名されていた [14]。

資格情報と横展開。 LSASS からの採取（T1003.001）に Mimikatz [17]、Dumpert、ForkDump を使い、NTDSDumpEx も併用する [12]。横展開は pass-the-hash（Invoke-TheHash）と Impacket の wmiexec による管理共有経由（T1021.002）[17]。SSH 系の正規ツール（T1021.004）として WinSCP・PSCP・Plink が持ち込まれる [17][14]。遠隔操作には Supremo のような正規のリモートデスクトップ製品も使う [12]。

C2。 主として HTTP（T1071.001）。VSingle は GET /polo/[Unix時刻]/[ランダム].php?ufw=...&uis=... の形で出て、応答の Set-Cookie ヘッダに AES 鍵が入る [1]。YamaBot は User-Agent 自体を Base64 で符号化し（T1132.001）、Cookie の captcha_session／captcha_val に RC4 鍵と本文を載せる（T1573.001）[3]。正規サービスを C2 の一部に使うのが近年の特徴で（T1102.002 / T1583.006）、VSingle は固定 C2 3つに繋がらないとき GitHub の raw.githubusercontent.com/…/README.de から次の C2 を読み（T1008）[2]、NineRAT は Telegram のボットとチャンネルを命令とファイル授受の経路にする [13]。プロキシ（T1090.001 / T1090.002）は 3proxy と Plink による逆トンネルが定番 [14][17][12]。追加の道具は curl などで引き込む（T1105）[15]。多段のシェルコード連鎖（T1104）も Preft に見られる [17]。

目的の実行。 破壊（T1485 / T1561.001 / T1561.002）は2013年の Jokra が代表例 [17]。暗号化（T1486）は Maui と2021年の独自ランサムウェア [11]。Maui は自動で広がらない——遠隔の操作者がコマンドラインから手で起動し、暗号化するファイルを選ぶ設計で、ファイルごとに AES-128 鍵を作り、その鍵を RSA で包み、RSA 公開鍵（maui.key）はドライブ情報から作った鍵で XOR する。実行後に残る maui.log は復号のために持ち出されているとみられる [4][5]。金銭の直接窃取（T1657）としては ATM の侵害が過去にある [11]。持ち出しは C2 チャネル経由（T1041）と、WinSCP・PSCP のような別プロトコル（T1048.003）の両方 [17]。BISTROMATH はマイク・クリップボード（T1115）・画面の監視まで持つ [7]。

公開情報（本記録が読んだ一次資料20本） — 3点ある。

  1. Maui の最初期事案の標的が日本にあった。 Kaspersky は CISA が報告した「初出2021年5月」を2021年4月15日まで遡らせ、その標的の所在地を日本だと明示している。同じシステムでは2020年12月25日に 3proxy が、2021年4月15日に DTrack が検知されており、Maui はその約10時間後に展開された。Kaspersky はこの一連を Andariel（Silent Chollima／Stonefly）に低〜中程度の確度で帰属させている [10]。
  2. 日本のエネルギー事業者が Log4j 経由のキャンペーンの標的に含まれていた。 Talos は2022年9月に、米国・カナダ・日本のエネルギー事業者を狙った活動を公表しており、そこで使われた VSingle・YamaBot・TigerRAT は「日本と韓国の政府機関が以前からこの実行主体に帰属させていた」マルウェアだとしている [14]。ただしこのキャンペーン自体を Talos は Lazarus Group として扱っており、Andariel と名指ししているのは別のマルウェア系統（CollectionRAT ↔ Jupiter／EarlyRAT）についてである [14]。
  3. JPCERT/CC が日本の組織への攻撃で使われたマルウェアとして VSingle を解析している。 2021年3月の記事の題は「Lazarus Attack Activities Targeting Japan（VSingle/ValeforBeta）」で、日本の組織への攻撃で使われたマルウェアとツールを扱うと明記されている [1]。2022年には VSingle の GitHub 経由 C2 取得 [2] と YamaBot の Windows 版 [3] を続けて公表した。JPCERT/CC はこれらを Lazarus に帰属させており、Andariel とは書いていない。 VSingle と YamaBot を Andariel 固有のファミリとして扱っているのは基礎層（Malpedia）である。

このほか Malwarebytes は Lazarus 全体について「米国・韓国・日本などを標的とすることで知られる」と書いている [19]。

公開情報（基礎層） — MISP galaxy は推定被害国に日本を挙げている。一方 MITRE ATT&CK の Andariel（G0138）の記述は韓国の政府機関・軍・国内企業を主標的とするもので、日本の名指しは無い〔ATT&CK G0138〕。

人手（台帳 config/japan_watchlist.yaml） — Andariel は独立した行ではなく、Lazarus の下位系統として「韓国の防衛産業・重要インフラを狙う系統。近年はランサムも使う」と登録されている。Lazarus を定点観測に載せている根拠は暗号資産交換業者への攻撃で日本国内の事業者にも被害が公表されていること、および IT技術者の身分偽装による就労への各国当局の警告であり、Andariel 単独の根拠ではない。

自前の観測 — 骨格に観測層の記載は無い。本記録は自前の観測を根拠にしていない。

実被害（リークサイト掲載） — 該当なし。Andariel はリークサイトを運営するランサムウェアブランドとして観測されていない。

最近の動き

読んだ20本のうち、日付のある最も新しい資料は2024年7月26日の Mandiant による APT45 プロファイルである [16]。公開されている資料は2024年7月までで、それ以降の動きは確認できていない。 CrowdStrike の実体プロファイル [20] は随時更新される形式のページで、本文に日付のある事案の記述が無いため、ここでの時期の判断には使えない。

具体的な侵害事例として資料に年月が書かれている最後のものは、2023年9月の欧州の製造業に対する NineRAT の使用 [13]、および同年10月の Microsoft による Onyx Sleet 帰属の公表 [13] である。したがって現時点で確認できる最後の姿は、外部公開資産の n-day 脆弱性を機会主義的に突き、DLang・Go・Rust といった解析しにくい言語で書き直した RAT を置き、Telegram や GitHub を C2 の一部に使うという2023年の形までである [13][8][2]。

ここから先は本記録の評価です。上の各節は公開資料に基づく事実で、以下は解釈と推論を含みます。

何が変わったか

ここからは本記録の評価です。

破壊から諜報へ、そして金銭へ。 2009〜2013年は DDoS とディスク破壊の集団だった [17]。2019年以降 Symantec は諜報一本になったとみている [17]。ところが2021年には Maui と独自ランサムウェアが出てくる [10][11]。系統としては撤退ではなく積み増しで、Mandiant が「ランサムウェアへの関心が他の北朝鮮系実行主体と一線を画す」と書くのはこの点だと読める [16]。攻撃の見た目（暗号化・身代金）から動機を推測すると外す集団になっている。

入り口が人からモノに移った。 2018年は水飲み場と ActiveX ゼロデイ [18]、2021年はマクロ入り Word [19][11]。2022年以降は Log4j・ManageEngine・Zimbra・Innorix と、公開資産の既知脆弱性が主経路になった [17][15][14][9]。ManageEngine の事例では PoC 公開から5日で悪用が始まっている [15]。標的を選んでから入るのではなく、入れたところから標的かどうかを判断する順序に変わったように見える。Kaspersky が観察した操作者の誤字の多さと、ポルトガル語環境だと気づくまで時間がかかった件 [12] は、この読み方と整合する。

標的が韓国から世界へ広がった。 南米の農業組織、欧州の製造業、欧州のインターネットバックボーン事業者、韓国企業の米国子会社 [13][15]。「韓国の防衛産業を狙う集団」という2018年までの理解は2023年で成り立たなくなっている。

道具を作り替える速さ。 Qt（MagicRAT / QuiteRAT）、Go（YamaBot / Black RAT / Goat RAT）、DLang（NineRAT / DLRAT / BottomLoader）、Rust（DurianBeacon）と、珍しい言語・フレームワークへ移っている [15][8][13]。Talos はこれが機械学習やヒューリスティックによる検知の信頼性を下げると指摘しており [15]、解析コストを上げることが目的だと考えられる。一方でインフラは使い回しており、2022年の MagicRAT キャンペーンと同じホストが2023年の QuiteRAT・CollectionRAT・DeimosC2 に使われていた [14]。道具は変えるが土地は変えない。

正規サービスの C2 化。 GitHub [2] と Telegram [13]。宛先ドメインの評判で弾く防御が効かなくなる方向の変化である。

日本の組織にとっての含意

「韓国向けの脅威」として整理すると外す。 日本に関わる公開情報は3点ある（前掲）が、そのうち最も強いのは Maui の最初期事案の標的が日本だったという Kaspersky の記述である [10]。この事案では 3proxy の検知から Maui 展開まで約4か月空いている [10]。侵入から暗号化までの間に気づく機会が数か月あったということでもあり、逆に言えば暗号化が起きた時点では侵害は数か月前に始まっている前提で初動を設計する必要がある。

業種の当てはめは医療・エネルギー・製造・防衛周辺に広がる。 資料に現れる標的は、医療（Maui）[4][5]、エネルギー・軍需の技術系企業 [17]、原子力施設 [16]、通信バックボーン [15]、製造業・農業・物理セキュリティ [13]、大学 [8]。日本の組織では、防衛・エネルギーの受託先や研究機関、医療機関、そして「軍民両用の技術を持つ中小の技術系企業」が該当しうる。Symantec が挙げる「軍事にも民生にも使える技術」という選び方 [17] は、日本の経済安全保障の議論と重なる範囲である。

身代金の支払いは制裁リスクを伴う。 米財務省は北朝鮮系へのランサム支払いに制裁上のリスクがあると警告しており、CISA・FBI・財務省は支払いを強く非推奨としている [4][5]。米国拠点や米ドル決済を持つ日本企業は、支払いの是非を「復旧できるか」だけで判断できない。

ファイル転送・資産管理といった「内側の道具」が入り口になる。 Innorix Agent の事例は、韓国国内で広く使われる正規のファイル転送クライアントの脆弱版が配布経路になったものである [9]。AhnLab は中央管理ソリューションの悪用にも触れている [8]。日本でも同種の国内向け業務ソフト（資産管理・ファイル転送・配布サーバー）は、境界機器ほど棚卸しの対象になっていないことが多い。

ランサムウェア対策を「暗号化を止める」で設計すると間に合わない。 Maui は自動拡散せず、操作者が手で起動して対象を選ぶ [4][5]。暗号化の振る舞いを見る検知は最終段階でしか働かない。効くのは侵入・常駐・横展開の段階である。

取るべき防御

骨格の ATT&CK 技術と資料の挙動から、優先順に挙げる（本記録の評価）。

  1. 外部公開資産の棚卸しと n-day への追随速度。 Log4j・ManageEngine ServiceDesk・Zimbra・VMware View と、悪用対象は毎年入れ替わる [17][15][14]。PoC 公開から5日で悪用された例がある以上 [15]、個別 CVE の対応表ではなく「公開資産を全部把握しているか」「PoC 公開から適用まで何日か」を指標にする。骨格の技術一覧に該当 ID は無いが、資料上は現在の主経路である。
  2. 国内向け業務ソフトの版管理（T1195.002）。ファイル転送クライアント・資産管理・配布サーバーなど、社内で自動更新されている前提になっている製品の実バージョンを確認する [9][8]。
  3. 正規ツールの持ち込みを検知する（T1105 / T1090.001 / T1090.002 / T1021.004 / T1571）。3proxy・Plink・PSCP・WinSCP・Supremo・Dumpert・NTDSDumpEx・ForkDump・Impacket は、この集団がほぼ毎回使う既製品である [17][12][14]。単体では正規なので、業務端末・サーバー上での初出と、非標準ポートでの外向き常時接続を見る。日本の Maui 事案でも 3proxy の検知が最初の兆候だった [10]。
  4. LSASS へのアクセス監視（T1003.001）。Mimikatz・Dumpert・ForkDump はいずれも LSASS を読む [17][12]。ここが取れていないと、以降の横展開はすべて正規の認証に見える。
  5. サービス作成とタスク登録の監視（T1543.003 / T1053.005 / T1569.002 / T1036.005）。sc create で Windows 標準風の名前を付ける [15][13]、タスク名にセキュリティ製品ベンダー名を使う [9]、nsIookup.exe のように1文字だけ替える [13]——いずれも名前を目で見ても気づけない。作成イベント自体を拾って、既知の正規サービス以外を洗い出す。
  6. マクロと mshta の実行を止める（T1059.005 / T1218.005 / T1027.003）。マクロの既定無効化に加え、Office 文書から mshta が起動する連鎖を検知する。画像内に隠す手口 [19][7] があるため、添付ファイルの静的検査だけでは足りない。
  7. 正規サービス宛の C2 を想定する（T1102.002 / T1583.006 / T1008）。GitHub の raw コンテンツ [2] と Telegram の Bot API [13] は、多くの環境で許可されている。サーバー用途の端末からこれらへ出る通信は、宛先の評判ではなくその端末が出てよいかで判断する。JPCERT/CC も用途の限られたサーバーは接続先を限定するよう勧めている [2]。
  8. バックアップの隔離と、暗号化より前の段階での検知（T1486 / T1485 / T1489 / T1561.001 / T1561.002）。Maui は手動実行で対象を選ぶ [4][5]。暗号化開始後に止められる前提を置かない。過去にはディスク破壊も行っている [17]。
  9. ログを端末外へ出す（T1070.004 / T1685.005 / T1690）。骨格の技術一覧にはイベントログの消去とコマンド履歴の記録抑止が含まれる。NineRAT のドロッパーは配置後に自分を消す [13]。

骨格に付く IoC（検体ハッシュ401件・ドメイン119件・IP62件）は機械抽出で悪性を検証しておらず、照合先のテレメトリも無い。そのまま検知に使わない。

分からないこと

  1. Andariel／APT45／Silent Chollima／Stonefly／Onyx Sleet が同じ実体かどうかが決着していない。 Mandiant は APT45 を独自のマルウェア系譜を持つ実体とみる [16]。Talos と AhnLab と Trend Micro は Lazarus 傘下の下位グループとする [13][8][18]。CrowdStrike の同義名一覧には Lazarus Group そのものが入っている [20]。どの立場を取るかで、他の北朝鮮系レポートを Andariel の資料として流用してよいかが変わる。
  2. RGB のどの部署かが確定していない。 国連は第970室と主張し、米政府と業界は RGB に帰属させているが、CrowdStrike 自身の見立ては取得したページで途中から欠けている [20]。
  3. 日本国内の被害の広がりが分からない。 資料に現れる日本の記述は、Maui 事案1件の所在地 [10] と、エネルギー事業者を含む地域の列挙 [14] だけである。組織名・業種・件数・持ち出された情報はどの資料にも無い。
  4. 初期侵入の経路が不明な事案がある。 CISA は Maui 事案について「初期侵入の経路は不明」と明記している [4][5]。日本の最初期事案でも、3proxy が置かれる前に何が起きたかは書かれていない [10]。
  5. ランサムウェア運用の位置づけが確定していない。 Mandiant は開発への関与を中程度の確度としつつ確認はできないとし [16]、Kaspersky の Maui → Andariel の帰属も低〜中程度の確度である [10]。資金獲得のためか、他の北朝鮮の優先事項の原資かも「可能性がある」以上には書かれていない [16]。
  6. 2024年8月以降の動きが分からない。 読んだ20本の最新が2024年7月26日で、事案の記述としては2023年10月が最後である [16][13]。現在も同じ手口かは確認できていない。
  7. 骨格の作戦欄にある Operation Dream Job と 3CX サプライチェーン侵害は年表に入れていない。 Symantec は Operation Dream Job を別の北朝鮮系グループ（Pompilus）の作戦だと明記しており [17]、3CX について記述のある資料は20本の中に無い。台帳が Lazarus 系統の作戦をまとめて Andariel に紐付けている可能性が高く、根拠が確認できないため採らなかった。
  8. 破壊的攻撃を現在も手段として持っているかが分からない。 2013年の Jokra 以降 [17]、読んだ資料にワイパーの新しい事例は無い。一方 CrowdStrike は目的に「破壊」を挙げ続けている [20]。
  9. 共有ツールの多さが帰属の判断を難しくしている。 3proxy・Mimikatz・Impacket・PuTTY・Supremo・DeimosC2 はいずれも誰でも使える [17][12][14]。これらの痕跡だけで Andariel と判断することはできない。
