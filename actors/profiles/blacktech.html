BlackTech

公開されている脅威インテリジェンスと一次資料から整理したもの。 事実と評価を分けて書いています。

作成 2026-08-26。一次資料20本（うち BlackTech の記述があったのは17本）を読んで書いた。

一言でいうと

台湾を主戦場としながら日本の組織も継続的に狙ってきた、中国系のサイバースパイ集団。少なくとも2007年から活動し、狙いは情報窃取である [6][12][15]。特徴は3つ——盗んだ正規のコード署名証明書で検体に署名する [18]、Windows と同じマルウェアを Linux 版でも持つ [3][4]、外部に露出したサーバ・機器の脆弱性を公開直後に突く [1][12]。JPCERT/CC は TSCookie・PLEAD・IconDown といったこの集団の道具を日本の組織で繰り返し確認している [7][9]。

素性

呼び名が発行元ごとに違う。台帳には別名が13ある——BlackTech、Palmerworm、CIRCUIT PANDA、Temp.Overboard、HUAPI、G0098、T-APT-03、Manga Taurus、Red Djinn、Earth Hundun、Canary Typhoon、Mobwork、CAVERN CASTLE。

台湾の TeamT5 は HUAPI（別名 PLEAD、Blacktech）と呼び、2007年から台湾を10年以上攻撃してきたとする。同社の集計では被害組織の5割超が政府機関で、被害国は台湾・米国・日本・韓国、うち台湾政府機関への侵入が最も多い [12]。Symantec は Palmerworm と呼び「少なくとも2013年から活動」とする [15]。開始年が食い違うのは、どの道具の系譜から数えるかの違いである [6][14]。

国籍について、TeamT5 は「中国の駭客組織」と明記する [12][14]。一方 ESET は「東アジア、とくに台湾に集中した高度なサイバースパイ集団」、Symantec は「東アジア地域に強い関心を持つ諜報集団」と書くにとどまり、国名を挙げていない [15][18]。台帳が持つ ATT&CK の記述は "suspected Chinese"（中国系と疑われる）である。

標的業種は資料間でおおむね一致する。TeamT5 は政府・教育・シンクタンク・金融・テクノロジー・ヘルスケア [6]、Symantec は2019〜2020年の作戦でメディア・建設・エンジニアリング・電機・金融を挙げた [15]。道具の系譜は Trend Micro が2017年に整理し、PLEAD（＋窃取ツール DRIGO）、Shrouded Crossbow（BIFROSE・KIVARS・XBOW）、Waterbear の3作戦を同一集団に連なるものとして結び付けた [19]。

これまでの活動

資料から出来事の年が特定できるものだけを並べる。

  1. 2007年
    HUAPI（＝BlackTech）の活動開始。以後、台湾を10年以上にわたり攻撃 [12]。
  2. 2009年
    バックドア DBGPRINT（別名 Waterbear）が遅くともこの年から出回る。DLL のエクスポート名 "DbgPrint" が名前の由来 [6][14]。
  3. 2017年7月4日／2018年7月3日
    Plead の署名に悪用された台湾 Changing Information Technology 社と D-Link 社のコード署名証明書が、それぞれ失効。Changing 社の証明書は失効後も使われ続けた [18]。
  4. 2018年8月頃
    TSCookie が更新される。C2 通信の暗号化データを Cookie ヘッダから URL パラメータへ移したが、設定のコピーサイズを直し忘れ、数日間 C2 に再接続できないバグを抱えた [10]。
  5. 2019年4月末
    ASUS WebStorage の正規プロセス AsusWSPanel.exe が Plead を生成・実行する事例を ESET が台湾で観測。同ソフトの更新は HTTP で真正性を検証しておらず、ルータ階層の中間者攻撃で偽の更新先を挿し込まれたとみられる。被害組織の多くが同一メーカーのルータを使い、その管理画面が外部から見えていた [17]。
  6. 2019年5月
    上記のバグを直した TSCookie が攻撃で使われる。JPCERT/CC はブログでバグを指摘しており、攻撃者が公開記事を読んで修正したとみている [8]。
  7. 2019年（通年）
    日本国内で CVE-2019-9489 を悪用した侵入。初期侵入に同脆弱性、横展開に資産管理ソフト（ウイルスバスター コーポレートエディション サーバ）の正規機能の悪用と PoshC2、到達先に AD サーバ、という流れが JSAC2020 で図示された [5]。
  8. 2019年8月〜2020年8月
    Symantec が Palmerworm の作戦を観測。台湾メディア企業と中国の建設会社から始まり、2019年9月には日本のエンジニアリング企業（数日）、2020年3月には台湾の電機企業（数週間）に及ぶ。台湾メディア企業には1年、米国の端末1台には約6か月居座った [15]。
  9. 2019年9月／11月
    侵入後に使う TSCookie Loader ＋ TSCookie の構成が日本で継続的に観測される [9]。11月にはダウンローダ IconDown を日本の組織で確認 [7]。
  10. 2020年1月31日
    台湾の学術ネットワークの図書館サイトに置かれた ELF 版 BiFrost が VirusTotal に投稿される（当時の検出は6社）。侵入経路は Tomcat 7.0.73 の Ghostcat（CVE-2020-1938）とみられ、サイトが配布拠点にされていた [12]。
  11. 2020年3月／11月
    ELF_TSCookie [4]、続いて ELF_PLEAD [3] が確認される。前者は侵入後に被害組織の Linux サーバへ仕込まれたとみられる。いずれも Windows 版とコードの大半を共有する。同年末、Intezer は2020年の主要な Linux 脅威一覧に両者を並べた [13]。
  12. 2020年8月19日
    台湾の法務部調査局（MJIB）が会見。政府機関の委託先 IT サービス事業者が侵害され、市政府・水資源局など少なくとも10機関と4社が被害を受けたと発表。攻撃者は長期潜伏に SoftEther VPN を使っていた。名指しは MustangPanda・APT40・BlackTech・Taidoor [14]。
  13. 2021年3月〜11月
    JSAC2022 の発表資料に、この期間のタイムスタンプを持つ検体群が並ぶ。TSCookie のほか BTSDOOR、SPIDERPIG、BUSYICE、Chrome の保存資格情報を吐き出す CHROMEPASSDUMP が扱われている [2]。
  14. 2022年5月頃
    F5 BIG-IP の CVE-2022-1388 を悪用した日本の組織への攻撃。標的組織では BIG-IP 内のデータが窃取されたことが確認され、攻撃コードには国内 BIG-IP の IP アドレスが複数列挙されていた。攻撃者のサーバには TSCookie・Bifrose に加え、IoT 機器向けと推測される新種 Hipid が置かれていた [1]。

手口

初期侵入は2系統。ひとつは標的型メール。PLEAD は添付ファイルかクラウドストレージへのリンクでバックドアを配り、盗んだ文書の置き場にも同じクラウドアカウントを使っていた [19]（T1566.001／T1566.002、T1204.001／T1204.002）。流出した Hacking Team のエクスプロイト CVE-2015-5119 を仕込んだ .docx によるファイルレス版 PLEAD もあった（T1203）。もうひとつが外部に露出したサーバ・機器の脆弱性（T1190）。前掲の CVE-2022-1388・Ghostcat・CVE-2019-9489 がその実例で、JPCERT/CC は「近年 BlackTech は外部からアクセス可能なシステムの脆弱性を悪用する事例が多く、本件では公開直後に悪用された」と結んでいる [1]。

実行と常駐は多層の復号で隠す。PLEAD は、PE リソースに AVI や BMP といったありふれた名前で暗号化ペイロードを埋める、3段階に復号する、暗号化本体を別ファイルに置きローダに読ませる、の3方式で導入される。常駐は autorun レジストリが主で、偽の WMI サービスとして登録する例もあった [19]。TSCookie Loader も同じ発想で、desktop.db・7???. といった名前で置かれた RC4 暗号化ファイルをメモリ上で復号して動かす [9]。DBGPRINT は二重の DLL サイドローディングまで進化した [6]（T1574.001）。

署名は盗む。Plead の検体は、正規ソフトの署名にも使われていた D-Link 社のコード署名証明書で署名されており、盗まれたものとみられる。台湾の Changing Information Technology 社の証明書でも署名されていた [18]（T1588.003／T1588.004）。Symantec も2019〜2020年の作戦で盗んだ署名証明書の使用を確認している [15]。

横展開は既製品で。Symantec は Putty・PsExec・SNScan・WinRAR の併用を挙げ [15]（T1588.002、T1046）、日本の事例では PoshC2 と資産管理ソフトの正規配布機能の悪用が図示されている [5]。台湾の事例では svchost.exe に偽装した SoftEther VPN が長期潜伏に使われた [14]。

通信は独自プロトコルと RC4 が基調。TSCookie は HTTP・HTTPS・独自プロトコルを設定で切り替え、設定にはプロキシ認証情報、注入先プロセス、ICMP で C2 情報を受け取る項目まで入っている [9]。TeamT5 は BiFrost が使う改変版 RC4 をこの集団を見分ける固有の特徴として挙げた [12]。C2 ドメインは www.google.com.dns-report.com [8]、update.symantec-product.com [14] のように、ベンダ名を左側に置いて別ドメインにぶら下げる形が繰り返し出る。

Linux も同じ設計で作り直す。ELF_TSCookie は Windows 版とコードの多くが同一だが、設定項目を17個から5個に減らし、独自プロトコルだけを残し、モジュールを落とさずともシェル実行・ファイル操作・ファイル転送ができるよう機能を最初から積んでいる [4]。JPCERT/CC はこの集団が TSCookie・PLEAD・KIVARS の Linux 版を持つとし、Windows でこの集団のマルウェアを見つけたら Linux 環境も調べることを明記している [3][4]。2022年の Hipid は mount コマンドでプロセスを隠す作りだった [1]。

なお骨格の ATT&CK 技術のうち T1106（Native API）・T1021.004（SSH）・T1036.002（Right-to-Left Override）については、読んだ20本の中に対応する具体的記述を見つけられなかった。

日本との関係

層を分けて書く。混ぜると帰属の確度を語れなくなる。

公開情報の層。台帳が持つ ATT&CK の記述は「BlackTech は少なくとも2013年から、東アジア——とくに台湾・日本・香港——と米国の組織を主に標的にしてきたとみられる中国系のサイバースパイ集団」である。読んだ一次資料も日本を繰り返し名指しする。TeamT5 は被害国に日本を含め [12]、Symantec は2019年9月に日本のエンジニアリング企業での活動を観測した [15]。JPCERT/CC は TSCookie の感染報告を「多数受けている」[9]、IconDown を「日本の組織で確認した」「同様の活動は今後も続く可能性が高い」[7] と書く。2022年5月頃の F5 BIG-IP の件では、標的となった日本の組織でBIG-IP 内のデータが実際に窃取されたことが確認されており [1]、今回の材料の中ではこれが最も具体的な日本の被害である。

人手の層（台帳の定点観測記録）。2023年9月、警察庁・内閣サイバーセキュリティセンターと米 CISA・NSA・FBI が合同で注意喚起を出した。日本企業の海外子会社のルータのファームウェアを改ざんし、そこを踏み台に本社網へ侵入する手口を名指ししている。これは台帳に人手で登録された記録であり、今回読んだ20本には含まれていない。

実被害の層・自前の観測の層。骨格に該当する記載が無い。BlackTech はランサムウェアのリークサイトに被害者を掲載する類の集団ではないため、実被害層が空であること自体は想定どおりである。

最近の動き

今回読んだ公開資料は2022年で止まっており、それ以降の動きはこの20本からは確認できていない。最も新しい実質的な記述は、2022年5月頃の F5 BIG-IP CVE-2022-1388 の悪用（JPCERT/CC、2022年9月公開）[1] と、2021年3月〜11月のタイムスタンプを持つ検体群を扱った JSAC2022 の発表 [2] である。骨格の年表には2026年の Mandiant 資料が並ぶが、取得できたのは同社のコンサルティングサービス紹介ページで、BlackTech の記述は無かった。Securelist の APT トレンドレポート Q2 2019 と Trend Micro のブログ索引ページも同様である。人手の層には2023年9月の日米合同注意喚起が記録されているが（前節）、それを裏づける一次資料は今回の20本に入っていない。

ここから先は本記録の評価です。上の各節は公開資料に基づく事実で、以下は解釈と推論を含みます。

何が変わったか

ここからは本記録の評価です。

第一に、狙う面が「人」から「機器」へ移った。2017年の Trend Micro レポートが描く PLEAD は標的型メールと文書エクスプロイトが主軸だった [19]。ところが2019年以降に日本と台湾で観測された事例は、CVE-2019-9489 [5]、Ghostcat [12]、CVE-2022-1388 [1] と、いずれも外部露出サーバの脆弱性である。JPCERT/CC 自身が2022年に傾向としてそう書いた [1]。人手の層の2023年のルータ改ざんもこの延長線上にある。メールの訓練で減らせる攻撃面ではなくなった、というのがこの10年の最大の変化だと評価する。

第二に、Linux が例外でなくなった。2018年までの公開資料は Windows 版の話がほとんどだが、2020年に ELF_TSCookie と ELF_PLEAD が立て続けに報告され [3][4]、2022年には ARM 版の Hipid が出た [1]。しかも Linux 版は Windows 版の移植でコードの大半を共有する。攻撃側の追加コストはほぼ無いのに、防御側は EDR も証跡の取り方も別建てになる——この非対称性が今後も効き続けると評価する。

第三に、この集団は公開レポートを読んで直してくる。JPCERT/CC が2018年に TSCookie の設定読み込みバグを公開したところ、2019年5月にはその一点だけを直した検体が使われた [8][10]。IoC 公開が防御に効く期間は、この集団に対しては短い。

一方で変わらないものもある。RC4（およびその改変版）を基調とする暗号化 [3][4][12]、ベンダ名を模した C2 ドメイン [8][14]、盗んだ正規署名証明書の使用 [15][18] は2017年から2022年まで一貫している。道具は入れ替わっても作り手の癖は変わっていない。

日本の組織にとっての含意

日本は「ついで」ではなく標的である。JPCERT/CC が BlackTech を名指しした記事を2018年から2022年まで出し続けている [1][7][8][9][10] という事実は、日本の CSIRT が継続的に注意を促すだけの件数を国内で扱ってきたことを意味する。

境界機器が最初の被害者になる。2022年の事例で確認されたのは「BIG-IP に侵入された」ではなく「BIG-IP 内のデータが窃取された」ことである [1]。ロードバランサや VPN 装置は鍵・設定・時に資格情報を抱えている。境界機器を「守る対象」ではなく「守られていない資産」として棚卸しし直す必要がある。

委託先とグループ会社が経路になる。台湾の MJIB 事例では、政府機関そのものではなく委託先の IT サービス事業者4社が侵害され、そこから少なくとも10機関に波及した [14]。人手の層の2023年の注意喚起も、海外子会社のルータを踏み台にする手口を指す。自社の境界だけを固めても意味がない。

Linux サーバの調査能力の欠落が、そのまま見落としになる。JPCERT/CC が Linux 版の記事を2本とも「Windows で見つけたら Linux も調べよ」で締めているのは [3][4]、その逆が実際に起きているからだと読むべきである。

署名済みバイナリと HTTP 更新は信用の穴になる。D-Link と Changing 社の証明書が示すのは、取引先の署名鍵の管理水準がそのまま自社のリスクになるということである [18]。ASUS WebStorage の件はさらに直接的で、更新チャネルが真正性を検証していなかったために任意の実行ファイルを送り込まれた [17]。

取るべき防御

  1. 外部公開機器のパッチを「公開直後」の速度で当てる。CVE-2022-1388 は公開後まもなく悪用されている [1]。VPN・ロードバランサ・ファイアウォール・ファイル転送装置には、通常のパッチ適用サイクルとは別の緊急枠を設ける。
  2. 境界機器の管理画面をインターネットから外す。ESET が観測した被害組織はルータの管理画面が外部から到達可能だった [17]。露出は外部スキャンで実測する。
  3. 境界機器を侵害前提で扱う。BIG-IP からデータが盗まれた事実 [1] を踏まえ、境界機器が持つ秘密（鍵・証明書・設定・資格情報）を洗い出し、侵害時に何を再発行するかを事前に決めておく。
  4. Windows で侵害を見つけたら、必ず Linux も調べる。JPCERT/CC の明示的な推奨である [3][4]。前提として Linux サーバの取得ログとフォレンジック手順を平時に決めておく。
  5. 資産管理ソフト・配布サーバの正規機能の悪用を監視する。日本の事例では資産管理ソフトのサーバから横展開されている [5]。配布機能によるプログラム実行は、実行元と実行先の組み合わせでベースラインを取る。
  6. 正規ツールの使われ方を見る。PsExec・Putty・WinRAR・SoftEther VPN [14][15] は存在自体が珍しくない。SoftEther は svchost.exe に偽装されていても証明書が残るため、証明書のファイル名で環境内を狩れる [14]。
  7. コード署名を「検証済み」の根拠にしない。署名の有無だけを許可条件にしている仕組みは、発行者と証明書のシリアルまで含めた条件に絞る。
  8. ソフトウェアの更新経路を棚卸しする。HTTP で更新を取得し真正性を検証しないクライアントソフトを洗い出し、置き換えるか通信経路を制限する [17]。
  9. IoC の扱い。骨格には検体ハッシュ330件・ドメイン165件・IP 31件が機械抽出されているが、これらは悪性を検証していない。照合先のテレメトリが無いため検知には使わない。過去の侵害を遡って探す手がかりに留める。

分からないこと

  1. 2023年以降にこの集団が何をしているか。読んだ20本は2022年で止まっている。人手の層に2023年9月の日米合同注意喚起の記録はあるが、それを裏づける一次資料は材料に無く、2024年以降は皆無である。
  2. ルータのファームウェア改ざんの技術的な中身。人手の層が記録する2023年の手口について、対象機種・改ざんの手段・初期アクセス経路・検知方法のいずれも今回の20本に記述が無い。日本の組織にとって最も差し迫った手口でありながら、ここが空白である。
  3. 中国政府のどの部分と結びついているか。TeamT5 は「中国の駭客組織」[12][14]、台帳の ATT&CK 記述は "suspected Chinese" と書くにとどまり、ESET と Symantec は国名すら挙げていない [15][18]。委託先企業や所管機関を特定した資料は無い。
  4. 日本での被害の全体像。JPCERT/CC は「日本の組織」「多数の感染報告」としか書かず [7][9]、業種・件数・規模を出していない。2022年の BIG-IP の件も「標的組織」としか特定されていない [1]。
  5. 初期侵入経路が不明なままの事例がある。Symantec は2019〜2020年の作戦について初期侵入の手段を掴めなかったと明記しており [15]、台湾 MJIB の事例でも委託先がどう侵害されたかは公開されていない [14]。
  6. 道具の系譜のつながり。Symantec が2020年に見つけた Consock・Waship・Dalwit・Nomri の4ファミリが新規開発か既存ツールの発展形かは同社も判断を保留している [15]。これらと JPCERT/CC が日本で観測する TSCookie 系との関係も分からない。
