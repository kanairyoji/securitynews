Lazarus Group

公開されている脅威インテリジェンスと一次資料から整理したもの。 事実と評価を分けて書いています。

一言でいうと

Lazarus Group は、少なくとも2009年から活動している北朝鮮の国家支援集団である [7][15]。破壊（2013年の韓国、2014年の映画会社）、諜報（防衛産業・セキュリティ研究者）、そして資金獲得（銀行の送金システム・ATM・暗号資産）の3つを同じ傘の下で回してきた点が他の国家系アクターと違う [15][8][5]。米国政府は2021年、この集団に連なる3名を訴追し、被害総額を約13億ドルとした [5]。日本との関係は、資金獲得系統（BlueNoroff）が日本のベンチャーキャピタルと銀行を装う偽ドメインを多数作っていたことが公開情報として確認できる [13]。

素性

国家帰属。 米国政府は北朝鮮政府による悪意あるサイバー活動を HIDDEN COBRA と総称し、FBI・CISA・財務省は Lazarus Group を「北朝鮮の国家支援 APT アクター」として扱っている [1][16][17]。Microsoft は ZINC を「DPRK に連なる国家支援グループ」とし、観測した手口・インフラ・マルウェアの型・アカウントの関係から高い確度で帰属させた [6]。Proofpoint は「情報セキュリティ業界・法執行機関・各国情報機関に広く受け入れられている」と書いている [15]。

基礎層（MITRE ATT&CK・MISP）。 骨格の帰属確度は MISP の 0-100 スケールで50。ATT&CK の記述は下位系統の Andariel（G0138）のもので、「少なくとも2009年から活動し、韓国の政府機関・軍・国内企業を主に狙い、ATM・銀行・暗号資産交換業者への金銭目的の作戦も行ってきた」「Andariel は Lazarus Group（G0032）の下位集合とみなされ、北朝鮮の偵察総局（Reconnaissance General Bureau）に帰属されている」とする〔ATT&CK G0138、2019年9月の米財務省発表を引用〕。

名前が59個ある。 骨格が持つ別名は Andariel、Silent Chollima、PLUTONIUM、Onyx Sleet、APT38、BlueNoroff、Stardust Chollima、Sapphire Sleet、Hidden Cobra、ZINC など59件。これは1つの実体の呼び名ではなく、複数の系統を1つの傘に束ねた結果である。台帳（config/japan_watchlist.yaml）は Lazarus Group（本体・諜報と破壊）、Andariel（韓国の防衛産業・重要インフラ）、APT38／BlueNoroff（資金獲得）の3系統に分けて整理しているが、Malpedia は資料もマルウェアも lazarus_group に統合しており、資金獲得系統の独立したプロフィールは作れない。本記録もその制約に従い、BlueNoroff の資料 [13] を Lazarus Group のページの中で扱う。

Microsoft は2023年4月に命名体系を天候由来へ変え、ZINC は Diamond Sleet として追跡されるようになった [6]。同じ活動が資料ごとに別名で書かれるため、突き合わせるときは名前ではなくマルウェアとインフラで照合する必要がある。

固有マルウェアが異常に多い。 骨格が Malpedia から引いた固有ファミリは133件。Windows だけでなく macOS 24件、Linux/ELF、AIX（aix.fastcash）、Android（apk.badcall）、PHP ウェブシェル、PowerShell まで揃っている。SentinelOne は macOS 検体群を分析して「Windows マルウェアを移植しているのではなく、Apple のプラットフォームに深く投資した Mac 専門の開発者がいる」と結論づけた [2]。

これまでの活動

  1. 2009年ごろ
    活動開始。複数の資料が「少なくとも2009年から」で一致する [7][15]。
  2. 2013年3月20日
    韓国で破壊的攻撃（Dark Seoul）[15][8]。
  3. 2014年
    映画会社（Sony Pictures）への攻撃 [15][8]。
  4. 2015〜2016年
    SWIFT を標的とした一連のキャンペーン [8]。
  5. 2016年
    バングラデシュ中央銀行から8,100万ドルを窃取。不正送金の証拠を消すために Trojan.Banswift を使った。Banswift は旧来の Backdoor.Contopee とコードを共有しており、Contopee と Fimlis／Fimlis.B は東南アジアの金融機関への限定的な標的型攻撃で既に使われていた。この一連の攻撃を受けて決済網 SWIFT が警告を出した [5]。
  6. 2016年10月
    ポーランドの少なくとも20行と他国の銀行を侵害する大規模作戦。この時期の実装体に、Spritz 暗号を XOR ではなく加減算で実装した独自版（Spritz-xor）が使われていた [15]。
  7. 2016年末〜2017年初
    銀行・金融を狙う水飲み場攻撃。標的組織の従業員が見そうなサイトを侵害し、独自のエクスプロイトキットで Ratankba を配布した。キットは約150個の IP アドレスからの訪問者だけを感染させるよう設定されており、その IP は31か国104組織（大半が銀行）に属していた [5][15]。
  8. 2017年
    WannaCry。流出した EternalBlue（CVE-2017-0144／CVE-2017-0145）を組み込んでワーム化し、数時間で世界中の数十万台に感染した。ただし実行は雑で、感染端末ごとに固有のビットコインアドレスを生成するはずが不具合で3つの固定アドレスに落ち、誰が支払ったか攻撃者側で分からなくなった。研究者がキルスイッチのドメインを登録したことで被害も限定された [5]。
  9. 2017年6月30日ごろ
    暗号資産を材料にした一連のキャンペーンが開始。少なくとも1社の暗号資産事業者の役員を狙ったスピアフィッシングから始まり、以降 PowerSpritz・LNK・CHM・JavaScript・マクロ入り Office 文書・バックドア入り PyInstaller アプリの6経路で PowerRatankba を配布した [15]。
  10. 2017年10〜12月
    韓国の POS フレームワークを狙う RatankbaPOS。Proofpoint は「国家主体が POS 関連フレームワークをクレジットカード情報の窃取のために狙った、公開された初の事例」としている。年末商戦期を狙った時期設定だった [15]。
  11. 2018年
    FASTCash。アフリカとアジアの ATM 網を狙い、銀行網に侵入して ATM 取引を処理するスイッチアプリケーションサーバーに到達、Trojan.Fastcash を置いて不正な出金要求を横取りし偽の承認応答を返させた [5]。
  12. 2018年8月
    AppleJeus の初確認。正規に見える暗号資産取引アプリを装う手口で、Kaspersky はこの作戦で「Lazarus が初めて macOS 利用者を標的にした」とし、信頼を得るために架空の会社まで作っていたと書いている [1][14]。
  13. 2018年9月19日
    中南米の複数の金融機関に AuditCred.dll／ROptimizer.dll を使ったモジュール型バックドアを設置。2017年にアジアの標的へ使われた FileTokenBroker.dll の手口とサービス登録・配置の型が一致していた [10]。
  14. 2019年3月
    Windows 版 AppleJeus の被害者を確認。WFCUpdater.exe から始まり、偽サイト wfcwallet[.]com を使い、RasMan（Remote Access Connection Manager）サービスに rasext.dll を登録して居座った [14]。
  15. 2019年9月〜2020年8月
    Operation Dream Job〔ATT&CK 作戦記録〕。航空宇宙・防衛の請負企業を狙って求人を装った [3]。
  16. 2019年12月
    Union Crypto（unioncrypto[.]vip）。Telegram のダウンロードフォルダから実行された痕跡があり、Kaspersky は偽サイト上の Telegram グループを見つけて「Telegram 経由で改変済みインストーラを配った」と高い確度で評価している [1][14]。同月、360 Netlab が Windows／Linux 版の Dacls RAT を公表 [11]。
  17. 2020年3月末
    VHD ランサムウェアを初観測。Kaspersky は既知の Lazarus ツールと近接して投下された事案を特定し、Lazarus が VHD の背後にいると結論づけた。同社は「Lazarus が金銭目的で標的型ランサムウェアに手を出したことが確認されたのは、我々の知る限りこれが初めて」としている [9]。
  18. 2020年4月〜6月
    macOS への本格展開。4月に二要素認証アプリを装う TinkaOTP（Dacls RAT の macOS 版）[11][7]、5月に暗号資産取引アプリを装う Cryptoistic、6月1日に軽量バックドア群 OSX.Casso、6月3日に CoinGoTrade、さらに WatchCat／MediaRemote が相次いで現れた [2]。
  19. 2020年前半
    韓国のソフトウェアベンダーを水飲み場攻撃で侵害し Bookcode（Manuscrypt の変種）を投入。同じ被害者を約1年前にもセキュリティツールを装って狙って失敗していた。Kaspersky はこの作戦の目的を知的財産の窃取と評価している [9]。同時期、学術と自動車の分野を狙う作戦でリモートテンプレートインジェクションと、オープンソースの Sumatra PDF を改造した閲覧ソフトが使われた。最終ペイロードは CISA が COPPERHEDGE と名付けたものと同じ Manuscrypt 変種だった [9]。
  20. 2020年ごろ〜2021年
    韓国の公共機関・大学、および多数の物流・IT・製造企業への NukeSped 攻撃。AhnLab は自社の ASD インフラのログから過去の感染事例をたどり、いずれも同じバックドアが使われていたことを確認している [4]。
  21. 2020年中頃〜10月
    セキュリティ研究者を狙う ZINC 作戦。Twitter で質の高いセキュリティ情報を再投稿して評判を作り、約2,000人のフォロワーを集めた。10月14日に自前ブログ（br0vvnn[.]io）の記事を Twitter で共有し、10月19〜21日に Chrome で閲覧した研究者が、接触もファイル受領もしていないのに感染した。Microsoft は Chrome のエクスプロイトチェーンがブログに置かれていた可能性が高いとしつつ、証明はできていないと明記している。公表は2021年1月28日 [6]。
  22. 2021年2月
    米国が3名を訴追。被害総額は約13億ドルで、金融機関と暗号資産交換業者が対象。カナダ系米国人1名がこの資金洗浄への関与を認めた。3名のうち1名は2018年に既に訴追されていた [5]。同月、FBI・CISA・財務省が AppleJeus の分析報告を公表し、少なくとも7つの版が確認されていることを示した [1][5]。
  23. 2021年4月
    韓国で悪性 Word 文書が多数収集される。文書内の PNG を BMP に変換して悪性 PE またはスクリプトを取り出すという、それまで報告のない手法だった [4]。
  24. 2022年8月
    ESET が Coinbase の求人を装う macOS 攻撃（Operation In(ter)ception）を確認。SentinelOne はその後、同じ枠組みで Crypto.com の求人を装う変種を確認した。誘導は LinkedIn の個別メッセージとみられている [3]。
  25. 2022年9月2日
    UAE の被害者（住宅金融会社とみられる）が "Shamjit Client Details Form.doc" を受領。侵入後、攻撃者は手で環境を調べ、18時間後に戻って高権限で追加のマルウェアを入れた [13]。
  26. 2022年10月
    BlueNoroff が新しい配送手法を採用。ISO と VHD で Mark-of-the-Web を回避し、VBScript・バッチ・Windows 実行ファイルの3種類を試していた。調査したインフラから70を超えるドメインが見つかり、その多くが日本のベンチャーキャピタルと銀行を装う偽ドメインだった [13]。
  27. 2022年11月〜2023年3月
    3CX サプライチェーン攻撃〔ATT&CK 作戦記録〕。本記録が読んだ20本にこの作戦の記述は無い。

手口

入り口（T1566 / T1189 / T1195.002 / T1204）。 大きく3系統ある。①求人を装うスピアフィッシング。航空宇宙・防衛 [3]、暗号資産取引所の従業員 [3]、日本の銀行の求人を装った囮 PDF [13] と、標的に合わせて業界を変える。②水飲み場。標的の従業員が見るサイトを侵害し、訪問元 IP で絞り込んで配る [5]。標的機関が使うソフトウェアの脆弱性を突いた例もある [4]。③改変済みアプリ。偽の暗号資産取引アプリ [1][14][2]、改造した二要素認証アプリ [11][7]、バックドア入りの PyInstaller アプリ [15]。3CX のようなサプライチェーン侵害〔ATT&CK 作戦記録〕もこの系統にあたる。

受け取らせる工夫が細かい。 ZIP に暗号化した囮文書と Password.txt.lnk を同梱し、パスワードを見るためにショートカットを実行させる [13]。パスワードを notepad で表示して不審を打ち消す [13]。囮 PDF と実行ファイルの拡張子の前に空白を大量に入れて隠す（T1036.006）[13]。CHM ファイルの中で x.Click(); を呼び、ショートカットオブジェクトを自動クリックさせる [15]。セキュリティ研究者に対しては、悪性の Visual Studio プロジェクトを送ってビルドイベントで実行させた [6]。標的の職業に合わせて実行の口実を変えている。

実行と回避（T1059 / T1218 / T1553.005 / T1548.002 / T1685）。 PowerShell [15][6]、Windows コマンドシェル [13][14]、Visual Basic [15][13] を使い分ける。正規バイナリの悪用が多く、rundll32 [6][13][14]、msiexec [13]、mshta [13]、CHM（T1218.001）[15]、SyncAppvPublishingServer.vbs [13]、UAC 回避に ieinstal.exe [13]。ISO と VHD で Mark-of-the-Web を回避する [13]。AV 製品を列挙し（T1518.001）、製品ごとに振る舞いを変える——Sophos・Kaspersky・Avast・Avira・Bitdefender・TrendMicro・Windows Defender を調べ、TrendMicro／Bitdefender／Windows Defender があれば ntdll の .text セクションを新しく読み直したもので上書きしてユーザーモードフックを外す（T1685）[13]。Themida によるパッキング（T1027.002）も使う [8]。

居座り（T1543.003 / T1547.001 / T1053.005）。 Windows サービスとしての登録が多い [10][8][6]。レジストリの Run キー（HKCU\...\Run\SSL Update に rundll32 の行を書く）[6]、スケジュールタスク [4][15]、macOS では LaunchAgent と LaunchDaemon（com.aex-loop.agent.plist、com.wifianalyticsagent.plist）[11][3]。設定と本体を別ディレクトリに分ける設計もある——ローダーとその設定ファイルは %windows%\system32 に、暗号化した本体は %Program Files%\Common Files\System\ado に置き、全部を見つけて消しにくくしている [10]。

C2（T1001.003 / T1573.001 / T1090 / T1571 / T1104）。 FakeTLS が一貫した指紋である。 BUFFETLINE は PolarSSL で TLS ハンドシェイクまで正規に行い、その後に生成された鍵を使わず、17 03 02 で始まる偽の TLS ヘッダに独自 XOR で暗号化したデータを載せる。PolarSSL のテスト証明書がそのまま埋め込まれ、server_name は !Q@W#E$R%T^Y&U*I(O)P に固定されている [17]。BADCALL も同じ「Fake TLS」を実装したプロキシである [16]。他に RC4、回転 XOR、独自エンコードを使い [8][7]、標準外ポート（8088・8443 など）に出る [8][2]。プロキシ／中継の実装が多く、HOPLIGHT は感染端末と C2 の間の中継 [8]、Dacls の RP2P プラグインと Socks プラグインも同じ役割を果たす [11][7]。macOS の Dacls は C2 の IP を暗号化した設定ファイル（/Library/Caches/com.applestore.db、AES-CBC）に保存して更新できるようにしている [11]。ビーコンの間隔は60秒が多い [6][8]。

多段化と選別（T1104 / T1620）。 UnionCryptoTrader の macOS 版は、現在時刻と固定文字列 12GWAPCT1F0I1S14 を結合した MD5 を auth_signature として送り、C2 側で再現できる値でなければ次段を渡さない。次段はディスクに落とさずメモリに読む [14]。最終ペイロードは事前に集めた情報をもとに特定のシステムでしか動かないよう作られていた [14]。PowerRatankba も同様に、まず情報を送って「価値がある」と判断された被害者にだけ Gh0st RAT を渡す設計だった [15]。全員に最終段を配らないのがこの集団の一貫した性質である。

探索・収集（T1046 / T1217 / T1056.001 / T1115 / T1070.006）。 NukeSped は ModuleShell・ModuleFileManager・ModuleKeyLogger・ModuleSocksTunnel・ModuleScreenCapture・ModuleInformation・ModulePortForwarder のモジュール構成で、感染後にはウェブブラウザと Outlook の認証情報窃取、クリップボードとウィンドウテキストの窃取、ファイルの MAC タイム改変（T1070.006）、ポートスキャナ、そして DarkComet RAT の追加設置が確認されている [4]。BISTROMATH はさらにマイク・ウェブカメラ・ブラウザのフォームグラビングまで持つ [8]。Dacls の LogSend プラグインにはワームスキャナがあり、ポート 8291／8292 でサブネットを走査する [7][11]。ZINC 作戦では Chrome のパスワード窃取ツールが使われた [6]。

サンドボックス回避。 BISTROMATH ほか US-CERT が分析した検体群は、VirtualBox・QEMU・VMware の痕跡（特定のデバイス・レジストリ・プロセス・ファイル）を複数チェックする [8]。物理メモリが 2GB 未満なら終了するダウンローダーもある [13]。

目的側の技術（T1657 / T1486 / T1485 / T1565）。 金銭窃取（T1657）が最も多い [5][15]。データの暗号化（T1486）は WannaCry [5] と VHD ランサムウェア [9]。破壊（T1485 / T1561）は2013年の韓国と2014年の映画会社 [15][8]。保存データ・送信データの改ざん（T1565.001 / .002）が特徴的で、Banswift は不正送金の証拠を消し [5]、FASTCash は ATM の出金要求に偽の承認応答を返させた [5]。これらは「盗む」だけでなく「記録を書き換える」ことを目的にした実装である。

日本との関係

層を分けて書く。混ぜると帰属の確度が語れなくなる。

公開情報（本記録が読んだ一次資料20本） — 日本に直接触れる資料は1本、Kaspersky の BlueNoroff 分析 [13] だけである。同社は調査したインフラから70を超えるドメインを見つけ、その多くが日本のベンチャーキャピタルと銀行を装う偽ドメインだったと報告している。具体名は Beyond Next Ventures（beyondnextventures.co）、三井住友銀行（smbc.ltd・smbcgroup.us・smbc-vc.com）、三菱UFJフィナンシャル・グループ（mufg.tokyo・cloud.mufg.tokyo）、ANOBAKA（vote.anobaka.info）、Z Venture Capital（it.zvc.capital）、ABF Capital（abf-cap.co）、Angel Bridge（angelbridge.capital）、みずほフィナンシャルグループ（mizuhogroup.us・careers.mizuhogroup.us）。同じ表に載る非日本企業は Bank of America（米国）と Trans-Pacific Technology Fund（台湾）の2つだけで、偽装対象は日本企業に強く偏っている [13]。

同じ資料には、日本語のファイル名を持つ ZIP（新しいボーナススケジュール.zip）と、日本の多国籍銀行からの求人を装った囮 PDF が出てくる。Kaspersky はこれらを根拠に「ドメインの命名と囮文書から、日本の組織がこのグループの視野に入っていると低い確度で推定する」「日本語のファイル名で届いたことは、標的が日本語を読めることを示唆する」と書いている [13]。確度が「低い」と明記されている点をそのまま伝える。 この資料で実際に侵害が確認された被害者は UAE の企業であり、日本の被害組織は1つも名指しされていない。

読んだ20本のうち、日本の組織が侵害されたと明記した資料は1本も無い。攻撃対象国として名前が挙がるのは韓国 [4][9][15]、バングラデシュ [5]、ポーランド [15][5]、中南米 [10]、アフリカ・アジアの ATM 網 [5]、英国・ポーランド・ロシア・中国 [14]、UAE [13] である。

公開情報（基礎層・MISP galaxy） — MISP galaxy が推定被害国のリストに日本を挙げている〔骨格・基礎層〕。これは推定であり、個別事案の裏付けではない。

人手（台帳 config/japan_watchlist.yaml） — 定点観測に載せた根拠は「暗号資産交換業者への攻撃で日本国内の事業者にも被害が公表されている。IT技術者の身分偽装による就労も各国当局が警告している」。台帳の記載であり、本記録が読んだ20本には含まれない。20本の中に日本の暗号資産交換業者の被害を扱った資料も、IT技術者偽装を扱った資料も無い。

自前の観測 — 骨格に観測層の記載は無い。本記録は自前の観測を根拠にしていない。

実被害（リークサイト掲載） — 該当なし。Lazarus はリークサイトを運用する型のランサムウェア集団ではない。

最近の動き

読んだ20本のうち、内容が最も新しいのは2022年10月の Kaspersky の BlueNoroff 分析 [13] と、同じ2022年の SentinelOne による Crypto.com 求人を装う macOS 攻撃の報告 [3] である。公開されている資料は2022年までで、それ以降の動きは確認できていない。

骨格が持つ ATT&CK の作戦記録は 3CX サプライチェーン攻撃（2022年11月〜2023年3月）まで伸びており、Malpedia も win.3cx_backdoor／osx.3cx_backdoor を Lazarus 帰属の固有ファミリとして持っている。しかし20本の中に 3CX を扱った資料は無く、本記録はその内容を書けない。

資料18・19（Mandiant の APT29 外交フィッシング／DPRK WhatsApp フィッシング）は取得したページがサービス紹介の定型文だけで、記事本文が取れていない。資料20（UNC4393／BASTA ランサムウェア）は Lazarus ではなく金銭目的の別クラスタを扱ったものである。この3本は本文の根拠に使っていない。

したがって現時点で確認できる最後の姿は、2022年秋の——①求人を装う macOS 攻撃を暗号資産取引所の従業員へ広げ [3]、②ISO/VHD による MOTW 回避と AV 製品ごとに振る舞いを変える回避を実装し [13]、③日本の金融機関とベンチャーキャピタルを装う偽ドメインを70以上抱えていた [13]——ところまでである。

ここから先は本記録の評価です。上の各節は公開資料に基づく事実で、以下は解釈と推論を含みます。

何が変わったか

ここからは本記録の評価です。

「破壊する集団」から「金を取る集団」へ、重心が完全に移った。 2013年の韓国、2014年の映画会社は破壊が目的だった [15][8]。2016年以降は、銀行の送金システム（Banswift）、ATM 網（FASTCash）、POS（RatankbaPOS）、暗号資産（AppleJeus・PowerRatankba）と、金が動く仕組みそのものを順に開けている [5][15]。Proofpoint は「これは制裁下での外貨調達に対する北朝鮮の切迫を示しているかもしれない」と書き、従来は諜報を担っていたチームの指令が変わった可能性に触れている [15]。20本の資料の時系列は、この読みと矛盾しない。

標的が組織から個人へ降りた。 Proofpoint はこれを2017年の時点で明示している——「このグループは今や組織だけでなく個人を狙うようになった。個人は守る資源と知識を欠く、より柔らかい標的である」[15]。以後の資料はすべてこの線上にある。求人を装って個人の端末に入る [3]、セキュリティ研究者個人を SNS で口説く [6]、二要素認証アプリを使う個人を狙う [11]。組織の境界防御を越える必要が無くなるという意味で、これは戦術の変更ではなく前提の変更である。

「まず調べて、価値がある相手にだけ本体を渡す」設計が定着した。 UnionCryptoTrader の署名検証と条件付き最終ペイロード [14]、PowerRatankba の選別 [15]、AV 製品ごとの分岐 [13]。これは検体の入手と解析を体系的に妨げる。サンドボックスに検体を投げても本体が出てこないことを前提に考える必要がある。

プラットフォームの壁が無い。 Windows・macOS・Linux・AIX・Android。SentinelOne は macOS 検体群を見て「移植ではなく Mac 専門の開発者がいる」と評価した [2]。組織として複数の開発ラインを並行して持てている、ということになる。

日本については、確実に言えることが「装われている」までである。 偽ドメインが日本企業に強く偏っている事実 [13] は動かない。ただしこれは日本企業が侵害された証拠ではなく、日本企業の名前が信用の材料に使われた証拠である。この2つを混ぜないことが、このアクターについて日本で語るときの最大の分岐点になる。

日本の組織にとっての含意

自社の名前が囮に使われる側に回る。 [13] の偽ドメイン表に載っているのは、いずれも侵害された企業ではなく名前を借りられた企業である。金融機関とベンチャーキャピタルが偏って選ばれているのは、その業界の相手にメールを送るときに最も疑われにくいからだろう。類似ドメインの監視を「自社が攻撃されるかどうか」の問題としてだけ見ていると、この形は視野に入らない。 取引先や投資先が自社を装った連絡を受けるリスクとして扱う必要がある。

入り口は採用と転職の会話である。 求人を装う手口は、航空宇宙・防衛 [3]、暗号資産取引所の従業員 [3]、日本の銀行の求人を装った囮 [13] と繰り返し出てくる。誘導は LinkedIn の個別メッセージとみられている [3]。業務メールの添付検査では届かない経路であり、個人の端末と個人のアカウントで起きる。持ち込み端末と私物アカウントの扱いを決めていない組織は、この経路に対して打つ手が無い。

「暗号資産を扱っていないから関係ない」は成り立たない。 20本の資料が示す被害業種は、銀行、ATM 網、POS、暗号資産事業者、航空宇宙・防衛、ソフトウェアベンダー、学術、自動車、物流、IT、製造、そしてセキュリティ研究者 [5][15][9][4][3][6]。金が動くか、価値ある技術があるか、他社へ配る製品を作っているかのいずれかに当てはまれば対象になりうる。

EDR が外されることを前提に設計する。 [13] のダウンローダーは AV 製品を列挙し、TrendMicro／Bitdefender／Windows Defender があれば ntdll を上書きしてユーザーモードフックを外す。製品のアラートが出ないことを「侵害が無い」の根拠にしてはいけないという、この集団に特有の具体的な理由がここにある。

FakeTLS はネットワーク側で見つけられる可能性がある。 [17] の CISA レポートは、443/TCP に TLS のように見えて実は独自暗号という通信の構造（17 03 02 の後ろのデータ長と実データ長が4バイトずれる）を示し、それを突く Snort ルールまで公開している。エンドポイントで隠されても、通信の構造が破綻しているため、ネットワーク側に検知の余地が残る。

取るべき防御

骨格の ATT&CK 技術と資料の挙動から、優先順に挙げる（本記録の評価）。

  1. 類似ドメインの監視を「自社を装う側」まで広げる（T1583.001）。[13] は日本の8社を装う偽ドメインを列挙している。自社名・ブランド名・採用サイト名を含む新規ドメイン登録と証明書発行を監視し、見つけたら取引先・投資先・求職者向けに周知する経路を先に決めておく。自社が侵害されていなくても、自社の名前で被害が出る。
  2. 求人・転職を装う接触の扱いを決める（T1566.003 / T1204.002）。SNS の個別メッセージで始まり、暗号化 ZIP や PDF に落ちる [3][13]。従業員の私物端末・私物アカウントで起きるため、①業務データを私物端末に置かない、②求人関連の添付を業務端末で開かない、の2点を明文化する。技術で止まらない部分が大きい。
  3. ISO・VHD・LNK・CHM の受け取りを絞る（T1553.005 / T1218.001）。MOTW 回避の目的で使われる形式である [13][15]。メールゲートウェイとブラウザのダウンロードで、これらの形式を業務上必要な範囲まで絞り込む。Password.txt.lnk のようにパスワード提示を口実にした形が繰り返し出ている [13]。
  4. 正規バイナリの異常な起動を記録する（T1218.005 / .007 / .011 / T1548.002）。rundll32 が %ProgramData% や %Public% 配下の .bin／.db／.dat を読む [6]、msiexec が外部 URL の MSI を静かに入れる [13]、mshta が PDF 拡張子のファイルを実行する [13]、SyncAppvPublishingServer.vbs が PowerShell を起こす [13]、ieinstal.exe が UAC 回避に使われる [13]。単体では正規なので、親子関係と引数の組み合わせで見る。
  5. ntdll の書き換えを検知対象にする（T1685）。ユーザーモードフックの解除は EDR の目を潰す手であり [13]、これ自体を高優先のアラートにする。カーネル側またはネットワーク側に、独立した観測点を持たせる。
  6. FakeTLS を疑う（T1001.003 / T1573.001 / T1571）。443/TCP なのに TLS の内部構造が壊れている通信を探す。[17] の Snort ルール（content:"PolarSSL"; pcre:"/\x17\x03\x02\x00\x23.{39}\x17\x03\x02/"）は起点として使える。あわせて標準外ポート（8088・8443 など）への長時間の定期通信（60秒間隔が多い [6][8]）を見る。
  7. サービス登録と Run キーの棚卸し（T1543.003 / T1547.001）。C:\Windows\System32 に置かれた .sys [6]、%windows%\system32 のローダーと別ディレクトリの本体という分割配置 [10]、HKCU\...\Run の rundll32 行 [6]。設定・ローダー・本体が別々の場所にある前提で探さないと片方だけ消して終わる。
  8. macOS を対象に含める（T1543 / T1547）。~/Library/LaunchAgents/ と /Library/LaunchDaemons/ の plist、~/Library 直下のドット始まりの隠しファイル [11][3]。検体は ad hoc 署名だけで Gatekeeper を通るものがあり [3]、署名の有無では判断できない。
  9. ワームスキャンと横方向の走査（T1046）。ポート 8291／8292 に対するサブネット走査 [7][11]、感染端末からのポートスキャナ実行 [4]。内部ネットワークの走査を検知する仕組みを持つ。

骨格に付く IoC（検体ハッシュ655件・ドメイン246件・IP157件）は機械抽出で悪性を検証しておらず、照合先のテレメトリも無い。そのまま検知に使わない。

分からないこと

  1. 日本で実際に何が起きたのかが分からない。 読んだ20本に、日本の組織が侵害された事案は1件も書かれていない。分かっているのは日本企業を装う偽ドメインが70超のうち多数を占めたこと [13] だけであり、Kaspersky 自身がその推定を「低い確度」としている。台帳が根拠とする「日本国内の暗号資産交換業者の被害公表」も、20本の中に裏付ける資料が無い。日本の被害を語るには、この20本とは別の資料が要る。
  2. 傘の内訳が決められない。 Lazarus Group・Andariel・APT38・BlueNoroff がそれぞれ何を担い、どこで分かれるのかは資料ごとに書き方が違う。Malpedia は資料もマルウェアも lazarus_group に統合しており、Proofpoint は「北朝鮮の傘の下に複数のチームがある」可能性に触れるにとどまる [15]。どの系統に狙われているかで防御の優先順位は変わるはずだが、公開情報だけでは決められない。
  3. 2022年10月以降の動きが分からない。 20本の資料はそこで止まっている。3CX サプライチェーン攻撃は骨格の ATT&CK 作戦記録にあるが本文の資料が無く、内容を書けない。
  4. どの機関が運用しているのかは、下位系統についてしか分からない。 ATT&CK は Andariel を偵察総局（RGB）に帰属させているが〔ATT&CK G0138〕、Lazarus Group 本体をどの機関が運用しているかを示す記述は20本に無い。
  5. ZINC 作戦の初期侵入が証明されていない。 Microsoft 自身が「ブログに Chrome のエクスプロイトチェーンが置かれていた可能性が高いが証明できていない」「一部の被害者のブラウザは完全にパッチが当たっていたため 0-day またはパッチギャップの悪用が疑われるが未証明」と書いている [6]。セキュリティ研究者がどう感染したかは、今も公開情報では確定していない。
  6. 窃取額の全体像が分からない。 [5] の13億ドルは訴追の対象になった範囲であり、[15] は暗号資産だけで約1億ドル相当という法執行機関の推定に触れる。両者の関係も、その後の増減も、20本からは読み取れない。
  7. 固有マルウェア133件のうち、現在も使われているものが分からない。 Malpedia の帰属は蓄積であって現役性を示さない。2022年以降どのファミリが生きているかは、この20本では判断できない。
