Tick

公開されている脅威インテリジェンスと一次資料から整理したもの。 事実と評価を分けて書いています。

一言でいうと

Tick（BRONZE BUTLER / REDBALDKNIGHT）は、中国に拠点を置くとみられるサイバースパイ集団である。Secureworks の Counter Threat Unit は、活動・標的・能力の分析から本グループが中華人民共和国（PRC）に所在する可能性が高いと評価し、日本の組織から知的財産と機密データを窃取しようとする長年の意図があり、標的が重要インフラ・重工業・製造業・国際関係のネットワークに集中していると述べている [18]。Trend Micro は2008年から本グループを追跡しており、防衛・航空宇宙・衛星通信・小売・工業化学を狙うサプライチェーン攻撃と、複数の独自マルウェアファミリの使い分けで知られると整理している [16]。

素性

Secureworks CTU は「PRC に所在する可能性が高い（likely）」という評価にとどめ、断定はしていない [18]。Trend Micro は帰属には踏み込まず、2008年以降の観測実績として、標的の所属に合わせた流暢な日本語のソーシャルエンジニアリングを常用してきた集団だと記述している [16]。

呼称はベンダーごとに分かれる。Trend Micro は REDBALDKNIGHT、Secureworks は BRONZE BUTLER、JPCERT/CC は「攻撃グループTick」と呼び、いずれも同一実体を指すものとして相互に言及している [2][17][18]。活動開始時期の根拠は、標的に送られたおとり文書（decoy document）のファイルプロパティで、Trend Micro は少なくとも2008年の時点で日本の組織に狙いを定めていたことがそこから読み取れるとしている [17]。

これまでの活動

年が特定できる出来事だけを並べる。

  1. 2008年
    標的に送られたおとり文書のファイルプロパティから、日本の組織への標的化がこの時期にさかのぼることが確認されている [17]。Trend Micro による観測開始も2008年 [16][19]。
  2. 2011年
    バックドア Daserf の存在が、この年までさかのぼって追跡されている [17]。
  3. 2015年〜2016年初頭
    xxmm 系バックドアの作者が2015年頃から開発を続けていた形跡が検体の PDB パスに残る。2016年初頭に同ファミリの Wali が日本で出現 [13]。
  4. 2017年頃まで
    Datper への感染はドライブバイダウンロード攻撃による事例が多かった [2]。
  5. 2017年6月〜2018年3月15日
    資産管理ソフトウェアの脆弱性を悪用する攻撃が Secureworks から公表される（2017年6月）。狙うスキャン通信は2017年10月頃にいったん収まり、2018年3月15日に再開する。悪用される脆弱性そのものに変化はない [2]。
  6. 2017年11月
    Datper の複数の亜種が観測される [3]。同月、Trend Micro が Daserf のステガノグラフィ利用を公表 [17]。
  7. 2018年以降
    感染経路が変化し、標的型攻撃メールに添付された PPT などの不正な文書ファイルからの感染が複数確認される。同じ2018年3月以降、Datper の通信暗号方式に RSA が加わる [2]。
  8. 2018年初頭
    Secureworks CTU の分析官は JSAC2019 の発表で「BRONZE BUTLER はまだ活動しているか？」と問い、2018年初頭以降は不活発に見える、と述べている [3]。
  9. 2018年11月頃
    Trend Micro が、マルウェアの開発・展開が異例に増加したことに気づく [19]。
  10. 2019年1月〜5月
    日本の経済調査会社と PR 会社を侵害してメール認証情報とおとり文書用のファイルを窃取し、乗っ取った正規アカウントから配送する横展開型フィッシングを実施。2月中旬〜4月中旬に1件目の正規アドレスから多数の組織へ、5月に別のアドレスから2巡目が送られた [16][19]。
  11. 2019年2月
    JPCERT/CC が、資産管理ソフトウェアの脆弱性を悪用する攻撃で、従来の xxmm や Datper に代わって Node.js 上で動く新しいマルウェア（NodeRAT）が使われていることを公表 [2]。
  12. 2019年11月27日／29日
    Trend Micro が一連の作戦を「Operation ENDTRADE」と名付けて公表（27日にウィーンの DeepINTEL 2019 で発表、29日にブログ公開）[19]。
  13. 2020年1月17日
    JPCERT/CC が JSAC2020 の基調で、2019年の振り返りとして Tick を取り上げ、資産管理ソフトウェアを狙うスキャン活動（TSUBAME による2017年1月〜2019年12月の観測）と NodeRAT を挙げる [1]。

手口

入口。 標的型攻撃メールの添付ファイル（T1566.001）が主で、2017年頃まではドライブバイダウンロード（T1189）も多用していた [2]。Secureworks はこれに加えて水飲み場型（strategic web compromise）とゼロデイ脆弱性の悪用を挙げる [18]。添付文書は日本語ワープロソフト一太郎で作成され、その脆弱性を突く（T1203、T1204.002）。おとりの表題は「平成20年の防災計画」のように、標的の業務に沿った流暢な日本語で作られる [17]。

もう一つの入口が資産管理ソフトウェアの脆弱性である。 JPCERT/CC の定点観測システム TSUBAME で、この脆弱性を悪用しようとするスキャン通信が長期にわたり観測され、しかもこれは日本のセンサーでのみ観測された。JPCERT/CC は、攻撃者が日本の IP アドレスレンジを中心に攻撃しようとしていると考えられる、と述べている。同記事は該当製品のアップデートを推奨し、参考情報として SKYSEA Client View の脆弱性（CVE-2016-7836）の注意喚起を挙げている [2]。

正規アカウントの悪用。 ENDTRADE では、まず日本の経済調査会社と PR 会社からメール認証情報とファイルを盗み、それを次の標的への配送に使った。メールは正規アカウントから送られ、正規の報告書のように書かれ、「給与水準の引き上げ」「求人市場」「米中貿易」といった、中国経済に関心のある読者に刺さる件名が付けられていた [19]。

日本本社と中国子会社の往復。 検体にハードコードされたコードページは932（日本語）と936（簡体字中国語）の2種類で、Trend Micro は、中国に子会社を持つ日本企業を足がかりに狙っていたと見ている。実際に、感染した中国子会社の端末から共有フォルダ経由で実行ファイルが渡り、日本の従業員がそれを実行した事例が確認されている（T1080）[19]。

マルウェア。 Malpedia が Tick 固有と帰属している系統は Daserf（別名 Muirim / Nioupale）、Datper、xxmm（別名 ShadowWalker）、BROLER（down_new）、NodeRAT、rarstar など。Daserf はシェルコマンド実行・ファイルのアップロード／ダウンロード・スクリーンショット取得・キーロギングの4機能を持ち（T1005、T1113、T1105）、日本・韓国のほかロシア・シンガポール・中国の企業に使われた版もある [17]。xxmm（別名 Minzen）は HTTP/HTTPS を主としつつ TCP・UDP・ICMP にも対応し、RSA と使い捨て RC4 で通信を暗号化する（T1071.001、T1573.001）[3]。Datper も2018年3月以降は実行のたびにランダムな RC4 キーを生成し RSA で包んで送るようになった [2]。NodeRAT は JavaScript で書かれ node.exe（Node.js）上で動き、C2 とは WebSocket で通信する。Node.js があれば動くマルチプラットフォーム型で、JPCERT/CC は攻撃者が Windows 以外に macOS も標的にしていると考えられると述べている [2]。

隠蔽。 Daserf の一部の版はステガノグラフィを使う（T1027.003）[17]。xxmm も画像ファイルを取りに行き、xxmm / mmxx というマーカーに挟まれた暗号化ペイロードから C2 の指示や接続先を読む（T1102.001）。ドロッパーはサービスまたは Run キーとして導入され（T1547.001）、UAC バイパスモジュールを同梱する（T1548.002）[3]。Datper は暗号化データを変則テーブルの Base64 で符号化して URL パラメータに載せる（T1132.001）[2]。ShadowWali / Wali のローダーは 50MB〜200MB に水増しされた実行ファイルで、Cybereason はこれを従来型アンチウイルスの検査を逃れる手口だとしている（T1027.001）。実際に注入されるペイロードは 120KB〜144KB にすぎず、ローダーは srvhost.exe のような正規らしい名前を騙る（T1036.005）[13]。ENDTRADE の新しいファミリは Qihoo 360 や McAfee などの製品の有無を調べ、Trend Micro 製品のプロセスを終了させようとする（T1685）[16]。Secureworks は、データを持ち出したあと痕跡を消す一方、可能なかぎりアクセスを維持し、侵害済みサイトを定期的に再訪して新しい持ち出しの機会を探る運用を報告している（T1070.004）[18]。

インフラ。 xxmm の C2 ドメイン・IP の多くは、侵害された日本の（または日本関連の）正規サイトに向いている。日本企業の正規サイトを模した偽サイトと見られるドメインもある。侵害サイトはほぼ例外なく PHP で書かれており、xxmm ビルダーが PHP トンネル通信に対応していることと符合する。Cybereason は、その多くが日本最大級のホスティング事業者である GMO インターネットグループでホストされていたと述べている [13]。

日本との関係

層を分けて示す。

公開情報（一次資料・引用つき）。 Trend Micro は「REDBALDKNIGHT は、政府機関（防衛を含む）、バイオテクノロジー、電子機器製造、工業化学といった日本の組織を標的とすることで知られるサイバースパイ集団である」と明記している [17]。Secureworks は「BRONZE BUTLER の活動は、日本の組織から知的財産およびその他の機密データを窃取しようとする長年にわたる意図を示している」としている [18]。Trend Micro は ENDTRADE の標的を「日本に本社を、中国に子会社を持つ、防衛・航空宇宙・化学・衛星の各産業」とし、主要な標的の一つが防衛セクターで、被害ネットワークから軍事関連文書を盗もうとしていたと述べている [19]。JPCERT/CC は自組織で確認した攻撃として「標的型攻撃メールによる Datper の感染」「資産管理ソフトウエアの脆弱性を悪用する攻撃」の2つを挙げ、「攻撃者は引き続き、日本の組織に対して攻撃を続けています」と結んでいる [2]。

公開情報（台帳ベース）。 MISP galaxy は推定被害国に日本を挙げる。MITRE ATT&CK は「本グループは主に日本の組織、とりわけ政府・バイオテクノロジー・電子機器製造・工業化学の分野を標的とする」と記述している。いずれも骨格が機械的に引いたもので、上の一次資料と方向は一致する。

自前の観測。 Tick 固有マルウェアの C2 として js.node_rat（NodeRAT）が2026年3月26日に初出として記録されている。機械収集であり、一次資料の裏付けも悪性の検証も無い。

人手（台帳）。 本プロジェクトの定点観測台帳には、BRONZE BUTLER の別名で知られ日本の製造業・防衛関連を長期に狙ってきたこと、資産管理ソフトの更新経路の悪用が知られること、を登録している。

最近の動き

Tick について公開されている一次資料は2020年1月で止まっており、それ以降の動きはこの20本からは確認できていない。 最新のものは JSAC2020 における JPCERT/CC の2019年振り返り（2020年1月17日）で、そこで扱われているのも2019年12月までの観測である [1]。以降について本記録が持つ材料は、前節の機械収集の C2 記録1件のみで、一次資料の裏付けを欠く。

なお、骨格が「読む資料」として挙げた20本のうち、Tick を扱っているのは8本（[1][2][3][13][16][17][18][19]）だけである。残る12本は Sharp Panda、Eternity、Kimsuky、Clasiopa、Bisonal、APT10、Vicious Panda、Rancor、Cycldek、Tropic Trooper など別のアクターを扱った資料で、Lilith のような共有・汎用のマルウェア名を介して機械的に紐づいたものと見られる。本文ではこれら12本を根拠として使っていない。

ここから先は本記録の評価です。上の各節は公開資料に基づく事実で、以下は解釈と推論を含みます。

何が変わったか

ここからは本記録の評価です。

第一に、入口が「待ち」から「奪ったアカウント」へ移った。2017年頃までのドライブバイダウンロードは標的が来るのを待つ手口である。2018年以降の標的型メール、そして ENDTRADE の「日本の経済調査会社と PR 会社を先に落として、そこの正規アカウントから送る」やり方は、標的の受信箱に確実に届く経路を自力で作りにいく手口だ [2][19]。送信元が本物の取引先である以上、送信ドメイン認証も添付の見た目も防御側の判断材料にならなくなる。

第二に、通信の解析を意図的に潰しにきた。Datper が2018年3月を境に、固定 RC4 キーから「実行ごとのランダム RC4 キーを RSA で包んで送る」方式へ変えたのは、検体を1つ手に入れて鍵を割り出せば過去の通信ログをまとめて復号できる、という防御側の常套手段を無効化する変更である。JPCERT/CC 自身が「RSA の秘密鍵がなければ通信を復号することができません」と明記している [2]。

第三に、日本本社ではなく中国子会社が入口になりうる構図が実証された [19]。

一方で、2018年初頭に Secureworks の分析官が「不活発に見える」と述べた直後の同年11月に、Trend Micro が開発活動の異例の増加を観測している [3][19]。片方のベンダーの視界から消えることと、活動が止まることは別だ。

日本の組織にとっての含意

1. 国内向けの製品・言語が、そのまま攻撃面になっている。 一太郎の脆弱性を突くおとり文書 [17]、日本の資産管理ソフトウェアの脆弱性 [2]、日本のホスティング事業者上の侵害サイトを使った C2 [13]。いずれも海外ベンダーの汎用的な検知ルールが最も薄くなる領域で、製品の「日本向け脅威インテリジェンス」が国内固有ソフトをどこまでカバーしているかは CISO が個別に確認すべきだと考える。

2. スキャンが日本のセンサーでしか観測されなかった、という事実の重みは大きい [2]。グローバルの脅威動向を眺めていても見えない攻撃が存在することを示す実測値であり、JPCERT/CC・国内ベンダーの発信を独立した情報源として持つ理由になる。

3. 中国子会社を「守る対象」ではなく「経路」として設計に入れる必要がある [19]。グループ会社間の共有フォルダ、共通の資産管理サーバ、統合された認証基盤は、いずれも ENDTRADE で使われた経路と同じ形をしている。

取るべき防御

資料に出てくる手口に直接対応するものだけを挙げる。

  • 資産管理ソフトウェアを最優先でパッチ管理の対象にし、管理サーバからの配信経路そのものを監視する [2]。エージェントが親サーバ以外と通信していないか、エージェント経由で見慣れない実行ファイルが配られていないかを見る。
  • 管理サーバの管理インターフェースをインターネットから到達不能にする。 日本の IP レンジに絞ったスキャンが数年観測されている以上 [2]、外部公開は探索対象そのものである。
  • 一太郎を含む国内文書ソフトのバージョンを把握してパッチを当て、文書ソフトが子プロセスとして PowerShell やスクリプトエンジンを起動する挙動を検知対象にする [17]。
  • 取引先の正規アカウントから来たメールを前提に検知を組む [19]。送信元の正当性ではなく、添付が何を実行するか（プロセス生成の連鎖、外部通信の発生）で判断する。
  • Node.js を業務で使っていない端末で node.exe が動いていないかを見る。 NodeRAT は %APPDATA% 配下に node.exe と app.js を展開して動くため、正規の Node.js が無い環境では強い手がかりになる [2]。
  • 異常に大きな実行ファイル（数十MB〜200MB規模）を検知の観点に入れる [13]。
  • グループ会社間の共有フォルダに置かれた実行ファイルの生成・実行を監視する [19]。特に海外子会社から本社側へ渡るファイルは、内部通信でも外部由来として扱う。
  • プロキシログの保全期間を見直す [3]。通信が復号できない以上、宛先・タイミング・頻度のログが唯一の材料になる。
  • セキュリティ製品のプロセス終了・停止イベントを検知する [16]。

IoC については、本記録が一次資料から機械抽出したハッシュ514件・ドメイン155件・IP48件がある。ただしこれらは悪性を検証しておらず、照合先のテレメトリも無いため、検知に使ってはならない。 過去の資料に出た C2 は数年前に侵害された正規サイトである可能性が高く、現在も悪性である保証は無い。

分からないこと

  1. 2020年以降の活動が分からない。 一次資料は2020年1月で途切れている [1]。活動が止まったのか、追跡が公開されなくなったのか、別名で追われているのかを区別できない。2018年初頭にも一度「不活発」と評価された直後に活動が確認されている [3][19]。
  2. 背後の組織が分からない。 別名に PLA Unit 61419 が含まれ、MISP は中国国防科技大学との近い関係とそれが人民解放軍につながる可能性に言及しているが、帰属の確度は MISP のスケールで50にとどまる。起訴・制裁のような、事実として扱える裏付けは今回の資料には無い。
  3. 2026年3月26日に記録された js.node_rat の C2 が本物か分からない。 機械収集で、一次資料の裏付けも悪性の検証も無く、誤検知の可能性を排除できていない。
  4. 国内での実被害の規模が分からない。 資料は業種（防衛・航空宇宙・化学・衛星・電子機器製造・工業化学・政府機関）を挙げるが [17][19]、被害組織数・被害期間・持ち出された情報量のいずれにも公開値が無い。
  5. 資産管理ソフトウェアの脆弱性が現在も攻撃面として残っているかが分からない。 公表されたスキャン状況は2019年12月までで [1][2]、その後の推移は材料に無い。
  6. 現在の主力マルウェアが分からない。 ENDTRADE で列挙された ABK、Avenger、BBK、build_down、down_new、doc_ll、Pretender、Casper といった系統 [16] の、2019年以降の使用状況を示す資料が無い。
