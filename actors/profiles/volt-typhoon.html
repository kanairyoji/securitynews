Volt Typhoon

公開されている脅威インテリジェンスと一次資料から整理したもの。 事実と評価を分けて書いています。

一言でいうと

Volt Typhoon は、米国とその領土（グアムを含む）の重要インフラの IT 環境に長期間潜り込んでいる、中華人民共和国（PRC）を背景としたサイバー攻撃グループである [2]。CISA・NSA・FBI は、その標的選定と行動様式が従来のサイバースパイや情報収集とは一致しないとし、有事や重大な危機の際に OT（制御系）資産へ横展開して機能を妨害するための「事前配置（pre-positioning）」であると高い確度で評価している [2]。マルウェアをほとんど置かず、OS 標準の道具と正規の認証情報だけで動く living off the land（LOTL）を特徴とし、一部の被害組織では少なくとも5年にわたり検知されずに居座っていた痕跡が確認されている [2]。

素性

MITRE ATT&CK は Volt Typhoon を G1017 として登録し、「少なくとも2021年から活動している PRC の国家支援アクターで、主に米国とその領土（グアムを含む）の重要インフラ組織を標的とする」と記述している〔ATT&CK G1017〕。同記述は、標的選定と行動様式が OT 資産への横展開を可能にするための事前配置と評価されていること、ウェブシェル・LOTL バイナリ・手動操作（hands on keyboard）・窃取した認証情報を用いて隠密性を重視していることを挙げる〔同〕。

CISA の合同アドバイザリ AA24-038A は、別名として Vanguard Panda、BRONZE SILHOUETTE、Dev-0391、UNC3236、Voltzite、Insidious Taurus を併記している [2]。本記録の骨格が持つ台帳ではこれに DEV-0391・Storm-0391・DazedToad などを加えた12件を同一実体の候補として束ねている。なお ATT&CK の記述は、初期侵入を担う SYLVANITE という別クラスタの存在が報告されている点にも触れている〔ATT&CK G1017〕。

このアドバイザリは、米国の CISA・NSA・FBI に加え、DOE（エネルギー省）・EPA（環境保護庁）・TSA（運輸保安庁）、およびオーストラリア ACSC・カナダ CCCS・英国 NCSC・ニュージーランド NCSC-NZ の連名で出されている [2]。Five Eyes 全体が同じ評価に署名しているという点で、単独ベンダーの見立てとは重みが違う。

固有マルウェアと道具。Malpedia が Volt Typhoon への帰属を明示しているファミリは3つ——sh.kv（KV。SOHO ルータ／ファイアウォールに感染するボットネットのマルウェア）、win.scanline（ScanLine。Foundstone 製のコマンドラインポートスキャナ）、jar.versamem（VersaMem）である。ただし本記録が読めた資料で内容を確認できたのは KV [3][4] と ScanLine [1] の2つだけである。

重要なのは、このグループは自前のマルウェアをほとんど使わないという点である。CISA は「Volt Typhoon は侵害後の実行にマルウェアをほとんど使わない。代わりにコマンドラインからの手動操作と、システム上の正規ツール・プロセス（いわゆる LOLBins）を使う」と明記している [2]。CISA が検体として解析したのも、オープンソースのリバースプロキシ FRP（Fast Reverse Proxy）のクライアント2種と ScanLine という、いずれも公開ツールだった [1]。

これまでの活動

  1. 2022年2月
    KV-botnet の走査用クラスタ「JDY」がこの月まで遡る。Lumen は同クラスタで使われた自己署名 X.509 証明書（「BBC」）を2022年2月7日に初めて観測しており、KV-botnet というネットワーク自体が少なくとも2022年2月から稼働していたと評価している [4]。
  2. 2022年7月
    Lumen が、グアムの ISP の IP アドレスと大量データを送受信する NETGEAR ProSAFE ファイアウォールを初めて観測（7月12〜22日）。この ProSAFE は中継ノードとして働き、DrayTek ルータへとトンネルが連なっていた。Lumen はこれを Volt Typhoon が使う秘匿ネットワークの一つと評価した [4]。
  3. 2022年9月
    JDY クラスタが約1,350台のボットを追加してピークに達する。同クラスタは Cisco RV320／RV325 のみで構成され、月平均約800台を維持していた [4]。
  4. 2022年10月〜12月
    同じ手口がグアムの別の資産に対して観測される。通信事業者2社と ISP 1社の計3組織について、9つの IP のうち4つが中継ノードとして働いていた [4]。同年11月には KV クラスタが400台超を感染させた（通常は月100台未満）[4]。
  5. 2023年2月
    グアムの準州政府機関（territorial government entity）が同月を通じて侵害されていたことを Lumen が新たに検出 [4]。
  6. 2023年5月21日
    ペイロードサーバを新 IP（45.11.92[.]176）へ切り替え、NETGEAR ProSAFE に対する新たな感染波を実施 [4]。
  7. 2023年5月24日
    米政府機関・外国政府・Microsoft・Dell SecureWorks が Volt Typhoon／BRONZE SILHOUETTE の報告を一斉に公表 [4]。CISA も、当局が業界パートナーと共同で Volt Typhoon 帰属の活動を公表したのは2023年5月だとしている [2]。公表の直後、KV クラスタの運用は5月第3週から停止した [4]。
  8. 2023年8月〜11月
    8月に活動が再開。約100台を新たに感染させ、Volt Typhoon が過去に関心を示した業種の組織と接触した [4]。この時期、ProSAFE →カメルーンの Cisco RV320 という経路で、欧州の再生可能エネルギー企業のサーバ2台に3か月以上にわたる接続が張られていた [4]。
  9. 2023年9月
    上記カメルーンの Cisco ルータが、米軍関連組織の多数の IP アドレスを走査していたことを Lumen が観測 [4]。
  10. 2023年11月14日
    「BBC」x.509 証明書を「JDY」証明書に差し替え、インフラを再編（04:09:29 UTC）[3]。
  11. 2023年11月29〜30日
    Axis 製 IP カメラ（M1045-LW、M1065-LW、p1367-E 等）に対する最初の感染波。11月29日に約36 IP、11月30日に約232 IP [3][4]。ボットネットの構成に IP カメラという新しい機種が加わった瞬間である。
  12. 2023年12月5日
    NETGEAR ProSAFE に対する感染波（約171 IP）。同日、補助のコールバックサーバ（152.32.138[.]247）が最初の交信を行う [3]。
  13. 2023年12月6日
    FBI による KV-botnet 停止措置の最初の令状（#5432）が署名される [3]。
  14. 2023年12月8〜11日
    停止措置を察知した運用者が再感染を試みる。12月8日に8時間連続（約2,098 IP）、9日に10時間連続（約3,246 IP）、11日に1時間（約270 IP）。この4日間で3,045台の機器に接触し、内訳は NETGEAR ProSAFE 2,158台、Cisco RV320/325 310台、Axis IP カメラ29台、DrayTek Vigor 17台、不明531台だった [3]。これは当時世界中に存在した ProSAFE 6,613台の約32.63% にあたる [3]。
  15. 2023年12月12〜13日
    Lumen が KV クラスタのサーバ（45.11.92[.]176、193.36.119[.]48、216.128.180[.]232）とプロキシ／ペイロードサーバ（144.202.49[.]189、159.203.113[.]25、216.128.179[.]235）を null-route。12月13日に最初の KV-botnet 報告を公開 [3]。
  16. 2024年1月
    新規 C2 サーバの立ち上げは観測されず。JDY クラスタのボット数は約1,500台から約650台へ半減した。Lumen は1月8日と1月12日にも追加のインフラを null-route した [3]。
  17. 2024年1月31日
    米司法省（DOJ）が KV-botnet の停止措置を公表 [3]。
  18. 2024年2月7日
    CISA・NSA・FBI ほか計11機関が合同アドバイザリ AA24-038A を公表。同日、マルウェア解析報告 MAR-10448362-1.v1 も公表された [1][2]。
  19. 2024年3月7日
    AA24-038A の緩和策節が更新され、「メーカーのサポート期限を過ぎた技術の end of life 計画」の項目が追加された [2]。

手口

偵察（T1591 / T1590 / T1589 / T1592 / T1593 / T1594 / T1589.002）。侵害前に、標的組織・そのネットワーク・そこで働く人について徹底的に調べる。特にネットワーク管理者と IT 管理者が誰かを狙って、公開情報や被害組織自身のウェブサイトを探す [2]。業界レポートによれば FOFA・Shodan・Censys で露出資産を検索している [2]。侵害後には、こうして特定した鍵となる担当者の個人のメールアカウントを標的にした例が確認されている [2]。

インフラの調達（T1584.005 / T1584.004 / T1587.004）。C2 は多段プロキシで、VPS または SOHO ルータで構成される [2]。近年は Cisco と NETGEAR のサポート終了（end-of-life）SOHO ルータに KV Botnet マルウェアを植えて運用の土台にしていた [2]。KV-botnet は Lumen が2つのクラスタに分けて追跡したもので、走査・偵察を担う「JDY」（Cisco RV320/325 のみ）と、JDY が選んだ高価値標的に対して手動操作を行う「KV」に分かれる [4]。管理元の IP は PRC 国内にあり、活動時間帯は中国標準時の業務時間と一致していた [4]。侵害済みの機器を数珠つなぎにして秘匿の通信路を作るため、標的と同じ国・同じ都市の回線から出てくることになり、地理でのフィルタが効かない [4]。侵害環境の内部では、監視ツールである PRTG サーバを踏み台に仕立て直した例もある [2]。脆弱性は公開エクスプロイトを使う一方、自らゼロデイを見つけて突く能力もある [2]。

KV マルウェアの作り（sh.kv）。感染は多段で、まず bash スクリプト kv-all.sh が既存のセキュリティ製品（httpd_watchdog、Symantec の firewallsd）と他のボットネットのファイル（mips_ff）を消して回る——同居を避け、その機器を独占するためである [4]。次に機種に応じた kv-{architecture} を落とし、自プロセス名を [kworker/0:1] というカーネルスレッド風の名前に偽装する [4]。ARM・MIPS・MIPSEL・x86_64・i686・i486・i386 に対応する [4]。最終ペイロード（a.elf）は /proc/ にマウントバインドしたうえで /tmp のファイルを削除し、完全にメモリ上だけで動く [4]。プロセス名も、その機器に元からあるファイル名を無作為に一つ選んで名乗る [4]。30000番以上のポートを無作為に開き、iptables に自分で穴を開けてトンネルを張る [4]。C2 との通信は 0x16 で始まる TLS 風の独自プロトコルで、RSA 公開鍵の検証とチェックサムを伴う [4]。この設計の代償として永続化機構を持たない——機器の電源を入れ直すだけでマルウェアは消え、攻撃者は再度侵入し直さなければならない [3]。

初期侵入（T1190 / T1133）。Fortinet、Ivanti Connect Secure（旧 Pulse Secure）、NETGEAR、Citrix、Cisco といったネットワーク機器の脆弱性を突くのが常道である [2]。確認された侵害の一つでは、未パッチの FortiGate 300D の CVE-2022-42475 を突いたとみられ、SSL-VPN のクラッシュログにバッファオーバーフローの痕跡が残っていた [2]。Fortinet は別途、Volt Typhoon が CVE-2022-27997 経由で一部のネットワークへ侵入したことを認めている [4]。侵入後は VPN セッションで接続し、通常のトラフィックに紛れる [2]。

認証情報（T1068 / T1552 / T1003.003 / T1003.001 / T1555.003 / T1552.004）。まず公開側の機器から認証情報を取る。OS やネットワークサービスの権限昇格の脆弱性を突き、機器上に不適切に保管された認証情報を拾う [2]。前述の Fortinet の事例では、機器に置かれていたドメイン管理者アカウントが奪われた [2]。次にドメインコントローラへ移り、Active Directory のデータベース NTDS.dit を抜く。手順は、①ドメイン管理者権限の窃取アカウントで RDP 接続、②Windows 標準の vssadmin でボリュームシャドウコピーを作成（T1006）、③WMIC 経由で ntdsutil を実行しシャドウコピーから NTDS.dit と SYSTEM レジストリハイブをコピー、④持ち出してオフラインでハッシュを解読、である [2]。comsvcs.dll の古い版を非標準フォルダに落とし、MiniDump と LSASS のプロセス ID を組み合わせて LSASS のメモリを吸い出した例もある [2]。Mimikatz の使用は当局が、Impacket の使用は業界パートナーが観測している [2]。ドメイン管理者のブラウザも狙う。Chrome の History を History.zip として Downloads に置いて持ち出し、その約4か月後に同じ利用者の Local State（保存パスワードを復号する AES 鍵）と Login Data へ SMB でアクセスした例が記録されている [2]。

探索（T1654 / T1057 / T1087.001 / T1010 / T1083 / T1012 / T1046 / T1016.001 / T1007 / T1033 / T1069 / T1120 / T1124 / T1518 / T1614 / T1217）。使う道具は cmd・certutil・dnscmd・ldifde・makecab・net・netsh・nltest・netstat・ntdsutil・ping・PowerShell・quser・reg・systeminfo・tasklist・wevtutil・whoami・wmic・xcopy——すべて Windows 標準である [2]。特徴的なのはイベントログの読み方で、Get-EventLog security -instanceid 4624 -after [日付] | fl * | Out-File 'C:\users\public\documents\user.dat' のように、ログオン成功（イベント ID 4624）だけを期間と利用者で絞って .dat ファイルへ抜き出す [2]。全ドメインコントローラを回ってローカルログオン（種別2）とリモートログオン（種別10）を仕分ける PowerShell スクリプト logins.ps1 も押収されている [2]。ドメインコントローラの C:\Windows\System32\ に rult3uil.log というファイルを作り、Chrome と PowerShell のウィンドウタイトル・フォーカス移動・打鍵・実行コマンドを時刻つきで記録していた例もある [2]。ファイル探索では、脆弱性診断関連の資料や施設データ（建築図面を含む）のディレクトリを列挙していた [2]。

横展開（T1021.001）。窃取した管理者資格情報での RDP が主である [2]。上下水道分野のある事例では、VPN で入ったのち9か月かけてファイルサーバ、ドメインコントローラ、Oracle Management Server、VMware vCenter へと渡り歩いた [2]。vCenter への移動は OT への事前配置として戦略的だったと CISA は評価する——攻撃者はそのサーバ上の PuTTY の保存済みセッションを列挙しており、浄水場・井戸・変電所・OT システム・ネットワークセキュリティ機器への接続情報に手が届く位置にいた [2]。別の事例では、ドメイン参加している OT 資産に対してOT ベンダーの初期パスワードでアクセスを試していた [2]。ある確認済みの侵害では、実際に制御系システムまで横展開し、二つ目の制御系へ移れる位置にいた [2]。

収集と持ち出し（T1074 / T1560.001 / T1113）。CISA は「Volt Typhoon が主に集めるのは、物理的な影響を伴う後続行動を可能にする情報である」と評価する [2]。ある事例では、SCADA・保護リレー・開閉装置に関する図面と文書をファイルサーバから複数の zip にまとめ、SMB 経由で持ち出したとみられる [2]。別の事例では WMIC で一時ディレクトリ（C:\Users\Public\pro など）を作って ntds.dit とレジストリハイブを集積し、rar.exe をリネームしたとみられる ronf.exe で圧縮している [2]。

C2（T1090 / T1090.001 / T1090.003 / T1105 / T1573.001）。侵害済み SOHO ルータと VPS で多段プロキシを組むほか、被害組織のインフラ内に FRP クライアントを植えてリバースプロキシを張る [2]。Shortel の ECC サーバに SMSvcService.exe、別のサーバに Brightmetricagent.exe を置き、PowerShell から実行した例が記録されている [2]。同じ侵害では PRTG サーバ上で netsh によるレジストリの PortProxy 設定（T1112）を作り、特定ポートの通信を自らのプロキシ基盤へ転送させていた [2]。KV-botnet 側では、JDY のプロキシサーバが公開 Tor エントリノードと大量のデータをやり取りしており、真の C2 は Tor 秘匿サービスの背後にあるとみられる [4]。

隠蔽（T1027.002 / T1036.005 / T1070.004 / T1218 / T1078）。FRP クライアント2種と ScanLine はいずれも UPX で圧縮されている [2]。Windows イベントログ・システムログを選択的に消し、ファイル名を偽装する [2]。C:\Users\Public\Documents に作った systeminfo.dat を後から削除した痕跡が残っている [2]。永続化はマルウェアではなく正規の認証情報に依存する（T1078）[2]。運用上の隠蔽も徹底しており、通常の業務時間外には窃取した資格情報を使わなかった例が観測されている——異常なアカウント活動としてのアラートを避けるためである [2]。

居座り方。侵入後の活動量は意図的に少ない。CISA は「正規アカウントを得たあと、（探索を除いて）環境内でほとんど活動しない。目的は即時の悪用ではなく永続化にあることを示唆する」と述べる [2]。ある侵害では4年間で3台のドメインコントローラから NTDS.dit を抜いており、別の侵害では9か月間に2回抜いていた [2]。資格情報が失効しても次があるよう、定期的に取り直しているということである。

実被害（リークサイト掲載） — 該当なし。骨格に日本の実被害の記載は無い。そもそもランサムウェアのリークサイトに載る種類のアクターではない。

公開情報（本記録が読んだ資料） — 日本の名指しは無い。 AA24-038A が確認したと述べる被害は米国本土・非本土および領土（グアムを含む）に限られ、業種は通信・エネルギー・輸送・上下水道である [2]。同アドバイザリで日本以外の国について言及があるのは連名機関の側で、カナダ CCCS は「カナダの重要インフラへの直接的な脅威は米国より低いと思われるが、米国のインフラが停止すればカナダも影響を受ける可能性が高い」、豪 ACSC とニュージーランド NCSC-NZ は「自国の重要インフラも同種の活動に対して脆弱でありうる」と述べている [2]。Lumen は KV クラスタの被害者像について「インド太平洋地域への戦略的関心と一致し、特に ISP と政府機関に焦点がある」と評価しているが [4]、これは地域についての記載であって、日本を名指ししたものではない。読んだ4本のいずれにも日本の組織を標的としたという記述は無い。

自前の観測 — 骨格に観測層の記載は無い。本記録は自前の観測を根拠にしていない。

人手（台帳 config/japan_watchlist.yaml） — 台帳は Volt Typhoon を定点観測の対象として登録している。理由は「重要インフラへの長期潜伏（事前配置）を米 CISA らが警告。日本国内での観測は公表されていないが、台湾有事の兵站という観点で通信・電力・輸送が同種の対象になりうると指摘されている」であり、日本での観測は未確認と明記されている。台帳自身が「日本での観測は無い。推論として追う対象であり、事実と混同しない」と注記している。これは人の判断による登録であって、資料が日本標的を示したものではない。

最近の動き

公開されている資料は2024年3月までで、それ以降の動きは確認できていない。 本記録が本文を読めた資料は4本で、最も新しいのは2024年2月7日公表・同年3月7日更新の合同アドバイザリ AA24-038A である [2]。Lumen の追跡も2024年1月時点の状況で終わっている [3]。

したがって現時点で確認できる最後の姿は次の通りである。KV-botnet の主力である KV クラスタは、FBI の令状に基づく停止措置と Lumen による null-route の結果、Lumen の評価では「もはや実質的に稼働していない」[3]。JDY クラスタはボット数を半減させながらも稼働を続けていた [3]。Fortinet クラスタの活動は2023年8月ごろに消滅したと評価されている [3]。ただし Lumen は同時に、「侵害したファイアウォールとルータの利用は、今後も攻撃者の運用の中核として現れ続ける」とも述べており、KV-botnet の停止はインフラの一つが潰れたことを意味するにすぎない [3]。Volt Typhoon 自身についても Lumen は「KV クラスタの利用者の少なくとも一つが Volt Typhoon だが、Volt Typhoon は他の秘匿ネットワークも使っていると考えられる」としている [4]。

なお本記録の骨格（機械抽出）には、Versa Director Zero Day Exploitation（2024年6月〜8月） という作戦と、それに対応する固有ファミリ jar.versamem（VersaMem）が記録されている。しかし対応する一次資料（資料 [5]）は本文の取得に失敗しており、内容を確認できていない。この作戦について本記録は何も述べない。

ここから先は本記録の評価です。上の各節は公開資料に基づく事実で、以下は解釈と推論を含みます。

何が変わったか

ここからは本記録の評価です。

「スパイ」という枠から外れた。 これが最大の変化である。CISA は明確に「標的選定と行動様式が従来のサイバースパイや情報収集と一致しない」と述べ、目的を事前配置と断じた [2]。証拠は消極的なものの積み重ねである——資格情報を抜いたあと静かになる、データを持ち出さない、探索だけを繰り返す、同じ組織を何年もかけて再訪する [2]。だが持ち出したものを見ると積極的な証拠になる。SCADA の図面、保護リレーと開閉装置の資料、建築図面、浄水場と変電所の PuTTY プロファイル [2]。これは「相手を知る」ための資料ではなく「相手を止める」ための資料である。

インフラの追い方が、攻撃者の追い方から独立した。 Lumen の2本 [3][4] が示したのは、Volt Typhoon そのものではなく彼らが乗っている土台を追う手法である。ProSAFE の x.509 証明書の差し替えを追い、活動時間帯のヒートマップを中国標準時にずらして見て、Tor エントリノードへの大量転送から真の C2 の存在を推測する。攻撃者が LOTL で端末側に痕跡を残さないなら、残るのは経路側だけだ、という筋である。

停止措置の効き方が測られた。 FBI の令状に基づく駆除と Lumen の null-route が組み合わさった結果として、KV クラスタは死に、JDY は半減した [3]。同時に、攻撃者の反応も測られた——12月8〜11日の再感染の試みで、彼らは世界中の ProSAFE の32.63% に手を伸ばした [3]。この数字は、彼らがどれだけ即座に、どれだけ広く動けるかの実測値である。そして KV マルウェアが永続化を持たない設計だったこと [3] は、彼らが「再感染し直せばよい」と考えていた証拠でもある。

IOC で捕まえる前提が崩れた。 CISA 自身が「この種の悪意ある活動に伴う通常の IOC は概して存在せず、ネットワーク防御者が識別・追跡・分類する努力を難しくしている」と書いている [2]。だから同アドバイザリの検知節は、ハッシュや IP ではなく ESENT アプリケーションログのイベント ID 216・325・326・327・637（NTDS.dit の異常な取り扱い）、セキュリティログ 1102（ログ消去）、ターミナルサービスの 21〜25、システムログ 1017 といった、振る舞いの副作用を並べる構成になっている [2]。

日本の組織にとっての含意

ここからも評価である。まず前提を確認する。読んだ資料に日本の名指しは無い。 以下は「日本が狙われている」という主張ではなく、「同じ手口が日本の同種の資産に対して成立するか」という問いへの答えである。

成立する条件はすべて日本にも揃っている。 侵入口は Fortinet・Ivanti・Citrix・Cisco・NETGEAR の公開機器 [2]。これらは日本の重要インフラ事業者でも普通に使われている。機器上にドメイン管理者の資格情報を置いてしまう運用 [2]、サポート終了機器を回線の端に置き続ける状態 [3][4]、IT と OT の境界に vCenter や監視サーバが座っている構成 [2]——どれも日本固有の事情ではない。

「地理で守る」が効かない。 KV-botnet の設計思想は、標的と同じ国・同じ都市の家庭用ルータから出てくることで地理フィルタを無効化することだった [4]。日本の組織が「海外からのアクセスを弾く」だけの対策を取っているなら、それは初めから設計上の対象外である。同時に、日本国内の家庭・小規模事業所のサポート終了ルータが、他国の組織を攻撃するための踏み台になりうることも意味する。これは被害の話ではなく加害インフラの話であり、通信事業者側の問題として別に立てる価値がある。

検知の設計が問われる。 マルウェアが置かれないなら、EDR のシグネチャは当たらない。CISA が求めているのは、①アプリケーションイベントログを長期に残して ESENT の異常を見ること、②正規ツールの「正常な使われ方」のベースラインを持つこと、③IT と OT の間の通信経路のログを取り異常を見ること、である [2]。①は特に重要で、セキュリティログより長く端末に残るためだ、と CISA は理由まで書いている——滞留期間が5年に及ぶ相手には、ログの保存期間そのものが検知能力である [2]。

「侵害されたら全ドメイン侵害とみなせ」。 CISA のインシデント対応節は、Volt Typhoon の痕跡を見つけたら NTDS.dit が抜かれた前提で動け、と指示する [2]。krbtgt を（履歴が2つあるので）2回リセットする、全ドメイン利用者と全ローカルアカウントのパスワードを変える、といった手順は、平時に手順書へ落として演習しておかないと当日には実行できない [2]。

経営層への説明のしかたが変わる。 「情報が盗まれる」ではなく「有事に止められる準備をされる」というリスクは、期待損失の計算になじまない。CISA の評価が「重大な危機や紛争の際の妨害」を条件にしている以上 [2]、これは地政学の変数と結びついた条件付きリスクである。日本の重要インフラ事業者にとっては、平時のインシデント件数では正当化できない投資を、条件付きリスクの側から正当化するという説明が要る。

取るべき防御

以下はすべて AA24-038A の緩和策から、日本の組織にとって優先度が高いと本記録が判断したものである [2]。冒頭で CISA が「今日やること」として挙げているのは4項目——公開機器へのパッチ適用、フィッシング耐性のある MFA、アプリケーション・アクセス・セキュリティのログを有効にし中央に集約、サポート期限切れ技術の end of life 計画——である [2]。

攻撃面を減らす
- 公開機器のパッチを、リスクに応じた期限内に当てる。特に Volt Typhoon が頻繁に突く Fortinet・Ivanti・NETGEAR・Citrix・Cisco の機器と、既知の悪用脆弱性を優先する [2]。
- 不要な管理インターフェースをインターネットに出さない [2]。
- IT 資産の目録を維持し、そこからメーカーのサポート期限を過ぎた機器を特定する。置き換えられないなら、追加の監視・設定変更・隔離・分割で補う [2]。

資格情報を守る
- エッジ機器に資格情報を置かない。 特にドメイン管理者権限に届くアカウントを機器上に持たせない [2]。これは Volt Typhoon が実際に成功した経路そのものである。
- 平文の資格情報をどのシステムにも置かない [2]。既定パスワードを変える [2]。
- グループポリシーでブラウザのパスワード保存と自動入力を無効にする [2]。ブラウザの保存パスワードは実際に狙われている [2]。
- LSASS メモリへの平文パスワード保存を無効にする [2]。

アカウントを守る
- 資産へのアクセスにフィッシング耐性のある MFA を実装する [2]。
- 利用者アカウントと特権アカウントを分ける。管理者アカウントでメールやウェブ閲覧をしない [2]。
- Enterprise Admins・Schema Admins から常設のアカウントを外し、必要なときだけ監査つきで戻す [2]。
- AD の階層モデル（tiering）を導入し、管理作業は階層に応じて堅牢化した端末からのみ行う [2]。

リモートアクセスと分割
- RDP の利用を制限し、必要な場合は棚卸し・未使用ポートの閉鎖・ログオン試行の記録を行う [2]。
- IT と OT を分割し、既定で OT への接続をすべて拒否したうえで、必要な経路だけをファイアウォール・踏み台・DMZ といった仲介を通す [2]。
- OT ネットワークへの全接続を、不正利用・異常・OT プロトコルの観点で常時監視する [2]。

備える
- ログを有効にし中央（SIEM 等）へ集約する。Volt Typhoon の LOTL と長い滞留を踏まえると、アプリケーションイベントログは特に価値が高い——端末上に比較的長く残るためである [2]。OT 資産でログが非標準または取れない場合は、その資産と他資産の間の通信を取る [2]。
- インストール済みツール・ソフトウェア、アカウントの振る舞い、ネットワークトラフィックのベースラインを作り維持する。LOTL の検知はここに依存する [2]。
- IT 担当者・管理者向けの訓練で、Volt Typhoon が IT スタッフの個人メールを狙うことを具体的に伝える [2]。
- 制御系を運用・防護する要員には、年1回以上の OT 固有のセキュリティ訓練を行う [2]。
- IT／OT を失った場合にどう運転を続けるかのレジリエンス計画を作り、手動制御を定期的に試す [2]。

探す
- ESENT アプリケーションログのイベント ID 216・325・326・327・637 を見る（NTDS.dit のシャドウコピー経由の複製・一時ディレクトリでの生成）[2]。
- セキュリティログの 1102（ログ消去）はすべて調査する。CISA は「ログは通常消されないうえ、これは Volt Typhoon の既知の手口である」と明記している [2]。
- C:\Windows\Temp\ と C:\Users\Public\ を、本来 System32 にあるはずのファイル（例：comsvcs.dll）の観点で見る [2]。
- VPN 等のログオンについて、時刻・頻度・継続時間・地理の不可能移動を見る [2]。
- IT と OT の間の通信経路のアクセスログを、異常なアクセスやプロトコルの観点で見る [2]。

分からないこと

  1. 日本での観測の有無。読んだ資料に日本の名指しは無く、日本国内での観測も公表されていない。「日本では起きていない」のか「起きているが公表されていない／気づかれていない」のかは、公開情報では区別できない。滞留が5年に及ぶ相手 [2] であることを踏まえると、この区別は重要だが埋まらない。

  2. 2024年3月以降の動き。本記録が読めた最新の資料は AA24-038A（2024年2月7日公表・3月7日更新）である [2]。それ以降に Volt Typhoon がどう再編したか、KV-botnet 以外のどの秘匿ネットワークへ移ったかは確認できていない。Lumen 自身が「Volt Typhoon は他の秘匿ネットワークも使っていると考えられる」と述べており [4]、KV-botnet の停止が全体の停止でないことだけが分かっている。

  3. Versa Director ゼロデイ悪用作戦（2024年6〜8月）と VersaMem の中身。骨格には作戦名と固有ファミリ jar.versamem が記録されているが、対応する一次資料の本文が取得できず、何が起きたのか確認できていない。

  4. 初期侵入の全体像。CISA は Fortinet・Ivanti・NETGEAR・Citrix・Cisco を挙げ、確認できた具体例として CVE-2022-42475 と CVE-2022-27997 の2件を示すのみである [2][4]。ゼロデイを自ら見つけて突く能力があるとされているが [2]、どの脆弱性がいつゼロデイとして使われたかは公開されていない。KV-botnet 側でも、Lumen は感染チェーンの第1〜3段階は特定したが最初の侵入手段そのものは未解明だと明言している [4]。

  5. 背後の組織。CISA は「PRC の国家支援アクター」とするだけで、どの機関（MSS か PLA か、あるいは契約企業か）かには踏み込んでいない [2]。Lumen が示したのは PRC 国内の管理元 IP と中国標準時の業務時間という状況証拠にとどまる [4]。ATT&CK が言及する SYLVANITE という初期侵入クラスタとの関係も、読んだ資料からは追えない。

  6. どこまで OT に到達したか。CISA は「ある確認済みの侵害では制御系システムまで横展開し、二つ目の制御系へ移れる位置にいた」と述べる [2]。しかし何件の組織で OT に到達したのか、到達していながら気づかれていない事例がどれだけあるのかは公開されていない。「機能を止める能力を持っていた」と「止める準備が完了していた」の距離も、公開情報では測れない。

  7. KV-botnet の運用者と Volt Typhoon の関係。Lumen は KV クラスタの利用者の少なくとも一つが Volt Typhoon だとする一方 [4]、Fortinet 機器に対する活動については「これらのネットワークは Volt Typhoon の被害者像と一致しない」として、KV の運用者が Volt Typhoon 以外の中国系クラスタにもアクセスを提供している可能性を挙げている [4]。運用者と利用者が同一なのか別なのかは決着していない。

MITRE ATT&CKVolt Typhoon は中華人民共和国（PRC）の国家支援を受けた主体で、遅くとも 2021 年から活動し、主に米国およびグアムを含む米国領の重要インフラ組織を標的としている。Volt Typhoon の標的選定と行動様式は、破壊的・妨害的な攻撃を将来行いうるよう、運用技術（OT）資産への横展開を可能にするための事前配置であると評価されている。Volt Typhoon は作戦上の隠密性を重視し、Web シェル、環境寄生（LOTL）バイナリ、手動操作による活動、窃取した認証情報を用いている。同グループは侵害した SOHO ルータを使ってコマンド＆コントロール通信を中継し、自らのインフラを隠蔽している。これは KV ボットネットに関連する活動である。報告によれば、これとは別の初期アクセスのクラスタ SYLVANITE が、インターネットに面したエッジ機器を悪用し、得たアクセスを VOLTZITE とも呼ばれる Volt Typhoon に引き渡して後続の作戦につなげているところが観測されている。
