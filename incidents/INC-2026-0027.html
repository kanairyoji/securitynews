Clopがインターネット公開のPTC Windchill/FlexPLM（CVE-2026-12569）を悪用し新規43組織を掲載——Shell・GE・Philipsが調査、製造・防衛・医療の設計データを二重恐喝

脅威・攻撃キャンペーン脆弱性続報が続いている有名事象として記録（日本と直接の関係は薄い）既知の脆弱性の悪用脆弱性の放置
初報: 2026年8月17日 最終更新: 2026年8月21日

2026年8月17日、ランサムウェアグループ Clop（Cl0p）が、製品ライフサイクル管理（PLM）製品
「PTC Windchill」および「PTC FlexPLM」の重大な脆弱性 CVE-2026-12569（不正な入力検証／
信頼できないデータのデシリアライズによる認証不要のリモートコード実行、CVSS 9.3）を悪用し、
新たに43組織をリークサイトに掲載しました。掲載先には石油大手 Shell、General Electric（GE）、
Philips が含まれ、Shell は89GB窃取の主張を調査中、Philips は「特定のエンタープライズ
サーバーへの侵害を封じ込め済みで顧客環境に影響なし」と表明、GE は評価中としています。
攻撃はインターネットに露出した Windchill/FlexPLM に対し、FlexPLM の WSDL エンドポイントの
情報漏洩と Windchill ログインサーブレットの欠陥を連鎖させて認証なしでコードを実行し、
16進名の JSP Web シェルを設置して設計図面・バックアップ等を窃取するものです。PTC は
2026年6月17日にパッチ提供を開始、6月25日には CISA が KEV に追加して連邦機関に3日以内の
対応を義務付け、独 BSI も緊急警告を出しました。PTC 製品は航空宇宙・防衛・自動車・重機・
医療機器など3万超の顧客が利用し、日本の製造業でも Windchill 利用が多いため、公開資産の
即時確認が必要です。8月18日に ReliaQuest が Web シェルの解析を公表し、Windchill の
キーストア内の全認証情報を復号する機能・メモリ内で任意の Java コードを実行するクラスローダー・
独自 HTTP ヘッダによるコマンド指定など、Windchill 専用に作り込まれた「恐喝プラットフォーム」の
全容と IOC（ハッシュ・IP・ヘッダ名）が示されました。パッチ適用だけでは不十分で、キーストアに
入っていた認証情報（LDAP 管理者を含む）の全ローテーションが点検範囲に入ります。ここでは、
公表・報道から確認できた範囲を、観測事実と本記録の評価を分けて整理します。

攻撃の経過

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

Clop は、インターネットに露出した PTC Windchill / FlexPLM に対し、FlexPLM の WSDL エンドポイントの事前認証情報漏洩と Windchill ログインサーブレットの欠陥（CVE-2026-12569）を 連鎖させて認証不要のリモートコード実行を成立させ、`/Windchill/login/` 配下に16進名の JSP Web シェルを設置した。以降、`flst.txt` によるファイル一覧化などの内部探索を経て、 バックアップ・設計図面・製造データをステージングして窃取し、リークサイト掲載による 二重恐喝を行っている。各被害組織の侵害・窃取の確定状況は組織ごとに異なる。

  1. 1. 初期侵入公表・報道に基づく[1] [3]
    インターネットに露出した Windchill / FlexPLM に対し、FlexPLM の WSDL エンドポイントの 事前認証情報漏洩と Windchill ログインサーブレットの欠陥を連鎖させ、認証なしで リモートコード実行を成立させた（CVE-2026-12569、CVSS 9.3）。
    根拠: The Hacker News・BleepingComputer の報道、Ransom-ISAC/ReliaQuest の確認
  2. 2. 永続化公表・報道に基づく[1] [3] [8]
    悪用後、`/Windchill/login/` 配下に16進名の JSP Web シェル （例: `[0-9a-f]{16}.jsp`）を設置し、恒常的なアクセス手段を確保した。
    根拠: Ransom-ISAC/ReliaQuest の確認、The Hacker News の IOC 記述
  3. 3. 認証情報アクセス公表・報道に基づく[5] [6] [8]
    ReliaQuest によれば、Web シェルの `S` コマンドは内部関数 `gs` で `ieStructProperties.txt` を 読み、キーストアから LDAP 管理者パスワードを復号したうえで、管理者アカウント・オブジェクト ストレージ認証情報・サイト管理者キーを順次復号して平文で返す。LDAP 管理者の認証情報は 企業ディレクトリ全体への到達を許しうる。復号は Windchill 既存の DB 接続とクラスを使って 行われ、別途の攻撃者アカウントを作らない。
    根拠: ReliaQuest のブログ（2026年8月18日）および SecurityWeek/CyberScoop（8月19日）の報道
  4. 4. 収集公表・報道に基づく[1]
    `flst.txt` によるファイル一覧化などの内部探索を経て、バックアップ・プロジェクト計画・ 図面・設計図・施設写真などをステージングした。
    根拠: BleepingComputer（Clop の窃取主張）、Ransom-ISAC の post-exploitation 記述
  5. 5. 実行公表・報道に基づく[8] [9]
    ReliaQuest によれば、`J` コマンドは Base64 エンコードされた ZIP 内のコンパイル済み Java バイトコードを受け取り、ディスクに書かずにメモリ上へロードして実行する。追加マルウェア・ ネットワーク伝播ツール・標的型エクスプロイト・暗号化ペイロードの投入に使えるとされる。
    根拠: ReliaQuest のブログ（2026年8月18日）
  6. 6. C2通信公表・報道に基づく[8] [9]
    Web シェルへの指示は独自 HTTP ヘッダ `X-windchill-req`（8文字、先頭1文字がコマンド）で 与えられ、応答は GZIP 圧縮される。ReliaQuest は関連 IP アドレス7件を公開した。
    根拠: ReliaQuest のブログ（2026年8月18日）、BleepingComputer（8月18日）
  7. 7. 持ち出し公表・報道に基づく[1]
    ステージングされたデータが外部へ持ち出された。Clop は Shell から89GB を窃取したと 主張し、掲載43組織全体で図面・設計図等を窃取したとしている。
    根拠: BleepingComputer（Clop の主張）
  8. 8. 影響（暗号化・破壊・改ざん）公表・報道に基づく[1]
    Clop はリークサイトに被害組織を掲載して二重恐喝（データ窃取＋公開の脅迫）を行っている。 暗号化の有無は本記録が参照した報道では明示されていない。
    根拠: BleepingComputer（リークサイト掲載）
公表されていない攻撃段階2
  • 権限昇格 / 横展開
    Web シェル設置後の権限昇格・横展開の詳細は、本記録が参照した報道の範囲では個別に 示されていない。ReliaQuest は復号された LDAP 認証情報が企業全体の侵害につながりうると 指摘するが、各被害組織での内部での動きは公表されていない。
  • 検知回避
    Web シェルが Windchill 既存の DB 接続・クラスで動作し GZIP 応答と独自ヘッダを使う設計は ReliaQuest が示したが、ログ消去等の積極的な痕跡隠蔽の有無は示されていない。

Clopが新規43組織を掲載し、Shell・GE・Philipsが調査・封じ込めを表明した概観出典 [1]

BleepingComputer（2026年8月17日）によれば、ランサムウェアグループ Clop がリークサイトに
新規43組織を掲載し、そこに石油大手 Shell、General Electric（GE）、医療機器大手 Philips が
含まれた。Clop はこれらの企業から、バックアップ・プロジェクト計画・施設写真・図面・
設計図（blueprints）などの機微データを窃取したと主張している。

各社の反応は分かれている。Philips は Reuters に対し「内部データに関する特定の
エンタープライズサーバーへのサイバー侵害の試みを特定し封じ込めた。顧客環境への影響はない」
と表明した。Shell は「潜在的なインシデントを認識しており、セキュリティチームおよび
関連する専門家とともに調査している」とし、Clop の89GB 窃取の主張を調査中とした。
GE の広報担当は「主張を認識しており、潜在的な問題の評価に取り組んでいる」とコメントした。

掲載は Clop の「窃取した」という主張の段階であり、各組織の侵害・窃取の事実が確定した
ことを意味しない。Philips のように顧客影響を否定する組織も含まれる点に留意が必要である。

不正な入力検証と信頼できないデータのデシリアライズにより、リモートの認証されていない
攻撃者が悪意あるリクエストで任意コードを実行できるものである。

報道・分析によれば、攻撃者は FlexPLM の WSDL エンドポイントにおける事前認証の情報漏洩と、
Windchill のログインサーブレットのサーバーサイドの欠陥を連鎖させることで、認証なしの
リモートコード実行を成立させる。悪用後は /Windchill/login/ 配下に16進名の JSP Web シェル

内部探索を経て、設計・製造データをステージングして窃取するとされる。

Oracle EBS と、企業向けのファイル共有・業務プラットフォームの脆弱性を連続的に悪用してきた。

campaign である。

続報——Clopは8月12日から実名掲載へ切り替えて40組織超を公表し、Windchill専用の「全量窃取」カスタムインプラントの使用が判明した波及・関係先出典 [5] [6]

2026年8月19日の SecurityWeek・CyberScoop の報道により、campaign の全体像が更新された。

第一に、掲載の進展。Clop は当初リークサイトに部分的な組織名のみを掲載していたが、
8月12日からフルネーム（完全な組織名）の公表に切り替え、8月19日までに40組織超が
実名で掲載された。実名が報じられた組織には、Shell・Philips・GE に加え、フィンテック
大手 Fiserv、Zebra Technologies、産業機器の Ingersoll Rand、POS の Toast、医療機器の
Mindray、Apple 向けカメラレンズ供給大手の Largan Precision が含まれる。Clop は組織
ごとに窃取したと主張するデータの種類（データベース・プロジェクトファイル・
バックアップ・写真・設計文書・設計図・図面・ログ等）と量（1GB〜数TB）を掲載している。
Toast と Zebra は CyberScoop に対し侵入の検知・封じ込めと影響の限定を表明し、
Shell・Philips・Fiserv・GE は「主張を認識し調査中」としつつ重大な侵害は確認していない
とする。GE は掲載後にリークサイトから削除されており、SecurityWeek は身代金の支払い
または交渉再開を示唆する可能性があると指摘する（確認された事実ではない）。

第二に、手口の解像度。ReliaQuest によれば、Clop が使用した Web シェルは Windchill
専用に作り込まれたカスタムインプラントで、機微な vault データをマッピングし、
Windchill キーストア内のすべての認証情報を復号し、独自の Java クラスローダーにより
アプリケーションプロセス内で任意の追加コードを実行できる。手動のコマンド実行なしに
初期アクセスからデータ窃取・後続活動（横展開・ランサムウェア・永続化）まで進める
恐喝プラットフォームであり、Windchill の標準機能を模倣することで検知を困難にしている。

第三に、時系列の遡及。Ransom-ISAC の分析では、一部の被害組織はパッチ提供前の
6月上旬にゼロデイ悪用で侵害されていた可能性が高く、Clop は7月中旬から被害組織への
脅迫メール送付を始めていた。つまり「6月17日のパッチ即時適用」でも間に合わなかった
組織がありえ、パッチ適用と侵害痕跡調査を1組で行う必要性がさらに強まった。
なお PTC は、脆弱性をどのように認知したか・最初の悪用時期・侵害された顧客数を
公表しておらず、CyberScoop のコメント要請にも応じていない。

続報（8月21日）——ReliaQuestの一次分析でWebシェルの8コマンドとIOCが公開され、「パッチ適用＋キーストア内の全認証情報ローテーション」が点検範囲になった対策・注意喚起出典 [7] [8] [9] [10]

2026年8月18日に ReliaQuest が公表した解析（著者は同社 Threat Research Team の John Dilgen・
Connor Short）は、8月19日の報道で概要のみ伝えられていた Web シェルの内部構造を示した。

第一に、コマンド体系。Web シェルは独自の HTTP ヘッダ X-windchill-req（8文字、先頭1文字で
コマンドを指定）でリクエストを受け取り、8つのコマンドを持つ。S（LDAP パスワードおよび
暗号化されたアプリケーションデータの復号）、L（Windchill のファイル vault のマッピング。
結果を flst.txt に出力）、D（ディレクトリ列挙・ファイルの部分取得）、G（ファイル全体の
読み出し）、R（ファイル削除）、J（Base64 エンコードされた ZIP 内の Java バイトコードを
メモリ上にロードして実行）、O（OS 判別）、E（応答確認）である。S コマンドは内部関数 gs で
ieStructProperties.txt を読み、キーストアから LDAP 管理者パスワードを復号し、管理者アカウント・
オブジェクトストレージ認証情報・サイト管理者キーを順次復号して平文で返す。

第二に、検知を困難にする設計。クエリは Windchill 既存のデータベース接続（アプリケーションの
DB 上の身元）で実行され、別途の攻撃者アカウントを作らない。応答は GZIP 圧縮され、独自ヘッダと
合わせて通常の Windchill トラフィックに紛れる。ReliaQuest は、ヘッダのログ記録・応答の展開・
TLS 検査がなければ可視化できないと指摘する。

第三に、IOC と帰属。ReliaQuest はファイルハッシュ
321e1fb01eb3462b48ff6ccdef132acc1182e3f7456548439f0d4ead12fd98bf、関連 IP アドレス7件、
windchill/codebase/login 配下の不審な JSP、MethodContext・WTConnection・WTKeyStoreUtil
クラスへの参照、codebase ディレクトリの最近の更新時刻を検知の手がかりとして挙げた。帰属は、
脅迫メールの連絡先が Clop のリークサイト上のものと一致すること、X-windchill-req ヘッダが
外部報告で Clop に紐づけられていたこと、DEWMODE（Accellion FTA）・LEMURLOOT（MOVEit）に続く
「大量悪用→専用 Web シェル」のパターンに合致することから「高い可能性で Clop」と評価している。
なお、このハッシュは The Hacker News（6月25日）が示した既知ハッシュ 55a1eb4c… と異なり、
両者の関係（別検体か、別段階のファイルか）は本記録の参照範囲では確認できない。

第四に、推奨対応。ReliaQuest は、CVE-2026-12569 の修正適用に加え、codebase 配下の最近の
タイムスタンプを持つ JSP の探索、侵害が疑われるサーバーでの LDAP および Windchill 管理者
認証情報のローテーション、管理インターフェースのインターネット露出の制限、WAF の配備を即時対応
として挙げ、露出した認証情報が再利用されている下流システムでのローテーション・セッション失効・
アカウント停止を運用対応として挙げている。また公開エクスプロイトの出現に伴い模倣アクターが
本脆弱性を採用する可能性を「中程度の確度」とし、支払わない組織へはより深いネットワーク侵入の
後続攻撃が予想されるとした。

報道面では、Security Affairs（8月21日）がドイツ警察が組織に直接攻撃を警告していたと伝えている
（「reportedly」付きで、警察の公表は本記録の参照範囲では確認できない）。Shell については、
Clop が主張する89GB の内訳が技術図面・施設点検報告のスキャン・写真・プロジェクト文書であると
報じられ、Shell は「潜在的なインシデントを認識しており、セキュリティ専門家および関連する
専門家とともに調査中」（原文英語）としている。実名掲載には Ingersoll Rand・Mindray・
Largan Precision が含まれ、Shell・Philips・Fiserv・GE は主張を認識し調査中だが重大な侵害は
確認していない。

PLMは設計図・部品表という「企業の中核知財」を保持するため、窃取の影響は個人情報漏えいと質が異なる評価・解釈出典 [1] [3]

本記録の作成者の整理として、この事案の先例性は2点にある。

第一に、標的が PLM（製品ライフサイクル管理）基盤である点が、従来の Clop campaign（ファイル
共有・ERP）と質的に異なる影響をもたらす。PLM は設計図面・部品表（BOM）・製造仕様・
サプライヤ情報といった、企業の競争力の源泉である技術知財を一元的に保持する。ここから
窃取された「図面・設計図・施設写真」は、個人情報の漏えいとは異なり、輸出管理対象技術や
防衛関連の設計情報を含みうる。Clop の主張どおりであれば、恐喝の圧力はデータ保護法制上の
リスクだけでなく、技術流出・国家安全保障の観点でも評価する必要がある。

第二に、パッチ提供（6月17日）から KEV 収載・悪用確認（6月25日）までがわずか8日であり、
「パッチが出た＝安全」ではなく「パッチが出た＝攻撃者も脆弱性を認識した」という前提で
動く必要があることを、Clop の即応性が改めて示した。インターネットに露出した業務基盤は、
アドバイザリ公開後の数日が最も危険な窓になる。

以上は本記録の作成者の評価を含み、各社・PTC の公表そのものではない。日本の製造業では
Windchill の利用が多く、公開資産の即時確認と、6月17日以降にパッチ未適用で露出していた
期間の侵害痕跡の点検が実務上の焦点になる。

波及の構造

事案の構造を図にしたものです。数値は公表値に基づきます。
露出したWindchill/FlexPLMの認証不要RCEからWebシェル設置・設計データ窃取に至る経路
攻撃者（Clop、layer 0）はインターネットに露出した PTC Windchill / FlexPLM（layer 1）に対し、 FlexPLM WSDL の事前認証情報漏洩と Windchill ログインサーブレットの欠陥（CVE-2026-12569）を 連鎖させて認証不要のリモートコード実行を成立させ、/Windchill/login/ 配下に16進名の JSP Web シェル（layer 2）を設置した。flst.txt によるファイル一覧化を経て設計図面・バックアップ・ 製造データ（layer 3）をステージング・窃取し、リークサイト掲載による二重恐喝（layer 4）を 行っている。掲載43組織のうち Shell・GE は調査・評価中、Philips は顧客影響なしと表明した。

対応の評価

CISO・経営層への示唆
  • PLM基盤の侵害は個人情報漏えいと質が違う——「技術知財・輸出管理対象技術の流出」として評価する
    Clop が窃取を主張したのは図面・設計図・製造データという企業の競争力の源泉であり、 航空宇宙・防衛・自動車・重機・医療機器の顧客が対象になっている。個人情報保護法制上の リスクだけで測ると、技術流出・国家安全保障上の影響を過小評価する。
    取るべき行動 PLM・CAD・設計文書管理システムに保持する知財を棚卸しし、「窃取された場合の影響」を 個人情報とは別軸（技術流出・輸出管理・契約上の守秘義務）で評価する。防衛・輸出管理 対象技術を扱う場合は、漏えい時の当局報告・取引先通知の経路を平時に決めておく。
  • 「パッチ公開」は安全化の合図ではなく攻撃開始の合図として扱う——露出資産は公開後の数日が最も危険
    パッチ提供（6月17日）から CISA の悪用確認・KEV 収載（6月25日）まで8日。Clop は アドバイザリ公開後の短期間で悪用に転じている。露出した業務基盤では、パッチ適用の 遅延がそのまま侵害の窓になる。
    取るべき行動 インターネット露出資産の緊急パッチについて「アドバイザリ公開から適用までの目標時間」を SLA として定め、露出面の可視化（外部アタックサーフェス管理）と併せて運用する。 適用が間に合わない資産は一時的に露出を落とす判断基準を持つ。
  • リークサイト掲載は「主張」であり、被害の確定と切り分けて公表・対応を設計する
    本件でも Philips は顧客影響なしと表明し、Shell・GE は調査・評価中である。掲載＝侵害確定 ではないが、放置すれば風評リスクになる。掲載を受けてから調査を始めると後手に回る。
    取るべき行動 自組織がリークサイトに掲載された場合の初動（掲載監視・事実確認・利害関係者への説明・ 公表方針）を手順化する。「掲載された事実」と「侵害・窃取の確定」を分けて説明できる テンプレートを用意する。
セキュリティ技術者への示唆
  • 認証不要のRCEは「アドバイザリ公開＝即侵害可能」——露出面の即時把握が前提になる
    CVE-2026-12569 は認証不要で、悪意あるリクエスト1つでコード実行に至る。FlexPLM の WSDL の事前認証情報漏洩と Windchill ログインサーブレットの欠陥を連鎖させる手口である。 インターネットに面していれば、パッチ未適用の間は誰でも悪用しうる。
    取るべき行動 Windchill / FlexPLM を含むインターネット公開資産の一覧を常に最新に保ち、 CVE-2026-12569 の対象バージョンかを即答できる状態にする。露出している場合は、 パッチ適用まで露出を落とす（アクセス制限・WAF・停止）代替統制を用意する。
  • パッチ適用だけでは既設のWebシェルは残る——「適用」と「侵害痕跡調査」を1組で行う
    攻撃者は `/Windchill/login/` 配下に16進名の JSP Web シェルを設置している。パッチは 新規侵入を止めるが、6月17日以降にパッチ未適用で露出していた期間に設置された Web シェルは パッチ適用後も残存する。
    取るべき行動 公開済み IOC（16進名 JSP・flst.txt・既知ハッシュ 55a1eb4c… および ReliaQuest の 321e1fb0…・`X-windchill-req` ヘッダ・関連 IP 7件）で Web ルート配下と作業ディレクトリを スキャンし、6月17日以降のアクセスログを保全して事後調査する。Web ルート配下の新規ファイル 生成の整合性監視を常設する。
  • Webシェルはキーストア内の全認証情報を平文で返す——「パッチ適用」と「認証情報の全ローテーション」を1組で行う
    ReliaQuest の解析では、`S` コマンド1つで LDAP 管理者パスワード・管理者アカウント・ オブジェクトストレージ認証情報・サイト管理者キーが復号される。パッチを当てても、既に 復号された認証情報は有効なまま残り、ディレクトリ全体への到達や下流システムへの再利用に使われる。
    取るべき行動 6月17日以降に露出していた Windchill / FlexPLM について、キーストアに入っていた全認証情報と、 同じ認証情報を使う下流システム（LDAP・ストレージ・連携先）をローテーションし、セッションを 失効させる。リバースプロキシで HTTP ヘッダを記録し、`X-windchill-req` 等の未知ヘッダを検知する。
  • PLMは設計データへの大量アクセスと外向き送信の監視点を持つべき業務システムである
    窃取は flst.txt によるファイル一覧化→ステージング→持ち出しという段を踏む。設計データへの 大量アクセスと外向き通信は、これを捕捉できる最後の共通検知点である。
    取るべき行動 PLM 上の設計図・BOM への大量アクセスのベースラインを定義し、逸脱をアラート対象にする。 PLM サーバーからの外向き通信を許可リスト化し、未知宛先への大量送信を検知・遮断する。

自組織に当てはまるか

該当する項目があれば、この事案と同じ構図が自組織でも成立しうることを意味します。
観点自社に当てはまるか該当する場合に何が起きうるか
システム構成□ PTC Windchill または FlexPLM を運用しており、インターネットから到達可能な経路があるCVE-2026-12569 は認証不要の RCE で、露出していれば誰でも悪用しうる。Clop が現に悪用中で KEV 収載済みのため、露出資産は即時のパッチ適用と侵害痕跡調査の対象になる。
データの保持□ 設計図面・部品表・製造仕様・輸出管理対象技術などの知財を PLM・設計文書管理に集約しているClop が窃取を主張したのはまさにこの種のデータである。漏えい時の影響を個人情報保護の 枠だけで評価すると、技術流出・輸出管理・契約守秘の観点を見落とす。
運用・監視□ インターネット露出資産の一覧と、緊急パッチの適用目標時間（SLA）が定義されていないパッチ公開から悪用確認まで8日だった。露出面の即時把握と迅速な適用がなければ、 アドバイザリ公開後の数日の窓で侵害される。
運用・監視□ Webルート配下の新規ファイル生成の整合性監視や、公開IOCによる侵害痕跡スキャンの手順がない攻撃者は Web シェルで持続化する。パッチ適用だけでは既設 Web シェルは残るため、 IOC ベースの痕跡調査を1組で行えないと侵害が残存する。
体制・契約□ リークサイト掲載時の初動（事実確認・利害関係者説明・公表方針）が手順化されていない本件でも掲載＝侵害確定ではなく、組織により対応が分かれた。掲載を受けてから調査を 始めると後手に回り、風評リスクが拡大する。
