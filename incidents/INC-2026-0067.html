INC-2026-0067拡張機能19本が買収と自動更新で悪性化

Chrome・Edge の拡張機能19本が16モジュール構成のマルウェア基盤を配信していた——うち5本は原作者から買収された「審査を通り利用者の信頼を積んだ正規の拡張」で、自動更新で悪性化し、最大のものは両ストア合計8万人が使っていた

脅威・攻撃キャンペーン委託先・再委託先起因で委託元多数に波及初報のみ有名事象として記録（日本と直接の関係は薄い）委託先・供給元起因設計・実装上の不備
初報: 2026年8月27日 最終更新: 2026年8月30日

アプリケーションセキュリティ企業 Socket は2026年8月27日、Google Chrome 向け18本と
Microsoft Edge 向け1本の計19本の拡張機能が、16のモジュールを持つマルウェア基盤を
配信していたと報告しました。Socket はモジュールの命名からこのキャンペーンを
「Superior」と呼んでいます。活動は2024年2月から2026年8月まで続いていたとされます。
記録すべきなのは配布の経路です。19本のうち14本は攻撃者が新規に作ったものですが、
残る5本は原作者から買収された拡張で、公開当初は宣伝どおりの機能を提供し
マルウェアを含んでいませんでした。利用者の信頼を積んだ後に、自動更新で
悪性コードが注入されています。両ストアに存在した
「Enable Right Click & Copy — Smart Unlock + OCR」は、悪性化した時点で
Chrome 約7万・Edge 約1万、合計約8万の利用者を抱えていました。
導入されたマルウェアは C2 サーバと WebSocket 接続を保ち（5分間隔の死活通信）、
JavaScript モジュールを都度取得し、訪問先すべてのサイトから
Content Security Policy ヘッダを削除して任意のスクリプトを注入します。
モジュールは暗号資産ウォレットのドレイン、Ledger・Trezor サイトの
シードフレーズ詐取ページへの差し替え、主要取引所と MetaMask のセッション窃取、
全サイトでの入力値の記録、Facebook・LinkedIn の認証情報の収集、
閲覧履歴の持ち出し、ClickFix 型の偽更新表示に及びます。
Chrome 版は削除されましたが、Edge 版は C2 ドメインを更新して残存していました。
本記録は、Socket の報告と報道が示した事実と、本記録の作成者による評価を
分けて整理します。

攻撃の経過

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

正規に公開され利用者の信頼を積んだ拡張機能を原作者から買収し、 ストアの自動更新を経路として悪性コードを配信する。導入後は C2 と 持続的な WebSocket 接続を保ち、必要なモジュールだけを都度取得して実行する。 訪問先すべてのサイトから CSP ヘッダを削除し、隠し要素を通じて スクリプトを注入することで、暗号資産ウォレットのドレイン、 ハードウェアウォレットのシードフレーズ詐取、取引所セッションの窃取、 全サイトでの入力値の記録、ClickFix 型の偽更新表示までを行う。

Socket が2026年8月27日に公開した調査によれば、Chrome 向け18本と Edge 向け1本の
計19本の拡張機能が、16のモジュールを持つマルウェア基盤を配信していた。
同社はモジュールの命名からこのキャンペーンを「Superior」と呼び、
活動は2024年2月から続いていたとしている。

19本のうち14本は攻撃者が新規に作ったものである。問題は残る5本のほうで、
これらは原作者から買収された拡張だった。公開当初は宣伝どおりの機能を
提供し、マルウェアは含まれていない。利用者を集め、レビューが積み上がり、
「安全な拡張」として定着した後に、自動更新で悪性コードが注入された。

名指しされた5本は、Enable Right Click & Copy — Smart Unlock + OCR、
RapidLens - Google Lens for Screen Search & Images、
QuickLens - Search Screen with Google Lens、Password Protect PDF、
そして Edge 向けの Allow Copy - Select & Enable Right Click である。
いずれも「右クリックを有効にする」「画面を検索する」「PDF にパスワードを掛ける」
といった、機能が単純で、権限の広さが目立たず、一度入れたら忘れられる類の
道具であることが共通している。

本記録の評価として、この経路の意味は「審査では止まらない」ことにある。
公開時の審査は、公開時のコードしか見ない。所有権の移転は
ストア側から見れば正当な手続きであり、自動更新は利用者を守るための仕組みである。
両方とも正しく働いた結果として、8万人の端末に悪性コードが届いた。

拡張機能は訪問先すべてから CSP ヘッダを削除できる——ブラウザ内の防御が前提から崩れる原因・手口出典 [1] [2] [3]

Socket によれば、インストールされたマルウェアは C2 サーバと暗号化された
WebSocket 接続を確立し、5分間隔で死活通信を行いながら JavaScript
モジュールを取得する。そのうえで、訪問するすべてのサイトから
Content Security Policy（CSP）ヘッダを削除し、隠し HTML 要素を通じて
悪性スクリプトを注入する。C2 の切り替えは動的に行われ、
被害者を別々の群と専用の C2 基盤に振り分けられる設計だとされる。
データの持ち出し先も動的に変更される。

CSP は、サイト側が「このページで実行してよいスクリプトの出所」を
ブラウザに宣言する仕組みである。これが拡張機能によって外されると、
サイト側がどれだけ丁寧に設定していても、そのページ上では任意の
スクリプトが動く。銀行のサイトも、社内の業務システムも、
同じ扱いになる。

本記録の評価として、ここが実務上いちばん重い。拡張機能は
「ブラウザの中の追加ソフト」ではなく、ブラウザが見るすべてのページに
対する特権を持つ実行環境である。ウェブ側の防御（CSP、サブリソース完全性、
フレーム制御）はいずれも拡張機能より内側にあり、この経路では前提が崩れる。
端末側で「何を入れさせるか」を決める以外に、実効的な統制点が無い。

16モジュールは暗号資産に寄っているが、全サイトの入力値の記録と閲覧履歴の持ち出しも含む被害規模・影響範囲出典 [1] [2] [3]

Socket が確認した16のモジュールは、それぞれ異なる目的を持ち、
「高度に拡張可能」な設計だとされる。報告と報道が挙げているのは次の機能である。

暗号資産まわりでは、EVM・Solana・Tron のウォレットに対するドレイン
（正規の「Connect Wallet」「Swap」ボタンを乗っ取る）、Ledger と Trezor の
サイトを説得力のあるシードフレーズ詐取ページに差し替える機能、
そして OKX・MEXC・Kraken・KuCoin・Coinbase・Binance・Bybit と MetaMask から
セッション・トークン・アカウント情報・残高を窃取する機能がある。

暗号資産に限らない機能も含まれる。全サイトでの認証情報とフォーム入力の記録、
Facebook のトークンとデータの収集、LinkedIn の CSRF 対策の除去と
セッションの悪用、閲覧履歴の持ち出し、そして ClickFix 型の偽ブラウザ更新表示
（利用者に攻撃者が用意したコマンドを実行させる）である。

本記録の評価として、被害の想定を暗号資産の保有者に限るのは誤りである。
全サイトでのフォーム入力の記録がある以上、業務システムの認証情報も
対象になる。偽更新表示による ClickFix は、ブラウザの外側——端末での
コマンド実行——への足掛かりになる。暗号資産を扱わない企業でも、
該当拡張が入っていた端末は認証情報の全面変更を前提に扱うべきである。

Chrome 版は削除されたが Edge 版は残り、C2 を切り替えて配信が続いていた対策・注意喚起出典 [1] [2]

Socket の報告公開時点（2026年8月27日）で、Chrome Web Store 上の該当拡張は
いずれも入手できなくなっていた。BleepingComputer は、Google が
「Enable Right Click & Copy — Smart Unlock + OCR」を早い段階で検知して
ストアから削除したと伝えている。

一方 Edge 版は、報告の公開時点でも入手可能なまま残っていた。しかも
2026年8月14日に C2 ドメインを更新した版が配信されている。
同一の拡張が2つのストアに存在し、片方だけが削除された状態が
少なくとも一定期間続いたことになる。

本記録の評価として、これは利用者側の実務に直結する。「ストアから消えた」
ことは、既に入っている拡張が無効化されたことを意味しない。
Chrome 側で削除されても Edge 側に残っていれば、同じ組織の中で
ブラウザによって状態が異なる。削除の告知が公になる前に自分の環境を
点検するには、拡張機能IDの一覧に対する能動的な照合が要る。
Socket は報告に拡張機能IDと C2 ドメインの一覧を付しており、
これが照合の材料になる。

公表されているのは露出の母数だけで、実際の被害の規模は分かっていない未確定事項出典 [1] [2] [3]

本記録が数値として扱えるのは、拡張機能のインストール数——
すなわち悪性コードが届きえた母数——だけである。実際に暗号資産を
抜かれた人数、盗まれた額、認証情報を窃取された人数はいずれも
公表されていない。

CISO・経営層への示唆
  • ブラウザ拡張は「導入時の審査」では守れない。所有権の移転と自動更新で後から悪性化する
    19本のうち5本は、公開当初は宣伝どおりに動作しマルウェアを含まない 正規の拡張だった。利用者の信頼が積み上がった後に買収され、 自動更新で悪性コードが注入されている。所有権の移転はストアの手続き上は 正当であり、利用者には通知されない。
    取るべき行動 ブラウザ拡張の統制を「入れるときに審査する」から 「入れられるものを限定し、変化を見る」へ切り替える。 Chrome Enterprise / Edge のポリシーで許可リストを配布し、 許可リストの見直しを定期の作業として予定に入れる。
  • 拡張機能はブラウザが見るすべてのページに対する特権を持つ。ウェブ側の防御は前提から外れる
    本件のマルウェアは、訪問先すべてのサイトから CSP ヘッダを削除して 任意のスクリプトを注入する。サイト側がどれだけ丁寧に設定していても、 拡張機能より内側の防御は効かない。サーバ側のログにも現れない。
    取るべき行動 自社のウェブアプリの防御策を評価する際に「利用者の端末の拡張機能が 侵害されている場合」を想定シナリオに加える。端末側の統制が 唯一の実効的な統制点であることを、投資判断の前提として経営に示す。
  • 「暗号資産を扱っていないから関係ない」で範囲を切ると、認証情報の漏えいを見落とす
    16モジュールのうち大半は暗号資産に寄っているが、全サイトでの 認証情報とフォーム入力の記録、閲覧履歴の持ち出し、 ClickFix 型の偽更新表示による端末上のコマンド実行の誘導も含まれる。 業務システムの認証情報も対象になる。
    取るべき行動 該当拡張が入っていた端末の利用者について、暗号資産の有無にかかわらず 全サービスの認証情報の変更とセッションの一括失効を実施する。 インシデント対応計画に「拡張機能の侵害」を独立した型として書き、 影響範囲の初期値を「その端末で使った全サービス」に置く。
  • ストアから消えたことは、既に入っている拡張が無効化されたことを意味しない
    Chrome 側では該当拡張が削除された一方、Edge 版は Socket の報告公開時点でも 残っており、2026年8月14日に C2 ドメインを更新した版が配信されていた。 同じ組織の中でも、ブラウザによって状態が違いうる。
    取るべき行動 報道でストアからの削除を知った時点で、自社の端末に当該拡張が 残っていないかを能動的に照合する運用を作る。ブラウザごとに 別々に確認する。拡張機能の導入状況を端末単位で把握できていなければ、 その棚卸しを先に行う。
セキュリティ技術者への示唆
  • 統制の単位は「拡張機能の名前」ではなく「拡張機能ID」にする
    同名・類似名の拡張は多数あり、悪性化した拡張が別名で再公開されることもある。 Socket が報告に付したのも拡張機能IDの一覧である。名前での照合は 取りこぼしと誤検知の両方を生む。
    取るべき行動 許可リストも遮断リストも拡張機能IDで記述する。資産管理側でも 端末ごとに導入済みの拡張機能IDとバージョンを収集する。 Socket の一覧との突き合わせは、この収集ができていて初めて成立する。
  • 悪性化は更新で起きる。バージョンではなく「要求権限の差分」を見る
    本件では自動更新で悪性コードが注入された。利用者の操作は不要であり、 バージョン番号が上がったこと自体は異常ではない。 変化として捉えられるのは、要求する権限とホストの範囲である。
    取るべき行動 許可した拡張の manifest の permissions と host_permissions を記録し、 更新のたびに差分を取る。差分が出たものは自動的に許可リストから外し、 再承認を必須にする。重要な業務で使う拡張はバージョンを固定する。
  • ブラウザからの持続的な WebSocket 接続は、この型で残る数少ないネットワーク上の痕跡である
    本件のマルウェアは C2 と暗号化された WebSocket 接続を保ち、 5分間隔で死活通信を行う。ブラウザ内の改変（CSP の削除、 スクリプトの注入）はサーバ側からは見えないが、 C2 との通信はネットワーク側に現れる。
    取るべき行動 Socket が公開した C2 ドメインの一覧を DNS・プロキシの遮断リストへ投入し、 過去の通信ログと突き合わせる。あわせて、ブラウザからの 業務に無関係なドメインへの持続的な WebSocket 接続を、 平常時の分布を測ったうえで検知対象にする。
  • 権限の広さが目立たない小さな拡張ほど、棚卸しから漏れる
    買収された5本はいずれも「右クリックを有効にする」「画面を検索する」 「PDF にパスワードを掛ける」といった単純な道具である。 機能が小さいと権限の広さが意識されず、一度入れたら忘れられる。
    取るべき行動 棚卸しの対象を「業務で重要な拡張」に絞らず、導入済みの全拡張を 対象にする。利用者に対しては「使っていない拡張を消す」を 定期の作業として案内し、実施状況を端末側の収集データで確認する。
  • 侵害された端末の影響範囲は「その端末で開いた全サイト」から始める
    全サイトでの認証情報とフォーム入力の記録が含まれる以上、 影響を特定のサービスに限定できない。閲覧履歴も持ち出されており、 攻撃者側は利用者がどのサービスを使っているかを把握できる。
    取るべき行動 該当拡張が入っていた端末について、閲覧履歴とブックマークから 利用サービスを洗い出し、認証情報の変更とセッション失効の対象一覧を作る。 多要素認証の再登録と、保存済みパスワードの棚卸しまで含める。

運用・監視□ 業務端末でブラウザ拡張の導入を利用者の判断に委ねており、許可リストによる制限をしていない本件の経路（買収と自動更新）は、利用者が正しく判断しても止まらない。 導入時に安全だった拡張が後から悪性化するため、 入れられるものを限定する以外に事前の統制点が無い。
運用・監視□ 端末ごとに導入済みの拡張機能IDとバージョンを収集していないSocket が公開した拡張機能IDの一覧との突き合わせは、 この収集ができていて初めて成立する。名前での照合では 取りこぼしと誤検知が生じる。
システム構成□ 業務システムの防御をウェブ側（CSP・サブリソース完全性・セッション管理）に依存しており、端末側の想定が無い拡張機能は訪問先すべてのサイトから CSP を削除できる。 サイト側の設定は拡張機能より内側にあり、この経路では前提が崩れる。 サーバ側のログにも痕跡が残らない。
認証・認可□ セッションの発信元や端末の変化を見ずに、認証済みセッションをそのまま信頼している本件ではセッションとトークンが窃取される。認証の時点では正当な 利用者であるため、認証の強度を上げてもセッションの持ち出しは止まらない。
体制・契約□ インシデント対応計画に「利用者端末のブラウザ拡張が侵害された場合」の型が無いこの型では影響範囲の初期値が「その端末で開いた全サイト」になる。 特定のシステムの侵害を前提にした手順では、 認証情報の変更対象を絞り込みすぎる。
委託・第三者部品□ 許可している拡張について、開発元が変わっていないかを定期的に確認していない所有権の移転はストアの手続き上は正当で、利用者に通知されない。 許可リストに載せた時点の判断は、開発元が変われば無効になる。
