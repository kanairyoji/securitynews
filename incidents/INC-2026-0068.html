INC-2026-0068PaperCut の事前認証RCEが実悪用される

印刷管理ソフト PaperCut NG/MF の事前認証RCE連鎖（CVE-2026-81578＋CVE-2026-82078）が実際の顧客環境で悪用された——緊急パッチは1日で2度出し直され、Huntress が追跡する約2,500台の47%を占めるv23以前には修正が存在しない

脆弱性不正アクセス・侵害続報が続いている有名事象として記録（日本と直接の関係は薄い）設計・実装上の不備既知の脆弱性の悪用脆弱性の放置
初報: 2026年8月27日 最終更新: 2026年9月1日

印刷管理ソフト PaperCut NG / PaperCut MF に、認証なしで遠隔からコードを実行できる
2つの脆弱性の連鎖が見つかり、実際の顧客環境で悪用されました。
PaperCut Software は2026年8月27日に緊急の注意喚起を出し、
「確認された顧客のインシデントを把握している」として最優先で対応していると述べています。
連鎖の1本目 CVE-2026-81578（CVSS 8.8）は管理用ウェブ画面のアクセス制御の不備で、
認証を経ていない遠隔からの要求が、アクセス検証の完了前に管理機能の処理を
起動させてしまうものです。2本目 CVE-2026-82078（CVSS 9.4）はデータベース接続
ユーティリティにおける安全でない動的クラス読み込みで、設定値を操作されると
任意の Java バイトコードが実行されます。1本目で設定を書き換え、
2本目で任意コードを実行する、という組み合わせです。
セキュリティ企業 Huntress は2026年8月26日と27日に2つの顧客環境で悪用を確認し、
さらに未修正の環境に対して連鎖全体を再現して、SYSTEM 権限でのコード実行に
至ることを実証しました。実際の攻撃で観測された活動は whoami・ver・tasklist の
実行のみで、1件目は2分未満で終わっています。
記録すべき点は3つあります。パッチが27日と28日の2度に分けて出し直されたこと
（watchTowr が最初のパッチの回避方法を複数見つけたため）。攻撃者がアプリケーションの
ログを消しても、組み込みデータベース Derby のログに痕跡が残ったこと。
そして Huntress が追跡する約2,500台のうち47%を占める v23 以前には、
そもそも修正が用意されていないことです。
本記録は、公表資料と調査報告に基づく事実と、本記録の作成者による評価を分けて整理します。

攻撃の経過

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

インターネットに公開された PaperCut のアプリケーションサーバに対し、 認証なしで CVE-2026-81578 を突いて設定を書き換え、続けて CVE-2026-82078 の 安全でない動的クラス読み込みを利用して任意の Java コードを実行する。 Huntress が確認した2件では、インストールディレクトリに悪性の Java クラスファイルを 置き、コマンドを実行し、出力とサーバのログを削除する動きが観測された。 実行されたのは whoami・ver・tasklist のみで、二次的なマルウェアや 永続化は確認されていない。

  1. 1. 初期侵入確認済[1] [2] [3]
    CVE-2026-81578 を利用し、細工した要求でサーバに「あるページを表示させながら 別のページの処理を実行させる」。PaperCut は実行する処理ではなく 表示するページの権限を検証していたため、認証を経ずに管理機能の処理が動く。 これによりサーバの設定を書き換えられる。
    根拠: PaperCut の注意喚起と Huntress の再現検証
  2. 2. 実行確認済[2] [3] [4]
    CVE-2026-82078 を利用し、データベース接続ユーティリティに安全でない Java クラスを読み込ませて任意のバイトコードを実行する。 Huntress の再現では、pc-app.exe が SYSTEM 権限で charmap.exe を起動した。 実際の侵入では、インストールディレクトリに Udydn.class・Moo97.class が 置かれ、コマンドの実行結果が一時ファイルへ書き出された。
    根拠: Huntress の調査報告と再現検証
  3. 3. 内部探索確認済[2] [4]
    実行されたコマンドは、1件目が whoami と ver（base64 で符号化）、 2件目がこれに tasklist を加えたもの。侵害したアカウントの権限、 Windows の版数、稼働中のプロセスの確認にとどまる。 1件目は2分未満で終わっている。
    根拠: Huntress の調査報告
  4. 4. 検知回避確認済[2] [4]
    悪性の Java クラスファイルは、自らの出力ファイル（Udydn.out）と サーバのログ（server.log）を削除する。server.log には `DB URL: jdbc:derby:memory:pwn` の行が記録されていたが、 ファイルごと消された。一方 /data/internal/derby.log は削除されず、 memory 配下の異常な名前のデータベースディレクトリの記録が残った。
    根拠: Huntress の調査報告と、PaperCut 自身の調査ガイダンス
公表されていない攻撃段階1
  • 永続化 / 権限昇格 / 横展開 / 収集 / 持ち出し / 影響（暗号化・破壊・改ざん）
    Huntress は、回収したペイロードから二次的なマルウェア、追加の コマンド＆コントロール通信、さらなる永続化や侵害後の活動を 観測していないとしている。権限は SYSTEM まで通っているため、 技術的な制約ではなく、観測された範囲がそこまでだったという意味である。 PaperCut は侵害後の活動について調査中を理由に開示を控えている。

表示するページの権限を見て、実際に動かすページの権限を見ていなかった——認可の取り違えが事前認証RCEの入口になった原因・手口出典 [2] [3]

連鎖の1本目は CVE-2026-81578（CVSS 8.8）である。攻撃者は細工した要求を送り、
サーバに「あるページを表示させながら、別のページの処理を実行させる」ことができる。
PaperCut は、実際に実行する処理ではなく、表示するページのほうの権限を検証していた。
PaperCut 自身の説明では「認証を経ていない遠隔からの要求が、アクセス検証の完了前に
管理機能の処理を起動しうる」（原文英語）。結果として、ログインせずに
サーバの設定を書き換えられる。

2本目は CVE-2026-82078（CVSS 9.4）である。PaperCut のデータベース接続
ユーティリティは、設定値によっては安全でない Java クラスを読み込んでしまう。
1本目で設定を書き換えられる以上、この2つは連鎖する。攻撃者は認証なしで
任意の Java コードをサーバ上で実行できる。

Huntress は、未修正の PaperCut NG 25.0.11.75758 に対してこの連鎖を
最初から再現した。遠隔から認証なしでコード実行に至り、PaperCut の
アプリケーションサーバ（pc-app.exe）が SYSTEM 権限で charmap.exe を
起動することを確認している。Windows で最も高い権限での実行が成立する。

本記録の評価として、この型の欠陥は「認証は掛かっているか」という点検では
見つからない。認証は掛かっている。壊れているのは、認証の後に
「どの処理に対して権限を確かめるか」の対応づけである。
自社の内製アプリケーションでも、表示と処理を別々に解決する仕組み
（画面の合成、リダイレクト、非同期の処理起動）を持つ箇所は
同じ取り違えを抱えうる。

実際の攻撃で観測されたのは whoami と ver だけ——2分未満で終わった1件目は「その後」の前触れとして読むべきである概観出典 [2] [4]

Huntress が確認した2件は、いずれも派手さの無い活動だった。
1件目（2026年8月26日、PaperCut MF v25.0.10.75465）は2分未満で終わり、
base64 で符号化された whoami と ver——侵害したアカウントと Windows の
版数を確認するだけのコマンド——が実行された。2件目（8月27日、
PaperCut MF v24.1.5.71847）はこれに tasklist が加わり、
稼働中のプロセスが確認された。

Huntress は「観測された活動はシステムの探索に集中していた。
二次的なマルウェア、追加のコマンド＆コントロール通信、
さらなる永続化や侵害後の活動は、回収したペイロードからは
観測していない」（原文英語）としている。

本記録の評価として、これを「大した被害ではなかった」と読むのは誤りである。
権限は SYSTEM まで通っており、実行できることに制限は無い。
観測されたのは、攻撃者が「ここは使える」と確認した段階である。
2件目が、まだ v24 向けの修正が無い時点の v24 サーバを狙っていることも
あわせて読む必要がある。攻撃側は、修正が出ていない版がどれかを
把握している。

攻撃者が消したのはアプリケーションのログ、消し忘れたのは組み込みデータベースのログだった発覚の端緒出典 [2] [4]

2件の侵入で、攻撃者は PaperCut のインストールディレクトリに悪性の
Java クラスファイル（Udydn.class、Moo97.class）を置き、コマンドを実行して
結果を一時ファイルに書き出したうえで、その出力ファイル（Udydn.out）と
サーバのログ（server.log）を削除して痕跡を消した。server.log には
DB URL: jdbc:derby:memory:pwn という行が記録されていたが、
このファイルごと消されている。

消えなかったのは /data/internal/derby.log である。PaperCut が内部で使う
組み込みデータベース Derby が書くログで、そこには
memory:C:\Program Files\PaperCut MF\server\data\internal\pwn という、
通常はありえない名前のデータベースディレクトリの記録が残った。
PaperCut 自身の調査ガイダンスは、これを高い確度の侵害指標として挙げている。

本記録の評価として、これは一般化できる教訓である。攻撃者が消すのは
「そのアプリケーションが書くログ」であり、そのアプリケーションが
使っている部品（組み込みデータベース、ランタイム、ミドルウェア）が
書くログまでは手が回らないことが多い。調査計画がアプリケーションのログだけを
保全対象にしていると、消去に弱い。ログの保全対象を決めるときは、
「攻撃者から見て消しやすい層」と「消しにくい層」を分けて考えたほうがよい。

緊急パッチは1日で2度出し直された——最初のパッチには回避方法が複数あった再発防止出典 [1] [3] [4]

PaperCut は2026年8月27日に最初の緊急パッチを公開した。その24時間以内の
8月28日に、緊急パッチ（第2版）を出し直している。理由は、
watchTowr が最初のパッチに対する回避方法を複数発見し、
あわせて追加の認証に関する脆弱性を見つけたことによる。
Huntress も連鎖全体を再現する過程で追加の回避方法を確認していた。
修正版は PaperCut NG v25.0.12.76497、PaperCut MF v25.0.12.76496 である。

さらに8月29日、PaperCut はパッチ適用後にカード／ID の照合と SAML に
不具合が生じたという報告を調査中であることを追記した。

本記録の評価として、実務側が引き受けることになるのは
「緊急パッチは1回で終わらない」という前提である。悪用が始まっている
脆弱性では、最初のパッチが回避される展開は珍しくない。
「当てたから終わり」で監視を戻すと、第2版が出たことを見落とす。
加えて本件では、パッチ適用後の機能不具合まで発生している。
カード認証と SAML は、印刷管理では日常業務そのものである。
止めずに当てるか、当ててから止まるかの選択を、事前に決めておく必要がある。

追跡台数の47%には当てるパッチが存在しない——「未適用」ではなく「適用できない」層である被害規模・影響範囲出典 [1] [2] [4]

Huntress が追跡している約2,500台の PaperCut のうち、およそ47%が
v23 以前を稼働させている。PaperCut はこれらの版について修正を用意せず、
最新版への移行を案内している。つまりこの47%は「まだパッチを当てていない」
層ではなく、「当てるものが無い」層である。

版を上げる作業は、パッチの適用とは性質が違う。印刷管理は複合機・
認証カード・課金・部門集計と結びついており、版を上げれば
周辺の連携を検証し直すことになる。教育機関であれば学期の区切り、
医療機関であれば診療の停止できない時間帯という制約も加わる。
「今日中に当てる」という話にはならない。

したがって、この層に対する現実的な手当ては構成のほうにある。
Huntress と PaperCut がともに勧めているのは、アプリケーションサーバを
インターネットから外し、VPN か信頼済みの内部ネットワークからのみ
到達できるようにすることである。本記録の評価としても、
版を上げられない期間の対処はこれに尽きる。印刷管理サーバを
インターネットに公開する業務上の必然性は、多くの組織では説明が難しい。

悪用の主体・開始時期・被害組織はいずれも公表されていない未確定事項出典 [1] [2] [3] [4] [5] [7]

Huntress が確認したのは2件で、いずれも組織名・業種・所在国は公表されていない。
偵察の後に何が起きたか、データが持ち出されたかも示されていない。
PaperCut は「確認された顧客のインシデント」があるとしながら、
件数も内容も公表していない。攻撃を「限定的かつ標的を絞ったもの」と
表現しているが、その根拠は示されておらず、侵害後の活動については
調査中を理由に開示を控えている。

攻撃者の主体も、悪用がいつ始まったかも公表されていない。
Huntress が確認した最初の悪用は2026年8月26日だが、それ以前から
悪用が始まっていた可能性は否定されていない。

日本国内の状況も分かっていない。PaperCut は国内の教育機関・企業でも
使われているが、稼働台数、インターネットに公開されている台数、
被害の有無はいずれも公表されておらず、本記録の作成者も確認していない。

［2026年9月2日追記］ インターネットに露出している台数については、
2026年9月1日時点で Shadowserver の観測として800台超（BleepingComputer）
あるいは1,000台超（SecurityWeek）という値が報じられた。
国別の内訳は示されていない。

偵察から実侵入へ移り、KEV に収載された——パッチだけでは既存の攻撃者を締め出せない評価・解釈出典 [5] [6] [7]

2026年8月31日、米 CISA は CVE-2026-81578 と CVE-2026-82078 を
「悪用が確認された脆弱性カタログ」（KEV）へ追加した。
連邦機関の対応期限は2026年9月14日である。
カタログの記載では、CVE-2026-81578 は「重要な機能に対する認証の欠如」、
CVE-2026-82078 は「安全でないリフレクション」と分類され、
両者は連鎖しうると明記されている。
ランサムウェアでの悪用の有無は、いずれも「不明」とされている。

同じ時期、攻撃の性質が変わった。WatchTowr の脅威情報責任者
Jake Knott 氏は2026年9月1日、
「もはや脆弱なシステムを見つけるための探索的なプローブだけではなく、
侵害したシステムを人間の攻撃者が対話的に探索する、
実世界の悪用が伴っている」（原文英語）と述べた。
外部から内部への横断を目的とした活動が見られ、
攻撃者は展開したメモリ上のペイロードにアクセスの鍵を設定して、
自分以外が侵害済みホストを使えないようにしていた。
同氏はこれを初期アクセスブローカーに特徴的な挙動としている。
PaperCut が更新した侵害の痕跡にも、遠隔アクセスツールの導入が加わった。

さらに Defused は、2026年8月29日以降に自社のハニーポットで
観測した活動を公表した。攻撃者は認証の迂回を悪用して
PaperCut の外部利用者照会の機能を乗っ取り、
公開されている解説記事にある遠隔コード実行の経路ではなく、
組み込みデータベース Derby 経由でデータベースのテーブルを吸い出す
というデータ窃取を狙っていた。

本記録の評価として、この3つの動きは同じ一つの結論を指している——
パッチの適用は対応の終わりではない。
Knott 氏はこう述べている。「直近数日のいずれかの時点で
インターネットへ公開されかつ未修正であったシステムは、
価値のある標的を探して脆弱なホストをしらみつぶしに調べている
能動的な攻撃者によって、侵害されたと仮定すべきである」
「まだであれば、今こそ事故対応の手順を起動する時である。
パッチの適用は新規の攻撃者を締め出すが、
既存の攻撃者はアクセスを保持したまま先へ進むことができる」（いずれも原文英語）。

あわせて、Defused の観測が示す方向も重い。
公開された解説記事の多くは遠隔コード実行の経路を扱っており、
防御側の検知もそちらに寄る。しかし実際に観測された活動は、
より地味で、より検知しにくいデータ窃取だった。
Derby は PaperCut に組み込まれたデータベースであり、
そこからのテーブルの読み出しは、外部から見れば
正規のアプリケーションの動作と区別がつきにくい。

日本の読者にとっての実務は次の順になる。
第一に、Release 3 を適用する（以前の緊急リリースを適用済みでも必要である）。
第二に、インターネットからの到達を止める。
第三に、直近にインターネットへ公開かつ未修正だった期間があるなら、
パッチの適用とは別に事故対応を起動する。
具体的には、server.log に残る Base64 文字列と不審な Java クラスファイルの捜索、
Derby からのテーブルの吸い出しの痕跡の確認、
遠隔アクセスツールの導入の有無、そして管理者の資格情報の入れ替えである。

PaperCut は7万を超える組織・1億の利用者で使われているとされ、
国内でも大学・学校・病院・自治体・企業に広く導入されている。
2023年の CVE-2023-27350／CVE-2023-27351 の際には、
LockBit と Clop のランサムウェア集団に加え、
イランの MuddyWater と APT35 も悪用に加わった。
ランサムウェアと国家系の双方が過去に狙った製品であることは、
優先順位を決めるうえで踏まえるべき事実である。

事案の構造を図にしたものです。数値は公表値に基づきます。

インターネットに公開された PaperCut のウェブ管理画面に対し、 認証なしで CVE-2026-81578 を突いて設定を書き換え（layer 1→2）、 CVE-2026-82078 で任意の Java コードを実行する（layer 3）。 Huntress の再現では pc-app.exe が SYSTEM 権限で子プロセスを起動した（layer 4）。 実際の侵入で観測された活動は whoami・ver・tasklist のみである（layer 5）。 攻撃者は出力ファイルと server.log を削除したが、 組み込みデータベース Derby のログは残った（layer 6）。

CISO・経営層への示唆
  • 「本業ではないが全社が使う」ソフトが、インターネットに公開されたまま残りやすい
    PaperCut は印刷管理という業務系のソフトで、学校・病院・オフィスで 広く使われている。基幹システムほど資産管理の対象として意識されず、 在宅勤務や複合機の都合でインターネットに公開されたまま 残っていることがある。本件はまさにそこが入口になった。
    取るべき行動 資産の棚卸しを「基幹システム」から「全社が使うが本業ではないソフト」へ 広げる。印刷管理、会議室予約、複合機の管理画面、勤怠、 ファイル転送——インターネットから到達できるものを一覧にし、 公開の必然性を業務側に確認する。
  • 緊急パッチは1回で終わらない前提を、対応手順に書き込む
    本件では8月27日の緊急パッチが、24時間以内に第2版へ出し直された。 watchTowr が最初のパッチの回避方法を複数見つけたためである。 「当てたから終わり」で監視を戻すと、第2版の公開を見落とす。
    取るべき行動 悪用が始まっている脆弱性への対応手順に「適用後も一定期間、 開発元の告知を追う担当と期限を決める」を入れる。 最初の適用から少なくとも2週間は、同じ脆弱性の続報を 追跡対象として残す。
  • 「当てていない」と「当てるものが無い」は別の問題であり、対処も別になる
    Huntress が追跡する約2,500台の47%は v23 以前で、PaperCut は これらに修正を提供していない。パッチ適用の督促では動かない層である。 版を上げる作業は、周辺の連携の検証と業務の区切りに縛られる。
    取るべき行動 脆弱性対応の管理表に「修正が提供されているか」の列を設け、 提供されていないものは構成変更（遮断・分離）の課題として 別の期限で管理する。移行の計画には業務側の区切り （学期・決算・診療の停止可能な時間帯）を最初から織り込む。
  • パッチが業務を止める可能性まで含めて、適用の判断を用意しておく
    PaperCut は2026年8月29日、パッチ適用後にカード／ID の照合と SAML に不具合が生じたという報告を調査中とした。印刷管理では カード認証と SAML は日常業務そのものである。
    取るべき行動 緊急パッチの適用手順に「適用後に確認する業務機能の一覧」と 「切り戻しの判断者と条件」を書いておく。適用しない選択を取る場合の 代替策（インターネットからの遮断）も同じ手順の中に置き、 どちらを選んでも当日に決められるようにする。
セキュリティ技術者への示唆
  • 認可は「表示するもの」ではなく「実行するもの」に対して確かめる
    CVE-2026-81578 は、表示するページの権限を検証し、実際に実行する処理の 権限を検証していなかったことによる。認証は掛かっていた。 壊れていたのは、認証の後の対応づけである。
    取るべき行動 自社のアプリケーションで、表示と処理を別々に解決する箇所 （画面の合成、リダイレクト、非同期の処理起動、要求パラメータによる 処理の切り替え）を洗い出し、権限の検証が「実際に実行される処理」に 対して行われているかを確認する。検証の位置が処理の起動より 後になっていないかも見る。
  • 攻撃者が消すのはアプリのログ、消し忘れるのは部品のログである
    本件で攻撃者は server.log と自らの出力ファイルを削除したが、 組み込みデータベース Derby が書く /data/internal/derby.log は 残った。PaperCut はこれを高い確度の侵害指標としている。
    取るべき行動 調査計画の保全対象に、アプリケーションのログだけでなく 組み込みデータベース・ランタイム・ミドルウェアが書くログを含める。 あわせて、アプリケーションのログをサーバ外へ転送し、 ローカルの削除では消えない場所に保全する。
  • 印刷管理サーバのアプリケーションプロセスがコマンドを起動するのは正常ではない
    実行されたのは whoami・ver・tasklist という Windows 標準のコマンドで、 単体では悪性と判定しにくい。異常なのは、それらが pc-app.exe を 親として起動されている点である。
    取るべき行動 サーバ用途ごとに「正常な子プロセスの一覧」を作り、そこから外れた 親子関係を検知対象にする。PaperCut のサーバでは pc-app.exe を親とするコマンドシェルの起動を優先して見る。 EDR が入っていない業務系サーバがどれだけあるかを先に把握する。
  • 探索は2分で終わる。「短時間の偵察」を軽い事象として閉じない
    1件目の侵入は2分未満で、whoami と ver の実行だけだった。 しかし権限は SYSTEM まで通っており、実行できることに制限は無い。 観測されたのは、攻撃者が「ここは使える」と確認した段階である。
    取るべき行動 侵害の疑いがある事象を「実害が確認できないので終了」で閉じる前に、 到達しえた権限の範囲を確認する手順を入れる。 SYSTEM 権限での実行が成立していた場合は、 実際の活動が偵察だけでも、資格情報の変更と再調査の対象にする。
  • パッチを当てる前に証拠を保全する。適用は調査の終わりではなく始まりである
    Huntress は、インターネットに公開されていた PaperCut サーバについて、 パッチの適用を対応の終わりではなく調査の始まりとするよう勧めている。 サーバを再起動すればプロセスの状態は失われ、 パッチの適用でファイルも上書きされる。
    取るべき行動 緊急適用の手順の先頭に「ログ・設定ファイル・プロセス一覧・ 通信記録の保全」を置く。保全先と手順を平時に決めておかないと、 緊急時には必ず飛ばされる。

自組織に当てはまるか

該当する項目があれば、この事案と同じ構図が自組織でも成立しうることを意味します。
観点自社に当てはまるか該当する場合に何が起きうるか
システム構成□ PaperCut NG / MF のアプリケーションサーバがインターネットから到達できる本件の連鎖は認証を必要としない。到達できることが、そのまま SYSTEM 権限でのコード実行の成立条件になる。 公開の必然性が説明できないなら、遮断が最も確実な対処である。
運用・監視□ PaperCut を v23 以前で運用しており、最新版への移行の計画が無いv23 以前には修正が提供されていない。Huntress が追跡する約2,500台の 47%がこの層である。パッチ適用の督促では解決せず、 構成変更か版の移行のどちらかを選ぶしかない。
運用・監視□ 印刷管理サーバに EDR が入っておらず、プロセスの親子関係を記録していない実行されたコマンドは Windows 標準のもので、単体では悪性と判定できない。 pc-app.exe を親とする起動という関係を見なければ検知できない。
運用・監視□ アプリケーションのログをサーバ内にしか置いておらず、外部へ転送していない本件では攻撃者が server.log をファイルごと削除している。 転送していなければ、最も直接的な痕跡は残らない。 残ったのは、攻撃者が想定していなかった組み込みデータベースのログだった。
体制・契約□ 脆弱性対応の管理表に「修正が提供されているか」の区別が無い「未適用」と「適用できない」を同じ列で管理すると、 修正が存在しない層がいつまでも未対応として残り、 構成変更という別の手当てに切り替わらない。
運用・監視□ 緊急パッチの適用手順に、証拠の保全と適用後の業務機能の確認が含まれていない本件ではパッチが1日で2度出し直され、適用後にカード／ID 照合と SAML の不具合まで報告された。保全せずに適用すれば調査ができず、 確認せずに適用すれば業務が止まる。
