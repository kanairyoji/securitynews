入力画面に仕込まれたスクリプトがカード番号とセキュリティコードを外へ送っていた——決済代行のトークン化では防げない場所原因・手口出典 [1] [2]

同社が公表した事実は次のとおりである（報道の引用による）。

  • 第三者がシステム内に悪意ある不正スクリプトを設置していた
  • 8月5日、システム内で不審な外部送信プログラムを発見し、同日15時30分からサイトを一時閉鎖した
  • 流出した可能性があるのは、5月1日〜8月5日に注文または情報を入力した利用者の
    氏名・住所・電話番号・メールアドレスと、クレジットカード番号・有効期限・セキュリティコード

本記録の評価として、この事案は国内 EC で繰り返されている「入力フォームの改ざん」型である
（同社は手口をそう呼んでいない）。カード番号だけでなくセキュリティコードが対象に
含まれるのは、EC 事業者がカード番号を保持していない場合でも、利用者が入力する画面そのものが
改ざんされれば、入力した瞬間の値が攻撃者の手に渡るためである。決済代行会社への
トークン化・リンク型決済を使っていても、改ざんされたのが「決済代行へ渡す前の自社の画面」なら
防げない。

設置の経路（EC システムの脆弱性・管理画面の認証情報・委託先など）と設置日は公表されておらず、
対象期間の始点5月1日が設置日を意味するのかも分からない。原因の分類は「公表されていない」とした。

3か月間気づかれず、発見の手段は公表されていない——同じ週に国内 EC で同型の公表が続いた発覚の端緒出典 [1] [2]

対象期間は5月1日から8月5日までの97日間（本記録の算出）で、同社が不審な外部送信プログラムを
発見したのは8月5日である。発見の手段は公表されていない。

本記録の評価として、この3か月は「改ざんされたページが本番で動き続けた期間」の下限を示す。
ファイルの整合性監視や、ページから外部へ送信される先の監視があれば、設置の時点か
最初の送信の時点で気づけた可能性がある（同社がそれらを持っていたかは公表されていない）。

本件が日次ニュースに載った9月3日の前日には、ペット用品通販のチャーム（INC-2026-0082）と
まんだらけの EC で同型の事案が報じられており、国内の EC 事業者に対する入力フォーム改ざんが
続いている。個々の事案の攻撃者や手口の同一性は確認されていないが、
「決済画面の改ざんを検知する仕組みが無い EC が狙われ続けている」という構図は共通する
（本記録の整理）。

本記録の評価として、発見当日の閉鎖と公表より前の個別連絡は評価できる。
カード情報の流出は利用者側の自衛（明細の確認・カードの差し替え）で被害を抑えられる種類であり、
2日でも早く届くことに意味がある。「注文済み商品は順次発送」「個人情報の削除希望は個別対応」

  • 決済代行のトークン化を使っていても、自社の画面にカード入力欄がある限り「入力フォーム改ざん」の被害は自社の責任範囲に残る
    本件ではカード番号・有効期限に加えてセキュリティコードが対象になった。 改ざんされたのは決済代行へ渡す前の自社の画面と読め、トークン化では防げない場所である
    取るべき行動 自社の EC のカード入力欄がどこで描画されているか（自社ページ／決済代行のページ／iframe）を 確認し、自社ページで描画している場合はリンク型または iframe 型への移行を判断する。 移行しない場合は、ファイル整合性監視と外部送信先の監視を「必須の統制」として予算をつける
  • 対象を「期間」で定義すれば、件数が確定していなくても公表と個別連絡ができる
    同社は対象を「5月1日〜8月5日に注文または情報を入力した利用者」と定義し、 件数が無いまま発見から5日で公表し、公表の2日前にカード情報対象者へ個別連絡した
    取るべき行動 事故公表の手順に「件数の確定を公表の条件にしない」「対象を期間・サービス単位で定義する」と 明記し、注文・入力の記録から期間で対象者を抽出できる仕組みを平時から確認しておく
  • 閉鎖の判断基準を事前に決めておく。入力フォーム改ざん型は閉鎖するまで被害が増え続ける
    同社は発見当日の15時30分にサイトを閉鎖し、8月18日時点でも閉鎖を継続している。 改ざんが動いている間は、注文のたびにカード情報が外へ出る
    取るべき行動 「決済代行会社・カード会社から不正利用の連絡を受けた」「本番ページから許可リスト外への送信を検知した」 などの条件を満たしたら即日で閉鎖する権限を EC の責任者に与え、閉鎖中の注文済み商品の発送・返金の 代替手順を用意しておく
  • 3か月間の未検知は「改ざんを検知する仕組みが無かった」ことを示す。同型の事案が続いている
    対象期間は97日間（本記録の算出）に及び、この間に検知されていない。同じ週に国内 EC で 同型の公表が続いており、EC 事業者は狙われ続けている
    取るべき行動 自社の EC について「本番ページの改ざんを何日以内に検知できるか」を技術部門に問い、 答えが無ければファイル整合性監視・Content Security Policy・外部送信先の巡回のいずれかを 四半期以内に入れる
セキュリティ技術者への示唆
  • 本番のページ・テンプレート・JavaScript のファイル整合性を監視し、想定外の変更を即日で検知する
    本件では不正スクリプトが設置されてから発見まで最長97日間（対象期間ベース）気づかれなかった。 改ざんはサーバ上のファイルかデータベース上のテンプレートの変更として残る
    取るべき行動 公開ディレクトリとテンプレートのハッシュを定期的に取得して基準値と比較し、差分があれば デプロイ記録と突合して説明できないものをアラートにする。CMS・EC パッケージの プラグイン・テーマの変更も対象にする
  • Content Security Policy でページから通信できる先を許可リストにし、違反レポートを監視する
    入力フォーム改ざん型は、利用者のブラウザから攻撃者のサーバへ直接送信する。 サーバ側のログには残らないが、ブラウザの CSP 違反レポートには残る
    取るべき行動 決済・会員ページに connect-src / form-action / script-src の許可リストを設定し、 report-uri / report-to で違反を収集して、未知の宛先が出たらアラートにする。 まず Report-Only で始め、正当な外部先を洗い出してから強制に切り替える
  • 自社の画面にカード入力欄を置かず、決済代行会社のページまたはトークン化 iframe に委ねる
    セキュリティコードまで対象になったことは、利用者が入力する画面そのものが改ざんされたことを示す。 入力欄が自社ドメインに無ければ、自社ページの改ざんだけではカード情報は取れない
    取るべき行動 カード入力を決済代行会社のホスト型ページ（リンク型）に移すか、トークン化 iframe に置き換える。 iframe 型でも親ページの改ざんで偽の入力欄を重ねられるため、親ページの整合性監視と CSP は併用する
  • 本番ページの外部送信先を定期的に自動巡回し、許可リスト外の宛先を検知する
    同社は8月5日に「不審な外部送信プログラム」を発見したが、手段は公表されていない。 自社で巡回していれば、設置直後に見つけられた可能性がある
    取るべき行動 ヘッドレスブラウザで決済導線を定期的に実行し、読み込まれたスクリプトの URL と 送信先を記録して、許可リストと比較する。差分が出たらページのソースと突合する
  • 閉鎖中の対象者抽出と個別連絡を、注文記録から期間で自動抽出できるようにしておく
    同社は対象を期間で定義し、発見から3日でカード情報対象者へ個別メールを送った。 期間で抽出できる注文記録が無いと、件数の確定を待たざるを得ない
    取るべき行動 注文・会員登録・カード入力のイベントを日時つきで記録し、「期間 × 入力項目」で対象者を 抽出するクエリを平時に用意しておく。メールアドレスが流出している前提で、 通知メールの文面は URL を含めず、公式サイトでの確認を促す形にする

自組織に当てはまるか

該当する項目があれば、この事案と同じ構図が自組織でも成立しうることを意味します。
観点自社に当てはまるか該当する場合に何が起きうるか
システム構成□ 自社ドメインのページにクレジットカードの入力欄があり、決済代行会社へはトークン化や API で渡している本件ではカード番号・有効期限・セキュリティコードが対象になった。トークン化は自社サーバに カード番号を残さない仕組みであり、入力画面の改ざんには効かない
運用・監視□ 本番のページ・テンプレート・JavaScript の改ざんを検知する仕組み（ファイル整合性監視・CSP 違反レポート・外部送信先の巡回）が無い本件は対象期間97日間、検知されなかった。改ざん型の被害は検知までの日数に比例する
委託・第三者部品□ EC システムの構築・保守を委託しており、管理画面の認証情報やパッチ適用の責任が委託先にある同社は設置の経路を公表していないが、国内 EC の同型事案では EC パッケージの脆弱性や 管理画面の認証情報が経路になることが多い。委託先任せではパッチと監視の責任が曖昧になる
体制・契約□ 決済代行会社・カード会社からの不正利用の連絡を受けたときに、即日で閉鎖を判断する基準と権限が決まっていない同社は発見当日に閉鎖した。閉鎖が遅れれば、その間の注文がすべて対象に加わる
データの保持□ 注文・入力の記録を期間で抽出して対象者を特定する仕組みが無く、件数の確定まで個別連絡ができない同社は対象を期間で定義し、公表の2日前にカード情報対象者へ個別連絡した
体制・契約□ グループ内の複数の子会社が別々に EC を運営しており、グループとして EC の改ざん検知の基準が統一されていない同じ日に同グループの別子会社の事案（INC-2026-0087）が公表された。手口は異なるが、グループとしての統制の単位が問われる
