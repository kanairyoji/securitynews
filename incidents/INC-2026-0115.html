INC-2026-0115ApplyNow、分析ツール経由で不正アクセス

きちりホールディングスの子会社 ApplyNow が提供する採用管理プラットフォーム「Interview Cloud」「ApplyNow」「ApplyNow Sign」が、同社の使うデータ分析ツールの脆弱性を突かれ、8月9日から9月7日までデータベース内の一部データにアクセスされた——応募者の氏名・連絡先、企業担当者の情報に加え、電子雇用契約の契約者のマイナンバー・基礎年金番号・金融機関口座情報が漏えいのおそれ。検知当日に遮断し2日後に公表したが、件数は「調査中」、ツールの製品名は公表されていない

不正アクセス・侵害委託先・再委託先起因で委託元多数に波及初報のみ日本の組織が当事者既知の脆弱性の悪用公表されていない／不明
初報: 2026年9月9日 最終更新: 2026年9月9日

飲食店の経営を手がける株式会社きちりホールディングス（東証スタンダード・3082）は2026年9月9日、子会社の株式会社ApplyNowが提供する採用管理プラットフォームに第三者による不正アクセスがあり、顧客企業と応募者の個人データが外部へ漏えいした可能性があると適時開示で公表しました。別紙として、ApplyNow 名義の「当社サービスをご利用いただいているお客様への重要なお知らせとお詫び」が添えられています。

対象は面接シェアリングサービス「Interview Cloud」、録画面接「ApplyNow」、電子雇用契約「ApplyNow Sign」の3サービスです。ApplyNow によれば、同社のシステムで利用しているデータ分析ツールの脆弱性を悪用した不正アクセスにより、データベース内に保存されていた一部データに第三者がアクセスした痕跡が確認されました。不正アクセスが確認された期間は2026年8月9日から9月7日までです。

漏えいした可能性があるのは、Interview Cloud と ApplyNow の応募者情報（氏名（カナ）・メールアドレス・電話番号など）と企業ユーザー情報（企業担当者のユーザー名・メールアドレス・権限など。Interview Cloud は外部連携情報も含む）、そして ApplyNow Sign の雇用契約情報、個人番号（マイナンバー）、基礎年金番号、金融機関口座情報を含む契約者情報です。画像・PDF 等のファイル実体と面接動画データは別の保管領域にあり、対象外と確認したとしています。対象データ件数は「現在調査中」です。

同社は9月7日に異常なアクセスログを検知し、同日に遮断等の緊急措置をとりました。該当ツールへのアクセスを完全に遮断し、修正版のセキュリティパッチを適用済みで、個人情報保護委員会と所轄警察署への報告・相談、対象者への個別連絡を進めています。9月9日時点で二次被害は確認されていないとしています。

本記録の評価として、この事案の読みどころは入口が顧客向けの本番サービスではなく、社内で使うデータ分析ツールだったことです。分析のために本番データベースへ接続されたツールが破られると、3つのサービスにまたがるデータ、それもマイナンバーや口座情報まで届いてしまう構図が見えます。もう一つは、採用や雇用契約の SaaS を使う企業の側から見れば、自社が預けたデータが委託先から漏れた事案だという点です。

データ分析ツールの製品名、脆弱性の内容、悪用の時点で修正版が出ていたか、件数、利用企業の社名・社数は公表されていません。本記録は、きちりホールディングスの適時開示（ApplyNow の告知を含む）と報道から確認できた範囲を整理します。

ApplyNow の告知は、原因を次のように記している。

当社システムにおいて利用しているデータ分析ツールの脆弱性を悪用した不正アクセスを受け、データベース内に保存されていた一部データに対し、第三者による不正アクセスが行われた痕跡が確認されました。

破られたのは、応募者や企業担当者が日々使う3つのサービスそのものではなく、同社がデータを分析するために使っていたツールである。そしてそのツールを経由して、データベース内のデータに到達された。

製品名、脆弱性の識別子、ツールが第三者の製品か自社開発か、SaaS か自社ホストかは公表されていない。分かっているのは、対応として「該当ツールへのアクセスの完全遮断」と「該当ツールの脆弱性に対する修正版のセキュリティパッチ適用」を完了したことである。修正版が存在することは読み取れるが、それが悪用の前から公開されていたのかは示されていない。前から公開されていたなら適用の遅れが原因であり、後から出たなら未知の脆弱性の悪用である。この区別で、他社が本件から引き出すべき教訓は変わる（本記録の評価）。

本記録の評価として、分析ツールは本番システムの資産台帳と監視から漏れやすい。開発や分析の担当が導入し、本番データベースへの読み取り権限を持ち、しかも顧客向けの画面ではないため、脆弱性情報の追跡や外部からの到達性の点検が本番サービスほど厳しくないことが多い。本 DB の国内事案では、VOISING（INC-2026-0086）も社内で使う BI ツールの脆弱性が入口で、全サービスの顧客データが1か所から持ち出された。

波及の構造

事案の構造を図にしたものです。数値は公表値に基づきます。
社内で使うデータ分析ツールの脆弱性から、3サービスのデータベース（マイナンバー・口座情報を含む）に到達された
layer 0 は攻撃者と、ApplyNow が利用するデータ分析ツール（製品名・脆弱性の内容は非公表）。 layer 1 は3サービスのデータベース内のデータ（接続構成は非公表）。別の保管領域にある 画像・PDF 等のファイル実体と面接動画は対象外と確認されている。 layer 2 は漏えいの可能性がある区分（応募者・企業担当者・雇用契約者）。 layer 3 は ApplyNow・きちりホールディングスの対応と報告先。件数はいずれの区分も調査中。 不正アクセスが確認された期間は 8/9〜9/7、検知は 9/7、公表は 9/9。

対応の評価

評価材料がない判断は「評価材料なし」としています。結果論で断じないための区分です。
判断評価評価の根拠と留保
検知から2日後、件数が「現在調査中」の段階で、適時開示と ApplyNow の告知により公表した機能した本記録の作成者の評価である。マイナンバーと口座情報が含まれる事案で、確定を待たずに 2日で項目と期間を示したことは、対象者が不審な連絡に備える時間を作った。 上場会社の適時開示として出したため翌日には報道され、周知の範囲も広がった
対象サービス・項目（サービス別）・期間・対象外の範囲（ファイル実体と面接動画）・経緯・対応を公表し、 件数・データ分析ツールの製品名・脆弱性の内容・利用企業の社名は公表しなかった部分的に機能本記録の作成者の評価である。項目の列挙は具体的で、ファイル実体と動画を対象外と明記した点は 対象者の不安を正しく絞る。一方、製品名と、悪用の時点で修正版が出ていたかが示されていないため、 原因が適用の遅れか未知の脆弱性かを読者は判断できない。件数は続報を待つ
影響を受ける可能性のある企業ユーザーへ、パスワード変更を促す緊急連絡を配信した評価材料なし本記録の作成者の評価である。パスワードやその変換値が参照された可能性があるのかが示されておらず、 依頼で十分だったかを評価する材料が無い。Interview Cloud の外部連携情報に連携用の資格情報が 含まれる場合、パスワード変更だけでは足りない
入口となったデータ分析ツールへのアクセスを完全に遮断し、修正版を適用した。3サービスの停止は公表されていない部分的に機能本記録の作成者の評価である。顧客向けでない分析ツールは切り離しても業務への影響が小さく、 検知当日に遮断できた判断は合理的である。ただし、ツール以外に経路が無いことをどう確かめたか （外部の専門機関による調査の有無を含む）は公表されていない
個人番号・金融機関口座情報が含まれる対象者には個別の注意喚起とサポート案内を、それ以外の企業と個人にも順次個別に案内するとした評価材料なし本記録の作成者の評価である。重い情報の対象者を分けて手厚く扱う方針は妥当だが、 手段・完了時期・利用企業との分担が公表されておらず、実施の状況は評価できない
CISO・経営層への示唆
  • 本番データベースにつながる分析ツール・BI は、本番システムと同じ重さの資産である——顧客向けでないから軽く扱うと、裏口になる
    本件の入口は3サービスそのものではなく、同社が使うデータ分析ツールだった。 そのツールからマイナンバー・口座情報を含むデータベースに到達された。国内では VOISING（INC-2026-0086）も 社内の BI ツールが入口だった
    取るべき行動 本番データベースに接続している分析ツール・BI・ダッシュボードを全部洗い出し、 誰が導入したか、外部から到達できるか、どの表まで読めるか、脆弱性情報を誰が追っているかを一覧にする。 台帳に無いものが見つかれば、それが最優先の是正対象である
  • 採用・雇用契約の SaaS を使う企業は、自社が委託元である——委託先の「使っているツール」まで監督の範囲に入る
    利用企業から見れば、本件は預けた応募者・従業員の情報が委託先の分析ツールから漏れた事案である。 ApplyNow Sign を使う企業はマイナンバーまで預けていた。委託先が内部でどんなツールを使っているかは、 通常の委託先評価の質問票では見えにくい
    取るべき行動 応募者・従業員の個人情報、とくにマイナンバー・口座情報を預けている外部サービスを数え、 それぞれについて「預けたデータを分析や運用のために別のツールへ流しているか」を質問票に加えて確認する。 本件のサービスを使っている場合は、ApplyNow からの案内を待たず、自社の対象者の範囲と 当局への報告の要否を自ら確認する
  • 件数が確定しなくても2日で出せる——対象項目と対象外の範囲を示す初報は、対象者の役に立つ
    ApplyNow は検知から2日で、件数は調査中のまま、サービス別の項目・期間・対象外の範囲 （ファイル実体と面接動画）を示して公表した。マイナンバーを含む事案で、対象者が不審な連絡に 身構える時間を作った
    取るべき行動 自社の公表の雛形に「件数が未確定でも出す」ための欄（対象サービス・項目・期間・対象外と確認できた範囲・ 二次被害の確認状況）を用意し、件数の確定を公表の条件にしない判断基準を事前に決めておく
  • 侵入から検知まで約1か月——分析ツールの利用ログは監視の対象から漏れやすい
    不正アクセスが確認された期間は8月9日から9月7日までで、検知まで最大で29日あった。 分析ツールは本来、大量のデータを読むことが仕事なので、攻撃者の読み出しが平常の利用に紛れやすい
    取るべき行動 監視の対象一覧に分析ツール・BI の問い合わせログが入っているかを確認する。 入っていなければ、まずマイナンバー・口座情報などの重い列を含む表への参照だけでも警報にする
セキュリティ技術者への示唆
  • 分析ツールに本番データベースを直に読ませない——複製や、重い列を除いた分析用の置き場に接続させる
    本件では分析ツールを経由して、3サービスのデータベース内のデータにまとめて到達された。 ツールが読める範囲がそのまま被害の範囲になる
    取るべき行動 分析ツールの接続先を本番の主データベースから読み取り専用の複製、または個人を特定できる列を除いた 分析用のデータ置き場に切り替える。マイナンバー・基礎年金番号・口座情報など分析に不要な列は、 接続アカウントの権限で参照不可にする
  • 分析ツールはインターネットに出さない——出すなら認証基盤の後ろに置き、到達元を絞る
    本件のツールが外部から到達可能だったかは公表されていないが、BI・分析ツールの脆弱性は 外部から直接到達できる設置で悪用されやすい（本記録の一般的な整理）
    取るべき行動 外部からの走査で、自社の分析ツール・BI の管理画面やログイン画面がインターネットから見えていないかを確認する。 見えていれば、VPN・ゼロトラストの接続基盤・送信元の IP 制限の後ろに移す
  • 分析ツールの接続アカウントと問い合わせを監視する——大量の読み出しと通常外の表への参照が侵害の兆候になる
    同社の検知は「異常なアクセスログ」によるが、検知まで最大で約1か月を要した。 分析ツールの接続アカウントは権限が広く、使われ方の平常時の姿を測っていないと異常に気づけない
    取るべき行動 データベース側で分析ツールの接続アカウントの問い合わせログを取り、1日あたりの読み出し行数と 参照する表の平常時の分布を測る。そこから外れた読み出しと、重い列を含む表への参照を警報にする
  • 修正版を当てるときは、当てる前に入られていないかを確かめる工程を一緒に行う
    本件では修正版の適用は検知の後になった。修正版が悪用の前から出ていたかは公表されていないが、 一般に、勧告が出てから適用までの間に侵入されている例は多い（本記録の一般的な整理）
    取るべき行動 脆弱性対応の手順に「修正版の適用」と「適用前の期間のログで悪用の痕跡を探す」を1組の作業として書き、 分析ツール・BI にもこの手順を適用する
  • SaaS との連携に使う API キーやトークンは、委託先が破られたら自社で失効させる
    Interview Cloud の企業ユーザー情報には「外部連携情報」が含まれる。中身は公表されていないが、 連携用の資格情報が含まれていれば、パスワード変更だけでは連携先を守れない
    取るべき行動 外部 SaaS に発行している API キー・OAuth トークン・Webhook の署名鍵を一覧にし、 委託先の侵害時に失効・再発行する手順と所要時間を確認しておく。本件のサービスと連携している場合は、 連携用の資格情報を再発行する
法務・コンプライアンスへの示唆
  • マイナンバーを扱わせる委託では、委託先が内部で使う外部ツールの扱いまで契約で押さえる
    本件の ApplyNow Sign はマイナンバーを含む契約者情報を保持しており、同社が使うデータ分析ツールから 到達された。委託元は委託先に対する監督の責任を負う（本記録の整理。個別の企業の法的な評価ではない）
    取るべき行動 マイナンバーや口座情報を扱う委託契約について、委託先が別の外部サービス・ツールでデータを扱う場合の 事前の承認、事故時の通知期限、対象件数の報告、本人通知の分担の条項があるかを棚卸しする

自組織に当てはまるか

該当する項目があれば、この事案と同じ構図が自組織でも成立しうることを意味します。
観点自社に当てはまるか該当する場合に何が起きうるか
システム構成□ 本番データベースに BI・データ分析ツールを直接接続しており、そのツールの接続アカウントが複数サービスの表をまとめて読める本件では分析ツールを経由して、3サービス分のデータに到達された。 ツールが読める範囲がそのまま被害の範囲になる
データの保持□ 分析ツールから、マイナンバー・基礎年金番号・金融機関口座情報など分析に不要な重い列が参照できる（列の除外や伏せ字が無い）本件で最も重い被害は、電子雇用契約の契約者情報に含まれるマイナンバー・基礎年金番号・口座情報である。 分析に使わない列が分析ツールから見えていなければ、この区分は対象から外れた可能性がある
委託・第三者部品□ 採用管理・録画面接・電子雇用契約などの外部サービスに、応募者や従業員の個人情報、とくにマイナンバーや口座情報を預けている利用企業から見れば、本件は委託先の分析ツールから自社の応募者・従業員の情報が漏れた事案である。 委託先が内部でどんなツールを使っているかは、通常の委託先評価では見えにくい
運用・監視□ 分析ツール・BI の問い合わせログを取得していない、または監視の対象一覧に入っていない本件では不正アクセスが確認された期間の始まりから検知まで最大で29日あった。 分析ツールの大量の読み出しは平常の利用に紛れやすい
認証・認可□ 外部 SaaS と API キー・OAuth トークンで連携しており、委託先の侵害時に失効・再発行する手順が決まっていない本件では Interview Cloud の「外部連携情報」も漏えいの可能性がある項目に含まれた。 連携用の資格情報であれば、パスワード変更だけでは連携先を守れない
体制・契約□ 分析ツール・BI が資産台帳に載っておらず、開発元の勧告を誰が追って修正版を当てるかが決まっていない本件は分析ツールの脆弱性が入口で、修正版は検知の後に適用された。 顧客向けでないツールは台帳と脆弱性管理から漏れやすい
