INC-2026-0119IDScan の顧客クラウドで免許証情報が流出か

米ルイジアナ州の本人確認サービス IDScan（IDScan.net）の顧客クラウドから、氏名・運転免許証番号・その他の政府発行 ID 番号を含む顧客情報が閲覧・複製された「可能性」——ダークウェブの「Nexus」が米加の運転免許証スキャン1億5,300万件超（ほか ID カード1,000万件・渡航文書300万件・医療カード57.9万件）の検索を売っていたと Brian Krebs が9月1日に報じてデータを IDScan に辿り、同社は9月4日付の告知（検索に出ない設定）で認めた。影響人数・侵入経路・侵害の期間・画像が含まれるかは公表されていない

不正アクセス・侵害続報が続いている有名事象として記録（日本と直接の関係は薄い）公表されていない／不明
初報: 2026年9月1日 最終更新: 2026年9月10日

米ルイジアナ州の本人確認サービス IDScan（IDScan.net） は2026年9月4日付の告知で、9月1日ごろに「一部のデータが許可なくアクセスされた可能性を示す情報を受け取った」と公表しました。調査は継続中としつつ、「権限のない第三者が、IDScan.net クラウド上の顧客のアカウント内に保存された顧客情報にアクセスし、または複製した可能性がある」（原文英語）と認め、対象の情報に氏名と運転免許証番号その他の政府発行 ID の番号が含まれうるとしています。影響を受けた可能性のある個人への告知と、与信監視・身元保護サービスの無償提供を案内しました。告知ページは検索エンジンに載せない設定（robots の noindex, nofollow）で置かれており、TechCrunch が9月10日に見つけて報じるまで広く知られていませんでした。

発端は IDScan 自身の検知ではありません。独立系のセキュリティ記者 Brian Krebs（KrebsOnSecurity） は8月31日に情報源から、ロシア語圏の犯罪フォーラム Exploit で広告されていた身元情報の検索サービス「Nexus」を知らされました。Nexus は 米国・カナダの運転免許証1億5,300万件超、ID カード1,000万件超、渡航文書300万件超、医療カード57.9万件以上、北米の1億7,000万人超の身分証スキャンを持つと称していました。Krebs は自分の免許証の記録（表裏の画像3組、うち赤外線と紫外線の版を含む6ファイル）を確認し、IDScan の技術が赤外線・紫外線で身分証を読むことなどから出所を IDScan に辿って9月1日に報じました。同日に FBI ニューオーリンズ支局が捜査を開始し、公開の直後に Nexus のサイトは消えました。

件数は攻撃者（Nexus）の主張で、身分証のスキャンの件数であって人数ではありません。 IDScan は影響人数を公表しておらず、告知は画像（身分証のスキャン）に触れていません。Nexus の広告は「1年以上にわたって新しいデータを継続的に持ち出してきた」（原文英語）と称しましたが、IDScan は侵害の期間も侵入経路も明らかにしていません。告知の「情報への完全なアクセスには支払いが必要だったが」（原文英語）という一文の意味も説明されていません。ルイジアナ州の連邦地裁には少なくとも4件の集団訴訟（案）が起こされています。

日本との直接の関係は薄いものの、本人確認（eKYC・身分証スキャン）の事業者に多数の事業者の身分証画像が集約される構造が、現実に1億件規模の流出として表面化した先例として記録します。本記録は IDScan の告知（一次公表）とKrebs の調査、報道から確認できた範囲を整理し、公表されていない点は未確定事項に残します。

ここからは本記録の評価である。

本件の構図は、個々の店（レンタカー・小売・大麻販売店・銃砲店・宿泊）が自社の本人確認のために行ったスキャンが、1つの本人確認事業者のクラウドに顧客アカウントごとに蓄積されていたことにある。店にとって本人確認はその場で済む手続きだが、画像と項目は事業者のクラウドに残り、多数の店の分がまとまって1つの攻撃面になった。Nexus が称した件数が正しければ、1社の侵害が北米の成人のかなりの割合に及ぶ規模になる。

身分証の番号や画像は、パスワードと違って変えられない。免許証は更新まで同じ番号と顔写真で使われ、表裏の画像と赤外線・紫外線の画像がそろえば、なりすましの口座開設や、画像を提出させる形の本人確認を通す材料になりうる。本人にできることは信用凍結と監視にとどまる。

日本に当てはめると、次の2点が要る。

  1. eKYC・本人確認の委託先に画像が集まっていないか。 犯罪収益移転防止法の特定事業者（金融機関・暗号資産交換業者など）や携帯電話事業者、古物商、宿泊施設などは、本人確認を外部の eKYC サービスやスキャン機器に任せていることが多い。委託先が画像を検証後も保存しているなら、本件と同じ集約が起きている。
  2. 法定保存と「画像を持つこと」を分けて考えているか。 犯収法は確認記録を取引終了日等から7年間保存するよう求めている。確認記録に本人確認書類の写し（画像）を添えて保存する運用では、7年分の画像が1か所にたまる。保存が要るのは確認記録であり、画像を持つことが常に必要とは限らない。法令の要件を法務と確かめたうえで、画像を持たない・持つなら分けて守る設計にする余地がある。2027年4月1日施行の犯収法施行規則の改正で、非対面の本人確認で券面画像を送る方式が原則廃止され IC チップの読み取り等へ移ることも、画像を持たない方向を後押しする（制度の詳細は原典で確認されたい）。

もう一つの論点は公表の作法である。検索に出ない設定の告知と「可能性」の表現は、法的な通知義務を満たしつつ注目を抑える選択として理解できるが、本人が自分で気づく経路を狭める。本件では記者・犯罪市場・訴訟が先に動き、当事者の告知は後から見つけられた。自社が同じ立場になったときに、どこに・どの表現で出すかは事前に決めておく必要がある。

CISO・経営層への示唆
  • 本人確認を外部に任せていても、身分証の画像は委託先のクラウドに残り、多数の委託元の分がまとめて1つの攻撃面になる
    本件では個々の店のスキャンが IDScan のクラウドに顧客アカウントごとに蓄積され、1社の侵害が1億件規模の流出として 現れた（件数は攻撃者の主張）。委託元から見れば「その場で済んだ本人確認」の画像が、委託先に残り続けていた
    取るべき行動 eKYC・身分証スキャンの委託先に、保存している項目（画像の種類を含む）・保存期間・保存場所・削除の方法と証跡を 質問票で確認し、答えを契約の別紙に書かせる。「検証後に画像を保存しない」設定があるなら既定にさせる
  • 法定保存（犯収法の確認記録の7年保存）と「画像を持つこと」は別であり、分けて設計すれば7年分の画像を1か所にためずに済む
    身分証の番号と画像は変えられず、漏れた影響は長く続く。確認記録に写しを添える運用では、保存期間の分だけ画像が たまり、本件のような集約の標的になる（本記録の評価。日本の制度の整理は本記録の作成者の理解に基づく）
    取るべき行動 法務と、確認記録として保存が必須の項目と、画像の保存が法令上必要かを確かめる。必須でなければ画像を削除または 保存しない設計にし、必要なら確認記録と画像を別の保管庫・別の鍵で守り、閲覧を記録する。非対面の本人確認を IC チップの読み取り等へ移す計画と合わせて見直す
  • 委託先の侵害でも、訴えられ名前が出るのは委託元である
    本件の訴訟は、原告が利用した店が IDScan を使っていたことを根拠にしており、Hertz の名前が挙がった。 一方で IDScan のサイトに顧客として載っていた Caesars は関係を否定した。委託先の顧客一覧に自社名が載ること 自体が、侵害時の巻き込まれ方を左右する
    取るべき行動 委託先が侵害されたときの通知の分担（誰が本人に知らせるか）、費用負担、訴訟への協力、自社名を顧客一覧に 載せる条件を契約で決める。利用をやめた委託先には、自社名の掲載の取り下げとデータの削除証明を求める
  • 発覚は自社の監視より先に、記者・犯罪市場・訴訟から来ることがある。その前提で初動を用意する
    本件は情報源が記者に知らせ、記者が報道し、FBI が捜査を始め、訴訟が起きたあとに当事者の告知が見つけられた。 当事者の説明が無い間に攻撃者側の数字が広まった
    取るべき行動 外部から「御社のデータが売られている」と知らされたときの窓口・確認手順・初動の声明文の雛形を用意する。 自社名と主要な委託先名で、犯罪フォーラム・流出データ市場の監視を契約する
  • 検索に出ない告知と「可能性」だけの表現は、義務を果たしても信頼を失う
    IDScan の告知は noindex の指定付きで置かれ、報道がそれを見つけて伝えた。画像・人数への言及も無かった
    取るべき行動 自社の公表手順に「告知は検索できる場所に置く」「確認した事実・未確認の事実・調査中の事項を分けて書く」を入れ、 公表前の確認項目にする
セキュリティ技術者への示唆
  • 検証が済んだ身分証の画像、とくに赤外線・紫外線などの検証用の画像は、保存しないか短期で消す
    Krebs の記録には通常・赤外線・紫外線の画像がそろっていた。これらは真贋判定には要るが、判定が済めば業務上の 用途は乏しく、残っていればなりすましの材料になる
    取るべき行動 本人確認の処理で、判定結果と必要な項目だけを保存し、画像は判定後に削除する流れにする。保存が必要な場合は 保存期間を設定して自動で消し、削除の記録を残す。委託先のサービスなら、その設定を確認して有効にする
  • テナント（顧客アカウント）・API キーごとの読み出し量を監視し、平常から外れた大量取得を検知する
    攻撃者は1年以上・1日数十万件の継続的な持ち出しを称し、Krebs は24時間で40万件近い増加を観測した。 主張が正しければ、量の異常として現れていたはずである
    取るべき行動 テナントごと・資格情報ごとの取得件数と転送量のベースラインを取り、急増や、普段は画像を取らない資格情報による 画像の一括取得を警報にする。1資格情報あたりの取得量に上限を設ける
  • 顧客アカウントへのアクセスは、事業者側の既定で多要素認証と接続元の制限をかける
    経路は非公表だが、対象が「顧客のアカウント内」の情報とされた以上、顧客アカウントの資格情報は侵入経路の 候補の一つになる（本記録の評価）。顧客任せの設定では、最も弱い顧客が全体の入口になる
    取るべき行動 マルチテナントの管理画面と API で、多要素認証を無効にできない既定にし、API キーには接続元 IP・有効期限・ 権限範囲を必須にする。新しい端末・接続元からのアクセスを顧客に通知する
  • 合成の身分証レコード（カナリア）を本人確認データに混ぜ、外部での出現を監視する
    本件は記者が自分の記録を市場で見つけたことから出所が特定された。自社で同じ仕掛けを持てば、外部より先に 流出と出所の範囲に気づける
    取るべき行動 テナントごとに識別できる合成レコード（実在しない氏名・番号）を保存領域に置き、流出データの監視サービスや 検索でその値の出現を監視する。出現したテナントから経路を絞り込む
  • 誰がいつ何を読んだかを答えられるログを、テナント横断で残す
    IDScan は閲覧・複製を「可能性」としか書けておらず、人数も期間も示していない。ログが無ければ範囲を 絞れず、最悪の場合を前提に説明せざるをえない（本記録の評価）
    取るべき行動 保存領域への読み出し（画像の取得を含む）を、資格情報・接続元・件数とともに記録し、保存領域とは別の場所に 1年以上保全する。侵害時に露出期間のログから対象の本人を特定する手順を用意する
法務・コンプライアンスへの示唆
  • 本人確認の委託先の侵害では、法令上の保存義務を持つ委託元が、保存の必要性と委託先の管理を説明する立場に置かれる
    本件の訴訟は利用した店と IDScan の関係を根拠にしている。日本でも犯収法の特定事業者は確認記録の保存義務を 負い、委託しても責任は残る（本記録の評価）
    取るべき行動 確認記録の保存方法（画像の要否・保存場所・委託先）を法務が把握し、個人情報保護法の委託先の監督の記録と 合わせて説明できる形にしておく
