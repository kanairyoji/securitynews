INC-2026-0144さくらさくみらい、委託先からサーバPWの流出可能性

保育園を運営するさくらさくみらいが、委託先のクラウドサービス事業者から「不正アクセスを受けた可能性のある環境に、貴社が利用するサーバのパスワードが保存されていた」と8月31日に連絡を受けた——対象は2017年までのメールサーバのバックアップ環境とドメインを管理する DNS サーバで、悪用されればメールの不正閲覧・自社ドメインを騙るなりすまし送信・Web サイトから悪意あるサイトへの誘導が起こりうる。同社はメールアカウント164件のパスワードを独自に変更し、不正な設定変更が無いことを確認して9月7日に公表した。委託先の名称と不正アクセスの詳細は公表されていない

委託先・再委託先起因で委託元多数に波及初報のみ日本の組織が当事者委託先・供給元起因
初報: 2026年9月7日 最終更新: 2026年9月16日

保育園を運営する株式会社さくらさくみらいは2026年9月7日、当社が利用する外部サーバーシステムへの不正アクセスに伴う影響と対応について公表しました。

同社によれば、2026年8月31日に委託先のクラウドサービス事業者から、同事業者のシステムに不正アクセスがあり、さくらさくみらいが契約・利用しているサーバのパスワードが、不正アクセスを受けた可能性のある環境に保存されていた旨の連絡がありました。

対象のサーバは2つです。2017年までのメールサーバのバックアップ環境と、ドメインを管理する DNS サーバ。同社は、パスワードが第三者に悪用された場合のリスクとして、2017年以前の送受信メールの不正閲覧、自社ドメインを悪用したなりすましメールの送信、DNS レコードの改ざんによる自社サイトから悪意のあるサイトへの誘導を挙げています。

委託先はパスワードの強制変更措置を実施し、同社は関連するメールアカウント164件のパスワードを独自に変更、アクセスログを調べて不正な設定変更（DNS レコードの改ざん等）が無いことを確認しました。現時点で二次被害は確認されていません。委託先の名称、委託先で起きた不正アクセスの時期・手口は公表されていません。

本件は、侵害されたのは自社ではないのに、自社のドメインとメールという「対外的な信用の基盤」が危険にさらされた例として記録します。一次資料は同社の公表で、評価・示唆は本記録の判断として分けて書きます。

侵害されたのは委託先で、危なくなったのは自社のドメインとメールだった原因・手口出典 [1] [2]

同社の公表によれば、2026年8月31日に委託先のクラウドサービス事業者から連絡があった。内容は同事業者のシステムに不正アクセスがあり、さくらさくみらいが契約・利用しているサーバのパスワードが、不正アクセスを受けた可能性のある環境に保存されていたというものである。

同社のシステムが直接破られたわけではない。危険にさらされたのは、委託先が預かっていた同社のサーバへ入るための鍵である。対象は次の2つのサーバだった。

  • DNS サーバ（ドメイン管理）

公表文は、パスワードが第三者に不正利用された場合に生じうる影響を具体的に挙げている。メールサーバについては2017年以前の同社の送受信メールの不正閲覧と同社ドメインを悪用したなりすましメールの不正送信。DNS サーバについてはDNS レコードの改ざんによる、同社が運営する Web サイトから悪意のある別サイトへの不正な誘導である。

同社は現在も詳細なログ等の調査を進めているが、現時点で同社のメールや DNS サーバへの不正アクセス、データの改ざん、情報流出等の二次被害は確認されていないとしている。今後は外部委託先のセキュリティ体制を含め、情報管理体制の一層の強化に努めるという。

委託先が握っているのは「データ」だけでなく「自社になりすませる鍵」でもある（本記録の評価）評価・解釈出典 [1]

ここからは本記録の作成者の評価である。

第一に、失われかけたのは情報ではなく、対外的な信用の土台である。 DNS を書き換えられれば、保護者が見に来た保育園のサイトが別のサイトに化ける。ドメインを騙ってメールを出されれば、「保育園からの連絡」として保護者に届く。どちらも同社の中のデータが1件も出ていなくても成立する。委託の棚卸しでは「どんな個人情報を預けているか」を数えることが多いが、ドメインとメールの管理権は、それとは別の軸で最上位に置くべき資産である。

第二に、対応の順番が良い。 委託先が強制変更をしたと聞いた後で「では大丈夫だろう」と止めず、同社は自分の側でも164件を変え、さらに委託先の管理画面のパスワードを変えて二要素認証を確かめている。委託先が侵害された局面で、その委託先の管理画面に入るための認証をどう扱うかは見落とされやすい。加えて、DNS レコードの改ざんが無いことをログで確認している。「相手が対応したから終わり」ではなく、自分の側で確かめられることを確かめた形になっている。

第三に、2017年までのバックアップという残り方が効いている。 対象は現役のメールサーバではなく、9年前までのバックアップ環境だった。日々の運用からは見えないが、中身は当時のやり取りそのものである。保育園の運営事業者であれば、保護者や自治体とのやり取りが含まれていても不思議はない。公表文はその中身に触れておらず、影響の重さは外から測れない。使わなくなったバックアップを「消していないだけ」で置き続けることの代償が、委託先の侵害という自分では選べない形で現れた。

第四に、委託先の名前が無いことの副作用がある。 同じ事業者を使う他の組織は、この公表を読んでも自社が対象かを判断できない。当事者としては取引先を名指ししにくい事情があるが、結果として業界全体の自衛が遅れる。名前を出さないなら、せめて「該当する事業者から連絡を受けた組織は同様の確認を」と呼びかける形があってよい。

layer 0 は委託先に不正アクセスを行った者。layer 1 は委託先のクラウドサービス事業者と、 そこに保存されていたさくらさくみらいのサーバパスワード。layer 2 は影響範囲に入った2つのサーバ。 layer 3 は悪用された場合に生じうる3つの結果（いずれも発生は確認されていない）。 layer 4 は委託元であるさくらさくみらいの対応。委託先の名称と不正アクセスの詳細は公表されていない。

どこで止められたか

段階ごとに検知の機会があったか、どの対策があれば効きえたかを整理したものです。「効きえた対策」は本記録の評価であり、当事者が述べたものではありません。
段階検知の機会効きえた対策
初期侵入公表されていない
委託先がいつ・どのように検知したかは公表されていない。委託元であるさくらさくみらい側に 検知の機会は無かった
影響を限定できた委託先の選定・更新時に、認証情報の保管方式と侵害時の通知条件を確認する
影響を限定できたドメイン・DNS の管理を、他の業務と同じ委託先へまとめず分離する
認証情報アクセス現実的な検知機会なし
委託先の環境内でのパスワードの保管状況は、委託元からは見えない。 事前に確認しうるのは契約・監査の段階であり、事後の検知ではない
侵入を防げたサーバ・DNS の管理アカウントに二要素認証を設定する　同社は事後に委託先の管理画面の二要素認証を再確認している
影響を限定できた管理用の認証情報を定期的に更新し、委託先に預ける鍵の有効期間を短くする
影響（暗号化・破壊・改ざん）検知した
同社はアクセスログ等を調査し、DNS レコードの改ざん等の不正な設定変更が無いことを確認した。 ログの保管期間と調査の範囲は公表されていない
検知できたDNS レコードの変更を監視し、意図しない変更に警報を出す（レジストラロックの併用）
影響を限定できた自社ドメインに SPF・DKIM・DMARC を設定し、なりすまし送信を拒否・監視する
影響を限定できた使わなくなったメールのバックアップを保存期間の規程に沿って削除する

対応の評価

評価材料がない判断は「評価材料なし」としています。結果論で断じないための区分です。
判断評価評価の根拠と留保
委託先によるパスワードの強制変更に加えて、自社でも関連するメールアカウント164件と 委託先の管理画面のパスワードを独自に変更した機能した本記録の作成者の評価である。委託先が対応したという報告で止めず、自社の管理範囲でも鍵を入れ替え、 さらに委託先の管理画面の二要素認証まで確かめている。委託先起因の事案での対応として過不足が少ない
委託先の名称を伏せたまま、対象サーバの用途と想定されるリスクを具体的に示して公表した部分的に機能本記録の作成者の評価である。リスクを「なりすましメール」「DNS 改ざんによる誘導」と 具体的に書いた点は読者に伝わる形だが、委託先が不明なため波及の全体像は外から追えない
CISO・経営層への示唆
  • 委託先に預けているのは「データ」だけでなく「自社になりすませる鍵」だと認識する
    今回危険にさらされたのは DNS とメールの管理権で、悪用されれば同社のサイトとメールを 第三者が名乗れる状態になる
    取るべき行動 委託先の一覧に、預けている個人情報の種類だけでなく「ドメイン・DNS・メール・証明書の管理権を 持たせているか」の列を追加し、持たせている先には最も高い要求水準を当てる
  • 委託先が「対応済み」と言ってきても、自社の側で確かめられることを確かめる
    同社は委託先の強制変更を受けたうえで、自社でも164件を変更し、DNS の設定変更が無いことを ログで確認した
    取るべき行動 委託先起因の事案の手順書に「委託先の措置とは別に自社が行う確認」を明記する。 最低限、自社が保有する認証情報の入れ替え、管理画面の認証の見直し、設定変更の有無の確認を入れる
  • 使っていないバックアップの保存期間を決め、棚卸しの対象に入れる
    影響対象の1つは「2017年までのメールサーバのバックアップ環境」で、9年前の通信がそのまま残っていた
    取るべき行動 メール・ファイルのバックアップについて、保存期間と削除の責任者を規程に書き、 委託先に置いたまま忘れている環境が無いかを年1回棚卸しする
  • 委託先を名指ししない公表でも、読者が自衛できる材料を残す
    委託先の名称が無いため、同じ事業者を使う他の組織は自社が対象かを判断できない
    取るべき行動 取引上の事情で事業者名を出せない場合でも、「同種の連絡を受けた組織が確認すべき項目」を 公表文に添える。自社の利用者（保護者・取引先）向けには、なりすましメールへの注意を明示する
セキュリティ技術者への示唆
  • DNS の変更を監視し、鍵を持つ相手を最小にする
    DNS サーバのパスワードが影響範囲に含まれ、改ざんされれば自社サイトから悪意あるサイトへ 誘導される状態だった
    取るべき行動 権威 DNS のレコードの変更を検知する監視を入れ、レジストラのロック機能を有効にする。 DNS の管理アカウントを他の業務と共用せず、二要素認証を必須にする
  • 自社ドメインのなりすまし対策を、事故の前に設定し終えておく
    想定されたリスクの1つが「自社ドメインを悪用したなりすましメールの不正送信」だった
    取るべき行動 SPF・DKIM・DMARC を設定し、DMARC のポリシーを監視から拒否へ段階的に上げる。 レポートで自社ドメインを騙る送信の有無を継続して確認する
  • 委託先に預けた認証情報の一覧を持ち、一斉に入れ替えられるようにしておく
    同社は連絡を受けてから、関連するメールアカウント164件のパスワードを独自に変更している
    取るべき行動 外部に預けているサーバ・管理画面・API の認証情報を一覧化し、 「委託先で侵害が起きたとき何時間で全部入れ替えられるか」を実際に測っておく
  • 古いバックアップ環境を稼働資産と同じ台帳に載せる
    2017年までのメールのバックアップ環境が、現役の運用から外れたまま影響範囲に入っていた
    取るべき行動 監視・パッチ・認証の対象一覧に、バックアップ環境・旧環境を含める。 載せられないものは削除の候補として期限を決める

自組織に当てはまるか

該当する項目があれば、この事案と同じ構図が自組織でも成立しうることを意味します。
観点自社に当てはまるか該当する場合に何が起きうるか
委託・第三者部品□ ドメイン・DNS・メールの管理を外部の事業者に委ね、管理用の認証情報を相手側に預けている本件で影響範囲に入ったのは、まさにその認証情報だった
認証・認可□ 外部サービスの管理画面に二要素認証を設定していない、または設定状況を定期的に確認していない同社は事後に委託先の管理画面のパスワード変更と二要素認証の再確認を行っている
データの保持□ 使わなくなったメール・ファイルのバックアップを、保存期限を決めずに委託先に置いている影響対象の1つは2017年までのメールサーバのバックアップ環境だった
運用・監視□ DNS レコードの変更を監視しておらず、改ざんされても気づく仕組みが無い想定されたリスクの1つが DNS 改ざんによる悪意あるサイトへの誘導だった
体制・契約□ 委託先で侵害が起きたときに自社が行う確認手順が、文書として決まっていない委託先の措置だけに委ねると、自社の側で確かめた根拠が残らない
委託・第三者部品□ 委託契約に、侵害時の通知の期限と提供される情報の範囲が書かれていない本件では8月31日に連絡があったが、委託先での発生時期は最後まで示されていない
