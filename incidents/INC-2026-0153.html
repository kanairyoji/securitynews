INC-2026-0153Admin Menu Editor Pro の配布元が乗っ取られる

WordPress の有償プラグイン Admin Menu Editor Pro の配布元サイトが乗っ取られ、Web シェルと隠しユーザーを仕込むバージョン 2.35 が正規の更新として配られた——開発者が同日中にクリーンな 2.36 を出し直したが攻撃者はサーバへのアクセスを保持しており、その 2.36 も汚染された。更新サーバのログ解析で約230顧客・少なくとも1,500サイトへ導入されている。有償プラグインは WordPress.org の審査を経ず開発者サイトから直接配布されるため、公式リポジトリ側の対策では覆われない経路である

委託先・再委託先起因で委託元多数に波及続報が続いている有名事象として記録（日本と直接の関係は薄い）委託先・供給元起因公表されていない／不明
初報: 2026年9月15日 最終更新: 2026年9月17日

WordPress プラグイン Admin Menu Editor の開発者 Janis Elsts は2026年9月14日、有償版の配布元サイト adminmenueditor.com が第三者に侵入され、悪性のバージョン 2.35 がPro 版の更新として配布されたことを公表しました。

悪性版は includes/wp-user-consent.php を通じてサイトに Web シェルを設置し、管理画面から見えない隠しユーザーを作成します。悪性の 2.35 が配布されていたのは同日のおよそ 06:00〜13:00（UTC）。開発者は侵入に気づいて更新を削除し、19:00（UTC）にクリーンな 2.36 を公開しました。

ところが攻撃者はまだサーバへのアクセスを保持しており、その 2.36 も汚染されました。開発者は約19:35（UTC）に2度目の侵害を検出し、約21:40（UTC）にサーバをオフラインにしています。攻撃者はサーバの root 相当のアクセスを得ていたとみられるとのことです。

更新サーバのログ解析では、約230顧客・少なくとも1,500サイトに悪性版が導入されました。該当時間帯の前後にダウンロードした顧客が数百おり、実際の被害はこれより大きい可能性があります。無償版（30万サイト超で利用）は影響を受けていないとされ、2.34 以前はクリーンと見られています。

本記録が重視するのは経路です。有償プラグインは WordPress.org の審査を経ず、開発者のサイトから直接配布されます。 公式リポジトリ側でどれだけ配布前の審査を強化しても、この経路は覆われません。一次資料は開発者の advisory で、評価・示唆は本記録の判断として分けて書きます。

ただし、Web シェルが動いた後のサイトを「取り除いて元に戻した」と言い切ることはできない（本記録の評価）。隠しユーザーと MU-plugins と Cron の3系統に痕跡を置く作りである以上、ほかにも仕込みが残っている前提で扱うのが安全である。

クリーン版を出し直しても止まらなかった——「配布物の差し替え」だけでは足りない組織の対応出典 [1] [2]

この事案でもっとも実務的な教訓は、19:00 の 2.36 公開が失敗した点にある。

開発者は侵入に気づいて悪性版を削除し、クリーンなビルドを出し直した。普通の対応である。しかし攻撃者はサーバの root 相当のアクセスを保持していたため、置いた直後の 2.36 も汚染された。2度目の侵害の検出（約19:35）まで35分、サーバのオフライン化（約21:40）までは2時間40分である。

配布元が侵害されたときの初動は「差し替え」ではなく「配布の停止」である（本記録の評価）。攻撃者の足場が残っているかどうかを確かめる前に新しい成果物を置けば、それも汚染される。本件は、その順序を誤るとどうなるかを時刻つきで記録した数少ない事例である。

オフライン化以降の対応は速い。約17時間後に静的ページで advisory を出し、その4時間半後に顧客への通知メールを送り始めている。再構築が終わるまで販売・更新確認・ダウンロードを止めたまま情報だけを出すという判断も明確である。

有償プラグインは公式リポジトリの審査を通らない——WordPress.org 側の対策では覆われない評価・解釈出典 [1] [2]

ここからは本記録の作成者の評価である。

第一に、配布経路が公式リポジトリの外にある。 WordPress の有償プラグインは、WordPress.org の審査や配布の仕組みを経由せず、開発者のサイトから直接配られ、更新も開発者の更新サーバから配信される。公式リポジトリ側で配布前の自動審査を強化しても、この経路は覆われない。利用者から見れば、管理画面に出る「更新があります」の表示は公式版も有償版も同じに見える。

第二に、更新の自動適用が攻撃の配送手段になっている。 WordPress 界隈では「プラグインは常に最新に保て」が基本の助言であり、自動更新を有効にしている運用も多い。本件ではその助言に従っていたサイトほど早く感染した。推奨の運用と被害の関係が逆転する類型であり、単純に「更新を止めろ」とも言えない。現実的な緩和は、更新の適用を数日ずらす、管理画面のユーザー一覧とファイルの変化を監視するの2点に絞られる。

第三に、個人開発者が単独で持つ配布基盤は、供給網の単一障害点になる。 300,000サイトに入るプラグインの更新サーバが、1人の開発者のサイトである。これは WordPress に限らず、npm・PyPI・RubyGems の個人メンテナと同じ構造である（本DB INC-2026-0121 の RubyGems 事案も、レジストリ側の運用の薄さが背景にあった）。利用する側は「誰が配っているか」を把握し、その主体が侵害されたときに自社がどう気づくかを決めておく必要がある。

第四に、日本の制作会社には他人事ではない。 国内の Web 制作では、有償プラグインを含む構成で納品し、その後の保守を年契約で続ける形が一般的である。納品先のサイトで9月14日前後に更新が走っていた場合、制作会社が検知の責任を負う。国・地域別の内訳は公表されていないため、自社の納品物を1件ずつ確認するしかない。

侵入経路・2.36 の被害数・Web シェルの使われ方・顧客データへの影響は公表されていない未確定事項出典 [1] [2]

2026年9月17日時点で、次の点は公表されていない。

  • adminmenueditor.com への侵入の経路（root 相当のアクセスを得ていたとみられる、とのみ）
  • 汚染された 2.36 を導入した顧客数・サイト数（開発者は判断が難しいとしている）
  • 設置された Web シェルを通じて実際に行われた操作
  • 攻撃者の目的・帰属
  • ライセンスキーや購入情報など、顧客データへの影響
  • 日本国内での導入サイト数と影響
