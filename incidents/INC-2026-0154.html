INC-2026-0154ScreenConnect の認可不備が実際に悪用される

遠隔支援ツール ConnectWise ScreenConnect のクライアントに権限管理と認可の不備（CVE-2026-84869・CVSS 9.9）があり、基本的な権限しか持たない攻撃者が、進行中の遠隔セッションを通じて操作対象の端末へファイルを転送し実行できる——ホスト側の確認も利用者の操作も要らない。米 CISA は2026年9月11日に KEV へ収載して連邦機関に3日以内の対処を命じ、Shadowserver は未修正のまま露出する1,000台超を追跡している。Huntress は8月下旬から、不正に導入された ScreenConnect が接続先の端末へスクリプトを広げるワームに近い挙動を観測していた

脆弱性続報が続いている有名事象として記録（日本と直接の関係は薄い）設計・実装上の不備権限管理の不備
初報: 2026年9月8日 最終更新: 2026年9月17日

ConnectWise ScreenConnect の遠隔支援クライアントに、権限管理の不備と認可の欠落が重なった脆弱性 CVE-2026-84869（CVSS 9.9） があり、実際に悪用されています。

米 CISA の記述によれば、この脆弱性は「進行中の遠隔セッションを通じて、認可もホストの確認もなしにファイルを転送し実行することを攻撃者に許しうる」ものです（原文英語）。基本的な権限しか持たない攻撃者が、利用者の操作なしに、低い複雑度で成立します。

経過は速い。ConnectWise は2026年9月3日に「ファイル転送の挙動」に関する advisory を出してTransferFiles 権限の無効化を暫定の緩和として案内し、9月8日に CVE を割り当てて26.6.5 で修正しました。米 CISA は9月11日に KEV へ収載し、連邦民間行政機関に9月14日まで（3日）の対処を命じています。Shadowserver は未修正のまま露出する1,000台超（北米758台・欧州180台）を追跡しています。

背景として重要なのは、この脆弱性が先に「使われて」から見つかったことです。Huntress は2026年8月20日以降、複数の無関係な組織で不正に導入された ScreenConnect が接続先の端末へ VBScript を広げる、ワームに近い挙動を観測していました。遠隔支援ツールは管理経路として正規に許可されるため、侵入後の横展開で最も摩擦が少ない道になります。

日本国内の被害は本記録の作成時点で確認できていませんが、MSP と情報システム部門の保守経路という適用範囲は国内でも同じです。一次資料は CISA KEV と ConnectWise の bulletin、観測の一次情報は Huntress のブログで、評価・示唆は本記録の判断として分けて書きます。

進行中の遠隔セッションを通じて、認可もホストの確認もなしにファイルを転送・実行できる概観出典 [1] [2] [4]

CISA の KEV カタログの記述は次のとおりである（原文英語）。

ConnectWise ScreenConnect には、不適切な権限管理（improper privilege management）と認可の欠落（missing authorization）の双方の脆弱性が存在し、進行中の遠隔セッションを通じて、認可もホストの確認もなしにファイルを転送し実行することを攻撃者に許しうる。

整理すると次のようになる。

  • 対象は ScreenConnect のクライアント（Client Support / Access セッション）。サーバは影響を受けない
  • 基本的な権限を持つ攻撃者が、利用者の操作なしに、低い複雑度で成立する
  • 影響を受けるのは 26.6.5 より前のバージョン。修正版は 26.6.5
  • 暫定の緩和は TransferFiles 権限の無効化（Administration > Security > Roles。旧版では TransferFilesInSession）
  • CVSS は 9.9
  • クラウド版のインスタンスは自動で更新される。オンプレミス版は手動更新で、修正の適用後はホストのクライアントの再インストールと Access エージェントの更新が要る

CISA は2026年9月11日に KEV へ収載し、期限を9月14日に設定した。収載時の分類では、ランサムウェアキャンペーンでの利用は「Unknown」、フォレンジック調査の要件の対象は「Yes」である。

3日という期限が付いた——KEV の通常の猶予より短い当局対応出典 [1]

CISA の KEV データを見ると、収載日が2026年9月11日、期限が2026年9月14日である。

KEV の期限は通常3週間程度に置かれることが多い。3日という設定は、「すでに悪用が進行しており、いま入られている可能性が高い」という判断の表れである（本記録の評価）。あわせて、BOD 26-04 のフォレンジック調査の要件の対象に指定されている。これは「更新すれば終わり」ではなく、入られていないかを調べることまで求める指定である。

日本の組織に KEV の期限は適用されないが、着手の優先度を決める根拠としては使える。とくに ScreenConnect は、次節のとおり侵入後の横展開に使われる製品である。

先に「使われ方」が観測されていた——8月下旬から、不正導入された ScreenConnect が接続先へスクリプトを広げていた背景・過去事例出典 [3]

Huntress は2026年9月9日のブログで、8月下旬に複数の無関係な組織で観測した一連のインシデントを公開した。以下は Huntress の報告による事実であり、CVE-2026-84869 の悪用と明示されたものではない（本記録の整理）。

  • 発端はいずれも社会工学だった。ある8月20日の事案では、利用者が Windows 標準のQuick Assist を起動させられる典型的なサポート詐欺から始まり、攻撃者が不正な ScreenConnect クライアントを導入した（C2 は 45.13.237[.]190）
  • 同日の別の事案では、フィッシング経由で ScreenConnect.ClientSetup.msi が実行され、131.123.40[.]98 のポート 8041 と通信するクライアントが導入された
  • 導入後、クライアントが wscript.exe を4回起動し、1.vbs〜4.vbs を実行した
  • 永続化は、利用者の AppData 配下の WindowsServiceHost.vbs を指すUser Run キー（WindowsServiceHost） で行われた
  • 一部の事案では UltraViewer も併せて導入されていた
  • もっとも重要な点として、改変された ScreenConnect クライアントが、接続済みのScreenConnect 端末へ4本の VBScript を実行させて伝播しており、新たに接続された端末へ広がるワームに近い挙動を見せていた

Huntress はこの観測を ConnectWise と共有し、9月3日の advisory と9月8日の修正が続いた。「脆弱性が見つかったから悪用が始まった」のではなく、「悪用の観測から脆弱性の公表に至った」という順序である（本記録の評価）。

被害組織・ランサムウェアとの関係・国内の台数はいずれも公表されていない未確定事項出典 [1] [2] [3]

2026年9月17日時点で、次の点は公表されていない。

  • 悪用された組織の名称・国・業種・件数
  • ランサムウェアキャンペーンでの利用の有無（KEV の分類は Unknown）
  • Huntress が観測したワームに近い挙動と本 CVE の関係
  • 日本国内の稼働台数・露出台数・被害の有無（Shadowserver の内訳は北米758・欧州180のみ）
  • 悪用の前提となる「基本的な権限」の具体的な意味
  • 実証コードの公開状況

遠隔支援ツールは「許可された侵入経路」——資産管理から漏れると検知の手がかりが消える（本記録の評価）評価・解釈出典 [1] [2] [3]

ここからは本記録の作成者の評価である。

第一に、RMM は正規の管理経路として許可されているため、侵入後の横展開で最も摩擦が少ない。 EDR の例外設定に入り、プロキシで許可され、管理者が使っていることが前提のプロセスである。Huntress の観測でも、攻撃者は脆弱性を突く前に社会工学で ScreenConnect を導入させるところから始めている。「誰も導入した覚えのない ScreenConnect が社内に無いか」を資産管理から洗い出すのが、パッチ適用と並ぶもう一つの初動である。

第二に、本件はサーバではなくクライアント側の欠陥である。 サーバを更新しても、端末に配られたクライアントが古ければ残る。ConnectWise も修正の適用後にホストのクライアントの再インストールと Access エージェントの更新が必要だと案内している。「サーバのバージョンを上げた」だけで完了と報告すると、実態は未修正のままになる。

第三に、MSP を経由した波及が構造的に起こりうる。 ConnectWise は10万社超の IT 事業者に製品を提供しており、その先に顧客企業の端末がある。1つの MSP のセッションが悪用されれば、その MSP が保守する全顧客の端末が射程に入る。委託先が使う遠隔支援ツールの版数を委託元が把握していないことは珍しくない。

第四に、日本国内の数字が無いことを「該当なし」と読んではいけない。 Shadowserver の内訳に日本が出ていないのは、内訳が公表されていないだけである。国内でも MSP と情報システム部門の遠隔保守で ScreenConnect は使われている。過去の ScreenConnect の脆弱性（CVE-2024-1709）は北朝鮮系の Kimsuky と複数のランサムウェア集団に悪用されており、この製品は継続的に狙われているという前提が要る。

経過

CISO・経営層への示唆
  • 遠隔支援ツールを「許可された侵入経路」として資産管理の対象に据える
    Huntress の観測では、攻撃者は社会工学で ScreenConnect を導入させることから始めており、 RMM は正規の管理経路として許可されるため検知の摩擦が小さい
    取るべき行動 社内で使用を認めた遠隔支援ツールと台数を台帳化し、それ以外の RMM（ScreenConnect・ UltraViewer・AnyDesk・Quick Assist 等）の実行を検知・原則禁止する方針を定める。 「誰も導入した覚えのない」導入の棚卸しを今回の件を機に実施する
  • 委託先・MSP が使う遠隔支援ツールの版数を委託元として把握する
    ConnectWise は10万社超の IT 事業者に製品を提供しており、1つの MSP のセッションが 悪用されればその顧客の端末が射程に入る
    取るべき行動 保守委託先に対し、遠隔支援に使う製品名・版数・更新の方針を定期的に報告させる。 緊急の脆弱性が出たときの連絡経路と着手期限を契約に書く
  • KEV の「3日」と「フォレンジック調査の要件」を、自社の着手条件に翻訳する
    CISA は2026年9月11日の収載に対し9月14日という短い期限を設定し、 フォレンジック調査の要件の対象にも指定した
    取るべき行動 「CISA KEV に載った製品を自社が使っている場合は、更新と侵害調査を並行して着手する」という 条件を文書化し、担当者の判断に依存させない。完了報告に「侵害調査の実施有無」の列を設ける
  • サーバの更新完了を「対応済み」と読まない運用にする
    本件はクライアント側の脆弱性で、修正の適用後にホストのクライアントの再インストールと エージェントの更新が必要である
    取るべき行動 脆弱性対応の完了判定を「影響を受ける構成要素のすべて（サーバ・クライアント・エージェント）」 単位で定義し、台数ベースで残存を追跡する
セキュリティ技術者への示唆
  • ScreenConnect のクライアントプロセスからのスクリプト実行を検知ルールにする
    Huntress は ScreenConnect のクライアントが wscript.exe を起動し、 1.vbs〜4.vbs を実行するパターンを複数の組織で観測した
    取るべき行動 EDR で「遠隔支援ツールのプロセスが wscript.exe / cscript.exe / powershell.exe を 子プロセスとして起動する」検知を作る。正規の保守作業で発生する場合は、実行元と時間帯で例外を絞る
  • 遠隔支援ツールの導入イベント自体を監視する
    観測された事案はいずれも、社会工学で不正な ScreenConnect クライアントを導入させることから始まっている
    取るべき行動 ScreenConnect.ClientSetup.msi などのインストーラの実行、Quick Assist の起動、 UltraViewer の導入を検知して通知する。未承認の RMM はアプリケーション制御でブロックする
  • ユーザーの Run キーへの永続化を定期的に洗い出す
    観測された事案では、AppData 配下の VBScript を指す User Run キーで永続化していた
    取るべき行動 HKCU の Run / RunOnce に登録されたエントリを定期的に収集し、 ユーザープロファイル配下のスクリプトを指すものを洗い出す
  • TransferFiles 権限の無効化を、更新が終わるまでの既定の状態にする
    ConnectWise は修正前の暫定の緩和として TransferFiles（旧 TransferFilesInSession）権限の 無効化を案内している
    取るべき行動 更新が完了していない環境では TransferFiles 権限をロールから外し、 ファイル転送が必要な作業だけ一時的に付与する運用に切り替える
  • 公表された C2 の IP を、過去のログに対して遡って照合する
    観測は2026年8月20日以降であり、公表（9月3日以降）より前に侵害されていた可能性がある
    取るべき行動 45.13.237[.]190 / 131.123.40[.]98 / 15.204.185[.]204 / 146.59.55[.]107 / 45.32.192[.]150 を プロキシ・ファイアウォール・DNS のログに対して8月以降まで遡って照合する。 これらは悪性が検証済みの指標ではなく、Huntress の観測にもとづく手がかりとして扱う
