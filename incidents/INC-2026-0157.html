INC-2026-0157山梨大学のレンタルサーバで54サイト停止

山梨大学が契約する1台のレンタルサーバで、あるWebサイトが使っていたJoomla拡張機能「JCE」の脆弱性を突かれてWebShellを設置され、そこを足場に同じサーバ上の他サイトへ侵害が広がった——不正ユーザの作成・WebShellの設置・SEOスパム/SEOポイズニングが確認され、同サーバ上の計59サイトのうち54サイトが閲覧不可になった。侵害されたサイトは個人情報や機微情報を扱っておらず情報流出は確認されていないが、1サイトの拡張機能1つの放置が同居する全サイトの停止につながった

不正アクセス・侵害システム障害続報が続いている日本の組織が当事者既知の脆弱性の悪用脆弱性の放置設定不備
初報: 2026年8月1日 最終更新: 2026年9月17日

国立大学法人山梨大学は2026年8月27日、同学が契約しているレンタルサーバ上のWebサイト改ざんについて経緯を公表しました。同学は8月1日から一部ホームページの学外公開を停止しており、8月5日に続報を出しています。

同学（総合情報戦略機構）によれば、6月上旬、あるWebサイトで利用していたJoomla の拡張機能「JCE」の脆弱性が悪用され、WebShell（外部からサーバを不正に操作するためのプログラム）が設置されました。その後7月下旬にかけて、この WebShell を利用して同じレンタルサーバ上の他のサイトへ侵害が拡大した可能性が高いとしています。7月中旬以降、複数のCMS利用サイトで不正なユーザの作成、WebShell等の不審なファイルの設置、SEOスパム・SEOポイズニング等の侵害が確認されました。

侵害が確認されたのは同学が契約している1台のレンタルサーバ内に開設されたWebサイトのみで、同サーバ上のWebサイトは計59サイト、うち54サイトが閲覧不可となりました（2026年8月27日時点）。侵害されたWebサイトでは個人情報や機微情報を取り扱っておらず、公表時点で情報流出も確認されていないとしています。

本記録は、1つのサイトが使っていた拡張機能1つの放置が、同じサーバに同居する全サイトの停止につながった事例として整理します。事実は同学の公表に基づき、評価・示唆は本記録の判断として分けて書きます。

公表は三段階で行われた。

最初の2つの告知は「セキュリティインシデント」としか書いていない。 何が起きたかが示されたのは公開停止から26日後である。一方で、8月27日の公表は技術的な経緯をかなり具体的に書いている。拡張機能の名前、WebShell という語、SEOポイズニングという手口、そして「同一サーバ上の他サイトへ侵害が拡大した可能性が高い」という因果まで踏み込んでいる。国内の組織の公表としては情報量の多い部類である（本記録の評価）。

大学は CVE 番号を挙げていないが、時期と手口は CVE-2026-48907 と整合する原因・手口出典 [1] [5]

大学の公表は「Joomla 拡張機能『JCE』の脆弱性」とだけ記し、CVE 番号を挙げていない。ここからは本記録の作成者による照合である。

JCE（Joomla Content Editor）には2026年、CVE-2026-48907（CVSS 4.0 で 10.0）が公表されている。これは認証を必要とせず、JCE のプロファイル管理の処理を悪用して新しいエディタプロファイルを作成し、その権限で任意の PHP ファイルをアップロードできるというものである。修正版は 2.9.99.5。米 CISA は 2026年6月16日にこの脆弱性を Known Exploited Vulnerabilities（KEV）カタログへ収載し、実際に悪用されていることを示している。

山梨大学で WebShell が設置されたのは6月上旬である。手口（認証不要で PHP ファイルを置ける）はWebShell の設置とそのまま一致し、時期は修正版の公開直後・KEV 収載の前後にあたる。本記録はこの脆弱性である可能性が高いと判断するが、大学がそう同定したわけではない。

この照合が実務上意味を持つのは、同じ拡張機能を使っている組織が自組織の該当性を確認できるからである。JCE を使っている Joomla サイトは、バージョンが 2.9.99.5 以上かをまず確認すればよい。

ここからは本記録の作成者の評価である。

第一に、被害の実体は「情報漏えい」ではなく「停止」と「信頼の悪用」である。侵害されたサイトは個人情報も機微情報も扱っていない。だからこの事案は、漏えい件数という物差しでは測れない。しかし59サイト中54サイト（約91.5%）が閲覧不可になった。附属学校園・附属図書館・研究室・研究センターの情報発信が、8月から1か月以上止まっている。教育・研究機関にとって、公開情報が読めないこと自体が業務影響である。

第二に、SEOポイズニングは第三者に向けた攻撃である。 改ざんされたのは大学のサイトだが、被害を受けるのは検索から辿り着いた一般の閲覧者である。大学ドメイン（ac.jp）は検索エンジンからも閲覧者からも信頼されているため、そこに置かれた誘導は効きやすい。攻撃者が狙ったのは大学が持つ情報ではなく、大学が持つ信頼である。誘導先が公表されていないため、閲覧者がどれだけ被害を受けたかは分からない。

第三に、同居構成が被害範囲を決めた。 侵害の起点は1つのサイトの1つの拡張機能である。それが同じサーバに同居する他のサイトへ広がった。共有ホスティングでは、サイト間の分離は事業者の設定と契約プランに依存する。ファイルの権限、PHP の実行ユーザ、ディレクトリの到達範囲——これらが甘ければ、1サイトの WebShell はサーバ全体の WebShell になる。大学が「同一サーバ上の他のサイトへ侵害が拡大した可能性が高い」と書いたのは、まさにこの分離が効かなかったという意味である。

第四に、大学のWebサイトは構造的に更新が滞りやすい。 研究室サイト、プロジェクトサイト、学会のサイト、終了した事業の名残——作った人が異動・卒業しても残り続ける。CMS と拡張機能の更新を誰が担うのかが決まっていないサイトが1つでもあれば、そこが同居する全体の入口になる。本件で止まった54サイトの中には、おそらく侵害と無関係に巻き添えで止まったものが多数含まれている。

第五に、8月27日の公表は資料として価値が高い。 拡張機能名・WebShell・SEOポイズニング・横展開の因果まで書いた公表は、国内では多くない。他の大学・研究機関がそのまま自己点検に使える形になっている。 CVE 番号まで書かれていれば、なお良かった。

波及の構造

事案の構造を図にしたものです。数値は公表値に基づきます。
1サイトの拡張機能の脆弱性から WebShell を置かれ、同居する59サイトのうち54サイトが停止した経路
layer 0 は攻撃者。layer 1 は JCE の脆弱性を突かれた起点のサイトと、そこに設置された WebShell。 layer 2 は同居する他のサイトと、そこで行われた不正ユーザ作成・SEOポイズニング。 layer 3 は停止した54サイトと、検索から誘導されうる閲覧者。 横展開を許したのは、1台のレンタルサーバ上でサイトが分離されていなかったことによる。

対応の評価

評価材料がない判断は「評価材料なし」としています。結果論で断じないための区分です。
判断評価評価の根拠と留保
侵害が確認された1台のレンタルサーバ上のWebサイトについて、学外公開を一括で停止した。 安全性が確認できたサイトから順次再開する方針を取った機能した本記録の作成者の評価である。同一サーバ上で横展開が起きている以上、どのサイトが侵害されているかを 1つずつ確定するより先に全体を止めた判断は妥当である。SEOポイズニングは閲覧者に被害が及ぶ種類の 改ざんであり、止める側に倒す理由が強い
8月1日・8月5日の告知では「セキュリティインシデント」とのみ記し、8月27日に技術的な経緯を公表した部分的に機能本記録の作成者の評価である。最終的な公表の内容は詳しく、他組織の自己点検に使える水準である。 一方で公開停止から26日間、何が起きたかが示されなかった。JCE の脆弱性は6月16日に CISA KEV へ 収載されており、早く公表されていれば同じ拡張機能を使う国内の組織が点検を急げた
CISO・経営層への示唆
  • 「個人情報を扱っていないサイト」を管理対象から外さない
    侵害されたサイトは個人情報も機微情報も扱っていなかったが、59サイト中54サイトが停止し、 SEOポイズニングで組織ドメインの信頼が悪用された
    取るべき行動 公開Webサイトの台帳に、扱うデータの有無とは別に「同居しているサーバ」「CMSと拡張機能」 「更新責任者」の欄を設ける。データが無いことを理由に台帳から外さない
  • 1台のサーバに同居させるサイトの範囲を、被害範囲の設計として決める
    1つのサイトの拡張機能の脆弱性から、同一サーバ上の他サイトへ侵害が広がり、大半が停止した
    取るべき行動 重要度・更新頻度・管理主体が異なるサイトを同じサーバに同居させない。 既に同居している場合は、サイト間の実行ユーザとディレクトリ権限の分離を事業者に確認する
  • 放置されやすいサイト（退職者・卒業者が作ったもの、終了した事業の名残）を定期的に棚卸しする
    大学のWebサイトは研究室・プロジェクト単位で作られ、作った人が異動しても残り続ける。 更新されない1サイトが同居する全体の入口になる
    取るべき行動 年1回、公開サイトの一覧に対して「今も必要か」「誰が更新するか」を確認し、 不要なものは閉鎖する。更新責任者が不在のサイトは静的HTMLへ変換するか閉鎖する
  • 公開停止の告知と、原因の公表を分けて計画する
    8月1日の公開停止から、何が起きたかが示される8月27日まで26日あった
    取るべき行動 インシデント公表の手順に「停止の告知（即時）」と「経緯の公表（調査後・期限つき）」を 別の工程として書く。経緯の公表には、他組織が自己点検できる情報（製品名・バージョン・CVE番号）を含める
セキュリティ技術者への示唆
  • CMS の拡張機能・プラグインを本体と同じ厳しさで更新する
    侵害の起点は Joomla 本体ではなく拡張機能「JCE」の脆弱性だった
    取るべき行動 CMS 本体と拡張機能のバージョンを収集する仕組みを作り、修正版の公開から適用までの日数を測る。 自動更新を有効にできる拡張機能は有効にする
  • CISA KEV と JVN の更新を、自組織のソフトウェア一覧に突き合わせる運用にする
    CVE-2026-48907 は2026年6月16日に CISA KEV へ収載されており、実際に悪用されていることが 公になっていた。山梨大学の WebShell 設置は6月上旬である
    取るべき行動 KEV の更新を購読し、追加された CVE を自組織のCMS・拡張機能・ミドルウェアの一覧に自動照合する。 該当したら期限を切って適用する
  • アップロード先ディレクトリでのスクリプト実行を禁止する
    悪用された脆弱性は任意ファイルのアップロードに至るもので、その結果 WebShell が設置された
    取るべき行動 Web サーバの設定で、アップロード用ディレクトリの PHP 実行を無効にする。 可能ならアップロードされたファイルを公開ディレクトリの外に置き、配信は別経路で行う
  • 公開ディレクトリのファイル改変と、CMS の管理ユーザ追加を検知する
    WebShell の設置から侵害の確認まで約40日あり、その間に不正なユーザの作成も行われている
    取るべき行動 ファイル整合性監視を入れ、公開ディレクトリに新しい PHP ファイルが現れたら通知する。 CMS の管理ユーザ追加・権限変更も通知対象にする
  • 自組織ドメインの検索結果を定期的に確認する
    SEOスパム・SEOポイズニングが確認されており、これは外部から気づかれやすい種類の改ざんである
    取るべき行動 Search Console のセキュリティ問題の通知を受け取る設定にし、 自組織ドメインを対象にした検索結果を月1回確認する。想定外のページが索引されていないかを見る
