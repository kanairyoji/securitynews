INC-2026-0161Cisco ISE にゼロデイ悪用

ネットワーク認証基盤 Cisco Identity Services Engine の API に認証制御の不備（CVE-2026-76460・CVSS 10.0）があり、認証を持たない遠隔の攻撃者が細工したリクエストだけで管理インタフェースの認証を回避し、root 権限でコマンドを実行される——Cisco PSIRT は実際の悪用を把握したとして2026年9月16日に修正版を公開し、米 CISA は同日 KEV へ収載して連邦機関に3日後の9月19日を期限とした。回避策は無く、Cisco は侵害が疑われる場合はノードの再イメージ化と構成バックアップからの復元を強く推奨している

脆弱性続報が続いている有名事象として記録（日本と直接の関係は薄い）設計・実装上の不備未知の脆弱性の悪用
初報: 2026年9月16日 最終更新: 2026年9月17日

企業や大学のネットワークで「誰を・どの端末を・どこまで入れるか」を決めるCisco Identity Services Engine（ISE）に、認証を持たない遠隔の攻撃者が管理インタフェースの認証をまるごと回避できる脆弱性 CVE-2026-76460 が見つかりました。CVSS 3.1 基本値は最高の 10.0（AV:N/AC:L/PR:N/UI:N/S:C/C:H/I:H/A:H）です。原因は API エンドポイントにおける認証制御の不備で、攻撃者は細工したリクエストを送るだけで済みます。Cisco ISE と Cisco ISE Passive Identity Connector（ISE-PIC）が対象で、機器の設定の内容によらず影響を受けます。

Cisco は2026年9月16日に advisory（cisco-sa-ISE-ABP-VNSW7Tn5）を公開し、「Cisco PSIRT は本脆弱性の実際の悪用を把握している」（原文英語）と述べました。回避策は提供されておらず、対処は修正版（3.1 Patch 12／3.2 Patch 11／3.3 Patch 12／3.4 Patch 7／3.5 Patch 4）への更新のみです。緩和策として、インフラ用アクセス制御リスト（iACL）で機器への到達を絞ることが挙げられています。

米 CISA は同じ2026年9月16日に、この脆弱性を「悪用が確認された脆弱性カタログ」（KEV）へ追加し、連邦民間行政機関の対応期限を3日後の9月19日に設定しました。公開と収載が同日であることは、世に出る前から悪用されていたことを示します。

悪用に成功した攻撃者は root 権限でコマンドを実行できるため、Cisco は痕跡が消されている可能性を前提に、全ノードの access.log で不審なユーザー名を確認し、ネットワークとファイアウォールのログを突き合わせるよう求めています。悪性の活動が疑われる場合は、ノードの再イメージ化と構成バックアップからの復元を強く推奨しています。本記録の作成者が2026年9月17日に確認した範囲では、日本国内での被害の公表も JPCERT/CC の注意喚起もありません。本記録は、公表資料に基づく事実と、本記録の作成者による評価を分けて整理します。

攻撃の経過

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

認証を持たない遠隔の攻撃者が、Cisco ISE / ISE-PIC の API エンドポイントへ 細工したリクエストを送り、Web ベースの管理インタフェースの認証を回避して 機器へ不正にアクセスする。悪用に成功すると root 権限でコマンドを実行でき、 侵害の痕跡を隠蔽・削除しうる。実際の攻撃で何が行われたか（どの資格情報が取得され、 どこへ送られたか）は公表されていない。Cisco は全ノードの access.log の確認、 ネットワーク・ファイアウォールのログとの突合、悪性の活動が疑われる場合の ノードの再イメージ化と構成バックアップからの復元を求めている。

  1. 1. 初期侵入確認済[1] [4]
    攻撃者が、影響を受ける API エンドポイントへ細工したリクエストを送り、 Web ベースの管理インタフェースの認証を回避して機器へアクセスする。 認証情報も利用者の操作も不要である。
    根拠: Cisco の advisory（cisco-sa-ISE-ABP-VNSW7Tn5）
  2. 2. 実行確認済[1] [5]
    悪用に成功した攻撃者は root 権限でコマンドを実行できる。 実際の攻撃で何が実行されたかは公表されていない。
    根拠: Cisco の advisory と SecurityWeek の記述
  3. 3. 検知回避確認済[1]
    Cisco は、root 権限を得た攻撃者が悪用の痕跡を隠蔽・削除しうると明記し、 機器の外のログとの突合を求めている。
    根拠: Cisco の advisory
  4. 4. 認証情報アクセスunconfirmed[1]
    本件で資格情報が取得されたかは公表されていない。一般に ISE には、 RADIUS の共有秘密、TACACS+ の鍵、Active Directory へ参加するためのアカウント、 証明書と秘密鍵、ネットワーク機器の管理者資格情報、端末とユーザーの一覧が集まる。
    根拠: 公表資料に記載なし（本記録の作成者による位置づけ）
  5. 5. 影響（暗号化・破壊・改ざん）unconfirmed[1]
    ISE はネットワークへの入場可否を判定する基盤であるため、掌握されれば 認証・認可の判定そのものを操作されうる。本件でそうした操作が行われたかは 公表されていない（本記録の作成者による位置づけ）。
    根拠: 公表資料に記載なし（製品の役割からの評価）

入場を判定する機器の認証が、認証なしで回避できた——ゼロトラストの土台そのものが的になった原因・手口出典 [1] [4] [5]

Cisco ISE は、有線・無線・VPN の利用者と端末を認証し（RADIUS／TACACS+）、ポスチャ評価やゲストアクセス、ネットワーク機器の管理者認証まで担う基盤です。ゼロトラストの実装で「誰を、どの端末を、どこまで入れるか」を判定する側に置かれます。

CVE-2026-76460 は、その ISE の API エンドポイントにおける認証制御の不備です。Cisco の説明では、攻撃者は影響を受ける API エンドポイントへ細工したリクエストを送ることで、Web ベースの管理インタフェースの認証を回避し、機器への不正なアクセスを得られます。認証情報は要らず、利用者の操作も要りません。CVSS は上限の 10.0 で、ベクタには影響範囲の変更（S:C）が含まれます。悪用に成功すれば root 権限でのコマンド実行に至る、と Cisco は注意しています。

本記録の評価として、押さえるべきは的の位置です。メールゲートウェイや VPN 装置の侵害は「境界を1枚破られた」ことを意味しますが、ISE の侵害は「入場の可否を決める判定者を奪われた」ことを意味します。攻撃者が判定者を握れば、正規の認証を通り抜けるのではなく、自分を正規と判定させることができます。ISE が保持する RADIUS 共有秘密、TACACS+ の鍵、Active Directory へ参加するためのアカウント、証明書、ネットワーク機器の管理者資格情報は、いずれも横展開の材料としてそのまま使える種類のものです。本件でそれらが実際に取得されたかは公表されていませんが、root を取られた機器に置かれている以上、読まれた前提で扱うのが安全です。

公開と KEV 収載が同じ日で、期限は3日——修正版が出た時点で防御側は後追いだった概観出典 [1] [2] [3]

Cisco が advisory を公開したのは2026年9月16日、CISA が KEV へ追加したのも同じ2026年9月16日です。対応期限は3日後の9月19日に設定されました。公開と収載が同日であるという事実は、修正版が世に出る前から悪用されていたことを意味します。Cisco 自身、脆弱性が TAC のサポートケースの対応の過程で見つかったとしています。

3日という期限の短さは、同じ時期の他の事案と比べると位置づけが分かります。2026年9月14日に KEV 入りした Cisco Secure Email Gateway の CVE-2026-76461（INC-2026-0146）も3日、9月11日の ConnectWise ScreenConnect の CVE-2026-84869（INC-2026-0154）も3日でした。KEV では2〜3週間の猶予が置かれることも多く（INC-2026-0068 の PaperCut は14日）、3日はこの期間の重大事案に集中しています。

本記録の評価として、日本の組織にこの期限の法的な効力はありません。ただし「当局が実悪用を確認し、自国の機関に3日で対処せよと命じた」という事実は、社内で緊急の停止・再起動・計画外の変更を通すときの根拠として使えます。ISE は止めると認証そのものが止まる機器であり、更新の合意形成が難しい部類です。その難しさは、更新を先送りする理由にはなりません。

回避策は無く、Cisco は「疑わしければ再イメージ化」を求めた——当てるだけでは終わらない対策・注意喚起出典 [1] [4] [5]

回避策は提供されていません。対処は修正版への更新のみです。対象と修正版は、3.1 → Patch 12、3.2 → Patch 11、3.3 → Patch 12、3.4 → Patch 7、3.5 → Patch 4 です。緩和策として、インフラ用アクセス制御リスト（iACL）で機器への到達元を絞れば、遠隔からの悪用は防げるとされています。

侵害の確認について、Cisco は全ノードの access.log に不審なユーザー名が残っていないかを確認するよう案内し、検出例として次のコマンドを挙げています。

admin#show logging application ise-kong/access.log | include dummyuser

出力に項目があれば悪性の活動の可能性があるとされます。分散配置ではすべてのノードで確認する必要があります。そのうえで Cisco は、悪性の活動が疑われる場合にはノードの再イメージ化と、必要に応じた構成バックアップからの復元を強く推奨しています。

さらに Cisco は、悪用に成功した攻撃者が root 権限でコマンドを実行できるため侵害の痕跡を隠蔽・削除しうると明記し、ファイアウォールやネットワークのログと突き合わせて、外部の不審な IP との送受信が無いかを確認するよう求めています。

本記録の評価として、この3点セット（更新・全ノードのログ確認・疑わしければ再構築）は、境界機器の緊急対応の型としてそのまま使えます。要点は、機器の中のログだけで「異常なし」と結論づけないことです。root を取られた後のログは攻撃者の制御下にあり、綺麗であることは侵害されていないことの証明になりません。判断の主資料は、機器の外（SIEM へ転送済みのログ、境界のファイアウォール、プロキシ、DNS の記録）に置く必要があります。

同じ日に ISE 関連で42件が公開された——1件の緊急対応に見えるものが、実際には棚卸しの機会である背景・過去事例出典 [4] [6]

Security NEXT によれば、Cisco は2026年9月16日（現地時間）に ISE 関連で15本の advisory を公開し、CVE ベースで42件の脆弱性を明らかにしました。重要度が最高の「クリティカル」とされた advisory は6本で、その中では21件の脆弱性が言及されています。BleepingComputer は、別の最高深刻度の認証回避（CVE-2026-76423）を含む複数が前日に修正されており、それらは実悪用の指定を受けていないと伝えています。

ISE に対するゼロデイ悪用は初めてではありません。BleepingComputer は、2025年7月に別の ISE のゼロデイ（CVE-2025-20337・同じく最高深刻度）が遠隔コード実行に悪用され、正規の ISE の部品を装った「IdentityAuditAction」という Web シェルが仕掛けられた事例を挙げています。また、過去5年で CISA が実悪用と指定した Cisco 製品の脆弱性は99件にのぼり、うち7件はランサムウェアに悪用されたとしています。

本記録の評価として、1件の CVE への緊急対応と、42件を含む版の更新は、作業としては同じ「パッチ適用」です。優先順位は CVE-2026-76460 に置くとしても、同じ更新で残りも閉じられる以上、この機会に版を最新の Patch まで進めておくほうが、次の緊急対応の回数を減らせます。なお、本記録の作成者が本文を確認したのは CVE-2026-76460 の advisory のみであり、他の41件については報道の記述に依拠しています。

日本語の注意喚起は出ておらず、国内の被害も公表されていない——「情報が無い」ことは「影響が無い」ことではない波及・関係先出典 [6] [9]

本記録の作成者が2026年9月17日に確認した範囲では、JPCERT/CC の2026年の注意喚起一覧に本脆弱性の注意喚起はありません（同月の注意喚起はCisco Secure Email Gateway・Adobe・マイクロソフトの3件です）。JVN/JVNDB でも該当の掲載を確認できませんでした。国内の被害公表も見当たりません。国内報道としては Security NEXT が2件を報じています。

同じ9月の Cisco Secure Email Gateway の事案（INC-2026-0146）では、JPCERT/CC が注意喚起を出し、過去に同製品の別の脆弱性を悪用した侵害事案が国内で発生していることを確認したと書いていました。本件にはその後押しがありません。

本記録の評価として、この差を「国内では緊急度が低い」と読むのは誤りです。ISE は日本の企業・大学のネットワーク認証で広く使われている製品であり、国内の稼働台数も露出台数も公表されていないため、外から影響を測る手段がありません。日本語の注意喚起が出るかどうかは、製品の普及度ではなく、その時点で国内の相談・報告が上がっているかに左右されます。着手の条件を「日本語の注意喚起が出たら」に置いている組織は、本件のような場合に動き出しが遅れます。本記録が日本との関係を「有名事象として記録」の扱いにしているのも、国内の影響を裏づける公表資料が現時点で無いためであり、影響が無いと判断したからではありません。

悪用の開始時期も、被害組織も、攻撃者も公表されていない未確定事項出典 [1] [4] [5]

公表されていないことを列挙します。悪用がいつ始まったか。悪用を受けた組織の名称・国・業種・件数。侵害後に何が行われ、ISE が保持していたRADIUS／TACACS+ の鍵、ディレクトリ参加用のアカウント、証明書がどこまで扱われたか。攻撃者の主体と動機。実証コードの公開状況。インターネットに露出している ISE の台数。国内の稼働台数と被害の有無。

Cisco が公表したのは、脆弱性の性質、対象版と修正版、回避策が無いこと、実悪用を把握していること、侵害確認の手順（access.log の dummyuser）、疑わしい場合は再イメージ化することです。攻撃の中身は何も示されていません。

本記録は、被害組織の公表、国内事例の有無、実証コードの公開、攻撃者の帰属、JPCERT/CC の注意喚起のいずれかが出た時点で更新します。status は updating のままとします。

緩和策
item: 修正版（3.1 Patch 12／3.2 Patch 11／3.3 Patch 12／3.4 Patch 7／3.5 Patch 4）への更新　副作用: ISE はネットワーク認証の判定を担うため、更新と再起動の間、 新規の認証が滞る・再認証が失敗するおそれがある。分散配置ではノードの更新順序 （管理・監視・ポリシーサービスの各ペルソナ）を設計する必要がある。 回避策が提供されていないため、更新を先送りする選択は 「侵害前提の運用を続ける」ことと同義になる
item: iACL による ISE の管理面・API への到達元の制限　副作用: 運用端末・監視系・連携するシステムからの到達も同時に絞られるため、 許可リストの洗い出しを誤ると運用と自動連携が止まる。 緩和策であって修正ではなく、到達できる位置にいる攻撃者には効かない
item: 全ノードの access.log の確認（検出例は dummyuser を含む項目）　副作用: root を取られた機器ではログが削除されている可能性があるため、 「出力なし＝安全」とは読めない。分散配置では確認漏れのノードが1台あれば 結論が崩れるため、確認したノード名を残す運用が要る
item: 悪性の活動が疑われる場合のノードの再イメージ化と構成バックアップからの復元　副作用: 再イメージ化の間、当該ノードが担っていた認証は停止する。 構成バックアップが侵害後のものであれば、攻撃者が加えた変更ごと復元してしまう。 バックアップの取得時点と侵害の疑いの時期を突き合わせる判断が要る
indicators
item: access.log に残る不審なユーザー名（Cisco の検出例: admin#show logging application ise-kong/access.log | include dummyuser）　補足: 出力に項目があれば悪性の活動の可能性がある。分散配置では全ノードで確認する
item: ISE と外部の不審な IP との間の想定外のダウンロード・アップロード　補足: Cisco がファイアウォール・ネットワークログとの突合を求めている層。攻撃者が消しにくい
item: 機器上のログの欠落・不自然な時刻の空白、身に覚えのない設定変更・管理者アカウントの追加　補足: Cisco は痕跡の隠蔽・削除の可能性を明記している。欠落そのものを疑いの根拠として扱う

CISO・経営層への示唆
  • 認証基盤の緊急更新は「止まると業務が止まる」から先送りされやすい——その合意形成を平時に済ませておく
    ISE はネットワークへの入場を判定する機器で、更新・再起動の間は 新規の認証が滞る。回避策が提供されておらず、対処は更新のみで、 米連邦機関の期限は収載から3日だった。先送りした期間は、 実悪用が続いている中で無防備な期間になる。
    取るべき行動 認証基盤・境界機器について、「実悪用の公表があった場合は変更管理の 次回の窓を待たずに更新する」事前承認を用意する。承認文には 実施者・想定停止時間・業務への影響の説明文を含め、 当日に判断する要素を減らしておく。
  • 当局が求めたのは「当てること」ではなく「侵害されていないかを調べること」まで含む
    Cisco は全ノードの access.log の確認、ネットワークログとの突合、 悪性の活動が疑われる場合のノードの再イメージ化と構成バックアップからの 復元を推奨している。CISA も BOD 26-04 に基づく対応の対象とした。 悪用が更新より先行していた以上、更新だけでは既に入られていた場合の被害は止まらない。
    取るべき行動 緊急更新の完了報告に「全ノードのログ確認の結果」「機器が保持する 資格情報の更新の有無」「再イメージ化の要否判断」の3欄を設け、 更新完了だけで案件を閉じない運用にする。
  • 日本語の注意喚起を着手条件にすると、本件のような事案で出遅れる
    本件では、本記録の作成者が2026年9月17日に確認した範囲で JPCERT/CC の 注意喚起が出ておらず、JVN/JVNDB でも該当の掲載を確認できなかった。 同じ9月の Cisco Secure Email Gateway の事案（INC-2026-0146）では 注意喚起が出ていた。出るかどうかは、その時点で国内の相談が 上がっているかに左右される。
    取るべき行動 脆弱性対応の着手条件に、開発元の advisory と CISA KEV の収載を 単独の条件として明記する。日本語の注意喚起は「あれば加点」であって、 待つ対象にしない。着手条件は文書化し、担当者の判断に依存させない。
  • 同じベンダーの重大事案が短期間に続くときは、1件ごとの対応ではなく製品群の棚卸しとして扱う
    2026年9月には、Cisco Secure Email Gateway の CVE-2026-76461（14日・INC-2026-0146）と 本件（16日）が相次ぎ、ISE 関連だけで同日に42件の脆弱性が公開された。 BleepingComputer は、過去5年で CISA が実悪用と指定した Cisco 製品の脆弱性が 99件にのぼると伝えている。
    取るべき行動 自組織が保有する当該ベンダー製品を一覧にし、版数・保守契約・ 更新の実施主体（自社か委託先か）・止めたときの影響を1枚にまとめる。 次の緊急時に、対象の洗い出しから始めなくて済む状態を作る。
セキュリティ技術者への示唆
  • 全ノードで確認する——分散配置では1台の確認漏れが結論を崩す
    Cisco は access.log の確認を「展開内のすべてのノードで行うこと」と明記している。 ISE は管理・監視・ポリシーサービスの各ペルソナを複数ノードへ分散して 構成することが多く、確認対象を取り違えやすい。
    取るべき行動 確認の記録に「ノード名・ペルソナ・確認時刻・出力の有無」を残す。 構成情報からノード一覧を機械的に取り出し、確認済みリストと突き合わせて 漏れが無いことを示せる形にする。
  • 「出力なし」を安全の証明として報告しない
    Cisco は、root 権限を得た攻撃者が痕跡を隠蔽・削除しうると明記している。 検出例のコマンドは、痕跡が残っていた場合に見つけるための手順であり、 出力が空であることは侵害が無いことの証明にならない。
    取るべき行動 調査結果は「検出された／検出されなかった（ただし痕跡削除の可能性があるため 周辺機器の通信記録での確認が別途必要）」の形で書く。 ファイアウォール・プロキシ・DNS の記録との突合を同じ調査の中に組み込む。
  • ISE が抱える鍵と資格情報を洗い出しておく——侵害が疑われた日に調べ始めると半日が消える
    ISE には RADIUS の共有秘密、TACACS+ の鍵、ディレクトリ参加用アカウント、 証明書と秘密鍵、ネットワーク機器の管理者資格情報が集まる。 本件で何が取得されたかは公表されていないが、root を取られた機器では すべて読める前提になる。
    取るべき行動 ISE ごとに「保持している鍵・資格情報の一覧」と「更新手順・所要時間・ 影響する業務（どの拠点の認証が止まるか）」を平時に作る。 共有秘密をネットワーク機器ごとに分けておくと、更新の影響範囲を分割できる。
  • 再イメージ化からの復元を、手順書ではなく実測で確認しておく
    Cisco は悪性の活動が疑われる場合の対処として、ノードの再イメージ化と 構成バックアップからの復元を強く推奨している。実施の判断は、 復元にどれだけかかるかが分からないと下せない。
    取るべき行動 検証環境で再イメージ化と構成バックアップからの復元を一度実施し、 所要時間と手順の欠落を記録する。バックアップの取得時点が分かるよう、 取得日時と世代を管理しておく（侵害後のバックアップから戻すと 攻撃者の変更ごと復元してしまう）。

自組織に当てはまるか

該当する項目があれば、この事案と同じ構図が自組織でも成立しうることを意味します。
観点自社に当てはまるか該当する場合に何が起きうるか
システム構成□ Cisco Identity Services Engine（ISE）または ISE Passive Identity Connector（ISE-PIC）を運用しているCisco は影響を受ける版を 3.0〜3.5 とし、機器の設定の内容によらず 影響を受けるとしている。導入していること自体が成立条件になる。
認証・認可□ ISE が Active Directory へ参加しており、ディレクトリ参加用アカウントやネットワーク機器の管理者資格情報を保持しているroot を取られた場合、機器に保存された鍵・資格情報は読まれた前提になる。 共用していれば、認証基盤の侵害がディレクトリや機器群へ広がる。
運用・監視□ ISE の版数（Patch レベル）を即座に答えられない、または版数を把握しているのが運用委託先だけである修正版は系列ごとに Patch 番号が異なる（3.1 P12／3.2 P11／3.3 P12／3.4 P7／3.5 P4）。 版数が分からなければ、当たっているかどうかも判定できない。
運用・監視□ ISE のログ（access.log を含む）を機器の中にしか置いておらず、SIEM や外部のログ基盤へ転送していないroot を取られた機器ではログが削除されうる。転送していなければ、 Cisco が案内する確認手順そのものが成り立たない。
システム構成□ ISE の管理面・API へ、管理セグメント以外から到達できる（iACL 等で到達元を絞っていない）緩和策として挙げられているのは iACL による到達元の制限のみである。 絞っていなければ、更新までの間の遠隔からの悪用を止める手段が無い。
運用・監視□ 認証基盤の再イメージ化・構成バックアップからの復元を、実際に試したことがないCisco は悪性の活動が疑われる場合に再イメージ化を推奨している。 所要時間と手順の実測が無ければ、実施の判断そのものができない。
