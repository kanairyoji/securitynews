INC-2026-0168WaterPlumに日米豪独が帰属公表

警察庁・国家サイバー統括室が米国・豪州・ドイツの情報機関とともに、北朝鮮のサイバー攻撃グループ「WaterPlum」（関連名称 Contagious Interview）と北朝鮮IT労働者が朝鮮労働党中央委員会軍需工業部313総局の指揮下にあると公表した——WaterPlum は求人・面接を装って日本を含む100以上の国と地域で3万台以上の端末を感染させ、7千件以上の暗号資産ウォレット情報を窃取し、少なくとも約17億円相当の暗号資産を送金していた。日本では国内の支援者宅に置かれた「ラップトップ・ファーム」を初めて把握・解体し、暗号資産取引所 bitFlyer のエンジニア職への応募が北朝鮮IT労働者とみられると判明した。両者は同一のIPアドレスを共有していた

脅威・攻撃キャンペーン詐欺の手口初報のみ日本の組織が当事者人を介した誘導（ビッシング・BEC）認証情報の悪用（使い回し・推測可能・窃取）委託先・供給元起因
初報: 2026年9月18日 最終更新: 2026年9月18日

警察庁および国家サイバー統括室（NCO）は2026年9月18日、米国連邦捜査局（FBI）、米国国防総省サイバー犯罪センター（DC3）、豪州通信情報局（ASD）豪州サイバーセキュリティセンター（ACSC）、ドイツ連邦情報庁（BND）およびドイツ連邦憲法擁護庁（BfV）とともに、北朝鮮を背景とするサイバー攻撃グループ「WaterPlum」（ウォータープラム／関連名称：Contagious Interview）の手口と、北朝鮮IT労働者の活動実態を合同で公表しました。いわゆるパブリック・アトリビューションです。

公表の核心は2つあります。1つは帰属です。警察庁とFBIは、WaterPlum と一部の北朝鮮IT労働者がともに朝鮮労働党中央委員会軍需工業部「313総局」の指揮下で運用されていると評価しました。その根拠として、WaterPlum の攻撃者が使っていたIPアドレスと、北朝鮮IT労働者がラップトップ・ファームやクラウドソーシングへ接続する際のIPアドレス、さらに国内の暗号資産取引所へ応募した北朝鮮IT労働者のIPアドレスが一致したことを挙げています。サイバー攻撃と外貨獲得が別の話ではなく、同じ指揮系統の両輪だという主張です。

もう1つは日本国内の実態です。警察庁は、国内の支援者（ドメスティック・イネーブラー）の居宅に設置された「ラップトップ・ファーム」を我が国で初めて把握し、捜査のうえ解体したと述べました。ラップトップ・ファームとは、北朝鮮IT労働者が遠隔操作するPCを支援者宅に置き、作業場所を日本国内に見せかける仕組みです。関連捜査で判明した分を含め、暗号資産等で数億円相当が海外へ送金されていました。あわせて、2025年5月に暗号資産取引事業者「bitFlyer」のエンジニア職へ北朝鮮IT労働者とみられる応募があった事実と、同社が面接で確認した不審点が公表されています。同社は不審点に気づいて適切に対応したため、採用にも被害にも至っていません。

攻撃側の規模は次のとおりです。WaterPlum は2025年12月頃から2026年7月にかけて、日本を含む100以上の国と地域で3万台以上とみられる端末をマルウェアに感染させ、7千件以上の暗号資産ウォレット情報を窃取しました。WaterPlum が管理するウォレットには少なくとも約17億円相当（約1,071万ドル・1ドル159円換算）の暗号資産が送金されています。標的はWeb関係のデザイナー・エンジニア、暗号資産・ブロックチェーン・Web3分野の技術者とみられます。

本記録は、警察庁・国家サイバー統括室・FBI（IC3）が公表した事実と、本記録の作成者による評価を分けて整理します。

  • ラップトップ・ファームの時期・場所・規模と、支援者の立件の有無捜査上の理由
    「我が国で初めて把握のうえ、捜査及び解体した」とあるだけで、いつ・どこで・何台が・ 何人の支援者によって運用されていたのかは公表されていない。支援者が検挙されたのか、 どの罪名で扱われたのかも書かれていない。捜査上の理由とみられるが、 公表資料はその理由を説明していない。

    注意喚起には、警戒すべきコマンド文字列の例（curl・base64・-enc・mshta・ Invoke-WebRequest -uri・iwr -uri・hidden）と、応募時に使われた VPN サービス名、 マルウェアファミリ名（BeaverTail・InvisibleFerret・OtterCookie・OtterCandy・ StoatWaffle）は載っているが、C2 のIPアドレス・ドメイン・ファイルハッシュ・ 悪性 npm パッケージ名の一覧は含まれていない。自社ログとの突き合わせに直接使える 指標は、この公表資料からは得られない。
  • bitFlyer 以外の国内企業への応募・受注の実態公表されていない
    公表資料に名前が出ている国内企業は bitFlyer のみである。他に何社が応募を受けたのか、 実際に採用・受注に至った国内企業があるのか、あった場合にどのような被害が生じたのかは 示されていない。「WaterPlum の一部メンバーは、日本や米国の企業で専門的なIT業務や ウェブシステム設計・開発の仕事に就くことに成功しており」という記述はあるが、 企業名・件数は伏せられている。

    警察庁の資料は同社名を挙げて経緯を記述し、謝辞にも掲げているが、 同社自身が本件について何らかの声明を出したかどうかを、本記録の作成者は 2026年9月18日時点で確認できていない（同社サイトへのアクセスが拒否された）。

    合同文書には ASD's ACSC・BND・BfV が名を連ねているが、各国が自国向けに 独自の勧告を同時に出したかどうかを本記録の作成者は確認できていない。 確認できたのは警察庁・国家サイバー統括室の日本語資料と FBI IC3 の英文 CSA である。

攻撃の経過

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

採用担当者を装ってIT技術者に接近し、「技術面接」「コーディング課題」という名目で 悪性の npm パッケージや VS Code プロジェクトを被害者自身の端末で実行させる。 ローダーがバックドアを設置し、RAT で接続と横展開の経路を維持しながら、 情報窃取ツールでブラウザの認証情報・クリップボード・キー入力・スクリーンショット・ 暗号資産ウォレットの秘密鍵とシードフレーズ・身分証画像を第三者のC2へ送る。 窃取した認証情報は被害者の勤務先ネットワークへの侵入に使われ、 盗まれた身分証は北朝鮮IT労働者のなりすましに再利用される。 これと並行して、同じ指揮系統の北朝鮮IT労働者が身分を偽って採用・受注に応募し、 国内の支援者が用意したラップトップ・ファームと VPS で作業場所を偽装する

今回の公表で最も重いのは、被害の数字ではなく帰属のしかたである。警察庁とFBIは、WaterPlum によるサイバー攻撃と、北朝鮮IT労働者による一部の外貨獲得活動の双方について、朝鮮労働党中央委員会軍需工業部313総局が中心的な役割を果たしていると評価した。

攻撃の入口は「面接課題を自分の端末で実行させる」ことで、防御の対象は組織ではなく個人の開発環境になる原因・手口出典 [1] [3]

WaterPlum の手口は公表資料に具体的に書かれている。ソーシャルメディア、オンライン求人サイト、ギグワークプラットフォーム、フリーランスマーケットプレイスを通じて世界中の求職者に接近し、正規のAI企業・暗号資産企業・NFT企業・人材紹介サービスになりすまして「魅力的な求人」を持ちかける。そのうえで、技術的なオンライン面接への参加か、コーディング課題の完了を求める。

ここで求職者は、複数のオンライン共同開発プラットフォームやコードリポジトリから「不正なプログラム」をダウンロードし、それを使ってビデオ会議プラットフォームの不具合を診断・修正するか、課題を完成させるよう指示される。配送経路として挙げられているのは、悪意のある npm パッケージと、悪性の VS Code プロジェクトである。後者は.vscode/tasks.json に自動実行コードを埋め込み、フォルダが開かれ「信頼」された時点で実行される。埋め込まれるマルウェアファミリは BeaverTail（JavaScript）、InvisibleFerret（Python のバックドア）、OtterCookie（RAT・情報窃取）、OtterCandy（OtterCookie と RATatouille の機能を統合）、StoatWaffle（モジュラー構成の Node.js マルウェア）と名指しされている。

本記録の評価として、この入口の性質は重要である。侵入が起きるのは組織の境界の外、求職者個人の端末である。メールゲートウェイもプロキシも通らない。標的になるのは現職の従業員とは限らず、転職を考えている従業員、副業のフリーランス、業務委託先の技術者である。そして「面接課題のコードを自分の環境で動かす」という行為は、開発者にとって不自然な依頼ではない。手口が業務の正常な形と区別できないという点が、この攻撃を教育で止めにくくしている。

個人の被害は個人で終わらない——窃取された認証情報が勤務先ネットワークへの入口になる被害規模・影響範囲出典 [1] [3]

公表資料は、窃取の対象を具体的に列挙している。ブラウザに保存された認証情報（ID・パスワード等）、クリップボードの情報、キー入力の記録、スクリーンショット、暗号資産ウォレットのデータ（秘密鍵・シードフレーズ等）、そしてPCや共有フォルダ内のファイル—— 運転免許証やパスポートといった身分証の画像を含む。

そのうえで資料はこう述べる。WaterPlum は「被害者の端末から窃取した認証情報を用いて、被害者を雇用している組織のコンピュータネットワークに侵入し、スパイ活動や知的財産の盗難、企業環境内へのさらなる横展開を可能とします」。また「盗まれた身分証画像は、北朝鮮IT労働者が外貨獲得のために被害者になりすますことにも利用され得ます」。

さらに、標的にされたIT技術者の勤務先だけでなく、北朝鮮IT労働者に業務発注した企業からも暗号資産や個人情報が窃取されたり、窃取された機微情報を悪用・脅迫されたりする可能性があるとしている。

本記録の評価として、ここに2段構えの構造がある。第一段は暗号資産の窃取で、被害者は技術者個人である。第二段は認証情報を使った勤務先への侵入で、被害者は企業になる。企業から見ると、自社の統制が及ばない場所（従業員の私的な求職活動）で起きた侵害が、自社の認証情報の漏えいとして返ってくる。盗まれた身分証が別人のなりすましに再利用される点も踏まえると、被害は時間差でも広がる。

国内初のラップトップ・ファーム解体——「日本にいる作業者」という見せかけが日本の支援者によって作られていた波及・関係先出典 [1] [2] [3]

北朝鮮IT労働者側の手口は、資料では次のように整理されている。労働者は日本に居住する支援者から提供を受けた身分証明書画像を悪用して支援者になりすまして業務を受注し、あるいは支援者が受注した業務を請け負って報酬を得、支援者の銀行口座を報酬の振込先に指定する。作業場所の偽装には、支援者宅に設置された遠隔操作用PC（ラップトップ・ファーム）と、支援者が借りた VPS が使われる。作業者自身は北朝鮮国内のほか中国・ロシアに拠点を持ち、少数はアフリカや東南アジアにも居住しているとされる。

警察庁は、このラップトップ・ファームを我が国で初めて把握し、捜査のうえ解体したと述べた。関連捜査で判明した分を含め、暗号資産等で数億円相当が海外へ送金されていた。

本記録の評価として、ラップトップ・ファームは発注側の確認手段を無力化する装置である。発注元がIPアドレスや振込先口座を確認しても、どちらも日本国内を指す。日本人名義の身分証も提示される。つまり、一般的な本人確認の手続きは通過してしまう。「国内の支援者が要る」ということは裏返せば、支援者を巻き込む勧誘——「海外からだと制約があって仕事がしにくいのでPCを置かせてほしい」という依頼——が実在するということでもある。資料はこの断り方まで書いている。

bitFlyer の面接で露見した特徴が、そのまま採用側のチェックリストになっている対策・注意喚起出典 [1]

公表資料のうち、日本の企業がそのまま使える形になっているのが、2025年5月のbitFlyer への応募事例である。同社は応募者が北朝鮮IT労働者である可能性を考慮したうえでオンライン面接を実施しており、その記録が公開された。

応募の段階で観察された特徴は、別人になりすました履歴書を採用フォームに直接添付（仲介事業者を介さない）、連絡先メールアドレスが Gmail、アクセス時に VPN（NETNUT Proxy・Astrill VPN・High Speed Rabbit Proxy）を使用、職務経歴書はプログラミング言語・ブロックチェーン・クラウドのそれぞれで10種類以上のスキルを主張し、欧州の大学卒業後に世界各地の都市で職歴がある、というものだった。

面接中の特徴はさらに具体的である。見た目はアジア系で、マレーシア出身・フィンランド在住、母国語はマレー語と中国語と説明した。英会話のレベルは学歴・職歴に見合わず、経歴書のスキルに応じた質問には抽象的な回答に終始した。日本への引っ越し（出社）を拒否するか「半年先なら」と答える。暗号資産での給与支払いに固執する。しきりに別モニターを確認し、画面内容を読み上げているような様子がある。時折、背後で他人の話し声が聞こえる。映像が途切れる、コマ送りになる。

本記録の評価として、この節の価値は「捜査側が実際に観測した挙動」である点にある。一般論としての「なりすまし対策」ではなく、面接という場で何が見えたかが書かれている。一方で、これらの特徴の多くは正当な応募者にも当てはまりうる（VPN の利用、リモート勤務の希望、英語の巧拙）。単独の指標で判断すると差別的な選別になりかねない。複数の特徴が重なるかどうか、そして経歴の検証可能性（資格の認定番号、前職への照会）と組み合わせて見るべきである。

波及の構造

事案の構造を図にしたものです。数値は公表値に基づきます。
同一の指揮系統から出た2つの経路——攻撃（求人を装った侵入）と就労（身分を偽った受注）が合流する構造
朝鮮労働党中央委員会軍需工業部313総局の指揮下に、WaterPlum と北朝鮮IT労働者の 双方が置かれていると警察庁・FBI は評価した（layer 0→1）。左の経路では、 求人・面接を装って求職者に悪性の npm パッケージや VS Code プロジェクトを 実行させ（layer 2）、暗号資産と認証情報・身分証画像を奪う（layer 3）。 窃取された認証情報は被害者の勤務先ネットワークへの侵入に使われ（layer 4）、 奪われた身分証は右の経路のなりすましに再利用される。右の経路では、 国内の支援者が提供する身分証・銀行口座・ラップトップ・ファーム・VPS が 「日本にいる作業者」という見せかけを作り（layer 2）、クラウドソーシングや 企業の採用を通じて正規の資格情報で内部に入る（layer 3・4）。 得られた暗号資産と報酬は海外へ送金される（layer 5）。 2つの経路は、攻撃者が使っていたIPアドレスの一致によって結びつけられた。

CISO・経営層への示唆
  • 採用と業務委託は、もはや人事だけの領域ではない——攻撃者は同じ指揮系統でそこから入ってくる
    警察庁とFBIは、サイバー攻撃を行う WaterPlum と、身分を偽って就職・受注する 北朝鮮IT労働者が、ともに313総局の指揮下にあると評価した。根拠として双方の IPアドレスの一致を挙げている。攻撃の入口と採用の入口が同じ組織から出ている。
    取るべき行動 採用プロセス（応募受付・書類選考・面接・入社手続き）と業務委託先の選定を、 情報セキュリティのリスク評価の対象に正式に加える。人事・調達部門と セキュリティ部門の間で、なりすましの兆候を共有する連絡経路を作る。 bitFlyer の事例に挙げられた面接時の観察点を、選考担当者向けの資料に落とす。
  • 侵害は自社の境界の外で起きる。従業員の求職活動という、統制が及ばない場所が入口になる
    WaterPlum の初期侵入は、求職者個人の端末で「面接課題を実行する」ことによって成立する。 メールゲートウェイもプロキシも通らない。標的は現職の従業員に限らず、 転職を考えている従業員、副業のフリーランス、業務委託先の技術者である。 窃取された認証情報は、その後で勤務先ネットワークへの侵入に使われる。
    取るべき行動 「従業員の私物端末が侵害された」を独立したインシデントの型として対応計画に書き、 影響範囲の初期値を「その人が業務で使っていた全アカウント」に置く。 認証情報の全面変更とセッション一括失効を、端末の感染が疑われた時点で 発動できる手順にする。あわせて、フィッシング耐性のある多要素認証を 全社アカウントに広げ、認証情報単体では入れない状態を作る。
  • ラップトップ・ファームは、発注側の一般的な本人確認を通過するように作られている
    国内の支援者宅に置かれたPCを遠隔操作するため、発注元から見えるIPアドレスは 日本国内を指す。報酬の振込先も支援者名義の国内口座で、提示される身分証明書画像も 支援者のものである。警察庁はこの仕組みを我が国で初めて把握・解体したと述べた。 IPアドレス・口座・身分証という3つの確認が、いずれも無力化される。
    取るべき行動 リモートの業務委託先について、本人確認を「書類の提示」から 「検証可能性の確認」へ移す（資格の認定番号の照会、前職への照会、 ビデオ面談での即時性のある受け答え）。再委託の禁止条項と、 疑いを把握した時点でのアカウント・セッションの即時無効化を契約に書き込む。 発注先へ渡す情報とアクセス権限を必要最小限・最小権限に絞る。
  • 北朝鮮IT労働者への発注は、被害にとどまらず制裁違反の問題になる
    公表資料は「北朝鮮IT労働者に対して業務を発注し報酬を支払った場合、または 外貨獲得の幇助行為を行った場合、国内法令や対北朝鮮制裁の違反行為に問われる おそれがあります」と明記している。個人に対しても、北朝鮮の者と知って報酬を支払ったり 身分証明書（画像を含む）を提供したりすると犯罪に加担する可能性があるとしている。
    取るべき行動 法務・調達部門と協議し、業務委託先のスクリーニングに制裁リスクの観点を加える。 疑いを把握した場合の社内エスカレーション経路と、警察への相談の判断基準を あらかじめ決めておく。クラウドソーシング経由の小口の発注が 部門ごとに散在していないか棚卸しする。
  • 当局の注意喚起は「読んで終わり」にできる形では出ていない——国内の被害規模もIoCも示されていない
    公表されているのは世界全体の数字（3万台以上・100以上の国と地域・7千件以上・約17億円相当）で、 日本国内の感染台数や被害額は示されていない。C2 のIPアドレス・ドメイン・ ファイルハッシュ・悪性 npm パッケージ名の一覧も含まれていない。 自社が影響を受けたかを確認する材料が、この資料だけでは足りない。
    取るべき行動 公表資料に載っているマルウェアファミリ名（BeaverTail・InvisibleFerret・ OtterCookie・OtterCandy・StoatWaffle）を手がかりに、ベンダーの解析記事から IoC を収集して自社のログと突き合わせる作業を、担当者に明示的に割り当てる。 「当局が注意喚起を出した」ことを対応の完了と扱わない。
セキュリティ技術者への示唆
  • VS Code の「ワークスペースの信頼」は、この攻撃に対する実効的な防御点である——ただし条件付きで働かない
    StoatWaffle は悪性の `.vscode/tasks.json` に自動実行コードを埋め込み、 フォルダが開かれ信頼された時点で実行される。制限モードで開けば実行されない。 ところが、過去に「信頼する」と設定したフォルダの配下で開いた場合や、 `security.workspace.trust.enabled` を無効にしている場合は警告が出ない。
    取るべき行動 開発端末のポリシーとして `security.workspace.trust.enabled` を有効のまま固定する。 第三者から受け取ったプロジェクトを、自分の信頼済みフォルダの中に配置しない運用を周知する。 受け取ったプロジェクトは制限モードまたは別のエディタで `.vscode/tasks.json` を 先に開いて確認する手順を、開発チームの標準作業に入れる。
  • 貼り付けを指示されたコマンドの文字列は、この手口を止める最後の分岐点になる
    注意喚起は、指示に従ってウィンドウに貼り付けるコマンドに curl・base64・-enc・ mshta・Invoke-WebRequest -uri・iwr -uri・hidden といった文字列が含まれる場合に 特に注意するよう促している。実行の直前であり、まだ何も起きていない段階である。
    取るべき行動 これらの文字列を含むコマンドを実行しようとしたときに警告する仕組みを、 端末側（EDR のスクリプト実行検知、PowerShell のスクリプトブロックログ）で用意する。 あわせて、開発者向けの周知資料に実際の文字列を列挙して載せる （抽象的な「不審なコマンドに注意」では止まらない）。
  • 駆除では終わらない。感染が疑われた端末は初期化を前提に扱う
    注意喚起は「ウイルス対策ソフトが検知・駆除したからといって安心しないでください」と述べ、 検知前に暗号資産を含む情報が既に窃取された可能性を考慮するよう求めている。 さらに検知できていない別のマルウェアが潜伏している可能性にも言及している。 永続化の具体的な手段は公表されていないため、残存の有無を確認する方法が無い。
    取るべき行動 インシデント対応手順に「本件の型では駆除ではなく初期化」を明記する。 初期化の前に必要なデータのバックアップを取る手順、通信の即時遮断 （Wi-Fi 切断・LAN ケーブルの抜去）を最初の操作として書く。 暗号資産を扱っていた場合は、別のPCから新しいウォレットを作って全資産を退避させる。
  • 組織のログに現れるのは「正規の認証情報による正常なログイン」だけである
    窃取されるのはブラウザに保存された認証情報・クリップボード・キー入力・ スクリーンショットで、収集は個人端末で行われる。組織側に痕跡が出るのは その認証情報が使われる段階からで、認証としては成功した正常なログインに見える。
    取るべき行動 発信元IPアドレス・端末・時間帯・地理の変化を条件にした再認証（条件付きアクセス）を 設定し、ベースラインからの逸脱を検知対象にする。ブラウザへの業務用認証情報の保存を ポリシーで禁じ、管理されたパスワードマネージャに寄せる。 セッショントークンの有効期間を短くし、失効を一括で行える状態にしておく。
  • 公表資料には機械可読なIoCが無い。マルウェア名からベンダーの解析へ辿る作業が要る
    注意喚起にはコマンド文字列の例・VPN サービス名・マルウェアファミリ名はあるが、 C2 のIPアドレス・ドメイン・ファイルハッシュ・悪性 npm パッケージ名の一覧は無い。 NTTセキュリティ・ジャパンが OtterCookie・OtterCandy・StoatWaffle の解析記事を 公開しており、警察庁の謝辞にも同社が挙げられている。
    取るべき行動 NTTセキュリティ・ジャパンの各解析記事および他ベンダーの Contagious Interview 関連レポートから IoC を収集し、DNS・プロキシ・EDR のログと突き合わせる。 開発端末が導入した npm パッケージの一覧を収集できる状態を作り、 悪性パッケージ名が公表された際に即座に照合できるようにする。
