INC-2026-0187F5 BIG-IP APM にゼロデイ悪用

社外からの入口を作る F5 BIG-IP Access Policy Manager（APM）に、ヒープベースのバッファオーバーフロー（CVE-2026-94127・CVSS 9.8）があり、認証を持たない攻撃者が細工した通信を送るだけで機器上で任意のコードを実行できる——F5 は自社内部で見つけ、実際の悪用を把握したとして2026年9月22日に修正版を公開した。成立条件は「同じ仮想サーバにアクセスポリシーと OAuth プロファイルを設定し、OAuth 認可サーバとして構成していること」で、APM を OAuth クライアント・リソースサーバとしてのみ使う構成は影響を受けない。米 CISA は同日 KEV へ収載し、対応期限を3日後の9月25日とした

脆弱性続報が続いている有名事象として記録（日本と直接の関係は薄い）設計・実装上の不備未知の脆弱性の悪用
初報: 2026年9月22日 最終更新: 2026年9月23日

社外から社内システムへ入るときの認証・認可を担う F5 BIG-IP Access Policy Manager（APM）に、認証を持たない遠隔の攻撃者が細工した通信を送るだけで任意のコードを実行できる脆弱性 CVE-2026-94127 が見つかりました。種別はヒープベースのバッファオーバーフロー（CWE-122）、CVSS v3.1 基本値は 9.8、CVSS v4.0 は 9.3 です。F5 は2026年9月22日（現地時間）にアドバイザリ K000162605 を公開し、実際の悪用を把握していると明らかにしました。脆弱性は F5 が自社内部で発見したものです。

成立条件は限定されています。同じ仮想サーバにアクセスポリシーと OAuth プロファイルを設定し、APM を OAuth 認可サーバとして構成している場合に限り影響を受けます。APM を OAuth クライアントまたはリソースサーバとしてのみ使い、認可サーバのプロファイルを設定していない構成は影響を受けません。一方で、アプライアンスモードでも影響を受けます。対象は 17.1.0〜17.1.3・17.5.0〜17.5.1・21.1.0 です。

米 CISA は公開と同じ2026年9月22日に KEV（悪用が確認された脆弱性カタログ）へ収載し、連邦民間行政機関の対応期限を3日後の9月25日としました。同じ日に CISA が追加した4件のうち3件は境界・管理機器のもので、Check Point の2件（CVE-2026-85102・CVE-2026-93616）とArista VeloCloud Orchestrator の1件（CVE-2026-93952）が並んでいます。

CERT-EU とカナダのサイバーセキュリティセンターは同日に勧告を出し、当てる前に侵害を調べることを求めました。F5 が示した手がかりは、/var/log/apm に繰り返し残る OAuth 認証失敗、tmctl global_oauth_stat の total_failed の不自然な増加、その前後の /var/log/audit の不審なコマンド、そして TMM のコアファイル（SIGABRT）です。本記録の作成者が2026年9月23日に確認した範囲では、JPCERT/CC の2026年の注意喚起一覧に本脆弱性の注意喚起はありません（F5 BIG-IP APM については2026年3月30日のCVE-2025-53521 の注意喚起が最後です）。国内の被害の公表も見当たりません。本記録は、公表資料に基づく事実と、本記録の作成者による評価を分けて整理します。

攻撃の経過

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

認証を持たない遠隔の攻撃者が、BIG-IP APM の OAuth 認可サーバとして構成された 仮想サーバへ細工した通信を送り、OAuth 処理のヒープベースのバッファオーバーフローを 突いて機器上で任意のコードを実行する。実際の攻撃で侵入後に何が行われたか （どの資格情報が取得され、どこへ送られたか）は公表されていない。 F5 と CERT-EU は、OAuth 認証失敗の繰り返し・監査ログの不審なコマンド・ TMM のコアファイル（SIGABRT）の連なりを手がかりとして示している。

  1. 1. 初期侵入確認済[1] [2] [4]
    攻撃者が、OAuth 認可サーバとして構成された仮想サーバへ細工した通信を送る。 資格情報も利用者の操作も不要である。OAuth プロファイルの処理が、 攻撃者が影響できるデータを大きさの検証なしにヒープ領域へ書き込む。
    根拠: F5 のアドバイザリ K000162605 と CERT-EU 勧告 2026-013
  2. 2. 実行確認済[1] [2] [3]
    バッファオーバーフローの成立により、機器上で任意のコードが実行される。 実際の攻撃で何が実行されたかは公表されていない。
    根拠: F5 のアドバイザリとカナダ AL26-022 の記述（remote code execution・full system compromise）
  3. 3. 認証情報アクセスunconfirmed[1]
    本件で資格情報が取得されたかは公表されていない。一般に APM には、 認証セッションの情報、連携先アプリケーションの設定、SSL 証明書と秘密鍵、 ディレクトリ連携用のアカウントが集まる。
    根拠: 公表資料に記載なし（製品の役割からの位置づけ。本記録の作成者による評価）
  4. 4. 影響（暗号化・破壊・改ざん）unconfirmed[3]
    APM は社外から社内への入口で認証・認可を判定する。掌握されれば、 通過の可否そのものを操作され、背後の社内システムへの足場になりうる。 本件でそうした操作が行われたかは公表されていない。
    根拠: 公表資料に記載なし（カナダ AL26-022 の「full system compromise」の記述からの位置づけ）

社外からの入口を守る機器が、認証の前に落ちた——OAuth 認可サーバ構成だけが的になった原因・手口出典 [1] [2] [6] [7]

BIG-IP APM は、社外から社内システムへ入るときの認証・認可を担う部品です。SSL-VPN やリモートアクセスの入口、あるいは複数のアプリケーションへのシングルサインオンの窓口として、社外に面した位置に置かれます。

CVE-2026-94127 は、その APM の OAuth 処理におけるヒープベースのバッファオーバーフロー（CWE-122）です。攻撃者が細工した通信を送ると、入力の大きさを検証しないままヒープ領域へ書き込みが行われ、認証を持たない攻撃者による任意コード実行に至ります。利用者の操作も、正規の資格情報も要りません。

成立条件は限定されています。F5 の説明では、同じ仮想サーバにアクセスポリシーと OAuth プロファイルの双方が設定され、APM がOAuth 認可サーバとして構成されている場合に限ります。APM を OAuth クライアントまたはリソースサーバとしてのみ使い、認可サーバのプロファイルを設定していない構成は影響を受けません。一方、アプライアンスモードでも影響を受けるため、「アプライアンスモードだから安全」とは読めません。

本記録の評価として、押さえるべきは的の位置です。この機器は「社外の誰かが最初に触れるもの」で、攻撃者から見れば資格情報を用意する必要がなく、内部ネットワークへの足場をいきなり得られます。APM には、認証のためのセッション情報、連携先アプリケーションの設定、証明書と秘密鍵、ディレクトリ連携用のアカウントが集まります。本件でそれらが実際に取得されたかは公表されていませんが、機器上でコードを実行された前提では読まれたものとして扱うのが安全です。

公開と KEV 収載が同じ日で、期限は3日——しかも同じ日に境界・管理機器が3社4件そろった概観出典 [5] [8]

F5 がアドバイザリを公開したのは2026年9月22日（現地時間）、CISA が KEV へ追加したのも同じ9月22日です。対応期限は3日後の9月25日に設定されました。公開と収載が同日であるという事実は、修正版が世に出る前から悪用されていたことを意味します。

この日、CISA が KEV へ追加したのは4件でした。

  • F5 BIG-IP APM CVE-2026-94127（本件・CVSS 9.8）
  • Check Point CVE-2026-85102（証明書検証の不備・9.8）とCVE-2026-93616（パストラバーサル・9.8）——INC-2026-0188
  • Arista VeloCloud Orchestrator CVE-2026-93952（入力検証の不備・CVSS 10.0）

いずれも期限は9月25日で、3社とも社外との境界か、機器の管理面に置かれる製品です。本記録の評価として、これは運用側にとって「1件ずつ順番に処理する」前提が崩れる日でした。対象機器の洗い出し・変更管理の承認・停止時間の確保・侵害調査を、3系統ぶん同時に走らせる必要があったことになります。平時に「実悪用が確認された境界機器は変更管理の次回の窓を待たない」という合意が無い組織では、この日の判断だけで数日が溶けます。

当局が求めたのは「当てること」ではなく「当てる前に調べること」だった対策・注意喚起出典 [1] [2] [3]

CERT-EU の勧告 2026-013 は、対処の順序を①証拠の保全 ②修正版の適用 ③侵害の痕跡の確認と明記しています。悪用が修正版の公開より先行していた以上、更新だけでは「すでに入られていた場合」の被害は止まりません。

F5 が示した手がかりは、単独では判断できないものを連なりとして見ます。CERT-EU は「複数回の OAuth 認証失敗 → その直後の不審なコマンド →ほどなく発生する TMM の SIGABRT、という組み合わせが人の目でのレビューへ進むべき合図である」（原文英語）としています。具体的には次の4点です。

  1. /var/log/apm に残る OAuth 認証失敗の繰り返し。とくに単一の IP から短時間に10回以上のRequest UserInfo from Source ID (null) IP <IP> failed. Error Code (invalid_token)
  2. tmctl global_oauth_stat -s total_requests,total_userinfo_requests,total_failed のtotal_failed の説明のつかない増加
  3. OAuth の失敗が見えた前後の /var/log/audit の不審なコマンド
  4. TMM のコアファイル。コアファイルの存在だけでは兆候にならないが、F5 は TMM がループに入り SOD デーモンが SIGABRT を送る挙動を観測したとしている

直ちに更新できない場合、F5 は当該仮想サーバ向けの iRule による緩和策をサポート経由で提供しています。本記録の評価として、これは「攻撃の通り道を塞ぐ」ものであって修正ではないため、適用したうえで更新の計画を止めないことが要ります。

影響するのは「APM を OAuth 認可サーバにしている構成」だけ——だからこそ設定の棚卸しが先に来る被害規模・影響範囲出典 [1] [4] [6] [7]

F5 は、APM を使っているすべての組織が危険なわけではないと強調しています。影響するのは APM の OAuth 部品で、OAuth 認可サーバのプロファイルを設定していない（クライアントまたはリソースサーバとしてのみ使う）構成は対象外です。対象版は 17.1.0〜17.1.3・17.5.0〜17.5.1・21.1.0 で、修正版は系列ごとに異なります（17.1 系は Hotfix-BIGIP-17.1.3.5.0.41.14-ENG、17.5 系は Hotfix-BIGIP-17.5.1.9.0.160.12-ENG、21.1 系はHotfix-BIGIP-21.1.0.2.0.30.22-ENG）。

本記録の評価として、この「条件つき」は運用側にとって楽な知らせではありません。判定に必要なのは版数だけでなく、どの仮想サーバに何のプロファイルが乗っているかという設定の中身だからです。BIG-IP は1台に多数の仮想サーバを抱えることが多く、設定の変遷を追えないまま「たぶん該当しない」と判断すると、当たっていない機器が1台残ります。

判定を機器の台数ではなく仮想サーバ単位で行い、「アクセスポリシーが設定されているか」「OAuth プロファイルが設定されているか」「認可サーバとして構成されているか」の3つを記録として残す。これが、次に同じ形の脆弱性が出たときに再利用できる資産になります。

国内の注意喚起は出ていない——日本語の合図を着手条件にすると出遅れる未確定事項出典 [6] [9]

本記録の作成者が2026年9月23日に確認した範囲では、JPCERT/CC の2026年の注意喚起一覧に本脆弱性の注意喚起はありません（2026年9月の注意喚起はCisco Secure Email Gateway・Adobe・マイクロソフトの3件）。F5 BIG-IP APM については、2026年3月30日の CVE-2025-53521 に関する注意喚起が直近のものです。国内での被害の公表も見当たりません。

一方、日本語の報道は翌9月23日に出ています。Security NEXT は「『BIG-IP APM』に脆弱性、悪用を確認 - 侵害調査を」として、F5 が自社内部で発見し、すでに悪用を確認していること、侵害状況の確認を呼びかけていることを伝えました。

本記録の評価として、着手の合図を「JPCERT/CC の注意喚起」に置いている組織は本件で動けません。注意喚起が出るかどうかは、その時点で国内の相談が上がっているかに左右されるためです。開発元のアドバイザリと CISA の KEV 収載を、それぞれ単独で着手条件として扱う運用にしておく必要があります。

緩和策
item: 修正版（17.1 系／17.5 系／21.1 系のホットフィックス）への更新　副作用: APM は社外からの接続の入口であるため、更新と再起動の間、 リモートアクセスとシングルサインオンが停止する。高可用性構成では 待機系から順に更新する手順と、切り替え時のセッション切断の扱いを決める必要がある。 系列ごとにビルドが異なるため、取り違えると「当てたのに直っていない」状態になる
item: F5 がサポート経由で提供する iRule による緩和　副作用: 当該仮想サーバの OAuth 処理に手を入れるため、正規の OAuth 連携にも 影響しうる。入手にサポート契約と問い合わせが要り、即時性に限界がある。 緩和であって修正ではなく、適用後も更新の計画を止められない
item: OAuth 認可サーバ構成の棚卸し（該当する仮想サーバの特定）　副作用: 設定の確認そのものに機器の停止は要らないが、仮想サーバが多い環境では 時間がかかる。「該当しない」と結論づけた根拠を残さないと、 次の脆弱性のときに同じ確認をやり直すことになる
item: 侵害調査（/var/log/apm・/var/log/audit・TMM コアファイルの確認）　副作用: ログの保全期間を超えている場合、確認そのものが成立しない。 「出力なし＝安全」とは読めず、機器の外の通信記録との突合が要る。 コアファイルの存在だけでは兆候にならないため、時刻の一致を見る判断が要る
indicators
item: /var/log/apm の OAuth 認証失敗の繰り返し（例: Request UserInfo from Source ID (null) IP <IP> failed. Error Code (invalid_token)）　補足: F5 は、単一の IP から短時間に10回以上の出現をとくに注視するよう求めている
item: tmctl global_oauth_stat -s total_requests,total_userinfo_requests,total_failed の total_failed の不自然な増加　補足: 認証失敗の統計値の跳ね上がりを、ログの grep とは別の角度から捉えるための指標
item: OAuth の失敗が観測された前後の /var/log/audit に残る不審なコマンド　補足: 失敗の繰り返しと時刻で突き合わせる。単独では判断材料にならない
item: TMM のコアファイル（TMM がループに入り SOD デーモンが SIGABRT を送る挙動）　補足: コアファイルの存在だけでは兆候にならないが、OAuth 失敗の直後であれば人の目で確認する

CISO・経営層への示唆
  • 境界機器の緊急更新は「止まると社外からの業務が止まる」から先送りされる——その承認を平時に用意しておく
    APM は社外からの接続の入口で、更新・再起動の間はリモートアクセスと シングルサインオンが止まる。実悪用が確認され、米連邦機関の期限は3日だった。 先送りした期間は、悪用が続いている中で無防備な期間になる。
    取るべき行動 境界機器について「実悪用の公表があった場合は変更管理の次回の窓を待たずに 更新する」事前承認を用意する。承認文に実施者・想定停止時間・ 利用者への案内文の雛形を含め、当日に決める要素を減らしておく。
  • 同じ日に3社4件が KEV へ並ぶことがある——「1件ずつ順番に」の前提は崩れる
    2026年9月22日、CISA は F5・Check Point（2件）・Arista の4件を同じ期限で KEV へ追加した。いずれも境界か管理面の製品である。対象の洗い出し・承認・ 停止時間の確保・侵害調査を、3系統ぶん同時に走らせる必要があった。
    取るべき行動 境界・管理系の機器について、製品ごとに「担当者・保守契約・更新の実施主体 （自社か委託先か）・止めたときに影響する業務」を1枚にまとめておく。 複数同時のときは、社外に面している順・実悪用の有無の順で並べて処理する。
  • 「当てた」を完了条件にしない——当局が求めたのは侵害の確認まで
    CERT-EU は「証拠の保全 → 適用 → 侵害の痕跡の確認」の順を示し、 F5 も侵害調査の観点を公開した。悪用が修正版より先行していた以上、 更新だけでは、すでに入られていた場合の被害は止まらない。
    取るべき行動 緊急更新の完了報告に「ログの確認結果」「機器が保持する証明書・ ディレクトリ連携用アカウントの更新の要否」「保全したログの範囲」の 3欄を設け、更新完了だけで案件を閉じない運用にする。
  • 日本語の注意喚起を着手条件にしない
    本件では、本記録の作成者が2026年9月23日に確認した範囲で JPCERT/CC の 注意喚起が出ていない。一方、日本語の報道（Security NEXT）は 翌日に出ている。注意喚起が出るかどうかは、その時点で国内の相談が 上がっているかに左右される。
    取るべき行動 脆弱性対応の着手条件に、開発元のアドバイザリと CISA KEV の収載を それぞれ単独の条件として明記する。日本語の注意喚起は「あれば加点」であって、 待つ対象にしない。
セキュリティ技術者への示唆
  • 判定の単位は機器ではなく仮想サーバ——版数だけでは該当の有無が決まらない
    影響するのは、同一の仮想サーバにアクセスポリシーと OAuth プロファイルが 設定され OAuth 認可サーバとして構成されている場合に限られる。 BIG-IP は1台に多数の仮想サーバを抱えることが多い。
    取るべき行動 仮想サーバごとに「アクセスポリシーの有無」「OAuth プロファイルの有無」 「認可サーバ構成かどうか」を機械的に抽出して一覧にする。 該当しないと判断した根拠も残し、次の脆弱性のときに再利用できる形にする。
  • 機器の「落ち方」を攻撃の痕跡として読む
    F5 は TMM がループに入り SOD デーモンが SIGABRT を送る挙動を観測したとしている。 コアファイルの存在は単独では兆候にならないが、OAuth 認証失敗の繰り返しの 直後であれば意味が変わる。運用の現場では、機器の異常終了は 「不安定だった」で片づけられやすい。
    取るべき行動 コアファイルの生成、TMM の異常終了、OAuth 失敗数の急増を監視項目にし、 発生時刻を突き合わせられるようログを機器の外へ転送する。 過去のコアファイルも、保全されていれば時刻を確認する。
  • 版数の管理はビルド番号まで——系列ごとに修正版が異なる
    修正版は 17.1 系・17.5 系・21.1 系でビルドが異なる （Hotfix-BIGIP-17.1.3.5.0.41.14-ENG／17.5.1.9.0.160.12-ENG／21.1.0.2.0.30.22-ENG）。 「17 系は対応済み」といった粒度の管理では、当たっていない機器が残る。
    取るべき行動 資産台帳の版数欄をビルド番号まで持たせ、更新後に実機から取得した値で 突き合わせる。委託先が更新を実施する場合も、報告に実機の出力を添えさせる。
  • 侵害調査に要るログが、その機器にしか無い状態を解消する
    調査の起点は /var/log/apm と /var/log/audit、そして TMM のコアファイルである。 いずれも機器上にあり、機器上でコードを実行された後は信頼性が下がる。 保全期間が短ければ、調べようとした時点で既に消えている。
    取るべき行動 APM のログを常時外部の基盤へ転送し、保全期間を明文化する。 転送されていない環境では、まず証拠の保全（スナップショット・ログの退避）を 行ってから更新する（CERT-EU が示す順序）。

自組織に当てはまるか

該当する項目があれば、この事案と同じ構図が自組織でも成立しうることを意味します。
観点自社に当てはまるか該当する場合に何が起きうるか
システム構成□ F5 BIG-IP の Access Policy Manager（APM）を運用しており、版が 17.1.0〜17.1.3・17.5.0〜17.5.1・21.1.0 のいずれかに該当する対象版であることが前提条件になる。版数をビルド番号まで把握していなければ、 該当の有無も判定できない。
認証・認可□ APM を OAuth 認可サーバとして構成している（同一の仮想サーバにアクセスポリシーと OAuth プロファイルがある）F5 はこの構成に限って影響を受けるとしている。逆に、この設定を 即座に答えられない組織は「影響を受けない」とも言えない状態にある。
システム構成□ 当該の仮想サーバがインターネットから到達できる位置にあるデータプレーン側の問題であり、管理面を閉じていても防御にならない。 社外に面していれば、認証を持たない攻撃者から直接到達される。
運用・監視□ APM のログ（/var/log/apm・/var/log/audit）を機器の中にしか置いておらず、外部へ転送していないF5 と CERT-EU が示す侵害調査は、これらのログを起点にする。 転送も保全もしていなければ、確認手順そのものが成り立たない。
運用・監視□ 境界機器の緊急更新に必要な承認・停止時間の確保が、その都度の調整になっているKEV の期限は3日で、同じ日に他社製品の緊急対応も重なった。 その都度の調整では、複数同時のときに処理が間に合わない。
体制・契約□ 脆弱性対応の着手条件が「JPCERT/CC の注意喚起が出たら」になっている本件では確認時点で国内の注意喚起が出ていない。日本語の合図を待つ運用では、 実悪用が確認されている期間に何も始まらない。
