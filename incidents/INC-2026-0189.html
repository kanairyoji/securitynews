INC-2026-0189ShinyHunters が FBI 侵害を主張

恐喝集団 ShinyHunters が「米連邦捜査局（FBI）の採用システムを Oracle PeopleSoft のゼロデイで破り、現職・元職員と応募者のデータ2〜3テラバイトを盗んだ」と主張し、FBI の求人サイト apply.fbijobs.gov を改ざんした——FBI は「FBIjobs.gov に影響する不正な活動の主張を把握しており調査中」と述べるにとどめ、侵害の有無もデータの流出も認めていない。攻撃者は金銭を求めず、2026年5月に FBI が同集団について出した注意喚起の訂正・撤回を1週間の期限つきで要求している。報道機関は約5,000件のサンプルの一部が実在の人物と一致することを確認したが、ゼロデイの存在は Oracle からも確認されていない

不正アクセス・侵害続報が続いている有名事象として記録（日本と直接の関係は薄い）未知の脆弱性の悪用公表されていない／不明
初報: 2026年9月22日 最終更新: 2026年9月24日

恐喝集団 ShinyHunters が、米連邦捜査局（FBI）の採用系システムを侵害したと主張しました。主張の骨子は、Oracle PeopleSoft の未修正のゼロデイ（遠隔コード実行）を2026年9月21日（月）の夜に使って FBI のシステムへ入り、そこからFBI が管理する AWS GovCloud 環境へ横展開し、現職・元職員と応募者に関する2〜3テラバイトのデータを持ち出した、というものです。攻撃者は FBI の刑事司法情報サービス（CJIS）・人事・MedLink などのサービスにも到達したと述べています。

FBI は報道機関に対し「FBIjobs.gov に影響する不正な活動の主張を把握しており、現在調査中である」（原文英語）と述べました。侵害の有無もデータの窃取も認めていません。一方で、求人サイト apply.fbijobs.gov と特別捜査官の応募ポータルは停止し、「メンテナンス中」の表示に切り替わっています。攻撃者は、同サイトを「THIS SITE HAS BEEN SEIZED BY SHINYHUNTERS.（このサイトは ShinyHunters に差し押さえられた）」という文言で改ざんしたスクリーンショットを複数の報道機関へ渡しました。

この事案の特異な点は動機です。ShinyHunters は「これは金銭目的ではない」と述べ、身代金ではなく、2026年5月15日に FBI が同集団について出した注意喚起の訂正か撤回を1週間の期限つきで求めています。その注意喚起は、同集団が被害者やその家族への脅迫的な連絡やスワッティングを行い、存在しない恥ずかしい写真や動画を持っていると偽って恐喝することがある、としたものでした。ShinyHunters はこれらを否定し、犯罪者の緩やかな連合体「The Com」との関係も否定しています。

裏付けの状況は限定的です。最初に報じた 404 Media は約5,000件の FBI 職員データのサンプルを受け取り、一部の電話番号が同姓同名の人物や米司法省関係者のものと一致することを確認したと報じました。他方、BleepingComputer はゼロデイの存在・横展開・盗まれた量のいずれも独自には確認できていないとしています。Oracle と AWS は報道機関の問い合わせに回答していません。本記録の作成者も2026年9月23日に FBI・FBIjobs.gov・Oracle の各サイトへアクセスを試みましたが、いずれも 403 で取得できませんでした。本記録は、攻撃者の主張と、確認された事実を区別して整理します。

2026年9月24日 続報反映更新履歴へ
続報の反映。2026年9月24日の日中の新着記事（iThome Security・Defense One）を起点に、 ロイターの配信版（9月23日）と Defense One（9月24日）を取得して裏取りした。 サンプル約5,000行の内訳（中国関連14人・ロシア関連9人・イランおよびヒズボラ関連3人・ 傍受や秘匿技術18人・人的情報収集11人）と、ロイターが22人以上について記載内容を 個別に確認したことを時系列と数値に追加した。 ただし**確認されたのは「記載された人物が実在すること」であって 「データが FBI から出たこと」ではない**点を数値の注記と本文に明記し、 データの真正性に関する未確定事項もこの趣旨で更新した。 機微な任務に就く職員とその家族への保護措置の有無が公表されていないことを 未確定事項に追加した。FBI・Oracle・Amazon の新たな公表は確認できていない。

  • 攻撃者が「他の組織や Fortune 500 に対して同じゼロデイを使っている」とする主張の実態検証できない
    ShinyHunters は BleepingComputer に対し、教育分野を狙ったあと、 同じ PeopleSoft の脆弱性を企業や Fortune 500 に対して使っていると述べている。 裏づけとなる被害の公表も、第三者による観測も本記録の確認時点では見当たらない。 ただし、もし実在するなら PeopleSoft を使う組織全体に関わるため、 「確認されていないが否定もされていない」状態として扱う必要がある。
  • 盗まれたとされるデータの中身と真正性調査したが確定せず
    404 Media は約5,000件のサンプルのうち一部の電話番号が実在の人物と一致したとしている。 BleepingComputer は2件のサンプルを受け取ったが、真正性も出所も独自には 確認できていないとして内容を公開していない。攻撃者が主張する 「ほぼ全ての FBI 捜査官と応募者」という範囲は、公表資料では裏づけられていない。 2026年9月23日のロイターの検証で、サンプルに記載された22人以上が実在の人物と 一致することは確認されたが、**そのデータが FBI から出たものかは依然として確認されていない**。
  • 機微な任務に就く職員への保護措置の有無公表されていない
    報道により、サンプルには中国・ロシア・イラン・ヒズボラ・カルテルを担当する部署、 傍受や秘匿技術を扱う部署、人的情報収集に携わる職員が含まれるとされる。 該当する職員とその家族に対して、FBI が住所・連絡先の変更や警護などの 保護措置を取っているかは公表されていない。緊急連絡先として名前が挙がる 家族への通知の有無も示されていない
  • FBI の検知と遮断の経緯公表されていない
    攻撃者は「FBI はすぐに気づき、影響を受けたシステムを直ちに切り離した」 「複数のネットワークへの接続が同時に絶たれた」「文字どおり全部のプラグを抜いた」と 述べているが、これは攻撃者の主張である。FBI は検知の時期も対応の内容も 公表していない。サイトの停止は確認されているが、停止の理由も説明されていない。

  • 404 Media が受け取った約5,000件のサンプルのうち、一部の電話番号が同姓同名の人物や米司法省関係者のものと一致したこと

これに対し、侵入の経路・データ量・到達したシステム・動機のいずれも攻撃者の主張です。FBI は侵害の有無を認めておらず、Oracle も AWS も回答していません。本記録の作成者が2026年9月23日に FBI・FBIjobs.gov・Oracle の各サイトへアクセスを試みたところ、いずれも HTTP 403 で取得できませんでした。

本記録の評価として、この段階の事案で最も危ういのは、攻撃者の主張をそのまま「事実」として社内へ伝えてしまうことです。2〜3テラバイト、ほぼ全ての捜査官、CJIS への到達——いずれも刺激的ですが、現時点で裏づけがあるのは「サンプルの一部の電話番号が実在の人物と一致した」ことまでです。逆に、裏づけが無いことは「起きていない」ことも意味しません。本記録は、確認された事実・攻撃者の主張・本記録の評価を分けて書きます。

狙われたのは採用系システムだった——「重要度が低い」と分類されがちな場所に最も機微な情報が集まる原因・手口出典 [1] [3] [4]

攻撃者の主張によれば、入口は求人サイトの Oracle PeopleSoft サーバでした。PeopleSoft は人事・採用の分野で、応募者の個人情報を保管するために広く使われています。そこから FBI が管理する AWS GovCloud 環境へ横展開し、職員と応募者のデータへ到達したとしています。

本記録の評価として、ここには一般化できる論点があります。採用系システムは、社内の重要度評価で低く置かれがちです。基幹業務でも、顧客データでもなく、外部（応募者）に向けて公開する必要があるためです。しかし実際にそこへ集まるのは、氏名・住所・電話番号・職歴・家族構成・場合によっては健康情報や身元調査の結果といった、組織が保持する中でも最も機微な種類の個人情報です。

さらに、採用系は「外部に公開されていること」が要件です。応募者が誰でも到達できなければ機能しないため、境界の内側に隠すという防御が使えません。本件で攻撃者が主張する構図——公開系の入口から、認証情報や信頼関係を介して内部のデータ基盤へ——は、採用系に限らず、「公開が要件である系」と「機微なデータを持つ系」が地続きになっている場所で繰り返し起きる形です。

要求が金銭ではない——「評判の訂正」を求める恐喝という前例評価・解釈出典 [1] [2] [4]

ShinyHunters はリークサイトの声明で、攻撃は2026年5月15日の FBI の注意喚起への報復であり「これは金銭目的ではない」と述べました。要求は身代金ではなく、注意喚起の訂正または撤回です。期限は1週間としています。

FBI の注意喚起は、同集団が被害者やその家族への脅迫的な連絡やスワッティングを行い、存在しない恥ずかしい写真や動画を持っていると偽って恐喝することがある、としたものでした。ShinyHunters はこれらを否定し、犯罪者の緩やかな連合体「The Com」との関係も否定しています。The Register には「私はこれらの主張と戦うために最善を尽くしてきた。これがそのための最良の方法だ」（原文英語）と述べています。

本記録の評価として、この形は恐喝の目的が「支払い」から「評判の管理」へ広がりうることを示す前例です。恐喝集団にとって、被害者が支払うかどうかは「この集団は本当に危険か」「約束を守るか」という評判に左右されます。当局の注意喚起がその評判を損なうなら、攻撃者にとっては収益基盤への攻撃に見える——という理屈です。

専門家の見方は分かれています。CyberScoop に対し、Halcyon のランサムウェア研究部門の幹部（FBI サイバー部門の元幹部）は「ランサムウェア集団が成功しているのは、おおむね企業のように動いているからだ。他の犯罪集団や法執行機関を、とくに公に辱める形で狙うのは規律の欠如を示しており、歴史的にはテイクダウンや乗っ取り、離反につながってきた」（原文英語）と述べています。一方 Flashpoint の分析者は「この攻撃は、信頼できる脅威としての評判を高めるという点で ShinyHunters に利益がある」（原文英語）としています。本記録はどちらかを採らず、両論を記録します。

主張されたゼロデイは確認されていない——だが「確認されていない」で止めると備えられない未確定事項出典 [1] [4] [6] [7]

攻撃者は「我々が悪用した Oracle の製品は PeopleSoft だ。昨日もう1つ見つけて、すぐに FBI に対して使った」（原文英語）と述べ、さらに同じ脆弱性を企業や Fortune 500 に対しても使っていると主張しています。証拠を消して脆弱性を特定されにくくしたとも述べています。

裏づけはありません。BleepingComputer はゼロデイの存在も横展開も盗まれた量も独自には検証していないと明記し、Oracle と Mandiant へ問い合わせています。The Register も Oracle と AWS から回答を得ていません。本記録の作成者が2026年9月23日に Oracle のセキュリティアラートのページへアクセスを試みたところ 403 で取得できず、CISA の KEV にもPeopleSoft の該当の収載は見当たりませんでした。

本記録の評価として、実務上の構えは次の形になります。「実在が確認されるまで何もしない」でも「主張を事実として扱う」でもなく、いま確認できる作業を先に済ませておく。 具体的には、PeopleSoft を含む人事・採用系の資産の所在とインターネットへの露出状況、それらが持つ他系統への認証情報（クラウド基盤への権限を含む）、Web アクセスログの保全期間の3つを、いま棚卸しすることです。これらはゼロデイが実在してもしなくても価値がある作業で、実在が確認されてから始めると、その時点では数日を要します。

盗まれたとされる情報の性質が、通常の個人情報流出と異なる被害規模・影響範囲出典 [3] [4] [5]

攻撃者が 404 Media に述べたところでは、データには捜査官の氏名・自宅住所・電話番号・配偶者に関する情報が含まれます。改ざんされたサイトの文言には、職員と応募者の機微な個人情報と健康関連情報が含まれるとする記述がありました。攻撃者は、過去の BreachForums の捜査に関わった特別捜査官とされる人物や、FBI 長官に関するとされる記録を報道機関に示しています（報道機関はいずれも真正性を確認しておらず、内容も公開していません）。

TechCrunch はこの点を「盗まれたデータは、ハッカーや外国のスパイが捜査官やその家族を強要・恐喝して外国政府への協力を迫る、重大な防諜上の脅威になりうる」（原文英語）と評しています。

本記録の評価として、ここには一般の組織にも通じる論点があります。流出の重大性は、件数ではなく「その情報が誰を何に晒すか」で決まります。職員の自宅住所と家族構成は、件数としては小さくても、本人の物理的な安全に直結します。自社の従業員データについて、「漏れたときに人が危険に晒される項目」（自宅住所・家族・健康・身元調査の結果など）がどこに、どの範囲で保管されているかを把握している組織は多くありません。件数ベースの影響度評価では、この種のリスクは軽く見積もられます。

波及の構造

事案の構造を図にしたものです。数値は公表値に基づきます。
攻撃者が主張する経路と、外形的に確認できている事実の境目
攻撃者は、求人サイトの PeopleSoft のゼロデイ（layer 1）から侵入し（layer 2）、 FBI が管理する AWS GovCloud 環境へ横展開して（layer 3） 2〜3テラバイトを持ち出したと主張する（layer 4）。 このうち外形的に確認できているのは、サイトの改ざんと停止、 FBI の「調査中」という声明、報道機関が受け取ったサンプルの一部が 実在の人物と一致したことである（layer 5）。破線より上は攻撃者の主張にとどまる。

対応の評価

評価材料がない判断は「評価材料なし」としています。結果論で断じないための区分です。
判断評価評価の根拠と留保
FBI は「FBIjobs.gov に影響する不正な活動の主張を把握しており、現在調査中である」と 述べるにとどめ、侵害の有無・データの窃取・影響範囲・対象人数のいずれも公表していない評価材料なし本記録の作成者の評価である。事案の初日であり、捜査中の機関という特殊性もあるため、 現時点で巧拙を判定する材料は無い。判断材料になるのは、 攻撃者が示した1週間の期限の前後で、職員・応募者への通知が行われるかどうかである。
apply.fbijobs.gov と特別捜査官の応募ポータルが停止し、 「メンテナンスのため一時停止中」の表示になっている評価材料なし本記録の作成者の評価である。停止の判断そのものは、改ざんが確認されている以上 妥当と考えられるが、FBI は停止の理由を説明していないため、 判断の速さも範囲も評価できない。なお「メンテナンス」という表示のまま 事実を説明しない運用は、本DBの他の事案でも繰り返し見られる形である。
CISO・経営層への示唆
  • 攻撃者の主張を、社内報告で「事実」に格上げしない
    本件で確認されているのは、サイトの停止、FBI の「調査中」という声明、 サンプルの一部が実在の人物と一致したことまでである。 2〜3テラバイト、ほぼ全ての捜査官、CJIS への到達は、いずれも攻撃者の主張で、 報道機関も検証していないと明記している。
    取るべき行動 脅威情報の社内共有の様式に「確認された事実／当事者の公表／攻撃者の主張／ 自組織の評価」の4欄を設け、出どころを混ぜずに書く。 経営報告でも、主張には必ず「攻撃者の主張」と添える。
  • 採用系システムの重要度評価を見直す——公開が要件で、かつ最も機微な情報が集まる
    攻撃者が主張する入口は求人サイトの人事システムだった。採用系は 「基幹業務ではない」として重要度が低く置かれがちだが、実際には 氏名・住所・家族構成・場合によっては健康や身元調査の情報が集まり、 外部に公開されていることが要件のため境界の内側に隠せない。
    取るべき行動 人事・採用系の資産を重要度評価で棚卸しし、①インターネットへの露出 ②保持する個人情報の項目 ③他系統（クラウド基盤・社内ディレクトリ）への 権限、の3点を明示する。委託先が運用している場合は、同じ3点を契約で報告させる。
  • 影響度を件数ではなく「漏れたら人が危険に晒される項目」で測る
    本件で問題とされているのは件数よりも中身である。捜査官の自宅住所と 配偶者の情報は、TechCrunch が指摘するとおり強要・恐喝の材料になりうる。 件数ベースの影響度評価では、この種のリスクは軽く見積もられる。
    取るべき行動 従業員データの台帳に「漏えい時に本人の物理的安全に関わる項目」の区分 （自宅住所・家族・健康・身元調査の結果など）を設け、 その区分を持つ表への一括取得を権限と経路の両面で制限する。
  • 恐喝の要求が「金銭以外」になりうることを、危機対応の前提に入れる
    ShinyHunters は身代金を求めず、当局の注意喚起の訂正・撤回を 1週間の期限つきで要求した。支払いの可否という枠組みだけを用意していると、 「公表内容の訂正」「特定の発言の撤回」「人事上の措置」といった 要求が来たときに、誰が判断するかが決まっていない状態になる。
    取るべき行動 インシデント対応計画の「恐喝への対応」の節に、金銭以外の要求 （発表内容の変更・特定個人への対応・第三者への働きかけ）を受けた場合の 判断者と判断基準を書き足す。広報・法務を含めた意思決定の経路を先に決めておく。
セキュリティ技術者への示唆
  • 公開系システムが持つクラウド権限を、いま棚卸しする
    攻撃者が主張する経路は「公開系の Web アプリケーション → 管理下のクラウド環境」である。 この形が成立するのは、公開系が内部のデータ基盤への認証情報や信頼関係を 持っているときである。ゼロデイの実在が確認されなくても、 この経路の点検には価値がある。
    取るべき行動 インターネットに面したシステムごとに、保持しているクラウドの権限・ 長期の鍵・サービス間の信頼関係を一覧にする。長期の鍵は短期の資格情報へ置き換え、 権限は必要な操作に絞る。棚卸しの結果は、次の同種の主張が出たときに再利用する。
  • ログを機器の外へ出しておく——攻撃者は痕跡を消すと明言している
    ShinyHunters は、侵害したサーバから活動の痕跡を消して脆弱性を 特定されにくくしたと述べている。機器上のログだけに頼る調査は、 この種の相手には成立しない。
    取るべき行動 公開系システムのアクセスログ・アプリケーションログ・認証ログを 即時に外部の基盤へ転送し、保全期間を明文化する。 転送の欠落そのものを監視項目にする（途絶えたことが異常の合図になる）。
  • 「識別子の無いゼロデイ」の主張に対する動き方を決めておく
    本件では CVE 番号もアドバイザリも存在せず、開発元は回答していない。 通常の脆弱性対応の手順（CVE を受け取り、対象を特定し、修正を当てる）が そもそも起動しない。何もしないか、過剰に騒ぐかの二択になりやすい。
    取るべき行動 識別子の無い主張に対しては「露出の確認・ログの保全期間の確認・ 当該製品の権限の確認」の3点だけを実施する定型手順を作る。 修正が出た時点で通常の手順へ合流させる。
  • 改ざんの検知と、停止時の案内をあらかじめ用意する
    本件では公開ページが改ざんされ、その画面が報道機関へ配られた。 その後サイトは「メンテナンス中」の表示で停止している。 改ざんの検知が遅れるほど、攻撃者の主張を載せた画面が外に晒される時間が伸びる。
    取るべき行動 公開ページの内容の定期比較による改ざん検知を置き、 検知時の停止判断と、停止中に表示する案内文（事実に反しない表現）を 平時に用意しておく。採用系では応募者向けの代替連絡手段も決めておく。

自組織に当てはまるか

該当する項目があれば、この事案と同じ構図が自組織でも成立しうることを意味します。
観点自社に当てはまるか該当する場合に何が起きうるか
システム構成□ Oracle PeopleSoft を含む人事・採用系のシステムを、インターネットから到達できる位置で運用している攻撃者は同じ脆弱性を他の組織や Fortune 500 に対しても使っていると主張している。 実在は確認されていないが、露出の把握は主張の真偽にかかわらず必要な作業である。
認証・認可□ 公開系のシステムが、社内のデータ基盤やクラウド環境への認証情報・信頼関係を持っている主張されている経路は「公開系 → 管理下のクラウド環境」である。 公開系が持つ権限の広さが、そのまま横展開できる範囲になる。
データの保持□ 従業員・応募者の自宅住所・家族・健康・身元調査の結果を保持しており、その所在を一覧にできない本件で問題になっているのは件数ではなく中身である。 所在が分からなければ、漏えい時に誰がどの危険に晒されるかを判断できない。
運用・監視□ 公開系システムのログを機器の外へ転送しておらず、保全期間が短い攻撃者は痕跡を消したと明言している。機器上のログだけでは、 侵害の有無を後から判断できない。
体制・契約□ 恐喝を受けた場合の判断基準が「金銭を払うかどうか」しか用意されていない本件の要求は注意喚起の訂正・撤回である。金銭以外の要求が来たときに 誰が判断するかが決まっていないと、期限のある交渉に対応できない。
体制・契約□ 脅威情報の社内共有で、攻撃者の主張と確認された事実を区別する様式が無い本件は主張が先行し、裏づけが限定的な段階で大きく報じられた。 区別せずに共有すると、根拠の弱い情報にもとづいて意思決定が行われる。
