恐喝集団 ShinyHunters が、米連邦捜査局（FBI）の採用系システムを侵害したと主張しました。主張の骨子は、Oracle PeopleSoft の未修正のゼロデイ（遠隔コード実行）を2026年9月21日（月）の夜に使って FBI のシステムへ入り、そこからFBI が管理する AWS GovCloud 環境へ横展開し、現職・元職員と応募者に関する2〜3テラバイトのデータを持ち出した、というものです。攻撃者は FBI の刑事司法情報サービス（CJIS）・人事・MedLink などのサービスにも到達したと述べています。

FBI は報道機関に対し「FBIjobs.gov に影響する不正な活動の主張を把握しており、現在調査中である」（原文英語）と述べました。侵害の有無もデータの窃取も認めていません。

さらに9月23日、FBI はこれをプレスリリースとして自ら fbi.gov に掲載し、次の一文を加えています——「侵入点が第三者か FBI 自身の環境かは依然として未確定である。我々は本件を積極的かつ徹底して調査しており、FBIJobs.gov を支える第三者事業者と緊密に連携して、あらゆるリスクを低減している」（原文英語）。つまり FBI 自身が、入口が自組織である可能性と委託先である可能性の両方を残したまま調査していると述べたことになります。侵害の有無・対象人数・第三者事業者の名前は、この声明でも示されていません。

一方で、求人サイト apply.fbijobs.gov と特別捜査官の応募ポータルは停止し、「メンテナンス中」の表示に切り替わっています。攻撃者は、同サイトを「THIS SITE HAS BEEN SEIZED BY SHINYHUNTERS.（このサイトは ShinyHunters に差し押さえられた）」という文言で改ざんしたスクリーンショットを複数の報道機関へ渡しました。

この事案の特異な点は動機です。ShinyHunters は「これは金銭目的ではない」と述べ、身代金ではなく、2026年5月15日に FBI が同集団について出した注意喚起の訂正か撤回を1週間の期限つきで求めています。その注意喚起は、同集団が被害者やその家族への脅迫的な連絡やスワッティングを行い、存在しない恥ずかしい写真や動画を持っていると偽って恐喝することがある、としたものでした。ShinyHunters はこれらを否定し、犯罪者の緩やかな連合体「The Com」との関係も否定しています。

裏付けの状況は限定的です。最初に報じた 404 Media は約5,000件の FBI 職員データのサンプルを受け取り、一部の電話番号が同姓同名の人物や米司法省関係者のものと一致することを確認したと報じました。他方、BleepingComputer はゼロデイの存在・横展開・盗まれた量のいずれも独自には確認できていないとしています。Oracle と AWS は報道機関の問い合わせに回答していません。本記録の作成者も2026年9月23日に FBI・FBIjobs.gov・Oracle の各サイトへアクセスを試みましたが、いずれも 403 で取得できませんでした。本記録は、攻撃者の主張と、確認された事実を区別して整理します。

【続報・2026年10月6日】FBI が初めて原因を述べ、委託先を解任しました。サイバー部門次長 Brett Leatherman の説明は次のとおりです（原文英語）—— 「現在までの調査で、本件は第三者組織が管理する基盤のセキュリティ上の失敗の結果として起きたと判断している。当該基盤を守るために明示的に発行されたセキュリティパッチを、委託先が適用しなかった後のことである」、「したがって FBI は当該委託先を解任し、さらなるリスクの低減と職員の保護のために必要なあらゆる措置を取った」。

FBI は第三者組織の名も、解任した委託先の名も明らかにしていません。ロイターは、第三者組織が Oracle PeopleSoft、解任された委託先が Accenture だと報じました。Accenture はロイターに「FBI の任務を支えてきたことを誇りに思い、今後も支え続ける」と述べています（原文英語）。

この説明が意味するのは、入口が「未知のゼロデイ」ではなかったということです。 Mandiant は、ShinyHunters が CVE-2026-35273（2026年6月10日にパッチ公開）を塞ぐはずの WAF の規則を、リクエストパスの P を %50 に置き換えて/%50SEMHUB/ と要求することで迂回していたと評価しています。FBI の「明示的に発行されたパッチを委託先が適用しなかった」という説明は、これと整合します（本記録の読み）。本記録が9月27日の時点で「入口の候補は未知のゼロデイからパッチを当てず WAF で塞いだサーバへ動いた」と書いた見方が、当事者の言葉で裏づけられた形です。

ただし終わっていない論点が2つ残っています。 1つは攻撃者が主張する「第2の未知のゼロデイ」で、CVE の採番も CISA の KEV への収載も無く、Oracle は依然として何も述べていません。 IDC の Philip Harris は「すべての報道が、ゼロデイの主張は攻撃者からのみ出ており、独立したフォレンジックの確認でも Oracle からの確認でもないと明記している。その区別が重要だ」と述べています（原文英語）。もう1つはOracle の沈黙そのもので、PeopleSoft の利用組織は「当初の指針のままで足りるのか」を判断できないままです。

これに対し、侵入の経路・データ量・到達したシステム・動機のいずれも攻撃者の主張です。FBI は侵害の有無を認めておらず、Oracle も AWS も回答していません。本記録の作成者が2026年9月23日および9月27日に FBI・FBIjobs.gov・Oracle の各サイトへアクセスを試みたところ、いずれも HTTP 403 で取得できませんでした。

9月23日の声明で1つだけ増えたのは、入口の候補に「第三者事業者」が入ったことです。本記録の評価として、これは細部ではありません。侵害されたのが FBI 自身の環境なのか、採用ポータルを支える委託先なのかで、事案の性格（自組織の運用の問題か、委託先管理の問題か）も、他組織が学ぶべき教訓も変わります。FBI 自身が5日たってもそれを確定できていないという事実のほうが、攻撃者の主張する容量よりも実務的な情報です。

本記録の評価として、この段階の事案で最も危ういのは、攻撃者の主張をそのまま「事実」として社内へ伝えてしまうことです。2〜3テラバイト、ほぼ全ての捜査官、CJIS への到達——いずれも刺激的ですが、現時点で裏づけがあるのは「サンプルの一部の電話番号が実在の人物と一致した」ことまでです。逆に、裏づけが無いことは「起きていない」ことも意味しません。本記録は、確認された事実・攻撃者の主張・本記録の評価を分けて書きます。

狙われたのは採用系システムだった——「重要度が低い」と分類されがちな場所に最も機微な情報が集まる原因・手口出典 [1] [3] [4]

攻撃者の主張によれば、入口は求人サイトの Oracle PeopleSoft サーバでした。PeopleSoft は人事・採用の分野で、応募者の個人情報を保管するために広く使われています。そこから FBI が管理する AWS GovCloud 環境へ横展開し、職員と応募者のデータへ到達したとしています。

本記録の評価として、ここには一般化できる論点があります。採用系システムは、社内の重要度評価で低く置かれがちです。基幹業務でも、顧客データでもなく、外部（応募者）に向けて公開する必要があるためです。しかし実際にそこへ集まるのは、氏名・住所・電話番号・職歴・家族構成・場合によっては健康情報や身元調査の結果といった、組織が保持する中でも最も機微な種類の個人情報です。

さらに、採用系は「外部に公開されていること」が要件です。応募者が誰でも到達できなければ機能しないため、境界の内側に隠すという防御が使えません。本件で攻撃者が主張する構図——公開系の入口から、認証情報や信頼関係を介して内部のデータ基盤へ——は、採用系に限らず、「公開が要件である系」と「機微なデータを持つ系」が地続きになっている場所で繰り返し起きる形です。

要求が金銭ではない——「評判の訂正」を求める恐喝という前例評価・解釈出典 [1] [2] [4]

ShinyHunters はリークサイトの声明で、攻撃は2026年5月15日の FBI の注意喚起への報復であり「これは金銭目的ではない」と述べました。要求は身代金ではなく、注意喚起の訂正または撤回です。期限は1週間としています。

FBI の注意喚起は、同集団が被害者やその家族への脅迫的な連絡やスワッティングを行い、存在しない恥ずかしい写真や動画を持っていると偽って恐喝することがある、としたものでした。ShinyHunters はこれらを否定し、犯罪者の緩やかな連合体「The Com」との関係も否定しています。The Register には「私はこれらの主張と戦うために最善を尽くしてきた。これがそのための最良の方法だ」（原文英語）と述べています。

本記録の評価として、この形は恐喝の目的が「支払い」から「評判の管理」へ広がりうることを示す前例です。恐喝集団にとって、被害者が支払うかどうかは「この集団は本当に危険か」「約束を守るか」という評判に左右されます。当局の注意喚起がその評判を損なうなら、攻撃者にとっては収益基盤への攻撃に見える——という理屈です。

専門家の見方は分かれています。CyberScoop に対し、Halcyon のランサムウェア研究部門の幹部（FBI サイバー部門の元幹部）は「ランサムウェア集団が成功しているのは、おおむね企業のように動いているからだ。他の犯罪集団や法執行機関を、とくに公に辱める形で狙うのは規律の欠如を示しており、歴史的にはテイクダウンや乗っ取り、離反につながってきた」（原文英語）と述べています。一方 Flashpoint の分析者は「この攻撃は、信頼できる脅威としての評判を高めるという点で ShinyHunters に利益がある」（原文英語）としています。本記録はどちらかを採らず、両論を記録します。

主張されたゼロデイは確認されていない——だが「確認されていない」で止めると備えられない未確定事項出典 [1] [4] [6] [7]

攻撃者は「我々が悪用した Oracle の製品は PeopleSoft だ。昨日もう1つ見つけて、すぐに FBI に対して使った」（原文英語）と述べ、さらに同じ脆弱性を企業や Fortune 500 に対しても使っていると主張しています。証拠を消して脆弱性を特定されにくくしたとも述べています。

裏づけはありません。BleepingComputer はゼロデイの存在も横展開も盗まれた量も独自には検証していないと明記し、Oracle と Mandiant へ問い合わせています。The Register も Oracle と AWS から回答を得ていません。本記録の作成者が2026年9月23日に Oracle のセキュリティアラートのページへアクセスを試みたところ 403 で取得できず、CISA の KEV にもPeopleSoft の該当の収載は見当たりませんでした。

本記録の評価として、実務上の構えは次の形になります。「実在が確認されるまで何もしない」でも「主張を事実として扱う」でもなく、いま確認できる作業を先に済ませておく。 具体的には、PeopleSoft を含む人事・採用系の資産の所在とインターネットへの露出状況、それらが持つ他系統への認証情報（クラウド基盤への権限を含む）、Web アクセスログの保全期間の3つを、いま棚卸しすることです。これらはゼロデイが実在してもしなくても価値がある作業で、実在が確認されてから始めると、その時点では数日を要します。

攻撃者自身が「WAF での迂回を使った」と認めた——入口の候補は未知のゼロデイから「パッチを当てず WAF で塞いだサーバ」へ動いた原因・手口出典 [10] [11]

2026年9月26日、Mandiant と Google Threat Intelligence Group が、同じ ShinyHunters（UNC6240）による Oracle PeopleSoft の既知の脆弱性 CVE-2026-35273 の大規模悪用の再開を公表しました（INC-2026-0225）。手口は単純です。脆弱なエンドポイント /PSEMHUB/ を WAF の文字列一致で塞いでいた組織に対し、P を URL エンコードした %50 に置き換えて/%50SEMHUB/ として要求する——WAF はデコード前の文字列で照合するため一致せず、アプリケーションサーバ側はデコードして脆弱なエンドポイントへ振り分けます。

同日、攻撃者は BleepingComputer に対し、この WAF 迂回を FBI Jobs に対して使ったことを認めました。 同時に「同じ PSEMHUB コンポーネントの新たな未知の脆弱性」も悪用したという主張は取り下げていません。

本記録の作成者が2026年9月27日に Mandiant の報告本文を確認したところ、FBI も米連邦政府機関も被害者として挙げられておらず、扱われている脆弱性は CVE-2026-35273 のみでした（業種として「政府」が挙がっていますが、個別の組織名はありません）。Oracle のアラートと fbijobs.gov は依然として 403 で取得できません。

本記録の評価として、読み方は2段になります。

  1. 当初の「未知のゼロデイで破られた」という像は、攻撃者の申告の範囲でさえ揺らいだ。 攻撃者自身の説明に従うなら、入口の少なくとも一部は6月10日にパッチが出ている既知の脆弱性であり、破られた条件はパッチを当てずに WAF のルールで代替していたことです。
  2. それでも「未知の脆弱性」の主張は消えていない。 否定もされていません。一方を確定として扱うことはできません。

実務上の含意は、ゼロデイの真偽より手前にあります。WAF のルールは、パッチの代替にならない。とくに「特定のパスを文字列で遮断する」形の緩和策は、エンコード・大文字小文字・正規化のずれで容易に迂回されます。緩和策として入れる場合は、①適用範囲を台帳に記録し、②パッチ適用の期限を同時に決め、③迂回の変種（パーセントエンコード・混在大文字）も検知条件に含める——この3点を最初から組にしておく必要があります。本件は、その組が無いまま「塞いだつもり」になっていた組織がどうなるかを示す例として読めます。

盗まれたとされる情報の性質が、通常の個人情報流出と異なる被害規模・影響範囲出典 [3] [4] [5]

攻撃者が 404 Media に述べたところでは、データには捜査官の氏名・自宅住所・電話番号・配偶者に関する情報が含まれます。改ざんされたサイトの文言には、職員と応募者の機微な個人情報と健康関連情報が含まれるとする記述がありました。攻撃者は、過去の BreachForums の捜査に関わった特別捜査官とされる人物や、FBI 長官に関するとされる記録を報道機関に示しています（報道機関はいずれも真正性を確認しておらず、内容も公開していません）。

TechCrunch はこの点を「盗まれたデータは、ハッカーや外国のスパイが捜査官やその家族を強要・恐喝して外国政府への協力を迫る、重大な防諜上の脅威になりうる」（原文英語）と評しています。

本記録の評価として、ここには一般の組織にも通じる論点があります。流出の重大性は、件数ではなく「その情報が誰を何に晒すか」で決まります。職員の自宅住所と家族構成は、件数としては小さくても、本人の物理的な安全に直結します。自社の従業員データについて、「漏れたときに人が危険に晒される項目」（自宅住所・家族・健康・身元調査の結果など）がどこに、どの範囲で保管されているかを把握している組織は多くありません。件数ベースの影響度評価では、この種のリスクは軽く見積もられます。

本記録の評価として、ここには日本の組織にも移せる論点があります。人事データの「所属」欄は、それ自体が機微な情報になりうるということです。氏名と自宅住所が出ることの重さは想像しやすいのに対し、「どの部署にいるか」は事務的な属性として扱われがちです。しかし本件では、所属を見れば、その人が何を担当しているかが分かってしまう。研究開発・M&A・法務・輸出管理・内部監査のように、担当していること自体を知られたくない職務を持つ組織では、人事システム・採用システム・連絡網に置く部署名の粒度を見直す理由になります。

拘束は報じられたが、当局の言葉は「捜査中」の水準にとどまっている刑事対応出典 [17] [18] [19]

  • 確認できること——FBI は公式に「ShinyHunters が関与したとされる今回のサイバー事案を引き続き積極的に捜査しており、すでに連携して複数の対象者を逮捕している」（原文英語）と述べました。これはFBI 自身の言葉です。

Leatherman 次長は、同集団について「昨年以降、140を超える組織を侵害し、少なくとも7,000万ドルの恐喝金を得た」と述べ、他の構成員に対して「逮捕には、誰が話す気になるかを変える働きがある。押収された基盤には、誰が残っているかを我々に見せる働きがある。この世界に長くいるほど、我々はあなたについて多くを知る」（原文英語）と呼びかけました。

本記録の評価として、この呼びかけの形そのものが読み取りに値します。捜査機関が公の場で「自首せよ」と語るのは、次の摘発の材料が人の供述に寄っていることを示します。協力者を1人得るたびに、集団の内部の見通しが開ける——その構図は、技術的な封じ込めとは別の時間軸で進みます（本記録の読み）。

ここが本事案の実務上の核心です。 CVE-2026-35273 のパッチは 2026年6月10日に出ていました。3か月半のあいだ、当該基盤ではパッチの代わりに WAF の規則が置かれていた。そして規則はたった1文字——P を %50 に——で素通りされました。

「緩和策で当面しのぐ」という判断は、どの組織でも日常的に行われています。変更の窓が取れない、業務影響の確認が終わっていない、ベンダーの互換性確認を待っている——理由はいくらでもあります。本件が示したのは、その判断に期限と検証が付いていなかったときに何が起きるかです。

  • 緩和策は「期限つきの暫定」として登録されていたか。 3か月半は暫定の期間としては長い。
  • 緩和策が実際に効くことを検証したか。文字列一致の WAF 規則は、エンコードの変形で抜けることが知られている手法である。入れたあとに変形した要求で試す工程があれば、6月の時点で分かったはずである（本記録の評価）。
  • 誰が期限を管理していたか。 FBI の説明では、基盤を管理していたのは第三者組織で、パッチを当てなかったのは委託先である。資産の所有者・運用者・パッチの実施者が分かれている構成では、「誰が期限を見るか」が決まっていないと落ちる（本記録の評価）。

FBI の対応は「委託先の解任」でした。ただし解任は再発防止策ではありません（本記録の評価）。同じ構成——パッチの代わりに WAF、実施者は委託先、期限の管理者は不明——が他の基盤に残っているかどうかは、何も公表されていません。FBI は委託先の名も第三者組織の名も明らかにしていません。

それでも終わっていない論点が2つある——「第2のゼロデイ」と Oracle の沈黙未確定事項

1つめは、攻撃者が主張する「第2の未知のゼロデイ」です。攻撃者は「CVE-2026-35273 とは別の、文書化されていないPeopleSoft の認証前の遠隔コード実行のゼロデイも使った」という主張を取り下げていません。IDC の Philip Harris はこう述べています（原文英語）—— 「CVE は採番されておらず、CISA の KEV カタログにも載っておらず、Oracle はコメントしていない。これを扱うすべての報道が、ゼロデイの主張は攻撃者からのみ出ており、独立したフォレンジックの確認でも Oracle からの確認でもないと明記している。その区別が重要だ。」

そのうえで Harris は、仮に実在した場合の意味をこう述べています—— 「本物だと仮定すれば、PeopleSoft には CVE-2026-35273 と同じ時期に2つめの critical な未修正の認証前 RCE があるということになる。単発のバグではなく、critical な露出が繰り返される型だ」、「攻撃者自身が『他の名前を出していない Fortune 500 の標的に対してすでに使っている』と主張していることを踏まえれば、すべての PeopleSoft 顧客が、ベンダーの指針が無いまま、修正できず開示もされていない欠陥に現在さらされているということになる。WAF 迂回の話よりも意味のある形で悪い状況だ—— Oracle が認めていないものを認めるのを待つあいだ、試せる緩和策が存在しないのだから」。

本記録はこれを「実在する」とも「実在しない」とも書きません。 実在が確認されていないこと自体が、この続報の時点の事実です（本記録の判断）。

2つめは Oracle の沈黙です。 CSO Online は、FBI も Oracle も PeopleSoft の関与について公式には何も述べていないと書いています。Acceligence の Jeff Valdes は、Oracle の沈黙は正当化できないとして「顧客は当然ベンダーからのより多くの連絡を求めている。Oracle の当初の指針で足りるのか、追加の緩和策を実施すべきか、Oracle 自身のサポート組織で見えているものがリスクの見方を変えるのか、露出を著しく増やす構成や設計上の選択があるのか、を理解したいのだ。それらは運用上のセキュリティの問いであり、帰属・逮捕・捜査手法その他 FBI の捜査を妨げうる事柄に触れずとも答えられる」と述べています（原文英語）。

PeopleSoft を使っている組織がいま打てる手は、報道が伝える助言の範囲にとどまります。 Dickson Research の Frank Dickson が挙げたのは次の4つです（原文英語）——

  1. Oracle のパッチを当てる。
  2. 使っていなければ Environment Management Hub を無効化または削除する（「Environment Management Hub と Integration Broker を公開インターネットから外す。通常の利用者セッションは壊れない」）。
  3. ログから PSEMHUB のパスを探すとき、literal な文字列ではなくエンコードされた変種を探す。
  4. web シェルが見つかったら、そのサーバは侵害されたものとして扱い、それが読めた可能性のある認証情報をすべて差し替える。

4番目が実務上もっとも重いところです（本記録の評価）。「web シェルが見つかった」は「1台を直す」話ではなく、そのサーバから到達できた認証情報すべての差し替えという話になります。差し替える対象の一覧を平時に持っていない組織では、この判断が止まります。

    取るべき行動 識別子の無い主張に対しては「露出の確認・ログの保全期間の確認・ 当該製品の権限の確認」の3点だけを実施する定型手順を作る。 修正が出た時点で通常の手順へ合流させる。
  • 改ざんの検知と、停止時の案内をあらかじめ用意する
    本件では公開ページが改ざんされ、その画面が報道機関へ配られた。 その後サイトは「メンテナンス中」の表示で停止している。 改ざんの検知が遅れるほど、攻撃者の主張を載せた画面が外に晒される時間が伸びる。
    取るべき行動 公開ページの内容の定期比較による改ざん検知を置き、 検知時の停止判断と、停止中に表示する案内文（事実に反しない表現）を 平時に用意しておく。採用系では応募者向けの代替連絡手段も決めておく。

自組織に当てはまるか

該当する項目があれば、この事案と同じ構図が自組織でも成立しうることを意味します。
観点自社に当てはまるか該当する場合に何が起きうるか
システム構成□ Oracle PeopleSoft を含む人事・採用系のシステムを、インターネットから到達できる位置で運用している攻撃者は同じ脆弱性を他の組織や Fortune 500 に対しても使っていると主張している。 実在は確認されていないが、露出の把握は主張の真偽にかかわらず必要な作業である。
認証・認可□ 公開系のシステムが、社内のデータ基盤やクラウド環境への認証情報・信頼関係を持っている主張されている経路は「公開系 → 管理下のクラウド環境」である。 公開系が持つ権限の広さが、そのまま横展開できる範囲になる。
データの保持□ 従業員・応募者の自宅住所・家族・健康・身元調査の結果を保持しており、その所在を一覧にできない本件で問題になっているのは件数ではなく中身である。 所在が分からなければ、漏えい時に誰がどの危険に晒されるかを判断できない。
運用・監視□ 公開系システムのログを機器の外へ転送しておらず、保全期間が短い攻撃者は痕跡を消したと明言している。機器上のログだけでは、 侵害の有無を後から判断できない。
体制・契約□ 恐喝を受けた場合の判断基準が「金銭を払うかどうか」しか用意されていない本件の要求は注意喚起の訂正・撤回である。金銭以外の要求が来たときに 誰が判断するかが決まっていないと、期限のある交渉に対応できない。
体制・契約□ 脅威情報の社内共有で、攻撃者の主張と確認された事実を区別する様式が無い本件は主張が先行し、裏づけが限定的な段階で大きく報じられた。 区別せずに共有すると、根拠の弱い情報にもとづいて意思決定が行われる。
