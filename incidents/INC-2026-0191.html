INC-2026-0191Next.js の next/og に重大なRCE

Next.js の OGP 画像生成機能 next/og（Node.js 版 ImageResponse）に、リモートコード実行に至りうる重大な脆弱性 CVE-2026-94545 が見つかり、2026年9月22日に 16.3.6 が緊急公開された——原因は Vercel 製の下請けライブラリ Satori が SVG 出力時に値を正しくエスケープしていなかったことで、攻撃者が制御できる値（リクエスト URL から読んだ文字列など）を画像に載せているアプリが対象になる。Next.js 側は CVSS 4.0 で 9.5（Critical）、Satori 側は同じ CVE に 5.3（Moderate）を付けている。Satori は next パッケージに同梱されており依存関係の一覧に現れないため、ロックファイルや npm audit からは見えない

脆弱性初報のみ有名事象として記録（日本と直接の関係は薄い）設計・実装上の不備
初報: 2026年9月22日 最終更新: 2026年9月23日

Vercel は 2026年9月22日、Next.js の脆弱性 CVE-2026-94545（GHSA-vcvr-r3jv-pc5j）を公表し、定例外（out-of-band）の修正版 16.3.6 を公開しました。同社の評価は CVSS 4.0 で 9.5（Critical） です。

影響を受けるのは next/og の ImageResponse を Node.js ランタイムで動かしている場合です。Node.js ランタイムは Next.js の既定であり、ImageResponse は OGP 画像（SNS で共有されたときに出るプレビュー画像）を動的に作るための機能です。Vercel のアドバイザリは、対象を「画像生成の際に、攻撃者が制御できる値をSVG のコンテンツ・属性・スタイルに渡しているアプリケーション」（原文英語）と書いています。

欠陥そのものは Next.js ではなく、Next.js が内部で使う Vercel 製ライブラリ Satori にあります。Satori は画像のレイアウトをいったん SVG へ変換する部品で、同日公開された Satori のアドバイザリ（GHSA-wx4j-mvgx-mqwp）は「Satori は生成する SVG 出力に含める前に、特定の値を適切にエスケープしていない。これにより細工された値が SVG のマークアップとして解釈されうる」（原文英語）と説明しています。Next.js では、そこから「他の上流依存の脆弱性」を経てリモートコード実行に至りうるとされていますが、その依存ライブラリの名前は公表されていません。

同じ CVE に対する評点は 2つに割れています。Next.js 側は 9.5（Critical）、Satori 側は 5.3（Moderate） で、Satori のアドバイザリは「影響は SVG 出力がどう使われるかに依存する」と但し書きを付けています。同じ欠陥でも、部品として見るか、製品として見るかで深刻度が変わるという形です。

本記録が注目するのは、この脆弱性が利用者側の道具からは見えにくいという点です。Satori は next パッケージに同梱されており、依存関係として宣言されていません（本記録の作成者が2026年9月23日に npm レジストリで next@16.3.5 の dependencies を確認したところ、satori は含まれていませんでした）。そのためロックファイルにも現れず、The Hacker News は9月23日時点で npm audit が影響版 16.3.5 を警告しなかったと報じています。本記録の作成者が同日に確認した範囲でも、CVE レコード（cveawg.mitre.org）は未公開で、GitHub Advisory Database（グローバル）にも GHSA-vcvr-r3jv-pc5j は収載されていませんでした。影響版 16.2.0 が npm に出たのは2026年3月18日で、修正までの窓は 188日あります。

攻撃の経過

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

公開されている OGP 画像生成のエンドポイントへ、攻撃者が細工した文字列を含むリクエストを送る。 アプリがその値を next/og の ImageResponse（Node.js ランタイム）へ渡すと、 Satori がエスケープせずに SVG へ書き出し、細工された値が SVG マークアップとして解釈される。 Vercel は、そこから「他の上流依存の脆弱性」を経てリモートコード実行に至りうるとしているが、 その依存の名称と具体的な連鎖は公表されていない。実際の悪用は確認されていない。

  1. 1. 初期侵入確認済[1]
    攻撃者が、OGP 画像を生成するルート（ルートハンドラや opengraph-image）へ、 細工した文字列を含むリクエストを送る。認証は不要で、当該エンドポイントは通常公開されている。
    根拠: Next.js アドバイザリ GHSA-vcvr-r3jv-pc5j の影響条件の記述
  2. 2. 実行確認済[3] [5]
    Satori が値を適切にエスケープしないまま SVG 出力へ含めるため、 細工された値が SVG のマークアップとして解釈される（Satori アドバイザリの記述）。
    根拠: Satori アドバイザリ GHSA-wx4j-mvgx-mqwp
  3. 3. 影響（暗号化・破壊・改ざん）unconfirmed[1] [2] [5]
    Next.js の説明では、注入された値が「他の上流依存の脆弱性」に届き、 リモートコード実行につながりうるとされる。依存の名称と連鎖の詳細は公表されていない。
    根拠: Next.js アドバイザリおよび公式ブログ（依存の名称は非公表）

壊れていたのは OGP 画像を作る経路——リクエスト由来の文字列が SVG のマークアップとして解釈された概観出典 [1] [2]

Vercel が2026年9月22日に公開したアドバイザリ（GHSA-vcvr-r3jv-pc5j）の要点は次のとおりである。

  • 対象パッケージは npm の next、影響範囲は 16.2.0 以上 16.3.6 未満、修正版は 16.3.6
  • 深刻度は Critical、CVSS 4.0 で 9.5（CVSS:4.0/AV:N/AC:L/AT:P/PR:N/UI:N/VC:H/VI:H/VA:H/SC:H/SI:H/SA:H）
  • 影響するのは Node.js 版の ImageResponse 実装（next/og） で、Edge 版の実装は影響を受けない
  • 対象となるのは「画像生成の際に、攻撃者が制御できる値を SVG のコンテンツ・属性・スタイルに渡しているアプリケーション」（原文英語）
  • 発見者は RaghavMaheshwari124 と rafabd1

公式ブログ「Next.js Security Update for a Critical Upstream Issue」（同日・Josh Story／Karim Rahal／Sebastian Silbermann）は、修正版として 16.3.6（Active LTS） と15.5.26（Maintenance LTS） を挙げ、「15.5.26 は関連するハードニングを含むが、Next.js 15.x はリモートコード実行の問題の影響を受けない」（原文英語）と明記している。

ImageResponse は、SNS で共有されたときに表示されるプレビュー画像（OGP 画像）などをサーバ側で動的に生成する機能である。記事タイトルや商品名をリクエストごとに画像へ焼き込む用途で使われ、その文字列がリクエストの URL から来ている作りは珍しくない。Next.js は既定で Node.js ランタイムを使うため、明示的に Edge を選んでいない限り影響側に入る。

欠陥は Next.js ではなく同梱ライブラリ Satori の SVG 出力にあり、同じ CVE に 9.5 と 5.3 の2つの評点が付いた原因・手口出典 [1] [2] [3]

Next.js は ImageResponse の中で、画像のレイアウトをいったん SVG に変換するためにVercel 製のライブラリ Satori を使っている。同日公開された Satori のアドバイザリ（GHSA-wx4j-mvgx-mqwp）の記述は次のとおりである（原文英語・訳は本記録）。

Satori は、生成する SVG 出力に含める前に特定の値を適切にエスケープしていない。これにより、細工された値が SVG のマークアップとして解釈されうる。影響は、その SVG 出力がどのように使われるかに依存する。

  • 影響範囲は 0.0.27 以上 0.33.5 未満、修正版は 0.33.5
  • 深刻度は Moderate、CVSS 4.0 で 5.3（CVSS:4.0/AV:N/AC:L/AT:P/PR:N/UI:P/VC:N/VI:N/VA:N/SC:H/SI:N/SA:N）

Next.js 側の記述は、ここから一段進む。「特定の条件下で、Satori が生成する SVG 出力における不適切なエスケープが、他の上流依存の脆弱性に起因してリモートコード実行につながりうる。修正はそれらの依存を更新するものである」（原文英語）。「他の上流依存」が何であるかは、アドバイザリにもブログにも書かれていない。

結果として、同じ CVE-2026-94545 に 9.5（Critical・Next.js）と 5.3（Moderate・Satori）という2つの評点が並んでいる。部品単体では「SVG が壊れる」だけだが、Next.js という製品の中ではその SVG が別の部品へ渡り、コード実行にまで届く、という違いである。

対処は 16.3.6 への更新——直ちに上げられないなら攻撃者制御値を SVG へ渡さない対策・注意喚起出典 [1] [2] [4] [5]

Vercel が示した対処は次のとおりである。

  • npm install next@16.3.6（16.3 系）。16.2 系に修正版は出ていないため、16.2 系のアプリも 16.3.6 へ移る必要がある（本記録の作成者が9月23日にnpm レジストリで確認した時点でも 16.2 系の修正版は無い）
  • npm install next@15.5.26（15.5 系・ハードニングのみ。15.x は RCE の影響を受けない）
  • 直ちに更新できない場合の回避策は、「Node.js 版 ImageResponse の実装で、攻撃者が制御できる値を SVG のコンテンツ・属性・スタイルに渡さないこと」（原文英語）

自分のアプリが該当するかは、next/og から ImageResponse を import している箇所（ルートハンドラや opengraph-image ファイル）を探すのが起点になる。

ホスティング事業者側の案内もある。Netlify は2026年9月22日付の告知で、影響を受けるのは「ImageResponse を使い、かつ信頼できない入力（テキストやリクエスト由来の画像）を含める場合のみ」と整理したうえで、次を案内した。

  • next を 15.5.26 以上または 16.3.6 以上へ更新して再デプロイする
  • 更新前の応急措置として、入力を XML エスケープするか画像から取り除く
  • 公開プレビューやブランチデプロイを手動で削除する（古い版が残り続けるため）
  • 自社の構成では「クラッシュする機能が他のリクエストに影響しない」が、悪用によるコスト増加の可能性は残る

最後の点は見落としやすい。更新したのは本番だけで、プレビュー環境に古い版が残るという状態は、ブランチごとにデプロイが残る運用では普通に起きる。

同梱された部品は依存関係の一覧に出ない——ロックファイルと npm audit では今回の影響を判定できなかった評価・解釈出典 [1] [4] [6]

ここからは本記録の作成者の評価である。

本件で実務上いちばん効くのは、「使っている部品なのに、自分の依存関係として見えない」という点である。

  • 本記録の作成者が2026年9月23日に npm レジストリで next@16.3.5 の dependencies を確認したところ、宣言されているのは postcss・@next/env・styled-jsx・@swc/helpers・caniuse-lite・baseline-browser-mapping の6つで、satori は含まれていない。Satori は next パッケージに同梱（バンドル）されている
  • したがって package-lock.json にも現れない。「Satori を使っているか」をロックファイルで調べても答えは出ない
  • The Hacker News は9月23日時点で npm audit が影響版である 16.3.5 を警告しなかったと報じている。本記録の作成者が同日に確認した範囲でも、GitHub Advisory Database（グローバル）にGHSA-vcvr-r3jv-pc5j は収載されておらず（github.com/advisories/... は HTTP 404）、CVE レコード（cveawg.mitre.org の API）も未公開（HTTP 404）だった。リポジトリ上のアドバイザリページは参照できるので、「公開されている」と「道具が読める」は別である

つまり本件では、ソフトウェア構成管理（SCA）の自動判定に頼っていると、当日は何も鳴らない。判定の材料は「next のバージョンそのもの」と「自分のコードが next/og に何を渡しているか」の2つしかない。

一般化すると、フレームワークが内部に抱え込んだ部品の脆弱性は、SBOM に載らないことがある。同梱・ベンダリング・コード取り込みのいずれでも同じことが起きる。SBOM を作っているから大丈夫、という前提は本件では成立しない。

OGP 画像は「利用者入力がサーバ側のレンダラに直接入る」数少ない経路である（本記録の評価）評価・解釈出典 [1] [3] [5]

本記録の作成者の評価を続ける。

Web アプリで利用者入力を扱う経路は普通、データベース・テンプレート・API を通る。一方 ImageResponse は、リクエストの文字列をそのままサーバ側の描画エンジンに渡す経路である。描画エンジンは HTML ではなく SVG を組み立て、そこからさらに画像ライブラリへ渡る。入力の検証が薄くなりやすい場所で、しかも「画像を作るだけ」という見た目から、攻撃面として意識されにくい。

今回はエスケープ漏れで SVG マークアップが注入され、そこから先（名前が公表されていない上流依存）でコード実行にまで届いた。SVG は画像であると同時にマークアップであるという性質が、そのまま注入の受け皿になっている。

実務としては次の3つを分けて考えたい。

  1. 何を画像に載せるか——リクエスト由来の値を載せているなら、それは利用者入力である
  2. どこでエスケープするか——ライブラリ任せにせず、渡す前に許可する文字を絞る（Netlify が示した応急措置も「入力の XML エスケープ」である）
  3. 誰が呼べるか——OGP 画像の生成エンドポイントは公開され、しかもクローラや SNS から高頻度で叩かれる。認証で守れない代わりに、入力の長さ・文字種・レート制限を設計に入れておく

上流依存の名称・悪用の有無・自社ホスティングでの保護はいずれも公表されていない未確定事項出典 [1] [2] [6] [7]

2026年9月23日時点で、次の点は公表されていない。

  • リモートコード実行に至る「他の上流依存の脆弱性」の名称と識別子
  • 実際の悪用の有無と実証コードの公開状況（KEV カタログ 2026.09.22 版にも未収載）
  • Vercel でホスティングしているアプリが保護されるか（2026年8月の2件では「保護済み・更新不要」と説明していた、と報道は対比している）
  • 攻撃者制御値をどの要素・属性に置いたときに成立するかの正確な範囲
  • 16.2 系に修正版が出るか
  • 影響を受けるアプリケーションの数・割合

事案の詳細

cves
id: CVE-2026-94545　cvss: 9.5　概要: Next.js の next/og（Node.js 版 ImageResponse）で、Satori が生成する SVG 出力の 不適切なエスケープにより、攻撃者が制御する値が SVG マークアップとして解釈される。 他の上流依存の脆弱性と組み合わさることでリモートコード実行に至りうる。 Next.js のアドバイザリは Critical（CVSS 4.0 で 9.5）、 上流の Satori のアドバイザリは同じ CVE を Moderate（CVSS 4.0 で 5.3）と評価している。 2026年9月23日時点で CVE レコード（cveawg.mitre.org）は未公開。　exploited: いいえ
affected_versionsNext.js 16.2.0 以上 16.3.6 未満（Node.js ランタイムの next/og ImageResponse を使い、 攻撃者制御値を SVG へ渡している場合）。修正版は 16.3.6。 Next.js 15.x はリモートコード実行の影響を受けないが、15.5.26 に関連するハードニングが入った。 Edge 版 ImageResponse は影響を受けない。16.2 系に対する修正版は公開されていない。 上流の Satori は 0.0.27 以上 0.33.5 未満が影響し、修正版は 0.33.5。
exploitation_status実際の悪用は確認されていない。Vercel は悪用に言及しておらず、The Hacker News は 2026年9月23日時点で攻撃の公開報告も公開された実証コードも無いとしている。 本記録の作成者が同日に取得した CISA の KEV カタログ（2026.09.22 版・1,721件）にも CVE-2026-94545 は収載されていない。 なお Vercel は、修正前に当該ルートが悪用されたかどうかを利用者が確認する方法を示していない。
緩和策
item: Next.js を 16.3.6（または 15.5.26）へ更新し、再デプロイする　副作用: マイナー更新とはいえ本番の再デプロイが要る。16.2 系を使っている場合は 16.3 系への移行になり、挙動差の確認が必要になる。 プレビュー環境やブランチデプロイは自動では更新されない
item: 更新できないあいだは、攻撃者が制御できる値を SVG のコンテンツ・属性・スタイルへ渡さない　副作用: 記事タイトルや商品名を画像に焼き込む機能が使えなくなるか、固定文言に置き換わる。 「どの値が攻撃者制御か」の判定を開発者が手作業で行う必要がある
item: 入力を XML エスケープしてから画像生成へ渡す（Netlify が示した応急措置）　副作用: エスケープの漏れが残る可能性があり、根本修正にはならない。 表示上の文字化け（実体参照がそのまま出る等）が起きうる
item: 公開プレビュー・ブランチデプロイを削除する　副作用: レビュー中のプレビュー URL が失われ、開発フローが一時的に止まる

波及の構造

事案の構造を図にしたものです。数値は公表値に基づきます。
OGP 画像生成のリクエストから、Satori の SVG 出力を経てリモートコード実行に至りうる経路
layer 0 は攻撃者と公開されている画像生成エンドポイント。layer 1 は Next.js の next/og（Node.js 版 ImageResponse）と、同梱されている Satori。layer 2 は エスケープされずに出力された SVG と、その先にある名称非公表の上流依存、そして到達しうる コード実行。右側は修正（16.3.6／Satori 0.33.5）と、依存関係の一覧に現れないことを示す。 上流依存の具体名は公表されていないため、その先の連鎖は破線的な扱いにとどめている。

対応の評価

評価材料がない判断は「評価材料なし」としています。結果論で断じないための区分です。
対応の巧拙を評価できる材料が公表資料から得られていません。
CISO・経営層への示唆
  • 「SBOM と SCA があるから把握できている」という前提を、同梱部品で点検する
    Satori は next パッケージに同梱されており依存関係に現れない。 本件当日は npm audit も警告せず、GitHub Advisory Database にも未収載だった。 自動判定の網に掛からない脆弱性が現実に存在する
    取るべき行動 自社の SCA が「同梱・ベンダリングされた部品」を検出できるかを、実物の パッケージ（next など）で試験する。検出できないなら、フレームワーク本体の バージョン監視を別立てで持つ
  • 脆弱性情報の入手経路を、配布元のアドバイザリまで遡って確保する
    本件はベンダーのリポジトリ上のアドバイザリと公式ブログが一次情報で、 CVE レコードも共通データベースも当日は追いついていなかった。 CVE 番号を起点にした運用だけでは当日動けない
    取るべき行動 主要フレームワーク（Next.js・WordPress・Spring など）の公式ブログ／ リポジトリのアドバイザリを購読対象に入れ、CVE 採番を待たずに判断できる導線を用意する
  • 「影響するか」の判定を、バージョンだけでなく自社コードの使い方で行う体制にする
    本件の成立条件は「Node.js 版 ImageResponse」かつ「攻撃者制御値を SVG へ渡している」で、 バージョンが該当しても影響しないアプリがある。逆に、条件の確認は 開発者にしかできない（アドバイザリの例示も限定的である）
    取るべき行動 脆弱性対応の手順に「該当コードの有無を開発チームが確認する」工程を明示し、 判定の期限（例: 受領から1営業日）と記録の残し方を決めておく
  • 本番以外の環境（プレビュー・ブランチデプロイ）を更新対象の外に置かない
    Netlify は公開プレビューとブランチデプロイの手動削除を推奨している。 自動デプロイの運用では古い版が公開されたまま残りやすい
    取るべき行動 公開されている非本番環境の一覧を作り、脆弱性対応のチェックリストに 「プレビュー・ステージング・ブランチデプロイの更新／削除」を入れる
セキュリティ技術者への示唆
  • next/og の ImageResponse に渡している値を棚卸しし、リクエスト由来かどうかで分類する
    影響の有無は「攻撃者が制御できる値を SVG のコンテンツ・属性・スタイルに渡しているか」で決まる。 アドバイザリは title 要素の例しか示しておらず、他の要素での成否は書かれていない
    取るべき行動 `next/og` から `ImageResponse` を import している箇所（ルートハンドラ・ opengraph-image ファイル）を grep で洗い出し、渡している変数の出所を1つずつ確認する。 判断が付かない箇所は「該当する」として扱う
  • バージョンの確認は、ロックファイルではなく実際に入っているパッケージで行う
    Satori は next に同梱されておりロックファイルに現れない。 「Satori を使っているか」を依存関係から判定しようとすると答えが出ない
    取るべき行動 `npm ls next` で実際の版を確認する。16.2.0〜16.3.5 なら影響版である。 Satori を直接使っているコードがあれば 0.33.5 へ上げる
  • SVG を組み立てる処理では、ライブラリのエスケープに全面依存しない
    本件はライブラリ側のエスケープ漏れであり、呼び出し側が正しく使っていても成立した。 SVG は画像であると同時にマークアップであり、注入の受け皿になる
    取るべき行動 画像生成へ渡す前に、入力の文字種と長さを許可リストで絞る。 更新前の暫定措置としては XML エスケープを挟む（Netlify の案内と同じ考え方）
  • 公開エンドポイントである画像生成ルートに、レート制限と入力長の上限を入れる
    OGP 画像の生成ルートは認証で守れず、SNS のクローラから高頻度で叩かれるため、 攻撃リクエストがログ上で目立たない。Netlify は悪用によるコスト増加にも触れている
    取るべき行動 画像生成ルートに入力長の上限とレート制限を設定し、 生成時間・エラー率の監視を入れて異常値を拾えるようにする
  • 修正が「上流依存の更新」である場合、自分のロックファイルの更新だけで終わらせない
    Vercel の修正は上流依存の更新であり、next のバージョンを上げることでしか入らない。 キャッシュされた古い成果物やビルド済みイメージが残ると、更新が反映されない
    取るべき行動 更新後にビルドキャッシュを破棄して再デプロイし、稼働中の版が 16.3.6 以上であることを 実行環境側で確認する（プレビュー環境も同様に確認する）
