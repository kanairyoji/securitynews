INC-2026-0255NeedyMantis で長期の足がかり維持

Microsoft が2026年9月28日、**侵入後に長期間の足がかりを維持するためのモジュール型マルウェア「NeedyMantis」**の解析を公表した——**2026年5月に発覚した DAEMON Tools の供給網汚染の痕跡をたどる過程で見つかった**もので、活動は**少なくとも2025年10月**にさかのぼる。**初期侵入には使われない**。攻撃者がすでに環境内に入ったあとで、**Poedit・curl・Vim・TightVNC といった正規ソフトウェアに悪性 DLL と独自形式の暗号化書庫を同梱し、DLL サイドロードで起動**する。C2 は **HTTPS で始まり WebSocket に切り替わり**、モジュールを随時読み込み・切り離しできる。ある事案では、**すでに侵入していた攻撃者が Impacket でネットワーク共有から一式をコピーして実行**していた。Microsoft は使用者として **Storm-3069**（DAEMON Tools 汚染の実行主体）を挙げ、**活動は中国由来と評価するが、中国の国家主体には帰属させていない**。**複数の主体が使っている可能性があり、すべてが同一主体によるものかは判断していない**。被害は**通信事業者・大学・国際機関・医療系の非営利団体・政府請負業者**で、**組織名・国・件数はいずれも公表されていない**

攻撃の経過

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

**侵入後の段階で投入されるマルウェアである。** 攻撃者がすでに環境内へのアクセスを得たあとで、 **正規ソフトウェア＋悪性 DLL＋独自形式の暗号化書庫の3点一組**を配置し、 **DLL サイドロード**で第1段を起動する。 第1段は書庫から第2段（拡張子は PowerShell だが中身は x64 の機械語）を取り出し、 第2段が**独自の実行ファイル形式に整形された主要部品**を復号する。 主要部品は **HTTPS で C2 に接触してから WebSocket に切り替え**、 **モジュールを随時読み込み・切り離しできる。** **モジュールの機能は公表されていない。**

3点一組を正規ソフトに同梱して読み込ませる——署名の検証では通り抜ける原因・手口出典 [1] [2] [3]

NeedyMantis の投入は、3つのファイルを一組にして置くことで成立する。

  1. 正規のソフトウェア本体（そのまま。改変されていない）
  2. 悪性 DLL——そのソフトが読み込む DLL の名前を持つ
  3. 暗号化書庫——DLL と同じ名前から拡張子を落としたもの（WinSparkle.dll なら WinSparkle）

正規のソフトを起動すると、Windows は同じ場所にある DLL を先に探して読み込む。これは仕様どおりの挙動であり、脆弱性ではない（本記録の明示）。土台に使われたことが公開されているのはPoedit（翻訳）・curl（データ転送）・Vim（テキストエディタ）・TightVNC（遠隔操作）で、Microsoft は「悪用された open-source ソフトウェアの一部」と書いている。これとは別に、Microsoft Office・Broadcom・Intel・NVIDIA の DLL 部品を装う例も観測されている。

公開された配置先は9件で、次のような形をとる。

%ProgramFiles%\Poedit\WinSparkle.dll
%ProgramData%\USOShared\libcurl.dll
%ProgramData%\VIM\vim64.dll
%ProgramData%\TightVNC\VIM\vim64.dll
%ProgramData%\office\dbghelp.dll
%ProgramData%\broadcom\dbghelp.dll
%ProgramData%\Intel\jli.dll
%ProgramFiles%\modifiable\nvml.dll
%ProgramData%\ics\nvml.dll

ここで注意が要る。 The Hacker News は「Poedit の経路に一致しただけでは感染の証明にならない。WinSparkle.dll は Poedit の正規の構成部品でもあるため、公開されたハッシュと突き合わせること」と注記している。経路の一致は手がかりであって結論ではない。

投入の実例として、Microsoft は次の1件を挙げている—— すでに環境内へのアクセスを得ていた攻撃者が、手動の操作のなかでImpacket を使い、ネットワーク共有から正規ソフト・悪性 DLL・書庫を標的端末へコピーして実行した。 初期侵入はこれより前に完了しており、その手口は説明されていない。

書庫と実行ファイル形式が独自で、鍵と配置はサンプルごとに変わる原因・手口出典 [1] [2] [3]

解析を難しくしている中心は、独自形式の多重化である。

暗号化書庫。 外側を XOR で復号し、Windows の展開機能で伸長すると、個々のファイルの項目が現れる。各項目ではファイル名を XOR で復号し、中身をさらに伸長する。そして、この形式の位置・XOR の鍵・値はサンプルごとに変わると Microsoft は明記している。

新しい版の書庫（11ファイル）の中身は、次のように正規と悪性が混ぜられている。

分類 内容
正規の部品 7-Zip の4ファイル、Sysinternals の2ファイル、正規の kernel32.dll

第1段ローダの耐解析。 重要な文字列の大半をスタック上で1つずつ組み立てて数式で復号する形に隠し、定数値も隠している。復号した文字列はWindows の機能名で、実行時に動的に解決される。さらに2種類のデバッガ検出（ProcessDebugFlags と ThreadHideFromDebugger）を持つ。

第2段以降。 第2段ローダは埋め込まれたデータを復号・伸長し、出てくるのは独自形式に整形された DLLである（通常の実行ファイル形式を削ぎ落としたもの）。主要部品は「利用者名とプロセス名」を組み合わせた名前で多重起動を防ぎ、第1段と同じ文字列の隠し方を使う。

C2。 まず HTTPS の要求を出し、応答のヘッダに入った符号化・圧縮された JSONとして端末名・利用者名・プロセス一覧などを送る。そのあとWebSocket に切り替える。通信部品には利用者エージェント文字列が固定で埋め込まれている（firefox/21.0）。主要部品が受け取れる命令はモジュールの読み込み・切り離し・データの受け渡し・動作中の印の解除である。

そして、そのモジュールが何をするのかは公表されていない。 Microsoft の言葉では「それらのモジュールの機能は未確認のままである」。枠組みは解析されたが、目的は分かっていない——これが本件の最大の空白である。

本記録はハッシュとホスト名の全文を転記していない。照合先のテレメトリを持たないまま並べても検知には使えず、誤った安心の材料になるためである（本記録の判断）。代わりに残したのは、配置先の形・プロセスの挙動・通信の切り替わり方——自組織の EDR で今日試せる形の情報である。原典（Microsoft の公表）に完全な一覧がある。

Kaspersky の解析によれば——

  • 2026年4月8日から、公式サイトで配布される DAEMON Tools のインストーラに悪性コードが含まれていた（対象は 12.5.0.2421〜12.5.0.2434）
  • 改変されたのは3つの実行ファイルで、いずれも開発元の有効な署名が付いたままだった
  • 起動されるとバックドアが動き、同名に似せた外部のホストへ要求を出して、受け取った命令で追加の実行体を取得する
  • 感染の試行は100か国以上で数千件に及んだが、第2段の常駐型バックドアまで入ったのは約12台にとどまる
  • その約12台はロシア・ベラルーシ・タイの政府・学術・製造・小売の組織だった
  • 2026年5月上旬、Kaspersky が公表し、開発元が修正版（12.6.0.2445）を公開した
  • Kaspersky はコードに中国語の文字列があったとしつつ、特定の主体への帰属は行っていない

配布期間は約27日間（本記録の算出）。

この「数千件の感染に対して踏み込んだのは約12台」という比は、本件の性格を説明している（本記録の評価）。供給網で広く撒き、そのうえで選んだ相手にだけ次の段を入れる。 NeedyMantis の被害区分（通信事業者・大学・国際機関・医療系の非営利団体・政府請負業者）と「限られた数の標的型オペレーション」という表現も、同じ選び方を示している。

ただし、混同してはならない点がある。 Microsoft は「NeedyMantis そのものが供給網汚染によって配られたことは観測していない」と明記している。供給網の活動は「NeedyMantis を展開するのに必要なアクセスを得る手段としてありうる」1つにすぎない。
