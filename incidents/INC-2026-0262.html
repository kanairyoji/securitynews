INC-2026-0262富士フイルムBI・シャープ複合機に情報窃取の脆弱性

富士フイルムビジネスイノベーション製の複合機・プリンター28系列とシャープ製の北米向けデジタル複合機2機種に、同一のパストラバーサルの脆弱性 CVE-2026-78249（CWE-22）があり、ウェブ管理インターフェースにログインできる攻撃者が細工したリクエストを送ると、機器内部の重要な情報を窃取できる。JPCERT/CC は2026年9月30日に JVNVU#90160989 として公表し「影響を受ける機器は、広範囲に及びます」と注記した。成立の前提は管理者権限であり、両社の回避策はいずれも「機械管理者パスワードを初期値から変更する」に集約されている。発見は Tier Zero Security の Jim Rush、報告経路は富士フイルムビジネスイノベーション → JPCERT/CC → シャープである

脆弱性初報のみ日本の組織が当事者設計・実装上の不備
初報: 2026年9月30日 最終更新: 2026年9月30日

2026年9月30日、JPCERT/CC は JVNVU#90160989 として、富士フイルムビジネスイノベーション製およびシャープ製の複合機（MFP）にパストラバーサルの脆弱性CVE-2026-78249（CWE-22）があることを公表しました。JVN は「本脆弱性の影響を受ける機器は、広範囲に及びます」と注記しています。

JVN の記述では、「当該製品のWeb管理インターフェースにログイン可能な攻撃者により細工されたリクエストを処理した場合、機器内部の重要な情報が窃取される可能性があります」。富士フイルムビジネスイノベーション側の説明はより実装に近く、「ウェブ管理インターフェースにおいて、外部から与えられるパラメータを処理する実装に不具合があり、不正に改ざんされた特定のリクエストを受信した場合、意図しない処理が実行されるおそれがあります」となっています。

影響範囲は非対称です。富士フイルムビジネスイノベーションは28系列（Apeos／ApeosPrint／ApeosPro／Revoria Press）を対象製品として列挙し、系列ごとに該当バージョンと対策済バージョンを示しました。一方シャープは「北米向け」の2機種（BP-1360M／BP-1250M）のみです。JVN は「この脆弱性情報は、製品利用者への周知を目的に、富士フイルムビジネスイノベーション株式会社がJPCERT/CC に報告し、JPCERT/CC が富士フイルムビジネスイノベーション株式会社およびシャープ株式会社との調整を行いました」と記しており、報告は富士フイルムビジネスイノベーションから、シャープは調整の対象として加わった形です。シャープは自社の CVSS 値を「富士フイルムビジネスイノベーション株式会社の評価を基に記載しています」と注記しています。

CVSS の値が JVN と両ベンダーで食い違っています。 JVN はAV:N（ネットワーク）で 6.9、両ベンダーは AV:A（隣接ネットワーク）で 6.8 です。CVSS v3.1 は双方 4.9 で一致しています。この差は「複合機の管理画面がインターネットから到達しうるか」の見立ての違いであり、読み替えの向きが重要です（後述）。

攻撃の前提は PR:H、すなわち管理者としてログインできることです。シャープは成立条件を3つ挙げ、「攻撃者が、複合機が接続されているコーポレートネットワークへのアクセスが可能」「管理者権限を保持している」「通常の操作では知り得ない情報を持っている」としています。両社の回避策はいずれも機械管理者パスワードを初期値から変更し、共有範囲を絞ることに集約されています。複合機の管理者パスワードが出荷時のままか、誰でも知っている状態かが、そのまま被害の分かれ目になります（本記録の評価）。

富士フイルムビジネスイノベーションは「本お知らせの掲載時点において、本脆弱性を悪用した攻撃は確認しておりません」としています。発見と報告は Tier Zero Security の Jim Rush によるもので、シャープには情報セキュリティ早期警戒パートナーシップにもとづきJPCERT/CC から報告されました。

本記録は JVN・富士フイルムビジネスイノベーション・シャープの3つの一次資料を取得し、対象製品リストを表から直接読み取って整理します。

JVNVU#90160989 の記述は次のとおりである。

当該製品のWeb管理インターフェースにログイン可能な攻撃者により細工されたリクエストを処理した場合、機器内部の重要な情報が窃取される可能性があります。

富士フイルムビジネスイノベーションの説明は実装に近い。

対象商品が提供するウェブ管理インターフェースにおいて、外部から与えられるパラメータを処理する実装に不具合があり、不正に改ざんされた特定のリクエストを受信した場合、意図しない処理が実行されるおそれがあります。

整理すると次のようになる。

  • CVE は CVE-2026-78249、分類は CWE-22（パストラバーサル）
  • 影響は情報の窃取のみ。CVSS のベクタも VC:H/VI:N/VA:N（機密性のみ高、完全性・可用性への影響なし）で、改ざんや停止は想定されていない
  • 成立の前提は PR:H（高い権限）——ウェブ管理インターフェースへのログインが要る
  • 利用者の操作は不要（UI:N）、攻撃の複雑さは低い（AC:L）
  • 対象は富士フイルムビジネスイノベーションの28系列とシャープの北米向け2機種（BP-1360M／BP-1250M）
  • JVN は「本脆弱性の影響を受ける機器は、広範囲に及びます」と注記している

シャープは成立条件を3つに分けて明示した。

  1. 攻撃者が、複合機が接続されているコーポレートネットワークへのアクセスが可能
  2. 攻撃者が、管理者権限を保持している
  3. 攻撃者が、通常の操作では知り得ない情報を持っている

3番目の条件は、パストラバーサルで狙うパスやファイル名を知っている必要がある、という意味と読める（本記録の推定）。ただし製品が共通であれば、その「知り得ない情報」は1台で分かれば全台に使える。前提の強さとしては、1番目と2番目のほうが実質的である。

CVSS が JVN 6.9（AV:N）とベンダー 6.8（AV:A）で食い違う——複合機の管理画面が外から見えるかの見立ての差評価・解釈出典 [1] [2] [3]

同じ CVE に対し、CVSS 4.0 の値が2通り公表されている。

シャープ 6.8（富士フイルムBI の評価を基に記載） AV:A 4.9（AV:N）

差は 0.1 点だが、意味の差は大きい。AV:A は「攻撃者が同一の論理ネットワーク上にいる必要がある」という見立てであり、シャープが条件の1番目に「コーポレートネットワークへのアクセスが可能」を挙げたのと整合する。一方 AV:N は「ネットワーク越しに到達できる」という見立てである。なお CVSS 3.1 では JVN もシャープも AV:N を採っており、食い違っているのは 4.0 の評価だけである。

実務上は次のように読み替えるべきである（本記録の評価）。複合機のウェブ管理インターフェースがインターネットから到達できる状態なら AV:N で読む。社内ネットワークに閉じているなら AV:A で読む。 どちらであるかは製品ではなく設置環境で決まる。両ベンダーが回避策の第一項として「ファイアウォール等の保護されたネットワークの中で機器をご利用ください」「複合機をインターネットに直接接続せず、ファイアウォールやルーターなどのネットワーク機器を介して接続する」を挙げているのは、まさにこの前提を守らせるためである。

そして AV:A であっても安心材料にはならない。すでに社内に足場を得た攻撃者にとって、複合機は横展開の途中で必ず通る資産である。 管理者パスワードが初期値のままの複合機は、スキャン連携先の共有フォルダやディレクトリサービスの認証情報を抱えている可能性がある。

複合機は「資産台帳の外にある認証情報の貯蔵庫」——更新経路とパスワード棚卸しの両方が要る（本記録の評価）評価・解釈出典 [1] [2] [3]

ここからは本記録の作成者の評価である。

第一に、複合機は情報資産としての扱いが弱い。 サーバや PC は資産台帳に載り、脆弱性管理の対象になり、EDR が入る。複合機は台数が多く、部署ごとに置かれ、リース契約で入ってくるため、情報システム部門の管理対象から外れやすい。しかし実態は、スキャン to フォルダの SMB／FTP 認証情報、アドレス帳、LDAP のバインド情報、メールサーバの資格情報を抱えた小さなサーバである。今回の脆弱性が「機密性のみ高」であることは、被害が軽いことを意味しない。複合機から抜けるのは、次の侵入に使える認証情報である。

第二に、PR:H を「だから低リスク」と読んではいけない。両社の回避策が管理者パスワードに集中しているのは、現場では PR:H が満たされてしまうという前提が共有されているからである。複合機の管理者パスワードは、設置業者が設定したまま、あるいは全台共通、あるいは出荷時の値のままという運用が珍しくない。CVSS の PR:H は「管理者パスワードが適切に管理されている」という仮定に立った減点であり、その仮定が崩れている組織では実効的に PR:N に近い。自社の評価では、まず「複合機の管理者パスワードの状態」を確認してから深刻度を判断すべきである。

第三に、更新の経路が製品群で分かれている点が運用の落とし穴になる。富士フイルムビジネスイノベーションは、オフィス向けはカストマーコンタクトセンター、「1」の7系列（プロダクションプリンター・広幅複合機）は担当営業、シャープは担当のサービスへ、という案内である。EP-BB 自動更新を有効にしている機器は自動で直るが、有効にしていない機器は誰かが動かないと永久に直らない。* 台帳に「自動更新の有効・無効」の列がない組織では、どの機器が放置されるかを事前に知ることができない。

第四に、2社にまたがる CVE は自社の製品名だけでは追えない。「富士フイルムの複合機は入れていない」と判断した組織が、実は同じ実装を含む別ベンダーの機器を使っている——という形が、本件の構図である（両社の技術的な関係は公表されていないが、同一 CVE と同一の CVSS 評価という事実は残る）。JVN のベンダー一覧を、自社の製品名ではなく CVE 単位で確認する習慣が要る。

第五に、シャープの告知が「北米向け」に限られていることを「国内は対象外」と読み替えるのは早い。 告知は国内向け機種について何も述べていない。対象外であることの確認が必要な組織は、ベンダーに直接問い合わせるほかない。「書かれていない」は「該当しない」ではない。

CISO・経営層への示唆
  • 複合機・プリンターを情報資産の台帳に載せ、脆弱性管理の対象に含める
    複合機はスキャン連携先の SMB／FTP 認証情報、アドレス帳、LDAP のバインド情報、 メールサーバの資格情報を保持しうる。本脆弱性の影響は「機密性のみ」だが、 抜けるのは次の侵入に使える認証情報である
    取るべき行動 リース契約で導入した複合機を含め、機種名・ファームウェア版数・設置場所・ 管理者パスワードの最終変更日・自動更新の有効無効を列に持つ台帳を作る。 脆弱性情報の受領先（ベンダー・JVN）を台帳に紐づけ、担当者を決める
  • 「管理者権限が必要」という前提を、自社の実態で検算する
    CVSS の PR:H は管理者パスワードが適切に管理されているという仮定に立った減点である。 両社の回避策は4項目中3項目が管理者パスワードの管理に集中しており、 現場で前提が崩れやすいことを示している
    取るべき行動 複合機の機械管理者パスワードについて、出荷時の値のままの台数・全台共通になっている台数・ 保守ベンダーと共有している台数を実地で数える。数え終わるまで、 本件の深刻度を「管理者権限が必要だから低い」と評価しない

セキュリティ技術者への示唆
  • 複合機のウェブ管理インターフェースがインターネットから到達できないかを実測する
    JVN は CVSS 4.0 を AV:N（ネットワーク）で評価し 6.9 としたが、 両ベンダーは AV:A（隣接ネットワーク）で 6.8 としている。 どちらで読むべきかは製品ではなく設置環境で決まる
    取るべき行動 自社の公開 IP レンジと、拠点のインターネット回線からの到達性を実測して、 複合機の管理ポート（HTTP／HTTPS）が外部に出ていないかを確認する。 ポートフォワードやUPnPで意図せず公開されている機器を探す
  • 複合機が保持している認証情報を洗い出し、権限を最小化する
    本脆弱性で窃取されるのは「機器内部の重要な情報」であり、 具体的な範囲は公表されていない。範囲が不明なら、 機器に預けている認証情報の側を弱めるしかない
    取るべき行動 スキャン to フォルダ・スキャン to メール・LDAP 連携に使っている アカウントを棚卸しし、書き込み専用・特定フォルダのみ・ ディレクトリ検索のみといった最小権限の専用アカウントへ置き換える。 汎用の管理者アカウントを複合機に登録しない
  • 機械管理者パスワードを台単位で変更し、変更日を記録する
    両社の回避策は、初期値からの変更・十分な長さ・共有範囲の最小化・ 広く共有されている場合の速やかな変更の4点を挙げている。 いずれも実施したかどうかを後から確認できる形で記録しないと管理できない
    取るべき行動 機器ごとに異なるパスワードを設定し、パスワード管理の仕組み（保管庫）に登録する。 全台共通の値を使っている場合は、保守ベンダーとの作業手順を先に調整してから変更する。 変更日を台帳に記録し、未変更の台数を残件として追跡する
  • 複合機のログを収集対象に入れ、管理者ログインを可視化する
    本脆弱性は管理者としてログインできることが前提である。 管理者ログインが記録も転送もされていなければ、 悪用された場合に気づく手がかりが残らない
    取るべき行動 機器が Syslog 転送に対応しているかを機種ごとに確認し、 対応する機器はログ収集基盤へ送る。 保守時間帯・保守元 IP から外れる管理者ログインをアラートにする。 非対応の機器は、その事実を台帳に残してネットワーク側の記録で代替する
  • ファームウェア更新の完了を台数ベースで追跡し、自動更新の有効無効を把握する
    富士フイルムビジネスイノベーションは EP-BB 自動更新を設定している顧客には 自動で更新されるとしている。設定していない機器は誰かが動かなければ更新されない
    取るべき行動 台帳に「自動更新の有効無効」と「現在のファームウェア版数」の列を持ち、 告知の対策済バージョン（1.50.6／1.0.4／1.2.0／1.20.10／1.22.12／1.3.0／1.23.7 等）と 突き合わせて残存台数を数える。完了報告は「手配済み」ではなく「版数が上がった台数」で行う
