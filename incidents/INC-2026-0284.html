INC-2026-0284TA419 が AI政策専門家を標的に

Proofpoint が2026年10月1日、中国系の脅威アクター **TA419** が**米国の著名な経済学者・AI政策当局者を装い、シンクタンク・大学・法律事務所の AI 政策専門家へ認証情報フィッシングを行っていた**と公表した——2026年7月8日以降、**元ホワイトハウス科学技術政策局（OSTP）の筆頭次席長官**や著名な経済学者の名を騙り、「AI 政策助言委員会への参加」「上院外交委員会の AI 輸出管理報告書への寄稿」といった**無害な会話の糸口**から入って返信を引き出し、短縮URL→複数段リダイレクト→**偽の OneDrive を被せた中間者（AitM）フィッシング**へ誘導した。基盤は公開ツール **Frameless BitB**（Browser-in-the-Browser）に **Evilginx の Microsoft 365 用 phishlet** を組み合わせたもので、**Microsoft の正規サインイン応答をリアルタイムで中継しながら2本のスクリプトを注入**し、**「サインインの状態を維持する」の自動承諾とワンタイムコードの自動投入**まで行う。**2026年2月には AI 企業 Anthropic の上級従業員を装い**、件名「Request for Feedback on Military Integration of Claude」でシンクタンクの AI 政策アナリストを狙っていた。**同グループは2025年4月以降、米国および日本のシンクタンク・防衛産業・大学・法律事務所を標的にしており**、なりすまし用ドメインには**日台交流協会・The Heritage Foundation・小泉進次郎氏の公式サイト**を装ったものが含まれる

脅威・攻撃キャンペーン初報のみ日本に波及した海外事案認証情報の悪用（使い回し・推測可能・窃取）設計・実装上の不備
初報: 2026年10月1日 09:00 UTC（Proofpoint の公表） 最終更新: 2026年10月1日

Proofpoint は2026年10月1日、同社が TA419 として追跡する中国系（China-aligned）でスパイ目的の脅威アクターが、米国の AI 政策専門家を狙った認証情報フィッシングを行っていたと公表しました。同グループの活動は、これまで公に報告されたことがないとされます。

公表（Proofpoint のブログ）から確認できた内容は次のとおりです。

標的と騙りの相手

  • 標的は米国のシンクタンク・大学・法律部門で働く AI 政策の専門家
  • 2026年7月8日以降、Lynne Edwards Parker（元ホワイトハウス科学技術政策局＝OSTP の筆頭次席長官）を装い、続いてHeidi Crebo-Rediker（著名な経済学者・外交政策専門家）を装った

手口

  • まず無害な「会話の糸口」メールを送る。「AI 政策助言委員会（AI Policy Advisory Committee）への参加」や「上院外交委員会の AI 輸出管理・供給網に関する報告書への寄稿」といったAI 政策を題材にした誘いで、信頼関係を作り返信を引き出す
  • 返信があると、短縮URLを送る。1段目のアクター管理ドメインが濾過器として働き、偽の OneDrive 読み込み画面の背後で Cloudflare Turnstile の検査を行い、2段目のドメインにある AitM（中間者）認証情報フィッシングページへ送る
  • 2026年7月の両キャンペーンは、1段目に driftshare[.]co、2段目に globalfileshareplatform[.]com を使った

技術の中身

  • 狙いは Microsoft 365 / Entra ID で、第一者アプリ OfficeHome（client_id=4765445b-32c6-49b0-83e6-1d93765276ca）を経路に使う
  • 基盤は公開ツール Frameless BitB（Browser-in-the-Browser）に、Microsoft 365 用の Evilginx phishlet とサーバ側の置換規則を組み合わせたもの。TA419 はこれに独自のテレメトリ・自動化モジュールを足している
  • 利用者が着地するのはMicrosoft 本物の/common/oauth2/v2.0/authorize の応答で、それをリアルタイムに中継しながら、プロキシが /secondary/script.js と /secondary/observe.js を注入する
  • BitB の偽ブラウザ枠の背後で本物の Microsoft 基盤へ中継されるため、パスワード・多要素認証コード・条件付きアクセスの検査はすべて成功し、攻撃者はその結果のセッションクッキーを奪う
  • observe.js は被害者がサインインのどの段階にいるかを攻撃者へ報告し、「サインインの状態を維持する（Keep me signed in）」を自動で承諾してセッションを延命し、ワンタイムコードが検証されると自動で投入する

基盤

  • Cloudflare の CDN で背後のホスティング IP を隠し、ドメインはNameSilo で登録する。ドメイン名はファイル共有・クラウドサービス風のものが多い

  • フィッシングメールの1ホップ目の Received ヘッダから、アクター管理と見られる VPS が露出したことが複数回ある。観測された全サーバが高位の一時ポートに同一の自己署名 TLS 証明書を持ち、主体名・発行者名はいずれもC=US, ST=Kansas, L=Millsstad, O=Castro Inc, CN=CI だった。これは匿名化のための隠れたネットワークと関係するとみられる。住宅用プロキシ経由の送信も観測されている

多要素認証を突破したのではなく、本物の画面ごと中継した原因・手口出典 [1]

技術の中核は AitM（Adversary-in-the-Middle。中間者）です。多要素認証を破ったわけではありません—— 本物の Microsoft のサインイン画面を、そのまま中継したのです。

プロキシが本物の応答を中継しながら、2本のスクリプトを注入します。

  • /secondary/script.js: Frameless BitB の駆動部（公開ソースの改変版）。Shadow DOM を container 要素に付け、囮文書を並べた OneDrive のフォルダ一覧を描く。実際の文書は攻撃者管理の OneDrive アカウントに置かれ、1drv.ms の共有リンクを同一オリジンの埋め込みページに変えるプロキシ経路で読み込まれる。さらに /primary/script.js を同じ Shadow DOM に読み込む
  • /primary/script.js: 同じく Frameless BitB の改変版だが、本体が置き換えられている。標的の操作を横取りし、クリック・タッチの処理を登録し、OneDrive 自身の「権限がありません」バナーを監視する。つまり文書をクリックしても、Microsoft が認証を求めても、どちらでも偽の Chrome 枠（BitB）が立つ
  • /secondary/observe.js: TA419 独自のテレメトリ・自動化スクリプト。被害者がサインインのどの段階にいるかを攻撃者へ報告し、セッションをライブで見られるようにする。さらに「サインインの状態を維持する」を自動で承諾してセッションを延命し、ワンタイムコードが検証された瞬間に自動投入する

3つめ。セッションクッキーを前提にした検知を置く必要があります。攻撃者が得るのはパスワードではなくセッションです。サインインの成否を見ていても何も起きません——成功しているのです。見るべきは、同一セッションの発信元が変わること、見慣れない地域・ASN からのトークン利用、サインイン直後のメール転送規則の追加やアプリ同意です。

4つめ。「実在の専門家を騙る」ことへの備えは、組織の側からも打てます。 Proofpoint は「実在の専門家の身元を騙る手口も続くだろう」と見込んでいます。自組織の研究者・役員が騙られる側になる前提で、公式の連絡経路を公開しておくこと（「当方からの照会は必ずこのドメインから送ります」）は、受け手の検証を容易にします。

CISO・経営層への示唆
  • 「MFA 導入済み」を対策済みと数えるのをやめ、要素の種類で棚卸しする
    本件ではパスワード・多要素認証コード・条件付きアクセスの検査が **すべて本物の Microsoft に対して成功している。** **攻撃者が得るのはその成功の対価であるセッションクッキー**である。 Proofpoint の推奨が「MFA を入れよ」ではなく **「パスキーのような、フィッシング耐性があり発信元に束縛された認証」**で あることがこれを示している。
    取るべき行動 **自組織の多要素認証を「発信元に束縛されるもの（パスキー・FIDO2）」と 「コードを入力するもの（SMS・認証アプリのコード・メール）」に 分けて数え直す。** 後者しか無い部門・システムを一覧にし、 **外部との専門的やり取りが多い部門から順に前者へ移す。**
  • 外部からの専門的な照会が業務の中核である部門を、特別な防御対象として扱う
    本件の標的は**シンクタンク・大学・法律事務所の AI 政策専門家**で、 **外部の見知らぬ専門家からの照会に応えることが仕事**である。 1通目は無害で、**返信した人にだけ2通目が来る**。 組織の最後の一線が個人の判断になる。
    取るべき行動 **「外部からの初回接触に応答することが業務に含まれる職種」を 人事データから特定し、その集団に対してのみ強い措置を適用する** （パスキー必須・管理対象端末からのみ到達可・永続セッション禁止）。 **全社一律では費用も摩擦も大きすぎるため、集団を絞る。**
  • 自組織の人間が「騙られる側」になる前提で、公式連絡経路を外部に示す
    本件は**実在の専門家・実在の組織**を騙っている （元 OSTP 幹部、著名な経済学者、Anthropic の上級従業員、 The Heritage Foundation、日台交流協会、小泉進次郎氏の公式サイト）。 Proofpoint は**この手口が続く可能性が高い**と見ている。
    取るべき行動 **自組織からの外部照会に使うドメインと差出人を公開ページに明示し、 「当方からの依頼はこの経路のみ」と書く。** 役員・研究者の氏名を使った照会が届いた場合の確認窓口 （電話番号・フォーム）を同じページに置く。
  • 公表されている脅威だけで防御を設計すると、観測と公表の時差の分だけ無防備になる
    Proofpoint は**2025年4月以降**この活動を観測していたが、 **公表は2026年10月1日**で、 **それまで公に報告されたことがない**と明記している。 **約18か月、標的になりうる側には情報が届いていなかった** （本記録の算出）。
    取るべき行動 **防御の設計を「既知の指標の遮断」から 「手口に依存しない構造」へ寄せる。** 具体的には、発信元に束縛された認証、管理対象端末の要求、 永続セッションの禁止、利用者同意の禁止—— **どのアクターが来ても同じように効く措置**を優先順位の上に置く。
  • 日本の組織が標的に含まれることを、公表元の記述として記録しておく
    Proofpoint は**「2025年4月以降、米国および日本を拠点とする シンクタンク・防衛産業・大学・法律事務所」**を標的と明記し、 結論部でも**関心が主として米国と日本に繋がる**としている。 なりすまし用ドメイン3組織のうち2つが日本関係である。
    取るべき行動 **自組織が「シンクタンク・大学・法律事務所・防衛産業」に 該当するか、またはそれらと共同研究・顧問契約を持つかを確認する。** 該当する場合、**AI 政策・輸出管理・安全保障に関わる担当者を 優先対象として上記の措置を適用する。**
セキュリティ技術者への示唆
  • サインインの「失敗」ではなく「成功後の挙動」で検知を組む
    本件では**標的の画面で何も失敗しない。** パスワードも MFA も条件付きアクセスも通る。 **失敗率・ロックアウトを見る検知は何も捕まえない**（本記録の評価）。
    取るべき行動 **Entra ID のサインインログで、同一セッション／同一利用者の 発信元 IP・ASN・地域の急な変化を検知する。** 併せて**サインイン直後のメール転送規則の追加、 アプリ同意の付与、OneDrive/SharePoint の一括ダウンロードと 外部共有リンクの一括作成**をアラートにする。
  • 永続セッションを禁止し、トークンを端末に束縛する
    攻撃者の自動化スクリプトは **「サインインの状態を維持する」を自動で承諾してセッションを延命**し、 **ワンタイムコードが検証された瞬間に自動投入**する。 **狙いはセッションそのもの**である。
    取るべき行動 **条件付きアクセスで永続セッション（サインインの状態を維持する）を 禁止し、サインイン頻度を明示的に設定する。** **トークンを発行元端末に束縛する機能を有効にし、 持ち出されたクッキーが別端末で使えない状態にする。**
  • 短縮URLと新規登録ドメインを、展開してから評価する経路に乗せる
    2通目に送られるのは**短縮URL**で、 1段目のドメインは**登録から日が浅く、 Cloudflare Turnstile の検査で自動解析を弾く。** **機械的な評価では2段目まで到達できない**（本記録の評価）。
    取るべき行動 **短縮URLを展開して最終到達先を記録し、 登録から日が浅いドメインへの到達を既定で隔離する。** **自動解析が結論を出せなかったURL（人間の操作を要求するもの）を 「安全」ではなく「未評価」として扱い、利用者に警告する。**
  • 指標ではなく「命名の癖」と「証明書の特徴」で探す
    インフラは**月単位で入れ替わっている** （2026年2月〜7月で1段目7件・2段目6件）。 一方で癖は安定している—— **ドメイン名はファイル共有・同期・クラウド系の語の組み合わせ**、 **全 VPS が高位の一時ポートに同一の自己署名 TLS 証明書 （O=Castro Inc, CN=CI）を持つ。**
    取るべき行動 **公表された13件のドメインとメールアドレス3件を遮断・検索に投入した上で、 命名の癖に基づく新規ドメインの監視と、 自己署名証明書の主体名による探索を継続的な調査項目にする。** **指標の遮断だけで終わらせない。**
  • BitB（偽ブラウザ枠）を前提に、利用者への指導を書き換える
    **「URL を確認しましょう」という指導は、BitB に対して効かない** （本記録の評価）。 Frameless BitB は Shadow DOM 上に偽の Chrome 枠を描き、 **クリックでも Microsoft 自身の権限バナーでも 同じ偽枠が立つ**ように改変されている。
    取るべき行動 **指導の文面を「URL を見る」から 「サインイン画面は自分でブックマークから開き直す」へ変える。** 併せて、**パスキーを使っていれば偽のページでは そもそも認証が完了しない**ことを、利用者が納得できる形で説明する。

自組織に当てはまるか

観点自社に当てはまるか該当する場合に何が起きうるか
認証・認可□ クラウドアカウントの多要素認証が、コードを入力する形式（SMS・認証アプリのコード・メール）に依存している本件はコードを自動投入して中継する。 **発信元に束縛されない要素は原理的に耐えない。** パスキーが入っていない部門は、この攻撃に対して未対策である。

体制・契約□ 自組織の役員・研究者が外部に照会を出す際の正規ドメイン・差出人を公開していない本件は実在の専門家を騙る。 受け手が「本物の経路」を確認できなければ、検証の手段が無い。
運用・監視□ 防御の設計が、公表済みの指標（ドメイン・IP・ハッシュ）の遮断を中心に組まれている本件は**約18か月間、公に報告されていなかった**。 インフラも月単位で入れ替わる。指標中心の設計には時差の穴がある。
