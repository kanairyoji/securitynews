INC-2026-0286MikroTik RouterOS に認証前RCE

米 CISA が2026年9月29日、MikroTik RouterOS の web 管理サービスに認証前で到達できる整数アンダーフロー（CVE-2026-84411）があるとして ICS 勧告 ICSA-26-272-06 を公表した。細工した1回の要求だけで root 権限での任意コード実行またはサービス不能に至る。CVSS v3.1 は 9.8、v4.0 は 9.3、分類は CWE-191。影響は 7.24 より前の全バージョンで、CISA は 7.24 以降への更新を求めている。CISA は悪用の報告を受けていないとしており、本記録の作成時点で MikroTik 自身のセキュリティ勧告は公表されていない

脆弱性初報のみ有名事象として記録（日本と直接の関係は薄い）設計・実装上の不備
初報: 2026年9月29日 最終更新: 2026年9月30日

米 CISA（サイバーセキュリティ・インフラセキュリティ庁）は2026年9月29日、MikroTik RouterOS の脆弱性 CVE-2026-84411 について ICS 勧告ICSA-26-272-06 を公表しました。

  • 欠陥 — web 管理サービスの HTTP 要求本体の処理にある整数アンダーフロー（CWE-191）
  • 到達性 — 認証の前に到達できる
  • 影響 — 細工した1回の要求で root 権限の任意コード実行、またはサービス不能
  • 深刻度 — CVSS v3.1 で 9.8、CVSS v4.0 で 9.3（いずれも Critical）
  • 対象 — RouterOS 7.24 より前のバージョン
  • 悪用 — CISA は悪用の報告を受けていないとしている

この事案の記録としての意味は、脆弱性そのものより知らせ方のほうにあります。

第一に、ベンダー自身の勧告がありません。BleepingComputer は MikroTik と CISA の双方に照会したものの記事の公開時点で回答を得られず、MikroTik はこの件についてセキュリティ勧告を出していないと報じています。本記録の作成者が2026年10月2日に MikroTik のダウンロード・変更履歴のページを参照した時点でも、CVE-2026-84411 への言及は確認できませんでした。利用者が確認できる一次情報は、ベンダーではなく外国政府機関の勧告だけという状態です。

第二に、直すべき版の表記が食い違っています。CISA の勧告は「7.24 以降へ更新せよ」としていますが、BleepingComputer は「CISA はベンダーが 7.23 以降への更新を推奨しているとも書いている」と指摘し、同時に最新の安定版は 7.24.4、長期版は 7.23.7（いずれも9月16日から入手可能）であると伝えています。影響範囲が「7.24 より前」であれば 7.23 系はその中に入るため、この2つの記述は両立しません。

第三に、MikroTik の機器は過去に実際に狙われています。BleepingComputer は、ポーランドの CERT がCVE-2026-67276 と CVE-2026-86060 の2つを連鎖させ、SSH を外部へ出していた機器が完全に掌握された攻撃を警告したことに触れています。今回の CVE-2026-84411 に悪用の報告は無いものの、この製品群は悪用の実績がある側です。

CISA の緩和策は、製品固有の対処ではなく到達性を断つことに寄っています——制御系を インターネットから到達できない状態に保つ、制御ネットワークと遠隔機器をファイアウォールの内側に置いて業務ネットワークから分離する、遠隔接続には更新済みの VPN を使う。「管理画面を外に出さない」が最初の対策であるという、構えの話です。

攻撃の経過

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

CISA の勧告が記述しているのは、**認証前に到達できる web 管理サービスの HTTP 要求本体の処理に 整数アンダーフローがあり、単一の細工した要求で root としての任意コード実行または サービス不能に至る**という1点である。 **実際の攻撃は報告されていないため、以下の段階は「勧告が述べた成立の筋」であって 観測された手口ではない。**

  1. 1. 初期侵入確認済[2]
    **認証されていないネットワーク上の攻撃者**が、web 管理サービスへ **細工した HTTP 要求を1回送る**。CISA の記述では 「web 管理サービスには HTTP 要求本体の扱いに整数アンダーフローがあり、 それは認証の前に到達できる」（原文英語）。 **事前の資格情報も、連鎖させる別の脆弱性も必要としない。**
    根拠: CISA ICS 勧告 ICSA-26-272-06（CVE-2026-84411 の記述）
  2. 2. 実行確認済[2]
    整数アンダーフローの結果として、**root 権限で任意のコードが実行される**。 あるいは**サービス不能**に至る。 **RouterOS では管理機能とルーティングが同一の機器上にあるため、 root の取得はその機器の全機能の掌握を意味する**（本記録の補足）。
    根拠: CISA 勧告（「root として任意のコード実行、またはサービス不能」）
  3. 3. 影響（暗号化・破壊・改ざん）確認済[2]
    掌握された機器はネットワークの境界そのものである。 **CISA が示した緩和策は、機器固有の対処ではなく 「到達させない」「分離する」「VPN を使う」という到達性の制御である。** 悪用の観測は報告されていない。
    根拠: CISA 勧告の推奨事項

認証の前に届く整数アンダーフローで、1回の要求が root の実行になる概観出典 [2] [3]

CISA の勧告（ICSA-26-272-06、2026年9月29日）の記述は短く、要点は3つです。

  1. 場所 — RouterOS の web 管理サービスの、HTTP 要求本体の処理
  2. 欠陥 — 整数アンダーフロー（CWE-191）
  3. 到達性 — 認証の前に到達できる

結果として、「認証されていないネットワーク上の攻撃者が、単一の細工した要求を用いて、root として任意のコードを実行し、またはサービス不能を引き起こせる」（原文英語）。

深刻度は CVSS v3.1 で 9.8、CVSS v4.0 で 9.3。どちらも Critical の帯に入ります。対象は RouterOS 7.24 より前で、CISA は 7.24 以降への更新を求めています。

悪用の報告は受けていないと CISA は明記しています。それでも勧告を出したのは、危険を知らせ防御策を示すためだと述べています。

ベンダーの勧告が無く、直すべき版の記述が食い違っている対策・注意喚起出典 [1] [2] [3]

この事案で実務が詰まるのは、修正版の特定です。

  • CISA の勧告は「7.24 より前が対象」「7.24 以降へ更新」と書いています
  • BleepingComputer は、同じ勧告に「ベンダーは 7.23 以降への更新を推奨」という記述もあると指摘しています
  • 同紙によれば、最新の安定版は 7.24.4、最新の長期版は 7.23.7で、いずれも9月16日から入手可能です

「7.24 より前が対象」であれば 7.23.7 は対象の中に入ります。つまり長期版を使い続ける運用では、勧告の文面どおりに読むと行き先が無いことになります。

そして、MikroTik 自身のセキュリティ勧告がありません。 BleepingComputer は MikroTik と CISA の双方へ照会し、記事公開時点で回答を得ていません。本記録の作成者が2026年10月2日にダウンロード・変更履歴のページを参照した時点でも、この CVE への言及は確認できませんでした。

実務上の意味は明快です（以下は本記録の評価）。「最新版へ上げる」以外の判断材料が無いため、長期版での運用を前提にしている現場は版の選択を根拠づけられません。このとき取れるのは、版を追う前に到達性を断つことです—— CISA の緩和策も、まさにその並びになっています。

  • 制御系をインターネットから到達できない状態に保つ
  • 制御ネットワークと遠隔機器をファイアウォールの内側に置き、業務ネットワークから分離する
  • 遠隔接続には更新済みの VPN を使い、接続する機器も安全にする

悪用の報告は無いが、この製品群は狙われてきた側である背景・過去事例出典 [3]

CVE-2026-84411 自体に悪用の報告はありません。ただし BleepingComputer は、MikroTik の脆弱性は攻撃者やボットネットのマルウェアにしばしば狙われると述べ、直近の例を挙げています。

  • ポーランドの CERT が警告した攻撃では、CVE-2026-67276 と CVE-2026-86060 の2つを連鎖させ、SSH を インターネットへ公開していた機器が完全に掌握された

これは本件とは別の脆弱性です。本記録の作成者はこの警告の一次資料を取得していません。それでも、記録として並べる意味はあります（本記録の評価）。「悪用の報告が無い」は「狙われない」ではありません。認証前・単一要求・root という組み合わせは、ボットネットが最も好む形です。

緩和策
item: RouterOS を CISA が示す 7.24 以降へ更新する　副作用: **再起動を伴うため通信の断が生じる。** 加えて、**ベンダーの勧告が無いため「7.24 系へ上げれば直る」ことを ベンダーの言葉で確認できない。** 長期版（7.23 系）での運用を定めている現場では、 **版の方針そのものを変える判断**になる
item: web 管理サービス（www / www-ssl）をインターネットから到達できないようにする　副作用: **遠隔地の機器を画面で管理していた運用が止まる。** 代替の経路（VPN・踏み台）を先に用意しないと、 現地対応が必要な機器が増えて復旧が遅くなる
item: 機器側のファイアウォール規則で管理面への接続元を限定する　副作用: 接続元の IP が変わる運用（可搬回線・在宅）では管理できなくなる。 **規則の誤りで自分が入れなくなると、現地に行くまで戻せない**
item: 制御ネットワークと遠隔機器をファイアウォールの内側に置き、業務ネットワークから分離する（CISA の推奨）　副作用: 業務側から現場の機器へ直接届いていた仕組み（監視・集計・遠隔操作）を 作り直す必要がある。**費用と期間がかかる**
item: 遠隔接続を更新済みの VPN に寄せる（CISA の推奨）　副作用: **VPN 自体が新たな単一障害点・攻撃面になる。** CISA も「VPN は接続する機器と同じだけ脆弱でありうる」という趣旨の注意を併せて示している
