INC-2026-0288偽 Zoom に隠れた macOS バックドア

Jamf Threat Labs が2026年9月30日、偽の Zoom インストーラに隠れた macOS のバックドア「CloudSyncD」を公表した。ディスクイメージは正規の Zoom インストーラを模し、背景画像で「システム設定からセキュリティの警告を手で越えろ」と利用者に指示して Gatekeeper を迂回させる。続いて偽の認証プロンプトでログインパスワードを求め、dscl でローカルアカウントに対して正しさを検証したうえで、そのパスワードを外部へ送らずに設定ファイルへ Base64 で埋め、位置と長さを48個のゼロ幅 Unicode 文字で符号化して隠す。第2段の universal Mach-O は /dev/fd 経由のファイルレス実行を試み、失敗すると一時ファイルへ書き出して sudo で実行する。C2 は 8〜16秒間隔・ChaCha20-Poly1305 の暗号通信で、2011年登録の2ドメインが Cloudflare の背後にある。初確認は9月15日の開発中ビルドで、2日後にはライブ C2 を向いた検体が現れた。ブラウザ・Keychain・暗号通貨ウォレットの収集機能は無く、情報窃取型ではなく遠隔タスク実行のバックドアである。永続化は観測されず、感染の確認例も報告されていない

脅威・攻撃キャンペーン初報のみ有名事象として記録（日本と直接の関係は薄い）人を介した誘導（ビッシング・BEC）
初報: 2026年9月30日 最終更新: 2026年10月1日

Jamf Threat Labs は2026年9月30日、偽の Zoom インストーラに隠されたmacOS のバックドア CloudSyncD を公表しました。名称は、第2段が動く際のデーモン名（cloudsyncd）から取られています。

経過は短く、そして速いです。

  • 2026年9月15日 — Jamf が開発中のビルドを初確認（C2 が内部向け・暗号鍵が仮）
  • その2日後 — ライブの C2 基盤を向いた検体が、1つを超えるドメインに対して構成されているのを確認。試験から配備へ進んだ
  • 2026年9月30日 — Jamf が解析を公表

手口の中心は3つの操作です。

  1. Gatekeeper を利用者の手で越えさせる。ディスクイメージは「Zoom」ボリュームとしてマウントし、アプリのアイコンと Applications へのエイリアスを置いて正規のインストーラを模します。署名は ad-hoc（正規の開発者証明書でも公証でもない）。そのうえで背景画像が「システム設定 → プライバシーとセキュリティ →『このまま開く』→ 管理者パスワード」という手順を指示します。
  2. 偽の認証プロンプトでパスワードを取り、dscl で正しさを確かめる。「Enter your password to allow this.」と表示し、入力値をローカルアカウントに対して検証します。パスワードはどこにも送信されません（Jamf）。代わりに ~/.config/zoom/ の data.json の cache フィールドへBase64 で入れ、32〜64文字のランダムな詰め物で埋め、位置と長さを48個のゼロ幅 Unicode 文字（U+200B・U+200C）で version フィールドに符号化します。人の目にも、文字列の目視検査にも映りません。
  3. そのパスワードで第2段を昇格して起動する。第2段は Apple silicon と Intel の両方に対応する universal Mach-O。まず /dev/fd 経由でディスクに書かずに実行しようとし、失敗した場合は mktemp で一時ファイルへ書き出し、sudo に窃取したパスワードを渡して実行します。

動き出した後は、8〜16秒間隔のビーコンで C2 と通信します。通信は ChaCha20-Poly1305 で暗号化され、URI は jQuery のスクリプトのパスに似せて普通の通信に紛れます。C2 の2ドメインはいずれも2011年に登録され、Cloudflare の背後にあります。最初にホストの調査結果（システム情報）を送り、以降のチェックインでは機体のハードウェア識別子を載せます。

記録として押さえておきたいのは、これが情報窃取型ではないことです。Jamf は、ブラウザのデータ・Keychain の項目・暗号通貨ウォレットを集める機能は組み込まれていないと述べています。パスワードは第2段を起動するためだけに使われました。実体は遠隔タスク実行のバックドアで、実行可能ファイル（Mach-O）または gzip 圧縮された tar アーカイブを受け取って実行・展開します。

永続化は観測されていません。 LaunchAgent / LaunchDaemon の設置も、cloudsyncd への改名も、Jamf の解析中には到達しませんでした—— 解析の間に C2 からタスクが降ってこなかったためです。発見は VirusTotal の監視経由で、確認された感染例の報告はありません。

macOS は正しく警告を出しており、その警告を越える手順を利用者に教えている概観出典 [1] [2]

CloudSyncD の配布物は、Zoom のインストーラを模したディスクイメージです。「Zoom」というボリュームとしてマウントし、アプリのアイコンとApplications へのエイリアスを並べて、正規の Mac インストーラの見た目を作ります。

ただし署名は ad-hoc です。正規の開発者証明書でも公証でもありません。したがって macOS は開くことを拒みます。

ここが要点です（以下は本記録の評価）。この攻撃は OS の防御を破っていません。ディスクイメージの背景画像が、防御を手で下げる手順を教えます——「システム設定を開き、プライバシーとセキュリティへ行き、セキュリティの節まで送って『このまま開く（Open Anyway）』を押し、管理者パスワードを入れる」（原文英語）。

つまりGatekeeper の警告は出ており、利用者がそれを越えています。技術的な脆弱性は使われていません。「警告が出たら止まる」が成立しない環境では、署名も公証も効きません。

窃取したパスワードを外へ送らず、ゼロ幅文字で位置を記して設定ファイルに埋める原因・手口出典 [1] [2]

インストーラは次に偽の認証プロンプトを出します。文面は「Enter your password to allow this.」。入力されたパスワードは、dscl（macOS のディレクトリサービスの道具）でローカルアカウントに対して検証されます。正しいパスワードが入るまで進まない作りです。

そしてパスワードはどこへも送信されません（Jamf）。

  • ~/.config/zoom/ の data.json の cache フィールドにBase64 で入れ、32〜64文字のランダムな詰め物で埋める
  • 位置（オフセット）と長さを、48個のゼロ幅 Unicode 文字（U+200B＝zero width space、U+200C＝zero width non-joiner）でversion フィールドに符号化する

目で見ても、文字列を眺めても、そこに何かあるとは分かりません。この設計の狙いは、解析の目から隠すことにあります（本記録の評価）。設定ファイルは「Zoom のキャッシュ」に見え、パスワードは「見えない文字」で位置を指されています。

パスワードの用途は第2段の起動です。

  1. 第2段はApple silicon と Intel の両方に対応する universal Mach-O
  2. まず /dev/fd 経由でディスクに書かずに実行しようとする
  3. それが失敗した場合（SIP の下ではよく失敗する）、mktemp で一時ファイルへ書き出し、sudo に窃取したパスワードを渡して実行する

資格情報の窃取が、権限昇格の手段として使われているという構図です。

情報窃取型ではなく遠隔タスク実行のバックドアで、永続化は観測されていない被害規模・影響範囲出典 [1] [2]

パスワードを求める見た目から情報窃取型（infostealer）に見えますが、Jamf の結論は違います。

  • ブラウザのデータ・Keychain の項目・暗号通貨ウォレットを集める機能は組み込まれていない
  • 窃取したパスワードは第2段の実行を可能にするために使われた

実体は遠隔タスク実行のバックドアです。operator は実行可能ファイル（Mach-O）またはgzip 圧縮された tar アーカイブを送り込み、実行・展開させられます。

通信は次のようになっています。

  • 8〜16秒の間隔でチェックイン（機体の UUID を載せる）
  • ChaCha20-Poly1305 による暗号化
  • URI は jQuery のスクリプトのパスに似せて普通の通信に紛れる
  • C2 は2ドメイン。いずれも2011年登録でCloudflare の背後
  • 最初にホストの調査結果（システム情報）を送り、以降はハードウェア識別子を載せる
  • 作業ディレクトリは利用者のホーム配下の隠しディレクトリ（~/.local/share/cloudsync/ 配下に暗号化したログを置く）

永続化は観測されていません。 LaunchAgent / LaunchDaemon の設置も、自身を cloudsyncd として置く動作も確認されませんでした。Jamf はその理由を「解析の間に C2 からタスクが降ってこなかったため、そこまで到達しなかった」と説明しています。

ここは記録として注意が要ります（本記録の評価）。「永続化しない malware」ではなく「永続化を見られなかった」です。遠隔からタスクを配れる implant なので、永続化は後から配られます。

2日で試験から配備へ移っており、同一の鍵と名前を使い回している評価・解釈出典 [1] [2]

時間の経過が示すものがあります。

  • 9月15日 — 開発中のビルド。C2 は内部向け、暗号鍵は仮の値
  • その2日後 — ライブの C2 を向いた検体。1つを超えるドメイン

2日です。開発中の検体が VirusTotal に上がり、その2日後には配備用の構成になっています。これは防御側にとって、「開発中の検体を見つけた」時点がすでに配備の直前であることを意味します（本記録の評価）。

一方で、攻撃者側の運用には手抜きがあります。Jamf は、全ビルドで文字列の難読化・暗号鍵と IV・デーモン名が同一で、違うのは接続先だけだと述べています。つまり1つの検体から取れた鍵と名前が、他の検体にも通用します。これは検知の作り手にとって有利な条件です。

そして C2 の2ドメインはいずれも2011年に登録されています。古いドメインは、評価（レピュテーション）による遮断をすり抜けます。「新規に登録されたドメインを警戒する」という一般的な指標は、ここでは効きません。

指標の表と技術 ID を本記録は持っていない——検知を作るなら一次資料を直接見ること未確定事項出典 [1] [2]

本記録の限界を明記します。

  • ハッシュ値と C2 の2ドメイン名を持っていません。 Jamf のレポートには「Indicators of compromise」の節がありますが、本記録の作成者が取得したページ本文には表の中身が含まれていませんでした
  • MITRE ATT&CK の技術 ID も転記していません。レポートは対応を掲げていますが、個々の ID を一次資料で確認できませんでした。記述から推定して当てはめることはしません

あわせて公表されていないことを並べます。

  • 配布の経路（検索広告・偽サイト・共有リンク・メールのいずれか）
  • 感染の確認例、標的の業種・地域
  • 永続化の方式とC2 から降ってくるタスクの内容
  • 攻撃者の帰属、既知のファミリ・集団との関係

検知やハンティングを作る場合は、Jamf のレポートの指標表を直接参照してください。

item: 業務端末の利用者から管理者権限を外す（「このまま開く」と `sudo` の経路を断つ）　副作用: **利用者が自分で application を入れられなくなる。** 管理側の配布の仕組みと申請の窓口を先に用意しないと、 業務が止まるか、管理外の端末（私物）へ逃げる

対応の評価

CISO・経営層への示唆
  • 「警告が出たら止まる」が成立しない環境では、署名も公証も効かない
    配布物は ad-hoc 署名で、macOS は正しく実行を拒んでいる。 攻撃は背景画像で「システム設定から『このまま開く』を押して管理者パスワードを入れる」 という手順を教え、利用者自身に防御を下げさせている。
    取るべき行動 **利用者が Gatekeeper の警告を越えられるかどうかを、組織の設定として確認する。** 越えられる状態であれば、**管理者権限の付与方針と「このまま開く」の禁止**を 端末管理の設定として入れる。利用者教育は補助であって、設定の代わりにならない。
  • 常用アプリを利用者に自分で入手させている限り、偽のインストーラは届く
    本件は Zoom を模している。Zoom のような会議ソフトは利用者が自分で入れることが多く、 入手元の正しさを利用者が判断する構図になる。 **入手の経路（検索広告・偽サイト等）は公表されていない**が、 自分で探して入れる余地があることが前提になっている。
    取るべき行動 **会議・通信・遠隔支援といった常用 application を管理側から配布し、 利用者が自分で探す必要をなくす。** 配布の版が遅れると利用者が自分で取りに行くため、**更新の追従も同時に設計する。**
  • 「情報窃取型ではない」ことは安心材料ではなく、目的が分からないという意味である
    Jamf はブラウザのデータ・Keychain・暗号通貨ウォレットを集める機能が無いことを 確認している。実体は遠隔タスク実行のバックドアで、 解析の間にタスクが降ってこなかったため最終的な目的は分かっていない。
    取るべき行動 **「何を盗る malware か」で優先度を決める運用を見直し、 『遠隔から任意のものを配れるか』を基準に加える。** 遠隔実行が可能な implant は、発見時点の機能が最終形ではない。
  • 永続化が観測されていないことを「永続化しない」と読み替えてはならない
    Jamf は永続化を観測していないが、その理由を 「解析の間に C2 からタスクが降ってこなかったため、そこまで到達しなかった」と 説明している。
    取るべき行動 **ベンダーのレポートを社内に回すとき、「観測されなかった」と「存在しない」を 区別して要約させる。** 要約の過程でこの区別が落ちると、 対策の優先度を誤る（本記録の評価）。
セキュリティ技術者への示唆
  • 一時ディレクトリからの Mach-O 実行と、対話なしの `sudo` の組み合わせを見る
    第2段は `/dev/fd` によるファイルレス実行を試み、失敗すると `mktemp` で 一時ファイルへ書き出して `sudo` に窃取したパスワードを渡して実行する。 Jamf も「予期しない一時パスからの Mach-O の実行」の監視を勧めている。
    取るべき行動 **`/tmp`・`/var/folders` 配下から起動された実行可能ファイルと、 `sudo` の成功記録を突き合わせる検知を作る。** まず記録と通報から始め、誤検知の量を測ってから遮断に進める。
  • 設定ファイルの中のゼロ幅文字は、それ自体が指標になる
    パスワードの位置と長さが、`data.json` の version フィールドに 48個のゼロ幅 Unicode 文字（U+200B・U+200C）で符号化されている。 正規の application の設定ファイルにこれが並ぶことはまず無い。
    取るべき行動 **利用者のホーム配下の設定ファイル（JSON・plist）を対象に、 U+200B・U+200C の出現を検査する。** 本件固有の指標であることを承知のうえで、安価に試せる検査として置く。
  • ドメインの登録年が古い C2 は、評価による遮断をすり抜ける
    C2 の2ドメインはいずれも2011年に登録され、Cloudflare の背後にある。 「新規登録ドメインを警戒する」という一般的な指標では引っかからない。
    取るべき行動 **通信先の評価だけに頼らず、通信の形（8〜16秒の規則的なチェックイン、 jQuery のパスに似せた URI で Web でない通信）を検知の軸に加える。**
  • 攻撃側が鍵と名前を使い回しているため、1検体から汎用の検知が作れる
    Jamf は、全ビルドで文字列の難読化・暗号鍵と IV・デーモン名が同一で、 違うのは接続先だけだと述べている。
    取るべき行動 **ドメインやハッシュではなく、固定の鍵・IV・デーモン名・符号化の方式を 対象にした静的検知（YARA 等）を作る。** 接続先だけを変えた新しい検体にも当たる。
