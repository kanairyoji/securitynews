INC-2026-0294イェガラム貯蓄銀行、届出は住民番号含む5万24件

韓国の예가람저축은행（イェガラム貯蓄銀行）が、2026年9月30日に身元不明のハッカーによる顧客個人情報を含むサーバへの接近と情報流出の情況を確認し、10月3日にホームページで「個人情報流出事実の通知案内およびお詫び文」を掲示した事案——2026年10月10日、国会議員が個人情報保護委員会から取り寄せた同行の「個人情報流出事故届出書」により、**届け出た流出項目には住民登録番号・口座番号・住所が含まれ、規模は5万24件**だったことが判明した。ホームページの通知文は氏名・生年月日・連絡先のみで、指摘が外部に知られたのちに**追加の告知なく既存の通知が書き換えられた**。届出書の流出経緯は**ホームページシステムのWeb脆弱性（Webシェル）とメモリダンプ**と記載されている

不正アクセス・侵害続報が続いている有名事象として記録（日本と直接の関係は薄い）既知の脆弱性の悪用公表されていない／不明
初報: 2026年10月3日 最終更新: 2026年10月10日

【2026年10月10日 続報】届け出た内容と顧客に知らせた内容が違っていた。国会政務委員会の김형연（キム・ヒョンヨン）議員（조국혁신당）が個人情報保護委員会から取り寄せた同行の「개인정보 유출사고 신고서（個人情報流出事故届出書）」により、次が判明しました。

  • 届出書に記載された流出項目は、顧客の氏名・電話番号・口座番号・住所・住民登録番号である（原文韓国語）。規模は5万24件。
  • 一方、銀行がホームページに掲示した「個人情報流出事実の通知案内およびお詫び文」には氏名・生年月日・連絡先しか書かれていなかった。口座番号・住所・住民登録番号が落ちていた。
  • この事実が外部に知られると、銀行は別途の追加告知を出さずに既存の通知を書き換えたと報じられている。書き換え後の通知には、金融取引内容・口座番号・住民登録番号・勤務先名・入社日・各種発給/満了日・シリアル番号・住所が追加されたとする報道がある。
  • 金融監督院へ提出した侵害事故の内容は、流出項目を伴わない「個人（信用）情報流出（確認中）」のみの記載だったとされる。
  • 届出書の流出経緯の欄には「ホームページシステムのWeb脆弱性（Webシェル）とメモリダンプ」と記載されていた。Webシェルは、攻撃者が脆弱性を通じてサーバへ密かに設置し遠隔操作に使うプログラムである。
  • 김議員は「個人情報保護法が流出の事実を遅滞なく知らせるよう定めたのは、事故を知る側が被害を受ける人に知らせて被害の拡大を先んじて断つための措置である」「住民登録番号と口座番号、住所の流出を政府に届け出ておきながら顧客向けの案内文でこれを落としたことは極めて遺憾だ」と指摘し（原文韓国語）、政府に対し住民登録番号の暗号化などの安全措置が適正に行われたかの確認と二次被害を防ぐ対策を求めました。

この続報で事案の性質が変わりました。初報の時点で本記録が書けたのは「氏名・生年月日・連絡先が約4万名分」でした。実際に監督機関へ届け出られていたのは、住民登録番号と口座番号を含む5万24件です。住民登録番号は韓国で生涯変わらない識別子であり、口座番号と組み合わされば本人確認を装う接触の材料から、金融上の実害に近い材料へ性質が変わります（本記録の評価）。

本記録が重く見るのは、数字より「経路」です。手口（Webシェルとメモリダンプ）も、本当の流出項目も、本当の規模も、銀行の公表からは出てきませんでした。 監督機関への届出書が国会を経由して外に出たことで初めて分かったものです。届け出る先と、知らせる相手が別で、内容が一致しているかを誰も突き合わせていなければ、こうなります（本記録の評価）。

届出書そのものは公開資料ではなく、本記録の作成者は原本を確認していません。本続報の事実関係は、議員室の資料を引用した韓国の複数の報道に依拠します（齟齬に記録しました）。銀行のホームページの通知文（書き換え前・書き換え後のいずれも）にも、本記録は到達できていません。

2026年10月3日、韓国の예가람저축은행（イェガラム貯蓄銀行）が、ホームページに「개인정보 유출 사실 통지 안내 및 사과문（個人情報流出事実の通知案内およびお詫び文）」を掲示し、顧客の個人情報が流出したことを公表しました。銀行は「9月30日、顧客の個人情報が含まれたサーバへの身元不明のハッカーの接近、および個人情報が流出した情況を確認した」（原文韓国語）としています。

流出した項目は顧客の氏名・生年月日・連絡先で、規模は約4万名と推定されるが正確な規模は確認中とされています。銀行は、流出の事実を認知した直後に関連サービスの停止と外部 IP の遮断など必要な緊急措置を完了し、追加被害の予防のためにセキュリティ監視を強化、被害事実の認知後24時間以内に当局への届け出も済ませたと述べています。顧客の被害救済のためのコールセンターを運営し、被害顧客には案内の文字メッセージを送る予定であるとしています。

本件が置かれている文脈は、韓国の金融機関で連続している侵害公表です。 10月1日以降、신한은행（新韓銀行）・KB국민은행（KB国民銀行）・하나은행（ハナ銀行）など主要な市中銀行で顧客情報の流出が相次いで確認されており、우리은행（ウリ銀行）・NH농협은행（NH農協銀行）も攻撃を受けたが流出は無かったと公表しています。本件は、その連鎖が第二金融圏（貯蓄銀行）に及んだ最初の公表例です。ただし他行の事案との関連を示す材料は、どの公表にもありません。

手口は公表されていません。 侵入の経路、滞留した期間、持ち出しの手段、攻撃者の帰属のいずれも示されておらず、規模も「推定」の段階です。本記録は、銀行の公表を引用した韓国の複数の報道から確認できた範囲を整理します。銀行自身の掲示文の本文は、本記録の作成者が取得できていません（齟齬に記録しました）。

    **届出書に住民登録番号が流出項目として記載されていたことは判明したが、 暗号化して保管していたかは示されていない。** **김형연議員自身が「政府は住民登録番号の暗号化の有無など必要な安全措置が 適正に行われたかを確認すべきだ」と述べており、議員の側も把握していない** （原文韓国語）。 **この一点で被害の重さが変わる**（本記録の評価）。 暗号化されていれば流出しても直ちに読めるものではないが、 **本件の経緯には「メモリダンプ」が挙がっている**—— メモリ上では復号された状態で扱われることがあるため、 **保管時の暗号化が有効に働いたとは言い切れない。** **直前の KB 国民銀行の事案では「暗号化された状態」と明示されていた** （INC-2026-0293。本記録の注記）。
  • 顧客向け通知文から住民登録番号・口座番号・住所が落ちた理由と、書き換えの日時公表されていない
    **銀行は、届出書に書いた項目が顧客向け通知文に載らなかった理由を説明していない。** 作業上の誤りか、確認中として意図的に伏せたのかの区別がつかない。 **書き換えの日時も、書き換えたことを知らせる告知も確認されていない**—— 報道は「別途の追加告知なく既存の告知をそっと直した」と伝えている（原文韓国語）。 **読者にとって重いのは、書き換えが追跡できない形で行われた点である** （本記録の評価）。同じURLの内容が差し替わると、 **いつ何が変わったかを後から誰も確認できない。** **本記録は書き換え前後のいずれの通知文にも到達できていない**（齟齬に記録した）。

**認知直後に関連サービスを停止し、外部 IP を遮断した**（銀行の公表）部分的に機能**封じ込めを公表より先に終えている点は評価できる**（本記録の評価）。 ただし**停止の範囲・継続時間・業務への影響が公表されていないため、 「どこまで止めたのか」が分からない。** **外部 IP の遮断だけでは、同じ経路を別の IP から使われれば再発しうる**—— 根本原因が公表されていない以上、**この措置が十分かどうかは判断できない。**
**認知から3日後の2026年10月3日に、ホームページで公表した**機能した**確定値を待たずに公表した判断は、顧客保護の観点からは妥当である** （本記録の評価）。流出項目が**本人確認を装う接触にそのまま使える組み合わせ** である以上、**注意喚起は早いほど効く。** **ただし「速い」ことと「十分」なことは別である**—— 流出元・手口・確定規模のいずれも示されていない。

    本件の銀行は**認知後24時間以内の届け出を完了**し、そのことを公表文に明記した。 **届け出の期限は、事案が起きてから手順を作っていては間に合わない。** **直前の新韓銀行の事案は認知の日時そのものを公表しておらず、 対応の速さを外部が評価できない。**

  • 同業で事案が連続しているとき、「うちは規模が違う」は対象外の根拠にならない
    本件は、韓国の主要な市中銀行で流出の公表が相次いだ直後に、 **第二金融圏（貯蓄銀行）で起きた最初の公表例**である。 **市中銀行と貯蓄銀行では規制の水準・投資余力・運用体制が同じではない。** **「大手から中堅へ」という広がり方は、同種の攻撃が規模を問わずに 成立しうることを示唆する**（本記録の評価）。

セキュリティ技術者への示唆
  • 「外部 IP の遮断」は封じ込めであって、原因の除去ではない
    本件で銀行が挙げた緊急措置は**関連サービスの停止・外部 IP の遮断・ パスワードの変更・接近権限の強化・監視の強化**である。 **これらはいずれも「入られた後」に効く措置で、 どのように入られたかが分からないままである。** **同じ経路を別の IP から使われれば再発しうる**（本記録の評価）。
    取るべき行動 **封じ込めの手順書に「遮断で止まるもの／止まらないもの」を明記し、 遮断の完了をもって対応完了としない運用にする。** 具体的には**遮断の直後に『この経路が使えなくなっても同じ結果に至る別経路は あるか』を書き出す工程**を手順に入れる。 **外部 IP の遮断は時間稼ぎであり、原因の特定までの猶予を作る措置だと 位置づける。**
  • 遮断すべき IP を特定できたということは、記録は残っていたということ
    銀行は**外部 IP を遮断した**と述べている。 **これは接近元を特定できる程度の記録が残っていたことを意味する** （本記録の評価。銀行はそう説明していない）。 **一方で、侵害の開始時期も滞留期間も公表されていない**—— **「遮断に足る記録」と「調査に足る記録」は別物である。**
    取るべき行動 **自組織の記録について「遮断に使えるか」と「遡って調査できるか」を 別々に点検する。** 前者は直近の接続元が分かればよいが、 後者には**保全期間・改ざん耐性・機器の外への転送**が要る。 **個人情報を保持する系統については、少なくとも接続元・主体・参照件数・ 転送量を機器の外へ転送し、調査に足る期間（最低90日を目安に）保全する。**
  • 大量参照は「1回あたり」ではなく「累計」で見ないと捉えられない
    本件で出たとされるのは**約4万名分**である。 **1件ずつの参照はどれも正当に見える**ため、 **不正は件数と範囲に現れる**（本記録の評価）。 **検知の契機は公表されていないが、規模から見て一定量の読み出しが 発生していたと考えられる。**
    取るべき行動 **顧客データの参照を主体別・日別に集計し、上限を超えた時点で自動で遮断する 仕組みを入れる。** 併せて**一括抽出（バッチ・エクスポート）を申請制にし、 実行の記録を業務側の申請と突き合わせる。** **「誰が参照したか」だけを記録して突き合わせをしない運用は、 事後の調査にしか使えない。**
  • 生年月日を本人確認の要素に使っている限り、流出のたびに確認が弱くなる
    本件の流出項目には**生年月日**が含まれる。 **生年月日は変更できない属性であり、一度出たら永久に「秘密」ではなくなる。** **それを本人確認の要素として使い続けると、流出のたびに確認の強度が下がる。**
    取るべき行動 **コールセンター・窓口・オンラインの本人確認手順を棚卸しし、 『流出しうる静的属性（氏名・生年月日・住所・電話番号）だけで本人確認が 完結する経路』を洗い出して潰す。** 代替として**ワンタイムの確認コード・既登録の端末・公的個人認証**など 動的な要素を最低1つ必須にする。 **流出対象の顧客については、一定期間この要件を引き上げる運用も用意する。**
