INC-2026-0303Microsoft 公式 X が乗っ取られる

Microsoft の公式 X アカウント（@Microsoft・フォロワー1,300万超）が2026年10月2日に乗っ取られ、 **Clippy を騙る暗号資産トークン「$Clippy」の宣伝に使われた**。 Microsoft は「**当社発でない投稿を含む不正アクセスを確認した**」と認め、 アカウントの保護と投稿の削除を完了したが、 **乗っ取りの手口は公表されていない**

不正アクセス・侵害続報が続いている有名事象として記録（日本と直接の関係は薄い）公表されていない／不明
初報: 2026年10月2日 最終更新: 2026年10月3日

2026年10月2日、Microsoft の公式 X アカウント（@Microsoft）が乗っ取られ、 Clippy（Microsoft Office の旧版に搭載されていたアニメーションのクリップ型アシスタント）を題材にした 暗号資産トークンの宣伝に使われた。 アカウントのフォロワーは1,300万人超である。 攻撃は、@Microsoft が Clippy を騙る別のアカウント（@clippymsftcto・その後 X により停止）を フォローし、その投稿をリポストしたことから始まった。 プロフィール画像も Clippy の画像に変更された。 この動きはトークンの価格をあおって売り抜ける「pump-and-dump」の形とみられている。 その後に投稿され、まもなく削除された投稿（Microsoft は自社が投稿したものではないとしている）には 「明確にしておくと、Microsoft はいかなる暗号資産・暗号資産関連トークンも 支持・推奨・後援・承認していない」（原文英語）という文面が含まれていた。 Microsoft の広報担当者は BleepingComputer に対し 「X 上の当社アカウントへの不正アクセスと、Microsoft 発ではない投稿があったことを確認した。 アカウントは保護され、不正な投稿は削除された。引き続き経緯を調査している」（原文英語）と回答した。 Clippy を騙るもう一方のアカウント（@ClippyMSFT）は停止されず、 「$MSFT 株と直接ペアになった流動性プールを持つ」と主張して $Clippy トークンの宣伝を続けていた。 乗っ取りの手口・攻撃者・被害者（トークンを買って損をした人）の規模はいずれも公表されていない。

攻撃の経過

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

**攻撃者が @Microsoft アカウントへのアクセスを得て、 Clippy を騙るアカウントをフォロー・リポストし、プロフィール画像を変更することで、 暗号資産トークン $Clippy に「Microsoft 公式が関心を示した」という外観を与えた。** **アクセスをどう得たかは公表されていない。** データの窃取ではなく**信用の借用**が目的であり、 被害は Microsoft のブランドと、トークンを買った第三者に生じる構造である。

  1. 1. 初期侵入確認済
    **攻撃者が @Microsoft アカウントで投稿・フォロー・プロフィール変更を行える状態を得た。** **手口は公表されていない。**
    根拠: Microsoft の声明（「X 上の当社アカウントへの不正アクセスを確認した」原文英語）
  2. 2. 影響（暗号化・破壊・改ざん）確認済
    **@Microsoft が Clippy を騙るアカウント @clippymsftcto をフォローし、 その投稿をリポスト。プロフィール画像も Clippy に変更された。** これにより $Clippy トークンは **フォロワー1,300万超の公式アカウントの信用を借りた状態**になった。 さらに**別のアカウント @ClippyMSFT が @Microsoft の投稿をリポストし、 「$MSFT 株と直接ペアになった流動性プールを持つ」と主張して宣伝を続けた。**
    根拠: BleepingComputer・SecurityWeek の報道（@Microsoft の挙動とプロフィール変更の記述）
  3. 3. 影響（暗号化・破壊・改ざん）確認済
    **「Microsoft はいかなる暗号資産も承認していない」という内容の投稿が現れ、 まもなく削除された。** **Microsoft はこの投稿も自社のものではないとしている。** 攻撃者自身が「免責の文面」を投稿した形になり、 **公式アカウントの発言として何が本物かが外部から判別できない状態が生じた。**
    根拠: BleepingComputer の報道（Microsoft が「自社は投稿していない」と述べたとする記述）

盗まれたのはデータではなく、1,300万人に対する信用だった概観出典 [1] [2] [3]

この事案では個人情報も社内データも出ていません。 攻撃者が得たのは「Microsoft が言っている」という状態です。

手順は単純でした。@Microsoft が Clippy を騙るアカウント（@clippymsftcto）を フォローし、その投稿をリポストする。プロフィール画像を Clippy に変える。 それだけで、暗号資産トークン $Clippy は 「1,300万人のフォロワーを持つ Microsoft 公式が関心を示したトークン」になります。

pump-and-dump（価格をあおって売り抜ける手口）で最も高くつくのは信用の調達です。 通常は偽アカウント・偽広告・インフルエンサーへの支払いで積み上げる必要があります。 公式アカウントを1つ乗っ取れば、その工程が丸ごと省ける（本記録の評価）。

そして公式アカウントの投稿は、消しても消えません。 スクリーンショットは残り、「Microsoft がフォローしていた」という事実は引用され続けます。 実際、@clippymsftcto が停止された後も、 別のアカウント（@ClippyMSFT）が @Microsoft の投稿をリポストしたうえで 「$MSFT 株と直接ペアになった流動性プールを持つ」と主張して宣伝を続けていました。 乗っ取りは数時間で終わっても、その痕跡を材料にした宣伝は続きます。

Microsoft は不正アクセスを認めたが、どう入られたかは語っていない原因・手口出典 [1] [3]

Microsoft の広報担当者の回答は次のとおりです（原文英語）。

「X 上の当社アカウントへの不正アクセスと、Microsoft 発ではない投稿があったことを確認した。 > アカウントは保護され、不正な投稿は削除された。引き続き経緯を調査している。」

確認できるのはここまでです。 認証情報が盗まれたのか、多要素認証が回避されたのか、 セッションが奪われたのか、SNS 管理ツール経由だったのかは公表されていません。

SecurityWeek は一般的な可能性として次の4つを挙げています （本事案で確認されたものではなく、一般論の列挙です）。

  1. SIM スワップで電話番号を奪い、SMS による再設定・二要素認証を突破する 2. パスワード再設定用のメールアドレスを侵害する 3. 情報窃取型マルウェアでブラウザのセッションクッキーを盗み、認証そのものを迂回する 4. 第三者のマーケティング・SNS 管理ツールを侵害し、連携経由で投稿する

実務上重いのは3と4です。 3 は多要素認証を設定していても成立します——セッションクッキーがあれば認証の工程を通りません。 4 は「アカウントの持ち主の認証」を強くしても効きません—— 投稿する権限は連携アプリ側にあり、そのアプリの管理が弱ければそこが入口になります（本記録の評価）。

つまり「公式アカウントの多要素認証を有効にした」で安心できる構造ではありません。 どこが破られたか分からないまま終わると、組織は対策の優先順位を決められません。

公式アカウントは「資産」として管理されていないことが多い評価・解釈出典 [2] [3]

この事案を自社に当てはめると、問いは1つに絞られます—— 自社の公式 SNS アカウントは、誰が、どの端末から、どの経路で投稿できるのか。

多くの組織でこれが即答できません。理由は本記録の見るところ3つあります。

第一に、持ち主が IT 部門ではない。 公式アカウントは広報・マーケティングが運用し、 パスワードの管理・連携アプリの承認・退職者の権限剥奪が 情シスの資産管理の外側で行われています。

第二に、連携アプリが増える。 投稿予約・分析・キャンペーン管理のツールが積み上がり、 それぞれが投稿権限を持ったまま忘れられます。 本件で SecurityWeek が可能性として挙げた経路の1つがこれです。

第三に、事故時の手順がない。 乗っ取られた瞬間に必要なのは 「①投稿を止める、②連携を全部切る、③認証情報を再発行する、④公式に否定する」ですが、 ②と④は広報と IT の両方が動かないと実行できません。 Microsoft の場合、偽の投稿が出てから否定の声明が報道に載るまで、 1日近くかかっています（10月2日の乗っ取り → 10月3日の声明掲載。 ただしMicrosoft は自社の対応時刻を公表していないため、 実際の封じ込めがいつ終わったかは分かりません）。

公式アカウントは、顧客データと同じ重さの資産として台帳に載せるべきものです（本記録の評価）。 載っていなければ、認証の強度も連携の棚卸しも誰の仕事にもなりません。

X 上の公式アカウント乗っ取りは繰り返されている背景・過去事例出典 [2]

本件は Microsoft にとっても、X にとっても初めてではありません。

  • 2024年6月: @MicrosoftIndia（フォロワー21万1,000超）が乗っ取られ、ミーム株トレーダー「Roaring Kitty」を騙ってウォレットドレイナーのサイト（presaIe-roaringkitty[.]com——l を大文字の I に差し替えた偽ドメイン）へ誘導。ウォレットを接続して取引を承認した人の暗号資産が奪われた
  • 2023年3月〜11月: X 上の広告キャンペーンで「MS Drainer」が使われ、約6万3,000人から約5,900万ドル相当が奪われた（ScamSniffer の集計）
  • 2024年1月: 米証券取引委員会の @SECGov が SIM スワップで乗っ取られ、ビットコイン ETF の承認という偽の発表が投稿されてビットコイン価格が一時急騰。実行者 Eric Council Jr. は2025年2月に有罪を認め、懲役14か月の判決を受けた

@SECGov の例は、本件の性質を言い当てています—— 公式アカウントの乗っ取りは情報の窃取ではなく市場の操作に使えます。 @SECGov では価格が動き、刑事事件になりました。 本件でも狙いは $Clippy の価格であり、 「$MSFT 株とペアになっている」という主張で株式の権威まで借りようとしています（本記録の評価）。

対応の評価

評価材料がない判断は「評価材料なし」としています。結果論で断じないための区分です。
判断評価評価の根拠と留保
**Microsoft は不正アクセスの事実とアカウントの保護・投稿の削除までを認め、 手口・時間・影響の規模は示さなかった。**部分的に機能**本記録の作成者の評価である。** 事実関係を認めた点は妥当だが、 **本件は「他社が真似できる手口」ではなく「他社が同じ立場に置かれる構造」の問題**である—— 公式アカウントの乗っ取りはプラットフォーム側の認証と連携アプリの管理の話で、 **破られた箇所を示すことの公益は大きい**（本記録の評価）。 調査完了後に手口の類型だけでも示されれば、 同じ規模のブランドを持つ組織の対策は具体化する。
**否定は「削除された投稿」と「報道取材への回答」で行われた。** 企業のニュースルームや別の公式経路での告知は確認できていない。不十分**本記録の作成者の評価である。** 公式の確認が報道の取材への回答という形に留まり、 **文書としての公表が確認できないことは、本件の性質に対して弱い。** 攻撃者自身が「Microsoft は暗号資産を承認していない」という文面を投稿していたため、 **外部からは何が本物の Microsoft の発言か判別できない状態**が生じていた。 **ニュースルームでの短い告知が1本あれば、この曖昧さは解消できた**（本記録の評価）。
CISO・経営層への示唆
  • 公式 SNS アカウントを、顧客データと同じ重さの資産として台帳に載せる
    本件で攻撃者が得たのは**1,300万人に向けて「Microsoft が言っている」と示せる状態**である。 データの窃取はない。 それでも**トークンの価格操縦という金銭的な目的に直結して使われた。** 多くの組織では公式アカウントは広報・マーケティングが運用し、 **認証の強度・連携アプリの承認・退職者の権限剥奪が情報セキュリティの管理の外側にある** （本記録の評価）。
    取るべき行動 **公式 SNS アカウントを情報資産台帳に登録し、管理責任者・認証方式・ アクセスできる人の一覧・連携アプリの一覧を記載すること。** 具体には、①対外発信に使うアカウントを全部洗い出す（休眠・地域法人・製品別も含む）、 ②各アカウントの認証方式と復旧用の連絡先を確認する、 ③四半期ごとにアクセス権と連携アプリを棚卸しする。
  • 乗っ取られた瞬間に「別の経路で否定する」手順を用意しておく
    本件では**攻撃者自身が「Microsoft は暗号資産を承認していない」という文面を投稿**し、 それが削除された。 Microsoft が「自社の投稿ではない」と明確にしたのは後の段階で、 **公式の確認が報道に載るまで約1日かかっている。** 乗っ取られたアカウントでの発信は**もはや信用の担保にならない**ため、 別経路が必要になる（本記録の評価）。
    取るべき行動 **「公式アカウントが当社の管理下にない」と告知する経路と文面を事前に用意すること。** 具体には、①ニュースルーム／コーポレートサイトに緊急告知を出す手順を決める、 ②別の公式アカウント（別言語・別ブランド）からの相互参照の形を決めておく、 ③広報と情報セキュリティのどちらが起案し誰が承認するかを決め、 **目標時間を「1時間以内」のように数字で置く。**
  • 自社ブランドを騙る「金融商品」は、自社に実害がなくても自社の問題になる
    $Clippy は Microsoft の製品でもサービスでもない。 それでも**「$MSFT 株と直接ペアになった流動性プール」という主張**まで出され、 同社の知的財産（Clippy・Microsoft・$MSFT）が無断で使われた。 **購入して損をする人が出れば、問い合わせと批判は Microsoft に向く**（本記録の評価）。
    取るべき行動 **自社名・自社ブランド・自社ティッカーを冠した暗号資産・投資話の監視を、 ブランド保護の定常業務に入れること。** 具体には、①トークン名・ドメイン・SNS アカウントの名義監視を外部サービスか自前で回す、 ②発見時に「当社は関与していない」と出す定型文を用意する、 ③法務と連携して削除申立ての経路（プラットフォーム・取引所）を事前に確認する。
  • 多要素認証を有効にしても、セッションと連携アプリが残っている
    SecurityWeek が挙げた可能性のうち、 **情報窃取型マルウェアによるセッションクッキーの窃取は多要素認証を通り抜ける。** **第三者の SNS 管理ツールの侵害も、アカウント本体の認証を強くしても効かない。** 「多要素認証を入れたから大丈夫」という報告が上がってきたときに、 **この2つが残っていないかを問えるかどうかが分かれ目になる**（本記録の評価）。
    取るべき行動 **公式アカウントの点検項目に「セッション」と「連携アプリ」を明記すること。** 具体には、①定期的に全セッションを強制ログアウトする運用を入れる、 ②投稿権限を持つ連携アプリを一覧化し、不要なものを解除する、 ③運用端末を業務用の一般端末から分離する（または専用プロファイルに限定する）。
セキュリティ技術者への示唆
  • 公式アカウントの「状態の変化」は機械で監視できる
    本件の乗っ取りは**フォローの追加・リポスト・プロフィール画像の変更**として外部に現れた。 **これらは API や公開ページから機械的に観測できる変化**である（本記録の評価）。 人が気づくのを待つと、気づくのは報道か顧客になる。
    取るべき行動 **自社の公式アカウントのプロフィール・フォロー数・固定投稿・表示名を定期取得し、 差分が出たらセキュリティ側へ通知する仕組みを作ること。** 具体には、①15分間隔で状態を取得して差分を検出する、 ②フォローの追加とプロフィール画像の変更を高優先のアラートにする、 ③休日・夜間も届く経路に流す。
  • セッションクッキーの窃取は、認証の強度では止まらない
    情報窃取型マルウェアはブラウザから**認証後のセッションクッキー**を抜く。 これを使われると**パスワードも多要素認証も通らずにログイン状態が再現される**。 公式アカウントを運用する端末が一般の業務端末と同じであれば、 **その端末の1回の感染がブランド全体の乗っ取りに直結する**（本記録の評価）。
    取るべき行動 **公式アカウントの運用を専用の端末・専用のブラウザプロファイルに限定すること。** 具体には、①運用端末では他のサイトの閲覧・ファイルのダウンロードを許可しない、 ②セッションの有効期限を短くし、定期的な再認証を強制する、 ③端末の EDR で情報窃取型マルウェアの検出を優先度高で監視する。
  • 連携アプリの投稿権限は、アカウントの認証とは別系統で生きている
    SNS 管理ツール・投稿予約ツール・分析ツールは **アカウントの認証を経ずに投稿できる権限を持っている。** ツール側が侵害されれば、**こちらのパスワード変更も多要素認証も関係なく投稿される** （本記録の評価。本事案でこの経路が使われたとは確認されていない）。
    取るべき行動 **公式アカウントに紐づく連携アプリを棚卸しし、投稿権限を持つものを最小化すること。** 具体には、①連携アプリの一覧を取得して用途と管理者を確認する、 ②使っていないものを解除する、 ③残すものについてはツール側の管理者アカウントにも多要素認証を要求する。
  • 乗っ取りの痕跡は、アカウントを取り戻しても引用され続ける
    本件では@clippymsftcto が停止された後も、 **@ClippyMSFT が @Microsoft の投稿をリポストして宣伝を続けていた。** **投稿を削除しても、スクリーンショットと引用は残る**（本記録の評価）。 「取り戻して削除した」は終わりではなく、そこから二次利用の監視が始まる。
    取るべき行動 **乗っ取りの後処理に「痕跡の二次利用の監視」を含めること。** 具体には、①削除した投稿のスクリーンショットが流通していないかを一定期間監視する、 ②自社名を含む暗号資産・投資関連の投稿を監視対象に加える、 ③問い合わせ窓口に「当社は関与していない」と答えられる案内を用意する。

自組織に当てはまるか

該当する項目があれば、この事案と同じ構図が自組織でも成立しうることを意味します。
観点自社に当てはまるか該当する場合に何が起きうるか
体制・契約□ 対外発信に使う SNS アカウントの管理責任者・認証方式・アクセス権者の一覧が 情報資産台帳に載っていない本件の被害は**公式アカウントの信用そのもの**だった。 台帳に載っていなければ、認証の強化も連携の棚卸しも誰の仕事にもならず、 **事故時に「誰が投稿できたのか」すら即答できない。**
認証・認可□ 公式アカウントの認証が SMS による二要素認証にとどまり、 パスワード再設定用の電話番号・メールアドレスが同等に保護されていないSIM スワップとパスワード再設定経路の侵害は、 **公式アカウント乗っ取りの典型的な入口**として挙げられている （2024年1月の @SECGov は SIM スワップだった）。 **強い認証を設定しても、復旧経路が弱ければそこが使われる。**
運用・監視□ 公式アカウントを一般の業務端末・業務ブラウザから運用している情報窃取型マルウェアによるセッションクッキーの窃取は **多要素認証を迂回する。** 運用端末が分離されていなければ、 **1台の感染がブランド全体の乗っ取りに直結する。**
委託・第三者部品□ SNS 管理ツール・投稿予約ツールなどの連携アプリが投稿権限を持ったまま棚卸しされていない連携アプリの権限は**アカウント本体の認証とは別系統**で生きている。 ツール側が侵害されれば、自社側の認証強化は効かない。
体制・契約□ 自社ブランド・自社ティッカーを冠した暗号資産・投資話を監視する仕組みがない本件では「$MSFT 株とペアになった流動性プール」という主張まで出された。 **自社に実害がなくても、損をした人の問い合わせと批判は自社に向く。**
運用・監視□ 公式アカウントが乗っ取られたときに、別経路で否定を出す手順と文面が用意されていない乗っ取られたアカウントでの発信は信用の担保にならない。 **本件では攻撃者自身が「Microsoft は暗号資産を承認していない」と投稿しており、 何が本物か外部から判別できない状態が生じた。**
