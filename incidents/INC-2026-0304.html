INC-2026-0304GlassWorm 連動のテーマ拡張10本

Socket が2026年10月2日、**VS Code Marketplace と Open VSX にまたがる10本の「テーマ拡張」のクラスタ**を公表。 うち2本は悪性と確認され、1本は**AES-256-CBC で復号した JavaScript を eval で実行し、 Solana のトランザクションメモを次の配信先の伝達手段（デッドドロップ）に使う** GlassWorm と同一の実装だった。 **見た目を変えるだけのテーマ拡張がコードを実行できる**という構造が前提にある

脅威・攻撃キャンペーン続報が続いている有名事象として記録（日本と直接の関係は薄い）設計・実装上の不備委託先・供給元起因
初報: 2026年10月2日 最終更新: 2026年10月2日

セキュリティ企業 Socket は2026年10月2日、 Visual Studio Marketplace の4本と Open VSX の6本にまたがる「テーマ拡張」のクラスタを公表した。 うち2本は悪性と確認され、GlassWorm との結びつきが高い確度で認められたという。 調査時点で Marketplace に残っていたのは Coca-Cola Christmas と Aurora Borealis Studio Theme の2本で、 いずれも配色を変えるだけのテーマを装いながら実行可能な JavaScript を含み、 ブランドの騙り（brandjacking）や名前の占有（name-squatting）の兆候があった。 すでに削除されていた Aurora Nocturne Night Theme は、 「microsoft」という発行者名義で公開され、 配布された実体は難読化された約59KB の Windows 向けダウンローダだった—— fingercakes4sale[.]store から取得した内容を %TEMP%\temp_batch.cmd に書き、 コマンドウィンドウを隠したまま cmd.exe で実行する。 さらに Socket が解析した Cosmic Nebula Themes の Marketplace 版は、 AES-256-CBC で復号した JavaScript を eval() で実行し、 ロシア語環境・ロシアのタイムゾーンの端末を避け、 Solana のトランザクションメモを次の配信先を伝えるデッドドロップとして使う実装で、 GlassWorm で既に文書化されていたものと同じ Solana アドレス・同じ AES 鍵・同じ実行モデルを持っていた。 Socket はこの版を高い確度で GlassWorm、クラスタ全体をGlassWorm 関連と評価している。 Socket の報告を受け、VS Code Marketplace 側は報告された拡張を速やかに削除したが、 調査中も Open VSX には同じクラスタの拡張が残っていた。 実際にどれだけの端末で悪性コードが実行されたか、何が盗まれたかは公表されていない。

攻撃の経過

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

**配色テーマを装った VS Code / Open VSX の拡張機能が、 実行可能な JavaScript を同梱して配布された。** 確認された2本のうち、一方は**難読化された約59KB のローダから 外部ドメインの内容を `%TEMP%\temp_batch.cmd` に落として cmd.exe で隠れて実行**し、 他方は**AES-256-CBC で復号した JavaScript を eval() で実行し、 Solana のトランザクションメモから次の配信先を解決**した。 **公開リポジトリには無害なコードを置き、配布パッケージの中だけに実体を入れる**という 二枚看板が共通している。

  1. 1. 初期侵入確認済
    **攻撃者が、配色テーマを装った拡張を Visual Studio Marketplace と Open VSX に公開する。** Aurora Nocturne Night Theme は**「microsoft」の発行者名義**で公開され、 Microsoft 製を装っていた。 Aurora Borealis Studio Theme は**先行する正規拡張と同じ名前**を使い、 Coca-Cola Christmas は飲料ブランドの名称を使っていた。 利用者は**エディタの正規の手順でインストールする。**
    根拠: Socket の解析（クラスタの特定・発行者名義・brandjacking / name-squatting の兆候）
  2. 2. 実行確認済
    **拡張が起動した時点でコードが走る。** Aurora Nocturne Night Theme のマニフェストは `{"main": "./out/extension.js", "activationEvents": ["*"]}` で、 **あらゆる場面で起動する**指定だった。 `out/extension.js` は**1行に圧縮された約59KB の難読化 JavaScript**で、 ランダム化された識別子・16進エスケープ・実行時の文字列再構成・ **ゼロ幅 Unicode 文字で符号化されたペイロード**を含み、`eval()` で復号結果を実行した。
    根拠: Socket が公開したマニフェストと難読化コードの抜粋・復号後の動作コード
  3. 3. 検知回避確認済
    **解析と検知を避けるための仕掛けが重ねられている。** ①難読化（識別子のランダム化・16進エスケープ・解析妨害のノイズ）、 ②**ゼロ幅 Unicode 文字によるペイロードの符号化**、 ③**公開リポジトリには無害な `app.js` を置き、配布パッケージの中だけに実体を入れる**、 ④Cosmic Nebula Themes では**AES-256-CBC による暗号化**と **ロシア語環境・ロシアのタイムゾーンの端末の回避**、 ⑤`windowsHide` によるコマンドウィンドウの隠蔽。
    根拠: Socket の解析（難読化コードの抜粋・ゼロ幅文字の記述・回避条件の記述）
  4. 4. C2通信確認済
    **Cosmic Nebula Themes の Marketplace 版は、 Solana のトランザクションメモをデッドドロップとして使い、 後続のペイロードの配信先を動的に解決する。** 使われた Solana アドレス・AES 鍵・実行モデルは **GlassWorm で既に文書化されていたものと同一**だった。 Aurora Nocturne Night Theme は単純に `fingercakes4sale[.]store` へ HTTPS で接続していた。
    根拠: Socket の解析（Solana アドレスと AES 鍵の同一性、ダウンロード先ドメイン）
  5. 5. 影響（暗号化・破壊・改ざん）確認済
    **取得された内容が `%TEMP%\temp_batch.cmd` として保存され、 cmd.exe で実行された（Aurora Nocturne Night Theme）。** **落ちてきたものの内容は公表されておらず、 実際に何が行われたかは分からない。** Socket は一般的な影響として 「**資格情報の窃取、二次ペイロードの配信、ファイルやシステムの改変**」を挙げている（原文英語）。
    根拠: Socket が復号して公開した動作コード（https.get → createWriteStream → exec）

被害組織の対応

この事案で下された判断
  • **Socket は、武器化されていない拡張についても名称を挙げて「高リスク」と公表した。** 確認済みの悪性2本と、クラスタに属する残りの拡張を区別して記述している。
    トレードオフ: 名称を挙げれば**まだ悪性が確認されていない拡張の作者に不利益が及ぶ**可能性がある。 挙げなければ**利用者は自分が入れているものが該当するか判断できない。** Socket は後者を選び、**根拠（開発の痕跡の共有・不要な実行機能の保持）を明示**した。
  • **両マーケットプレースへ報告し、削除の対応がなされた後に公表した。** 一方で**Open VSX には調査中もクラスタの拡張が残っていた**状態で公表している。
    理由は公表されていない
    トレードオフ: 全部の削除を待てば利用者への警告が遅れ、 **その間もダウンロードは続く。** 残っている状態で公表すれば、**攻撃者に先に知らせることになる。**

配色を変えるだけの拡張が、ダウンローダを実行できる概観出典 [1]

この事案の芯は、特定の拡張が悪性だったことではありません。 テーマ拡張という「見た目を変えるだけ」と理解されている部品が、 任意のコードを実行できるという構造です。

Socket はこう書いています（原文英語）—— 「テーマ拡張はとくに危険になりうる。悪性のコードを含んで実行できるのに、 VS Code にはそのコードができることを制限する粒度の細かい権限制御が無い。」

悪性と確認された Aurora Nocturne Night Theme のマニフェストは次のようになっていました。

{ "main": "./out/extension.js", "activationEvents": ["*"] }

activationEvents: ["*"] はあらゆる場面で起動するという指定です。 そして out/extension.js は、テーマのコードとは似ても似つかない 1行に圧縮された約59KB の難読化 JavaScript でした。 復号した中身はこれだけです——

  1. fingercakes4sale[.]store から内容を取得する 2. %TEMP%\temp_batch.cmd として保存する 3. cmd /c で実行する。windowsHide でコマンドウィンドウを隠す

Socket の言葉を借りれば「配色テーマがこれを行う正当な理由は無い」。 そしてこの実体は公開リポジトリには置かれていません—— GitHub 上の app.js は無害に見えるテーマ選択と歓迎ページの実装で、 配布されたパッケージの中だけに難読化されたランタイムが入っていました。 ソースを読んで安全だと判断した調査者は、実際に動くコードを見ていないことになります。

Solana のトランザクションメモが次の配信先を教える原因・手口出典 [1]

Socket が解析した Cosmic Nebula Themes（Visual Studio Marketplace 版）は、 段階を分けたローダでした。要素は4つです。

  1. AES-256-CBC で暗号化された JavaScript を復号し、eval() で実行する 2. ロシア語環境とロシアのタイムゾーンの端末を避ける 3. Solana のトランザクションメモをデッドドロップとして使い、後続のペイロードの配信先を動的に解決する
  2. GlassWorm で既に文書化されていた Solana アドレス・AES 鍵・実行モデルと同一

3 が実務上もっとも重い要素です（本記録の評価）。 配信先が C2 サーバのドメインとして埋め込まれていれば、 そのドメインを止めればキャンペーンは止まります。 しかしブロックチェーン上のトランザクションメモは、取り下げも差し押さえもできません。 読み取り先は公開のパブリックチェーンで、 ブロックされにくい（開発端末から RPC エンドポイントへの通信は通常の通信に見える）。 つまりインフラの停止による対処が効かない設計です。

2 も示唆があります。ロシア語環境を避ける実装は 運用者が自国で動かしたくない意図の表れと読めますが、 本記録はそこから運用者の所在を断定しません—— コミットのオフセット（UTC-08:00）はロシアの時間帯と合いませんし、 言語の痕跡とタイムゾーンは偽装できます。 Socket も特定の国・集団を名指ししていません。

「いま武器化されていない」拡張をどう扱うか評価・解釈出典 [1]

Socket の評価でもっとも扱いの難しい部分がここです。

調査時点で Marketplace に残っていた Coca-Cola Christmas と Aurora Borealis Studio Theme は、武器化されていませんでした。 Open VSX に残っていた他の数本も、活動中の悪性ペイロードを含んでいませんでした。 それでも Socket は高リスクと評価し、両マーケットプレースへ報告しています。

理由は2つです。

  • 配色テーマには不要な実行機能を保持している（後の更新で悪用されうる） - 確認済みの悪性拡張を2本出したクラスタと、開発・公開・ソースコードの痕跡を共有している

この判断の仕方は、日本の組織がサプライチェーンのリスクを扱うときにそのまま使えます（本記録の評価）。 「現時点で悪性か」ではなく「悪性になりうる機能を持っているか」「出自を共有しているか」で見る。 拡張機能・ライブラリ・コンテナイメージのいずれでも、 更新は自動で入ってくるのだから、 いま無害であることは明日の保証になりません。

一方で、この基準を機械的に当てはめると正規の拡張も多数が引っかかります—— 実際、テーマ拡張が歓迎ページを表示するために JavaScript を含むのは珍しくありません。 Socket が根拠として重ねているのは開発の痕跡の共有（Git の作者名義・ コミットの時刻・ロシア語コメントの節見出しの一致・テーマ定義のほぼ100%の類似）であり、 実行機能の有無だけでは判断していません。 自組織で同じ判定をするなら、同じ重ね方が必要になります（本記録の評価）。

発行者名義が「microsoft」でも通る対策・注意喚起出典 [1]

悪性と確認された Aurora Nocturne Night Theme は、 「microsoft」の発行者名義で公開され、Microsoft 製の拡張を装っていました。 また Coca-Cola Christmas は飲料ブランドの名称を使い、 Aurora Borealis Studio Theme は先行して存在する正規の拡張 （mister-gold.aurora-borealis-theme）と同じ名前を使っていました。

利用者側の防御として現実的なのは次の順です（本記録の評価）。

  1. 発行者の識別子（publisher.extension の形）で確認する。表示名は自由に付けられる。microsoftvs.microsoftvs は Microsoft ではない
  2. 組織で許可する拡張を一覧で管理する（VS Code のextensions.allowed による許可リスト）。テーマも対象に含める
  3. インストール数と公開からの経過期間を見る。ただし本件のクラスタは8,000件超・数万件を集めている—— 数は安全性の指標にならない
  4. GitHub のソースだけで判断しない。本件では公開リポジトリと配布パッケージの中身が違っていた

3と4は、通常よく勧められる確認方法がそのまま効かないことを示しています。 「インストール数が多いものを選ぶ」「ソースが公開されているものを選ぶ」は、 本件では両方とも通り抜けられています。

段階検知の機会効きえた対策
初期侵入機会はあったが検知できず
**配布の時点で止める機会は配布基盤の側にあった**（本記録の評価）。 とくに**「microsoft」という発行者名義が通っていること**は、 名義の検証で防げる種類の問題である。 利用者側でも、**テーマ拡張が実行可能コードを含むこと自体**は パッケージを開けば分かる（ただし難読化されているため意図の判定は難しい）。

侵入を防げた配布基盤側での発行者名義の検証（既存ブランド名の占有を禁止する）

検知できた開発端末で %TEMP% 配下のスクリプト（.cmd / .ps1 / .bat）の作成と実行を監視する
検知回避現実的な検知機会なし

対応の評価

評価材料がない判断は「評価材料なし」としています。結果論で断じないための区分です。
判断評価評価の根拠と留保
**Socket は、武器化されていない拡張についても名称を挙げて「高リスク」と公表した。** 確認済みの悪性2本と、クラスタに属する残りの拡張を区別して記述している。機能した**本記録の作成者の評価である。** この判断は妥当だと考える。 **拡張機能は自動で更新される**ため、 **「いま無害」は明日の保証にならない**という理由付けは筋が通っている。 とくに評価したいのは**帰属の確度を二段に分けた**点で—— 「解析した版は高い確度で GlassWorm」「より広いクラスタは GlassWorm 関連」と 書き分けることで、**読者が自分の判断の強さを調整できる。**
**両マーケットプレースへ報告し、削除の対応がなされた後に公表した。** 一方で**Open VSX には調査中もクラスタの拡張が残っていた**状態で公表している。部分的に機能**本記録の作成者の評価である。** 公表を待たない判断は妥当だが、 **「どの拡張がまだ入手可能なのか」が時点付きで分かる形になっていない**—— 読者が自分で確認する必要がある。 **削除の状況は時間とともに変わるため、公表時点のスナップショットを 表の形で持つべきだった**（本記録の評価）。
CISO・経営層への示唆
  • 開発端末は、拡張機能という自動更新される部品を無審査で受け入れている
    本件の入口は脆弱性ではなく**正規の配布経路からのインストール**である。 そして**拡張機能は自動で更新される**—— **導入時に無害だったものが、更新で悪性になりうる。** Socket が武器化されていない拡張まで「高リスク」とした理由がこれである。 開発端末には**ソースコード・クラウドの資格情報・パッケージレジストリのトークン**が集まるため、 **1台の侵害が自社の製品そのものへの侵入経路になる**（本記録の評価）。
    取るべき行動 **開発端末の拡張機能を許可リストで管理し、テーマや配色の拡張も対象に含めること。** 具体には、①VS Code の `extensions.allowed` 相当の設定を端末管理で配布する、 ②許可する拡張は発行者の識別子（`publisher.extension`）で指定する、 ③新規の追加要求を受ける窓口と判断基準（発行者の実在・実行コードの必要性）を決める。 **「テーマは見た目だけだから自由」という例外を作らない。**
  • 「現時点で悪性か」ではなく「悪性になりうるか・出自を共有しているか」で判定する
    Socket の判定は**実行機能の有無だけではない。** Git の作者名義・2025年12月6日の約3時間に収まる5コミット・ 同一の UTC-08:00 オフセット・ロシア語コメントの節見出しの一致・ テーマ定義のほぼ100%の類似——**開発の痕跡の共有**を重ねている。 **この重ね方が、確認済みの悪性2本から残り8本への評価を支えている**（本記録の評価）。
    取るべき行動 **サプライチェーンのリスク判定の基準に「出自の共有」を入れること。** 具体には、①自社が使う拡張・ライブラリについて、 既知の悪性パッケージと同じ発行者・同じリポジトリ所有者・ 同じメールアドレスのものがないかを確認する、 ②1つの悪性パッケージが見つかったとき、 **同じ出自の他のパッケージまで遡って点検する手順を決める**、 ③判定の根拠を記録に残し、後から見直せるようにする。
  • 配信先がブロックチェーン上にあると、インフラの停止による対処が効かない
    解析された Cosmic Nebula Themes は **Solana のトランザクションメモをデッドドロップとして使い、 後続の配信先を動的に解決していた。** **ドメインは差し押さえられるが、パブリックチェーン上の記録は取り下げられない。** つまり**「C2 を止めてキャンペーンを終わらせる」という対処が成立しない**（本記録の評価）。 防御は端末側と通信の制御に寄らざるを得ない。
    取るべき行動 **「配信元を止められない」前提で、端末側の封じ込めを設計すること。** 具体には、①開発端末からの外向き通信をプロキシ経由に限定する、 ②暗号資産を扱わない組織では、 **パブリックチェーンの RPC エンドポイントへの接続を遮断または警告の対象にする**、 ③開発端末上の資格情報を短命化し、侵害時の被害の上限を下げる。
  • 「公開リポジトリがあるから安全」「インストール数が多いから安全」が通らない
    本件では**公開リポジトリの `app.js` は無害で、 配布パッケージの中だけに難読化されたローダが入っていた。** そして**クラスタは Marketplace で8,000件超、Open VSX で数万件**を集めている。 **一般に勧められる2つの確認方法が、両方とも通り抜けられている**（本記録の評価）。
    取るべき行動 **拡張・ライブラリの採用基準から「ソース公開」「インストール数」を 単独の根拠として外すこと。** 具体には、①基準を「許可リストに載っているか」に置き換える、 ②新規採用時は**配布パッケージの中身**（.vsix を展開した実体）を確認する、 ③確認を人手で毎回やらないために、 許可リストの維持を少人数の担当に集約する。
セキュリティ技術者への示唆
  • エディタが cmd.exe を起動したら異常である
    Aurora Nocturne Night Theme は **`exec('cmd /c "%TEMP%\temp_batch.cmd"', {windowsHide: true})` を実行していた。** **配色テーマの適用でコマンドプロセッサが起動する理由は無い**（Socket も同旨を記す）。 **`windowsHide` でウィンドウは表示されないため、利用者が目で気づく機会は無い。** 一方で**プロセスの親子関係は EDR から見える。**
    取るべき行動 **開発端末の EDR に「エディタのプロセスがシェル・スクリプトホストを子として起動した」 検知ルールを入れること。** 具体には、①親プロセスが Code.exe / cursor.exe 等で 子が cmd.exe / powershell.exe / wscript.exe の組み合わせを検知する、 ②%TEMP% 配下の .cmd / .bat / .ps1 の作成と実行を記録する、 ③開発者が正規に使うケース（タスク実行・ターミナル）との差を調整して誤検知を減らす。
  • 配布パッケージと公開リポジトリは別物として扱う
    **Socket は「GitHub 上の無害に見える `app.js` だけを見た調査者は、 Marketplace の拡張が実際に実行していた別の難読化ランタイムを見落としうる」と指摘している。** **拡張の審査もレビューも、見ているものが配布物でなければ意味がない**（本記録の評価）。
    取るべき行動 **採用を検討する拡張については、配布パッケージ（.vsix）を取得して中身を確認すること。** 具体には、①.vsix を展開して `package.json` の `main` と `activationEvents` を見る （`activationEvents: ["*"]` は配色テーマには不要）、 ②`out/` 配下に難読化された JavaScript が無いかを見る、 ③公開リポジトリとの差分を確認する。
  • ゼロ幅 Unicode 文字は、コードを読んでも見えない
    本件のローダは**ゼロ幅 Unicode 文字（U+200B / U+200C / U+200D）で ペイロードを符号化**し、復号して `eval()` に渡していた。 **目で読んでも、通常のエディタ表示でも見えない。** 難読化と組み合わされると、レビューでの発見はほぼ不可能になる（本記録の評価）。
    取るべき行動 **ソースコードの検査にゼロ幅 Unicode 文字の検出を加えること。** 具体には、①自社のリポジトリとサードパーティのコードに対して U+200B〜U+200D・U+FEFF を検出する検査を CI に入れる、 ②検出時は意図を確認する（正当な用途はほぼ無い）、 ③`eval()` と動的な文字列再構成の組み合わせも併せて検出する。
  • 拡張を入れていた端末では、端末の清掃ではなく資格情報の再発行が本体の作業になる
    ダウンローダが**何を落としていたかは公表されていない。** Socket は一般的な影響として**資格情報の窃取・二次ペイロードの配信・ ファイルやシステムの改変**を挙げている。 開発端末には**SSH 鍵・クラウドのトークン・パッケージレジストリのトークン・ ブラウザのセッション**が揃っており、 **端末をきれいにしても、持ち出された秘密は生きたまま残る**（本記録の評価）。
    取るべき行動 **該当する拡張を導入していた端末が見つかった場合、資格情報の再発行まで行うこと。** 具体には、①SSH 鍵・個人アクセストークン・クラウドの認証情報・ パッケージレジストリのトークンを再発行する、 ②当該端末から行われたコミット・パッケージの公開を期間を区切って点検する、 ③`fingercakes4sale[.]store` への接続の有無を DNS / プロキシのログで遡って確認する。

自組織に当てはまるか

該当する項目があれば、この事案と同じ構図が自組織でも成立しうることを意味します。
観点自社に当てはまるか該当する場合に何が起きうるか
運用・監視□ 開発者が VS Code / VS Code 互換エディタ（Cursor・Windsurf・VSCodium 等）の拡張機能を 自由にインストールできる本件の入口は**正規の配布経路からの正規のインストール**である。 **Open VSX は VS Code 互換エディタが参照する**ため、 「VS Code を使っていない」ことは条件から外れる理由にならない。
委託・第三者部品□ 拡張機能の採用判断を「ソースが公開されているか」「インストール数が多いか」で行っている本件では**公開リポジトリと配布パッケージの中身が違い**、 クラスタは**8,000件超・数万件のインストール**を集めていた。 **よく勧められる2つの確認方法が両方とも通り抜けられている。**

運用・監視□ 開発端末からの外向き通信が無制限で、未知のドメインやブロックチェーンの RPC エンドポイントへの接続を観測していない`fingercakes4sale[.]store` への接続は観測できるが、 **Solana のデッドドロップは配信先を止められない。** **端末側と通信の制御が唯一効く層になる。**
