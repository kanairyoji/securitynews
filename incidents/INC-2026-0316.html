2026年9月18日、警察庁は我が国で初めて「ラップトップ・ファーム」を把握し、捜査のうえ解体したことを公表しました。

ラップトップ・ファームとは、国内の支援者の居宅内に設置され、北朝鮮IT労働者が遠隔から操作する PC のことです。北朝鮮IT労働者は、これと支援者が借りた VPS を使って居場所と作業場所を偽装し、国内外のクラウドソーシング・サービスでオンラインの開発業務を受注して報酬を得ていました。受注は、支援者から提供を受けた身分証明書画像で支援者になりすます、支援者が受注した業務を請け負う、支援者の銀行口座を振込先に指定して送金してもらうという形で行われています。警察庁は、関連捜査で判明した分を含め、暗号資産等で数億円相当が海外へ送金されていたとしています。

同じ公表で、北朝鮮を背景とするサイバー攻撃グループ WaterPlum（関連名称 Contagious Interview）の手口と規模も示されました。AI・暗号資産・NFT の企業や人材紹介サービスになりすまして求職者に接近し、オンライン面接や「コーディング課題」の名目でマルウェアを実行させる手口で、2025年12月頃から2026年7月にかけて100以上の国と地域で3万台以上とみられる PC が感染、7千件以上の暗号資産ウォレット情報が窃取され、WaterPlum 管理のウォレットに少なくとも約17億円相当（約1,071万ドル）が送金されていました。

警察庁と FBI は、WaterPlum と一部の北朝鮮IT労働者が、朝鮮労働党中央委員会軍需工業部313総局の指揮下で運用されていると評価しています。両者を結ぶ根拠として、WaterPlum の攻撃者が使っていた IP アドレスと、北朝鮮IT労働者がラップトップ・ファームやクラウドソーシング・サービスへ接続する際に使っていた IP アドレス、さらに国内暗号資産取引所（bitFlyer）の採用に応募した北朝鮮IT労働者が使っていた IP アドレスが合致したことが示されています。

攻撃の経過

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

**2つの経路が同じ指揮系統の下で動いている**（警察庁・FBI の評価）。 経路①**サイバー攻撃**——求人・ヘッドハンティングを装って IT 技術者に接近し、 コーディング課題の名目で悪意のある NPM パッケージを実行させ、 バックドア・RAT・情報窃取ツールで認証情報・暗号資産・身分証画像を奪い、 さらに**被害者の勤務先ネットワークへ侵入**する。 経路②**就労の偽装**——国内の支援者から身分証明書画像・居宅内の遠隔操作用 PC （ラップトップ・ファーム）・VPS・銀行口座の提供を受け、 クラウドソーシングで開発業務を受注し、報酬を暗号資産等で海外へ送金する。 **経路①で盗んだ身分が経路②のなりすましに使われ得る**と公表文は述べている。

検知できたEDR による端末の挙動監視（警察庁の緩和策に明記）
認証情報アクセス公表されていない
**公表文は、被害者側が収集に気づいた事例に触れていない。** 警察庁は「ウイルス対策ソフトが検知・駆除したからといって安心しないでください。 検知前に暗号資産を含む情報が既に窃取された可能性を考慮し」と述べており、 **検知時点では既に奪われている前提で動くよう促している。**
影響を限定できたウォレットのシードフレーズを PC 内に保管しない（紙に書き写す）。 感染が疑われたら別 PC で新しいウォレットを作り資産を退避する（警察庁の緩和策）
影響を限定できたブラウザのパスワード保存機能に業務の認証情報を置かない
永続化機会はあったが検知できず
**ラップトップ・ファーム側には、観測可能な特徴がある**（本記録の評価）—— 住宅回線から業務時間帯に継続する遠隔操作、 同一の居宅から複数の受注者アカウントへの接続。 **ただしこれを見られるのは回線事業者とプラットフォーム側であり、 発注側の企業からは見えない。**
検知できた発注側——受注者のアクセス元 IP と申告された所在地の整合を確認する （警察庁は採用応募について Whois 等での確認を挙げている）
侵入を防げた個人——自宅に第三者が遠隔操作できる PC を置かない。 依頼されたら警察へ相談する（警察庁の対策）
横展開機会はあったが検知できず
**組織側で見える局面である**（本記録の評価）—— 正規の認証情報を使った、普段と違う場所・時間からのアクセス。 **「従業員個人の求職活動」が組織侵入の入口になるという前提が無いと、 このアラートは優先されない。**
影響を限定できた外注先・受注者に渡す情報とアクセス許可範囲を必要最小限・最小権限にする （警察庁の対策）
影響を限定できた疑いを把握した時点でのアカウントとセッションの即時無効化（警察庁の対策）。 セッションの無効化まで含めることが要点——パスワード変更だけでは生きたセッションが残る
侵入を防げた多要素認証と、所在地・端末に応じた条件付きアクセス
持ち出し公表されていない
**資金の流れを誰が・どの時点で捉えたのかは公表されていない。** 「関連捜査で判明した分を含め」という書き方から、 **捜査の過程で事後に判明した部分があることは読み取れる**（本記録の読み）。
検知できた発注側——報酬の振込先が受注者本人の名義か、海外の第三者名義でないかを確認する （警察庁は本人名義以外の海外口座への送金要求を注意点として挙げている）
検知できた暗号資産での報酬支払いへの固執を注意信号として扱う（警察庁の注意点）
影響（暗号化・破壊・改ざん）検知した
**ソースコードの公開と Web サイトの改ざんは、起きてから分かる種類の結果である** （本記録の評価）。 発注側が「相手が誰か」を確かめる機会は、**納品物ではなく契約と支払の段階にある。**
侵入を防げた外注・再委託に関する禁止条項と契約内容の明確化（警察庁の対策）
検知できた納品物に対するコードレビューと、公開リポジトリへの流出監視

対応の評価

評価材料がない判断は「評価材料なし」としています。結果論で断じないための区分です。
判断評価評価の根拠と留保
**警察庁は、bitFlyer の事例を社名入りで、面接で見られた具体的な挙動まで公表した。** 一方で**ラップトップ・ファームについては、場所・時期・人数・検挙の有無を いずれも示していない。**機能した**本記録の作成者の評価である。** この配分は妥当だと考える。 **使える側（採用の現場）には具体を出し、捜査に触れる側は伏せる**という 切り分けになっている。 とくに評価したいのは、bitFlyer の節が **「気づけた点」を再現可能な粒度で並べている**ことで—— 別モニターを読み上げる様子、背後の話し声、出社の拒否、暗号資産での支払の固執は、 そのまま面接の確認項目にできる。 **一方で、国内の感染端末数を出さなかったことは惜しい**（本記録の評価）—— 日本の読者が規模を自分の文脈に置き換える材料が無い。
**4か国の機関による共同公表という形を採った** （警察庁・NCO・FBI・DC3・ASD/ACSC・BND・BfV）。 313総局の指揮下という評価は**「警察庁と FBI」の評価**として限定して書かれている。機能した**本記録の作成者の評価である。** **帰属の評価の主体を明示した書き方**を評価する—— 「警察庁と FBI は……評価しています」と限定することで、 読者は**どの機関がどこまで言っているのかを区別できる。** 共同公表の全体に同じ強さの評価が付いていると誤読させない書き方になっている。
CISO・経営層への示唆
  • 「委託先の身元」は、委託先企業ではなく実際に手を動かす個人まで降りないと確かめられない
    本件の構図は、**発注の相手が日本の身分証・日本の IP アドレス・日本の銀行口座を 備えているのに、作業者は国外にいる**というものである（公表文にもとづく）。 警察庁は、受注先の**提携先や再委託先**に北朝鮮IT労働者が関与する可能性を 考慮せよと明記している。 **契約書の相手方と、コードを書く人が同じだという前提が崩れている** （本記録の整理）。 さらに、発注してしまった場合の帰結は情報漏えいだけではない—— **外貨獲得の幇助として国内法令や対北朝鮮制裁の違反を問われるおそれ**がある。
    取るべき行動 **外注・再委託の契約を見直し、再委託の禁止または事前承諾の条項と、 実作業者の所在地・本人確認の方法を明記する。** 既存の契約についても、**開発業務をクラウドソーシング経由で発注している案件を 洗い出す**（部門ごとの小口発注が見落としやすい）。 あわせて**報酬の振込先が受注者本人の名義か**を確認する運用を入れる—— 警察庁は本人名義以外の海外口座への送金要求を注意点として挙げている。
  • 採用プロセスはセキュリティの管理対象である
    bitFlyer の事例で止まったのは、**技術的な検知ではなく面接での違和感**である （公表文は「同社は応募者の不審点に気づき適切に対応したため、 採用や被害には至っていない」とする）。 逆に言えば、**採用の現場が兆候を知らなければ通ってしまう。** 警察庁が挙げた兆候は人事部門が扱う情報である—— 応募経路、履歴書の内容、面接中の様子、報酬の受け取り方（本記録の整理）。
    取るべき行動 **人事・採用の担当者と、警察庁が挙げた確認項目を共有する。** 最低限、①普段応募が少ない職種への短期間の多数応募、 ②アクセス元 IP と申告居住地の不整合、③電話番号への連絡確認、 ④経歴書のスキルを面接で具体的に説明させる、 ⑤リモートワークと暗号資産での報酬支払いへの固執、 ⑥本人名義以外の口座への送金要求——をチェックリストにする。 **不審点に気づいた後の相談先（社内の窓口・警察）も先に決めておく** ——気づいても止める権限が無ければ通る。
  • 従業員個人の求職活動が、組織のネットワークへの入口になる
    公表文は、**窃取した認証情報で「被害者を雇用している組織」のネットワークに 侵入する**と明記している。 標的は Web 関係のデザイナー・エンジニアや暗号資産分野の技術者であり、 **転職活動は個人の私事として扱われるため、組織の視界に入らない** （本記録の整理）。 さらに盗まれた身分証画像は、別の誰かのなりすましに使われ得る。
    取るべき行動 **「選考課題としてコードを実行させられた」「ビデオ会議の不具合修正を頼まれた」 場合に相談してよい、という通知を出す。** 相談が不利益にならないことを明示する（求職を申告させるのが目的ではない）。 技術的には**業務端末と私用端末の分離**を確認し、 業務の認証情報をブラウザに保存しない運用を徹底する。
  • 「国内初の1件」を「国内に1件」と読み替えない
    公表文の表現は**「我が国で初めて……把握し、捜査及び解体しました」**であり、 **初めて把握したという意味である**（本記録の読み）。 解体の時期・場所・支援者の人数・設置台数はいずれも非開示で、 **同種の設置が他にいくつあるかは公表されていない。** 米国では同種の摘発が繰り返されており、**日本が例外である根拠は示されていない。**
    取るべき行動 **自社の採用・外注の経路で「国内の住所・国内の身分証」をもって 所在地の確認を終わりにしていないかを点検する。** リスク評価では「国内なら安全」という前提を外し、 **遠隔操作の有無（作業端末の実機所在と操作元の一致）を確認項目にする。**
セキュリティ技術者への示唆
  • 選考課題のコードは、業務端末で動かすものではない
    WaterPlum の実行経路は**悪意のある NPM パッケージ**と **悪質な VS Code プロジェクト（StoatWaffle）**である（公表文にもとづく）。 後者は**フォルダを開いて信頼した時点で `.vscode/tasks.json` の 自動実行コードが走る**——ビルドもテストも要らない。 **「開くだけ」が実行である**という点が、ふだんの感覚と食い違う（本記録の注記）。
    取るべき行動 **第三者から渡されたプロジェクトは、使い捨ての仮想マシンで開く。** VS Code は**制限モード**で開き （「このフォルダ内のファイルの作成者を信頼しますか？」に「いいえ」）、 `security.workspace.trust.enabled` を無効にしない。 **依頼されたプロジェクトを、過去に信頼済みのフォルダ配下へ置かない。** 開いたら最初に `.vscode/tasks.json` をエディタで読む。
  • 貼り付けを指示されたコマンドには、警察庁が挙げた文字列がそのまま現れる
    公表文は注意すべき文字列として `curl` / `base64` / `-enc` / `mshta` / `Invoke-WebRequest -uri` / `iwr -uri` / `hidden` を列挙している。 **「不具合を診断するためにこれを実行して」という指示の形で現れる**のが本件の特徴で、 診断という文脈が疑いを弱める（本記録の整理）。
    取るべき行動 **貼り付け前に、実行したときの動作を自分の言葉で言えるかを基準にする。** 言えないものは実行しない。 組織側では、**開発端末で `mshta` や `Invoke-WebRequest` が走ったこと、 エディタのプロセスが外部ホストへ接続したことを検知するルール**を用意する （警察庁も EDR の活用を挙げている）。
  • 感染が疑われたら、暗号資産の鍵は「作り直す」側である
    警察庁は**「ウイルス対策ソフトが検知・駆除したからといって安心しないでください。 検知前に暗号資産を含む情報が既に窃取された可能性を考慮し」**と述べ、 別 PC での新規ウォレット作成と資産の退避、 **シードフレーズを PC 内に保管しないこと**、 **PC の初期化（再セットアップ）**を推奨している。 秘密鍵は**パスワードと違い、漏れた時点で取り返しがつかない**（本記録の注記）。
    取るべき行動 **ウォレットの鍵とシードフレーズの保管場所を棚卸しし、PC 内のファイル・ クラウドメモ・スクリーンショットから除く。** 感染時の手順書に「別端末での鍵の再生成と資産の移動」を明記する。 **駆除の成功を復旧の完了としない。**
  • 遠隔の受注者について見るべきは、成果物ではなく接続の形である
    ラップトップ・ファームは**居場所と作業場所を偽装する仕組み**であり、 成果物の品質からは判別できない（公表文は、実際に受注業務を遂行していたとする）。 観測可能な手がかりは、**アクセス元 IP と申告居住地の不整合、 住宅回線からの継続的な遠隔操作、VPN・プロキシの常用**である （警察庁は VPN の多用を注意点として挙げている）。
    取るべき行動 **外部受注者に付与するアカウントのアクセス元を記録し、 申告された所在地との整合を定期的に確認する。** 権限は最小とし、**疑いが生じた時点でアカウントとセッションを無効化する手順**を あらかじめ用意する（セッションまで切ることが要点）。 ソースコードの持ち出し範囲を限定し、公開リポジトリへの流出を監視する。

自組織に当てはまるか

該当する項目があれば、この事案と同じ構図が自組織でも成立しうることを意味します。
観点自社に当てはまるか該当する場合に何が起きうるか
委託・第三者部品□ 開発業務をクラウドソーシング・サービス経由で発注している案件を、全社で一覧にできない
体制・契約□ 外注・再委託に関する禁止条項や事前承諾の規定が契約に無い、または運用されていない
認証・認可□ 外部受注者・応募者について、アクセス元 IP と申告された居住地の整合を確認していない
運用・監視□ 採用・人事の担当者が、北朝鮮IT労働者の兆候（面接中の挙動・報酬の受け取り方）を知らない
データの保持□ 外注先・受注者に渡すソースコード・認証情報とアクセス許可範囲が最小になっていない
システム構成□ 従業員の業務端末と私用端末が分離されておらず、業務の認証情報がブラウザに保存されている
