INC-2026-0318BambooToken が MQTT を C2 に使う

Lumen の Black Lotus Labs が、IoT 向けの MQTT 通信プロトコルを C2 に使う 未記載のマルウェアファミリ「BambooToken」を公表した。Windows 版は 中国の金融・政府機関で使われる USB トークン製品 Tendyron「OnKey」の DLL サイドローディングで入り、金山（Kingsoft）Office を装う版もある。 2023年2月から2026年7月まで活動し、モバイルアプリのバックエンド・法律事務所・ 金融・生体医療・ホテル・GitLab サーバなどアジアと南米の組織で感染が観測された。 感染端末は攻撃者のサーバへ直接つながらず MQTT のブローカー経由で指令を受け取り、 C2 ドメインは Cloudflare を代理に置いて背後の基盤を隠す。 Lumen は公開済みの既知の活動クラスタとの対応づけができず「新興の脅威クラスタ」と 位置づけたが、検体の多くが中国の IP 空間からアップロードされていることを示した

脅威・攻撃キャンペーン初報のみ有名事象として記録（日本と直接の関係は薄い）設計・実装上の不備委託先・供給元起因
初報: 2026年9月（本記録は正確な日付を確認できていない） 最終更新: 2026年10月4日

C2 に IoT 用のプロトコルを使うと、通信の相手が攻撃者のサーバでなくなります。

Lumen の Black Lotus Labs が公表した BambooToken は、MQTT（Message Queueing and Telemetry Transport）を指令経路に使うWindows / Linux 両対応のマルウェアです。MQTT は IoT 機器と制御側の通信に使われる「発行・購読（publish-and-subscribe）」方式で、メッセージは「トピック」へ発行され、購読者が受け取り、配送は「ブローカー」という中継点が管理します。

攻撃者から見た利点を、Lumen は3つ挙げています（原文英語）。①ブローカーの背後に残りの基盤を隠せる——感染した機器は C2 サーバと直接通信しない。②非同期の通信ができる。③ボットがトピックを購読しようとしても、ブローカーが承認しなければメッセージを受け取れない。 マルウェアで MQTT を使う例は稀で、Lumen が過去に確認したのは3件だけです（IOCONTROL・Korplug（PlugX）・WailingCrab）。

侵入の実行経路はDLL サイドローディングです。担ぎ手にされたのは Tendyron「OnKey」——USB ドライブに置いた暗号素材で端末へのアクセスを検証するハードウェアトークンの製品で、同社のサイトは中国の金融・政府分野の顧客を挙げています。 Lumen は、Tendyron のコード署名証明書もビルド環境も侵害されていないと評価し、標的のネットワークに元からあるサイドローディングに脆弱なファイルを悪用していると疑っています。 珠海金山办公软件（Kingsoft Office）を装う版もあります。

活動期間は2023年2月から2026年7月。観測された感染は、モバイルアプリのバックエンドサーバ（少なくとも4台）、法律・金融、スマートウォッチ関連のソフトウェア企業、ホテル、GitLab サーバ1台。個別に挙げられた標的は、香港の GitLab サーバ、ベトナムの機器開発企業、ベトナムのホテル、アルゼンチンの生体医療企業、チリの法律事務所、リトアニアの暗号資産サイト、マレーシアの金融組織です。

帰属について、Lumen は踏み込んでいません。 「このマルウェアのフレームワークを公開されている既知の活動クラスタと対応づけることができず、新興の脅威クラスタとして位置づける」としたうえで、検体の多くが中国の IP 空間からアップロードされ、テレメトリも中国国内のサーバから対応して得られていることを示しています（原文英語）。

本記録の起点は、2026年10月2日の台湾 iThome の報道です。事実関係は Black Lotus Labs の報告本文で裏取りしました。

攻撃の経過

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

**正規の署名付きプログラム（Tendyron「OnKey」）の DLL サイドローディング、 あるいは Kingsoft Office を装う形で Windows 端末に入り、 感染端末の環境情報を収集したうえで、IoT 向けの MQTT を C2 経路に使う。** 感染端末はブローカーと通信するだけで攻撃者のサーバへ直接つながらず、 C2 ドメインは Cloudflare を代理に置いて背後の基盤を隠す。 Windows 版はプラグインを読み込んで機能を足し（確認されたのは WMI でアンチウイルス製品を列挙するもの）、 **Linux 版はシェルコマンドの実行とファイルの上り下り・削除を行う。** **活動期間は2023年2月から2026年7月。**

  1. 1. 実行確認済
    **正規の署名付きプログラム Tendyron「OnKey」が悪性の DLL を読み込む （DLL サイドローディング）。** OnKey は USB ドライブに置いた暗号素材を取り出して端末へのアクセスを検証する製品で、 中国の銀行・政府のネットワークで広く使われているとされる。 **別の版は珠海金山办公软件（Kingsoft Office）を装っていた。** **初期の版（2023年2月）では `Update.log` というファイル名から始まり、 リモートスレッドを呼んでメモリへ注入する形だった。** エージェントは C++ 製で、**XOR で復号した GUID 文字列をミューテックスに使う。**
    根拠: Black Lotus Labs の報告（検体解析・VirusTotal の投稿記録）
  2. 2. 内部探索確認済
    **感染後、ハンドラ `ONLINE` が端末の環境情報を収集して C2 へ送る。** あわせて**回収されたプラグインは、Windows Management Instrumentation（WMI）を 使ってローカルで動作しているアンチウイルス製品の情報を収集し、 C2 へ返す。**
    根拠: Black Lotus Labs の報告（ハンドラとプラグインの解析）
  3. 3. C2通信確認済
    **MQTT を指令経路に使う。** トピックの構造（版 2.0 以降）は**全体への配信用トピックと `{GUID}/unPlugin`・`{GUID}/removePlugin`・`{GUID}/Plugin`・`{GUID}/`**で、 エージェントは `{"op": "offline", "gid": "{算出されたホストの GUID}"}` のような 状態メッセージを発行する。 **感染端末はブローカーと通信するだけで、C2 サーバへ直接つながらない。** **C2 ドメインは Cloudflare を代理に置く**（api80.c2iznja[.]com、 live-hk.c2iznja[.]com、turbo.c2iznja[.]com、ccc80.c2iznja[.]com、 古いものは chat5188[.]tk 系）。 **使われたポートは 1883・2883（MQTT）および 8883（SSL MQTT）、 加えて 63196 / 63916 が SSH として観測されている。**
    根拠: Black Lotus Labs の報告（トピック構造・IoC 一覧・Censys / VirusTotal の記録）
  4. 4. 収集推定
    **Windows 版はプラグインを読み込んで機能を拡張できる （`Plugin` / `unPlugin` / `removePlugin` のトピック）。** **確認されたプラグインはアンチウイルス製品の列挙である。** **検体の未実行コード（dead code）には、鍵入力の記録（文字列「KEY_RECOURD」）・ クリップボードへのアクセス・録音・カメラと画面の取得を示す文字列が残っていたが、 実装・有効化は確認されていない。**
    根拠: Black Lotus Labs の報告（プラグインの回収と文字列の解析）
  5. 5. 持ち出し確認済
    **ハンドラ `FILEEX` がファイルのダウンロード・アップロード・削除を行い、 `SHELL` がコマンドシェルを起動する。** **Linux 版はシェルコマンドの実行とファイルの上り下り・削除を実行できる。** **感染先に GitLab サーバ・ソフトウェア企業・モバイルアプリの バックエンドが含まれており、Lumen は供給網への含意を指摘している。**
    根拠: Black Lotus Labs の報告（ハンドラの解析・被害の構成）

この事案で下された判断
  • **Lumen は、被害組織を業種と国で示し、組織名は出さなかった。** **一方で悪用された製品名（Tendyron「OnKey」・Kingsoft Office）は明示し、 同時に「証明書もビルド環境も侵害されていない」という評価を併記した。**
    理由は公表されていない
    トレードオフ: 製品名を出せば**読者は自社に該当する資産を探せる**が、 **製品そのものが危険だという誤解を招きうる。** 出さなければ誤解は避けられるが、**防御側は何を探せばよいか分からない。**
  • **帰属については「公開されている既知の活動クラスタと対応づけできない」とし、 新興の脅威クラスタとして位置づけた。** 特定のアクター名を当てずに、**検体のアップロード元・テレメトリの所在・ 過去の PRC 関連クラスタの行動様式という状況証拠を並べる形を採った。**
    トレードオフ: アクター名を当てれば**読者は既存の脅威情報と結びつけられる**が、 **根拠が足りなければ誤った帰属が固定化する。** 当てなければ誤りは避けられるが、**読者は「誰が狙っているのか」を 既存の知識に接続できない。**

C2 をブローカーの後ろに隠すと、感染端末は攻撃者と直接つながらなくなる概観

本件で記録しておく価値があるのは、設計の選択です。

BambooToken は、指令の受け渡しに MQTT を使います。IoT 機器と制御側の通信に使われるプロトコルで、メッセージは「トピック」へ発行（publish）され、購読（subscribe）している側が受け取り、配送は「ブローカー」が管理します。

Lumen が挙げた攻撃者側の利点は3つです（原文英語）。

利点 意味
基盤を隠せる 感染した機器は C2 サーバと直接通信しない（相手はブローカー）
非同期 指令と応答の時刻が噛み合わなくてよい
購読の承認 ボットがトピックを購読しようとしても、ブローカーが承認しなければ受け取れない

3番目は防御側から見ると厄介です。検体を手に入れて C2 につないでも、承認されなければ指令が流れてこない ——解析側が指令の全体像を得にくい構造です（本記録の整理）。

マルウェアで MQTT を使う例は稀です。 Lumen の調査で見つかった先行例は3件のみ—— IOCONTROL（IoT マルウェア）、Korplug（別名 PlugX）、WailingCrab（サイバー犯罪のマルウェアファミリ）。Korplug は中国に関連するとみられるアクターと結びついていますが、Lumen は技術的指標にもとづく追加の重なりは確認していないとしています。

そして、C2 ドメインは Cloudflare を代理に置いています。 Lumen は、1つのドメインが Cloudflare Radar の上位50万に入り、もう1つは最盛期に上位100万に入っていたことを、感染の広がりを示す材料として挙げています—— 順位に出るほどの通信量があった、ということです。

担ぎ手にされたのは「本物の署名付きプログラム」だが、供給網は汚れていない原因・手口

Windows 版の実行経路は DLL サイドローディングです。

担ぎ手は Tendyron「OnKey」——USB ドライブに置いた暗号素材を取り出して端末へのアクセスを検証する製品で、Tendyron はワークステーションの利用者認証に使うハードウェアトークンを作っており、同社サイトは中国の金融・政府分野の顧客を挙げています。

ここで Lumen が明記している評価が重要です（原文英語）。

「Tendyron のコード署名証明書もビルド環境も、いずれも侵害されていないと評価する。攻撃者は、サイドローディングに脆弱なファイルであって、標的のネットワーク内に元から存在している可能性が高いものを悪用していると疑われる。」

つまりこれは供給網の汚染ではありません（本記録の整理）。正規の署名付き実行ファイルが、同じフォルダに置かれた悪性の DLL を読み込んでしまうという古典的な構造です。「正規の製品が入っていること自体が、攻撃者の足場になる」という話であり、Tendyron の製品に限った問題ではありません。

別の版は珠海金山办公软件（Kingsoft Office）を装っていました。

一方で、最初の侵入——そのファイルをどうやって端末に置いたのか——は公表されていません。 Lumen の記述は「標的のネットワークに元からあるファイルを悪用している」という推定までで、入口を塞ぐ対策は書けません。 防御側に残るのは、実行と通信の検知です（本記録の評価）。

本件に日本の被害組織は挙がっていません。一方で、C2 ノードとして挙げられた IP の一部は日本の IP 空間にあります。

ここから読み取れる実務上の論点は2つです（いずれも本記録の評価）。

① 「国外への不審な通信」という見方では引っかからない。日本の組織から見れば、日本の IP 空間への発信は「国内向け」に見えます。地理情報を使った絞り込みでは落ちます。見るべきは宛先の国ではなく、プロトコルとポートです。

② MQTT が外向きに出ていく必要がある端末は限られる。 Lumen の推奨もここを突いています—— 「MQTT のような異常なプロトコルがネットワークの外へ出ていくことを検知するルール」（原文英語）。ポート 1883（平文）・2883・8883（SSL）は、IoT 基盤を自社で運用していない組織では、出ていく理由がありません。

Lumen が挙げた防御側への推奨は、ほかに供給網とコード依存関係の把握（CI/CD パイプラインの整備）、ルータの定期的なパッチ適用と SNMP の堅牢化、調整された EDR、匿名の通信を探す集中型ファイアウォール、そして「宛先 IP が地理的に同じ地域にある場合でも、ネットワーク外への大量のデータ転送を把握すること」です。最後の1つは、①と同じ問題を別の言い方で指しています。

帰属について、Lumen は「できない」と書いている帰属

報告の帰属の扱いを、正確に引いておきます。

「我々はこのマルウェアのフレームワークを、公開されている既知の活動クラスタのいずれにも対応づけることができず、新興の脅威クラスタ（emerging threat cluster）として位置づける。」（原文英語）

示されているのは状況証拠です。

  • 検体の多くは中国の IP 空間からアップロードされ、対応するテレメトリも中国国内に所在するサーバから得られている ——Lumen はこれを中国および近隣国の利用者層を対象としたデータ収集キャンペーンを示すものとする
  • 現在の活動は東南アジアと南米に向いているが、PRC に基盤を持つ活動クラスタが、世界規模の標的へ移る前に目立たない場所で新しい能力を試す例を見てきた（Volt Typhoon・GhostEmperor・ZuoRAT の背後のアクターを挙げる）
  • 近年、PRC に連なるアクターがラテンアメリカへ標的を移す動きを観測している
  • 悪用された Tendyron の製品は中国の銀行・政府のネットワークで広く使われている

報道（iThome）は「Lumen は、その攻撃目標と活動の様式が中国に関連する脅威活動の特徴に合致するとみている」と伝えています。 本記録はこれを、上記の状況証拠を要約した表現として扱います ——Lumen は特定のアクターへの帰属を述べていません（本記録の整理）。

この区別を落とすと、「中国の国家支援アクターによる攻撃」という確定した事実があるかのように読めてしまいます。本記録の立場は、層を分けて書くことです—— ①観測（検体のアップロード元・テレメトリ・標的の所在）、②比較（過去の PRC 関連クラスタの行動様式）、③結論（対応づけできない＝新興クラスタ）。

**Lumen は「宛先 IP が地理的に同じ地域にある場合でも、 ネットワーク外への大量のデータ転送を把握すること」を推奨している**（原文英語）。 **転送量という指標は、プロトコルを変えられても残る**（本記録の評価）。
検知できた外向きの転送量の基準値を持ち、逸脱を警報にする
影響を限定できたソースコード基盤（GitLab 等）へのアクセスを限定し、 クローン・ダウンロードの監査ログを取る

対応の評価

評価材料がない判断は「評価材料なし」としています。結果論で断じないための区分です。
判断評価評価の根拠と留保
**Lumen は、被害組織を業種と国で示し、組織名は出さなかった。** **一方で悪用された製品名（Tendyron「OnKey」・Kingsoft Office）は明示し、 同時に「証明書もビルド環境も侵害されていない」という評価を併記した。**機能した**本記録の作成者の評価である。** この組み合わせは適切だと考える。 **「製品名を出す」と「製品は侵害されていないと明記する」を同時に行うこと**が 要点で——サイドローディングの事案では、 **担ぎ手の名前が無いと資産の洗い出しができない**一方、 **名前だけを出すと供給網の汚染と読み違えられる。** Lumen は後者を**「コード署名証明書もビルド環境も侵害されていないと評価する」**と 明示的に否定した（原文英語）。
**帰属については「公開されている既知の活動クラスタと対応づけできない」とし、 新興の脅威クラスタとして位置づけた。** 特定のアクター名を当てずに、**検体のアップロード元・テレメトリの所在・ 過去の PRC 関連クラスタの行動様式という状況証拠を並べる形を採った。**機能した**本記録の作成者の評価である。** **「できない」と書いたことを評価する。** 共有ツールや言語・時間帯だけで帰属を語る報告は多いが、 本報告は**対応づけの失敗を結論として明示し、 状況証拠を状況証拠として並べた。** **ただし読者側には読み替えの危険が残る**—— 報道は「中国に関連する脅威活動の特徴に合致する」と要約しており、 **元の留保が落ちやすい**（本記録の評価。本文の帰属の節で層を分けて示した）。
CISO・経営層への示唆
  • 正規の製品が入っていること自体が、攻撃者の足場になりうる
    本件で悪用されたのは**正規の署名付きプログラム（Tendyron「OnKey」）**で、 **Lumen は証明書もビルド環境も侵害されていないと評価している。** 攻撃者が使ったのは**「サイドローディングに脆弱で、 標的のネットワークに元からあるファイル」**である。 **つまり資産台帳に正しく載っているソフトウェアが担ぎ手になった** （本記録の整理）。 **供給網の汚染への備え（署名検証・SBOM）では、この経路は止まらない。**
    取るべき行動 **常駐するクライアントソフト（USB トークン・VPN・印刷・会議・セキュリティ製品）の 導入先ディレクトリの権限を点検する。** **利用者が書き込めるディレクトリから署名付き実行ファイルが起動していないか**を 確認し、該当するものはアプリケーション許可制御（WDAC / AppLocker）の 対象に入れる。 **「正規の製品だから」を理由に点検対象から外さない。**
  • 外部に出ていくプロトコルの一覧を持っていないと、珍しい C2 は見えない
    BambooToken は**IoT 用の MQTT**を C2 に使い、 **感染端末はブローカーとだけ通信して攻撃者のサーバへ直接つながらない。** Lumen が確認した先行例は3件のみで、**検知ルールが整っていない領域である。** 加えて**C2 ノードの一部は日本の IP 空間（ASN 63916）にあり、 日本の組織からは国内向けの通信に見える**（本記録の評価）。
    取るべき行動 **自組織から外部へ出てよいプロトコルとポートを明文化し、 それ以外を既定で遮断する。** **MQTT（1883 / 2883 / 8883）が外へ出る必要のある端末を特定し、 無ければ遮断する。** **検知の条件を「宛先の国」に依存させない** ——Lumen も「宛先が同じ地域にあっても大量のデータ転送を把握する」ことを 推奨している。
  • 開発基盤が感染先に並ぶ事案は、自社の外側まで影響する
    感染先には**香港の GitLab サーバ、スマートウォッチ関連のソフトウェア企業、 モバイルアプリのバックエンドサーバ（少なくとも4台）**が含まれ、 **Lumen 自身が供給網への含意を指摘している**（原文英語）。 **開発基盤が取られると、そこで作られた成果物を通じて 影響が下流へ広がりうる**（本記録の評価。本件で下流への波及が 確認されたという記述は無い）。
    取るべき行動 **自社の開発基盤（ソースコード管理・CI/CD・ビルド環境）について、 外部通信の許可範囲と資格情報の保管場所を点検する。** Lumen の推奨にある**供給網とコード依存関係の把握**を、 自社が「供給する側」の立場でも実施する ——**顧客に渡す成果物のビルド環境が感染していた場合に、 何を確認して何を伝えるかを先に決めておく。**
  • 帰属の表現は、報道を経ると留保が落ちる
    Lumen は**「公開されている既知の活動クラスタと対応づけることができず、 新興の脅威クラスタとして位置づける」**と明記したうえで、 検体のアップロード元・テレメトリの所在・過去の PRC 関連クラスタの行動様式を 状況証拠として並べている。 **報道は「中国に関連する脅威活動の特徴に合致するとみている」と要約しており、 元の留保が見えにくくなっている**（本記録の整理）。
    取るべき行動 **脅威情報を社内で回すとき、「誰が」の部分は一次資料の表現で引く。** 報告書が「対応づけできない」と書いているものを、 **社内資料で国家名に置き換えない。** 帰属の確度は対策の優先度を変えるため（国家支援の標的型か、 広く無差別かで対応が変わる）、**層を分けて記録する。**
セキュリティ技術者への示唆
  • サイドローディングは、実行ファイルではなく読み込み元のパスで見る
    担ぎ手は**正規の署名付き実行ファイル**であり、 **署名の検証では止まらない**（本記録の整理）。 見えるのは、**その実行ファイルが標準でない場所に置かれた DLL を 読み込んだという組み合わせ**である。 初期の版では `Update.log` というファイル名から始まり、 **リモートスレッドを呼んでメモリへ注入する**形も使われていた。
    取るべき行動 **EDR に「署名付きプロセスが非標準パスの DLL を読み込んだ」という 検知を入れる。** 加えて**リモートスレッドの生成（CreateRemoteThread 系）**を監視する。 ふだんの運用で、**常駐ソフトの導入ディレクトリに 利用者が書き込めないことを確認する。**
  • WMI でのアンチウイルス列挙は、攻撃の初期にしか出てこない行動である
    回収されたプラグインは、**WMI を使ってローカルのアンチウイルス製品の 情報を収集し C2 へ返す**ものだった。 **防御側の構成を調べる行動は、正常な業務ではほとんど現れない** （本記録の評価）。
    取るべき行動 **WMI の `root\SecurityCenter2` 名前空間への問い合わせを検知対象にする。** スクリプトブロックログと WMI 活動のログを有効にし、 **「どのプロセスが問い合わせたか」まで残す。**
  • ルータは中継だけでなく被害者にもなる
    Lumen は、**MQTT ポートで C2 と持続的に通信していた MikroTik・DrayTek の ルータについて、implant が MQTT で通信する性質から 「中継ではなく被害者とみられる」**としている。 **150台への走査が1日のうちに観測されている**（12月15日 07:30〜23:45 UTC）。 Lumen の推奨にも**ルータの定期的なパッチ適用と SNMP の堅牢化**がある。
    取るべき行動 **境界のルータ・SMB 向け機器のファームウェアの更新状況を一覧にし、 管理インタフェースを外部に出していないか確認する。** **SNMP の公開コミュニティ名とアクセス元を点検する。** 機器自身の外向き通信（とくに見慣れないポート）をログで確認する。
  • 検体にある文字列を「機能がある」と読まない
    鍵入力の記録・クリップボード・録音・カメラと画面の取得を示す文字列は、 **未実行のコード（dead code）に現れたものである。** **Lumen は実装・有効化を確認していない。** **一方でプラグイン機構は動いており、機能は後から足せる** （本記録の整理）—— つまり**「いま無い」は「次の版にも無い」の根拠にならない。**
    取るべき行動 **検知を機能単位ではなく、常駐と通信の形で組む。** プラグインの読み込みは C2 経路を通るため、 **通信側の検知（外向き MQTT・新規ドメイン）の方が持続する。** 脅威情報を社内で共有するときは、 **「確認された機能」と「文字列が見つかった機能」を書き分ける。**

自組織に当てはまるか

該当する項目があれば、この事案と同じ構図が自組織でも成立しうることを意味します。
観点自社に当てはまるか該当する場合に何が起きうるか
システム構成□ 自組織から外部へ出てよいプロトコル・ポートの一覧が無い（既定が許可になっている）
運用・監視□ 不審な通信の判定を宛先の国・地域に依存させている
委託・第三者部品□ 常駐するクライアントソフトの導入先ディレクトリの権限を点検していない
システム構成□ 開発基盤（ソースコード管理・CI/CD・モバイルアプリのバックエンド）が、他の業務系と同じ出口を共有している
運用・監視□ 境界のルータ・SMB 向け機器のファームウェア更新状況と管理インタフェースの露出を把握していない
