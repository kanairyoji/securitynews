INC-2026-0324PFU スキャナLinux版に2件

株式会社PFU が2026年9月29日13時、スキャナ用ドライバ Image Scanner Driver for Linux の 脆弱性2件（CVE-2026-78229・CVE-2026-81310）を公表し、 IPA・JPCERT/CC も同日 JVNVU#96968110 として出した。 1件は OS コマンドインジェクション（CWE-78・CVSS 3.1 で 6.7）で任意の OS コマンドが実行され、 もう1件はファイルアクセス時のリンク解釈の不備（CWE-59・同 6.6）で任意のファイルが上書きされる。 **いずれも成立の前提は「当該 Linux システムにログインできる攻撃者が事前に準備を行うこと」**で、 遠隔から単独で踏めるものではない。影響は fi Series の10版（V2.0.0〜V2.8.2）と SP Series の8版（V2.0.0〜V2.3.0）。 **示された対策は「最新版へ更新」だけで、修正された版番号も回避策も書かれていない。** 報告は Cipher Security Labs の Nir Yehoshua 氏。 悪用の有無、脆弱な機能・経路の詳細、国内の導入台数はいずれも公表されていない

脆弱性初報のみ日本の組織が当事者設計・実装上の不備
初報: 2026年9月29日 最終更新: 2026年10月2日

株式会社PFU は2026年9月29日13時（JST）、スキャナ用ドライバ「Image Scanner Driver for Linux」の脆弱性2件を自社のセキュリティ情報（PFU-2026-000001）として公表しました。 同日、IPA と JPCERT/CC もJVNVU#96968110として JVN に掲載しています。

公表された2件は次の通りです。

  • CVE-2026-78229 — OS コマンドインジェクション（CWE-78）。任意の OS コマンドがシステム上で実行される。 CVSS 3.1 基本値 6.7（AV:L/AC:H/PR:L/UI:R/S:U/C:H/I:H/A:H）、CVSS 4.0 基本値 5.4
  • CVE-2026-81310 — ファイルアクセス時のリンク解釈が不適切（CWE-59）。システム内の任意のファイルが上書きされる。 CVSS 3.1 基本値 6.6（AV:L/AC:L/PR:L/UI:R/S:U/C:N/I:H/A:H）、CVSS 4.0 基本値 5.2

読む順番を間違えないために、先にベクタを見ます。どちらも AV:L（ローカル）・PR:L（低い権限が必要）・UI:R（利用者の操作が必要）です。PFU と JVN の表現も揃っており、「当該製品がインストールされている Linux システムにログインできる攻撃者が、あらかじめ特定の準備を行うことで」成立するとされています。インターネット側から単独で踏めるものではありません。

その代わり、効き方は素直です。一般利用者の権限しか持たない者が、任意の OS コマンド実行と任意ファイルの上書きに届く——つまりローカルの権限昇格の足場として使える形です（本記録の評価。PFU も JVN も「権限昇格」という語は使っていません）。共用の作業端末・踏み台サーバ・複数人が入る業務サーバにスキャナを繋いでいる構成では、ログインできる人の数がそのまま前提条件を満たす人の数になります。

そして、この公表でいちばん扱いに困るのは対策の書き方です。 PFU も JVN も示しているのは「最新版へアップデートしてください」の一文とダウンロードサイトの URL だけで、どの版で修正されたのかが書かれていません。回避策の記載もありません。版番号が示されない限り、資産管理台帳の版と突き合わせて「直った／まだ直っていない」を機械的に判定することができません（本記録の評価）。

AV:L と PR:L の2つが、この2件の性格を決めています。外から単独で踏めるものではなく、ログインできる人が居ることが前提です。その代わり、要るのは低い権限だけで、結果は任意の OS コマンド実行と任意ファイルの上書きです。

したがって危険度は、製品ではなく構成で決まります。 1人しか使わない端末にスキャナを繋いでいるなら、前提条件を満たす人は本人だけです。一方、共用の業務サーバ・踏み台・複数人がログインする作業端末に繋いでいるなら、前提条件を満たす人の数はログインできる人の数と同じになります。同じ CVSS 6.7 が、構成によって別の重さになります（本記録の評価）。

直った版が示されていない——「最新版へ」だけでは、台帳と突き合わせて判定できない対策・注意喚起出典 [1] [2]

PFU と JVN が示した対策は次の一点だけです。

開発者が提供する情報をもとに、最新版へアップデートしてください。

PFU 側のセキュリティ情報も同じで、ダウンロードサイト（www.pfu.ricoh.com/fi/dl/）の URL が添えられているだけです。回避策の記載はありません。

ここで困るのは、「修正された版番号」が書かれていないことです。影響を受ける版は18版ぶん列挙されているのに、「どの版から安全か」という境界だけが無い状態です。

これは実務では次の差になります（本記録の評価）。

  • 版番号が示されている場合 — 資産管理台帳の installed_version と比較するだけで、対応が要る台数が機械的に出る。更新後の検証も版番号の確認で済む
  • 「最新版へ」だけの場合 — 「いまの最新は何か」を人がダウンロードサイトで調べ、その値を基準に台帳と突き合わせる。最新版が今後更新されれば基準も動くため、「本件に対応したか」の記録が残りにくい

対応の記録が残らないことは、次に同じ製品で脆弱性が出たときに効いてきます。本件については、更新を終えた時点の版番号を自組織側で記録しておくことを勧めます（公表資料に無いものは、自分で残すしかありません）。

「任意のファイルを上書きできる」が何に化けるかは、ドライバの権限次第（本記録の評価）評価・解釈出典 [1] [2]

ここからは本記録の評価です。

CVE-2026-81310 は C:N/I:H/A:H で、読まれるのではなく壊される側の脆弱性です。低い権限の利用者が、ドライバが書き込む先をリンクで別の場所へ向け替えられるという形（CWE-59）で、AC:L ——攻撃条件は低いとされています。

問題は「誰の権限で書かれるのか」です。スキャナのドライバは、装置の検出・ファームウェアの読み出し・USB や SCSI へのアクセスのために特権で動く部分を持つことがあります。仮にその部分が書き込みを行うなら、上書きの対象は設定ファイルや起動時に読まれるスクリプトにも届き、ローカルの権限昇格の足場になります。

ただし——PFU も JVN も、ドライバのどの部分が影響を受けるのかを書いていません。特権で動く部分を持つのかどうかも示されていません。したがって本記録は「権限昇格に至る」とは書けません。書けるのはここまでです。「任意のファイルの上書き」と公表されており、その先の到達範囲は読者の環境で変わる。

もう1件（CVE-2026-78229）は C:H/I:H/A:H で、任意の OS コマンド実行です。こちらは AC:H（攻撃条件が高い）とされており、成立には条件の整えが要ると読めます。2件を並べると「踏みやすいのは上書き側、効果が大きいのはコマンド実行側」という組み合わせになります。

  • 脆弱な機能・経路 — インストーラか、常駐サービスか、スキャン実行時の処理かが不明。特権で動く部分を持つかどうかも示されていない
  • 悪用の有無・実証コードの存在 — 記述が無い。「悪用されていない」の確認ではない
  • 回避策 — 記載が無い。すぐに更新できない場合の手当てが読み取れない
  • 国内の導入台数・業種の分布 — 公表されていない

推測で埋めずに、上の6点を「公表されていないこと」として残します。このうち実務に直接効くのは修正版の版番号と回避策の2つです。
