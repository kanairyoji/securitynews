INC-2026-0325バッファロー2機種に2件の脆弱性

株式会社バッファローが2026年9月28日、Wi-Fi ルータ WSR-300HP と Wi-Fi 中継機 WEX-G300 の 設定画面に2件の脆弱性があることを公表し、IPA・JPCERT/CC も同日 JVNVU#94863997 として出した。 CVE-2026-86530 は OS コマンドインジェクション（CWE-78・CVSS 4.0 で 8.6／CVSS 3.1 で 7.2）で **認証済み利用者**による細工された入力から任意の OS コマンドを実行され、 CVE-2026-95104 はスタックベースのバッファオーバーフロー（CWE-121・同 8.7／7.5）で サービス運用妨害（DoS）に至る。 **対策済みファームウェアは公表より前に出ており**（WSR-300HP Ver.2.55 が2026年8月25日、 WEX-G300 Ver.1.71 が9月3日）、**両機種は自動ファームウェア更新が既定で有効**なため、 既定のまま使っていた利用者は公表の時点で更新済みである。 **バッファローの告知は、DoS 側が「インターネット側から設定画面へのアクセス」を 有効にしている場合に外部から到達しうると書いているが、 本記録が確認した範囲で JVN の記述にはこの条件が現れない。** 報告は Veeti Punnonen 氏。悪用の有無、自動更新を無効にしている機器の台数、 両機種のサポート終了の扱いはいずれも公表されていない

脆弱性初報のみ日本の組織が当事者設計・実装上の不備
初報: 2026年9月28日 最終更新: 2026年10月2日

株式会社バッファローは2026年9月28日、Wi-Fi ルータ「WSR-300HP」とWi-Fi 中継機「WEX-G300」の設定画面に脆弱性2件があることを公表しました。同日、IPA と JPCERT/CC も JVNVU#94863997 として JVN に掲載しています。報告者は Veeti Punnonen 氏です。

  • CVE-2026-86530 — OS コマンドインジェクション（CWE-78）。認証済みユーザーによる細工された入力を処理することによって、任意の OS コマンドを実行される。CVSS 4.0 基本値 8.6／CVSS 3.1 基本値 7.2
  • CVE-2026-95104 — スタックベースのバッファオーバーフロー（CWE-121）。細工された入力を処理することによってサービス運用妨害（DoS）状態にされる。CVSS 4.0 基本値 8.7／CVSS 3.1 基本値 7.5

この事案でいちばん重要なのは、時間の順序です。

  • 2026年8月25日 — WSR-300HP の対策済みファームウェア Ver.2.55 を提供
  • 2026年9月3日 — WEX-G300 の対策済みファームウェア Ver.1.71 を提供
  • 2026年9月28日 — 脆弱性を公表（バッファローの告知と JVNVU#94863997）

修正が先、公表が後です。 公表の時点で、WSR-300HP は34日前、WEX-G300 は25日前に直ったファームウェアが出ていました（日数は本記録の算出）。しかも両機種は自動ファームウェア更新が既定で有効です。つまり、既定のまま使っていた機器は、公表の日にはすでに直っています。

だから読者が今日確認すべきことは「更新したか」ではありません。「自動更新を切っていないか」と「設定画面をインターネット側に開けていないか」の2つです。

後者が効くのは DoS 側です。バッファローの告知は、CVE-2026-95104 について「インターネット側からの設定画面へのアクセス」を有効にしている場合に外部から到達しうると説明しています。 OS コマンド実行側（CVE-2026-86530）は認証済みが要件なので、設定画面の管理パスワードを既定値のまま使っているかどうかが分かれ目になります（本記録の評価。バッファローは既定パスワードについて言及していません）。

公表された脆弱性は次の2件です。

  • CVE-2026-86530（OS コマンドインジェクション・CWE-78） — 認証済みユーザーによる細工された入力から任意の OS コマンドを実行される。CVSS 4.0 で 8.6／CVSS 3.1 で 7.2

順序が「修正 → 公表」になっていることが、この事案の性格を決めています。公表の時点で、WSR-300HP は34日前、WEX-G300 は25日前に直ったファームウェアが出ていました（日数は本記録の算出）。自動更新が既定で有効ですから、既定のまま電源が入っていた機器は、公表の日にはすでに更新されていることになります。

これは「急いで更新してください」という事案ではありません。 「更新が届かなかった機器がどれだけあるか」という事案です（本記録の評価）。

残るのは「自動更新を切った機器」と「設定画面を外に開けた機器」対策・注意喚起出典 [1] [2]

自動更新が既定で有効である以上、本件で危ないのは次の2種類に絞られます（本記録の評価）。

1. 自動ファームウェア更新を無効にした機器

既定を変更して自動更新を切っている機器は、34日／25日の先行期間の恩恵を受けていません。長期間電源を切っていた機器も同じです。バッファローは手動更新の手順（Windows／Mac のダウンロードページ）を案内していますが、自動更新を無効にしている機器がどれだけあるかは公表していません。

2. 設定画面をインターネット側から到達できるようにしている機器

バッファローの告知は、DoS 側（CVE-2026-95104）について「インターネット側からの設定画面へのアクセス」を有効にしている場合に外部から到達しうると説明しています。既定では設定画面は LAN 側からのアクセスに限られる作りです。

一方、OS コマンド実行側（CVE-2026-86530）の要件は認証済みです。したがって分かれ目は設定画面の管理パスワードになります。既定値のまま、あるいは推測しやすい値のままなら、「認証済み」という条件は障壁として働きません（本記録の評価。バッファローは既定パスワードについて言及していません）。

確認すべきことは3つです。

  • 機器のファームウェア版が Ver.2.55 / Ver.1.71 以降か
  • 自動ファームウェア更新が有効か
  • 設定画面へのインターネット側からのアクセスが無効で、管理パスワードが既定値でないか

点数が高いのは DoS 側だが、後始末が重いのは OS コマンド実行側（本記録の評価）評価・解釈出典 [1] [2]

ここからは本記録の評価です。

CVSS の点数は DoS 側（8.7／7.5）が OS コマンド実行側（8.6／7.2）より高いです。しかし、2件を自組織の優先度に落とすときは、結果の性質が違うことを見たほうが筋が通ります。

  • DoS（CVE-2026-95104） — 機器が止まる、あるいは応答しなくなる。復旧は再起動と更新で済むことが多い。ただしインターネット側から届きうる（バッファローの告知）ため、到達しやすさはこちらが上
  • OS コマンド実行（CVE-2026-86530） — 機器の上で任意のコマンドが動く。認証済みという条件が付く代わりに、通った後はネットワークの境界に置かれた装置を攻撃者が操れる状態になる。DNS の向き先・経路・接続機器の通信が触られうる。「直せば終わり」ではなく、通ったかどうかを調べる手順が要る

そして、家庭・小規模拠点の無線機器には、その手順がありません。ログは残っていないか、残っていても読む人が居ません。だから本件の実務上の答えは「踏まれたかを調べる」ではなく「踏まれる条件を作らない」——自動更新を切らない、設定画面を外に出さない、管理パスワードを既定値から変える、の3つに寄ります。

これは本件に限った話ではなく、「調べる手段を持たない機器」に共通する扱い方です（本記録の評価）。

  • 脆弱な機能・パラメータ — 「設定画面」までしか示されておらず、どの入力項目かは不明。そのため「その機能を使わない」という回避ができない。回避策の記載も無い
  • 悪用の有無・実証コードの存在 — 記述が無い。「悪用されていない」の確認ではない
  • サポート提供期間・サポート終了の扱い — 示されていない。次に脆弱性が出たときに修正が出るかどうかが読めない
  • 報告日と調整の経緯 — 報告者名のみが示されている
