INC-2026-0333HPE Instant On に18件、隣接網から

Hewlett Packard Enterprise が2026年9月29日に公開したセキュリティ情報 **HPESBNW05150** で、無線LANアクセスポイント **HPE Networking Instant On AP** に **CVE ベースで18件**の脆弱性が明らかになった。**うち5件が「クリティカル」**である—— **基盤 OS 上で特権を取得できるバッファオーバーフロー（CVE-2026-76721・CVSSv3.1 9.8）**、 **フォーマット文字列の処理の問題（CVE-2026-76722・9.8）**、 そして**隣接ネットワークから認証なしで攻撃可能**な **バッファオーバーフロー（CVE-2026-76723・9.6）・ コマンドラインインタフェースのコマンドインジェクション（CVE-2026-76724・9.6）・ 管理プロトコルの認証回避（CVE-2026-76725・9.6）**である。 **本件の要点は「隣接ネットワークから認証なし」という条件の意味にある**—— アクセスポイントにとって隣接とは**電波の届く範囲**であり、 **店舗・クリニック・小規模オフィスでは、来客用 Wi-Fi の圏内に立つだけで その条件は満たされる**（本記録の読み）。 Instant On は**情報システム担当のいない現場に置かれる製品群**であり、 **影響の大きさは製品の価格帯と反比例しない。** **影響は 3.4.1.0 以下で、修正は 3.4.2.0 以降。公表時点で悪用は確認されていない**

脆弱性初報のみ日本に波及した海外事案設計・実装上の不備
初報: 2026年9月29日 最終更新: 2026年10月5日

2026年9月29日（現地時間）、Hewlett Packard Enterprise（HPE）がセキュリティ情報 HPESBNW05150「Multiple Vulnerabilities in HPE Networking Instant On APs」を公開しました。 対象は無線LANアクセスポイントHPE Networking Instant On AP、対処された脆弱性は CVE ベースで18件です。

うち5件が「クリティカル（Critical）」です。

CVE 内容 CVSSv3.1 攻撃元
CVE-2026-76721 バッファオーバーフロー（基盤 OS 上で特権を取得） 9.8 遠隔・認証なし
CVE-2026-76722 フォーマット文字列の処理の問題 9.8 遠隔・認証なし
CVE-2026-76723 バッファオーバーフロー 9.6 隣接ネットワーク・認証なし
CVE-2026-76724 コマンドラインインタフェースのコマンドインジェクション 9.6 隣接ネットワーク・認証なし
CVE-2026-76725 管理プロトコルの認証回避 9.6 隣接ネットワーク・認証なし

本記録がもっとも重く見るのは、「隣接ネットワークから認証なしで攻撃可能」という条件が、アクセスポイントでは何を意味するかです。

CVSS の「隣接（Adjacent Network）」は、攻撃者が同じ論理的なネットワーク区画（または同じ物理的な近傍）にいる必要があるという条件です。一般のサーバであれば、これは「まず内部に入る必要がある」というハードルの高さとして読まれます。ところがアクセスポイントでは逆です。 無線LANの機器にとって隣接とは電波の届く範囲であり、来客用 Wi-Fi を提供している店舗や待合室では、その圏内に立って接続するだけで条件が満たされます（本記録の読み）。「認証なし」とあわせると、必要なのは物理的な近さだけになります。

もう一点。Instant On という製品の位置づけです。これは HPE の小規模事業者向けの系列で、クラウド管理により専任の担当者なしで運用できることを売りにしています。つまり置かれているのは、情報システム担当が常駐しない現場です（本記録の評価）。影響の大きさは製品の価格帯と反比例しません——アクセスポイントで特権を取られた場合、攻撃者はそこを通る通信の経路上に立ちます。

CVE-2026-76721 は「基盤となる OS 上で特権を取得できる」とされ、CVE-2026-76725 は「管理プロトコルにおける認証回避」です。後者について本記録が読み取る意味は、認証を強くする対策が効かないことです——破られるのはパスワードではなく、認証するかどうかの判定そのものです。

影響を受けるのは Instant On の 3.4.1.0 以下、修正は 3.4.2.0 以降です（本記録が報道と当局の注意喚起で確認した値。一次公表である HPE のセキュリティ情報の本文は、本記録の作成者が取得できませんでした ——後述）。公表時点で、公開された実証コードや実際の悪用は確認されていないとされています。

カナダ当局（Canadian Centre for Cyber Security）は2026年10月1日にAV26-982 として注意喚起しましたが、これは HPE の6本のセキュリティ情報をまとめた形で、Instant On はサーバ製品群（Superdome Flex・Compute Scale-up Server・Telco Service Orchestrator・Unified OSS Console）と同じ一覧に並んでいます。 大型サーバの一覧の中に、店舗のアクセスポイントが混じっているという形であり、読み手の属性によっては自社に関係する1行を見落としやすい構成です（本記録の評価）。

アクセスポイントにおける「隣接ネットワーク」とは、電波の届く範囲である概観出典 [1]

クリティカル5件のうち3件に「隣接ネットワークから認証なしで攻撃が可能」と書かれています。この条件の重さは、製品の種類によって変わります。

CVSS の攻撃元区分「隣接（Adjacent Network）」は、攻撃者が同じ論理的なネットワーク区画か、同じ物理的な近傍にいる必要があるという条件です。だから評点も、遠隔から到達できる 9.8 より低い 9.6 になります。

一般のサーバであれば、この差は意味があります。「まず内部に入らなければならない」というハードルが1つ増えるからです。

アクセスポイントでは、この前提が崩れます。

設置場所 「隣接」を満たす条件
店舗・飲食店 店内（または店先）に立つ
クリニック・歯科医院 待合室に座る
小規模オフィス 同じフロア・隣室・廊下にいる
来客用 Wi-Fi を同じ機器で提供 提供されたパスワードで接続する（来客は全員が該当）

「認証なし」とあわせると、必要なのは物理的な近さだけになります（本記録の読み）。したがって、本記録は 9.6 の3件を 9.8 の2件より軽いとは読みません。 評点の順序は、自組織における危険度の順序と一致しません。

とくに来客用 Wi-Fi を同じ機器で提供している場合、攻撃者は正規の利用者として機器に接続した状態で始められます。来客用の区画が業務用と論理的に分離されていても、破られるのは区画ではなく、区画を作っている機器そのものです（本記録の評価）。

前の4件と5件目は、性質が違います。

前4件（76721〜76724）は「入力をそのまま信じた」類の誤りです。バッファオーバーフロー・フォーマット文字列・コマンドインジェクションは、いずれも1990年代から知られている実装の誤りです。2026年に公開された製品系列の更新でこれが5件のうち4件を占めていることは、組み込み機器のコードベースが長命であることの表れと読めます（本記録の評価。HPE はこの形で説明していません）。とくにフォーマット文字列の脆弱性は、現代のコンパイラの警告でも検出しやすい種類であり、検査の網にかかっていなかった領域があることを示します（本記録の推定）。

5件目（CVE-2026-76725）だけは、対策の性質が違います。これは管理プロトコルにおける認証回避です。つまり破られるのはパスワードの強度ではなく、「認証するかどうか」の判定そのものです。

ここから出る結論は実務的です。「管理者パスワードを長くする」「多要素認証を入れる」という対策は、この1件には効きません（本記録の読み）。効くのは管理プロトコルに到達できる範囲を絞ることと、修正版を当てることの2つだけです。

  • **管理プロトコルと CLI に到達できる範囲を絞る。 CVE-2026-76725 は認証回避なので、認証の強化では止まらない**
    **CVE-2026-76725 は「管理プロトコルにおける認証回避」**である （国内媒体の記述）。 **破られるのはパスワードの強度ではなく、認証するかどうかの判定そのもの** であり、**パスワードを長くしても多要素認証を入れても効かない** （本記録の読み）。 **CVE-2026-76724 は CLI のコマンドインジェクション**で、 これも到達範囲を絞ることが直接の対策になる
    取るべき行動 **管理面（管理プロトコル・CLI・ウェブ管理）に到達できる経路を、 管理用の区画または有線からのみに限定する。** **無線側（とくに来客用の SSID）から管理面に届かないことを、 実際に端末を接続して確認する**（設定上の分離と実際の到達可能性は別である）
  • **来客用 Wi-Fi を業務用と同じ機器で提供している構成を見直す。 論理分離は、機器そのものが破られたときに効かない**
    **「隣接ネットワークから認証なし」の条件は、 来客用 Wi-Fi に接続できる全員が満たす**（本記録の読み）。 **VLAN やゲストネットワークによる分離は、 その分離を作っている機器の OS 上で特権を取られた時点で意味を失う。** **CVE-2026-76721 は「基盤となる OS 上で特権を取得できる」**とされている
    取るべき行動 **来客用 Wi-Fi を、業務用とは別の機器・別の回線で提供する** （費用は小さく、効果は構造的である）。 分けられない場合は、**来客用の提供を止める判断ができる状態**にしておく （誰が止められるか・止めたときに何が困るかを事前に把握する）。 **あわせて業務通信を端末から目的地まで暗号化・認証し、 アクセスポイントを信頼しない前提に移す**
  • **ネットワーク機器の記録を外部へ出す。 基盤 OS 上で特権を取られた機器の記録は、その機器の中に置いても意味がない**
    **CVE-2026-76721 の結果は基盤 OS 上での特権の取得である。** **本記録が確認した資料には、侵害を見分ける痕跡が示されていない。** **小規模事業者向けの機器では記録が機器内に留まることが通常であり、 後から「侵害されていない」と言う根拠が作れない**（本記録の評価）
    取るべき行動 **機器が syslog の外部転送に対応しているかを確認し、対応していれば有効にする。** 対応していない場合は、**クラウド管理の画面に残る履歴 （再起動・版の変化・設定変更）を定期的に確認する手順を作る。** **「見る人がいない機器」を作らないことが、記録を持つことの前提である**
