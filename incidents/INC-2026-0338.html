INC-2026-0338偽会議サイトで金融従業員に新種2種

北朝鮮系 STARDUST CHOLLIMA が偽の動画会議サイトで金融サービス事業者の従業員に コマンドを貼り付けさせ、未知のマルウェア2種（GeniexLoader・GeniexRAT）を投入した—— CrowdStrike が ClickFix の実例として公表

脅威・攻撃キャンペーン初報のみ有名事象として記録（日本と直接の関係は薄い）
初報: 2026年9月29日 最終更新: 2026年10月4日

CrowdStrike は2026年9月29日に公開したブログで、ClickFix（偽のエラー表示で利用者自身にコマンドを実行させる手口）の実例として2つの国家背景のアクターの作戦を示しました。

ひとつは北朝鮮系の STARDUST CHOLLIMA です。 2026年7月、動画会議サイトを装ったインフラを使って金融サービス事業者の従業員を標的にしたと CrowdStrike は述べています。従業員が会議に参加しようとすると偽の技術的な不具合が表示され、その「修正」としてコマンドが提示されました。 そのコマンドを実行した結果、PowerShell と VBScript による感染の連鎖が動き、それまで知られていなかったマルウェア2種——GeniexLoader と GeniexRAT——が投入されました。

もうひとつはロシア系の VOODOO BEAR です。 2026年5月と6月、CrowdStrike の MDR が、フランス・米国・カナダの組織にいるウクライナ人とみられる従業員に影響する侵入を検知しました。こちらは偽の会議ではなく、ウクライナのウェブサイトを侵害してウクライナからの訪問者に偽の CAPTCHA を出す形でした。地方自治体・エネルギー・農業・物流といった多様な組織のサイトが侵害されたとみられると述べています。

この事案の要点は、攻撃者が「ファイルを開かせる」のをやめたことです。 ClickFix が利用者に求めるのは、ウェブページに書かれたコマンドをコピーして、Windows の「ファイル名を指定して実行」やPowerShell、ターミナルに貼り付けて押すことです。悪性のファイルは介在しません。 CrowdStrike は「悪性のファイルを止めるためだけに作られたセキュリティ製品を回避する」と書いています（原文英語）。

数字がひとつだけ公表されています。 CrowdStrike 2026 Global Threat Report は、2025年に偽の CAPTCHA を使った事案が563%増えたとしています。

一方で、本件は被害の記録ではありません。 侵害された組織の名前・国・人数・持ち出されたものは一切公表されておらず、IoC（通信先・ハッシュ・ドメイン）も示されていません。 このブログは自社製品の説明を主たる目的としており、ベンダー分析として読む必要があります（本記録の評価）。

ClickFix の流れを、CrowdStrike の記述のとおりに並べます。

  1. 攻撃者が問題を作る — 利用者が、偽のエラー・CAPTCHA・システムメッセージを表示するサイトに着く。到達させる手段はフィッシングメールのほか、より狙いを定めた手法もあるとされる
  2. サイトが「解決策」を出す — ページがコマンドのコピーを指示する。変種によっては、悪性の JavaScript がコマンドを直接クリップボードに置く
  3. 利用者が境界を越える — Windows の「ファイル名を指定して実行」、PowerShell、ターミナルなど、信頼された OS の道具に貼り付けさせる
  4. OS が攻撃者の命令を実行する — PowerShell・VBScript などの正規の解釈器が起動し、追加の実行物を取得・実行する

この4段のどこにも、利用者がファイルを開く場面がありません。 CrowdStrike は「By prompting the victim to run the command, the adversary evades security tools solely built to stop malicious files.」（被害者にコマンドを実行させることで、攻撃者は悪性のファイルを止めるためにだけ作られたセキュリティ製品を回避する／原文英語）と書いています。

なぜ効くのかについての CrowdStrike の説明は、技術ではなく日常にあります。会議が開けない、認証を求められる、CAPTCHA が出る、ブラウザがエラーを出す ——これらは企業の従業員が毎日こなしていることです。「ちょっと直してください」という指示は、予期しない実行ファイルや添付よりもずっと疑われにくいとされます。

そして口実は差し替えられます。 長く使う1つのフィッシング用ドメインや1つの定型に依存しません。ドメインを回す、正規のサイトを侵害する、装うブランドを変える、偽の会議エラーを偽の CAPTCHA に取り替える—— 見た目は変わっても、中核の行為（コピーして、貼って、実行させる）は同じままです。

本記録の読み方—— この手口に対しては「あやしいファイルを開かない」という教育が効きません。 ファイルが無いからです。 止めるべき行為は「ウェブページに書かれた文字列を OS の実行欄に貼ること」です（本記録の評価）。

ここから先は本記録の整理です。 CrowdStrike は自社製品による防御を章立てて説明していますが、製品を持たない組織が取れる手も含めて、段階ごとに何が効きうるかを並べます。

① 到達させない段（偵察・誘導）

② 貼り付けを止める段（ここが中核）
- Windows の「ファイル名を指定して実行」（Win+R）をグループポリシーで無効化する—— 業務で使う人は限られます（本記録の評価）

④ 広がりを止める段
- 資格情報の悪用と横展開—— CrowdStrike は「クレデンシャルやトークンが盗まれればID の攻撃になり、SaaS やクラウドへ広がる」と述べています

対応の評価

対応の巧拙を評価できる材料が公表資料から得られていません。
CISO・経営層への示唆
  • **「あやしい添付を開かない」という教育は、この手口に効かない。** ClickFix に悪性のファイルは介在せず、 利用者が自分の手で OS の正規の道具を動かす
    CrowdStrike は **「被害者にコマンドを実行させることで、攻撃者は悪性のファイルを 止めるためにだけ作られたセキュリティ製品を回避する」**と書いている （原文英語）。 **多くの組織の教育と訓練は、添付とリンクを前提に作られている** （本記録の評価）。 **本件で越えられる境界は「ブラウザから OS の実行欄へ文字列を移す」 という行為そのものであり、ファイルを開く場面が存在しない。**
    取るべき行動 **教育の教材に「ウェブページに書かれたコマンドを 『ファイル名を指定して実行』や PowerShell に貼り付けることは絶対にない」 という1行を加え、訓練の題材に入れる。** **あわせて「会議が開けないときに取るべき正しい行動」 （情報システム部門へ連絡する経路）を明記する**—— **禁止だけを伝えると、利用者は目の前の問題を解こうとする**
  • **標的の選び方が「自社の属性」ではないことがある。** VOODOO BEAR の事例では、フランス・米国・カナダの組織が、 従業員がウクライナ人であるという理由で影響を受けた
    **攻撃者はウクライナのウェブサイトを侵害し、 ウクライナからの訪問者に偽の CAPTCHA を出した**（CrowdStrike の記述）。 **その結果、組織の所在国や業種とは無関係に標的が決まっている** （本記録の評価）。 **「自社は狙われる理由が無い」という前提の脅威評価は、 この形を取りこぼす**（本記録の判断）
    取るべき行動 **自社の従業員が業務や私的な関心で日常的に訪れる外部サイトのうち、 自社が守れないものを把握する**（業界団体・官公庁・出身国の報道・ 専門家のブログ・取引先の公開ページ）。 **そのサイトが侵害されて偽の表示を出したときに、 自社の防御が何段目で働くのかを机上で追う。** **多国籍・多国籍人材の職場では、この観点を脅威評価に明記する**
  • **この資料はベンダーの製品説明でもある。** ブログの約半分が自社製品7つの説明に充てられており、 事実の記述と製品の割り当てを分けて読む必要がある
    **IoC（ドメイン・ハッシュ・コマンドの文字列）がひとつも示されていない** （本記録の確認）。 **このため、製品を持たない組織が自社の記録を遡って突き合わせることは できず、使えるのは手口の理解にとどまる**（本記録の評価）。 **ベンダーのブログとしては珍しくないが、 「対策が書いてある」と受け取ると、実際には何も確認できていない状態が残る**
    取るべき行動 **ベンダーのレポートを読んだときに「自社の記録で確認できること」が あるかを必ず問う。** **IoC が無いレポートは「検知の形を作る」ための材料として扱い、 遡及調査の対象にはしない**—— **その区別を社内の報告書式に入れる**
  • **公表された唯一の数値（偽 CAPTCHA の事案が2025年に563%増）は、 ベンダー自身の集計であり分母が公表されていない**
    **CrowdStrike 2026 Global Threat Report の値で、 第三者による検証は無く、2024年の件数も母集団も示されていない** （本記録の確認）。 **また「ClickFix 全体」ではなく「偽 CAPTCHA を使った事案」に 限った値である**——口実には偽の会議エラーもあるため、 **手口全体の増加を表していない**（本記録の読み）
    取るべき行動 **ベンダーの増加率を経営報告に引くときは、 分母・母集団・測定の対象を同じ行に書く。** 書けないなら**「方向（増えている）」としてのみ扱う**と明記する。 **563%のような数字は、根拠を添えずに資料に載ると 次の予算要求の前提として独り歩きする**（本記録の評価）
セキュリティ技術者への示唆
  • **検知の形は「ブラウザの子プロセスとしての解釈器」と 「explorer.exe を親とする PowerShell」である。** CrowdStrike はこの具体を書いていない
    **ClickFix の実行は、ブラウザで見た文字列を Win+R や PowerShell へ 移すことで起きる**（CrowdStrike の記述）。 **親子関係に痕跡が出る**—— ブラウザから直接起動すれば chrome.exe / msedge.exe の子として、 **Win+R 経由なら explorer.exe の子として powershell.exe が現れる** （本記録の整理）。 **CrowdStrike の記述は「suspicious PowerShell, VBScript, process, command-line」という抽象にとどまる**
    取るべき行動 **次の2つの検知を作る**—— **①ブラウザ（chrome.exe・msedge.exe・firefox.exe）の子プロセスとして powershell.exe / wscript.exe / cscript.exe / mshta.exe が起動したこと、 ②explorer.exe を親とする powershell.exe の起動で、 コマンドラインに外部への到達を含むもの。** **②は正規の利用もあるため、まず可視化から始めて量を測る**
  • **RunMRU レジストリキーには、貼り付けられた文字列そのものが残る。** 調査の材料として最も直接的である
    **Windows の「ファイル名を指定して実行」の履歴は `HKCU\\Software\\Microsoft\\Windows\\CurrentVersion\\Explorer\\RunMRU` に残る**（本記録の整理）。 **ClickFix の中核が「Run ダイアログへの貼り付け」である以上、 ここに攻撃者のコマンドが文字列として残る。** **CrowdStrike はこの点に言及していない**
    取るべき行動 **端末から RunMRU の内容を収集する仕組みを用意する** （EDR の収集項目、またはログオン時の収集スクリプト）。 **ClickFix が疑われる端末では、ここを最初に見る。** **併せて PowerShell のスクリプトブロックログ（イベント ID 4104）を 有効にしておく**——**貼り付けられたコマンドが難読化されていても、 展開後の内容が残る**
  • **封じ込めは端末の隔離で終わらない。** 資格情報とセッショントークンの入れ替えまでが1つの手順である
    CrowdStrike は**「クレデンシャルやトークンが盗まれれば ID の攻撃になり、 その資格情報で SaaS・クラウド・他の系統へ侵入が広がる」**と述べている （原文英語）。 **実際に窃取されたかは本件では公表されていない**が、 **GeniexRAT のような遠隔操作の道具が入った時点で、 端末上の資格情報は失われたものとして扱うのが妥当である** （本記録の評価）
    取るべき行動 **ClickFix を踏んだ端末が見つかったときの手順に、 ①端末の隔離、②その利用者のパスワード変更、 ③セッショントークンの一括失効（SaaS・クラウド・VPN すべて）、 ④ブラウザに保存された資格情報の洗い出し、を並べて書く。** **③を忘れると、パスワードを変えても既存のセッションで入り続けられる**
  • **Win+R（「ファイル名を指定して実行」）を業務で必要とする利用者は限られる。** 無効化は、この手口の中核を直接断つ
    **ClickFix の4段のうち、3段目「信頼された OS の道具に貼り付ける」が 成立しなければ、4段目の実行は起きない**（本記録の整理）。 **Run ダイアログはグループポリシーで無効化できる** （`NoRun`）。 **PowerShell の対話実行も、一般利用者には不要なことが多い** （本記録の評価）
    取るべき行動 **一般利用者の端末で Win+R を無効化し、 PowerShell の対話実行を AppLocker / WDAC または制約言語モードで制限する。** **まず「誰が実際に使っているか」を1か月測ってから適用範囲を決める**—— **測らずに全面適用すると、運用部門の業務が止まる**
  • **侵害された正規サイトが入口になるため、ドメインの評判では止まらない。** VOODOO BEAR の事例がそれを示している
    **侵害されたのはウクライナの地方自治体・エネルギー・農業・物流などの 正規のサイトである**（CrowdStrike の記述。「likely compromised」）。 **これらは評判のよいドメインであり、遮断の対象にならない** （本記録の評価）。 **一方、STARDUST CHOLLIMA が使った「装われた動画会議サイト」は 新規のインフラであり、別の手が効く**
    取るべき行動 **ドメインの評判に依存しない段を1つ持つ**—— **ブラウザ側の統制、または実行段での検知（上記①②）。** **あわせて、新しく登録されたドメインへの到達を遅らせる仕組みは、 装われたインフラの側に効くため併用する**
