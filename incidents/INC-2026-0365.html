INC-2026-0365露医療機関にCyber Partisans2年潜伏

ロシアの医療機関（名称非公表）のネットワークに、ベラルーシのハクティビスト集団 Cyber Partisans（ベンダー名 Partisan Zmiy）が2024年初頭から約2年間潜伏していた——2025年12月に系列の医療機関から発した不正活動として検知され、Telegram を C2 に使うバックドア Vasilek・DNS トンネリング・VMware Tools や WSUS を騙る常駐で機微な医療データへ到達し、ドメインコントローラまで押さえていたが破壊行為は行われなかった。報告はロシア国営系ベンダー Solar によるもので、被害組織名・初期侵入経路は公表されていない

不正アクセス・侵害脅威・攻撃キャンペーン初報のみ有名事象として記録（日本と直接の関係は薄い）公表されていない／不明
初報: 2026年10月5日 最終更新: 2026年10月6日

ロシアのサイバーセキュリティ企業 Solar（国営 Rostelecom 傘下）の調査部門 Solar 4RAYS は2026年10月2日、ロシアの医療機関（名称非公表）のネットワークに、ベラルーシのハクティビスト集団Cyber Partisans（同社の呼称 Partisan Zmiy）が2024年初頭から約2年間潜伏していたと公表しました。発見は 2025年12月で、きっかけは系列の医療機関から発した不正な活動でした。

報告によれば、攻撃者は Telegram の Bot API を C2 に使うバックドア Vasilek（v1.5.8）、DNS トンネリング（DNSCat2・PartisanDNS）、プロキシ（GOST・3proxy）を併用し、VMware Tools や WSUS の部品を騙る Windows サービスと正規 vmtools.dll の DLL ハイジャックで常駐していました。さらに毎週土曜22時〜23時といった業務時間外のスケジュールでペイロードを動かす自作のローダーを使っていました。ドメインコントローラへのアクセスも得ており、機微な医療データへ到達していました。

それでも破壊・妨害は行われていません。研究者は「破壊行為が無かったのは、さらなる諜報活動と信頼関係を悪用した攻撃のために、このアクセスを保ち続ける価値があったためだと考える」（原文ロシア語）としています。標的となった組織は多数の医療機関と双方向の信頼関係を持つ広い基盤を運用しており、そこを足場に他組織へ届く余地があったと指摘されています。

本記録は、破壊を伴わない侵入は長く気づかれないこと、そして系列・連携先との相互信頼がそのまま攻撃経路になることの実例として整理します。日本の医療も地域連携・系列間のデータ共有を広げており、同じ構造を持ちます。一方で本件は、被害組織が非公表であり、帰属はロシア国営系ベンダー1社の判断で、攻撃者側の主張も無いという情報の限界があります。その点は分けて記録します。

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

    Solar 4RAYS の報告に基づく事実は次のとおりである。

    • 標的はロシアの医療機関（名称非公表）。多数の医療機関と双方向の信頼関係を持つ広い基盤を運用していた
    • 最も古い痕跡は2024年初頭。発見は2025年12月で、約2年にわたり侵入が続いていた
    • 発見の端緒は、系列の医療機関から発した不正な活動をスキャンで検知したことだった
    • 攻撃者は機微な医療データへアクセスし、ドメインコントローラへのアクセスも得ていた

    • 研究者の評価は「破壊行為が無かったのは、さらなる諜報活動と信頼関係を悪用した攻撃のために、このアクセスを保ち続ける価値があったためだと考える」（原文ロシア語）

    ここで言う「信頼関係を悪用した攻撃」とは、まず相手が既に信頼している組織を侵害し、その接続を使って本来の標的へ入る型の攻撃である。報告は、この組織が多数の医療機関とつながっていたことが、攻撃者にとっての価値だったと見ている。

    常駐の作り方が「正規の部品に見えること」に寄っている——VMware Tools・WSUS を騙り、土曜深夜に動かす原因・手口出典 [1] [2]

    報告が示した手口は次のとおりである（技術者向け）。

    • 永続化: VMware Tools や WSUS の部品を騙る Windows サービスを登録。さらに正規の vmtools.dll を DLL ハイジャックして読み込ませる
    • スケジュール実行: 自作のローダーが cron 風のスケジュールでペイロードを起動する。報告には「毎週土曜22時〜23時」のような業務時間外の設定例が挙げられている
    • 実行・横移動: Impacket の wmiexec.py による WMI 経由のコマンド実行。出力が \\127.0.0.1\ADMIN$\__<UNIX時刻>.<マイクロ秒> へリダイレクトされる痕跡が残る
    • C2: バックドア Vasilek（v1.5.8）。Telegram の Bot API を通じて指令と窃取データをやり取りする。端末情報の収集・Windows コマンドの実行・プロセスの起動と終了・ファイル転送・画面取得・キー入力の記録・自己更新と自己削除ができる
    • 通信の隠蔽: DNSCat2・PartisanDNS による DNS トンネリング、GOST・3proxy によるプロキシ連鎖
    • 権限: ドメインコントローラへのアクセスを得ていた

    この組み合わせは、どれも単体では珍しくないが、そろうと「正常な運用に見える」。サービス名は仮想化基盤と更新管理の部品、読み込まれる DLL は正規ファイル名、通信先は Telegram と DNS、動く時刻は人がいない土曜深夜である。破壊を伴わない侵入が2年続いたという結果は、この設計の帰結として読める（本記録の評価）。

    なお Solar は、ロシア国内での Telegram の制限により Vasilek の C2 通信の信頼性が下がっていたと述べつつ、攻撃者は他の通信手段へ切り替えられるとも指摘している。

    日本の医療連携も「相互に信頼し合う基盤」で成り立っている（本記録の評価）評価・解釈出典 [1] [2]

    この事案から日本の読者が取り出せる論点は3つある。

    1. 破壊が無い侵入は、検知の設計をしていない組織には存在しないのと同じである。本件は暗号化もサービス停止も起きていない。利用者からの苦情も業務の異常も出ない。ランサムウェアを前提に組んだ検知・訓練は、この型にまったく当たらない。気づいたのは被害組織自身ではなく、系列の医療機関で観測された不正活動だった。

    2. 系列・連携先との相互信頼が、そのまま攻撃経路になる。 日本でも地域医療連携ネットワーク、系列病院間の電子カルテ参照、検査・レセプト業務の共通基盤、運用の一括委託が広がっている。「どこを信頼しているか」の一覧を持っていない組織は、侵害の広がりを見積もれない。本件の攻撃者はドメインコントローラを押さえており、信頼の経路を使う条件を満たしていた。

    3. C2 の見え方が変わっている。 Telegram の Bot API と DNS トンネリングは、いずれも業務で使われる通信に紛れる。「不審な宛先への接続」を見る発想では当たらない。見るべきは宛先ではなく、その端末がその通信をする理由があるかである。

    一方で、本件を日本への脅威として扱うことはしない。標的はロシアの医療機関であり、攻撃者の動機はロシア・ベラルーシの体制に向いている。手口の型は普遍的だが、標的の選び方は本件の文脈に固有である（本記録の評価）。

    対応の評価

    評価材料がない判断は「評価材料なし」としています。結果論で断じないための区分です。
    対応の巧拙を評価できる材料が公表資料から得られていません。
    CISO・経営層への示唆
    • 「業務に異常が出ていないこと」を安全の根拠から外す
      本件は約2年のあいだ暗号化も停止も起きていない。苦情も障害も出ないため、 業務影響を起点にした検知・訓練ではまったく当たらなかった
      取るべき行動 インシデント検知の指標に「業務影響に依存しない項目」（新規サービス登録・特権使用・ 外向き通信の宛先変化・夜間の端末活動）を明示的に入れる。 机上訓練の題材に**破壊を伴わない長期侵入**を1本加える
    • 「どこを信頼しているか」の一覧を作り、信頼の方向と範囲を書き出す
      標的は多数の医療機関と双方向の信頼関係を持つ基盤を運用しており、 研究者はこの信頼関係を悪用した攻撃の価値を攻撃者の動機として挙げている
      取るべき行動 AD の信頼関係、相互 VPN、共有アカウント、委託運用の管理経路、相互参照する業務システムを 一覧化し、**各信頼が「相手が侵害された場合に自組織のどこまで届くか」を1行で書く**。 書けない信頼は、設計を見直す対象として扱う
    • ハクティビストを「破壊するだけの相手」として分類しない
      Cyber Partisans は破壊的攻撃で知られる集団だが、本件では約2年の諜報を選び、 破壊を控えてアクセスを維持したと評価されている
      取るべき行動 脅威シナリオの一覧で、動機（抗議・諜報・金銭）と手口（破壊・潜伏）を独立の軸として扱う。 **「この集団は壊すタイプだから長期潜伏は想定外」という前提を文書から外す**
    • ベンダー報告を根拠にするときは、帰属の確度と報告主体の立場を添えて社内に流す
      本件の帰属はロシア国営 Rostelecom 傘下のベンダー1社の判断で、攻撃者側の主張も 第三者の裏付けも無い。ロシアは同集団を法的に「極端主義組織」と指定している
      取るべき行動 脅威情報の社内共有の様式に「出所」「確度」「裏付けの有無」の欄を設ける。 技術的な手口（検知に使える部分）と、帰属・動機の解釈を**同じ確度で扱わない**
    セキュリティ技術者への示唆
    • 正規の運用部品に似せた常駐を、名前ではなく配置と署名で検証する
      攻撃者は VMware Tools・WSUS の部品を騙る Windows サービスを登録し、 正規 vmtools.dll を DLL ハイジャックして読み込ませていた
      取るべき行動 サービスの新規登録・変更イベントを収集し、**実行ファイルの配置先・署名・親プロセス**を 突き合わせる規則を作る。既知製品と同名のサービスが想定外のパスを指していれば警報にする。 正規 DLL と同名ファイルの読み込み元も監視対象に入れる
    • 外部メッセージング API と DNS を C2 として監視対象に入れる
      Vasilek は Telegram の Bot API を C2 に使い、DNSCat2・PartisanDNS で DNS トンネリングも 併用していた。いずれも業務通信に紛れる
      取るべき行動 サーバと業務端末から Telegram 等のメッセージング API への直接通信を既定拒否にし、 例外を申請制にする。DNS はクエリ数・名前の長さ・サブドメインの多様性を指標に監視する。 **宛先の良悪ではなく「その端末がその通信をする理由」で判定する**
    • 横移動の痕跡として wmiexec の特徴的な出力先を検知規則に落とす
      報告は `\\127.0.0.1\ADMIN$\__<UNIX時刻>.<マイクロ秒>` という Impacket wmiexec.py 特有の出力リダイレクト先を痕跡として挙げている
      取るべき行動 管理共有（ADMIN$）への書き込みと WMI によるプロセス生成を収集し、 管理端末以外を発信元とするものを警報にする。**既知ツールの固有の痕跡は規則化が容易**で、 費用対効果が高い
    • 夜間・週末のアクティビティを基準線として持つ
      自作ローダーは「毎週土曜22時〜23時」のような業務時間外のスケジュールでペイロードを起動していた
      取るべき行動 端末・サーバごとに平常時の時間帯別アクティビティを基準線として記録し、 **人がいない時間の実行を優先度の高い警報**として扱う。警報が当番へ届く経路も同時に整える
    • 抽出された指標は検知に使う前に自組織での有効性を確かめる
      報告の指標は調査対象の環境で観測されたもので、本記録はその悪性を検証していない
      取るべき行動 ベンダー報告の指標は、まず過去ログへの遡及検索（ハンティング）に使い、 **遮断規則へ直接入れない**。自組織のテレメトリで誤検知の量を測ってから運用に載せる

    自組織に当てはまるか

    該当する項目があれば、この事案と同じ構図が自組織でも成立しうることを意味します。
    観点自社に当てはまるか該当する場合に何が起きうるか
    システム構成□ 系列組織・連携先と双方向の信頼関係（AD 信頼・相互 VPN・相互参照する業務システム）がある本件の攻撃者は、この信頼関係を悪用する価値のためにアクセスを維持したと評価されている
    運用・監視□ 侵害の検知が業務影響（障害・暗号化・苦情）を起点にしている本件は破壊が無く、約2年にわたり業務からは何も見えなかった
    運用・監視□ 夜間・週末のサーバ/端末アクティビティに基準線が無く、警報の24時間到達経路も無いペイロードの起動は毎週土曜22時台など業務時間外に寄せられていた
    システム構成□ サーバや業務端末から外部メッセージング API・外向き DNS が自由に出られるC2 は Telegram Bot API と DNS トンネリングで、宛先の良悪では判別できない
    認証・認可□ ドメインコントローラへの管理アクセスが一般端末から到達可能である攻撃者はドメインコントローラへのアクセスを得ていた
    体制・契約□ 脅威情報を社内へ流すときに、出所・確度・裏付けの有無を記録していない本件の帰属は報告主体1社の判断で、攻撃者側の主張も第三者の裏付けも無い
