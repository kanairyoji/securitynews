INC-2026-0378ASOS のアプリから恐喝の通知

英オンライン衣料小売 ASOS の公式アプリから2026年10月6日午前、顧客に「ASOS HACKED」と題するプッシュ通知が送られ、「Snowflake インスタンスを完全に侵害した。交渉しなければ流出させる」という恐喝文と Telegram チャンネルへのリンクが表示された——攻撃者は自らを Xuanye Group と名乗ったが Snowflake 侵害の証拠を示していない。ASOS は顧客への連絡に用いる第三者プラットフォームでの不正な活動を調査中とし、氏名と連絡先が参照された可能性を認めたうえで決済カード情報とパスワードへの影響は考えていないとした。ロンドン証券取引所の株価は一時12%近く下落し、英 NCSC が顧客向けの注意喚起を出した

初報: 2026年10月6日 最終更新: 2026年10月6日

ASOS（英オンライン衣料小売・ロンドン証券取引所上場）の公式アプリから2026年10月6日午前（英国時間10時ごろ）、顧客に「ASOS HACKED」と題するプッシュ通知が送られました。本文は次のとおりです（原文英語）。

「ASOS の DPO（データ保護責任者）および IT 部門へ。我々は Snowflake インスタンスを完全に侵害した。我々と交渉せよ。さもなければ流出させる」

通知には Telegram チャンネルへのリンクが添えられており、チャンネルは自らを Xuanye Group と称していました。この名称は、恐喝グループを追跡する専門家にとってそれまで確認されていない新しい名前です。

本記録が中心と見るのは恐喝の経路そのものです。恐喝グループは通常、被害組織に非公開で接触してから、応じない場合に自らのリークサイトや Telegram で公表します。本件は順序が逆で、被害組織の顧客向け通知基盤を乗っ取り、顧客の端末に直接恐喝文を表示させました。 Check Point の Charlotte Wilson 氏はこれを「ASOS 自身のアプリを身代金要求書に変えた」と評しています（原文英語）。

影響は株価に即座に出ました。ロンドン証券取引所の ASOS 株は一時12%近く下落しました。通知が送られたのは午前10時ごろで、ASOS が規制上の声明を出したのは同日午後遅くです。会社が何が起きたかを公表する前に、投資家が結果を織り込み始めていたという順序になります。

ASOS は、顧客との連絡に用いる第三者プラットフォームに関わる不正な活動を調査中とし、氏名と連絡先を含む基本的な個人情報が参照された可能性を認めました。一方で決済カード情報とアカウントのパスワードへの影響は考えていないとしています。当該通知プラットフォームへのアクセスは制限し、専門のアドバイザーと関係当局と連携しているとのことです。ウェブサイトとアプリは正常に稼働しており、業績への影響を数値化するのは時期が早すぎるとしています。

英 NCSC は同日、顧客向けの注意喚起を公表し、「ASOS の顧客であれば、不正な通知を受け取っていなくても自分が影響を受けたと想定すべき」としました。

Xuanye Group は Snowflake 侵害の証拠を一切示しておらず、Telegram チャンネルには顧客データの標本も置かれていません。後の投稿では「決済情報は影響を受けていない」「当該企業のアプリは安全に利用できる」「顧客情報は所定の期間は公開しない」と述べていますが、いずれも裏付けがありません。本記録は、攻撃者の主張と ASOS が確認した事実を厳密に分けて記録します。評価・示唆は本記録の判断として分けて書きます。

通知には Telegram チャンネルへのリンクが添えられていた。SNS で共有されたスクリーンショットでこの文面が広まった。報道によれば数千人の顧客が受け取った。

恐喝グループの通常の手順は、被害組織に非公開で接触し、応じない場合にリークサイトや Telegram で公表することである。本件はその順序を飛ばしている。Check Point の Charlotte Wilson 氏は「確認されれば、攻撃者はきわめて大胆なことをしたことになる——ASOS 自身のアプリを身代金要求書に変えた」と述べた（原文英語）。

確実に言えるのは、攻撃者が ASOS の顧客向け通知基盤に対して「任意の文面を全顧客に配信する」権限を持っていたことである。ASOS がこのプラットフォームへのアクセスを制限したことからも、その経路が実在したことは裏付けられる。侵害の態様——プラットフォームのアカウントが乗っ取られたのか、プラットフォーム自体に不備があったのか、ASOS 側の資格情報が漏れたのか——は公表されていない。

ここからは本記録の作成者の評価である。

第一に、顧客向け通知基盤は、侵害されたときの被害が「データの流出」ではなく「発言権の奪取」になる。会員データベースが侵害されれば失われるのは情報だが、プッシュ通知基盤が侵害されれば失われるのは自社の名前で語る権利である。顧客の端末に表示される「ASOS」というアプリ名とアイコンは、メッセージの内容を検証せずに信じる理由として機能する。本件で攻撃者が得たのは ASOS のデータではなく（それは主張にとどまる）、ASOS の声だった。Check Point の評に倣えば、アプリそのものが身代金要求書になった。

第二に、証拠のない主張でも株価は動く。 Xuanye Group は Snowflake 侵害の証拠を一切示していない。標本も無い。それでも株価は一時12%近く下落し、下落は ASOS の声明より前に始まった。ここから読めるのは、市場が反応しているのは侵害の事実ではなく「侵害された可能性の可視性」であるということだ。顧客の端末に恐喝文が表示され、スクリーンショットが SNS に並んだ時点で、真偽の確認を待たずに評価が織り込まれる。恐喝の有効性が、データの価値ではなく「どれだけ多くの人に見せられるか」で決まる構造になっている。

第三に、「第三者プラットフォームでの不正な活動」という説明の粒度が、同業他社の防御を妨げている。顧客への通知配信は、小売業では外部のサービスに委ねるのが一般的である。どのサービスだったかが示されなければ、同じサービスを使っている事業者は自社が同じ状態にあるかを確認できない。 ASOS にとっては調査中の情報を出さない判断に理由があるが、その結果として、同じ経路が他社でも開いたままになる。この非対称は、委託先経由の侵害が公表されるたびに繰り返されている。

第四に、本件で ASOS が「決済カード情報とパスワードは影響を受けていないと考えている」と早期に明示したことは、顧客の行動を正しい方向に向けた。 恐喝文は「完全に侵害した」と全面的な被害を主張しており、放置すれば顧客は決済情報の停止やパスワード変更に殺到する。範囲を区切る一文が、顧客の過剰反応と、便乗するフィッシングの余地を同時に狭める。 NCSC がこの一文を引き継いだうえで「それでもパスキーか強固なパスワードと2段階認証を使え」と重ねたのは、「今回は影響なし」と「そもそも備えよ」を混ぜずに伝える形として参考になる。

第五に、ASOS は2026年7月にも顧客アカウントへの不正アクセス（ASOS 外部から入手した認証情報による）を公表している。報道によれば約13万8,828人が対象だった。本件との関係は ASOS も報道も述べておらず、本記録は別事案として扱う。ただし同一の小売事業者で3か月以内に2件の顧客データ関連事案が公表されたという事実は、攻撃者が ASOS を継続的な標的として見ている可能性を示す（本記録の推測であり、裏付けは無い）。

    取るべき行動 恐喝の主張を受けたときに**24時間以内に真偽を判定して声明に書ける体制**を作る。 具体的には、顧客データを持つ主要な基盤（データウェアハウス・CRM・会員DB）ごとに **認証ログ・クエリ履歴・外部書き出しの記録を誰がどこから即日照会できるかを事前に特定し、 インシデント対応手順に照会先として書き込む。** **否定を裏付ける記録が無ければ、証拠のない主張にも反論できない**
  • 公表では「影響していない範囲」を明示し、当局の助言と役割を分ける
    ASOS は「決済カード情報とアカウントのパスワードへの影響は考えていない」と範囲を区切り、 NCSC はそれを引き継いだうえで「それでもパスキーか強固なパスワードと2段階認証を使え」と重ねた
    取るべき行動 インシデント公表のひな型に「**影響した範囲／影響していないと判断した範囲／その判断の根拠／未確定の範囲**」の4区分を置く。 「影響していない」と述べるときは**何を確認してそう言えるのかを併記する** （本件は根拠が示されておらず、後に覆れば訂正の負担を負う）。 顧客への一般的な防御策の助言は当局の案内を参照する形にし、**自社の公表は事実の範囲に集中させる**
  • 同一の攻撃対象として繰り返し狙われる前提で、過去の事案との連続性を自ら点検する
    ASOS は2026年7月28日にも顧客アカウントへの不正アクセス（ASOS 外部から入手した認証情報による）を検知し、 8月21日付で通知を行っていた（約13万8,828人が対象と報じられた）。 **本件との関係は公表されていないが、3か月以内に2件の顧客データ関連事案が公表された**
    取るべき行動 **過去12か月のインシデント・不正アクセスの試行を一覧にし、標的となった資産・経路・攻撃者の特徴の重なりを点検する。** 重なりがあれば、前の事案で得た情報（窃取された認証情報・顧客リスト）が次の事案に使われていないかを調べる。 **個別対応で閉じると、同じ組織が繰り返し狙われていることに気づけない**
セキュリティ技術者への示唆
  • 通知配信プラットフォームの管理アカウントと API 資格情報を棚卸しし、多要素認証と到達元の制限を適用する
    侵害の態様は公表されていないが、ASOS は「顧客との連絡に用いる第三者プラットフォームに関わる不正な活動」を 調査対象とし、当該プラットフォームへのアクセスを制限した
    取るべき行動 配信基盤（プッシュ通知・メール・SMS）について、 **①管理者アカウントの一覧と多要素認証の適用状況、②発行済み API キー・サービスアカウントの一覧と有効期限、 ③管理コンソールへ到達できる接続元の範囲**の3点を確認する。 **配信基盤は「どこからでも使える」必要がないため、接続元 IP と管理端末で限定する**
  • 通知配信の件数・時刻・内容を監視し、配信カレンダーに無い大量配信を即時に通知する
    数千人への恐喝通知が配信され、ASOS が把握したのは配信後と読める（公表の順序からの推定）。 検知が数分早ければ、SNS での拡散と株価の反応の前に声明を出せた可能性がある
    取るべき行動 配信基盤の送信ログを監視基盤へ取り込み、 **「販促の配信予定に無い時刻の、しきい値を超える配信」をアラートにする。** 販促の一斉配信は定期的に行われるため、**配信そのものではなく「予定外であること」を異常の定義にする**
  • 配信基盤の権限を「文面の作成」と「配信の実行」に分離する
    攻撃者は任意の文面を作り、かつ数千人への配信を実行できた
    取るべき行動 配信プラットフォームのロール設定を見直し、 **テンプレートの編集権限と配信の実行権限を別のロールに分け、同一アカウントに両方を付与しない。** 自動配信（注文・配送の通知）は固定テンプレートのみを使う専用の資格情報で行い、 **任意の文面を送れる資格情報と分ける**
  • クラウドデータ基盤のテナントで、多要素認証とネットワークポリシーが全アカウントに適用されているか確認する
    攻撃者は「Snowflake インスタンスを完全に侵害した」と主張した。 本件での侵害は確認されていないが、 **2024年に Snowflake の顧客テナントが多要素認証のない窃取済み認証情報で侵害される事案が多数発生した経緯があり、 この名前だけで重大さが伝わる土台ができている**
    取るべき行動 自組織のデータウェアハウス（Snowflake・BigQuery・Redshift 等）で、 **①多要素認証が全ユーザーに強制されているか、②サービスアカウント・連携用ユーザーに ネットワークポリシー（接続元の制限）が適用されているか、③外部ストレージへの書き出し（アンロード）が 記録・制限されているか**を確認する。**「人のアカウントだけ多要素認証」では面が残る**
  • 恐喝の主張を受けた直後に照会するログの一覧を、インシデント対応手順に書いておく
    攻撃者は証拠のない主張で株価を12%近く動かし、ASOS の声明より前に市場が反応した。 主張を否定するには、否定を裏付ける記録が要る
    取るべき行動 主要なデータ基盤ごとに**「誰が・どのコンソール・どのクエリで、認証ログ／クエリ履歴／外部書き出しの記録を何分で出せるか」**を 実際に試して所要時間を測り、手順書に書く。 **ログの保持期間が主張の対象期間に足りているかも併せて確認する** （保持90日の基盤に対して「半年前から侵害していた」と主張されれば否定できない）
