INC-2026-0397Trump Mobile 顧客3,615人分が公開

Trump Mobile の顧客3,615人分の氏名・メールアドレス・電話番号・住所・注文情報がランサムウェア群 BYOD のリークサイトで公開された——BYOD は「MVNO の Liberty Mobile 従業員を情報窃取型マルウェアに感染させ、そこから Trump Mobile へ到達した」「どちらも多要素認証を使っていない」と主張しているが、両社は取材に応じておらず公表もしていない

不正アクセス・侵害委託先・再委託先起因で委託元多数に波及初報のみ有名事象として記録（日本と直接の関係は薄い）委託先・供給元起因認証情報の悪用（使い回し・推測可能・窃取）公表されていない／不明
初報: 2026年10月6日 最終更新: 2026年10月7日

ランサムウェア・アズ・ア・サービスを名乗る新興の群 BYOD が、トランプ氏のブランドを冠した携帯通信事業 Trump Mobile に侵入したと主張し、自身のリークサイトで3,615人分の顧客データを公開した。公開されたとされる項目は氏名・メールアドレス・電話番号・自宅住所・注文情報、および通信契約に関する情報である。Trump Mobile は BYOD のリークサイトに掲載された3番目の組織にあたる。

BYOD の主張によれば、侵入の経路は次のとおりである。

  • Liberty Mobile（フロリダ州の MVNO。Trump Mobile に回線を提供している）の従業員を情報窃取型マルウェアに感染させた
  • そこから MVNO 経由で Trump Mobile へ到達した
  • 両社とも多要素認証を一切使っていなかった
  • 現在も Trump Mobile のシステムへのアクセスを保持している
  • 侵害を Trump Mobile に伝えたところ「対応できるチームがいない」「我々をハックする者は誰であれテロリストだ」と返された（原文英語）

これらはいずれも攻撃者側の主張である。 Trump Organization と Liberty Mobile はThe Register の問い合わせに応じていない。本記録の作成者が2026年10月7日に両社のサイトを確認したところ、Liberty Mobile のサイトには本件に関する告知が無く、Trump Mobile のサイトは HTTP 403 で取得できなかった。公開データにはトランプ大統領とその家族の情報は含まれていない一方、Trump Organization のIT・情報セキュリティ全般を統括する副社長兼 CIO Eric Brunnett の個人情報が含まれているとされる。

本記録がこの事案を記録する理由は、規模ではない。3,615人は小さい。記録に値するのは構造である。

  1. ブランドだけを提供する事業体は、守る実体を持たない。 Trump Mobile は自前の通信網を持たず、MVNO に依拠している。顧客データの保管も運用も委ねた先にあり、ブランド側に「対応できるチーム」が無いという主張が成立しうる
  2. MVNO は多数のブランドの顧客データを1か所に集める。 1社の従業員端末が情報窃取型マルウェアに感染すれば、その先に並ぶブランドの顧客が一斉に射程に入る
  3. 同じ侵害が別の群から二度売られた。 BYOD の掲載の約1週間前にEndZone という別の群も Trump Mobile の侵害を主張してデータを公開しており、セキュリティ研究者 Dominic Alvieri は「同一の元の侵害とみられる」としている
  4. 2026年5月には研究者が Web サイトの脆弱性を指摘していた。 単純な POST 要求で顧客情報が取得できたとされ、当時修正された。同じ対象に対する3度目の指摘である

ブランドだけを提供する事業体は、守る実体を持たない——顧客データは委ねた先にある評価・解釈出典 [1] [2]

Trump Mobile は自前の通信網を持たない。MVNO である Liberty Mobile に回線を依拠している。BYOD の主張する経路が正しければ、侵害の起点は Trump Mobile ではなく MVNO 側であり、Trump Mobile 自身のシステムはその先にある到達点だった。

本記録は、この形の事業体に共通する弱さを3点挙げる。

1. 対応する能力が、事業の構造上どこにも無い。 BYOD が主張する「対応できるチームがいない」という返答は、裏付けが無い。だがこの返答が成立しうる構造は実在する。ブランドのライセンスと販売だけを担い、回線・課金・顧客データの保管を外部に委ねた事業体には、侵害の報告を受けて調査を始める主体が置かれていないことがある。連絡を受ける窓口が無ければ、攻撃者からの通報も研究者からの指摘も届かない。

2. 侵害の範囲を自分で測れない。顧客データが MVNO 側の基盤にあるなら、何が持ち出されたかを調べるログはブランド側に無い。公表するかどうかを判断する材料も、本人通知の対象を定める材料も、委託先の申告に依存する。本件で当事者の公表が無いのは、出せない（分からない）のか、出さない（方針）のかが区別できない状態である。

3. MVNO は複数ブランドの顧客を1か所に集める。 MVNO の事業は、複数のブランドに回線と裏側の仕組みを提供することで成り立つ。つまり1社の従業員端末の感染が、その先に並ぶ全ブランドの顧客を射程に入れる。Liberty Mobile が Trump Mobile 以外にどのブランドへ回線を提供しているか、そのブランドの顧客が対象になったかは公表されていない。

日本の読者にとっての当てはめは、通信事業に限らない。自社ブランドで提供しているが、基盤・課金・顧客管理を外部に委ねているサービスはすべて同じ形である。EC のモール出店、OEM の家電、提携カード、ホワイトラベルの SaaS。ブランドを出している側が、侵害時に調査も通知も公表もできない構造になっていないかを点検する対象になる。

同じ侵害が2つの群から二度公開された——リークサイトの掲載は「新しい侵害」を意味しない帰属出典 [1]

The Register は、BYOD の掲載の約1週間前に EndZone という別の群もTrump Mobile の侵害を主張してデータを公開していたと伝えている。セキュリティ研究者 Dominic Alvieri は、これが「同一の元の侵害とみられる」としている。

本記録は、この点をリークサイトを材料に使うときの注意として記録する。

  • 1つの侵害が複数の群のサイトに現れる。 侵害を行った者と、データを公開する者が同一である必要は無い。データは売られ、転売され、別の群の「実績」として掲載される
  • 掲載の数は被害の数ではない。 2つの群が掲載していても、起きた侵害は1件である可能性がある。逆に、同一データの再掲載を別件と数えれば、統計は膨らむ
  • 時期の新しさが、侵害の新しさを意味しない。 本件の BYOD の掲載は2026年10月だが、データがいつ取られたかは分からない。2026年5月には同じ対象の Web サイトに顧客情報が取得できる脆弱性があったと指摘されている
  • 新興の群は実績を作るために掲載する。 BYOD はランサムウェア・アズ・ア・サービスを名乗る新興の群で、Trump Mobile は3番目の掲載である。知名度のある対象を掲載することが、それ自体で宣伝になる

本記録の評価として、リークサイトの掲載を1件の事案として数える前に、データの重複と出所の確認が必要である。本件では両者のデータの同一性も重複の度合いも検証されていないため、本記録は EndZone の公開を独立した事案として立てず、本記録の時系列の中に置いた。

  • 自社ブランドで提供し基盤を外部に委ねるサービスでは、侵害時に「誰が調査し、誰が公表し、誰が通知するか」を事前に決める

    取るべき行動 ホワイトラベル・OEM・提携サービスの契約を洗い出し、各案件について 〈顧客データの保管場所〉〈ログの保有者〉〈公表の主体〉〈本人通知の主体〉 〈侵害時の通報期限〉を1枚の表に書く。空欄がある案件は契約の改定対象にする。 **「どちらも動かない」状態が最悪の結果である**

    BYOD は「侵害を伝えたが対応できるチームがいないと返された」と主張している （真偽は確認できない）。本件では2026年5月にも研究者が Web サイトの脆弱性を指摘している

    公開されたデータの一部が実在することは報道機関が確認している。 対象とされた3,615人には現実の危険があるが、当事者の公表が無いため 自分が含まれるかを確かめる手段がリークサイトと報道しかない
    取るべき行動 漏えいが主張された段階の公表方針を事前に作る。最低限 〈主張を把握していること〉〈確認を進めていること〉 〈顧客が今取るべき行動〉を出せる雛形を用意する。 攻撃者の主張の真偽に踏み込まなくても、この3点は出せる

    本件では BYOD の掲載の約1週間前に別の群 EndZone も同一とみられる侵害で データを公開していた。1つの侵害が複数の群のサイトに現れる

    取るべき行動 自社が「名前で注目される対象」であるかを評価に含める。 該当するなら、小規模な漏えいでも報道対応と顧客説明の準備を 規模相応ではなく注目度相応に用意する
セキュリティ技術者への示唆
  • 情報窃取型マルウェア対策を「認証情報」だけでなく「セッション Cookie」まで広げる
    攻撃者は MVNO の従業員を情報窃取型マルウェアに感染させたと主張している。 この種のマルウェアはブラウザの保存資格情報とセッション Cookie を まとめて持ち出すため、多要素認証を越えられることがある
    取るべき行動 業務システムのセッションを端末に紐づけ（device-bound session）、 別の端末・別のネットワークからの Cookie の再利用を拒否する。 あわせてブラウザへのパスワード保存を方針として禁止し、 保存資格情報の読み出しを検知の対象にする
  • 基盤提供者の従業員が到達できる範囲を、提供先（ブランド・テナント）ごとに分離する
    MVNO は複数ブランドの顧客データを1か所に集める。 1人の従業員の権限が複数ブランドに及ぶ構成なら、 1台の端末の感染で全ブランドの顧客が射程に入る
    取るべき行動 運用者の権限をテナント単位に分け、横断して参照できる権限を 作業の都度発行する一時的なものに切り替える。 横断参照が必要な業務（請求集計等）は、個人データを含まない集計面で行う
  • ブランド側（委託元）が、基盤側での自社データへのアクセス記録を受け取る
    本件はブランド側に顧客データの保管も運用も無いとみられ、 侵害の範囲を自分で測れる立場にない。だから公表も通知もできない
    取るべき行動 基盤提供者との接続に、自社データへの参照・出力の記録を 自社側へ送る経路を設ける。契約で「ログの提供」を成果物として書く。 **受け取っていないログは、侵害時に存在しない**
  • 顧客データの一括出力を、申請と承認を伴う操作にする
    本件では3,615人分の顧客データがまとまった形で公開されている
    取るべき行動 管理画面・API の一括出力に申請と承認の工程を置き、 実行を1件単位で記録・通知する。日常業務で一括出力が必要な箇所を洗い出し、 集計結果の参照に置き換えられるものを置き換える
