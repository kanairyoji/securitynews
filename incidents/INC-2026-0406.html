INC-2026-0406Movable Typeに未認証RCE、EOL版も影響

シックス・アパートは2026年10月7日、**CMS「Movable Type」のアップグレードスクリプト `mt-upgrade.cgi` に、認証を要さずに任意の Perl コードと SQL を実行できる コードインジェクションの欠陥（CVE-2026-96408・CVSS v4.0 9.3／v3.0 9.4）**があったことを公表し、 同時に修正版 **9.3.0 / 9.0.10 / 8.8.6 / 8.0.13**（Premium は 9.3.0 / 9.0.10 / 2.18）を提供した。 **サイト内検索 `mt-search.cgi` の SQL インジェクション（CVE-2026-103668・v4.0 8.8／v3.0 8.6）**も 同日に公表され、**非公開のデータが出力されるおそれがある**とされた。 **成立に必要なのは、認証も利用者の操作もなく、該当の CGI に到達できることだけである**（ベンダーの記述）。 **サポートが終了した系列（Movable Type 4.0〜4.38・5.0〜5.2.13・6.0.1〜6.8.8・ 7 r.4207〜r.5510・8.4.0〜8.4.4、Premium 1.0〜1.68）も影響を受けるが、これらには修正版が出ない。** JVN（JVN#91153973）と IPA も同日に公表・注意喚起を出した。 **公表資料はいずれも悪用の有無に触れていない。**

攻撃の経過

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

**本件は実際の被害事例ではなく、協調公表された欠陥の記録である**（本記録の位置づけ）。 **公表資料はいずれも悪用の有無に触れていない**（出典1〜7）。 **本記録が連鎖として書くのは、公表された技術的条件から導ける経路までであり、 実際に観測された攻撃ではない。** **本件の性格は「連鎖が短いこと」である**（本記録の整理）—— **攻撃者に必要なのは、対象の `mt-upgrade.cgi` または `mt-search.cgi` に HTTP で到達できることだけで、認証も利用者の操作も要らない。** **CVE-2026-96408 は Perl コードの実行、CVE-2026-103668 は非公開データの出力につながる。**

  1. 1. 偵察
    **攻撃者は、`mt-upgrade.cgi` / `mt-search.cgi` / `mt-ftsearch.cgi` が 外部から見える設置を探す**（本記録が公表された技術的条件から導いた経路。 実際にそのような探索が行われたかは公表されていない）。 **Movable Type の既定の配置ではこれらは CGI のディレクトリに並ぶため、 パスの推測が容易である**（本記録の一般的理解）。 **回避策として「ファイルの削除」や「実行権の削除」が挙げられていること自体が、 到達性が成立条件であることを示している**（本記録の読み。出典1）。
  2. 2. 初期侵入
    **CVE-2026-96408 の場合** —— **攻撃者は `mt-upgrade.cgi` に細工したリクエストを送る。** **ベンダーの記述では「リモートコード実行（RCE）や不正な SQL が実行されるおそれ」、 JVN の記述では「システム上で任意の Perl コードや SQL クエリが実行される」** （出典1・3）。 **認証は不要である**（CVSS の PR:N・UI:N、および Security NEXT の 「認証を必要とすることなくネットワーク経由で」という記述。出典3・7）。 **CVE-2026-103668 の場合** —— **`mt-search.cgi` / `mt-ftsearch.cgi` に細工した検索条件を送り、 任意の SQL を実行させる**（出典3）。
  3. 3. 実行
    **CVE-2026-96408 では、Perl コードが Movable Type を動かしている権限で実行される** （本記録の整理。JVN の「システム上で任意の Perl コードが実行される」という記述から。 実行権限の具体的な範囲は公表されていない）。 **Web サーバのプロセス権限で動くのが通常の構成である**（本記録の一般的理解）。 **ベンダーの告知は MTC-31703 を本件の管理番号として挙げている**（出典2）。
  4. 4. 持ち出し
    **CVE-2026-103668 の想定される影響は「非公開とされるものも含むデータが出力される」ことである** （出典7。ベンダーの英語版告知は "potentially exposing unpublished data"。出典2）。 **JVN の記述は「システム上で SQL クエリが実行される」**（出典3）。 **Movable Type のデータベースには、未公開の記事・下書き・ 利用者アカウントの情報が入る**（本記録の一般的理解。 公表資料は取り出せる対象を具体的に挙げていない）。

更新用のスクリプトが、認証の前に任意の Perl コードを実行する経路になっていた原因・手口

本件の中心は CVE-2026-96408 である。

ベンダーの記述（出典1）—— アップグレードスクリプト mt-upgrade.cgi に、「リモートコード実行（RCE）や不正な SQL が実行されるおそれ」がある。 管理番号は MTC-31703（出典2）。

JVN の記述（出典3）—— 「アップグレードスクリプトにおけるコードインジェクション（CWE-94）」で、想定される影響は「システム上で任意の Perl コードや SQL クエリが実行される」。

評価値が示す成立条件を読む（本記録の読み）。

要素 値 意味
AV（攻撃経路） N ネットワーク経由
AC（条件の複雑さ） L 特別な条件が要らない
PR（必要な権限） N 認証が不要
UI（利用者の操作） N 誰かにクリックさせる必要がない
VC / VI（機密性・完全性） H / H いずれも高い影響

つまり攻撃に必要なのは、対象の mt-upgrade.cgi にHTTP で到達できることだけである（本記録の評価）。

なぜこのスクリプトが認証の前段にあるのか（本記録の一般的理解。公表資料は設計の経緯に触れていない）—— アップグレードはデータベースの構造を変える処理であり、「新しいプログラムを置いた直後、まだ新しい構造になっていない状態」で動かす必要がある。 この状態では認証の仕組み自体が完全に動くとは限らない。 だからこの種のスクリプトは、認証に依存しない作りになりがちである。

ベンダーが示した回避策が「ファイルを削除する」「実行権を削除する」である点が、この性格を裏づけている（本記録の読み。出典1）—— 権限で守る対象ではなく、置かないことで守る対象だということである。

サイト内検索の SQL インジェクションは、未公開の記事まで出しうる原因・手口

もう1件は CVE-2026-103668 である。

JVN の記述（出典3）—— 「サイト内検索機能における SQL インジェクション（CWE-89）」。想定される影響は「システム上で SQL クエリが実行される」。

ベンダーの英語版の記述（出典2。原文英語）—— 「任意の SQL 実行を許し、未公開のデータを露出させるおそれがある」。 Security NEXT は「非公開とされるものも含むデータが出力されるおそれがある」と報じた（出典7）。

CVSS は v4.0 8.8／v3.0 8.6 で、こちらも PR:N・UI:N である（出典3・6）。

対象は mt-search.cgi と mt-ftsearch.cgi（出典1・2）。ベンダーは「mt-ftsearch.cgi は Movable Type 8 以降には存在しない場合がある」と注記している（出典1）。

本記録が CVE-2026-96408 と分けて読むべきと考える理由（本記録の評価）——

① 到達性の性質が違う。 mt-upgrade.cgi は「平常時は誰も叩かない」スクリプトだが、mt-search.cgi は読者が日常的に使う公開機能である。 前者は消せるが、後者は消すと機能が止まる。

② 検知の見込みが違う。 前者へのアクセスはログ上で目立つが、後者は正常な検索との区別がつかない。

③ したがって、残る手が違う。 前者は「置かない」で済むが、後者は「更新する」か「検索機能を外部の仕組みに移す」しかない。

本記録がここを本件の核心と判断した理由（本記録の評価）——

① 対象が10年以上前の版まで遡る。 Movable Type 4 系は2007年ごろの製品である（本記録の一般的理解）。「10年以上動き続けているサイト」が影響を受ける。

② そうしたサイトは、動いているために触られていない。 静的ファイルを書き出す構成では、CMS が古いままでも公開されているページは正常に見える（本記録の一般的理解）。運用の必要がないので、更新の動機が生まれない。

③ 修正版が出ないため、更新という選択肢自体が無い。 残るのは「回避策を当てる」か「保守対象の系列へ移行する」の二択で、後者は実質的にサイトの作り直しである。

④ 情報が届く経路も細い（unknowns 参照）—— サポート終了版の利用者は、定義上ベンダーの保守連絡の対象外である。

回避策は CGI と PSGI で別の手を使い、古い PSGI では効果が弱い対策・注意喚起

ベンダーが示した回避策（出典1・2・3・4。すべて同じ内容）。

環境 回避策
CGI（全版） mt-upgrade.cgi・mt-search.cgi・mt-ftsearch.cgi を削除する、または実行権限を削除する
PSGI（MT 6.2 以降） mt-config.cgi に RestrictedPSGIApp upgrade・RestrictedPSGIApp new_search・RestrictedPSGIApp ft_search を追加する（ft_search は 6.2.4 以降）

本記録の評価 ——

① CGI 環境の回避策は、本質的に有効である。 攻撃の成立条件が到達性だけなので、置かなければ成立しない。 ただし mt-search.cgi を消せば検索機能が止まる —— 副作用を受け入れられるかどうかはサイトによる。

② PSGI 6.2 以降の RestrictedPSGIApp も、該当アプリを無効にする設定であり効果が明確である。

③ MT 6.0 / 6.1 の回避策だけは性質が違う。 「長く推測されにくい値を設定する」は、スクリプトの名前を秘密にする緩和である（本記録の読み）—— 名前が漏れれば効果を失う。 設定ファイルの流出・バックアップの露出・過去のログに名前が残っている、といった経路で破れる。 この系列はサポート終了版でもあるため、回避策の弱さと修正版が無いことが重なる（本記録の指摘）。

④ ベンダーは恒久対策を1つに絞っている。 英語版の告知は「最新版への更新だけが、これらの問題を完全に解消する」と明記している（出典2。原文英語）。

    取るべき行動 **自組織が運用する CMS・ミドルウェアについて、 ①現在の版、②その版の保守終了時期、③保守終了後の方針 （移行・回避策での継続・サイト自体の終了）を一覧にする。** **「保守終了の日付」を更新計画の起点に置き、 脆弱性の公表を起点にしない。** **移行予算を、脆弱性対応の予備費ではなく 通常の更新計画として確保する。**
  • 年に複数回の緊急更新が来る製品だという前提で、体制と予算を組む
    **本記録が取得して確認した範囲で、2026年のうちに プレスリリースを出す深刻度の公表が少なくとも2回あった** （4月8日の CVE-2026-25776 / CVE-2026-33088、および本件。出典1・8）。 **いずれも「Perl コードの実行」と「SQL インジェクション」の組み合わせである。** **本記録は原因の同一性については判断していない** （discrepancies 参照）—— **しかし利用者側の運用負荷は、原因が同じかどうかに関係なく発生する** （本記録の評価）。
    取るべき行動 **CMS の緊急更新を「年数回起きる定常業務」として手順化する。** **具体的には、①更新の実施者と代替者、②検証環境での確認工程、 ③業務時間外に実施する場合の承認経路、④回避策を先に当てる判断基準を あらかじめ決めておく。** **外部に委託している場合は、緊急更新の対応時間を契約に書く （「翌営業日」では認証不要の RCE に間に合わない）。**
  • 「認証の前段にある部品」の一覧を、自組織が持っているかを確かめる
    **本件の2件はいずれも PR:N（権限不要）・UI:N（操作不要）であり、 多要素認証・管理画面の IP 制限・権限の見直し・利用者教育のいずれも効かない** （本記録の整理。出典3）。 **効くのは版を上げることと、到達できないようにすることだけである。** **ベンダーの回避策が「ファイルを削除する」である点が、 この性格を端的に示している**（出典1）。
    取るべき行動 **公開している Web サーバ上で、 認証を経ずに実行される CGI・スクリプト・エンドポイントの一覧を作る。** **各項目について「平常の運用で誰が叩くか」を書き、 誰も叩かないものは配置そのものをやめる。** **この一覧を、脆弱性公表時に「自組織が該当するか」を 即座に判定するための台帳として使う。**
  • 静的書き出し型の CMS は「動いて見える」ため、更新漏れが可視化されない
    **Movable Type は静的ファイルを書き出す構成が多く、 CMS 本体が古いままでも公開ページは正常に表示される** （本記録の一般的理解。公表資料は構成に触れていない）。 **障害として現れないため、更新の動機が業務側から出てこない** （本記録の評価）。 **公表資料には国内の設置数も版の分布も無く、 母数が外から分からない**（unknowns 参照）。
    取るべき行動 **「サイトが正常に表示されているか」ではなく 「CMS の版が保守対象か」を監視項目にする。** **資産管理台帳に CMS の版を登録し、 四半期ごとに保守対象であることを確認する工程を置く。** **部門が独自に立てたサイト（いわゆる野良サイト）の洗い出しを、 同じ工程に含める。**
セキュリティ技術者への示唆
  • まず該当スクリプトの到達性を切る。更新より先に打てる手である
    **攻撃の成立条件は到達性だけである**（本記録の読み。出典3 の PR:N・UI:N）。 **ベンダーの回避策は、CGI 環境では `mt-upgrade.cgi`・`mt-search.cgi`・`mt-ftsearch.cgi` の 削除または実行権限の削除である**（出典1）。 **英語版の告知は「Web からのアクセスを遮断するか、サーバから削除する」と 表現している**（出典2。原文英語）。 **更新には検証が要るが、到達性を切るのは即座にできる**（本記録の評価）。
    取るべき行動 **本番サーバで `mt-upgrade.cgi`・`mt-search.cgi`・`mt-ftsearch.cgi` の 有無を確認し、`mt-upgrade.cgi` は削除する（更新作業時だけ置く運用に変える）。** **`mt-search.cgi` / `mt-ftsearch.cgi` は、 検索機能を止める影響を確認したうえで判断する。** **PSGI 環境（MT 6.2 以降）では `mt-config.cgi` に `RestrictedPSGIApp upgrade` / `new_search` / `ft_search` を追加する （`ft_search` は 6.2.4 以降）。**
  • MT 6.0 / 6.1 の回避策は「名前を隠す」緩和であり、効果を過大に見ない
    **MT 6.0 / 6.1 の PSGI 環境に示された回避策は、 `UpgradeScript` と `SearchScript` に長く推測されにくい値を設定することである** （出典1・2）。 **これはスクリプトの名前を秘密にする緩和であり、 名前が漏れれば効果を失う**（本記録の評価）—— **設定ファイルの流出、バックアップの露出、 過去のアクセスログやリファラに名前が残っている、といった経路で破れる。** **この系列はサポート終了版でもあるため、修正版も出ない。**
    取るべき行動 **MT 6.0 / 6.1 を使っている場合は、 回避策の適用で止めず、保守対象の系列への移行計画を立てる。** **移行までの期間は、設定した名前を含むファイル （`mt-config.cgi`・バックアップ・構成管理のリポジトリ）の 公開範囲を確認する。** **アクセスログ・リファラに名前が残る経路も点検する。**
  • アクセスログで `mt-upgrade.cgi` への外部アクセスを探す。平常時は現れない
    **`mt-upgrade.cgi` は更新作業のときだけ使うスクリプトであり、 平常の運用では外部からのアクセスが発生しない**（本記録の評価。 公表資料は検知手段に触れていない）。 **これに対し `mt-search.cgi` は読者が日常的に使う公開機能であり、 正常な検索と探索を分けるのは難しい**（本記録の整理）。 **つまり2件の欠陥で、ログから分かることの質が違う。**
    取るべき行動 **Web サーバのアクセスログを `mt-upgrade.cgi` で検索し、 作業者以外の送信元からのアクセスが過去にあったかを確認する。** **保存期間の範囲で遡り、見つかった場合は 応答コードと応答サイズまで確認する。** **`mt-search.cgi` については、 1リクエストあたりの応答サイズの異常値と、 同一送信元からの短時間の多数実行を手がかりにする。**
  • 「どの系列に乗っているか」を先に確定しないと、上げ先の版が決まらない
    **修正版は7つある** —— **Movable Type 9.3.0 / 9.0.10 / 8.8.6 / 8.0.13、 Movable Type Premium 9.3.0 / 9.0.10 / 2.18**（出典1）。 **さらに 9.2 系はクラウド版のみという条件がつく。** **自組織の製品名（Movable Type / Advanced / Premium / Premium Advanced / クラウド版）と系列を確定しないと、上げ先が一意に決まらない** （本記録の評価）。
    取るべき行動 **管理画面またはファイルから、製品名・エディション・系列・版を確定する。** **その上で、同じ系列の修正版へ上げる （系列をまたぐ更新は移行作業になるため、緊急対応では分けて扱う）。** **確定結果を資産台帳に記録し、次回の公表時に再調査しなくて済むようにする。**
  • 復旧の前提として、DB の権限と設定ファイルの読み取り範囲を見直す
    **CVE-2026-96408 は Perl コードの実行と SQL の実行の双方につながる** （出典1・3）。 **実行権限の具体的な範囲は公表されていない**（本記録が確認）—— **通常は Web サーバのプロセス権限である**（本記録の一般的理解）。 **任意コードが動くことを前提に、そこから何に届くかを縮めるのが 残された備えである**（本記録の評価）。
    取るべき行動 **①Movable Type を動かすプロセスに、 書き出し先以外への書き込み権限を与えない。** **②`mt-config.cgi` の読み取り権限を必要最小限にする。** **③データベースの接続利用者に、CMS の動作に不要な権限 （他のデータベースへの参照・ファイル操作系の関数）を与えない。** **④データベースの監査ログを有効にし、 事後に「何を取られたか」を確定できるようにする。**
