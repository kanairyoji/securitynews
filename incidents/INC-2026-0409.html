INC-2026-0409Veeam B&Rの閲覧ロールからSYSTEM実行

Veeam は2026年10月6日、**Veeam Backup & Replication** のバックアップサーバ上で **「Backup Viewer」ロールを持つ低権限の利用者が SYSTEM として 任意のコードを実行できる欠陥（CVE-2025-64393・CVSS v4.0 9.4・Critical）**を 公表した（KB4934）。 **原因は Mount Service が受け取った信頼できないデータの 安全でないデシリアライズ処理である**（ベンダーの記述。原文英語）。 **Backup Viewer は本来、バックアップの状態を見るための読み取り中心のロールである** （本記録の整理）—— **それがバックアップサーバの最高権限に届く。** 同じ KB で、**Backup Viewer が Enterprise Manager のマスターキーを 変更・削除し、保存されたウイルス対策更新用の資格情報を 読み取り・上書きできる CVE-2026-93026（6.1）**と、 **Enterprise Manager の反射型 XSS CVE-2025-64392（4.8）**も公表された。 **修正は 12.3.2 P4（ビルド 12.3.2.4934）。影響は 12.3.2.4854 以前のバージョン12系で、 Veeam はバージョン13は影響を受けないとしている。** **別途、認証済みの Cloud Connect テナントがサービスプロバイダ側のホスト上の 任意のファイルを読み取れる CVE-2026-58069（v4.0 8.3・High）も同日に登録された** —— **ただしこの1件は KB4934 には載っておらず、 NVD の登録ではバージョン13（13.0.3 以下）も影響を受けるとされている**（本記録が確認）。

攻撃の経過

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

**本件は実際の被害事例ではなく、協調公表された欠陥の記録である** （本記録の位置づけ）。 **Veeam は悪用の有無について述べていない**（本記録が確認）—— **ただし KB4934 は「攻撃者が修正を解析して 未修正のシステムを狙う可能性が高い」と注意を促している**（出典1。原文英語の要旨）。 **本記録が連鎖として書くのは、公表された技術的条件から導ける経路までであり、 実際に観測された攻撃ではない。** **本件の性格は「権限の境界が境界になっていなかったこと」である** （本記録の整理）—— **起点は Backup Viewer ロールを持つ認証済みの利用者であり、 到達点はバックアップサーバ上の SYSTEM である。** **攻撃者が外部から認証を突破する必要はなく、 すでにそのロールを持つ者か、 そのロールの資格情報を得た者であればよい**（本記録の読み）。

  1. 1. 認証情報アクセス
    **攻撃者は、Backup Viewer ロールを持つ資格情報を得る** （本記録が公表された技術的条件から導いた経路。 本件についてそのような入手が行われたかは公表されていない）。 **CVSS の PR:L（低い権限が必要）が、この前提を示している**（出典2）。 **本記録の整理** —— **Backup Viewer は読み取り中心のロールであるため、 運用の担当者・監査担当・委託先・レポート閲覧者に 広く配られやすい**（本記録の一般的理解。 公表資料は付与の実態に触れていない）。 **つまり「最も配りやすいロール」が起点になっている。**
  2. 2. 実行
    **Mount Service へ細工したデータを送る。** **Veeam の記述**（出典1。原文英語の要旨）—— **「Backup Viewer ロールを持つ低権限の利用者が、 Mount Service 経由で受信した信頼できないデータの 安全でないデシリアライズを通じて、 バックアップサーバ上でリモートコード実行を達成できる」。** **NVD の説明は「Backup Viewer がバックアップサーバ上で SYSTEM として任意のコードを実行できる」**（出典2。原文英語）。 **実行されるのは SYSTEM、すなわち Windows の最高権限である** （本記録の整理）。
  3. 3. 認証情報アクセス
    **同じロールから、保存された資格情報へ到達する経路も公表された。** **CVE-2026-93026** —— **Backup Viewer ロールを持つ認証済み利用者が、 Enterprise Manager のマスターキーを変更・削除し、 保存されたウイルス対策更新用の資格情報を 読み取り・上書きできる**（出典1。原文英語の要旨）。 **本記録の整理** —— **CVE-2025-64393 とは別の欠陥だが、起点のロールが同じである。** **公表資料は2件の連鎖には言及していない**（本記録が確認）。
  4. 4. 影響（暗号化・破壊・改ざん）
    **バックアップサーバ上の SYSTEM 権限は、 バックアップそのものに対する完全な支配を意味する** （本記録の評価。公表資料は影響の具体例を挙げていない）。 **CVSS v4.0 の後続への影響（SC:H / SI:H / SA:H）が これを反映している**（出典2。本記録の読み）。 **本記録の整理** —— **バックアップは、ランサムウェア被害からの復旧の最後の手段である。** **侵入者から見れば、暗号化を仕掛ける前に 無力化しておくべき対象になる。** **したがってバックアップサーバの権限の欠陥は、 単独の被害ではなく「他の被害からの回復可能性」を左右する** （本記録の評価）。

「見るだけ」のロールから、バックアップサーバの SYSTEM に届いていた原因・手口

中心は CVE-2025-64393 である。

Veeam の記述（出典1。原文英語の要旨）—— 「Backup Viewer ロールを持つ低権限の利用者が、Mount Service 経由で受信した信頼できないデータの安全でないデシリアライズを通じて、バックアップサーバ上でリモートコード実行を達成できる」。

NVD の説明（出典2。原文英語）—— 「Veeam Backup & Replication のこの脆弱性は、Backup Viewer がバックアップサーバ上で SYSTEM として任意のコードを実行することを許す」。

2つを合わせると、起点と到達点が確定する（本記録が突き合わせて確認）。

項目 内容
起点 Backup Viewer ロールを持つ認証済み利用者
経路 Mount Service が受け取るデータの安全でないデシリアライズ
到達点 バックアップサーバ上の SYSTEM（Windows の最高権限）

評価値（出典2）—— CVSS v4.0 9.4（Critical）・AV:N/AC:L/AT:N/PR:L/UI:N/VC:H/VI:H/VA:H/SC:H/SI:H/SA:H。

本記録が注目するのは PR:L と、影響側がすべて H であることである（本記録の読み）—— 「低い権限で足りる」のに「影響は全面的」。 この組み合わせが、権限の段差の大きさを数値として表している。

デシリアライズがなぜコード実行になるか（本記録の一般的理解。公表資料は実装の詳細に触れていない）—— デシリアライズは「受け取ったバイト列をオブジェクトに戻す」処理である。 戻す過程で任意の型を構築できる実装だと、その型の初期化処理や後処理が攻撃者の指定どおりに動く。 「データを読んでいるつもりが、コードを動かしている」という構造である。

本記録の評価 —— この型の欠陥は、入力の検証では塞がりにくい。 検証すべき対象が「データの中身」ではなく「どの型に戻すことを許すか」であり、実装の設計そのものを変える必要があるためである。

影響を限定できたバックアップの一部を、書き換え・削除ができない形 （イミュータブルな保管・オフラインの媒体）で保持する　**本記録の評価による。** **バックアップサーバの管理権限を取られても、 書き換えられない複製が残れば復旧の手段が残る** （本記録の整理）。
検知できたバックアップの成否と世代数を、 バックアップ基盤の外側から監視する　**本記録の評価による。** **基盤自身が報告する「正常」を信頼の根拠にしない** （本記録の評価）—— **基盤が支配されていれば、その報告も操作されうる。**

対応の評価

評価材料がない判断は「評価材料なし」としています。結果論で断じないための区分です。
対応の巧拙を評価できる材料が公表資料から得られていません。
CISO・経営層への示唆
  • 「読み取り専用」と見なしているロールの付与先を、攻撃面として数える
    **本件の2件（CVE-2025-64393・CVE-2026-93026）は いずれも Backup Viewer ロールを起点とする**（出典1）。 **前者はバックアップサーバ上の SYSTEM 権限に、 後者はマスターキーと保存された資格情報に届く**（出典1・2）。 **読み取り中心のロールは「安全だから広く配ってよい」と 扱われやすい**（本記録の一般的理解）—— **運用担当・監査担当・委託先・レポート閲覧者に配られる。** **付与先の数がそのまま攻撃面の広さになる**（本記録の評価）。
    取るべき行動 **バックアップ基盤のロール付与先を一覧にし、 「読み取り専用」とされているロールも含めて棚卸しする。** **各付与について、業務上の必要性と付与期限を記録する。** **委託先に付与している場合は、 契約終了時の削除が実施されているかを確認する。** **この棚卸しは、更新の窓が取れるまでの緩和としても機能する。**
  • バックアップ基盤の脆弱性は、他の被害からの回復可能性の問題として扱う
    **CVSS v4.0 の後続への影響がすべて H（SC:H / SI:H / SA:H）である** （出典2）—— **影響がバックアップサーバの内側で止まらないという評価である。** **バックアップサーバの SYSTEM 権限は、 バックアップの削除・保持期間の短縮・ジョブの無効化を可能にし、 これらは基盤の中では正規の管理操作として実行される** （本記録の評価）。 **ランサムウェア攻撃では、暗号化の前にバックアップを 無力化することが攻撃者の成功条件になる** （本記録の一般的理解）。
    取るべき行動 **「バックアップ基盤が侵害されたときに何が残るか」を 経営として確認する。** **具体的には、①書き換え・削除のできない形 （イミュータブルな保管・オフラインの媒体）で保持している 世代があるか、②バックアップの成否と世代数を 基盤の外側から監視しているか、を確認する。** **基盤自身が報告する「正常」を、 事業継続計画の前提に置かない。**
  • 「修正が公開されたこと」が攻撃の起点になるという前提で、更新の窓を確保する
    **KB4934 は、本件について悪用の記載は無いものの 「攻撃者が修正を解析して未修正のシステムを狙う可能性が高い」と 警告している**（出典1。原文英語の要旨）。 **バックアップ基盤の更新には固有の難しさがある** （本記録の一般的理解）—— **ジョブが走っている間は更新できず、 更新中はバックアップが取れない。** **「いつ更新の窓を取るか」が業務の調整になる**（本記録の評価）。
    取るべき行動 **バックアップ基盤の緊急更新について、 あらかじめ「窓」を確保する運用を決める （何曜日の何時なら更新できるか、誰が承認するか）。** **窓の確保に日数がかかる場合は、 その間の緩和（ロールの棚卸し・到達経路の限定）を 手順として併記する。** **更新中にバックアップが取れない時間について、 事業側の了解を事前に取っておく。**
  • 勧告を1本読んで終わりにしない。同日の公表が別勧告に分かれていることがある
    **CVE-2026-58069（認証済みの Cloud Connect テナントが サービスプロバイダ側ホストの任意のファイルを読み取れる・ CVSS v4.0 8.3）は、KB4934 の本文に記載が無い** （出典1。本記録が確認）。 **CERT-FR の注意喚起も参照 CVE に含めていない**（出典3）。 **一方 NVD では同日に登録され、 バージョン13（13.0.3 以下）も影響を受けるとされている**（出典4）。 **KB4934 の「バージョン13は影響を受けない」をそのまま 全体の結論として受け取ると、この1件を見落とす**（本記録の評価）。
    取るべき行動 **ベンダー勧告のほかに、CVE データベース側でも 製品名による検索を行い、同時期に登録された CVE を突き合わせる。** **とくに Cloud Connect のようにサービス提供側に 固有の欠陥がある構成では、 自組織の立場（利用者／提供者）に応じた確認先を決めておく。** **確認した結果を記録に残し、 「勧告に無かったから対象外」という判断の根拠にしない。**
セキュリティ技術者への示唆
  • ビルド番号で判定する。12.3.2.4854 以前なら対象、修正は 12.3.2.4934
    **Veeam は影響範囲を 「ビルド 12.3.2.4854 およびそれ以前のバージョン12系」とし、 修正を 12.3.2 P4（ビルド 12.3.2.4934）としている**（出典1）。 **CERT-FR も同じビルドを示している**（出典3）。 **版の表記が「12.3.2 P3」のようなパッチ名と 「12.3.2.4854」のようなビルド番号の2系統あるため、 パッチ名だけでは判定を誤りうる**（本記録の指摘）。
    取るべき行動 **運用中の Veeam Backup & Replication のビルド番号を確認し、 12.3.2.4854 以前であれば対象と判定する。** **判定はパッチ名ではなくビルド番号で行う。** **複数のバックアップサーバがある場合は、 台ごとにビルド番号を記録する。**
  • Backup Viewer ロールの実際の権限を確認する。公表資料に一覧が無い
    **公表資料には Backup Viewer ロールの権限一覧が無く、 なぜこのロールが Mount Service へデータを送れ、 Enterprise Manager のマスターキーを操作できたのかも 説明されていない**（本記録が確認。unknowns 参照）。 **2件の欠陥が同じロールを起点としていることは、 「他にも経路があるか」を利用者が判断できないことを意味する** （本記録の評価）。
    取るべき行動 **自組織の構成で Backup Viewer ロールに 実際に許可されている操作を、製品のロール定義から確認する。** **「読み取りのみ」という理解が実装と合っているかを検証する。** **確認結果を記録し、ロール付与の判断基準として使う。**
  • バックアップサーバの EDR 除外設定を見直す。正規プロセス内での実行は外形に出ない
    **デシリアライズを通じたコード実行は、 正規のサービスプロセス（Mount Service）の中で起きる** （本記録の整理。公表資料は実装の詳細に触れていない）。 **したがって「不審な実行ファイルが起動した」という形では現れず、 Mount Service のプロセスから子プロセスが起動する、 あるいは外部へ通信するという形で現れる**（本記録の評価）。 **バックアップサーバは性能への影響を理由に EDR の除外対象にされていることがある**（本記録の一般的理解）。
    取るべき行動 **バックアップサーバが EDR の監視対象に入っているかを確認し、 除外設定（パス・プロセス単位）の内容を点検する。** **性能の都合で除外している場合は、 少なくともプロセスの親子関係と外向き通信の記録は 取得する設定に変える。** **バックアップ基盤の操作ログ（鍵・資格情報に関わる操作を含む）を 外部のログ基盤へ転送する（機器上の記録は侵害後に信頼できない）。**
  • Cloud Connect を提供している場合は、CVE-2026-58069 を別に追う
    **CVE-2026-58069 は、認証済みの Cloud Connect テナントが サービスプロバイダのホスト上の任意のファイルを 読み取れるものである**（出典4。原文英語の要旨）。 **CVSS v4.0 は 8.3（High）で、 `SC:H`（後続への機密性の影響が高い）が付いている** —— **テナントの境界を越える性質を表している**（本記録の読み）。 **この1件は KB4934 に載っておらず、 NVD ではバージョン13（13.0.3 以下）も対象とされている** （discrepancies 参照）。
    取るべき行動 **Cloud Connect を提供している場合は、 KB4934 の適用だけで終わらせず、 CVE-2026-58069 に対応する勧告を Veeam に確認する。** **バージョン13を運用している場合も確認対象に含める。** **サービスプロバイダ側のホストに、 テナントから読まれて困るファイル（他テナントの情報・ 資格情報・構成ファイル）が置かれていないかを点検する。**
  • 更新の窓が取れるまでの緩和を手順に落とす。ロールの削減が即座に効く
    **本件の成立前提は「Backup Viewer ロールを持つ認証済み利用者」である** （出典1・2）。 **ベンダーは回避策を示していない**（本記録が確認した範囲では KB4934 に回避策の記載が無い。discrepancies 参照）。 **しかし前提を満たす者を減らすことは即座にできる**（本記録の評価）—— **これは恒久対策ではなく、 正当な保持者からの攻撃や資格情報の漏えいには効かない。**
    取るべき行動 **更新の窓が取れるまでの緩和として、 ①Backup Viewer ロールの不要な付与を取り消す、 ②バックアップ基盤の管理画面へ到達できる経路を限定する、 ③該当アカウントの認証に多要素認証を要求する、 の3点を実施する。** **緩和であることと、更新の期限を記録に残す。**
