対応の評価

評価材料がない判断は「評価材料なし」としています。結果論で断じないための区分です。
対応の巧拙を評価できる材料が公表資料から得られていません。
CISO・経営層への示唆
  • 「自組織が狙われるか」の判断に、扱っている主題を入力として入れる
    **本件の2020年の局面は、 「COVID-19 研究をしていたこと」が標的の条件になっている** （出典1）—— **大学という業種でも、規模でも、保有する個人情報の量でもない。** **2020年初頭は感染症の性質がまだ分かっていなかった時期であり、 研究データを先に得ることの意味は、 金銭的な価値ではなく情報の優位にある**（本記録の一般的理解）。 **本記録の評価** —— **規模や保有データ量だけを入力にした脅威の評価では、 この形の標的化は見落とす。** **2021年の局面では法律事務所も被害者に含まれており**（出典1）、 **顧客の機密を集約する業種も対象になっている。**
    取るべき行動 **①自組織が扱う主題のうち、 国家の関心が向きうるものを一覧にする （先端研究・感染症・エネルギー・防衛・半導体・ 政府案件の法務や監査など）。** **②その主題を扱う部門・プロジェクトに限って、 通常より厚い監視と権限の制限を適用する**—— **全社一律では費用が合わない。** **③一覧を年次で見直す**—— **関心が向く主題は国際情勢で変わる。**
  • 国家が関与する侵害は「4〜6年後に公表される」前提で記録を残す
    **本件の時間の流れは次のとおりである**（出典1・2）—— **侵入が2020年初頭〜2021年、 起訴状の公開が2025年とされ、 懸賞金の提示を本記録が確認したのが2026年。** **本記録の評価** —— **自組織が過去の大量侵害に含まれていたかを後から確認するには、 当時の記録が残っていなければならない。** **本件は「世界中で数千台」とされる大量侵害キャンペーンであり** （出典1）、 **被害組織の名前は公表されていない** —— **「自分が含まれていたか」は自分で調べるしかない。**
    取るべき行動 **①外部に公開しているサービス （メール基盤・VPN・ファイル共有）のアクセス記録と認証記録について、 保持期間を決め、その根拠を記録する。** **②後から過去を調べられる形で保管する （長期の保管は低コストの保管先へ移してよい。 引き出せることが条件）。** **③大規模な侵害キャンペーンの公表があったときに、 自組織の記録を遡って照合する手順を決めておく**—— **誰が判断し、どの記録をどう照合するか。**
  • 「国家の関与」の帰属は、技術的な観測だけでは成立しない——層を分けて受け取る
    **出典1が提示しているのは技術的な痕跡ではない**（本記録の整理）—— **「MSS 上海市国家安全局の指示のもとで活動した」という主張であり、 報道によれば検察は「SSSB の上官に報告していた」とみている**（出典2）。 **一方、出典1は「中国は、政府の関与を見えにくくする形で 侵入と情報窃取を行うために、 中国国内の民間企業と請負業者の広範なネットワークを用いている」と 述べている**（原文英語の要旨）—— **請負の構造があるため、 侵入の痕跡が同じでも国家の指示か民間の営利活動かを 技術だけでは分けられない**（本記録の評価）。
    取るべき行動 **①外部の脅威情報を受け取るとき、 「技術的な観測」「当局・捜査機関の主張」「自組織の観測」を 分けて記録する**—— **混ぜると、どれが検証可能な事実かが後から分からなくなる。** **②報告書やブリーフィングで「国家が関与」と書くときは、 根拠がどの層のものかを必ず添える。** **③起訴や制裁の情報は、裁判による認定とは別物として扱う**—— **本件の Zhang は逃亡中で裁判は行われていない。**
  • 懸賞金・起訴・制裁は、自組織の防御には直接効かないものとして位置づける
    **出典1は懸賞金の提示であり、 CVE 番号も技術的な痕跡も含まれていない**（本記録が確認）。 **懸賞金が提示された日付も記載が無い**（unknowns 参照）。 **本記録の評価** —— **この種の資料から取り出せるのは、 「誰が何を狙っているか」という戦略的な理解であり、 明日の防御を変える材料ではない。** **一方、名指しされた組織名 （Shanghai Firetech・Shanghai Powerock 他）は、 取引や委託の判断には関わりうる** —— **ただし出典1は、これらに対する制裁や 取引制限の措置には言及していない**（unknowns 参照）。
    取るべき行動 **①懸賞金・起訴・制裁の情報は、 脅威情報の受け入れ口で「戦略」に分類し、 技術的な対処の待ち行列に入れない**—— **混ぜると、対処できない項目が溜まる。** **②名指しされた企業名については、 自組織の取引先・委託先の一覧と突き合わせる （法的な制限の有無は別に確認する）。** **③経営への報告では「この件で我々が明日やることは無い」と はっきり書く**—— **書かないと、報告のたびに対処を求められる。**
セキュリティ技術者への示唆
  • 公開されたメール基盤の緊急修正を「通常の変更管理の外」で適用できる手順を持つ
    **本件の2021年の局面は、 Microsoft Exchange Server の脆弱性の悪用とされる**（出典1）—— **「HAFNIUM」として公に知られる大量侵害キャンペーンの一部で、 世界中で数千台が侵害された。** **CVE 番号は公表されていないため、 本件で何が有効だったかは言えない**（本記録の明示）。 **一般に、インターネットに公開されたメール基盤の脆弱性は 公表から悪用までの時間が短い**（本記録の一般的理解）—— **通常の変更管理の日程では間に合わない。**
    取るべき行動 **①公開面の資産（メール基盤・VPN・ファイル共有・管理画面）を 一覧にし、それぞれに「緊急適用の判断者」を決めておく。** **②緊急適用の手順を書き、年1回は実際に通してみる （通さない手順は本番で動かない）。** **③適用で業務が止まったときの代替手段を同時に決める**—— **メールが止まる前提の連絡手段を持っていないと、 適用の判断そのものが遅れる。**
  • メールボックスからの一括取得を、量で監視する
    **報道は、米当局が「この工作でコンピュータ数千台が侵害され、 文書とメールが大量に流出した」としたと伝えている**（出典2）—— **本記録はこの主張の一次資料を取得していない （「齟齬・沈黙の記録」参照）。** **侵害されたのが Microsoft Exchange Server であること**（出典1）**から、 収集の対象にメールが含まれたことは資料と整合する** （本記録の読み）。 **本記録の評価** —— **メール基盤では、認証が正当であれば大量の取得も「正常な操作」に見える。** **検知の手がかりは量と宛先である。**
    取るべき行動 **①メールボックスからの一括エクスポート・ 大量ダウンロード・委任アクセスの付与を記録する設定を確認する （既定で無効になっている製品がある）。** **②平常時の分布を取り、上位の分位点を超えたら警報を出す。** **③移行・訴訟対応の証跡保全など正規の大量操作を 事前に登録して例外にし、 登録の無い大量操作だけを警報の対象にする。**
  • 大量侵害キャンペーンの公表に対して、過去を遡って照合できる状態を作る
    **本件は侵入から4〜6年後に経緯が公表されている**（出典1・2）。 **被害組織の名前は公表されておらず （出典1は「米国内の大学1校と法律事務所1社」とするのみ）、 自組織が含まれていたかは自分で調べるしかない**（本記録の整理）。 **本記録の評価** —— **公表の時点で当時の記録が無ければ、 「分からない」で終わる。** **そして「分からない」は、 取引先や当局に説明するときに最も弱い答えである。**
    取るべき行動 **①公開面のアクセス記録・認証記録について、 「何年遡れるか」を実際に確認する （設定上の保持期間と、実際に引き出せるかは別である）。** **②遡れない期間がある場合、それを課題として記録する**—— **「記録が無い」ことを把握していれば、 公表時に即答できる。** **③照合の手順（どの記録に、どの指標を、どう当てるか）を あらかじめ書いておく。**
  • 脅威情報に CVE が書かれていないとき、推測で当てはめない
    **出典1は「Microsoft Exchange Server が動作するコンピュータの 脆弱性を悪用した」とするのみで、 CVE 番号を示していない**（本記録が確認）。 **出典2も示していない。** **本記録の方針** —— **HAFNIUM という名前から特定の CVE を当てはめることはできるが、 それは資料に無い情報を記録に加えることになる。** **「当てはめられる」ことと「資料がそう書いている」ことは別である。** **実務上の帰結** —— **推測で CVE を当てはめた記録は、 後から「どこまでが資料で、どこからが推測か」を 切り分けられなくなる。**
    取るべき行動 **①脅威情報を社内の台帳に取り込むとき、 「資料に書かれていた識別子」と 「自組織が推定した識別子」を別の欄に分ける。** **②推定した識別子には、推定の根拠と推定者を残す。** **③対処の優先度は、資料に書かれた識別子から決める**—— **推定に基づく対処は、推定が外れたときに空振りする。**
