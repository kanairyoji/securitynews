攻撃の経過

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

**勧告が示す手口の特徴は、「自動化された広い走査」と 「手作業による深い侵害」を1つの流れに繋いでいる点である** （出典1。本記録の整理）。 **勧告自身の要約** —— **「中国政府とつながる脅威アクターは、 Integrity Technology Group に支えられ、自動化された走査ツール、 大規模ボットネット、手作業による悪用技術を組み合わせて、 世界中の組織（米国の重要インフラ各分野を含む）を標的にし、 機微情報を窃取している」**（出典1。原文英語の要旨）。 **勧告は MITRE ATT&CK Enterprise 第19版に沿って段階を整理している**（出典1）。 **情報源は FBI の複数の捜査で回収・観測された技術的証拠である**（出典1）—— **ベンダーのテレメトリではなく捜査証拠が基礎にあるため、 道具の実物の名前（live700_v1.exe、office-cli、Curlc4.txt）まで 具体的に示されている。**

  1. 1. 偵察
    **公開されている走査ツールを多数使い、ネットワークとウェブアプリケーションの 脆弱性を探している**（出典1）—— **BBScan、dirsearch、Fscan、ksubdomain、masscan、NMAP、OneForAll、 ShuiZe、wpscan**（ATT&CK: T1595.002）。 **走査の対象ポートは 21（FTP）・22（SSH）・53（DNS）・80（HTTP）・ 443（HTTPS）・1080（SOCKS）に集中している**（出典1）。 **ウェブサイトを dirsearch で走査するときは、PHP と ASP（.NET）の ページを列挙しようとする**（出典1）。 **これに加えて自製の「MicroScan」がある**（2017年以降。Python 製の ウェブアプリで1,300本超のスクリプトを含む）。 **勧告の評価** —— **「GitHub で一般に見つかるオープンソースツールの 使用は、脅威アクターがより脆弱な標的を探す傾向にあることを示す」** （出典1。原文英語の要旨）。
  2. 2. 初期侵入
    **2つの経路が示されている**（出典1）。 **①既知の脆弱性の悪用** —— **2021年1月中旬以降、Python や Go で 書かれた悪用コードを基にしたコマンドライン実行形式の道具で、 被害組織のネットワークとクラウドサービスへ侵入している** （ATT&CK: T1059.006）。 **悪用の成功が確認された脆弱性8件** —— **CVE-2014-6278（GNU Bash）、CVE-2015-3306（ProFTPD）、 CVE-2015-5477（ISC BIND）、CVE-2016-3081（Apache Struts）、 CVE-2019-11510（Pulse Connect Secure）、CVE-2021-22205（GitLab）、 CVE-2021-3199（ONLYOFFICE DocumentServer）、 CVE-2023-22894（Strapi）**（出典1）。 **②クロスサイトスクリプティング（XSS）** —— **JavaScript （ATT&CK: T1059.007）と HTML を使って XSS 攻撃を実行する。** **XSS に脆弱な第三者のアプリケーションを使ってウェブページの内容を 書き換え（ATT&CK: T1189）、別の被害者を標的にする**（出典1）。 **③Microsoft Exchange サーバに対するパスワードスプレー**（出典1）。
  3. 3. 実行
    **XSS ペイロードの中身が、捜査で回収されている**（出典1）。 **動作の順序** —— **①脆弱なウェブサイト上で JavaScript として実行されると、 ページの内容を書き換えて利用者名とパスワードの入力欄を表示させ、 資格情報を収集する。②利用者が何らかの利用者名とパスワードを 入力すると、パスワード付きの .zip ファイルをダウンロードする リンクが生成される。③.zip の中身は XSS ペイロードに 符号化して埋め込まれたバイト列から復元され、 実行形式ファイル `live700_v1.exe` を含む。** **④`live700_v1.exe` を解析すると、 `DiagTrack.exe` という名前のプロセスを開始する**—— **これは正規の Windows ソフトウェアと同じ名前である** （ATT&CK: T1036.003 名前の偽装）。 **⑤`DiagTrack.exe` は HTTP プロトコル上で暗号化された通信を確立する** （出典1）。
  4. 4. 永続化
    **SoftEther VPN のクライアントを被害端末にインストールして、 遠隔アクセスを維持し、指令・制御（C2）通信を隠している**（出典1）。 **手口の具体** —— **①インストーラを PowerShell・curl・wget で ダウンロードする。②起動時に自動で再接続するよう設定する。 ③インストーラに `conhost.exe` または `dllhost.exe` という名前を付け、 正規の Windows バイナリに似せる**（出典1）。 **本記録の整理** —— **正規の VPN ソフトウェアを永続化の手段に 使っているため、マルウェアの検知では引っかかりにくい**（本記録の評価）。
  5. 5. 認証情報アクセス
    **2つの手口が示されている**（出典1）。 **①格納型 XSS による資格情報の収集** —— **ウェブページの内容を 書き換えて利用者名とパスワードの入力欄を表示させ、入力された値を 取得する**（execution 段階の記述を参照）。 **②Microsoft Exchange サーバに対するパスワードスプレー**（出典1）—— **多数のアカウントに対して少数のパスワードを試す形で、 アカウントロックを回避しながら有効な資格情報を探す手口である** （本記録の補足説明）。 **窃取した資格情報は、後述の `office-cli` の設定ファイルに 書き込まれ、Outlook 365 のメールボックスへの継続的なアクセスに 使われている**（出典1）。
  6. 6. 収集
    **メールの持ち出しに特化した2つの道具が示されている**（出典1）。 **①`office-cli`** —— **資格情報を含む設定ファイルを使って Microsoft Outlook 365 のメールボックスへ継続的にアクセスし、 期間を区切ってメールを持ち出す。** **②`Curlc4.txt`** —— **PHP で書かれたスクリプト。 Microsoft EWS（Exchange Web Services）API を使ってメールを取得し、 圧縮して（場合により RC4 または AES-128-CBC で暗号化して） 遠隔のサーバへアップロードする**（出典1）。 **収集したデータは、検知を避けるため当たり障りのない ファイル名で待機させている**（出典1）。
  7. 7. 持ち出し
    **圧縮・暗号化したメールのかたまりを、遠隔のサーバへアップロードしている** （出典1）—— **暗号化には RC4 または AES-128-CBC が使われる場合がある。** **被害** —— **勧告は、メール窃取の被害者として 東南アジアの政府機関・法執行機関・医療機関・宗教団体を挙げている**（出典1）。 **勧告はまた、スクリプトを使ってメールと資格情報を 持ち出していると要約している**（出典1）。 **本記録の整理** —— **本件の最終目的は、破壊や恐喝ではなく 機微情報の窃取である**（出典1の表題と要約から）。

名指しされたのは攻撃グループではなく、攻撃を支える営利企業だった帰属出典 [1] [2]

本勧告の特徴は、帰属の単位である。

対象は Integrity Technology Group（Integrity Tech）——中国に拠点を置く営利企業で、中国政府とつながりを持つ、とされる（出典1。原文英語の要旨）。攻撃グループの名前ではない。

勧告が挙げる同社の関与は4つの形を取る（出典1・2）—— ①攻撃用ツールの取得・開発（使用と販売の両方）、②インフラの取得とホスティング、③世界各地の被害組織のネットワークの侵害、④中国のサイバー生態系全体への寄与。

②と③が同じ主体の中にあることが、この名指しの意味である（本記録の整理）—— 道具を作って売る会社が、自ら侵害も実行している。 「攻撃者」と「攻撃インフラの提供者」を分けて考える前提が成り立たない。

既知の呼称との関係について、勧告は2つの留保を付けている。

留保① —— 「Integrity Tech に支えられた脅威アクターはFlax Typhoon、Ethereal Panda、Red Juliett などとして公に知られる活動と整合する TTP を用いる。ただしこれらの脅威アクターはIntegrity Tech と関連しない活動も行っている可能性がある」（出典1。原文英語の要旨）。

留保② —— 「セキュリティ企業は脅威アクターの追跡と帰属に異なる手法を用いており、これらが米国政府の手法と理解に対してすべての活動について1対1で対応するとは限らない」（出典1。原文英語の要旨）。

読み方 —— 本件を「Flax Typhoon の勧告」と呼ぶことは、勧告自身が否定している（本記録の整理）。ベンダーの呼称と当局の分類は別の体系であり、同一視すると帰属の確度を語れなくなる。

一方、公表されていないことが1つある —— 「中国政府とつながりを持つ」の具体的な形である。 契約関係か、出資か、人員の往来か、指示系統かを区別できる記述は勧告にも英 NCSC の発表にも無い（出典1・2。本記録が確認）。帰属の確度を語るうえで、この欠落は小さくない。

本件は2024年9月の公表の延長線上にある（出典2）—— 当時、英 NCSC と国際パートナーは Integrity Tech を「Flax Typhoon が利用した大規模ボットネットの運用者」として公表した。 2026年の今回は、名指しの範囲が「ボットネットの運用者」から「ツール・インフラ・侵害の実行を含む生態系の一部」へ広がっている（本記録の整理）。英国はその間（2025年）に、同社を制裁対象に指定している（出典2）。

この勧告で最も実務に直結するのは、脆弱性の一覧である。

勧告は、悪用の成功が確認された脆弱性8件を列挙している（出典1）——

この一覧が示していること（本記録の評価）——

①攻撃側は新しい欠陥を見つける必要がなかった。自製の走査アプリ「MicroScan」は1,300本超のスクリプトを持ち（出典1）、2017年から運用されている。広く走査して、直っていないものを見つける。 勧告自身が「GitHub で一般に見つかるオープンソースツールの使用は、脅威アクターがより脆弱な標的を探す傾向にあることを示す」と評している（出典1。原文英語の要旨）。

②製品の並びに特徴がある。 ProFTPD・ISC BIND・Apache Struts・GitLab・ONLYOFFICE DocumentServer・Strapi —— 「業務の中心ではないが誰かが立てた」種類のソフトウェアが多い（本記録の評価）。これらは資産台帳に載っていない可能性が高く、載っていなければ更新の対象にもならない。

③したがって、必要な作業は「更新を当てる」ではなく「台帳に無い資産を見つける」である（本記録の評価）。こちらのほうが手間がかかる。

MicroScan が標的にしたソフトウェアとして、勧告は別にOpenSSL・Oracle WebLogic・Rejetto・WordPress・Juniper ScreenOS・Jenkins・Apache Struts を挙げている（出典1）—— 走査の対象は、悪用成功が確認された8件よりはるかに広い。

正規のソフトウェアと正規のプロセス名を使うため、悪性のものを探す検知では見つからない原因・手口出典 [1]

勧告が示した手口の一貫した性質は、「正規のものに見せる」ことである（本記録の整理）。

①永続化は、正規の VPN ソフトウェアで行う。 SoftEther VPN のクライアントを被害端末にインストールし、遠隔アクセスの維持と C2 通信の隠蔽に使う（出典1）。インストーラは PowerShell・curl・wget でダウンロードし、起動時に自動再接続するよう設定する。 ファイル名は conhost.exe または dllhost.exe ——いずれも Windows の正規バイナリ名である（出典1）。

②実行は、正規の Windows プロセス名で行う。 XSS ペイロードから復元される live700_v1.exe は、DiagTrack.exe という名前のプロセスを開始する—— 正規の Windows ソフトウェアと同名である（ATT&CK: T1036.003 名前の偽装。出典1）。DiagTrack.exe は HTTP プロトコル上で暗号化された通信を確立する（出典1）。

③持ち出しは、正規の API で行う。 Curlc4.txt（PHP スクリプト）は Microsoft EWS（Exchange Web Services）API を使ってメールを取得し、圧縮して（場合により RC4 または AES-128-CBC で暗号化して）遠隔サーバへアップロードする（出典1）。office-cli は、資格情報を含む設定ファイルを使ってOutlook 365 のメールボックスへ継続的にアクセスし、期間を区切ってメールを持ち出す（出典1）。持ち出したデータは、検知を避けるため当たり障りのないファイル名で待機させる（出典1）。

ここから導かれる検知の方針（本記録の評価）——

「悪性のものを探す」検知は効きにくい。 SoftEther VPN は正規の製品であり、conhost.exe・dllhost.exe・DiagTrack.exe は正規の名前であり、EWS は正規の API である。名前で探せば誤検知が出る。

効く形は「許可していないものがある」という探し方である（本記録の評価）—— ①許可していないリモートアクセス・VPN ソフトウェアが入っていないか（資産の側から確認する）。 ②正規のプロセス名が正規でない配置先から起動していないか（名前ではなくパスと署名で見る）。 ③EWS など古い API 経由のメールボックスアクセスが業務で必要かどうか（不要なら閉じる）。

いずれも「許可リストを持っている」ことが前提になる（本記録の整理）—— 勧告が挙げた監視項目（環境に元からある道具の悪用、予期しない Active Directory の複製、異常な外向き通信。出典1）も、平常時の基準値が無ければ判別できない。

日本の関わりは「署名機関」と「報告先の提示」であり、国内被害の記載は無い未確定事項出典 [1] [2] [7]

本記録が日本との関わりとして確認できたのは、2点だけである（本記録の明示）。

①日本の警察庁（National Police Agency, NPA）と国家サイバー統括室（National Cybersecurity Office, NCO）が、勧告の署名機関に名を連ねている（出典1。本記録が確認）。署名機関は全10機関・7か国で、Five Eyes（米英豪加新）に日本とスペインが加わった構成である。

②勧告が、日本の組織に対する報告経路を示している —— NCO への電子メール、または警察庁のウェブ窓口（出典1）。

以下は公表されていない。

勧告が挙げた被害の地理的範囲は「米国の重要インフラ各分野」および「東南アジア・アフリカ・北米の組織」であり、日本は含まれていない（出典1。本記録が確認）。メール窃取の被害に限ると、東南アジアの政府機関・法執行機関・医療機関・宗教団体が挙げられている（出典1）。日本国内の被害組織・件数・標的にされたかどうかは、いずれも記載が無い。

本記録はこれを「日本が標的にされた」と書かない（本記録の明示）—— 署名機関として名を連ねたことから国内で何らかの観測があったと推測することはできるが、推測は書かない。 同時に「日本に被害が無い」とも書かれていない。

窃取したメールを第三者に見せるポータルが運用されていた評価・解釈

本記録が、本件の構造を他の国家支援型の作戦と分ける1点と見るものです。

勧告の記述 —— 「脅威アクターは、窃取したメールの内容への第三者アクセスを提供する独自のウェブアプリケーションを維持している」（出典1。原文英語の要旨）。

「FBI は、脅威アクターが被害組織のメールアカウントを標的にするために使用していた、アーカイブされたメールデータベースを回収した。脅威アクターはアカウントの資格情報を収集し、オンプレミスのシステムとクラウドのサービスの両方から被害者のメールデータを持ち出している」（出典1・6。原文英語の要旨）。

「メールデータ窃取の被害として観測されたのは、東南アジアに所在する政府機関・法執行機関・医療システム・宗教団体である。一部の事例では、脅威アクターは持ち出したデータへのアクセスを中国・厦門（Xiamen）のIPアドレスからのみに制限していた」（出典1・6。原文英語）。

FBI の押収に関する宣誓供述書からは、規模の一端が分かります（出典5）—— FishHub に関連するサーバー上で、20を超える組織に属するデータとファイルが発見され、そのうち6校は台湾の大学でした。

本記録が読者に伝えたいのは、構造のほうです（本記録の整理）。

窃取したメールが、窃取した主体の外にいる第三者に提供される仕組みがありました。 「攻撃者」「道具の提供者」「情報の受益者」が、別の主体として並んでいるということです。

既存の節で整理したとおり、Integrity Tech は①ツールの取得・開発、②インフラの取得とホスティング、③侵害の実行、を同じ主体の中に持っていました（出典1）。ここに④窃取情報の第三者への提供が加わります。

第三者が誰なのかは公表されていません（未確定事項を参照）—— 政府機関か、別の攻撃グループか、商業的な顧客か。 有償だったのかも、ポータルの運用期間も、第三者が何件のメールを参照したかも示されていません。 本記録は推定しません。

厦門のIPアドレスへの制限という記述の読み方（本記録の評価）。

アクセス制御がかかっていたということは、ポータルが「誰でも見られる掲示」ではなく「特定の相手に見せる仕組み」だったということです。 恐喝のための公開とは性質が違います。

防御側にとっての実務的な意味（本記録の判断）。

メールの持ち出しが成立した場合、被害の範囲を「攻撃者1者が見た」と想定するのは不足です。 本件では、持ち出されたデータが別の主体に提供される経路が確認されています。 影響評価・顧客への通知・法的な対応の前提を、「受益者が複数いる可能性」の側に置く必要があります。

    取るべき行動 **①認証失敗の集計軸を「どの送信元が、いくつの異なるアカウントに 試したか」に変える。** 閾値は平常時の実測値から決める。 **②除外対象を先に定義する** —— メールゲートウェイ・モバイル管理基盤など、 正規に多数のアカウントを扱う接続元がある。 **③MFA に対応できないアカウント（古いクライアント・ 連携用アカウント）の一覧を作り、 そこを条件付きアクセスや接続元の限定で守る。** **例外の一覧を持たないと、例外そのものが攻撃の対象になる。**
  • メールボックスへの大量アクセスを、累積で見る仕組みを置く
    **`office-cli` は「期間をまたいでメールを持ち出す」とされている** （出典1）—— **1回あたりは不自然でなくても、期間を区切って繰り返す形は 累積では大量取得になる**（本記録の評価）。 **`Curlc4.txt` は EWS API を使う**（出典1）—— **業務で EWS を使っていない組織であれば、 この経路を閉じるだけで持ち出しの手段を1つ減らせる。** **持ち出したデータは当たり障りのないファイル名で待機させるため、 ファイル名での検知は効かない**（出典1）。
    取るべき行動 **①Microsoft 365 のメールボックス監査記録を有効にし、 保存期間を確認する。** 無効なら、発見時に範囲を特定できない。 **②EWS 経由のアクセスの有無と利用元を棚卸しし、 不要なら無効化する。** 会議室予約・メール連携の仕組みが 依存している場合があるため、無効化の前に利用実態を確認する。 **③メールボックスからの取得件数を、1回ではなく 期間（週・月）の累積で集計し、閾値を設ける。** **副作用** —— **移行作業・訴訟対応の証拠保全などで 正規の大量取得が発生する。** 事前の届け出と照合する運用が要る。
  • 自組織のウェブアプリケーションが「他の被害者を狙う踏み台」に なっていないかという観点で XSS を扱う
    **本件の XSS は、自組織が被害を受けるだけの話ではない**（出典1）—— **勧告は「XSS に脆弱な第三者のアプリケーションを使って ウェブページの内容を書き換え、別の被害者を標的にする」と している**（原文英語の要旨。ATT&CK: T1189）。 **具体的には、ページを書き換えて利用者名とパスワードの入力欄を 表示させ、資格情報を収集する。入力すると、 パスワード付き .zip（実行形式 `live700_v1.exe` を含む）の ダウンロードリンクが生成される**（出典1）。 **本記録の整理** —— **自組織のサイトが、自組織とは無関係の 第三者を騙す場所として使われる。** **「自社に被害が無いから優先度が低い」という判断が成り立たない構造である。**
    取るべき行動 **①外部に公開しているウェブアプリケーションについて、 利用者入力の無害化（出力時のエスケープ）が 全ての出力経路で行われているかを確認する。** 勧告の主要な推奨事項の第2項に対応する（出典1）。 **②格納型 XSS を特に確認する。** 本件は 「ページの内容を書き換えて入力欄を表示させる」形であり、 保存された値が他の利用者に表示される経路が問題になる。 **③自社開発でない製品については、提供元の対応状況を確認し、 対応が無い場合は公開範囲の限定を検討する。**

自組織に当てはまるか

該当する項目があれば、この事案と同じ構図が自組織でも成立しうることを意味します。
観点自社に当てはまるか該当する場合に何が起きうるか
運用・監視□ インターネットに面した資産の一覧を、台帳ではなく外部からの実測で 確認する仕組みを持っていない**勧告が挙げた悪用成功済みの脆弱性8件は、すべて既知であり、 ProFTPD・ISC BIND・Apache Struts・GitLab・ONLYOFFICE DocumentServer・ Strapi など「業務の中心ではないが誰かが立てた」種類の製品が多い** （出典1。本記録の評価）—— **これらが直っていないのは、台帳に載っていないからである可能性が高い。** **攻撃側は1,300本超のスクリプトを持つ走査基盤を2017年から 運用しており**（出典1）、**台帳の穴を見つける能力は組織側より高い。** 該当する場合は、脆弱性の対応率ではなく台帳の網羅性が課題になる。
認証・認可□ Microsoft Exchange・ウェブメール・VPN のアカウントに 多要素認証が適用されていない、または適用できない例外が存在する**本件では Exchange サーバに対するパスワードスプレーと、 格納型 XSS による資格情報の収集の両方が使われている**（出典1）—— **さらに、窃取した資格情報を設定ファイルに書き込んで Outlook 365 のメールボックスへ継続的にアクセスする道具 （`office-cli`）まで用意されている。** **パスワードだけで入れる作りが、この道具の前提になっている。** **勧告も多要素認証を主要な推奨事項に挙げ、ウェブメール・VPN・ 重要システムのアカウントを特に挙げている**（出典1）。 該当する場合は、例外の一覧を持ち、そこを別の手段で守る必要がある。
システム構成□ Microsoft 365 のメールボックス監査記録が有効になっていない、 または EWS など古い API 経由のアクセスを棚卸ししていない**本件の持ち出しは、EWS API を使う PHP スクリプト（`Curlc4.txt`）と、 Outlook 365 へ継続的にアクセスする道具（`office-cli`）で行われる** （出典1）—— **1回の大量ダウンロードではなく、期間を区切った継続的なアクセスである。** **持ち出したデータは当たり障りのないファイル名で待機させるため、 ファイル名での検知は効かない**（出典1）。 **監査記録が無ければ、発見時に「どこからどこまで持ち出されたか」を 特定できない。** 該当する場合は、発見時の範囲特定ができない状態にあると認識する必要がある。
運用・監視□ 業務で許可しているリモートアクセス・VPN 製品の一覧が無い （インストール済みソフトウェアと照合できない）**本件の永続化は、正規の VPN ソフトウェア（SoftEther VPN）の インストールで成立している**（出典1）—— **インストーラは `conhost.exe`・`dllhost.exe` という Windows の正規バイナリ名で設置され、 PowerShell・curl・wget でダウンロードされる。** **マルウェアの検知では引っかかりにくいが、 「許可リストに無いリモートアクセス製品が入っている」という形では 確実に見つかる**（本記録の評価）—— **ただし許可リストが無ければ、この判別ができない。** 該当する場合は、許可リストの作成が検知の前提作業になる。
システム構成□ 外部に公開しているウェブアプリケーションがあり、 格納型クロスサイトスクリプティング（XSS）の検査を定期的に行っていない**本件の XSS は、自組織が被害を受けるだけでなく、 自組織のサイトが他の被害者を狙う踏み台として使われる形を取る** （出典1。ATT&CK: T1189）—— **ページを書き換えて利用者名とパスワードの入力欄を表示させ、 資格情報を収集し、実行形式を含む .zip のダウンロードリンクを生成する。** **「自社に被害が無いから優先度が低い」という判断が成り立たない。** **勧告の主要な推奨事項の第2項が入力の無害化である**（出典1）。 該当する場合は、出力経路全体のエスケープの確認が課題になる。
体制・契約□ 当局の勧告を受けて「過去の侵害を探す」作業を、期間・対象・担当を 決めた1回の作業として定義する仕組みが無い**勧告が防御側に求めている第1の行動は「この活動による侵害の可能性を 探索すること」である**（出典1。原文英語の要旨）—— **活動の開始時期は2021年1月中旬以降（走査基盤は2017年以降）とされる一方、 終期については何も述べられていない**（本記録が確認）。 **本件は正規のソフトウェアと正規の名前を使うため、 既存の検知には引っかからなかった前提で探す必要がある**（本記録の評価）。 **「注意喚起を共有した」で終わると、探索は行われない。** 該当する場合は、探索の定義（期間・対象・担当・完了の基準）と、 保有ログの保存期間の確認が必要になる。
