攻撃の経過

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

**勧告が示す手口の特徴は、「自動化された広い走査」と 「手作業による深い侵害」を1つの流れに繋いでいる点である** （出典1。本記録の整理）。 **勧告自身の要約** —— **「中国政府とつながる脅威アクターは、 Integrity Technology Group に支えられ、自動化された走査ツール、 大規模ボットネット、手作業による悪用技術を組み合わせて、 世界中の組織（米国の重要インフラ各分野を含む）を標的にし、 機微情報を窃取している」**（出典1。原文英語の要旨）。 **勧告は MITRE ATT&CK Enterprise 第19版に沿って段階を整理している**（出典1）。 **情報源は FBI の複数の捜査で回収・観測された技術的証拠である**（出典1）—— **ベンダーのテレメトリではなく捜査証拠が基礎にあるため、 道具の実物の名前（live700_v1.exe、office-cli、Curlc4.txt）まで 具体的に示されている。**

  1. 1. 偵察
    **公開されている走査ツールを多数使い、ネットワークとウェブアプリケーションの 脆弱性を探している**（出典1）—— **BBScan、dirsearch、Fscan、ksubdomain、masscan、NMAP、OneForAll、 ShuiZe、wpscan**（ATT&CK: T1595.002）。 **走査の対象ポートは 21（FTP）・22（SSH）・53（DNS）・80（HTTP）・ 443（HTTPS）・1080（SOCKS）に集中している**（出典1）。 **ウェブサイトを dirsearch で走査するときは、PHP と ASP（.NET）の ページを列挙しようとする**（出典1）。 **これに加えて自製の「MicroScan」がある**（2017年以降。Python 製の ウェブアプリで1,300本超のスクリプトを含む）。 **勧告の評価** —— **「GitHub で一般に見つかるオープンソースツールの 使用は、脅威アクターがより脆弱な標的を探す傾向にあることを示す」** （出典1。原文英語の要旨）。
  2. 2. 初期侵入
    **2つの経路が示されている**（出典1）。 **①既知の脆弱性の悪用** —— **2021年1月中旬以降、Python や Go で 書かれた悪用コードを基にしたコマンドライン実行形式の道具で、 被害組織のネットワークとクラウドサービスへ侵入している** （ATT&CK: T1059.006）。 **悪用の成功が確認された脆弱性8件** —— **CVE-2014-6278（GNU Bash）、CVE-2015-3306（ProFTPD）、 CVE-2015-5477（ISC BIND）、CVE-2016-3081（Apache Struts）、 CVE-2019-11510（Pulse Connect Secure）、CVE-2021-22205（GitLab）、 CVE-2021-3199（ONLYOFFICE DocumentServer）、 CVE-2023-22894（Strapi）**（出典1）。 **②クロスサイトスクリプティング（XSS）** —— **JavaScript （ATT&CK: T1059.007）と HTML を使って XSS 攻撃を実行する。** **XSS に脆弱な第三者のアプリケーションを使ってウェブページの内容を 書き換え（ATT&CK: T1189）、別の被害者を標的にする**（出典1）。 **③Microsoft Exchange サーバに対するパスワードスプレー**（出典1）。
  3. 3. 実行
    **XSS ペイロードの中身が、捜査で回収されている**（出典1）。 **動作の順序** —— **①脆弱なウェブサイト上で JavaScript として実行されると、 ページの内容を書き換えて利用者名とパスワードの入力欄を表示させ、 資格情報を収集する。②利用者が何らかの利用者名とパスワードを 入力すると、パスワード付きの .zip ファイルをダウンロードする リンクが生成される。③.zip の中身は XSS ペイロードに 符号化して埋め込まれたバイト列から復元され、 実行形式ファイル `live700_v1.exe` を含む。** **④`live700_v1.exe` を解析すると、 `DiagTrack.exe` という名前のプロセスを開始する**—— **これは正規の Windows ソフトウェアと同じ名前である** （ATT&CK: T1036.003 名前の偽装）。 **⑤`DiagTrack.exe` は HTTP プロトコル上で暗号化された通信を確立する** （出典1）。
  4. 4. 永続化
    **SoftEther VPN のクライアントを被害端末にインストールして、 遠隔アクセスを維持し、指令・制御（C2）通信を隠している**（出典1）。 **手口の具体** —— **①インストーラを PowerShell・curl・wget で ダウンロードする。②起動時に自動で再接続するよう設定する。 ③インストーラに `conhost.exe` または `dllhost.exe` という名前を付け、 正規の Windows バイナリに似せる**（出典1）。 **本記録の整理** —— **正規の VPN ソフトウェアを永続化の手段に 使っているため、マルウェアの検知では引っかかりにくい**（本記録の評価）。
  5. 5. 認証情報アクセス
    **2つの手口が示されている**（出典1）。 **①格納型 XSS による資格情報の収集** —— **ウェブページの内容を 書き換えて利用者名とパスワードの入力欄を表示させ、入力された値を 取得する**（execution 段階の記述を参照）。 **②Microsoft Exchange サーバに対するパスワードスプレー**（出典1）—— **多数のアカウントに対して少数のパスワードを試す形で、 アカウントロックを回避しながら有効な資格情報を探す手口である** （本記録の補足説明）。 **窃取した資格情報は、後述の `office-cli` の設定ファイルに 書き込まれ、Outlook 365 のメールボックスへの継続的なアクセスに 使われている**（出典1）。
  6. 6. 収集
    **メールの持ち出しに特化した2つの道具が示されている**（出典1）。 **①`office-cli`** —— **資格情報を含む設定ファイルを使って Microsoft Outlook 365 のメールボックスへ継続的にアクセスし、 期間を区切ってメールを持ち出す。** **②`Curlc4.txt`** —— **PHP で書かれたスクリプト。 Microsoft EWS（Exchange Web Services）API を使ってメールを取得し、 圧縮して（場合により RC4 または AES-128-CBC で暗号化して） 遠隔のサーバへアップロードする**（出典1）。 **収集したデータは、検知を避けるため当たり障りのない ファイル名で待機させている**（出典1）。
  7. 7. 持ち出し
    **圧縮・暗号化したメールのかたまりを、遠隔のサーバへアップロードしている** （出典1）—— **暗号化には RC4 または AES-128-CBC が使われる場合がある。** **被害** —— **勧告は、メール窃取の被害者として 東南アジアの政府機関・法執行機関・医療機関・宗教団体を挙げている**（出典1）。 **勧告はまた、スクリプトを使ってメールと資格情報を 持ち出していると要約している**（出典1）。 **本記録の整理** —— **本件の最終目的は、破壊や恐喝ではなく 機微情報の窃取である**（出典1の表題と要約から）。

対象は Integrity Technology Group（Integrity Tech）——中国に拠点を置く営利企業で、中国政府とつながりを持つ、とされる（出典1。原文英語の要旨）。攻撃グループの名前ではない。

②と③が同じ主体の中にあることが、この名指しの意味である（本記録の整理）—— 道具を作って売る会社が、自ら侵害も実行している。 「攻撃者」と「攻撃インフラの提供者」を分けて考える前提が成り立たない。

既知の呼称との関係について、勧告は2つの留保を付けている。

留保① —— 「Integrity Tech に支えられた脅威アクターはFlax Typhoon、Ethereal Panda、Red Juliett などとして公に知られる活動と整合する TTP を用いる。ただしこれらの脅威アクターはIntegrity Tech と関連しない活動も行っている可能性がある」（出典1。原文英語の要旨）。

読み方 —— 本件を「Flax Typhoon の勧告」と呼ぶことは、勧告自身が否定している（本記録の整理）。ベンダーの呼称と当局の分類は別の体系であり、同一視すると帰属の確度を語れなくなる。

③したがって、必要な作業は「更新を当てる」ではなく「台帳に無い資産を見つける」である（本記録の評価）。こちらのほうが手間がかかる。

正規のソフトウェアと正規のプロセス名を使うため、悪性のものを探す検知では見つからない原因・手口出典 [1]

勧告が示した手口の一貫した性質は、「正規のものに見せる」ことである（本記録の整理）。

①永続化は、正規の VPN ソフトウェアで行う。 SoftEther VPN のクライアントを被害端末にインストールし、遠隔アクセスの維持と C2 通信の隠蔽に使う（出典1）。インストーラは PowerShell・curl・wget でダウンロードし、起動時に自動再接続するよう設定する。 ファイル名は conhost.exe または dllhost.exe ——いずれも Windows の正規バイナリ名である（出典1）。

②実行は、正規の Windows プロセス名で行う。 XSS ペイロードから復元される live700_v1.exe は、DiagTrack.exe という名前のプロセスを開始する—— 正規の Windows ソフトウェアと同名である（ATT&CK: T1036.003 名前の偽装。出典1）。DiagTrack.exe は HTTP プロトコル上で暗号化された通信を確立する（出典1）。

③持ち出しは、正規の API で行う。 Curlc4.txt（PHP スクリプト）は Microsoft EWS（Exchange Web Services）API を使ってメールを取得し、圧縮して（場合により RC4 または AES-128-CBC で暗号化して）遠隔サーバへアップロードする（出典1）。office-cli は、資格情報を含む設定ファイルを使ってOutlook 365 のメールボックスへ継続的にアクセスし、期間を区切ってメールを持ち出す（出典1）。持ち出したデータは、検知を避けるため当たり障りのないファイル名で待機させる（出典1）。

ここから導かれる検知の方針（本記録の評価）——

「悪性のものを探す」検知は効きにくい。 SoftEther VPN は正規の製品であり、conhost.exe・dllhost.exe・DiagTrack.exe は正規の名前であり、EWS は正規の API である。名前で探せば誤検知が出る。

効く形は「許可していないものがある」という探し方である（本記録の評価）—— ①許可していないリモートアクセス・VPN ソフトウェアが入っていないか（資産の側から確認する）。 ②正規のプロセス名が正規でない配置先から起動していないか（名前ではなくパスと署名で見る）。 ③EWS など古い API 経由のメールボックスアクセスが業務で必要かどうか（不要なら閉じる）。

いずれも「許可リストを持っている」ことが前提になる（本記録の整理）—— 勧告が挙げた監視項目（環境に元からある道具の悪用、予期しない Active Directory の複製、異常な外向き通信。出典1）も、平常時の基準値が無ければ判別できない。
