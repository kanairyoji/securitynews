公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

**本件は実際の被害事例ではなく、ベンダーが公表した脆弱性の記録である** （本記録の位置づけ）。 **HPE は公表時点で、脆弱性に関する議論やエクスプロイトコードの公開を 把握していないとしている**（出典3）。 **以下の chain は、報道が示した個別の脆弱性の性質 （認証回避・デシリアライズによるコード実行・SQL インジェクション・ パストラバーサル）から、本記録が段階を立てたものである**（出典3）—— **実際に観測された攻撃の記録ではない。** **攻撃に必要なものは、報道の記述に基づけば1つである** —— **ClearPass のウェブ管理インタフェースまたは API に ネットワーク経由で到達できること**（出典3）。 **認証は、報道が挙げた3件（CVE-2026-76750・76752・79796）では 不要とされている。**

    **攻撃者は、到達可能な ClearPass の管理インタフェース （ウェブ管理画面・API）を探す**（出典3の記述から本記録が 構成した段階）。 **本記録の整理** —— **ClearPass の管理面は、運用の都合で 社内の広いセグメントから見えている構成になりやすい** （本記録の評価）—— **ネットワーク運用者・ヘルプデスク・監視システムが 日常的に触る画面であるため。** **HPE が回避策として示したのが「管理インタフェースを専用の L2 セグメント／VLAN に閉じる」ことであるのは、 この状態が一般的であることの裏返しと読める**（本記録の読み。 回避策の文言は二次情報。齟齬1）。

    **認証を必要としない脆弱性で管理面に入る**（出典3）—— **①CVE-2026-76752：ウェブ管理インタフェースおよび API の認証回避。 「認証を必要とすることなく、管理者権限を取得されるおそれがある」 （出典3）。②CVE-2026-79796：同様に認証を回避できる。 ③CVE-2026-76750：信頼できないデータのデシリアライズ処理に起因し、 認証を必要とせず遠隔から任意のコードを実行されるおそれがある。** **本記録の整理** —— **①②は「管理者としてログインした状態」を作る経路、 ③は「サーバ上でコードを動かす」経路であり、到達点が違う。** **どちらから入っても、以後の段階は同じ場所に合流する。**

    **本段階は公表資料に記載が無く、本記録が ClearPass の 機能から構成したものである**（本記録の明示）—— **公表資料は、管理権限の取得後に何が取られ得るかを述べていない** （本記録が確認）。 **本記録の評価** —— **NAC の方針決定点は、その役割上 次のものを保持している。** **①ネットワーク機器との間の RADIUS／TACACS+ の共有秘密、 ②利用者ディレクトリ（Active Directory・LDAP）への 問い合わせ用アカウント、③端末のオンボーディングで 発行した証明書と、その発行に使う鍵。** **これらは、ClearPass 自体の外側（スイッチ・無線コントローラ・ ディレクトリ）へ手を伸ばすための材料になる。**

    **本段階は公表資料に記載が無く、本記録が ClearPass の役割から 構成したものである**（本記録の明示）。 **本記録の評価** —— **NAC の方針決定点を握られた場合に起こり得る ことは2つある。** **①接続の可否と割り当て VLAN を書き換えられる** —— **本来は検疫 VLAN に落ちるべき端末を業務 VLAN に通す、 あるいは正当な端末を一律に拒否して業務を止める。** **②認証の記録を書き換えられる** —— **誰がいつどの端末で接続したかの記録が、 事後の調査の土台を失う。** **CVE-2026-76750 のようなサーバ上でのコード実行が成立する場合は、 ①②の両方が同時に可能になる。**

NAC が落ちると、以後の端末認証はすべて攻撃者の判断になる評価・解釈

以下は本記録の評価であり、公表資料に記載のある内容ではない（本記録の明示）。

ClearPass Policy Manager は、ネットワークアクセス制御の方針決定点（policy decision point）である。 有線のスイッチ・無線のコントローラ・VPN 装置が接続要求を受けると、RADIUS で ClearPass に問い合わせ、ClearPass が「通す／通さない／どの VLAN に入れる」を返す。

この構造には、他の業務システムと違う性質がある（本記録の整理）——

①侵害されたときの影響が「データ」ではなく「以後の判断」に出る。 顧客データベースが侵害されれば、失われるのは中にあるデータである。 方針決定点が侵害されると、失われるのは「これから先の全ての接続可否の判断」である。 検疫 VLAN に落ちるべき端末を業務 VLAN に通す設定変更は、データの持ち出しを伴わないため、データ漏えいを前提とした検知には引っかからない。

②保持している資格情報が、横に広がるための材料そのものである。 方針決定点はその役割上、次のものを持たざるを得ない —— ネットワーク機器との RADIUS／TACACS+ の共有秘密、利用者ディレクトリへの問い合わせ用アカウント、端末のオンボーディングで発行した証明書とその鍵。 これは「ClearPass が侵害された」で終わる話ではなく、スイッチ・無線コントローラ・Active Directory へ手を伸ばす足場になる。

③記録そのものが同じ装置の中にある。 誰がいつどの端末で接続したかという記録は、侵害の調査に使う一次情報である。 それを侵害された装置の中に置いたままにしていると、調査の土台が消える。

本記録が実務の結論として置くのは1点である —— NAC の方針決定点は「業務システム」ではなく「認証基盤」として扱う。 到達性の制限、ログの外部転送、保持する資格情報の棚卸しを、ディレクトリサーバや証明書発行局と同じ水準で設計する。
