CISA は2026年10月8日、電力系統の同期位相計測（PMU）データを集約する オープンソース製品 Grid Protection Alliance openPDC と、 時系列データ保管の openHistorian について、6件の脆弱性を扱う ICS 勧告 ICSA-26-281-02 を公表した。サービスコンソールの デシリアライズ（CVE-2026-100730・CVSSv3.1 9.8）は、Windows 認証を 使っていない構成では認証なしの遠隔攻撃者がサービスアカウント権限で コードを実行できる。公開 Docker イメージには変更を強制されない 固定の管理者資格情報があり（CVE-2026-105278・同 9.8）、 修正の予定は無いとされた。データ公開インタフェースの 既定値の修正は新規導入にのみ適用され、更新した既存環境には 引き継がれない。悪用は確認されていない

攻撃の経過

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

**本件は実際の被害事例ではなく、当局が公表した脆弱性の記録である** （本記録の位置づけ）。 **CISA は「本勧告に記載された脆弱性を具体的に標的とした 公開された悪用は、現時点で CISA に報告されていない」としている** （出典1）。 **以下の chain は、勧告が各 CVE について示した成立条件と影響から 本記録が段階を立てたものである**（出典1）—— **実際に観測された攻撃の記録ではない。** **本記録が注目したのは、6件が「認証の要否」で3層に分かれることである** （本記録の整理）—— **①認証不要（CVE-2026-100730〈Windows 認証を使っていない場合〉・ CVE-2026-105281・CVE-2026-85479・CVE-2026-105278〈Docker イメージ〉）、 ②認証済みの利用者が必要（CVE-2026-101022）、 ③認証済みかつホスト上にファイルを置ける必要がある（CVE-2026-104629）。** **①の4件が、到達できる位置にいる攻撃者にとっての入口になる。**

  1. 1. 偵察
    **攻撃者は、到達可能な openPDC／openHistorian の サービスコンソールおよびデータ公開インタフェースを探す** （出典1の成立条件から本記録が構成した段階）。 **勧告の記述から分かる成立条件は2つある**（出典1）—— **①該当バージョンであること、 ②Windows 認証を使っていないこと（CVE-2026-100730 の場合） または既定の構成のまま運用していること （CVE-2026-105281・CVE-2026-85479 の場合）。** **本記録の整理** —— **後者が重要である。** **既定値の修正は新規導入にのみ適用され、 以前の版から更新した環境は従来の設定を保持する**（出典1）—— **つまり「更新済みだが既定値は古いまま」という状態が 正常に起こり得る。**
  2. 2. 初期侵入
    **認証を必要としない経路で入る**（出典1）—— **①CVE-2026-100730：openPDC／openHistorian の サービスコンソールインタフェースが、クライアントから 与えられたデータ構造をデシリアライズする。 「Windows 認証を使用しているシステムでは、攻撃者はこの機能に 到達するために既に認証されている必要があるが、 Windows 認証を使用していないシステムでは、 認証されていないネットワーク上の攻撃者から到達可能である」 （原文英語。本記録が訳した）。 任意のオブジェクトグラフのデシリアライズを引き起こし、 影響するサービスアカウントの権限で遠隔コード実行に至り得る。** **②CVE-2026-105278（公開 Docker イメージのみ）： 変更を強制されない固定の管理者資格情報が含まれており、 管理インタフェースにネットワーク到達できる者に 完全な管理権限を与える。**
  3. 3. 内部探索
    **認証なしで系の構成を読み出す**（出典1）—— **CVE-2026-105281：openPDC の内部データ公開インタフェースが 既定の構成で認証なしの接続を受け付ける。 「認証されていないネットワーク上の攻撃者がこのインタフェースへ 接続し、システムの装置および計測の完全なトポロジを 取得できる」（原文英語。本記録が訳した）。** **CVE-2026-85479：STTP ベースのデータ公開インタフェースも 既定の構成で認証なしの接続を受け付け、データの交換ができる。** **本記録の評価** —— **「装置および計測の完全なトポロジ」は、 どの計測点がどこに存在し何を測っているかの一覧である。** **これは侵入の前段ではなく、それ自体が価値のある情報にあたる** —— **系統の広域監視の構成が外部から読める状態は、 以後の標的選定の土台になる。**
  4. 4. 実行
    **認証済みの利用者がホスト上でコードを動かす**（出典1）—— **CVE-2026-104629：コンポーネントのローダが、 指定された任意の型を構築する。 「ホスト上にファイルを配置できる認証済みの利用者は、 影響するサービスアカウントの権限で任意のコンストラクタの コードを実行できる」（原文英語。本記録が訳した）。** **開発元は openPDC 2.9.477 以降・openHistorian 2.8.580 以降で、 アダプタの検証と整合性の確認を追加して修正した**（出典1）。
  5. 5. 横展開
    **内部ネットワークを外側から走査させる**（出典1）—— **CVE-2026-101022：Modbus 接続機能が任意の宛先アドレスと ポートを受け付ける。 「認証済みの利用者が内部のホストを探索でき、 内部ネットワークの地図を作れる可能性がある」 （原文英語の要旨。本記録が訳した）。** **本記録の整理** —— **これはサーバサイドリクエスト フォージェリ（CWE-918）であり、openPDC 自身が 攻撃者の代わりに内部へ接続を試みる形になる。** **制御系では、この「内部からの接続」が ファイアウォールの許可側に当たることがある**（本記録の評価）。
  6. 6. 影響（暗号化・破壊・改ざん）
    **本段階は勧告に記載が無く、openPDC の役割から 本記録が構成したものである**（本記録の明示）。 **勧告が示す影響は、CVE ごとの技術的な帰結 （サービスアカウント権限でのコード実行、トポロジの取得、 データの交換、完全な管理権限）までである**（出典1）。 **本記録の評価** —— **openPDC は同期位相計測装置から送られる データを集約し、系統の広域監視に渡す位置にある。** **ここを握られたときに起こり得ることは2通りある。** **①計測データの改変** —— **保護リレーのような安全系とは別の経路であり、 遮断器を直接動かすものではない。** **影響が出るのは「運用者が見ている景色」のほうである。** **②保管された時系列データの改変・消去** —— **openHistorian 側では、事後の分析（事故解析・需給の検証）の 土台が失われる。** **本記録はこの2つを可能性として書いており、 公表資料に記載のある被害ではない。**

②直ったことにならないもの——CVE-2026-105281・CVE-2026-85479。 認証なしで接続を受け付けていたデータ公開インタフェースの修正は、「既定値をローカルループバックのみに束ねる」という変更である。 勧告は続けてこう書いている（原文英語。本記録が訳した）—— 「この変更は新規のインストールに適用される。以前の版から更新した既存のインストールは従来の構成を保持し、新しい既定値を自動では受け取らない。運用者は自環境の構成を明示的に確認し、全インタフェースで接続を受け付ける設定のままであればインタフェースの束ね先を変更すべきである。」

本記録の評価 —— ②は、脆弱性対応の記録の付け方に直接ひびく。 「2.9.482 へ更新済み」という記録は、この2件については対策の完了を意味しない。 完了の証拠になるのは版番号ではなく、待ち受けアドレスの実測値である。

③修正版が2段ある。 CVE-2026-104629 だけが 2.9.477／2.8.580 で修正され、他は 2.9.482／2.8.585 である（出典1）—— 2.9.477 で止めると、認証不要の遠隔コード実行（CVE-2026-100730）が残る。

計測の集約点を握られると、壊れるのは系統ではなく「見えている景色」か評価・解釈

以下は本記録の評価であり、公表資料に記載のある内容ではない（本記録の明示）。勧告が示す影響は、CVE ごとの技術的な帰結までである（出典1）。

openPDC は Phasor Data Concentrator——系統各所の同期位相計測装置（PMU）から秒間数十回の頻度で送られてくる計測値を集約し、広域監視へ渡す位置にある。 openHistorian はその時系列データを保管する。

この位置にある装置は、保護リレーのような安全系とは別の経路にある（本記録の整理）—— openPDC を握っても、遮断器が直接動くわけではない。 だから「制御を奪われる」類の事案と同じ枠で語ると、危険度を取り違える。

実際に効くのは別の方向である。

①運用者が見ている景色が汚れる。 広域監視は、系統の揺れ・位相差・周波数の偏差を人と自動の判断に渡すための仕組みである。 入力が改変されれば、判断の前提が変わる。 しかもこの改変は、データの持ち出しを伴わない —— 漏えいを前提とした検知の網には、原理的にかからない。

②事後の分析の土台が消える。 保管された時系列データは、事故の原因解析・需給の検証・制度上の報告の根拠になる。 サービスアカウントの権限でコードが動く状態（CVE-2026-100730・CVE-2026-104629）では、保管済みのデータも操作の対象になり得る。

③構成そのものが読み出せる。 CVE-2026-105281 は「装置および計測の完全なトポロジ」を認証なしで取得できるとされている（出典1）—— これは侵入の前段ではなく、それ自体が情報である。 どこに何の計測点があるかの一覧は、以後の標的選定の土台になる。

本記録が実務の結論として置くのは2点である。

第一に、計測データの保管基盤の記録を、別の基盤へ書き換え不可の形で複製しておく。 同じ系の中だけを見ていると、改変は検出できない。

第二に、この種の装置の露出の判定を「制御系かどうか」で分けない。 openPDC は制御をしないが、制御の判断の入口にある。 分類の都合で監視の網から外れやすい位置である。

修正版の入手先が勧告から辿れないという、運用側の実務の穴未確定事項

本件には、読者が更新に着手する段で詰まる点がある（本記録の明示）。

CISA の勧告（出典1）には、開発元の配布ページ・リポジトリへのリンクが無い。 ページ上の外部リンクは、CSAF 形式の同一勧告、各 CVE の CVE.org の記録、CWE の定義、CVSS 計算機だけである（本記録が確認）。

本記録は開発元自身の公表文（リリースノート・セキュリティ勧告）を確認できなかった（未確定事項を参照）。GitHub 上の openPDC のリリース一覧（1ページ目）にも、2.9.477／2.9.482 の記載を見つけられなかった（齟齬2）。

本記録の立場は明確である —— これを「修正版が存在しない」証拠として扱わない。 ①確認したのは一覧の1ページ目だけであり、②開発元がインストーラを自社サイトで配布している可能性があり、③勧告は当局が開発元から得た情報として修正の提供を明記している。

ただし実務上の結論は変わらない —— 更新を担当する者は、修正版の入手先を自分で特定する必要がある。 そして、入手先が1つに定まらない製品は、緊急の更新に時間がかかる。

本記録が勧めるのは、脆弱性が出てからではなく平時に確認しておくことである —— 自組織で動かしているオープンソース製品について、「誰が・どこから・どうやって更新を取ってくるか」を製品ごとに書いておく。 これが無い製品は、公表の当日に探索から始めることになる。

対応の評価

CISO・経営層への示唆
  • 脆弱性対応の完了判定を「版番号」から「設定の実測値」へ 広げる規則を置く
    **本件の2件（CVE-2026-105281・CVE-2026-85479）の修正は 「既定値をローカルループバックのみに束ねる」変更であり、 新規導入にしか適用されない**（出典1）—— **以前の版から更新した環境は従来の設定を保持し、 新しい既定値を自動では受け取らない。** **勧告は運用者に対し、設定を明示的に確認するよう求めている。** **本記録の評価** —— **「最新版へ更新済み」という台帳の記録が、 この2件については対策の完了を意味しない。** **既定値の変更で直す形の修正は珍しくなく、 版番号だけを見る運用はこの類型を取りこぼす。**
    取るべき行動 **①脆弱性対応の完了条件に「設定の実測値」の欄を追加する。** 版番号だけで閉じられない案件を識別できるようにする。 **②勧告・公報を読む担当者に、 「修正の性質（コードの修正か／既定値の変更か／ 構成上の回避か）」を記録させる。** **③本件については、更新の有無に関わらず データ公開インタフェースの待ち受けアドレスを 実測して報告させる。**
  • 「修正が出ない」と宣言された配布物を、資産台帳で 別扱いにする
    **CVE-2026-105278（公開 Docker イメージの固定管理者資格情報・ CVSSv3.1 9.8）について、勧告は「修正の予定は無い」とし、 開発元は公開 Docker イメージの本番利用を推奨していない** （出典1）—— **他の5件についても、Docker イメージへは修正が公開されていない。** **本記録の評価** —— **これは「対応を待つ」案件ではなく 「配布物の選択を変える」案件である。** **通常の脆弱性管理の流れ（検出→更新→完了）に乗せると、 いつまでも未完了のまま残り、 やがて例外として黙認されるようになる。**
    取るべき行動 **①資産台帳に「開発元が修正を提供しない配布物」の区分を設け、 通常の更新待ちと分ける。** **②この区分に入ったものは、 「代替の配布物へ移す」「運用形態を変える」「使用をやめる」の いずれかを期限付きで決める案件として扱う。** **③本件については、公開 Docker イメージで openPDC を 動かしている環境（本番・検証を問わず）の有無を確認させる。** 検証環境が本番ネットワークに接続していることは珍しくない。
  • オープンソース製品ごとに「誰が・どこから・どうやって 更新を取るか」を平時に書いておく
    **CISA の勧告には、開発元の配布ページ・リポジトリへの リンクが無い**（出典1。本記録が確認）。 **本記録は開発元自身の公表文を確認できず、 GitHub のリリース一覧（1ページ目）にも 修正版の記載を見つけられなかった**（齟齬2・未確定事項）。 **本記録の評価** —— **修正版が存在しないという結論ではない。** **しかし「入手先が勧告から辿れない」ことは事実であり、 公表当日に探索から始める運用では、 更新の着手が半日から数日遅れる。** **商用製品では保守窓口が入手先を兼ねるが、 オープンソース製品にはその経路が無いことがある。**
    取るべき行動 **①自組織で動かしているオープンソース製品の一覧を作り、 製品ごとに「更新の責任者」「配布元の URL」 「入手と検証の手順」を書いておく。** **②書けない製品（配布元が特定できない・責任者がいない）を 洗い出し、それ自体をリスクとして扱う。** **③本件については、修正版 2.9.482／2.8.585 の入手先の 特定を担当者に割り当て、所要時間を記録させる。** 次回の指標になる。
  • 計測・監視の基盤を「制御系かどうか」で分類せず、 監視対象に入れる
    **以下は本記録の評価であり、公表資料に記載のある内容ではない。** **openPDC は制御をしない** —— **遮断器を動かすのは保護リレーであり、別の経路にある。** **しかし openPDC は、系統の広域監視へ渡す計測データの 集約点にある。** **握られたときに起こるのは「制御の奪取」ではなく 「運用者が見ている景色の汚染」であり、 データの持ち出しを伴わないため 漏えいを前提とした検知の網にかからない。** **分類上「制御系ではない」ために監視の網から外れやすい位置である。**
    取るべき行動 **①資産の分類に「判断の入力になる系」という観点を加え、 計測・監視・ログ集約の基盤をここに入れる。** **②この区分には、制御系と同じ水準の到達性制限と 記録の外部保全を求める。** **③計測データの保管基盤について、 別の基盤への書き換え不可な複製があるかを確認させる。** 無ければ、改変の有無を後から検証する手段が無い。
セキュリティ技術者への示唆
  • 更新の前後で、データ公開インタフェースの待ち受けアドレスを 実測する
    **CVE-2026-105281 と CVE-2026-85479 の修正は 「既定値をローカルループバックのみに束ねる」変更で、 新規導入にのみ適用される**（出典1）—— **更新した環境は従来の設定を保持する。** **勧告は「運用者は自環境の構成を明示的に確認し、 全インタフェースで接続を受け付ける設定のままであれば インタフェースの束ね先を変更すべきである」としている** （原文英語。本記録が訳した）。 **本記録の評価** —— **設定ファイルの記述を読むだけでは足りない。** **実際に待ち受けているアドレスを、 稼働中のプロセスの状態として見る必要がある （設定と実際の挙動がずれることがある）。**
    取るべき行動 **①稼働中の openPDC／openHistorian で、 データ公開インタフェースが待ち受けているアドレスを プロセスの状態から取得する。** **②ループバック以外で待ち受けている場合、 別ホストから当該ポートへの到達試験を行って露出を確認する。** **③ループバックに束ねる前に、 同一ホスト以外からデータを購読している下流の処理を 一覧にする。** 束ねた後にデータが来なくなる形 （エラーにならない）で下流が止まることがある。
  • 目標の版を 2.9.482／2.8.585 に固定する（2.9.477 で止めない）
    **勧告の影響バージョンの記載は「2.9.477 未満、2.9.482 未満」 という2段になっている**（出典1）—— **CVE-2026-104629（安全でないリフレクション）だけが openPDC 2.9.477 以降・openHistorian 2.8.580 以降で修正され、 CVE-2026-100730（デシリアライズ・CVSSv3.1 9.8）は openPDC 2.9.482 以降・openHistorian 2.8.585 以降で修正される。** **本記録の評価** —— **2.9.477 へ上げた環境は、 認証不要の遠隔コード実行が残った状態で 「更新済み」と記録される危険がある。**
    取るべき行動 **①更新計画の目標版を openPDC 2.9.482 以降・ openHistorian 2.8.585 以降と明記する。** **②中間の版（2.9.477／2.8.580）で止まった場合は 「部分対応」として記録し、未対応の CVE 番号を残す。** **③更新の作業記録に、適用後の版番号を実測値で残す。**
  • Windows 認証の有無を、脆弱性の成立条件として確認する
    **CVE-2026-100730 の記述は条件分岐している**（出典1。 原文英語。本記録が訳した）—— **「Windows 認証を使用しているシステムでは、 攻撃者はこの機能に到達するために既に認証されている 必要があるが、Windows 認証を使用していないシステムでは、 認証されていないネットワーク上の攻撃者から到達可能である。」** **本記録の評価** —— **同じ CVE が、構成によって 「認証不要の遠隔コード実行」と 「認証済み利用者による遠隔コード実行」に分かれる。** **緊急度が大きく違うため、自環境がどちらかを 先に確定させるべきである。**
    取るべき行動 **①openPDC／openHistorian の各ノードで Windows 認証の構成を確認する。** **②使っていないノードを「認証不要で成立する」側として 優先度を上げ、更新までの間は サービスコンソールへの到達元を限定する。** **③Windows 認証を導入する場合、 自動化（スクリプト・監視からの参照）で使う資格情報を 設定ファイルに平文で置かない設計にする。** 別の露出を作ることになる。
  • 公開 Docker イメージで動かしている環境を、本番・検証を問わず洗い出す
    **CVE-2026-105278 は公開 Docker イメージにのみ付与されており、 変更を強制されない固定の管理者資格情報が含まれる**（出典1）—— **管理インタフェースにネットワーク到達できる者に 完全な管理権限を与え、修正の予定は無い。** **他の5件についても、イメージへは修正が公開されていない。** **本記録の評価** —— **この経路は、悪用に技術的な解析を要しない。** **資格情報が公開のイメージから読み取れる形であれば、 PoC の公開という段階を経ずに使われ得る。** **「悪用未確認」を猶予と読まないこと。**
    取るべき行動 **①コンテナ基盤のイメージ一覧から openPDC のイメージを検索し、 稼働中のコンテナ（本番・検証・一時的な動作確認を含む）を特定する。** **②該当があれば、管理インタフェースへの到達元を 即時に限定する（固定資格情報は変更を強制されないため、 到達性を削ることが唯一の手になる）。** **③恒久対応として、自前イメージの構築か 通常インストールへの移行を計画する。**
  • openPDC から出ていく接続の宛先を記録し、 Modbus の宛先制限を入れる
    **CVE-2026-101022 は、Modbus 接続機能が任意の宛先アドレスと ポートを受け付けるサーバサイドリクエストフォージェリである** （出典1）—— **認証済みの利用者が内部のホストを探索でき、 内部ネットワークの地図を作れる可能性がある。** **勧告にベンダー修正の記載は無く、示されているのは 「Modbus へのアクセスをファイアウォールで制限し、 明示的に必要でない限りループバックおよび RFC 1918 の 私的アドレス範囲への接続を遮断する」という構成上の制限だけである。** **本記録の評価** —— **制御系では、openPDC から出ていく接続は ファイアウォールの許可側に当たることが多く、 この経路は既存の許可を流用する形になる。**
    取るべき行動 **①openPDC が発信する接続の宛先を記録する設定にする （記録が無いと、探索の試行が痕跡を残さない）。** **②正当な Modbus の接続先を一覧にし、 それ以外の私的アドレス範囲・ループバックへの接続を遮断する。** **③装置の増設時に許可一覧を更新する手順を 運用手順書に入れる。** 更新を怠ると 「つながらない」原因として現れる。

システム構成□ openPDC／openHistorian を Windows 認証を使わない構成で 運用している**CVE-2026-100730 の成立条件がここで分かれる**（出典1）—— **「Windows 認証を使用していないシステムでは、 認証されていないネットワーク上の攻撃者から到達可能である」 （原文英語。本記録が訳した）。** **本記録の評価** —— **同じ CVE が、構成によって 「認証不要の遠隔コード実行」と「認証済み利用者による 遠隔コード実行」に分かれる。** 該当する場合は優先度を上げ、更新までの間は サービスコンソールへの到達元を限定する判断対象になる。
