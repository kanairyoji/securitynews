INC-2026-0437UAT-11985 が台湾研究機関にAitM

台湾の研究機関に所属する個人を狙った標的型フィッシングで、**実在する公開イベントの案内を装った招待メール**が 使われた——Cisco Talos が UAT-11985 として2026年10月8日に公表。招待文は3通が構文までほぼ同一で、 同社は**AIによる文面生成・個別化の関与を強く示す証拠がある**と評価した（断定はしていない）。 メールには**正規のイベントポスターのQRコードだけを差し替えた添付**が付き、 印刷して掲示された場合に受信者以外も巻き込む経路（QRコードフィッシング）を作っていた。 誘導先は **Google の認証画面を模した中間者型（AitM）のフィッシング基盤**で、 HTTP と WebSocket を併用して本物の Google との認証手続きを実時間で同期し、 **多要素認証の課題と認証済みセッションのトークンまで取得できる**構成だった。 フィッシングキットの画面表示は簡体字・繁体字・英語の3種のみで、 Talos は**開発者の主要言語が簡体字中国語である**と中程度の確度で評価した。 被害件数・侵害の成否・標的の組織名、および国家への帰属はいずれも公表されていない

Cisco Talos が2026年10月8日、台湾の研究機関に所属する個人を狙った標的型フィッシングの分析を公表しました。同社はこの活動を UAT-11985 として追跡しています。観測時期は 2026年半ばです。

組み立ては4段階です。

  • 実在するイベントの案内を装う。 装われたのはTaiwan European Union Centre、NCCU Institute of International Relations、Taiwan Research Institute の3機関。日程・会場・登録方法といった本物の情報が使われています
  • 文面はAIの関与が強く疑われる。 3通は扱う地政学の主題が違うのに構文がほぼ同一で、相手を褒める部分の表現も入れ替え可能な一般論でした。Talos は再利用できる指示文の雛形から生成されたと見ており、「AIによる文面生成・個別化の強い証拠がある」としつつ、大規模言語モデルが全文を書いたとは断定していません
  • ポスターのQRコードだけが差し替えられている。 添付のポスターは正規サイトから取られた意匠で、埋め込まれたQRコードだけが悪性のものでした。Talos は、受信者が印刷して掲示板に貼ることを見込んだ物理世界への拡張だと評価しています
  • 誘導先は Google を模した中間者型（AitM）の基盤。 偽の Google フォームが偽の Google ログイン画面へ強制的に遷移させ、入力された識別子とパスワードは本物の Google へ中継されます。多要素認証が要求されれば、その種別と画面の構成が攻撃者側の基盤から指示され、利用者の画面が1手ずつ進みます。結果として認証済みセッションのトークンが取得され、多要素認証は実効的に迂回されます

受信者の1人が、差出人を確認するために当該機関へ問い合わせています。3つの機関はいずれも、その差出人が自機関の職員・代表者であることを確認できませんでした。つまり差出人は捏造で、機関名と公開情報だけが借用されていたことになります。

技術的な特徴としては、フィッシングキットの画面表示が簡体字（zh-CN）・繁体字（zh-TW）・英語の3種のみで、利用者のブラウザの言語設定から地域を判定していました。Talos はキットの実装を分析し、利用者向け画面がもともと簡体字中国語で作られ、のちに繁体字と英語へ適応されたと中程度の確度で評価しています。国家への帰属は示されていません。

攻撃の経過

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

実在するイベントの案内を装った招待メールで、研究機関の個人を偽の Google フォームへ誘う。 フォームは偽の Google ログイン画面へ強制遷移し、入力は本物の Google へ中継される。 HTTP が一度きりの送信（指紋・識別子・認証情報・死活確認）を、 WebSocket が画面の制御を担い、**多要素認証の課題の種別まで実時間で同期する**。 結果として認証済みセッションのトークンが取得される。 別経路として、正規のポスターのQRコードだけを差し替えた添付が、 印刷・掲示を通じて受信者以外へ攻撃面を広げる

  1. 1. 偵察推定
    **公開情報から素材を集めている。** 装われた3機関の実在するイベント （主題・日程・会場・登録方法）が正規のサイトや公開告知から写され、 ポスターの意匠も正規サイトから取られた。 受信者ごとの個別化は、**公開されている職業上の情報**をもとに 再利用可能な雛形へ当てはめる形だったと Talos は評価している。 **標的の名簿の入手経路は公表されていない**
    根拠: Talos の記事（正規の告知からの転記、公開された職業情報による個別化の評価）
  2. 2. 初期侵入確認済
    招待メールが届く。3部構成（地政学の文脈 → 受信者を褒める部分 → 開催要領）で、 3通の構文がほぼ同一。差出人は捏造で、**機関名と公開情報だけが借用されている**。 登録用のリンクは**表示される文字列が正規の Google フォームに見える一方、 実際の遷移先は第三者の基盤に置かれた偽サイト**である。 数通には**QRコードだけを差し替えた正規の意匠のポスター**が添付されていた
    根拠: Talos の記事（3通の構造の分析、リンクの表示と遷移先の不一致、 ポスターの改変、3機関が差出人の所属を確認できなかったこと）
  3. 3. 認証情報アクセス確認済
    偽の Google フォームが**偽の Google ログイン画面へ強制的に遷移**させる。 入力された識別子は本物の Google へ中継され、**アカウントの存在と パスキーの手続きが有効かどうか**が確かめられる。 パスワードは本物の Google へ転送される。 **多要素認証が要求されれば、課題の種別と画面の構成が攻撃者側の基盤から返され、 利用者の画面が1手ずつ進む。** 結果として**認証済みセッションのトークンが取得され、多要素認証は実効的に迂回される**
    根拠: Talos の記事（中間者型の基盤の動作、パスキーの確認、課題の種別の中継）
  4. 4. 検知回避確認済
    悪性の JavaScript は **HTML の末尾**に置かれ、Base64 で符号化された文字列の 大きな配列と、**実行時に解決される回転処理**（`while(!![])` の押し出しと取り出しの 繰り返し）で難読化されている。Talos は、これにより **静的な自動解析の道具が効かなくなる**と述べている。 さらに、成功を装うための隠された領域（`google-success-frame` という識別子の枠が `allow-scripts` の制限付きでローカルの成功画面を読み込む）が用意されていた
    根拠: Talos の記事（難読化の手法、隠された領域と枠の構成）

本物のイベント情報が「信頼の洗浄」に使われている——確認の相手は差出人ではなく主催機関である原因・手口

招待メールの3通は、同じ3部構成でした。

  1. 地政学・政策の文脈の説明。 「世界の戦略的な地勢」「大国の秩序の再編」「三次元的な分析」「先見的で深い分析」「高強度の専門的対話」といった、壮大だが具体性のない言い回しが多用されています。Talos は「文章は概して流暢だが、政策用語と抽象的な戦略語が過剰で、定型的に見える」と評価しました
  2. 受信者を褒める部分。 「敬意」「権威ある見解」「極めて洞察に富む」「実務上の重要な側面」といった表現が3通に共通して現れます。褒め言葉は誰にでも当てはまる内容で、受信者の実際の仕事に関する検証可能な記述はほとんどありません。限定的な参加・VIP席の確保・唯一無二の専門性といった言い方で、職業上の承認欲求に働きかけて警戒を下げる形です
  3. 開催要領。 主題・日程・会場・登録方法。この部分の多くは正規の機関のサイトや公開された告知から写されています

Talos はこの3点目を 「legitimacy laundering（正当性の洗浄）」 と呼びました。情報が正確であることは、そのメールや差出人が正当であることを意味しない——この区別がこの事案の核心です。

実際、埋め込まれた登録用のリンクは、見えている文字列が正規の Google フォームのURL に見えるのに、実際の遷移先は第三者の基盤に置かれた偽サイトでした。そして受信者の1人が差出人の実在を機関へ問い合わせたところ、3つの機関はいずれも、その差出人が自機関の職員・代表者であることを確認できませんでした。

ここから出てくる実務上の帰結は1つです。確認すべき相手はメールの差出人ではなく、イベントの主催機関の公表されている連絡先である。メール内の電話番号や返信先に問い合わせても、確認にはなりません。

ポスターのQRコードだけが差し替えられ、攻撃面が「受信者」から「掲示板を見た人」へ広がる原因・手口

数通のメールにはイベントのポスターが添付されていました。

意匠は正規のサイトから取られたもので、改変されていたのは埋め込まれたQRコードだけです。Talos はこれを「計算された物理世界の攻撃経路」と評価しています。想定されているのは、受信者がポスターを印刷して職場の掲示板に貼る動きです。そうなると、メールを受け取っていない人がQRコードを読み取って登録しようとする形になります。

技術者にとってこれが厄介な理由は2つあります。

  • メールのゲートウェイで止めても、紙に出たあとは効かない。添付が通過してしまえば、以後の経路に電子メールの検査は介在しません
  • 読み取る端末が組織の管理外になりやすい。 QRコードは個人のスマートフォンで読み取られることが多く、組織のウェブフィルタや端末の保護が効かない経路へ出ます

なお、実際に印刷・掲示された事例、読み取られた事例は公表されていません。 Talos の記述は、攻撃者の意図の推定です。

AitM の基盤は HTTP と WebSocket で役割を分けている——「一度きりの送信」と「画面の遠隔操作」原因・手口

誘導先の仕組みは、偽の画面を見せるだけのものではありません。

最初に開くのは正規の Google フォームに見える画面で、これが偽の Google ログイン画面へ強制的に遷移させます。そのログイン画面は本物と見分けの付かない作りで、難読化された JavaScript を隠し持っています。

通信は2経路に分かれています。

  • HTTP の POST — 一度きりの送信。 ブラウザの指紋情報、識別子（メールアドレス）、入力された認証情報、そして定期的な死活確認。要求には google_login_start・google_input_identifier・google_login_check といった名前が付いています
  • WebSocket — 継続的な制御。 攻撃者側の基盤から遅延の少ない持続的な経路で、セッションの状態の写しを送り、次にどの画面を描くかを指示します

この分担が意味するのは、利用者の画面が攻撃者側から1手ずつ操作されているということです。流れはこうなります。

  1. 入力された識別子が本物の Google へ中継され、アカウントの存在とパスキーの手続きが有効かどうかが確かめられる
  2. パスワードが本物の Google へ転送される
  3. 多要素認証が要求されれば、その課題の種別と画面の構成が攻撃者側から返され、利用者の画面が次の段階へ進む
  4. 結果として認証済みセッションのトークンが取得され、多要素認証は実効的に迂回される

仕上げとして、画面には成功を装うための隠された領域が用意されています。google-success-frame という識別子の枠が、allow-scripts の制限付きでローカルに置かれた成功画面を読み込みます。

解析を妨げる仕掛けも入っています。悪性の JavaScript は HTML の末尾に置かれ、Base64 で符号化された文字列の配列と実行時に解決される回転処理（while(!![]) の押し出しと取り出しの繰り返し）で難読化されています。Talos は、これにより静的な自動解析の道具が効かなくなると述べています。

対応する ATT&CK の技術として記事が挙げているのは T1557（Adversary-in-the-Middle） です。

「言語」から開発者を推定している——ただし中程度の確度で、国家への帰属ではない帰属

Talos の帰属に関する記述は、キットの実装の分析に限られます。

  • 偽の Google ログイン画面が対応していたのは簡体字（zh-CN）・繁体字（zh-TW）・英語の3種だけで、地域の判定はブラウザの言語設定（navigator.languages）で行われていた
  • 利用者向け画面の文言の作りは、既定の分岐が簡体字になっていた
  • 用語に中国大陸で使われる語彙が見られた

これらを合わせて、同社は利用者向け画面がもともと簡体字中国語で作られ、のちに繁体字と英語へ適応された、開発者の主要な作業言語は簡体字中国語であると中程度の確度で評価しています。

ここで止まっていることが重要です。記事は特定の国家・既知の集団との結び付けを示していません。UAT-11985 という符号そのものが「未分類」を意味します。キットの開発者の言語は、運用した主体の所在や指示系統とは別の話であり、本記録もそれ以上を書きません。

文面についても同じ姿勢です。Talos は「AIによる文面生成と個別化の強い証拠がある」としつつ、「メールが大規模言語モデルによって完全に生成されたかは結論付けられない」と明記しています。根拠は、流暢だが定型的な文章、壮大で抽象的な政策用語の過剰、入れ替え可能な褒め言葉、反復する文型、そして異なる相手・機関・主題への素早い個別化です。

日本の研究機関・大学が同じ条件を持っている（本記録の評価）評価・解釈

本記録の判断です。 観測された標的は台湾の研究機関であり、日本の組織が対象に含まれていたかは公表されていません。

それでも、この手口が前提にしている条件は日本の研究機関にそのまま当てはまります。

  • イベントの開催情報が公開されている。 国際会議・シンポジウム・政策対話の日程と会場と登録方法が、組織のサイトに載っています。これが素材になります
  • 外部の機関から招待が届くことが日常である。 「知らない差出人からの招待」は異常ではなく、研究者の通常の業務です
  • ポスターを印刷して掲示する習慣がある。 研究室・学科の掲示板は、QRコードの差し替えが効く場所です
  • 個人の判断で登録する。 組織の承認を経ずに、本人がフォームに入力します
  • Google のアカウントで業務をしている組織が多い。中継の対象が組織の主たる認証基盤になります

    悪性の JavaScript は HTML の末尾に置かれ、Base64 の文字列配列と 実行時に解決される回転処理で難読化されている。 Talos は、これにより**自動的な静的解析の道具が効かなくなる**と述べている。 隠された領域（`allow-scripts` の制限付きの枠がローカルの成功画面を読み込む）も 表示上は現れない
    取るべき行動 不審なページの確認手順に、**隔離した環境での実行**を含める （静的な取得と文字列の検索だけで判断しない）。 確認の対象には、①HTML の末尾の長い文字列配列、 ②WebSocket の接続先、 ③`iframe` が読み込むローカルの資源、を明示的に入れる
  • **WebSocket の外向き通信を「見ていない」経路があると、この型の基盤は通る**
    この基盤は、一度きりの送信を HTTP に、**画面の遠隔制御を WebSocket**に 分けている。HTTP の POST だけを見る検査では、 攻撃者側からの制御の往復が落ちる。 また要求には `google_login_start`・`google_input_identifier`・ `google_login_check` のような名前が付いており、 **経路上で見える名前が手がかりになりうる**（本記録の注記）
    取るべき行動 ①ウェブの経路の記録で**WebSocket の接続先が残っているかを確認**し、 残っていなければ記録の対象に加える、 ②**認証を扱う正規のドメイン以外への WebSocket の接続**を点検の対象にする。 研究機関では利用者の端末が組織の経路を通らないことが多いため、 **端末側での記録が取れているかも併せて確認する**
  • **QRコードは、組織の管理外の端末へ経路を移す。** 技術的な統制の射程を正しく見積もる
    差し替えられたQRコードが印刷・掲示されれば、 読み取るのは個人のスマートフォンになる。 メールのゲートウェイ、組織のウェブフィルタ、管理された端末の保護、 条件付きのアクセス——**このうち最後だけが残る**
    取るべき行動 **組織の認証基盤の側に統制を置く。** ①パスキー・FIDO2 を既定にする、 ②**管理外の端末からの認証を、少なくとも記録して事後に点検できる状態**にする、 ③認証の成功に続く**新しい端末の登録・連絡先の変更**を警告の対象にする （トークンが奪われた後に行われる操作である）

認証・認可□ 外部のクラウドの認証（Google・Microsoft 等）を主たる業務基盤にしており、パスキー・FIDO2 が一部の利用者にしか設定されていない**中継の基盤はパスキーの手続きが有効かどうかを先に確かめている。** 一部だけに設定した状態は、無効な利用者を選別させる
