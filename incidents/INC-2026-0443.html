2026年10月8日ごろ、サプライチェーンセキュリティのベンダー Apiiro は、GitHub 上の悪性リポジトリでマルウェアローダー SmartLoader を配布する「FakeGit」 キャンペーンが 10月4日に活動を再開し、リポジトリ数が 17,610件 に達したと報告しました（出典3・4）。

本記録が中心と見るのは、「増えた」ことではなく「作り直していない」ことです。

研究者の言葉は 「誰も新しいリポジトリを1つも作る必要がなかった。艦隊（fleet）はすでにそこにあった。ただ狙いを変えただけだ」（原文英語）です（出典3）。標本では コミットの97%が README だけを触り、88%がその「Download」ボタンをSmartLoader を入れる ZIP に向け替えていました（出典3）。34時間で13,000件超が投入され、ピークは1時間あたり2,999件です（出典3）。

削除で追いつかない理由も、報告は具体的に書いています（出典3）。

  1. 報告前の時点で、艦隊の71%が URLhaus に載っていなかった
  2. GitHub 上の1ファイルを、ドメイン単位の DNS ブロックリストでは止められない ——GitHub 全体を止めることになる
  3. 悪性アーカイブは fork・古いファイル・リリース資産・issue の添付・別のダウンロード用リポジトリにも置かれており、リンクを1本消すと、予備のコピーに向け直される

投稿元の構成にも注意すべき点があります —— 大半は使い捨てアカウントですが、700件以上は正規の開発者のものと見られるアカウントでした（出典3・4）。

7月に Island が同じ呼称で報告した規模は7,600件で、うち800件はAI スキルや MCP サーバーを装い、公開の AI レジストリやカタログに載っていました（出典3・5）。最終ペイロードは情報窃取型マルウェア StealC とされます（出典3・4）。

一次資料である Apiiro の報告そのものは、本記録が取得できていません（出典4。齟齬2を参照）。数値はすべて、報道が引用した範囲での確認です。評価・示唆は本記録の判断として分けて書きます。

攻撃の経過

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

**既に存在していた大量の GitHub リポジトリの README を書き換え、 「Download」ボタンの行き先をマルウェアの ZIP に向け直すことで、 新規にリポジトリを作らずに配布網を再構成した**（出典3）。 **ZIP の中身は SmartLoader で、これが他のマルウェア （情報窃取型の StealC）を導入する**（出典3・4）。 **本記録が核心と見る点** —— **攻撃の単位が「リポジトリ」ではなく 「誘導先の1行」になっている。** **防御側がリポジトリの削除で対処しようとすると、 消す対象が17,610件、書き換える対象が1行、という非対称が生じる。**

  1. 1. 偵察
    **既存のリポジトリ群（報告の表現は「the fleet」＝艦隊）が、 再利用可能な状態で確保されていた**（出典3）—— **「誰も新しいリポジトリを1つも作る必要がなかった。 艦隊はすでにそこにあった。ただ狙いを変えただけだ」**（原文英語）。 **アカウントの構成は、大半が使い捨てで、 700件以上は正規の開発者のものと見られるものだった**（出典3・4）。 **本記録の明示** —— **艦隊がいつ・どのように用意されたかは 公表されていない。** **7月の7,600件がそのまま残っていたのか、 別に積み上げられていたのかも示されていない**（unknowns を参照）。
  2. 2. 初期侵入
    **README に置かれた「Download」ボタンから ZIP を取得させる**（出典3）—— **「悪性リポジトリは、説得力のある README の手順と、 初期ペイロード（SmartLoader）を含む ZIP アーカイブを指す ダウンロードボタンを使う」**（原文英語の要旨）。 **標本では、コミットの97%が README のみを触り、 88%がボタンを SmartLoader を入れる ZIP に向けていた**（出典3）。 **7月時点の特徴として、800件超が AI スキルや MCP サーバーを装い、 公開の AI レジストリやカタログに載っていた**（出典3・5）。 **本記録の整理** —— **脆弱性は使われていない。** **使われたのは「このリポジトリは目的のツールだ」という読者の判断である。**
  3. 3. 実行
    **ZIP に含まれる初期ペイロード SmartLoader が実行される**（出典3）—— **SmartLoader は「他のマルウェアを配布するために使われる」ローダーである** （出典3。原文英語の要旨）。 **本記録の明示** —— **SmartLoader の実行方法（ユーザーが手で起動するのか、 インストーラの形を取るのか）、ファイル名、永続化の手段は、 本記録が確認した報道に示されていない**（unknowns を参照）。
  4. 4. 影響（暗号化・破壊・改ざん）
    **SmartLoader が情報窃取型マルウェア StealC を導入する**（出典3・4）。 **Apiiro は、SmartLoader の実行が疑われる場合に 「GitHub アカウントの侵害として扱い、有効なセッションと アクセストークンを無効化し、パスキーへ移行する」ことを推奨している** （出典3）。 **本記録の読み取り** —— **この推奨が示しているのは、 被害の範囲が端末ではなく「開発者が持つ鍵」であるという見立てである。** **開発者の端末には、ソースコードのリポジトリへの書き込み権限、 CI/CD のトークン、クラウドの資格情報が同居していることが多い。** **感染した1台が、組織のソフトウェア供給網への入口になりうる。** **ただし実際にそうした二次被害が起きたという報告は無い**（unknowns を参照）。

AI スキルと MCP サーバーの導入経路には、まだ「どこから取るか」の規範が無い評価・解釈

なぜこの経路が弱いのか（本記録の評価）。

AI スキルと MCP サーバーは、2026年に新しく開いた供給経路です。 「エディタの設定を1行足す」「一覧から選ぶ」という体験で入るため、ソフトウェアの導入として審査の対象になっていない組織が多い。 一方で、実行される権限は開発者本人と同じです。

審査の経路が無いことは、攻撃側から見れば「審査を回避する必要がない」ことを意味します。

推奨された復旧手順は「端末の再構築」ではなく「鍵の無効化」だった再発防止

Apiiro の推奨のうち、本記録がもっとも実務に近いと見るのはこれです。

「SmartLoader の実行が疑われる場合、利用者はその事象をGitHub アカウントの侵害の可能性として扱い、有効なセッションとアクセストークンを無効化し、パスキーへ移行すべきである」（出典3。原文英語の要旨）。

この推奨が示しているのは、被害の範囲の見立てです（本記録の読み取り）。

最終ペイロードは情報窃取型マルウェア StealC とされます（出典3・4）。取られるのはブラウザのセッションとアクセストークンです。 端末を再構築しても、無効化していない鍵は生き続けます。

開発者の端末には、次のものが同居していることが多い（本記録の整理）。

  • ソースコードのリポジトリへの書き込み権限
  • CI/CD のトークン
  • クラウドの資格情報

したがって、感染した1台が組織のソフトウェア供給網への入口になりえます。 ただし本件でそうした二次被害が起きたという報告はありません（本記録の明示。unknowns を参照）。

実装の障害は、意思ではなく台帳です（本記録の評価）。

「どのトークンが、どのパイプラインで使われているか」を把握していない組織では、無効化が「何が止まるか分からない操作」になります。 結果として無効化は後回しになり、対応は完了したことになっているのに鍵は攻撃者の手元に残ります。
