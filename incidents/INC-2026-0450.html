INC-2026-0450NewsPicksのMetabaseから36万件

ユーザベースが運営する経済メディア「NewsPicks」が業務で使う BI ツール「Metabase」の 脆弱性（CVE-2026-72898・ログイン前の SQL インジェクション）を突かれ、 2026年8月10日から9月28日まで不正アクセスを受けて クレジットカード情報の一部361,598件・メールアドレス322,531件などが漏えいした—— 多要素認証と権限制御が同時に無効化され、修正版を当てた後も攻撃者が作った API キーが 47日残り、検知は59日後に JPCERT/CC の注意喚起を受けた自主調査だった

不正アクセス・侵害続報が止まり調査も完了日本の組織が当事者既知の脆弱性の悪用権限管理の不備
初報: 2026年10月8日（ユーザベース／NewsPicks の第一報） 最終更新: 2026年11月18日（ユーザベースの調査結果の報告）

ユーザベースは2026年10月9日、経済メディア「NewsPicks」の業務用管理ツールへの不正アクセスについて第二報を公表し、漏えいの可能性がある情報の件数を示した（第一報は10月8日）。

最も多い項目はクレジットカード情報の一部で36.2万件（カード名義とカード番号の下3桁あるいは下4桁など）。メールアドレス32.3万件、所属先の役職の7分類27.3万件、所属（勤務先など）6.5万件、氏名5.9万件、配送先住所・宛名3.1万件、所属先の電話番号2.9万件、生年月日2.8万件。法人向けサービス（NewsPicks Enterprise／NewsPicks Education）の運営担当窓口名と連絡先メールアドレス122件も対象である。いずれも「最大想定件数」として報告されている。

カード番号の全体と セキュリティコードは漏えいしていない——番号の全体は決済代行会社が管理し、同社のシステムには保存されておらず、セキュリティコードも保存していないと説明している。パスワードの漏えいも確認されていない。

原因は「NewsPicks が業務で利用する管理ツールの脆弱性を突いたもの」（第二報）。サービス本体およびユーザベースの他の情報システムへの侵入は確認されていない。

本記録が構造上の中心と見るのは2点である（本記録の判断）。

①初動は速い。 第一報の経緯は分単位で記されている—— 10月8日12時48分に検知し対策本部を設置、14時01分に第三者による不正アクセスと判断して該当サーバーを遮断、21時44分に個人情報保護委員会へ速報を提出し所轄警察署へ被害相談。 検知から遮断まで1時間13分、検知から当局への速報まで約9時間である（本記録の算出）。

②しかし「管理ツール1つ」の射程が広すぎた。 同社は実施済みの対応として「管理ツールのデータアクセス権限を、業務上必要な最小限まで縮小」を挙げている。縮小できる余地があったということは、侵害時点では必要を超える範囲に手が届いていた（本記録の読み）。カード情報の一部36.2万件という最大の項目は、サービス本体ではなく業務用の管理ツール経由で危険に晒された。

【2026年11月18日・第三報の追記】

ユーザベースは2026年11月18日、「調査結果のご報告」を公表した（出典4）。第二報で伏せられていた点がほぼすべて埋まった。

侵害されたのは BI ツール「Metabase」である（出典4）〈重要〉—— ニュース編成・マーケティング・記事や番組の視聴分析に使っていたオープンソースのBI ツールで、多要素認証付きのシングルサインオンを経由してアクセスする構成だった。 突かれたのは CVE-2026-72898——ログイン前に悪用できる SQL インジェクションである（出典4）。攻撃者はこれで多要素認証を迂回して管理者になりすまし、管理者権限の API キーを作り、接続先のデータベースからデータを取得した（出典4）。

時間の並びが本件の核心である（本記録の判断）〈重要〉。Metabase 社の公表は8月6日。攻撃の開始は8月10日（公表から4日後・CVE 番号が割り当てられる前）。データの取得は8月11日。同社が修正版へ更新したのは8月12日（公表から6日後・3営業日後）（出典4・5）。つまり修正版を当てた時点で、データはすでに取られていた。 そして攻撃者が作った API キー等が残存していたため、8月20日から9月28日にかけて管理者アカウントが追加作成され、断続的な偵察が続いた（出典5）〈重要〉。検知は10月8日——JPCERT/CC の注意喚起を受けた自主調査による（出典4）。

件数は確定し、第二報の最大想定件数より減った（出典4）〈重要〉—— メールアドレス322,531件、クレジットカード情報の一部361,598件、所属先の役職の7分類272,392件、所属64,572件、氏名58,754件、配送先住所・宛名30,906件、所属先の電話番号28,013件、生年月日27,194件、法人窓口122件。項目に変更は無い。 カード情報の一部には「有効期限」が明記された（第二報は名義と下位桁のみ）。ログインパスワード（ハッシュ化されたものを含む）は含まれない（出典4）。二次被害は確認されていない（出典4）。

攻撃元の IP アドレスは国外を含む7件（出典4）。外部専門機関の分析では、同時期に国内の複数の組織で起きた不正アクセスと手口に共通点があったとされている（出典4）〈重要〉。

本記録が第三報から新たに取り出す論点は2つである（本記録の判断）。

①多要素認証と権限制御が「同時に」無効化された。 同社の説明は率直である—— 「当該脆弱性はアプリケーションの認証そのものを迂回できるものであったため、『多要素認証』と『権限制御』の両方が同時に無効化されました」（出典4）。認証の前段に穴があると、認証の後ろに積んだ対策はまとめて無効になる（本記録の評価）〈重要〉—— MFA と最小権限を「2つの防御」として数えていた前提が崩れる。

②修正版を当てても、攻撃者は残った。 残存した API キー等により、9月28日まで47日間アクセスが続いた（本記録の算出）〈重要〉—— 同社も課題として「不正アクセスを早期に検知する仕組み」を挙げ、「Metabase の操作記録は保存していたものの、大量のデータ取得などの異常を常時監視する対象とはしていませんでした」と書いている（出典4）。
