INC-2026-0518警察庁起点で YAM Store 制圧

日本の警察庁が国内を狙う不審なメッセージについて Microsoft に通報したことを端緒に、 中国語のサイバー犯罪マーケットプレイス「YAM Store」（Storm-3119）と、 そこへ連なるフィッシングキット CoGUI・Haozi・Iron Man System（まとめて Storm-2990）の 制圧が2026年10月14日に公表された。2026年1月以降、3者で10億通を超える悪性メッセージが 7万5千を超える組織へ送られ、うち7億5千万通超が Microsoft の顧客を狙っていた。 米国フロリダ州南部地区連邦地方裁判所の命令により Microsoft と Health-ISAC が ドメインを差し押さえ、2万超のアカウントを無効化、10万超のドメインを遮断した

初報: 2026年10月14日（Microsoft の公表および各報道） 最終更新: 2026年10月14日

2026年10月14日、Microsoft は中国語のサイバー犯罪マーケットプレイス「YAM Store」（Storm-3119）と、そこへ連なるフィッシングキット群の制圧を公表しました（出典1・2・3）。

調査の端緒は日本です（出典2・3）。日本の警察庁が、国内の人々を狙う悪性メッセージのキャンペーンについてMicrosoft に通報したことから、2025年後半に調査が始まりました（出典2）。そこから、フィッシングの道具とサービスを売る中国語の犯罪市場が見つかっています（出典3）。

規模は次のとおりです（出典1・3）。

  • 2026年1月以降、10億通を超える悪性メッセージ（出典1）
  • 7万5千を超える組織が標的（出典1）
  • うち7億5千万通超が Microsoft の顧客向け（メールとSMS）（出典3）
  • 影響が大きい国は米国と日本（出典1）

本記録が注目するのは、売られていたものの中身です（本記録の評価）。YAM Store が扱っていたのは、フィッシングのメール文面やキットだけではありません。 侵害または不正に取得した Microsoft・Google のクラウド環境そのもの——テナント・アカウント・ライセンス・ストレージです（出典1）。つまり、攻撃者は「正規のテナントから送る」「正規のストレージに置く」ことを購入できていました（本記録の評価）。受信側の対策が送信元の正当性に依存しているかぎり、この市場は対策を迂回する商品を売り続けられます。

攻撃の経過

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

**本件は単一の侵害事案ではなく、攻撃を供給する基盤の構造である** （本記録の整理）。 **YAM Store が侵害・不正取得したクラウド環境を売り、 CoGUI・Haozi・Iron Man System がフィッシングの実行手段を提供し、 購入した攻撃者が各国の組織へメッセージを送る**（出典1・2・3）。 **2026年1月以降、3者で10億通を超えるメッセージが 7万5千を超える組織へ送られた**（出典1）。 **以下の各段階は、Microsoft と Resecurity・Proofpoint の報告内容を 本記録が段階に分けて並べたものであり、 出典が段階別に説明したものではない**（本記録の整理）。

  1. 1. 偵察確認済
    **YAM Store の運営者が、実在組織の失効したドメインを取得した**（出典3）。 **サイトを再構築し、活動を終えた実体が活動中であるように見せかけた** （出典3）。 **別の手口として、AIツールを使い、コンテンツと文書を揃えた 架空の組織を生成した**（出典3）。
    根拠: BleepingComputer が伝える Microsoft の報告内容 「運営者は実在組織の失効したドメインを取得し、 ウェブサイトを再構築して活動を終えた実体を活動中に見せかけ、 その身元を使ってクラウドアカウントを取得した」（出典3。本記録の訳）。
  2. 2. 初期侵入確認済
    **偽装した身元を使ってクラウドアカウントを取得し、 あるいは既存の Microsoft 環境を侵害した**（出典1・3）。 **侵害された Microsoft 環境では、盗まれたアプリケーションの 認証情報を使ってアカウントとライセンスを管理していた**（出典3）。 **取得・侵害された環境は、テナント・アカウント・ライセンス・ ストレージとして YAM Store 上で販売された**（出典1）。 **教育機関（.edu）や非営利団体（.org）の環境も含まれていた**（出典1）。
    根拠: Microsoft の記述「侵害または不正に取得した Microsoft・Google の クラウド環境を販売していた」（出典1。本記録の訳）、 および盗まれたアプリケーション認証情報の利用に関する記述（出典3）。
  3. 3. 検知回避確認済
    **フィッシングキットは、セキュリティ解析を妨げる機能を備えていた** （出典3）。 **ジオフェンシング（地域による振り分け）、偽の CAPTCHA ゲート、 IPフィルタリングなどである**（出典3）。 **また、フィッシングページと添付の置き場所として、 侵害された環境の SharePoint と OneDrive が流用された**（出典3）。
    根拠: BleepingComputer の記述「キットはジオフェンシング、偽のCAPTCHAゲート、 IPフィルタリング、その他の措置に対応し、 セキュリティ解析を妨げた」（出典3。本記録の訳）、 および SharePoint・OneDrive の流用に関する記述（出典3）。
  4. 4. 認証情報アクセス確認済
    **Microsoft 365 の顧客に向けて7億5千万通を超えるメッセージが配信され、 その多くが device code フィッシングによって 認証トークンを取得しようとしていた**（出典3）。 **CoGUI に関連するキャンペーンは、日本の著名企業や国際機関を装い、 認証情報と決済データの窃取に焦点を置いていた**（出典3）。 **Resecurity は、決済カードの捕捉に連なる商品選択の仕組みを 特定している**（出典3）。
    根拠: Microsoft の説明として BleepingComputer が伝える記述 「多くは認証トークンを取得するために device code フィッシングを 用いていた」（出典3。本記録の訳）、 および Proofpoint の観測内容（出典3）。
  5. 5. 影響（暗号化・破壊・改ざん）確認済
    **2026年1月以降、10億通を超える悪性メッセージが 7万5千を超える組織へ送られた**（出典1）。 **BleepingComputer は対象が150か国にわたると伝えている**（出典3）。 **誘い文句は未払いの通行料・交通違反の罰金・配送の問題・ アカウントの確認要求**（出典3）。 **Iron Man System は銀行・小売・配送・政府機関を装う 2,335超のテンプレートを備え、139超の国を対象としていた**（出典1）。 **実際に認証情報やトークンを奪われた件数、 その後の侵害、被害金額は公表されていない**〈未確定5〉。
    根拠: Microsoft の規模に関する記述（出典1）、 および BleepingComputer が伝える到達先の国数とルアーの種類（出典3）。

この事案で下された判断
  • トレードオフ: **関与する組織が増えれば、観測の範囲は広がる**（本記録の整理）。 **Resecurity は露出していたレジストリを解析し、 Proofpoint は2年前からの観測を持ち込んでいる**（出典3）。 **一方、参加者が増えるほど情報の統制は難しくなり、 制圧の準備が相手に漏れる危険が増す**（本記録の整理）。
  • トレードオフ: **ドメイン一覧を公表すれば、各組織は自社のログを照合して 被害の有無を確認できる**（本記録の整理）。 **一方、追加のインフラ削除が進行中であること（出典3）を踏まえると、 一覧の公表は残存インフラの移転を促しうる**（本記録の整理）。

売られていたのはフィッシングの文面ではなく、正規のクラウド環境そのものだった概観

Microsoft は YAM Store を初期アクセスブローカーと位置づけています（出典2）。扱っていた商材は次のとおりです（出典1）。

  • 侵害または不正に取得した Microsoft・Google のクラウド環境
  • テナント、アカウント、ライセンス、ストレージ
  • 教育機関（.edu）や非営利団体（.org）の環境を含む

ここが本件の構造の核です（本記録の評価）。フィッシング対策の多くは、送信元の正当性を検査することで成り立っています。 送信元ドメインの認証、送信元の評価、添付の保管先の評価——いずれも「正規の基盤から来たか」を見ます。 YAM Store が売っていたのは、まさにその「正規の基盤」です。

侵害された Microsoft 環境での具体的な使い方も報じられています（出典3）。

  • 盗まれたアプリケーションの認証情報でアカウントとライセンスを管理した
  • SharePoint と OneDrive のストレージをホスティングに流用した

つまり、フィッシングのページや添付が、本物のテナントの本物のストレージに置かれていました（出典3。整理は本記録）。「信頼できるドメインかどうか」で判定する仕組みでは区別できません（本記録の評価）。

「フィッシングプラットフォームは、Microsoft 365 の顧客を標的とする7億5千万通を超えるメッセージを配信し、その多くは認証トークンを取得するために device code フィッシングを用いていた」
（出典3。原文英語。本記録の訳）

device code フィッシングは、技術者向けに重要な点を含みます（本記録の評価）。

第一に、偽のログインページを作る必要がありません。 利用者は本物の Microsoft のページでコードを入力します。 したがって「URLを確認する」という利用者教育が効きません（本記録の評価）。

第二に、得られるのはパスワードではなくトークンです。 多要素認証を済ませた後の状態が持ち出されるため、多要素認証そのものでは止まりません（本記録の評価）。

第三に、この認証の流れは、本来は入力手段の限られた機器（テレビ・IoT機器など）のために用意されたものです（本記録の整理）。組織がその用途を使っていないなら、条件付きアクセスで経路ごと止められます（本記録の評価）。

本記録の評価として、本件から技術者が持ち帰るべき設定はこの一点に集約されます ——device code フローを使う正当な必要があるかを確認し、無ければ無効化する。

CISO・経営層への示唆
  • **「正規のクラウドテナントから届く攻撃」が商品として売られていることを前提に置く**
    **YAM Store が売っていたのは、侵害または不正に取得した Microsoft・Google のテナント・アカウント・ライセンス・ストレージである** （出典1）。 **フィッシングページと添付は、本物のテナントの SharePoint・OneDrive に置かれていた**（出典3）。 **送信元の正当性を検査する仕組みは、この構造では機能しない** （本記録の評価）。 **「怪しいドメインを遮断する」という考え方の射程が 狭まっているということである。**
    取るべき行動 **①自組織のメールゲートウェイとプロキシが、 「正規ドメインから届く／正規ストレージに置かれた」攻撃を どう扱うかをベンダーに確認する。** **②自組織が業務で使わない外部テナントの SharePoint・OneDrive への リンクを、どう判定しているかを確認する。** **③対策の説明を取締役会にする際、 「送信元の検査」と「内容・文脈の検査」を別の層として示す。**
  • **使わなくなったドメインを手放すことは、将来の攻撃に身元を貸すことである**
    **YAM Store の運営者は、実在組織の失効したドメインを取得し、 サイトを再構築して活動中に見せかけ、 その身元でクラウドアカウントを取得していた**（出典3）。 **元の保有組織は、既に関心を失っているため気づかない** （本記録の評価）。 **事業終了・統合・ブランド廃止のたびに、 この足場が1つ増えていることになる。**
    取るべき行動 **①自社が過去に保有していたドメインの一覧を作る （廃止事業・旧社名・キャンペーン用・買収した会社のもの）。** **②手放す判断をするドメインについて、 「手放した後に第三者が取得して自社名を騙る」risk を 評価の列に加える。** **③主要なドメインは、使っていなくても保持を続けることを 既定にする（維持費と信用の損害を比較する）。**
  • **業界団体・ISAC が「共有する」だけでなく「法的手続きの当事者になる」形がある**
    **Health-ISAC は Microsoft とともに民事訴訟に参加し、 裁判所命令にもとづくドメインの差し押さえを執行した**（出典2・3）。 **参加の理由は、脅威アクターがこの犯罪インフラを使って 病院や医療機関を標的にしたことである**（出典2）。 **会員が狙われたという事実を、原告としての立場に 変換している**（本記録の評価）。
    取るべき行動 **①自社が参加している業界団体・ISAC が、 情報共有以外にどの手段（法的措置・当局への集団申告・ 共同の注意喚起）を取りうるかを確認する。** **②自社の業種が標的とされた事実を団体へ報告する経路と、 報告の粒度（匿名化の範囲）を事前に決める。** **③団体側が法的手続きを取る場合に、 自社が証拠として提供できる範囲を法務と確認しておく。**
  • **教育機関・非営利団体は、自組織のテナントが「商品」になる側である**
    **YAM Store の商材には、教育機関（.edu）や 非営利団体（.org）の環境が含まれていた**（出典1）。 **これらは、信頼される送信元として価値がある一方、 監視と対策の予算が相対的に小さい**（本記録の評価。 出典1はこの理由を述べていない）。 **自組織が直接の被害を受けないまま、 他者を攻撃する道具として売られる可能性がある。**
    取るべき行動 **①テナント内の全アカウント（職員・学生・卒業生・ 外部協力者・サービスアカウント）を棚卸しし、 休眠アカウントを無効化する。** **②アプリケーション登録とその認証情報を一覧化し、 用途不明のものを削除する（本件では盗まれたアプリケーション 認証情報が使われていた）。** **③外向きのメール送信量とストレージの共有リンク発行数を 測り、異常なときに受ける担当を決める。**
セキュリティ技術者への示唆
  • **device code 認証フローを使う必要があるか確認し、無ければ遮断する**
    **Microsoft 365 の顧客を狙った7億5千万通超のメッセージのうち、 多くが device code フィッシングで認証トークンを 取得しようとしていた**（出典3）。 **この手口では利用者は本物のページにコードを入力するため、 URLの確認という教育が効かない**（本記録の評価）。 **得られるのはトークンであり、 多要素認証を済ませた後の状態が持ち出される**（本記録の評価）。
    取るべき行動 **①直近90日の監査ログから、device code フローによる サインインの件数と対象利用者を抽出する。** **②正当な用途（入力手段の限られた機器など）が無ければ、 条件付きアクセスでこのフローを遮断する。** **③用途がある場合は、対象を特定の利用者・機器・ 場所に絞った例外として構成する。**
  • **自組織が使わない外部テナントのストレージへのリンクを、判定の対象にする**
    **侵害された Microsoft 環境の SharePoint と OneDrive が、 フィッシングのホスティングに流用されていた**（出典3）。 **ドメインは正規であり、評価による判定を通過する** （本記録の評価）。 **区別できるのは「自組織の業務で使う相手かどうか」だけである。**
    取るべき行動 **①直近90日で受信したメールに含まれる SharePoint・OneDrive の リンクを、テナント単位で集計する。** **②業務で使う取引先のテナントを許可リストにし、 それ以外のテナントへのリンクを警告または隔離の対象にする。** **③許可リストの更新手順と担当を決める （新規取引先が増えるたびに運用が詰まるため）。**
  • **ジオフェンシングとIPフィルタリングを備えた相手には、「踏んで確認する」が通じない**
    **キットはジオフェンシング・偽のCAPTCHAゲート・ IPフィルタリングに対応し、セキュリティ解析を妨げていた**（出典3）。 **防御側の調査環境からアクセスすると、無害な内容が返る** （本記録の評価）。 **「開いて無害だったから問題ない」という判定が 誤りになる**（本記録の評価）。
    取るべき行動 **①不審URLの調査手順に、 「調査環境からのアクセスで無害だった場合も安全と結論しない」旨を 明記する。** **②調査時の出口IP・利用者エージェント・言語設定を 被害者側に近づけられる手段（調査用の環境）を用意する。** **③判定を外部サービスだけに委ねず、 利用者からの報告内容（実際に表示された画面）を 記録する経路を作る。**
  • **アプリケーション登録とその認証情報を、人のアカウントと同じ厳しさで棚卸しする**
    **侵害された Microsoft 環境では、盗まれたアプリケーションの 認証情報を使ってアカウントとライセンスが管理されていた**（出典3）。 **アプリケーションの認証情報による操作は、 利用者のサインインとして現れない**（本記録の評価）。 **人のログインだけを監視する仕組みでは異常にならない。**
    取るべき行動 **①テナント内のアプリケーション登録とサービスプリンシパルを 全件抽出し、用途・所有者・付与された権限を列にする。** **②所有者不明・用途不明・長期未使用のものを削除する。** **③残すものについて、認証情報（シークレット・証明書）の 有効期限と更新手順を決め、 アプリによる管理操作を監査ログの監視対象に加える。**
