INC-2026-0534Cisco SEG に悪用済みの9.8、2か月連続

Cisco Secure Email Gateway の AMP 添付ファイル処理に任意ファイル書き込みの脆弱性 CVE-2026-76519（CVSS 9.8）——細工した添付メール1通で root 権限のコマンド実行に至り、 2026年10月に悪用が確認、CISA は追加3日で修正を命じた

脆弱性脅威・攻撃キャンペーン初報のみ有名事象として記録（日本と直接の関係は薄い）未知の脆弱性の悪用設計・実装上の不備
初報: 2026年10月14日（Cisco のセキュリティアドバイザリ公開） 最終更新: 2026年10月15日

Cisco Systems は2026年10月14日（現地時間）、Cisco Secure Email Gateway（SEG）の任意ファイル書き込みの脆弱性CVE-2026-76519 についてセキュリティアドバイザリを公開しました（出典1・5）。CVSS v3.1 の基本値は9.8（Critical）で、ベクトルは CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H です（出典1）。

成立の条件はメール1通です。 脆弱性はマルウェア対策機能 Advanced Malware Protection（AMP）におけるメール添付ファイルの処理に存在し、細工した添付ファイルを含むメールを未修正の機器に処理させることで、認証を必要とせずに悪用できます（出典1・3）。Cisco は「攻撃が成功すると、基盤となるOS上で任意のファイルを書き込み、root 権限でコマンドを実行できる可能性がある」としています（出典1。本記録の訳）。

悪用はすでに確認されています。 アドバイザリは「2026年10月、Cisco PSIRT は本脆弱性の活発な悪用を認知した」と記しています（出典1。本記録の訳）。米国 CISA は同日（2026年10月14日）これを Known Exploited Vulnerabilities カタログへ収載し、連邦政府機関に対する修正期限を2026年10月17日——わずか3日後——に設定しました（出典2・4）。

影響を受けるのは、2つの条件が揃った機器です（出典1）。①File Reputation サービス（Cisco AMP の一部）が有効でメールポリシーに割り当てられている②Content Scanner Tools の版が 25.3.0.5525 より前である。 回避策はありません（出典1）。Content Scanner Tools を 25.3.0.5525 以降にすれば再起動なしで修正を適用できます（出典1）。

本記録が重く見るのは、これが同一製品で2か月連続、11か月で3件目の「悪用済み root 奪取」であることです（本記録の評価）。2026年9月の CVE-2026-76461（SQLインジェクション・CVSS 9.8）、2026年1月の CVE-2025-20393（AsyncOS・最大深刻度）がいずれもゼロデイとして悪用されています（出典3・4）。メールを検査するために全社のメールが必ず通る装置が、いま最も狙われている入口の1つになっています（本記録の評価）。

復旧の手順にも注意が要ります。 Cisco は、侵害が疑われる仮想アプライアンスについて「アップグレードするとフォレンジックのデータが破壊される」ため先に保全せよと明記しています（出典1。本記録の訳）。またクラスタ構成では SSH 鍵が露出しているおそれがあるため、1台でも侵害された場合は全メンバを復旧させるよう求めています（出典1）。

攻撃の経過

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

**公表されている攻撃の筋道は短い**（出典1） ——**①細工した添付ファイルを含むメールを未修正の機器に処理させる ②AMP の File Reputation による添付ファイルの処理で 相対パストラバーサル（CWE-23）が成立する ③基盤OS上に任意のファイルを書き込める ④root 権限でコマンドを実行できる。** **認証は不要であり、利用者の操作も要らない**（出典1）。 **公表されていないのは、攻撃者の帰属、 root 権限の取得後に行われた操作、 通信先やマルウェアといったネットワーク側の指標である**〈未確定1・5〉。 **以下は、アドバイザリに書かれた範囲だけで段階を組み立てる**（本記録の明示）。

  1. 1. 初期侵入確認済
    **攻撃者が、悪意をもって細工した添付ファイルを含むメールを 未修正の機器を通して送る**（出典1・3）。 **認証は不要**（出典1）。
    根拠: **Cisco のアドバイザリ**（出典1）。 **「Threat actors can exploit this issue by sending an email with a maliciously crafted attachment through an unpatched device.」** （出典3。本記録の訳: 攻撃者は未修正の機器を通して 悪意をもって細工した添付ファイル付きのメールを送ることで悪用できる）。
  2. 2. 実行確認済
    **AMP による添付ファイルの処理において相対パストラバーサル（CWE-23）が成立し、 基盤となるOS上に任意のファイルを書き込める**（出典1・2）。 **その結果、root 権限でコマンドを実行できる**（出典1）。 **CVSS v3.1 の評点は9.8、ベクトルは `CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H`**（出典1）。
    根拠: **Cisco のアドバイザリ**（出典1） ——**「A successful exploit could allow the attacker to write arbitrary files and execute commands with root privileges on the underlying operating system.」**（出典1・3。本記録の訳: 攻撃が成功すると、 攻撃者は基盤となるOS上で任意のファイルを書き込み、 root 権限でコマンドを実行できる可能性がある）。
  3. 3. 検知回避推定
    **Cisco は、攻撃者が脆弱なシステム上で root 権限のコマンド実行を得た後に 悪用の証拠を消す可能性があるとして、 ファイアウォールとネットワークのログを突き合わせ、 外部や不審なIPアドレスとのダウンロード・アップロードを含む 疑わしい活動の兆候を確認するよう顧客に求めている**（出典1・3）。
    根拠: **Cisco のアドバイザリおよび報道**（出典1・3）。 **実際に痕跡の消去が行われたという記述ではなく、 その可能性を前提に確認を求める記述である**（本記録の明示）。
  4. 4. 永続化推定
    **クラスタ構成では、クラスタの SSH 鍵が露出しているおそれがあるため、 1台でも侵害された場合は全メンバを復旧させるよう Cisco は求めている**（出典1）。 **また侵害が疑われる機器については、 認証情報とアプライアンス上の暗号資材を更新するよう求めている**（出典1）。
    根拠: **Cisco のアドバイザリの Recommendations 節**（出典1）。 **実際に永続化が設置された事例の記述ではない**（本記録の明示） ——**ただし先行の CVE-2025-20393 では、 攻撃者が永続化の仕組みを設置したと報じられている**（出典4）。

メール1通で root を取られる——しかも装置の「検査する機能」が入口だった原因・手口

脆弱性の位置が、この事案の読みどころです（本記録の評価）。

CVE-2026-76519 は、Cisco Secure Email Gateway のAdvanced Malware Protection（AMP）機能におけるメール添付ファイルの処理に存在します（出典1・3・5）。CWE-23（相対パストラバーサル）で、未修正の機器に細工した添付ファイル付きのメールを処理させることで、認証を必要とせず悪用できます（出典1・3）。

「攻撃が成功すると、攻撃者は基盤となるオペレーティングシステム上で任意のファイルを書き込み、root 権限でコマンドを実行できる可能性がある」（出典1。原文英語。本記録の訳）

攻撃の前提は「メールが届くこと」だけです（本記録の整理）。メールゲートウェイは、外部からのメールを受け取るためにインターネットに向いている必要があります。 そして AMP は、まさに添付ファイルを検査するための機能です。 つまり、守るための機能に、守りを破る入口がありました（本記録の評価）。

影響を受けるのは、次の2条件が揃った物理・仮想アプライアンスです（出典1）。

  1. File Reputation サービス（Cisco AMP の一部）が有効で、メールポリシーに割り当てられている
  2. Content Scanner Tools の版が 25.3.0.5525 より前

Cisco Secure Email and Web Manager および Secure Web Appliance は影響を受けないと明記されています（出典1）。

回避策はありません（出典1）。修正は、AsyncOS 15.5 系で 15.5.5-014、16.5 系で 16.5.0-780、16.0 系は修正版への移行です（出典1）。Content Scanner Tools を 25.3.0.5525 以降にすることでも修正が適用され、こちらは再起動を要しません（出典1）——メールの滞留を避けたい運用では、この経路が現実的です（本記録の評価）。

自機が該当するかの判定方法も示されています（出典1・3）。CLI の contentscannerstatus コマンドで Content Scanner Tools の版を確認し、管理画面の Mail Policies > Incoming Mail Policies > Advanced Malware Protection（および Outgoing Mail Policies 側）で「Enable File Reputation」のチェックを見る、という手順です（出典3）。

期限3日は短いです（本記録の評価）。The Register はこれを「土曜日の期限」と表現しています（出典4）。先行の CVE-2026-76461 も収載9月14日・期限9月17日の3日間であり、同じ間隔です（出典2。本記録の対比）。

要求されているのは適用だけではありません（出典2）。BOD 26-04（リスクに基づくセキュリティ更新の優先順位付け）および「フォレンジック・トリアージ要件」の遵守が求められ、緩和策が無い場合は製品の使用中止まで選択肢に挙げられています（出典2。本記録の訳）。

日本の組織に CISA の期限は直接適用されません（本記録の明示）。しかし「収載から3日」という水準は、米国政府が本件の緊急度をどう評価したかを示す指標として使えます（本記録の評価）——自社の緊急適用の判断に、外部の第三者評価として引用できます。

アップグレードがフォレンジックの証拠を壊す——順序を間違えると調査できない組織の対応

アドバイザリの「Recommendations」節には、実務上もっとも間違えやすい点が書かれています（本記録の評価）。

侵害が疑われる仮想アプライアンスについて、Cisco は「アップグレードするとフォレンジックのデータが破壊される」ため先に保全せよと明記しています（出典1。本記録の訳）。そのうえで、修正版で新しい仮想マシンを立ち上げ、以前の設定ファイルを取り込まずに構成を作り直し、認証情報と暗号資材を更新し、監視を続けるよう求めています（出典1）。

物理アプライアンスの場合は、Cisco TAC に連絡し、調査を助けるためにリモートアクセスを有効にするよう求めています（出典1）。

クラスタ構成には別の注意があります（出典1）。クラスタの SSH 鍵が露出しているおそれがあるため、1台でも侵害された場合は全メンバを復旧させるよう求めています（出典1）。「1台だけ直して終わり」にできない構成です（本記録の整理）。

侵害の有無の判定方法は、機器のログです（出典1・3）。grep "System Security" system_logs を実行し、クラスタ構成では各メンバのログを確認します（出典1）。現れるメッセージは3種です（出典1・3）。

ログメッセージ 意味と推奨される対応
Suspected compromise indicator was found. 侵害を検知。アドバイザリの推奨手順に従う
Security scan did not complete. Cisco TAC に連絡する
No compromise indicator was found. 侵害は検知されず。該当すれば修正版へアップグレード

ただし、この判定には限界があります（本記録の評価）。Cisco は、攻撃者が root 権限のコマンド実行を得た後に悪用の証拠を消す可能性があるとして、ファイアウォールとネットワークのログも突き合わせるよう求めています（出典1・3）。機器上の判定だけに頼ると、「No compromise indicator was found」を誤って安心の根拠にしかねません（本記録の評価）。

Cisco Secure Email Cloud については、Cisco がすでに緩和策を展開し、侵害の可能性を示す痕跡を見つけた顧客に連絡したとしています（出典1・3）。連絡を受けた顧客には、認証情報とアプライアンス上の暗号資材の更新、機器へのアクセス制限と堅牢なアクセス制御の実施を強く推奨しています（出典1）。

日本の読者にとっての距離——国内の被害公表は無いが、該当機器は国内にもある評価・解釈

本記録は、日本国内の被害を示す公表を確認できていません〈未確定6〉。影響が無いという意味ではありません（本記録の明示）。

判断に使える材料は3つです（本記録の整理）。

①Cisco 広報は影響が「限られた数の顧客」に及ぶとしています（出典4）——ただし件数は示されていません〈未確定2〉。

②Shadowserver はインターネット上に露出したCisco Secure Email Gateway を約300台追跡しているとされます（出典3）——これは本脆弱性の条件を満たす台数ではなく、露出している製品の台数という背景値です（本記録の明示）。

③本脆弱性の悪用には、機器がインターネットに露出していることは必須ではありません（本記録の整理）——攻撃の経路はメールであり、外部からのメールを受け取る構成であれば成立します（出典1・3）。したがって、露出台数の少なさを安心の根拠にできません（本記録の評価）。

確認すべきことは単純です（本記録の整理）。自社または委託先が Cisco Secure Email Gateway を使っているか。 使っているなら、File Reputation が有効か、Content Scanner Tools の版は 25.3.0.5525 以降か。 ログに「System Security」で始まる侵害の指標が無いか。

メールゲートウェイの運用を外部に委託している組織は、委託先に同じ確認を依頼する必要があります（本記録の評価）——自社で管理画面に入れない場合、上記の確認はすべて委託先しか実行できません。

検知できた　**本記録の評価。** **アドバイザリは堅牢化として、 ログを外部サーバへ送ることを挙げている**（出典1）。 **本脆弱性では、Cisco が示す侵害の指標が 機器上のログメッセージであるため、 転送していれば検知の自動化に使える**（本記録の整理）。
検知回避機会はあったが検知できず
**本記録の評価**——**機器の外に記録があるかどうかで分かれる。** **根拠は、Cisco 自身が機器上の判定に加えて ファイアウォールとネットワークのログの突き合わせを 求めていることである**（出典1・3） ——**提供者が機器上の判定の限界を認めている形である**（本記録の読み）。 **本記録の留保**——**実際に痕跡消去が行われた事例の公表は無い**（本記録の明示）。
検知できた　**本記録の評価。** **Cisco が求めている確認（外部・不審なIPとの ダウンロード／アップロード）を、 事後ではなく常時行う形にしたものである**（出典1。本記録の整理）。
永続化公表されていない
**公表されていない**（出典1）。 **本脆弱性で永続化が設置されたという記述は無い**（本記録の明示）。 **本記録は、クラスタの SSH 鍵露出という Cisco の警告から、 侵害の影響が1台に留まらない構造であることだけを読む**（本記録の読み）。
影響を限定できた　**本記録の評価。** **Cisco が明記している手順である**（出典1）。 **重要なのは順序である**——**アップグレードは フォレンジックのデータを破壊するため、保全を先に行う**（出典1）。

対応の評価

評価材料がない判断は「評価材料なし」としています。結果論で断じないための区分です。
判断評価評価の根拠と留保
部分的に機能**本記録の評価**——**部分的に機能した。** **評価できる点が3つある。** **①侵害の判定方法を具体的なコマンドと ログメッセージの形で示したこと**（出典1）。 **②「アップグレードするとフォレンジックのデータが破壊される」という 順序の注意を明記したこと**（出典1） ——**これを書かなければ、善意の対処が調査を不可能にする。** **③クラスタの SSH 鍵露出という波及の構造を示したこと**（出典1）。 **不十分な点は、ネットワーク側で照合できる侵害指標が無いことである**〈未確定5〉 ——**機器上のログは攻撃者に消される可能性があると Cisco 自身が警告しており**（出典1・3）、 **その場合に顧客が使える指標が残らない**（本記録の評価）。
機能した**本記録の評価**——**クラウド分については機能した。** **根拠は、緩和策の展開と痕跡にもとづく個別連絡の双方を 提供者側で実施したとされることである**（出典1・3）。 **本記録の留保**——**連絡した顧客の数は公表されていない**〈未確定2〉 ——**実施の規模は検証できない。**
機能した**本記録の評価**——**機能した。** **根拠は、修正版（AsyncOS および Content Scanner Tools）と 判定手順が公開と同時に揃っており、 読んだ組織がその日に行動できる状態だったことである**（出典1）。 **特に Content Scanner Tools の更新が再起動を要しない点は、 メールを止められない組織にとって実務上大きい**（本記録の評価）。
CISO・経営層への示唆
  • **境界に置く装置は、月次のパッチ運用では間に合わない前提で予算と権限を置く**
    **本件は、同一製品で2か月連続、11か月で3件目の 「悪用済みで root に至る」脆弱性である**（本記録の算出。出典1・3・4）。 **CISA は収載から3日後の期限を課しており、 先行の CVE-2026-76461 でも同じ3日間だった**（出典2）。 **月次の定例作業として扱う限り、この間隔には追いつけない**（本記録の評価）。
    取るべき行動 **①メールゲートウェイ・VPN装置・ファイル転送装置・ 境界のファイアウォールを「緊急適用の対象」として別枠に定義する。** **②その枠について、営業時間外・休日の作業を 事前承認（都度の決裁を不要）にしておく。** **③緊急適用に伴う業務停止の許容時間を、事業部門と事前に合意する ——有事に決める事項を減らす。**
  • **善意の復旧が調査を不可能にする。順序を手順書に書く**
    **Cisco は、侵害が疑われる仮想アプライアンスについて 「アップグレードするとフォレンジックのデータが破壊される」ため 先に保全せよと明記している**（出典1。本記録の訳）。 **通常の障害対応では「まず最新版へ上げる」が正しい手順であり、 その習慣がそのまま証拠の破壊になる**（本記録の評価）。 **CISA も本件を「フォレンジック・トリアージ」の対象（Yes）に 設定している**（出典2）。
    取るべき行動 **①機器更新の手順書の冒頭に 「侵害が疑われる場合はここで止めて保全する」という分岐を入れる。** **②保全の具体的な手段（仮想機器のスナップショット、 ディスクイメージ、ログの外部退避）を機器種別ごとに書く。** **③保全の判断権者と、判断に迷ったときの連絡先 （ベンダのサポート窓口）を手順書に明記する。**
  • **ベンダが「限られた数の顧客」と言うとき、自社がその中にいるかは自分で確かめる**
    **Cisco 広報は影響が「限られた数の顧客」に及ぶとした一方、 件数を示さず、侵害された機器の台数についての質問には 回答を拒んだとされる**（出典4。本記録の訳）〈未確定2〉。 **影響条件は2つの設定の組み合わせであり**（出典1）、 **自社が該当するかは自社でしか判定できない**（本記録の評価）。
    取るべき行動 **①該当判定を「誰が・いつまでに・何を見て行うか」を指示として出す （本件なら Content Scanner Tools の版と File Reputation の有効／無効）。** **②判定結果を記録として残す ——「該当しなかった」ことの根拠を後から示せるようにする。** **③メールゲートウェイの運用を委託している場合、 同じ判定を委託先に依頼し、回答を文書で受け取る。**
  • **クラウド提供の機器とオンプレミスの機器で、気づける人が違う**
    **本件では、Cisco Secure Email Cloud については Cisco が緩和策を展開し、侵害の痕跡を見つけた顧客に 個別に連絡したとされる**（出典1・3）。 **オンプレミスの機器については、 顧客自身がログを検索して判定する必要がある**（出典1）。 **同じ製品でも、提供形態によって 「誰が最初に気づくか」が変わる**（本記録の評価）。
    取るべき行動 **①自社の境界装置を提供形態（クラウド／オンプレミス／委託運用）で 分類し、それぞれ「侵害に最初に気づくのは誰か」を書き出す。** **②自社が気づく側になる区分について、 確認手順と確認の頻度を決める。** **③ベンダからの連絡を受け取る窓口（メールアドレス・担当）が 最新かを確認する——連絡が届かなければ提供者側の検知も意味を持たない。**
セキュリティ技術者への示唆
  • **Content Scanner Tools の版から確認する（再起動なしで直せる経路がある）**
    **影響条件は、File Reputation が有効でメールポリシーに割り当てられ、 かつ Content Scanner Tools が 25.3.0.5525 より前であること**（出典1）。 **Content Scanner Tools を 25.3.0.5525 以降にすれば 修正が適用され、再起動を要しない**（出典1）。 **AsyncOS 本体の更新は再起動を伴い、メールの滞留を招く**（本記録の整理） ——**止められない環境では、まずこちらを確認する価値がある。**
    取るべき行動 **①CLI で `contentscannerstatus` を実行し、 Content Scanner Tools の版を確認する**（出典3）。 **②管理画面の Mail Policies > Incoming Mail Policies > Advanced Malware Protection および Outgoing Mail Policies 側で 「Enable File Reputation」のチェックを確認する**（出典3）。 **③該当する場合、Content Scanner Tools を 25.3.0.5525 以降へ更新し、 続いて AsyncOS を修正版（15.5.5-014／16.5.0-780）へ計画する。**
  • **侵害の判定を、機器上のログだけで打ち切らない**
    **Cisco が示す侵害指標は、機器の system_logs に現れる 「System Security」で始まるメッセージ3種である**（出典1・3）。 **同時に Cisco は、攻撃者が root 権限のコマンド実行を得た後に 悪用の証拠を消す可能性があるとして、 ファイアウォールとネットワークのログの突き合わせを求めている**（出典1・3）。 **「No compromise indicator was found」は、 それだけでは安心の根拠にならない**（本記録の評価）。
    取るべき行動 **①`grep "System Security" system_logs` を実行する。 クラスタでは各メンバで実行する**（出典1）。 **②同じ期間のファイアウォール・プロキシのログで、 当該機器から外部や不審なIPへのダウンロード／アップロードが無いかを見る。** **③今後に備えて、機器のログを外部のログ基盤へ転送する設定を入れる ——アドバイザリの堅牢化にも挙げられている**（出典1）。
  • **クラスタは1台の侵害で全体が汚染される。構成を把握しておく**
    **Cisco は、クラスタの SSH 鍵が露出しているおそれがあるため、 1台でも侵害された場合は全メンバを復旧させるよう求めている**（出典1）。 **「1台だけ直す」では再侵入の経路が残る**（本記録の整理）。
    取るべき行動 **①メールゲートウェイのクラスタ構成（メンバ数・鍵の共有範囲）を 図にして把握する。** **②全メンバを復旧させる場合の所要時間と、 その間のメール配送の代替手段を見積もる。** **③見積もれない場合、それ自体を課題として記録し、 代替経路（別系統のゲートウェイ、クラウド側への一時切替）を検討する。**
  • **「回避策が無い」と書かれた脆弱性では、機能を止める発想に逃げない**
    **Cisco は本件について回避策（workaround）が無いと明記している**（出典1）。 **File Reputation を無効化すれば悪用条件は外れるが、 Cisco はそれを回避策として示していない**（出典1。本記録の確認） ——**添付ファイルのマルウェア検査を止めることは、 別のリスクを開く**（本記録の評価）。
    取るべき行動 **①「回避策なし」の脆弱性では、更新までの時間を短くすることに資源を割く （機能の無効化を代替としない）。** **②どうしても更新できない期間がある場合、 その期間に開くリスクを文書化して承認を取る。** **③機能を止める判断をするときは、 止めたことで開くリスク（検査されない添付ファイルの流入）を併記する。**

自組織に当てはまるか

該当する項目があれば、この事案と同じ構図が自組織でも成立しうることを意味します。
観点自社に当てはまるか該当する場合に何が起きうるか
システム構成□ Cisco Secure Email Gateway（物理または仮想）を運用しており、File Reputation サービスを有効にしてメールポリシーに割り当てている
運用・監視□ 境界装置の緊急パッチ適用に、都度の決裁や定例の作業窓を要し、3日以内の適用ができない
運用・監視□ アプライアンスの更新手順に「侵害が疑われる場合は保全を先に行う」という分岐が無い
システム構成□ メールゲートウェイをクラスタで構成しているが、1台侵害時の全メンバ復旧の所要時間を見積もっていない
運用・監視□ アプライアンスのログを外部のログ基盤へ転送しておらず、機器上の記録だけが侵害判定の材料である
委託・第三者部品□ メールゲートウェイの運用を外部に委託しており、自社では版の確認も設定の確認もできない
