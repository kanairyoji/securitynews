INC-2026-0546Langflow の認証後RCEに1,423回

Langflow の MCP Stdio 設定から任意コマンドが走る脆弱性に、 ハニーポットで1,423回の悪用試行——ログインできた利用者なら誰でも実行できた（CVE-2026-105740）

脆弱性脅威・攻撃キャンペーン初報のみ有名事象として記録（日本と直接の関係は薄い）設計・実装上の不備認証情報の悪用（使い回し・推測可能・窃取）
初報: 2026年9月10日（GitHub 勧告 GHSA-7w94-79vh-5mr2 の公開） 最終更新: 2026年10月16日（本記録の確認時点）

「認証が必要」は緩和要因になりませんでした。ログインできる利用者であれば誰でも、サーバ上で任意のコマンドを実行できた脆弱性です。

CVE-2026-105740 は、Langflow 1.9.0 より前の版に存在する認証後のリモートコード実行です（出典1・2）。MCP サーバを「Stdio」トランスポートで追加すると、利用者が入力した command の値が検証なしに bash -c "exec {command}" へ渡され、サーバ一覧が取得された時点で実行されます（出典1・2）。深刻度は CVSS v3.1 で 9.9（AV:N/AC:L/PR:L/UI:N/S:C/C:H/I:H/A:H）、分類は CWE-78 です（出典2・3）。

本記録が要点と見たのは、次の3点です。

  • 仕込んだ設定は残り、他の利用者や管理者がサーバ一覧を開くたびに再実行される。 GitHub の勧告は、Langflow プロセスの権限でサーバが完全に侵害されうるとし、悪意ある設定が永続して、他の利用者や管理者を含めサーバ一覧が読み込まれるたびに再実行されると記載しています（出典1。原文英語）。env フィールドによる環境変数の注入（LD_PRELOAD や PATH の上書き）も経路として挙げられています（出典1・3）。
  • 悪用が観測されている。ハニーポットで1,423回という数字が報じられた。 The Hacker News は2026年10月15日、「脅威アクターが Langflow の重大な脆弱性を悪用している。Previdian の警報による」（原文英語）として、1,423回の悪用試行を伝えました（出典4）。集約サイトの記述では、27 の固有 IP アドレスからの試行で、2026年9月19日に始まり、10月11日には1日で 333回、10月15日の報告時点で 66回とされています（出典5）。本記録はこれらの数値を Previdian の一次資料で確認できていません〈齟齬2〉。
  • 「認証後」であることが、むしろ資格情報の弱さと結びついた。 報道では、観測された攻撃は自動ログインの試行が失敗した後にありふれた資格情報で認証し、得たベアラトークンで当該端点へ到達したとされます（出典5）。公表されている推奨にも「自動ログインを無効化し、資格情報を強化し、ネットワークの露出を絞り、アカウントを信頼できる利用者に限定する」が含まれています（出典5）。

本記録は2026年10月16日に GitHub の勧告 GHSA-7w94-79vh-5mr2（出典1）、GCVE の CVE 記録（出典2）、HOL の CVE 記録（出典3）を直接取得して裏を取りました。 一方、The Hacker News の記事本文（出典4）には到達できず（収集時に本文取得が失敗し、再取得も HTTP 403）、Previdian 自身のブログにも本件の記事は見当たりませんでした〈齟齬2・3〉。

攻撃の経過

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

脆弱性の仕組みは開発者の勧告で確認できる（出典1）。 実際に観測された経路は報道・集約サイト経由であり、 Previdian の一次資料では確認できていない〈齟齬2〉（出典4・5）。

  1. 1. 初期侵入推定
    インターネットに面した Langflow に対し、 自動ログインまたはありふれた資格情報で認証し、ベアラトークンを得る （出典5。本記録は一次資料で確認できていない〈齟齬2〉）。
    根拠: 「自動ログインの試行が失敗した後、攻撃者はありふれた資格情報で認証し、 その後ベアラトークンを使って脆弱な MCP 端点に到達した」（出典5。原文英語）。
  2. 2. 実行確認済
    MCP サーバを Stdio トランスポートで追加し、 `command` フィールドに任意の OS コマンドを入れる。 値は検証されずに `bash -c "exec {command}"` へ渡され、 サーバ一覧の取得時に実行される（CVE-2026-105740。出典1・2・3）。
    根拠: 「利用者が与えた command の値は検証・許可リスト・サンドボックスなしに サーバ上で実行され、サーバ一覧が取得されたときに実行される」（出典3。原文英語）。
  3. 3. 永続化確認済
    書き込んだ設定が残り、他の利用者や管理者を含めて サーバ一覧が読み込まれるたびに再実行される（出典1）。
    根拠: 「悪意ある設定は永続し、他の利用者や管理者を含め、 サーバ一覧が読み込まれるたびに再実行される」（出典1。原文英語）。
  4. 4. 権限昇格確認済
    `env` フィールドで環境変数を注入する （`LD_PRELOAD` や `PATH` の上書きが例として挙げられている）（出典1・3）。
    根拠: 「env フィールドは任意の環境変数の注入を許す（LD_PRELOAD や PATH の上書きなど）」 （出典3。原文英語）。
  5. 5. 収集推定
    ホストのファイルシステム（Docker 経由を含む）へアクセスし、 環境変数と機微な設定値を窃取する （出典5。本記録は一次資料で確認できていない〈齟齬2〉）。
    根拠: 集約サイトは、観測された攻撃としてファイルシステムへのアクセス、 環境変数と機微な設定値の窃取を挙げる（出典5）。
  6. 6. 持ち出し推定
    取得した設定データを外部のホストへ送信する （集約サイトは `146.70.211[.]112:18764` を挙げる。出典5）。 本記録はこの IP の悪性を検証していない（検知・遮断の根拠には使わないこと）。
    根拠: 集約サイトは、設定データを遠隔のホスト（出典上は無害化表記）へ 送信していたと記す（出典5）。
  7. 7. 影響（暗号化・破壊・改ざん）推定
    Langflow プロセスの権限でのサーバの完全な侵害。 集約サイトはホストの侵害・設定の窃取・横展開・ 永続的なバックドアの可能性を挙げる（出典1・5）。 成功した侵害の件数は公表されていない〈未確定1〉。
    根拠: GitHub の勧告は「Langflow プロセスの権限での完全なサーバ侵害」を記す（出典1。原文英語）。

被害組織の対応

2026年9月10日（T1）から2026年10月5日（T3）まで約25日 （出典1・2。日数は本記録の算出）。
勧告公開から悪用の「確認」記録まで
2026年9月10日（T1）から2026年10月11日（T5）まで約31日 （出典1・2。日数は本記録の算出）。 集約サイトの記述では悪用試行の開始は2026年9月19日とされ〈齟齬1〉、 その場合は勧告公開から約9日である（出典5。算出は本記録）。
この事案で下された判断
  • トレードオフ: 勧告が先に出ることで更新の判断は早くできる。 一方 CVE が遅れると、CVE 番号を入口にしている脆弱性管理の仕組みでは 約25日間、本件が台帳に載らない（本記録の評価）。
  • トレードオフ: フィードとして「悪用あり」が流通することで、 購読者には早く届く。 一方、購読していない読者は数値の根拠を辿れない（本記録の評価）。

「認証が必要」は緩和にならない——ログインできる利用者であれば誰でも実行できた原因・手口

GitHub の勧告の表題がそのまま性質を表しています（出典1）。

MCP Stdio トランスポート経由の認証後リモートコード実行により、どの利用者でもサーバ上で任意の OS コマンドを実行できる（出典1。原文英語）

成立の筋は短いものです（出典1・2・3）。管理者でない利用者を含め、認証済みのどの利用者でもMCP サーバを「Stdio」トランスポートで追加できます（出典1）。そのとき利用者が入力した command の値は、検証・許可リスト・サンドボックスのいずれも通さずにbash -c "exec {command}" へ渡されます（出典2・3）。実行されるのは、サーバ一覧が取得された時点です（出典1・2）。

GitHub の勧告はさらに2点を加えています（出典1）。1つは、env フィールドによって任意の環境変数を注入できること—— LD_PRELOAD や PATH の上書きが例として挙げられています（出典1・3）。もう1つが、本記録が最も重いと見た点です（本記録の評価）。悪意ある設定は残り続け、他の利用者や管理者を含めてサーバ一覧が読み込まれるたびに再実行される、と記載されています（出典1。原文英語）。

つまり、仕込む側は一度書き込めば済み、引き金を引くのは別の利用者になります（出典1。整理は本記録）。評点の S:C（スコープが変わる）と PR:L（低い権限で足りる）が組み合わさって CVSS v3.1 で 9.9 になっているのは、この性質を反映したものと読めます（評点は出典2・3、読み方は本記録）。

分類は CWE-78（OS コマンドインジェクション）、修正版は 1.9.0 です（出典1・2・3）。修正はプルリクエスト #12290、コミット efbc4a16e639409d938a4883463d27ef0bc637a0 として記録されています（出典2）。

ハニーポットで1,423回——ただし数値の出所は報道経由である被害規模・影響範囲

The Hacker News は2026年10月15日、次のように報じています（出典4）。

脅威アクターが Langflow の重大な脆弱性を悪用している。Previdian の警報による（出典4。原文英語）

見出しに「1,423 Honeypot Exploit Attempts」とあり、ハニーポットでの悪用試行が1,423回だったとされます（出典4）。

集約サイトの記述では、内訳はこうなっています（出典5）。27 の固有 IP アドレスからの試行で、2026年9月19日に Previdian のハニーポットに現れ始め、2026年10月11日には1日で 333回、2026年10月15日の報告時点で 66回です（出典5）。観測された挙動として、ホストのファイルシステムへのアクセス（Docker 経由を含む）、環境変数と機微な設定値の窃取、設定データを外部のホスト（146.70.211[.]112:18764）へ送信することが挙げられています（出典5）。

ここで本記録の立場を明示します（本記録の整理）。これらの数値と挙動は、いずれも Previdian の一次資料で確認できていません〈齟齬2〉。The Hacker News の記事は収集時に本文取得が失敗しており、本記録による再取得も HTTP 403 で拒否されました（本記録の確認）。Previdian 自身のブログを確認しましたが、本件に関する記事は見当たらず、最も近いのは別の脆弱性（CVE-2026-0770）に関する2026年7月21日の記事でした〈齟齬3〉。また上記の IP アドレスは報道経由の値であり、本記録は悪性を検証していません。検知や遮断の根拠には使わないでください（本記録の注記）。

一方、Previdian が「悪用あり」と記録していること自体は確認できています（出典2）。GCVE の CVE 記録には、2026年10月11日 17:42 UTC 時点で「Exploited: Yes」「Status: Confirmed」「信号: 公開報告による悪用成功」「確度 70%」「初観測 2026年10月11日」「CISA KEV には未収載」と登録されています（出典2）。

ここに食い違いがあります〈齟齬1〉。集約サイトは悪用の開始を2026年9月19日とするのに対し（出典5）、Previdian の記録上の初観測は2026年10月11日で、しかも信号の種類は「公開報告による」とされています（出典2）。本記録はこの差を解消できていません（本記録の整理）。

観測された経路は、ありふれた資格情報と自動ログインを踏み台にしていた評価・解釈

「認証後」という条件が、どう満たされたかが本件の肝です（本記録の評価）。

集約サイトの記述では、観測された攻撃の経路はこうなっています（出典5）。自動ログインの試行が失敗した後、攻撃者はありふれた資格情報で認証し、得たベアラトークンで脆弱な MCP 端点へ到達したとされます（出典5）。本記録は一次資料で確認できていません〈齟齬2〉。

この記述が正しいとすれば、読み方は次のようになります（本記録の評価）。CVSS の PR:L は「権限が要る」という条件ですが、その権限の獲得コストが、自動ログインの有効化や既定・推測可能な資格情報によってほぼゼロに下がっていた——ということです（出典2・3・5。評価は本記録）。公表されている推奨に「自動ログインを無効化し、資格情報を強化し、ネットワークの露出を絞り、アカウントを信頼できる利用者に限定する」が入っているのは、この経路に対応するものと読めます（出典5。読み方は本記録）。

もう1点、EPSS の値に注意を促します（本記録の評価）。GCVE の記録では EPSS は 0.00589、パーセンタイルは約 0.47 です（出典2）。悪用が観測されているにもかかわらず、EPSS は低いままです（出典2・4・5。対比は本記録）。さらに CISA KEV には未収載とされています（出典2）。EPSS と KEV を優先順位の唯一の入口にしている組織では、本件は「後回し」の列に入り続けていた可能性があります（本記録の評価）。SSVC（CISA ADP）の評価は Exploitation が「poc」、Automatable が「no」、Technical Impact が「total」です（出典2）。

対策は 1.9.0 への更新だが、同系の別 CVE が並んでいることに注意が要る対策・注意喚起

修正版は Langflow 1.9.0 です（出典1・2・3）。

報じられている推奨は次のものです（出典5）。

  • Langflow 1.9.0 または以降の修正版へ更新する（出典5）
  • 自動ログインを無効化し、資格情報を強化し、ネットワークの露出を絞り、アカウントを信頼できる利用者に限定する（出典5）

CISO・経営層への示唆
  • 「認証が必要」を緩和要因として扱わない。認証の壁の高さは自組織の設定で決まる。
    本件は認証後のリモートコード実行だが、CVSS v3.1 は 9.9 である（出典2・3）。 集約サイトの記述では、観測された攻撃は自動ログインの試行とありふれた資格情報で その壁を越えている（出典5）。
    取るべき行動 脆弱性の評価で「認証後だから後回し」とする判断を禁じる。 かわりに「自組織でその認証をどれだけ容易に得られるか」 （自動ログイン・既定資格情報・外部からの到達性）を確認する手順を置く。
  • EPSS と CISA KEV を優先順位の唯一の入口にすると、本件は後回しの列に残る。
    悪用が観測されているにもかかわらず、 EPSS は 0.00589（パーセンタイル約 0.47）、 CISA KEV には未収載とされている（出典2）。 一方 Previdian は2026年10月11日に「悪用あり・確認」と記録している（出典2）。
    取るべき行動 脆弱性の優先順位づけに、KEV・EPSS 以外の悪用観測の情報源を1つ加える。 加えた情報源について、確度の表記（本件では 70%）を そのまま社内の判断に持ち込む運用を決める。
  • AI ワークフロー基盤は「社内の誰でもログインできる開発ツール」として置かれやすい。
    本件は認証済みのどの利用者でも実行できる脆弱性で、 仕込んだ設定は他の利用者や管理者がサーバ一覧を開くたびに再実行される（出典1）。 アカウントを広く配った配備ほど、攻撃可能な主体が増える（本記録の評価）。
    取るべき行動 社内で立てている AI 基盤（Langflow・エージェント実行環境・MCP サーバ）を 資産台帳に登録し、インターネットからの到達性とアカウント数を確認する。 「実験用だから」で管理外に置かれているものを洗い出す。
  • 更新だけでは終わらない事案がある。仕込まれた設定の棚卸しを手順に入れる。
    GitHub の勧告は、悪意ある設定が永続して サーバ一覧の読み込みごとに再実行されると明記している（出典1）。 更新時に既存の設定がどう扱われるかは示されていない（本記録の確認）。
    取るべき行動 脆弱性対応の手順に「更新後の設定・永続化物の確認」という段を加える。 本件では MCP サーバ設定と認証ログが対象になる（出典5）。
セキュリティ技術者への示唆
  • 利用者の入力をシェルに渡す実装を残さない。`bash -c` の文字列組み立てが本件の核である。
    利用者が与えた `command` の値が検証・許可リスト・サンドボックスのいずれも 通さずに `bash -c "exec {command}"` へ渡されていた（出典2・3）。 分類は CWE-78 である（出典1・2）。
    取るべき行動 外部プロセスの起動を、シェルを経由しない API（引数の配列を渡す形）に置き換える。 コマンド名は固定の許可リストから選ばせ、引数は型と値域で検証する。
  • MCP の stdio トランスポートは「任意のコマンドを起動する機能」である。管理者機能として扱う。
    Stdio の MCP サーバ設定は、設計上サーバ上でプロセスを起動する（出典1・3）。 Langflow ではこれを認証済みのどの利用者でも追加できた（出典1）。
    取るべき行動 自前で MCP クライアントを実装・運用している場合、 stdio トランスポートの登録を管理者ロールに限定し、 登録・変更を監査ログに残す。 可能であれば stdio を禁止し、ネットワーク越しのトランスポートに限定する。
  • 「保存された設定が後で実行される」構造は、仕込みと実行が時間的に離れる。
    悪意ある設定は永続し、他の利用者や管理者を含め サーバ一覧が読み込まれるたびに再実行される（出典1）。 実行の引き金を引くのは仕込んだ本人ではない（本記録の整理）。
    取るべき行動 設定から実行される処理には、実行時のログに 「どの設定が・いつ・誰の操作で」実行されたかを記録する。 設定の作成者と実行の契機を別々に残す。
  • 環境変数を利用者が指定できる構造は、権限昇格の経路になる。
    `env` フィールドが任意の環境変数の注入を許し、 `LD_PRELOAD` や `PATH` の上書きが例として挙げられている（出典1・3）。
    取るべき行動 子プロセスへ渡す環境変数を、許可した名前の白名簿に限定する。 `LD_PRELOAD`・`LD_LIBRARY_PATH`・`PATH` 等の実行に関わる変数は 利用者入力から受け取らない。
  • 外向き通信の宛先とポートを記録していないと、持ち出しの段階が見えない。
    集約サイトの記述では、設定データが非標準ポートの外部ホストへ 送信されていたとされる（出典5。本記録は一次資料で未確認〈齟齬2〉）。
    取るべき行動 AI 基盤からの egress を既定で絞り、 許可した宛先以外への接続を記録・遮断する。 非標準ポートへの接続は警報の対象にする。
