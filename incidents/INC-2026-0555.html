攻撃の経過

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

**Linux サーバにウェブシェルを置き、PHP の `auto_prepend_file` を改変して 永続化する**（出典1）。 **`.bashrc` の `sudo` 別名・PHP のログイン画面への追記・ 設定ファイルと履歴の走査で資格情報を集め**（出典1）、 **LinPEAS と PwnKit（CVE-2021-4034）で権限昇格を試み、 SUID の root シェルや改名した `/bin/bash` で root を保つ**（出典1）。 **Go 製の RAT「SysGoRAT」と、少なくとも7台の C2 に対する インメモリのリバースシェルで足場を維持する**（出典1）。 **内部の MSSQL で `xp_cmdshell` を有効化して二段跳びで別サブネットへ届け、 `sshpass` と `authorized_keys` への鍵注入で横展開する**（出典1）。 **政府のメールサーバからメールボックスを、 データベースから全件のダンプを持ち出そうとする**（出典1）。 **配備されたスクリプトには、AI が操作者へ向けて書いた会話調の説明が 残っていた**（出典1）。

  1. 1. 初期侵入確認済
    **標的の Linux サーバに多様なウェブシェルを配備した**（出典1）。 **自前のものと GitHub にある公開のものの組み合わせである**（出典1）。 **一例では、正当に見せるため `/usr/lib/php/plesk_sys_driver.php` という名前で 悪性の PHP ウェブシェルを配置した**（出典1）。 **ウェブシェルの操作は `php-fpm` の親プロセスから 対話的に行われていた**（出典1）。 **ウェブシェルを置けた経路は公表されていない**〈未確定2〉。
    根拠: 「アクセスを得て、標的網への永続的なバックドアを維持するため、 攻撃者は標的の Linux サーバに多様なウェブシェルを配備した」 （原文英語。出典1）
  2. 2. 永続化確認済
    **`/etc/php/` と `/opt/plesk/php/` 配下のすべての PHP 設定で `auto_prepend_file` の値を改変した**（出典1）。 **これらは既定の PHP 設定ファイルと Plesk（ウェブホスティング管理画面）の 設定ファイルが置かれる場所である**（出典1）。 **`auto_prepend_file` に指定したファイルは、 他のいかなる PHP スクリプトよりも先に自動で読み込まれ実行される**（出典1）。 **SysGoRAT 側では6種の永続化手段を持つ—— `systemd` のサービス（`/etc/systemd/system/sys-update.service`）、 5分間隔の cron、Windows のレジストリ Run キー （`%APPDATA%\Onedrive Update\Updater.exe`）、 `Onedrive` という日次タスク、OS で自動選択、 OS と権限で自動選択**（出典1）。 **SSH では `authorized_keys` に公開鍵を注入し、 `.ssh` の作成・`chmod 700`・鍵の追記・厳格な権限設定を順に実行した** （出典1）。
    根拠: 「永続化を達成するため、攻撃者は `/etc/php/` と `/opt/plesk/php/` の 各ディレクトリ配下のすべての PHP 設定で `auto_prepend_file` の値を 改変した」（原文英語。出典1）
  3. 3. 認証情報アクセス確認済
    **3つの方法で資格情報を集めた**（出典1）。 **①`.bashrc` の置き換え**——**`sudo` コマンドの別名を作り、 利用者が `sudo` を実行するたびに動くようにした**（出典1）。 **標準の認証プロンプトを模した入力要求を表示し、 入力されたパスワードを捕まえて攻撃者のログファイルへ書き出し、 そのパスワードを本来の `sudo` に渡して実行する**（出典1） ——**被害者は傍受に気づかない**（出典1）。 **ログファイルの名前は `Solarwinds.StatusLog.txt`**（出典1）。 **②PHP の資格情報ロガー**——**PHP のログイン画面に1行を追記し、 管理者がログインすると利用者名とパスワードを 攻撃者のログファイルへ転送する**（出典1）。 **データベースの認証処理が狙いと見られるとされる**（出典1）。 **③平文パスワードの走査**——**設定ファイルとコマンド履歴ファイルの中から、 メール・SMTP・データベースのパスワードを探した**（出典1）。 **`wp-config.php` を検索してハードコードされたデータベースの 資格情報を取り出し、`catbox[.]moe` の API へ出力をアップロードする スクリプトも確認されている**（出典1）。
    根拠: 「攻撃者は `Solarwinds.StatusLog.txt` という名前をログファイルに付け、 環境内の正当な SolarWinds の活動を装った。 本作戦において SolarWinds のシステムおよび基盤が侵害された証拠は無い。 攻撃者は検知回避の手段として同社の名を悪用したものである」 （原文英語。出典1）
  4. 4. 権限昇格確認済
    **Linux サーバへのアクセスを得た後、権限昇格を行った**（出典1）。 **まず公開ツール LinPEAS を配備・実行して ローカルの権限昇格の経路を調べ、 次に PwnKit（CVE-2021-4034 の単体実行型の悪用コード）で root 権限の取得を試みた**（出典1）。 **root を得た後、root アクセスを維持するために3つのバイナリを配備した** （出典1）。 **①改名した正規の Python 3 インタプリタ（`.libpython-helper`）—— `os.setuid(0)` と `os.setgid(0)` で root 権限のシェルを得る。 ②自製の SUID root シェル（`.libsystemd-helper`）—— `setuid(0)`・`setgid(0)` の後 `/bin/sh` で任意のコマンドを実行。 ③改名した正規の `/bin/bash`（`.tourch`）——`chmod u+s` を適用し、 所有者（root）としてコマンドを実行できるようにした**（出典1）。
    根拠: 「攻撃者はディスクに `.tourch` という名前のファイルを書き、 `chmod u+s` でその権限を変更した。これにより任意の利用者が ファイル所有者——この場合は root——としてコマンドを実行できるように なった。`.tourch` は実際には `/bin/bash` のバイナリであるため、 攻撃者は bash のコマンドを root として実行できた」 （原文英語。出典1）
  5. 5. 検知回避確認済
    **検知回避に方法論的な取り組みが見られた**（出典1）。 **①侵害したシステムでエンドポイント保護を無効化しようとした。 ②攻撃の証拠を含みうるシステムログを改変しようとした。 ③正当なセキュリティ評価であるかのように活動を装うため、 欺瞞的なレッドチームの印を仕込んだ**（出典1）。 **ファイル名・プロセス名による偽装も一貫している—— `Solarwinds.StatusLog.txt`（監視製品）、 `plesk_sys_driver.php`（ホスティング管理画面）、 `sys-update.service`・`Onedrive`（更新処理）、 `[kcached]`（カーネルのキャッシュスレッド）、`gs-dbus`（D-Bus）、 `pip2.7`・`ea_install`・`./semanage`（システム管理ツール）**（出典1）。 **GSocket のセッションは `HISTFILE=/dev/null` を設定して シェルのコマンド履歴がディスクに残らないようにし、 実行引数は環境変数 `GSOCKET_ARGS` で渡してプロセス監視から隠した** （出典1）。
    根拠: 「様々な検知回避の技法を観測した。これにはエンドポイント保護の 無効化の試み、システムログの消去、 および活動を正当なセキュリティ評価として装うための 欺瞞的なレッドチームの印の設置が含まれる」（原文英語。出典1）
