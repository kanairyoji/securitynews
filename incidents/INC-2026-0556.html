INC-2026-0556PwnEscape でゲストがホストを読む

ゲスト VM がホストのメモリを1パケット32バイトずつ読める——Linux カーネルの IPv4 チェックサム処理の不備（CVE-2026-99999「PwnEscape」・CVSS 9.3）。Vercel の本番サンドボックスで 漏えいが実証され、2.6.27 以降が影響範囲とされた

脆弱性初報のみ有名事象として記録（日本と直接の関係は薄い）設計・実装上の不備
初報: 2026年10月14日（Vercel による調査結果の公表。CVE の公表は10月15日） 最終更新: 2026年10月16日（本記録の確認時点）

仮想マシンの中で動くコードが、そのマシンを載せているホストのメモリを読めました。欠陥はハイパーバイザではなく、Linux カーネルのネットワーク処理にあります。

CVE-2026-99999（通称「PwnEscape」）は、Linux カーネルのIPv4 のチェックサム処理における不備です（出典1・4）。カーネルの CNA が2026年10月15日に公表し、CVSS v3.1 の基本値は 9.3（Critical）、ベクタは AV:L/AC:L/PR:N/UI:N/S:C/C:H/I:H/A:H です（出典1）。

本記録が要点と見たのは、次の4点です。

  • 漏えいは Vercel の本番サンドボックスで実証された。クラッシュとコード実行は研究者の実験機までである。 Vercel は「ホストメモリの漏えいは Vercel の本番サンドボックスに対して実証された」とし、「クラッシュとコード実行は、Vercel の構成に合わせた研究者自身の KVM および Firecracker のマシン上で実証された」と区別して述べています（原文英語。出典3）。この区別は落とせません（本記録の方針）。
  • 1パケットあたり32バイト。送り続ける限り読み続けられる。 IHL を 5 から 15 に変えることで、28バイトの線形ヘッダ領域から60バイトを複写させ、差の32バイトにホストのメモリが現れます（出典4）。
  • 影響は Linux 2.6.27 以降とされ、修正は7つの安定版系列に入った。 カーネルの CVE 記録は、修正済みの安定版として5.10.272・5.15.223・6.1.190・6.6.159・6.12.113・6.18.57・7.2.11 を挙げ、元の修正は 7.3-rc7 としています（出典1）。本流への取り込みは2026年10月14日です（出典2・4）。
  • 「どのクラウドの問題でもない」と当事者自身が述べている。 Vercel は「この欠陥は Vercel 固有のものではない。上流の Linux カーネルにある」とし、「主要なクラウド事業者の多くが分離のために同じカーネルの層を使っているため、いかなる欠陥も共有基盤のリスクである」と述べています（原文英語。出典3）。顧客データへの到達を示す報告は無かったとしています（出典3）。

攻撃の経過

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

**ゲスト VM の内部から、不正なチェックサムのメタデータを持つパケットを 送出する**（出典1・4）。 **`CHECKSUM_PARTIAL` と `csum_start` / `csum_offset` の組み合わせにより、 遅延されたチェックサムの書き込みが、検証済みの IPv4 ヘッダを 上書きしうる**（出典4）。 **IHL の値を 5 から 15 に変えると、 論理的には28バイトしかない線形ヘッダ領域から 断片化処理が60バイトのヘッダを複写し、差の32バイトに ホストのメモリが現れる**（出典4）。 **ゲストはパケットを送り続ける限り読み続けられる**（出典5）。 **実験機では、選択した64バイトのホストカーネルへの書き込みを用いた 限定された連鎖でホストの root 権限の実行に至った**（出典4）。

  1. 1. 実行確認済
    **ゲスト VM の内部で、不正なチェックサムのメタデータを伴う パケットを組み立てて送出する**（出典1・4）。 **`CHECKSUM_PARTIAL` を指定し、 `csum_start` / `csum_offset` を細工する**（出典4）。 **カーネルの CVE 記録は「IPv4 スタックは不正なチェックサムの メタデータを持つパケットを受け取ることができる」としている** （原文英語。出典1）。
    根拠: 「IPv4 スタックは不正なチェックサムのメタデータを持つパケットを 受け取ることができ、その後 `skb_checksum_help` が ネットワークヘッダを破壊しうる」（原文英語。出典1）
  2. 2. 収集確認済
    **IHL（ヘッダ長）の値を 5 から 15 に変えることで、 出力時の断片化処理が、論理的には28バイトしかない線形ヘッダ領域から 60バイトのヘッダを複写する**（出典4）。 **差の32バイトにホストのメモリが現れ、 ゲストへ返るパケットに載る**（出典4・5）。 **ゲストはパケットを送り続ける限り読み続けられる**（出典5）。 **漏えいは Vercel の本番サンドボックスに対して実証された**（出典3）。
    根拠: 「ホストメモリの漏えいは Vercel の本番サンドボックスに対して 実証された」（原文英語。出典3）
  3. 3. 影響（暗号化・破壊・改ざん）確認済
    **3つの帰結が示されている**（出典3・4）。 **①ホストメモリの漏えい——Vercel の本番サンドボックスで実証。 ②ホストのクラッシュ（可用性の喪失）——使い捨ての Linux 6.12 および 7.x のホストで確認。 ③ホストでのコード実行——研究者所有の KVM の検証環境で、 選択した64バイトのホストカーネルへの書き込みを用いた 限定された実験上の連鎖として実現し、ホストの root 権限の 補助プログラムを実行してホスト側で生成した標識をゲストへ返した。 4回の独立した完全なコールドブートで成功した。** **②と③は研究者自身の実験機でのみ確認されており、 本番環境でのコード実行は明示的に主張されていない**（出典3・4）。
    根拠: 「クラッシュとコード実行は、Vercel の構成に合わせた 研究者自身の KVM および Firecracker のマシン上で実証された」 （原文英語。出典3）

影響範囲も広いです。 CVE 記録は「2.6.27 以降が影響を受ける」としています（出典1）。修正コミットの Fixes: タグが指すのはf43798c「tun: Allow GSO using virtio_net_hdr」とbfd5f4a「packet: Add GSO/csum offload support.」の2件で、いずれも2009年前後のものです（出典2）。

②利用しているクラウド事業者が対処済みかを、自組織では確かめられません（本記録の評価）。Vercel は「AWS と業界の他の関係者とともに修正の優先度を上げた」とし（原文英語。出典3）、pwn.ai は「影響を受ける他のハイパーバイザ事業者・サンドボックス事業者へ通知した」としています（出典4）。しかし AWS 以外の事業者名は公表されておらず、各社の対応状況も分かりません〈未確定3〉。読者にできるのは、利用先へ本 CVE への対処状況を問い合わせ、回答が得られない事実を記録に残すことです（本記録の提案）。
