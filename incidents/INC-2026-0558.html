INC-2026-0558DirtyClone の実証コード公開

Linux カーネルのネットワーク処理に、共有データの印 SKBFL_SHARED_FRAG を 引き継がない欠陥 CVE-2026-43503（通称 DirtyClone）があり、2026年5月に修正された—— NVD の CVSS v3.1 は 8.8（AV:L/AC:L/PR:L/UI:N/S:C/C:H/I:H/A:H）、Red Hat の評価は 7.0。 ローカルに侵入した攻撃者が SUID ファイルのページキャッシュを上書きして root 権限を 奪える。GitHub に実証コードが公開されており（star 36・fork 6）、 対象 OS ごとの調整を要さず1つのコードを使い回せるため、 侵入後の権限奪取に使われる可能性が高いと国内で注意喚起された（2026年10月16日）。 Siemens は SIMATIC S7-1500 TM MFP の GNU/Linux サブシステムが影響を受けるとし、 修正は未提供で対話シェルへのアクセス制限を回避策として示している

5か月前に直った欠陥が、実証コードの公開で現役に戻りました。

CVE-2026-43503 は、Linux カーネルのネットワーク処理で共有データの印 SKBFL_SHARED_FRAG を引き継がない欠陥です（出典1・2・5・6）。NVD への登録は2026年5月23日、最終更新は2026年10月15日で、状態は Modified です（出典2）。CVSS v3.1 は NVD の評価が 8.8（AV:L/AC:L/PR:L/UI:N/S:C/C:H/I:H/A:H）、Red Hat の評価は 7.0 です（出典2）。

本記録が要点と見たのは、次の3点です。

  • 「ローカル限定」だが、侵入後の価値が極端に高い。 ベクタは AV:L（ローカル）・PR:L（低い権限が必要）で、リモートからは悪用できません（出典2・5）。一方、成功すれば SUID ファイルのページキャッシュを上書きしてroot 権限を奪えます（出典6）。S:C（スコープ変更あり）が付いているのはこのためです（出典2）。

  • 実証コードが「使い回せる」と評価されている。 国内の注意喚起は「攻撃対象の OS に合わせたエクスプロイトコードの調整を必要とせず、脆弱な Linux カーネルで動作している環境であれば1つのエクスプロイトコードを使いまわせる」としています（出典6）。実証コードは GitHub で公開され、star 36・fork 6 です（本記録が2026年10月16日に確認。出典5）。

  • 同じ欠陥が、資料によって別の問題に見える。 Red Hat の記録は、skb_try_coalesce() が印を失うことでESP（IPsec）の入力処理が共有断片の存在を誤認し、ページキャッシュに基づく断片上で in-place 復号を行う恐れがある、という形で説明しています（出典1）。一方、実証コードと国内の注意喚起は、SUID ファイルのページキャッシュ上書きによる root 奪取として説明しています（出典5・6）。Red Hat の記述だけを読むと「IPsec を使っていないから関係ない」と読める危険があります（本記録の評価）。

対策はカーネルの更新です（出典1・2・5・6）。ただし Siemens は SIMATIC S7-1500 TM MFP の GNU/Linux サブシステムに修正を提供しておらず、回避策は「対話シェルへのアクセスを信頼できる担当者のみに制限する」です（出典4）。

同じ欠陥が、資料によって「IPsec の問題」と「root 奪取の問題」に見える原因・手口

本記録が最も注意すべきと見たのは、ここです（本記録の評価）。

根本の原因は1つです。 ネットワークバッファ（skb）の断片を複製・移動する処理が、共有データであることを示す印 SKBFL_SHARED_FRAG を引き継がない——これだけです（出典1・2・5・6）。

Red Hat の記述だけを読むと、本記録の評価では誤読の危険があります（本記録の評価）。「ESP 入力処理」は IPsec の受信処理です。 IPsec を使っていない環境の担当者が Bugzilla の説明だけを読めば、「自社には関係ない」と判断しうる形になっています（本記録の評価）。

一方、国内の注意喚起と実証コードの説明は、ページキャッシュ上書きによる root 奪取として書いています（出典5・6）。ScanNetSecurity の説明は具体的です。 「攻撃者は SUID が設定されたファイルがキャッシュされているページ領域のデータを上書きし、任意のプログラムを root 権限でSUID 設定された状態で実行可能となり、root 権限の奪取が可能となる」（出典6）。

本記録はこれを矛盾ではなく、同じ原因の異なる現れ方として整理します（本記録の整理）——印を失えば「共有されているページに書き込んでよい」と誤判断する箇所が複数生じ、そのうちの1つが ESP の in-place 復号、別の1つがページキャッシュ上書きである、という読み方です。 ただし、この整理は本記録の読み方であり、いずれの資料もこの形で説明していません（本記録の明示）〈齟齬2〉。

実務上の含みは1つです（本記録の評価）。ベンダーの脆弱性記録に書かれた影響の例を、影響の全体と読み替えないこと。 本件では、ベンダー記録の例（IPsec）を見て除外判定すると、実際の攻撃経路（ページキャッシュ上書き）を見落とします（本記録の評価）。

「ローカル限定」の脆弱性が、実証コードの公開で優先度を変える評価・解釈

CVSS のベクタは、はっきり「ローカル」です（出典2・6）。

CVSS:3.1/AV:L/AC:L/PR:L/UI:N/S:C/C:H/I:H/A:H（出典2・6）。

  • AV:L——攻撃経路はローカル
  • AC:L——攻撃の複雑さは低い
  • PR:L——低い権限が必要
  • UI:N——利用者の関与は不要
  • S:C——スコープの変更あり
  • C:H / I:H / A:H——機密性・完全性・可用性への影響はいずれも高

実証コードの README も「攻撃にはローカルの認証済み利用者が必要で、リモートからは悪用できない」と明記しています（出典5）。

それでも基本値が 8.8 と高いのは、S:C と C/I/A の High によります（本記録の整理）。ローカルの一般利用者権限から root へ——境界を1つ越えるためです。

本記録が優先度の論点と見るのは、次の3点です（本記録の評価）。

①「ローカル限定」は、多段攻撃の2手目として最も使われる位置である。 Web アプリの欠陥・漏えいした SSH 鍵・悪意ある依存パッケージなど、低い権限の実行を得る手段は別に存在します（本記録の評価）。その次に root を取る道具として、本件は条件が良すぎます（本記録の評価）。

②「使い回せる」という評価が、攻撃の費用を下げる。 国内の注意喚起は「攻撃対象の OS に合わせたエクスプロイトコードの調整を必要とせず、脆弱な Linux カーネルで動作している環境であれば1つのエクスプロイトコードを使いまわせる」としています（出典6）。カーネルの権限昇格の脆弱性は、通常はカーネル版・設定ごとの調整を要します（本記録の整理）。その調整が不要であれば、攻撃側は環境を選びません（本記録の評価）。

③共有環境では、「ローカル」の意味が変わる。 複数の利用者・複数のテナントが同じカーネルを共有する構成——共用のビルドサーバ、学術計算機、CI の実行機、カーネルを共有するコンテナ基盤——では、「ローカル権限を持つ者」が自組織の管理外にいることがあります（本記録の評価）。この場合、PR:L の前提はすでに満たされています（本記録の評価）。

なお、CVSS の値は2つあります（出典2）。NVD が 8.8、Red Hat が 7.0 です〈齟齬1〉。深刻度の区分はどちらも High ですが、優先度の閾値を 8.0 や 7.5 に置いている組織では、どちらを採るかで結論が変わります（本記録の評価）。
