INC-2026-0561BeyondTrust RS ゼロデイを中国系が悪用

BeyondTrust Remote Support の認証バイパス脆弱性 CVE-2026-102764 を、中国系とみられるスパイ活動グループ ARMORY CASTLE（旧 UNC5221）が2026年8月下旬からゼロデイとして悪用していた——Mandiant はインシデント対応の中で、SAWFLY Web シェルの設置、SUID による root 昇格、bt-secrets による資格情報庫のダンプ、起動スクリプトと sudoers テンプレートの改変による永続化、ログの systematic な削除、Administrator 権限の改変による下流システムへの横展開を確認した。BeyondTrust は10月15日に脆弱性を公表し、Mandiant は公開後の広範な日和見的悪用への備えを促している【続報・2026年10月17日】CISA は10月16日に CVE-2026-102764 を KEV へ収載し（期限10月19日・forensic triage 要）、カナダ・サイバーセキュリティセンター（Cyber Centre）は同日 AL26-025 を発して**実地での悪用を確認**したうえで、**影響は Remote Support の全バージョン（26.2.3 以前）**、修正は 24.3.1〜26.2.3 向けの **BT26-05-RS パッチ**で、**24.3.1 より古い版は先に対応版へ上げてから当てる**必要があると明記した。**SaaS（Remote Support／Privileged Remote Access）は2026年10月9日時点で適用済みで顧客側の作業は不要**とされる。あわせて BeyondTrust は、**ゼロデイ悪用の最初の既知の事例が2026年8月29日**で、**9月28日に検知・封じ込めた**こと、**きっかけは9月27日に別のセキュリティベンダー製品でゼロデイ悪用が確認されたことだった**と説明した——その日付は Citrix NetScaler の公表（INC-2026-0229）と一致する

脅威・攻撃キャンペーン脆弱性不正アクセス・侵害続報が続いている有名事象として記録（日本と直接の関係は薄い）未知の脆弱性の悪用設計・実装上の不備権限管理の不備
初報: 2026年10月15日 最終更新: 2026年10月17日

BeyondTrust は2026年10月15日、同社の Remote Support（旧 Bomgar）アプライアンスに影響する脆弱性CVE-2026-102764 を公表しました。悪用に成功すると任意のファイルアップロードに至ります。

Mandiant / Google Threat Intelligence Group（GTIG） は同日のブログで、インシデント対応の中で、中国（PRC）系とみられるスパイ活動グループ ARMORY CASTLE（旧 UNC5221。CrowdStrike は Warp Panda と呼称）が、この脆弱性を 2026年8月下旬にゼロデイとして悪用していた証拠を確認したと公表しました。

Mandiant が観測した侵害後の動きは次のとおりです。SAWFLY（mangoapi.php）という難読化された PHP Web シェルの設置、/bin/sh を /usr/bin/dbus-authd に複製して SUID を立てる root 昇格、アプライアンス固有の CLI bt-secrets による資格情報庫（vault）のダンプ試行とそのログの削除、起動時実行ディレクトリへの zz-root-persist 配置と sudoers テンプレートの改変による再起動・設定リセットに耐える永続化、多数のログの systematic な削除、そして奪った Administrator 権限で Jump Item / Team 権限を No Access から Administrator へ変更して下流システムへリモートセッションを張る横展開です。BARECLAW というトンネラーも使われました。

Mandiant の評価は明快です。「Web シェルで足場を得た後、攻撃者は Web サービスアカウントからアプライアンスホストの root 権限へ昇格した。これにより、アプライアンスが保管または仲介していたすべての資格情報へのアクセスと、再起動や設定リセットを生き延びるファイルの改変が可能になった」（原文英語）。そして「悪用の期間中に脆弱なバージョンでインターネットから到達可能だったアプライアンスは、レビューが済むまで侵害された可能性があるものとして扱うべきである」（原文英語）としています。

日本に直接の被害報告はありませんが、Remote Support はサービスデスクの標準的な製品であり、「他システムへ入るための資格情報を集約した装置」が侵害されたという構造は、国内で同種の特権アクセス管理製品を使う組織にそのまま当てはまります。事実と評価は分けて記述します。

攻撃の経過

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

ARMORY CASTLE が2026年8月下旬に CVE-2026-102764 をゼロデイとして悪用し、 BeyondTrust Remote Support アプライアンスに SAWFLY Web シェルを設置。 SUID バックドアで root へ昇格し、bt-secrets で資格情報庫をダンプしようとしたうえ、 sudoers テンプレートの改変で再起動と設定リセットに耐える永続化を作り、 ログを削除しながら、Administrator 権限の改変で下流システムへリモートセッションを張った。

  1. 1. 初期侵入disclosed[1]
    CVE-2026-102764 を悪用し、認証なしでアプライアンスにファイルをアップロードできる状態にした。 攻撃者は /app_84304470%2Ephp へ POST リクエストを送った（関連ファイルは復元できなかった）
    根拠: Mandiant が access・syslog・messages・thin-scc・brain・SSL の各ログで悪用の証拠を確認した
  2. 2. 永続化disclosed[1]
    最初の POST から約11分後、Web ルート（/%SITE_SERVICE_ACCOUNT%/ingredi/app/laravel/public/）に SAWFLY Web シェル（mangoapi.php）が作られた。侵入期間を通じて主要な足場として使われた
    根拠: Mandiant によるファイルシステム上の作成記録の確認と SAWFLY の解析
  3. 3. 権限昇格disclosed[1]
    /bin/sh を /usr/bin/dbus-authd にコピーし、所有者を root に変更して SUID を有効にした。 これにより非特権のサービスアカウントから恒久的な root バックドアが成立した
    根拠: Mandiant の解析（ファイル作成と権限変更の痕跡）
  4. 4. 認証情報アクセスdisclosed[1]
    アプライアンス固有の管理 CLI /ns/sbin/bt-secrets を使い、サイトのサービスアカウント向け vault、 次にアプライアンス全体のパスワードセーフを、構文を変えながら繰り返しダンプしようとした。 その後 bt-secrets.log とその保存ファイルを削除した
    根拠: Mandiant が message ログから復元したコマンド列
  5. 5. 永続化disclosed[1]
    起動時実行用の /home/bomgar/sbin/post_boot.d を作り、zz-root-persist を配置した。 スクリプトは /ns/config/sudoers.template に 「%SITE_SERVICE_ACCOUNT% ALL=(ALL) NOPASSWD: ALL」が無ければ追記し、 /ns/sbin/bt-sysconfig --no-restart misc を実行して /etc/sudoers を再構築させる。 これにより権限昇格が再起動と設定リセットを生き延びる
    根拠: Mandiant が復元した zz-root-persist の内容
  6. 6. 検知回避disclosed[1]
    SAWFLY から sudo 権限で、/ns/log 配下（auth.log・ssl.log・proto-handler.log・bt-docker.log・ http-access.log・http-errors.log・php-fpm.log 等）、/var/log/messages、 サイト側の httpd_access.log・httpd_error.log、/tmp/sshauth.* を削除した
    根拠: Mandiant が復元したコマンド
  7. 7. 横展開disclosed[1]
    奪った Administrator 資格情報で Web 管理ポータルにログインし、 侵害アカウントの Jump Item 権限と Team 権限を「No Access」から「Administrator」へ変更した。 これにより Jump Item 一覧の下流システムへリモートセッションを張る恒久的な権限を得た。 BARECLAW トンネラーも併用された
    根拠: BeyondTrust の syslog に残る login 成功と user_changed のイベント（Mandiant が引用）

Web シェルから11分、root 昇格・資格情報庫のダンプ・再起動に耐える永続化まで原因・手口出典 [1]

Mandiant が観測した侵害後の流れは、アプライアンス内部の構造をよく知った者の手順である。

1. Web シェルの設置。 悪用後、攻撃者は /app_84304470%2Ephp に POST リクエストを送った。その約11分後、Web ルート（/%SITE_SERVICE_ACCOUNT%/ingredi/app/laravel/public/）にSAWFLY Web シェルが作られた。SAWFLY（mangoapi.php）は難読化された軽量 PHP Web シェルで、Base32 の独自トランスポート層と 256bit の RC4 で双方向の暗号化 C2 を実装する。POST に難読化パラメータ _c94mfe が無ければ即座に HTTP 404 を返して終了し、クローラや脆弱性スキャナから隠れる。

2. SUID による root 昇格。 SAWFLY はサイトのサービスアカウント（非特権）で動く。攻撃者は /bin/sh を /usr/bin/dbus-authd にコピーし、所有者を root に変え SUID を立てた。これで恒久的な root バックドアが成立する。

3. 資格情報庫のダンプ。 アプライアンス固有の管理 CLI /ns/sbin/bt-secrets を使い、サイトのサービスアカウント向け vault、次にアプライアンス全体のパスワードセーフを構文を変えながら繰り返しダンプしようとした。その後 bt-secrets.log とその保存ファイルをrm -f で削除している。

4. 再起動と設定リセットを生き延びる永続化。 起動時に実行される/home/bomgar/sbin/post_boot.d を作り、zz-root-persist というシェルスクリプトを置いた。内容は、/ns/config/sudoers.template に%SITE_SERVICE_ACCOUNT% ALL=(ALL) NOPASSWD: ALL が無ければ追記し、/ns/sbin/bt-sysconfig --no-restart misc を実行してアプライアンスに /etc/sudoers を作り直させるものである。/etc/sudoers を直接書き換えると設定リセットで消えるが、テンプレート側を書き換えれば生き残る。

5. アンチフォレンジック。 /ns/log/auth.log・ssl.log・http-access.log・php-fpm.log、/var/log/messages、サイト側の httpd_access.log など多数のログを sudo 権限で削除した。

6. 横展開。 奪った Administrator 資格情報で Web 管理ポータルにログインし、当初は Administrators グループへ一時的に参加できることを確認したうえで、当該アカウントの Jump Item 権限と Team 権限を「No Access」から「Administrator」へ直接変更した。これにより、アプライアンスの Jump Item 一覧にある下流システムへリモートセッションを張る恒久的な権限を得ている。BARECLAW というトンネラーも併用された。

Mandiant は Remote Support アプライアンスの内部（独自 CLI、起動設定テンプレート、ローカルのリバースプロキシ経路）への深い理解がうかがえるとしている。

「アプライアンスが保管または仲介していたすべての資格情報」が攻撃者の手に渡る被害規模・影響範囲出典 [1] [2]

Mandiant の評価を引用する（原文英語、以下は本記録による訳）。

「Web シェルを通じて足場を確立した後、攻撃者は Web サービスアカウントからアプライアンスホストの root レベルの制御へ昇格した。これにより、アプライアンスが保管または仲介していたすべての資格情報へのアクセスと、再起動や設定リセットを生き延びるファイルの改変が可能になった」

「悪用の期間中、脆弱なバージョンでインターネットから到達可能だったアプライアンスは、レビューが済むまで侵害された可能性があるものとして扱うべきである」

ここが本事案の核心である。Remote Support は他システムへ入るための装置であり、その中には顧客環境の資格情報が集約されている。装置の root を取られた時点で、被害は装置1台では終わらない。Mandiant が観測した Jump Item 権限の改変は、それが実際に下流システムへのアクセスに使われたことを示す。

さらに Mandiant は、公開後の展開についてこう述べている（原文英語、本記録による訳）。

「過去のキャンペーンで ARMORY CASTLE は、選択的にゼロデイとして悪用していた脆弱性が公に開示された後、広範で日和見的な悪用を行い、標的組織にパッチが適用される前に侵入しようと競ってきた。CVE-2026-102764 でも同様の広範な悪用の試みが観測される可能性がある」

Shadowserver は1,400を超える Remote Support インスタンスの露出を観測している。修正済みの台数は不明である。

「侵入を防ぐ」から「侵入された装置を前提に資格情報の爆発半径を縮める」へ（本記録の評価）評価・解釈出典 [1] [2]

ここからは本記録の作成者の評価である。

第一に、この事案で防御側が選べたのは「侵入を防ぐこと」ではない。ゼロデイであり、8月下旬の悪用時点で修正は存在しなかった。パッチ管理の成熟度では防げない。したがって問われるのは、侵入された後に何が失われるかの設計である。

第二に、失われたのは「アプライアンスが保管または仲介していたすべての資格情報」である。特権アクセス管理製品は、資格情報を集約することで運用を安全にする道具だが、その集約点が侵害されれば、集約した分だけ被害が増幅する。ここから導かれる実務は明確である。アプライアンスに預ける資格情報を「そこが落ちたら失われてよいもの」に限ること、そして預けた資格情報の一覧を、事故の日に即座に取り出せる形で別に持っておくことである。本事案で侵害を疑うべき組織が最初にやるべきことは、パッチ適用ではなくアプライアンスが仲介していた全資格情報の洗い替えである。

第三に、永続化の手口が「設定リセットでは消えない」点を重く見るべきである。 /etc/sudoers ではなく sudoers.template を書き換え、ベンダー提供の bt-sysconfig に再構築させている。これはアプライアンスの「出荷状態に戻す」操作が復旧手段として成立しないことを意味する。侵害が疑われるアプライアンスは、設定のリセットではなく再構築（再インストール）が前提となる。

第四に、ログがアンチフォレンジックで消され、しかも残存痕跡がLUKS 暗号化パーティション経由でしか読めないという組み合わせは、調査の難度を大きく上げる。アプライアンス型の製品では、ログを装置の外（SIEM・syslog 集約先）へ即時に転送しておくことが、事後に何が起きたか分かる唯一の保険である。装置の中のログは消される前提で設計する。

第五に、SaaS 顧客が10月8日に修正され、公表が10月15日だったという順序は、自己ホスト型の顧客が1週間「知らないまま未修正だった」ことを意味する。これはベンダーの一般的な運用（SaaS を先に直し、調整の後に公表する）であり非難すべき点ではないが、自己ホストで運用する以上、公表と同時がパッチ適用の最速であるという前提を運用計画に織り込む必要がある。

CISO・経営層への示唆
  • 特権アクセス管理製品は「落ちたときの被害が集約される点」として評価する
    Mandiant は「アプライアンスが保管または仲介していたすべての資格情報へのアクセスが可能になった」と評価している
    取るべき行動 リモート支援・特権アクセス製品に預けている資格情報の一覧を作り、 「この装置が侵害されたら何が失われるか」を金額と業務影響で見積もる。 最上位の特権アカウント（ドメイン管理者・基幹の管理者）は同じ装置に預けない方針を決める
  • ゼロデイ前提の運用計画を持つ——防げない前提で「気づく」と「縮める」に投資する
    2026年8月下旬の悪用時点で修正は存在せず、パッチ管理の成熟度では防げなかった
    取るべき行動 インターネットに面した装置の一覧を維持し、各装置について 「ログは外に出ているか」「資格情報は何を預けているか」「侵害時に再構築できるか」の3点を四半期で点検する。 防御の投資配分を予防偏重から検知・封じ込めへ振り替える
  • 「侵害された可能性がある」と言われた装置の扱いを事前に決めておく
    Mandiant は「悪用期間中に脆弱なバージョンで到達可能だったアプライアンスは、 レビューが済むまで侵害された可能性があるものとして扱うべき」と勧告している
    取るべき行動 ベンダーからこの種の勧告が出た場合の発動手順（対象装置の洗い出し、 仲介資格情報の全面洗い替え、装置の再構築、下流システムのセッション記録の確認）を あらかじめ文書化し、承認者と所要時間を決める
  • 自己ホスト運用は「公表と同時がパッチ適用の最速」である前提で体制を組む
    報道によれば SaaS 顧客は10月8日に修正され、公表は10月15日だった
    取るべき行動 自己ホスト型の境界装置について、公表当日に適用判断ができる当番体制と 計画外の再起動を許容する業務合意を取る。自動更新を有効にできるかを製品ごとに確認する
  • 同じアクターが同じ種類の装置を繰り返し狙っていることを調達判断に入れる
    報道によれば同アクターは Citrix NetScaler・Ivanti Connect Secure でも同様の活動を行い、 BeyondTrust 製品自体も CVE-2026-1731 や Silk Typhoon の事案で標的になってきた
    取るべき行動 境界装置・アクセス仲介装置の調達・更新時に、過去3年の実悪用（KEV 収載）実績と ベンダーの対応速度を評価項目に入れる。単一製品への依存を減らす設計も検討する
セキュリティ技術者への示唆
  • アプライアンスのログを生成と同時に装置外へ転送し、欠落を警報にする
    攻撃者は /ns/log 配下と /var/log/messages、サイトの httpd ログを systematic に削除した。 残存痕跡は LUKS 暗号化パーティション経由でしか読めない
    取るべき行動 Remote Support 等のアプライアンスの syslog 転送を有効にし、転送先を append-only で保管する。 転送の停止・レートの急減を監視項目にして、ログが「来なくなったこと」を検知する
  • SUID バイナリと sudoers 関連ファイルを基準値化して変更を検知する
    攻撃者は /bin/sh を /usr/bin/dbus-authd にコピーして SUID を立て、 sudoers.template に NOPASSWD 行を追記して設定リセットに耐える永続化を作った
    取るべき行動 装置ごとに SUID/SGID 一覧、/etc/sudoers、sudoers.template、起動スクリプトディレクトリ （post_boot.d 等）のハッシュを基準値として保存し、差分を日次で確認する
  • 管理 CLI の実行と権限変更イベントを SIEM の警報にする
    資格情報庫のダンプには /ns/sbin/bt-secrets が使われ、 横展開では Jump Item / Team 権限が No Access から Administrator へ変更された。 いずれも通常運用ではまれな操作である
    取るべき行動 アプライアンスの syslog から login 成功・user_changed・権限ロール変更を抽出し、 「権限が上がる方向の変更」を即時警報にする。管理 CLI の実行は原則ゼロをベースラインに置く
  • 侵害が疑われるアプライアンスは「設定リセット」ではなく再構築する
    永続化はベンダー提供のテンプレートを書き換え、bt-sysconfig に /etc/sudoers を再構築させる形で、 再起動と設定リセットを生き延びるよう作られていた
    取るべき行動 アプライアンスの復旧手順を「再インストール＋設定の再投入＋全資格情報の洗い替え」として文書化し、 設定のバックアップから戻すだけの手順を侵害時の選択肢から外す。再構築の所要時間を実測しておく
  • Web ルート配下のファイル追加と未知パスへの POST を検知する
    最初の POST から約11分で SAWFLY（mangoapi.php）が Web ルートに作られた。 SAWFLY は正しいパラメータが無いと 404 を返し、スキャナからは見えない
    取るべき行動 アプライアンスの Web ルートを FIM の対象にし、PHP ファイルの新設を即時警報にする。 前段のリバースプロキシで未知パスへの POST を記録・遮断し、404 応答のパターンも保全する
  • アプライアンスに預ける資格情報を短命にし、下流の到達範囲を分割する
    root を取られた時点で「保管または仲介していたすべての資格情報」が失われ、 Jump Item の権限改変で下流システムへセッションを張られた
    取るべき行動 仲介する資格情報を自動ローテーション（取得ごとの使い捨て）にし、 Jump Group を業務・環境単位に分割して1つのグループが全環境に届かない構成にする。 下流システム側でもリモート支援セッションの開始を記録・通知する
