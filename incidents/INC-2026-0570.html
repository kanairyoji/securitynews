INC-2026-0570OK貯蓄銀行が3日で2度目の侵害

韓国の OK저축은행（OK貯蓄銀行）が2026年10月16日、最初の侵害からわずか3日後の10月15日未明に モバイル受信（預金）サービス関連のホームページが攻撃を受け、顧客268名の氏名・口座番号・商品名・残高・利率・ 最終取引日が追加で流出したと明らかにした——攻撃は10月15日午前3時32分から約4時間続き、 使われた IP は金融保安院が事前に共有していた不審 IP とは別のものだった。 10月12日に公表済みの融資申込ページの侵害（顧客250名）と合わせ、公表された被害者は計518名になる（重複の有無は未確認）

不正アクセス・侵害続報が続いている有名事象として記録（日本と直接の関係は薄い）公表されていない／不明
初報: 2026年10月16日 最終更新: 2026年10月18日

韓国の貯蓄銀行 OK저축은행（OK貯蓄銀行）は2026年10月16日、モバイル受信（預金）サービス関連のホームページが攻撃を受け、顧客268名の情報が追加で流出したことを確認したと明らかにした。

攻撃が行われたのは 10月15日午前3時32分から約4時間（報道の一部は午前7時34分までと記す）。流出したのは氏名・口座番号・金融商品名・残高・利率・最終取引日である。同行は10月12日に、融資申込ウェブページの侵害で顧客250名の氏名・生年月日・住所・年収・融資額などが流出したと公表したばかりで、3日後に2度目の攻撃を受けたことになる。

注目すべき点が2つある。第一に、今回の攻撃に使われた IP は、金融保安院（금융보안원）が事前に共有していたハッキング疑い IP とは別のものだった。第二に、追加の流出は、最初の侵害を受けて10月15日まで実施していたシステム全数点検の過程で見つかった——つまり、点検中に新たな攻撃を受けていた。

同行は金融監督院（금융감독원）へ報告し、対象顧客へショートメッセージとメールで個別に通知した。対策として「疑わしい IP と接続経路の遮断、口座照会の防御ロジックのパッチ、異常行為検知・遮断ソリューションの緊急適用」を完了し、「現在、新規の異常接近は無い状態」としている。

公表された被害者は計518名になるが、2つの事案の対象が重複するかどうかは確認されておらず、単純合算での被害規模の算定は難しいと伝える報道もある。

「緊急対応を完了した」と「別系統は無防備だった」は両立する評価・解釈出典 [1] [2] [3]

ここからは本記録の作成者の評価である。

第一に、この事案の要点は件数ではなく、3日という間隔である。流出したのは268名で、規模としては大きくない。しかし、最初の侵害を公表し、緊急対応を完了したと述べた3日後に、別系統のサービスが4時間にわたって攻撃を受け、成功している。しかもそれに気づいたのは攻撃の最中ではなく、全数点検という別の作業の中だった。

第二に、「疑い IP の共有」を前提にした防御の限界が、そのまま現れている。金融保安院は業界に対しハッキング疑い IP を事前共有しており、同行はそれを遮断していた。ところが今回使われたのは共有リストに無い IP だった。指標ベースの遮断は、攻撃者が送信元を変えるだけで回避される。同行が事後に投入したのが「異常行為検知・遮断ソリューション」だったことは、この順序を物語っている——指標（誰が来たか）から振る舞い（何をしたか）への切り替えが、侵害を2回受けてから行われた。

第三に、「最初の対応の範囲」が問われる。最初の侵害は融資申込ページ、2度目はモバイル受信サービスで、系統が異なる。最初の緊急対応が当該ページの周辺に閉じていたとすれば、他系統は手つかずのまま残る。侵害の初動で「同じ作りの他のページはどこにあるか」を先に列挙するかどうかで、この3日間の結果は変わりえた（本記録の評価。同行はそう説明していない）。

第四に、流出項目の性格が最初の事案と違う。最初は申込情報（年収・融資額）、今回は口座番号・残高・利率・最終取引日である。後者は、本人しか知らないはずの取引情報を含む。「お客様の残高は◯◯円、最終取引は◯月◯日ですね」と言える相手は、金融機関を名乗る詐欺電話にとって決定的な説得材料になる（本記録の評価）。

事案の構造を図にしたものです。数値は公表値に基づきます。

どこで止められたか

段階ごとに検知の機会があったか、どの対策があれば効きえたかを整理したものです。「効きえた対策」は本記録の評価であり、当事者が述べたものではありません。
段階検知の機会効きえた対策
初期侵入機会はあったが検知できず
深夜3時32分という時間帯、かつ最初の侵害公表からわずか3日後である。 接続記録は残っており時刻も特定できているが、進行中には検知されていない
検知できた侵害公表後の期間は、全公開ページに対して深夜帯のアクセス急増を即時通知する監視を一時的に強める
検知できた指標（IP）ベースの遮断に加え、振る舞いベースの検知を併用する
収集機会はあったが検知できず
4時間という持続時間は、単発の侵入ではなく継続的な照会であることを示す。 同行が事後に「口座照会の防御ロジック」をパッチしたことも、照会経路の反復利用を示唆する（本記録の推定）
影響を限定できた口座照会 API に呼び出し元ごとの件数上限とレート制限を設け、上限到達で自動停止させる
検知できた同一セッション・同一送信元からの連続照会、連番・列挙的なパラメータを検知して遮断する
影響を限定できた残高・利率・最終取引日の返却を、認証強度に応じて段階的に制限する
持ち出し機会はあったが検知できず
発見は攻撃の最中ではなく、全数点検という別作業の中であった
検知できた顧客情報を返す経路の応答件数・転送量を常時集計し、日次のベースライン比較で異常を通知する

対応の評価

評価材料がない判断は「評価材料なし」としています。結果論で断じないための区分です。
判断評価評価の根拠と留保
攻撃の翌日（10月16日）に追加流出を公表し、同日に対象顧客へ個別通知した機能した本記録の評価である。対象者数・流出項目・攻撃の時間帯まで具体的に示しており、初報として水準は高い
攻撃時刻・継続時間・流出項目・対象者数に加え、「使用された IP が金融保安院の共有した疑い IP とは 別だった」ことまで明らかにした機能した本記録の評価である。自社に不利な事実を含めて開示した点は、同種の連鎖侵害が続く韓国金融業界では価値が高い
サービスを停止せず、疑わしい IP と接続経路の遮断、口座照会の防御ロジックのパッチ、 異常行為検知・遮断ソリューションの緊急適用で対応した部分的に機能本記録の評価である。1度目のあと「緊急対応を完了した」としながら3日で2度目が成立しているため、 同じ判断の繰り返しになっていないかは続報で確認する必要がある
CISO・経営層への示唆
  • 侵害公表後の数日間は、最も狙われる期間だと想定して監視を強める
    同行は10月12日に最初の侵害を公表し緊急対応を完了したとしたが、3日後の10月15日未明に 別系統のサービスが4時間にわたり攻撃され、成功している
    取るべき行動 インシデント公表後の一定期間（例: 2週間）を「高警戒期間」と定義し、 全公開サービスの監視しきい値を下げる、深夜帯のアラートを担当者の端末へ直接鳴らす、 といった手順を危機対応計画に明文化する
  • 初動の封じ込めは「侵害された経路」ではなく「同じ作りの全経路」を対象にする
    最初の侵害は融資申込ページ、2度目はモバイル受信サービスで系統が異なる。 最初の対応が当該ページ周辺に閉じていれば、他系統は手つかずで残る
    取るべき行動 封じ込めの手順に「同じ認証方式・同じ基盤・同じ開発ベンダーの公開画面を列挙し、 すべてに同じ対策を当てる」工程を必須で挟む。列挙の元になる公開資産一覧を平時から維持する
  • 当局・業界から共有された指標（IP）の遮断は、防御の出発点であって到達点ではない
    今回の攻撃に使われた IP は、金融保安院が事前に共有していた疑い IP とは別のものだった
    取るべき行動 共有指標の遮断状況を報告させるだけでなく、「指標に依存しない検知（振る舞い・量・時間帯）が どの経路に入っているか」を定例で確認する項目に加える
  • 流出項目の性格によって、顧客に出す警告の内容を変える
    今回流出したのは口座番号・残高・利率・最終取引日で、本人しか知らないはずの取引情報である。 これは金融機関を騙る詐欺電話の説得材料として機能する
    取るべき行動 通知文に「当行の職員が残高や取引内容を先に述べて本人確認を求めることはない」といった、 流出項目に即した具体的な警告を入れる。汎用の注意喚起で済ませない
セキュリティ技術者への示唆
  • 口座照会のような高価値 API に、件数上限とレート制限を必ず置く
    4時間という持続時間は、単発の侵入ではなく継続的な照会があったことを示す。 同行も事後に「口座照会の防御ロジックのパッチ」を当てている
    取るべき行動 顧客情報を返すすべての経路に、セッション単位・送信元単位の時間当たり件数上限と 日次累積上限を実装し、上限到達でトークン失効とアラートを同時に起こす
  • 深夜帯の異常を、人が見ていなくても止まる形にする
    攻撃は午前3時32分に始まり約4時間続いた。この時間帯に反応できる人はいない
    取るべき行動 平日日中のベースラインから大きく外れた時間帯のアクセス急増について、 通知だけでなく自動の縮退（レート制限の強化・該当経路の一時停止）まで実装する
  • 共有された疑い IP のリストと、実際に遮断した結果を突き合わせる
    共有 IP を遮断していても、別 IP からの攻撃は通る。 遮断の有効性を測らないと、何が守れていないかが分からない
    取るべき行動 共有指標による遮断件数と、遮断をすり抜けた異常アクセスの件数を並べて記録し、 すり抜けの比率を定点観測する。比率が高ければ検知方式の重心を振る舞い側へ移す
  • 公開画面の棚卸しを、系統（サービス）単位で持つ
    融資申込ページとモバイル受信サービスという別系統が、3日のうちに相次いで狙われた
    取るべき行動 公開しているすべてのウェブ画面・API を、認証方式・バックエンド・開発主体の3軸で分類した一覧にし、 1系統で問題が出たときに同じ属性を持つ全系統を即座に抽出できるようにする
  • インシデント対応中に新たな攻撃を受ける前提で、点検と監視を並行させる
    今回の追加侵害は「全数点検の過程で見つかった」。点検の最中に攻撃を受けていた
    取るべき行動 全数点検の実施中も通常監視を止めず、点検作業由来のアクセスと攻撃を区別できるよう、 点検用の送信元・アカウントを分離して記録する
