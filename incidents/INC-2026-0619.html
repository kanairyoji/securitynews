INC-2026-0619Siemens Software Centerが悪用

Siemens Software Center の DLL サイドローディング脆弱性 CVE-2026-110936（CVSS v4.0 8.4）が 実際の攻撃で悪用された——攻撃者は**正規の署名が付いた Siemens の実行ファイル**に 自前の DLL を並べた配布物を作り、ClickFix の誘導でこれを実行させていた。 Siemens は自社のシステム・製品・更新チャネルは侵害されていないとし、 10月19日にブログで悪用を公表、CISA は翌20日に KEV へ収載した

脆弱性脅威・攻撃キャンペーン続報が続いている有名事象として記録（日本と直接の関係は薄い）設計・実装上の不備人を介した誘導（ビッシング・BEC）
初報: 2026年10月19日 最終更新: 2026年10月20日

「正規の署名が付いているから安全」という判定が、そのまま攻撃の足場になった事例です。

2026年10月19日、Siemens ProductCERT は「Active Exploitation of CVE-2026-110936 in Siemens Software Center」を公表しました（出典2）。Siemens Software Center は、購入した Siemens 製ソフトウェアのダウンロード・インストール・ライセンス認証・更新を扱うツールです。CVE-2026-110936（CWE-427・CVSS v4.0 基本値 8.4／v3.1 基本値 6.7） は、アプリケーションが信頼されない検索パスから DLL を読み込むというもので、10月15日に SSA-580366 として公表され（出典1）、V4.0.9.8 で修正されています。CISA は10月20日に本 CVE を KEV カタログへ収載しました（出典4・是正期限 2026年11月3日）。

本記録が要点と見たのは、次の3点です。

  • 侵害されたのは Siemens ではない。 Siemens は「当社の把握する限り、Siemens のシステム・製品・更新チャネルはいずれも侵害されていない」と明記しています（出典2）。攻撃者は正規の、有効な署名を持つ Siemens Software Center の実行ファイルを入手し、自前の悪性 DLL と並べた配布物を作って配りました。Siemens のソフトウェアそのものは改変されていません（出典2・5）。
  • だから Siemens はハッシュで検知するなと言っている。 実行ファイルが本物である以上、ファイルのフィンガープリントによる検知は働きません。Siemens が挙げる手がかりはフォルダと振る舞いです——インストールした覚えのない PC のスタートアップやタスクスケジューラに「Siemens Software Center」がある、AppData\Local\Programs にSM Software Provisioning Service フォルダがある、SiemensSoftwareCenter.exe の隣に activate.bak や statinfosta.DB がある、AppData\Local に FTSuite フォルダと ftc.uml がある、96.62.218[.]59 への通信がある（出典2・6）。
  • この脆弱性は「認証済みのローカル攻撃者」を前提にしている——前提を満たすのは利用者自身である。 CVSS ベクタは AV:L/PR:H、つまりローカルかつ高い権限が要るという評価です（出典1）。紙の上では悪用しにくく見えますが、ClickFix は「利用者に自分でコマンドを実行させる」手口なので、その前提は攻撃者が自分で満たす必要がありません（本記録の評価）。Siemens は利用者向けに「Web ページに書かれたコマンドを Win+R・ファイル名を指定して実行・PowerShell に貼り付けてはいけない。本物の『私はロボットではありません』確認がそれを求めることはない」と明記しています（出典2）。

攻撃の経過

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

攻撃者は**正規の、有効な署名を持つ Siemens Software Center の実行ファイル**を入手し、 自前の悪性 DLL と同じフォルダに並べた配布物（MSI パッケージ）を用意する。 脆弱なバージョン 3.5.8.7 は、自身のフォルダ内に置かれたヘルパーファイルを **検証せずに読み込む**ため、起動すると攻撃者の DLL が Siemens Software Center と同じ権限で実行される（CVE-2026-110936・DLL サイドローディング）。 配布は ClickFix——偽の確認画面などで利用者自身にコマンドを貼り付けて実行させる手口——で行われ、 Siemens はこれをマルチプラットフォームの ClickFix キャンペーン「Romulus」に関連づけている。 **Siemens のソフトウェア自体は改変されておらず、Siemens の配布チャネルも使われていない。** 実行ファイルが本物であるため、**ハッシュによる検知は働かない**

  1. 1. 初期侵入disclosed[2] [5] [6]
    利用者が ClickFix のルアーページに誘導され、**画面に書かれたコマンドを 自分の端末（Win+R・ファイル名を指定して実行・PowerShell）に貼り付けて実行**する。 Siemens は配布元として `2.27.248[.]127` を挙げ、**現在は停止しているが、 それ以前にダウンロードした端末は感染している可能性がある**としている。 **誘導の具体的な文面・ルアーページの URL・どのような検索・広告経路で 利用者がそこへ到達したかは公表されていない**
    根拠: Siemens ProductCERT のニュース記事（ClickFix ルアーによる配布、 Win+R・PowerShell への貼り付けに対する警告、配布元 IP の停止と既感染の可能性）
  2. 2. 実行disclosed[2] [5]
    実行された配布物（Siemens は IoC として `AllMyBasic.msi` と `archive.dll` の SHA-256 ハッシュを掲載している）が、**正規の、有効な署名を持つ Siemens Software Center の実行ファイル**と攻撃者が用意した DLL を 同じフォルダに展開する。実行ファイルが起動すると、自フォルダ内の DLL が読み込まれる
    根拠: Siemens ProductCERT のニュース記事（正規の署名付き実行ファイルと攻撃者供給の DLL の組み合わせ、 IoC としての MSI・DLL のハッシュ掲載）および SecurityWeek の報道
  3. 3. 検知回避disclosed[1] [2]
    **脆弱なバージョン 3.5.8.7 は、自身のフォルダ内に置かれたヘルパーファイルを 検証せずに読み込んでいた**（CVE-2026-110936・CWE-427）。 攻撃者のコードは、有効な署名を持つ正規プロセスの文脈で実行される。 Siemens は「当社のソフトウェアは改ざんされておらず、 悪性のパッケージが Siemens の配布チャネルで配られたこともない」としている
    根拠: SSA-580366（CWE-427・信頼されない検索パスからの DLL 読み込み）および Siemens ProductCERT のニュース記事（3.5.8.7 がヘルパーファイルを検証せず読み込んでいた旨、 配布チャネルは使われていない旨）
  4. 4. 永続化disclosed[2] [6]
    マルウェアはスタートアップ項目またはタスクスケジューラへ「Siemens Software Center」を登録する。 Siemens は侵害の兆候として「**インストールした覚えのない PC の スタートアップアプリまたはタスクスケジューラに Siemens Software Center がある**」ことを挙げている。 あわせて `AppData\Local\Programs` に `SM Software Provisioning Service` フォルダ、 `SiemensSoftwareCenter.exe` の隣に `activate.bak` と `statinfosta.DB`、 `AppData\Local` に `FTSuite` フォルダと `ftc.uml` が作られる
    根拠: Siemens ProductCERT のニュース記事および Infosecurity Magazine の報道 （侵害の兆候のリスト）
  5. 5. C2通信disclosed[2] [6]
    感染端末は `96.62.218[.]59` へ接続する。Siemens はこの IP と ドメイン `wizardexpensive[.]com` を**現在も有効な IoC** とし、 ファイアウォール・プロキシ・DNS でのブロックとログ検索を推奨している。 配布元として使われた `2.27.248[.]127` は停止している
    根拠: Siemens ProductCERT のニュース記事（IoC の一覧と「現在も有効」「停止済み」の区別） および Infosecurity Magazine の報道

署名は本物だった——だから Siemens は「ハッシュで検知するな」と書いている原因・手口出典 [1] [2] [5] [6]

この事案の技術的な中心は、DLL サイドローディングである。

Windows のアプリケーションは、起動時に必要な DLL を決められた順序で探す。その探索先に実行ファイルと同じフォルダが含まれており、かつアプリケーションが読み込む DLL を検証しない場合、攻撃者は実行ファイルの隣に同名の悪性 DLL を置くだけで、そのアプリケーションの権限で自分のコードを走らせられる。Siemens Software Center の 3.5.8.7 は、まさにこの状態だった。

ここで重要なのは、攻撃者が用意したのは DLL だけだという点である。実行ファイルのほうは Siemens が配った本物であり、有効な電子署名が付いている。Siemens が繰り返し強調しているのはこの一点である。

Siemens のソフトウェアは改ざんされておらず、悪性のパッケージがSiemens の配布チャネルで配られたこともない（出典2・趣意）

この構造から、検知側には具体的な帰結が生じる。ファイルのハッシュ（フィンガープリント）による検知が働かない。実行ファイルは本物なので、どのハッシュリストにも悪性として載らない。署名検証も通る。「署名があるから許可する」という許可リストの運用は、ここでは防御ではなく攻撃者の通行証になる。

Siemens は、これを踏まえて検知の方針そのものを指示している—— ファイルのフィンガープリントではなく、マルウェアに関連するフォルダと不審な振る舞いに検知を向けること（出典2・5）。

ベンダーが「自社製品のハッシュを見るな」と書くのは珍しい（本記録の評価）。これは、自社の署名が信頼の根拠として使えなくなったことをベンダー自身が認めた文であり、利用者側の検知設計を正しい方向へ向けさせる効果がある。

CVSS は「ローカル・高権限が必要」と評価している——その前提は ClickFix が埋める評価・解釈出典 [1] [3] [4]

CVE-2026-110936 の CVSS ベクタは次のとおりである（出典1）。

  • v4.0: CVSS:4.0/AV:L/AC:L/AT:N/PR:H/UI:N/VC:H/VI:H/VA:H/SC:N/SI:N/SA:N（基本値 8.4）
  • v3.1: CVSS:3.1/AV:L/AC:L/PR:H/UI:N/S:U/C:H/I:H/A:H（基本値 6.7）

いずれも AV:L（ローカル）・PR:H（高い権限が必要） である。脆弱性管理の実務でこのベクタを見れば、「攻撃者がすでに端末上で高い権限を持っている場合の話」と読むのが普通であり、優先度は下がる。

しかし ClickFix は、その前提を攻撃者が満たす必要をなくす（本記録の評価）。ClickFix で実行されるのは利用者自身であり、利用者はその端末の正当な利用者である。「ローカルで、その端末の権限で」という条件は、攻撃者が突破するものではなく、利用者が代わりに満たすものになる。

ここから実務上の帰結が2つ出る。

  1. CVSS のスコアだけで優先度を決める運用は、この種の脆弱性を取りこぼす。 v3.1 で見ていれば 6.7（Medium）である。同じ脆弱性が v4.0 では 8.4（High）になる——社内の基準がどちらのバージョンで書かれているかによって、同じ CVE の扱いが変わる。
  2. 「悪用されているか」は CVSS とは別の軸で入手する必要がある。本件では CISA KEV への収載（10月20日）が、その軸での最も明快な信号だった。

なお、CISA KEV の是正期限（2026年11月3日）は米国連邦政府機関に向けたものであり、日本の組織に法的な義務は生じない。ただし「実際に悪用されている」という事実は、所在地によって変わらない（本記録の評価）。

侵害の兆候は、専門家でなくても確認できる粒度で出ている対策・注意喚起出典 [2] [5] [6]

Siemens が挙げる侵害の兆候は次のとおりである（出典2・6）。

  • インストールした覚えのない PC のスタートアップアプリまたはタスクスケジューラに「Siemens Software Center」がある
  • AppData\Local\Programs の中に SM Software Provisioning Service というフォルダがある（マルウェアが作る）
  • SiemensSoftwareCenter.exe の隣に activate.bak または statinfosta.DB がある
  • AppData\Local の中に FTSuite フォルダと ftc.uml がある
  • 96.62.218[.]59 への通信がある

IoC としては、96.62.218[.]59 と wizardexpensive[.]com が現在も有効としてブロック対象に挙げられ、配布元として使われた 2.27.248[.]127 はすでに停止しているが、それ以前にダウンロードした端末は感染している可能性があるとされている。MSI（AllMyBasic.msi）と DLL（archive.dll）の SHA-256 ハッシュも掲載されている。

対応として Siemens が示しているのは次のとおりである。

  • Siemens Software Center を V4.0.9.8 以降へ更新する（起動時に自動更新される）
  • Siemens のソフトウェアは公式サイトからのみ入手する
  • 上記の IP アドレスとドメインをファイアウォール・プロキシ・DNS でブロックし、ログを遡って該当する接続を検索する
  • Siemens Software Center の実行ファイルの近くに想定外の DLL が無いか確認する
  • 侵害が疑われる場合は端末を隔離し、プロセスを停止してからスタートアップ項目とタスクを削除し、パスワードをリセットする

ひとつ注意がある（本記録の指摘）。「インストールした覚えのない PC に Siemens Software Center がある」という兆候は、Siemens 製品を正規に使っている組織では効かない。製造業・プラント系で Siemens のツールが日常的に入っている環境では、この条件での絞り込みができないため、フォルダ名（SM Software Provisioning Service・FTSuite）とファイル名（activate.bak・statinfosta.DB・ftc.uml）、および実行パスが正規のインストール先かどうかで見る必要がある。

本記録は、これらの IoC が悪性であることを独自に検証していない。照合先のテレメトリを持たないため、検知への投入は各組織の判断で行うこと。

ClickFix 配信基盤「Romulus」との関連は、インフラの重複による推定である帰属出典 [2] [5] [6] [7]

Siemens は本攻撃を Romulus——マルチプラットフォームの ClickFix キャンペーン——に関連づけている（出典2・6・7）。

Romulus は、2026年10月14〜15日に Forescout Research — Vedere Labs が公表したClickFix の配信基盤（パネル）である。複数のサーバーで稼働が確認されており、Siemens が悪性配布物の配布元として特定したサーバーは、その1つに含まれていた（SecurityWeek の報道による）。

Forescout が観測したのは LegionLoader の配布と、Stardock の正規アプリケーションを DLL サイドローディングに悪用するトロイの木馬化インストーラである。Huntress も2026年9月下旬、不正な ChatGPT Custom GPT で ClickFix ページへ誘導し、Canon・Stardock の署名付きプログラムを悪用して RAT を導入するキャンペーンを報告している。

ここで本記録が線を引く（本記録の整理）。

  • Siemens Software Center は、Huntress のレポートにも Forescout のレポートにも登場しない（SecurityWeek の明示）
  • 関連づけの根拠は、インフラの重複と同種のサイドローディング手法である
  • SecurityWeek はこれを「Siemens のプログラムが同じツールキットに追加された可能性を示唆する」と書いており、断定していない
  • Forescout は Romulus の運用者を特定できていない。私的なパネル・商用の配信サービス・アフィリエイト基盤・コピーされたソフトウェアのいずれもありうるとしている

したがって、「Romulus の運用者が Siemens を狙った」とは書けない。書けるのは「Siemens Software Center を悪用した配布物が、Romulus として追跡されている基盤のインフラと重なっていた」までである。

波及の構造

事案の構造を図にしたものです。数値は公表値に基づきます。
正規の署名付き Siemens 実行ファイルが、ClickFix 経由で攻撃者の DLL を読み込むまで
layer 0 は正規の供給元（Siemens と、本物の署名付き実行ファイル）。 layer 1 は攻撃者側——ROMULUS として追跡される ClickFix 基盤と、 正規実行ファイル＋悪性 DLL を同梱した配布物（`AllMyBasic.msi`）。 layer 2 は利用者の端末で起きること——ClickFix のルアーに従ったコマンド実行、 配布物の展開、正規実行ファイルによる自フォルダ内 DLL の読み込み（CVE-2026-110936）。 layer 3 は侵害後の痕跡——永続化（スタートアップ／タスク）と C2 通信。 layer 4 は公表側（Siemens ProductCERT・CISA KEV・カナダ サイバーセンター）。 **Siemens の配布チャネルは経路に入っていない**——攻撃者は正規ファイルを入手して 自分で配っている。実行ファイルが本物であるため、ハッシュによる検知は働かない。 ROMULUS との関連づけはインフラの重複による推定であり、確定した帰属ではない。

Siemens は IoC（IP・ドメイン・MSI と DLL の SHA-256 ハッシュ）に加え、 **利用者が自分で確認できる形の侵害の兆候**（スタートアップ項目・フォルダ名・ファイル名・通信先）を公表し、 さらに「**ハッシュではなくフォルダと振る舞いで検知せよ**」という 検知の方針まで明示した。あわせて当局・EDR ベンダーと脅威情報を共有しているとした機能した**本記録の評価である。** 「自社製品は侵害されていない」とだけ述べて終わらず、 **自社製品が攻撃の部品として使われたことを認めたうえで、 利用者が今日確認できる手順まで書いた**点を評価した。 とくに「ハッシュで検知するな」という指示は、 **検知側が間違った方向に労力を使うことを先回りで止めている**
CISO・経営層への示唆
  • 「署名付きなら許可」という許可リストの前提を、いま一度確認する
    本件で攻撃者が使った実行ファイルは**正規の Siemens 製バイナリで、 署名も有効**だった。Siemens 自身が「ファイルのフィンガープリントではなく、 フォルダと振る舞いで検知せよ」と書いている。 **署名は「誰が作ったか」を保証するが、「どこに置かれ、隣に何が並んでいるか」は保証しない**
    取るべき行動 ①アプリケーション制御・EDR の除外リストに「署名の有無」だけを条件にした エントリがないか棚卸しする ②`%LOCALAPPDATA%` 配下など**利用者が書き込めるパスから起動する署名付きバイナリ**を 許可している箇所を洗い出し、発行元＋パスの組み合わせに書き換える ③書き換えが難しい箇所については、少なくとも検知（アラート）を入れる
  • 脆弱性の優先度を CVSS 単独で決めず、「悪用されているか」を別の経路で入れる
    CVE-2026-110936 は **v3.1 で 6.7（Medium）、v4.0 で 8.4（High）**と、 同じ脆弱性でもバージョンによって扱いが変わる。 さらに `AV:L/PR:H` というベクタは「ローカルで高権限が要る」と読めるが、 **ClickFix はその前提を利用者に満たさせる手口である。** 10月15日のアドバイザリ時点でこれを「通常のローカル脆弱性」と分類していれば、 19日の悪用公表まで対応は動かない
    取るべき行動 ①脆弱性管理の判定基準に **CISA KEV への収載**を独立した昇格条件として入れる （本件は10月20日に収載された） ②社内基準が CVSS v3.1 と v4.0 のどちらで書かれているかを確認し、 **両方が出ている CVE では高いほうを採る**と決める ③「ローカル・要高権限」という理由だけで優先度を下げるルールがあれば、 **利用者自身が実行する手口（ClickFix・悪性インストーラ）を除外条件**として加える
  • サプライヤのソフトウェアを「どの端末に入っているか」言えるようにしておく
    Siemens が挙げる最も分かりやすい侵害の兆候は 「**インストールした覚えのない PC に Siemens Software Center がある**」だが、 これは**自社がどの端末に何を入れているかを言えることが前提**である。 設計・製造・OT 系のツールは、情報システム部門ではなく事業部門や 装置メーカーの手で入ることがあり、台帳に載っていないことがある
    取るべき行動 ①Siemens 製ソフトウェアを含む**ベンダー製ツールの導入端末一覧**を、 資産管理の仕組みから出せるか確認する（出せなければそれ自体が課題である） ②出せる場合、**正規のインストール先以外**にある同名の実行ファイルを探索する ③出せない場合は、フォルダ名・ファイル名ベースのハンティング （`SM Software Provisioning Service`・`FTSuite`・`activate.bak`・`statinfosta.DB`・`ftc.uml`）で代替する
  • 利用者向けの注意喚起を「メールを開かない」から「画面のコマンドを貼り付けない」へ更新する
    ClickFix は利用者自身に実行させる手口であり、 **従来の「怪しい添付を開かない」という教育では射程に入らない。** Siemens は公式に「**Web ページに書かれたコマンドを Win+R・ファイル名を指定して実行・ PowerShell に貼り付けてはいけない。本物の『私はロボットではありません』確認が それを求めることはない**」と書いている
    取るべき行動 ①社内の注意喚起文・新人教育の資料に、Siemens のこの一文をそのまま入れる （**ベンダーの公式文言である**ことが説得力になる） ②「CAPTCHA の確認でコマンドを貼り付けるよう求められた」という報告を 受け付ける窓口を周知する ③ヘルプデスクに、この報告が来たときの初動（端末の隔離・RunMRU の確認）を渡しておく
セキュリティ技術者への示唆
  • ClickFix の検知を「ブラウザ → 実行ダイアログ → PowerShell」の線で入れる
    ClickFix は、**利用者がブラウザからコピーしたコマンドを Win+R または PowerShell に貼り付ける**という、はっきりした痕跡を残す。 これは Siemens 固有ではなく ClickFix 全般に効く検知であり、 **本件のためだけに作るものではない**
    取るべき行動 ①`HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\RunMRU` への 書き込みを検知対象にする ②ブラウザ（`chrome.exe`・`msedge.exe`・`firefox.exe`）を親とする `powershell.exe`・`cmd.exe`・`mshta.exe`・`msiexec.exe` の起動をアラートにする ③`msiexec.exe` が `%TEMP%` 配下の MSI を**サイレントインストール**する挙動を併せて見る （Forescout が Romulus の検知観点として挙げている）
  • 署名付きバイナリによる未署名 DLL のロードを、実行パスと組み合わせて見る
    DLL サイドローディングの検知は、イメージロードイベント単独では誤検知が多い。 **正規のアプリケーションでも日常的に起きる**からである。 本件の特徴は「**署名付きの実行ファイルが、利用者書き込み可能なパスに置かれ、 その隣の未署名 DLL を読み込む**」という組み合わせにある
    取るべき行動 ①EDR のイメージロードイベントで、 **「署名付きプロセス × 未署名 DLL × 実行パスが `%LOCALAPPDATA%`・`%APPDATA%`・`%TEMP%` 配下」**の 3条件 AND のクエリを作る ②まず検知のみで運用してベースラインを取り、誤検知の多い正規アプリを除外する （パス込みで除外し、**署名だけを条件にした除外を作らない**） ③本件の具体名（`SiemensSoftwareCenter.exe`）は、このクエリの一例として扱う
  • Siemens が示した侵害の兆候を、そのままハンティングクエリに落とす
    Siemens は**フォルダ名・ファイル名・通信先**という、 クエリに直せる形で侵害の兆候を出している。 **このまま使える形で公表されることは多くない**（本記録の評価）
    取るべき行動 ①ファイル名で検索: `activate.bak`・`statinfosta.DB`・`ftc.uml` ②フォルダで検索: `%LOCALAPPDATA%\Programs\SM Software Provisioning Service`・`%LOCALAPPDATA%\FTSuite` ③自動起動で検索: 製品名「Siemens Software Center」のスタートアップ項目・スケジュールタスク （**Siemens 製品を正規導入している端末は、ここで絞れないことを織り込む**） ④通信ログを遡って検索: `96.62.218[.]59`・`wizardexpensive[.]com`、 および**すでに停止した配布元** `2.27.248[.]127`
  • 「自動更新されるから対応済み」を、起動されていない端末まで含めて確認する
    Siemens は「既存のインストールは次回起動時に自動更新される」としている。 これは **①端末が起動されること ②更新サーバーへ到達できること**の 2つを前提にしている。 **設計・製造・OT 系の端末には、月単位で起動されないものや、 意図的にネットワークから切り離されているものがある**（本記録の指摘）
    取るべき行動 ①資産管理から Siemens Software Center のバージョンを収集し、 **V4.0.9.8 未満の端末を残件として数える** ②数えられない端末（オフライン・台帳外）を列挙し、 担当部門に現物確認を依頼する ③オフライン端末については、更新ではなく**実行ファイル周辺の DLL の目視確認**を 手順として渡す

自組織に当てはまるか

該当する項目があれば、この事案と同じ構図が自組織でも成立しうることを意味します。
観点自社に当てはまるか該当する場合に何が起きうるか
委託・第三者部品□ Siemens 製ソフトウェア（設計・製造・OT 系の製品群）を利用しており、 Siemens Software Center がいずれかの端末に導入されている**V4.0.9.8 より前の全バージョンが対象**であり、CISA KEV に収載された 「実際に悪用されている」脆弱性である。 自動更新は次回起動時に働くが、起動されない端末・オフライン端末には届かない
運用・監視□ アプリケーション制御・EDR の許可リストや除外設定に、 **「有効な署名があること」だけを条件にしたエントリ**がある本件で使われた実行ファイルは**正規の署名付きバイナリ**である。 署名だけを条件にした許可は、攻撃者が正規バイナリを持ち込んだ時点で素通りする。 Siemens 自身が「ハッシュではなくフォルダと振る舞いで検知せよ」と書いている
運用・監視□ 脆弱性の対応優先度を CVSS のスコアだけで決めており、 **CISA KEV への収載を独立した昇格条件にしていない**本 CVE は v3.1 で 6.7（Medium）、v4.0 で 8.4（High）と評価が分かれ、 ベクタは `AV:L/PR:H` である。 **CVSS だけを見ていれば優先度は上がらない。** 「悪用されている」という事実は KEV 収載（10月20日）で初めて明確な信号になった
システム構成□ 利用者が書き込めるパス（`%LOCALAPPDATA%`・`%APPDATA%`・`%TEMP%` 配下）からの 実行可能ファイルの起動を、制限も検知もしていない本件の侵害の兆候は `AppData\Local\Programs` 配下のフォルダと、 その中の実行ファイル・DLL である。 **このパスからの起動を一律に見ているかどうかで、気づけるかどうかが決まる**
体制・契約□ 事業部門・装置メーカーが導入したベンダー製ツールが、 IT 資産台帳に載っていない（または版数まで把握していない）Siemens が挙げる最も分かりやすい兆候は「インストールした覚えのない PC にある」ことだが、 **何がどこに入っているかを言えなければ、この判定はできない**
運用・監視□ 利用者向けの注意喚起が「不審なメール・添付を開かない」に留まり、 **「Web ページに表示されたコマンドを貼り付けない」を含んでいない**ClickFix は利用者自身にコマンドを実行させる手口で、 メールの添付を経由しない。 Siemens は公式に「本物の『私はロボットではありません』確認がそれを求めることはない」と書いている
