INC-2026-0620ClickFix配信基盤ROMULUS

ClickFix の配信基盤「ROMULUS」が稼働している——Forescout は無関係の事案を調べる過程で このパネルを見つけ、同じログイン画面を持つサーバーを6つ特定した。 被害者ごとにトークンを発行し、PowerShell のステージングスクリプトと トロイの木馬化した MSI を配る作りで、観測された経路は Stardock アプリの DLL サイドローディングと、約882MB に水増しした LegionLoader の2系統。 **運用者が誰かは特定できていない**

脅威・攻撃キャンペーン初報のみ有名事象として記録（日本と直接の関係は薄い）人を介した誘導（ビッシング・BEC）
初報: 2026年10月14日 最終更新: 2026年10月20日

「ClickFix のキャンペーン」ではなく「ClickFix を配る基盤」が見つかりました。

2026年10月14〜15日、Forescout Research — Vedere Labs は ClickFix の配信基盤「ROMULUS」に関する調査結果を公表しました（出典1）。同社は無関係の事案を調査する過程で、サーバー 86.109.75[.]7 上にROMULUS という名前のパネルを見つけました。そこで配られていたマルウェアは、Huntress が別途報告していたキャンペーンのものと同じでした。

本記録が要点と見たのは、次の3点です。

  • 1台のマルウェア配布サーバーではなく、使い回せる配信基盤だった。 Forescout はこれを「ハードコードされた単一のマルウェアサーバーではなく、再利用可能な配信バックエンド」と表現しています（出典1）。被害者ごとにトークンを発行し、PowerShell のステージングスクリプトとトロイの木馬化した MSI インストーラを配ります。VirusTotal と Shodan での横展開により、同じログイン画面を持つ IP が6つ見つかりました。
  • 運用形態が特定できていない。 Forescout は、ROMULUS が私的に運用されるパネルなのか、商用のサイバー犯罪配信サービスなのか、アフィリエイト基盤なのか、運用者間でコピーされたソフトウェアなのか、判断できないとしています（出典1）。つまり「ROMULUS を使った攻撃」を単一の攻撃者の仕業として扱えないということです。
  • 配布経路の片方は、検知回避のために実行ファイルを約882MB まで水増ししていた。 LegionLoader を配る経路では、パスワード付きの 7z アーカイブを正規の 7-Zip で展開し、パディングで約882MB に膨らませた実行ファイルを使います（出典1）。スキャナとサンドボックスには、大きすぎるファイルを解析対象から外す実装があります。サイズそのものが回避手段になっています。

攻撃の経過

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

ROMULUS は、**ClickFix の誘導と配布を使い回せる形にしたバックエンド**である。 偽のランディングページで利用者にコマンドを実行させ、 **被害者ごとに発行したトークン**で配布物を紐づけ、 PowerShell のステージングスクリプトとトロイの木馬化した MSI インストーラを配る。 観測された配布経路は2系統で、 **①Stardock のアプリケーションをトロイの木馬化した MSI がパッチ適用済み DLL を サイドロードし悪性ローダーを読み込む経路**（Huntress が報告した連鎖と一致）、 **②パスワード付き 7z を正規の 7-Zip で展開し、約882MB に水増しした実行ファイルから LegionLoader を動かす経路**である。 LegionLoader の C2 は `smashshape[.]com` で、通信は RC4 と Base64 で符号化され、 Chrome のブラウザデータを収集できる

  1. 1. 初期侵入disclosed[1] [2]
    利用者が ClickFix の偽ランディングページに誘導され、 **画面の指示どおりにコマンドを自分の端末で実行**する。 ROMULUS は**被害者ごとにトークンを発行**して配布物を紐づける。 **ランディングページへの到達経路は公表されていない**
    根拠: Forescout の報告（ClickFix 形式のルアー、被害者ごとのトークン発行、 PowerShell ステージングスクリプトと MSI の配信）
  2. 2. 実行disclosed[1]
    ステージングスクリプトが配布物を取得して実行する。 **経路A（Stardock）** ではトロイの木馬化した MSI をダウンロードし、 **`%TEMP%` からのサイレントインストール**で導入する。 **経路B（LegionLoader）** ではパスワード付きの 7z アーカイブを取得し、 **正規の 7-Zip バイナリ**で展開する
    根拠: Forescout の報告（2系統のステージングスクリプトと取得物、 検知観点としての「`%TEMP%` からのサイレント MSI インストール」）
  3. 3. 検知回避disclosed[1]
    **経路A** では、Stardock の**正規アプリケーション**を土台にした DLL サイドローディングにより、信頼されたプロセスの中で悪性コードが動く。 **経路B** では、最終的な実行ファイルを**パディングで約882MB に水増し**し、 スキャナとサンドボックスを回避する。 LegionLoader の C2 通信は **RC4 と Base64 で符号化**される
    根拠: Forescout の報告（Stardock DeElevation のサイドローディング、 約882MB への水増しによるスキャナ・サンドボックス回避、 LegionLoader の RC4/Base64 符号化通信）
  4. 4. C2通信disclosed[1]
    LegionLoader は **`smashshape[.]com`** を C2 とし、 通信は **RC4 と Base64 で符号化**される。 Forescout は検知観点として「**単一の base64 文字列を含む form-urlencoded 形式の POST**」を挙げている。 IoC には `orbitflownetwork[.]lol`・`novatrafficcore[.]lol` などのドメインが含まれる
    根拠: Forescout の報告（LegionLoader の C2 と符号化方式、 検知観点としての form-urlencoded POST、IoC のドメイン一覧）
  5. 5. 収集disclosed[1]
    LegionLoader は **Chrome のブラウザデータを収集**できる。 **実際に何が収集され、どこへ送られたかの具体的な記述は公表されていない**
    根拠: Forescout の報告（LegionLoader が Chrome のブラウザデータを収集しうること）

見つかったのはキャンペーンではなく、ClickFix を配るための基盤だった概観出典 [1] [2]

Forescout Research — Vedere Labs の報告（2026年10月14〜15日）によれば、起きていることは次のとおりである。

  • Forescout は無関係の事案を調査する過程で、サーバー 86.109.75[.]7 上にROMULUS という名前のパネルを発見した。そこで配られていたマルウェアは、Huntress が別途報告していたキャンペーンのものと同じだった
  • ROMULUS はマルチペイロードの ClickFix 配信プラットフォームであり、Forescout はこれを「ハードコードされた単一のマルウェアサーバーではなく、再利用可能な配信バックエンド」と表現している
  • 被害者ごとにトークンを発行し、PowerShell のステージングスクリプトとトロイの木馬化した MSI インストーラを配る
  • VirusTotal と Shodan での横展開により、同じログイン画面を持つ IP が6つ特定された
  • 86.109.75[.]7 のノードには統計ページが露出しており、ユニークインストール数・総実行回数・国別の内訳が表示されていた（数値も国名も公表されていない）
  • 配布経路は2系統——①Stardock DeElevation のサイドローディング（Huntress 報告と一致）、②LegionLoader（約882MB に水増しした実行ファイル）
  • 運用者の身元も、配布される複数のマルウェアファミリが同一の所有者に属するかも不明

Forescout は、ROMULUS が私的に運用されるパネルなのか、商用のサイバー犯罪配信サービスなのか、アフィリエイト基盤なのか、運用者間でコピーされたソフトウェアなのかを判断できないとしている。また、Proofpoint が報告した RomulusLoader との関連を示す証拠は見つかっていない。

「基盤である」という判断が、攻撃の数え方を変える評価・解釈出典 [1] [2] [3]

本記録が重要と見るのは、6つの IP という数そのものではない（本記録の評価）。重要なのは、Forescout がこれを「再利用可能な配信バックエンド」と判断したことである。

配信が基盤になると、次の3つが変わる。

1. 攻撃者と攻撃を1対1で対応づけられなくなる。同じ基盤を複数の運用者が使っている場合、「ROMULUS が配った」は「同じ攻撃者が配った」を意味しない。Forescout が運用形態を4つの可能性（私的パネル・商用サービス・アフィリエイト・コピーされたソフトウェア）として並べ、どれとも決めていないのは、決める材料が無いからである。帰属を語れない状態で、手口と IoC だけが共有される——これは防御側にとって不利ではない。手口と IoC は帰属が分からなくても使えるからである。

2. 配布される中身が入れ替わる。 ROMULUS が配っていたのは LegionLoader と Stardock 悪用のローダーだが、基盤である以上、明日には別のものが載る。実際、Siemens が2026年10月19日に公表した CVE-2026-110936 の悪用では、Siemens Software Center を悪用した配布物が使われており、その配布元サーバーは Forescout が ROMULUS 稼働ホストとして挙げたものの1つだった（別記録 INC-2026-0619）。Siemens Software Center は Forescout のレポートには登場しない——つまり、レポート公表の時点ですでに観測外の配布物が載っていたことになる。

3. 「このマルウェアの対策」では足りなくなる。 LegionLoader のハッシュをブロックしても、同じ入口から別のものが入る。効くのは入口側の検知——ClickFix の実行痕跡（隠しウィンドウの PowerShell、10進表記 IP、%TEMP% からのサイレント MSI インストール）である。Forescout が挙げた検知観点が、マルウェアの特徴ではなく配信の仕組みの特徴に寄っているのは、この性質を反映している（本記録の解釈）。

回避のための加工は、そのまま検知の手がかりになっている原因・手口出典 [1] [2]

LegionLoader を配る経路（経路B）の手順は次のとおりである（出典1）。

  1. ステージングスクリプトがパスワード付きの 7z アーカイブをダウンロードする
  2. 正規の 7-Zip バイナリを使って展開する
  3. 展開された実行ファイルは、パディングで約882MB に水増しされている
  4. その中身が LegionLoader（2019年から活動しているローダー）である
  5. C2 は smashshape[.]com、通信は RC4 と Base64 で符号化される
  6. Chrome のブラウザデータを収集できる

ここには、検知回避の意図が3段階で入っている。①パスワード付きアーカイブ——ゲートウェイのスキャナは中身を開けない。②正規の 7-Zip での展開——展開処理そのものは正規バイナリの正常な動作に見える。③約882MB への水増し——多くのスキャナとサンドボックスは、一定サイズを超えるファイルを解析対象から外す実装を持つ。

しかし③は、同時に検知の手がかりでもある（本記録の指摘）。Forescout が挙げた検知観点に「過大な PE ファイル」が入っているのはこのためである。数百MB の実行ファイルが、利用者のダウンロードフォルダや %TEMP% に突然現れること自体が異常である。

経路A（Stardock）のほうは性質が異なる。トロイの木馬化した MSI がパッチ適用済みの DLL をサイドロードして悪性ローダーを読み込む。こちらは正規アプリケーションの信頼を借りる手口であり、サイズのような分かりやすい異常を残さない。Forescout が「Stardock の DLL サイドローディング」という製品名入りの検知観点を挙げているのは、一般化した検知が難しいことの裏返しである（本記録の解釈）。

Siemens の事案との関係は「配布元サーバーの重複」までである帰属出典 [1] [2] [3]

2026年10月19日、Siemens は CVE-2026-110936（Siemens Software Center のDLL サイドローディング脆弱性）の実際の悪用を公表し、これを Romulus に関連づけた（別記録 INC-2026-0619）。

両者の関係について、本記録が確認できた事実は次のとおりである。

  • Siemens が悪性配布物の配布元として特定したサーバーは、Forescout が ROMULUS 稼働ホストとして挙げたものの1つに含まれていた（SecurityWeek の報道による）
  • Siemens Software Center は、Forescout のレポートにも Huntress のレポートにも登場しない（SecurityWeek の明示）
  • Siemens 自身は「Romulus に関連づけている」とするのみで、関連づけの根拠を公表していない

したがって、「ROMULUS の運用者が Siemens を狙った」とは書けない。書けるのは「配布元サーバーが重なっていた」までである。

ただし、この重複には実務上の意味がある（本記録の評価）。Forescout のレポートが示した6つの IP は、レポートに載っていない配布物も配っていたことになる。IoC のリストは、観測された時点で観測されたものの一覧であり、その基盤が配りうるものの一覧ではない。

緩和策
数え方: **ClickFix の実行痕跡（隠しウィンドウの PowerShell・10進表記 IP・ `%TEMP%` からのサイレント MSI インストール）を検知ルールにする**（Forescout の推奨）　副作用: **本記録の評価による。** `%TEMP%` からの MSI インストールは、 ソフトウェア配布の仕組みや一部のインストーラが正当に行うことがある。 除外リストを作らないと運用できず、**除外を広く取りすぎると検知が形骸化する。** 隠しウィンドウの PowerShell も、運用自動化のスクリプトで日常的に使われる組織がある
数え方: **公表された IoC（`smashshape[.]com`・`orbitflownetwork[.]lol`・ `novatrafficcore[.]lol`・6つの IP アドレス）をブロックし、過去ログを遡る**　副作用: **本記録の評価による。** `.lol` のような TLD のドメインは**使い捨てが容易**で、 ブロックの寿命は短い。 「IoC を入れた」ことを対策完了と報告すると、**実際には翌週には効かなくなっている。** また**本記録はこれらが悪性であることを独自に検証していない**—— 照合先のテレメトリを持たないため、投入は各組織の判断による
数え方: **過大な PE ファイル（数百MB 規模）の出現を検知する**（Forescout の推奨）　副作用: **本記録の評価による。** 正当に巨大なインストーラ（統合開発環境・CAD・ ゲームクライアント）が存在するため、サイズ単独では誤検知が出る。 **「ダウンロード直後」「利用者書き込み可能なパス」という条件と 組み合わせないと運用できない。** また攻撃者側はパディング量を調整できるため、閾値を知られれば回避される
数え方: **署名付きバイナリによる DLL サイドローディングを、実行パスと組み合わせて検知する**　副作用: **本記録の評価による。** 正規アプリケーションの多くが自フォルダから DLL を読む。 ベースラインを取らずに有効化すると大量の誤検知が出る。 **ベースラインの取得には数週間を要し、その間は検知として機能しない**

波及の構造

事案の構造を図にしたものです。数値は公表値に基づきます。
ROMULUS が被害者ごとにトークンを発行し、2系統の経路でマルウェアを配るまで
layer 0 は配信基盤——ROMULUS パネル（同じログイン画面の IP が6つ）と、 ユニークインストール数・総実行回数・国別内訳を表示する統計ページ。 layer 1 は誘導——偽のランディングページ（到達経路は非公表）と、 そこで指示されたコマンドを自分で実行する利用者、被害者ごとのトークン発行。 layer 2 は2系統の配布連鎖——経路A（トロイの木馬化 Stardock MSI → パッチ適用済み DLL のサイドローディング）と 経路B（パスワード付き 7z → 正規 7-Zip での展開 → 約882MB に水増しした PE）。 layer 3 は配布物と C2（LegionLoader・`smashshape[.]com`・RC4/Base64・ Chrome データの収集）。 layer 4 は観測側（Forescout・Huntress）と、同じ基盤のサーバーから配られていた Siemens Software Center 悪用の配布物（Forescout のレポートには載っていない）。 **運用者の身元・運用形態は特定されていない。** IoC が悪性であることを本記録は独自に検証していない。

どこで止められたか

段階ごとに検知の機会があったか、どの対策があれば効きえたかを整理したものです。「効きえた対策」は本記録の評価であり、当事者が述べたものではありません。
段階検知の機会効きえた対策
初期侵入機会はあったが検知できず
**検知機会はある**（本記録の評価）。 Forescout 自身が検知の観点として「**URL を含む隠しウィンドウの PowerShell**」を 挙げている。ブラウザを親とする PowerShell の起動、 RunMRU への書き込みは EDR の標準的なテレメトリで取れる
検知できた**URL を引数に含む PowerShell の隠しウィンドウ実行**（`-w hidden` 等）を 検知ルールにする（Forescout の挙げた観点）
検知できた**10進表記の IP アドレス**を含むコマンドライン・URL を検知する （Forescout の挙げた観点。`http://1234567890/` のような形で ドット区切りの IP 検知を回避する）
実行機会はあったが検知できず
**`%TEMP%` からのサイレント MSI インストールは、業務で正当に起こることが少ない** （本記録の評価）。Forescout もこれを検知観点に挙げている。 一方、正規の 7-Zip による展開は日常的な挙動であり、単独では検知に使えない
検知できた`msiexec.exe` が **`%TEMP%` 配下の MSI を `/quiet` 等でインストール**する挙動を 検知する（Forescout の挙げた観点）
検知できた**パスワード付きアーカイブの展開**（7-Zip のコマンドラインに `-p` が付く）を、 ダウンロード直後に起きた場合に限ってアラートにする
検知回避機会はあったが検知できず
**水増しは検知側から見れば異常な特徴でもある**（本記録の評価）。 Forescout は検知観点に「**過大な PE ファイル**」を挙げている。 回避のための加工が、そのまま指標になる。 一方、DLL サイドローディングのほうは正規アプリの振る舞いと区別しにくい
検知できた**異常に大きな PE ファイル**（数百MB 規模）が 利用者書き込み可能なパスに出現したことを検知する（Forescout の挙げた観点）
検知できた**Stardock 製バイナリによる DLL サイドローディング**のパターンを検知する （Forescout の挙げた観点）。より一般には 「署名付き実行ファイル × 未署名 DLL × 利用者書き込み可能なパス」の組み合わせ
C2通信検知した
**公表された IoC で検知できる。** ただし **`.lol` のような新規・低価値 TLD は使い捨てが容易**であり、 ドメイン単位のブロックの寿命は短い（本記録の評価）。 **本記録は、これらのドメインが悪性であることを独自に検証していない**
検知できた`smashshape[.]com`・`orbitflownetwork[.]lol`・`novatrafficcore[.]lol` を DNS・プロキシでブロックし、**過去のログを遡って接続の有無を検索する**
検知できた**単一の base64 文字列だけを本文に持つ form-urlencoded POST** を プロキシログで検知する（Forescout の挙げた観点）。 ドメインと違い、この特徴は使い捨てできない
収集公表されていない
**この段階の検知可否について Forescout は述べていない。** 一般論として、ブラウザのプロファイルディレクトリ（`User Data`）への 別プロセスからのアクセスは検知可能だが、本件固有の記述は無い（本記録の留保）

対応の評価

評価材料がない判断は「評価材料なし」としています。結果論で断じないための区分です。
対応の巧拙を評価できる材料が公表資料から得られていません。
CISO・経営層への示唆
  • 「このマルウェアへの対策」という単位で報告させるのをやめる
    ROMULUS は**再利用可能な配信バックエンド**であり、 載せる中身は入れ替わる。実際、Forescout のレポートに載っていない Siemens Software Center 悪用の配布物が、 同じ基盤のサーバーから配られていた（別記録 INC-2026-0619）。 **LegionLoader のハッシュをブロックしても、同じ入口から別のものが入る**
    取るべき行動 ①脅威対応の報告様式を「マルウェア名ごとの対応状況」から **「入口の手口ごとの検知状況」**へ変える（ClickFix・悪性広告・ フィッシング添付・公開サーバーの脆弱性、など） ②ClickFix については「検知ルールがあるか」「過去90日で発火したか」の 2点を定期的に確認する ③IoC のブロックを「対策完了」として報告させない—— **ドメインは使い捨てられる**ことを前提に、有効期間の見込みを添えさせる
  • 攻撃者が特定できていない報告でも、手口と検知観点は今日から使える
    Forescout は ROMULUS の運用者を特定できておらず、 4つの可能性を並べたまま公表している。 **帰属が決まるのを待つと、その間の防御が止まる。** 一方、公表された検知観点（隠しウィンドウの PowerShell・10進表記 IP・ `%TEMP%` からのサイレント MSI インストール・過大な PE・ 単一 base64 の form-urlencoded POST）は、帰属とは独立に使える
    取るべき行動 ①脅威情報を受け取る社内のルールから、 **「帰属が確定しているもののみ対応する」という条件があれば外す** ②レポートを受け取ったら、まず**検知観点の節だけを抜き出して SOC・EDR 運用へ渡す**運用にする ③帰属に関する記述は、**そのまま引用して確度の表現を保つ** （「ROMULUS の運用者は特定されていない」と書く）
  • ClickFix は「利用者が自分で実行する」手口なので、技術対策だけでは閉じない
    ROMULUS の入口は**偽のランディングページと、そこに書かれたコマンド**である。 メールの添付も、脆弱性の悪用も経由しない。 **従来の「怪しい添付を開かない」という教育では射程に入らない**
    取るべき行動 ①社内の注意喚起に 「**Web ページに表示されたコマンドを、実行ダイアログや PowerShell に貼り付けない**」を 明記する（Siemens が同趣旨の公式文言を出しており、そのまま引用できる） ②「CAPTCHA でコマンドの貼り付けを求められた」という報告の窓口を周知する ③ヘルプデスクに初動（端末の隔離・RunMRU の確認）の手順を渡す
セキュリティ技術者への示唆
  • 検知は「配布物」ではなく「配信の仕組み」に寄せる
    Forescout が挙げた検知観点は、マルウェアの特徴ではなく **配信の仕組みの特徴**に寄っている—— 隠しウィンドウの PowerShell、10進表記の IP、 `%TEMP%` からのサイレント MSI インストール、過大な PE、 単一 base64 文字列の form-urlencoded POST。 **基盤が中身を入れ替えても、この5つは残る可能性が高い**（本記録の評価）
    取るべき行動 ①この5つをそれぞれ独立した検知ルールとして実装する ②誤検知の多いもの（`%TEMP%` の MSI・隠しウィンドウ PowerShell）は、 **まず検知のみで2〜4週間運用してベースラインを取る** ③除外は**パス＋発行元**で書き、署名の有無だけを条件にした除外を作らない
  • 過大な PE ファイルを検知対象にする——回避のための加工が指標になる
    LegionLoader 経路では、実行ファイルを**パディングで約882MB に水増し**して スキャナとサンドボックスを回避している。 多くの解析基盤は一定サイズ超のファイルを対象外にするためこれが効くが、 **逆に言えば「数百MB の実行ファイルが突然現れた」ことは異常である**
    取るべき行動 ①ダウンロードフォルダ・`%TEMP%`・`%LOCALAPPDATA%` 配下に **100MB を超える新規 PE ファイル**が出現したことを検知する （閾値は自組織の正当な巨大インストーラの実測から決める） ②自組織のサンドボックス・ゲートウェイの**ファイルサイズ上限の設定値を確認する**—— 上限を超えたファイルが**素通りしているのか、ブロックされるのか**を把握する ③素通りする設定であれば、せめてログに残るようにする
  • パスワード付きアーカイブの展開を、ダウンロード直後に限って見る
    経路Bは**パスワード付き 7z** をゲートウェイのスキャンから守り、 **正規の 7-Zip** で展開している。 展開処理は正規バイナリの正常動作に見えるが、 **「ダウンロード直後にパスワード付きで展開される」という時系列は特徴的である**
    取るべき行動 ①`7z.exe`・`7zG.exe` のコマンドラインに `-p` が含まれる実行を記録する ②直前（数分以内）にブラウザまたは PowerShell によるファイルのダウンロードが あった場合に限ってアラートにする ③正当な業務（取引先からのパスワード付き ZIP の受領）と区別するため、 **取得元がメール添付ではなく Web ダウンロードであることを条件に加える**
  • IoC は入れるが、「入れたこと」を対策完了にしない
    公表された IoC には `.lol` TLD のドメイン（`orbitflownetwork[.]lol`・ `novatrafficcore[.]lol`）が含まれる。 **この種のドメインは使い捨てが容易で、ブロックの寿命は短い。** また6つの IP も、スキャンで見える範囲の値にすぎない
    取るべき行動 ①IoC はブロックに入れると同時に、**過去ログを遡って接続の有無を検索する** （こちらが本体である——未来を止めるより過去を確認するほうが価値が高い） ②IoC ごとに**有効期限（レビュー日）**を設定し、期限が来たら残すか外すかを判断する ③**本記録はこれらの IoC が悪性であることを独自に検証していない**—— 投入は各組織の判断で行い、誤検知が出た場合に外せる形で入れる

自組織に当てはまるか

該当する項目があれば、この事案と同じ構図が自組織でも成立しうることを意味します。
観点自社に当てはまるか該当する場合に何が起きうるか
運用・監視□ ClickFix の実行痕跡（RunMRU への書き込み、ブラウザを親とする PowerShell の起動）を 検知する仕組みが無いROMULUS の入口は ClickFix であり、**利用者自身がコマンドを実行する。** メールの添付も脆弱性の悪用も経由しないため、 従来の入口対策（メールゲートウェイ・パッチ適用）では捕まらない
運用・監視□ サンドボックス・ゲートウェイのファイルサイズ上限を把握しておらず、 **上限を超えたファイルが素通りする設定になっているかどうかを知らない**LegionLoader 経路は実行ファイルを**約882MB に水増し**して解析を回避している。 上限超過時の挙動（素通り／ブロック／ログのみ）が分からなければ、 この回避が自組織で効くかどうかを判断できない
運用・監視□ `%TEMP%` からの MSI のサイレントインストールを、検知も制限もしていないROMULUS の経路Aはこの形でトロイの木馬化 MSI を導入する。 Forescout が検知観点として明示している
システム構成□ 署名付きバイナリによる DLL サイドローディングについて、 **実行パスを条件に含めた検知を持っていない**経路Aは Stardock の正規アプリケーションを土台にする。 署名の有無だけを条件にした許可・除外は、この手口を素通りさせる
体制・契約□ 脅威情報の社内運用が「攻撃者の帰属が確定したもの」を前提にしている**Forescout は ROMULUS の運用者を特定できていない。** 帰属が決まるのを待つ運用では、公表された検知観点を今日使えない
運用・監視□ IoC の投入を「対策完了」として報告しており、 **IoC ごとのレビュー期限や過去ログの遡り調査を手順化していない**公表された IoC には使い捨てが容易な TLD のドメインが含まれる。 **ブロックより、過去ログを遡って接続の有無を確認するほうが価値が高い**（本記録の評価）
