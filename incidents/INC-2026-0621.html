INC-2026-062110FXRATが暗号資産探索を追加

日本組織を狙う攻撃キャンペーンで使われるモジュール型 RAT「10FXRAT」が機能を拡張していた—— 9月の検体には暗号資産ウォレットを探索する CRYPTO_WALLET_SCAN が**本体の組み込みタスク**として追加され、 9月下旬には9エントリの独自パッケージ「NWPK」で KillAV モジュール・カーネルドライバ2種・ ローダー・本体をまとめて配る新しいドロッパーが確認された。 LAC は標的が日本・中国語圏からインドなどアジア他地域へ広がったとしている

脅威・攻撃キャンペーン続報が続いている日本の組織が当事者公表されていない／不明
初報: 2026年10月20日 最終更新: 2026年10月20日

日本を狙い続けているマルウェアが、半年で「何を盗むか」を変えています。

2026年10月20日、株式会社ラックは WATCHER'S LOG で「進化を続ける 10FXRAT マルウェアの活動」を公表しました（出典1）。同社が2026年6月に報告した、PoisonX ドライバを用いた日本組織への攻撃キャンペーンの続報です。内容の一部は、2026年10月14〜16日の Virus Bulletin Conference 2026（VB2026） での発表「Under the Surface: Inside the Evolving 10FXRAT Campaign」を反映しています。

本記録が要点と見たのは、次の3点です。

  • 9月の検体で、暗号資産ウォレットの探索が「本体の機能」になった。 CRYPTO_WALLET_SCAN は、ブラウザのウォレット拡張機能・暗号資産関連のブックマーク・ウォレットアプリの存在を確認し、さらに Desktop / Documents / Downloads・クリップボード・テキストエディタからシードフレーズ・秘密鍵・暗号資産アドレスに一致する候補文字列を探します（出典1）。プラグインではなく本体に組み込まれている—— C2 からプラグインを取りに行かずに実行できるということです。
  • 検体のコードに中国語簡体字が残っている。 LAC は、検出結果の生成処理に「私钥」（秘密鍵の意）という文字列を確認したと報告しています。PEM 形式の秘密鍵候補には「PEM 私钥」、16進数形式には「HEX 私钥」というラベルが付きます（出典1）。探索対象のブラウザにも 360 Chrome・QQBrowser が含まれます。
  • 配布方法が「独自パッケージ」に変わった。 9月下旬に確認されたドロッパーは、9つのエントリを持つ NWPK という独自形式のパッケージに、KillAV モジュール（セキュリティ製品の妨害）・カーネルドライバ2種・Second Loader・10FXRAT 本体・統括モジュールをまとめています。パッケージ全体はファイルとして保存されずメモリ上で展開されます（出典1）。永続化は、ログオン時に fontcache.exe を起動するスケジュールタスク「MicrosoftDeviceSetup」です。

攻撃の経過

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

**IMG ファイルから展開された実行ファイル**が `QtsVFS.dll` を読み込み、 この DLL が `cache.dat` を**インクリメンタル XOR** でデコードして **NWPK パッケージをメモリ上に展開**する。 パッケージのエントリ8（CoreEntry モジュール）をメモリ上に手動マッピングして呼び出すと、 CoreEntry が**防御回避用コンポーネント**（KillAV モジュール・GLCKIo／ENE ドライバ・ PROCEXP152 ドライバ）と後続コンポーネントの展開・起動を統括する。 続いて 10FXRAT 本体を格納する `_plcache.dll` を用意し、内包する `fontcache.exe` を配置して起動する。 `fontcache.exe` はカスタムのペイロードローダーとして動作し、 `_plcache.dll` をロードして**エクスポート関数 `StartPayload`** を呼ぶことで 10FXRAT を実行する。 永続化は、ログオン時に `fontcache.exe` を起動する スケジュールタスク「**MicrosoftDeviceSetup**」。 10FXRAT は C2 からコマンド ID `0x10` でタスクを受け取り、 本体が処理する「組み込みタスク」とプラグインに委譲する「プラグイン向けタスク」に振り分ける。 **IMG ファイルが標的へどう届くかは公表されていない**

  1. 1. 実行disclosed[1]
    IMG ファイルから展開された実行ファイルが **`QtsVFS.dll`** を読み込む。 この DLL が `cache.dat` をデコードし、**NWPK パッケージをメモリ上に展開**する。 `cache.dat` は**先頭1バイト（本検体では `0x42`）を XOR シードとする インクリメンタル XOR** でデコードされ、2バイト目以降は XOR シードを起点に 1ずつ増加する鍵で処理される。デコード後のデータは先頭4バイトに **「NWPK」というマジック値**を持つ
    根拠: LAC WATCHER'S LOG「進化を続ける 10FXRAT マルウェアの活動」 （実行チェーンの図8・NWPK のデコード手順・マジック値）
  2. 2. 検知回避disclosed[1]
    CoreEntry モジュールが**防御回避用コンポーネント**を展開・起動する。 エントリ1の **KillAV モジュール**（87,040バイト）が**セキュリティ製品の動作を妨害**し、 ロードまたは実行関数の取得に失敗した場合はエントリ0の **KillAV フォールバック用シェルコード**（106,582バイト）が代替処理を行う。 エントリ2の **GLCKIo／ENE ドライバ**（18,712バイト）は物理メモリへのアクセスを提供し **カーネルコールバックの改変**に使われ、`eneio64.dat` としてエンコードされた状態で配置される。 エントリ3の **PROCEXP152 ドライバ**（38,408バイト）は **対象プロセス内の指定ハンドルを閉じる**もので、`procexp.dat` として配置される。 **NWPK パッケージ全体はファイルとして保存されず、メモリ上のデータとして引き渡される**
    根拠: LAC WATCHER'S LOG（NWPK の各エントリの内容と役割を示した表3、 デコード済みパッケージがファイル保存されない旨）
  3. 3. 永続化disclosed[1]
    9月末に確認されたドロッパーは、**ログオン時に `fontcache.exe` を起動する スケジュールタスク「MicrosoftDeviceSetup」を登録**する。 `fontcache.exe` はカスタムのペイロードローダーとして動作し、 `_plcache.dll` をロードして**エクスポート関数 `StartPayload`** を呼ぶ
    根拠: LAC WATCHER'S LOG（スケジュールタスク「MicrosoftDeviceSetup」の登録、 `fontcache.exe` と `StartPayload` の関係）
  4. 4. 収集disclosed[1]
    9月の検体で追加された組み込みタスク **`CRYPTO_WALLET_SCAN`** が、 ①ブラウザプロファイル内の**ウォレット拡張機能の痕跡**（19種類の拡張機能 ID）、 ②**暗号資産関連のブックマーク**（binance.com・okx.com・coinbase.com・kraken.com・ huobi.com・gate.io・bybit.com・kucoin.com・bitget.com・mexc.com・uniswap・ pancakeswap・opensea.io・metamask.io）、 ③**ウォレットアプリケーションの存在**（Exodus.exe・Electrum.exe・Wasabi Wallet.exe・ Atomic.exe・Ledger Live.exe・Bitcoin-qt.exe・Guarda.exe）を確認する。 さらに **Desktop・Documents・Downloads などの候補ファイル、クリップボード、 対応するテキストエディタから取得したテキスト**を調べ、 **シードフレーズ（BIP39 形式の12・15・18・21・24語）・秘密鍵（HEX・WIF・ xprv/yprv/zprv・Cardano の xprv1・NEAR の ed25519:・Solana の Base58 と JSON 配列）・ 暗号資産アドレス**に一致する候補文字列を探索する。 固定ドライブ上の一部ディレクトリも対象になる。 結果は JSON にまとめられ、コマンド ID `0x11` で C2 へ送信される
    根拠: LAC WATCHER'S LOG（`CRYPTO_WALLET_SCAN` の探索対象と検出形式を示した 図3・図4・表2および Appendix の表4〜表8）
  5. 5. C2通信disclosed[1]
    10FXRAT は C2 からコマンド ID **`0x10`** のリクエストを受信すると、 JSON ペイロードで指定されたタスクを処理する。 **プラグインが未ロードの場合は、`PluginMgr_RequestFromServer` 関数が プラグイン識別子 `all_plugins` を JSON に格納し、コマンド ID `0x20` を指定して C2 へ送信してプラグインの取得を要求する**。あわせて受信タスクへの応答として `{"status":"loading_plugin"}` を返す。 タスクの結果は `SendJsonResponse` 関数が `{"taskId":"...","data":{...}}` の形に整形し、 `SendPacket` 関数がコマンド ID **`0x11`** で送信する。 追加された9タスクはいずれも `all_plugins` という識別子に対応付けられていた
    根拠: LAC WATCHER'S LOG（コマンド ID `0x10`／`0x11`／`0x20`、 `PluginMgr_IsLoaded`・`PluginMgr_Dispatch`・`PluginMgr_RequestFromServer` の動作、 `{"status":"loading_plugin"}` の応答）
  6. 6. 持ち出しdisclosed[1]
    収集結果は JSON 形式で C2 へ送信される。 `CRYPTO_WALLET_SCAN` の応答には、`items`（個別の検出結果の配列）・ `counts`（分類別の件数）・`summary`（**検出分類を中国語のラベルで連結した要約**）・ `total`（総件数）が含まれる。 **秘密情報そのものを常に送るわけではない**—— Ethereum keystore に関連する文字列を検出した場合は、内容全体を収集せず `encryptedkeystorejson` という**固定の検出マーカー**を記録する。 PEM 形式の処理でも、秘密鍵そのものではなく固定マーカーが設定される
    根拠: LAC WATCHER'S LOG（応答 JSON のフィールド構成を示した表2、 固定の検出マーカーに関する記述）

波及の構造

事案の構造を図にしたものです。数値は公表値に基づきます。
IMG ファイルから NWPK パッケージを経て 10FXRAT が動き、暗号資産の秘密情報を探すまで
layer 0 は起点（IMG ファイルと、そこから展開された実行ファイル。**配布経路は非公表**）。 layer 1 はパッケージの展開（`QtsVFS.dll` による `cache.dat` のインクリメンタル XOR デコード、 メモリ上の NWPK パッケージ、統括する CoreEntry モジュール）。 layer 2 は防御回避の部品（KillAV モジュールとフォールバック、 GLCKIo／ENE ドライバ、PROCEXP152 ドライバ）。 layer 3 は実行と永続化（`fontcache.exe` → `_plcache.dll` の `StartPayload` → 10FXRAT 本体、スケジュールタスク「MicrosoftDeviceSetup」）。 layer 4 は収集と送信（組み込みタスク `CRYPTO_WALLET_SCAN` が探す3層の対象と、 コマンド ID `0x11` での C2 への応答、`0x20` でのプラグイン要求）。 **Second Loader（エントリ4）の経路は、LAC が「最終ペイロードが実行されることは 確認できていない」としているため破線に相当する扱いである。** C2 のアドレス・プロトコルは公表されていない。
