INC-2026-0622BRONZE SANDCASTLEを新規命名

Sophos CTU が中国拠点とみる新規の攻撃グループ「BRONZE SANDCASTLE」を命名した—— 最も特徴的な痕跡は Sandboxie の正規実行ファイルに `sbiedll.dll` を並べる DLL サイドローディングで、 **LINE の `LineAppMgr.exe` を含む9通りの組み合わせ**が確認されている。 ペイロードは Metasploit 風だが API 解決に ROR13 を使わない独自実装で、 GitHub から暗号化設定を取り、ntds.dit の窃取まで行う。 2025年8月〜2026年8月の被害はフィリピン・台湾・アフガニスタン・ナミビア、および韓国の可能性

脅威・攻撃キャンペーン初報のみ有名事象として記録（日本と直接の関係は薄い）設計・実装上の不備公表されていない／不明
初報: 2026年10月20日 最終更新: 2026年10月20日

「LINE の実行ファイルが DLL サイドローディングに使われる」という組み合わせが、公開レポートに載りました。

2026年10月20日、Sophos の Counter Threat Unit（CTU）と SophosLabs は、新しい攻撃グループ「BRONZE SANDCASTLE」に関する分析を公表しました（出典1）。複数の事案を調べた結果、既存のグループに確実には結びつかない独自の技術的特徴があったため、別の呼称を新設したというものです。

本記録が要点と見たのは、次の3点です。

  • 最も特徴的な痕跡は Sandboxie の DLL サイドローディングで、組み合わせの一覧に LINE が入っている。複数の被害環境で、Sandboxie の正規実行ファイル（SandboxieWUAU.exe、および名前を変えた Start.exe）の隣に悪性の sbiedll.dll が置かれていました。Sophos はこれを「このグループの署名として機能する」と表現しています。ほかに javaw.exe→jli.dll、Krita.exe→Krita.dll、NvdaHelper.exe→NvdaHelperRemote.dll、Jcef_helper.exe→Libcef.dll、Vmmap.exe→Version.dll、LineAppMgr.exe→msvcp140.dll、bginfo64.exe→snmpapi.dll の計9通りが挙げられています（出典1）。
  • ペイロードは Metasploit に似ているが、Metasploit ではない。位置独立実行・手動の PE 検証・埋め込み実行ファイルのメモリ内ロードといった構造は Metasploit のステージレス shellcode に似ていますが、API 解決のロジックが Metasploit で有名な ROR13 ではない独自のハッシュ・変換を使い、コードベースも大きく複雑です。さらに COFFLoader の要素が含まれており、Sophos は「作者が独自の Beacon Object File（BOF）を使って自前のポストエクスプロイト機能を作った」とみています（出典1）。
  • 検知は静的では効かない、と明言している。 Sophos は「このグループは実行時に復号される暗号化されたペイロードと設定ファイルを主に使うため、静的なファイルベースの検知は効果がない可能性がある」とし、DLL がローカルファイルを読んだ直後にメモリ上で実行するといった振る舞い指標に目を向けるよう推奨しています（出典1）。

攻撃の経過

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

侵害された端末に、**正規の実行ファイルと悪性 DLL、暗号化された `config.ini`** を ZIP アーカイブなどで展開する。正規の実行ファイルが起動すると悪性 DLL が読み込まれ、 この DLL が `config.ini` を復号して**メモリ上でペイロードを実行**する。 ディスクには追加の成果物が残らない。 悪性 DLL のコードは**フラット化された制御フロー（仮想化された状態機械）**で難読化されており、 状態値をテーブル経由でビット混合して間接ジャンプする。 復号されたペイロードはバックドアで、**位置独立の PE ローダー（リフレクティブローダー）**を 先頭に持つ。構造は Metasploit のステージレス shellcode に似るが、 **API 解決に ROR13 ではない独自のハッシュ・変換**を使い、 **COFFLoader の要素**を含む。 起動すると**ホスト識別情報・OS・内部／外部 IP・プロセス一覧**などを入れ子の `info` ブロックに まとめた JSON で C2 へ送る。 侵害後は `net` コマンドによる列挙と、**`vssadmin.exe` でボリュームシャドウコピーを作成してから `ntds.dit` をコピー**する動きが観測されている

  1. 1. 実行disclosed[1]
    **正規の実行ファイルと悪性 DLL、暗号化された `config.ini`** が同じ場所に展開される。 Sophos は ZIP アーカイブ `aez.zip` の例として、 クリーンなローダー（`javaw.exe`）・サイドロードされる DLL（`jli.dll`）・ 暗号化ペイロードを含むファイル（`config.ini`）の3点を挙げている。 正規の実行ファイルが起動すると、信頼されたアプリケーションが **実行時に攻撃者のコードを読み込む**
    根拠: Sophos CTU の記事（サイドローディング組み合わせの表1、 ZIP アーカイブ `aez.zip` の構成を示した図1）
  2. 2. 検知回避disclosed[1]
    3段構えである。 **①サイドローディングそのもの**——信頼された正規プロセスの中でコードが動く。 Sophos は「**名前を変えた正規実行ファイルが、被害環境に溶け込むために 頻繁に使われる**」とし、実行の結果は**ディスク上の追加成果物ではなく メモリ内の shellcode 活動**になると述べている。 **②DLL の難読化**——悪性 DLL は**フラット化された制御フロー**を実装し、 直接の分岐の代わりに**仮想化された状態機械**でプログラムの論理を隠す。 状態値が状態ごとのテーブルを引き、その値を**バイト交換・可変ローテーション・反転・ 否定**からなる独自のビット混合ルーチンに通し、結果をコードポインタの ジャンプテーブルの添字にして間接ジャンプする。 **一部の添字は意図的にフォールスルー位置へ解決され**、静的解析をさらに妨げる。 **③ペイロードと設定の暗号化**——`config.ini` は暗号化されており、実行時に復号される
    根拠: Sophos CTU の記事（改名した正規実行ファイルの使用、メモリ内 shellcode 活動、 フラット化された制御フローのディスパッチャとビット混合ルーチンを示した図2、 暗号化された `config.ini`）
  3. 3. C2通信disclosed[1]
    起動したペイロードは、入れ子の `info` ブロックを持つ構造化 JSON を C2 へ送信する。 含まれるのは**ホスト識別情報（ホスト名・ユーザー名・GUID・ドメイン）・ OS バージョン（例: 10.0.19042）・内部 IP・外部 IP・ プロセス一覧とメタデータ（PID・プロセス名・実行方式）・作業ディレクトリ・ コードページ・CPU アーキテクチャ・インプラント開始時刻・ インプラント種別（server/client）**である。 **バージョン 1.1.5** の C2 は `dc[.]cathaypacifice[.]com`・`net[.]dpworldto[.]com`。 **バージョン 1.1.7** は **`github[.]com` のリポジトリから暗号化設定ファイルを取得**する。 さらに **`file[.]io`・`gofile[.]io`・`ably[.]net`・`ably[.]io` といった 正規サイトへの接続**も観測されており、Sophos は**C2 からの指示受信に 使われた可能性**を挙げている
    根拠: Sophos CTU の記事（図6 の JSON `info` ブロック、バージョンごとの C2、 GitHub リポジトリ `hxxps://api[.]github[.]com/repos/LatonyCharnleyaW` と その中の暗号化設定とみられるファイル、正規サイトへの接続）
  4. 4. 内部探索disclosed[1]
    ペイロードの導入後、攻撃者は**一般的な調査タスク**を実行する。 Sophos が挙げているのは **Windows の `net` コマンドによる ローカルネットワークと利用者アカウントの列挙**である
    根拠: Sophos CTU の記事（`net` コマンドによる列挙）
  5. 5. 認証情報アクセスdisclosed[1]
    攻撃者は **`vssadmin.exe` でボリュームシャドウコピーを作成**してから、 **Windows の `ntds.dit` をコピー**している。 Sophos は `ntds.dit` を「**Active Directory の中核データベースファイルで、 利用者の認証情報・グループポリシー・セキュリティ設定・ドメイン構成を含む**」と 説明している
    根拠: Sophos CTU の記事（`vssadmin.exe` によるボリュームシャドウコピーの作成と `ntds.dit` のコピー、`ntds.dit` の内容の説明）
  6. 6. 収集推定[1]
    Sophos は、メモリ上の文字列（C++ の関数デコレータに関連するもの）から **BRONZE SANDCASTLE がペイロードに組み込んでいるデータ窃取の機能**を 確認したとしている。 **具体的に何を収集する機能かは記事に明示されていない**
    根拠: Sophos CTU の記事（図5 のメモリ内文字列とデータ窃取機能に関する記述）

Sandboxie の sbiedll.dll が繰り返し現れたため、Sophos は新しいグループ名を立てた概観出典 [1]

Sophos X-Ops（Counter Threat Unit および SophosLabs）の分析（2026年10月20日）によれば、分かっていることは次のとおりである。

  • 最も特徴的な技術的痕跡は、Sandboxie の DLL サイドローディングである。複数の被害環境で、正規の Sandboxie 実行ファイルの隣に悪性の sbiedll.dll が置かれ、信頼されたアプリケーションが実行時に攻撃者のコードを読み込んでいた。Sophos は「この一貫したパターンがこのグループの署名として機能する」としている
  • サイドローディングの組み合わせは9通りが公表されている（下表）
  • サイドロードされた DLL は、暗号化された config.ini に格納されたペイロードを読み込んで実行する。Sophos はこれを「静的検知を最小化し、DLL バイナリを差し替えずに挙動を調整できる設計」と説明している
  • 名前を変えた正規実行ファイルが頻繁に使われ、実行の結果はディスク上の追加成果物ではなくメモリ内の shellcode 活動になる
  • ペイロードはバージョン 1.1.5 と 1.1.7 の2種類が確認された
  • 被害は2025年8月〜2026年8月の事案で、フィリピン・台湾・アフガニスタン・ナミビア、およびおそらく大韓民国。組織名・件数・業種は公表されていない

Metasploit に似ているが Metasploit ではない——ROR13 を使っていない原因・手口出典 [1]

復号されたペイロードはバックドアである。メモリ上に展開された config.ini は、一見すると Windows の実行ファイルに見える。

ファイルの先頭は位置独立の PE ローダーと実行スタブ——いわゆるリフレクティブローダーである。Sophos はこのペイロードについて、次のように整理している（出典1）。

Metasploit のステージレス shellcode と似ている点

  • 位置独立での実行
  • 手動での PE 検証
  • 埋め込まれた実行ファイルのメモリ内ロード

Metasploit の標準的な成果物ではないと判断した点

  • API 解決のロジックが、Metasploit で広く知られた ROR13 アルゴリズムではなく、独自のハッシュ・変換ルーチンを使っている
  • コードベースが、典型的な MSF shellcode より大幅に大きく複雑である

さらに、解析された検体には COFFLoader プロジェクトの要素が含まれていた。Sophos は「このプロジェクトの標準 API が使われていることは、マルウェアの作者が独自の Beacon Object File（BOF）を用いて自前のポストエクスプロイト機能を作ったことを示唆する」としている。

この判断の仕方が実務的に重要である（本記録の評価）。「Metasploit 風だから Metasploit」と結論すると、既製ツールを使う一般的な攻撃者として扱ってしまう。 Sophos は API 解決のアルゴリズムという細部で区別し、「観測されたローダーと新規の Meterpreter ベースのペイロードの詳細は、BRONZE SANDCASTLE に固有のものと思われる」と結論している。既製ツールの模倣は、帰属の手がかりを消す方向にも働く——だからこそ、細部での区別が要る。

悪性 DLL 側の難読化も独自である。コードはフラット化された制御フローを実装し、直接の分岐の代わりに仮想化された状態機械で論理を隠す。状態値が状態ごとのテーブルを引き、その値がバイト交換・可変ローテーション・反転・否定からなるビット混合ルーチンに通され、結果がコードポインタのジャンプテーブルの添字になって間接ジャンプする。一部の添字は意図的にフォールスルー位置へ解決されるよう作られており、静的解析をさらに妨げる。

C2 は実在企業に似せたドメインと、GitHub や file.io のような正規サービスである被害規模・影響範囲出典 [1]

起動したペイロードは、入れ子の info ブロックを持つ構造化 JSON を C2 へ送る。含まれる情報は次のとおりである（出典1）。

  • ホスト識別情報: ホスト名・ユーザー名・GUID・ドメイン
  • OS バージョン（例: 10.0.19042）
  • 内部 IP アドレス・外部 IP アドレス
  • プロセス一覧とメタデータ（PID・プロセス名・実行方式）
  • 作業ディレクトリ・コードページ・CPU アーキテクチャ
  • インプラントの開始時刻・インプラント種別（server/client）

通信先はバージョンによって異なる。

  • バージョン 1.1.5: dc[.]cathaypacifice[.]com・net[.]dpworldto[.]com
  • バージョン 1.1.7: github[.]com のリポジトリから暗号化された設定ファイルを取得。Sophos が挙げたリポジトリは hxxps://api[.]github[.]com/repos/LatonyCharnleyaW で、履歴がほとんど無く、投稿も数件だった。暗号化された設定ファイルとみられるのはmain.3ku8inqb.js.map・main.lhxjkkai.js.map・main.y8hnze7q.js.map・README.md、さらに .ts 拡張子の暗号化ファイルがあり、Sophos は「バックドアが使うインプラントである可能性」を挙げている
  • いずれのバージョンでも、file[.]io・gofile[.]io・ably[.]net・ably[.]io といった正規サイトへの接続が観測されており、Sophos はC2 からの指示受信に使われた可能性を指摘している

2つ、本記録から補っておく（本記録の指摘）。

  1. 1.1.5 のドメインは実在企業に似せてある。 cathaypacifice[.]com は Cathay Pacific（キャセイパシフィック航空）、dpworldto[.]com は DP World（港湾運営大手）を思わせる綴りである。ログを目視で確認する運用では見落とされやすい——一瞬では正規のドメインに見える。
  2. 1.1.7 の GitHub 利用は、ドメイン単位のブロックが効かない。 file[.]io・gofile[.]io・ably も同様である。「悪性ドメインをブロックする」という対策の射程外にあり、効くのは「誰がそこへアクセスしているか」を見る側の対策である。

侵害後の動きとしては、Windows の net コマンドによるローカルネットワークと利用者アカウントの列挙、そしてvssadmin.exe によるボリュームシャドウコピーの作成と ntds.dit のコピーが観測されている。

ntds.dit まで到達した事例がある——端末の駆除で終わらない評価・解釈出典 [1]

Sophos は、攻撃者が vssadmin.exe でボリュームシャドウコピーを作成してからntds.dit をコピーした事例を報告している。同社はこのファイルを「Active Directory の中核データベースファイルで、利用者の認証情報・グループポリシー・セキュリティ設定・ドメイン構成を含む」と説明している。

ここから先は本記録の評価である。

ntds.dit を取られた場合、影響は「その端末が侵害された」では済まない。ドメイン内の全利用者のパスワードハッシュがオフラインで解析できる状態になり、さらに krbtgt アカウントのハッシュが含まれるため、攻撃者は任意の権限のチケットを偽造できる（ゴールデンチケット）。この状態は、侵害された端末を駆除しても解消しない。

対応は次の性質を持つ（本記録の補足。Sophos はこの点に触れていない）。

  • krbtgt のパスワードを2回リセットする必要がある（1回目と2回目の間に、全ドメインコントローラへのレプリケーションが完了する時間を空ける）
  • 全利用者・全サービスアカウントのパスワードリセットの要否を判断する
  • これらは業務停止を伴う可能性がある決定であり、経営判断を要する

したがって、実務上の含意は次の2点になる。

  1. 検知の優先順位として、ntds.dit へのアクセスは最上位に置く価値がある。ドメインコントローラ上での vssadmin create shadow は、正規のバックアップ製品以外ではほぼ起きない——除外の設計が容易で、誤検知の少ない検知ルールになる。
  2. ntds.dit が取られた場合の手順を、事前に用意しておく。インシデントの最中に krbtgt の2回リセットの手順と影響を調べ始めると、判断が遅れる。

活動時間帯が UTC+8 に集中——「996」との整合が帰属の補強に使われている帰属出典 [1]

Sophos が中国拠点と評価する根拠は次のとおりである（出典1）。

  • 地理的な標的の重なり——アジアとアフリカの組織を標的にしており、これは BRONZE PRESIDENT・BRONZE ATLAS を含む複数の中国拠点グループに典型的である
  • 活動時間帯——攻撃者が UTC+8 の時間帯に最も活発であることが、中国拠点という帰属を補強する。Sophos は、活動時間が中国のテック業界で特に広まった「996」の勤務形態（午前9時〜午後9時・週6日）と整合すると指摘している

一方で、BRONZE PRESIDENT・BRONZE ATLAS のいずれにも確実には結びつけられなかった。 Sophos は次のように述べている。

地理的な標的は これらのグループと重なるものの、観測された活動を確実にいずれかへ結びつけることはできず、独自の技術的特徴を示した。そのため CTU の研究者は、この活動の背後にいるグループを表すためにBRONZE SANDCASTLE という別個の呼称を設けた（原文英語・訳）

本記録はこの区別を保つ（本記録の整理）。「中国拠点とみられる」とは書けるが、「中国政府の作戦である」とは書けない。 Sophos が示したのは地理的傾向と活動時間帯であり、組織的な帰属（どの機関か、国家の指示か）を示す材料は公表されていない。

なお推奨の節で Sophos は、名宛人を「中国の情報収集活動（China's intelligence-gathering operations）に狙われるおそれのある組織」としている。自社がこれに当たるかどうかの判定は、各組織が行うことになる（本記録の評価）。

**Sophos 自身が「静的なファイルベースの検知は効果がない可能性がある」としている。** 実行ファイルは正規のもので、ペイロードは暗号化されている。 一方、**「DLL がローカルファイルを読んだ直後にメモリ上で実行する」**という 振る舞いは観測でき、Sophos はこれを推奨する指標として挙げている
検知できた**正規の実行ファイルが本来のインストール先以外（ZIP 展開先・ 利用者書き込み可能なパス）から起動することを検知する。** Sandboxie・Krita・NVDA・LINE・Sysinternals などの実行ファイルが 想定外のパスにあること自体が指標になる
侵入を防げた**アプリケーション制御を「発行元＋パス」で書く。** 署名が有効であっても、利用者書き込み可能なパスからの起動を許可しない
検知回避機会はあったが検知できず
**Sophos は明確に方針を示している**—— 「静的なファイルベースの検知は効果がない可能性があるため、 **DLL がローカルファイルを読み、直ちにメモリ上で実行する**といった 振る舞い指標に注目すべきである。 **エンドポイントのテレメトリとメモリベースの検知が不可欠**であり、 **リフレクティブローディングのパターン、メモリ上の異常な PE ヘッダー、 位置独立 shellcode の実行特性を持つプロセス**の監視を有効にすべきである」
検知できた**DLL が同ディレクトリのローカルファイル（`config.ini` など）を読んだ直後に メモリ上で実行する**という連鎖を検知する（Sophos の推奨）
検知できた**メモリ上の異常な PE ヘッダーとリフレクティブローディングのパターン**を 監視する。メモリベースの検知を有効にする（Sophos の推奨）
検知できた**正規実行ファイルの改名**を検知する—— 既知のハッシュを持つ正規バイナリが、本来と異なるファイル名で実行されていないか （Sophos は `Start.exe` が改名した Sandboxie 実行ファイルであると明記している）
C2通信機会はあったが検知できず
**ドメイン名が実在企業に似せてある**（本記録の指摘）—— `cathaypacifice[.]com` は Cathay Pacific（キャセイパシフィック航空）、 `dpworldto[.]com` は DP World（港湾運営大手）を思わせる。 **タイポスクワッティングは、ログを目視する運用では見落とされやすい。** さらに難しいのは **GitHub・`file[.]io`・`gofile[.]io`・`ably` への接続**で、 **いずれも正規サービスであり、ドメイン単位のブロックは業務影響が大きい**（本記録の評価）
検知できた`dc[.]cathaypacifice[.]com`・`net[.]dpworldto[.]com` をブロックし、 **過去ログを遡って接続の有無を検索する**。 あわせて**自社の取引先・著名企業に似せたドメイン**への通信を 定期的に洗い出す仕組みを作る
検知できた**GitHub API（`api.github.com`）への、開発用途でない端末からのアクセス**を検知する。 ブロックは業務影響が大きいため、まず「開発部門以外の端末からの GitHub API アクセス」をアラートにする
検知できた**`file[.]io`・`gofile[.]io` といった匿名ファイル共有サービス**への 業務端末からのアクセスをブロックまたはアラートにする
内部探索機会はあったが検知できず
**`net` コマンドによる列挙は、検知ルールとして広く知られたものである**（本記録の評価）。 `net user /domain`・`net group`・`net view` といった実行は プロセス起動ログで取得でき、**通常の利用者端末では滅多に実行されない。** Sophos はこの段階固有の推奨を書いていないが、 **エンドポイントのテレメトリを求める一般的な推奨の射程に入る**
検知できた`net.exe`・`net1.exe` による**ドメインの利用者・グループ・共有の列挙**を 検知ルールにする。利用者端末での実行を優先的にアラートにする
認証情報アクセス機会はあったが検知できず
**ここが最も重い段階であり、かつ最も検知しやすい段階でもある**（本記録の評価）。 `ntds.dit` はドメインコントローラ上にあり、 **`vssadmin create shadow` の実行はドメインコントローラでは バックアップ以外にほぼ起きない。** **`ntds.dit` が取られた場合、ドメイン全利用者の認証情報が オフラインで解析できる状態になる**—— 対応は端末の駆除では終わらず、**krbtgt アカウントのパスワードを2回リセットする**などの ドメイン全体の措置が要る（本記録の補足。Sophos はこの点に触れていない）
検知できた**ドメインコントローラ上の `vssadmin.exe`／`wmic shadowcopy`／ `diskshadow.exe` の実行を検知する。** 正規のバックアップ製品のプロセスを除外したうえで、それ以外は必ずアラートにする
検知できた**`ntds.dit` へのアクセスとコピーを監査する** （ファイルシステム監査、またはシャドウコピー経由の読み取りの検知）
復旧を早められた**`ntds.dit` の持ち出しが疑われた場合の手順をあらかじめ用意する**—— `krbtgt` のパスワードを（レプリケーション間隔を空けて）2回リセットし、 全利用者のパスワードリセットの要否を判断する
収集公表されていない
**この段階の検知について Sophos は述べていない。** 収集対象が明示されていないため、 **本記録はこの段階の具体的な対策を書けない**（本記録の留保）
検知できたメモリベースの検知（Sophos の一般的な推奨）を有効にし、 位置独立 shellcode の実行特性を持つプロセスを監視する

対応の評価

評価材料がない判断は「評価材料なし」としています。結果論で断じないための区分です。
対応の巧拙を評価できる材料が公表資料から得られていません。
CISO・経営層への示唆
  • 「日本の被害は確認されていない」を「関係がない」と読み替えない
    Sophos が確認した被害国は**フィリピン・台湾・アフガニスタン・ナミビア、 および おそらく韓国**で、日本は含まれていない。 **しかし DLL サイドローディングの組み合わせに LINE の `LineAppMgr.exe` が入っている。** LINE は日本で広く使われており、 **業務端末に導入されていれば同じ組み合わせが成立しうる**（本記録の評価）。 台湾・韓国という地理的な近接も考慮に値する
    取るべき行動 ①**業務端末に LINE が導入されているかを把握する**（個人利用の持ち込みを含む） ②導入されている場合、`LineAppMgr.exe` の近傍に **想定外の `msvcp140.dll` が無いか**を確認する ③脅威レポートを読む際の社内ルールとして、 **「被害国に日本が無い」を除外の理由にしない**ことを明記する—— 見るべきは**悪用される前提条件（どのソフトウェアが入っているか）**のほうである
  • ntds.dit が取られた場合の手順を、インシデント前に用意しておく
    BRONZE SANDCASTLE は **`vssadmin.exe` でボリュームシャドウコピーを作成してから `ntds.dit` をコピー**している。 `ntds.dit` にはドメイン利用者の認証情報と `krbtgt` のハッシュが含まれ、 **取られた場合、侵害端末の駆除では解消しない。** `krbtgt` の2回リセットと全利用者のパスワードリセットは**業務停止を伴いうる経営判断**である
    取るべき行動 ①**`ntds.dit` の持ち出しが疑われた場合の手順書**を作る—— `krbtgt` の2回リセット（レプリケーション完了を待つ間隔）、 全利用者・サービスアカウントのパスワードリセットの判断基準、業務影響の見積もり ②**その判断を誰が行うか**を事前に決める（インシデント対応体制の中で明記する） ③年1回の机上演習の題材に入れる
  • 「静的検知が効かない」と書かれたレポートを、EDR の能力確認の機会にする
    Sophos は「**実行時に復号される暗号化ペイロードと設定ファイルを主に使うため、 静的なファイルベースの検知は効果がない可能性がある**」とし、 **エンドポイントのテレメトリとメモリベースの検知が不可欠**だとしている。 **これは製品の有無ではなく能力の問題である**—— EDR を入れていても、メモリスキャンの精度・リフレクティブローディングの検知は 製品によって大きく異なる
    取るべき行動 ①自社の EDR が**メモリ上の異常な PE ヘッダー・リフレクティブローディング・ 位置独立 shellcode の実行**を検知できるか、**ベンダーに具体的に確認する** （「できます」ではなく、どのイベントとして出るかを確認する） ②検知できる場合、**その機能が有効になっているか**を設定で確認する （負荷を理由に無効化されていることがある） ③できない／有効化していない場合、**それを受容したリスクとして記録に残す**
  • 帰属の表現を「中国拠点とみられる」で止める
    Sophos が示した根拠は**地理的な標的傾向**と**UTC+8 への活動時間の集中** （中国の「996」勤務形態との整合）である。 **既存グループ（BRONZE PRESIDENT・BRONZE ATLAS）には確実に結びつけられなかった**ため 新しい呼称が設けられた。 **組織的な帰属——どの機関か、国家の指示によるか——を示す材料は公表されていない**
    取るべき行動 ①社内・取締役会への報告で「中国の攻撃」と断定していないか確認する ②**Sophos が書いた確度の表現（「確実に結びつけることはできなかった」 「補強する」）をそのまま伝える** ③帰属が未確定でも対策は進められることを明記する—— **9通りのサイドローディングの組み合わせと `ntds.dit` の検知は、帰属と独立に使える**
セキュリティ技術者への示唆
  • 9通りの組み合わせを、ファイル名の対で今日ハンティングする
    Sophos は**正規ファイルと悪性 DLL の対**を具体的に公表している。 **対としての出現**（正規実行ファイルの隣に特定名の DLL）は、 それぞれ単独よりはるかに絞り込める
    取るべき行動 ①次の対を検索する—— `SandboxieWUAU.exe`／`Start.exe` ＋ `sbiedll.dll`、 `javaw.exe` ＋ `jli.dll`、`Krita.exe` ＋ `Krita.dll`、 `NvdaHelper.exe` ＋ `NvdaHelperRemote.dll`、 `Jcef_helper.exe` ＋ `Libcef.dll`、`Vmmap.exe` ＋ `Version.dll`、 **`LineAppMgr.exe` ＋ `msvcp140.dll`**、`bginfo64.exe` ＋ `snmpapi.dll` ②あわせて**同ディレクトリの `config.ini`** の有無を見る （暗号化ペイロードの格納先） ③**これらは観測された範囲の一覧である**—— 恒久策は「署名付き実行ファイル × 未署名 DLL × 利用者書き込み可能パス」の 一般形の検知にする
  • 「DLL がローカルファイルを読んだ直後にメモリ上で実行する」を検知の軸にする
    **Sophos が最初に挙げた推奨の振る舞い指標がこれである。** 暗号化された `config.ini` を読み、復号してメモリ上で実行する—— この連鎖は、ファイルのハッシュが毎回変わっても残る。 Sophos はこれを「**復号とステージングの活動を示しうる**」としている
    取るべき行動 ①EDR で、**DLL をロードしたプロセスが同ディレクトリの非実行ファイル （`.ini`・`.dat`・`.cfg`）を読み、直後に RWX メモリ領域を確保する**という 連鎖を検知ルールにする ②あわせて**メモリ上の異常な PE ヘッダー**（`MZ`／`PE` シグネチャを持つ 無名のメモリ領域）の検知を有効にする ③**位置独立 shellcode の実行特性**を持つプロセス—— イメージにマップされていないメモリからの実行——を監視する
  • ドメインコントローラでの vssadmin 実行を、除外を絞って必ず上げる
    攻撃者は **`vssadmin.exe` でボリュームシャドウコピーを作成してから `ntds.dit` をコピー**している。 **ドメインコントローラ上でのシャドウコピー作成は、 正規のバックアップ製品以外ではほぼ起きない**—— 他の検知ルールと比べ、**除外の設計が容易で誤検知が少ない**（本記録の評価）
    取るべき行動 ①ドメインコントローラでの `vssadmin.exe`・`wmic shadowcopy`・`diskshadow.exe` の 実行をすべて記録する ②**正規のバックアップ製品のプロセスとスケジュール時刻だけを除外**し、 それ以外は例外なくアラートにする ③**`ntds.dit` への直接アクセス・コピー**をファイルシステム監査の対象にする （シャドウコピー経由の読み取りを含む）
  • C2 の見分け方を「悪性ドメインのブロック」から広げる
    **バージョン 1.1.5 のドメインは実在企業に似せてある**—— `dc[.]cathaypacifice[.]com`（Cathay Pacific）、 `net[.]dpworldto[.]com`（DP World）。 **バージョン 1.1.7 は GitHub から暗号化設定を取る**。 さらに `file[.]io`・`gofile[.]io`・`ably[.]net`・`ably[.]io` への接続も観測されている—— **いずれも正規サービスで、ブロックは業務影響が大きい**
    取るべき行動 ①公表された2つのドメインをブロックし、**過去ログを遡って接続の有無を検索する** ②**自社名・取引先名・著名企業名に似せたドメイン**への通信を 定期的に洗い出す仕組みを作る（タイポスクワッティングの検出） ③**`api.github.com` への、開発部門以外の端末からのアクセス**をアラートにする （ブロックではなく検知から始める） ④`file[.]io`・`gofile[.]io` などの匿名ファイル共有サービスは、 業務上の必要を確認したうえでブロックを検討する
  • 「正規バイナリが本来の場所にない」を見る——ただし除外の設計を先に決める
    Sophos は「**名前を変えた正規実行ファイルが、被害環境に溶け込むために 頻繁に使われる**」としている。`Start.exe` は改名した Sandboxie 実行ファイルである。 **ファイル名ではなくハッシュ・内部名で見れば、改名は検知できる**
    取るべき行動 ①既知の正規バイナリ（Sandboxie・Sysinternals・LINE・Krita・NVDA）について、 **ファイル名と内部名／署名者が一致しない実行**を検知する ②**ポータブル版ツールを業務で使う文化がある場合、 除外の設計を先に行う**——Sysinternals は管理者が `%TEMP%` や共有フォルダから 直接実行することが多く、除外なしでは運用できない ③除外は**実行者（管理者アカウント）と実行元パスの組み合わせ**で書き、 「ファイル名だけ」の除外を作らない

認証・認可□ **`ntds.dit` が持ち出された場合の手順**（`krbtgt` の2回リセット・ 全利用者のパスワードリセットの判断基準・業務影響）が用意されていない`ntds.dit` を取られた影響は**侵害端末の駆除では解消しない。** インシデントの最中に手順と影響を調べ始めると、判断が遅れる
運用・監視□ ポータブル版ツール（Sysinternals など）を業務で使う文化があり、 **正規バイナリの「本来の場所以外からの実行」を区別する仕組みが無い**Sophos は「**名前を変えた正規実行ファイル**が被害環境に溶け込むために 頻繁に使われる」としている。 ポータブル版を日常的に使う環境では、この手口と正規利用を区別できない
体制・契約□ 脅威レポートを社内で扱う際に、 **「被害国に日本が無い」ことを対応不要の理由にしている**本件で日本の被害は確認されていないが、 **悪用される前提条件（LINE をはじめとする正規アプリの導入）は日本でも成立する。** 見るべきは被害国ではなく前提条件である（本記録の評価）
