INC-2026-0627英ICOがPassword1放置の2組織を戒告

英 ICO、2024年11月のランサムウェア被害をめぐりウェールズの2組織を戒告—— 2012年1月に作られた検証用アカウント「Test2」がパスワード「Password1」のまま 12年半放置され、ローカル管理者アカウントも3台で同じパスワードを共有していた。 漏えいしたのは3,300人分、その大半が子どもの個人情報

ランサムウェア被害（暗号化・リークサイト恐喝が中心）不正アクセス・侵害委託先・再委託先起因で委託元多数に波及初報のみ有名事象として記録（日本と直接の関係は薄い）認証情報の悪用（使い回し・推測可能・窃取）権限管理の不備ガバナンス・組織文化（ガイドライン理解不足・丸投げ等）委託先・供給元起因
初報: 2026年10月14日（ICO の執行記録の日付） 最終更新: 2026年10月20日（ICO の報道発表）

12年半前に作った検証用アカウントが、子ども3,300人分の個人情報を持ち出す入口になった事例です。

2026年10月20日、英国の情報コミッショナー事務局（ICO）は、ウェールズの2組織に対する戒告（reprimand）を公表しました（出典1）。対象はOgi Networks Limited（ONL）——Data Cymru にサーバ・接続基盤・ライセンス・サポートを提供していた事業者と、Local Government Data Unit – Wales（通称 Data Cymru）——ウェールズの公共機関のデータ活用を支援する組織です。2024年11月1日、Data Cymru がランサムウェア攻撃を受け、3,300人分（大半が子ども）の個人情報が持ち出されました（出典1）。

本記録が要点と見たのは、次の3点です。

  • 入口は「12年半前に作った検証用アカウント」だった。 ONL は2012年1月、Data Cymru 向けの初期プロジェクトで「Test2」という検証用アカウントを作り、パスワードに 「Password1」 を付けた（出典1・2）。本番移行前に利用者アカウントの動作を確かめる目的だったとされ、移行後も消されずに残った。ICO は Bitwarden のパスワード強度判定を引き、「Password1」は「very weak」で解読に要する時間は1秒未満と評価されたことを示している（出典2）。
  • 1台の侵害が全台に広がった理由は、ローカル管理者の使い回しだった。被害を受けた3台のシステムのローカル管理者アカウントはすべて同じパスワードで、1台が破られるとローカルアカウントのハッシュを収集して他のシステムへ認証できた（出典2）。ONL はこれらのアカウントを初期導入後に一度も棚卸ししていなかったとされる。
  • ICO は「責任は一方の組織だけにあるのではない」と書いて2組織を同時に戒告した。アカウントを作ったのは ONL、ネットワーク全体の統制（ONL にアカウントの作成・削除を指示する権限を含む）を保持していたのは Data Cymru である。ICO は「どちらも、不要になった古いアカウントを定期的に特定して削除する十分に明確で実効的な措置を講じていなかった」と認定した（出典1・2。原文英語）。

処分は制裁金ではなく戒告です。 ONL は UK GDPR 第32条(1)(b)・(1)(d) の違反、Data Cymru は第28条(4)・第32条(1)(b)・(1)(d) の違反と認定されました（出典1）。両組織は2025年4月30日に適法な データ処理契約を締結し、Data Cymru は定期的なアカウント棚卸しと多要素認証を導入しています（出典1）。ランサムウェアの攻撃グループ名、Test2 の認証情報の入手方法、本人通知の範囲は公表されていません〈未確定1〉〈未確定3〉。

公表されていない・確定していないこと6
  • 攻撃者が「Test2」アカウントの認証情報を入手した方法公表されていない
    ICO は「脅威アクターが『Test2』という検証用アカウントを悪用してネットワークへ侵入した」とするのみで、 総当たり・推測・パスワードスプレー・漏えい済み資格情報の再利用のいずれであったかを示していない（出典2）。 **「Password1」の強度評価（1秒未満）は Bitwarden のツール出力であり、 実際の解読時間ではない**（本記録の明示）。 また、そのアカウントがどの経路（VPN・RDP・公開サービス）から使われたかも公表されていない
  • 戒告文書（PDF）の本文に書かれている詳細検証できない
    ICO の戒告文書は ONL・Data Cymru の双方について PDF で公開されているが、 **ページが画像として埋め込まれており、テキスト層を持たない**（出典7・8）。 本記録の作成者は本文を読み取れておらず、条項番号・数値・経緯は ICO の報道発表（出典1）と The Register の引用（出典2）で確認した〈齟齬3〉
  • 3,300人のうち子どもの人数、関係した2つの事業の名称、データ項目の内訳、本人通知の有無公表されていない
    ICO は「3,300人分で、その大半が子どもだった」「子どもと家庭を支援する2つの事業に関係する」と記すのみである（出典1）。 子どもの人数、事業の名称、漏えいした項目（氏名・生年月日・住所・支援内容等）の内訳、 本人またはその保護者への通知の有無・時期・方法、Data Cymru が ICO へ報告した日は いずれも公表されていない
  • 制裁金ではなく戒告を選んだ理由、および ICO の調査に要した期間公表されていない
    処分は戒告（reprimand）であり制裁金は課されていないが、その判断理由は公表文に説明が無い（出典1）。 2024年11月1日の被害から2026年10月14日の戒告まで約23か月が経過しているが、 ICO がいつ報告を受け、いつ調査を開始・終了したかは示されていない
  • ランサムウェアの攻撃グループ名、身代金要求と支払の有無、リークサイト掲載の有無公表されていない
    ICO の公表文・報道のいずれにも、攻撃グループの名称、ランサムウェアのファミリ名、 身代金の要求額、支払の有無、リークサイトへの掲載の有無は書かれていない（出典1・2・5・6）。 42GB の持ち出しが確認されていることから二重恐喝型の手口と読めるが、本記録は断定しない
  • 被害を受けたシステムの OS・製品名・バージョン、および復旧の経過公表されていない
    Active Directory・ドメインコントローラ・SQL サーバという一般名は示されているが、 具体的な製品・バージョン、暗号化からの復旧に要した期間、 バックアップからの復元の成否はいずれも公表されていない（出典1・2）

攻撃の経過

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

以下は ICO の報道発表と、ICO 戒告文書を引用した報道に書かれた事実関係を段階ごとに並べたものである（出典1・2）。 2012年1月に作られた検証用アカウントが有効なまま残り、 攻撃者はそれを悪用して2024年11月1日に Data Cymru のネットワークへ侵入した。 被害3台のローカル管理者アカウントが同一パスワードを共有していたため、 ローカルアカウントのハッシュを収集して他システムへ認証できた。 ランサムウェアの展開に先立って42GB を持ち出し、そのうえで182.7GB を暗号化した。 認証情報の入手方法、侵入に使われた到達経路、攻撃グループ名はいずれも公表されていない。

  1. 1. 初期侵入disclosed[1] [2]
    2024年11月1日、攻撃者が検証用アカウント「Test2」を悪用して Data Cymru のネットワークへ侵入した。 当該アカウントは2012年1月13日に ONL が作成したもので、 本番移行前の検証を目的としていたとされるが、移行後も有効なまま残っていた。 パスワードは作成時に設定された「Password1」のままだった
    根拠: ICO 報道発表「a threat actor exploited a test account called Test2 to infiltrate its network」 （出典2が引用する戒告文書。原文英語）
  2. 2. 認証情報アクセスdisclosed[1] [2]
    攻撃者が、侵害した1台からローカルアカウントのパスワードハッシュを収集した。 被害を受けた3台のシステムのローカル管理者アカウントは、 2012年1月の作成時に設定された同一の既定パスワードを共有していた
    根拠: 「The local administrator accounts on the three impacted systems all had the same password」 （出典2が引用する戒告文書。原文英語）
  3. 3. 横展開disclosed[2]
    収集したローカルアカウントのハッシュを用いて、 Data Cymru ネットワーク上の他のシステムへ認証した
    根拠: 「the local account hashes could be collected and used by the threat actor to authenticate access to other systems on the Data Cymru network」（出典2が引用する戒告文書。原文英語）
  4. 4. 持ち出しdisclosed[1] [2]
    ランサムウェアの展開に先立ち、プライマリ・ドメインコントローラ、ファイルサーバ、SQL サーバから 42GB のデータを持ち出した。 持ち出されたデータには3,300人分（大半が子ども）の個人情報が含まれていた
    根拠: 「Before deploying the ransomware, the threat actor exfiltrated 42 GB of data from a primary domain controller, a file server and an SQL server」 （ICO の ONL 戒告文書。出典2が引用。原文英語）
  5. 5. 影響（暗号化・破壊・改ざん）disclosed[1] [2]
    ファイルサーバと内部データベースサーバに置かれていた182.7GB のデータを暗号化した
    根拠: ICO 報道発表「182.7GB of data was encrypted」および 「encrypt 182.7 GB of data housed in a file server and an internal database server」（出典1・2。原文英語）

**本記録の作成者による算出。** 2024年11月1日（T3）から2026年10月14日（T6）まで約23か月である。 **これは「組織が当局へ報告するまで」ではなく「当局が処分を記録するまで」の期間である**（本記録の明示）—— Data Cymru が ICO へ報告した日は公表されていない〈未確定4〉
この事案で下された判断
  • ICO は2組織を同時に戒告し、その理由として 「アカウントを作ったのは ONL、ネットワークの統制を保持していたのは Data Cymru」という 責任の分かれ方そのものを明示的に述べた
    トレードオフ: 2組織を並べて処分し理由を説明することで、同じ委託構造を持つ他組織は 「自社ではどちらの立場でアカウントの棚卸し責任を負うのか」を点検できる。 一方で、処分が戒告にとどまったため、同種の不備に対する金銭的な抑止は働かない
  • ICO は執行記録の日付（2026年10月14日）から6日後の10月20日に報道発表を行い、 「Password1」という具体的なパスワード文字列を見出しに出した
    理由は公表されていない
    トレードオフ: 具体的な文字列を見出しに置いたことで報道が広く取り上げ、 「検証用アカウントの放置」という抽象的な論点が読者に届きやすくなった。 一方で、同じパスワードを使っている組織が狙われやすくなるという指摘も成り立つ （**ただし「Password1」は既知の弱パスワード辞書に当然含まれており、 公表によって新たな危険が生じたとは本記録は見ない**）

入口は12年半前の検証用アカウントで、横展開はローカル管理者パスワードの使い回しだった原因・手口出典 [1] [2]

ICO の公表文から読み取れる技術的な経緯は次のとおりである（出典1・2）。

段階 起きたこと 成立させた条件
初期侵入 検証用アカウント「Test2」を悪用してネットワークへ侵入 2012年1月13日に作られたアカウントが有効なまま残り、パスワードが「Password1」だった
横展開 ローカルアカウントのハッシュを収集し、他システムへ認証 被害3台のローカル管理者アカウントが同一パスワードを共有していた
持ち出し プライマリ・ドメインコントローラ／ファイルサーバ／SQL サーバから42GB —
影響 ファイルサーバと内部データベースサーバの182.7GB を暗号化 —

「Test2」は本番移行前の検証用である。 ONL は ICO に対し、「『Test2』アカウントの作成は、本番の利用者を自社サービスへ移行する前に利用者アカウントのアクセスを検証する意図だったと考えられる」と説明している（出典2。原文英語）。つまり目的を終えた時点で消すべきアカウントであり、作成から12年半以上、使われたかどうかにかかわらず有効なまま残った。

ICO が特に指摘したのは、棚卸しの不在である。 ONL は Data Cymru の Active Directory 内の利用者アカウントを点検する手続き（auditing procedures）を持っておらず、ローカル管理者アカウントについても初期導入後に一度も点検していなかった（出典2）。Data Cymru 側の棚卸しは「不定期かつ網羅的でなかった（irregular and incomplete）」とされる（出典1）。

ローカル管理者パスワードの使い回しが、1台の侵害を全台の侵害に変えている。 ICO は「1台が侵害されると、ローカルアカウントのハッシュを収集して脅威アクターが Data Cymru ネットワーク上の他システムへの認証に使うことができた」と書いている（出典2。原文英語）。これは技術的に新しい手口ではなく、2012年の初期構築時の既定値がそのまま残っていたことによる（本記録の評価）。

ICO は「責任は一方の組織だけにあるのではない」と書き、作った側と統制する側の両方を戒告した当局対応出典 [1] [2]

ICO 調査責任者 David Doodson の発言は次のとおりである（出典1・2。日本語訳は本記録・原文英語）。

「Password1 は適切なパスワードではなく、悪意ある者に対して大きく開いた扉である」

「この事案は、もはや必要のないアカウントに付いた1つの弱いパスワードが、数千人に影響しうる重大なサイバー攻撃への扉を開けたままにしうることを示している」

「これらの不備の責任は、一方の組織だけにあるのではない。ONL が検証用アカウントを作成した一方、Data Cymru は自らのネットワークに対する全体的な統制—— ONL にアカウントの作成や削除を指示する権限を含む——を保持していた。どちらも、古いアカウントが定期的に特定され削除されることを確かにするための、十分に明確で実効的な措置を講じていなかった」

認定された違反条項は組織ごとに違う（出典1）。

組織 認定された UK GDPR 違反 内容
ONL 第32条(1)(b)・(1)(d) 検証用アカウントに「Password1」を設定しパスワード強度要件を適用しなかった。作成したアカウントの棚卸しを行わなかった。ローカル管理者パスワードを12年以上変更しなかった
Data Cymru 第28条(4)・第32条(1)(b)・(1)(d) ONL を再処理者とする適合契約が無かった。Active Directory サービスの責任分担を明確に文書化していなかった。休眠アカウントを特定・削除できず、棚卸しが不定期かつ網羅的でなかった

第28条(4) の違反は Data Cymru 側にのみ付いている。 再処理者（sub-processor）を使う場合に同等の義務を契約で課す責任は、処理者である Data Cymru の側にあるという整理である（本記録の読み）。「誰がアカウントを棚卸しするのか」が契約に書かれていなかったことが、技術的不備（弱いパスワード）と並べて処分理由になっている点が本件の特徴である（本記録の評価）。

両組織は2025年4月30日に適法なデータ処理契約を締結し、Data Cymru は定期的なアカウント棚卸しと多要素認証を導入した（出典1）。戒告は制裁金を伴わない〈未確定4〉。

ICO は他組織に向けて6つの行動を挙げた——委託契約に「どう監査するか」まで書くことを含む対策・注意喚起出典 [1]

ICO は報道発表のなかで、他の組織が取るべき行動として次を挙げている（出典1。日本語訳は本記録・原文英語）。

  • 検証用・休眠・退職者のアカウントを特定し、無効化する
  • 弱いパスワード・よく使われるパスワードをブロックする
  • リモートアクセスには既定で多要素認証を適用する
  • 一部だけでなく、すべてのアカウント・権限・セキュリティグループを点検する
  • 特権アカウントには固有の資格情報を与え、1台の侵害が他を露出させないようにする
  • IT 提供者および再処理者とのセキュリティ統制について、どのように実施・監視・監査するかを契約に定める（法的に要求されるすべての条項を含める）

4番目の「一部だけでなくすべて」という書き方に、本件の失敗が凝縮されている（本記録の評価）—— Data Cymru の棚卸しは「不定期かつ網羅的でなかった」と認定されており、棚卸しを行っていたが対象が足りなかったという形である。検証用アカウントは「利用者」の名簿にも「退職者」の名簿にも載らないため、人事起点の棚卸しでは原理的に拾えない（本記録の指摘）。

5番目の「特権アカウントに固有の資格情報」は、本件の横展開を止めた唯一の統制である（本記録の評価）。3台のローカル管理者パスワードが別々であれば、1台のハッシュ収集から他2台への認証は成立しなかった。

経過

2012年1月13日事案前のプロジェクト上の出来事（移行計画等）ONL が Data Cymru 向けの初期プロジェクトにおいて、検証用アカウント「Test2」を作成した。 ONL は ICO に対し、本番利用者を自社サービスへ移行する前に 利用者アカウントのアクセスを検証する意図だったと説明している。 作成時に付けられたパスワードは「Password1」だった。 同じ時期に3台のシステムのローカル管理者アカウントも作成され、 いずれも同一の既定パスワードが設定された
2012年1月〜2024年11月（12年半以上）露出の開始「Test2」アカウントとローカル管理者アカウントが、利用の有無にかかわらず有効なまま残り、 作成時の既定パスワードが変更されなかった。 ONL は初期導入後にローカル管理者アカウントの点検を一度も実施しておらず、 Data Cymru の Active Directory 内の利用者アカウントを点検する手続きも持っていなかった。 Data Cymru 側のアカウント棚卸しは不定期かつ網羅的でなかった
2024年11月1日発生Data Cymru がランサムウェア攻撃を受けた。 攻撃者は「Test2」アカウントを悪用してネットワークへ侵入し、 ランサムウェアの展開に先立ってプライマリ・ドメインコントローラ、ファイルサーバ、SQL サーバから 42GB を持ち出した。そのうえでファイルサーバと内部データベースサーバに置かれていた 182.7GB を暗号化した。 3台のシステムのローカル管理者アカウントが同一パスワードを共有していたため、 1台が侵害された時点でローカルアカウントのハッシュを収集し、 Data Cymru ネットワーク上の他システムへの認証に使うことができた
日付は公表されていない（2024年11月1日以降）判明3,300人分の個人情報が持ち出されたことが判明した。 大半が子どものデータであり、子どもと家庭を支援する2つの事業に関係するものだった。 **判明の経緯・本人への通知の有無・ICO への報告日はいずれも公表されていない**

  • 委託先が作ったアカウントは、委託元の棚卸し名簿にも委託先の作業手順にも載らない
    本件の「Test2」は ONL が初期プロジェクトで作ったアカウントだが、 ONL は Data Cymru の Active Directory 内の利用者アカウントを点検する手続きを持たず、 Data Cymru の棚卸しは不定期かつ網羅的でなかった（出典1・2）。 **人事起点の棚卸し（入社・異動・退職）では、人に紐づかない検証用アカウントは原理的に拾えない**
    取るべき行動 アカウントの棚卸し手順に「人に紐づかないアカウント（検証用・サービスアカウント・ベンダー作成分）」の 区分を設け、所有者と存続理由を記載する欄を作る。 委託先が作成したアカウントの一覧を委託先から定期的に提出させ、 自社の名簿と突き合わせる作業を年次の点検項目に入れる
  • 「誰が棚卸しするか」が契約に書かれていないと、技術的不備と並べて処分理由になる
    ICO は Data Cymru に対し、ONL を再処理者とする第28条(4) 適合の契約が無く、 Active Directory サービスの責任分担を明確に文書化していなかったことを違反として認定した（出典1）。 **契約の空白が、弱いパスワードと同じ重さで処分理由に並んでいる**
    取るべき行動 IT 運用を委託している契約を洗い出し、①アカウントの作成・削除・棚卸しの実施主体、 ②実施頻度、③結果の報告方法、④委託元が監査できる権利の4点が書かれているかを点検する。 再委託（再処理者）がある場合は、同等の義務が再委託先まで及ぶ条項があるかを確認する
  • 処分までに2年近くかかる——事案の終わりは当局の処分であって、復旧ではない
    2024年11月1日の被害に対する戒告は2026年10月14日付である（約23か月後）。 **この期間、組織は調査対応を続けながら、処分が公表される日を自分では決められない**
    取るべき行動 インシデント対応計画に「当局の調査対応フェーズ」を明示的に置き、 担当者の継続確保（異動・退職で引き継ぎが切れない体制）と、 処分公表時の対外説明の雛形を事前に用意する。 あわせて、処分公表時点で「すでに是正済み」と言える状態を作るための是正期限を社内で設定する
  • 子どものデータを扱う事業は、同じ基盤に載せるだけで処分時の重みが変わる
    ICO は3,300人の「大半が子ども」であることと「子どもと家庭を支援する2つの事業に関係する」ことを 報道発表の見出し近くに置いている（出典1）。 **被害件数は3,300人と決して大きくないが、対象の性質が処分と報道の扱いを決めている**
    取るべき行動 要配慮性の高いデータ（子ども・医療・支援記録）を扱う事業を特定し、 同一のファイルサーバ・ドメインに他業務と同居していないかを点検する。 同居している場合は、到達できるアカウントの限定と保存期間の設定を優先して行う
セキュリティ技術者への示唆
  • 特権アカウントの資格情報をシステムごとに固有にする——これが本件の横展開を止めた唯一の統制である
    3台のローカル管理者アカウントが同一パスワードだったため、 1台のハッシュ収集から他システムへの認証が成立した（出典2）。 **パスワードが別々であれば、この経路は成立しなかった**
    取るべき行動 ローカル管理者パスワードを自動で固有化・定期変更する仕組み（Windows であれば LAPS 相当）を導入する。 導入前の棚卸しとして、同一のローカル管理者パスワードを共有しているホストの組を洗い出し、 組の大きさ（何台で共有しているか）を一覧にする
  • 休眠アカウントは「最終ログイン日時」だけでなく「作成日」でも洗う
    「Test2」は2012年1月13日に作られ、2024年11月の攻撃まで残った（出典2）。 **検証用アカウントは一度も本番利用されないことがあり、 最終ログイン日時が空のまま「使われていないから無害」と見過ごされうる**（本記録の評価）
    取るべき行動 アカウント一覧を「作成日が古い順」「最終ログインが無いもの」の2軸で抽出し、 存続理由を所有者に確認する作業を半年ごとに行う。 検証用アカウントには命名規則（接頭辞）と有効期限を必須にし、 期限切れで自動無効化する設定を入れる
  • よく使われるパスワードは、強度ルールではなく拒否辞書で止める
    「Password1」は大文字・小文字・数字を含み、長さ9文字で、 多くの複雑性ルールを形式的には満たす。 **ICO が引いた Bitwarden の判定は very weak・解読1秒未満である**（出典2）
    取るべき行動 パスワード設定時に既知の漏えいパスワード辞書・よく使われるパスワード辞書との照合を入れる （NIST SP 800-63B の推奨に沿う）。 既存アカウントについても、辞書との照合で該当するものを洗い出して強制変更の対象にする
  • ローカル管理者アカウントによるネットワーク越しのログオンを既定で拒否する
    本件の横展開は「ローカルアカウントのハッシュを収集して他システムへ認証」する形である（出典2）。 **ローカルアカウントがネットワーク越しに使える構成であることが前提になっている**
    取るべき行動 ローカルアカウントによるネットワークログオンを拒否するポリシーを適用し、 管理作業は集中管理された個別アカウントと踏み台経由に限定する。 適用前に、ローカルアカウントで動いている運用スクリプト・監視エージェントを棚卸ししておく
  • 持ち出しの量が後から確定できるだけの記録を残しておく
    ICO は42GB・182.7GB という具体的な量を示している（出典1・2）。 **量が確定できたのは記録が残っていたからだと読めるが、 記録が短期で消える設定なら範囲の特定そのものができない**（本記録の評価）
    取るべき行動 外向き通信量とファイルサーバのアクセス記録の保持期間を、 少なくとも調査に耐える長さ（1年）確保する。 ドメインコントローラの認証ログについても同様に保持期間を点検する
