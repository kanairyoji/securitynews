悪用された脆弱性は最も古いものが2020年公表で、すべて既知である原因・手口

勧告が名指しした CVE は5件である（出典1・3。出典3 は「ほかにも含まれる」としている）。

  • CVE-2020-3259 — Cisco ASA 系 - CVE-2023-20269 — Cisco ASA 系 - CVE-2023-27532 — Veeam Backup & Replication - CVE-2024-40711 — Veeam Backup & Replication - CVE-2024-40766 — SonicWall

（製品名の対応は本記録の整理であり、勧告の原文の表記ではない。 対策にあたっては原本と各ベンダーの告知で確認すること。）

5件すべてが既知の脆弱性であり、最も古いものは2020年公表である（本記録の整理）。 SafePay はインターネットに公開されたシステムに対し、 自動化スクリプトで脆弱性を横断的に探索する（出典1）。 未知の脆弱性を使っているのではなく、塞がれていない既知の穴を機械的に探している。

脆弱性と並ぶもう一方の入口は認証情報である。 窃取・流出した認証情報の利用、総当たり攻撃（ATT&CK T1110）、 フィッシングで取得したアカウント情報の利用、そして VPN アクセスの悪用—— VPN の悪用では、VPN プロバイダ Mullvad の IP アドレスが使われている（出典1）。

この最後の点は防御側の手がかりになる（本記録の評価）。 業務上の必要が無いのに商用 VPN の出口 IP から VPN や Webメールへの認証が 成功しているなら、それ自体が調査の端緒である。 認証の成否だけを見ていると気づけない——「どこから成功したか」を見る必要がある。

バックアップは入口でもあり、潰される先でもある評価・解釈

本記録が勧告から最も重いと見たのは、バックアップの扱いである（本記録の評価）。

SafePay は暗号化の前に、ボリュームシャドウコピーサービスを停止し、 NAS を初期設定に戻し、ネットワーク上のバックアップを削除する（出典1）。 つまり同じネットワークから到達できるバックアップは、当てにならない。

さらに、初期侵入に使われた CVE のうち2件（CVE-2023-27532・CVE-2024-40711）は Veeam Backup & Replication のものである（本記録の整理）。 バックアップ基盤が「入口」であり、同時に「潰される先」でもあるという構図になっている。

これは防御の設計に直接効く（本記録の評価）。 バックアップ製品の管理サーバは、守るべき資産の一覧の中で最上位に置くべきである ——そこを取られると、侵入の起点と復旧の手段を同時に失う。 勧告の緩和策が「暗号化・改変不可・組織全体・オフライン」という4条件を 並べているのは、どれか1つが欠けると本件の手口で無効化されうることの裏返しである。

「バックアップはある」と「バックアップから戻せる」は別の話である（本記録の評価）。 勧告は復旧手順を定期的にテストすることを併記している—— テストしていないバックアップは、暗号化された後に初めて試すことになる。

身代金は売上に連動し、電話で催促される被害規模・影響範囲

暗号化は ChaCha20 と RSA のハイブリッドで、拡張子は .SafePay が付く（出典1）。 身代金要求メモはデスクトップやルートディレクトリに置かれ、 TOR の .onion サイト（チャット窓口）への連絡を求める。

要求額は固定ではない。「被害組織の売上の一部に相当する額を暗号資産で」要求する （出典1・3）。 これは防御側の見積り方を変える（本記録の評価）—— 「身代金の相場」から自組織のリスク額を計算することができない。 売上が大きい組織は、それだけで要求額が大きくなる。

そして恐喝には電話が使われる。 勧告は「被害組織に圧力をかけるため、グループの担当者が代理で電話をかける」と 記している（出典3 からの日本語訳。原文英語）。 一部の事例では、システム利用者のパスワードを変更して、 本人のログインと対応を妨げる（出典3）。 対応能力を削りながら、人に直接圧力をかけるという組み合わせである。

支払いがなければ、窃取データがリークサイトで公開される（出典1）。 リークサイトには多数のドイツ企業、加えてラテンアメリカと米国の政府機関が 掲載されているとされる（出典3）。

身代金を払わなくても、コストは8,000万ドルになりうる業績・金銭影響

SafePay は最近、米国有数のIT製品・サービス事業者、英国の Microlise、 政府向け技術受託の Conduent への攻撃を名乗っている（出典3）。

Conduent の事例が示すのは、被害の総額が身代金では測れないことである（本記録の評価）。 同社は Medicaid・養育費・食料支援・道路通行料などの業務を担っており、 攻撃は米国内で広範な影響を生じたとされる。 そして2026年10月16日、同社はランサムウェア攻撃を受けて提起された集団訴訟に対し、 8,000万ドルの和解を公表した（出典3）。

これは身代金ではない。訴訟の和解額である（本記録の明示）。 身代金を払うかどうかの議論とは別の軸で、被害組織1社に8,000万ドルのコストが 発生している——自組織のリスク額を見積もるとき、 身代金・復旧費用・訴訟費用の3つを別に積む必要がある（本記録の評価）。

なお、和解額は報道（出典3）の値であり、本記録は Conduent 自身の公表を 確認していない（本記録の留保）。

道具はすべて正規品で、独自のマルウェアは入ってこない対策・注意喚起

勧告が挙げる道具の一覧は、そのまま「管理者が普段使う道具」の一覧である（本記録の評価）。

  • リモート操作 — AnyDesk・TeamViewer（ランサムウェアの転送に使う）・ScreenConnect（永続化とアクセス維持）
  • 横展開・実行 — PsExec・WinRM・RDP - 偵察 — ShareFinder.ps1・SharpShares.exe・NetExec - 認証情報窃取 — Mimikatz - 圧縮・持ち出し — 7-Zip・WinRAR・FileZilla・RClone・WinSCP・Backblaze（b2.exe）・OneDrive

すべて正規のソフトウェアである（出典1）。 このため、「使われたこと」自体では異常を判定できない（本記録の評価）。 判定の材料になるのは「業務で使う予定が無いのに入っていること」である—— RClone・WinSCP・b2.exe が一般の業務端末に存在する必要はほとんど無く、 ScreenConnect が業務のリモート管理ツールでないなら、その存在自体が異常である。

持ち出し先がクラウドストレージ（Backblaze・OneDrive）である点は厄介である （本記録の指摘）。業務でも使う宛先のため、宛先の遮断では区別できない。 見るべきは量と経路である——サーバ系から外部クラウドへの大量アップロードは、 通常の業務では発生しない。

緩和策は勧告に詳しく書かれている（出典1）。 本記録は detail.mitigations に、それぞれの副作用（導入すると何が困るか）を 添えて整理した——副作用を書かない対策一覧は、現場で止まる。

対応の評価

評価材料がない判断は「評価材料なし」としています。結果論で断じないための区分です。
対応の巧拙を評価できる材料が公表資料から得られていません。
CISO・経営層への示唆
  • **バックアップ基盤を「守る資産」の最上位に置き直す**
    本件では**初期侵入の CVE のうち2件が Veeam Backup & Replication のもの**であり、 同時に**シャドウコピーの停止・NAS の初期化・ネットワーク上のバックアップの削除**が 行われる（出典1。本記録の整理）。 **侵入の起点と復旧の手段が同じ場所にある**（本記録の評価）
    取るべき行動 バックアップ製品の管理サーバを**業務セグメントから分離し、 専用の管理経路からのみ到達できるようにする。** **「暗号化・改変不可・組織全体・オフライン」の4条件を自社のバックアップが 満たしているかを、条件ごとに○×で評価する**—— **1つでも欠けていれば本件の手口で無効化されうる**
  • **リスク額を「身代金・復旧・訴訟」の3つに分けて積む**
    Conduent は**ランサムウェア攻撃を受けて提起された集団訴訟に対し 8,000万ドルの和解を公表した**（出典3）。 **身代金額は被害組織の売上に連動して決まるため、相場からは計算できない**（出典1）
    取るべき行動 インシデントのリスク評価に**訴訟・和解・規制当局対応のコストを独立した項目として 加える。**サイバー保険の補償範囲が**第三者への賠償を含むか**を確認する
  • **恐喝の段階で電話がかかってくる前提で、応対の手順を決めておく**
    勧告は**「被害組織に圧力をかけるため、グループの担当者が代理で電話をかける」**と 記している（出典3 の日本語訳。原文英語）。 さらに**利用者のパスワードを変更して対応を妨げる**事例もある（出典3）
    取るべき行動 **攻撃者からの接触（電話・メール・従業員や顧客への直接連絡）を受けたときの 窓口と応対方針を1ページで決める。** **現場の個人が即答しない**ことを明記し、記録の取り方（録音・報告先）まで決める
  • **MFA の「例外一覧」を持つ**
    勧告は**VPN・Webメール・重要システムを含め、可能な限りすべてのサービスに MFA を 適用する**よう求めているが（出典1）、 **実際には MFA に対応しない旧来システムとサービスアカウントが残る**（本記録の評価）。 **本件の初期侵入の多くは認証情報の悪用である**
    取るべき行動 **MFA が適用できていない認証経路を一覧にし、件数を経営の指標として毎月見る。** 例外には**代替の防御（接続元の制限・パスワード長・監視の強化）を必ず対で付ける**
セキュリティ技術者への示唆
  • **「どこから認証が成功したか」を見る**
    SafePay は**VPN プロバイダ Mullvad の IP アドレス**から VPN アクセスを悪用している （出典1）。**認証の成否だけを見ていると、正常なログインに見える**（本記録の評価）
    取るべき行動 VPN・Webメール・SSO の**認証成功ログに接続元の ASN・国・ 商用 VPN / ホスティング事業者の判定を付ける。** **業務上の必要が無い出口からの成功を異常として通知する**
  • **業務で使うリモート管理ツールを一覧化し、それ以外の存在を異常として扱う**
    **AnyDesk・TeamViewer がランサムウェアの転送に、 ScreenConnect が永続化に使われる**（出典1・3）。 **いずれも正規製品であり、実行ファイルの検知では区別できない**（本記録の評価）
    取るべき行動 **許可するリモート管理ツールを決めて一覧にし、それ以外の実行・インストールを 検知・阻止する。**RClone・WinSCP・b2.exe なども**一般の業務端末には不要**として扱う
  • **サーバから外部クラウドストレージへの大量送信を監視する**
    持ち出し先に**Backblaze（b2.exe）・OneDrive** が使われる（出典1）。 **業務でも使う宛先のため、宛先の遮断では区別できない**（本記録の評価）
    取るべき行動 **サーバ系セグメントから外部への送信量を宛先別に可視化し、 平常時の分布から外れた送信を通知する。** **サーバからのクラウドストレージ接続は、原則として禁止する**
  • **セキュリティ製品の無効化とシャドウコピーの削除を、最優先の警報にする**
    この2つは**暗号化の直前に現れる最後の警報である**（本記録の評価）。 SafePay は**検知回避のためにセキュリティ保護を無効化し、 ボリュームシャドウコピーサービスを停止する**（出典1・3）
    取るべき行動 **改ざん防止（tamper protection）を有効にし、無効化の試行を即時通知する。** **`vssadmin delete shadows` 相当の操作を検知対象にする。** 通知先は**夜間・休日でも人が見る経路**にする
  • **IoC を使うときは観測時期を区別する**
    **勧告の IoC は2024年11月から2026年8月の22か月にわたる観測をまとめたものである** （出典1。本記録の算出）。 **古い指標が現在も有効とは限らず、誤検知と見落としの両方を生む**（本記録の評価）
    取るべき行動 IoC の取り込みに**観測日の属性を持たせ、古いものは「過去の侵害の調査用」と 「現在の検知用」に分けて使う。** **検知に使う IoC は定期的に棚卸しする**

自組織に当てはまるか

該当する項目があれば、この事案と同じ構図が自組織でも成立しうることを意味します。
観点自社に当てはまるか該当する場合に何が起きうるか
システム構成□ **Cisco ASA / SonicWall SSL VPN / Veeam Backup & Replication を インターネットから到達できる形で使っているか**（本件で悪用された CVE の対象製品）**悪用された5件はすべて既知の脆弱性であり、自動化スクリプトで探索される**（出典1）。 **公開されていて未更新なら、標的にされるのは時間の問題である**（本記録の評価）
認証・認可□ **VPN・Webメール・重要システムのすべてに MFA が適用されているか。 適用できていない経路の一覧を持っているか**本件の初期侵入は**窃取した認証情報・総当たり・フィッシング**が中心である（出典1）。 **MFA の無い1経路が、600組織の列に加わる入口になる**（本記録の評価）
システム構成□ **バックアップが「暗号化・改変不可・組織全体・オフライン」の4条件を満たしているか。 バックアップ製品の管理サーバが業務セグメントから分離されているか**SafePay は**シャドウコピーの停止・NAS の初期化・ネットワーク上のバックアップの削除**を 行う（出典1）。**同じネットワークから到達できるバックアップは当てにならない**
運用・監視□ **復旧手順を定期的にテストしているか**（実際に戻せることを確認しているか）勧告は緩和策に**復旧手順の定期的なテスト**を明記している（出典1）。 **テストしていないバックアップは、暗号化された後に初めて試すことになる**（本記録の評価）
運用・監視□ **業務で使うリモート管理ツールが一覧化され、それ以外の存在を検知できるか****AnyDesk・TeamViewer・ScreenConnect はいずれも正規製品であり、 実行ファイルの検知では区別できない**（出典1・3）。 **判定の材料は「業務で使う予定があるか」しかない**（本記録の評価）
体制・契約□ **攻撃者からの直接の接触（電話・従業員や顧客への連絡）を受けたときの 窓口と応対方針が決まっているか****グループの担当者が被害組織へ電話をかけて圧力をかける**（出典3 の日本語訳。原文英語）。 **事前に決めていなければ、現場の個人が応対することになる**（本記録の評価）
