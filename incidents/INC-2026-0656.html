INC-2026-0656お名前.com デスクトップクラウド侵害

GMOインターネットは2026年10月21日、VPSサービス「お名前.com デスクトップクラウド」に 第三者による不正アクセスがあり、一部の顧客サーバー環境に不正なプログラムが設置されたことを 10月20日に確認したと公表した——影響の可能性があるサーバー数は26,739件、 サーバー内に保管されている情報が閲覧された可能性があるとされ、同社は被害拡大防止のため 10月21日4:00以降に全プランの顧客サーバーを順次停止した。再開時期・侵入経路・ 不正プログラムの内容・実際に設置された台数は公表されていない

初報: 2026年10月21日 最終更新: 2026年10月21日

GMOインターネット株式会社は2026年10月21日、VPS サービス 「お名前.com デスクトップクラウド」に対する第三者による不正アクセスについて 「お詫びとお知らせ（2026年10月21日 4:00時点）」を公表しました（出典1）。公表によれば、2026年10月20日に一部の顧客サーバー環境で第三者による 不正なプログラムの設置を確認し、影響の可能性のあるサーバー数は26,739件。 サーバー内に保管されている情報が閲覧された可能性があるとされています。 現時点で個人情報の漏えいや閲覧された情報が悪用された事実は確認されておらず、 クレジットカード情報を含む決済情報は同社では保持していないとされています。同社は被害拡大防止のため、2026年10月21日4:00以降、全プランの顧客サーバーを 順次停止しました。再開時期は「確定次第お知らせ」とされ、本記録作成時点（10月22日）でも 示されていません。利用者にはサーバー内に保管・利用している認証情報の速やかな変更と、 他サービスでの同一パスワードの変更、本件に便乗したフィッシングへの注意を求めています。本サービスは「MT4 の連続稼働を含む FX 自動売買に最適」と訴求されてきた Windows 系 VPS であり、 顧客の資産運用プログラムが動いている基盤が、事業者側の判断で停止した点が本件の特徴です。 なお同社は約1か月前（2026年9月20日公表）にもレンタルサーバー「ConoHa WING byGMO」で 顧客426件の Web サーバー領域に不正プログラムを設置される事案を公表していますが （INC-2026-0497）、両事案の関係は公表されていません。

26,739件の顧客サーバーが「影響の可能性」の範囲に入り、全プランが止まった概観出典 [1]

GMOインターネットの公表（2026年10月21日 4:00時点・出典1）によれば、起きたことは次のとおりである。

  • 2026年10月20日、お名前.com デスクトップクラウドの一部の顧客サーバー環境で、第三者による不正なプログラムの設置を確認した。

  • 影響の可能性のあるサーバー数は26,739件。

  • サーバー内に保管されている情報が閲覧された可能性がある。

  • 現時点で、預かっている顧客の個人情報の漏えい、および閲覧された情報が悪用された事実は確認されていない。

  • クレジットカード情報を含む決済情報は同社では保持していない。

  • 2026年10月21日4:00以降、被害拡大防止のため全プランの顧客サーバーを順次停止した。停止中はサービスを利用できず、再開時期は「確定次第お知らせ」とされた。

  • 顧客サーバーを対象とした調査を継続しており、詳細が判明次第公表するとされた。

公表は「お客様のサーバー環境において」という表現を使っており、 侵害の主たる対象は基盤そのものではなく、その上で動く顧客の仮想サーバーである。 ただし、個々の顧客が別々に侵入されたのではなく26,739件という単位で範囲が示されている点は、 基盤側を経由して顧客環境へ到達した構図を示唆する—— もっともこれは本記録の読みであり、公表に経路の説明は無い。

停止は「守るための決断」だが、止まったのは顧客の資産運用プログラムだった業務・事業への影響出典 [1] [3]

本サービスは Windows デスクトップ環境を VPS として提供するもので、 MetaTrader 4（MT4）の連続稼働を含む FX 自動売買に適すると訴求されてきた（出典3）。 連続稼働が前提の用途では、停止はそのまま自動売買の停止・ポジション管理の断絶を意味する。

公表（出典1）に書かれている事実は次の3点である。
- 停止は2026年10月21日4:00以降、順次。
- 対象は全プラン。
- 停止中はサービスを利用できない。再開時期は未定。

ここから先は本記録の評価である。基盤側に不正プログラムが残る疑いがある状態で稼働を続けると、 顧客の認証情報や取引口座の資格情報が流出し続ける。停止はその出血を止める唯一の手段であり、 確認の翌日に踏み切った判断そのものは合理的である。一方で、 利用者側に「停止されたら何が止まるか」の備えが無ければ、守られても損害は出る。 この種のサービスを使う側の設計責任が問われる局面でもある。

事業者は鍵を回せない——認証情報の変更は利用者の手に委ねられた対策・注意喚起出典 [1]

公表（出典1）が利用者に求めたのは次の3点である。
- サーバー内に認証情報（ID・パスワード等）を保管・利用している場合は、速やかに変更すること。
- 同一のパスワードを他のサービスでも使っている場合は、あわせて変更すること。
- 本件に便乗したフィッシングメールや不審な連絡に注意すること（同社から顧客にパスワードやクレジットカード情報をメール・電話で尋ねることはない）。

ここから先は本記録の評価である。IaaS・VPS の侵害では、事業者は顧客サーバーの中にある 認証情報を把握しておらず、一括で失効させることができない。 顧客が自分のサーバーに置いた API キー・取引所の資格情報・他サービスのパスワードは、 顧客が自分で回すしかない。しかも本件ではサーバーが停止されているため、 「中に何を置いていたか」を思い出す手がかりそのものに到達できない可能性がある。 自分のサーバーに何の秘密を置いたかを、サーバーの外側に台帳として持っているかが分かれ目になる。

同じ事業者の基盤で、約1か月前にも顧客環境への不正プログラム設置があった背景・過去事例出典 [1]

GMOインターネットは2026年9月20日、レンタルサーバー「ConoHa WING byGMO」の一部収容ホストに 9月3日から第三者の不正アクセスがあり、顧客426件の Web サーバー領域に不正プログラムを 設置されたと公表している（INC-2026-0497）。

事実として共通するのは、①同一事業者が運営するホスティング基盤であること、 ②顧客の環境に不正なプログラムが設置されたこと、③侵入経路が公表されていないこと、 ④会員情報・決済情報は別環境のため影響が無いとされたこと、の4点である。

両事案の関係については、同社から一切の言及が無い（公表されていない）。 同一の攻撃者か、同一の経路か、9月の事案の調査が本件の発見につながったのかは分からない。 本記録は関係を推定しない。ただし読者の観点では、「同じ事業者の別サービスでも起きた」 という事実そのものが、委託先の集中リスクを見直す材料になる（本記録の評価）。
