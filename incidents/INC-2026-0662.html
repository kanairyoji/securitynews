INC-2026-0662GitLab に CVSS 10.0 の未認証 RCE

GitLab は現地時間2026年10月21日、定例のパッチリリースで12件の脆弱性を修正した—— **最上位の CVE-2026-110264 は CVSS 10.0 で、正規表現のコンパイル時に起きる 整数オーバーフローにより、認証を経ていない外部の攻撃者が GitLab サーバ上で任意のコードを実行できる。** **影響範囲は CE・EE の 7.0 以降のすべての系列**で、 GitLab は最新系列だけでなく 18.11・19.0・19.1・19.2 の旧系列まで 修正を逆移植し、7つの版（18.11.13 / 19.0.10 / 19.1.9 / 19.2.9 / 19.3.6 / 19.4.3 / 19.5.1）を一斉に公開した。 GitLab.com と条件を満たす Dedicated テナントは対処済みで、 **対応が残るのは自社で構築・運用している自己管理型インスタンスである。** 韓国の KISA は翌10月22日に国内の利用組織へ速やかな適用を求めた（報道による）

脆弱性初報のみ有名事象として記録（日本と直接の関係は薄い）設計・実装上の不備
初報: 2026年10月21日 最終更新: 2026年10月22日

CVSS は 10.0。認証も利用者の操作も要らず、当たるのは社内のソースコードと CI/CD を抱えた基盤です。

GitLab は現地時間2026年10月21日、定例のパッチリリースを公開しました（出典1）。修正されたのは12件の脆弱性で、そのうち最上位の CVE-2026-110264 はCVSS 10.0（Critical） です（出典1）。

原因は、正規表現をコンパイルするときに起きる整数オーバーフローです（出典1・2）。これを悪用すると、ログイン認証を経ていない外部の攻撃者がGitLab サーバ上で任意のコードを実行できます（出典1）。

影響範囲は CE（Community Edition）・EE（Enterprise Edition）の7.0 以降のすべての系列です（出典1）。GitLab は最新系列だけでなく、18.11・19.0・19.1・19.2 の旧系列にも修正を逆移植（バックポート）し、7つの版を一斉に公開しました（出典1）。

GitLab.com は適用済みで、Dedicated テナントのうち19.3.5-internal0・19.4.2-internal0 以降を動かしているものは追加の対処は不要です（出典2）。対応が残るのは、社内ネットワークや自社クラウドに直接導入して運用している自己管理型（Self-managed）インスタンスです（出典2）—— 管理者が自分で上げる以外に手がありません。

韓国の KISA は翌10月22日に、国内の利用企業・機関へ速やかなパッチ適用を求める公知を出しました（出典2）。日本の当局による本件の注意喚起は、本記録の作成時点では確認できていません〈齟齬2〉。

正規表現のコンパイルで整数があふれ、ログイン前の相手にサーバを渡す原因・手口

一次資料（出典1）が示している CVE-2026-110264 の内容は次のとおりである。

  • 題名は 「Integer Overflow issue in Regular Expression Compiler impacts GitLab CE/EE」（正規表現コンパイラにおける整数オーバーフローの問題。原文英語を本記録が訳した）。

  • CVSS 10.0（Critical）。ベクトルはネットワーク経由で、権限も利用者の操作も不要、機密性・完全性・可用性のいずれも High。

  • 一次資料の記述によれば、特定の条件下で「認証を経ていない利用者が GitLab サーバ上で任意のコードを実行できた可能性がある」（原文英語を本記録が訳した）。

  • 影響範囲は CE・EE の 7.0 以降、各系列の修正版より前のすべて。

  • 報告者は HackerOne 経由の研究者 joaxcar。

報道（出典2）はこれに原因の説明を足している—— 「特殊に細工した正規表現をコンパイルする際に発生する整数オーバーフロー」。

ここから先は本記録の評価である。この脆弱性が重いのは、スコアではなく位置である。 GitLab は、ソースコード・CI/CD の実行環境・デプロイ鍵・レジストリの資格情報を ひとまとめに抱える基盤である。 そこで「認証前に任意コード実行」が成立するということは、 開発資産とデプロイ経路の統制が丸ごと移るという意味になる。 侵入の起点になるだけでなく、そこから本番環境へ降りていく経路が すでに用意されている場所である（本記録の整理）。

なお、どの処理のどの経路で発火するかは公表されていない〈未確定1〉。 正規表現のコンパイルは、プロジェクト設定・Webhook のフィルタ・検索・ CI の条件式など多くの入口から呼ばれうるが、 本記録はどれが該当するかを推定しない。

7.0 以降の全系列が対象で、旧系列へ逆移植されたのはこの1件だけ被害規模・影響範囲

一次資料（出典1）の一覧から読み取れる構造は、次の2段である（整理は本記録）。

①CVE-2026-110264（CVSS 10.0）だけが、7つの版すべてに逆移植された。 対象は CE・EE の 7.0 以降で、修正は 18.11.13 / 19.0.10 / 19.1.9 / 19.2.9 / 19.3.6 / 19.4.3 / 19.5.1 に入っている。 GitLab が最新3系列だけで済ませず 18.11 系まで戻したこと自体が、 この1件の扱いの重さを示している（本記録の評価）。

  • CVE-2026-112212（CVSS 7.5・High） — OAuth / OIDC のディスカバリ端点におけるキャッシュ汚染。対象は CE・EE 18.3 以降。報道（出典2）は「認証なしの攻撃者が共有キャッシュを汚染し、正常な認証フローを外部のサーバへ誘導できる」としている。

  • CVE-2026-12664（CVSS 6.8） — GraphQL の work item のメールアドレス項目に対するアクセス制御の不備。対象は CE・EE 18.2 以降。

  • CVE-2026-16255（CVSS 5.9・EE のみ） — インスタンス全体のSAML / LDAP メンバーシップロックの強制が不完全で、許可されていないメンバー追加ができる。対象は EE 12.0 以降。

  • CVE-2026-105777（CVSS 4.3） — 内部向け応答ヘッダからの資格情報の露出。対象は CE・EE 17.6.5 以降。

  • 以下、CVE-2026-13319（4.3・グループマイルストーンAPI の認可バイパス）、CVE-2026-112378（4.3・AI Gateway の機能有効化ヘッダ）、CVE-2026-105711（3.5・MR タイトル描画のキャッシュ）、CVE-2026-14288（3.1・MR 承認ポリシーの強制）、CVE-2026-112326（3.1・security findings の例外時の後処理）、CVE-2026-103515（2.7・グループの Duo 管理ロックと Amazon Q 設定）。

SaaS は済んでいて、残っているのは自分で建てた分対策・注意喚起

報道（出典2）が伝える適用の区分は次のとおりである。

  • GitLab.com（クラウドサービス） — すでに適用済み。

  • Dedicated テナント — 19.3.5-internal0 および 19.4.2-internal0 以降を動かしているものは別途の措置は不要。

  • 自己管理型（Self-managed） — 企業内部網や自社クラウドに直接導入して運用しているインスタンスは、管理者が自分で最新版へ上げる必要がある。

  • 配布形態は Omnibus・ソースコード・Helm チャートのすべてが対象。

適用時の注意として、報道（出典2）は次の2点を挙げている。

  • 今回のパッチにはデータベースのマイグレーションが含まれる。単一ノード構成の環境は、アップグレードの途中でサービス停止が発生する。多ノード構成は標準の無停止アップグレード手順に従えば停止なしで反映できる。

  • 事前の悪用の試みを検知する手がかりとして、システム内のOnigmo ネイティブワーカーのクラッシュ記録、またはOrg モードの描画エラーの急増を確認する方法がある。

この最後の点は本記録として強調しておく（本記録の評価）。 一次資料（出典1）にこの検知の手がかりは見当たらず、 本記録は報道（出典2）の記述として扱う〈齟齬3〉。 ただし内容としては筋が通る——Onigmo は Ruby の正規表現エンジンであり、 整数オーバーフローを突く細工された正規表現がコンパイルされれば、 ネイティブ側のクラッシュとして痕跡が残りうる（本記録の読み）。 パッチを当てる前に、この痕跡を探しておくかどうかで、 「塞いだ」で終わるか「既に入られていたか」まで分かるかが変わる。

    取るべき行動 **単一ノード構成の GitLab について、停止枠を先に確保する （深夜・週末の数十分〜数時間）。** **マイグレーションの所要が読めない場合は、 本番と同じデータ量の複製で先に試す。** **多ノード構成であっても、無停止手順の前提（版の飛ばし方の制約）を 確認してから着手する**
  • GitLab 上の長期資格情報を減らし、本番への到達を切り離す
    **GitLab サーバ上で任意のコードが実行されるなら、 そこに保存された CI/CD 変数・デプロイ鍵・レジストリのトークンは そのまま攻撃者に渡る**（本記録の評価）。 **影響が「開発が止まる」で済むか「本番の統制が移る」になるかは、 鍵の寿命と保管場所で決まる**
    取るべき行動 **①GitLab の CI/CD 変数に入っている長期の資格情報を棚卸しし、 外部の秘密管理（Vault・クラウドの秘密管理）と短命トークン（OIDC 連携）に 置き換える、②本番への自動デプロイに承認を要する段を1つ入れる、 ③レジストリ・クラウドの権限を「GitLab が持つべき最小」に絞る。** **①から着手し、残ったものを一覧で管理する**
