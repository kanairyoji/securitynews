INC-2026-0665カプコン CAPCOM ID 1,177万件漏えい

カプコンの会員サービス「CAPCOM ID」が不正アクセスを受け、 全世界合計1,177万4,247アカウントのメールアドレスとログイン履歴が漏えい—— 43アカウントでは生年月日・性別・ニックネームまで、 196アカウントではログインパスワードが不正に変更されていた

不正アクセス・侵害初報のみ日本の組織が当事者公表されていない／不明
初報: 2026年10月22日 最終更新: 2026年10月23日

カプコンは2026年10月22日、会員サービス「CAPCOM ID」が第三者の不正アクセスを受け、全世界合計1,177万4,247アカウントの情報が漏えいしたと公表した（出典1）。漏えいしたのはメールアドレスと、アカウント作成日時・最終ログイン日時・ログイン回数・最終ログインIPアドレスといった識別情報である。このうち43アカウントでは生年月日・性別・国／地域・ニックネームも対象となり、196アカウントではログインパスワードが第三者によって不正に変更されていた（出典1）。クレジットカード情報は含まれていない。

経緯は3日に収まっている。10月19日に不審な痕跡を発見してアクセス元を遮断し、同日に不正アクセスを確認。20日に全社の対応本部を設置して漏えいとパスワードの不正変更を確認し、21日に警察と個人情報保護委員会へ報告、22日に公表した（出典1）。検知から公表まで3日という速さである。

一方で、侵入がいつ始まったのかは示されていない〈未確定2〉。攻撃手段も「特定済み」とされるだけで内容が無い〈未確定1〉。読者が自組織に当てはめるために要るのはこの2つだが、初報の段階では埋まっていない。

本件はカプコンにとって2度目の大規模事案である。 2020年11月のランサムウェア被害では米国子会社の旧型VPN機器が侵入口となり、最終的に個人情報1万5,649人分の流出が確認された（出典5・先行事例）。前回は「社内ネットワークの端」が入口で、今回は「全世界共通の会員基盤」が対象になっている（本記録の評価）—— 桁は1万5,649人から1,177万アカウントへ、3桁ちかく上がった。

発見から公表まで3日——だが「いつ入られたか」は空欄のままである発覚の端緒

カプコンの公表（出典1）が示す経緯は次のとおりである。

  • 2026年10月19日 — 社内システムで不正アクセスの痕跡を発見。同日中にアクセス元を遮断し、第三者による不正アクセスを確認。影響範囲の調査を開始した。

  • 2026年10月20日 — 全社の対応本部を設置。同日、CAPCOM ID の情報漏えいと、196アカウントでのログインパスワードの不正変更を確認。社外のセキュリティ監督委員会へ報告した。

  • 2026年10月21日 — 警察および個人情報保護委員会へ報告。

  • 2026年10月22日 — 公表。

ここから先は本記録の評価である。 1,177万件規模の事案で、検知から公表まで3日は速い。 当局報告は2日、対応本部の設置は翌日である。 「調査が終わるまで公表しない」という選択を採らなかった ——初報の時点で件数・項目・パスワード不正変更の件数まで出している。

一方で、この経緯には起点が無い。 「10月19日に痕跡を発見した」とあるが、 その痕跡がいつからのものかは書かれていない〈未確定2〉。 つまり侵入から検知までの期間（dwell）が算出できない。 本記録が response.metrics に dwell を置けなかったのはこのためである。

読者が自組織に当てはめるときに要るのは、まさにこの数字である（本記録の評価）—— 「3日で公表した」は広報の速さを示すが、 「何日気づかなかったか」は監視の実力を示す。 前者だけが公表されると、事案は「迅速な対応の事例」として読まれ、 後者から得られる教訓（自社の検知までの期間はどれだけか）が失われる。

1,177万件の中身は「メールアドレスとログイン履歴」である——それが軽いとは言えない被害規模・影響範囲

公表された範囲は次のとおりである（出典1）。

  • 全世界合計1,177万4,247アカウント — メールアドレスと、アカウント作成日時・最終ログイン日時・ログイン回数・最終ログインIPアドレスといったシステム上の識別情報。

  • うち43アカウント — 上記に加えて生年月日・性別・国／地域・ニックネーム。

  • うち196アカウント — ログインパスワードが第三者によって不正に変更。カプコンはパスワードをリセット済みとし、影響を調査中としている。ただし「お客様のパスワード自体が漏えいしたことは確認していない」とも述べている。

  • クレジットカード情報は含まれていない。

  • ゲームおよび CAPCOM ID で提供するサービスへの影響は無いとしている。

ここから先は本記録の評価である。 「メールアドレスとログイン履歴だけ」と読むのは早い。

第一に、最終ログインIPアドレスが含まれている。 これは利用者の接続元——多くの家庭では居住地域に対応する——の記録である。 メールアドレスと組み合わせると、 「このアドレスの持ち主は、この地域から、この頻度でゲームを遊んでいる」 という像が作れる（本記録の評価）。

第二に、ログイン回数と最終ログイン日時は、 フィッシングの説得力を作る材料になる（本記録の評価）—— 「最終ログインから○日経過しています」「ログイン回数が通常と異なります」 といった文面は、実際の数値を知っている側が書くと本物に近づく。

第三に、196アカウントのパスワード不正変更は、 「漏えい」とは別の性質を持つ（本記録の明示）—— これは乗っ取りが現に成立した記録である。 本記録が数値の測定対象を、 1,177万件は「流出の事実が確認された範囲」、 196件は「実際にアクセス・操作が確認された範囲」と 分けたのはこのためである。

43アカウントだけ項目が深いことも、読み流すべきではない〈未確定4〉。 全件が同じ項目なら「テーブルごと持ち出された」と読める。 43件だけ生年月日・性別・ニックネームまで届いているのは、 別の操作か別の経路があったことを示唆する（本記録の読み）—— ただしカプコンはこの差の理由を説明していない。

2020年のランサムウェアから6年——入口が「社内の端」から「会員基盤」へ移った背景・過去事例

カプコンにとって大規模な情報流出は2度目である。

2020年11月の事案（出典5・先行事例）はランサムウェア被害だった。 侵入口は米国子会社の旧型VPN機器で、 標準的なファイアウォールはあったが SOC のような24時間監視が無かったと 報じられている。 最終的に流出が確認された個人情報は1万5,649人分で、 同社は攻撃者との交渉を行わなかったとしている。

ここから先は本記録の評価である。 2つの事案は、桁も入口も違う。

  • 桁 — 1万5,649人 → 1,177万4,247アカウント。3桁ちかく上がっている。

  • 入口（2020年） — 社内ネットワークの端にある機器。ネットワークに入ってから、保存されていた書類・記録に到達した。

  • 対象（2026年） — 全世界共通の会員サービス基盤。1つの基盤に、全世界の利用者の識別情報が集まっている。

この差は、カプコン固有の話ではない（本記録の評価）—— 会員サービスを全世界共通の1基盤に寄せる設計は、 運用の効率と利用者の利便を上げる一方で、 1回の侵害で露出する母数を「全利用者」に固定する。 2020年の教訓（境界の機器を監視する）を実装しても、 2026年の構図（会員基盤そのものに到達される）は防げない。

見出しを presumed（「か」で閉じる性質の推定）としたのは、 カプコンが今回のリリースで2020年の事案に触れておらず、 2つを並べる読み方が本記録のものであるためである（本記録の明示）。

パスワードの「不正変更」とパスワードの「漏えい」は別である——196件の読み方評価・解釈

公表文（出典1）は2つのことを同時に述べている。

  • 196アカウントで、ログインパスワードが第三者によって不正に変更された。
  • お客様のパスワード自体が漏えいしたことは確認していない。

この2つは矛盾しない（本記録の明示）。 パスワードを変更するのに、変更前の値を知る必要は無い—— アカウントに対する操作権を得ていれば足りる。 逆に、パスワードが漏えいしていれば わざわざ変更する必要が無い（静かに使えるほうが有利である）。

ここから先は本記録の評価である。 196件という数が示しているのは「選別」である。 1,177万アカウントに到達していながら、 パスワードを変更したのは196件——1万分の1以下である。 全件に同じ操作をすれば即座に発覚するし、価値も薄い。 196件に絞っているのは、何らかの基準で「価値のあるアカウント」を 選んだことを示唆する（本記録の読み）—— ゲーム内資産、連携している決済手段、あるいは再利用されている メールアドレスの先にあるサービスである。

ただしカプコンは選別の基準を説明していない〈未確定4〉。 196件が何を基準に選ばれたかは、 同種の会員基盤を運用する組織にとって最も知りたい情報である（本記録の評価）—— 自社の「狙われる層」を特定できるためである。

なお「パスワードをリセット済み」という対応は、 変更されたアカウントの奪還としては正しいが、 196件の所有者が被った被害（変更されていた期間の操作）を 元に戻すものではない（本記録の明示）—— その期間に何が行われたかは「影響を調査中」とされている。

    **本件で漏えいしたのは「全世界合計1,177万4,247アカウント」である**（出典1）—— **地域別・サービス別の内訳ではなく、全世界合計で1つの数字が出た。** **同じ会社の2020年の事案では1万5,649人だった**（出典5）—— **入口は社内ネットワークの端で、到達した先は個別の記録だった。** **会員機能を1つの共通基盤へ寄せると、 運用の効率と利用者の利便は上がる一方で、 侵害1件あたりの露出母数が「全利用者」に固定される**（本記録の評価）
    取るべき行動 **自組織の会員・顧客基盤について、 「1つの環境が侵害されたときに露出する母数」を実数で出す。** **サービス別・地域別に分かれていると認識していても、 認証と会員情報が共通基盤に寄っていれば母数は全体である。** **出た数を経営会議の資料に載せ、 その母数を小さくする（分割・保持期間の短縮・項目の削減）か、 その母数のまま監視を厚くするかを明示的に決める**
  • 検知から公表までの速さは、侵入から検知までの遅さを隠す
    **本件は検知から公表まで3日、当局報告まで2日である**（出典1）—— **速い。** **しかし侵入の開始時期は公表されていない**〈未確定2〉—— **侵入から検知までの期間（dwell）が算出できない。** **報道も「19日に痕跡を発見し、22日に公表」という形で伝えている**（出典2）—— **この書き方では、事案は「迅速な対応の事例」として読まれる**（本記録の評価）。 **だが自組織の備えを点検するために要るのは、 「3日で公表できるか」ではなく「何日気づかずにいるか」である**
    取るべき行動 **自組織の公表の雛形に、 ①侵入の開始（または最も古い痕跡の時点）、②検知、③封じ込め、④公表 の4つの日付を書く欄を設ける。** **①が「調査中」であっても、そう書く欄を残す**—— **欄が無いと、埋まっている3つだけが並び、 最も重い1つが落ちたことが読者に見えない。** **社内の報告でも同じ4点を並べ、 ①→②の期間を監視投資の指標として追う**

  • 「1件ずつの参照」と「母数ごとの抽出」を同じ記録に混ぜない
    **本件では1,177万4,247アカウント分が漏えいしている**（出典1）—— **この規模の抽出は、利用者のログイン処理とは明確に形が違う**（本記録の評価）。 **両者を同じアクセス記録に並べると、 1,177万件の抽出1回は、毎日発生する数百万件のログインに埋もれる**—— **件数では見えず、形（単一の送信元からの連続した範囲参照）で見るしかない**
