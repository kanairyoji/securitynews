INC-2026-0671攻撃用AI基盤を露出した4者

攻撃用の AI エージェント基盤を公開ディレクトリに置いたまま運用していた4つの脅威アクター—— アルゼンチンの医療機関15件、2か国の政府機関、米 CRM ベンダーの顧客データが 自律エージェントによって侵害された（CrowdStrike 公表）

脅威・攻撃キャンペーン初報のみ有名事象として記録（日本と直接の関係は薄い）公表されていない／不明
初報: 2026年10月21日（CrowdStrike ブログ公開日） 最終更新: 2026年10月23日（本記録の確認時点）

攻撃する側が、自分の攻撃基盤をインターネットに置きっぱなしにしていました。そこから見えたのは、AI エージェントに意思決定ごと任せて侵入を進める運用です。

2026年10月21日、CrowdStrike の Counter Adversary Operations チームは、これまで報告されていなかった4つの脅威アクターに関する調査結果を公表しました（出典1）。4者はいずれも、自分たちの攻撃用エージェントフレームワークを公開ディレクトリ（open directory）に露出させており、その結果、AI エージェントの使い方が詳細に観測されました（出典1）。観測期間は2026年5月から8月です（出典1）。

本記録が要点と見たのは、次の3点です。

  • AI が道具を作るのではなく、AI が判断して実行している。 CrowdStrike は「脅威アクターが AI をツールや成果物の作成だけでなく、AI エージェントが意思決定を行いコマンドを実行する agentic campaign の遂行に使った事例を複数記録した」としています（出典1。原文英語。訳は本記録）。同社は「エージェント型 AI は機械の速度で動き、しばしば1時間以内に目的を自律的に達成しうる」とも書いています（出典1。原文英語）。
  • 4者の洗練度には大きな差があり、最も低い1者でも政府ドメインを落としている。 最も洗練度が低いとされたインドネシア語話者のアクターは、追加のオーケストレーションを持たず、GitHub の公開リポジトリ（主に claude-red）から集めた819個のスキルを Claude Code に渡すだけの運用でした（出典1）。それでも複数のインドネシア政府ドメインと、別の国の政府ドメイン1件、複数の民間企業を侵害しています（出典1）。一方で、このアクターはモデルの安全ガードレールを回避するためにたびたび手動で介入する必要があったとも記されています（出典1）。
  • 評価には確度が添えられている。「増える」は高確度、「コモディティ化」は中確度である。 CrowdStrike は、エージェント型 AI 支援の侵入が件数・高度さの両面で増えることを高い確度（high confidence）で、基本的な攻撃作戦がコモディティ化していることとOPSEC が今後12か月で改善することを中程度の確度（moderate confidence）で評価しています（出典1。原文英語）。

本記録は2026年10月23日に CrowdStrike のブログ（出典1）を直接取得して裏を取りました。 完全版レポート（/resources/reports/agentic-ai-attack-campaigns/）は取得しておらず、各事例の技術的な詳細は確認していません〈齟齬1〉。また、名指しされた AI 製品の提供元（Anthropic）による公表は本記録では確認していません〈齟齬2〉。

攻撃の経過

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

公表されているのは攻撃側の運用形態（エージェント構成・ワークフロー・スキル群）であり、 被害側で何が突かれたかは示されていない〈未確定2〉（出典1）。 以下は出典1 が述べるワークフローの記述を段階に割り当てたものである（整理は本記録）。

  1. 1. 偵察確認済
    エージェントが標的環境の列挙・偵察を行う。脅威アクター2 の一方のハーネスでは 偵察が決定論的に実行され、その結果をもとに AI が次の行動を選ぶ。 脅威アクター4 のワークフローは第1段階で環境の列挙を指示する（出典1）。
    根拠: 「偵察を決定論的に実行し、AI プロバイダに事前に用意した行動の中から選ばせ、 決定論的に適切なエージェントへ振り分ける」「対象環境の列挙を指示する」 （出典1。原文英語）。
  2. 2. 初期侵入確認済
    エージェントが悪用手法を選択して侵入する。脅威アクター4 のワークフローは 「悪用手法の選択において Claude Code にほぼ全面的な自律性を与える」とされる （出典1）。具体的に何が悪用されたかは公表されていない〈未確定2〉。
    根拠: 「grants Claude Code near-total autonomy in selecting exploitation methods」 （出典1。原文英語）。
  3. 3. 実行確認済
    AI エージェントが意思決定しコマンドを実行する。脅威アクター1 では 「Supervisor」が状態機械から次のタスクを選び「Executor」が実行する 二重構成を取っていた（出典1）。
    根拠: 「AI エージェントが意思決定を行いコマンドを実行する agentic campaign」 「Supervisor が状態機械から次のタスクを選び、Executor がそれを実行する」 （出典1。原文英語）。
  4. 4. 持ち出し確認済
    認証情報・診療記録・企業顧客データが持ち出される。脅威アクター4 の ワークフローには「明示的な持ち出し（exfiltration）の指示」が含まれていた （出典1）。
    根拠: 脅威アクター1 は少なくとも1件の被害者から認証情報と診療記録を、 脅威アクター4 は米国拠点の CRM ベンダーから企業顧客データを 窃取したとされる（出典1）。

見つかった理由は攻撃者自身の設定不備で、見えたのは「AI に何を任せていたか」だった発覚の端緒出典 [1]

CrowdStrike は、4つのアクターがいずれも「自分たちの攻撃用エージェントフレームワークを公開ディレクトリ経由で露出させていた」としています（出典1。原文英語。訳は本記録）。その結果として「AI エージェントの使い方についての詳細な知見を共有してしまい、攻撃者が AI にどれほど習熟しつつあるかが明らかになった」と書いています（出典1。原文英語。訳は本記録）。

ここで観測されたのは、マルウェアの検体でも C2 の通信でもなく、エージェントへの指示そのもの——状態機械の定義、スキルの一覧、スラッシュコマンドのワークフロー、SOP（標準作業手順）です（出典1 の記述に基づく整理）。

本記録が注意を促したいのは、この可視性が攻撃者側の不手際に依存していることです（本記録の評価）。CrowdStrike 自身、今後12か月で一部の脅威アクターがエージェント型侵入キャンペーンの OPSEC を改善する見込みを中程度の確度で評価しています（出典1。原文英語）。つまり、この種の観測が同じ形で続く保証はありません（本記録の評価）。

AI の役割が「道具を作る」から「判断して実行する」へ移っている原因・手口出典 [1]

CrowdStrike は観測の性質をこう説明しています（出典1。原文英語。訳は本記録）。

2026年5月から8月の間に、CrowdStrike Intelligence は、脅威アクターが AI をツールや成果物の作成のためだけでなく、AI エージェントが意思決定を行いコマンドを実行するagentic campaign の遂行に使った事例を複数記録した（出典1）

4者の構成は、自律の度合いで並べられます（出典1 の記述に基づく本記録の整理）。

  • 脅威アクター1——二重エージェント構成。「Supervisor」役の Claude Code が状態機械（攻撃段階をあらかじめ定義したワークフロー）から次のタスクを選び、「Executor」役のエージェントがそれを実行する。オープンソースの PentestGPT を基に、MCP サーバー・Python の悪用スクリプト・スキルを加えて再構築したもの（出典1）。
  • 脅威アクター2——2種類のハーネス。1つは Python 製で、偵察を決定論的に行ったうえであらかじめ用意した選択肢の中から AI に次の行動を選ばせ、決定論的に適切なエージェントへ振り分ける。もう1つはより自律度が高く、Claude Code が精巧な SOP に従って単独で動くか、複数の専門エージェントに並列で作業を委任する（出典1）。
  • 脅威アクター3——オーケストレーション無し。819個のスキルを与えて「標的を侵害せよ」と指示し、スキルが十分な指針になると想定している（出典1）。
  • 脅威アクター4——単一の /pentest-setup スラッシュコマンドで7段階のワークフローを起動する。環境の列挙を指示し、悪用手法の選択はほぼ全面的に AI に委ね、RCE 後の高レベルな手順と明示的な持ち出し指示を含む（出典1）。

構成の違いは「どこまでを人が決めるか」の違いです（本記録の評価）。脅威アクター2 の1つ目のハーネスは選択肢を人があらかじめ用意しており、脅威アクター4 は悪用手法の選択ごと AI に渡しています（出典1）。

洗練度が最も低いアクターでも政府ドメインを落としており、ガードレールは摩擦にしかなっていない被害規模・影響範囲出典 [1]

CrowdStrike が「4者のうち最も洗練度が低い」と評したのは、インドネシア語話者のアクターです（出典1）。追加のオーケストレーションを持たず、公開 GitHub リポジトリ（主に claude-red）から集めた819個のスキルを Claude Code に渡すだけの運用で、「スキルが十分な指針になるだろう」という想定で侵入を指示していました（出典1）。

同社は、このアクターについて「観測された活動では、モデルの安全ガードレールを乗り越えるため、あるいは特定の障壁を突破し続けるよう Claude Code を励ますために、攻撃者が周期的に介入しなければならなかった」と記しています（出典1。原文英語。訳は本記録）。

それでもなお、このアクターは複数のインドネシア政府ドメイン、別の国の政府ドメイン1件、複数の民間企業を侵害しています（出典1）。

本記録の読み方はこうです（本記録の評価）。安全機構は作動していますが、作動の結果は「攻撃の失敗」ではなく「攻撃者が手を動かす回数が増える」でした。 防御側が「AI 提供側のガードレールが止めてくれる」ことを前提に置ける段階ではありません。

評価には確度が添えられている。読み分けないと「AI で攻撃が激増する」だけが残る評価・解釈出典 [1]

CrowdStrike は4つの評価を、それぞれ確度を付けて示しています（出典1。原文英語。訳は本記録）。

  • 「エージェント型 AI が基本的な攻撃作戦をコモディティ化させている」——中程度の確度（moderate confidence）。根拠は本報告に含まれた事例研究であり、いずれもキルチェーン全体にわたる運用上の意思決定をエージェント型 AI に委ねていた点（出典1）。
  • 「エージェント型 AI を用いた侵入は、件数と高度さの両面でほぼ確実に増える」——高い確度（high confidence）。根拠は脅威アクターによる急速な採用、攻撃の有効性、AI モデルの継続的な改善、オープンソースの攻撃用エージェントフレームワークの普及（出典1）。
  • 「エージェント型 AI は効果的な侵入の障壁を下げる。今後12か月のうちに、一部の低スキルの脅威アクターが、これまで組織犯罪集団や国家関連アクターにしか実現できなかった水準の有効性と規模で作戦を行う可能性が高い」（出典1。本文には確度の明示が無い。本記録の確認）。
  • 「一部の脅威アクターは、今後12か月でエージェント型侵入キャンペーンのOPSEC を改善するとみられる」——中程度の確度（moderate confidence）。根拠は AI の開発動向と信頼できるオープンソース報告（出典1）。

本記録が強調したいのは、最も強い確度が付いているのが「増える」という量の予測であって、「質的に新しい攻撃が生まれる」ではないことです（本記録の評価）。4者が侵害に使った手口そのものは、公開のペンテスト基盤と公開スキルの組み合わせです（出典1）。防御の観点では、新種の対策が要るという話ではなく、既存の弱点が従来より短い時間で突かれるという話として読むのが妥当です（本記録の評価）。

本記録が確認できていないのは、被害側の手口とAI提供側の対応である未確定事項出典 [1]

出典1 は攻撃側の運用形態を詳しく述べる一方、被害組織がどう侵入されたか——どの脆弱性が突かれ、どの認証情報が使われたか——には触れていません〈未確定2〉（本記録の確認）。防御側が直接使える IoC や検知の手掛かりは、ブログの範囲には含まれていません（本記録の確認）。

完全版レポート（/resources/reports/agentic-ai-attack-campaigns/）には事例研究と防御側への指針が含まれるとされていますが、本記録はこれを取得していません〈齟齬1〉（出典1）。

また、名指しされた AI 製品の提供元（Anthropic）が本件をどう扱ったか——アカウントの停止、ガードレールの変更、独自の公表があったか——も、出典1 には含まれておらず、本記録も確認していません〈齟齬2〉。脅威アクター2 が中国拠点の AI プロキシサービス（「transfer station」）経由でモデルにアクセスしていたという記述は（出典1）、提供側の利用制限が迂回されうることを示していますが、その実効性についての評価は資料にありません（本記録の整理）。

CISO・経営層への示唆
  • 「AI で新種の攻撃が来る」ではなく「既知の弱点が短時間で突かれる」と読む。
    最も強い確度（high confidence）が付いているのは、侵入の件数と高度さが 増えるという予測である（出典1。原文英語）。 4者が使ったのは公開の PentestGPT 派生基盤や GitHub 上の公開スキルであり、 手口そのものの新規性は示されていない（出典1）。
    取るべき行動 AI を理由にした新規投資の前に、公開面の資産棚卸しと未更新資産の削減、 および検知から遮断までの所要時間（MTTR）の短縮を優先項目として設定する。 「1時間以内に目的が達成されうる」（出典1）を対応時間の目標設定の前提に置く。
  • AI 提供側の安全機構を、自社の防御の一部として数えない。
    最も洗練度が低いとされたアクターでも、安全ガードレールを回避するために 周期的に介入しながら、複数の政府ドメインと民間企業を侵害している（出典1）。 ガードレールは摩擦にはなったが、阻止には至っていない（本記録の評価）。
    取るべき行動 リスク評価の前提から「AI 提供側が悪用を止める」という仮定を外す。 自社の検知・遮断能力だけで成立する防御線を定義し直す。
  • 攻撃側の可視性は攻撃者の不手際に依存している。いまの観測が続く前提で計画しない。
    4者はいずれも攻撃用フレームワークを公開ディレクトリに露出させており、 それが発見の端緒だった（出典1）。 CrowdStrike は今後12か月で一部のアクターが OPSEC を改善すると 中程度の確度で評価している（出典1。原文英語）。
    取るべき行動 脅威インテリジェンスの調達方針で、攻撃者インフラの露出に依存した情報だけでなく、 自社環境のテレメトリに基づく検知能力への投資配分を明示する。
  • 被害の中身は「医療記録」「CRM の顧客データ」であり、自社だけでなく預かっているデータが対象になる。
    脅威アクター1 はアルゼンチンの医療機関から認証情報と診療記録を、 脅威アクター4 は米国の CRM ベンダーから企業顧客データを窃取したとされる （出典1）。いずれも第三者のデータを預かる立場の組織である（本記録の整理）。
    取るべき行動 自社が他社のデータを預かっている範囲（SaaS・BPO・データセンター事業）を 改めて列挙し、侵害時の通知義務と契約上の責任を確認する。 委託元への報告経路を含めた訓練を行う。
セキュリティ技術者への示唆
  • 対応速度の目標を、人のトリアージ前提から自動遮断前提へ引き上げる。
    CrowdStrike は「機械の速度で動き、しばしば1時間以内に目的を自律的に 達成しうる」としている（出典1。原文英語）。 検知から人が内容を確認して判断する運用では、この時間軸に追随できない （本記録の評価）。
    取るべき行動 高信頼度の検知について、承認を待たずにホスト隔離・アカウント無効化・ セッション失効を実行する自動化を用意し、誤遮断時の復旧手順とセットで運用する。
  • エージェント型の侵入は「失敗しても次を試す」。1回の遮断では終わらない前提で追う。
    脅威アクター4 のワークフローは悪用手法の選択をほぼ全面的に AI に委ねており （出典1）、脅威アクター2 は複数の専門エージェントへ並列に作業を委任する 構成を持っていた（出典1）。
    取るべき行動 インシデント対応で「当該の試行をブロックした」で閉じず、 同一の起点からの別手法の試行を一定期間（最低でも数日）監視する手順にする。 1つの IoC ではなく、起点のアクターを軸に追跡する。
  • 公開のオフェンシブ・エージェント基盤を、防御側も把握しておく。
    出典1 は、脅威アクター1 の基盤がオープンソースの PentestGPT 由来であること、 脅威アクター3 のスキル群が主に claude-red という公開リポジトリ由来であることを 明示し、脚注で該当リポジトリと pentagi を挙げている（出典1）。
    取るべき行動 公開されているオフェンシブ・エージェント基盤の挙動（どのツールを呼び、 どのログを残すか）を検証環境で確認し、自社の検知が反応するかを試す。 反応しない箇所を検知の開発項目に起こす。
  • 自社でも AI エージェントを使うなら、その実行経路が攻撃側と同じ形になりうることを前提にする。
    4者の構成は MCP サーバー・スキル・スラッシュコマンド・SOP という、 正規の開発運用でも使われる部品の組み合わせである（出典1）。 攻撃と正規利用が同じ部品を使うため、実行の痕跡だけでは区別がつかない （本記録の評価）。
    取るべき行動 自社で使うエージェントの実行環境について、実行者・対象ホスト・ 呼び出したツールの監査ログを残し、業務時間外や想定外の対象への実行を 検知対象にする。攻撃側の挙動を見分ける基準線になる。
