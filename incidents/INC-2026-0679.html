INC-2026-0679チケット当選装うフィッシング急増

「チケット抽選に当選した」と装うフィッシングが国内で急増——イープラスをかたる報告が 1か月で85件から552件へ約6.5倍。ローソンチケット・チケットぴあも同時にかたられ、 支払いリンクは AWS のクラウドURLに置かれていた

詐欺の手口初報のみ日本の組織が当事者認証情報の悪用（使い回し・推測可能・窃取）
初報: 2026年10月23日（本記録の起点となった報道。注意喚起は10月2日から出ている） 最終更新: 2026年10月24日（本記録の作成・確認時点）

「【イープラス】チケット抽選結果のご案内［ご当選］」—— 当選を知らせて支払いを急がせるフィッシングメールが、2026年10月に国内で急増した（出典2）。 ITmedia NEWS がフィッシング対策協議会に取材した集計では、 イープラスをかたる報告は2026年9月19日からの1週間で85件だったのに対し、 10月10日からの1週間では552件と約6.5倍に増えた。 チケットぴあは毎週110〜160件台で推移し、ローソンをかたる報告も10月10日からの1週間で65件に達した。 支払い用のリンク先はイープラスの公式ドメインではなく Amazon Web Services の クラウドサービスの URL に置かれていた。 総務省の委託で迷惑メールの相談を受け付ける迷惑メール相談センターは、 10月13日から19日までの1週間で、3社をかたる偽メールを10件以上掲載している。 ローソンエンタテインメントは10月2日に注意喚起を公開し、主な事例を9種類に整理した。 フィッシング対策協議会は「偽メールは基本的には見分けられない」として、 見分ける努力ではなくメール・SMS のリンクを開かない運用を勧めている。 被害の件数・金額は公表されていない。

攻撃の経過

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

**技術的な侵入は行われていない。** 正規のチケット販売事業者を装ったメール・SMS で偽サイトへ誘導し、 ID・パスワード・個人情報・決済情報を入力させる手口である（出典2）。 **特徴は2点。** ①文面が4類型（当選・未払い・再認証・決済情報の更新）に分かれており、 反応する感情を変えて同じ標的層を狙える。 ②**誘導先が AWS のクラウドサービスの URL に置かれており、 ドメインの見た目で怪しさを判定しにくい**（出典2）。

  1. 1. 偵察推定[2]
    攻撃者が、かたるブランドを選定する。 **フィッシング対策協議会は「昨今の攻撃者は名乗る企業を短期間で次々に 切り替えており、詐取の成功率やメールの到達率で選んでいるのではないか」 との見方を示している**（出典2）。 あわせて、年末に向けてイベントが増える時節柄の影響も指摘されている。
    根拠: 「昨今の攻撃者は名乗る企業を短期間で次々に切り替えており、 詐取の成功率やメールの到達率で選んでいるのではないか、との見方」（出典2）。
  2. 2. 初期侵入確認済[1] [2]
    「当選した」「利用料が未払い」「再認証が必要」「決済情報を更新してほしい」 といった文面のメール・SMS を送信する（出典2）。 **送信元が事業者のドメインになりすましている場合がある**（出典1・2）。
    根拠: 「送信元が同社のドメインになりすましている場合もあるため、 本文とリンク先のURLも確認するよう求めている」（出典2）。
  3. 3. 実行確認済[2]
    **利用者がメール本文のリンクを開き、偽サイトへ到達する。** 報じられた例では、支払い用のリンク先が**イープラスの公式ドメインではなく AWS のクラウドサービスの URL** だった（出典2）。 文面は当日午後9時までの支払いを求めるもので、**期限で急かす形になっている。**
    根拠: 「支払い用のリンク先はイープラスの公式ドメインではなく、 米Amazon Web Services（AWS）のクラウドサービスのURLになっている」（出典2）。
  4. 4. 収集確認済[2]
    偽サイトで ID・パスワード・個人情報を入力させる（出典2）。 **支払いを求める類型では決済情報の入力が想定される** 〈本記録の推定。入力項目の一覧は公表されていない〉。
    根拠: 「手口は基本的に、偽サイトへ誘導してIDやパスワード、個人情報を 盗み取るものだという」（出典2）。
  5. 5. 影響（暗号化・破壊・改ざん）推定[2]
    **窃取された情報の悪用。** 報道は、入力してしまった場合の対処として パスワード変更、クレジットカードの利用停止と再発行、 身に覚えのない利用や登録情報の書き換えの確認を挙げている（出典2）。 **実際の被害件数・被害額は公表されていない**〈未確定〉。
    根拠: 「万一、偽サイトに情報を入力してしまった場合は、すぐにパスワードを変え、 クレジットカードは利用停止と再発行の手続きを取る」（出典2）。

「当選した」という文面は、支払いを急がせる口実として機能する原因・手口出典 [1] [2]

報じられた偽メールの中身は、こうである（出典2）。

「【イープラス】チケット抽選結果のご案内［ご当選］」

プレオーダーの抽選で当選しチケットを確保済みだとして、同日午後9時までの支払いを求める内容だった。支払い用のリンク先はイープラスの公式ドメインではなく、米 Amazon Web Services（AWS）のクラウドサービスの URL だった（出典2）。

この文面が効く理由は、嘘が巧妙だからではない。チケットの抽選は、当選したら期限内に支払わなければ権利が失効する—— 正規の仕組みがもともと「急いで払わせる」形をしている（本記録の評価）。攻撃者は新しい不安を作る必要がなく、利用者が既に持っている「払い忘れたら取られてしまう」という感覚に乗るだけでよい。

類型は当選装いだけではない（出典2）。ローチケを装うメールは「【ローチケ】抽選先行予約 当選結果のお知らせ」という件名で、テーマパークのペア招待に当選したとしてシステム利用料などを支払わせる内容だった。ほかに、チケットぴあやローチケの名前で「抽選エントリー料が未払い」と迫るもの、3社のアカウントの再認証や決済情報の更新を求めるものも確認されている。

4つの類型が並んでいることに意味がある（本記録の評価）。当選（喜び）・未払い（焦り）・再認証（手続きの義務感）・決済情報の更新（維持の必要）—— どの感情に反応する利用者も取り込める構えになっている。 1つの文面がすり抜けなくても、別の文面が当たる。

手口の技術的な中身は、報道の説明では「偽サイトへ誘導してIDやパスワード、個人情報を盗み取るもの」という基本形である（出典2）。多要素認証の突破（AiTM 等）に言及した記述は無い〈未確定〉。

イープラスは3週間で6.5倍、チケットぴあは高止まり——同じ波ではない被害規模・影響範囲出典 [2]

フィッシング対策協議会が示した直近6週間の動向は、ブランドごとに形が違う（出典2）。

イープラス 2026年9月19日からの週 85件 → 10月10日からの週 552件（約6.5倍）
チケットぴあ 毎週 110〜160件台で推移
ローソン 10月10日からの週 65件

イープラスは急増、チケットぴあは高止まりである。チケットぴあは増えていないが、もともと週100件を超える水準が続いている。つまり本件は「イープラスが新たに狙われた」事象であり、チケット販売サービス全体が以前から継続して標的になっているという背景の上に起きている（本記録の評価）。

協議会は、増加の背景について2つの見方を示している（出典2）。①年末に向けてイベントが増える時期との「時節柄の影響」。②昨今の攻撃者は名乗る企業を短期間で次々に切り替えており、詐取の成功率やメールの到達率で選んでいるのではないか。

②は、防御側の見方を変える指摘である（本記録の評価）。かたられるブランドが「狙われやすい業種」で決まるのではなく、攻撃者が成功率と到達率を見て回しているのなら、自社ブランドがかたられるかどうかは自社の属性ではなく攻撃者の都合で決まる。 今かたられていないことは、安全の根拠にならない。

なお、協議会は「フィッシング全体に占める割合は少ないものの、増加の傾向は見て取れる」としている（出典2）。チケット関連が国内フィッシングの主流になったという話ではない。

「基本的には見分けられない」——協議会が見分け方の普及を勧めない理由対策・注意喚起出典 [2]

偽メールをどう見分けるかを問われた協議会の回答は、「基本的には見分けられない」だった（出典2）。

理由はこう説明されている（出典2）。見分ける方法が全くないわけではないが、スマートフォンの普及で利用者の層が広がった今、細かな見分け方を広めても全員が実践できるわけではなく、かえって危うい。

この立場は、注意喚起の定番と正面から食い違う（本記録の評価）。「送信元アドレスを確認する」「リンク先のドメインを確かめる」——こうした指導は長年行われてきたが、本件ではローソンエンタテインメント自身が「送信元が同社のドメインになりすましている場合もある」と認めている（出典2）。送信元の表示が本物に見えることがあるなら、送信元を見る指導は、見た人に誤った安心を与えうる。

協議会が代わりに勧めるのは、判断しない運用である（出典2）。

  • メールや SMS のリンクをそもそも開かない
  • 手続きが必要なら、公式のスマートフォンアプリかブックマークからアクセスする
  • BIMI（正規メールの送信元に企業のロゴを表示する仕組み）に対応したメールサービスを使えば、本物のメールを見た目で判断しやすくなる

構造として優れているのは、最初の2つである（本記録の評価）。「リンクを開かない」は、偽物を見分ける能力を前提にしない。当選通知が本物であれば、アプリかブックマークから入っても同じ手続きができる。偽物であれば、入口に辿り着けない。見分ける力の個人差に依存しないという点で、組織の指導としても再現性がある。

万一入力してしまった場合の手順も示されている（出典2）。すぐにパスワードを変え、クレジットカードは利用停止と再発行の手続きを取る。身に覚えのない利用や登録情報の書き換えがないかもすぐに確認する。一方、住所や電話番号といった個人情報は、どう悪用されるかその場では分からず、被害に遭って初めて気付くこともあるため、その場合は警察などの捜査機関に相談する。

かたられた3社の対応は、公表の有無も内容も揃っていない波及・関係先出典 [1] [2] [3]

3社の対応状況は、報じられた範囲では次のとおりである（出典2）。

ローソンエンタテインメント（ローソンチケット） 2026年10月2日に注意喚起を公開。主な事例を9種類に整理し、当選を装うもの、利用料の未払いを理由に支払いを求めるもの、当選チケットの取り消しを告げて手続きを急がせるものなどを挙げている。送信元が同社のドメインになりすましている場合もあるため、本文とリンク先の URL も確認するよう求めている（出典1・2）。

ぴあ（チケットぴあ） ITmedia NEWS の取材に対し、同社をかたる偽メールの存在を把握していると回答。利用者から真偽を尋ねる問い合わせはあるものの、被害の連絡は受けていない。対策として、チケットぴあのサイトで注意喚起のお知らせを随時更新し、返信やリンク先へのアクセスをしないよう案内している（出典2）。

イープラス 報道に同社の対応についての記述は無く、本記録も本件に関する同社の注意喚起を確認できなかった〈探索したが発見できず〉。報告件数が最も急増したブランドでありながら、一次情報としての注意喚起を確認できないという状態である（本記録の確認）。

3社の差は、利用者の立場から見ると実害になる（本記録の評価）。届いたメールの真偽を確かめようとして公式サイトを見たとき、注意喚起が出ている会社とそうでない会社がある。出ていなければ、利用者は「まだ知られていない新しい手口かもしれない」と考える余地が残る。注意喚起は、被害を防ぐ道具であると同時に、利用者が自力で真偽を判定するための参照点でもある。

誘導先がクラウドのURLだったことは、ドメインを見る対策の限界を示している評価・解釈出典 [2]

報道が具体的に記しているのは、支払い用のリンク先が「イープラスの公式ドメインではなく、米 Amazon Web Services（AWS）のクラウドサービスの URL」だったという点である（出典2）。

これは2つのことを意味する（本記録の評価）。

第一に、ドメインが「怪しく見えない」。タイポスクワッティング（eplus に似せた綴り）ではなく、誰もが知っている事業者のクラウドサービスのドメインである。「公式ドメインかどうか確認する」という指導は、利用者が正規ドメインを記憶していることを前提にしている。チケット販売各社の正規ドメインを正確に覚えている利用者は多くない。見慣れた大手クラウドのドメインが出てきたとき、それが「正規ではない」と判断できる根拠を一般の利用者は持たない。

第二に、ブロックしにくい。大手クラウドのドメインはサブドメイン単位で無数の正規サイトが同居しており、組織のプロキシやフィルタでドメインごと遮断する運用は取りにくい（本記録の評価）。遮断するなら URL 単位になり、個別のテイクダウンやフィード更新の速さに依存する。

ここから、協議会の「リンクを開かない」という指導の合理性が裏付けられる（本記録の評価）。誘導先の見た目を手がかりにする対策は、攻撃者が誘導先を正規のクラウド上に置いた時点で効きが落ちる。 一方、「アプリかブックマークから入る」という運用は、誘導先がどこに置かれていても成立する。

組織の立場では、もう一段の読み替えができる（本記録の評価）。従業員が受け取るこの種のメールは、業務システムではなく私的な利用に関わるため注意喚起の対象から外れやすい。しかし入力されるのは ID とパスワードであり、使い回しがあれば業務側の資産に届く。チケット販売サイトのフィッシングは、「業務外のサービスで盗まれた認証情報が、業務側のリスクになる」経路の具体例として社内教育に使える。

    取るべき行動 **「自社ブランドがかたられたときの初動」を、起きる前に決めておく。** 誰が検知を受け、誰が公表を判断し、どのページに何を書くか。 ローソンエンタテインメントのように**手口の類型を整理して出せる状態**を 平時に作る（出典1・2）。
  • **注意喚起の公表は、被害防止だけでなく「利用者が真偽を判定する参照点」になる。**
    本件で注意喚起を公開しているのはローソンエンタテインメントとぴあで、 **報告件数が最も急増したイープラスについては本記録が注意喚起を確認できなかった** （出典2・本記録の探索）。 **参照点が無ければ、利用者は公式サイトを見ても判断できない。**
    取るべき行動 **自社サイトに「なりすましメールに関するお知らせ」の常設枠を用意し、 確認中でも「調査中である」と書ける運用にする。** 公表を「確定してから」にすると、急増期に間に合わない。
  • **業務外サービスのフィッシングは、認証情報の使い回しを通じて業務側のリスクになる。**
    本件で盗まれるのは ID とパスワードである（出典2）。 **チケット販売サイトは私的利用であり、社内の注意喚起の対象から外れやすいが、 同じパスワードが業務システムに使われていれば経路がつながる**（本記録の評価）。
    取るべき行動 社内教育の題材に、**業務システムではなく身近な私的サービスのフィッシング**を使う。 あわせて、業務側の認証を**パスワード単独で通らない構成**にする （フィッシング耐性のある多要素認証）。使い回しの有無を監査できない前提で設計する。
  • **「報告件数が増えた」は「被害が増えた」と同じではない。経営への説明で混ぜない。**
    本件の数値はすべて**協議会への報告件数**であり、被害の集計ではない（出典2）。 **注意喚起や話題化によって報告率自体が上がる**（本記録の評価）。 ぴあは「被害の連絡は受けていない」と回答している（出典2）。
    取るべき行動 経営報告やリスク評価で外部の件数を引くときは、 **「何を数えた件数か」を1行添える運用にする**（報告／検知／被害の別）。 自社の指標でも同じ区別を保つ。
セキュリティ技術者への示唆
  • **誘導先が大手クラウドの URL に置かれると、ドメイン単位の遮断が使えない。**
    報じられた例では、支払い用リンクが**イープラスの公式ドメインではなく AWS のクラウドサービスの URL** だった（出典2）。 **大手クラウドのドメインには無数の正規サイトが同居しており、 まとめて遮断する運用は取れない**（本記録の評価）。
    取るべき行動 プロキシ・メールフィルタの方針を見直し、 **「ドメイン評価で止める」前提から「URL 単位の評価＋ 到達後の入力を防ぐ」前提へ**重心を移す。 クラウドストレージ系ドメイン上の HTML への直接アクセスを 業務上不要なら制限する、という設定は検討の余地がある。
  • **送信元ドメインの確認を利用者に求める指導は、本件では成立しない。**
    ローソンエンタテインメント自身が **「送信元が同社のドメインになりすましている場合もある」**と注意喚起している（出典1・2）。 協議会も「基本的には見分けられない」と述べている（出典2）。
    取るべき行動 社内の注意喚起文から**「送信元アドレスを確認しましょう」を単独の対策として外す。** 代わりに**「リンクを開かず、アプリかブックマークから入る」**を主の指示にする。 見分け方は補助情報として残すにとどめる。
  • **自社ドメインのなりすましは、DMARC の厳格化でしか止まらない。**
    なりすまし送信が成立しているなら、受信側で拒否できる設定が効いていない 可能性がある（本記録の評価）。 **3社の DMARC 設定状況は公表されていない**〈未確定〉。
    取るべき行動 自社の全送信ドメイン（サブドメイン・非送信用も含む）について、 **SPF／DKIM の整合と DMARC ポリシーを確認する。** 非送信ドメインには `p=reject` と空の SPF を設定する。 レポートを受け取り、正規送信の取りこぼしが無いことを確認してから厳格化する。
  • **BIMI は「本物を示す」仕組みであり、「偽物を止める」仕組みではない。**
    協議会は BIMI 対応のメールサービスを使えば 「本物のメールを見た目で判断しやすくなる」と説明している（出典2）。 **ロゴが無いことは偽物の証明にはならない**（本記録の評価）。
    取るべき行動 自社が送信側なら BIMI 対応（DMARC 強制＋VMC）を検討する。 社内説明では**「ロゴがあれば本物／無ければ不明」**と、 非対称であることを明記する。
