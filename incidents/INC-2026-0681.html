INC-2026-0681ArubaOS に72件・満点8件

HPE の無線LAN向けOS「ArubaOS」に 72 件の脆弱性—— **うち 33 件がクリティカル、8 件は CVSS 3.1 基本値が満点の 10.0** で、 いずれも認証不要・利用者の操作不要・攻撃条件が容易、かつスコープ変更を伴う。 対象はモビリティコンダクタ・コントローラ・ゲートウェイ・アクセスポイントで、 公表時点で悪用も実証コードも確認されていない（HPESBNW05162）

脆弱性初報のみ日本に波及した海外事案設計・実装上の不備
初報: 2026年10月22日（HPE のアドバイザリ公開日・米国時間） 最終更新: 2026年10月24日（本記録の確認時点）

「満点」が 8 件同時に出るのは、脆弱性情報としてはかなり珍しい形です。

2026年10月22日（米国時間）、Hewlett Packard Enterprise はセキュリティアドバイザリ HPESBNW05162 を公開し、無線LAN向けOS「ArubaOS（AOS-10 / AOS-8）」の 72 件の脆弱性を明らかにしました（出典1）。本記録が一次公表のCVE表を数えたところ、CVSS 3.1 基本値 9.0 以上（クリティカル）が 33 件、そのうち 8 件が満点の 10.0 でした（出典1。本記録の算出）—— この 33 件という数は、国内報道の「クリティカルが33件」と一致します（出典3）。

満点 8 件のベクタはすべて同じです（出典1）。

CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:C ＋ 機密性・完全性への「高」影響

読み下すと——ネットワーク越しに（AV:N）、容易な条件で（AC:L）、権限を持たず（PR:N）、利用者に何もさせずに（UI:N）成立し、影響が脆弱な部品の外へ出る（S:C）、ということです（本記録の整理）。

本記録が要点と見たのは、次の3点です。

  • 「管理画面を出していなければ安全」とは言い切れない。 HPE が示した回避策は、CLI と Web 管理インターフェースを専用のL2 セグメント／VLAN に閉じ、L3 以上ではファイアウォールで制御することです（出典1）。一方で、満点 8 件のうち 2 件は PAPI プロトコルの不備であり、PAPI は管理画面ではなく機器間の通信路です（出典1。本記録の整理）—— 「Web 管理画面を閉じた」だけでは、同じ対策範囲に入らない可能性があります（本記録の評価）。
  • 対象が「機器」ではなく「OS」なので、台数が効く。 影響を受けるのはモビリティコンダクタ、モビリティコントローラ、HPE Networking Central が管理するモビリティゲートウェイ、AOS-10 のアクセスポイント、AOS-8 の Instant AP です（出典1）—— アクセスポイントが含まれるため、更新対象は数百台・数千台の規模になりえます（本記録の評価）。
  • 保守期限切れの版は「影響あり」として扱われる。 HPE は End of Maintenance を過ぎた版を「影響を受けると推定する」とし、End of Support を過ぎた版については評価自体を行っていないため「影響を受ける可能性があるものとして扱うべき」としています（出典1）—— 古い機器は、アドバイザリの修正版一覧に自分の系列が載っていないことがあります。

  • 悪用の有無公表されていない
    **HPE は「公開日時点で、公開の議論や実証コードは把握していない」としている**（出典1・4）—— **これは「悪用されていない」の確認ではなく、「把握していない」という表明である** （本記録の整理）。 **本記録も悪用を示す公開情報を確認していない**（本記録の確認）。 **CISA の KEV にも満点 8 件は収載されていない**（出典6）。
  • 各脆弱性の技術的な詳細と前提条件意図的に非開示
    **アドバイザリの CVE 説明は1行の要約にとどまり、 到達経路・必要なポート・前提となる構成は書かれていない**（出典1。本記録の確認）。 **満点 8 件についても、たとえば CVE-2026-79845 が 「PAPI プロトコルの認証バイパス」であること以上の記述は無い**（出典1）。 **これは修正版の普及前に詳細を出さないという一般的な判断と読めるが、 理由の明示は無い**（本記録の整理）。
  • 影響を受ける機器の台数・利用組織の数公表されていない
    **一次公表にも報道にも、影響台数・組織数の記載は無い**（出典1・3・4。本記録の確認）。 **BleepingComputer は HPE 全体の規模として 「従業員6万1,000人超、法人顧客5万5,000社超、 Fortune 500 の90%」を挙げているが、 これは本件の影響範囲を示す数字ではない**（出典4。本記録の明示）。
  • 脆弱性が存在していた期間（いつから入っていたか）公表されていない
    **アドバイザリは「影響を受ける版」と「修正版」を示すだけで、 いつ混入したかには触れていない**（出典1。本記録の確認）。 **AOS-8.10 系が対象に含まれることから相当に古くから 存在した脆弱性が含まれる可能性はあるが、裏付けは無い**（本記録の推測）。
  • 侵害の有無を確かめる方法（痕跡・ログの見方）公表されていない
    **アドバイザリには、悪用されたかどうかを利用組織が確認する手順・ 残る痕跡・見るべきログの記載が無い**（出典1。本記録の確認）。 **示されているのは修正版への更新と、管理インターフェースの セグメント分離・ファイアウォール制御・利用操作の記録という 予防的な措置だけである**（出典1）。
  • 保守期限切れの版に該当する具体的なバージョン公表されていない
    **「End of Maintenance を過ぎた版は影響を受けると推定する」 「End of Support を過ぎた版は評価していないので 影響を受ける可能性があるものとして扱うべき」とあるが、 どの版がそれに当たるかの一覧はアドバイザリ内に無い**（出典1。本記録の確認）。

攻撃の経過

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。
  1. 1. 偵察
    **インターネットまたは到達可能なネットワークから、 ArubaOS の管理インターフェース（CLI／Web UI）や PAPI の待ち受けを見つける**（本記録の整理）。 **一次公表は満点 8 件を `AV:N`（ネットワーク）と評価しており、 到達できることが前提である**（出典1）。 **具体的なポート・指紋・探索手法は公表されていない**〈未確定2〉—— **アドバイザリに記載があるのは、PAPI に関連する1件（CVE-2026-79860）で 「UDP 8211 番」という記述だけである**（出典1）。
  2. 2. 初期侵入
    **満点 8 件のいずれかを使い、認証を経ずに侵入する**（出典1）。 **一次公表が示す成立条件は `PR:N`（権限不要）・`UI:N`（利用者の操作不要）・ `AC:L`（攻撃条件が容易）である**（出典1）。 **手口の型は4つに分かれる**—— **認証バイパス（CVE-2026-79844・79845・79850）、 コマンドインジェクション（CVE-2026-79846）、 SQL インジェクション（CVE-2026-79848・79849）、 バッファオーバーフロー（CVE-2026-79847・79851）**（出典1・4）。 **個々の脆弱性の具体的な到達経路・リクエストの形は公表されていない**〈未確定2〉。
  3. 3. 実行
    **機器上で任意のコードが実行される**（出典1）。 **CVE-2026-79850 については「認証バイパスからの root としての RCE」と 明記されている**（出典1）—— **機器上で最上位の権限が取られる形である。** **実行後に攻撃者が何をするか（永続化・横展開・収集）については、 本件は実際の侵害事例ではないため公表資料が存在しない**（本記録の明示）。
  4. 4. 影響（暗号化・破壊・改ざん）
    **満点 8 件は機密性・完全性への影響が「高」と評価され、 `S:C`（スコープ変更）が付いている**（出典1）—— **影響が脆弱な部品の権限範囲を越えて及ぶ、という評価である**（本記録の整理）。 **CERT-FR はリスクとして 「データの完全性への侵害」「データの機密性への侵害」 「セキュリティポリシーの回避」「遠隔のサービス拒否」 「任意コードの遠隔実行」「SSRF」「XSS」「SQLi」「権限昇格」を挙げている**（出典2）。 **実際の被害事例は公表されていない**〈未確定1〉。

満点 8 件はすべて同じベクタで、「条件が整えば」ではなく「条件が無い」原因・手口

CVSS が 10.0 になるのは、評価軸が全部いちばん悪い側に倒れたときです（本記録の整理）。一次公表によると、満点 8 件のベクタはすべて同一です（出典1）。

CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:C（機密性・完全性への影響は「高」）

記号 値 意味
AV:N Network ネットワーク越しに届く
AC:L Low 特別な準備・待ちが要らない
PR:N None 権限を持っていなくてよい
UI:N None 利用者に何もさせなくてよい
S:C Changed 影響が脆弱な部品の外へ出る

つまり、攻撃の成立に「条件」がほぼありません（本記録の整理）—— 届くこと以外に要るものが無い、という評価です。

CVE-2026-79850 だけは「root として」と明記されています（出典1）—— 機器の上で最上位の権限を取られる、という意味です。

PAPI は管理画面ではない——「Web UI を閉じた」が同じ対策にならない理由対策・注意喚起

HPE が示した回避策は、管理面の封じ込めです（出典1）。

「To minimize the likelihood of an attacker exploiting these vulnerabilities, HPE Networking recommends that the CLI and web-based management interfaces be restricted to a dedicated layer 2 segment/VLAN and/or controlled by firewall policies at layer 3 and above along with accounting controls for tracking and logging user activities and resource usage」（出典1）

（攻撃者がこれらの脆弱性を悪用する可能性を最小化するため、HPE Networking はCLI および Web ベースの管理インターフェースを専用の L2 セグメント／VLAN に限定すること、および／または L3 以上でファイアウォールポリシーにより制御すること、あわせて利用者の操作とリソース使用を追跡・記録するアカウンティング制御を行うことを推奨する／原文英語）

ここで注意が要るのは、満点 8 件のうち CVE-2026-79845 が「PAPI プロトコルの認証バイパス」である点です（出典1）。PAPI は Aruba 機器どうしが管理情報をやり取りする通信路で、管理者が開く Web UI や CLI とは別のものです（本記録の整理）。

一次公表のCVE表を見ると、PAPI を明示している脆弱性は満点以外にも多数あります（出典1）—— たとえば CVE-2026-79860 は「PAPI の UDP 8211 番経由で下位サービスにバッファオーバーフロー」（CVSS 9.8）とされています。

したがって、実務上は2つを分けて考える必要があります（本記録の評価）。

  • CLI／Web UI の閉じ込め — HPE が明示した回避策。これは効く範囲が書かれている
  • PAPI の到達範囲 — 回避策の文面に PAPI は出てこない。機器間通信のセグメントに誰が届くかは、別に確認が要る

本記録は「Web 管理画面を閉じてあるので回避策は適用済み」と判断するのは早い、と評価します（本記録の評価）—— ただし HPE が PAPI について何を推奨しているかはアドバイザリに書かれていません〈未確定2〉。回避策はあくまで緩和であり、修正版への更新の代わりにはなりません（出典1）。

更新対象は「コントローラ数台」で終わらない——アクセスポイントが含まれる被害規模・影響範囲

影響を受ける製品は、一次公表に列挙されています（出典1）。

  • Mobility Conductors（モビリティコンダクタ）
  • Mobility Controllers（モビリティコントローラ）
  • Mobility Gateways（HPE Networking Central が管理するもの）
  • AOS-10 Access Points（AOS-AP）
  • AOS-8 Instant Access Points（AOS-IAP）

修正版は 5 系列について示されています（出典1）。

系列 影響を受ける版 修正版
AOS-10.8.x.x 10.8.1.1 以下 10.8.1.2 以降
AOS-10.7.x.x 10.7.2.6 以下 10.7.2.7 以降
AOS-10.4.x.x 10.4.1.13 以下 10.4.1.14 以降

ファームウェアは HPE Networking Support Portal（https://networkingsupport.hpe.com ）から入手するよう案内されています（出典1）。

ここで実務上きいてくるのは、アクセスポイントが対象に入っていることです（本記録の評価）。コントローラだけなら数台〜十数台の作業ですが、アクセスポイントはフロアごと・部屋ごとに置かれており、組織によっては数百台から数千台になります。

さらに、保守期限を過ぎた版の扱いが明示されています（出典1）。

  • End of Maintenance を過ぎた版 — 「影響を受けると推定する」（修正版は示されない）
  • End of Support を過ぎた版 — 「評価していないので、影響を受ける可能性があるものとして扱うべき」

つまり、上の表に自分の系列が載っていないことは「対象外」を意味しません（本記録の評価）—— 古い機器が残っている組織ほど、表だけを見ると安心してしまう構図です。 どの版が期限切れに当たるかの一覧は、アドバイザリには載っていません〈未確定6〉。

「悪用は確認していない」は時点の表明であり、安全の証明ではない未確定事項

一次公表はこう書いています（出典1・4）。

「HPE Networking is not aware of any public discussion or exploit code that targets the listed vulnerabilities as of the release date of this advisory」

（本アドバイザリの公開日時点で、掲載した脆弱性を狙う公開の議論や実証コードは把握していない／原文英語）

これは3つの限定が付いた文です（本記録の整理）。

  • 「as of the release date」 — 2026年10月22日時点の話である
  • 「public」 — 公開されているものの話であり、非公開の悪用は対象外
  • 「is not aware」 — 「無い」ではなく「把握していない」

本記録が2026年10月24日に CISA の KEV カタログ（版 2026.10.23・収載1,756件）を取得して検索したところ、満点 8 件（CVE-2026-79844〜79851）はいずれも収載されていませんでした（出典6。本記録の確認）。

ただし、KEV に無いことは悪用が無いことの証明にはなりません（本記録の明示）—— KEV は「悪用が確認された」ものを載せる台帳であり、確認されるまでは載りません。

一方で、本件には優先度を上げるべき条件がそろっています（本記録の評価）。

  • 満点 8 件が同時に出ており、攻撃者側の関心を集めやすい
  • 対象が境界に近い機器（無線LANのコントローラ・AP）である
  • 修正版が公開されたことで、差分から脆弱性を特定する作業が可能になる

本記録は、公開から実証コードが出るまでの期間について具体的な予測は示しません（本記録の明示）—— 過去事例の統計を本記録では確認していないためです〈齟齬3〉。

CERT-FR の勧告は2つのアドバイザリを束ねている——ClearPass の2件は別事案関係が否定された事象

CERT-FR の CERTFR-2026-AVI-1369 を読むとき、注意が要る点があります（本記録の注意喚起）。

この勧告が参照している HPE のアドバイザリは2本です（出典2）。

  • HPESBNW05162（2026年10月22日） — 本件。ArubaOS の 72 件
  • HPESBNW05171（2026年10月22日） — ClearPass Policy Manager の2件

そのため CERT-FR の「影響を受けるシステム」一覧には、AOS の各系列に加えて ClearPass Policy Manager 6.11.x／6.14.x が並びます（出典2）。

本記録が HPESBNW05171 を直接取得して確認したところ、こちらは別の事案でした（出典5。本記録の確認）。

  • 表題は「Multiple "PHP2Shell" Vulnerabilities identified in PHP allow for Unauthenticated Remote Code Execution」
  • CVE-2026-109618（CVSS 3.1 で 9.8）と CVE-2026-109619（同 9.8）の2件
  • 原因は ClearPass が同梱する PHP 側にあり、ArubaOS の実装不備ではない
  • 対象は ClearPass 6.14.1 以下および 6.11.16 以下で、それぞれに Hotfix Patch が出ている
  • 回避策として、更新まで「ゲストポータルと管理インターフェースを公開から外すことを検討する」と書かれている

したがって、CERT-FR の CVE 一覧にある CVE-2026-109618 とCVE-2026-109619 の2件は、本記録の対象（ArubaOS の 72 件）には含まれません（本記録の明示）〈齟齬1〉。72 ＋ 2 ＝ 74 件を「ArubaOS の脆弱性」として数えないようにしてください。

対応の評価

評価材料がない判断は「評価材料なし」としています。結果論で断じないための区分です。
対応の巧拙を評価できる材料が公表資料から得られていません。
CISO・経営層への示唆
  • **「満点が8件」は件数の話ではなく、優先度の切り替えを求める合図である。**
    **満点 8 件のベクタはすべて `AV:N/AC:L/PR:N/UI:N/S:C` であり、 成立に前提条件がほぼ無い**（出典1）。 **通常の脆弱性管理は「評点の高いものから順に」で回るが、 本件は評点の上限に8件が同時に並んでおり、順番を付ける意味が薄い** （本記録の評価）。 **さらに対象がアクセスポイントを含むため、 作業量が「数台」ではなく「数百台」の桁になる組織がある**（出典1。本記録の評価）—— **通常のパッチ適用の枠では日程が収まらない可能性が高い。**
    取るべき行動 **ArubaOS を使っているなら、通常の脆弱性管理の枠から外し、 別立ての作業として日程と体制を決める。** **まず台数（コントローラ／ゲートウェイ／AP）とバージョンを棚卸しし、 更新にかかる時間と無線が止まる時間帯を見積もる。** **更新が今週中に終わらない場合は、 HPE の回避策（管理面のセグメント分離）を先に実施する。**
  • **保守期限切れの機器は、アドバイザリの表に載らないまま影響を受ける。**
    **HPE は保守期限（EoM）を過ぎた版を「影響を受けると推定する」とし、 サポート期限（EoS）を過ぎた版は評価自体を行っていない**（出典1）。 **修正版の表に自分の系列が無いことは、対象外を意味しない**（本記録の評価）—— **むしろ「修正が出ない」という、より悪い状態である。** **どの版が期限切れに当たるかの一覧はアドバイザリに無い**〈未確定6〉。
    取るべき行動 **ネットワーク機器の資産台帳に、保守期限・サポート期限の欄を設ける。** **期限を過ぎた機器について「更改するか、隔離するか、 リスクを受容するか」を事前に決めておき、 アドバイザリが出るたびに判断し直さずに済む形にする。**
  • **「悪用は確認していない」で優先度を下げない。時点の表明にすぎない。**
    **HPE の文面は「as of the release date」「public」「is not aware」の 3つの限定が付いている**（出典1。本記録の整理）。 **本記録が確認した時点（2026年10月24日）でも CISA の KEV には収載されていないが、 KEV は悪用が確認されてから載る台帳であり、不在は安全の根拠にならない** （出典6。本記録の明示）。 **修正版が公開されたことで、差分から脆弱性を特定する作業が可能になる** （本記録の評価）。
    取るべき行動 **脆弱性対応の優先度判断で「KEV 収載」「実証コードの公開」を 必要条件にしない運用に改める。** **境界に近い機器で未認証 RCE が出た場合は、 悪用の報告を待たずに動く基準をあらかじめ決めておく。**
  • **無線LAN基盤は「情報システム」ではなく「設備」として管理されていることがある。**
    **対象にアクセスポイントが含まれるため、更新作業はフロア・拠点ごとの 物理的な範囲に及ぶ**（出典1。本記録の評価）。 **組織によっては、無線LANの機器更新が総務・施設部門の所管になっており、 セキュリティ部門の脆弱性管理の対象台帳に載っていないことがある** （本記録の評価）—— **その場合、アドバイザリが出ても誰にも届かない。**
    取るべき行動 **無線LANのコントローラとアクセスポイントが、 自組織の脆弱性管理の対象台帳に載っているかを確認する。** **載っていなければ、所管部門と連絡経路を決めてから台帳に追加する。**
セキュリティ技術者への示唆
  • **PAPI は Web UI でも CLI でもない。回避策の適用範囲を確認すること。**
    **HPE の回避策は「CLI と Web ベースの管理インターフェース」を 対象に書かれている**（出典1）。 **一方、満点 8 件のうち CVE-2026-79845 は 「PAPI プロトコルの認証バイパス」であり、 満点以外でも PAPI を明示した脆弱性が多数ある （たとえば CVE-2026-79860 は PAPI の UDP 8211 番経由）**（出典1）。 **PAPI は Aruba 機器どうしの管理通信路であり、 管理者が開く画面とは別のものである**（本記録の整理）—— **「Web UI を閉じた」が同じ対策にならない可能性がある**（本記録の評価）。
    取るべき行動 **コントローラ・ゲートウェイ・AP 間の通信（PAPI を含む）が どのセグメントを通り、どこから到達できるかを図に起こす。** **管理セグメントの外から PAPI に届く経路があれば、 ファイアウォールで閉じる。** **HPE が PAPI について何を推奨しているかはアドバイザリに 書かれていないため、必要なら HPE に直接確認する。**
  • **未認証で成立する脆弱性では、認証ログに痕跡が残らないことを前提に検知を組む。**
    **満点 8 件は `PR:N`（権限不要）であり、 攻撃者はログインを試みない**（出典1）—— **認証失敗の急増を見る仕組みでは捉えられない**（本記録の推測）。 **一次公表には、侵害の有無を確認する手順・残る痕跡の記載が無い** （出典1。本記録の確認）〈未確定5〉。
    取るべき行動 **管理インターフェースおよび PAPI への到達記録を、 機器の外（syslog／SIEM）へ送っているかを確認する。** **機器上で root を取られた場合、機器内のログは信用できないため、 外へ出した記録だけが証拠になる。** **あわせて、機器の再起動・設定変更・ファームウェア変更の履歴を 外部の構成管理と突き合わせる仕組みを用意する。**
  • **AOS-10 へ移行済みでも対象である。系列の新しさは安全の根拠にならない。**
    **満点 8 件の内訳は AOS-10 が 4 件、AOS-8 が 4 件で偏っていない** （出典1。本記録の算出）。 **影響を受ける系列も AOS-10.8／10.7／10.4 と AOS-8.13／8.10 の 両方にまたがる**（出典1）。
    取るべき行動 **資産台帳のバージョンを、系列（AOS-10 / AOS-8）ではなく パッチ版（10.8.1.1 等）まで記録する。** **更新の完了判定を「新しい系列にしたこと」ではなく 「アドバイザリが示す修正版以上であること」で行う。**
  • **CERT-FR の CVE 一覧をそのまま使わない。別事案の2件が混ざっている。**
    **CERTFR-2026-AVI-1369 は HPESBNW05162（ArubaOS の 72 件）と HPESBNW05171（ClearPass の PHP2Shell 2件）を1つの勧告にまとめている** （出典2・5。本記録の確認）。 **そのため CVE 一覧に CVE-2026-109618／109619 が含まれ、 影響を受けるシステムにも ClearPass Policy Manager が並ぶ**（出典2）。 **対応のチケットを CVE 一覧から機械的に起こすと、 ArubaOS を使っていない ClearPass の担当にも作業が飛ぶ、 あるいは逆に ClearPass の対応が ArubaOS の作業に埋もれる**（本記録の評価）。
    取るべき行動 **対応の根拠はベンダのアドバイザリ単位（HPESBNW05162 / HPESBNW05171）で分ける。** **ClearPass を使っているなら、Hotfix Patch（6.14.1 / 6.11.16）の適用を 別のチケットとして立てる。**
