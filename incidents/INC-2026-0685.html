INC-2026-0685Chocolatey偽装SEO汚染でArmorsteal

Zscaler ThreatLabz は2026年10月22日、Chocolatey（Windows のパッケージ管理ツール）と Microsoft Activation Scripts（MAS）を装った偽サイトを検索結果の上位に押し上げ、 表示した PowerShell コマンドを利用者自身に実行させて Python 製の新種マルウェア「Armorsteal」を配る SEO 汚染キャンペーンを公表した—— **侵入口は脆弱性ではなく「インストール手順をコピーして貼る」という日常の作業**である。 **Armorsteal は Python 3.11 ランタイムごと `C:\Windows\SystemHealth\Update\` に展開され、 遠隔操作・監視・情報窃取の3部品に分かれる。** **遠隔操作部品は C2 から受け取った Python コードを RSA-2048 の署名検証に通してから メモリ上で実行し、Pyarmor 9.1.7（試用版）でバイトコードと文字列を暗号化している。** **監視部品はキー入力・クリップボード（0.5秒ごと）・画面を取り、 コピーされた暗号資産のアドレスを攻撃者のアドレスに差し替え、 Exodus・MetaMask・Phantom を装う偽の取引通知を出す。** **窃取部品は Discord クライアント22種のトークン、ブラウザのウォレット拡張と デスクトップ版21種、A:〜Z: ドライブを走査した BIP39 のシードフレーズ、 保存済みパスワード、SSH 鍵、Steam のセッションを集める。** **検体は ipinfo[.]io で自分の接続元の組織名を調べ、Google・Amazon・Microsoft・Azure に 当たると「メモリが不足しています」という偽の表示を出して終了する**—— **クラウド上の解析環境を避けるための作りである。** **偽 Massgrave サイトは2026年9月25日、偽 Chocolatey サイトは10月1日ごろに停止した。** **被害組織数・被害者数・被害の地域はいずれも公表されていない。**

脅威・攻撃キャンペーン初報のみ有名事象として記録（日本と直接の関係は薄い）人を介した誘導（ビッシング・BEC）
初報: 2026年10月22日（Zscaler ThreatLabz ブログ公開日） 最終更新: 2026年10月24日（本記録の確認時点）

狙われたのは脆弱性ではなく、「公式の手順をコピーして貼る」という作業です。

2026年10月22日、Zscaler ThreatLabz は、Chocolatey（Windows のパッケージ管理ツール）とMicrosoft Activation Scripts（MAS）の偽サイトを検索結果の上位に押し上げ、Python 製の新種マルウェア「Armorsteal」を配るキャンペーンを公表しました（出典1）。同社が活動を把握したのは2026年9月です（出典1）。

経路はこうです（出典1）。

  • 「install Chocolatey」「Chocolatey PowerShell」などで検索した利用者が、choclatey[.]org（本物は chocolatey.org）というタイポスクワット（綴り間違いを狙ったドメイン）のサイトに到達する
  • 「Microsoft Activation Scripts」「MAS activation script」「Massgrave activation」で検索した利用者は massgravel[.]net に到達する
  • どちらのサイトも、インストール用と称する PowerShell のコマンドを表示する
  • 実行すると install.ps1 が遠隔操作部品をダウンロードして設置する
  • 偽 Chocolatey サイトの install.ps1 は、そのあと本物の Chocolatey インストーラも走らせる——利用者から見ると Chocolatey は正常に動く

この最後の1点が、本事案でもっとも実務に効く部分です（本記録の評価）。「入れたはずのものが入っていない」という形の違和感が、意図的に消されています。

設置されるものは、マルウェアの実行ファイルではなく環境一式です（出典1）。ZIP が C:\Windows\SystemHealth\Update\ に展開され—— Windows のシステムディレクトリに見える名前です——中身は Python 3.11 のランタイム、Pyarmor のランタイム、そして Armorsteal の Python スクリプトです（出典1）。永続化は2つのスケジュールタスクで、SysCheck2 が利用者のログオン時に最高権限で、SysCheckX がシステム起動の45秒後に SYSTEM として遠隔操作部品を起動します（出典1）。

部品は3つに分かれています（出典1）。

  • 遠隔操作（SysMon.py）——ホスト名・OS・CPU・メモリ・ディスク・ローカルIP・公開IP・ネットワークインタフェースを集め、マザーボードのシリアル番号から機体識別子を作る。HTTPS で4つの C2 ドメイン候補の生存を確認してから通信し、60秒ごとに「この機体向けの指示」と「全感染機体共通の指示」を取りに行く。受け取った Python コードは RSA-2048 の公開鍵で署名を検証したうえでメモリ上で実行する
  • 監視（basrq.py）——キー入力を記録し（英語・フランス語・スペイン語・ドイツ語向けの処理を持つ）、アクティブウィンドウの題名を併せて記録し、クリップボードを0.5秒ごとに監視する。コピーされた暗号資産のアドレスを攻撃者のアドレスに差し替え、設定したキーワードが窓の題名やキー入力に現れると画面を撮り、Exodus・MetaMask・Phantom を装う偽の取引通知を出す
  • 窃取（got.py）——Discord クライアント22種のトークン、ブラウザのウォレット拡張とデスクトップ版の計21種、A: から Z: までのドライブを走査した BIP39 のシードフレーズ、ブラウザの Cookie（Chrome DevTools Protocol の 9222 番ポート経由）、保存済みパスワード・自動入力・クレジットカードの属性情報、KeePass・1Password・RoboForm・Password Safe・Enpass・Bitwarden・Dashlane、SSH 鍵、Steam のセッションを集める

解析を避ける作りも入っています（出典1）。遠隔操作部品は ipinfo[.]io で自分の公開IPと組織名を調べ、組織名が Google・Amazon・Microsoft・Azure に当たると「メモリが不足しています」という偽の表示を出して終了します—— クラウド上のサンドボックスでは動かないようにするための仕掛けです。 Python のコードは Pyarmor 9.1.7（試用版）で保護されています（出典1）。試用版が使われているのは、商用ライセンスを買わずに難読化だけを得られるためだと同社は評しています（出典1）。

侵入口は脆弱性ではなく「公式の手順をコピーして貼る」作業だった原因・手口出典 [1]

本件で突かれたのは、ソフトウェアの欠陥ではありません（出典1。整理は本記録）。Chocolatey も MAS も、導入手順が「PowerShell に1行を貼って実行する」形で案内される種類の道具です。 攻撃側は、その作業の手前——検索結果——に割り込みました（出典1）。

到達先は綴りを1文字ずらしたドメインです（出典1）。

  • choclatey[.]org（本物は chocolatey.org）——「install Chocolatey」「Chocolatey PowerShell」等で検索した利用者向け
  • massgravel[.]net——「Microsoft Activation Scripts」「MAS activation script」「Massgrave activation」等で検索した利用者向け

どちらのサイトも、インストール用と称する PowerShell のコマンドを表示します（出典1）。実行すると install.ps1 が走り、昇格した権限を要求し、PowerShell のコンソール窓を隠し、ZIP を C:\Windows\SystemHealth\Update\ にダウンロードします（出典1）。この置き場は Windows のシステムディレクトリに見えるよう選ばれています（出典1）。

そして偽 Chocolatey サイトの install.ps1 は、本物の Chocolatey インストーラも続けて実行します（出典1）。その結果、Chocolatey は期待どおりに動きます（出典1）。

ここが本事案でもっとも実務に効く点です（本記録の評価）。「入れたはずのものが動かない」という違和感は、利用者が自力で気づく最後の手掛かりでした。 攻撃側はそれを塞いでいます。 したがって、この経路に対して「利用者の注意」を主たる防御線に置くことはできません（本記録の評価）。

配られたのは実行ファイルではなく Python 環境一式で、難読化は試用版のツールだった被害規模・影響範囲出典 [1]

展開される ZIP の中身は、Python 3.11 のランタイム、Pyarmor のランタイム、そして Armorsteal の Python スクリプトです（出典1）。つまり被害端末には、攻撃者が任意の Python コードを動かせる環境が丸ごと置かれます（本記録の整理）。

永続化は2つのスケジュールタスクです（出典1）。

タスク名 起動の契機 内容
SysCheck2 利用者のログオン 利用可能な最高権限で遠隔操作部品を起動
SysCheckX システム起動 45秒の遅延のあと SYSTEM として起動

名前は「システムの点検」に見えるよう付けられています（本記録の評価）。45秒の遅延は、起動直後の監視・保護の立ち上がりを避ける形です（本記録の推定）〈齟齬3〉。

難読化には Pyarmor 9.1.7 の試用版が使われています（出典1）。Pyarmor は Python のバイトコードと文字列定数を暗号化し、静的な解析と検知を難しくします（出典1）。Zscaler は、試用版が使われている理由を「商用ライセンスを買わずに難読化だけが得られるため、運用上は好都合である」と評しています（出典1。原文英語。訳は本記録）。

防御側にとっての意味はこうです（本記録の評価）。「商用の難読化ツールを買う資力」は、この種の攻撃者の障壁になっていません。 検体の難読化の質から運用者の規模を推し量ることはできません。

解析環境の判定にクラウド事業者名を使い、受け取る指示には署名を要求している評価・解釈出典 [1]

遠隔操作部品は、自分が解析環境にいるかをipinfo[.]io への照会で判定します（出典1）。公開IPと組織名を取り、組織名が Google・Amazon・Microsoft・Azure といったクラウド事業者に当たると、「メモリが不足しています」という偽の表示を出して終了します（出典1）。

これが効くのは、自動解析の多くがクラウド上で動いているからです（本記録の整理）。逆に言えば、オンプレミスの解析環境や、出口IPが事業者名に結びつかない環境では作動しません（本記録の評価）。

もう一方の作りは、受け取る指示の側に向いています（出典1）。

  • 指示は2経路——機体別（/get-onetime-code/{machine_id}）と全機体共通（/get-global）
  • どちらも RSA-2048 の公開鍵（検体に埋め込み）で署名を検証してからメモリ上で実行する。検証は独自実装の RSASSA-PKCS1-v1_5
  • 指示の中に埋め込まれた版番号（ONETIME_VERSION / GLOBAL_VERSION）を作業ディレクトリのファイル（onetime_version.txt / global_version.txt）と比べ、大きいときだけ実行する
  • 自己更新も共通指示で行い、新しい SysMon.py の SHA256 を検証してから差し替える

本記録の読み方はこうです（本記録の評価）。署名検証と版番号の管理は、研究者が C2 を模倣して検体を操ることを防ぎ、同時に「古い指示が再実行される」運用事故も防いでいます。 つまりこれは、攻撃側の運用品質を上げるための設計です—— 解析の妨害だけが目的ではありません。 防御側から見ると、C2 を押さえても検体を無害化する指示は送り込めない、ということになります（本記録の評価）。

窃取の対象は暗号資産と、技術者が持つ鍵とパスワードに向いている被害規模・影響範囲出典 [1]

窃取部品（got.py）が集めるものは、大きく2つの層に分かれます（出典1 の列挙に基づく本記録の整理）。

1つは暗号資産です（出典1）。

  • ブラウザのウォレット拡張とデスクトップ版の計21種のデータ
  • A: から Z: までのドライブを走査して見つけた BIP39 のシードフレーズ
  • 監視部品によるクリップボードのアドレス差し替え（0.5秒ごと）
  • Exodus・MetaMask・Phantom を装う偽の取引通知

もう1つは、組織の中に入るための鍵です（出典1）。

  • ブラウザの Cookie（Chrome DevTools Protocol の 9222 番ポート経由で取得）
  • 保存済みパスワード・自動入力・クレジットカードの属性情報（復号には Chrome App-Bound Encryption Decryption プロジェクトの公開ツール chrome-decryptor をダウンロードして使う）
  • パスワードマネージャ——KeePass・1Password・RoboForm・Password Safe・Enpass・Bitwarden・Dashlane
  • SSH 鍵
  • Discord クライアント22種のトークン（有効性を検証する）
  • Steam のセッション

後者の意味を強調します（本記録の評価）。SSH 鍵とパスワードマネージャとブラウザの Cookie が同時に取られるのは、「個人の金銭被害」で終わらない構えです。 Chocolatey と MAS を検索する人は、多くの場合、業務で Windows を触る技術者です（本記録の推定）〈齟齬3〉。その端末に SSH 鍵と保存済み認証情報があるなら、この1件の感染は組織への初期侵入の材料になります。

なお Cookie の取得に DevTools Protocol の 9222 番ポートを使う点は、検知の手掛かりになります（本記録の整理）—— 正規の業務でブラウザをリモートデバッグ用に起動することは稀です。

本記録が確認できていないのは、規模と帰属、そして IoC の悪性である未確定事項出典 [1]

出典1 は攻撃の仕組みを詳しく述べる一方、規模を示す数値を一つも示していません〈未確定1〉（本記録の確認）。感染台数・被害者数・被害額・標的の地域が、いずれも書かれていません。 「新種のマルウェアが見つかった」という事実と「どれだけ広がったか」は別の問いであり、後者には答えが無い状態です（本記録の明示）。

帰属についても踏み込まれていません〈未確定2〉（出典1）。Zscaler がまとめているのは「2つのおとりが単一のオペレーションである」までで、誰かという問いには触れていません。

本記録は、出典1 が公表した IoC（SHA256 10件・ドメイン7件・IP 5件）の悪性を検証していません〈齟齬1〉。照合先のテレメトリを持たないためです。 したがってこれらを検知ルールに直接投入することは、本記録の情報だけでは勧められません（本記録の方針）。

また、装われた側——Chocolatey と Massgrave プロジェクト——が本件についてどう公表・対応したかも確認できていません〈齟齬2〉。偽サイトは既に停止していますが（出典1）、停止が誰の措置によるものかも示されていません〈未確定3〉。
