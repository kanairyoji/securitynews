INC-2026-0690ウクライナ穀物物流で消去攻撃

ウクライナの**穀物物流企業**が、**2025年7月16日の標的型メール**を起点に侵害され、 **2か月後の2025年9月17日にデータを消去された**。 ESET は、**初期侵入を UAC-0099、データ消去を Sandworm（GRU 第74455部隊に帰属されている）**と、 **いずれも高い確度で**帰属している。 **UAC-0099 が侵入後に Sandworm へアクセスを引き渡したことも高い確度で評価されており**、 **ESET は「UAC-0099 が Sandworm の初期アクセス担当として機能しうる」と述べている**。 消去には **Microsoft の正規ユーティリティ `SDelete`** が使われ、 **Active Directory のグループポリシー経由で全社的に展開された**。 本件で初めて確認されたのが、**Go 言語で書かれた新種のバックドア `MythicRatatoskr`** である。 **C2 サーバーを分散メッシュネットワーク Yggdrasil の内部に置き**、 **起動ごとに新しい Yggdrasil 識別子（IPv6 アドレス）を生成し**、 **埋め込まれた32のピアから無作為に3つを選んで公開網へ参加する**。 **ESET は、国家に紐づく攻撃者が Yggdrasil をこの形で悪用した事例を 記録したのは初めてだとしている**。 **Yggdrasil 自体は匿名性を目的としていないが、ESET は C2 サーバーの 物理的な所在を特定できなかった**。 **MythicRatatoskr をどちらの群が運用していたかは判明していない**。 **被害企業の名前・被害の程度はいずれも公表されていない**。

侵入から破壊まで2か月あった。 その2か月のあいだ、2つの群が同じ企業の中にいた——入った群と、壊した群である。

2025年7月16日、ウクライナの穀物物流企業の従業員が、悪意ある添付ファイル付きのメールを開いた。ESET はこの初期侵入を UAC-0099 に高い確度で帰属している（出典1）。約1分後に MATCHBOIL（ダウンローダー）が置かれ、MATCHWOK（バックドア）を取得した。翌7月17日、これまで観測されていなかったバックドア MythicRatatoskr が届いた。

そして2025年9月17日——侵入から63日後（本記録の算出）—— Microsoft の正規ユーティリティ SDelete が Active Directory のグループポリシー経由で展開され、データが消去された。ESET はこの破壊工程を Sandworm に高い確度で帰属している（出典1）。Sandworm は GRU 第74455部隊に帰属されている群である（出典1・2）。

本件の技術的な新しさは C2 の置き場所にある（本記録の整理）。MythicRatatoskr は、Go で書かれ、C2 サーバーを分散メッシュネットワークYggdrasil の内部に置く。起動ごとに新しい識別子（IPv6 アドレス）を生成し、埋め込まれた32のピアから無作為に3つを選んで公開網に参加する。通信はメッシュ内の HTTPS（443番）であり、yggstack を使うためトンネルインタフェースも管理者権限も要らない（出典1）。ESET は、国家に紐づく攻撃者による Yggdrasil のこの形の悪用を記録したのは初めてだとし、Yggdrasil は匿名性を目的としていないにもかかわらず、C2 サーバーの物理的な所在を特定できなかったと述べている（出典1）。

日本の読者にとっての論点は2つある（本記録の評価）。①分業である。 入る群と壊す群が別であり、初期侵入の検知を逃すと、次に現れるのは別の群の別の目的である—— ESET は「UAC-0099 が Sandworm の初期アクセス担当として機能しうる」と述べている（出典1）。②C2 の宛先が「普通の IP アドレス」でなくなっていることである。宛先の評判・地理・既知の悪性リストに依存した検知は、この形では当たらない。

入った群と壊した群が別だった。ESET は引き渡しを高い確度で評価している帰属

本件の構造上の特徴は、工程が2つの群に分かれていることである。

ESET の帰属は工程ごとに分かれている（出典1）。初期侵入は UAC-0099 に「高い確度」で帰属——根拠は既知の道具立て（MATCHBOIL・MATCHWOK）である。2か月後のデータ消去は Sandworm に「高い確度」で帰属——根拠は関与した TTP である。そして「UAC-0099 が侵入の途中のどこかで Sandworm へアクセスを引き渡したと高い確度で評価する」（出典1。原文英語）。

ESET はさらに踏み込んでいる—— 「UAC-0099 は Sandworm の初期アクセス担当として機能しうると評価する」（出典1。原文英語）。

確度の分け方に注意が必要である（本記録の明示）〈重要〉。初期侵入の帰属は「高」だが、UAC-0099 がロシアの利害に沿うという評価は「中」である（出典1）。これは別の判断であり、まとめて「ロシアの攻撃」と読むと確度が失われる。

判明していないことも明示されている（出典1）—— MythicRatatoskr を主に運用していたのがどちらの群かは判定できていない。結論部では「UAC-0099 または Sandworm のいずれかに帰属」と記載されている（出典1）。

防御側にとっての意味はこうである（本記録の評価）。初期侵入の段階で検知を逃すと、次に現れるのは別の群の別の目的である。入った群の目的（アクセスの確保と転売・引き渡し）と、壊した群の目的（破壊）は違う。「侵入されたが、まだ大きな被害は見えない」という状態は、引き渡しの前である可能性がある。

C2 を分散メッシュ Yggdrasil の内部に置き、起動ごとにアドレスを変えていた原因・手口

本件の技術的な新しさは、C2 の置き場所にある（本記録の整理）。

MythicRatatoskr は Go で書かれたバックドアで、C2 サーバーを Yggdrasil の内部に置く（出典1）。Yggdrasil は実験的な経路制御方式を持つ分散メッシュネットワークで、ノードは Ed25519 鍵を使い、IPv6 アドレスはその鍵から導出される（出典1）。

マルウェアの挙動は次のとおりである（出典1）。①起動ごとに新しい Yggdrasil 識別子を生成する——したがってIPv6 アドレスが毎回変わる。②埋め込まれた32の公開ピアから無作為に3つを選んで公開網に参加する。③メッシュ内の C2 へ HTTPS（443番）で接続する。 ④yggstack を使うため、トンネルインタフェースも管理者権限も要らない〈重要〉。設定は AES-256-CFB で暗号化され、鍵はハードコードされている（出典1）。

ESET は、国家に紐づく攻撃者が Yggdrasil をこの形で悪用した事例を記録したのは初めてだとしている（出典1）。そして、Yggdrasil は匿名性を目的として設計されていない（開発者自身がそう述べている／出典2）にもかかわらず、ESET は C2 サーバーの物理的な所在を特定できなかった（出典1・2）。

防御側の論点は、検知の手がかりが何に依存しているかである（本記録の評価）〈重要〉。宛先 IP の評判、地理的位置、既知の悪性インフラの一覧—— これらはどれも「宛先が普通のインターネット上の固定的な住所である」ことを前提にしている。 本件はその前提を外している。

残る手がかりは2つある（本記録の整理）。①公開網への入口である公開ピアへの接続。 ESET が示す唯一の具体的対策も「公開ピアのアドレスを遮断すること」である（出典1）。ただし公開ピアの一覧は変化するため、一度の遮断では終わらない。②端末側の挙動。 yggstack は利用者空間で動くため、インタフェースの一覧を見る監視には現れない—— 見るべきはプロセス単位の通信である。

消去は正規ユーティリティ SDelete を、グループポリシーで全社に配って行われた被害規模・影響範囲

2025年9月17日、データ消去が検知された（出典1・2）。使われたのは Microsoft の正規ユーティリティ SDelete であり、Active Directory のグループポリシー経由で展開された（出典1）。ESET は、この展開方法が過去の Sandworm の破壊作戦と一致するとしている（出典1）。

この2点が、防御の観点では決定的である（本記録の評価）〈重要〉。

①使われたのはマルウェアではない。 SDelete は Microsoft が配布する正規のツールであり、署名も正当である。マルウェア検知では止まらない。 止めるには「誰がどの端末で使ってよいか」という実行制御が必要になる。

②配布経路が管理の仕組みそのものである。グループポリシーは「1か所の変更が全端末に及ぶ」ために作られている。攻撃者から見れば、これは最も効率のよい配布経路である。そして、グループポリシー経由で全社的に展開できたということは、ドメイン全体を制御できる権限が奪われていたことを意味する（本記録の整理）。その権限がどう取得されたかは報告されていない〈未確定3〉。

検知された段階が問題である（本記録の評価）。侵入は2025年7月16日、消去は9月17日——63日（本記録の算出）。この間、侵害は検知されていない。検知されたのは破壊が始まった時点であり、破壊型の作戦ではこれは手遅れである——消去は不可逆であり、検知から封じ込めまでの時間が復旧可能性を決める。

被害の規模は公表されていない〈未確定2〉。消去されたデータの種類・量、業務停止の期間、バックアップが機能したかどうかも示されていない。破壊型の事案では復旧可能性が被害の大きさを決めるが、本件にはその材料がない。

本件は単発の事案としてではなく、継続する標的選定の中で読む必要がある（本記録の評価）。
