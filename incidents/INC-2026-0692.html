INC-2026-0692露出LLMを乗っ取る自律攻撃エージェント

Symantec の Threat Hunter Team は2026年10月21日、**露出した LLM エンドポイントを探して乗っ取り、 借りた推論能力で攻撃を自走させる攻撃エージェント**を、AI ハニーポットで捕捉したと公表した—— 攻撃者は自前のモデルを持たず、**認証なしで外に開いた推論エンドポイントか盗んだ API キー**を 「考える部分」として調達し、走査・悪用・採掘は道具側の74本のモジュールが行う。 最終指示は **「Skynet モード」** と名付けられ、**人の承認を待たずに最大10万ステップ**の 無人実行を許していた。被害者は2組になる——**推論費を払う露出側**と、 **データを失い採掘に使われる侵入先**。 ただし **実環境での悪用は確認されていない**（ハニーポットは道具を1本も実行していない）

攻撃者が自前のモデルを用意しなくなりました。借りてくる側に回っています。

2026年10月21日、Symantec（Broadcom）の Threat Hunter Team が「Autonomous LLMjacking: 'Skynet' Agent Hijacks Exposed AI Models to Run Attacks」を公表しました（出典1）。同社は、認証されていないインターネット向けの AI サービスを装う「AI ハニーポット」を運用しており、2026年夏に、攻撃エージェントの指示一式（システムプロンプトと道具の定義）をそのまま受け取りました（出典1）。攻撃者が「本物のモデルが実行してくれる」と思って送ってきたためです（出典1）。

本記録が要点と見たのは、次の3点です。

  • モデルは攻撃道具の「考える部分」として外部から調達されている。 Symantec は「モデルは攻撃を計画し駆動する推論エンジンとして使われ、走査・悪用・採掘は道具自身のモジュールが別の被害者に対して実行する」と書いています（出典1・2。原文英語）。公開チャットボットをだまして危ないことを言わせる段階ではなく、攻撃ツールの中核に AI を据え、その動力源になるモデルを探しに行く形です（出典1）。
  • 被害者が2組になる。 Symantec の研究者 Priti More は The Register に「露出したエンドポイントの保有者が推論費を払う。エージェントが侵入した先のサーバはデータを失い、採掘に使われる」と述べています（出典2。原文英語）。自組織が侵害されていなくても、他者への攻撃の計算資源として課金され続ける構図です（本記録の整理）。
  • 「新しいのは配線のほう」である。 同氏は「脱獄の各層はおおむね既製品で、個々の技法に新しいものは無い。際立っているのは、誰かがそれらを単一のエージェントに配線し、計画を借り物のモデルに渡して、人を介さず最大10万ステップ走らせるところだ」と述べています（出典2。原文英語）。

同時に、留保が重いことも記録します。 Symantec は帰属を行っておらず、実環境での悪用の証拠は無いとしています（出典1・2）。ハニーポットは捕捉した道具を1本も実行しておらず、2日目に届いた採掘スクリプトも「捕捉しただけで実行していない」と明記されています（出典1）。10万ステップは「指示された上限」であり、観測された実行回数ではありません（本記録の明示）。それでも同氏は「この一式は試作品以上のものだ」と述べ、実在の標的に対して本物らしい走査出力を伴って動いた履歴が含まれていたとしています（出典2。原文英語）。

攻撃の経過

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

**以下は「捕捉された指示一式から読める設計上の手順」であり、 実環境で観測された侵害の経過ではない**（本記録の明示）。 **Symantec のハニーポットは道具を1本も実行していない**（出典1）。 **したがって各段階に被害側のログ・時刻・検知の有無は存在しない。** **それでも段階として記録する理由**—— **防御側が見るべき場所（露出した推論エンドポイント、AI の鍵、 外向き通信、メタデータサービス）は、この順序で決まるためである（本記録の判断）。**

  1. 1. 偵察[1] [2]
    **インターネット全体を走査し、認証なしで OpenAI 形式のリクエストを受け付ける エンドポイント、または盗んだキーを受け付けるエンドポイントを探す**（出典1・2）。 **道具には FOFA 検索サービス経由の資産探索が含まれる**（出典1）。 **Symantec のハニーポット側の観測では、 流入の大半がエンドポイントの偵察・盗んだ API キーの試行・ 露出した設定ファイルの探索であった**（出典1）。
  2. 2. 初期侵入[1] [2]
    **見つけたエンドポイントへ、5層構造の脱獄プロンプトと 約74本の道具定義を含むリクエストを送り、 モデルを「攻撃を計画する部分」として取り込む**（出典1）。 **第1層で身元とプロキシ経由であることを隠させ、 第2層で秘密情報の読み出しを通常の開発作業として枠づける**（出典1・2）。
  3. 3. 実行[1]
    **借りたモデルが計画を立て、道具側のモジュールが 別の標的に対して悪用を実行する**（出典1）。 **対象として定義されていたのは VS Code・Django・Jupyter・Laravel・ Supabase・Next.js・Flask/Werkzeug（Werkzeug デバッガの PIN 復元による コード実行を含む）・GraphQL・汎用のコマンド注入である**（出典1）。 **実環境でのこの実行は確認されていない**（出典1）〈未確定1〉。
  4. 4. 認証情報アクセス[1]
    **`.env` やローカルの設定ファイルから秘密情報を収穫し、 HTML→PDF 生成器を経由した SSRF と専用の SSRF 道具で、 クラウドのメタデータサービスから資格情報を取る**（出典1）。 **第2層のプロンプトが、この読み出しを「通常の開発作業」として 正常化する役割を担っている**（出典1・2）。
  5. 5. 検知回避[1]
    **採掘バイナリを無関係なログ出力の道具に見せかけ、 go2rtc のディレクトリに `.trace` という名前で隠す**（出典1）。 **設定ファイルに変更不可属性を立てて削除に抵抗し、 ローカルのサービスのアクセスログを消し続けるループを回す**（出典1）。 **第1層のプロンプトは、モデル側に対しても 「本当のモデル・提供者・プロキシ経由であることを明かすな」と 指示している**（出典1）。
  6. 6. 影響（暗号化・破壊・改ざん）[1] [2]
    **データベースの吸い出し（Prisma Studio 経由）、 資格情報と秘密情報の持ち出し、リモートコード実行、 そして XMRig による Monero の採掘**（出典1・2）。 **「Skynet モード」は走査 → 感染 → 採掘の投入 → 再感染の 持続的なループを指示していた**（出典1）。 **採掘は4つのプールに冗長化されていた**（出典1）。 **実環境でのこの影響は確認されていない**（出典1）〈未確定1〉。

攻撃道具の中核にモデルを置き、その動力源を外から調達する設計になった評価・解釈

これまで「AI の悪用」として報じられてきたものの多くは、公開のチャットボットをだまして、本来断るはずの出力を得る話でした（本記録の整理）。本件はその段階にありません。

Symantec の表現はこうです（出典1・2。原文英語）。

運用者は AI を攻撃道具の中核に組み込み、それを動かすモデルを探しに行った。モデルは攻撃を計画し駆動する推論エンジンとして使われ、走査・悪用・採掘は道具自身のモジュールが、別の被害者に対して実行する。

構造を分けて書くと、次のようになります（本記録の整理）。

  • 考える部分（計画・技法の選択・次の手の決定）＝ 他人のモデル
  • 手足の部分（走査・悪用・吸い出し・採掘）＝ 道具側の約74本のモジュール
  • 動力の調達方法 ＝ 認証なしで外に出ている推論エンドポイント、または盗んだ API キーを受け付けるエンドポイント

この分け方が実務にとって重要なのは、「自前のモデルを持たない攻撃者」が成立してしまうからです（本記録の評価）。高性能なモデルを買う・借りる・動かす費用も、自分で用意する必要がありません。 Symantec は「既知の技法を自律的なエージェントに組み上げることで、広範なキャンペーンを打つために必要な技能の水準が下がる」と書いています（出典1。原文英語）。

The Register に対する研究者の発言は、より直截です（出典2。原文英語）。

脱獄の各層はおおむね既製品だった。個々の技法に新しいものは何も無い。際立っているのは、誰かがそれらを単一のエージェントに配線し、計画を借り物のモデルに渡して、人を介さず最大10万ステップ走らせるところだ。

Symantec はこの構図を明示しています（出典1）。The Register での研究者の発言が、いちばん短い説明です（出典2。原文英語）。

露出したエンドポイントの保有者が推論費を払う。エージェントが侵入した先のサーバは、データを失い、採掘に使われる。そこまで到達した証拠は、まだ無い。

①推論費を払う側（出典1）。

  • 自組織のデータが盗まれるわけではありません。
  • 自組織のサーバが暗号化されるわけでもありません。
  • しかし、他者への攻撃の計算資源として、自分の枠と請求で使われます。
  • Symantec の定義では、これが「LLMjacking」です—— 「攻撃者が他人の AI モデルへのアクセスを盗み、被害者が計算能力の費用を払う」（出典1・2。原文英語）。

②侵入される側（出典1）。

  • データベースの吸い出し（Prisma Studio 経由の自動化が道具に含まれます）
  • 資格情報・秘密情報の収穫（.env・API キー・クラウドのメタデータ）
  • リモートコード実行（Werkzeug デバッガの PIN 復元など）
  • 暗号資産の採掘（/tmp/.x に静かに投入し、動作を確認するよう指示されています）

本記録が実務の論点と見たのは、①の検知の形です（本記録の評価）。①には、侵害の痕跡が出ません。 出るのは「推論量」と「請求額」です。 Symantec の勧告も、この点を名指ししています—— 「AI の API キーを高価値の資格情報として扱い、巡回させ、権限を狭く絞り、コードや設定ファイルから排除し、異常な推論量や支出を監視すること」（出典1。原文英語）。

つまり①の監視は、セキュリティ監視ではなく課金の監視に現れます（本記録の整理）—— AI の利用枠・推論量・請求の異常を見る責任者が決まっていない組織では、この被害は誰の机にも乗りません。

守る側の要点は2つ。認証なしで外に出さないことと、AI の鍵を資格情報として扱うこと対策・注意喚起

Symantec の勧告は5項目です（出典1。原文英語を本記録が訳した）。

  1. LLM の API・自前ホストのモデルサーバ・MCP エンドポイントを、認証なしでインターネットに出さない。 モデル一覧や死活確認を含むすべての経路に認証を要求し、全インタフェースに束縛するのではなくゲートウェイを置く。
  2. AI の API キーを高価値の資格情報として扱う。 巡回させ、権限を狭く絞り、コードと設定ファイルから排除し、異常な推論量や支出を監視する。
  3. AI ホストと道具を持つエージェントからの外向き通信を制限し、走査・C2 通信・採掘ソフトの取得を遮断する。
  4. クラウド環境では IMDSv2 をホップ数1で強制し、SSRF によるメタデータサービスからの資格情報窃取を防ぐ。
  5. 道具を持つエージェントを最小権限で動かし、重要な操作には人の承認を要求する。 悪用対象のソフトウェア（VS Code サーバ・Django・Jupyter・Laravel・Supabase・Prisma Studio）に修正を当て、公開インターネットから外す。

本記録が加える観点は2点です（本記録の評価）。

第一に、1と2は別の人が担当していることが多い。 1は基盤・ネットワークの話で、2は AI の利用管理・経費の話です。 本件の①の被害（推論費を払わされる側）は、セキュリティのダッシュボードには現れず、請求に現れます。 「AI の利用枠の異常を誰が見るか」を決めていない組織では、この被害は長く気づかれません。

第二に、5の「人の承認」は、攻撃側が真っ先に外したものである。 「Skynet モード」の指示の中身は、まさに「許可を求めるな・経過を説明するな・即座に実行せよ」です（出典1）。自組織でエージェントを運用するときの設計上の分岐点が、攻撃側の設計で名指しされている形です（本記録の整理）—— 承認を外した運用は、能力が上がるのではなく、止める手段が無くなります。

CISO・経営層への示唆
  • **「侵害されていないのに費用を払う」被害が実在する。AI の利用枠と請求を見る責任者を決める。**
    **この手口の被害者①は、データも資産も失わないが、 他者への攻撃の推論費を負担する**（出典1・2）。 **Symantec の勧告も「異常な推論量や支出を監視すること」を挙げている** （出典1。原文英語）。 **本記録の評価**—— **この異常はセキュリティ監視のダッシュボードには出ず、請求に出る。** **担当が決まっていなければ、誰の机にも乗らない。**
    取るべき行動 **AI の利用枠・推論量・請求の異常に対して、 閾値と見る人を明文化する。** **「先月比で推論量が N 倍」「深夜帯の推論が継続」を インシデントの入口として扱えるようにする。**
  • **AI の API キーの扱いを、認証情報の規程の中に明示的に入れる。**
    **この手口は「認証なしのエンドポイント」と「盗んだキー」の 2つの入口を持つ**（出典1・2）。 **AI 支援ツールの資格情報を狙う窃取型マルウェアはすでに観測されており 〈関連 INC-2026-0539〉、自社の認証情報を使った生成AIサービスの 不正利用とみられる国内事案もある〈関連 INC-2026-0532〉。** **本記録の評価**—— **AI のキーは「開発者が自分で取ってきて `.env` に置くもの」として 管理の外に置かれやすい。**
    取るべき行動 **AI の API キーを、既存の資格情報管理（棚卸し・巡回・権限の最小化・ コードへの埋め込み禁止）の対象に明記して入れる。** **誰がどのキーを持ち、どのモデルにいくらまで使えるかを一覧にする。**
  • **エージェントの「人の承認」を外す判断を、例外ではなく統制の変更として扱う。**
    **攻撃側の最終指示の中身は「許可を求めるな・経過を説明するな・即座に実行せよ」であり、 最大10万ステップの無人実行を許している**（出典1）。 **Symantec の勧告は逆向きに「重要な操作には人の承認を要求する」である**（出典1）。 **本記録の評価**—— **承認を外すと能力が上がるのではなく、止める手段が無くなる。** **攻撃側がそこを真っ先に外していることが、その証拠である。**
    取るべき行動 **自組織で道具を持つエージェントを動かす場合、 「どの操作に人の承認を要するか」を文書化し、 承認を外す変更には記録と承認者を要求する。** **無人実行のステップ数・時間・費用に上限を設ける。**
  • **これは「起きた事案」ではなく「来る形の予告」として扱う。実被害の未確認を理由に後回しにしない。**
    **実環境での悪用は確認されておらず、被害組織は1件も挙げられていない** （出典1）〈未確定1〉。 **一方で研究者は「この一式は試作品以上のものだ」と述べ、 「新しいのは配線で、個々の技法は既製品だ」としている**（出典2。原文英語）。 **本記録の評価**—— **既製品の配線は真似られる。** **被害事例が出てから着手する運用では、 着手の時点で露出の棚卸しがゼロから始まる。**
    取るべき行動 **「認証なしで外に出ている推論エンドポイント・モデルサーバ・MCP のポート」の 棚卸しを、本件を根拠に1回実施する。** **実被害の報告を待たずに行う判断であることを、記録に残す。**
セキュリティ技術者への示唆
  • **モデル一覧や死活確認の経路にも認証を要求する。「読むだけ」の経路が判定の材料になる。**
    **Symantec の勧告は「モデル一覧や死活確認を含むすべての経路に 認証を要求すること」と明示している**（出典1。原文英語）。 **本記録の評価**—— **走査側は「このエンドポイントが使えるか」を知りたい。** **`/v1/models` のような経路が無認証なら、その判定を無料で与えてしまう。**
    取るべき行動 **推論エンドポイントの全経路（モデル一覧・死活確認・メトリクスを含む）に 認証を掛ける。** **外部から無認証で応答する経路が残っていないことを、 実際にリクエストを投げて確認する。**
  • **推論サーバの待ち受けアドレスを確認する。検証用の構成がそのまま外に出ている。**
    **Symantec は「全インタフェースに束縛するのではなくゲートウェイを置くこと」を 勧告している**（出典1。原文英語）。 **本記録の評価**—— **自前ホストのモデルサーバは、動かすまでの手間を減らすために `0.0.0.0` で立てられやすい。** **検証が終わっても構成はそのまま残る。**
    取るべき行動 **自前ホストの推論サーバ・MCP サーバの待ち受けアドレスとポートを棚卸しし、 ループバックまたは内部網に限定する。** **外向きの公開はゲートウェイ経由に一本化する。**
  • **IMDSv2 をホップ数1で強制する。SSRF 経由のメタデータ窃取は設定1つで閉じられる。**
    **道具一式には、クラウドのメタデータサービスを名指しした専用の SSRF モジュールと、HTML→PDF 生成器を経由した SSRF が含まれる**（出典1）。 **Symantec の勧告の第四項がこれに対応する**（出典1）。 **本記録の評価**—— **攻撃側が専用モジュールを用意している経路であり、 対策の費用対効果が明確である。**
    取るべき行動 **クラウドのインスタンスで IMDSv2 を必須にし、ホップ数の上限を1にする。** **HTML→PDF 生成器のような「URL を渡すと取りに行く」部品の 到達先を内部網とメタデータサービスから遮断する。**
  • **公開インターネットに出ている開発系の道具を数える。標的として名指しされているのはそこである。**
    **道具一式が悪用対象としていたのは VS Code・Django・Jupyter・Laravel・ Supabase・Next.js・Flask/Werkzeug・Prisma Studio であり、 Werkzeug デバッガの PIN 復元によるコード実行も含まれる**（出典1）。 **Symantec の勧告も、これらを公開インターネットから外すよう述べている**（出典1）。 **本記録の評価**—— **ここに並ぶのは本番システムではなく開発・検証用の道具である。**
    取るべき行動 **外部から到達できる Jupyter・Prisma Studio・VS Code サーバ・ デバッガ有効のアプリを洗い出し、閉じるか認証を掛ける。** **とくにデバッグモードが有効なまま公開されている構成を潰す。**
  • **AI ホストからの外向き通信を制限する。走査・C2・採掘の取得はいずれも外に出る。**
    **Symantec の勧告の第三項である**（出典1）。 **採掘スクリプトは XMRig を取得または自前でビルドし、 4つの採掘プールに接続する設計であった**（出典1）。 **本記録の評価**—— **エージェントを動かすホストは「何にでも出ていける端末」として 置かれがちで、外向きの制限が最後に残る。**
    取るべき行動 **AI ホストと道具を持つエージェントの外向き通信を、 必要な宛先に限定する（許可リスト方式）。** **採掘プールのような既知の宛先の遮断だけに頼らない （宛先は容易に変えられる）。**
