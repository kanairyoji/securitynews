INC-2026-0693Help TDS が技術支援詐欺に2万ページ

偽の Windows 警告でコールセンターへ電話をかけさせ遠隔操作ツールを入れさせる 技術支援詐欺が、Cloudflare Pages の無料サブドメインを1日約300件・ 半年で2万件超にわたって使い捨てている——Infoblox は、この振り分け基盤 「Help TDS」の運営者をロシア語圏のアフィリエイト・プログラム Hotejka と特定し、 2018年に正体が割れた ROI777 の看板の掛け替えであると高い確度で判定した。 最新の広告では、流入を求める国に日本が明示的に挙げられている

詐欺の手口脅威・攻撃キャンペーン初報のみ日本に波及した海外事案人を介した誘導（ビッシング・BEC）認証情報の悪用（使い回し・推測可能・窃取）
初報: 2026年10月15日（Infoblox Threat Intel の調査公表） 最終更新: 2026年10月25日（보안뉴스の報道を起点に Infoblox の原文で裏を取った）

2026年10月15日、Infoblox Threat Intel が「Inside Help TDS: Hotejka, Cloudflare Pages and Predictive Detection」を公表した（出典1）。技術支援詐欺（テックサポート詐欺）へ人を流し込む振り分け基盤「Help TDS」の運営者を、ロシア語圏のアフィリエイト・プログラムHotejka と特定し、アフィリエイト・パネルへの直接のアクセスを含む調査結果を示したものである（出典1）。

手口そのものは目新しくない（本記録の評価）—— 偽の Windows 更新画面が出て、「Microsoft がこのコンピュータを無効にした」という警告と警報音が鳴り、「再起動するな」という音声が流れ、「Microsoft Security」の電話番号が表示される（出典1）。電話に出た相手は Microsoft のテクニカルサポートを名乗り、Ctrl-Alt-Delete の操作を指示したうえで、遠隔操作ツール UltraViewer をダウンロードさせる（出典1）。

新しいのは、その舞台の作り方である（本記録の評価）。運営者は2026年4月に、有料ホスティング（King Servers）からCloudflare Pages の無料サブドメインへ移った（出典1）。十数種のドメイン生成アルゴリズムを使い、1日あたり約300件の使い捨てページを作る（出典1）—— ドメインは DNS に約1週間だけ現れて消える。 Infoblox はこうして作られたドメインを半年で2万件超（集計の仕方によっては約3万件）検出した（出典1）〈齟齬1〉。

帰属は Hotejka = ROI777 である（出典1）。Infoblox は「ROI777 と Hotejka が同一であることに高い確度を持つ」とし、根拠として、同じ IP（162.244.35.33）が2022年3月まで roi777[.]com をホストし hotejka[.]com の PTR レコードでもあったこと、命令制御の作法が一貫していること、アフィリエイトID h2xkd0 が別の広告基盤でも使い回されていること、2018年に ROI777 のサーバが侵害され Telegram 上の身元が露見したこと、そしてアフィリエイト・パネルへ直接アクセスできたことを挙げた（出典1・原文英語を本記録が訳した）。

規模の推定は「疑い」のレベルである（本記録の明示）—— Infoblox は「ヨーロッパの2つのプログラムが、彼らに少なくとも数百万ドル（USD）を支払ってきたと疑っている」と書いており（出典1）、8年分の DNS の量・アフィリエイトIDの追跡・一般に言われている支払い率から組み立てた推定であると明記している（出典1）。確定した金額ではない。

日本は無関係ではない（出典1）。最新の広告では、流入を求める対象に日本が明示的に含まれている—— ただし日本での実被害は公表されていない〈未確定4〉。

攻撃の経過

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

**これは組織への侵入ではなく、人への誘導である**（本記録の明示）。 **以下の chain は、Infoblox が記録した詐欺の流れ（出典1）を 段階に割り当てたものである**—— **attack_stages の語彙は組織侵害を前提にしているため、 `initial-access` は「被害者の画面に到達すること」、 `execution` は「被害者が自分で遠隔操作ツールを入れること」と 読み替えている**（本記録の明示）。 **各段の中身は Infoblox の記述に基づく事実であり、 検知機会の評価は本記録の判断である。**

  1. 1. 偵察確認済
    **Help TDS が、流入してきた訪問者の地域・端末情報・IP の評判・ 自動化されたブラウザかどうかを判定する**（出典2・3）—— **条件に合わない訪問者（調査者のクローラ等）には 無害な内容を見せる**
    根拠: 出典2・3 の記述（トラフィック分配システムは、 地域と端末情報・IP 評判・自動化ブラウザかどうかを判定して 振り分け先を決める）。 出典1 の記述（直接アクセスしたときに無害なデコイの内容を示し、 のちに運営者の告知に現れたドメインがある）
  2. 2. 初期侵入確認済
    **Cloudflare Pages の使い捨てサブドメイン（`*.pages[.]dev`）上の 詐欺ページが被害者のブラウザに表示される**（出典1）。 **偽の Windows 更新画面から始まり、 「Microsoft がこのコンピュータを無効にした」という警告、 警報音、「再起動するな」という合成音声、 抜け出しにくい全画面のロックが続く**
    根拠: 出典1 の記述（偽の更新通知・Microsoft による無効化の警告・ 「Microsoft Security」の電話番号・抜けにくいブラウザロック・ 再起動するなと告げる合成音声）
  3. 3. 実行確認済
    **被害者が表示された番号へ電話をかけ、 Microsoft のテクニカルサポートを名乗る相手の指示で 遠隔操作ツール UltraViewer をダウンロード・インストールする** （出典1）—— **Infoblox の調査員がかけた通話では、その後に電話が切られた**
    根拠: 出典1 の記述（通話相手が Microsoft のテクニカルサポートを名乗り、 Ctrl-Alt-Delete の操作を指示し、 遠隔アクセスのために UltraViewer をダウンロードさせた）
  4. 4. 影響（暗号化・破壊・改ざん）推定
    **遠隔操作を得た相手が被害者の PC を操作する**（出典1・2）。 **Infoblox は、攻撃者が同じ被害者のところへ 繰り返し戻ってこられると分析している**（出典3）
    根拠: 出典1 の記述（コールセンターでの社会工学により 遠隔デスクトップツールを導入させる）。 出典3 の記述（攻撃者は同じ被害者のところへ繰り返し戻ってこられる）
  5. 5. C2通信推定
    **改ざんされた WordPress サイトに置かれた悪性プラグインが、 命令制御サーバから転送先を受け取る**（出典2・3）〈齟齬2〉—— **転送先を外から差し替えられるため、 サイト側のコードを見ても現在の行き先が分からない**
    根拠: 出典2・3 の記述（プラグインは WordPress のアカウント情報を盗み、 命令制御サーバから移動先の URL を受け取る）。 出典1 の記述（Hotejka がアフィリエイトへ配る悪性 WordPress プラグインを GoDaddy が報告している）

技術的な侵害は起きていない——起きているのは「電話をかけさせること」である原因・手口

Infoblox が記録した詐欺の流れは次のとおりである（出典1）。

  • 偽の更新通知が出て、「PC を再起動します」と告げる。

  • 続いて「Microsoft がこのコンピュータを無効にした」という警告が出る。警報音が鳴り、「Microsoft Security」の電話番号が表示される。

  • ブラウザのロック画面は抜け出しにくく、合成音声が「コンピュータを再起動するな」と繰り返す。

  • 電話に出た相手は Microsoft のテクニカルサポートを名乗り、Ctrl-Alt-Delete の操作を指示したうえで、遠隔操作ツール UltraViewer をダウンロードさせる。

  • Infoblox の調査員が実際にかけた通話では、そこで電話が切られた。

  • 別経路として、偽の CAPTCHA でブラウザのプッシュ通知を承諾させるものがある（出典1）。

ここから先は本記録の評価である。

この流れのどこにも、端末の脆弱性を突く工程が無い。 使われているのは、全画面のロックと音と「再起動するな」という指示で 被害者の判断を止め、電話という別の経路へ移すことだけである。 UltraViewer は正規の遠隔操作ツールであり、 被害者が自分の手でインストールする—— 署名も評判も正常なので、端末の防御は何も言わない。

したがって、この手口に対して 「マルウェア検知が止める」という期待は成り立たない（本記録の評価）。 止まるとすれば、①偽の警告ページへ到達する前（DNS・URL の遮断）、 ②電話をかける前（人が気づく）、 ③遠隔操作ツールの導入を禁じる端末側の制御——のどれかである。 ②は被害者が恐怖で動かされている最中なので、 最も当てにならない（本記録の評価）。 Infoblox は「攻撃者は同じ被害者のところへ繰り返し戻ってこられる」とも 分析している（出典3）——一度でも繋がれば、関係は続く。

無料で誰でも使えることが、そのまま使い捨ての土台になっている評価・解釈

運営者は2026年4月に、有料ホスティング（King Servers）から Cloudflare Pages の無料サブドメインへ移った（出典1）。 Infoblox が示した運用の形はこうである（出典1）。

  • 半年で約十数種のドメイン生成アルゴリズムを使い、うち半分を大規模に回している。

  • 1日あたり約300件の新しい Cloudflare Pages を告知する。

  • 各ドメインが DNS で解決されるのは約1週間。

  • 半年で2万件超（別の数え方で約3万件、うち約1万6,000件がTelegram で告知されたもの）を検出した〈齟齬1〉。

  • ほかに約1万件が、別のフィッシングやデコイに見える（出典1）。

ここから先は本記録の評価である。

この作りが効くのは、遮断の一覧（ブロックリスト）が 「見つけてから載せる」仕組みだからである。 1週間で消えるドメインを1日300件作られると、 見つけて載せた時にはもう次へ移っている。 Cloudflare Pages 全体では1日12万5,000件超の新規サブドメインが 観測されており（出典3）、300件はその中に埋もれる。 「*.pages[.]dev を丸ごと遮断する」は正規の利用を巻き込むので、 多くの組織では採れない（本記録の評価）。

Infoblox の主張は、ここに対する答えとして出されている（本記録の読み）—— ドメイン生成アルゴリズムの規則性と DNS の挙動から、 使われる約7日前（中央値）に先回りして検出するというものである（出典1）。 2026年7月以降、Telegram で告知される前に1万件超を検出し、 自社顧客の露出は単日最大4%から9月には0.5%未満へ下がったとしている （出典1）。 これは同社の顧客基盤での数値であり、 インターネット全体の話ではない（本記録の明示）—— 残っている露出には、同社いわく応答ポリシーゾーン（RPZ）の 設定不備が含まれる。 つまり「仕組みを入れたのに効いていない組織」が一定数ある、 ということである（本記録の読み）。

帰属は民間の調査による判定であり、司法の認定ではない帰属

Infoblox は、Help TDS の運営者を Hotejka と判定し、 Hotejka は2018年に正体が割れた ROI777 の看板の掛け替えであると 「高い確度」で述べている（出典1）。 根拠として挙げられているのは次の各点である（出典1）。

  • 同じ IP（162.244.35.33）が2022年3月まで roi777[.]com をホストし、hotejka[.]com の PTR レコードでもあった。

  • 命令制御の仕組みが一貫している。

  • アフィリエイトID h2xkd0 が別の広告基盤でも使い回されている。

  • 2018年に ROI777 のサーバが侵害され、Telegram 上の身元とキャンペーンの内容が露見した。

  • Telegram 上の身元の一致。

  • アフィリエイト・パネルへの直接のアクセスを得た。

ここから先は本記録の評価である。

この帰属の確かさは、痕跡の重なりの量ではなく、 「パネルへ入れた」ことに支えられている（本記録の読み）—— 運営の内側から見た情報は、外形的な DNS の一致より強い。 一方で、これは民間事業者の調査による判定であって、 捜査機関の認定でも司法手続の結果でもない（本記録の明示）。 運営者側の反論は存在しない（当事者の公表が無い）。

「ロシア語圏のアフィリエイト・プログラム」という性格づけは、 国家の関与を意味しない（本記録の明示）—— Infoblox もそのような主張はしていない。 資金の流れについても、 「ヨーロッパの2つのプログラムが少なくとも数百万ドルを支払ってきたと 疑っている」という推定にとどまる（出典1）〈齟齬3〉。

緩和策
数え方: **組織**: 従業員の端末で、許可していない遠隔操作ツール （UltraViewer・AnyDesk・TeamViewer 等）の新規インストールと起動を 検知・禁止する（出典1 が示す手口への対処として本記録が整理した）　副作用: **本記録の評価。** **正規の保守・ヘルプデスクが 同種のツールを使っている組織では、業務が止まる。** **「許可した1種類だけを残して他を禁じる」形にしないと運用できず、 その1種類が偽装の標的になる。** **例外申請の窓口を作ると、そこ自体が 社会工学の入口になりうる**（攻撃者が「申請してください」と言える）。

CISO・経営層への示唆

    取るべき行動 **自組織の端末で、許可していない遠隔操作ツールの 新規インストールと起動が検知・禁止されているかを確認する。** **できていなければ、許可する1種類を決めたうえで 他を禁じる規則とその実装（アプリケーション制御）を手配する。** **「禁止したら保守が止まる」部門を先に洗い出すこと。**
  • 自社サイトの改ざんは「自社の被害」だけでは勘定が合わない
    **改ざんされた WordPress サイトは、 訪問者を詐欺へ流すための在庫として売買されている**（出典1）—— **2026年5月には、1通話あたり100ドルの値がついている**（出典1）。 **放置された自社サイトには市場価格がある、ということである** （本記録の評価）。 **自社の情報が盗まれなくても、 自社のドメインを信用した訪問者が被害に遭う。**
    取るべき行動 **自社が保有する全ての WordPress サイト （キャンペーン用・過去の特設サイト・子会社のものを含む）を 棚卸しし、所有者と更新責任者を確定させる。** **「誰も見ていないサイト」を特定して、 停止するか、維持する責任者を決めること。**
  • 「標的として名指しされた」段階で動くか、被害数を待つか
    **最新の広告で、流入を求める国に日本が明示的に挙げられている**（出典1）。 **一方で、日本の被害者数・被害金額は公表されていない**〈未確定4〉—— **技術支援詐欺は被害者が自分で遠隔操作を許すため、 本人が届け出なければ数えられない**（本記録の評価）。 **「数字が出ていない」ことを「起きていない」と読むと、 対処は常に後手になる。**
    取るべき行動 **「被害件数」ではなく「到達可能性」で判断する運用に切り替える。** **具体的には、自組織の DNS ログで `*.pages[.]dev` への 問い合わせがどれだけあるかを一度測り、 正規の用途（開発・プレビュー）とそれ以外を仕分ける。** **ここが空なら、丸ごと遮断する選択肢が取れる。**
  • 無料サービスの悪用は、自組織では止められない部分が残る
    **1日約300件・寿命約1週間という回転は、 「見つけてから載せる」遮断一覧の更新周期より速い**（出典1）。 **Cloudflare Pages 全体では1日12万5,000件超の新規サブドメインが あり**（出典3）、**その中に紛れる。** **提供事業者側の施策が入らないかぎり、 利用側の対策には上限がある**（本記録の評価）。
    取るべき行動 **自組織の対策を「完全に止める」ではなく 「漏れた前提で、次の段階で止める」設計に置き直す。** **具体的には、到達を許した場合に備えて 〈電話をかけさせない周知〉と〈遠隔操作ツールの導入を禁じる制御〉の 2段を用意する。前者だけでは足りない。**
セキュリティ技術者への示唆
  • 1回アクセスして無害だったことは、白の根拠にならない
    **Help TDS は、地域・端末情報・IP の評判・ 自動化されたブラウザかどうかで振り分ける**（出典2・3）。 **Infoblox は、直接アクセスすると無害なデコイの内容を示し、 のちに運営者の告知に現れたドメインがあると注意している**（出典1）。
    取るべき行動 **不審 URL の確認を「自分のブラウザで開いて見る」で済ませない。** **判定には、DNS 上の素性（登録・解決の履歴・近傍のドメイン）と 複数の環境からの取得結果を併せる。** **「見たら普通のページだった」を報告に書くときは、 どの環境から見たかを必ず添えること。**
  • 寿命1週間・1日300件のドメインには、事後の遮断一覧が効かない
    **各ドメインが DNS で解決されるのは約1週間である**（出典1）—— **検出して一覧に載せたころには、次の300件に移っている。** **Infoblox が中央値7日の事前検出を主張しているのは、 この時間差を逆転させるためである**（出典1）。
    取るべき行動 **自組織の DNS 遮断が「どれだけ古い情報で動いているか」を測る。** **具体的には、直近に遮断一覧へ追加されたドメインについて、 初回解決からの経過日数の分布を出す。** **中央値が1週間を超えているなら、この手口には効いていない。**
  • 無料ホスティングのサブドメインを、自組織の用途から仕分けておく
    **`*.pages[.]dev` を丸ごと遮断する案は、 正規の開発用サイトを巻き込むため多くの組織で採れない**（本記録の評価）。 **採れるかどうかは、自組織が実際にその用途を使っているかで決まる。**
    取るべき行動 **DNS ログから `*.pages[.]dev`（および `*.vercel.app`・ `*.netlify.app` 等の同種）への問い合わせを抽出し、 発信元と件数を一覧にする。** **正規の利用が特定の開発チームに限られるなら、 そのセグメントだけ許可して他を遮断する。**
  • WordPress の棚卸しは、資格情報の総入れ替えとセットでないと無駄になる
    **運営者はフォーラムで web shell と管理画面（admin panel）を 買い求めている**（出典1）—— **すでに資格情報が売られているサイトでは、 プラグインを消しても入れ直される**（本記録の評価）。 **報道は、悪性プラグインが WordPress のアカウント情報を盗むと 伝えている**（出典2・3）〈齟齬2〉。
    取るべき行動 **不審なプラグインを見つけたら、削除と同時に ①全管理者アカウントのパスワードとセッションの失効、 ②`wp-config.php` の DB 認証情報とソルトの更新、 ③APIキー・Webhook の再発行——を行う。** **削除だけで終えた場合は、再発を前提に監視を残すこと。**
  • サイトから外部への発信を見ていないと、転送先の差し替えに気づけない
    **悪性プラグインは命令制御サーバから転送先を受け取ると 報じられている**（出典2・3）〈齟齬2〉—— **サイト側のコードを読んでも、 その時点の行き先が分からないということである**（本記録の読み）。
    取るべき行動 **自社サイトのサーバから外部への HTTP(S) 発信を記録し、 宛先ドメインの一覧を定期的に見る。** **CMS のサーバが、更新・外部APIとして説明できない宛先へ 継続的に発信しているなら、そこを起点に調べる。**
