INC-2026-0698AGENTS.mdでAIエージェント乗っ取り

Forever Security は2026年10月22日、顧客端末の `~/Downloads` に置かれた**悪性の AGENTS.md**が AI コーディングエージェントに悪性 npm パッケージ `function-color` のインストールを指示していたと公表した—— 同社の再現試験では **Codex が90%超の試行でマルウェアを実行**し、 悪性 `CLAUDE.md` を使った別の試験では **Claude Code の API 通信が攻撃者のサーバへ向けられ OAuth ログイントークンが漏えいする手口が約50%で成立**した。 **ウェブページは利用者の操作なしに `~/Downloads` へ任意の名前のファイルを書き込める**一方、 指示ファイルは実行ファイルではないため OS の実行承認が働かない。 研究者は「ここに OpenAI や Anthropic が直すものは無い」としている（原文英語）

脅威・攻撃キャンペーン不正アクセス・侵害初報のみ有名事象として記録（日本と直接の関係は薄い）設計・実装上の不備
初報: 2026年10月22日（Forever Security のブログ公開） 最終更新: 2026年10月26日（本記録の作成時点）

直すべきバグが無い、という種類の事案です。

2026年10月22日、Forever Security（著者: Gal Weizman・Omer Samet）は、顧客の端末で AI コーディングエージェントが悪性の npm パッケージfunction-color をインストールしようとしたところを遮断し、その指示の出所が ~/Downloads フォルダに置かれた悪性の AGENTS.md だったと公表しました（出典1。同社ブログ）。AGENTS.md や CLAUDE.md は、エージェントに使う道具・テストの回し方・コーディング規約を伝えるための平文のファイルで、エージェントは作業ディレクトリにある該当ファイルを自動で読み込みます（出典2）。

本記録が要点と見たのは、次の3点です。

  • 成立した経路は「ダウンロードフォルダ」でした。同社は "It is the one folder the web can write to on its own."（「ウェブが自力で書き込める唯一のフォルダである」・出典1。原文英語）と書いています。Chrome・Edge・Firefox は既定で保存先を尋ねずに ~/Downloads へ保存し、指示ファイルは実行ファイルではないため、OS のダウンロード実行承認（Gatekeeper 等）が働きません（出典1・2）。
  • 再現試験の成功率が高い。 Codex に対しては「90%を超える試行でマルウェアを実行した」（原文英語: "In our testing, Codex ran the malware in more than 90% of attempts."・出典1）。悪性 CLAUDE.md を使った別の試験では、Claude Code の API 通信を攻撃者のサーバへ向けさせて OAuth ログイントークンを漏えいさせる手口が「約半分の割合で」成立した（原文英語: "In our testing, Claude followed through on this about 50% of the time."・出典1）。
  • ベンダーが直す対象がありません。 "There is nothing here for OpenAI or Anthropic to patch."（出典1。原文英語）—— エージェントが自分のフォルダの AGENTS.md に従うのは、作られたとおりの動作だからです。 したがって対策は利用者側の運用（起動する場所を絞る・指示ファイルを読む・承認ゲートとサンドボックスを切らない）に寄ります（出典1・2）。

攻撃の経過

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

**攻撃の実行者は、利用者自身のエージェントである**（本記録の整理）。 攻撃者はウェブページ経由で `~/Downloads` に `AGENTS.md`（または `CLAUDE.md`）を置く。 **利用者がそのフォルダでエージェントを起動すると、エージェントは作業ディレクトリの 指示ファイルを自動で読み込み、書かれた内容を自分の持つ道具と権限で実行する**（出典1・2）。 **実行ファイルは1つも落ちていないため、OS のダウンロード実行承認は働かない。** 観測された結果は2通りで、**①悪性 npm パッケージ `function-color` のインストール試行** （顧客端末・遮断済み）、**②API 通信の向き先の書き換えによる OAuth ログイントークンの漏えい** （同社の再現試験）である。 **①では `~/.codex/config.toml`（端末全体の設定）が書き換え先であり、 以後どのフォルダで起動しても影響が続くとされる**（出典1）—— **「そのフォルダを離れれば終わり」ではない**

  1. 1. 初期侵入disclosed[1] [2]
    **ウェブページが `~/Downloads` へ `AGENTS.md` を書き込む。** **Chrome・Edge・Firefox は既定で保存先を尋ねずに保存する**（出典2）。 **Brave は承認を求めた**（出典2。BleepingComputer の検証）。 **指示ファイルは実行ファイルではないため、 OS がダウンロード実行物に課す承認は働かない**（出典1）
    根拠: Forever Security のブログ（出典1・一次）および BleepingComputer による実証ページの検証（出典2）。 **本記録の作成者は、ブログ本文の該当記述を2026年10月26日に照合した**
  2. 2. 実行disclosed[1] [2]
    **利用者が `~/Downloads` を作業ディレクトリとしてエージェントを起動する。** **エージェントは作業ディレクトリの指示ファイルを自動で読み込み、 内容を自分の道具と権限で実行する**（出典2）。 **Codex は「90%を超える試行でマルウェアを実行した」** （原文英語: "Codex ran the malware in more than 90% of attempts."・出典1）。 **研究者によれば、ダウンロードフォルダの整理や 落としたファイルの処理をエージェントにやらせるのは一般的な使い方である**（出典2）
    根拠: 同社の再現試験（出典1）。**実際の攻撃ペイロードを隔離した仮想環境で動かしたもの**
  3. 3. 永続化disclosed[1]
    **書き換え先が端末全体の設定ファイルだった**（出典1）—— **`~/.codex/config.toml` に書かれるため、 以後どのフォルダでエージェントを起動しても影響が続くとされる。** **同社は、確認すべき場所として `~/.codex/config.toml` の 予期しない `[mcp_servers.*]` と、`.claude/settings.json` の `ANTHROPIC_BASE_URL` のような API の接続先設定を挙げている**（出典1）
    根拠: Forever Security のブログ（出典1）。**本記録の作成者が該当の推奨を確認した**
  4. 4. 認証情報アクセスdisclosed[1] [2]
    **悪性 `CLAUDE.md` は、Claude Code の API 通信を攻撃者のサーバへ向けさせる。** **その結果 OAuth ログイントークンが攻撃者側へ渡る** （原文英語: "It leaks Claude's OAuth login token to us"・出典1）。 **指示に従った割合は約50%**（出典1）。 **BleepingComputer は、攻撃者のサーバがモデルになりすまして コードを実行する道具呼び出しを返せたと伝えている**（出典2）
    根拠: 同社の再現試験（出典1）。**顧客端末で実際にトークンが漏えいしたという記述は無い** （本記録の確認）
  5. 5. 影響（暗号化・破壊・改ざん）disclosed[1] [2]
    **観測された影響は2通り**（本記録の整理）—— **①悪性 npm パッケージ `function-color` の導入試行**（顧客端末・遮断済み・出典1）、 **②OAuth トークンの漏えいによるアカウントの乗っ取りとコード実行** （同社の再現試験・出典1・2）。 **顧客端末で実害が生じたという記述は無い**（本記録の確認）
    根拠: 出典1・2。**侵害指標として同社が挙げているのは 「`function-color` が入っていればその端末は侵害されたものとして扱う」の1点である**（出典1）

止まったのは「悪性パッケージの導入」で、「エージェントへの指示」は誰も見ていなかった発覚の端緒出典 [1] [2]

発見の順序が、この事案の性格をよく表しています（本記録の整理）。

Forever Security が最初に捉えたのは、コーディングエージェントが既知の悪性 npm パッケージ function-color をインストールしようとした場面でした（出典1）。止まったのは依存の導入の層です。

そこから調査を遡って見つかったのが、顧客の ~/Downloads に置かれた悪性の AGENTS.md でした（出典1・2）。そのフォルダは、エージェントの作業ディレクトリでもありました。

順序を逆にして読むと、備えの穴がはっきりします（本記録の評価）。

  • 指示ファイルが置かれた段階——誰も見ていませんでした。
  • エージェントがそれを読んで従った段階——記録も警報もありません。
  • 悪性パッケージを入れようとした段階——ここで初めて止まりました。

つまり検知は「最後の1段」でしか働いていません。 そして最後の1段が効いたのは、パッケージが既知の悪性だったからです（本記録の評価）。未知の名前であれば、あるいは curl を叩くだけの指示であれば、同じ場所では止まりません。

誰がそのファイルを置いたのか、どうやって入ったのかは、同社も特定できていません（出典1・2）〈未確定3〉。BleepingComputer には「悪性のページを訪れるだけで、利用者の操作なしに置かれうる」と説明し、実証ページを別に用意しています（出典2）。

~/Downloads は「ウェブが自力で書き込める唯一のフォルダ」だった原因・手口出典 [1] [2]

同社の説明は1文です。

"It is the one folder the web can write to on its own."（「ウェブが自力で書き込める唯一のフォルダである」・出典1。原文英語）

ここに2つの既定動作が重なります（出典1・2）。

  • ブラウザ側——Chrome・Edge・Firefox は、既定では保存先を都度尋ねず、~/Downloads へ保存します。 BleepingComputer の検証では、Brave は承認を求めました。
  • OS 側——ダウンロードされた実行ファイルには承認の仕組みが働きますが、指示ファイルは実行ファイルではないため、その保護の対象外です（出典1）。

攻撃者が必要としたのは、コードを実行する権限ではなく、テキストファイルを1つ置く権限でした（本記録の整理）。実行は、利用者自身のエージェントが引き受けます。

ただし「完全に無音」とは言えません（本記録の整理）。Chrome・Edge・Firefox も既定ではダウンロード通知を表示します（出典2）。気づく機会はありました。 気づけなかったのは、通知が「ファイルが保存された」ことしか伝えず、それがエージェントへの命令として読まれることを伝えないからです（本記録の評価）。

成功率は Codex が90%超、Claude Code が約50%——ただし分母が示されていない被害規模・影響範囲出典 [1] [2]

同社は、実際の攻撃ペイロードを隔離した仮想環境で動かして再現しました（出典1）。

  • Codex——"Codex ran the malware in more than 90% of attempts."（「90%を超える試行でマルウェアを実行した」・出典1。原文英語）。書き込み先は ~/.codex/config.toml という端末全体の設定であり、以後どのフォルダで起動しても影響が続くとされます。
  • Claude Code——悪性 CLAUDE.md で API 通信を攻撃者のサーバへ向けさせる手口に「約半分の割合で」従いました（原文英語: "In our testing, Claude followed through on this about 50% of the time."）。結果として OAuth ログイントークンが漏えいします（原文英語: "It leaks Claude's OAuth login token to us"）。同一セッション内の「サブエージェント」経由のコード実行は約5分の1でした。

BleepingComputer は、漏えいしたトークンによって攻撃者のサーバがモデルになりすまし、コードを実行する道具呼び出しを返せたと伝えています（出典2）。

本記録が留保するのは、分母です（本記録の明示）〈未確定6〉。90%超・約50%・約5分の1のいずれにも試行回数が付いていません。 さらに、承認ゲートとサンドボックスを有効にした状態での成功率が示されていません。 同社の推奨がまさに「それらを有効のままにすること」である以上、読者が最も知りたい数値が欠けています（本記録の評価）。

また BleepingComputer は、Codex に対する試験の検体を「電卓アプリを開くだけの無害なもの」と書いており、ブログの「実際の攻撃ペイロード」という記述とは別の試験を指している可能性があります〈齟齬2〉。

ベンダーに直すものが無い——だから対策は「起動する場所」に寄る対策・注意喚起出典 [1] [2]

研究者の主張は明確です。

"There is nothing here for OpenAI or Anthropic to patch."（「ここに OpenAI や Anthropic が直すものは無い」・出典1。原文英語）

自分のフォルダの AGENTS.md に従うエージェントは、作られたとおりに動いている——これが同社の立場です（出典1・2）。

したがって対策は利用者側に寄ります（出典1・2）。

  1. Downloads フォルダでエージェントを起動しない。
  2. 自分が作っていない AGENTS.md・CLAUDE.md の有無を確認し、自分で読む。
  3. ~/.codex/config.toml の予期しない [mcp_servers.*]、.claude/settings.json の ANTHROPIC_BASE_URL のような接続先の設定を確認する。
  4. 承認ゲートとサンドボックスを有効のままにし、それを切るよう促す指示を強く疑う。
  5. 侵害が疑われたらトークンを失効・再発行する。

侵害指標は1つだけ示されています—— function-color が入っていれば、その端末は侵害されたものとして扱う（出典1）。

OpenAI と Anthropic の推奨も同じ方向です（出典2）—— 作業対象のプロジェクトの直下で起動し、作業範囲は必要最小限にとどめ、必要になってから広げる。

本記録が補うのは、3層に分けた考え方です（本記録の評価）。

  • 置かれることを防ぐ——ブラウザの保存先を都度尋ねる設定にする。
  • 読まれることを防ぐ——起動する場所をプロジェクト直下に限る。
  • 従われても止める——依存の導入を決定的な検査にかけ、通信先を許可リストで固定する。

モデルの判断を賢くする方向には賭けない（本記録の評価）—— 90%と50%という数値は、「指示に従うかどうか」が確率的であることを示しています。 確率的な層に防御を置くと、確率的にしか守れません。

「設計どおり」が攻撃面になったとき、責任は利用者側に寄せられる評価・解釈出典 [1] [2]

本記録が、この事案で最も重いと見るのはここです（本記録の評価）。

脆弱性であれば、修正が出て、適用の期限を切れます。 本件には修正がありません。 同社自身が「リスクはブラウザとエージェントの意図された挙動の組み合わせであり、備えと防御の責任は利用者に直接かかる」と書いています（出典2の整理）。

これは、組織にとって3つの意味を持ちます（本記録の評価）。

  • 1. 資産管理の対象が増えます。 開発端末の ~/.codex/config.toml や.claude/settings.json は、いまやネットワーク機器の設定と同じ性格を持ちます—— 平文で、書き換え可能で、誰も見ていません。
  • 2. 検査の対象が増えます。 リポジトリに入っている AGENTS.md はレビューを通りますが、~/Downloads に落ちたものは誰のレビューも通りません。
  • 3. 「禁止」だけでは終われません。 落としたファイルをエージェントに処理させるのは一般的な使い方だと研究者は述べています（出典2）。禁止したうえで代替の手順（一時ディレクトリへ移してから起動する等）を用意しないと、現場は元の使い方に戻ります。

そして、対象は2製品ではありません（本記録の評価）。AGENTS.md を読む実装は他にもあり、同社のテレメトリにもCursor CLI が挙がっています（出典2）。「Codex と Claude Code の問題」として扱うと、次の実装で同じことが起きます。

「およそ2年」という期間だけが示され、被害の広がりは示されていない未確定事項出典 [1] [2]

しかし、その2年の中身は公表されていません（本記録の指摘）〈未確定1〉。

  • インストールが完了した端末の数——示されていません。
  • function-color 以外のパッケージの有無——示されていません。
  • npm 上で現在も公開されているか、削除されたか——示されていません。
  • 「気づかれていなかった」の主語（業界全体か、同社の観測範囲か）——読み分けられません。

公表されたテレメトリも、すべて割合です（出典1・2）—— 顧客の約半数、測定した企業の半数、セッションの約4分の1。 母数が1つも示されていません〈未確定7〉。

BleepingComputer が伝える「数百の顧客」「Claude Code だけで1,300件超のセッション」は、Gal Weizman の同誌への説明であり、本記録が確認したブログ本文には見当たりません〈齟齬1〉。

本記録は、これらを「成立条件を満たしている人がどれだけいるか」の指標として扱い、被害規模としては扱いません（本記録の方針）。

layer 0 は攻撃側——**ウェブページが利用者の操作なしに `~/Downloads` へ `AGENTS.md`（または `CLAUDE.md`）を書き込む。** **「ウェブが自力で書き込める唯一のフォルダ」である**（出典1。原文英語）。 layer 1 は置かれたファイル——**実行ファイルではないため、 OS のダウンロード実行承認は働かない**（出典1）。 ブラウザの既定動作（Chrome・Edge・Firefox は保存先を尋ねない／ Brave は承認を求めた）が成立条件の一部になっている（出典2）。 layer 2 は実行の主体——**利用者がそのフォルダでエージェントを起動すると、 エージェントは指示ファイルを自動で読み込み、自分の道具と権限で実行する。** **Codex は90%超の試行でマルウェアを実行した**（出典1）。 layer 3 は結果——**①悪性 npm パッケージ `function-color` の導入試行** （顧客端末。**Forever Security が遮断した**）、 **②`~/.codex/config.toml`（端末全体の設定）の書き換えによる持続化**、 **③API 通信の向き先の書き換えによる OAuth ログイントークンの漏えい（約50%）**。 layer 4 は帰結——**アカウントの乗っ取りとコード実行** （再現試験での成立。実環境での発生は公表されていない）。 右端は「直す主体」——**OpenAI・Anthropic に修正すべきものは無いとされ、 対策は利用者側の運用に寄る**（出典1）。

対応の評価

評価材料がない判断は「評価材料なし」としています。結果論で断じないための区分です。
対応の巧拙を評価できる材料が公表資料から得られていません。
CISO・経営層への示唆
  • **「修正が出ない種類のリスク」を、脆弱性管理とは別の枠で持つ**
    **ベンダーは直す対象が無いと明言している** （"There is nothing here for OpenAI or Anthropic to patch."・出典1。原文英語）。 **脆弱性管理の仕組みは「修正の適用」を単位に回っているため、 本件はどの台帳にも乗らない**（本記録の評価）
    取るべき行動 **AI エージェントの利用に関する前提条件（起動していい場所・ 有効にしておく保護・禁じる設定変更）を1枚の方針にし、 四半期ごとに点検する項目として登録する。** **パッチ適用率と同じ扱いにはできないため、 「方針に沿った構成になっている端末の割合」を指標にする**
  • **開発端末の設定ファイルを、資産として管理する対象に加える**
    **攻撃の持続性は `~/.codex/config.toml`（端末全体の設定）の書き換えで 確保されており、以後どのフォルダで起動しても影響が続くとされる**（出典1）。 **平文で、書き換え可能で、誰も見ていない**（本記録の評価）
    取るべき行動 **`~/.codex/config.toml`・`.claude/settings.json` を構成管理の監視対象に入れ、 変更時に通知する。** **とくに `[mcp_servers.*]` の追加と `ANTHROPIC_BASE_URL` 等の 接続先の上書きを、変更禁止の項目として定める**（出典1の推奨に基づく）
  • **「禁止」ではなく「代替の手順」を配る**
    **落としたファイルをエージェントに処理させるのは一般的な使い方だと 研究者が述べている**（出典2）。 **禁止だけでは現場は元の使い方に戻る**（本記録の評価）
    取るべき行動 **「ダウンロードしたものを扱うときは、専用の一時ディレクトリへ移してから エージェントを起動する」手順を文書化し、 その手順を1コマンドで実行できる形にして配る。** **禁止事項の一覧ではなく、既定の作業手順として配ること**
  • **測定値の母数が無い報告を、そのまま社内の意思決定に使わない**
    **90%超・約50%・顧客の約半数という数値に、試行回数も母数も付いていない** （出典1。本記録の確認）〈未確定6・7〉。 **一方で手口の成立自体は顧客端末で実際に起きている**（出典1）
    取るべき行動 **「成立するか」と「どれくらいの確率で成立するか」を分けて扱う。** **前者（成立する）は確定として対策の根拠にし、 後者（確率）は社内資料に引くときに出所と留保を必ず添える**
セキュリティ技術者への示唆
  • **エージェントの起動場所を、プロジェクトの直下に固定する**
    **エージェントは作業ディレクトリの指示ファイルを自動で読み込む**（出典2）。 **`~/Downloads` は、ウェブが利用者の操作なしに書き込める唯一のフォルダである** （出典1。原文英語）
    取るべき行動 **`~/Downloads`・ホームディレクトリ・広い親ディレクトリでの起動を禁じ、 起動用のラッパースクリプトで作業ディレクトリを検査する。** **禁止場所で起動されたら、エージェントを立ち上げずに終了させる**
  • **`~/Downloads` 直下に指示ファイルが現れたら警報を出す**
    **この場所に `AGENTS.md`・`CLAUDE.md` を置く正規の理由が無い**（本記録の評価）—— **誤検知が少なく、置かれた段階で気づける唯一の層である**
    取るべき行動 **`~/Downloads/AGENTS.md`・`~/Downloads/CLAUDE.md`・ `~/Downloads/.cursorrules` などの出現を監視し、通知する。** **macOS なら launchd + ファイル監視、 企業端末なら EDR のファイル作成ルールで実装する**
  • **依存の導入を、モデルの判断ではなく決定的な検査で止める**
    **本件で遮断が効いたのは、`function-color` が既知の悪性パッケージだったからである** （出典1。本記録の整理）。 **指示に従うかどうかは90%・50%という確率の問題であり、 確率的な層に防御を置くと確率的にしか守れない**（本記録の評価）
    取るべき行動 **パッケージの導入前に、名前・公開日・取得元・ダウンロード数を 機械的に突き合わせる検査を入れる（導入は検査を通ってからにする）。** **`npm install` をエージェントの承認不要の操作から外す**
  • **エージェントの通信先を許可リストで固定する**
    **攻撃は API 通信の向き先を攻撃者のサーバへ書き換えることで OAuth トークンを奪っている**（出典1）。 **エージェントの通信先は本来少数の固定された宛先である**（本記録の評価）
    取るべき行動 **開発端末の外向き通信で、エージェントの接続先を許可リストに限る。** **`ANTHROPIC_BASE_URL` 等の環境変数・設定による上書きを無効化し、 上書きが検出されたら警報を出す**
  • **侵害の確認手順を1つ決めておく**
    **同社が示した侵害指標は「`function-color` が入っていれば、 その端末は侵害されたものとして扱う」の1点である**（出典1）
    取るべき行動 **全開発端末に対して `function-color` の有無を一括確認する手順を用意し、 検出時はトークンの失効・再発行と端末の再構成を行う。** **確認は1回で終わらせず、依存ツリー（間接依存）まで見る**
