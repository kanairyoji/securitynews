INC-2026-0710uCreator 正規アプリ内で動く諜報基盤

**正規のメッセンジャーアプリの「中身」に入り込んで動く Android スパイウェアが、 レンタル型の製品として多年にわたり売られていた。** 研究者 Ovi は2026年10月21日、**uCreator（uCreater）／YingGai** と呼ばれる Android スパイウェア基盤の解析結果を公表した（出典1）。 **偽の画面を重ねる（オーバーレイ）従来の銀行マルウェアと違い、 正規アプリの中に実行時フックで入り込み、 ログイン済み・復号済みの状態のデータに内側から触る**（出典1・出典2）〈重要〉。 **Telegram モジュールは、アプリの生きたデータベースへ運用者が渡した SQL を直接実行でき （`Db_MessagesStorageRawQuery`）、二段階認証のパスワードを ハッシュ化される前の平文で取得する（`SRPHelper.getX` のフック）**（出典1）。 **セッション一覧から自分の端末を消す機能まで備える**（出典1）。 **コードで対応が確認された対象アプリは約20で、WeChat・WeCom・QQ・Telegram・WhatsApp・ LINE・Zalo・KakaoTalk・Viber・MoMo・GCash の名が挙がる**（出典1）〈重要〉。 **公開の端緒は、運用者側の自前 GitLab が IP 制限から外れて露出していたことである** （出典1）——**C2 のソースコード・設定・コミット履歴が丸ごと読める状態だった。** **帰属は長沙・湖南の3社に結び付く痕跡があるが、共通の所有者は「もっともらしいが 未証明」のままである**（出典1）。 **被害端末数も顧客数も確立していない**〈未確定1〉。

研究者 Ovi は2026年10月21日、Android 向けスパイウェア基盤uCreator（uCreater） の解析結果を公表しました（出典1）。製品ブランドは YingGai（鹰盖） 系で、レンタル型の多テナント基盤として下流の運用者に売られていたとされます（出典1・出典2）。

従来の銀行マルウェアとの違いが、この事案の中心です（本記録の評価）〈重要〉。

技術的な土台は3つの既存技術です（出典1・出典2）。

  • VirtualApp — 別アプリを自身のプロセス内のコンテナで動かす
  • LSPatch — root 権限なしに、改造 APK へコードフックを統合する
  • Pine — Android のランタイム（ART）をインラインでフックする

Ovi の評価は、これらが新しいからではなく「製品になっているから」notable だという点です（出典1・出典2）。

「uCreater が注目されるのは、これらの技術を再利用可能で遠隔管理される製品に変えているところである」（出典2。原文英語。訳は本記録）

Telegram モジュールの能力は、認証情報の窃取という表現では足りません（出典1）。

  • Db_MessagesStorageRawQuery — 運用者が渡した SQL を、アプリの生きたデータベースに対して直接実行し、結果を返す
  • SRPHelper.getX のフック — 二段階認証のパスワードを、ハッシュ化される前の平文で取得して保存する
  • セッションの一覧・失効、電話番号の変更・確認、アカウントの削除、利用者のロックアウト
  • 自分のセッションを被害者の端末一覧から消す〈重要〉

Ovi は、これらが「ソースコードが示す能力」であり、「すべての操作が被害者に対して実際に成功したこと」ではないと明示しています（出典1・出典2）。

公開の端緒も記録に値します（出典1）。運用者の自前 GitLab サーバが IP 許可リストから外れて露出しており、C2 の基盤のソースコード・設定・運用情報が丸ごと読める状態でした（研究者 Jurre の協力により判明。出典1・出典2）。

攻撃の経過

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

**形は「非公式経路から改造版アプリ（またはコンテナアプリ）を導入させる → インストール後に対象別のコードを取得する → 正規アプリの内部にフックで入り込む → 局所コマンドサーバ経由で運用者が操作する → OSS／Redis 経由で持ち出す」である** （出典1・出典2。段階への割り当ては本記録）。 **この経路の特徴は、攻撃者が「外から」何かを注入しないことである**（本記録の評価） 〈重要〉 ——**利用者がアプリを入れた後は、すべてアプリの内部で起きる。**

  1. 1. 初期侵入確認済
    **改造版の Telegram・Telegram-X・WeChat・GCash 等を、 サイドローディングまたはソーシャルエンジニアリングによって導入させる** （出典2）。 **再パッケージした APK は比較的薄くてよい**（出典2）〈重要〉 ——**対象別の計装は、インストール後に運用者の Alibaba OSS と MinIO から 取得される。**
    根拠: **「再パッケージされた APK は比較的薄くてよい。対象別の計装は、 インストール後に運用者の Alibaba OSS と MinIO のインフラから取得される ——`Huuk_<target>` や `fengzhuang-app`（文字どおり「包装」）と名付けられた バケットとパスを含む。配布ホストには `telegram-apk.uzyzx.com` がある」** （出典2 が引く Ovi の言葉。原文英語。訳は本記録）。
  2. 2. 実行確認済
    **LSPatch で改造 APK にフックを統合するか、`assets/TgJarPine.dex` から Pine で注入する**（出典1・出典2）。 **WeChat の場合は VirtualApp のコンテナ（`va_vx`／洋葱盒子）の中で動かす** （出典1・出典2）。
    根拠: **「LSPatch は元の APK を `cache/lspatch/origin/*.apk` の下に保存する。 このパスまたは特定の資産の存在が、感染端末の識別に役立つ」** （出典2。原文英語。訳は本記録）。
  3. 3. 認証情報アクセス確認済
    **Telegram の `SRPHelper.getX` をフックし、二段階認証のパスワードを ハッシュ化される前の平文で捕捉して持ち出しのために保存する**（出典2）。 **WeChat では `_2_0_UploadAppLoginInfo` でログインの識別情報を取得する**（出典2）。
    根拠: **「モジュールは Telegram の `SRPHelper.getX` ルーチンもフックし、 二段階認証のパスワードをハッシュ化の前に平文で捕捉し、 持ち出しのために保存する」**（出典2。原文英語。訳は本記録）。
  4. 4. 収集確認済
    **局所コマンドサーバ（約40の番号付きハンドラ）経由で、 端末の監視・連絡先と SMS の収集・インストール済みアプリの列挙・ メッセージ送信・チャット履歴の取得・セッション管理・ アカウント関連の操作を行う**（出典2）。 **Telegram では `Db_MessagesStorageRawQuery` により、 運用者が与えた SQL をアプリの生きたデータベースへ直接実行する**（出典2）。
    根拠: **「その `Db_MessagesStorageRawQuery` ハンドラは運用者が与えた SQL を受け取り、 Telegram のオブジェクトを再生成する互換クラスを通じて結果を返す。 これは、アプリが動作している間、本来は暗号化または局所保存の中で 保護されるはずの情報を露出させうる」**（出典2。原文英語。訳は本記録）。
  5. 5. 検知回避確認済
    **自分のセッションを被害者の端末一覧から消す**（出典2）〈重要〉。 **バックエンドは、セキュリティ制御の作動を避けるよう活動を日程化する**（出典2）。
    根拠: **「自分のセッションを被害者の端末一覧から削除することもでき、 運用者のアクセスを隠しうる」**（出典2。原文英語。訳は本記録）。
  6. 6. 持ち出し確認済
    **署名付き JSON のビーコンが `/api/callback/Tg*` 配下へ報告し、 更新と追加のコードは Alibaba OSS と MinIO を通じて届く**（出典2）。 **WeChat ではアプリのデータを梱包して OSS へ上げ、アカウントの複製に用いる** （出典2）。 **連絡先は `contacts.vcf` の形で扱われる**（出典1・出典2）。
    根拠: **「`_2_0_UploadAppLoginInfo` コマンドはログインの識別情報を取得し、 その後アプリのデータが梱包され、OSS へアップロードされ、 アカウントの複製に用いられうる」**（出典2。原文英語。訳は本記録）。
  7. 7. 影響（暗号化・破壊・改ざん）推定
    **アカウントの乗っ取り（セッションの失効・電話番号の変更・ アカウントの削除・利用者のロックアウト）と、 WeChat アカウントの複製が可能である**（出典2）。 **モバイルウォレット（GCash・MoMo）と認証コードの窃取に焦点があることから、 Ovi は金銭目的の犯罪と評価している（証明された事実としてではなく評価として）** （出典2）。
    根拠: **「リセラーのモデル、モバイルウォレットへの注力、 認証コードの窃取は、金銭目的の犯罪を示唆するが、 研究者はこれを証明された事実ではなく評価として提示している」** （出典2。原文英語。訳は本記録）。

偽の画面を重ねるのではなく、正規アプリの内側で動く原因・手口

この事案の中心は、手口の「位置」である（本記録の評価）。

従来の銀行型トロイ（例: Zimperium が記録した GodFather）は、アプリを仮想コンテナで動かしたうえで偽のオーバーレイを表示し、利用者が入力した認証情報を奪う（出典2）。

uCreator はオーバーレイを使わない（出典2）〈重要〉。

事案の詳細

how_it_runs**3つの既存技術の組み合わせである**（出典1・出典2）。 **①VirtualApp——別アプリを自身のプロセス内のコンテナで動かす。** **②LSPatch——root 権限なしに、改造 APK へコードフックを統合する。** **③Pine——Android のランタイム（ART）をインラインでフックする。** **結果として、悪意あるコードは、正規アプリがログイン済みで 復号済みのデータに触れている状態の「内側」で動く**（出典2）〈重要〉。 **Telegram 系はモジュールを LSPatch で統合するか、 資産 `assets/TgJarPine.dex` から Pine で注入する**（出典1・出典2）。 **WeChat は VirtualApp のコンテナ（`va_vx` または洋葱盒子＝Onion Box のホスト）の中で 動かす形をとる**（出典1・出典2）。
difference_from_overlay**Zimperium が記録した銀行型トロイの GodFather は、 アプリを仮想コンテナで動かしたうえで偽のオーバーレイを表示して 認証情報を奪う**（出典2）。 **uCreator はオーバーレイに依存せず、実アプリの内部で動作する**（出典2）〈重要〉 ——**XposedBridge のフック、リフレクション、 アプリ自身のデータベースインターフェースへのアクセスを使う**（出典2）。 **これにより、ログイン画面の先にまで到達し、 提供元がモジュールを作ればどのアプリにも対応しうる**（出典2）。 **Ovi は両者を結び付ける証拠は見つけていない**（出典2）。
local_command_server**フック対象の各アプリの中に、局所的なコマンドサーバが埋め込まれている** （出典1・出典2）〈重要〉。 **`IHttpDoc` インターフェースで自己記述された、約40の番号付きハンドラを公開しており、 説明とパラメータが付いているため運用者が利用可能な機能を発見できる**（出典1・出典2）。 **対応するのは、端末の監視、連絡先と SMS の収集、 インストール済みアプリの列挙、メッセージ送信、チャット履歴の取得、 セッション管理、アカウント関連の操作である**（出典2）。
telegram_module**`Db_MessagesStorageRawQuery` は、運用者が与えた SQL を アプリの生きたデータベースに対して直接実行し、 Telegram のオブジェクトを再生成する互換クラスを通じて結果を返す**（出典2）〈重要〉 ——**アプリが動作している間、暗号化されたデータや局所に保存されたデータの中で 本来は保護されるはずの情報が露出しうる**（出典2）。 **`SRPHelper.getX` のフックは、二段階認証のパスワードを ハッシュ化される前の平文で捕捉し、持ち出しのために保存する**（出典2）〈重要〉。 **さらに、セッションの一覧・失効、連携電話番号の変更・確認、 アカウントの削除、利用者のロックアウトに対応し、 自分のセッションを被害者の端末一覧から消すこともできる**（出典2）。 **Ovi は、これらはソースコードが能力を示すものであり、 すべての操作が被害者に対して実際に成功したことを示すものではないと強調している** （出典2）〈重要〉。

    **本件が届く条件は、非公式経路から改造版アプリを入れること、 または提供元のコンテナアプリの中でアプリを動かすことに絞られている** （出典3。出典1・出典2 も同旨）〈重要〉。 **端末の脆弱性を突いて勝手に入ってくるものではない**（本記録の整理）。
    取るべき行動 **MDM／EMM で「提供元不明のアプリのインストール」を禁止する設定が 業務端末に適用されているかを確認する。** **BYOD では、業務アプリを動かす条件として同設定を要求する。** **併せて、海外拠点・渡航者が必要とする現地アプリの正規の入手経路を 一覧として提供する**（本記録の提案） ——**禁止だけを出すと迂回される。**
  • 「ログイン中の端末一覧の確認」を、アカウント乗っ取り対策の最後の砦に据えない。
    **本件のモジュールは、自分のセッションを被害者の端末一覧から削除できる** （出典2）〈重要〉——**利用者が自力で確認できる唯一の手がかりが潰される。** **さらに、二段階認証のパスワードはハッシュ化される前の平文で取得される**（出典2）。
    取るべき行動 **メッセンジャーや SaaS のアカウント保護について、 「利用者が自分で確認する」手段に依存している箇所を洗い出す。** **業務で使うアカウントは、サービス側の管理機能（組織管理・ デバイス承認・条件付きアクセス）で統制する**（本記録の提案） ——**個人の目視確認に委ねている範囲は、本件の形では無効になる。**
  • 「対応モジュールが存在する」と「被害が出た」を混同しないが、前者で備える判断をする。
    **コードで対応が確認された対象アプリは約20で、LINE・KakaoTalk・Viber・ WhatsApp・Zalo・MoMo・GCash の名が挙がる**（出典1）〈重要〉。 **一方、被害端末数も顧客数も確立していない**〈未確定1〉。 **Ovi は対象の全体像を「still unknown」としている**（出典1）。
    取るべき行動 **自組織の業務で使っているメッセンジャー・ウォレットが 対象アプリの一覧に含まれるかを確認する。** **含まれる場合、被害事例の報告を待たずに、 導入経路の抑止と端末側の点検を先に実施する**（本記録の提案） ——**「日本での被害報告が無い」は、対策を遅らせる理由にならない。**

    **Doctor Web は Baohuo について累計5万8,000台以上を報告しており**（出典4）、 **The Hacker News は uCreator の Telegram 部分が Baohuo に一致するとしている** （出典3）〈齟齬3〉。 **しかし Ovi のレポートに Baohuo への言及は無く**（本記録の確認）、 **本記録は一致を主張する報道の本文を取得できていない**〈齟齬5〉。

セキュリティ技術者への示唆
  • root 検知に依存した端末健全性の判定を見直す。本件は root を要しない。
    **LSPatch は root 権限なしに改造 APK へコードフックを統合する**（出典1・出典2） 〈重要〉。 **Pine は Android のランタイムをインラインでフックする**（出典1）。 **root 検知では見つからない**（本記録の評価）。
    取るべき行動 **アプリ側の端末健全性チェックに、 ①自アプリの署名者の検証 ②`cache/lspatch/origin/*.apk` のような フック基盤の痕跡の確認 ③自プロセス内のフックの検出（可能な範囲で）を足す。** **root 検知の有無だけを合否の基準にしない**（本記録の提案）。
  • 配布時点の APK を調べる検査だけでは足りない。中身は後から降りてくる。
    **「再パッケージされた APK は比較的薄くてよい。対象別の計装は、 インストール後に運用者の Alibaba OSS と MinIO のインフラから取得される」** （出典2。原文英語。訳は本記録）〈重要〉。 **静的解析の時点では、見るべきものがまだ存在しない**（本記録の評価）。
    取るべき行動 **アプリの検査を、静的解析とインストール後の挙動観察の2段で行う。** **とくに、インストール直後に外部のオブジェクトストレージから コードまたは DEX を取得する挙動を異常として扱う**（本記録の提案）。
  • 固定ドメインの遮断に頼らない。C2 のアドレスは Redis から配られる。
    **「実装は C2 のアドレスを Redis の `Domain` キーから取得し、 チャネルごとに値を選べる。アドレスはキャッシュされ固定値への フォールバックもあるため、ビルドによってコールバック先のドメインが異なる」** （出典2。原文英語。訳は本記録）〈重要〉。
    取るべき行動 **ブロックリストの更新に依存した対策を、唯一の手段にしない。** **通信の内容を見られる環境では、`/api/callback/Tg*` のような 経路の形（パスの型）を検知条件に加える**（出典2 の記述に基づく本記録の提案）。 **ただし、通信先が大手クラウドのオブジェクトストレージであるため、 ドメイン単位の遮断は業務影響を伴う**（本記録の明示）。
  • アプリ内の指標（パッケージ名）だけで悪性と判定しない。正規名を名乗る。
    **指標に挙がるパッケージ名には、正規の Telegram 系アプリの名前 （`org.thunderdog.challegram`・`org.telegram.messenger.web`）が含まれる** （出典1）〈重要〉。 **また、タイ所在の中継は賭博サイト・広告アカウントのサービス・ SMS のサービスも提供していた**（出典2） ——**IP の観測だけで本件と結び付けられない。**
    取るべき行動 **パッケージ名による判定は、必ず署名者の検証と組み合わせる。** **IP アドレス単位の指標は、同居するサービスの有無を確認してから使う。** **本記録に記載した指標は出典1 の写しであり、 本記録は悪性を検証していない**（本記録の明示）〈齟齬6〉 ——**これを根拠に検知を組まないこと。**
  • 端末 OS の更新を、緩和策として位置づける（恒久的な防御ではない）。
    **Ovi は Pixel 10 Pro（Android 17）で検証し、 同梱の Pine エンジンが内部 API の変更により動かないことを確認した**（出典2）。 **最新サンプル（2026年7月29日）も古いエンジンのままである**（出典2）。 **ただし、Pine を更新すれば機能は回復しうるし、他の機種は未検証である**（出典2） 〈重要〉。
    取るべき行動 **業務端末の OS 更新を、本件に対する緩和として明示的に数える （「効果があるが恒久ではない」と注記する）。** **更新だけを対策として報告しない**（本記録の提案） ——**エンジンの更新で回復しうることを併記する。**
