INC-2026-0718npm testmetest が実在42repo汚染

npm の「testmetest」キャンペーンは試験ではなかった—— 11名義の実在リポジトリ42件に、AIコーディング支援（Claude・Gemini・Cursor）と VS Code の起動フックを仕込み、12.9〜13.7MB の肥大化した塊で GitHub の検索とAPIの探索を外していた

初報: 2026年10月26日（JFrog のレポート公開日） 最終更新: 2026年10月27日（本記録の作成時点）

SafeDep が2026年10月に npm 上で見つけた「testmetest」キャンペーンは、当初「運用者自身の試験アカウントだけで、第三者のパッケージも被害者も無い」と評価されていた（出典2）。JFrog は2026年10月26日、この評価が成り立たないことを示した（出典1）——「運用者は、確立した開発者と組織に属する実在のリポジトリを、すでに武装化していた」（出典1。原文英語。訳は本記録）。武装化された実在リポジトリは11名義にまたがる42件である（出典1）。

この事案の読みどころは、見逃された理由のほうにある（本記録の評価）。仕込まれた塊（init.js）は 12.9〜13.7MB あり、GitHub のコード検索とAPIがこの種の侵害を探すときに通る経路から外れる大きさだった（出典1）〈重要〉——「大きすぎて見つからない」。 JFrog は、コード検索ではなく Git のツリーを直接列挙して探すよう勧めている（出典1）。

起動の仕掛けは、AIコーディング支援と IDE の設定ファイルである（出典1）。.claude/settings.json の SessionStart フックはnode .github/init.js || bun .github/init.js を走らせる（出典1）——リポジトリを開いた時点で実行される。 .gemini/settings.json・.cursor/mcp.json・.cursor/rules/setup.mdc・.vscode/tasks.json も同様に仕込まれていた（出典1）。

ワームは資格情報を盗み、リポジトリと CI 設定を改変し、npm 経由で広がる（出典1・出典3）。加えて、盗まれた GitHub トークンを被害者が無効化したときにホームディレクトリを削除するワイパーを備える（出典3）——「永続化を除去する前にトークンを無効化してはならない」（出典1 の勧告。訳は本記録）〈重要〉。

攻撃の経過

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

**形は「npm パッケージの導入時に `binding.gyp` のコマンド展開で実行 → GitHub／npm の資格情報を盗む → その名義で実在リポジトリに AI／IDE の起動フックと肥大化した塊を仕込む → OIDC トークンを npm トークンへ交換して新たなパッケージを公開する → 暗号化した封筒を運用者のリポジトリへ置く」である** （出典1。段階への割り当ては本記録）。 **この経路の特徴は、2つの入口が併存することである**（本記録の評価）〈重要〉 ——**`npm install` を実行した者と、武装化されたリポジトリを AI 支援ツールで 開いた者の両方が、実行の契機になる。**

  1. 1. 初期侵入確認済[1]
    **汚染された npm パッケージを導入した時点で実行される**（出典1）。 **`binding.gyp` のコマンド展開を使うため、 `package.json` に宣言されたインストールスクリプトは無い**（出典1）〈重要〉 ——**「install スクリプトの有無」を見る検査をすり抜ける**（本記録の評価）。 **別の経路として、`@iobandamwer/cache-helper` のような ネイティブアドオン型のパッケージは `addon.node` を同梱し、 `postinstall` で `.napi_cache` を `0x96` の XOR で復号して 切り離したプロセスで `node` に渡す**（出典1）。
    根拠: **「npm ワームは、宣言されたインストールスクリプトが無いにもかかわらず、 `binding.gyp` のコマンド展開を通じてインストール時に実行された」** （出典1。原文英語。訳は本記録）。 **エラーは黙って飲み込まれる**（出典1）。
  2. 2. 実行確認済[1] [3]
    **ローダは Caesar 変換・AES-128-GCM・Bun 1.2.18 を使う**（出典1）。 **ビルドによって、`bun run -` で走るものと、 一時ディレクトリ `.b-*` から走るものがある**（出典1）。 **ネイティブアドオンを使って別のペイロードを復号・起動する版もある**（出典1・出典3）。
    根拠: **「マルウェアは、別のペイロードを復号して起動するために、 コンパイルされたネイティブアドオンを使う」**（出典3。原文英語。訳は本記録）。
