INC-2026-0738署名済みAIアプリに偽DLLを同梱するYoba

Check Point Research が、**AI デスクトップアプリを装った偽の GitHub リポジトリ**で マルウェアを配る攻撃キャンペーン **Yoba** を公表した。 **攻撃者は「GPT-5.6 Sol」「GPT-6 Astra」「Claude Opus」という 存在しない製品名のリポジトリと GitHub.io のページを作り、 ZIP 形式のリリースとしてマルウェアを置いた**。 **ZIP の中身の要は、OpenAI および Anthropic が正規に署名した `Setup.exe` を そのまま同梱し、その隣に偽の `winmm.dll` を置いていたことである**〈重要〉—— **実行されるのは署名された正規の実行ファイルで、 悪性コードは DLL の横取り（DLL サイドローディング）で読み込まれる**。 **攻撃者は専用の C2 サーバを持たない**—— **Telegram のチャンネルのプロフィール画像から URL の種を取り、 Google の DNS over HTTPS（DoH）の TXT レコードで次の指示を受け、 ペイロードは Catbox（ファイル共有サービス）から取る**。 **最終的に入るのは暗号資産採掘ソフト XMRig 6.26.0 で、`svchost.exe` に注入される**。 **ただし読み込み器（YobaLoader）は汎用であり、別の種類のマルウェアを 配ることもできる作りである**（出典1）。 **攻撃者はロシア語など CIS 諸国のキーボード配列を持つ端末への感染を避けており （ウクライナ語は明示的に除外から外されている）、 Check Point はロシア系をうかがわせる兆候があるとしている**。 **被害端末数・感染件数・日本の組織への影響はいずれも公表されていない**。

署名は本物だった。偽物は、その隣に置かれた DLL である。

Check Point Research は2026年10月27日、Yoba と名付けた攻撃キャンペーンを公表した（出典1）。攻撃者は AI ツールの人気に便乗し、「GPT-5.6 Sol」「GPT-6 Astra」「Claude Opus」という存在しないデスクトップ製品のリポジトリと GitHub.io のページを作って、ZIP 形式のリリースにマルウェアを置いた（出典1）。

ZIP の中身の作りが本件の核心である（出典1）〈重要〉。OpenAI および Anthropic が正規に署名した Setup.exe を同梱し、その隣に偽の winmm.dll を置く。 利用者が起動するのは署名された正規の実行ファイルであり、悪性コードはその実行ファイルが隣の DLL を読み込むときに動き出す。 つまり、署名の検証は通る。改ざんもされていない。

投入された偽 DLL（YobaDropper）は、解析を避ける細工を重ねている（出典1）。自分を読み込んだ実行ファイルの名前を DJB2 で計算し、Setup.exe でなければSleep(5500) を20万回——約12.73日——繰り返して何もしない。 キーボード配列を見て CIS 諸国の言語であれば感染しない（ウクライナ語は除外から明示的に外されている）。

管制の経路に専用のサーバが無い（出典1）〈重要〉。Telegram のチャンネルのプロフィール画像の末尾50バイトを種にドメイン名を組み立て、Google の DoH で TXT レコードを引き、Ed25519 の署名を検証してからAES-ECB で復号してペイロードの URL を得る。ペイロードは Catbox から取る。

最後に入るのは暗号資産採掘ソフト XMRig 6.26.0 で、svchost.exe に注入される（出典1）。採掘先は Tor の onion の端点で、利用者の操作が検知されると採掘を止める（出典1）。

ただし Check Point は、読み込み器（YobaLoader）が汎用であり、今後の波では別のマルウェアが配られうると明記している（出典1）〈重要〉—— 仕掛けの重さと、現時点のペイロードの軽さは釣り合っていない。

攻撃の経過

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

**本件は実在のキャンペーンの解析であり、仮想の経路ではない**（出典1）。 **ただし被害の規模は公表されていない**〈未確定1〉—— **以下は出典1 が示した経路の整理である**（本記録の整理）。 **工程の特徴は、攻撃者が用意したものが極端に少ないことである** （本記録の評価）〈重要〉—— **実行ファイルは正規の署名済み、配布基盤は GitHub、 管制は Telegram・Google DoH・Catbox、採掘先は Tor。 攻撃者自身の持ち物は偽 `winmm.dll` と暗号鍵だけである。**

  1. 1. 初期侵入[1]
    **攻撃者は存在しない AI 製品名（GPT-5.6 Sol・GPT-6 Astra・Claude Opus）の GitHub リポジトリと GitHub.io のページを作り、 ZIP 形式のリリースとしてマルウェアを置いた**（出典1）。 **星やフォークの水増しは行われていない**（出典1）—— **それでも Google の検索結果の上位に出ており、 Check Point は SEO ポイズニングによるものとみている**（出典1）。 **ZIP にはパスワードが掛けられていない**（出典1）〈重要〉—— **Check Point は「解析回避の細工が十分で検知率が低かったため、 パスワードで守る必要が無かった」と評価している**（出典1）。
  2. 2. 実行[1]
    **利用者が ZIP を展開して `Setup.exe` を起動する**（出典1）。 **`Setup.exe` は OpenAI（または Anthropic）が正規に署名した 実行ファイルそのものである**（出典1）〈重要〉。 **同じフォルダに置かれた偽 `winmm.dll` が横取りで読み込まれ、 その `DllEntryPoint` から悪性コードが動き出す**（出典1）。 **偽 DLL は正規の `winmm.dll` の輸出関数の名前を180個並べているが、 中身はすべて `return`（C3）と NOP（90）である**（出典1）—— **読み込み時の解決を通すためである**（本記録の整理）。 **ZIP には他にも正規に見えるファイル （`snapshot_blob.bin`・`vk_swiftshader.dll`・`vulkan-1.dll` 等）が 同梱されており、Check Point はコンパイル時刻の比較で 悪性ファイルを特定している**（出典1）。
  3. 3. 検知回避[1]
    **投下器は3つの回避の細工を持つ**（出典1）。 **①自分を読み込んだ実行ファイルの名前の DJB2 ハッシュを `0xE6C2F326` と比較し、`Setup.exe` でなければ Sleep(5500) を20万回（約12.73日）繰り返しながら 局所の UTF-16 の緩衝に `pddy` を書き足し続ける**（出典1）—— **処理は終了しない**（出典1）〈重要〉。 **②キーボード配列の言語 ID が `0x19`〜`0x44` の範囲にあるかを見て、 ビットマスク `0xEC0400C8401` で CIS 諸国かを判定し、感染を避ける。 `0x22`（ウクライナ語）は明示的に例外とされ、除外から外されている**（出典1）。 **③Windows の API を `kernel32.dll`・`ntdll.dll` から 関数名の DJB2 ハッシュの比較で動的に解決する**（出典1）—— **輸入テーブルに痕跡を残さない**（本記録の整理）。 **初期（2026年6月）の変種にはデバッガ検知・仮想環境検知もあったが、 後の版では取り除かれ、地域の絞り込みが投下器へ移された**（出典1）。
  4. 4. 権限昇格[1]
    **投下器は管理者権限を要する**（出典1）。 **権限が無い場合は、管理者として再実行するよう促す画面を出す**（出典1）〈重要〉—— **昇格は攻撃者の技術ではなく、利用者の操作で得られている**（本記録の整理）。 **権限を得たのち、XOR で復号したファイルを `ProgramData\WMProcess` に展開し、 `WMPDMC.exe` を複製して読み込み器を `wmpdui.dll` として書き出す**（出典1）。
  5. 5. 永続化[1]
    **起動から3分遅らせて、複製した `WMPDMC.exe` を Local System として 実行する予定実行（スケジュールタスク）が作られる**（出典1）。 **タスクには Microsoft の体裁の説明が付けられている**（出典1）。 **読み込み器（`wmpdui.dll`）は `WMPDMC.exe` の下でのみ動き、 2つ目の DJB2 のハッシュ検査（種が別）で API を解決する**（出典1）—— **投下器と同じ考え方の、二重の宿主の検査である**（本記録の整理）。
  6. 6. C2通信[1]

第一の細工は宿主の検査である（出典1）。自分を読み込んだ実行ファイルの名前を DJB2 で計算し、ハードコードされた 0xE6C2F326 と比べる。 期待される名前は Setup.exe である。 DLL を単体でサンドボックスに入れても、この検査は通らない。

重要なのは、検査に失敗したときの振る舞いである（出典1）〈重要〉。処理は終了しない。 Sleep(5500) を20万回——約12.73日——繰り返しながら、復号した詰め物の文字列 pddy を局所の緩衝に書き足し続ける。

これは「落ちる」設計ではなく「終わらない」設計である（本記録の評価）。落ちれば、クラッシュとして記録が残る。終わらなければ、自動解析の側は時間で打ち切るほかなく、結果は「何もしなかった」になる。 そして「何もしなかった」は、多くの仕組みで無害と記録される。

第二の細工は地域の絞り込みである（出典1）。キーボード配列の言語 ID が 0x19〜0x44 の範囲にあるかを見て、ビットマスク 0xEC0400C8401 の対応するビットで CIS 諸国かを判定する。言語 ID を1つずつ比較するのではなく範囲とビットマスクで見る形は、過去に Bazarloader が使っていた手法（ビットマスク 0xD8080190C03）に近い（出典1）。0x22（ウクライナ語）は明示的に例外とされ、除外から外されている（出典1）。

第三の細工は API の解決である（出典1）。kernel32.dll・ntdll.dll の輸出関数の名前を DJB2 で突き合わせて動的に解決する——輸入テーブルに痕跡を残さない（本記録の整理）。

なお、初期（2026年6月）の変種にはデバッガ検知・仮想環境検知もあったが、後の版では取り除かれている（出典1）。攻撃者は仕掛けを足すのではなく、削って軽くしている（本記録の評価）—— 検知率が十分に低ければ、重い細工は要らないという判断である。 実際、ZIP にパスワードが掛けられていないことについてCheck Point は「検知率が低かったので守る必要が無かった」と述べている（出典1）。

専用の C2 を持たないため、遮断すべき宛先が業務で使う正規サービスと重なる評価・解釈

一方で、この作りは攻撃者の側にも制約を課している（本記録の評価）。種を運ぶのは Telegram のチャンネルのプロフィール画像である（出典1）—— そのチャンネルが止まれば、新しい指示の経路は失われる。 攻撃者は専用の基盤を持たない代わりに、他人の基盤の存続に依存している。

検知として現実的に残るのは、構成で潰せる部分である（本記録の評価）—— 端末から直接出る DNS over HTTPS を止め、組織の解決器に集約すること。 集約すれば .dedyn.io の TXT レコードの問い合わせが見える。 ただし DGA で生成されるドメインは種によって変わるため、固定の宛先を遮断する運用では当たらない（出典1。整理は本記録）。
