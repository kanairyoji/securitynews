INC-2026-0757Convertr の共有解析スクリプト改ざん

EC セキュリティ企業 Sansec は2026年10月26日、**ブラジルの EC プラットフォーム Convertr が自社管理のサーバで配信していた Plausible の解析スクリプトが改ざんされ、 同プラットフォームを使うすべての加盟店の決済ページでカード情報が窃取されていた**と 公表した（出典1）。 **Sansec は2026年10月24日 23:22 UTC にスキマーを検知し、 窃取対象はカード番号・有効期限・CVV・カード名義人・CPF（ブラジルの納税者番号）の 5項目で、決済フォームと決済 API へのリクエストの双方から取得されていたとしている** （出典1）。 **侵入経路について Sansec は、Convertr が2025年に導入し更新していなかった Plausible Community Edition 3.0 の脆弱性 CVE-2026-8467（認証なしで /storybook に 到達でき、サーバ上でコマンドを実行できる）の悪用を疑うとしているが、 サーバログを確認しておらず確定していないと明記している**（出典1）。 **Convertr は2026年10月27日 12:54 UTC にスキマーの除去と Plausible の パッチ適用済み版への更新を報告し、加盟店・決済事業者・当局へ通知中としたと 伝えられている**（出典1・2）。 **Convertr はブラジルのファッションブランド数十社のオンラインストアと 決済を支えており、加盟店の販売総額は R$20億超とされる**（出典1・2）。

委託先・再委託先起因で委託元多数に波及不正アクセス・侵害初報のみ有名事象として記録（日本と直接の関係は薄い）脆弱性の放置委託先・供給元起因設計・実装上の不備
初報: 2026年10月26日（Sansec の調査公表） 最終更新: 2026年10月28日（本記録の作成時点）

これは、決済ページに読み込ませていたアクセス解析のスクリプトが、そのまま全加盟店のスキマーになった事案である。

改ざんされたのは1つのファイルである（出典1）—— analytics.convertr.app.br/js/script.pageview-props.tagged-events.js。 Plausible（Google Analytics の代替となるオープンソースの解析ツール）の正規のトラッカーの末尾に、eval で実行される難読化コードが追加されていた（出典1）。

このファイルは、Convertr を使うすべての加盟店の決済ページで読み込まれる（出典1）〈重要〉—— Convertr はブラジルのファッションブランド数十社のストアと決済を支えており、加盟店の販売総額は R$20億超とされる（出典1・2）。1ファイルの改ざんが、そのまま全加盟店の決済ページに及んだ。

窃取された項目は5つである（出典1）—— カード番号・有効期限・CVV・カード名義人・CPF（ブラジルの納税者番号）。 取得元は決済フォームと、決済 API へ送るリクエストの双方である（出典1）。

攻撃者は2日後に精度を上げている（出典1）〈重要〉—— 10月24日の初期版は汎用的な項目名の照合だったが、10月26日には Convertr の決済 API の正確な項目名を狙う版に更新された。 プラットフォームの中を観察して作り直したことになる（本記録の評価）。

露出は約3日続いた（本記録の算出）—— 改ざん前の最後の正常なトラッカーが2026年10月24日 05:03 UTC、正常化の確認が10月27日 13:08 UTC である（出典1）。Sansec は、ブラウザのキャッシュにより除去後も最大24時間は悪性スクリプトが残りうると警告している（出典2）。

本件の構造は、ファイル1つで説明できる。

改ざんされたのはanalytics.convertr.app.br/js/script.pageview-props.tagged-events.jsである（出典1）。Plausible（Google Analytics の代替となるオープンソースの解析ツール）の正規のトラッカーで、Convertr が自社管理するサーバで配信していた（出典1・2）。

改ざんの形は「置き換え」ではなく「追加」である（出典1）〈重要〉—— 標準の Plausible スクリプトの末尾に、eval で実行される難読化コードが足されていた。 解析の機能はそのまま動くため、挙動の変化として表に出にくい（本記録の評価）。

そしてこのファイルは、Convertr を使うすべての加盟店の決済ページで読み込まれる（出典1）〈重要〉—— Sansec は「全加盟店がこのトラッカーを読み込んでいたため、Convertr のすべての決済が影響を受けた」としている。

加盟店の側から見ると、これは自社では防げない形である（本記録の評価）〈重要〉—— 改ざんされたのは自社のサーバでもコードでもない。 自社の決済ページが、プラットフォーム提供元のドメインからスクリプトを読み込んでいる、という構成だけが条件である。

侵入経路は確定していない〈未確定1〉。Sansec は、Convertr が2025年に導入して更新していなかったPlausible Community Edition 3.0 の脆弱性 CVE-2026-8467（認証なしで /storybook に到達でき、サーバ上でコマンドを実行される恐れ）の悪用を疑うとしているが、サーバログを確認しておらず確定できないと明記している（出典1）。修正済みの 3.2.1 は2026年5月15日に出ており、検知までに約5か月あったことになる（本記録の算出）。

カード番号・有効期限・CVV・名義人・CPF——止める手段は停止しかない被害規模・影響範囲

窃取するよう設定されていた項目は5つである（出典1・2）—— カード番号、有効期限、CVV、カード名義人、CPF（ブラジルの納税者番号）。

取得元は2か所である（出典1）〈重要〉—— ①決済ページの決済フォーム②決済が決済 API へ送るリクエスト。

この組み合わせの意味を書いておく（本記録の評価）〈重要〉—— カード番号・有効期限・CVV・名義人が揃うと、カード現物を必要としないオンラインの取引にそのまま使える。 CVV が含まれているため、決済側で止まる要素が少ない。 CPF が加わることで、本人確認を求める取引への悪用も作りやすくなる。

したがって、買い物客に残る手段はカードの停止である（本記録の評価）—— Sansec は、2026年10月24日以降に決済ページのアドレスにcheckout.convertr の文字列を含むブラジルのストアでカード決済をした者は、ただちに銀行へ連絡してカードの停止を依頼するよう推奨している（出典2）。

窃取された件数・影響を受けた買い物客の人数は公表されていない〈未確定3〉。公表されているのは「全加盟店の決済ページで読み込まれていた」という構成上の範囲だけである（出典1。本記録の明示）—— 実際の件数が分かるのは Convertr と決済事業者だけである。

検知の2日後、攻撃者は決済APIの項目名に合わせて作り直した評価・解釈

スキマーには版がある。

10月24日の初期版——汎用的な決済項目の照合パターンを使っていた（出典2）。10月26日の更新版——Convertr の決済 API の正確な項目名を狙う、より精緻な版になった（出典1・2）。

この2日で何が起きたかを考える（本記録の評価）〈重要〉—— 汎用パターンから特定の項目名へ変えるには、Convertr の決済がどの名前で値を送っているかを知る必要がある。 つまり攻撃者は、改ざんしたあともプラットフォームの中の作りを観察し、精度を上げる作業をしていた。

実務上の意味は2つある（本記録の評価）。

①滞在時間が収穫の質を決める。 汎用パターンでは取れなかった項目が、2日後には正確に取れるようになっている。 スキマーの事案では「いつ入られたか」よりも「何日動いていたか」が被害の質を左右する。

②配信の停止までに2日以上かかっている（本記録の算出）〈重要〉—— Sansec の検知が10月24日 23:22 UTC、正常化の確認が10月27日 13:08 UTC である（出典1）。その途中、10月26日 15:34 UTC の時点でまだ配信されていた（出典1）。Sansec は公表前に Convertr へ通知したが、公表までに返答はなかったとしている（出典1）—— Convertr が通知を受領した時刻は公表されていないため、同社の対応の速さとしては測れない〈未確定7〉。

除去しても終わらない——ブラウザのキャッシュに最大24時間残る対策・注意喚起

対応の時系列は分単位で分かっている（出典1）。

2026年10月27日 12:54 UTC——Convertr が、スキマーの除去とPlausible のパッチ適用済み版への更新を報告。加盟店・決済事業者・当局へ通知中とした。 2026年10月27日 13:08 UTC——Sansec がanalytics.convertr.app.br のトラッカーの正常化を確認。

しかし、ここで終わらない（出典2）〈重要〉—— Sansec は「ブラウザのキャッシュにより、除去後も最大24時間は悪性スクリプトが影響を受けたサイトで動き続けうる」と警告している。 BleepingComputer は買い物客に対し、脅威が除去された後でも、新しい注文の前にキャッシュを消去するよう促している（出典2）。

これは、事業者側の措置の完了と買い物客側の露出の終わりが一致しないことを意味する（本記録の評価）〈重要〉。

読者が自社に移せる論点は2つある（本記録の評価）—— ①決済ページで読み込む JavaScript のキャッシュの有効期間をどう設定しているか。 長く設定すれば配信の負荷は下がるが、改ざん時には除去後も残る時間がそのまま延びる。 ②改ざんが判明したときに、キャッシュを強制的に無効化する手段（ファイル名の変更・クエリの付与・CDN のパージ）を手順として持っているか。 「消した」と「もう読み込まれない」は別である。

決済ページに解析スクリプトを読み込ませる構成そのものが問われる評価・解釈

本件の原因を Convertr の更新漏れだけに置くと、読み落ちる（本記録の評価）〈重要〉。

確かに Convertr は2025年に Plausible Community Edition 3.0 を導入し、その後更新していなかったとされる（出典1）—— 修正済みの 3.2.1 は2026年5月15日から存在していた（出典1）。ただし侵入経路は確定していない〈未確定1〉—— 「更新していれば防げた」とは言えない（本記録の留保）。

構成の側を見る。 1つのトラッカーファイルが、全加盟店の決済ページで読み込まれていた（出典1）。この構成では、ファイル1つの改ざんが被害の範囲を決める（本記録の評価）。

アクセス解析は、決済ページで本当に必要な機能かという問いが残る（本記録の評価）〈重要〉—— 決済の完了率を測る目的があるとしても、カード情報を入力する画面と同じ実行環境に第三者由来のスクリプトを置く必要はない。

PCI DSS v4.0 がこの形に対応する要件を持っている（本記録の評価）—— 要件 6.4.3 は決済ページで読み込むスクリプトの管理（許可・完全性の確認・一覧の維持）を求め、要件 11.6.1 は決済ページの改変の検知を求めている。 これらは、まさに本件のような「プラットフォーム側が配信するスクリプトが改ざんされる」形を想定して置かれたものである（本記録の評価）。

本記録は Convertr の PCI DSS 準拠状況を確認していない（本記録の明示）—— ブラジルの事業者であり、適用の範囲と評価の状況は公表されていない。 ここで述べているのは、同種の構成を持つ日本の事業者が自社を点検する際の手がかりである。
