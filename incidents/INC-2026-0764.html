INC-2026-0764Warp がベンダ侵害でAI判断ログ露出

AI エージェント開発環境 Warp が、インフラに組み込んだ第三者ベンダの侵害により 利用者の「エージェントの判断ログ（agent traces）」とテレメトリが 露出したと公表した——創業者・CEO の Zach Lloyd が2026年10月26日に X で明らかにし、把握は10月23日（金）、全利用者の約1%が影響を受けた 可能性があると見積もった。 **サイトは利用者を少なくとも80万としている。** **公表の中で「エージェントの群れ（agent swarm）による、 きわめて高度な侵入と権限昇格の技法」と述べ、 ベンダの依存関係の穴から始まったとみているが、 ベンダ名も脆弱性の内容も公表していない。** **露出したログに、ソースコード・プロンプト・資格情報が 含まれていたかも明らかにしていない。** **CrowdStrike を調査に起用し、当局にも通報したとされる。** **同じ週には AI コーディング基盤 OpenCode が 外部プロバイダ向けの API キーの露出を利用者に通知しており （利用者の約1.4%・一部で最大1,700ドルの不正請求）、 本記録はこれを別事案として扱う。**

委託先・再委託先起因で委託元多数に波及不正アクセス・侵害意図せぬ露出（設定不備等で外部から到達可能だった）初報のみ有名事象として記録（日本と直接の関係は薄い）委託先・供給元起因
初報: 2026年10月26日（Zach Lloyd 氏の X 投稿） 最終更新: 2026年10月27日（BleepingComputer による報道）

AI エージェント開発環境 Warp が、インフラに組み込んだ第三者ベンダの侵害によって、利用者の「エージェントの判断ログ（agent traces）」とテレメトリが露出したと公表しました（出典1）〈重要〉。

公表したのは創業者・CEO の Zach Lloyd で、2026年10月26日（月）に X の投稿として行われました（出典1・出典2）。把握は10月23日（金）です（出典1）。

Lloyd の説明は次のとおりです（出典1。訳は本記録）。「金曜日、Warp のインフラにあるベンダに対する、活発で帯域の狭い（narrow-banded）悪用と我々が考えるものを把握した」「数時間のうちに作戦を検知し、影響を是正・緩和することができた」。

影響の見積もりは「Warp 利用者の約1%が影響を受けた可能性がある」です（出典1）。Warp のサイトは利用者を少なくとも80万としており、単純に当てると約8,000人になります（出典1。算出は本記録）—— ただし Warp はこの換算を示しておらず、母数の定義（登録者か、能動的な利用者か）も公表されていません〈未確定3〉。

本記録が、この事案を他の基盤侵害と分けて記録するのは、露出したデータの種類が新しいからです（本記録の評価）〈重要〉。

Warp は、2020年代前半に「現代的なターミナル」として始まり、その後エージェント型開発環境（ADE）へ発展した製品です（出典1）。開発者が AI エージェントに指示してコードを書かせ、テストし、ソフトウェアを配備する——ターミナル・コードエディタ・タスクの編成・エージェントのレビュー機能が1つの作業空間に入っています（出典1）。

その「エージェントの判断ログ」が露出しました。 これは、エージェントが何を読み、何を考え、何を実行したかの記録です（本記録の整理）。従来の分類——個人情報か、資格情報か、ソースコードか——のどれにも収まりません。

そして、中に何が入っていたかは公表されていません（出典1）〈未確定2〉。Warp は、露出した可能性のあるデータとして「エージェントのトレースとテレメトリ」を挙げましたが、そこにソースコード・プロンプト・資格情報・その他の機微な情報が含まれていたかを明らかにしていません（出典1）。

本記録はこれを、本事案の最大の空白として記録します（本記録の評価）。理由は単純です—— エージェントの実行ログには、エージェントが扱ったもの全部が映りうるからです。 開発者が貼り付けたトークン、読み込ませたソースコード、実行したコマンドとその出力。 「トレースが露出した」という表現だけでは、利用者は自分が何を失ったかを判断できません（本記録の読み）。

攻撃の性格についての記述は、踏み込んでいます（出典1）。Lloyd は、攻撃が「エージェントの群れ（an agent swarm）」によるもので、「きわめて高度な侵入と権限昇格の技法」に依っており、おそらくベンダの依存関係の穴から始まったとみられると述べました（訳は本記録）。

ただし、ここは見立てです（本記録の明示）〈重要〉。ベンダ名も、脆弱性の内容も公表されていません〈未確定1〉。「エージェントの群れ」という判断の根拠も示されていません ——速度か、並列度か、残された成果物の性質かが分かりません。 報道もこの点を「独立に確認されていない」と記しています（出典2）。

対応として公表されているのは4つです（出典1）。数時間での検知と是正・緩和、影響が特定された利用者への通知、CrowdStrike の起用、法執行機関への通報です。 ベンダへは脆弱性について連絡したものの、ベンダ側からは何も共有されていないとされます（出典1）。

なお、同じ週に AI コーディング基盤 OpenCode が、保存していた外部プロバイダ向けの API キーが露出したと利用者に通知しています（出典1・出典2）——影響は利用者の約1.4%で、一部では最大1,700ドルの不正請求が発生しました。 本記録はこれを別事案として扱い、同一の攻撃者を推定しません〈未確定5〉。

    取るべき行動 **自組織が保存しているエージェントの実行ログについて、 保存期間を決める。** **決め方は「障害調査に必要な期間」と 「品質改善に必要な期間」を分けて考える** ——**後者は、個別のログではなく 集計値で足りることが多い。** **個別のログは短く、集計値は長く持つ構成にすると、 侵害時に失う範囲が小さくなる。**
  • 自社の AI 開発基盤の利用を、ログの観点から棚卸しする
    **本件・OpenCode の事案（同じ週・利用者の約1.4%・ 一部で最大1,700ドルの不正請求）・ Railway の事案（INC-2026-0668）の3件に共通するのは、 開発者が自分の作業のために外部基盤へ預けたものが 狙われたという構図である**（出典1。本記録の整理）〈重要〉。 **預けられるものは鍵だけではない** ——**本件が示したのは、 エージェントの実行履歴も預かられているということである。** **ただし本記録は3件に共通の攻撃者を推定しない** 〈未確定5〉。
    取るべき行動 **自組織の開発者が使っている AI 開発ツールを、 実名で一覧にする（個人が入れたものを含む）。** **各々について、①何が外部へ送られるか、 ②送られたものの保存期間、 ③提供者の侵害時に自組織が取る行動を書く。** **一覧を作る過程で、 「業務のコードをどのツールに読ませてよいか」の 線を引く**—— **線が無いと、侵害後に調査の範囲が決められない。**
