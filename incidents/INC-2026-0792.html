公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

**認証不要・ネットワーク経由で到達できる use-after-free である**（出典1）。 **CNA が挙げる影響は、ヒープ内容の漏えい、境界外書き込みと制御フローの破壊の 可能性、カーネルの停止である**（出典3）。 **Anthropic は、MPTCP のリスナーを持つ Linux サーバに対し、 パケットを送るだけで認証なしに任意のシェルコマンドを root で実行する 2段階の実証を公表した**（出典2）—— **第1段階で遠隔から KASLR を突破し、第2段階で制御フローを奪う。** **本節は研究環境での実証の整理であり、実環境での攻撃の記録ではない** （本記録の明示）。

  1. 1. 初期侵入確認済[1] [3]
    **攻撃者が IPv4 の Record Route または Timestamp オプション付きの TCP SYN を送り、続けて同じ要求への再送 SYN を送る**（出典3）—— **オプションが要求ソケットの ireq_opt に保存され、 別の CPU で SYNACK の組み立てが始まる**（出典3）。
    根拠: **CNA の記述（出典3 が整理したもの）。関数名まで示されている** （ip_rcv_options()・tcp_v4_save_options()・tcp_v4_rcv()・ tcp_check_req()・tcp_rtx_synack()・tcp_v4_send_synack()）
  2. 2. 実行確認済[1] [2] [3]
    **SYNACK の組み立ての間に同じ接続の確立と破棄が進み、 子ソケットが解放される。tcp_v4_syn_recv_sock() はオプションを複製せず 子ソケットへ渡し、inet_sock_destruct() が通常の kfree() で解放するため、 ip_options_build() で解放済みの領域を読む**（出典3）〈重要〉—— **競合が成立すると、隣接するカーネルヒープの内容が SYNACK に載って 攻撃者へ返る**（出典3）。
    根拠: **CNA の記述（出典3）と、修正内容（kfree() から kfree_rcu() への変更）** （出典1・3）
  3. 3. 内部探索確認済[2]
    **攻撃者が制御する長さフィールドをカーネルに読ませ、 余分なバイトを応答に載せて返させる。 応答にカーネルポインタが含まれれば、遠隔から KASLR を突破できる** （出典2）〈重要〉—— **Anthropic の PoC では、この段階に約48分を要した**（出典2）。
    根拠: **Anthropic の研究レポートの記述**（出典2）。 **研究環境での実証であり、実環境の攻撃ではない**（本記録の明示）
  4. 4. 権限昇格確認済[2]

    根拠: **Anthropic の研究レポートの記述**（出典2）
  5. 5. 影響（暗号化・破壊・改ざん）確認済[2] [3]
    **CNA が挙げる影響は、①隣接するカーネルヒープの内容が SYNACK に載って 相手へ送られる ②境界外のカーネルへの書き込みと制御フローの破壊の可能性 ③skb_under_panic() や oops によるカーネルの停止 である**（出典3）。 **Anthropic の実証では、認証なしでの root 権限コマンド実行に至っている** （出典2）〈重要〉。

認証も操作も要らず、パケットを送るだけで成立する競合である原因・手口出典 [1] [3]

CVE レコードの説明の要点は次のとおりである（出典1。原文英語を本記録が訳した）。

TCP の SYN 受信時に IPv4 オプション（inet_opt / ireq_opt）の所有権が子ソケットに移るが、同じ要求ソケットへの再送 SYN による SYNACK 生成と並行して、子ソケットが解放される可能性がある。その結果、ip_options_build() で解放済みメモリを読む use-after-free が起きる。同様の問題が要求ソケットの移行経路にもある。修正として inet_sock_destruct() と tcp_v4_reqsk_destructor() でkfree() の代わりに kfree_rcu() を使う。IPv6 は最初の問題の影響を受けない。

CNA の評価は CVSS 3.1 で 9.8（Critical）、ベクタはAV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H である（出典1。本記録が CVE レコードを取得して確認）〈重要〉。

この評価の意味を分解すると次になる（本記録の整理）。

  • AV:N — ネットワーク経由で到達できる
  • AC:L — 攻撃の複雑さは低い
  • PR:N — 権限は不要
  • UI:N — 利用者の操作は不要
  • C:H / I:H / A:H — 機密性・完全性・可用性のすべてに高い影響

攻撃に必要なのは、対象サーバへ TCP SYN を送れることだけである（本記録の整理）。つまりインターネットに TCP ポートを開いているすべての Linux サーバが対象になりうる（本記録の評価）。

CNA が攻撃の複雑さを Low とした根拠は、接続を受け付けるサーバでの競合について、競合の両側が攻撃者の誘発によるものであり、マルチコアのスケジューリングやヒープ整形は攻撃者の制御外の条件には当たらないという判断である（出典3）。

起点となったのは、要求ソケットをリスナーのロックなしで処理するようにした 4.4 系のコミット 079096f103fa である（出典1）〈重要〉—— 性能のためにロックを外した変更が、解放と参照の競合を生んだ（本記録の評価）。修正は解放を待たせる方（kfree_rcu()）に寄せたもので、ロックを戻すものではない（出典1。本記録の整理）。

競合に負けても落ちないため、攻撃側は成功するまで再試行できる評価・解釈出典 [1] [2] [3]

Anthropic のレポートが示した実証は2段階である（出典2）。

第1段階（遠隔からの KASLR 突破・約48分）競合を利用して、カーネルに攻撃者が制御する長さフィールドを読ませ、余分なバイトを応答に載せて返させる。その返信にカーネルポインタが含まれれば、カーネルアドレス空間のレイアウトが分かる（出典2）。

第2段階（制御フローの乗っ取りと root でのコマンド実行・約5分）同じ use-after-free でバッファをあふれさせ、コールバックポインタを、通常のプロトコル機能で事前にカーネルメモリへ置いたペイロードのアドレスで上書きする。カーネルがコールバックを呼ぶと、既存のカーネル関数を連鎖させ、攻撃者が指定したシェルコマンドが root として実行される（出典2）。

この実証で最も重いのは所要時間ではなく、失敗したときに何も起きないという性質である（本記録の評価）〈重要〉。レポートは次のように述べている（出典2。原文英語の要旨）。

競合に負けても失敗するのはハンドシェイクだけで、システム全体はクラッシュしない。そのため、攻撃者は成功するまで繰り返し試行できる。

カーネルの競合を狙う攻撃は、通常は失敗すると panic や oops を起こし、標的に異常として現れる（本記録の整理）。本件では失敗が「接続が1回失敗した」としか見えない。48分という数字は「時間がかかるので現実的でない」ではなく、「止められない限り必ず到達する」ことを意味する（本記録の評価）。

なお、実証に用いられたモデルの名称は公表されていない〈未確定4〉。レポートは全体の作業に「未公開の社内研究用モデル」を用いたと説明しており、末尾で言及される Claude Opus 5.5・Sonnet 5.5・Mythos 5.1 はCyber Verification Program の説明に登場するもので、この実証に使われたとは書かれていない（出典2。本記録の確認）。

また、実証の条件（MPTCP のリスナー）は、CVE の記述が挙げる条件（接続を受け付ける IPv4 の TCP サービス）より狭い〈未確定6〉。CVE の説明文と修正コミットには MPTCP の記載が無い（出典1・3）。したがって「すべての Linux サーバで root を取れる」とは読めない（本記録の明示）。

本記録の作成者は2026年10月30日に CISA の Known Exploited Vulnerabilitiesカタログの JSON フィードを取得し、catalogVersion 2026.10.29・収載1,764件のうちに CVE-2026-98432 が含まれないことを確認した（出典6。本記録の観測）〈重要〉。

KEV への収載は、実際の悪用が確認されたことを意味する（本記録の整理）。したがって未収載は「実環境での悪用が CISA により確認されていない」状態を示す。

Anthropic が公表したのは研究環境での PoC であり、実環境での攻撃の報告ではない（出典2。本記録の明示）。出典3・4・5 のいずれにも、実環境での悪用の観測に関する記述は無い（本記録の確認）。

ただし「確認されていない」は「起きていない」ではない（本記録の明示）〈重要〉。本件では、侵害の兆候（IoC）と検知方法が公表されていない〈未確定3〉。攻撃が成功すれば root 権限でのコマンド実行に至るため、痕跡の消去も可能である（本記録の評価）。つまり、悪用されていたとしても気づく手段が示されていない。

実務上の意味は次になる（本記録の評価）。

  • KEV 未収載を「急がなくてよい」と読んではならない。 KEV は観測の結果であり、観測の手段が無い脆弱性では収載が遅れる構造がある
  • 逆に、KEV に入っていないことを根拠に優先度を下げる運用をしている組織は、本件のような「検知できないが到達できる」脆弱性を取り落とす

PoC のコードが公開されているかどうかは、本記録の確認した範囲では示されていない（本記録の確認）。

手順: **各系列の修正版以降のカーネルへ更新する**（出典1・3）—— **Linux カーネル CVE チームは最新の stable への更新を勧め、 個別コミットの cherry-pick は推奨していない**（出典3）。　副作用: **カーネルの更新は再起動を要するため、 稼働中のサービスに停止時間が生じる**（本記録の評価）—— **ライブパッチの対象になるかは配布元ごとに異なる。** **また、2026年10月30日時点で Ubuntu は修正版を提供しておらず、 Red Hat も RHEL 8・9・10 を影響ありとしているため、 この対処を今すぐ実行できない利用者がいる**（出典3）〈重要〉。
手順: **IPv4 の TCP 接続を受け付ける面を、必要な送信元に限定する** （本記録の推奨）—— **攻撃には対象サーバへ TCP SYN を送れることが要る**（出典1）。　副作用: **公開サービス（Web・メール・DNS over TCP 等）では送信元を 限定できない**（本記録の評価）〈重要〉—— **限定できるのは管理用の面や内部向けサービスに限られる。** **また、この対処は脆弱性を解消しない。**
手順: **要求ソケットの移行に関する2つ目の経路については、 net.ipv4.tcp_migrate_req の設定値を確認する**（出典3。本記録の推奨）。　副作用: **tcp_migrate_req は、リスナーの入れ替え時に確立前の接続を 引き継ぐための機能である**（本記録の整理）—— **無効化すると、無停止でのリスナー更新を行っている構成で 接続が失われる恐れがある。** **なお、この設定を変えても1つ目の経路（IP オプション付き SYN）は 残るため、脆弱性は解消しない**（本記録の明示）〈重要〉。
