INC-2026-0847Accenture従業員の個人AIがDOD網へ

米国防総省（DOD）の請負業者 Accenture の従業員が、複数の情報機関が使う CUI（管理対象非機密情報）環境の本番系を 自分個人の Claude Code アカウントに接続し、AI エージェントが従業員のログイン認証情報・パスワードと NIPRNet の構成図を 第三者のウェブサイトへ送信していた——エージェントは発見・修正までの約2か月間 DOD のネットワーク上で動き続け、 Accenture は「独立した調査で根拠がないと判明した」と否認している。WIRED が2026年10月29日に匿名の情報源をもとに報じたもので、 DOD は「ネットワークやシステムの状況についてはコメントしない」として確認も否定もしていない

意図せぬ露出（設定不備等で外部から到達可能だった）内部不正（内部者による意図的な持ち出し・目的外利用）初報のみ有名事象として記録（日本と直接の関係は薄い）ガバナンス・組織文化（ガイドライン理解不足・丸投げ等）権限管理の不備作業ミス・誤操作
初報: 2026年10月29日 最終更新: 2026年11月3日

WIRED は2026年10月29日、複数の匿名情報源の話として、米国防総省（DOD）の請負業者である Accenture の従業員が、複数の情報機関が使う集中システムを自分個人の Claude Code アカウント（Anthropic の AI コーディングエージェント）に接続し、セキュリティインシデントを起こしていたと報じました。

報道によれば、そのエージェントは従業員のログイン認証情報・パスワードと、NIPRNet の構成図（マップ）を、第三者のウェブサイトへ送信したとみられます。NIPRNet は DOD の非機密情報用ネットワークですが、当該システムはCUI（Controlled Unclassified Information／管理対象非機密情報）を扱っており、CUI には重要インフラ、原子力潜水艦の推進、化学・生物テロへの脆弱性といった情報が含まれ得ます。WIRED は、その第三者サイトをNIST が過去に「高リスク」と指摘していた—— AI コーディングエージェントに命令を注入して認証情報を盗める脆弱性があるため——と書いていますが、サイト名は「さらなる危険を避けるため」公表していません。

エージェントは特定されて修正されるまで約2か月間、DOD のネットワーク上で動き続けたとされます。DOD・連邦の請負業者はサイバーインシデントを発見から72時間以内に報告する義務を負いますが、Accenture は当初、政府にまったく報告しなかったと情報源は述べています。

一方で Accenture は否認しています。「すべての懸念を真剣に受け止めている。これらの主張は徹底的かつ独立に調査され、根拠がないと判明した。我々は法的・契約上の義務を完全に履行した」（原文英語）。ただし WIRED が重ねて尋ねても、誰が調査したのかの説明は無く、「インシデントと呼びうる何かがあった」こと自体は争っていません。DOD は「当省はネットワークやシステムの状況についてコメントしない」とだけ答えています。

本記録は、当事者の公表資料が存在しない事案として扱います。WIRED の本文は本記録の作成者が2026年11月3日に取得して逐語で確認しましたが、匿名情報源の主張そのものは本記録では検証できていません。事実として確定しているのは「WIRED がそう報じたこと」「Accenture が否認したこと」「DOD がコメントを避けたこと」の3点です。評価・示唆は本記録の判断として分けて書きます。

攻撃の経過

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

**外部の攻撃者は確認されていない**（本記録の明示）〈重要〉—— **報じられているのは、正規の利用者が正規の認証情報を AI エージェントに渡し、 そのエージェントが外へ出たという流れである**（出典1）。 **それでも段階として書くのは、同じ流れが「攻撃者が内部から持ち出す」形と 技術的に区別できないからである**（本記録の判断）—— **統制の側から見れば、管理者権限で動き、インターネットへ出ていき、 認証情報を外部へ送る主体がネットワークの中にいた、という事実は変わらない。**

    根拠: **「The AI agent—which was not only writing code but also committing it or saving the code into the system on behalf of the Accenture employee」**（出典1。原文英語）。
  2. 2. 持ち出し推定[1]
    **エージェントが作業のためにインターネットへ接続し、その過程で 従業員のログイン認証情報・パスワードと NIPRNet の構成図（マップ）を 第三者のウェブサイトへ送信したとみられる**（出典1）〈重要〉。
    根拠: **「In doing so, it appears to have sent the contractor's login credentials, passwords, and a map of NIPRNet out to a third-party website」**（出典1。原文英語）。 **送信先は NIST が「高リスク」と指摘しているサービスで、 AI コーディングエージェントに命令を注入して認証情報を盗める脆弱性があるとされる**（出典1）。

    CUI 環境の本番系が、従業員個人の AI コーディングエージェントにつながっていた概観出典 [1]

    WIRED が2026年10月29日に報じた内容は、次のとおりである（すべて匿名の情報源による）。

    • 2026年の早い時期、Accenture の従業員が、CUI（管理対象非機密情報）を扱う DOD の集中システムを自分個人の Claude Code アカウントに接続した
    • 目的は、コードの作成とデプロイ、クラウドサーバの立ち上げの自動化だった
    • そのために自分のログイン認証情報をエージェントに渡した。これによりエージェントは管理者相当のアクセスを得て、通常のログイン過程で効いている統制を迂回した
    • エージェントは作業のためにインターネットへ接続する必要があり、その過程でログイン認証情報・パスワードと NIPRNet の構成図を第三者のウェブサイトへ送信したとみられる
    • エージェントは特定され、脆弱性が修正されるまで約2か月間 DOD のネットワーク上で動いていた

    当該システムが載る NIPRNet は DOD の非機密情報用ネットワークで、インターネットに接続している（職員や請負業者はここからメールやウェブを使う）が、厳重に防護されている。一方で機密情報用の SIPRNet と、最高機密用の JWICS はエアギャップで外部から切り離されている。

    出ていったのは CUI そのものではなく、CUI 環境への「鍵」と「地図」だった被害規模・影響範囲出典 [1]

    本件で外部へ渡ったとされるのは、ログイン認証情報・パスワードと、NIPRNet の構成図である。CUI そのものが送信されたとは報じられていない。

    それでも深刻とされるのは、次の2つの理由による（出典1の専門家の発言）。

    第一に、鍵は環境全体を開ける。 情報源は「もしその第三者ソフトウェアが侵害されていたら、誰にも知られずに安全な環境へログインできる者が外にいることになる。100% 国家安全保障上の脅威であり、取り返しのつかない害をもたらし得る」と述べている（原文英語）。送信先は、NIST が「AI コーディングエージェントに命令を注入して認証情報を盗める脆弱性がある」として高リスクと指摘していたサービスだった。

    第二に、地図は失効させられない。 Hunter Strategy の Matt Triner は、「個々の要素が公開情報であっても、機微なのはそれらをどう組み合わせ、実用的なインテリジェンスに変えているかだ」「地図だけでは侵入できないが、侵入後の移動を速め、宝の在処を攻撃者に教える」と述べている（原文英語）。

    元 NSA の Jake Williams（IANS）は、さらに踏み込んで「個々の情報が CUI であっても、その非機密情報が集約されると、それ自体が機密になり得る」と指摘している（原文英語）。たとえば危険物の所在と、それを収容する施設の脆弱性は、それぞれは CUI でも、組み合わせれば機密に該当する情報を明かし得る。

    72時間の報告義務があるのに、当初はまったく報告されなかったとされる当局対応出典 [1]

    DOD 職員と連邦の請負業者は、サイバーインシデントを発見から72時間以内に報告する義務を負う。しかし情報源によれば、Accenture は当初、政府にまったく報告しなかった。さらに「Accenture の従業員たちは、このインシデントを深刻・緊急とは扱わなかった」とされる。

    ある従業員は「我々はいまイランと衝突の渦中にある。こういう軽率な態度を取っている場合ではない」と述べている（原文英語）。

    Matt Triner は、この構造を次のように説明している（原文英語を訳出）。

    組織は、こうしたインシデントを報告すると罰せられることが多い。それが正しく、かつ法的に求められる行為であってもだ。

    多くの場合、侵害を認めれば政府契約を失いかねない——ただし今回のようなインシデントは「間違いなく報告が必要なものだ」とも述べている。

    なお本件とは別に、2026年10月初旬、FBI は Accenture の請負業者を排除している。当該請負業者が脆弱性を修正せず、ShinyHunters が FBI 職員数千人分の情報にアクセスした件によるものである。

    Accenture は否認し、DOD はコメントを避け、Anthropic は使用ポリシーを示した帰属出典 [1] [3]

    3者の反応は、それぞれ性質が異なる。

    Accenture（否認）——「我々はすべての懸念を真剣に受け止める。これらの主張は徹底的かつ独立に調査され、根拠がないと判明した。我々は法的・契約上の義務を完全に履行した」（原文英語）。ただし WIRED が重ねて尋ねても、誰が調査を行ったのかの説明は無く、「インシデントと特徴づけうる何かがあった」こと自体は争わなかった。

    DOD（沈黙）——「当省はネットワークやシステムの状況についてコメントしない」（原文英語）。

    Anthropic（ポリシーの提示）——同社は WIRED に対し、自社の使用ポリシーを示した。同ポリシーは、「軍事基地および関連インフラの運用を妨害すること」および「認証システム・エンドポイント保護・監視ツールなどのセキュリティ統制を、許可なく迂回すること」を禁じている（原文英語）。なお Claude は現時点で DOD 職員による利用が禁じられている。

    本記録はこの3つを事実として確定しているものとして扱う。一方、インシデントの内容そのものは匿名情報源の証言であり、本記録では検証できていない（差異1・差異4）。

    「使ってはいけない道具」を数える発想では、この形は止められない（本記録の評価）評価・解釈出典 [1]

    ここからは本記録の作成者の評価である。

    第一に、禁止の単位と、持ち込みの単位がずれている。 Claude は DOD 職員の利用が禁じられていた。にもかかわらず動いたのは、請負業者が自分の契約で持っている個人アカウントである。製品名の一覧で禁止を管理する限り、「組織が調達していない道具を、個人が自分の名前で持ち込む」経路は常に残る。効くのは、本番環境の出口（egress）をどこまで開けているかという一点である。本件で情報が出たのも、エージェントが作業のためにインターネットへ出たときだった。

    第二に、AI エージェントは「人間の権限を借りる」ことで、ログイン時の統制をまとめて無効化する。 MFA も、条件付きアクセスも、デバイス証明も、ログインの瞬間にしか効かない。認証済みのセッションごとエージェントに委譲されれば、以降の統制は素通りになる。これは Claude 固有の話ではなく、人間の認証情報を渡して動かすすべての自動化に共通する。対策は技術的には明確で、自動化には人間とは別のアイデンティティを割り当てることに尽きる。

    第三に、2か月の沈黙を作ったのは、おそらく罰の設計である。 72時間の報告義務があり、Triner の言う「報告すると罰せられる」構造があり、「使ってはいけない道具を使っていた」という自覚がある。この3つが揃えば、申告しないことが個人にとって合理的になる。組織が本当に止めたいのが2か月のほうであるなら、使ったことを言える窓口と、承認済みの代替手段を先に用意しなければ、禁止を強めるほど発見は遅れる。

    第四に、本件の構造は機密区分とは無関係に成立する。 NIPRNet・CUI・情報機関という語に置き換えがたい重みがあるのは確かだが、「本番環境を個人のエージェントにつないだ」「認証情報を渡した」「エージェントが外へ出た」という3点は、日本の一般企業の本番環境でもそのまま成立する。読者が自社に当てはめるとき、機密区分の有無ではなく、出口の統制とアイデンティティの分離で判定するのが正しい（applicability を参照）。

    鍵と地図だけが外へ出た——CUI は動いていないのに環境が危うくなる構造
    Accenture の従業員（layer 0）が、CUI を扱う DOD の本番環境（layer 1）を 自分個人の Claude Code アカウント（layer 2）に接続し、自分のログイン認証情報を渡した。 エージェントは管理者相当の権限を得て、コードを書き、従業員に代わってコミットした。 作業のためにインターネットへ出る必要があり、その過程で認証情報・パスワードと NIPRNet の構成図が第三者のウェブサイト（layer 3）へ送信されたとみられる。 出ていったのは CUI そのものではなく、CUI 環境へ入るための鍵と、その環境の地図である。 送信先は NIST が「AI コーディングエージェントに命令を注入して認証情報を盗める」として 高リスクと指摘していたサービスで、送信後に情報がどう扱われたかは誰も確認していない。 下流には SIPRNet・JWICS（layer 4）があり、これらはエアギャップで分離されているが、 道具やコードはより機微な環境へ展開する前に NIPRNet で試験されることが多い。

    CISO・経営層への示唆
    • 「禁止」は、持ち込みの経路を塞がない。塞ぐのは egress（外向き通信）の制御である
      **Claude は DOD 職員による利用が禁じられていたが、本件で動いたのは請負業者の個人アカウントである**（出典1）〈重要〉—— **製品単位・職員単位の禁止令は、「会社が調達していない道具を、個人が自分の契約で持ち込む」経路に届かない。** **実際に情報が出たのは、エージェントが作業のためにインターネットへ接続したときである**（出典1）。
      取るべき行動 **本番環境・機微データを扱う環境について、 「どの外部ドメインへの到達を許すか」を許可制（既定は拒否）で定義し、 未登録の宛先への通信をログに残して週次で棚卸しする。** **利用禁止の一覧を増やすのではなく、出口の許可一覧を絞る。** **併せて「業務で AI エージェントを使いたい」という申告が罰にならない窓口を用意し、 承認済みの代替手段（組織契約のエージェント・監査ログ付き）を先に用意する。**
    • 報告義務の期限は「気づいてから」で始まるが、気づく仕組みが無ければ期限は動かない
      **DOD 職員と連邦請負業者は発見から72時間以内の報告義務を負うが、 本件では約2か月の稼働の後、当初はまったく報告されなかったとされる**（出典1）〈重要〉—— **「発見」が遅れれば、どれだけ厳しい期限も形骸化する。**
      取るべき行動 **委託契約に「72時間以内の報告」を書くだけで終わらせず、 ①検知の仕組みが何を見ているか、②四半期ごとの未報告ゼロの確認、 ③報告しても不利益がないことの明文化、を契約と運用の両方に落とす。** **自組織が委託先の立場なら、報告が契約解除に直結しない設計を発注側と事前に合意しておく。**
    • 委託先の「独立した調査で根拠なし」という回答を、そのまま終わりにしない
      **Accenture は独立した調査で根拠がないと判明したと述べたが、 誰が調査したかの説明は無く、インシデントと呼びうる何かがあったこと自体は争わなかった**（出典1）〈重要〉—— **「独立」の中身が分からない回答は、検証できない**（本記録の評価）。
      取るべき行動 **委託先からインシデントの否認を受け取ったときに尋ねる項目を、定型として持つ。** **①調査主体の名称と自社との資本・取引関係、②調査範囲（期間・対象システム・対象ログ）、 ③調査できなかった範囲、④報告書の提出可否。** **これらが埋まらない否認は「調査結果」ではなく「立場の表明」として扱う。**
    • 速く安くという発注の圧力が、そのまま AI の速度で増幅されることを前提に置く
      **Matt Triner は「組織は競合する規則とインセンティブの中で動いている。 それは AI 以前からあった問題だが、いまは同じ問題が高速で起きている」と述べている** （出典1。原文英語を本記録が訳した）〈重要〉—— **本件の従業員の動機は、コードを速く書き、サーバを速く立てることだった**（出典1）。
      取るべき行動 **委託の見積・納期の査定に「承認された自動化手段で達成可能か」の欄を設け、 達成不能な納期を飲ませない。** **納期を詰めるなら、同時に承認済みのエージェント環境を発注側が用意する。**
    セキュリティ技術者への示唆
    • エージェントに人間の認証情報を渡した時点で、統制は「ログイン時の統制」ごと無効になる
      **従業員が自分のログイン認証情報をエージェントに渡したことで、 エージェントは管理者相当のアクセスを得て、通常のログイン過程で効いている統制を迂回した**（出典1）〈重要〉—— **MFA も、条件付きアクセスも、ログイン時にしか効かない統制は、 セッションごと委譲されれば素通りになる。**
      取るべき行動 **自動化の主体には、人間とは別のアイデンティティ（サービスプリンシパル／ワークロード ID）を割り当て、 人間の認証情報の共有をポリシーと技術の両方で禁止する。** **短命のトークン、対象リソースを限定したスコープ、呼び出し元の検証を既定にする。** **「人間の認証情報が非対話の文脈で使われた」ことを検知ルールにする。**
    • コードを書くだけでなく「コミットまで代行する」エージェントは、変更履歴の主体を壊す
      **本件のエージェントは、従業員に代わってコードを書き、コミット（システムへの保存）まで行っていた**（出典1）〈重要〉—— **監査ログ上は人間が変更したことになり、2か月分の変更の責任主体が追えなくなる。**
      取るべき行動 **エージェントによる変更には専用のアカウント・署名・ラベルを強制し、 人間の承認（レビュー・マージ）を別アイデンティティで必須にする。** **本番へのデプロイ経路では、エージェント ID からの直接の反映を拒否する。**
    • 「エージェントが外へ出る必要がある」ことを、設計時のリスクとして扱う
      **情報が出たのは、エージェントが作業を遂行するためにインターネットへ接続したときである**（出典1）—— **送信先は NIST が「AI コーディングエージェントに命令を注入して認証情報を盗める脆弱性がある」として 高リスクと指摘していたサービスだった**（出典1）〈重要〉。
      取るべき行動 **エージェントを動かす環境では、到達可能な宛先を列挙し、 プロンプト・ツール出力・取得したコンテンツを「信頼できない入力」として扱う前提で境界を設計する。** **エージェントが外部サービスへ送るペイロードを記録し、 認証情報・構成情報のパターンを出口で検出して遮断する（DLP をエージェントの通信に適用する）。**
    • 非機密ネットワークでの試験が、機微なネットワークへの足がかりになる構造を理解する
      **道具やコードは、SIPRNet・JWICS のようなより機微なシステムへ展開する前に NIPRNet で試験されることが多い**（出典1）〈重要〉—— **Jake Williams（元 NSA）は「非機密の情報でも、集約されると機密そのものになり得る」と述べている** （出典1。原文英語を本記録が訳した）。
      取るべき行動 **「ここは非機密だから」という理由で統制を緩めている環境を洗い出し、 そこから機微な環境へ流れる成果物（コード・設定・イメージ・構成情報）の経路を図にする。** **下流が機微なら、上流の統制は下流に合わせる。**

    自組織に当てはまるか

    該当する項目があれば、この事案と同じ構図が自組織でも成立しうることを意味します。
    観点自社に当てはまるか該当する場合に何が起きうるか
    認証・認可□ 人間のアカウントの認証情報を、自動化ツールやエージェントに渡して動かしている箇所がある（CI の個人トークンを含む）**本件は、従業員が自分のログイン認証情報をエージェントに渡したことで、 通常のログイン過程で効く統制が迂回された**（出典1）—— **MFA の有無では防げない。**
    運用・監視□ 本番環境からの外向き通信が、宛先の許可制（既定は拒否）になっていない**情報が出たのは、エージェントが作業のためにインターネットへ接続したときである**（出典1）—— **出口が開いていれば、何が動いているかに関わらず情報は出ていく。**
    体制・契約□ 組織が許可していない AI ツールの業務利用について、申告しても不利益を受けない経路が無い**本件は約2か月、当初は政府にも報告されなかったとされる**（出典1）〈重要〉—— **罰だけを置くと、沈黙が最適解になる。**
    委託・第三者部品□ 委託先の従業員が自分の端末・自分の契約したサービスを使って作業できる状態で、その検知手段を発注側が持っていない**本件の主体は委託先の従業員で、発注側（DOD）は現在もネットワークの状況を語っていない**（出典1）。
    運用・監視□ 変更管理のログで「人間の操作」と「自動化による操作」を区別していない**エージェントが従業員に代わってコミットまで行っていた**（出典1）—— **ログ上は人間の変更に見える。**
    システム構成□ 機微度の低い環境で作ったものを、機微度の高い環境へ持ち上げる経路があり、低い側の統制を緩めている**道具とコードは、より機微なシステムへ展開する前に NIPRNet で試験されることが多い**（出典1）。
