INC-2026-0850Mercado Bitcoinで大規模な資産流出

ブラジル最大の暗号資産取引所 Mercado Bitcoin が2026年11月2日未明にセキュリティインシデントに遭い、 17のブロックチェーンにまたがって約4,900万ドル相当の暗号資産が波状に流出した—— 同社は入出金を停止し「顧客に損害は無く、データ漏えいも無い」と説明したが、 複数のブロックチェーン調査者は顧客ウォレットから資金が抜かれた証跡を示して反論している。 Chainalysis は通報から30分で法執行機関に凍結可能なアドレスを伝え、 Tether・Paxos・Circle・Ripple・Anchorage Digital と連携して約1,000万ドルを凍結させた

不正送金・資金詐取（主損害が金銭）不正アクセス・侵害システム障害続報が続いている有名事象として記録（日本と直接の関係は薄い）公表されていない／不明
初報: 2026年11月2日 最終更新: 2026年11月3日

Mercado Bitcoin（MB）——自ら「ラテンアメリカ最大のデジタル資産投資プラットフォーム」と称し、顧客約450万人を持つブラジルの暗号資産取引所——は2026年11月2日、セキュリティインシデントを受けて入出金のすべてを停止しました。

Chainalysis の公表（同社は MB の顧客）によれば、11月2日未明に攻撃者が17のブロックチェーンにまたがる資産を動かし始め、波状に（in waves）約4,900万ドル相当を抜き出しました。最大の部分は Bitcoin と Ethereum ですが、Base・Tron・Polygon のような小規模チェーンの資産も掃われています。

一方、MB の説明と第三者の観測は食い違っています。同社は SNS で「このサイバー攻撃は顧客に損害を与えず、データ漏えいにもつながらなかった」と述べましたが、複数のブロックチェーンセキュリティ専門家は、攻撃者が一部の顧客ウォレットから資金を吸い出せたことを示すオンチェーンの証跡を提示して、この評価に異を唱えています（出典2）。流出額についても MB は自ら数値を確認しておらず、報道は 4,600万ドル（ブロックチェーン調査会社）、4,900万ドル（Chainalysis）、約4,000万ドル（Hypernative のアラート）と分かれています。

対応で際立ったのは最初の数時間です（出典3）。米東部時間 2時30分、MB の役員が Chainalysis の現地担当に電話で侵害を伝え、不正取引の一覧を共有しました。その30分以内に Chainalysis は法執行機関に凍結可能なアドレスを伝達。朝までにステーブルコイン400万ドルを押さえ、その後さらに積み増して合計約1,000万ドルの凍結に至りました。連携先は Paxos・Anchorage Digital・Ripple・Circle・Tether。Tether 単独で900万ドル超を凍結しています。Tether CEO の Paolo Ardoino は約450万ドルの凍結に言及し、他のプラットフォームでさらに200万ドルが凍結されたとも報じられました。

同社のステータスページでは、11月2日 12:52 UTC にモバイルアプリ・会員登録・ログイン・取引 API の障害が記録され、19:32 UTC に解消しています（6時間39分）。ただしこれらは自動監視が作成した記録であり、入出金の再開時期は公表されていません。

本記録の作成者は2026年11月3日に同社のステータスページを直接取得し、障害の時刻を確認しました。侵入の原因、顧客資産への影響の確定、入出金の再開時期は、いずれも公表されていません。評価・示唆は本記録の判断として分けて書きます。

第三に、速さで取り返せる範囲には構造的な上限がある。凍結できたのは約1,000万ドル、流出額の約20%にとどまる。Chainalysis 自身が説明しているように、凍結できるのは中央発行のステーブルコインのような発行者が止められる資産であり、BTC・ETH への変換が済めば難しくなる。つまり「どの資産なら第三者が止められるか」を平時に分類していることが、インシデント時の回収可能額を決めている。これは暗号資産に限らず、決済・ポイント・権利証券のように第三者が介入できる資産を扱う事業に共通する設計の問題である。

    取るべき行動 **サービス停止の手順に「再開の判断基準と、見通しの更新頻度」を組み込む。** **「いつ再開するか」が言えなくても、「次にいつ状況を伝えるか」は言える。** **ステータスページに、自動監視の記録とは別に、人が起票する事案の欄を用意する—— 顧客が最も知りたい情報が、監視の体系の外に落ちないようにする。**
セキュリティ技術者への示唆
  • 凍結できる資産と、できない資産を事前に分けて把握する
    **Chainalysis は「ハック直後の数時間が最も重要な窓である。 その窓のうちに、攻撃者が BTC や ETH のような妨害しにくい暗号資産へ変換する前に、 中央発行のステーブルコインのような一部の資産を凍結できる」と述べている**（出典3）〈重要〉—— **実際の凍結率は約20%（約1,000万ドル／約4,900万ドル）だった**（本記録の算出）。
    取るべき行動 **自社が保管する資産を「発行者が凍結できるもの」「できないもの」に分類した一覧を平時に作る。** **チェーンごとに、発行者・連絡経路・必要な情報の形（アドレス・取引ハッシュ・裏付け資料）を書く。** **インシデント時には、この一覧の上位から順に連絡するだけの状態にしておく。**
  • 17チェーンへの同時展開を前提に、「不正取引の一覧」を即座に出せるようにする

    取るべき行動 **自社の全チェーン・全ウォレットの出金を1つのクエリで横断的に抽出できる仕組みを用意する。** **「直近N時間の全出金を、チェーン・アドレス・金額・取引ハッシュの表で出す」を インシデント時の第1手として手順に書き、平時に実行時間を測る。** **チェーンごとに別のツールで手作業なら、30分では出ない。**
  • ステータスページの自動記録は、事案の説明にはならない
    **本記録の作成者が同社のステータスページを取得したところ、 記録されていた4件の障害はいずれも「自動監視サービスが作成した」ものだった**（出典1。T11）〈重要〉—— **「モバイルアプリが不安定です」という自動文面しかなく、 入出金の停止も、その理由も記録されていない。**
    取るべき行動 **ステータスページに、自動監視の記録と人が起票する事案を別の種別として持つ。** **インシデント時は人が起票し、影響範囲・対応状況・次回更新時刻を書く。** **「自動監視が解消を検知したら Resolved になる」仕組みだけでは、 業務影響が続いているあいだも Resolved になりうる。**
  • 調査会社との連携は、相手が作業できる形でデータを渡せるかで決まる
    **Chainalysis が30分以内に法執行機関へ凍結可能なアドレスを伝達できたのは、 MB が「不正取引の一覧」を共有したからである**（出典3。T2・T3）〈重要〉—— **同社は「単にブロックチェーン上で資産を追跡するだけの案件ではなかった。 調査員が介入の機会を特定し、どの組織が行動できるかを理解し、 必要な対応を迅速に調整することが求められた」と述べている**（原文英語を本記録が訳した）。
    取るべき行動 **外部調査会社・当局に渡すデータの形式を平時に取り決める （項目・ファイル形式・受け渡し経路・暗号化の方法）。** **「送れるデータはあるが、相手が使える形になっていない」状態を、机上演習で洗い出す。** **受け渡し経路が自社基盤に依存していないか（自社が止まっても送れるか）も確認する。**
