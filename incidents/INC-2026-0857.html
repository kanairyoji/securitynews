INC-2026-0857BTCPay Server 旧版から約163万ドル窃取

自己ホスト型の暗号資産決済ソフト BTCPay Server の旧版（2.4.1 以前）を運用していた事業者の ホットウォレットから Bitcoin と Litecoin が掃き出され、 第三者分析は約163万ドル相当・682回の送金を追跡した。 修正版は約3か月前に公開されていた

初報: 2026年11月1日22時25分 UTC（BTCPay Server が X で利用者へ警告した時刻） 最終更新: 2026年11月4日

自己ホスト型・オープンソースの暗号資産決済処理ソフト BTCPay Server は、2026年11月2日、「BTCPay Server 2.4.1 以前に影響するセキュリティ事案」として調査の更新を公表した（出典1）。同プロジェクトは「我々の調査により、これらの攻撃はBTCPay Server 2.4.1（2026年7月23日公開）またはそれ以前を動かしているサーバーを標的にしていたことが分かった」と述べている（出典1。本記録の訳。原文英語）。被害は、サーバー上に送金鍵を置く「ホットウォレット」からの Bitcoin と Litecoin の窃取である（出典1）。

公表の順序は速かった。 同プロジェクトの時系列によれば、最初の窃取の報告メールが届いたのは2026年11月1日20時56分 UTC で、その1時間29分後の22時25分 UTC に X で利用者へ警告し、サーバーを停止するよう求めた（出典1。本記録の算出）。同じ11月1日には、LunaNode を含む仮想サーバーの提供事業者に連絡し、該当インスタンスをオフラインにするよう依頼している（出典1）。

プロジェクト自身は損失額を公表していない（出典1）。ブロックチェーン分析企業 Bitquery の解析として報じられた値は、同プロジェクトが名指しした2つのアドレスへ移された 18.38 BTC と 3,405 LTC（約163万ドル相当）であり、2026年10月30日から11月2日の午前までに682回の掃き出しで動いたとされる（出典4）。うち87%は11月1日の午後から夜にかけての一波で動き、22時25分 UTC の警告の後にも約15万ドル相当・267回の掃き出しが続いた（出典4）。

本件の核心は、修正が無かったことではない。 修正版 2.4.2 は2026年8月7日に公開済みであり、本件の被害は「その修正を一度も適用していなかったサーバー」に集中した（出典1・2・3）。さらに8月7日の勧告は、影響を Lightning 実装 LND の資格情報ファイルに限り、「BTCPay Server のオンチェーンのウォレット（ホットウォレットを含む）は影響を受けない」と明記していた（出典2。本記録の訳。原文英語）——その3か月後に、未更新のサーバーでオンチェーンのホットウォレットが空にされた。

攻撃の経過

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

**公表されているのは、影響を受ける版と被害の結果だけである**（出典1）。 **悪用の方法について同プロジェクトが述べたのは 「2.4.2 で修正された脆弱性を、別の方法で悪用していた」という一文で、 技術的な詳細は意図的に公表されていない**（出典1・2。本記録の訳。原文英語）。 **攻撃者がサーバー上で何をしたかについての唯一の記述は、 「管理者としてサインインし、ホットウォレットを掃き出した」という 第三者分析の報道である**（出典4）〈齟齬1〉。

  1. 1. 初期侵入確認済[1] [2] [3]
    **2.4.1 以前の BTCPay Server に存在した脆弱性が悪用された**（出典1）。 **同じ脆弱性は 2.4.2（2026年8月7日公開）で修正されており、 今回の攻撃はそれを「別の方法で」悪用したとされる**（出典1。本記録の訳。原文英語）。 **8月7日の勧告は、この脆弱性を 「未認証の遠隔攻撃者が Lightning 実装 LND の資格情報ファイル（`.macaroon`）を 取得できる」ものと説明していた**（出典2。本記録の訳。原文英語）。 **具体的な悪用手順は、更新の時間を確保するため公表されていない** （出典2）〈未確定4〉。 **攻撃者がいつ悪用を始めたかも確定されていない**（出典1）〈未確定3〉。
    根拠: 調査更新の影響範囲の記述と8月の勧告（出典1・2）
  2. 2. 権限昇格推定[4]
    **Bitquery の解析として、「窃取者は管理者としてサーバーにサインインし、 ホットウォレットを掃き出した」と報じられている**（出典4。本記録の訳。原文英語）。 **BTCPay Server 自身の公表には、サインインの手順についての記述が無い**（出典1）。 **資格情報を奪ったのか、認証を迂回したのか、既存の権限を乗っ取ったのかは 公表されていない**〈未確定8〉。
    根拠: Bitquery の解析として報じられた記述（出典4）
  3. 3. 影響（暗号化・破壊・改ざん）確認済[1] [4]
    **サーバー上に送金鍵を置くホットウォレットから、 Bitcoin と Litecoin が掃き出された**（出典1）。 **Bitquery の解析として、18.38 BTC と3,405 LTC（約163万ドル相当）が 2つのアドレスへ、2026年10月30日から11月2日の午前までに 682回の掃き出しで移されたと報じられている**（出典4）。 **うち87%は11月1日の午後から夜にかけての一波で動いた**（出典4）。 **送金鍵をサーバーの外に保持しているウォレット（ハードウェアウォレットを含む）の資金は 影響を受けなかった**（出典1。本記録の訳。原文英語）。
    根拠: 調査更新の記述（出典1）と Bitquery の解析として報じられた数値（出典4）
  4. 4. 永続化推定[1]
    **同プロジェクトは「更新だけでは、攻撃者が既に得たアクセスを取り除くことはできない」 と明記した**（出典1。本記録の訳。原文英語）。 **そして 2.4.1 以前を動かしていた運用者には、 窃取に気づいていなくても、またその後に更新していても、 新しいサーバーと新しいウォレット（新しい種）へ移すよう求めた**（出典1）。 **古いサーバー全体を新しいサーバーへ復元してはならないとも述べている**（出典1）。 **これは、攻撃者が残した足がかりが更新では消えないという判断である** （本記録の読み） ——**具体的に何が残るのかは公表されていない**〈未確定4〉。
    根拠: 調査更新の助言の記述（出典1）

**本記録は、修正版の公開（2026年8月7日）から最初の記録された流出（11月1日）までの 86日を、侵入の滞留時間としては使わない**（本記録の方針） ——**86日は「更新されなかった期間」であって「攻撃者が内部にいた期間」ではない。**
認識から封じ込めまで
**算出できない。** **封じ込めを行う主体が単一でない**（本記録の明示）。 **同プロジェクトが取れた手は、公開の警告（11月1日22時25分 UTC・認識から89分）と ホスティング事業者への直接の依頼（同日）である**（出典1）。 **実際に止まったかどうかは各運用者の操作に依存し、集計されていない**〈未確定1〉。 **Bitquery の解析では、警告の後にも267回・約15万ドル相当の掃き出しが数えられた** （出典4）。
**本記録は、この89分を「封じ込め」とは呼ばない**（本記録の判断） ——**警告の発信は封じ込めの依頼であって、封じ込めそのものではない。** **自己ホスト型の提供者が持つ実効手段は、警告とホスティング事業者への連絡に限られる** （本記録の整理）。
認識から公開の警告まで
**89分である**（出典1。本記録の算出）。 **最初の窃取報告メールが11月1日20時56分 UTC に届き、 同日22時25分 UTC に X で警告してサーバーの停止を求めた**（出典1）。
**本記録はこれを速いと評価する**（本記録の判断） ——**根拠は、影響範囲（どの版が対象か）の特定を待たずに 「止めてほしい」を先に出していることである**（出典1）。 **版の特定は翌日（11月2日）の調査更新で行われた**（出典1）。 **順序として、正確さより先に停止を取っている**（本記録の評価）。

**算出できない。** **復旧の単位が各運用者であり、完了を集計する主体が無い** （本記録の明示）〈未確定1〉。 **同プロジェクトが求めているのは復旧ではなく再構築である** ——**新しいサーバーと新しいウォレットへの移行、資格情報の失効と入れ替え**（出典1）。
**「更新だけでは、攻撃者が既に得たアクセスを取り除くことはできない」という明示があり、 更新の完了を復旧とみなせない構造になっている**（出典1。本記録の訳。原文英語）。
