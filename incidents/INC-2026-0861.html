INC-2026-0861ESET が Gorbag を命名

ESET が2026年11月3日、2025年2月以降ウクライナの標的だけを狙い続けるロシア寄りの脅威アクターを Gorbag と命名して公表した。標的の約4分の1が法執行・司法機関、約4分の1が前線近くの市議会などの地方自治体で、ほかに防衛関連組織と外国からの軍事支援の主要な輸送拠点が含まれる。道具は自製の情報窃取ツール BeautyStealer と公開コードを改変した Prime ReverseShell で、2026年初頭に初期侵入を WinRAR の脆弱性 CVE-2025-8088 を悪用した RAR 書庫へ切り替えた。長期の居座りをせず情報を取ったら痕跡を消すため、ESET は他の攻撃者への初期アクセス提供の可能性を指摘している

脅威・攻撃キャンペーン脆弱性初報のみ有名事象として記録（日本と直接の関係は薄い）既知の脆弱性の悪用人を介した誘導（ビッシング・BEC）脆弱性の放置
初報: 2026年11月3日 最終更新: 2026年11月3日

2026年11月3日、ESET が Gorbag と名付けたロシア寄りの脅威アクターの調査結果を公表しました（記事題名「Gorbag: Orcs at the border harvesting intelligence from Ukraine」）。

少なくとも2025年2月以降、標的はウクライナのみです。 ESET は「少なくとも2025年2月から活動しており、同グループはもっぱらウクライナの標的に集中してきた。明確な傾向として、法執行・司法機関、前線近くの地方自治体、そして防衛部門を好んでいる」（原文英語）と述べています。

標的の構成が、目的を物語っています。 約4分の1がウクライナの法執行・司法機関で、ESET はロシアの戦争犯罪に関する捜査や、ウクライナ国内のロシア工作員・協力者の特定の動きを監視する狙いがありうるとしています。さらに約4分の1は前線に近い地域の市議会などの地方自治体で、こうした機関はロシアの空爆による被害の査定や重要インフラの復旧見込みといった非公開の情報を持ちます。残りは防衛関連組織と、外国からの軍事支援の主要な輸送拠点（施設名は非公表。過去にロシアの空爆を受けたことがあるとされる）です。

道具は高度ではありません。 主力は C++ で書かれた情報窃取ツールBeautyStealer（バージョン 0.9 から 2.0 まで追跡）で、ブラウザに保存された認証情報・Cookie・OpenVPN の設定・各種文書を集め、Telegram または FastAPI で作られた独自の C&C サーバへ送った後、自身を削除します。もう一つは公開の GitHub リポジトリから派生したPowerShell のリバースシェル Prime ReverseShell です。

2026年初頭、初期侵入が切り替わりました。 それまでのマクロ付き Excel から、WinRAR の脆弱性 CVE-2025-8088 を悪用する RAR 書庫になりました。この脆弱性は2025年7月30日に修正済みで、ESET が最初に報告したときの悪用者は別のロシア寄りの攻撃者 RomCom でした。

長く居座らないことが、この攻撃者の特徴です。 ESET は、数か月にわたって侵害網への接続を維持する高度な諜報グループと違い、Gorbag は素早く情報を盗んで痕跡を消すことに集中していると述べ、盗んだ認証情報や文書を後続の侵入を担う別の攻撃者へ渡す「初期アクセス提供者」として動いている可能性を指摘しています（ただし ESET は、そうした協力が実際にあるかは確認できていないとしています）。

攻撃の経過

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

**Gorbag は、素早く情報を取って痕跡を消すことに特化している**（出典1）。 **初期侵入は2025年がマクロ付き Excel、2026年初頭からは CVE-2025-8088 を 悪用する RAR 書庫である**（出典1・2）。 **主力の BeautyStealer はブラウザの認証情報・Cookie・OpenVPN の設定・ 各種文書を集め、Telegram または独自の C&C サーバへ送った後、 自身を削除しようとする。** **以下の各段階は ESET の記述に基づく。 手口はいずれも既知のもので、新しいのは標的の選び方の精密さである** （本記録の整理）。

  1. 1. 初期侵入確認済[1] [2] [3]
    **2025年——マクロを有効にした Excel 文書によるスピアフィッシング**（出典1）。 **題目は行政上の過料や税金といった公的なもの。 1通は侵害されたウクライナの地方自治体のアカウントから送られていた** ——**正規の送信元から届くため、送信者の照合では見分けられない** （本記録の注記）。 **2026年初頭以降——CVE-2025-8088 を悪用する RAR 書庫**（出典1・2）。 **代替データストリームを用いるパストラバーサルで、 意図しない場所へファイルを書き込む。** **この脆弱性は2025年7月30日に修正されており、ゼロデイではない。**
    根拠: ESET のテレメトリおよび回収された検体（SHA-1 で4点が記事に掲載）
  2. 2. 実行確認済[1]
    **マクロ経路**——マクロが **base64 のペイロードを復号**して **BeautyStealer** を設置する（出典1）。 **RAR 経路**——**おとりの PDF を表示**しつつ、 **暗号化されたペイロードと PowerShell のローダ**を設置する（出典1）。 **Prime ReverseShell は PS2EXE で実行形式に包んだ PowerShell であり、 公開の GitHub リポジトリから派生している**（出典1）。
    根拠: ESET による検体解析
  3. 3. 永続化確認済[1]
    **RAR 経路では、スタートアップフォルダに LNK ファイルを置いて 永続化する**（出典1）。 **一方で BeautyStealer 自体は、情報を送った後に自身を削除しようとする** ——**長期の居座りを目的としていない**（出典1・2）。
    根拠: ESET による検体解析
  4. 4. 認証情報アクセス確認済[1] [2]
    **BeautyStealer が、ブラウザに保存された認証情報と Cookie、 および OpenVPN の設定を収集する**（出典1・2）。 **Cookie を取れば多要素認証を経た後のセッションを引き継げる** （本記録の注記）。
    根拠: ESET による検体解析
  5. 5. 収集確認済[1] [2]
    **BeautyStealer が、コンピュータ本体・取り外し可能な記憶装置・ 接続されたネットワークドライブを探索し、価値のありそうなファイル （Office 文書・メールの記録・書庫ファイル）を集める**（出典1・2）。
    根拠: ESET による検体解析
  6. 6. 持ち出し確認済[1] [2]
    **持ち出しは Telegram、または FastAPI で作られた独自の C&C サーバへ行う** （出典1）。**送信後、BeautyStealer は自身を削除しようとする**（出典1・2）。 **記事には持ち出し先の IP アドレスが1点示されている。**
    根拠: ESET のテレメトリおよび検体解析（IP アドレス2点を記事に掲載）

BeautyStealer の動きは、一般的な諜報型のバックドアと逆である。

  • 探す範囲——コンピュータ本体、取り外し可能な記憶装置、接続されたネットワークドライブ
  • 集めるもの——ブラウザに保存された認証情報と Cookie、OpenVPN の設定、Office 文書、メールの記録、書庫ファイル
  • 送る先——Telegram、または FastAPI で作られた独自の C&C サーバ
  • 送った後——自身を削除しようとする

ESET は「数か月にわたって侵害したネットワークへの接続を維持しようとするより洗練されたサイバー諜報グループと異なり、Gorbag はマルウェアの痕跡を消す前に素早く情報を盗むことに集中しているようにみえる」（原文英語）と述べ、そこから他のグループとの協力の可能性——盗んだ認証情報や文書を後続の侵入を行う操作者へ渡しているのではないか——を指摘している。

ただし ESET は、そうした協力が実際に行われているかを確認していないと明記している〈未確定4〉。本記録はこれを可能性の指摘として扱い、確認された事実としては扱わない。

ここからは本記録の作成者の評価である。

第一に、「VPN の設定を取る」ことの意味が大きい。 OpenVPN の設定ファイルは、どこへどうつなぐかの地図である。ブラウザに保存された認証情報と組み合わせれば、次の侵入はフィッシングを経ずに正面から入れる。 居座らずに消える設計と、VPN 設定を取る設計は、同じ目的（次の侵入者への引き渡し）にきれいに整合する。

第二に、「道具が高度でないこと」は、防げることを意味しない。マクロ付き Excel も、修正済みの WinRAR の穴も、公開コード由来のリバースシェルも、どれも新しくない。 にもかかわらず ESET が21か月にわたる活動を追跡できているのは、標的側で古い WinRAR が動き、マクロが実行できる状態が残っているからである。高度な攻撃者への備えより先に、既知の穴が埋まっているかを測るべき事例である。

第三に、前線近くの自治体が持つ情報の価値に注意が要る。 ESET が挙げたのは「空爆の被害査定」「重要インフラの復旧見込み」である。これは軍事機密ではなく、行政の業務情報である。自治体の情報システムは防衛関連組織ほどの投資を受けないのが通例だが、攻撃者から見た価値は、打撃の効果測定に直結する。 「機密を扱わないから狙われない」という前提が成り立たない。

ここからは本記録の作成者の評価である。

Gorbag の標的構成が示しているのは、戦時の情報要求が「軍事機密」より広いということである。司法機関が持つのは捜査の進捗であり、地方自治体が持つのは被害の査定と復旧の見込みである。どちらも軍の秘密ではない。だが前者は工作員の摘発の予測に、後者は打撃の効果測定に直結する。

日本の読者への当てはめは、「紛争当事国でないから無関係」とはならない点にある。本件の構造は、「業務情報を持つ中小規模の公的組織が、高度でない手口で継続的に狙われる」というものである。日本でも、自治体・司法関連・物流拠点は、①相対的に投資が小さく、②業務情報の価値が外部から見えにくく、③委託・連携が多い——という同じ条件を備えている。

もう一つ、「正規のアカウントから届くフィッシング」への備えが要る。本件では侵害されたウクライナの地方自治体のアカウントからスピアフィッシングが送られていた。 送信ドメインの認証（SPF・DKIM・DMARC）は通る。送信元の正当性ではなく、添付の中身とマクロの実行可否で止めるしかない。

最後に、この事案は「パッチの遅れがそのまま国家の諜報に使われる」例として読むべきである。 CVE-2025-8088 は修正から1年近く経ち、KEV にも載っていた。それでも2026年初頭に初期侵入として選ばれたのは、選ばれるだけの未更新の端末が標的側に残っていたからである。既知の脆弱性の棚卸しは、高度な攻撃者への備えより先に来る。

段階検知の機会効きえた対策
初期侵入機会はあったが検知できず

対応の評価

評価材料がない判断は「評価材料なし」としています。結果論で断じないための区分です。
判断評価評価の根拠と留保
ESET が、標的の業種構成（約4分の1が法執行・司法、約4分の1が地方自治体）と 地理は示したが、**組織名と標的の総数は示さなかった。** 軍事支援の輸送拠点についても施設名を明示的に伏せた部分的に機能**本記録の作成者の評価である。** **戦時下の輸送拠点の施設名を伏せた判断は妥当である** ——同拠点は過去にロシアの空爆を受けたと ESET 自身が述べている。 **一方、標的の総数を示さなかったことで、 「約4分の1」という割合が規模の情報として使えなくなっている** 〈未確定2〉。**10組織の4分の1と200組織の4分の1は、 読者が取るべき行動が違う。**
ESET が、MITRE ATT&CK の21技術と指標（ファイル4点・IP アドレス2点）を 記事に掲載し、**全量は GitHub リポジトリに置いた**機能した**本記録の作成者の評価である。** **指標を機械可読な形で別に置き、記事では代表例と ATT&CK の対応だけを 示す構成は、防御側が使いやすい。** **ただし本記録は指標の全量を確認していないため、 内容の充分性は評価していない**〈齟齬4〉。
CISO・経営層への示唆
  • 「高度でない攻撃者」が21か月続いている事実を、投資の優先順位の根拠にする
    Gorbag はゼロデイを持たず、マクロ付き Excel と修正済みの WinRAR の 脆弱性、公開コード由来のリバースシェルで21か月活動を続けている
    取るべき行動 次の四半期の投資判断で、**高度な脅威への新規投資より前に 「既知の脆弱性の残存率」と「マクロ実行の許可範囲」を数値で報告させる。** 未更新端末の割合を KPI に置き、月次で経営へ出す
  • 「機密を扱っていないから狙われない」という前提を捨てる
    狙われたのは軍事機密ではなく、前線近くの自治体が持つ 空爆の被害査定・重要インフラの復旧見込みという**行政の業務情報**だった
    取るべき行動 自組織の保有情報を「機密区分」ではなく「**外部の誰にとって 価値があるか**」で棚卸しし直す。復旧見込み・在庫・稼働率・ 人員配置といった業務情報の持ち出しが事業に何をもたらすかを リスク評価に明記する
  • 委託先・連携先の正規アカウントから届くフィッシングを前提に備える
    スピアフィッシングの1通は、**侵害されたウクライナの地方自治体の アカウント**から送られていた。送信ドメインの認証は通る
    取るべき行動 「取引先からのメールだから安全」という運用を廃し、 **添付の種類（書庫・マクロ付き文書）で判断する方針**に切り替える。 連携先に侵害があった場合の相互通報を契約に書き込む
  • 認証情報の窃取が「次の侵入者への引き渡し」である可能性を、 初動の判断に織り込む
    ESET は、Gorbag が長期の居座りをせず素早く盗んで消える傾向から、 他の攻撃者への初期アクセス提供の可能性を指摘している （確認はされていない）
    取るべき行動 情報窃取型マルウェアを検知したときの初動手順に、 **「盗まれた認証情報と VPN 設定の全面無効化・再発行」を 必須の工程として書き込む。** 「大した被害はない」で終わらせない
セキュリティ技術者への示唆
  • WinRAR のような「自動更新を持たない常用ソフト」の版を継続的に測る
    CVE-2025-8088 は2025年7月30日に修正され KEV にも載ったが、 2026年初頭に初期侵入の経路として選ばれた——未更新の端末が残っていた
    取るべき行動 資産管理で WinRAR・7-Zip・PDF 閲覧ソフトなど**自動更新を持たない 常用ソフトの版を一覧化**し、KEV 収載済みの脆弱性に該当する端末を 週次で洗い出す。配布の仕組みが無ければ、まず一覧化だけでも始める
  • スタートアップフォルダへの LNK 作成を警報にする
    CVE-2025-8088 経由の侵入は、スタートアップフォルダに LNK ファイルを 置いて永続化していた
    取るべき行動 ファイル整合性監視または EDR で、利用者・全ユーザのスタートアップ フォルダへの新規ファイル作成（とくに .lnk）を検知条件にする。 正規の登録を棚卸ししてから有効化し、誤検知を潰す
  • ブラウザの認証情報ストアと `.ovpn` ファイルへの読み取りを検知対象にする
    BeautyStealer はブラウザの認証情報と Cookie、OpenVPN の設定を集めていた。 VPN 設定は「どこへどうつなぐか」の地図である
    取るべき行動 EDR で、ブラウザの認証情報ストアと拡張子 `.ovpn` のファイルへの 読み取りアクセスを検知する規則を作る。**`.ovpn` は業務上ほとんど 読まれないため誤検知が少ない。** あわせて VPN を証明書・ デバイス認証へ移し、端末に再利用可能な設定を置かない構成を検討する
  • 自己削除するマルウェアを前提に、ネットワーク側の記録を長期保存する
    BeautyStealer は情報を送った後に自身を削除しようとする。 端末側の証跡が消える
    取るべき行動 外向き通信のログ（接続先・データ量・時刻）を最低90日保存し、 **端末の検体が無くても「いつ・どこへ・どれだけ送ったか」を 復元できる状態にする。** 業務で使わないメッセージング サービスの API への通信は既定で遮断する
  • Office アプリケーションからの子プロセス生成を遮断する
    2025年の侵入は、マクロが base64 のペイロードを復号して BeautyStealer を設置する形だった
    取るべき行動 攻撃面の削減規則（ASR）で Office からの子プロセス生成を遮断モードにする。 影響を測るため先に監査モードで2週間運用し、業務のマクロを洗い出してから 切り替える
