INC-2026-0882搜狗入力法のDNS乗っ取りでDarkVigil配布

中国寄りの脅威グループ SlippyNunchucks が、搜狗入力法（Windows 版）が 平文 HTTP で取りに行く「ブランド宣伝」設定の応答を DNS 乗っ取りで差し替え、 監視用インプラント DarkVigil（FDMTP）を配っていた—— ESET が2026年11月4日に公表。2026年7月1日からの配布で、 日本を含む6か国の組織と中国語話者が標的になった。 Tencent は10月末の 16.10 で該当通信を HTTPS へ移したが、 ダウンローダ側の検証不足は残っている

脅威・攻撃キャンペーン脆弱性初報のみ日本に波及した海外事案設計・実装上の不備既知の脆弱性の悪用公表されていない／不明
初報: 2026年11月4日（ESET Research の公表） 最終更新: 2026年11月5日（本記録の作成。ESET の報告を取得して裏を取った時点）

ESET は2026年11月4日、「SlippyNunchucks hijacks Sogou Input Method's brand promotion mechanism to distribute malware」を公表した（出典1）。中国寄りの脅威グループが、搜狗入力法（Sogou Input Method）の Windows 版が平文 HTTP で取りに行く設定の応答を DNS 乗っ取りで差し替え、監視用インプラント DarkVigil（別名 FDMTP）を配っていたとする（出典1）〈重要〉。

仕組みはこうである（出典1）。搜狗入力法には2016年から「Startup Brand Support Program」があり、承認されたブランド名が変換候補に緑の新芽の印つきで出る。 この仕組みのためにブランド用のアイコンを取得する設定要求が、config.pinyin.sogou[.]com/api/brandScd/getBrandScd.php へ平文 HTTP で送られていた（出典1）。要求を出すのは SGTool.exe（--appid=scdreg -update で起動）である（出典1）。応答は AES-256-CBC で暗号化されているが、鍵と初期化ベクトルは SGTool.exe の .rdata にハードコードされており、攻撃者は正しい md5 値を添えた偽の設定を返せた（出典1）〈重要〉。

被害者の環境では、このホスト名の名前解決が攻撃者の中継サーバ（47.239.250[.]102 または 47.237.122[.]175）へ向けられていた（出典1）。偽の設定は2つのファイルの取得を指示する（出典1）—— biz_helper.exe（Adobe の正規署名入りバイナリを改名したもの）とlibcef.dll（DarkVigil 本体）。 これらは搜狗の部品として置かれ、搜狗自身の処理の流れがAdobe のバイナリを実行し、そこから libcef.dll が読み込まれる（出典1）〈重要〉—— 別の永続化の仕掛けを要しない。

観測されたのは2026年7月1日からで、標的は香港・タイ・日本・ベトナム・スリランカ・オマーンの組織および中国語話者である（出典1・3）〈重要〉—— 日本が標的国に挙げられている。 具体例として、スリランカ・フィリピン・香港で中国語の賭博サイトを運営する多国籍の賭博組織、ドバイのインターネットカフェ、デンマークの大学生が挙げられている（出典1・2）。侵害された端末数・被害者数は公表されていない（本記録の確認）〈未確定3〉。

ESET は2026年9月11日に Tencent Security へ報告し、同月21日に Tencent が認識した（出典1・2）。搜狗入力法 16.10 が10月末に公開され、該当する要求は HTTPS へ移り、証明書のピン留めが入った（出典1・2）。ただし ESET は、ダウンローダが取得したファイルの型を検証せず保存先も制限していない点は残っていると指摘している（出典1・2）〈重要〉。

帰属について、ESET は DarkVigil を Mustang Panda に結びつける公開報告があることに触れつつ、自社のテレメトリに重なりは無く、SlippyNunchucks を別のグループとして追跡しているとしている（出典1）〈重要〉—— 本記録はこの不一致をそのまま記録する（本記録の明示）。

攻撃の経過

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

**本件の攻撃は、利用者が何も操作しないまま、 正規のアプリが自分で取りに行く通信の応答を差し替えることで始まる** （出典1）〈重要〉—— **突かれたのは「平文 HTTP」と「ハードコードされた鍵」と 「取得ファイルの検証不足」の3点である。** **設置も実行も搜狗自身の処理の流れに乗るため、 攻撃者は永続化の仕掛けを作らない。** **以下の各段階は ESET の報告（出典1）に基づく。** **DNS の改変がどこで行われたのかは特定されていないため、 その段階は `unknown` として記録する**（本記録の明示）〈未確定1〉。

  1. 1. 初期侵入確認済[1] [2]
    **被害者の環境で `config.pinyin.sogou[.]com` の名前解決が 攻撃者の中継サーバ（47.239.250[.]102 または 47.237.122[.]175。 `sogou-cdn[.]com` を提供）へ向けられていた**（出典1）。 **改変がどこで起きたのかは特定されていない**（出典1）〈未確定1〉—— **ESET は、悪性の DNS 設定を入れられたルータ、 DNS 乗っ取りの機能を埋め込まれたルータ、 ISP 水準での傍受の3つを可能性として挙げている**（出典1・2）。 **ATT&CK では T1557（Adversary-in-the-Middle）に対応づけられている** （出典1）。
    根拠: ESET の報告（名前解決の向き先・中継サーバの IP・ATT&CK の対応づけ）
  2. 2. 実行確認済[1] [2]
    **`SGTool.exe` が `--appid=scdreg -update` で起動され、 `config.pinyin.sogou[.]com/api/brandScd/getBrandScd.php` へ 平文 HTTP で設定を要求する**（出典1）。 **応答は AES-256-CBC で暗号化されているが、 鍵と初期化ベクトルは `SGTool.exe` の `.rdata` にハードコードされており、 攻撃者は正しい md5 値を添えた偽の設定を返せた**（出典1）〈重要〉。 **TLS が無いため証明書の検証も働かない**（出典1）。 **ATT&CK では T1659（Content Injection）に対応づけられている**（出典1）。
    根拠: ESET の報告（端点・鍵と IV の位置・md5 の整合・ATT&CK の対応づけ）
  3. 3. 永続化確認済[1]
    **偽の設定は2つのファイルの取得を指示する**（出典1）—— **`biz_helper.exe`（Adobe Licensing WF Helper の正規署名入りバイナリを 改名したもの）と `libcef.dll`（DarkVigil 本体）。** **設置の経路は2つあり、同時には一方しか働かない**（出典1）。 **経路A: Adobe のバイナリを `\Components\SogouComMgr.exe` として保存し、 正規の管理プログラムを置き換える。 以後、導入や読み込みの呼び出しが Adobe のバイナリを実行する。** **経路B: `\Components\biz_center\<version>\` の下に置く。 `SGTool.exe` はしばしば `SogouComMgr.exe` を `-invoke BizCenterComBundle BizCenterCom` で起動し、 そのディレクトリの Adobe のバイナリを実行する。** **ESET は両経路とも破壊的で、ソフトウェアの動作不良を 引き起こしやすいとしている**（出典1）。 **ATT&CK では T1036.005（Masquerading: Match Legitimate Resource Name or Location）に対応づけられている**（出典1）。
    根拠: ESET の報告（2経路の配置先・起動引数・破壊的である旨）
  4. 4. 検知回避確認済[1]
    **実行されるのは Adobe の正規署名入りバイナリであり、 そこから悪性の `libcef.dll` が側読み込み（side-load）される**（出典1）。 **ATT&CK では T1574.001（Hijack Execution Flow: DLL）に 対応づけられている**（出典1）。 **搜狗自身の処理の流れを使うため、別の永続化の仕掛けは要らない** （出典1）〈重要〉。
    根拠: ESET の報告（側読み込みの経路・永続化を別に要しない旨）
  5. 5. C2通信確認済[1]
    **DarkVigil は DMTP（Duplex Message Transport Protocol）で C&C と通信する**（出典1）—— **TouchSocket を基にした Vigil という枠組みの上に作られており、 逆方向の RPC と、クライアント・サーバおよびクライアント間の 同時の通信路を持つ**（出典1）。 **クライアント側は PluginService と OptionService の RPC サービスを持つ** （出典1）。 **起点となるドメイン・サーバとして `blog.wangmengfun[.]top`・`update.mssproxy[.]net`・`img.fusfun[.]top`・ 47.86.15[.]162 が挙げられている**（出典1）。 **ATT&CK では T1071.001（Application Layer Protocol: Web Protocols）と T1573（Encrypted Channel）に対応づけられている**（出典1）。
    根拠: ESET の報告（DMTP の説明・RPC サービス・起点サーバの一覧）
  6. 6. 収集確認済[1] [2]
    **プラグインは DMTP のファイル転送でサーバから送られ、 レジストリ（`HKCU\Software\Microsoft\IME\<HWID>\pluginHash`）に 圧縮された形で登録されてから実行される**（出典1）。 **確認されているのは20を超えるプラグインだが、 名前が挙がっているのは Pillager の1つだけである**（出典1・2）〈未確定6〉。 **プラグインの通信はクライアントを経由して C&C に中継される**（出典1）。 **ATT&CK では T1112（Modify Registry）と T1105（Ingress Tool Transfer）に 対応づけられている**（出典1）。
    根拠: ESET の報告（プラグインの配送と登録の仕組み・レジストリの位置）
  7. 7. 持ち出し確認済[1]
    **持ち出しは C&C の通信路（DMTP）を通じて行われ、 データは Vigil という名のウェブ管理画面で扱われる**（出典1）。 **ATT&CK では T1041（Exfiltration Over C2 Channel）に 対応づけられている**（出典1）。 **何がどれだけ持ち出されたかは公表されていない**（本記録の確認）〈未確定3〉〈未確定6〉。
    根拠: ESET の報告（DMTP 経由の持ち出し・Vigil の管理画面・ATT&CK の対応づけ）

    平文 HTTP と同梱された鍵——「暗号化してある」が成り立たなくなっていた原因・手口

    本件の中核は、搜狗入力法の設定取得の設計である（出典1）。

    搜狗入力法には2016年から「Startup Brand Support Program」があり、承認されたブランド名が変換候補に緑の新芽の印つきで表示される（出典1）。この仕組みのためにブランド用のアイコン（セル辞書のアイコン）を取得する設定要求が、config.pinyin.sogou[.]com/api/brandScd/getBrandScd.php へ平文 HTTP で送られていた（出典1）。要求を出すのは SGTool.exe（--appid=scdreg -update で起動）で、少なくとも30のコマンドIDを持つ多目的のタスク配分器である（出典1）。

    設定の応答は AES-256-CBC で暗号化されている（出典1）—— 一見、守られているように見える。 しかし鍵と初期化ベクトルは SGTool.exe の .rdata セクションにハードコードされていた（出典1）〈重要〉。攻撃者は正しい md5 値を添えた偽の設定を返せたため、完全性の検査も通った（出典1）。TLS が無いので証明書の検証も働かない（出典1）。

    本記録はこの構造をこう整理する（本記録の整理）〈重要〉—— 「暗号化してある」は、鍵が相手側にしか無いときに意味を持つ。 鍵をクライアントに同梱した暗号化は、通信の秘匿にはなっても、送り手の真正性の保証にはならない。 ここで必要だったのは暗号化ではなく、TLS と署名検証だった。

    範囲についての数字が1つ出ている（出典1）—— ESET は同一ホスト（config.pinyin.sogou[.]com）上に、平文 HTTP でアクセスされる端点を20個確認している〈数値5〉。悪用されたのはそのうち1つである。

    DNS をどこで曲げたのかは分かっていない——「製品を直せば終わる」話ではない未確定事項

    本記録はどれかを断定しない（本記録の留保）〈未確定1〉。そのうえで、この欄が空いていることの意味を書いておく（本記録の判断）〈重要〉—— 搜狗入力法 16.10 で該当する要求が HTTPS になっても、DNS を曲げられる地点に居る主体は消えない。 同じ地点に居る主体は、平文 HTTP で設定や更新を取りに行く他のアプリに対して同じことができる。
