INC-2026-0883NIKKEランチャー配布基盤が改ざん

人気ゲーム「勝利の女神：NIKKE」の PC ランチャーが、公式の配布基盤（Level Infinite の CDN）ごと改ざんされた—— 2026年9月27日に Tencent Cloud のオブジェクトストレージ上の JavaScript 4本へローダーが仕込まれ、 ランチャーを起動しただけで LuaJIT 製の遠隔操作エージェントがメモリ上で走る。 エージェントは任意コマンドの実行・全画面のスクリーンショット・ブラウザ保存の資格情報に加え、 SSH 鍵・クラウド鍵・開発ツールの設定など264の経路と28種の暗号資産ウォレット拡張を走査する。 Level Infinite は2026年11月4日にファイル改ざんを認めて修正版を配信したが、感染台数も流出の有無も公表していない

委託先・再委託先起因で委託元多数に波及不正アクセス・侵害続報が続いている有名事象として記録（日本と直接の関係は薄い）委託先・供給元起因権限管理の不備設計・実装上の不備
初報: 2026年11月3日（独立研究者 MotherSphere の技術解析レポートの公開） 最終更新: 2026年11月5日（本記録の作成。研究者レポートと報道を取得して突き合わせた時点）

公式サイトから正規に入手したゲームランチャーを起動しただけで、PC が外部から遠隔操作される状態になる。 2026年11月、人気ゲーム 「勝利の女神：NIKKE」（開発: 韓国 SHIFT UP／流通: Tencent の海外パブリッシングブランド Level Infinite）の PC 版ランチャーの配布基盤がソフトウェアサプライチェーン攻撃を受けていたことが明らかになりました。

侵害の起点は、ゲームクライアント自体の欠陥ではありません。 流通側 Level Infinite が運用する公式 CDN（Tencent Cloud のオブジェクトストレージ／COS 上の playerinfinite.com）に置かれた4本の JavaScript ファイル（aegis-fix.min.js・images.7fec4c32.js・FeedList.feb647c9.js・vue-bucket.min.js）です。独立研究者 MotherSphere の技術解析によれば、これらは 2026年9月27日 06時41〜42分（GMT）に書き換えられ、攻撃者ドメイン insightjs.com（予備に insightjs.org）から追加コードを取得するローダーが仕込まれました。

ランチャーを起動すると、改ざんされたスクリプトが内蔵ブラウザの背後で攻撃者サーバに接続します。続いてランチャー自身のダウンロード機能を使い、LuaJIT 製のペイロード（insight.bundle）をログファイルを装った拡張子で取得してメモリ上で実行します。これは K2F と名付けられた遠隔操作エージェントで、自前の通信機能を持たず、通信はすべてランチャーの内蔵ブラウザを経由します。

できることは、任意のプログラムとシェルコマンドの実行・端末内のファイルの閲覧と持ち出し・全モニタのスクリーンショット・Chrome／Edge／Brave／Vivaldi／Opera／Firefox に保存されたパスワードと Cookie の窃取・Windows 資格情報マネージャーの開発者向けエントリの読み出しです。走査対象として挙げられているのは 264のファイルおよびレジストリ経路—— SSH 鍵・クラウドと開発者の資格情報・AI ツールの設定・シェル履歴・プロジェクトの .env——および 28種の暗号資産ウォレット拡張です。永続化は Chrome を使います。 HKCU\Software\Classes\CLSID\{E77CC89B-...} に DLL を登録し、ランチャーを閉じた後も Chrome の起動のたびに走り続けます。

Level Infinite は2026年11月4日（GMT 03時13分）に、「PC ランチャーのスクリプトファイルが第三者によって改ざんされた可能性のある異常を確認した」と表明し、同日午前2時30分ごろ（KST）にクライアントの修正と更新を実施したと説明しました。ただし、感染台数・情報流出の有無・攻撃者が配布基盤の書き込み権限をどう取得したかは、いずれも公表されていません。

攻撃の経過

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

**本件は「配布基盤への書き込み → 正規ファイルの汚染 → 利用者端末での実行」という 3段の構造を持つ**（出典1・3。本記録の整理）〈重要〉—— **第1段（どうやって書き込み権限を得たか）は公表されていない**〈未確定1〉。 **第2段と第3段は、研究者の静的解析と BleepingComputer の確認によって具体的に分かっている**（出典1・3）。 **本記録は、第1段を推測で埋めない**（本記録の明示）。

  1. 1. 初期侵入推定[1] [2]
    **攻撃者が Level Infinite の公式配布網（Tencent Cloud COS 上の `playerinfinite.com`）への 書き込み権限を取得した**（出典1・2）。 **取得の経路・手段は公表されていない**（本記録の確認）〈未確定1〉。 **時期の上限は、改ざんが観測された2026年9月27日 06時41分（GMT）である**（出典1）。
    根拠: 研究者レポート（改ざんファイルの内容とタイムスタンプ）／報道（COS 基盤の公式配布網と記述）
  2. 2. 実行確認済[1] [3]
    **公式ランチャー用の JavaScript 4本に、`insightjs.com` から `l.js` を取得するローダーが挿入された** （出典1・3）。 **利用者がランチャーを起動すると、内蔵ブラウザの背後で攻撃者ドメインに接続し、 追加のペイロードを読み込む**（出典1・2・3）。 **BleepingComputer は4本のうち2本を自ら確認し、 難読化されたローダーが insightjs.com／insightjs.org からコードを取得・実行することを裏付けたと報じている** （出典3）。
    根拠: 研究者レポート（改ざんファイルと正規ファイルのハッシュ）／BleepingComputer の独自確認
  3. 3. 検知回避確認済[1] [2]
    **ペイロードはランチャーのダウンロード機能を使い、 LuaJIT 製の本体を平文のログ拡張子に見せかけて取得し、メモリ上で実行する**（出典2）。 **エージェントは自前の通信機能を持たず、 通信はすべてランチャーに内蔵されたブラウザのプロセスを経由する**（出典1）。 **サーバから中継されたコマンドにのみ応答する**（出典1）。
    根拠: 研究者レポートの静的解析／報道の記述
  4. 4. 認証情報アクセス確認済[1]
    **エージェントは、ランチャーが保存した NIKKE のログイン情報を復号し、 Chrome／Edge／Brave／Vivaldi／Opera／Firefox に保存されたパスワードと （無効化されていなければ）Cookie を読み出す**（出典1）。 **Windows 資格情報マネージャーの開発者向けエントリも読む**（出典1）。 **走査対象として264のファイル・レジストリ経路を持ち、 SSH 鍵・クラウドと開発者の資格情報・AI ツールの設定・シェル履歴・ プロジェクトの .env が含まれる**（出典1）〈数値3〉。 **28種の暗号資産ウォレット拡張のデータも対象だが、読み出しは Chrome のプロファイルに限られる** （出典1）〈数値4〉。
    根拠: 研究者レポートの静的解析（264経路・28ウォレット拡張 ID の列挙）
  5. 5. 永続化確認済[1] [2]
    **Windows では、`HKCU\Software\Classes\CLSID\{E77CC89B-7401-4C04-8CED-149DB35ADD04}` に DLL を登録し、 `PlatformExperienceHelper` の64桁16進のサブフォルダに配置する**（出典1）。 **Chrome がこれを読み込み、ランチャーを閉じた後も動作を続ける**（出典1）。 **登録自体に Chrome は不要である**（出典1）。 **報道は「レジストリに偽のモジュールを登録し、PC 起動後に Chrome が実行されるたびに バックドアが自動で走る」と伝えている**（出典2）。
    根拠: 研究者レポート（CLSID・配置先・読み込み経路）
  6. 6. C2通信確認済[1] [3]
    **第2段の取得先は `analytics.insightjs.com/comm/assets/insight.bundle` である**（出典1）。 **予備ドメインとして `insightjs.org` が用意されていた**（出典1・3）。 **エージェントの状態ファイルによれば、約30分（±6分）ごとに接続している**（出典1）。 **通信は 89.126.250.172（2026年10月21日ごろまで・未検証）および 89.127.233.127 を経由したと記録されている** （出典1）。
    根拠: 研究者レポート（ドメイン・IP・エージェント状態の解析）
  7. 7. 影響（暗号化・破壊・改ざん）確認済[1] [2] [4]
    **感染端末では、任意のプログラムとシェルコマンドの実行・ 利用者が到達できるファイルの閲覧と持ち出し・全モニタのスクリーンショットが可能だった**（出典1・2）。 **研究者は、任意コマンドの実行を「最も重大な機能」と評している**（出典1）。 **Linux／Steam Deck（Proton）でも、Wine がホームフォルダと環境変数を prefix に写すため保護にならないと記している**（出典1）。 **感染台数と実際の被害は公表されていない**（出典4）〈未確定4〉。
    根拠: 研究者レポートの静的解析／Level Infinite の声明（被害範囲は確認中）

    本件で突かれたのは、開発元 SHIFT UP が作ったクライアントの欠陥ではない（出典2・1）〈重要〉。流通を担う Level Infinite が運用する公式 CDN—— Tencent Cloud のオブジェクトストレージ（COS）を基盤とする playerinfinite.com——に置かれた4本の JavaScript が書き換えられた。

    書き換えの時刻は2026年9月27日 06時41〜42分（GMT）（出典1）。攻撃者ドメイン insightjs.com が登録されたのは同日01時59分で、ドメインを用意してから約4時間40分後に配布基盤へ手を入れている（本記録の算出）。準備と実行が同じ日のうちに完結していることは、書き込み権限がすでに手元にあったことを示唆する（本記録の読み。公表に根拠の記載は無い）。

    仕込まれたのはローダーである（出典1・3）—— ランチャーを起動すると、内蔵ブラウザの背後で insightjs.com から l.js を取り、さらに analytics.insightjs.com/comm/assets/insight.bundle を読み込む。 BleepingComputer は4本のうち2本を自ら確認し、難読化されたローダーが2つのドメイン（一方が落ちていれば他方）からコードを取得・実行することを裏付けたと報じている（出典3）。

    利用者の側に自衛の余地はほとんど無い（本記録の評価）〈重要〉—— 公式サイトから入手した正規のランチャーであり、署名も更新経路も通常どおりである。 「怪しいサイトから落とさない」という助言は、この形の攻撃には効かない。

    では配布側は何を見ていればよかったのか。 オブジェクトストレージへの書き込みは、「誰が・いつ・どのオブジェクトを置き換えたか」が記録に残せる操作である（本記録の評価）—— 38日間気づかれなかったことは、その記録が無かったか、見ていなかったかのどちらかを示す。 攻撃者がどうやって書き込み権限を得たのかは、いまも公表されていない〈未確定1〉。

    狙いは娯楽の資産ではなく開発者の鍵だった——264の経路と28のウォレットを走査する被害規模・影響範囲

    ペイロードは LuaJIT 製の遠隔操作エージェント（研究者は K2F と呼ぶ）で、自前の通信機能を持たない（出典1）〈重要〉—— 通信はすべてランチャーの内蔵ブラウザを経由し、サーバから中継されたコマンドにのみ応答する。 ランチャーが「自分のサーバから任意のファイルを取ってきて開く」能力を持っていたことが、改ざんされた JavaScript をそのまま遠隔操作の足場に変えた（本記録の評価）。

    機能として列挙されているのはこうである（出典1・2）—— 任意のプログラムとシェルコマンドの実行（研究者は「最も重大な機能」と評している）・利用者が到達できるファイルの閲覧・読み取り・持ち出し・全モニタのスクリーンショット・Chrome／Edge／Brave／Vivaldi／Opera／Firefox に保存されたパスワードと Cookie・ランチャーが保存した NIKKE のログイン情報の復号・Windows 資格情報マネージャーの開発者向けエントリ。

    本記録が重く見るのは、走査対象として実装されていた264の経路である（出典1）〈数値3〉〈重要〉—— SSH 鍵・AWS／Azure／GCP の鍵・GitHub トークン・Docker と Kubernetes の設定・AI ツールの設定・シェル履歴・プロジェクトの .env。 28種の暗号資産ウォレット拡張も対象だが、こちらは Chrome のプロファイルに限られる（出典1）〈数値4〉。

    この構成は、ゲームの利用者を踏み台にして「その人が働いている会社」へ入ることを狙っている（本記録の評価）。報道も、開発者端末を足掛かりにゲーム会社・IT 企業の内部開発網へ進む二次攻撃の意図と読んでいる（出典2）。韓国では事態を受けてネクソンが全社に「社内端末に NIKKE の PC ランチャーが入っていれば即削除し、セキュリティ部門へ引き渡す」よう通知し、クラフトンとネットマーブルも社内端末と業務網の監視を強化した（出典2）〈重要〉—— 「削除せよ」ではなく「引き渡せ」である点は、保全を残す形として理にかなっている（本記録の読み）。

    ただし、実際に何が持ち出されたかは分からない（出典1）〈未確定4〉—— 研究者は「窃取範囲は operator が送ったコマンド次第で、そのコマンドは記録されていない」と明示している。 本記録は「264経路・28ウォレットが窃取された」とは書かない（本記録の明示）。

    ランチャーを消しても残る——Chrome の CLSID 登録という永続化原因・手口

    永続化には Chrome が使われる（出典1）〈重要〉。HKCU\Software\Classes\CLSID\{E77CC89B-7401-4C04-8CED-149DB35ADD04} に DLL を登録し、PlatformExperienceHelper の64桁16進のサブフォルダに置く。 Chrome がこれを読み込むため、ランチャーを閉じた後も動き続ける。 登録そのものに Chrome は要らない（出典1）。

    実務上の意味は2つある（本記録の整理）。第一に、HKCU 配下の書き込みは管理者権限を要しない—— 一般利用者の権限で成立する永続化である。 第二に、ランチャーのアンインストールでは消えない〈重要〉—— 「ゲームを消したから大丈夫」は成り立たない（本記録の評価）。

    さらに、DLL は被害者ごとにビルドされるためハッシュが共有の指標にならないと研究者自身が記している（出典1）—— ハッシュのブラックリストに頼る検知は、この層では効かない。 見るべきは、ブラウザが読み込む DLL の新規登録という「振る舞い」のほうである（本記録の評価）。

    オリジンを直してもエッジには残る——「差し替えた日」と「解消した日」は7日ずれた復旧の経過

    時系列はこうである（出典1）。

    ここから読める運用上の教訓は1つである（本記録の評価）〈重要〉—— 配信物の汚染では、オリジンの修復は「対応の開始」であって「解消」ではない。 本件では、オリジンでの差し戻しから確認範囲での全台正常化まで7日かかった（本記録の算出）〈数値2〉。その間、利用者の挙動は「どの CDN サーバに当たったか」で変わる（出典1）—— 同じ版のランチャーを同じ手順で起動しても、結果が人によって違う状態である。

    さらに端末側のキャッシュが残る（出典1）—— 研究者は、ランチャーを開き直す前に tbs_cache を削除するよう助言している〈重要〉。この助言は公式の告知には含まれていない（出典4。本記録の確認）。キャッシュの寿命を考えない「修正しました」は、利用者にとって事実と食い違う（本記録の評価）。

    公式が認めたのは「改ざんの可能性」までで、感染の判定方法を出したのは研究者だった組織の対応

    Level Infinite の声明は2026年11月4日 03時13分（GMT）に X へ投稿された（出典1・4・2）。内容は、「PC ランチャーのスクリプトファイルが第三者によって改ざんされた可能性のある異常を確認した」「現在被害の範囲を確認しており、今後の対応は別途告知で共有する」である（出典4・2。原文韓国語）。

    技術的な封じ込め（ファイルの差し替え）は、この声明より前に行われている（出典1）〈重要〉—— 順序が逆になっている（本記録の整理）。利用者は、自分が改ざん期間中にランチャーを起動したかどうかを判断する材料を公式からは与えられないまま、修正版を受け取った。

    自己点検の手掛かりはすべて研究者の側から出ている（出典1）—— Launcher/intl_service/debug.log の k2f_chan registered・adopted・agent started as、tinyget ログの insight.bundle 取得記録、Local Storage の k2f.agent.state、一時ファイル k2f-bcreds-*.db・k2f_screen_*.jpg、改ざん版と正規版の SHA-256。 研究者は読み取り専用の点検ツールも示している（出典1）。

    本記録の評価では、ここが本件の「対応」の弱点である（本記録の判断）〈重要〉—— 被害範囲の確認には時間がかかる。それは当然である。 しかし「改ざんされていた期間」と「感染したかを自分で確かめる方法」は、被害範囲の確認を待たずに出せる事実である（本記録の評価）。窃取の対象に開発者の資格情報が含まれるなら、点検すべき相手は個人のプレイヤーだけでなく、その人を雇っている組織でもある。

    同じ配布基盤を共有する他タイトルについて、「影響なし」を示した資料は1件しか無い波及・関係先

    Level Infinite は、世界累計10億ダウンロードを超える「PUBG MOBILE」、日間アクティブ利用者1億人規模の「王者栄耀」、PC の抽出シューター「Arena Breakout: Infinite」などのグローバル配信を担っている（出典2）。

    本記録が確認できた「被害なし」の明示は1件だけである〈重要〉—— KRAFTON の「PUBG MOBILE には PC 版が存在せず、本件とは無関係」という説明である（出典5）。本記録はこれを配布基盤の検査結果とは読まない（本記録の読み）—— PC ランチャーを持たないという構造上の理由にもとづく説明であり、同じ CDN に別の PC タイトルのファイルが置かれていた場合には成り立たない論法である。

    Level Infinite 自身が他タイトルの検査結果を示した資料は確認できなかった（本記録の確認）〈未確定3〉。研究者も「他に改ざんされた Level Infinite のファイルが無いかは未解決」と記している（出典1）。報道では、ペイロードの解析中に Tencent の別タイトル「デルタフォース」に関係するレガシーなファイル経路の痕跡が交差確認されたとされるが（出典2）、本記録はこれを他タイトルの汚染の証拠とは読まない（本記録の留保）。

    配布基盤が侵害された事案では、波及の全体像は基盤の運用者しか示せない（本記録の評価）〈重要〉—— 個々のタイトルの権利者が「自分のところは大丈夫」と言い合っても、共有された CDN の検査結果は埋まらない。

    窃取の記録が残らない設計が、事後の判断をいちばん難しくしている評価・解釈

    本記録がこの事案から取り出す中心の論点は、技術の巧拙ではない（本記録の判断）〈重要〉。「何を取られたか」が、誰の手元にも残っていないことである。

    研究者は3つの事実を明示している（出典1）—— ①実際の窃取範囲は operator が送ったコマンド次第であり、そのコマンドは記録されていない。②DLL は被害者ごとにビルドされるためハッシュが共有の指標にならない。③感染端末でも SRUM にデータ送信の急増が現れない場合がある。

    この3つが同時に成り立つと、被害を受けた側には「感染した」ことは示せても「何を失った」かは示せない（本記録の評価）。企業の立場で言えば、「この端末で使っていた鍵とトークンを、すべて失効したものとして扱う」以外の選択肢が無くなる。

    これは費用の問題として現れる（本記録の評価）〈重要〉—— 鍵の一斉失効は CI/CD と自動化された処理を止める。 どの鍵がどの処理に使われているかの台帳が無ければ、失効の判断そのものができない。 本件のような事案で初動の速さを決めるのは、EDR の性能ではなく、この台帳の有無である（本記録の判断）。

    もう一点。本件の攻撃は、権限昇格も脆弱性の悪用も使っていない（本記録の整理）—— 読み出した対象はいずれも、本人の権限で普通に読めるファイルである。 開発者の端末に平文で置かれた鍵が、そのまま成果物になった。 守りを足すのではなく、置き方を変えるしか効かない層の問題である（本記録の評価）。
