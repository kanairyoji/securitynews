INC-2026-0922ノジマオンライン 約700万件流出

家電量販大手ノジマが運営する EC 専門サイト「ノジマオンライン」と中古スマホ買取サイトの会員管理システムが第三者による不正アクセスを受け、退会者を除く約700万件の会員情報が2026年11月1日に漏えいした——検知・漏えい確認は同日、公表は翌11月2日で、両サイトはサービスを一時休止したまま。漏えいしたのは氏名（漢字・カナ）・生年月日・性別・郵便番号・住所・電話番号・ログインID・暗号化されたパスワード・メールアドレスで、決済情報の非保持化によりクレジットカード情報は保持していないとされた。侵入経路・手口・パスワードの暗号化方式・不正利用の有無はいずれも公表されていない

不正アクセス・侵害初報のみ日本の組織が当事者公表されていない／不明
初報: 2026年11月2日 最終更新: 2026年11月7日

株式会社ノジマ（代表執行役社長・野島廣司）は2026年11月2日、「ノジマオンラインの不正アクセスに伴う個人情報漏えいに関するお詫びとお知らせ」を公表しました。同社が運営する EC 専門サイト「ノジマオンライン」の会員管理システムに第三者による不正アクセスがあり、同サイトと中古スマホ買取サイトの会員情報が約700万件漏えいしたという内容です。

公表によれば、不正アクセスの検知・確認は2026年11月1日（日）で、漏えいも同日に確認されています。対象となったのは退会者を含まない約700万件で、項目は氏名（漢字・カナ）・生年月日・性別・郵便番号・住所・電話番号・ログイン ID・暗号化されたパスワード・メールアドレスです。同社は決済情報の非保持化に対応しており、この2サイトではクレジットカード情報を保持していないとしています。

対応として、外部アクセス遮断を含むセキュリティ対策と監視体制の強化・所轄警察署への相談・個人情報保護委員会への報告準備・対象2サイトのサービス一時休止を実施しています。再開時期は「安全性の確認が取れ次第」とされ、公表時点では示されていません。本件に起因する不正利用や二次被害については「現在調査中」とされています。

この事案の特徴は、検知と漏えい確認と公表が実質2日に収まっている一方、漏えいの規模が約700万件という桁であることです。会員管理システムという「認証とプロフィールの集積点」が一度破られると、サイト単位ではなく会員基盤単位で全量が出ます。パスワードは暗号化されていたとされますが、方式も、強制リセットを行うかどうかも公表されていません。評価・示唆は本記録の判断として分けて書きます。

公表されていないのは「どう入られたか」と「パスワードをどうするか」である未確定事項出典 [1] [2]

本記録の作成者が一次資料を逐語で確認した範囲で、読者の判断に直結するのに示されていない事項は次のとおりである。

  • 侵入経路と手口。「第三者による不正アクセス」以外の記述が無い。同種のシステムを持つ事業者が自社の点検箇所を絞る材料にならない
  • パスワードの暗号化方式。「暗号化されたパスワード」とのみ記されている。ハッシュ関数・ソルト・ストレッチングの有無が分からないため、会員は使い回しを変える緊急度を判断できない

  • サイト別の内訳と対象期間。2サイト合計の約700万件だけが示されている
  • 本人への個別通知。自社サイトと公式 SNS での告知は挙がっているが、会員個別への連絡の方針は示されていない

これらは「公表が不十分である」という指摘ではなく、公表から4日後（11月6日）の報道時点でも読者が自分のリスクを測れない項目が残っているという事実の記録である。

会員基盤は「サイトの数」では守れない——共通の会員管理システムが破られると全量が出る評価・解釈出典 [1]

ここからは本記録の判断である。

この事案で漏えいしたのは「ノジマオンラインの会員」ではなく、ノジマオンラインと中古スマホ買取サイトの会員である。不正アクセスを受けたのはノジマオンラインの会員管理システムだが、漏えいは買取サイトにも及んだ。つまり2つのサービスが1つの会員基盤を共有していたことが、被害の母数を決めている。

会員基盤の共通化は、利用者の利便（1 ID で複数サービス）と運用の効率（重複登録の排除）のために行われる。その代わりに、侵害されたときの露出はサービス単位ではなく基盤単位になる。自社のサービス一覧を見て「このサイトは小さいから影響は小さい」と考えることはできない。見るべきはどの会員基盤に相乗りしているかである。

もう一点は、約700万件という規模に対して、公表された項目に「暗号化されたパスワード」が含まれていることである。暗号化されていれば即座に平文にはならないが、方式が弱ければ時間の問題になる。読者の組織が同じ公表を出す立場になったとき、方式を書けるか（あるいは書けない方式を使っていないか）は、事案発生前に決まっている。

CISO・経営層への示唆
  • 漏えいの母数は「サービスの数」ではなく「会員基盤の数」で決まる
    不正アクセスを受けたのは「ノジマオンライン」の会員管理システムだが、漏えいは中古スマホ買取サイトにも及び、 合計約700万件になった
    取るべき行動 自社のサービス一覧を会員基盤（認証・プロフィールの保管先）単位で描き直し、基盤ごとに 「1つ破られたら何件・どの項目が出るか」を数で出す。数が経営の受容範囲を超える基盤は分割か最小化の対象にする
  • 「暗号化されたパスワード」と書くだけでは、会員のリスクを下げられない
    公表は「暗号化されたパスワード」とのみ記し、方式も強制リセットの方針も示していない。 会員は他サービスでの使い回しを変える緊急度を判断できない
    取るべき行動 インシデント公表のひな型に「パスワードの保存方式の世代」と「強制リセットの実施方針」を欄として入れ、 事案前に書ける状態（方式を自信をもって書ける実装）にしておく
  • サービスを止める判断には「会員が自衛する経路も止まる」副作用がある
    被害拡大防止のため2サイトを休止した結果、会員が自らパスワードを変更する手段も止まった
    取るべき行動 停止計画に「認証情報の変更・アカウント削除・問い合わせ」だけは縮退して残す経路を定義しておく。 残せない場合は、強制リセットを停止中に実施して再開時に再設定を求める方針を事前に決める
  • 当局報告を「準備中」と書いたまま第2報が出ないと、対応が止まって見える
    11月2日の公表では個人情報保護委員会への報告は「準備（速やかに提出予定）」とされ、 11月6日の報道時点でも完了は示されていない
    取るべき行動 公表文に「次の報告をいつ出すか」を明記する運用にする。進捗が無い場合も日付を切って 「変化なし」を出すほうが、沈黙より信頼を損なわない
  • EC と買取のように性質の違う事業が同じ基盤に乗っていると、停止の影響も同時に出る
    1つの会員管理システムへの侵害で、EC 専門サイトと中古スマホ買取サイトが同時に休止した
    取るべき行動 事業部ごとの売上を基盤単位で合算し、「この基盤が1週間止まったときの売上影響」を試算して経営会議で共有する。 影響が大きい組み合わせは基盤を分けるか、縮退運転の手段を用意する
セキュリティ技術者への示唆
  • 会員管理システムは「認証とプロフィールの集積点」であり、全量取得を前提に守る
    侵害対象は会員管理システムで、結果として2サイト分の会員情報が外部へ出た。 1か所の突破が全量に直結する構造だった
    取るべき行動 会員データの一括参照・エクスポートに件数上限と承認を設け、閾値超過を検知して自動遮断する。 平常時の参照件数の分布を先に測り、閾値を根拠のある値にする
  • パスワードの保存方式は「公表文に書ける状態」で実装する
    公表は「暗号化されたパスワード」とのみ記しており、方式が分からないため会員の緊急度も判断できない
    取るべき行動 保存方式を棚卸しし、計算コストの高いハッシュ（ソルト・ストレッチング付き）へ移行する。 移行済み・未移行の会員数を把握し、未移行分は次回ログイン時に再計算する仕組みを入れる
  • 漏えいの範囲を「日単位」で言えたのは記録があったからで、それ以上を言うには設計が要る
    公表は漏えいを「11月1日同日」と特定している一方、どの会員のどの項目が持ち出されたかの区分は示されていない
    取るべき行動 会員データへの参照・エクスポート操作のログを、アプリ側と独立した保管先に長期保存する。 「どのログがあれば誰の分が出たと言えるか」を侵害想定ごとに事前に対応づけておく
  • 遮断と休止を同時に行うと、会員の自衛操作も止まる
    外部アクセス遮断とサイト休止が同時に実施され、パスワード変更の経路も止まった
    取るべき行動 緊急遮断のルールに「認証情報の変更系 API だけは別経路で残す」か「全件強制リセットを同時に実行する」の いずれかを選べるよう、手順と実装を用意しておく
  • 決済情報の非保持化は、事案のときに「書ける安心」として効く
    カード情報を保持していないため漏えいの対象にならないと明示でき、会員が警戒すべき範囲を絞れた
    取るべき行動 カード情報に限らず「保持しない」と言える項目を増やす（本人確認書類・生体情報・詳細な購買履歴の保持期間短縮）。 保持しない設計は、事案時に公表できる事実そのものになる
