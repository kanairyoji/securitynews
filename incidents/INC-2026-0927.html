2026年11月5日、露出観測事業者 Censys（米国）が、AI 自律侵入フレームワーク「ARTEX」の管理コンソールが認証なしで公開網から到達できるホストを 1,465台 観測したと公表しました（出典1）。うち約650台は同一構成のホスティング2ブロックに集まっているため、独立した配備として数えると約815件になります（出典1）。TechCrunch はこれを「800を超える別個の配備」と報じました（出典2）。

ARTEX は、2026年7月26日に GitHub で AGPL-3.0 として公開されたオープンソースの自律侵入テストフレームワークです（出典1・2）。Microsoft はこれを「偵察からデータ持ち出しまでを、人の介入をほとんど必要とせずに実行できる AI エージェントの系」と表現しています（出典2・原文英語）〈重要〉。Anthropic・OpenAI の高度なモデルに手が届かない者でも、自前のサーバーで動かせる点が広まった理由として挙げられています（出典2）。

露出の中身が問題です。 Censys は、観測時点で 32台のホストに「オープンディレクトリ」（一覧が見える公開ディレクトリ）が開いていたとしています（出典1）〈重要〉。そこには Windows の横展開キット（GodPotato・pass-the-hash スクリプト・MSSQL の UDF DLL）、sudo の公開エクスプロイト（CVE-2021-3156）、Linux 向けビーコン実装の3種のビルド、コンパイル済みの Windows ステージャと C2 のコード、HTA ドロッパ、MITM 用のルート CA の秘密鍵、wpad.dat、内部スキャナ fscan、そして運用者のホームディレクトリ一式（.ssh とシェル履歴を含む）がありました（出典1）。CrowdStrike が報告で名指ししたサーバーでは、エクスプロイトのバイナリと、プロンプト・セッション履歴・設定を収めた.claude フォルダが開いていました（出典1）。

ARTEX は実際の攻撃に使われたと報告されています（出典1）〈重要〉—— ①CrowdStrike は10月7日、韓国の金融企業に対する9月下旬から10月初旬の攻撃でARTEX が使われたと報告しました（銀行の融資照会サービスと役職員向けモバイル系に侵入しデータを持ち出した。主に使われたモデルは DeepSeek v4.1-flash で、API の再販業者経由で購入したとみられる）。 ②Microsoft は10月21日、中国国家に連なる Storm-0940 がConnectWise Cloud Backup の供給網侵害で ARTEX を使い、2,250を超えるテナントにサインインを試み、毎分2,900回のピークに達したと報告しました。一部の被害者では3時間未満で雲の特権アクセスに至っています。

時間の順序に見るべき点があります（出典1。本記録の整理）〈重要〉—— CrowdStrike が名指ししたサーバーのオープンディレクトリは、2026年8月18日に初めて観測されていました。CrowdStrike の報告（10月7日）の約7週間前です。 攻撃の基盤は、報告が出るずっと前から外から見えていた。

ARTEX はその後、作者がクローズドソース化を表明し、リポジトリは取り下げられました（出典1・2）——しかし保管された複製・翻訳版・「ScopeWeaver」などの改称版が流通しています（出典1）。TechCrunch は「コード共有サイトに ARTEX のコードの複製がまだ数十は残っており、現に攻撃で使える」と書いています（出典2・原文英語）。

攻撃の経過

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

**本件の「攻撃」は2層ある**（本記録の整理）〈重要〉—— **①ARTEX を使った攻撃（韓国の金融機関・ConnectWise・WorkOS。 報告されているのは第三者のベンダーによる観測である）、 ②露出したコンソールを拾った第三者による攻撃（起きたという観測は無い）。** **以下の段階は、Censys が観測した露出の構造と、 CrowdStrike・Microsoft が報告した ARTEX の使われ方を並べたものである** （出典1）——**単一の侵害の経路を再現したものではない**（本記録の明示）。

  1. 1. 偵察確認済[1]
    **ARTEX のコンソールは、公開網の走査で機械的に見分けられる**（出典1）〈重要〉—— **既定ポート 8787/tcp、ページ題名が「ARTEX」で始まること、 Next.js の静的資産（`_next/static`）の3点で特定できる**（出典1）。 **Censys はこの方法で 1,465台を見つけた**（出典1）。 **同じ方法は、Censys 以外の誰にでも使える**（本記録の評価）。 **Censys は、コンソールが現れる前の兆候として mitmproxy のバナーと、高位ポートの短命な Python `SimpleHTTP` サーバーが 走査履歴に残ることを挙げている**（出典1）。
    根拠: Censys の検出手法の記述（出典1）
  2. 2. 初期侵入推定[1] [2]
    **ARTEX が使われたと報告された攻撃の入口は、単純なものだった** （出典2）〈重要〉—— **TechCrunch は「弱いまたは既知のパスワードの推測、 多要素認証の欠如といった単純な脆弱性の悪用を含んでいた」と書いている** （出典2・原文英語）。 **ConnectWise の事案では、2,250を超えるテナントへのサインイン試行が行われ、 ピークは毎分2,900回だった**（出典1）。 **韓国の事案では、銀行の融資照会サービスと役職員向けモバイル系が侵入された** （出典1）。
    根拠: Microsoft の報告（出典1 経由）／CrowdStrike の報告（出典1 経由）／TechCrunch の整理（出典2）
  3. 3. 実行確認済[1] [2]
    **ARTEX は「偵察からデータ持ち出しまでを、 人の介入をほとんど必要とせずに実行できる AI エージェントの系」と Microsoft が表現している**（出典2・原文英語）〈重要〉。 **露出したホストには、実行に使う道具が揃っていた**（出典1）—— **Windows の横展開キット（GodPotato・pass-the-hash・MSSQL の UDF DLL）、 sudo の公開エクスプロイト（CVE-2021-3156）、 Linux 向けビーコン実装、HTA ドロッパ、 MITM 用のルート CA 秘密鍵と `wpad.dat`。** **モデルへの経路も自前で持っている例がある （43台に CLIProxyAPI・New API 等）**（出典1）。
    根拠: オープンディレクトリの中身の列挙（出典1）
  4. 4. 持ち出し確認済[1] [2]
    **韓国の事案では、侵入後にデータが持ち出された**（出典1）。 **ConnectWise の事案では、Microsoft 雲上に置かれた顧客のデータとファイルが 対象になった**（出典1・2）〈重要〉—— **Microsoft は「防御側が検知し対処する時間がほとんど無い速さで 顧客の雲環境に侵入しデータを盗んだ」と述べている**（出典2・原文英語）。 **持ち出されたデータの一部は、露出したオープンディレクトリに置かれていた** （出典1）——**Censys は、CrowdStrike が名指ししたサーバーのデータが 「韓国の銀行をはるかに超えて」広がり、 決済事業者とゲーム事業者を含んでいたとしている**（出典1・原文英語）。
    根拠: Censys の記述（出典1）／Microsoft の報告（出典2 経由）

露出を作ったのは ARTEX ではなく、ARTEX を動かしている側の設定です（出典1・2）〈重要〉。Censys は「コンソールは公開網からの到達を必要としない」と明記しています（出典1・原文英語）——つまり、外に出す理由が無いものが出ていました。 TechCrunch も「なぜ数百台のこれらの ARTEX システムが公開網に露出しているのかは分からない」と書いています（出典2・原文英語）。

観測された既定ポートの偏りが、理由の一端を示しています（出典1）。コンソールが見えた端点 1,931 のうち最多は 8787/tcp——ARTEX の既定値です（出典1）。既定のまま、外向きに置いた形です（本記録の読み）。

もう一つの手がかりは、ホスティングの偏りです（出典1）〈重要〉。PEG Tech（AS54600）に 493台が、13の /24 にまたがって同一のポート構成で並んでいます。38.11.221.0/24 と 38.11.173.0/24 にはそれぞれ125台。 Yancy Limited（AS138415）の157台は、CyberPanel とメールサーバーの同一テンプレートを共有しています。 Censys はこれを「数百の個別の運用者ではなく、払い出しのテンプレートがあることを示唆する」と読みました（出典1・原文英語）。

設定不備が、1人の手落ちではなく雛形として複製されている（本記録の読み）〈重要〉—— この読みが正しければ、個々の運用者に「気をつける」余地は無く、テンプレートが直るまで同じ露出が供給され続けます。 実際、11月3日から5日の間に10件のオープンディレクトリが閉じられた一方で、別のホストで15件が新たに現れています（出典1）。

開いていたのは管理画面だけではありません（出典1）〈重要〉。32台ではオープンディレクトリが見える状態で、そこには Windows の横展開キット（GodPotato・pass-the-hash スクリプト・MSSQL の UDF DLL）、sudo の公開エクスプロイト（CVE-2021-3156）、ヒープダンプ、総当たりスクリプト、Linux 向けビーコン実装の3種のビルド、リバースシェル、コンパイル済みの Windows ステージャと C2 のコード、HTA ドロッパ、MITM 用のルート CA の秘密鍵、wpad.dat、内部スキャナ fscan（Vshell のリスナーの隣）、そして運用者のホームディレクトリ一式——.ssh とシェル履歴を含む——が置かれていました。

CrowdStrike が報告で名指ししたサーバーでは、エクスプロイトのバイナリと、プロンプト・セッション履歴・設定ファイルを収めた .claude フォルダが開いていました（出典1）〈重要〉—— AI エージェントを使う攻撃では、プロンプトとセッション履歴が攻撃の設計書そのものになります（本記録の評価）。155台（10.6%）では、Vshell・Cobalt Strike・Adaptix C2・他の AI 攻撃フレームワークが同居していました（出典1）—— ARTEX は既存の攻撃基盤に足されている、という形です（本記録の読み）。

露出は報告の7週間前から見えていた評価・解釈

本記録がこのレポートで最も重いと見るのは、台数ではなく時間です（本記録の評価）〈重要〉。

CrowdStrike は2026年10月7日、韓国の金融企業への攻撃で ARTEX が使われたと報告しました（出典1）。帰属は示されていません（unattributed actor）。9月下旬から10月初旬にかけて、銀行の融資照会サービスと役職員向けモバイル系に侵入してデータを持ち出した。主に使われたモデルは DeepSeek v4.1-flash で、API の再販業者経由の購入とみられる、という内容です（出典1）。CrowdStrike が攻撃者を特定できた理由の一つは、攻撃者がシステムを置いたサーバーに「オープンディレクトリ」を残していたことでした（出典2）。

Censys は、自社の走査履歴を遡って、そのサーバーのオープンディレクトリが2026年8月18日に初めて観測されていたことを示しました（出典1）〈重要〉—— 報告の約7週間前です。

ここから2つのことが言えます（本記録の評価）。①攻撃の基盤は、インテリジェンス報告が出るずっと前から外から見えていた。 見えていたが、「これは攻撃基盤である」と結びつけられていなかった。 走査のデータは記録されており、結びつける作業が行われていなかった、という順序です。 ②露出したデータの範囲は、報告された範囲より広かった—— Censys は、そのサーバーのデータが「韓国の銀行をはるかに超えて」広がり、決済事業者とゲーム事業者を含んでいたとしています（出典1・原文英語）。

読者にとっての意味は、監視の向きです（本記録の判断）〈重要〉。自組織のデータが攻撃者のオープンディレクトリに置かれていないかは、走査事業者の記録に照会すれば分かる可能性があります。 これは予防ではなく、漏えいの確認の手段です。 そして、確認できる期間が限られます—— Censys は「走査履歴は、運用者が一覧を閉じたあとも参照できる」と述べています（出典1）が、走査が入っていなかったホストについては何も残りません（本記録の留保）。

道具が止まっても、配備は止まらない評価・解釈

ARTEX は、作者がクローズドソース化を表明し、GitHub のリポジトリは取り下げられました（出典1・2）。一見すると、問題は収束に向かう形です。

しかし観測はそうなっていません（出典1・2）〈重要〉。①既に動いている配備は止まりません—— Censys が観測したのは 1,465台・独立した配備として約815件で、これはリポジトリの取り下げ後の数字です（出典1）。②複製が流通しています—— Censys は「保管された複製・翻訳版・『ScopeWeaver』などの改称版がなお流通している」としており、TechCrunch も「コード共有サイトに ARTEX のコードの複製がまだ数十は残っており、現に攻撃で使える」と書いています（出典1・2・原文英語）。

AGPL-3.0 で一度公開されたものを、あとからクローズドソースにしても、配布済みの複製には及びません（本記録の整理）〈重要〉—— これはライセンスの性質から導かれる話であり、作者の意図とは無関係です。

この事案を「AI の攻撃」として読むと、対策を見失います（本記録の判断）〈重要〉。TechCrunch は「ARTEX に結びついた攻撃の多くは、弱いまたは既知のパスワードの推測、多要素認証の欠如といった単純な脆弱性の悪用を含んでいた」と書いています（出典2・原文英語）。入口は従来のままです。

変わったのは速度です（本記録の評価）〈重要〉—— Microsoft は ConnectWise Cloud Backup の供給網侵害で、Storm-0940 が 2,250 を超えるテナントにサインインを試み、ピークは毎分2,900回、一部の被害者では3時間未満で雲の特権アクセスに至ったと報告しています（出典1）。「防御側が検知し対処する時間がほとんど無い速さ」という表現です（出典2・原文英語）。

対策の内容は同じで、間に合わせるべき時間が短くなった（本記録の判断）—— 夜間に起きて朝に気づく運用では、3時間に間に合いません。 人の判断を待たずに自動で止める閾値を持つかどうかが、ここで効く違いになります。
