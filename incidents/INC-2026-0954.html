波及の形が特徴的です。三井住友海上あいおい生命保険の漏えい（約5,300件）は、自社システムが侵害されたものではなく、損保2社の専用ページに自身の生命保険契約を表示するよう顧客自身が設定していたために、損保側の画面に集まっていた情報が出たものです。三井ダイレクト損害保険は別系統で、11月4日早朝に自社 Web サイトへの不正アクセスを検知し、Web サイトとアプリでのすべての手続きを能動的に停止したうえで、最大23.4万件を公表しました。こちらは契約者情報・記名被保険者情報に加え、車両情報（車名・用途車種・登録番号・所有者等）と保険契約の条件・補償内容まで含みます。

      取るべき行動 自社サービスを「止めても金銭的不便にとどまるもの」と 「止まると顧客の安全・損害に直結するもの」に分類し、後者は別経路で冗長化する。 インシデント対応手順の停止リストにこの区分を書き込む
    • 「カード番号は下4桁だけ」「口座番号は一部だけ」は、件数が少なくても本人確認のなりすまし材料になる
      あいおいニッセイ同和損保ではカード3件・口座19件という少数の決済系項目が混じっていた。 全桁は出ていないが、下4桁は電話の本人確認で使われる要素である
      取るべき行動 自社のコールセンター・Web の本人確認要素から「カード下4桁」「口座の一部」 「生年月日」を単独の決定要素として外す。漏えい発生時には、 これらを要素に使う全チャネルを棚卸しして一時的に確認を強化する運用を定める
    • 件数の公表には基準時刻を付け、合計を出す／出さないの方針を先に決めておく
      4社は「11月6日9時時点」と基準時刻を添えたが、 MS&AD ホールディングスはグループ合計を公表しておらず、報道は異なる括り方で 「約72万件」「48万件超」と報じている。重複関係も示されていない
      取るべき行動 公表文のひな形に「件数の基準時刻」「件／人の別」「他社・他サービスとの重複の有無」を 必須項目として組み込む。グループ企業では、合計を出す主体と括り方を事案発生前に決めておく
    • 停止サービス一覧は「どこが侵害されたか」を答えていない——侵害元の公表は別の約束として設計する
      「ＭＳコンパス」は11月3日の停止サービス一覧に14番目の項目として載っていたが、 そこが侵害された入口であり約2.3万件が漏えいしたと公表されたのは6日後の11月9日である。 利用企業はその6日間、「止まっているサービスの1つ」としてしか理解できなかった
      取るべき行動 インシデント公表のひな形を「止まっているサービスの一覧」と 「侵害が確認されたサービスの一覧」の2本立てにし、後者は調査の途中でも 「調査中」の状態で名前を出す運用に変える。公表済みの停止一覧に後から侵害が確定した サービスが出た場合は、停止一覧の側にも確定日を追記して遡って読めるようにする
    セキュリティ技術者への示唆
    • 契約者向けポータルから、決済系の部分情報を排除する
      44.4万件のうち22件にだけクレジットカードの下4桁と口座番号の一部が含まれていた。 少数でも「どの機能がそれを保持していたのか」が設計上の穴である
      取るべき行動 契約者向け画面が参照するテーブル・API の応答に、カード下4桁・口座番号の一部が 含まれていないかを全画面について洗い出す。表示が必要な場合は、 画面表示の瞬間に決済基盤へ照会し自系統に保持しない形へ移す
    • 1アカウントが単位時間に引ける個人情報の件数に上限を置き、超過を遮断する
      「ご契約者さま専用ページに登録されているお客さま」の情報が 44.4万件規模で出ている。正常な契約者の操作では到達しない量である
      取るべき行動 契約者向け API・画面ごとに、1セッション／1時間あたりの照会件数のしきい値を設定し、 超過時は自動でセッションを切る。しきい値は正常利用の実測値の上位パーセンタイルから決める
    • グループ他社のデータを自社画面に表示する機能は、保持ではなく都度取得にする
      三井住友海上あいおい生命の契約情報が、損保2社の専用ページ側に存在していたために漏えいした
      取るべき行動 他社データの表示機能について、自系統のデータストアにコピーを置いていないかを確認する。 置いている場合は保持期間とマスキング範囲を定め、 可能なものは表示時の API 取得（キャッシュ無し）へ切り替える
    • 封じ込めのための「ネットワークからの切り離し」を、事前にスイッチとして用意する
      両社は検知の翌日深夜に「ご契約者さま専用ページ」をネットワーク環境から切り離し、 「停止以降の外部からの不正アクセスはございません」と言える状態を作った
      取るべき行動 サービス単位の隔離手順（経路の遮断・DNS の切り替え・静的な停止ページへの退避）を 手順書とスクリプトで用意し、四半期に1回、本番に近い環境で実行時間を測る
    • 「流出の有無と範囲を言える」ためのログを、侵害想定ごとに事前に対応づける
      両社は影響調査の過程で漏えいの事実と件数・項目を特定できた。 これはアプリケーション層の参照記録が残っていたことを示唆する（本記録の読み）
      取るべき行動 個人情報を返す画面・API について、「誰が・いつ・どのレコードを・何件引いたか」が 後から再構成できるかを確認する。再構成できない経路を洗い出し、 改ざんできない保管先に90日以上の保持を設ける
    • マーケティング目的で集めた見込み客の台帳に、保存期間の定めと自動削除を入れる
      「ＭＳコンパス」の漏えい対象には、2023年11月から2026年11月まで37か月分の セミナー申込者と、お問い合わせフォームからの連絡者が含まれていた。 契約データと違い、見込み客の情報には業務側から「消す理由」が出てこない
      取るべき行動 セミナー申込・資料請求・問い合わせフォームの保存先について、保存期間を定め、 期間満了で自動削除されることをバッチの実行記録で確認できる状態にする。 削除できない業務上の理由がある項目（売上高・従業員数など与信に使うもの）は 分離した保存先に移し、Web に面したサイトから参照しない形にする

    自組織に当てはまるか

    該当する項目があれば、この事案と同じ構図が自組織でも成立しうることを意味します。
    観点自社に当てはまるか該当する場合に何が起きうるか
    システム構成□ インターネットに面した顧客向けポータルに、認証後に参照できる個人情報を集約しており、 そこが止まると複数の業務系統が同時に止まる「ご契約者さま専用ページ」の隔離により、三井住友海上では契約手続き・事故受付・ 災害アラートを含む14系統が同時に停止した
    委託・第三者部品□ グループ会社・提携先の画面に自社のデータを表示する機能があり、 表示のためにデータのコピーを相手側に置いている三井住友海上あいおい生命は自社を侵害されていないが、損保側に集まっていた 約5,300件が漏えいし、自社名で公表と個別案内を行うことになった
    データの保持□ 顧客向け画面でクレジットカードの下4桁・口座番号の一部などマスキングされた 決済系の値を表示しているあいおいニッセイ同和損保ではカード名義人と下4桁が3件、 口座名義人名・金融機関名・口座番号の一部が19件漏えいした
    認証・認可□ コールセンターや Web の本人確認で、カードの下4桁・口座の一部・生年月日を 確認要素として使っている漏えいした項目がそのまま本人確認の要素と重なるため、件数が少なくても なりすましの成功率を上げる（本記録の評価）
    運用・監視□ サービスの顧客接点に、デジタル以外で成立する代替経路（電話・書面・対面）が残っていない損保2社が主要サービスを能動的に停止できたのは代理店・電話・書面が残っていたためで、 ダイレクト専業の三井ダイレクト損保は手続きが全停止した
    体制・契約□ グループ複数社が関わる事案で、件数の集計主体・公表の括り方・ 重複の扱いが事前に決まっていないMS&AD ホールディングスは4社を束ねたお知らせを出しながら合計を示さず、 報道は異なる括り方の数字を出している。件数の重複関係も公表されていない
    データの保持□ 自社サイトのセミナー申込・資料請求・問い合わせフォームの登録内容を、 保存期間の定めなく同じサイトから参照できる場所に置き続けている「ＭＳコンパス」の漏えい対象には37か月分（2023年11月〜2026年11月）の セミナー申込者と問い合わせ者が含まれていた
    データの保持□ 取引先向けの情報提供サイト・会員サイトで、法人の売上高・従業員数・業種と、 役職つきの担当者名・メールアドレス・電話番号を同じレコードで保持している漏えいした項目の組み合わせは、BEC と標的型の営業詐欺が必要とする材料と一致する （本記録の評価）
    運用・監視□ インシデントの公表で「停止中のサービス一覧」を出しているが、 そのうちどれが侵害された入口かを別に示す手順が無い「ＭＳコンパス」は停止一覧に名前が載った6日後に、侵害元として公表された
