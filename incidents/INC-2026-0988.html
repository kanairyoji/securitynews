INC-2026-0988SAP が CVSS 10.0 を4件修正

SAP が2026年11月10日の定例パッチで **CVSS 10.0 の脆弱性を4件**修正した——うち **ICM2SHELL（CVE-2026-76964／CVE-2026-89126）は SAP カーネルの WebSocket 再組立の欠陥**で、報告元の Onapsis は**認証不要の遠隔コード実行が端から端まで成立する実証コードを SAP に提供**したと述べている。**PROXYGATE（CVE-2026-89103）は SAP Gateway を内部サーバーと誤認させる**もので、いずれも**保守の切れたカーネル版にも影響**する。悪用は確認されていない

脆弱性初報のみ日本に波及した海外事案設計・実装上の不備設定不備
初報: 2026年11月10日 最終更新: 2026年11月11日

SAP SE は2026年11月10日（日本時間）、定例の SAP Security Patch Dayとして同月分の修正を公開しました。SAP の公表ページによれば、新規の Security Note が35件・GitHub セキュリティアドバイザリが4件（計39件の新規）に加え、既存 Note の更新が3件、一覧としては42項目です。

このうち4件が CVSS 基本値 10.0（最高値）に評定されています。

Note CVE 対象 欠陥の種類
3778530 CVE-2026-76964 NetWeaver AS ABAP（Internet Communication Manager） メモリ破壊
3778556 CVE-2026-89126 SAP Web Dispatcher メモリ破壊
3798345 CVE-2026-89103 SAP Gateway アクセス制御の不備
3849308 CVE-2026-120017 NetWeaver AS ABAP／ABAP Platform（SAML2 Service Provider） 認証の欠落

報告元のセキュリティ企業 Onapsis は、CVE-2026-76964 と CVE-2026-89126 をICM2SHELL、CVE-2026-89103 を PROXYGATE と名付けています。ICM2SHELL について Onapsis はこう述べています（原文英語）。

これは理論上の帰結ではない。Onapsis Research Labs は、対象システム上で <sid>adm として任意のコマンドを実行する、端から端まで完全な認証不要の遠隔コード実行を達成する動作する実証コードをSAP に提供した。 サービス不能の状態のほうは、試験したすべてのSAP カーネル版で再現した。

PROXYGATE については、Onapsis はこう述べています（原文英語）。

PROXYGATE は、認証されていない外部の攻撃者が内部のアプリケーションサーバーの1つであると SAP Gateway に信じ込ませることで成立する。（中略）SAP の利用者も、パスワードも、利用者の操作も要らないのに、インストールを所有するアカウントとして SAP システムの完全な制御が得られる。本番の ERP システムでは、それは業務データ・取引の整合性・重要な業務アプリケーションの可用性が直接さらされることを意味する。

実際の攻撃での悪用は、本記録の作成時点でどの資料にも報告されていません。一方で BleepingComputer は、CISA が2021年11月以降に SAP の脆弱性14件を悪用確認済みとして指定しており、そのうち3件はランサムウェア集団にも悪用されたと報じています。本件はその文脈に置かれる修正です。

攻撃の経過

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

**実際の攻撃は観測されていない。** 以下は Onapsis が公表した仕組みの説明に 基づく、ICM2SHELL と PROXYGATE の到達経路の整理である。 攻撃者の実在を示すものではない。

  1. 1. 初期侵入undisclosed[2] [3]
    （ICM2SHELL）細工した一連の WebSocket メッセージを ICM または Web Dispatcher に送る。断片の再組立処理が、接続のために確保した メモリの終端を越えて攻撃者が制御するデータを書き込む。 **SAP の利用者・パスワード・利用者の操作のいずれも要らない** （Onapsis の説明。原文英語）
    根拠: Onapsis の公表した仕組みの説明（SecurityWeek・BleepingComputer 経由）
  2. 2. 初期侵入undisclosed[2] [3]
    （PROXYGATE）SAP Gateway に対し、内部のアプリケーションサーバーから 来たように見える一連の要求を送る。`prxyinfo` アクセス制御リストが 開いたままだと、Gateway はこれを受け入れる。 **利用者名・パスワード・証明書のいずれも提示しない** （Onapsis の説明。原文英語）
    根拠: Onapsis の公表した仕組みの説明（SecurityWeek・BleepingComputer 経由）
  3. 3. 実行undisclosed[2] [3]
    いずれの経路でも、到達後は**`<sid>adm` 権限でオペレーティングシステムの コマンドを実行できる**と Onapsis は述べている。ICM2SHELL については 「端から端まで完全な認証不要の遠隔コード実行を達成する動作する実証コードを SAP に提供した」としている（原文英語）
    根拠: Onapsis の公表（実証コードは SAP に提供、公開はされていない）

この事案で下された判断
  • Onapsis は仕組みの概略（WebSocket の再組立、`prxyinfo` ACL の誤認）と 帰結（`<sid>adm` でのコマンド実行）を公表し、再現手順と実証コードは 公開しなかった。SAP は Note 本体を認証の要る場所に置き、 一般公開ページには CVE・CVSS・部品名・欠陥の種類のみを載せた
    理由は公表されていない
    トレードオフ: 詳細を伏せることで、Note の適用が行き渡る前に攻撃用コードが広まることを 抑えられる。一方で利用側は**影響する版を一般公開情報から確かめられず、 緩和策の設計も「露出しているかどうか」という粗い軸でしか行えない**
  • Onapsis は ICM2SHELL について「動作する実証コードを SAP に提供した」ことを 修正公開と同日に明言した
    トレードオフ: 実証済みと明言することで、利用側は「理論上の最悪値」として 先送りできなくなる。一方で、**攻撃者側にも「確実に動く経路がある」ことを 知らせる**ことになり、独自の再現に向かう動機を与える

注目すべきは、4件の最高深刻度のうち3件が「ネットワークに面するカーネル部品」に集まっていることです。Internet Communication Manager（ICM）は HTTP・HTTPS・WebSocket の通信を受け取る部品、Web Dispatcher はその前段に置く負荷分散・逆プロキシ、Gateway は外部アプリケーションが SAP の裏側に接続するための枠組みです。

ICM2SHELL（CVE-2026-76964／CVE-2026-89126）が ICM と Web Dispatcher の両方に CVE を持つのは、Onapsis の説明によれば両者が同じ SAP カーネル部品を共有しているためで、「SAP カーネルの中の、HTTP・HTTPS・WebSocket の通信を受け取る部品における単一の弱点」です（原文英語）。つまり1つの欠陥が、配置の違いによって2つの CVE になっている構図です。

WebSocket の断片の継ぎ目で、確保した領域の外に書き込まれる原因・手口出典 [1] [2] [3]

ICM2SHELL の仕組みについて、Onapsis は次のように説明しています（原文英語）。

問題は、大きな WebSocket メッセージの再組立に関わるものである。大きなメッセージはサーバーとブラウザのやり取りの中で断片に分割され、受け取った側が組み立て直すことがある。特別に細工した一連の WebSocket メッセージによって、ICM またはWeb Dispatcher は、その接続のために確保したメモリの終端を越えて攻撃者が制御するデータを書き込む。 そのデータの形によって、結果はプロセスの即時の異常終了か、制御されたメモリの破壊のどちらかになる。

到達すると何ができるかについて、Onapsis は<sid>adm 権限でのオペレーティングシステムのコマンド実行と述べています。<sid>adm は SAP システムのインストールを所有する OS アカウントで、そこを取られると SAP システムの中身は実質すべて触れます。

PROXYGATE（CVE-2026-89103）は別の仕組みです。SAP Gateway のprxyinfo アクセス制御リストは、本来「信頼されたネットワークのみに要求を制限する」ためのものですが、Onapsis の説明では開いたままになっていると、攻撃者は内部ネットワークから来たように見える一連の要求を送って Gateway に受け入れさせられます。結果は同じく <sid>adm 権限でのコマンド実行で、利用者名・パスワード・証明書のいずれも要りません。

SAP の公表における分類は、ICM2SHELL の2件が「メモリ破壊」、PROXYGATE が「アクセス制御の不備」、CVE-2026-120017 が「認証の欠落」です。

保守切れのカーネル版にも影響するが、そこへの修正は無い被害規模・影響範囲出典 [2] [3] [4]

Onapsis は PROXYGATE について次のように述べています（原文英語）。

欠陥が SAP カーネルの中にあるため、すでに保守期間を終えたカーネル版を含む、広範な版に影響する。 さらに Gateway は ABAP だけでなくAS Java・デュアルスタック・単独構成の Gateway システムでも動いている。

これは本件のなかで最も実務に響く点です。影響範囲が「製品」ではなく「カーネル」で決まるため、ABAP か Java かという区分では切れません。そして保守期間を終えた版には、定義上、修正 Note が提供されません。

ただし、具体的にどの版が影響を受けるのかは、本記録の参照した資料には載っていません。 Security Note 本体には記載があるとみられますが、SAP の認証が必要で本記録では確認していません。利用側は「自分のカーネル版が対象か」を Note 本体で確かめる必要があります。

なお Onapsis の分析ブログ自体は、本記録の作成者が取得を試みたもののCloudflare による遮断（HTTP 403）で読めませんでした。引用はいずれも SecurityWeek・BleepingComputer が引いた範囲です。

悪用は報告されていないが、SAP の最高深刻度は過去に数日で悪用された評価・解釈出典 [2] [3]

以下は本記録の作成者の評価です。

本件について「悪用されている」と述べた資料は1つもありません。一方で、BleepingComputer が並べた直近の経緯は無視しにくいものです。

  • 2026年8月、Commerce Cloud の CVSS 10.0（CVE-2026-58231）を修正。修正の数日後、脅威情報企業 Defused が実際の攻撃での悪用を指摘した
  • 2026年9月、SAP カーネルのメモリ破壊（CVE-2026-44756・Onapsis がOVERPASS と命名）を修正
  • 2026年10月、マルチテナントの BTP アプリケーションの OAuth2 SSRF（CVE-2026-89111）を修正
  • CISA は2021年11月以降、SAP の脆弱性14件を悪用確認済みとして指定しており、うち3件はランサムウェア集団にも悪用された

3か月連続で最高深刻度が出ており、うち1件は修正後まもなく悪用されています。「悪用の報告がない」を「まだ時間がある」と読む根拠にはなりません。

緊急度の判断に使える材料は、公表された情報の中では1つだけです。ICM・Web Dispatcher・Gateway がインターネットから到達可能かどうか。 ICM2SHELL は Onapsis の言葉どおり「設計上ネットワークに面している部品」に対する遠隔コード実行であり、PROXYGATE は ACL が開いていることに依存します。自組織の露出を測ることが、Note の適用計画を立てる前にできる唯一の作業です。

数え方: SAP Gateway の `prxyinfo` アクセス制御リストを確認し、信頼された ネットワークのみに要求を制限する（PROXYGATE は ACL が開いていることに 依存する）　副作用: ACL を絞ると、正規の外部アプリケーションからの Gateway 接続が 拒否される。接続元の棚卸しなしに絞ると連携が止まる
数え方: 保守期間を終えた SAP カーネル版を使っている箇所を洗い出す。 Onapsis は本件が保守切れのカーネル版にも影響すると述べており、 **そこには修正が提供されない**　副作用: カーネルの入れ替えは互換性試験を要し、短期では終わらない。 移行までの期間はネットワーク側での隔離に頼ることになる

対応の評価

評価材料がない判断は「評価材料なし」としています。結果論で断じないための区分です。
判断評価評価の根拠と留保
Onapsis は仕組みの概略（WebSocket の再組立、`prxyinfo` ACL の誤認）と 帰結（`<sid>adm` でのコマンド実行）を公表し、再現手順と実証コードは 公開しなかった。SAP は Note 本体を認証の要る場所に置き、 一般公開ページには CVE・CVSS・部品名・欠陥の種類のみを載せた部分的に機能本記録の作成者の評価である。ERP のように停止調整に時間がかかり、 適用が数週間単位になる製品では、詳細を伏せる判断は合理的である。 ただし**「影響するカーネル版の範囲」まで Note 本体に閉じているのは 過剰**で、これは悪用に直結しない一方で、利用側の優先順位づけに 直接必要な情報である
Onapsis は ICM2SHELL について「動作する実証コードを SAP に提供した」ことを 修正公開と同日に明言した機能した本記録の作成者の評価である。CVSS 10.0 は年に何度も出るため、 評点だけでは優先順位の材料にならない。「実証コードがある」という 一文のほうが、停止調整を動かす材料として実務上強い
CISO・経営層への示唆
  • ERP の緊急パッチは「適用日」ではなく「停止調整が終わる日」で管理する
    本件はネットワークに面したカーネル部品の修正であり、適用には SAP システムの 再起動を伴う。本番 ERP の停止は業務部門との調整が要り、 数週間かかることがある。**その間は未修正のまま外に面している。** 「適用予定」を報告させているだけでは、未修正でさらされている期間が見えない
    取るべき行動 脆弱性対応の報告様式に「**停止調整が完了する日**」「その日までの 暫定の隔離策」「暫定策で残るリスク」の3欄を設ける。 調整が4週間を超える案件は経営会議の議題に上げる
  • 保守期間を終えた基幹システムの部品を、台帳で「修正が来ない資産」として分ける
    Onapsis は本件が保守切れの SAP カーネル版にも影響すると述べている。 保守切れの資産には定義上、修正が提供されない。 **「パッチ適用率」の分母に入れていると、永久に100%にならないか、 あるいは分母から黙って外れて見えなくなる**
    取るべき行動 資産台帳に「提供元の保守状態」の欄を設け、保守切れの資産は 別の一覧で管理する。各資産に「隔離で守っているのか、 移行予定があるのか、受容しているのか」のいずれかを明記し、 受容の場合は決裁者の名前を残す
  • 「悪用の報告がない」は猶予ではない——同じ提供元の直近の実績で判断する
    SAP は2026年8月に CVSS 10.0 を修正した数日後に悪用を指摘され、 9月・10月にも最高深刻度を出している。CISA は2021年11月以降に SAP の脆弱性14件を悪用確認済みとして指定し、うち3件はランサムウェア集団に 悪用された。**提供元ごとに「修正から悪用までの実績」が違う**
    取るべき行動 主要な業務システムの提供元ごとに、過去2年の「最高深刻度の件数」と 「修正から悪用確認までの最短日数」を1枚にまとめる。 その数字を、緊急パッチの停止調整を急がせる根拠に使う
  • 外部に面した業務システムの露出を、脆弱性情報より先に把握しておく
    本件で公表情報から緊急度を判断できる軸は「ICM・Web Dispatcher・Gateway が インターネットから到達可能か」の1つだけである。 **脆弱性が出てから露出を調べ始めると、その調査に数日使ってしまう**
    取るべき行動 四半期ごとに、外側から見た自組織の到達可能な資産の一覧を作らせる （提供元・部品名・ポート・保守状態）。脆弱性情報が出た日に 突合だけで済む状態にしておく
セキュリティ技術者への示唆
  • ICM・Web Dispatcher・Gateway の到達可能性を、内部からではなく外側から確かめる
    ICM2SHELL は設計上ネットワークに面している部品への認証不要の遠隔コード実行、 PROXYGATE は Gateway の ACL が開いていることに依存する。 **内部の構成図では「閉じているはず」になっていても、 負荷分散装置の設定や過去の例外で開いていることがある**
    取るべき行動 外部のアドレスから、SAP の ICM／Web Dispatcher の HTTP(S) ポートと Gateway のポート（既定 33NN／48NN）への到達を実測する。 到達した場合は、前段での遮断か ACL の設定を先に入れ、 Note の適用はその後でよい
  • `prxyinfo` アクセス制御リストの中身を読み、既定のままになっていないか確かめる
    PROXYGATE は、本来「信頼されたネットワークのみに要求を制限する」ための `prxyinfo` ACL が開いたままであることに依存する。 **Note の適用とは別に、設定側の確認が要る**
    取るべき行動 各 SAP システムの Gateway で `prxyinfo` の設定内容を書き出し、 許可範囲が内部のアドレス範囲に限定されているかを確認する。 絞る前に、現に Gateway へ接続している外部アプリケーションを 記録から洗い出す（絞ると連携が止まる）
  • ICM／Web Dispatcher プロセスの異常終了を監視項目に入れる
    Onapsis は「サービス不能の状態は、試験したすべての SAP カーネル版で 再現した」と述べている。**遠隔コード実行に至らない探索でも、 プロセスが落ちる。** 検知の指標は公表されていないが、 異常終了は最も安く取れる手がかりである（本記録の評価）
    取るべき行動 ICM／Web Dispatcher の異常終了・自動再起動を監視対象に加え、 1日あたりの回数に閾値を置く。発生時は直前の WebSocket 接続の 記録を保全する手順を決めておく
  • 影響するカーネル版は Security Note 本体で確かめる（一般公開情報には無い）
    Onapsis は「保守切れの版を含む広範な版に影響する」と述べるだけで、 範囲は示していない。**SAP の一般公開ページにも載っていない。** 自組織のカーネル版が対象かは、認証の要る Note 本体を読むしかない
    取るべき行動 Note 3778530／3778556／3798345／3849308 を SAP の支援ポータルで開き、 自組織の SAP カーネル版（`disp+work -version` 等で確認）が 対象一覧に含まれるかを1件ずつ照合する。保守切れで修正が無い場合は ネットワーク側の隔離に切り替える
  • ABAP か Java かという区分で影響範囲を切らない
    Onapsis は「Gateway は ABAP だけでなく AS Java・デュアルスタック・ 単独構成の Gateway システムでも動く」と述べている。 **欠陥はカーネルにあるため、アプリケーション層の種別では切れない**
    取るべき行動 SAP の資産一覧を「製品名」ではなく「動いているカーネル版」で 並べ直す。単独構成の Gateway のように、ERP 本体と別に立っている インスタンスを漏らさない
