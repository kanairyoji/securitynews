社内の判断に使うなら、月例の一覧から最初に抜くべきは「Exploited:Yes」と「KEV 収載」の2つのフラグである（本記録の推奨）。

警告が出ないことが本体で、利用者側には気づく手がかりがない原因・手口出典 [2] [3]

Microsoft の説明は次のとおりである（出典2。原文英語を訳出）。

「認証されていない攻撃者が細工されたメッセージファイルを送り、影響を受ける版の Microsoft Outlook で開かせる可能性がある。ファイルを開くと、Outlook が通常表示される外部コンテンツの警告を出さずに攻撃者の管理するネットワーク位置へ接続し、利用者になりすますのに使える認証情報が漏えいするおそれがある。悪用にはネットワーク接続と利用者の操作が要る」

JPCERT/CC はこれを CWE-356（安全でない操作をユーザーに警告しない）と記している（出典3）。

つまり、不備は「外部へ接続する前に出るはずの警告が出ない」ことにある（本記録の整理）〈重要〉。利用者教育の観点では、ここが難所である—— 警告が出ないのだから、利用者が「怪しい」と判断する材料は画面に現れない（本記録の評価）。唯一の手がかりは、添付ファイルそのものの出自である。

残る防御は端末の外側にある。外向きの SMB／WebDAV を遮断していれば、接続自体が成立しない（本記録の整理。なおこの推奨は Microsoft の勧告には記載されていない）。この型（開くと外部へ認証を取りに行く）は過去にも繰り返し現れており、境界での遮断は個別の CVE に依存しない対策になる（本記録の評価）。

悪用の中身は公表されていない——「検知された」以外は分からない未確定事項出典 [1] [2] [3] [4]

公表されているのは、CVRF の Exploit Status が「Publicly Disclosed:No / Exploited:Yes」であり、最新の状態が「Exploitation Detected」であることだけである（出典1・2）。

攻撃者の帰属・標的の業種や地域・観測の開始時期・被害の件数は、いずれも示されていない〈未確定1〉。CISA KEV の「ランサムウェアキャンペーンでの使用」も "Unknown" である（出典4）。JPCERT/CC の注意喚起も「悪用されていることを公表しています」と伝えるに留まる（出典3）。

本DBがこの区別を明示するのは、「悪用が確認された」という語が「広く攻撃が観測されている」と読まれることがあるためである（本記録の整理）〈重要〉。本件で確認できるのは、Microsoft が悪用を検知し、CISA が2週間の期限を付けた、という2点である。

この材料で判断できることは限られる。標的が絞られているのか広いのかが分からないため、「自社が標的か」ではなく「当てていないなら当てる」で動かすしかない（本記録の評価）。

【続報】「当てられない」場合の手当てが、月例の運用に組み込まれるようになった対策・注意喚起出典 [7] [10] [11]

ここは本記録の解釈である（確度: presumed）。

Qualys が示した5段階の波は次のものである（出典7）。

  • Wave 0 実証済みの危険な露出——CISA KEV 収載・外部公開資産・自動化して完全掌握に至る不備。最初に直す
  • Wave 1 運用への影響が小さいもの——信頼性の高い更新を無人で配布
  • Wave 2 運用への影響が大きいもの——信頼性の高い更新をリングで配布。最初のパイロットには「壊れる可能性が最も高い構成」を入れる（KB5131085 なら Exchange サーバー）
  • Wave 3 当てない手当て——信頼性の低い更新・修正が無い脆弱性・保守切れのアプリは緩和策で凌ぐ
  • Wave 4 削除——使っていないアプリを消して攻撃面を減らす

本記録が新しいと見るのは Wave 3 である（本記録の評価）〈重要〉。「当てられないから待つ」ではなく、当てないまま攻撃経路を閉じ、修正が出たら当てて緩和策を外すという手順を月例の運用の中に置いている。

実例として挙がっているのは KB5132061 である（出典7・10）。2026年10月のプレビュー更新 KB5127936 を入れた端末では11月の更新が導入できず、その間その端末は今月の修正をすべて欠いた状態になる（出典7）。Microsoft は自動修復を行うとし、「インターネットに接続し Windows Update を使っている対象端末は、2026年11月11日午前10時（米太平洋時間）から24〜48時間以内に修復される」とした（出典10。原文英語を訳出。対象は 24H2 の Enterprise / Education のみ）。待つ側の選択は「48時間、修正なしで放置する」ことになる（本記録の整理）——だから KEV 収載や「悪用の可能性が高い」ものだけ先に緩和する、という順序になる。

SQL Server の例（KB5129299）は、緩和策に副作用があることを示している（出典11）。Microsoft の回避策はトレースフラグ 4696 の有効化だが、その副作用として、セカンダリレプリカに対するsys.dm_exec_requests／sys.sysprocesses の監視クエリがエラー 976 または 978 を返す（この更新より前の挙動に戻る）（出典11）〈重要〉。ほかの回避策は「復旧中のデータベースを照会しない」「更新を削除する」である（出典11）。

緩和策は無料ではない（本記録の評価）——どれも監視や機能を一部手放す。だからこそ「いつ外すか」を決めずに入れると、外し忘れが次の穴になる（本記録の推奨）。
