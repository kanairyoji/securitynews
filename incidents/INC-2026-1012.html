INC-2026-1012Qlik Sense からEU複数社へ3分で同時投下

インターネットに面した Qlik Sense サーバを起点に、 EU の複数の顧客環境へ約3分間のあいだに同じ PowerShell リバースシェルが投げられた—— Cynet の CyOps が2026年10月に観測し、スクリプトの実行を阻止した。 親プロセスは scheduler.exe で、2023年の Cactus による Qlik 侵害と同じ形。 初期侵入に使われた脆弱性は確定していない。 攻撃者の公開ディレクトリ（ポート8012）には Go 製バックドア（Windows・Linux・組み込み向け）、 SSH 常駐スクリプト、Apache ActiveMQ の CVE-2023-46604 エクスプロイト、 Veeam の CVE-2024-40711 向け改変ツールチェーンが置かれていた。 ActiveMQ 経由で侵害された顧客は観測されていない。

脅威・攻撃キャンペーン初報のみ有名事象として記録（日本と直接の関係は薄い）脆弱性の放置既知の脆弱性の悪用
初報: 2026年11月11日 最終更新: 2026年11月12日

Cynet の CyOps・リサーチチームは2026年10月、EU 所在の複数の顧客環境で同じ親子プロセスの並びを観測しました（出典1）〈重要〉。

観測の形はこうです（出典1）。

  • 窓は「約3分」。出典1は「approximately three minutes」と書き、記事の要約は「just over three minutes」（3分強）としています。同じ並びが、複数の EU 所在顧客環境にまたがって現れました。 環境の正確な数は示されていません〈未確定2〉。
  • プロセスの並びは scheduler.exe → cmd.exe → 隠しウィンドウの符号化された PowerShell（出典1）。出典1はこれを「2023年の Cactus による Qlik 侵害に似ている」とし、当時 Arctic Wolf が Scheduler.exe が cmd.exe と PowerShell を起動する形を報告していたと述べています。
  • 初期侵入に使われた脆弱性は確定していません（出典1）〈未確定1〉。出典1は「CVE-2023-41266 と CVE-2023-41265 の組み合わせ、あるいは CVE-2023-48365（DoubleQlik）を使ったとみられる」としつつ、「正確な脆弱性は未確定のままである」と明記しています。 公開ディレクトリにも、脅威ハンティングでも、Qlik のエクスプロイトツールは見つかっていません（出典1）。
  • 投げられたのは1行の PowerShell リバースシェルで、宛先はポート4455（出典1）。Nishang の Invoke-PowerShellTcpOneLine にきわめて近く、変数名を短縮し Flush と Close の呼び出しを省いている——出典1はこれを署名回避の試みかもしれないとしています。
  • 別に、WebClient でコンピュータ名と利用者名をポート80の /hb へ送るチェックインがありました（出典1）。この登録処理は空の catch ブロックで包まれており、失敗しても実行が続く作りです（出典1）。
  • 結果——Cynet はスクリプトの実行を阻止しました（出典1）〈重要〉。その環境でリバースシェルは起動していません。

広がりが見えたのは、その後の基盤の調査からです（出典1）。攻撃者のサーバのポート8012に公開ディレクトリがあり、Windows・Linux・組み込み向けの Go 製バックドア、Bash 製エージェント、SSH 常駐スクリプト、Apache ActiveMQ の CVE-2023-46604 向けエクスプロイト、Veeam Backup & Replication の CVE-2024-40711 向け改変ツールチェーンが置かれていました（出典1）。

ただし ActiveMQ 経由で実際に侵害された顧客は観測されていません—— 出典1は「We did not observe any customers that were successfully exploited through ActiveMQ.」（原文英語。訳: ActiveMQ 経由で侵害に成功した顧客は観測していない）と明記しています（出典1）〈重要〉。

攻撃の経過

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

**外部公開された Qlik Sense を起点に、 `scheduler.exe` 配下で符号化された PowerShell を走らせ、 ポート4455のリバースシェルで足場を作る。 その足場から常駐スクリプトを落とし、 Go 製エージェント（4456）と SSH 常駐で居座り、 内部を探索して ActiveMQ を探す**（出典1。本記録の整理）〈重要〉—— **観測された環境では最初の段階で阻止されている。**

  1. 1. 初期侵入推定[1]
    **外部公開された Qlik Sense サーバが侵害され、 `scheduler.exe` から `cmd.exe` が起動された**（出典1）。 **使われた脆弱性は確定していない—— 出典1は CVE-2023-41266 と CVE-2023-41265 の組み合わせ、 あるいは CVE-2023-48365（DoubleQlik）とみられるとしつつ、 「正確な脆弱性は未確定のままである」と明記している。**
    根拠: **プロセスの親子関係（`scheduler.exe` → `cmd.exe`）**（出典1）—— **出典1はこれを2023年の Cactus による Qlik 侵害 （Arctic Wolf が `Scheduler.exe` → `cmd.exe`・PowerShell を報告）に 似た形としている。** **Qlik のエクスプロイトツールは、 公開ディレクトリにも脅威ハンティングでも見つかっていない。**
  2. 2. 実行確認済[1]
    **`cmd.exe` が隠しウィンドウで符号化された PowerShell を起動した**（出典1）。 **中身は1行のリバースシェルで、宛先はポート4455。 Nishang の `Invoke-PowerShellTcpOneLine` にきわめて近く、 変数名を短縮し `Flush` と `Close` の呼び出しを省いている。** **Cynet はこのスクリプトの実行を阻止した—— 「Cynet blocked the script from executing」（原文英語。 訳: Cynet はそのスクリプトの実行を阻止した）。**
    根拠: **符号化された PowerShell の内容と、Nishang との一致**（出典1）。
  3. 3. C2通信確認済[1]
    **`WebClient` でコンピュータ名と利用者名を、 IP 45.115.26.23 のポート80の `/hb` へ送るチェックインが含まれていた**（出典1）。 **この登録処理は空の catch ブロックで包まれており、 失敗しても実行が続く作りである。** **本来のリバースシェルはポート4455で、 Cynet の検証によれば偵察と常駐スクリプトの投下に使われる。**
    根拠: **スクリプトの内容と、Cynet による検証（実際に接続して挙動を確認）**（出典1）。
  4. 4. 永続化推定[1]
    **常駐スクリプト（`persist.ps1`）が、 Ed25519 鍵を `C:\ProgramData\ssh\administrators_authorized_keys` に追加し、 継承した権限を外して Administrators と SYSTEM にのみ許可を与える**（出典1）。 **さらに OpenSSH を導入または再利用して `sshd` を自動起動に設定し、 受信側の TCP 22 を開ける。 スケジュールタスク `WinUpdCheck` が `winc.ps1` を 5分ごとに SYSTEM 権限で要求して起動し、 `wsvc` を「Windows Service Controller」の表示名で自動起動サービスに登録しようとする。**
    根拠: **公開ディレクトリにあった `persist.ps1`（SHA256 2種）と `OpenSSH-Win64.zip`・`install-sshd.ps1` の解析**（出典1）—— **出典1は「その文字列だけでは、コールバックが完了したことの 検証にはならない」と留保し、 これらの経路が「すべての仕組みが成功したことの証明ではない」としている。**
  5. 5. 内部探索確認済[1]
    **Windows 側では `whoami`・`hostname`・ WMIC による CPU/GPU/OS の照会・`systeminfo`・`ipconfig`、 および C: と D: の SmarterMail のドメインフォルダの確認**（出典1）。 **Linux 側では `id`・`uname`・`uptime`・PID 1 の情報、 ActiveMQ のプロセスとパスの探索、 待ち受けポートの列挙、`/etc/shadow` と `/etc/passwd` の読み取り試行、 ARP エントリ・ディスク・メモリ・ログディレクトリの確認。 出力は `F1`・`F2` のような区切りで分けられていた。**
    根拠: **Go 製リバースシェルのセッションで観測されたコマンド**（出典1）—— **出典1は「the threat actor was looking for ActiveMQ」 （原文英語。訳: 攻撃者は ActiveMQ を探していた）としている。**
  6. 6. 横展開推定[1]
    **次段として Apache ActiveMQ と Veeam Backup & Replication が 準備されていた**（出典1）。 **ActiveMQ 向けには CVE-2023-46604 を狙う `poc_amq.xml`・`poc_amq2.xml`・`poc_amq3.xml` （Java の OpenWire 処理における安全でないクラスのインスタンス化）。 Veeam 向けには CVE-2024-40711 の watchTowr 公開ツールチェーンの改変版 `ysosrc.tgz`。** **ただし出典1は、ActiveMQ 経由で侵害に成功した顧客を観測しておらず、 Veeam のツールチェーンは ループバックへのコールバックと試験用の仕掛けを含み 「キャンペーンに使える状態ではない」と評価している （SOAP の第2段と remoting のツールが欠けていた）。**
    根拠: **公開ディレクトリ（ポート8012）の内容の解析**（出典1）〈重要〉—— **これは「観測された攻撃」ではなく「攻撃者の準備物」である。**

  • C:\ProgramData\ssh\administrators_authorized_keys の作成・変更。
