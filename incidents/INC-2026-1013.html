INC-2026-1013Citrus ランサム・委託先経由とLLM生成

これまで記録の無かったランサムウェア集団「Citrus」が、 委託先の従業員から盗んだ認証情報で VPN と外部公開の RDP ターミナルサーバに入り、 AD CS の認証バイパス（CVE-2026-54121・Certighost）でドメインコントローラになりすまして 権限を奪い、Go 製の Sn00py（RaaS）で暗号化していた—— Kaspersky が2026年11月11日に公表。 通信は Xray の VLESS トンネルを REALITY で mirror.yandex.ru・yastatic.net 宛に見せかけ、 配布は「Kaspersky GPO」と名付けた悪性グループポリシーで行う。 アカウント無効化コマンドや並列実行スクリプトは LLM が生成したものとみられる。 被害はロシア企業に限られ、組織名・件数は公表されていない。

Kaspersky は2026年11月11日、これまで記録の無かったランサムウェア集団「Citrus」の手口を公表しました（出典1）〈重要〉。

出典1が「興味深い」としているのは2点です（出典1）。ネットワークトンネリングの型破りなやり方と、補助的な道具を作るのに AI を使っていることです。

侵入の経路は、すべて委託先です（出典1）〈重要〉。委託先の従業員から盗んだ認証情報を使い、企業の VPN、または外部公開された RDP のターミナルサーバへ直接接続します。 我々が知るすべての事例で、その委託先のドメインアカウントはきわめて限定的な権限しか持っていなかったと出典1は述べています。

そこから権限を上げる手段が、本件の核心です（出典1）。AD CS の認証バイパス脆弱性 CVE-2026-54121（Certighost）を試行し、Active Directory に GHOST ＋ 8文字のランダムな英字という名前のマシンアカウントを作ります（例: GHOSTAUFTAFGS・GHOSTCZYQVAZS・GHOSTIVPRLDZA）。この名前は GitHub に公開されたエクスプロイトを使うスクリプトが生成するものです（出典1）。仕組みはこうです（出典1）。

  • 作ったアカウントの名義で、AD CS の役割を持つ機器にMachine テンプレートに基づく証明書を要求する。
  • 要求の Attributes にはCertificateTemplate:Machine / SAN:dns=dc01.victim.domain / cdc:91.210.109[.]118 / rmd:dc01.victim.domain のような値を入れる。
  • cdc 属性は、認証局がデータの検証のために接続すべき機器のIP または名前を指定するもの。攻撃者はここに自分が支配する機器の address を書き、そこから偽のデータを返す。
  • 悪用が成功すると、認証局は指定されたテンプレートに基づき、指定されたパラメータを持つ証明書を発行する。
  • 発行された証明書の SubjectAlternativeName にドメインコントローラの名前が入るため、攻撃者はドメインコントローラのアカウントとして認証できる。

最終段は Go 製の Sn00py です（出典1）。RSA-2048 と ChaCha20 で利用者のファイルを暗号化し（システムファイルは対象外）、拡張子は .citrus。出典1は「現時点では、攻撃者の秘密鍵なしに復号することは不可能である」としています。 身代金要求メモ（CITRUS_README.txt）には「We`re going to do something special today :). Made with RaaS platform Sn00py.」という文字列があり、Sn00py が RaaS として提供されていることを示しています（出典1）。

配布にはグループポリシーが使われます（出典1）〈重要〉。「Kaspersky GPO」という名前のグループポリシーオブジェクトがランサムウェアを配り、WinRM を有効化し、ボリュームシャドウコピーと Windows Defender を無効化し、身代金要求メモを壁紙に設定します。 host_blacklist では DC01 から DC04 が除外されており、ポリシーが配り続けられるようにしてあります。

被害の範囲は公表されていません（本記録の確認）〈未確定1〉。出典1が示すのは「いくつかのインシデント」であり、被害組織の名称・業種・件数・時期のいずれも記載がありません。国については「ロシア企業のみを攻撃している」とのみ述べられています。

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

**委託先の限定権限アカウントで入り、AD CS を使ってドメインコントローラになりすまし、 中央管理コンソールを奪って防御を一斉に止め、 グループポリシーでランサムウェアを配る**（出典1。本記録の整理）〈重要〉—— **通信は VLESS トンネルで正規の国内 CDN 宛に見せかけ、 痕跡はログ消去と「Kaspersky」を名乗るファイル名で隠す。**

    根拠: **出典1のインシデント対応の観測による**（出典1）—— **認証情報の入手方法は公表されていない。**
  2. 2. 実行推定[1]
    **標準の Windows コマンドインタプリタと PowerShell でコマンドを実行する**（出典1）。 **進行につれて PowerShell スクリプト・バッチファイル・ LLM が生成したコマンドを作って動かす。 Impacket の `atexec` でスケジュールタスクを作り、 各ホストでコマンドを走らせる（タスク名 `sIErKswD`・`PpMBCCSR`・`QwZtLmNp`、 起動するのは `cmd.exe`）。 1C:Enterprise サーバでは外部データ処理（1C-Shell）を使う。**
    根拠: **LLM の使用の根拠はコメントの付き方である**（出典1）〈重要〉—— **管理者アカウントを無効化するコマンドに 「# アカウントを無効化」「# 結果を確認」のコメントが付いていた。 出典1は「攻撃者はコメントをわざわざ書かないので、 コメントは LLM の使用を強く示唆する」としている。**
  3. 3. 権限昇格確認済[1]
    **AD CS の認証バイパス（CVE-2026-54121・Certighost）を使う**（出典1）〈重要〉。 **`GHOST` ＋ 8文字のランダムな英字のマシンアカウントを Active Directory に作り、 その名義で `Machine` テンプレートに基づく証明書を要求する。 要求の `Attributes` に `cdc:91.210.109[.]118` を入れ、 認証局がデータ検証のために接続する先を攻撃者の機器に向けて偽のデータを返す。 成功すると、ドメインコントローラの名前を `SubjectAlternativeName` に持つ 証明書が発行され、攻撃者はドメインコントローラのアカウントとして認証できる。** **別に、Metasploit とみられる実行ファイル経由で CVE-2020-1337 のエクスプロイトも使われた。 1C:Enterprise の安全でない構成にも関心を示した。**
    根拠: **AD に残ったマシンアカウント名（`GHOSTAUFTAFGS`・`GHOSTCZYQVAZS`・ `GHOSTIVPRLDZA`）と、証明書要求の `Attributes` の記録**（出典1）—— **`Attributes` には `CertificateTemplate:Machine`・ `SAN:dns=dc01.victim.domain`・`cdc:91.210.109[.]118`・ `rmd:dc01.victim.domain` のような値が入っていた。** **名前は GitHub に公開されたエクスプロイトを使うスクリプトが生成する。**

    **道具と出力ファイルを削除し、コマンド履歴を消す。 使用中の道具には正規に見える名前を付ける （`KasperskyGPO_Deploy_64.exe`・GPO 名「Kaspersky GPO」・ タスク名 `KasperskyAgentInstallTask`・`Sysvc` 等）**（出典1）。 **`wevtutil` で一部の機器のイベントログを消去する。 十分な権限を得るとホストのアンチウイルスを無効化し、 自分の道具を除外リストに手で追加する。 セキュリティ製品の集中管理コンソールを狙い、 それを使って防御を一斉に無効化する。 Impact 段ではグループポリシーで Windows Defender の レジストリ設定を変更して停止させる—— 出典1は「その結果、ランサムウェアが起動したときに アンチウイルスは反応しなかった」としている。**
    根拠: **残存した配布物とログ、GPO の内容**（出典1）—— **出典1は「悪性ファイル名に Kaspersky の名を使っても 検知を避けられない」と述べている。**

限定権限の委託先アカウントが、AD CS でドメインコントローラの権限に化ける原因・手口出典 [1]

本件の分かれ目は、権限昇格の段にあります（出典1。本記録の評価）〈重要〉。

侵入の入口は委託先です。委託先の従業員から盗んだ認証情報で、企業の VPN、または外部公開された RDP のターミナルサーバへ接続します（出典1）。ここで重要なのは、出典1が明記している次の一文です。

我々が知るすべての事例で、初期侵入に使われた委託先のドメインアカウントはきわめて限定的な権限しか持っていなかった（出典1。原文英語より訳）。

つまり最小権限は実施されていました。それでもドメインコントローラの権限まで到達しています。

使われたのは AD CS の認証バイパス脆弱性 CVE-2026-54121（Certighost）です（出典1）。手順はこうです。

  1. Active Directory に GHOST ＋ 8文字のランダムな英字という名前のマシンアカウントを作る（GHOSTAUFTAFGS・GHOSTCZYQVAZS・GHOSTIVPRLDZA）。この命名は GitHub に公開されたエクスプロイトを使うスクリプトが生成するものです。
  2. そのアカウントの名義で、AD CS の役割を持つ機器にMachine テンプレートに基づく証明書を要求する。要求の Attributes にはCertificateTemplate:Machine / SAN:dns=dc01.victim.domain / cdc:91.210.109[.]118 / rmd:dc01.victim.domain のような値が入ります。
  3. cdc 属性は、認証局がデータの検証のために接続すべき機器のIP または名前を指定するもの。 攻撃者はここに自分が支配する機器を書き、そこから偽のデータを返します。
  4. 成功すると、認証局は指定されたパラメータを持つ証明書を発行する。 証明書の SubjectAlternativeName にドメインコントローラの名前が入るため、攻撃者はドメインコントローラのアカウントとして認証できます。

別経路として、Metasploit とみられる実行ファイル経由でCVE-2020-1337 のエクスプロイトも使われています（出典1）。根拠は、常駐用にアップロードされた実行ファイルの名義で起動されたPowerShell スクリプトの HostName フィールドがMSFConsole という非標準の値だったことです。ファイルは後に削除されていました。

ロシア圏に固有の足場もあります（出典1）。1C:Enterprise サーバの安全でない構成に攻撃者が関心を示しており、出典1は「設定上の不備に加えて、1C:Enterprise には Active Directory で高い権限を持つ保守担当者や管理者が日常的にアクセスする。この2つが合わさって、権限昇格と横展開が容易になる」としています。

なぜこの段が分かれ目なのか（本記録の評価）〈重要〉。ドメインコントローラとして認証できた時点で、後述するとおり配布・防御の無効化・バックアップの破壊がすべて1つの仕組み（グループポリシー）で実行可能になります。暗号化の検知で止めようとするのは、既に手遅れの地点です。

配布と防御の無効化とバックアップの破壊が、1つのグループポリシーに収まっている被害規模・影響範囲出典 [1]

「Kaspersky GPO」という名前のグループポリシーオブジェクトが、次のすべてを行います（出典1）〈重要〉。

  • ランサムウェアを配る。
  • WinRM を有効化する。
  • ボリュームシャドウコピーを無効化する。
  • Windows Defender を無効化する。
  • 身代金要求メモを壁紙に設定する。

host_blacklist では DC01 から DC04 が除外されています（出典1）。出典1は理由を「ポリシーが配り続けられるようにするため」としています。自分の配布の仕組みを壊さないための設計です（本記録の整理）。

防御の無効化は、これだけではありません（出典1）。

  • wevtutil で一部の機器のイベントログを消去する。
  • 十分な権限を得ると、ホスト上のアンチウイルスを無効化する（これにより mimikatz が動く）。
  • セキュリティ製品の集中管理コンソールを狙い、それを使って防御を一斉に無効化する。
  • 自分の道具をアンチウイルスの除外リストに手で追加する。

結果として、出典1はこう書いています——「その結果、ランサムウェアが起動したときにアンチウイルスは反応しなかった」（出典1）〈重要〉。

道具の名前も、正規に見えるものが選ばれています（出典1）。KasperskyGPO_Deploy_64.exe・KasperskyGPO_Deploy_64_FIXED.exe（自己展開書庫。中身は Deploy-KasperskyGPO.ps1・悪性 GPO のディレクトリ・KasperskyAgent.exe または agent.exe）、KasperskyAgentInstaller.exe、GPO 名「Kaspersky GPO」、スケジュールタスク名 KasperskyAgentInstallTask・Sysvc、ログ Kaspersky_GPO_Deployment.log。 キーロガーのパスも C:\ProgramData\Oracle\Java\jhost.exe、ログは C:\Users\<username>\AppData\Roaming\Microsoft\CLR\ErrorLog.txt です。

出典1はこれについて「悪性ファイル名に Kaspersky の名を使っても検知を避けられない」と添えています（出典1）。自社名が悪用された事実を伏せずに書いている点を本記録は評価します（本記録の評価）—— ベンダー名を含むパスを広く除外設定している組織は多く、そこを突かれていることは実務上必要な情報です。

最終段の Sn00py は Go 製で、RaaS です（出典1）。RSA-2048 と ChaCha20 で利用者のファイルを暗号化し（システムファイルは対象外）、拡張子は .citrus。出典1は「現時点では、攻撃者の秘密鍵なしに復号することは不可能である」としています。 身代金要求メモ（CITRUS_README.txt）には「Made with RaaS platform Sn00py.」の文字列があり、Citrus が暗号化の道具を借りていることを示します（出典1）。メモは ProtonMail のアドレスを登録してメールまたは Telegram で連絡するよう求め、72時間の期限を示し、サービスのダンプ・従業員の個人データ・会計記録・契約・ソースコードの公開を脅します。金額の記載はありません〈未確定2〉。

トンネルは正規の国内CDN宛に見え、自作の道具はほとんど無い評価・解釈出典 [1]

出典1が「型破り」としているのはトンネリングです（出典1）〈重要〉。

Xray で C2 サーバへポート443の逆方向 VLESS トンネルを張り、REALITY を使って、通信を mirror.yandex.ru とyastatic.net 宛のものに見せかけます（出典1）。設定ファイルは起動後に削除されることもありました。

委託先アクセスの管理が結論だが、多要素認証には触れられていない対策・注意喚起出典 [1]

出典1の結論は1点に絞られています（出典1）〈重要〉。

組織のインフラへの委託先のアクセスは、厳格に管理し制限しなければならない（出典1。原文英語より訳）。

ただし「権限を絞る」だけでは足りないことも、同じ報告が示しています（本記録の評価）〈重要〉—— 使われた委託先アカウントは「きわめて限定的な権限しか持っていなかった」のです。 足りないのは、権限の広さ以外の制限です。

以下は出典1の観測から本記録の作成者が導いたものです（出典1は対策の節を持ちません）。

1. 委託先アカウントの点検項目を、権限以外に広げる。

  • 接続元IPの制限があるか。
  • 多要素認証があるか。 出典1は多要素認証に触れていません（本記録の確認）〈重要〉—— 窃取した認証情報だけで VPN・RDP に入られている以上、少なくとも観測された事例では有効に働いていなかったとみられますが、これは本記録の推測です。
  • ドメイン参加の機器アカウントを作れる権限（ms-DS-MachineAccountQuota）が残っていないか。
  • AD CS の証明書を要求できるか。

2. AD CS のログを取り、遡って探す。 攻撃者は端末のイベントログを wevtutil で消しています（出典1）。それでも経路が再構成できたのは、痕跡が端末の外にあったからです（出典1）。探すべきは次の3つです。

  • GHOST で始まるマシンアカウントの作成。
  • Machine テンプレートへの要求のうち、SAN にドメインコントローラ名を含むもの。
  • cdc 属性に外部IPを指定する要求。

ただし①の命名規則はエクスプロイトの実装に依存するので、攻撃者が変えれば効かなくなります（本記録の評価）—— ②③のほうが寿命があります。

3. 集中管理コンソールを分離する。 攻撃者はここを奪って防御を一斉に無効化しています（出典1）。コンソールの管理者を通常のドメイン管理者と分け、コンソール上の重要操作のログをコンソールの外へ転送します（コンソールを失っても記録が残る形にする）。

4. バックアップを「GPO で消せるか」で判定する。 配布・WinRM の有効化・シャドウコピーの無効化・Defender の停止がすべて同じグループポリシーで行われています（出典1）〈重要〉。AD の認証で到達できる範囲のバックアップは、同時に失われます。少なくとも1系統を、別の認証系・物理的分離・不変ストレージに置きます。

5. 外向き通信を、宛先ではなく出所で見る。 REALITY 偽装により宛先ベースの許可リストは通ります（出典1）。サーバからの外向き通信を既定で拒否する構成になっているかを確認し、なっていなければ「どの機器が外へ443の常時接続を持っているか」を一覧で出せるようにします。

6. 再起動されないサーバを、プロセスと接続の側から点検する。 出典1は「定期的に再起動されない機器（ターミナルサーバ等）では、攻撃者は常駐をまったく確立せずに道具を動かすことがある」としています（出典1）〈重要〉—— スケジュールタスク・サービス・自動起動の確認だけでは見落とします。

7. 防御の無効化を最優先の警報として扱う。 「保護が無効化された」「除外が追加された」「GPO が作成・変更された」「ボリュームシャドウコピーが無効化された」は、暗号化より必ず前に現れます（出典1）。これらが情報レベルの記録になっているなら、重大度を上げます。
