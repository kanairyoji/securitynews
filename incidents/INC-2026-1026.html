JVN の「対策」欄は次のように記している（出典1）。

「開発者によると、修正済みのファームウェアが展開済みであり、またインターネット未接続の機器もインターネット接続時に自動的に修正済みのファームウェアが適用されるため、ユーザーの対応は不要とのことです。」

この形は、通信事業者が機器と回線を一体で提供している製品の強みである（本記録の評価）〈重要〉——利用者が版を調べ、配布サイトを探し、更新作業を行う必要が無い。一般的なルーター製品では、脆弱性が公表されても更新されない機器が長く残る。

一方で、残るのは「自動適用が届かない機器」である（本記録の評価）。出典1 自身が「インターネット未接続の機器も接続時に適用される」と書いていることは、未接続のまま置かれている機器が存在することを前提としている（本記録の整理）。解約後に返却されていない機器、予備として保管されている機器、長期不在の住居にある機器がどれだけあるかは公表されていない〈未確定3〉。

前提は「管理画面にログインできること」——家庭用機器ではこの前提が崩れやすい原因・手口出典 [1]

想定される影響は次のとおりである（出典1）。

「当該機器のWeb管理画面にログイン可能なユーザによって、root 権限で任意のコマンドが実行される可能性があります。」

CVSS v4.0 の評価は AV:A（隣接ネットワーク）・PR:L（低い権限が必要）・UI:N（利用者の関与は不要）である（出典1）。つまり、インターネット側から誰でも叩ける脆弱性ではない（本記録の整理）——同じネットワークに到達でき、管理画面にログインできることが要る。

この前提を「高いハードル」と読むかどうかが、本件の実務的な評価を分ける（本記録の評価）〈重要〉。企業のネットワーク機器なら、管理画面の資格情報は管理者しか持たない。しかし本機は家庭・小規模事業所に置かれるホームルーターである（本記録の整理）。管理画面の資格情報は筐体の記載どおりで使われることが多く、同じ Wi-Fi につながる同居者・来客・持ち込み端末が前提を満たしうる（本記録の評価。出典1・2 にこの点の記述は無い）。

そして影響は root 権限での任意コマンド実行である（出典1）。機器を完全に掌握できれば、宅内の通信の観測、DNS 設定の書き換えによる偽サイトへの誘導、常駐プログラムの設置が成立しうる（本記録の評価）。在宅勤務でこの機器の下に業務端末を置いている組織にとっては、自組織が管理していない経路上の機器がこの状態にあることを意味する（本記録の評価）〈重要〉。

「root 権限で実行される可能性」は、悪用が観測されたという意味ではない未確定事項出典 [1] [2]

出典1・2 のいずれにも、悪用の観測・被害の報告・攻撃キャンペーンへの言及は無い〈未確定2〉（本記録の確認）。

CVSS v4.0 で 8.6 という値と「root 権限で任意のコマンド実行」という語が並ぶと、進行中の攻撃として読まれることがある（本記録の整理）〈重要〉——本件で確認できるのは、脆弱性の存在と、修正が2026年9月に配布済みであることまでである（出典1・2）。

脆弱性の所在（どの機能・どのパラメータ）と実証手順も公表されていない〈未確定1〉。修正が自動で適用される製品では、詳細を出さない判断は残存機器の保護に働く（本記録の評価）——一方で、利用者や組織が「自分の機器が該当するか」を自分で確かめる材料も無い（本記録の評価）。版の確認方法も出典1・2 には示されていない。

報告者は4名の連名で、所属に大学と中学校が併記されている背景・過去事例出典 [1]

出典1 は公表の経緯を次のように記している（出典1）。

「この脆弱性情報は、情報セキュリティ早期警戒パートナーシップに基づき下記の方がIPAに報告し、JPCERT/CCが開発者との調整を行いました。報告者：大平 剛 氏、socho 氏、京都工芸繊維大学 栗山 樹 氏、豊中市立第十一中学校 小川 智也 氏」

4名の連名で、所属に大学（京都工芸繊維大学）と中学校（豊中市立第十一中学校）が併記されている（出典1）〈重要〉—— 国内の脆弱性報告が、企業の研究者以外の層からも届いていることを示す記載である（本記録の整理）。

報告日は公表されていない〈未確定4〉ため、受付から修正までの期間は測れない（本記録の留保）。測れるのは、修正リリース（2026年9月）から JVN 公表（2026年11月12日）までのおおむね2か月である（本記録の算出）。早期警戒パートナーシップの枠組みでは、修正の配布が済んでから公表する運用が基本であり、本件はその順序どおりに進んでいる（本記録の整理）。

ベンダの告知は JVN 上のベンダステータスのみで、自社サイトの告知は確認できなかった未確定事項出典 [1] [2]

出典1 のベンダ情報欄からたどれるのは、JVN 上に掲載されたソフトバンクのベンダステータス（出典2）である。内容は「該当製品あり」「Airターミナル6 v1.01.80およびそれ以前」「2026年9月に本脆弱性の修正を行ったファームウェアをリリースしており、自動的にアップデートが適用されます」（出典2）である。

ソフトバンク自社サイトに置かれた告知ページは、本記録では確認できなかった〈未確定5〉（本記録の確認）——検索でも、同社サポート情報の URL 推定でも到達できていない。

利用者の作業が不要であれば、自社サイトでの告知を省く判断はありうる（本記録の評価）。ただし読者の立場から見ると、困るのは「自分の機器が該当するか」と「更新はもう適用されたのか」を確かめたいときである（本記録の評価）〈重要〉。JVN のベンダステータスには版の確認手順も適用状況の確認手順も無い。資産管理の観点では、通信事業者が自動更新する機器は「更新されたはずの機器」として台帳に載せるしかない（本記録の評価）。

  • 管理画面の処理を root で動かしているかを確認する。 同じ入力の不備でも、実行権限が影響の大きさを決める。
    **本件の影響は「root 権限で任意のコマンドが実行される」ことである**（出典1） 〈重要〉——**入力検証の不備（CWE-78）と、処理が特権で動いていたことの 2つが重なって成立している**（本記録の整理）。

  • 外部入力をシェル経由で扱っている箇所を洗い出す。 コマンド文字列の組み立てをやめ、引数配列で渡す。
    **CWE-78（OS コマンドインジェクション）が割り当てられている**（出典1）—— **ネットワーク機器の管理 UI では、ping・traceroute・設定反映などで 外部コマンドを呼ぶ実装が残りやすい**（本記録の評価）。
    取るべき行動 **`system()`・`popen()`・シェル経由の実行を検索し、 ①外部プロセスを呼ばない実装に置き換える ②やむを得ない場合は引数を配列で渡し、シェルを経由させない ③入力を許可リスト（数値・IP 形式）で検証する——の順で直す。**
  • 「隣接ネットワークからのみ」という条件を、信頼境界として扱わない。 Wi-Fi は同じネットワークの内側である。

    取るべき行動 **機器の管理 UI へのアクセスを、既定で有線・特定 VLAN からのみに制限する 設計にする。** **自社が運用する拠点では、業務セグメントとゲスト・IoT セグメントを分離する。**
  • 自動更新に依存する機器は「更新されたはず」で止まる。 版を機械的に収集できる経路を用意する。
    **本件は自動適用で利用者の対応が不要とされている**（出典1）—— **一方で版の確認方法も適用状況の確認方法も示されていない**〈未確定5〉 （本記録の確認）。
    取るべき行動 **自社が配布・運用する機器では、現在のファームウェア版を 管理画面と API の両方から取得できるようにし、 利用者・運用者が適用結果を確認できる状態にする。**
