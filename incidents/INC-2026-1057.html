INC-2026-1057FBIが北朝鮮FaceStealerを警告

FBI は2026年11月12日、暗号資産・Web3業界とオープンソースソフトウェアの 保守担当者に向けて FLASH（AC-111226-MS・TLP:CLEAR）を公表し、 **北朝鮮の国家支援ハッカーによる「FaceStealer」と呼ぶ手口で、 過去18か月に4億ドル超の暗号資産が窃取された**と警告した。 **手口の中核は、先に侵害した被害者のウェブカメラ映像を秘密裏に録画しておき、 偽の Zoom／Teams 会議でそれを再生して本人に見せることである**—— 招待は乗っ取った本人の Telegram・LinkedIn・Slack・Discord から届き、 会議中に「音声の不具合」を装って修正手順を指示し、 その作業で被害者自身がマルウェアを入れる。 **FBI は900本を超える被害者の録画映像を押収した**。 同日、米司法省は **FaceStealer に使われたクラウド基盤の押収**と、 別件として**Binance から窃取された暗号資産のうち12億ドル超の 裁判所の許可に基づく押収・保全**を公表した。 **オープンソースの供給網も標的で、週に数千万回ダウンロードされる JavaScript ライブラリの保守担当者が同じ手口で侵害され、 悪性の依存関係が作られる寸前まで進んでいた**。

いちばん効く偽装は、本人の顔だった。

FBI が2026年11月12日に出した FLASH（AC-111226-MS）は、北朝鮮の国家支援ハッカーによる手口を「FaceStealer」と名付けて警告している（出典1）。過去18か月で4億ドルを超える暗号資産が窃取され、オープンソースソフトウェアの供給網を侵害する試みも行われた（出典1）。

手口の中心は、先に侵害した被害者のウェブカメラ映像を、本人が会議の開始を待っている間に秘密裏に録画しておくことである（出典1）〈重要〉。次の標的には、乗っ取った本人の Telegram や LinkedIn から会議の誘いが届く。過去のやり取りが読めるので、文面は相手ごとに作られる（出典1）。日程調整には Calendly のような正規のサービスが使われ、直前に送られるリンクは Zoom や Teams を装った打ち間違い狙いのドメインである（出典1。例として uu01webzoom.us・teams.livemeet.us が挙げられている）。

標的が入室すると、録画された「本人」の映像が再生される（出典1）。参加者が複数いるように見せるため、別の被害者の映像も同時に流される。そのうえで「音声が聞こえていない」と告げ、本人を装って修正の手順を指示する——更新の案内を押す、スクリプトを走らせる、端末に文字列を貼り付けて実行する（出典1）。その作業で入るのは、ブラウザのクッキーの収集、キー入力の記録、画面の取得、そして遠隔操作の裏口である（出典1）。同時に、標的のウェブカメラ映像の録画も始まっている（出典1）〈重要〉——次の被害者を釣る材料が、その場で作られる。

FBI は900本を超える被害者の録画映像を押収した（出典1）。同日、米司法省は FaceStealer に使われたクラウド基盤の押収を公表し、別件として Binance から窃取された暗号資産のうち12億ドル超の押収・保全が裁判所に認められたとした（出典2）。

本記録が最も重く見るのは、オープンソースの部分である（本記録の評価）〈重要〉。週に数千万回引かれている JavaScript ライブラリの保守担当者が同じ手口で侵害され、攻撃者はその権限で悪性の依存関係を作った（出典1）。検知と対応が速かったために大規模な被害には至らなかったが、成立していれば「1人の被害者が数百万人の被害者になりうる」とFBI は書いている（出典1。原文英語を訳出）。

攻撃の経過

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

**FBI は手口を6段階で整理している**（出典1）—— **本記録は以下に、防御側が検知・遮断を置ける位置という観点で 同じ流れを並べ直す**（本記録の整理）。 **注意すべきは、技術的な侵害が「標的自身の手による実行」で成立する点である** （出典1。本記録の評価）〈重要〉—— **送られてくるのは実行ファイルではなく、 信頼している相手からの作業指示である**（本記録の評価）。

  1. 1. 偵察[1]
    **既に侵害した被害者の端末から、連絡先一覧・会話履歴・ 各種通信アプリ・ウェブカメラ映像を入手し、次の標的を選ぶ** （出典1。事実）—— **会話履歴が読めるため、重要な相手には過去のやり取りに 合わせた文面が作られる**（出典1）。
  2. 2. 初期侵入[1]
    **乗っ取った本人のアカウントから映像会議の誘いが届き、 正規の日程調整サービスを経て、 Zoom・Teams を装った打ち間違い狙いのドメインのリンクが送られる** （出典1。事実）—— **リンク先には本物と区別できない複製の画面が置かれている**（出典1）。
  3. 3. 実行[1]
    **会議内で「音声の不具合」を装った指示が出され、 標的自身が更新の案内を押す、スクリプトを走らせる、 文字列を貼り付けて実行する、のいずれかを行う**（出典1。事実）〈重要〉—— **偽の参加者を複数置くことで、 「自分だけが問題を起こしている」という圧力が作られる**（出典1）。
  4. 4. 認証情報アクセス[1]
    **入るのはブラウザのクッキーの収集、キー入力の記録、 画面の取得、遠隔操作の裏口である**（出典1。事実）—— **ウォレット・シードフレーズ・その他の価値ある権限が走査され、 暗号化通信アプリが乗っ取られて本人は締め出される**（出典1）。
  5. 5. 影響（暗号化・破壊・改ざん）[1]
    **暗号資産が窃取され、通信アカウントが乗っ取られ、 勤務先のネットワークやオープンソースの保守権限が悪用される** （出典1。事実）〈重要〉—— **窃取は初期侵害から数か月〜1年以上後に行われた例があり、 攻撃者はウォレットの残高が増えるのを待っていたとされる**（出典1）。 **オープンソースでは、保守担当者の権限で 悪性の依存関係が作られた**（出典1）。

  • **押収した被害者の映像のうち、目隠し処理をした例を 注意喚起の図として掲載した**（出典1。事実）。
    トレードオフ: **被害者の映像を公にすることの負担を受け入れる代わりに、 「本人の顔が再生される」という手口の核心を 読者に一目で伝えることを選んでいる**（本記録の評価）〈重要〉—— **文章だけでは「偽の会議で騙された」としか伝わらない** （本記録の評価）。
  • **注意喚起（FBI）と押収の公表（司法省）を同日に行った** （出典1・2。事実）。
    トレードオフ: **押収を先に伏せて捜査を続ける選択を捨て、 業界への警告を優先している**（本記録の評価）—— **攻撃者に手口の露見を知らせることになるが、 手口の中核（録画映像の再生）は利用者側の行動変更でしか止まらない** （本記録の評価）〈重要〉。
  • **業界向けの包括的な注意喚起（暗号資産・Web3業界と オープンソースの保守担当者を名指し）という形を採った**（出典1。事実）。
    トレードオフ: **被害者を個別に特定して通知する手間を避け、 到達範囲の広い公開の警告を選んでいる**（本記録の評価）—— **一方で、900本の映像の被写体となった個人が 自分の被害を知る手段は示されていない**（本記録の整理）〈未確定1〉〈重要〉。

本人の顔が再生される。だから「よく知っている相手」ほど効く原因・手口

この手口の核心は、技術ではなく素材にある（本記録の評価）〈重要〉。

攻撃者は、すでに侵害した被害者が映像会議の開始を待っている間に、 その人のウェブカメラ映像を秘密裏に録画しておく（出典1。事実）。 次の標的の会議では、その映像を再生する（出典1）。 参加者が複数いるように見せるために、 別の被害者の映像も同時に流される（出典1）。

標的の側から見える状況を順に並べると、疑う手がかりが乏しいことが分かる （本記録の整理）—— ①よく知っている相手の正規の Telegram から会議の誘いが来る （過去のやり取りを踏まえた文面である）、 ②正規の日程調整サービスで時間を決める、 ③会議の直前に Zoom や Teams に見えるリンクが届く、 ④控室で待たされ、入室すると本人の顔と声がある（出典1）。

FBI ロサンゼルス支局の責任者は、この手口を 「経験豊富でセキュリティ意識の高い利用者すら騙しうる」と述べ、 「自分が引っかかる場面を想像できないなら、 想像力が足りていない」とも述べている（出典2・3。原文英語を訳出）〈重要〉。

本記録の評価では、研修で対抗できる類型ではない（本記録の評価）。 「不自然な文面」「見知らぬ送信者」といった見分け方は、 乗っ取られた本人のアカウントと本人の顔の前では機能しない （本記録の評価）—— 残るのは、FBI が推奨する2つの行動 （リンクではなく会議コードで参加する、 相手と双方向に会話できるまでカメラをオンにしない）のように、 文脈の判断を要しない手順である（出典1。本記録の評価）。

録画は「次の被害者を作る部品」であり、被害は循環する評価・解釈

この手口が自己増殖する構造を持っている点が、 通常のなりすまし詐欺と違う（本記録の評価）〈重要〉。

標的が偽のリンクを押した時点で、 攻撃者は標的のウェブカメラ映像の録画を始めている（出典1。事実）。 マルウェアが入った後は、連絡先一覧・SNS・通信アプリ・ ウェブカメラ映像が攻撃者の手に渡る（出典1）。 FBI は「被害者と乗っ取られた連絡先一覧が増えるごとに、 標的と被害者の母数は指数的に増える」と書いている （出典1。原文英語を訳出）。

押収された映像が900本を超えるという数は、 この循環が何巡も回ったことを示している（本記録の評価）—— 映像の本数は人数と同じではないが、 少なくともその人数分の初期侵害が成立していたと読める （本記録の評価・推測）〈未確定1〉。

もう1つ、時間の使い方が特徴的である（本記録の整理）。 初期侵害から数か月〜1年以上経ってから暗号資産の窃取と アカウントの乗っ取りに及んだ例が複数報告されており、 攻撃者はウォレットの残高が増えるのを待っていたとされる（出典1）〈重要〉。 侵害の兆候と被害の発生が年単位で離れると、 被害者はその2つを結び付けられない（本記録の評価）—— 「あの時の会議が原因だった」と分かるのは、 捜査機関が基盤を押収した後になる（本記録の評価・推測）。

週に数千万回引かれるライブラリが、1人の端末の先にあった波及・関係先

本記録が本件で最も重く見るのは、この部分である（本記録の評価）〈重要〉。

事実関係はこうである（出典1。事実）—— 攻撃者は複数回のやり取りを重ねて、 相当な規模のオープンソース JavaScript ライブラリの保守担当者を 偽の Teams 会議に誘い込んだ。会議には複数の参加者がいるように見せられ、 そのうち少なくとも1人は保守担当者が見知った人物だった。 「システムに問題がある」と伝えられ、 言われたとおりの「修正」を行ってマルウェアを入れた。 攻撃者はその保守権限で、正規のライブラリと一緒に取得される 悪性の依存関係を作った。当該ライブラリは週に数千万回 ダウンロードされている（出典1）。

FBI は「迅速な検知と対応が無ければ、 この失敗した攻撃は容易に極めて大規模な被害を生みえた」と記している （出典1。原文英語を訳出）〈重要〉。

さらに、同種の試みは1件ではない（出典1）—— FBI は npm のレジストリに公開している保守担当者に対する複数の試みと、 最近は Rust のクレートの保守担当者に対する試みも把握しているとしている （出典1）。

ライブラリの名称は公表されていない（本記録の整理）〈未確定4〉〈重要〉—— これは利用側にとって痛い。 自社の依存関係に当該ライブラリが含まれるかどうかを 確認する手がかりが無いためである（本記録の評価）。 本記録の評価では、名称を出さない判断には 正規の理由（捜査・さらなる悪用の防止）がありうるが、 その結果として利用側にできるのは 「依存関係の追加と版の変化を検知する仕掛けを常設すること」だけになる （本記録の評価）。

構造としての問題は、権限の集中である（本記録の評価）。 週に数千万回引かれる部品の配布権限が、 1人の個人の作業端末の上にある。 その端末は、本人が信頼する相手からの会議の誘いで侵害される （出典1。本記録の整理）〈重要〉。

深層偽造は補助で、主役は今も本物の映像である評価・解釈

FLASH には「新たな警告」として深層偽造の節がある（出典1）。

FBI は、攻撃者が「超知能（SI）」と呼ぶ技術を使い始めており、 暗号資産・Web3業界の著名で影響力のある人物の 公開された写真や映像から現実的な深層偽造を作っていると記している （出典1。原文英語を訳出。用語は FBI の表記）〈重要〉。 用途は、偽の会議に著名人が参加しているように見せることで、 本物の被害者映像の代わりにも、併用にも使えるとされる（出典1）。 「深層偽造の品質は、ウェブカメラの映像として通じる程度で足りる」 という指摘も添えられている（出典1。原文英語を訳出）。

ただし FBI の評価は明確である（出典1）—— 「FaceStealer の手口は、現時点でも圧倒的に 本物の被害者映像の窃取に依存している」（出典1。原文英語を訳出）。

本記録の評価では、ここは落ち着いて読むべき部分である （本記録の評価）〈重要〉—— 深層偽造の検知技術に投資する話に見えるが、 対策として FBI が挙げているのは 「本物の映像でも偽造でも同じように効く」行動である （正規アプリと会議コードでの参加、 双方向の会話が成立するまでカメラをオンにしない）（出典1）。 つまり、映像の真偽を見分ける方向に解を求めていない（本記録の整理）。

押収は手口を止めない。止まるのは利用者側の手順が変わったときである刑事対応

同日、米司法省は2つの措置を公表した（出典2。事実）—— ①FaceStealer の手口に使われたクラウド基盤の押収 （カリフォルニア州中部地区。900本超の被害者映像は 連邦の令状に基づいて押収された）、 ②別件として、2026年10月29日ごろに Binance から窃取された 60億ドル超の仮想資産のうち、 27億ドル超が官民の取り組みで凍結され、 12億ドル超について裁判所が押収・保全を認めたこと（出典2）。

2つの数字を足さないこと（本記録の明示）〈重要〉—— FaceStealer の4億ドル超（18か月）と Binance の60億ドル超（単一の事案）は別の事案である（出典2。本記録の整理）。 本記録は後者を比較・背景として併記するにとどめ、 事案そのものは別の記録で追っている（本記録の整理）。

刑事局の担当者は、凍結について 「法執行の手が届かなくなる前に押さえた」「この歴史的な侵害の 約半分を直ちに止めた」と述べている（出典2・3。原文英語を訳出）。

一方、押収されたクラウド基盤の内容（事業者名・構成・押収の時点）と、 押収後に同じ手口が続いているかどうかは公表されていない （本記録の整理）〈未確定5〉。

本記録の評価では、基盤の押収が手口を止める効果は限定的である （本記録の評価）〈重要〉—— 必要なものは、乗っ取った通信アカウント、偽の会議画面を置くサーバ、 そして録画された映像である。いずれも作り直せる（本記録の評価）。 恒久的に効くのは、録画の素材を作らせないこと （会議の控室でカメラをオンにしない）と、 偽の会議画面に到達しないこと（リンクを押さない）である （出典1。本記録の評価）。

侵入を防げた**業務上の重要な依頼について、 通信アプリのスレッド内で完結させない運用にする**　**乗っ取られた本人のアカウントから届く連絡を、 文面で見分けることはできない**（出典1。本記録の評価）。
初期侵入機会はあったが検知できず
**偽装ドメインへの接続は、端末と出口の通信記録に残る** （本記録の評価）—— **ただし会議サービスに似たドメインは日々新しく作られるため、 一覧による遮断は追いつかない**（本記録の評価）〈重要〉。
侵入を防げた**業務端末から会議サービスへの接続を、 正規アプリの経路に限る（ブラウザ版の利用を既定で止める）**　**FBI の推奨も、リンクではなく会議コードでの参加である** （出典1）。
検知できた**会議サービスの名前を含む新規登録ドメインへの接続を通知する**　**打ち間違い狙いのドメインは、 登録からの日数と文字列の近さで機械的に拾える**（本記録の評価）。
実行機会はあったが検知できず
**実行の瞬間は端末側に記録が残る類型である**（本記録の評価）—— **会議中に端末の設定を変える、コマンドを実行する、 署名のない実行ファイルを動かすといった行為は、 業務の文脈から外れている**（本記録の評価）〈重要〉。
侵入を防げた**業務端末で、利用者が貼り付けたコマンドの実行と 署名のない実行ファイルの起動を制限する**　**この手口が成立するのは、 利用者が自分の権限で実行できる状態にあるときだけである** （本記録の評価）。
侵入を防げた**「会議中に指示された修正作業」を、 情報システム部門への連絡なしに行わない運用を周知する**　**技術的な制限が難しい環境では、 手順として先に決めておく以外に方法がない**（本記録の評価）。
認証情報アクセス機会はあったが検知できず
**クッキーの持ち出しによるセッションの再利用は、 多要素認証を迂回する**（本記録の評価）〈重要〉—— **検知の手がかりは、 普段と異なる地点・端末からの同一セッションの利用である** （本記録の評価）。
影響を限定できた**業務の重要なサービスで、セッションを端末に結び付ける （機器証明書・端末の健全性の確認を条件にする）**　**クッキーを盗まれても、別の端末では使えない状態にする** （本記録の評価）。
検知できた**暗号化通信アプリのアカウントに、 端末の追加を通知・承認する設定を入れる**　**本人が締め出される前に、 端末追加の通知が届く構成にしておく**（本記録の評価）。
影響（暗号化・破壊・改ざん）検知した
**JavaScript ライブラリの事例では、 侵害の検知と対応が速かったため大規模な被害に至らなかったと FBI は記している**（出典1）〈重要〉—— **誰が検知したか、どう気づいたかは示されていない** （本記録の整理）〈未確定4〉。
侵入を防げた**公開レジストリへの公開操作に、 多要素認証と別の承認者を要求する**　**1人の端末の侵害が、 そのまま配布物の汚染につながる構造を断つ**（本記録の評価）。
検知できた**自社の依存関係について、 新しい依存先の追加と版の変化を検知する**　**利用側に残る最後の防衛線である**（本記録の評価）—— **本件では悪性の依存関係が 「正規のライブラリと一緒に取得される」形で作られた**（出典1）。

対応の評価

評価材料がない判断は「評価材料なし」としています。結果論で断じないための区分です。
判断評価評価の根拠と留保
**押収した被害者の映像のうち、目隠し処理をした例を 注意喚起の図として掲載した**（出典1。事実）。機能した
**注意喚起（FBI）と押収の公表（司法省）を同日に行った** （出典1・2。事実）。機能した
**業界向けの包括的な注意喚起（暗号資産・Web3業界と オープンソースの保守担当者を名指し）という形を採った**（出典1。事実）。部分的に機能
CISO・経営層への示唆
  • **「不審なメールを見分ける」研修は、この手口には効かない。 会議の参加手順そのものを変える必要がある**
    **招待は乗っ取られた本人のアカウントから届き、 文面は過去のやり取りに合わせて作られ、 会議では本人の顔と声が再生される**（出典1。事実）〈重要〉—— **FBI ロサンゼルス支局の責任者も 「経験豊富でセキュリティ意識の高い利用者すら騙しうる」と述べている** （出典2・3。原文英語）。
    取るべき行動 **映像会議の参加方法を規程で定める。 「リンクを押さず、正規アプリに会議コードを入力して参加する」 「相手と双方向に会話が成立するまでカメラをオンにしない」の2点を 例外なしの運用とし、取引先にも自社の運用として伝える**
  • **会議中に出る「技術的な不具合の修正手順」は、 それ自体が攻撃の実行段階である**
    **第5段階では、音声の不具合を装い、 偽の参加者を複数置いて「自分だけが問題を起こしている」という 圧力をかけたうえで、更新の案内・スクリプトの実行・ 文字列の貼り付けを指示する**（出典1。事実）〈重要〉。
    取るべき行動 **「会議中に相手から指示された端末操作は行わない。 いったん会議を抜け、情報システム部門に連絡する」ことを 明文の手順にする。 従業員が会議を中断して確認することを、評価上の不利益にしない**
  • **侵害と被害は年単位で離れる。1年前の会議が原因であり得ると 前提を置かないと、調査の範囲を取り違える**
    **初期侵害から数か月〜1年以上経ってから暗号資産の窃取と アカウントの乗っ取りに及んだ例が複数報告されている** （出典1。事実）〈重要〉—— **攻撃者はウォレットの残高が増えるのを待っていたとされる**（出典1）。
    取るべき行動 **端末・認証の記録の保存期間を、 事故の調査に必要な範囲（少なくとも1年）まで延ばす。 短い保存期間を費用で決めている場合は、 「1年前の侵害を追えない」ことをリスクとして明記して再決裁する**
  • **自社が引いているオープンソースの部品は、 個人の作業端末1台の先にあることがある**
    **週に数千万回ダウンロードされる JavaScript ライブラリの 保守担当者が同じ手口で侵害され、 悪性の依存関係が作られた**（出典1。事実）〈重要〉—— **ライブラリの名称は公表されていない**（本記録の整理）〈未確定4〉。
    取るべき行動 **自社の製品・社内システムの依存関係の一覧（部品表）を 常時取得できる状態にする。 依存先の追加と版の変化を検知して通知する仕組みを入れ、 更新を自動で取り込む構成を見直す（固定と検証を挟む）**
セキュリティ技術者への示唆
  • **偽の会議画面への到達は、正規アプリの経路に限ることで断てる**
    **攻撃者は Zoom・Teams を装った打ち間違い狙いのドメインに 本物と区別できない複製の画面を置いている**（出典1。事実）—— **FBI の推奨も、リンクではなく会議コードでの参加である**（出典1）。
    取るべき行動 **業務端末で、会議サービスのブラウザ版の利用を既定で止め、 正規アプリ経由に限る。 あわせて会議サービス名を含む新規登録ドメインへの接続を 検知対象にする（登録からの日数と文字列の近さで拾う）**
  • **クッキーの持ち出しは多要素認証を迂回する。 セッションを端末に結び付ける**
    **インストールされるのはブラウザのクッキー収集、 キー入力の記録、画面の取得、遠隔操作の裏口である** （出典1。事実）〈重要〉—— **クッキーを持ち出されれば、認証をやり直さずに入れる** （本記録の評価）。
    取るべき行動 **重要な業務サービスで、セッションの利用条件に 端末の識別（機器証明書・端末の健全性）を加える。 同一セッションが別の地点・別の端末から使われたときに 失効させる設定を入れる**
  • **利用者が貼り付けたコマンドの実行は、 この手口の成立条件である。そこを塞ぐ**
    **攻撃は、標的自身が更新の案内を押す、スクリプトを走らせる、 文字列を貼り付けて実行することで成立する**（出典1。事実）〈重要〉。
    取るべき行動 **業務端末で、署名のない実行ファイルの起動と 利用者による管理者権限での実行を制限する。 スクリプト実行の記録を残し、 会議の時間帯に発生した実行を検知の対象にする**
  • **公開レジストリへの公開権限を、日常の作業端末から切り離す**
    **保守担当者の端末が侵害された結果、 その権限で悪性の依存関係が作られた**（出典1。事実）—— **FBI は npm のほか Rust のクレートの保守担当者に対する 試みも把握しているとしている**（出典1）。
    取るべき行動 **自分が保守している公開パッケージについて、 公開の操作に多要素認証（物理鍵）を必須にし、 可能なら別の承認者を要求する設定にする。 公開用の資格情報を日常の開発端末に置かない**
  • **公表された痕跡は例示の2件だけで、検知の主軸にならない**
    **FLASH が挙げた偽装ドメインは2件であり、 「事前に登録した多数のドメインのうちの例」とされている** （出典1。事実）〈重要〉。
    取るべき行動 **2件のドメインは記録と遡及調査に使い、 検知は挙動（会議サービス名に似た新規ドメインへの接続、 会議中の端末操作、セッションの地点の急変）で作る**
