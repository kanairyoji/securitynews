INC-2026-1060NetScaler ADC/Gateway に28件

Cloud Software Group が2026年11月12日、Citrix NetScaler ADC／NetScaler Gateway の メモリ関連脆弱性28件を一度に修正した——最高は Gateway・AAA 構成に対する CVSS v4.0 9.5（CVE-2026-107412）、そして CVE-2026-120868 は **既定構成のすべての導入が対象で、機能の有効化も認証も要らない**。 ベンダーが示した影響の表現は「予測不能な挙動とサービス拒否」までで、 悪用は確認されていないとされる

脆弱性初報のみ有名事象として記録（日本と直接の関係は薄い）設計・実装上の不備
初報: 2026年11月12日（Cloud Software Group のセキュリティ情報 CTX697305） 最終更新: 2026年11月13日

2026年11月12日、Cloud Software Group が Citrix NetScaler ADC（旧 Citrix ADC）とCitrix NetScaler Gateway のセキュリティ情報 CTX697305 を公開し、28件の脆弱性を一度に修正した（出典1）。深刻度はベンダー自身が「Critical」としている。

最高値は CVE-2026-107412 の CVSS v4.0 9.5 である（出典1）。Gateway（SSL VPN・ICA プロキシ・CVPN・RDP プロキシ）または AAA 仮想サーバーを構成している場合に該当し、複数のメモリオーバーフローが束ねられている。 CERT-EU は、この経路に認証は要らないとベンダーが述べていると記している（出典2）。

しかし実務上もっとも重いのは9.5ではなく、9.3の1件である（本記録の評価）〈重要〉。CVE-2026-120868 は、パケット処理におけるメモリオーバーフローで、前提条件が「なし」——既定構成を含むすべての導入が対象で、特定の機能の有効化も認証も要らない（出典1・2）。28件のうち27件は「この機能を使っていれば該当」という形だが、この1件だけは使い方に関係なく当たる。

ベンダーが示した影響の表現は「予測不能な挙動とサービス拒否」である（出典1・2）。CERT-EU は、10件が機密性・完全性・可用性のいずれにも高い影響と評点されている一方で、ベンダーの記述が予測不能な挙動とサービス拒否に留まることを指摘している（出典2）〈重要〉—— 評点と記述が噛み合っていない。 メモリオーバーフローの系統であり、コード実行に至るかどうかはベンダーの文面からは判断できない（本記録の読み）。

悪用は確認されていない。 CERT-EU は「Citrix は悪用を報告しておらず、公開された実証コードも確認されていない」と記している（出典2。原文英語を訳出）。修正は4系統の版で提供されている——14.1-73.57／13.1-64.39／14.1-73.58 FIPS／13.1-37.293（FIPS・NDcPP）。回避策は示されていない。

本記録が構造上の中心と見るのは2点である（本記録の判断）。①「構成していなければ関係ない」で終わらせられない1件がある—— 28件を機能別の該当判定で処理する運用は、前提条件が「なし」の1件を見落とす形になりやすい。②NetScaler は2026年に入って繰り返し修正を出しており、うち一部は実際に悪用されてきた（出典4。本記録の確認）—— 今回は悪用の確認が無い段階で28件がまとまって出た。適用の順序を決める余地があるのは、この段階だけである。

CWE の内訳を見ると、系統はメモリ破壊である（出典1。本記録の整理）。

  • CWE-120（境界検査のないバッファコピー）

メモリ破壊がコード実行に至るかどうかは、不備の性質と緩和策の有無に依存し、ベンダーの文面からは判断できない（本記録の読み）〈重要〉。「サービス拒否」と書かれているから機器が落ちるだけ、とは読めない。 一方で、コード実行が可能だという根拠も公開されていない〈未確定1〉。

本記録の立場はこうである（本記録の判断）。評点（9.5・9.3）を優先度の判断に使い、ベンダーの影響記述を上限として読まない。 CERT-EU が同じ理由で「強く推奨」としているのが、外部の読み方としてもっとも近い（出典2）。

なお、1件だけ系統が違う CVE-2026-111338（CWE-532・6.9）は、読み方が別である（本記録の整理）。認証に関わる機密情報がログファイル（/var/log/httperror.log）に書かれるというもので、前提はログアウトが発生した機器上でのローカル読み取り権限である（出典1）。評点は低いが、ログの持ち出し先（SIEM・ログ集約基盤）にその情報が流れている可能性を考える必要がある（本記録の読み）〈重要〉—— 機器の更新だけでは、すでに出てしまったログは消えない。
