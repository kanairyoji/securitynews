INC-2026-1068macOS 窃取型 DownTheDRAIN

2026年11月13日、SANS ISC の Brad Duncan が macOS 狙いの窃取型マルウェアに 「DownTheDRAIN」と名を付けた——偽 CAPTCHA で利用者自身に Terminal へ コマンドを貼らせる Macfinger ClickFix 作戦の負荷で、 **暗号資産の残高を全部でも一部でも攻撃者の財布へ移す DRAIN 機能を持つ。** 検体は macOS 26.7.3 に遮断されたが、**その前に4回の送信が出ている**

脅威・攻撃キャンペーン初報のみ有名事象として記録（日本と直接の関係は薄い）人を介した誘導（ビッシング・BEC）
初報: 2026年8月6日（Huntress による最初の解析公表） 最終更新: 2026年11月14日

2026年11月13日、SANS Internet Storm Center の Brad Duncan が、macOS を狙う窃取型マルウェアに「DownTheDRAIN infostealer」という通称を与えた（出典1）。名の由来は、Huntress が2026年8月6日に公開した解析が示した DRAIN 関数である（出典1・3）〈重要〉—— この関数は「各種の暗号資産の財布のアドレスを特定し、その中身を攻撃者が管理する財布へ向け直すことができる」（出典1 が出典3 から引用。原文英語を訳出）。

配送は Macfinger ClickFix 作戦である（出典1・2）。Duncan が2026年9月22日に最初に書いた作戦で、正規サイトに仕込まれたスクリプトが macOS 利用者に偽のボット確認画面を見せ、指示されたコマンドを Terminal に貼らせる（出典2）。「Macfinger」という名は、macOS 端末の指紋取りを行うことに由来する（出典2）。

本記録が構造上の中心と見たのは、2つの事実である（本記録の判断）。

①遮断されたが、送信は起きている。 Duncan の Mac mini（macOS 26.7.3）は検体を遮断してゴミ箱へ移した（出典1）〈重要〉—— ただし遮断までに hxxp[:]//171.22.131[.]24:8133/api/t へ4回の HTTP POST が出ている（出典1）。「OS が止めた」は「何も出ていない」ではない（本記録の評価）。

②C2 のポートとパスが3か月以上変わっていない。 8月の Huntress の検体（C2 は 138.124.118[.]69）、9月の作戦（95.163.153[.]80）、11月の検体（171.22.131[.]24）はいずれもポート 8133 で /api/t を使う（出典1・2・3。照合は本記録）〈重要〉—— IP は3回変わったが、ポートとパスは変わっていない。 検知の足場は IP ではなくそこにある（本記録の判断）。

Huntress は、DRAIN 機能が財布の残高の一部だけを抜けることを「残高の全部ではない額を抜ける malware を見たのは初めてだ」と記している（出典3。原文英語を訳出）〈重要〉—— DRAIN_PCT という変数で割合が決まる。

    **偽 CAPTCHA のドメインは毎回替わっている**（出典1・2・3）〈重要〉—— **quill-kraee-um2gf[.]pro（11月）、 velvet-otter-glagceis[.]life（9月）、 profitnow[.]io（8月の Huntress 事例）。** **いずれも機械的に生成した見た目の名前で、 既知悪性ドメインの一覧では追いつかない**（本記録の評価）。 **配送元は正規サイトへのスクリプト注入でもあり （出典2）、参照元で判定することもできない。**
    取るべき行動 **ウェブプロキシ・DNS 側で、 登録から日数の浅いドメインへの到達を警告または隔離する。** **判定できない場合、少なくとも 「新しい TLD（.pro・.life 等）＋ 初めて見るドメイン」への 到達を記録に残す。** **到達の直後に Terminal が起動した端末を優先して調べる。**
  • ブラウザのクッキー窃取に備えて、セッションの有効期間と 再認証の条件を見直す。
    **窃取対象にブラウザの資格情報とクッキーが含まれる**（出典3）〈重要〉。 **9月の観測では C2 に `/api/credentials` というパスがあり、 資格情報の送信先が分かれていた**（出典2。本記録の読み）。 **パスワードを変えても、持ち出されたセッションは生き残る** （本記録の評価）。
    取るべき行動 **業務アプリのセッションの有効期間を短くする対象を決める （まず管理コンソール・特権アカウントから）。** **IP・端末の変化で再認証を要求する条件を設定する。** **感染が疑われた端末について、 パスワードの変更とセッションの無効化を 両方行う手順にする（片方だけにしない）。**
