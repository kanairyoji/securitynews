広告のために流れているデータが、監視製品の在庫になっている。

2026年11月12日、Citizen Lab は、Bloomberg の調査報道がPenlink の広告ベース位置情報監視システム「Webloc」の顧客を新たに8か国で特定したと伝えました（出典1）。加わったのは英国・オランダ・ドイツ・メキシコ・シンガポール・サウジアラビア・アラブ首長国連邦・イスラエルです（出典1）。Citizen Lab 自身は2026年4月の報告（Report No.191）で米国・エルサルバドル・ハンガリーの顧客を特定しており、その後オーストリア内務省も顧客として確認されています（出典1・2）。

Webloc は、イスラエルの Cobwebs Technologies が開発し、現在は後継の Penlink が web インテリジェンス基盤「Tangles」の追加機能として販売しています（出典2）。データ源は2つです（出典2）。

  • RTB（リアルタイム入札）——広告枠の入札では、端末識別子・位置・IP・デバイス情報・推定属性が入札に参加しうる事業者へ一斉に配られます。監視事業者は、これをブローカーから買うか、自ら入札に参加して受け取ります。
  • SDK——アプリに組み込まれた第三者の部品が集めたデータを、ブローカーが販売します。

2021年の Webloc の資料では、扱う項目としてモバイル広告 ID・時刻・GPS と Wi-Fi による位置・IP アドレス・デバイス情報・年齢・性別・言語・使用アプリ・広告ターゲティングの区分が挙げられており、推定された自宅と職場の位置も含まれます（出典2）。機能としては、ジオフェンス検索、複数の地点に現れた端末の特定、アラート、ヒートマップ、Wi-Fi のネットワーク名を手掛かりにした端末 ID と人物の結び付けが挙げられています（出典2）。規模は、最大5億台の端末と最大3年分の履歴です（出典2）。

本記録がこの事案を「侵害ではない事案」として記録するのは、防御側の手の届く場所が通常の事案と違うからです（本記録の判断）〈重要〉。

侵入も脆弱性も関与していません。 アプリが広告のために正規の経路で流しているデータが、ブローカーを経て監視製品の在庫になっています。 したがって——

  • 対象となる端末の持ち主の側に「守りの失敗」はありません。 自分が対象かどうかを確かめる方法も示されていません〈未確定1〉。
  • 対象の組織（企業・官庁）が自社のネットワークやエンドポイントを固めても、この経路は塞がりません。 データは従業員の私物端末のアプリから、会社の統制の外で出ていきます（本記録の評価）。
  • 点検できるのは供給側だけです——自社が配っているアプリにどの SDK が入っていて、どの入札経路に何を流しているか。

Penlink は Citizen Lab の指摘を否定しています（出典2）〈齟齬3〉。報告は「もはや存在しない製品」を扱っているとし、「Penlink は米国の州プライバシー法を遵守している」、データ提供者は「病院・学校・宗教施設のような機微な場所を除外している」、「SDK を通じて位置情報の共有について利用者の同意を得た提供者から位置データを取得している」と述べました（出典2・原文英語。本記録が訳した）。Citizen Lab は、Webloc とそのデータ源がプライバシー法に適合していることをどう担保しているかという質問には答えがなく、欧州法を含む米国外の法についての言及も無かったと記しています（出典2）。

日本については、機関が顧客として挙げられたことはなく、特定されたサーバ所在地（約24か国）にも日本は含まれていません（出典1・2。本記録の確認）〈未確定5〉。ただしデータ源は世界規模の広告取引であり、日本のアプリ提供者が参加している経路と技術的には同じ仕組みです（本記録の評価。公表された事実ではありません）。

事案の詳細

影響を受けたサービス**Penlink の web インテリジェンス基盤「Tangles」の追加機能としての 「Webloc」**（出典2）。 **Webloc 単体で売られているのではなく、Tangles の plug-in である** （出典3）—— **したがって調達記録には「Tangles」として現れ、 Webloc の有無は記録から読み取れないことがある** （出典2。本記録の整理）〈重要〉。
緩和策
数え方: **利用者側**——**iOS では、アプリのインストール時に 他社のアプリ・サイトをまたぐ追跡の許可を拒否し、 過去に与えた追跡の許可と、位置情報その他のデータアクセスの許可を 見直す。iOS 14.5 より前のバージョンでは追跡の制御が使えない** （出典2）。 **Android では、設定で広告 ID を削除するか 広告のパーソナライズを無効にする（手順は端末と OS のバージョンで異なる）。 あわせてアプリの位置情報とデータの許可を見直す**（出典2）。　副作用: **Citizen Lab は、これらの手順が 「データ共有を減らすが、確実に防ぐわけではない」と明記している** （出典2）〈重要〉—— **アプリは別の識別子を使うことができ、 自ら処理したデータを第三者へ送ることもできる。** **したがって、これを「対策済み」として扱うと誤る**（本記録の評価）。 **また、広告 ID の無効化は無料アプリの収益モデルを弱めるため、 組織として全端末に強制する場合は、 業務アプリの動作確認が必要になる**（本記録の判断）。
数え方: **供給側（アプリを配る組織）**——**自社アプリに組み込んでいる 第三者 SDK を棚卸しし、送信先と送信項目を実測する。 位置情報の取得粒度を業務上必要な範囲まで落とす。 データ提供先の再販の可否を契約条件に入れる** （本記録の提案。出典2 の指摘に基づく）。　副作用: **広告 SDK の制限は広告収益を下げる**（本記録の明示）。 **また、送信項目の実測には通信の復号が必要で、 SDK の規約がこれを禁じている場合がある**（本記録の判断）—— **その場合は、SDK の採用判断そのものを見直す材料になる。**
数え方: **調達側（監視・分析ツールを買う組織）**——**Citizen Lab は 「政府はベンダーについて厳格なデューディリジェンスを 行わなければならない」とし、 能力の分析、供給網全体でのデータ処理、悪用の可能性、 およびベンダーのより広い事業慣行の分析を挙げる** （出典2・原文英語。本記録が訳した）。　副作用: **審査を厳しくすれば調達は遅くなる**（本記録の明示）。 **また、供給網の開示を要求すると、 ベンダーが営業秘密を理由に応じないことがあり、 その場合は「開示しないベンダーを選ばない」という判断が要る** （本記録の判断）。
legal_status**Citizen Lab は「欧州と英国でこれらのシステムを使うことの 合法性は極めて議論がある」と記し、 欧州各国のデータ保護当局が 「欧州のデータ主体の権利と自由の潜在的な侵害を 能動的に調査する必要がある」と主張している** （出典1・2・原文英語。本記録が訳した）。 **本記録の作成時点で、いずれかの当局が Webloc について 調査を開始したという公表は確認していない**（本記録の確認）〈未確定6〉。 **Penlink は「米国の州プライバシー法を遵守している」と述べたが、 欧州法については言及しなかった**（出典2）〈齟齬3〉。
