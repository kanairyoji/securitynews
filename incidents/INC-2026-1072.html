**以下は FLASH の TTP 表（出典1）を段階別に整理したものである** （本記録の整理）〈重要〉—— **FLASH 自身が「挙動は campaign ごとに異なり、 単一の固定した定石として扱うべきではない」という趣旨の注意を 付けている（Talos も同旨を明記している）**（出典1・2）。 **したがってこの連鎖は「ある1件の侵入の経路」ではなく、 複数の campaign で観測された手口の集合である。** **ATT&CK の技術IDは FLASH が自ら付したものをそのまま引く** （本記録の方針）——**本記録が独自に写し取ることはしない。**

  1. 1. 偵察確認済[1]
    **Azure の資格情報（SAS トークン・サービスプリンシパル・Kudu の資格情報・ ストレージアカウントキー）の実効権限を、秒未満の能力確認・ 試験的な blob 書き込みと削除・ARM デプロイの検証用 dry-run によって 自動で把握する**（出典1）。 **侵害した IAM ユーザの権限は DryRun フラグで試す。** **Web のディレクトリを500件超の要求で総当たりし、 WHOIS で資産を地図化し、脆弱性走査をかける。** **被害者の地理的位置を調べるため api.db-ip[.]com に問い合わせる。**

CISO・経営層への示唆
  • 対策の一覧は変わらない。変わったのは締め切りである。 「ARTEX 対策」という新しい予算項目を立てる前に、 既存の未完了項目の期限を見直す。
    **FLASH の TTP 表に並ぶ弱点は、未署名の SAML アサーションから SQL インジェクションまで、すべて既知のものである**（出典1）。 **未知の脆弱性の悪用は記されていない**（本記録の確認）。 **一方で FBI は「初期の標的選定から特権アクセスまで3時間未満」 の例を挙げ、Dosu の事案では90分で80,000件超の要求が 生成されている**（出典1・2）。
    取るべき行動 **未完了の是正項目（公開面の脆弱性・資格情報の棚卸し・ EDR 未導入機）の一覧を出し、 それぞれに「3時間で特権に到達される前提で許容できるか」を 1行で記入させる。** **許容できないものだけを前倒しし、 残りは期限を据え置く——全部を前倒しにすると何も動かない。**
  • 封じ込めを自動で始める検知を、平時に決めて承認しておく。 事案発生後に「誰が止めるか」を相談する手順は間に合わない。
    **FBI は「ARTEX は法科学的に騒がしい通信を大量に生成するため 警報が鳴ることはあるが、攻撃の速度のために、 防御側が協調して対応する時間はほとんど残らない」と記した** （出典1・原文英語。本記録が訳した）〈重要〉。 **Elastic も「封じ込めを開始させる検知は、 事案が始まる前に選んでおかなければならない」と書いている** （出典4・原文英語。本記録が訳した）。
    取るべき行動 **「この検知が出たら、人の承認を待たずに 該当の資格情報を無効化する／該当端末を網から切る」という規則を 3〜5個に絞って作り、経営の承認を事前に取る。** **併せて、誤遮断が起きたときの業務復帰手順と、 その所要時間を数字で押さえておく。**
  • 攻撃面の棚卸しを「旗艦システム」ではなく「周辺システム」から始める。 FBI が名指ししたのは後者である。
    **FLASH は ARTEX の特徴として 「旗艦アプリよりも注意の薄い周辺システムを見つけて突くことに 長けている」と記し、取引先・供給元ポータル、 モバイルのバックエンド、従業員向けアプリ、営業支援システム、 旧システム、第三者連携、事業部ごとに作られたアプリを 列挙した**（出典1・原文英語。本記録が訳した）。 **「直ちに行う行動」の先頭もこの棚卸しである。**
    取るべき行動 **情報システム部門が把握していない公開アプリを洗い出す工程を 1回入れる（外部からの走査と、事業部への照会の両方で）。** **出てきたものに所有者を割り当て、 所有者が決まらないものは停止の判断に上げる。** **この作業は事業部との交渉を伴うため、経営の後ろ盾が要る。**
  • 取引先・供給元の侵害が自社に及ぶ経路を、契約ではなく権限で確認する。
    **FLASH の初期侵入には「外部の取引先テナントからの クラウド間信頼関係の悪用」「第三者ベンダーの資格情報を使った 信頼済み B2B 連携経由の侵入」が並ぶ**（出典1）。 **ConnectWise 経由の事案では、2,250を超える下流テナントへの アクセスが可能になった**（出典1）。 **FBI は「自律的なエージェントは組織間の信頼関係を 体系的に地図化できる」と記した** （出典1・原文英語。本記録が訳した）。
    取るべき行動 **自社テナントに対して外部から信頼が設定されている関係 （クロスアカウントのロール・B2B 連携・OAuth アプリの権限）を 一覧にし、「相手が侵害されたとき、自社側で何ができるか」を 権限の粒度で記入する。** **契約書の免責条項では答えが出ない。**
セキュリティ技術者への示唆
  • EDR の導入率ではなく「未導入機の一覧」を持つ。 攻撃側はその一覧を機械的に作っている。
    **FLASH の権限昇格の行に 「端末センサーの導入状況を棚卸しして、 CrowdStrike Falcon が入っていない Windows 機を特定する」が 記録されている**（出典1）〈重要〉。 **網の穴を探す作業が、攻撃の工程に組み込まれている。**
    取るべき行動 **資産台帳と EDR の管理コンソールを突き合わせ、 未導入機の一覧を毎週生成する。** **業務上導入できない機器には、網の分離か 到達範囲の制限を代替として割り当て、一覧に併記する。**
  • クラウドの監査ログで「権限確認の連打」を時間密度で見る規則を置く。 単体の API 呼び出しはどれも正常である。
    **FLASH の偵察の行は、Azure の資格情報の実効権限を 「秒未満の能力確認・試験的な blob 書き込みと削除・ ARM デプロイの検証用 dry-run」で自動把握する挙動を記している** （出典1）。 **FBI が報告を求める項目にも 「秒未満のタイミングでの試験的な blob 書き込みと削除」 「複数のリソース種別に跨る ARM デプロイの検証用 dry-run」が 挙がっている**（出典1）。
    取るべき行動 **GetCallerIdentity 相当の呼び出し、DryRun 付きの呼び出し、 検証用デプロイについて、 「同一の資格情報から n 秒以内に m 回」を条件にした検知を作る。** **閾値は、自組織の平常時の頻度を1週間測ってから決める。**
  • IoC は遡っての狩猟に使い、遮断の主軸にしない。 住宅用プロキシと IP の再割り当てで効かなくなる。
    **FBI は IoC 表の前書きで 「クラウドや仮想化基盤では IP が動的・一時的に割り当てられるため、 ある時点で悪性だったアドレスが後に正当なサービスへ 再割り当てされることがある」と注意し、 「活動期間中に歴史的に観測された基盤として解釈し、 現在のテレメトリで裏付けるべきである」と記した** （出典1・原文英語。本記録が訳した）。 **C2 の行には住宅用プロキシ・Tor・SOCKS・侵害した中継が並ぶ** （出典1）。
    取るべき行動 **FLASH の IP を遮断リストに直接入れる前に、 過去90日のログに対する検索をかける。** **遮断は、自組織で当たりが出たものに限る。** **恒常的な検知は、挙動側（連番の列挙・構造化データの外部転送・ 想定外のパスの Web シェル・想定外の LLM API 端点への送信）に置く。**
  • SPA の JavaScript バンドルとモバイルアプリに資格情報が 入っていないかを、リリース前の工程で機械的に検査する。
    **FLASH の初期侵入に 「SPA の JavaScript バンドルに埋め込まれた管理者パスワード」が 挙がっている**（出典1）。 **これは走査と文字列検索で機械的に見つかる種類の弱点であり、 エージェントが最も得意とする部分である**（本記録の評価）。
    取るべき行動 **CI に秘密情報の検査を入れ、 配布物（バンドル後の成果物）に対して実行する。** **ソースだけを検査すると、ビルド時に埋め込まれる値を見落とす。**
  • LLM の API 端点への外向き通信を、分類して記録できる状態にしておく。
    **FBI は挙動指標として 「api.anthropic.com・api.deepseek.com・open.bigmodel.cn・api.x.ai への 想定外の呼び出し（他の不審な活動と併せて調べること）」を挙げ、 報告を求める項目にも 「自前の LLM 中継・再販ソフト（CLIProxyAPI・New API）の痕跡」 「トークン消費や API 課金の異常」を含めた**（出典1）〈重要〉。
    取るべき行動 **出口の通信記録で LLM の API 端点を分類できるようにし、 自組織が正規に使っている端点の一覧を先に確定させる。** **一覧に無い端点への送信を調査の対象にする。** **なお FLASH 自身が「他の不審な活動と併せて」と条件を 付けている通り、これ単体では警報にしない。**

観点自社に当てはまるか該当する場合に何が起きうるか
