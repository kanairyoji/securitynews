認証APIのSQLインジェクションが未認証で任意のファイルの読み書きに届く原因・手口

クリティカルの中身を、公表されている範囲で正確に置く（出典1・3）。

CVE-2026-76954
- コンポーネント: DSM の Auth API（認証API）
- CWE: CWE-89（SQL コマンドで使われる特殊要素の不適切な無効化）
- CVSS v3.1: 9.8（Critical）
- ベクタ: CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H
- 影響（訳。原文英語を引用）: 「リモートの攻撃者が任意のファイルを読み書きし、サービス拒否攻撃を行うことを許す」

ベクタから読めることを分解する（本記録の整理）。

  • AV:N —— ネットワークから到達する
  • AC:L —— 攻撃条件の複雑さが低い（特別な条件を揃える必要がない）
  • PR:N —— 権限不要。認証を通す必要がない
  • UI:N —— 利用者の操作不要。誰かが何かを押す必要がない
  • C:H / I:H / A:H —— 機密性・完全性・可用性のすべてに高い影響

要点は、不備がある場所が「認証を行う API」であることである（本記録の評価）〈重要〉。認証の前段で成立するため、認証を固めても効かない。パスワードを長くしても、二要素認証を入れても、認証処理に到達した時点で成立する不備は防げない。

そしてこれは NAS である（本記録の評価）。「任意のファイルの読み書き」が意味するのは、そこに置いてある業務データ・バックアップ・共有ファイルそのものに届くことである。一般的なサーバの脆弱性と違い、NAS の場合は「侵入の足場」と「目的の資産」が同じ箱にある。

緩和策は「None」と明記されている（出典1）〈重要〉。設定変更で回避する手段は提供されておらず、更新が唯一の対策である。

もう1件、CVE-2026-85101 も未認証である。
- コンポーネント: DSM の rsync
- CWE: CWE-288（代替経路または代替チャネルを用いた認証回避）
- CVSS v3.1: 8.6（Synology の評定は「Important」）
- ベクタ: CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:L/I:H/A:L
- 影響（訳。原文英語を引用）: 「リモートの攻撃者が特定のファイルを読み、任意のファイルを書き込み、限定的なサービス拒否攻撃を行うことを許す」

読める範囲は限定的（C:L）だが、書き込みは「任意のファイル」で完全性への影響は High（I:H）である（出典1）〈重要〉。CWE-288 は「本来の認証を通らずに同じ機能へ到達できる別の入口があった」型である（本記録の整理。CWE の定義による）。rsync は Hyper Backup・Snapshot Replication などで使われるため、業務で有効にしている組織は少なくないとみられる（本記録の推定）—— ただし rsync の有効化が前提となるかは公表されていない〈未確定7〉。

2本を並べると、分け方に規則性がある（本記録の照合）〈重要〉。

Synology-SA-26:19（2件）: 両件とも PR:N（認証不要）。

Synology-SA-26:18（25件）: 大半が認証を前提とする（出典2）。アドバイザリ自身が、必要な到達条件で項目をまとめている——「リモートの未認証の攻撃者」「リモートの認証済み利用者」「リモートの認証済み管理者」。最高値の3件（CVSS 8.8）はいずれも認証済み利用者が前提である（CVE-2026-13672 / SSOAuth、CVE-2026-18792 / Sharing API、CVE-2026-74857 / Auth API）。未認証で到達するものは、本記録が数えた限り4件にとどまり、いずれも CVSS 7.5 以下である（CVE-2026-15198 / Webdav API 6.5、CVE-2026-18633 / nfsd 7.5、CVE-2026-124993 / Security Advisor 5.3、CVE-2026-85098 / synoscgi 5.3）。

この分け方には実務上の意味がある（本記録の評価）。「認証不要」と「認証必要」は、対応の緊急度が別物である。
- 認証不要: 機器がネットワークから到達できる限り、攻撃者は何も持たずに試せる。到達性がそのままリスクになる。
- 認証必要: 攻撃者はまず資格情報を得る必要がある。侵害の2段目として効くが、1段目の入口ではない。

本件で急ぐべきは SA-26:19 の2件である。 ところが件数では25対2で SA-26:18 が圧倒的に多い（本記録の明示）〈重要〉—— 件数の多い側が重要とは限らない。 27件という合計値は、この区別を消してしまう。

紛らわしい点を1つ明示する（本記録の注意）。SA-26:18 にも SQL インジェクション（CWE-89）が1件ある ——CVE-2026-81584、User API、CVSS 8.1。ただしこちらは「侵害された LDAP または Active Directory サーバの制御」が必要とされており（出典2）、クリティカルの CVE-2026-76954 とは別物である。 「DSM の SQL インジェクション」で検索すると2件出てくるため、対応の際は CVE 番号で突き合わせる必要がある（本記録の推奨）。
