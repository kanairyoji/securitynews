課題を立てられる者が、CI のトークンに手を伸ばせる状態だった原因・手口

本件の中心は、入口の素朴さにあります（本記録の評価）〈重要〉。

issue-labeler.yml は、新しい課題の題名と本文をエージェントのプロンプトへ渡していました（出典1）。allow-users: "*" が付いていたため、課題を立てられる者であれば誰でもエージェントへの指示に介入できました（出典1）。リポジトリへの書き込み権も、資格情報も要りません（出典1・3）。

ここで効かなかった対策を2つ挙げます（本記録の整理）。

1つは、サンドボックスです（出典1）〈重要〉。Codex の workspace-write サンドボックスは外部通信・プロセスのデバッグ・大半のファイル系を制限していました（出典1）—— それでも、ランナーが /tmp に露出していた.NET/CoreCLR のデバッグ用インタフェース経由でランナー作業プロセスのメモリを読めました（出典1・3）。

もう1つは、秘密を環境変数から落とすという作りです（出典1）〈重要〉。サンドボックスは環境変数を落としていましたが、秘密は親プロセスのメモリに残っていました（出典1）—— 得られたのは ACTIONS_RUNTIME_TOKEN と GITHUB_TOKEN です（出典1）。

つまり本件は、「AI の挙動を縛る」対策（サンドボックス）と「秘密の置き場所を変える」対策の両方をすり抜けています（本記録の読み）〈重要〉—— 残っていた前提は「同じホストの上に強い権限がある」ことでした。

キャッシュを汚染して、特権ワークフローの中で動く原因・手口

トークンを得たあとの段は、CI の内側の横移動です（出典1）。

ACTIONS_RUNTIME_TOKEN は、OpenAI の環境の外からでもリポジトリの Actions キャッシュへの書き込みに使えます（出典1）〈重要〉。研究者は、ジョブの途中でキャッシュを復元し、かつ広い権限を持つワークフローとして rust-ci.yml を名指ししています（出典1）。

キャッシュは「速くするための仕組み」であって「信頼境界」として設計されていません（本記録の評価）〈重要〉—— 権限の低いジョブと高いジョブが同じキャッシュを共有していれば、そこが権限昇格の経路になります。

最終段は「人が release を削除すること」に依存していた被害規模・影響範囲

CISO・経営層への示唆
  • **AI エージェントを CI に入れることは、「CI の資格情報を外部入力に晒す」ことだと理解する。**
    **本件の入口は、誰でも立てられる GitHub の課題だった**（出典1・3）〈重要〉—— **到達点は CI のトークンと、公開パイプラインの権限である**（出典1・2）。 **エージェントの導入は「開発の自動化」として決裁されるが、 実際には信頼境界の引き直しである**（本記録の評価）。
    取るべき行動 **①社内のリポジトリで、外部入力（課題・コメント・PR の本文）を エージェントのプロンプトへ渡しているワークフローを棚卸しする。 ②そのワークフローが触れる秘密と権限を一覧にする。 ③「エージェントを使う決定」を、CI の権限設計の変更として承認手続きに載せる。**
  • **自動更新される開発者向けツールを、サーバの依存物と同じ台帳で管理する。**
    **研究者が強調しているのは、エージェント型の道具が 開発者の資格情報を持ったまま動き、設計上コードを実行する点である**（出典1）〈重要〉—— **`@openai/codex` のダウンロードは直近1週で 26,440,004 回である** （出典6。本記録の確認）。 **「開発者が各自で入れる道具」は資産台帳から落ちやすい**（本記録の評価）。
    取るべき行動 **①開発端末に入っている AI コーディング道具とその版を把握する。 ②自動更新の可否を方針として決め、新しい版の採用に短い待機期間を置くかを判断する （修正版の適用も遅れるという副作用を併せて決める）。 ③道具が持つ資格情報（クラウド・リポジトリ・レジストリ）の範囲を棚卸しする。**
  • **公開（publish）の権限は、CI の中で最後まで人の関門を残す。**
    **本件の最終段は「保守担当者に偽の release を削除させ、 それを契機に npm が信頼する身元トークンを発行させる」経路だった**（出典1・3）〈重要〉—— **善意の片付けが引き金になりうる構造である**（本記録の評価）。
    取るべき行動 **①レジストリへの公開を起動するイベントを洗い出し、 削除・訂正のような副作用から切り離す。 ②公開前の人の承認を、形式ではなく「何が公開されるか」を見る段として作る。 ③自社が配布する成果物に出所証明（provenance）を付け、利用者が検証できる状態にする。**
  • **報奨金制度の評価額を、脆弱性の重大さの指標として読まない。**
    **本件は P1 で、初回の報奨は 1,000 米ドルだった**（出典1・2）〈重要〉—— **OpenAI の制度は重大な発見に最大 100,000 米ドルを掲げており、 研究者は「報告はまだ検討中」と書いている**（出典1）〈未確定3〉。 **支払額は制度・時点・交渉の結果であり、技術的な影響の大きさとは別である** （本記録の評価）。
    取るべき行動 **①外部からの報告を受ける窓口を持つ場合、 評価額ではなく「何が起きうるか」を社内の判断材料にする。 ②自社製品について外部研究者の公表を監視し、 報奨金の記録だけで重大性を判断しない。**
セキュリティ技術者への示唆
  • **利用者が書ける文字列をエージェントのプロンプトへ連結している箇所を、全部洗い出す。**
    **`issue-labeler.yml` は課題の題名と本文をプロンプトに渡し、 `allow-users: "*"` を指定していた**（出典1）〈重要〉—— **プロンプト注入は入力の検証では止まらない**（本記録の読み）。
    取るべき行動 **①`.github/workflows/` を `github.event.issue`・`github.event.comment`・ `pull_request_target` で検索し、 それらの値がエージェントやシェルへ渡る経路を特定する。 ②分類・ラベル付けのような定型処理は、エージェントではなく固定のスクリプトに置き換える （現行の `issue-labeler.yml` がこの形である。出典4）。 ③どうしてもエージェントを使う場合は、対象を組織の構成員が立てた課題に限る。**
  • **エージェントを走らせるジョブに、CI のトークンを同居させない。**
    **サンドボックスは環境変数を落としていたが、 ランナー作業プロセスのメモリに `ACTIONS_RUNTIME_TOKEN` と `GITHUB_TOKEN` が残っていた**（出典1・3）〈重要〉—— **`/tmp` の .NET/CoreCLR のデバッグ用インタフェース経由で読まれている**（出典1）。 **「秘密を環境変数から外す」対策では止まらない**（本記録の読み）。

  • **Actions のキャッシュを、信頼境界として扱わない。**
    **窃取したトークンでキャッシュを汚染し、 ジョブの途中でキャッシュを復元する特権ワークフロー（`rust-ci.yml`）へ 実行を移す経路が示されている**（出典1・2）〈重要〉—— **キャッシュは速度のための仕組みであり、完全性の保証を持たない**（本記録の読み）。
    取るべき行動 **①特権を持つジョブでのキャッシュ復元をやめるか、 復元した実行可能物をハッシュで検証する。 ②キャッシュのキーを、権限の高いジョブと低いジョブで分離する。 ③ツールの導入をキャッシュ任せにせず、固定した版と検証可能な配布元から取る。**
  • **ワークフローのログ・成果物・キャッシュを「持ち出しの道」として数える。**
    **サンドボックスに外部通信が無くても、 トークンはワークフロー自身のログ経由で持ち出された**（出典1）〈重要〉—— **短い行は削られるため分割したという記述は、 ログの伏字処理が部分的にしか効かないことを示す**（出典1）。
    取るべき行動 **①公開リポジトリの Actions ログを秘密の検出器にかけ、 検出したら該当トークンを失効させる手順を用意する。 ②伏字処理を最後の砦にしない（秘密を出し得るジョブのログ公開範囲を絞る）。 ③成果物・ジョブの出力・キャッシュについても、同じ観点で経路を数える。**
  • **`.github/` 配下の変更を、通常の差分レビューに埋もれさせない。**
    **連鎖の永続化の段は、`id-token: write` を持つ裏口のワークフローの設置である** （出典2）〈重要〉—— **ワークフロー定義の変更は差分として見える唯一の段である**（本記録の評価）。
    取るべき行動 **①`.github/workflows/` の変更に必須レビューを設定し、 変更を独立した通知として流す。 ②ワークフローから呼ぶ外部アクションをコミットハッシュで固定する （現行の `issue-labeler.yml` は `actions/checkout` をハッシュで固定している。出典4）。 ③`id-token: write` を持つジョブを棚卸しし、必要な箇所だけに限る。**
