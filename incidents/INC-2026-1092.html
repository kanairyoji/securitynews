「git status は状態を見るだけの安全なコマンド」という前提が、この事案で崩れました原因・手口出典 [1] [2]

仕掛けの核心は、Git の clean フィルタです（出典1）。 .git/config に [filter "ltr"] clean = .git/ltr を書き、 .git/info/attributes で全ファイルにそのフィルタを割り当てると、 Git が作業ファイルの内容を内部表現へ変換するときに .git/ltr が起動します（出典1・2）。 著者は、安全なテスト用リポジトリでフィルタを 「呼ばれた事実をログに書くだけ」のスクリプトに差し替えて確かめ、 git status が実際にフィルタを呼んだと報告しています（出典1）。

ここには1つ留保が必要です（本記録の明示）〈重要〉〈齟齬1〉—— Git の公式文書は、フィルタが走る場面として 「チェックイン時」（git add・git commit）と 「チェックアウト時」を挙げており、 git status については何も書いていません （出典2。本記録の確認・2026年11月15日）。 本記録は再現検証を行っていません。 したがってこの記録は「著者の検証結果としてそう報告されている」 という形で保持します。
