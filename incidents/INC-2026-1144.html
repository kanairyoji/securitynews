攻撃の経過

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

**経路は、サーバの悪用または偽 PDF で足場を取り、 HTTP/3 の RAT で居座り、認証情報を集めて ドメイン管理者権限からログオンスクリプトで面に広げ、 文書とメールを持ち出す流れである**（出典1。本記録の整理）〈重要〉。 **侵入の主経路は未修正の Microsoft Exchange サーバと Web サーバで、 ウェブシェル（ASPXSpy・Godzilla・Bysunue.aspx・Suo5 の変種）が 置かれた**（出典1）—— **従の経路は、政府の公式サイトを装った領域から PDF のアイコンを付けた実行ファイルを踏ませる誘導である**（出典1）。 **実行の形は3つ観測されている**（出典1）〈重要〉—— **①DLL の横読み（正規の実行ファイルを改造して XOR 暗号化したシェルコードを埋め込み、 付属の悪性 DLL が読み出して復号し記憶上で実行する）、 ②囮のインストーラ（正規の GlobalProtect の設定画面を見せながら 裏で RAT を書き出して実行）、 ③フィッシング（囮 PDF を表示しつつ裏で動く）。** **横展開の主な手口は、侵害したドメイン制御装置に 悪性のログオンスクリプトを仕込むことである**（出典1）〈重要〉—— **正規の利用者がドメインに認証するたびに、 その端末で KUKURAT の取得と実行が起きる。** **最終目的は情報収集で、国際関係と国内政治に関わる 文書の持ち出しと、Exchange の代理権限の悪用による 全メールボックスへのアクセス取得が観測された**（出典1）。

    **インターネットに面した未修正の Microsoft Exchange サーバと Web サーバを悪用し、ウェブシェルを設置する**（出典1）〈重要〉—— **使われたのは自作と公開物の混成で、 ASPXSpy・Godzilla・Bysunue.aspx・Suo5 の変種が観測された**（出典1）—— **この道具立ては同集団の過去の活動と一致する**（出典1）。 **従の経路として、政府の公式サイトを装った領域から PDF のアイコンを付けた実行ファイルを配り、 開くと囮の PDF を表示しながら裏でマルウェアが動く**（出典1）—— **囮の一つはミャンマー連合選挙管理委員会の2025年の公式文書を 装っていた**（出典1）。
    根拠: Unit 42 報告の「exploitation of vulnerable, unpatched Microsoft Exchange servers and web servers to deploy web shells」の記述、およびウェブシェルから PerfectPioneer RAT を実行する図1（出典1）
  2. 2. 実行third_party_research[1]
    **PerfectPioneer RAT は、ディスクへの書き出しに加えて 3つの方法で実行された**（出典1）〈重要〉—— **①DLL の横読み：攻撃者は正規の良性の実行ファイルを 構造的に改造して XOR 暗号化したシェルコード（RAT 本体を含む）を 埋め込み、付属の悪性ローダ DLL が 改造された実行ファイルから読み出して復号・実行し、 シェルコードが記憶上に本体を展開する**（出典1）—— **②囮のインストーラ：正規の設定画面を見せながら 背後で RAT を書き出して実行する。 一例では正規の GlobalProtect のインストーラを 実際に書き出して実行し、覆いとして使っていた**（出典1）—— **③フィッシング：PDF のアイコンを付けた実行ファイル。**
    根拠: Unit 42 報告の「Loaders and Execution」節（DLL side-loading／decoy installers／phishing の3方法）（出典1）
  3. 3. C2通信third_party_research[1]
    **PerfectPioneer RAT と KUKURAT はいずれも HTTP/3 を C2 通信の主経路として使い、接続に失敗すると 自動で HTTP/2 へ退避する**（出典1）〈重要〉—— **HTTP/3 は UDP 上の QUIC で動くため、 企業の防御は下位の接続を壊さずに受動的な TLS 傍受を行えない** （出典1）—— **一部の企業用防火壁と従来の IDS/IPS は UDP を TCP と同じ厳しさで検査するよう更新されておらず、 外向きの UDP 443 番がしばしば深層パケット検査を迂回する**（出典1）。 **KUKURAT は起動時に /register へ接続して ホスト名・利用者名と完全性レベル・OS と機種・IP アドレス・ 実行時に生成した個体 ID を送り、 C2 から初期設定（擬装の入切と各種時間切れ）を受け取る**（出典1）—— **以後は /heartbeat で生存を知らせつつ待機中の命令を引く**（出典1）。
    根拠: Unit 42 報告の「HTTP/3 Adoption」節および KUKURAT の /register・/heartbeat の記述と既定設定 JSON（出典1）
  4. 4. 検知回避third_party_research[1]
    **PerfectPioneer RAT の2変種（Pioneer・rat_http3_cc）は、 C2 からの命令を実行する前に isDangerousCommand で 固定の拒否一覧と照合し、一致すれば命令を完全に阻止する**（出典1）〈重要〉—— **一覧には、実行すればきわめて破壊的あるいは痕跡が多く、 セキュリティ製品に監視されうる管理命令が含まれる**（出典1）—— **拒否一覧には Windows と Linux 双方の文法が混在していた**（出典1）。 **KUKURAT は擬装エンジンで、通信・レジストリ・ファイルの 3方向に偽の活動を生成する**（出典1）〈重要〉—— **C2 命令 set_obfuscation で各方向を個別に入切できる。** **また見張り役の実行ファイルと対で動き、 名前付きパイプ WINDOW_SEC_WATCHDOG 経由で3秒ごとに 自分の経路を書き、15秒無応答なら見張り役が再起動する**（出典1）—— **その見張り役が C:\ProgramData\Cyvera\Ransomware\ という 歴史的に Cortex XDR に関連づけられた経路に置かれた例がある**（出典1）。
    根拠: Unit 42 報告の「The isDangerousCommand Foolproof Mechanism」「Spoofing Endpoint Activity: Heuristic Camouflage Engine」「The Watchdog Component」各節（出典1）
  5. 5. 認証情報アクセスthird_party_research[1]
    **攻撃者は LSASS のメモリ取得と ディレクトリ複製（DCSync）で認証情報を集めた**（出典1）〈重要〉—— **LSASS は環境常備の手口で、正規の comsvcs.dll を悪用する—— MiniDump 関数を名前ではなく序数（#+000024）で呼び出し、 MiniDump という文字列を探す検知を回避する**（出典1）。 **DCSync では、ドメイン制御装置の振る舞いを模して 利用者の資格情報の複製を要求し、 パスワードのハッシュを直接取り出した**（出典1）。 **併せて Mimikatz・ProcDump・SharpDPAPI（DPAPI の復号）と、 SAM・SYSTEM レジストリハイブの手動取得が使われた**（出典1）。
    根拠: Unit 42 報告の「Credential Stealing Techniques」節に示された comsvcs.dll の実行コマンド行と DCSync の記述（出典1）
  6. 6. 横展開third_party_research[1]
    **最も特徴的な横展開は、ドメインのログオンスクリプトの改変である** （出典1）〈重要〉—— **ドメイン制御装置を侵害した後、悪性のログオンスクリプトを設置し、 正規の利用者がドメインに認証するたびに その端末で KUKURAT の取得と実行が走るようにした**（出典1）—— **併せて PsExec・WMI・WinRM が使われた**（出典1）—— **KUKURAT 自身も、外部モジュールとして PsExecService.exe を投入し、 PsExec という名前のローカルサービスと 名前付きパイプ \\.\pipe\PSEXEC を作って遠隔実行を担わせた**（出典1）。
    根拠: Unit 42 報告の「Lateral Movement via Domain Log-on Scripts」節と Cortex XDR の図5・図6（出典1）
  7. 7. 持ち出しthird_party_research[1]
    **攻撃者は大量の文書を C2 基盤へ持ち出そうとした**（出典1）〈重要〉—— **対象は主に .pdf・.docx・.xlsx・.png で、 ファイル名からは国際関係と国内政治への顕著な関心がうかがえた**（出典1）。 **文書に加えてメール基盤も標的になった**（出典1）〈重要〉—— **侵害した Exchange サーバの足場から PowerShell を実行し、 まず ApplicationImpersonation 役割の割り当てを確認して （この役割があれば個別のパスワードなしに 任意の利用者のメールボックスへ到達できる）、 無ければ管理権限で全メールボックスを巡回し、 掌握済みの口座に FullAccess を与える命令を実行した**（出典1）。

C2 を UDP に移しただけで、多くの環境の検査は空振りになる原因・手口出典 [1]

本件で最も実務に効く指摘は、マルウェアの精巧さではなく通信の層にある（出典1）。

PerfectPioneer RAT と KUKURAT はいずれも、C2 通信に HTTP/3 を主経路として使い、接続に失敗したときだけ HTTP/2 へ退避する（出典1）。HTTP/3 は UDP 上の QUIC で動く。Unit 42 の説明はこうである（出典1。原文英語）。

  • UDP を使うため、企業の防御は下位の接続を壊さずに受動的な TLS 傍受を行えない
  • 一部の企業用防火壁と従来の IDS/IPS は、UDP の通信をTCP と同じ厳しさで検査するよう更新されていない
  • 旧来の方針が TCP ベースの Web 経路だけに最適化されている場合、外向きの UDP 443 番は深層パケット検査をまるごと迂回する

つまり問題は「見えない通信」ではなく、許可されているのに検査されていない通信である（本記録の評価）。外向き UDP 443 を許可している環境は多い。そこに検査が入っていなければ、攻撃者は暗号を破る必要も、新しい経路を掘る必要もない。

Unit 42 の対策は率直である——QUIC を記録して検査するか、外向き UDP 443 を遮断して TCP へ退避させる（出典1）。遮断すれば HTTP/3 は既存の検査・復号の経路に乗る。副作用として正規の HTTP/3 利用も TCP に落ちるため、体感の速さは下がる（本記録の評価）。

マルウェア側が運用者の「危険な命令」を拒否していた評価・解釈出典 [1]

Unit 42 が「前例がない」と評した機能が isDangerousCommand である（出典1）。実装されているのは PerfectPioneer RAT の2変種（攻撃者自身の呼称で Pioneer と rat_http3_cc）である。

動作は単純だ。C2 から来た命令を実行する前に、固定の拒否一覧と照合する。一致すれば命令を完全に阻止する（出典1）。一覧に入っているのは、実行すればきわめて破壊的、あるいは痕跡が多く（noisy）、セキュリティ製品に監視されうる管理命令である。

Unit 42 はこれを「運用上の安全装置」と呼び、運用者が操作を誤って活動を発覚させることを防ぐ仕掛けだと評価している（出典1）。

ここから読み取れることが2つある（本記録の評価）。

  1. 攻撃者の組織は、実行役と開発役が分かれている。開発側が実行側の操作ミスを想定して、道具の側に歯止めを入れている。個人の技巧ではなく、運用の規律を道具で担保する作りである。
  2. 「長く居座ること」が目的として優先されている。破壊できる能力はあるが、使わせない。本件が情報収集の活動であることと整合する（出典1）。

なお拒否一覧には Windows と Linux 双方の文法が混在していた（出典1）。Go は同一のソースから相互コンパイルできるため、Unit 42 は並行して Linux 版を開発していたことを強く示唆すると評価している（出典1）。ただし Linux 版の実物が観測されたとは書かれていない〈未確定5〉。

擬装エンジンは、振る舞い検知の「普段」を攻撃者側が書き換えに来る評価・解釈出典 [1]

KUKURAT は、通信・レジストリ・ファイルの3方向で無害に見える偽の活動を生成する擬装エンジンを持つ（出典1）。C2 命令 set_obfuscation で各方向を個別に入切できる。

方向 生成される偽の活動
通信 1周期ごとに、固定で持つ15の有名サイトから無作為に選び、無作為の URL 経路へ10件の囮 HTTP 要求を出す
レジストリ HKCU\Software\Google\Chrome\BrowserCrashRecovery へ無作為のデータを書き、読み戻し、削除する。続けて HKCU\Software\Google\Update\ClientState を列挙し、Chrome のクラッシュ復旧に見せる
ファイル %temp% に無作為の名前・内容の一時ファイルを作り、即削除する

Unit 42 は、個々の技法に前例はあるが、3方向を協調させ、実行時に個別に入切できる点が独特だと評価している（出典1）。

本記録はここを最も重く見る（本記録の評価）。振る舞いによる検知は「普段と違うこと」を数えて判断する。擬装エンジンが狙うのは、その普段（基準線）そのものである。偽の活動で分母を膨らませれば、本物の操作の比率は下がる。

ただし皮肉なことに、雑音を増やす設計は固定の目印を残している（本記録の評価）。レジストリ経路は固定であり、見張り役との通信に使う名前付きパイプ WINDOW_SEC_WATCHDOG も固定である（出典1）。検知は、量ではなく筋——書き込み→読み戻し→削除の連続、固定名のパイプ、見張り役と本体の対——で見るべきである。

見張り役を併走させ、セキュリティ製品のフォルダに隠れていた原因・手口出典 [1]

KUKURAT は多くの事案で、別の見張り役（watchdog）の実行ファイルと対で投入されていた（出典1）。

  • KUKURAT 本体は専用のスレッドを作り、名前付きパイプWINDOW_SEC_WATCHDOG へ自分の実行ファイルの経路を3秒ごとに書く
  • 見張り役はその経路を読み、1秒ごとに生存信号を取る
  • 15秒受け取れなければ停止と判断し、記憶した経路から自動で再起動する

運用上の含意は単純である（本記録の評価）。プロセスを止めるだけの対処は駆除にならない。 本体と見張り役を同時に止め、両方の実行ファイルを取り除く必要がある。

さらに、ある事案では見張り役がC:\ProgramData\Cyvera\Ransomware\ に置かれていた（出典1）。この経路は歴史的に Cortex XDR に関連づけられたもので、Unit 42 はセキュリティ製品のフォルダ構造に隠れて疑いを下げる試みだと評価している（出典1）。

同種の発想は囮のインストーラにも現れている。ある事例では、囮のインストーラが正規の GlobalProtect のインストーラを実際に書き出して実行し、利用者には普通の設定画面を見せながら、背後で PerfectPioneer RAT を書き出して実行していた（出典1）。

ドメイン制御装置を取った後は、ログオンのたびに配られた被害規模・影響範囲出典 [1]

横展開で最も特徴的なのは、ドメインのログオンスクリプトの改変である（出典1）。

攻撃者はドメイン制御装置を侵害した後、悪性のログオンスクリプトを設置した。以後、正規の利用者がドメインに認証するたびに、その端末で KUKURAT の取得と実行が走る（出典1）。利用者の側に不審な操作は要らない。普通に業務を始めるだけでよい。

併せて PsExec・WMI・WinRM が使われ、KUKURAT 自身も外部モジュールとしてPsExecService.exe を投入した。これは PsExec という名前のローカルサービスと名前付きパイプ \\.\pipe\PSEXEC を作る自作の遠隔実行サービスで、5分間活動がないとサービスを自動解除して痕跡を片付ける（出典1）。

この段階については、Unit 42 が検知の実例を示している（出典1）。ログオンスクリプトによる永続化は警報を発生させた——理由は「ローカルまたはドメイン利用者の SID で、通常は見られない起動処理が実行された」ことである（出典1）。

つまりここは見える段階である（本記録の評価）。sysvol 共有と GPO の改変を変更管理と突き合わせ、ドメイン利用者 SID で動く異例の起動処理を警報にしておけば、面に広がる前に気づける余地がある。

持ち出しは文書だけでなく、全メールボックスへの権限付与にも及んだ被害規模・影響範囲出典 [1]

最終目的は情報収集である（出典1）。持ち出しの対象は主に.pdf・.docx・.xlsx・.png で、ファイル名からは国際関係と国内政治への顕著な関心がうかがえたとされる（出典1）。

加えてメール基盤が狙われた（出典1）。侵害した Exchange サーバの足場から PowerShell を実行し、2段構えで動いている。

  1. 代理権限の偵察 —— ApplicationImpersonation 役割の割り当てを確認する。この役割を持つ口座は、個々の利用者のパスワードを知らなくても任意のメールボックスへ直接到達できる
  2. 広域のアクセス取得 —— 代理権限が無ければ、管理権限で全メールボックスを巡回し、掌握済みの口座に FullAccess を与える（Add-MailboxPermission を Get-Mailbox -ResultSize Unlimited の結果に対して繰り返す形）

2番目の操作は、正規の運用ではまず起きない形である（本記録の評価）。移行作業や一括設定で似た操作が走ることはあるが、変更管理の記録と突き合わせれば区別できる。Unit 42 が対策として同じ監視を挙げていることから、実環境では見られていなかったとみられる（本記録の推定）。

数え方: **LSASS のメモリ取得を、関数名ではなく振る舞いで検知する**（出典1）〈重要〉—— **rundll32.exe が comsvcs.dll と相互作用する挙動を追う規則を作り、 序数による呼び出し（#+000024 のような形）で 文字列照合を回避する手口を捕まえる**（出典1）。　副作用: **comsvcs.dll は正規の COM＋の基盤でもあるため、 規則の作り方によっては誤検知が出る**（本記録の評価）。
数え方: **Exchange の代理権限とアクセス権限を定期的に監査する**（出典1）〈重要〉—— **ApplicationImpersonation 役割が割り当てられた口座を点検し、 Add-MailboxPermission の実行、とくに 組織全体に FullAccess を与える繰り返し処理を警報にする**（出典1）。　副作用: **移行作業・一括設定・監査用の正規口座も同じ操作を使うため、 例外の扱いを事前に決めておく必要がある**（本記録の評価）。
