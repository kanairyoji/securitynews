**韓国最大手の宅配事業者 CJ大韓通運が、配送サービス「오네（O-NE）」の チャットボットのサーバログと一部DBを分析していた2026年11月16日ごろ、 「異常な自動化された大量アクセス」を確認し、11月18日に個人情報流出の 疑いを公表した。** **照会されえた項目は荷物の受取人（인수인）の氏名と、 全住所ではなく「洞（동）」単位までの住所である。** **住民登録番号等の固有識別情報と連携情報（CI）は含まれていないとされる。** **流出の規模と対象の情報主体は確定していない。** **同社はチャットボットの流入経路に Web アプリケーションファイアウォールを 適用し、過剰な要求の検知・遮断とアクセス制御を強化した。**

「16日ごろ、CJ大韓通運『오네』（O-NE）チャットボットサービスのサーバログおよび一部DBデータの分析過程で、異常な自動化された大量アクセスを確認した」

ここで押さえるべきことは、何が起きなかったかである（本記録の整理）。

  • 脆弱性の悪用への言及が無い。
  • マルウェアへの言及が無い。
  • 権限昇格・横展開・永続化への言及が無い。

報告されているのは、外部に開かれた照会の窓口を、機械的に大量に叩いたことだけである〈重要〉。

チャットボットは、利用者から見れば「対話」だが、実装から見ればパラメータを受け取って個人データを返すAPIである（本記録の整理）。同社が事後対策として挙げたのが「チャットボットサービスの流入区間への WAF 適用」と「異常・過多な要求に対する検知および遮断機能の強化」であることは（出典1）、窓口が API として扱われていなかったことを示している（本記録の読み）。通常の API なら、認証・レート制限・応答項目の最小化が設計時の検討事項になる。対話の体裁をとると、この検討が抜け落ちやすい。

公表されていないことが3つあり、本件の再現性はここで決まる（本記録の評価）〈未確定2〉。

  1. 窓口は認証を要していたか。送り状番号のような推測可能な値だけで照会できたのであれば、攻撃者は番号を順に試すだけでよい。
  2. 1回の応答にどれだけの情報が含まれていたか。氏名と洞単位の住所が同時に返るのであれば、1照会で1人分が得られる。
  3. 照会の総回数・期間・レートはどれくらいだったか。

本記録はこの3点を推定しない。しかし自組織を点検するときは、この3つがそのまま問いになる（本記録の評価）——「対話型の窓口から、認証なしで、個人データが1回1件ずつ返る作りになっていないか」。

当事者は「流出したか」と「そもそも個人情報か」を同じ案内文で争点にしている評価・解釈

本記録が本件の対応で最も注目するのは、次の一文である（出典1。原文韓国語。本記録が訳した）。

「オネチャットボットサービスのサーバには、市・郡・区、詳細住所、連絡先など個人を追加的に特定できる情報が含まれていないため、これらの情報が個人情報保護法上の個人情報に該当しない可能性もある」

これは被害の説明ではなく、法的な立場の表明である（本記録の評価）〈重要〉。

韓国の個人情報保護法でも、日本の個人情報保護法でも、「個人情報」とは特定の個人を識別できる情報である。氏名と「洞」単位の住所だけでは、同姓同名が同じ洞にいる可能性があり、個人の特定に至らない——という論理構成になる（本記録の整理）。そして同社は、氏名の欄に「문앞（玄関前）」「경비실（警備室）」のような配送場所の文字列が相当数含まれているとも説明している（出典3）。氏名として機能していない行が混ざっていれば、識別可能性はさらに下がる。

この主張には一定の筋がある（本記録の評価）。実際、連携情報（CI）が含まれていないことは実質的に重要である—— CI は韓国で本人確認機関が発行する利用者ごとの識別子であり、これがあれば他サービスのデータと突合して同一人物を追跡できる。含まれていないのであれば、名寄せの難度は大きく上がる。

しかし、同じ案内文に置くことの問題がある（本記録の評価）〈重要〉。

読者（照会されえた受取人）が受け取るのは、2つの未確定である。

未確定 内容
事実の未確定 流出したのか、規模はどれくらいか（「確定していない状態」）
法的な未確定 そもそも個人情報に該当するのか（「該当しない可能性もある」）

この2つが並ぶと、読者は何をすべきか判断できない（本記録の評価）。「個人情報ではない可能性がある」と書かれていれば、警戒の必要も薄いと読むのが自然である。一方で同社は、配送業務を装った電話・SMS・メールへの注意も呼びかけている（出典2・3）——つまり警戒は必要だという立場も同時に示している。

届け出義務との関係も切り離せない（本記録の評価）〈重要〉。個人情報に該当しなければ、当局への届け出義務も本人通知義務も生じない。本件について、個人情報保護委員会・KISA への届け出の有無は公表されていない〈未確定5〉。本記録は、この2つが無関係とは考えない——ただし、同社が届け出を回避する目的でこの一文を書いたと断定する材料も無い（本記録の明示）。

日本の読者への含意は、公表文の設計にある（本記録の評価）。被害者に向けた事実の説明と、自社の法的立場の主張は、読み手も目的も違う。同じ文書に混ぜると、どちらの効果も弱まる。

「AI を悪用したハッキング」は報道の解釈であり、当事者の説明ではない関係が否定された事象

本件の報道には、当事者の説明に無い要素が混ざっている（本記録の整理）〈齟齬1〉〈重要〉。

保安ニュースは次のように書いている（出典1。原文韓国語。本記録が訳した）。

「異常な自動化された大量アクセスという点から、AI を悪用したハッキングの可能性が有力視される」

しかし、同社の説明にこの記述は無い（本記録の確認）。同社が述べているのは「異常な自動化された大量アクセス」であり、その手段についての言及は無い。

本記録はこれを事実として扱わない。理由は2つある（本記録の評価）。

第一に、根拠が示されていない。「自動化されていた」から「AI が使われた」は導けない。大量の照会を自動化する手段は、十数行のスクリプトで足りる——これは何十年も前から存在する手口である。

第二に、防御側の打ち手が変わらない。攻撃者がスクリプトを手書きしたのか、言語モデルに書かせたのか、エージェントに実行させたのかによって、窓口側で必要な対策は変わらない〈重要〉——認証条件、1回の応答に含める情報量、照会数の上限の3つである。

本記録がこれを独立した節として書くのは、「AI による攻撃」という枠が、対策の議論を別の場所へ連れていくためである（本記録の評価）。AI の脅威として語られると、対策は「AI 対策の製品」の話になる。本件で必要だったのは、窓口のレート制限である。

留保: 攻撃手段は公表されていない（本記録の明示）〈未確定6〉——本記録は「AI が使われていない」とも主張しない。言えるのは、現時点でそれを示す材料が公表されていないことだけである。

照会されえたのは「宅配を装った連絡」を通りやすくする組み合わせである被害規模・影響範囲

照会されえたのは2項目である（出典1）。

  • 荷物の受取人（인수인）の氏名
  • 住所のうち「洞（동）」単位までの情報（全住所ではない）

項目としては軽い（本記録の評価）。住民登録番号も、携帯電話番号も、詳細住所も、連絡先も含まれていないとされる。連携情報（CI）も含まれていない——他サービスのデータとの名寄せは難しい。

それでも本記録が注意を要すると見るのは、この組み合わせの用途である（本記録の評価）〈重要〉。

韓国では、宅配を装ったスミッシング（SMS フィッシング）が一般的な手口として知られている。「お荷物のお届けに伺いましたが不在でした。住所の確認をお願いします」という形の連絡である。この種の連絡が通るかどうかは、受け手が「自分のことだ」と思うかで決まる。

氏名が合っていて、住んでいる洞が合っていれば、受け手の警戒は下がる（本記録の評価）。そして同社自身が、配送業務を装った電話・SMS・メール、および出所不明のリンクや添付ファイルへの注意を呼びかけている（出典2・3）—— 同社もこの筋を見ていると読める（本記録の読み）。

一方で、被害の見積もりには重要な留保がある（本記録の明示）。

  1. 氏名欄に「문앞（玄関前）」「경비실（警備室）」のような配送場所の文字列が相当数含まれている（出典3）——氏名として機能していない行が混ざっている。
  2. 連絡先が含まれていない（出典1）——攻撃者はこのデータだけでは SMS を送れない。別の経路で入手した電話番号と突合する必要がある。そして突合の鍵となる CI も含まれていない。
  3. 流出そのものが確定していない（出典1）〈未確定3〉。

つまり本件のデータは、単体では使えず、他のデータと組み合わせたときに効く性質を持つ（本記録の評価）〈重要〉。この性質は、個人情報該当性の議論（氏名＋洞では特定できない）とリスクの議論（他のデータと組み合わせれば効く）がかみ合わない理由そのものである。

留保: 実際の悪用・スミッシングの観測は報告されていない（本記録の明示）——上記はデータの性質からの評価である。本節の確度を presumed としたのはこのためである。
