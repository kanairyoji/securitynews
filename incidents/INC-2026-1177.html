C2 の所在を公開台帳に置いたため、ドメインの遮断では止まらない原因・手口

技術的な要点を、一次資料の記述に沿って置く（出典1）。

① 置き場所。 Overlord RAT は、Solana ブロックチェーンの Memo プログラムを使った取引のメモ欄（1取引あたり最大566バイト）から C2 の URL を取り出す。 取り出し方は、getSignatures で署名の一覧を取り、 getTransaction（jsonParsed）で内容を読み、 命令データの長さがちょうど43文字のものだけを C2 の情報として扱う—— 43文字は AES-256 で暗号化し Base58 で符号化した WebSocket の URL に対応する。

② 何が変わるか。 C2 を変更するには、新しい取引を1件出すだけでよい。 すでに配った実体の設定を書き換える必要がない（出典1）。 防御側から見ると、C2 のドメインや IP を遮断しても、 相手は取引を1件追加するだけで全ての実体を新しい宛先に向けられる。

③ 止める場所が1つ上に移る。 本記録の評価では、 この構成に対して効くのは 「ブロックチェーンの公開 RPC エンドポイントへの読み出しを止める」 ことである。暗号資産を扱わない組織の利用者端末が Solana の RPC に接続する理由はない。 逆に、暗号資産関連の業務を持つ組織では遮断できないため、 接続元を特定の端末に限定する形にせざるを得ない。

④ この手法は1つの集団のものではない。 Talos は、Solana の取引メモを使う手法が2026年3月に Lazarus の手口として最初に報告され（当時の実装は Node.js 経由）、 2026年10月には他の脅威集団のキャンペーンでも 用いられていることが報告されたと明記している（出典1）。 本記録の整理では、後者には npm の供給網キャンペーン MALFEX （Checkmarx が2026年10月5日に公表。Overlord RAT を配り、 C2 を Solana 経由で解決する。本DB の INC-2026-0384）が含まれうるが、 Talos が参照した報告がそれであるとは明示されていない。

取得も実行も Windows 標準の署名済みプログラムに代行させている原因・手口

3種の初期侵入経路は、いずれも「自分の道具を持ち込まない」形である （出典1）。

① LNK（2種）。 1つは標準の文書アイコンで PDF を装い、 Windows Defender のコマンドライン道具 MpCmdRun.exe と 引数 -DownloadFile でペイロードを取得する。 Talos は「MpCmdRun.exe は Microsoft が署名したバイナリであるため、 ダウンロードはアプリケーションの許可リストの制御を そのまま通過する」と述べている（原文英語。本記録が訳した）。 もう1つは二重拡張子と Edge の PDF アイコンで装い、 certutil -urlcache -f を使う。 取得した実体は RuntimeBroker.exe として保存され、 コンソール窓は最小化される。 2つの LNK は同じ機械（win-8oa3ccqae4d）で作られていた。

② HTA。 mshta.exe が実行し、JavaScript が MSXML2.ServerXMLHTTP でペイロードを取得して ADODB.Stream で %TEMP%\s.exe に書き、窓を隠して実行する。

③ MSBuild の XML。 dl.xml にインラインの C# を CodeTaskFactory で持ち、msbuild.exe で実行すると メモリ上でコンパイル・実行される。 ダウンローダ段階の実行ファイルがディスクに残らない。 取得時の User-Agent は「Microsoft BITS/7.8」に偽装され、 Windows Update や Defender の背景通信に見せる。

本記録の評価では、ここが防御の要である。 署名に依存した許可リストでは止まらず、 「悪性ファイルを見つける」型の検知も効きにくい。 効くのは、コマンドラインの形（-DownloadFile・-urlcache）と、 役割に不要な標準ツールの実行を見ることである。 どちらも誤検知が少なく、実装の費用も小さい。

端末の初期化を無効化する永続化が仕込まれている原因・手口

Overlord RAT の永続化は2段構えで、 2段目が本件で最も見落とされやすい（出典1）。

1段目。 HKCU の自動実行（Run）に無作為な値名を作り、 利用者プロファイルのアプリケーションデータ配下の Network フォルダに置いた実体を指す。 情報窃取ツールは値名「Zoipers」とスタートアップフォルダへの複製、 クリップボード書き換えツールは %APPDATA%\MsgEdgeUpdate.exe（隠し属性・システム属性。 Edge の更新プログラムを装う）と Run キーを使う。

2段目。 Windows 回復環境（WinRE）を使った起動前の永続化である。 %TARGETOSDRIVE%\Recovery\OEM\ に無作為な20文字の名前で自身を書き、 それを起動するバッチを作り、 WinRE の動作を決める ResetConfig.xml を書き換える （既存の設定は事前に退避する）。 %TARGETOSDRIVE% は WinRE の中でしか解決されない環境変数であり、 この仕掛けは「この PC を初期状態に戻す」の実行時に OS の復元より先に動くことを狙っている。

本記録の評価では、ここは運用手順そのものを変える必要がある。 侵害された端末に対する「初期化して返す」という手順は、 この永続化がある限り対策にならない。 復旧は記憶装置の消去を含む再構築にする必要がある。 あわせて、Recovery\OEM 配下のファイル作成と ResetConfig.xml の変更は、正規には機器の出荷時整備でしか起きないため、 監視を置けば誤検知の少ない検知になる。

なお、Overlord RAT は強制終了に対抗する仕掛けも持つ。 SeDebugPrivilege を取得した上で NT API（NtSetInformationProcess）を 直接呼び、自プロセスに ProcessBreakOnTermination を設定する。 止めようとすると OS 全体が停止し、 CRITICAL_PROCESS_DIED のブルースクリーンになる（出典1）。 本記録の評価では、隔離はプロセスの停止ではなく ネットワーク側で行うべきである。

CISO・経営層への示唆
  • 侵害端末の復旧手順から「初期化して返す」を外す
    **Overlord RAT は Windows 回復環境（WinRE）の OEM 領域に自身を置き、 ResetConfig.xml を書き換える**（出典1）〈重要〉—— **「この PC を初期状態に戻す」を実行すると、 OS の復元より先に攻撃者のコードが動く。** **本記録の評価では、これは運用手順そのものが 攻撃者に織り込まれている例である。** **初期化を前提にした復旧手順を持つ組織は、 対処したつもりで感染を残す。**
    取るべき行動 侵害端末の復旧手順を、記憶装置の消去を含む再構築に改める。 手順書に「初期化（リセット）は使わない」ことを明記し、 理由としてこの事例を添える。 委託先に端末の再構築を任せている場合は、手順の内容を確認する。
  • C2 の遮断を前提にした封じ込め計画を見直す
    **Overlord RAT は C2 の URL を Solana の公開台帳から取り出し、 取引を1件出すだけで切り替えられる**（出典1）〈重要〉—— **本記録の評価では、「C2 のドメイン・IP を遮断する」という 封じ込めの定石が本件では機能しない。** **止める場所は1つ上—— 公開台帳の読み出し（ブロックチェーンの RPC エンドポイント）に移る。**
    取るべき行動 封じ込め手順に「C2 の遮断が効かない型」の節を追加し、 ブロックチェーンの公開 RPC エンドポイントへの通信を 遮断できる構成になっているかを確認する。 暗号資産関連の業務がある場合は、接続を許す端末を特定し、 それ以外から遮断する。
  • 業務で使う正規ソフトの配布経路を、自組織から1本に絞る
    **おとりには Viber の偽インストーラと microsip（VoIP ソフト）を装う実行ファイルが使われている** （出典1）〈重要〉—— **本記録の評価では、利用者が自分で業務ソフトを探して インストールする運用が残っている組織では、 この型のおとりが成立する。** **コールセンター・問い合わせ窓口のように VoIP ソフトを多数の端末に入れる業務は、とくに該当する。**
    取るべき行動 業務で使うソフトの配布を社内の1経路（配布基盤・社内カタログ）に 限定し、利用者が外部サイトから取得する必要がない状態にする。 VoIP・メッセージングのソフトは、 利用部門と配布経路を一覧にして確認する。
  • 脅威情報の帰属の確度を、社内の報告で潰さない
    **Talos の帰属評価は「低確度」で、 Talos 自身が「同じ道具と手法は他の集団も使う」と明記している** （出典1）〈重要〉—— **本記録の評価では、これを「北朝鮮の攻撃」とまとめると、 留保と反証材料の両方が消える。** **帰属を上げて報告すると、 対策の優先順位が「国家級の脅威だから特別扱い」へ ずれる危険がある—— 本件で必要なのは特別な対策ではなく、 標準ツールの使われ方を見る基本的な対策である。**
    取るべき行動 脅威情報の社内報告様式に「評価の確度」と 「その評価を出した主体」を記す欄を設ける。 帰属が低確度の情報を扱うときは、 対策の根拠を帰属ではなく手口に置いて記述する。
セキュリティ技術者への示唆
  • MpCmdRun.exe の `-DownloadFile` と certutil.exe の `-urlcache` を 検知・遮断する
    **本件の LNK はこの2つで取得を代行させる**（出典1）〈重要〉—— **Talos は MpCmdRun.exe が Microsoft の署名済みバイナリであるため、 アプリケーションの許可リストをそのまま通過すると指摘している （原文英語。本記録が訳した）。** **本記録の評価では、署名に依存した制御では止まらず、 コマンドラインの形で見るしかない。** **正規の運用でこの組み合わせが現れることはほぼ無く、 誤検知が少ない。**
    取るべき行動 プロセス起動のコマンドラインを収集し、 MpCmdRun.exe に `-DownloadFile`、 certutil.exe に `-urlcache` が含まれる実行を検知・遮断する。 あわせて役割ごとに mshta.exe・msbuild.exe の実行を制限する （記録のみの段階から始める）。
  • Recovery\OEM 配下のファイル作成と ResetConfig.xml の変更を監視する
    **Overlord RAT は %TARGETOSDRIVE%\Recovery\OEM\ に 無作為な20文字の名前で自身を書き、 ResetConfig.xml を書き換える**（出典1）〈重要〉—— **本記録の評価では、この領域が正規に変更されるのは 機器の出荷時整備に限られるため、 監視を置けば誤検知がほとんど無い。** **これは端末の初期化という最後の手段を守るための検知である。**
    取るべき行動 ファイル作成・変更の監視対象に Recovery\OEM 配下と ResetConfig.xml を追加し、変更を警報にする。 警報が出た端末は、初期化ではなく再構築の対象として扱う。
  • システムの正規プロセス名が標準でない場所から動いていないかを検知する
    **取得された実体は RuntimeBroker.exe として保存され、 クリップボード書き換えツールは %APPDATA%\MsgEdgeUpdate.exe として Edge の更新を装う** （出典1）〈重要〉—— **本記録の評価では、プロセス名だけを見る監視は この偽装をそのまま通す。** **名前と実行パスの組み合わせで見れば区別できる。**
    取るべき行動 プロセス起動の記録から、システムの正規プロセス名 （RuntimeBroker.exe 等）が %SystemRoot%\System32 以外から起動された場合に警報を出すルールを作る。 あわせて %APPDATA% 配下からの実行を一覧化して棚卸しする。
  • プロセスの強制終了に頼らない隔離手順を用意する
    **Overlord RAT は自プロセスに ProcessBreakOnTermination を設定し、 強制終了されると OS 全体を停止させる （CRITICAL_PROCESS_DIED のブルースクリーン）**（出典1）〈重要〉—— **本記録の評価では、「怪しいプロセスを止める」という 初動は端末を落とすだけで、 揮発性の証拠（メモリ上のプラグイン・接続状態）も失われる。**
    取るべき行動 隔離の初動を「ネットワークからの切り離し」に統一し、 プロセスの強制終了を行わない手順にする。 メモリの取得を先に行い、その後に端末を再構築する。
  • User-Agent が「Microsoft BITS/7.8」の通信を、発生元のプロセスと 組み合わせて検知する
    **MSBuild 経由の取得は、この User-Agent を偽装して Windows Update や Defender の背景通信に見せる**（出典1）〈重要〉—— **本記録の評価では、宛先だけを見る監視では区別できないが、 「BITS を名乗る通信を出しているプロセスが msbuild.exe である」ことは異常として判定できる。**
    取るべき行動 プロキシ・ファイアウォールのログで User-Agent を記録し、 BITS を名乗る通信の発生元プロセスを突き合わせる。 BITS の正規の経路以外から出ている場合に警報を出す。
法務・コンプライアンスへの示唆
  • 暗号資産の送金手順に、アドレスの全桁照合を手続として組み込む
    **クリップボード書き換えツールは500ミリ秒ごとに監視し、 見つけたアドレスを攻撃者のものに置き換える**（出典1）〈重要〉—— **ネットワーク機能を持たないため、 通信監視では一切映らない（本記録の評価）。** **送金が実行された後の回復は、 送金先の協力が無ければ事実上できない。**
    取るべき行動 暗号資産の送金を行う業務について、 貼り付けたアドレスの全桁を別経路（紙・別端末）の値と 照合する手順を定める。 先頭と末尾の数桁のみの確認では足りないことを手順書に明記し、 一定額以上は二者承認とする。
