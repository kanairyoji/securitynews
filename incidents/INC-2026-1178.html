INC-2026-1178Apache Roller に悪用中の無認証 RCE

Apache が2026年11月、グループブログ基盤 **Apache Roller** の **無認証の遠隔コード実行の脆弱性 CVE-2026-129448 を「実際に悪用されている」と明記して公表した**。 **XML-RPC エンドポイントが、要求元を認証する前にベンダー拡張型を逆シリアル化する**ため、 認証を持たない遠隔の攻撃者が任意のコードを実行できる。 **影響範囲は 4.0.0 から 6.1.4 まで**で、 **これは2026年10月6日に 6.1.5 のみを影響範囲として公表された CVE-2026-82384 と同一の脆弱性である**—— **1か月前の採番では「6.1.5 だけの問題」に見えていたものが、 実際には 4.0.0 以降の16年分すべてに存在した**（本記録の整理）。 **修正は 6.1.6 以降**（拡張型を無効化し、XML-RPC 機能が無効のときは要求を拒否する）。 **すぐに上げられない場合の緩和策は、`WEB-INF/web.xml` で `enabledForExtensions` を `false` にするか、 `/roller-services/xmlrpc` のサーブレットマッピングを削除して再起動すること**で、 **管理画面で XML-RPC を無効にするだけでは止まらない** ——**古い版は、その設定を見る前に要求を逆シリアル化してしまう**。 **攻撃の実態（誰が・どれだけの台数が侵害されたか）は Apache が示していない。** **CISA の KEV には、本記録が確認した2026年11月18日19時17分（UTC）版の カタログ（1,786件）の時点で収載されていない**（本記録による確認）

脆弱性不正アクセス・侵害初報のみ有名事象として記録（日本と直接の関係は薄い）設計・実装上の不備既知の脆弱性の悪用
初報: 2026年11月17日（Apache の security advisory 一覧の最終更新日） 最終更新: 2026年11月19日

Apache Roller の XML-RPC エンドポイントに、認証の前に逆シリアル化を行う無認証の遠隔コード実行の脆弱性があり、すでに悪用されている。

公表の要点は3つである。

  • 影響範囲が16年分に広がった。 CVE-2026-129448 の影響範囲は4.0.0 から 6.1.4。Apache は「これは CVE-2026-82384 と同一の脆弱性であり、そちらは 6.1.5 のみを影響範囲として挙げていた」と明記した（原文英語）。同じ欠陥が、10月6日の採番では「最新の1版だけの問題」として世に出ていた。
  • 悪用されている。 Apache の security advisory 一覧には「This issue is being actively exploited.」とある（原文英語）。ただし攻撃者・侵害台数・手口の詳細は示されていない。
  • 設定で止めるには、管理画面では足りない。 緩和策はWEB-INF/web.xml の enabledForExtensions を false にするか、/roller-services/xmlrpc のサーブレットマッピングを削除して再起動すること。管理画面で XML-RPC を無効にしても、古い版は設定を見る前に逆シリアル化する。

本記録が最も重く見たのは、悪用の事実ではなく「採番の影響範囲が実態を映していなかった1か月」である（本記録の評価）—— 10月6日の CVE-2026-82384 を見て「自分は 6.1.5 ではないから無関係」と判断した運用者は、11月まで同じ欠陥を抱えたまま放置されていた。CVE の影響範囲は、公表時点で分かっている範囲にすぎない。

攻撃の経過

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

**以下は、Apache の advisory が記述した「脆弱性の仕組みの上で成立する経路」であり、 実際に観測された攻撃の再構成ではない**（本記録の明示）〈重要〉—— Apache は悪用の事実のみを公表し、手口・台数・攻撃者を示していない。 認証を持たない攻撃者が XML-RPC エンドポイント（`/roller-services/xmlrpc`）へ ベンダー拡張型を含む要求を送ると、**要求元の認証より前に** それが逆シリアル化され、任意のコードが実行されうる。

  1. 1. 初期侵入disclosed[1]
    認証を持たない遠隔の攻撃者が、XML-RPC エンドポイントへ ベンダー拡張型（vendor extension types）を含む要求を送る。 **実際の攻撃でこの段階がどう行われたかは公表されていない**
    根拠: Apache security advisory（CVE-2026-129448／CVE-2026-82384 の説明）
  2. 2. 実行disclosed[1]
    エンドポイントが、**要求元を認証する前に**拡張型を逆シリアル化する。 信頼できないデータの逆シリアル化により任意のコードが実行されうる。 **実際に何が実行されたかは公表されていない**
    根拠: Apache の security advisory（「要求元を認証する前にそれを逆シリアル化する」。 原文英語「deserializes them before authenticating the requester」）

認証の前に逆シリアル化が走るため、認証を持たない遠隔の攻撃者が任意コードを実行できる原因・手口出典 [1]

Apache の説明を引用する（原文英語）。

「Deserialization of Untrusted Data in Apache Roller versions 4.0.0 through 6.1.4 allows an unauthenticated remote attacker to execute arbitrary code. The XML-RPC endpoint accepts vendor extension types and deserializes them before authenticating the requester.」

本記録による訳: 「Apache Roller 4.0.0 から 6.1.4 における信頼できないデータの逆シリアル化により、認証を持たない遠隔の攻撃者が任意のコードを実行できる。XML-RPC エンドポイントはベンダー拡張型を受け付け、要求元を認証する前にそれを逆シリアル化する。」

同一の脆弱性を 6.1.5 について扱った CVE-2026-82384 の説明は、もう一段踏み込んでいる（原文英語の要旨。本記録が訳した）。

  • XML-RPC エンドポイントは、認証前の要求の解析中に逆シリアル化されるベンダー拡張型を受け付ける
  • サーブレットが無条件にマッピングされているため、XML-RPC 機能を無効にしていても解析そのものは行われる
  • 既定以外の特別な設定は不要である
  • 遠隔でのコード実行につながりうる

この3点目が重い（本記録の評価）——「うちは XML-RPC を使っていないから無効にしてある」という運用は、この脆弱性に対しては無効である。

1か月前の採番では「6.1.5 だけの問題」に見えていた評価・解釈出典 [1]

Apache は CVE-2026-129448 の説明にこう書き添えている（原文英語）。

「This is the same vulnerability as CVE-2026-82384, which listed only Apache Roller 6.1.5 as affected. This issue is being actively exploited.」

本記録による訳: 「これは CVE-2026-82384 と同一の脆弱性であり、そちらは影響を受けるものとして Apache Roller 6.1.5 のみを挙げていた。本件は実際に悪用されている。」

時系列で並べると、次のことが起きていた（本記録の整理）。

時点 公表されていた影響範囲 悪用の記載
2026年10月6日（CVE-2026-82384） 6.1.5 のみ 無し
2026年11月17日（CVE-2026-129448） 4.0.0〜6.1.4 「actively exploited」

10月6日の時点で 6.1.4 以前を運用していた管理者が advisory を読んだとすれば、自分は影響範囲の外だと判断するのが自然である。実際には同じ欠陥を抱えていた。その状態が 42日間（T1→T2）続いた。

ここから引ける教訓は、Roller 固有のものではない（本記録の評価）—— CVE の affected 欄は「公表時点で開発元が確認できた範囲」であって、欠陥が存在する範囲ではない。とくに「最新版のみが影響」という珍しい形の advisory を見たときは、同じ処理が旧版に無いことを自分で確かめる価値がある。

管理画面で XML-RPC を無効にしても止まらない——設定を見る前に逆シリアル化する対策・注意喚起出典 [1] [2]

Apache が示した対処は次のとおりである。

恒久対処

  • 6.1.6 以降へ更新する。 この版では拡張型が無効化され、XML-RPC 機能が無効のときは要求が拒否される
  • プロジェクトサイトの最新リリースは 6.1.7 である（出典4）

すぐに更新できない場合の緩和策（いずれか）

  • WEB-INF/web.xml で enabledForExtensions を false に設定して Roller を再起動する
  • /roller-services/xmlrpc のサーブレットマッピングを削除して Roller を再起動する

効かない対処

  • 管理画面（administration user interface）で XML-RPC を無効にするだけでは攻撃を止められない。 Apache は、古い版はその設定が有効かどうかを確認する前に要求を逆シリアル化するためだと説明している。

運用上の含意（本記録の評価）——緩和策はどちらも設定ファイルの編集と再起動を要する。つまり「無停止で設定だけ変えて凌ぐ」ことはできない。再起動の窓を取れない環境では、経路側で /roller-services/xmlrpc への到達を落とす（リバースプロキシ・WAF・ネットワーク ACL）ほうが早いことがある。ただしこれは Apache が示した緩和策ではなく、本記録の補足である。

KEV には収載されていない——「悪用されている」と「期限付きの指示がある」は別である当局対応出典 [1] [2] [3]

本記録は2026年11月18日19時17分（UTC）版の CISA KEV カタログ（JSON 配布・収載1,786件）を取得して照合した。CVE-2026-129448・CVE-2026-82384 のいずれも収載されていない（本記録による確認）。

つまり現時点では、

  • 開発元は「実際に悪用されている」と明記している（出典1）
  • CISA は期限付きの是正を米連邦機関に命じていない（本記録による確認）

という状態である。BleepingComputer は背景として、CISA が2021年11月以降 KEV にApache 製品の脆弱性を 41件追加し、うち8件はランサムウェア犯罪集団にも悪用されていると添えている（出典2。本記録は KEV 側でこの集計を再現していない）。

KEV の収載を待って動く理由は無い（本記録の評価）—— KEV は米連邦機関への命令の道具であり、悪用の有無を測る唯一の指標ではない。本件は開発元自身が悪用を認めているのだから、そちらのほうが早く、かつ強い根拠である。

攻撃の実態は公表されていない未確定事項出典 [1] [2]

Apache は悪用の事実だけを記し、以下を示していない。

  • 攻撃者（誰が・どの集団か）
  • 既に侵害されたサーバの台数
  • 侵害後の行動（Web シェル設置・横展開・データ持ち出しのいずれか）
  • 悪用を観測した主体と時期
  • 悪用が CVE-2026-82384 の期間（6.1.5 のみが影響範囲とされていた42日間）から続いていたのか、11月に入って始まったのか

BleepingComputer も「Apache はこれらの進行中の攻撃について、責任主体や既に侵害されたサーバの数を含む詳細をまだ提供していない」と書いている（原文英語。本記録が訳した）。

本記録は、これらを推測で埋めない。侵害の有無を自組織で判断する材料は、現時点では「XML-RPC エンドポイントへのアクセスログ」と「サーバ上の不審なプロセス・ファイル」しかない。開発元が IoC を出していないため、照合先が無い（本記録の評価）。
