INC-2026-1191米物流を狙う3系統の攻撃

**米国のトラック運送・物流事業者を狙う3系統の攻撃が、 同時に動いていることが示された** （ANY.RUN が2026年11月17日に公表）〈重要〉。 **1系統目「HelloFriends」は米連邦自動車運送安全局（FMCSA）を装い、 攻撃者が自ら管理するドメインから送るため SPF・DKIM・DMARC の検査をすべて通過し、 受信者の実在の運送事業者番号（USDOT 番号）を本文に入れていた**（出典1）〈重要〉—— **偽の SAFER／Motus 画面で社会保障番号・雇用主識別番号・生年月日と 給油カードの認証情報を取り、一度わざと誤りを返して再入力させた上で 6桁のコードまで聞き出す**（出典1）。 **2系統目「NodeRemote」は偽の reCAPTCHA 画面で 悪性コマンドをクリップボードに置き、利用者自身に貼り付けさせて Node.js 製のバックドアを入れる**（出典1）—— **接続先の中継サーバーは BNB スマートチェーンのスマートコントラクト・ 暗号化された DNS レコード・GitHub Gist の3経路から取得し、 10月25日から11月3日の間に12個のうち6個が 新しい検体を配らずに差し替わった**（出典1）〈重要〉。 **3系統目は貨物取引サイト TIMOCOM・DAT を装う偽ポータルで、 正規の遠隔管理ツール MeshCentral を入れたうえで BitLocker の回復パスワードを取り出し、 Microsoft Defender に除外を追加して CastleRAT を置いた**（出典1）〈重要〉—— **ファイルを暗号化する活動は観測されていない**（出典1）。

2026年11月17日、マルウェア解析サービスの ANY.RUN は、 米国のトラック運送・物流業界を狙う3系統の攻撃を 同時に追跡した報告を公表した（出典1）〈重要〉—— 運送事業者を監督する政府機関、貨物の仲介書類、 貨物取引サイトのいずれかを装い、 口座・金銭・業務用 PC を狙う。 1系統目「HelloFriends」は米連邦自動車運送安全局（FMCSA）の 担当者名義を使う（出典1）—— 送信元のドメインは攻撃者自身が管理しているため SPF・DKIM・DMARC の検査をすべて通過し、 本文には受信者の実在の USDOT 番号が入っていた（出典1）〈重要〉—— リンク先は運送事業者情報の照会サイト SAFER や 給油カードの管理画面 Motus を模した偽ページで、 実在の会社情報の横に「運行の承認なし」という警告を出し、 番号の再有効化が急を要すると迫る（出典1）—— 確認の過程で300ドルの「事務手数料」が現れ、 社会保障番号・雇用主識別番号・生年月日を取る（出典1）。 ANY.RUN は、2026年のこのキャンペーンに関連するドメインを 約1,430個見つけている（出典1）。 2系統目「NodeRemote」は、仲介事業者の登録ページ・船荷証券・ 保険金請求書・運賃確認書を装う（出典1）—— 偽の reCAPTCHA 画面が悪性の PowerShell コマンドを 自動でクリップボードに写し、 利用者に Windows の「ファイル名を指定して実行」へ 貼り付けさせる（出典1。いわゆる ClickFix）—— Node.js の実行環境と難読化された main.js が %LOCALAPPDATA%\WebServer-\ に置かれ、 NodeRemote{GUID} という名前のスケジュールされたタスクで常駐する（出典1）。 接続先の中継サーバーの情報は、 BNB スマートチェーン上のスマートコントラクト・ DNS over HTTPS で取る暗号化された TXT レコード・ GitHub Gist の3経路から取得される（出典1）〈重要〉—— 2026年10月25日から11月3日の間に、 12個の中継先のうち6個が差し替わった（出典1）—— 新しい検体を配り直さずに接続先だけを替えられる構造である（本記録の読み）。 3系統目は貨物取引サイト TIMOCOM と DAT を装う偽ポータルである（出典1）—— 2026年5月には貨物関連の実行ファイルで正規の遠隔操作製品 NetSupport Manager を入れさせていたが、 10月の攻撃では「PDF を表示」を押させ、 実際には攻撃者の WebDAV 共有が開いて PDF を装ったショートカットファイルが動く（出典1）—— これが正規の遠隔管理ツール MeshCentral の エージェントを入れる（出典1）〈重要〉—— ANY.RUN が解析した感染事例では、 攻撃者はこの経路で manage-bde を使って BitLocker の回復パスワードを取り出し、 Microsoft Defender に C:\Users と SysmonDrivers.exe の除外を追加したうえで、 CastleRAT（NightshadeC2 とも呼ばれる）を C:\Users\SysmonDrivers.exe として置いた（出典1）—— ファイルを暗号化する活動は観測されていない（出典1）—— ANY.RUN は、回復パスワードの取得と防御機能の無効化と 居座りが一体になること自体が大きな危険であるとしている（出典1。原文英語）。 本記録は ANY.RUN の原文を取得して確認した（本記録の観測）—— 一方、装われた側（FMCSA・TIMOCOM・DAT・Motus および給油カード各社）の 公表は本記録の環境から取得できていない〈齟齬3〉。

攻撃の経過

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

攻撃者が管理するドメインから FMCSA の担当者名義で、 受信者の実在の USDOT 番号を入れたメールを送る。 メール認証の検査は通過する。偽の SAFER／Motus 画面で 「運行の承認なし」と迫り、個人情報と給油カードの認証情報、 一度わざと誤りを返して再入力させた秘密の語、SMS や6桁のコードを取り、 サーバー側の API を経由して Telegram へ送る。 別系統では、仲介書類を装うページの偽 reCAPTCHA が 悪性コマンドをクリップボードに置き、利用者が Run ダイアログへ貼り付けて Node.js 製のバックドアが入る。中継先はブロックチェーン・暗号化 DNS・Gist から取り直す。 さらに別系統では、偽の貨物取引ポータルの「PDF を表示」が 攻撃者の WebDAV 共有を開き、PDF を装ったショートカットが MeshCentral のエージェントを入れ、BitLocker の回復パスワードの取得と Defender の除外追加を経て CastleRAT が置かれる

  2. 2. 認証情報アクセスdisclosed

  3. 3. 持ち出しdisclosed

    根拠: ANY.RUN の報告（exfiltration の経路の記述）
  4. 4. 実行disclosed
    2系統目では、偽の reCAPTCHA 画面が悪性の PowerShell コマンドを 自動でクリップボードに写し、利用者に Windows の 「ファイル名を指定して実行」へ貼り付けて実行させる。 業務書類を装った VBS ファイルを配る変種もある。 PowerShell または VBS が Cloudflare Workers の終端から部品を取得し、 Node.js の実行環境と難読化された main.js を `%LOCALAPPDATA%\WebServer-\` に展開する
    根拠: ANY.RUN の報告の NodeRemote の節
  5. 5. 永続化disclosed
    `NodeRemote{GUID}` という名前のスケジュールされたタスクが作られ、 ログオン時と一定間隔で起動する。 2026年11月の MSI 形式の変種では `NodeRemoteWebServer-` という名前が使われた。 `.env` ファイルに `SUPER_ADMIN_KEY` の値が置かれ、 攻撃者の管理システム上で感染端末をテナントに対応づけているとみられる
    根拠: ANY.RUN の報告（常駐とタスク名の記述）
  6. 6. 権限昇格disclosed
    2系統目では `higeleveltask_x64.exe` が、 ms-settings のレジストリハンドラを書き換えて `fodhelper.exe` と `ComputerDefaults.exe` 経由で UAC を回避しようとする。 ANY.RUN は、これには侵害された利用者が すでにローカルの管理者である必要があると述べている。 3系統目でも、CastleRAT を `ComputerDefaults.exe` 経由で 再起動して昇格を試みている
    根拠: ANY.RUN の報告（両系統の権限昇格の記述）
  7. 7. 初期侵入disclosed
    3系統目では、偽の貨物取引ポータル（update-dat[.]com 等）が ダウンロードを予約の確認・口座へのアクセス手順・約款の変更の確認として提示する。 2026年10月の連鎖では「PDF を表示」を押すと Windows のエクスプローラーが攻撃者の WebDAV 共有 （termsconditionsrelease[.]pro@8080）を開き、 その中の `terms_and_conditions.pdf.lnk` が 遠隔の共有上の `terms_and_conditions.exe` を実行する
    根拠: ANY.RUN の報告の偽ポータルの節（10月の感染連鎖）
  8. 8. 検知回避disclosed
    3系統目では、設置された MeshCentral のエージェントを通じて Microsoft Defender に `C:\Users` と `SysmonDrivers.exe` の除外が追加された。 遠隔管理の通り道そのものが正規の製品であるため、 設置されていること自体は不正の証拠にならない

3系統目で使われた NetSupport Manager（5月）と MeshCentral（10月以降）は、 どちらも正規の製品である（出典1）〈重要〉—— 脆弱性は使われていない（本記録の明示）。

보안뉴스 はこの点を的確に言い切っている—— 「메시센트럴은 정상 프로그램이므로 설치 여부보다 배포 경로와 설치 뒤 행동을 봐야 한다」 （MeshCentral は正規のプログラムなので、 入っているかどうかより配布の経路と設置後の行動を見るべきだ）（出典2。原文韓国語）。

ANY.RUN は、暗号化の活動を観測しなかったと明記したうえで、 回復パスワードの取得・防御機能の無効化・居座りが一体になること自体が 大きな危険であると述べている（出典1。原文英語）〈重要〉。

「ランサムウェアではなかった」で調査を閉じると、 ②と③が残ったまま運用に戻る（本記録の評価）〈重要〉—— 除外設定が残っていれば次の検体は検知されず、 回復パスワードが残っていれば暗号化は防御として働かない（本記録の評価）。

  • 「DMARC を通った」は正規性の根拠にならない
    1系統目の送信ドメインは攻撃者自身が管理しており、 SPF・DKIM・DMARC の検査をすべて通過していた（出典1）。 メール認証は「表示される差出人ドメインを使う権限があるか」を見る仕組みで、 攻撃者が自分のドメインを正しく設定すれば全部通る（本記録の明示）
    取るべき行動 メールの真正性に関する社内の説明文から 「認証を通っているので安全」という趣旨の記述を外す。 行政・金融・取引先からの「重要な通知」の確認手順を、 リンクではなく既知の窓口へ自分で入り直す形に書き換える。 **本件は本文に受信者の実在の事業者番号が入っており、 「自分の番号を知っている」が正規性の根拠として働いてしまう**
  • 狙われているのは業種ではなく「外部の通知に従って手続きを進める業務」の動線である
    3系統の体裁は「許可番号の失効」「口座の再有効化」「約款の変更」であり、 いずれも業界を入れ替えればそのまま成立する（出典1。本記録の評価）
    取るべき行動 自社で「外部から来る通知に従って手続きを進める業務」を洗い出す （許認可・業務口座・請求・取引先登録）。 動線ごとに確認先と報告先を1行で書いた手順を現場に配る。 **全社一律の教育ではなく、動線を持つ職務に絞って配る**
  • 「ランサムウェアではなかった」で調査を閉じると、防御が外れたまま運用に戻る
    3系統目では暗号化活動が観測されない代わりに、 BitLocker の回復パスワードの取得・Defender への除外追加・ CastleRAT の設置が行われていた。 ANY.RUN は、回復パスワードへの到達と防御の弱体化と居座りが 一体になること自体が大きな危険であるとしている（出典1。原文英語）
    取るべき行動 インシデント対応の終結条件に 「マルウェア対策の除外設定の棚卸しと復元」 「許可していない遠隔管理エージェントの除去」 「BitLocker の回復パスワードの再生成」を明記する。 **暗号化の有無を終結の判断に使わない**
  • 端末の管理者権限の扱いが、同じ誘導で到達できる深さを決める
    2系統目の `higeleveltask_x64.exe` の UAC 回避について、 ANY.RUN は「侵害されたアカウントが既にローカルの管理者である必要がある」と 明記している（出典1。原文英語）。 3系統目の CastleRAT の昇格も同じ前提に立つ（出典1）
    取るべき行動 日常業務の端末からローカル管理者権限を外す計画を持つ。 外せない業務（現場の機器の設定・特定の業務アプリ）を列挙し、 例外の件数と期限を経営の指標として見る。 **この一点が2系統に同時に効く**
