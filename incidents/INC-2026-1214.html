INC-2026-1214UPS管理ソフト PowerPanel 悪用でDC侵害

Symantec は2026年11月18日、UPS（無停電電源装置）管理ソフト CyberPower PowerPanel Business の 「電源イベント時にスクリプトを実行する」設定機能が、Windows ドメインコントローラ上で 攻撃者に悪用され、投入した .cmd スクリプトが SYSTEM 権限で実行されていたと公表した—— 攻撃者はアンチウイルス停止ツールを配置し、ロックされた ntds.dit を ボリュームシャドウコピー経由で複製して Active Directory の資格情報データベースを収集し、 DLL サイドローディングで常駐型インプラントを仕込んだ。被害組織・初期侵入経路・ 攻撃者の帰属はいずれも公表されていない

不正アクセス・侵害初報のみ有名事象として記録（日本と直接の関係は薄い）設計・実装上の不備公表されていない／不明
初報: 2026年11月18日（Symantec Threat Intelligence のレポート公開日） 最終更新: 2026年11月20日（本記録の作成時点）

Symantec Threat Intelligence は2026年11月18日のレポートで、ある組織の Windows ドメインコントローラ上で、CyberPower の UPS 管理ソフト PowerPanel Business（PPB）が 遠隔コマンド実行の経路として使われていた侵害を報告した（出典1）〈重要〉。 PPB は管理コンソールの REST ファイルアップロード機能（TCP 3052）を持ち、 アップロードされたスクリプトを extcmd フォルダに保存して、電源イベント発生時に SYSTEM 権限で実行する（出典1）。 攻撃者は pp?????.cmd という名前のスクリプトを投入し、ppbed.exe の子プロセスとして SYSTEM で走らせた（出典1）。 スクリプトは certutil と curl でツールを取得・デコードし、netstat で状況を確認し、 PowerShell から .NET アセンブリをリフレクションでメモリ上に読み込ませた（出典1）。 攻撃者は .NET 製のアンチウイルス停止ツール（wupd.exe）を配置したうえで、 ntdsutil ifm で Active Directory データベースの抽出を試み、 うまくいかないと esentutl /vss に切り替えてボリュームシャドウコピーから ロック中の ntds.dit を複製し、reg save で SYSTEM レジストリハイブも保存した（出典1）。 永続化には SYSTEM プロファイル配下から起動する upnpcont.exe が使われ、 これが悪性の atl.dll を読み込む DLL サイドローディングの形を取っていた（出典1）。 Symantec は、収集スクリプトが侵害の最中に何度も書き換えられたことから 「人間の操作者が実時間で作業していた」と読んでいる（出典1）。 データの持ち出しもランサムウェアも観測されておらず、動機は不明とされる（出典1）。 被害組織の名称・業種、攻撃者の帰属はいずれも示されていない（出典1）〈未確定2〉〈未確定3〉。

攻撃の経過

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

**脆弱性の悪用ではなく、製品が備えた「スクリプト実行」機能の悪用である**（出典1）〈重要〉—— **PPB は電源イベントに紐づけた .cmd スクリプトを SYSTEM 権限で実行する。 攻撃者は管理コンソールのファイルアップロード経由でスクリプトを置き、 サービスやスケジュールタスクを新規に作らずに SYSTEM 実行を得た**（出典1）。 **使われた道具はほぼ Windows 同梱のもの（certutil・curl・netstat・PowerShell・ ntdsutil・esentutl・reg・vssadmin・robocopy）で、持ち込みは アンチウイルス停止ツールと常駐インプラントに絞られている**（出典1）。

  1. 1. 初期侵入[1]
    **攻撃者が PPB の管理コンソール（TCP 3052）に到達し、REST のファイルアップロード機能で `pp?????.cmd` を投入した**（出典1）。 **ネットワークへの侵入経路、コンソールへの到達手段はいずれも公表されていない**〈未確定1〉—— **Symantec が可能性として挙げたのは、管理者資格情報の窃取、既定の管理者パスワード、 ハードコードされた資格情報、ファイルアップロードのパストラバーサルである**（出典1）。
    根拠: Tomcat の一時ファイル upload_[RANDOM].tmp と、extcmd 配下の pp?????.cmd 群（出典1）
  2. 2. 実行[1]
    **電源イベントに紐づけられたスクリプトが、PPB のサービスプロセス ppbed.exe の子として SYSTEM 権限で実行された**（出典1）〈重要〉—— **新しいサービスもスケジュールタスクも作られていない。 「正規の設定機能が、そのまま遠隔コマンド実行の経路になった」のが本件の芯である**（出典1）。
    根拠: ppbed.exe を親に持つ cmd.exe / powershell.exe のプロセス系列（出典1）
  3. 3. 内部探索[1]
    **certutil と curl でツールを取得・デコードし、外向きの通信が通るかを試し、 netstat で接続状況を確認した**（出典1）。 **PowerShell が .NET アセンブリをリフレクションでメモリ上に読み込む動きもあり、 その段階で読み込まれたのは「挨拶を表示するだけの無害な検証用バイナリ」だった**（出典1）—— **攻撃者が実行経路の成否を確かめていたと読める**（本記録の読み）。
    根拠: certutil / curl / netstat の実行と、hello.exe（挨拶のみを表示する検証用バイナリ）（出典1）
  4. 4. 検知回避[1]
    **.NET 製のバイナリ wupd.exe が配置され、Symantec はこれをアンチウイルス停止ツール （antivirus killer）と判定した**（出典1）。
    根拠: wupd.exe（SHA-256 bdea6084…c835e26）（出典1）
  5. 5. 認証情報アクセス[1]
    **攻撃者は Active Directory データベースの取得を試み、スクリプトを何度も書き換えた**（出典1）〈重要〉—— **まず `ntdsutil ifm`（インストールメディア作成機能）を使い、 次に `esentutl /vss` に切り替えて、ボリュームシャドウコピーから ロック中の ntds.dit を複製した**（出典1）。 **あわせて `reg save` で SYSTEM レジストリハイブを保存している**（出典1）—— **ntds.dit の復号には SYSTEM ハイブ内の鍵が要るため、この2つは組で意味を持つ**（本記録の説明）。
    根拠: ifm.cmd / ifm2.cmd / ifm3.cmd / ifm4.cmd の各版、vssadmin・robocopy の使用（出典1）
  6. 6. 永続化[1]
    **SYSTEM プロファイル配下のパスから upnpcont.exe が起動され、 これが悪性の atl.dll を読み込んだ（DLL サイドローディング）**（出典1）。 **インプラントが生んだプロセスは ppbed.exe と services.exe に遡れる**（出典1）。
    根拠: upnpcont.exe（SHA-256 5b2285f7…4a9c3fe）と atl.dll（SHA-256 d4032e61…554b7d95）（出典1）
  7. 7. 収集[1]
    **vssadmin と robocopy を使って、複製した資格情報データベースなどを集約した**（出典1）。 **持ち出し（exfiltration）は観測されていない**（出典1）〈未確定4〉。
    根拠: vssadmin・robocopy の使用（出典1）

悪用されたのは脆弱性ではなく、製品が備えた正規の「スクリプト実行」機能だった原因・手口出典 [1]

PowerPanel Business は、停電などの電源イベントを検知したときに、管理者が指定した.cmd スクリプトを実行する設定を持つ。実行はサービスプロセス ppbed.exe の子としてSYSTEM 権限で行われる（出典1）〈重要〉。攻撃者はこの機能に対して、管理コンソールの REST ファイルアップロード（TCP 3052）からpp?????.cmd を投入し、SYSTEM 権限での実行を得た（出典1）。Symantec はこの機能を「スクリプトを受け取り、保存し、SYSTEM として実行するだけ」（原文英語: "simply accepts a script, stores it, and runs it as SYSTEM"）と書いている（出典1）。つまり、修正プログラムで閉じる類の欠陥ではない。 閉じられるのは「誰がそのコンソールに到達できるか」の側だけである（本記録の読み）。

ドメインコントローラの資格情報データベースが複製された被害規模・影響範囲出典 [1]

攻撃対象は Windows ドメインコントローラで、Active Directory データベース（ntds.dit）が複製された（出典1）〈重要〉—— ntds.dit にはドメイン内の全アカウントの資格情報が入る。 攻撃者は ntdsutil ifm を先に試し、うまくいかないと esentutl /vss に切り替えてボリュームシャドウコピーからロック中のファイルを複製し、さらに reg save で SYSTEM レジストリハイブを保存した（出典1）。持ち出しは観測されていない（出典1）〈未確定4〉—— ただし Symantec は、指標が見つかった組織に対しては「AD の資格情報が露出したと想定し、krbtgt のリセットと広範な資格情報の入れ替えを計画せよ」と勧めている（出典1）。「持ち出しが確認されていない」ことと「資格情報が安全である」ことは別である（本記録の読み）。

スクリプトが何度も書き換えられたことから、人間の操作者が実時間で動いていたと読まれている発覚の端緒出典 [1]

収集用スクリプト（ifm.cmd 系）には4版以上の異なるハッシュがあり、Symantec はこの試行錯誤を「人間の操作者が実時間で作業していた」証左と読んでいる（出典1）。これは自動化された一括攻撃ではなく、手作業で環境に合わせて調整された侵害だという読みである（出典1。帰属の主張ではない）。攻撃者の素性・動機は公表されていない（出典1）〈未確定3〉。データの持ち出しもランサムウェアも観測されていないため、Symantec 自身も動機を「不明」としている（出典1）。

Symantec は、電源管理ソフトを「遠隔管理ツールと同じ疑いの目で扱う」よう求めている対策・注意喚起出典 [1]

Symantec が挙げた対策は次のとおりである（出典1）。
1. PPB の全インスタンスを洗い出し、TCP 3052 を指定した管理ホストのみに制限する。インターネット・他のサーバ・利用者ネットワークに公開しない。
2. 既定の管理者パスワードを変更し、PPB にパッチを当て続ける。
3. 全 PPB ホストの extcmd および temp\profile\extcmd フォルダを製品既定と突き合わせ、見覚えのないスクリプトは悪性とみなす。イベントとコマンドの紐づけ設定も点検する。
4. 指標が見つかったら AD の資格情報が露出したと想定し、krbtgt のリセットと広範な資格情報の入れ替えを計画する。
5. 電源管理ソフトが動く機器を高価値資産として扱い、プロセス単位の監視を適用する。 PPB は停電時にサーバを安全に停止させる役目のため、仮想化基盤・データベースサーバ・ファイルサーバといった「攻撃者が最も欲しい機器」に同居しやすい（出典1）—— この同居が、本件で「UPS 管理ソフトの一機能」が「ドメインコントローラ上の SYSTEM 実行」に直結した理由である（本記録の読み）。

被害組織・初期侵入経路・帰属は公表されていない未確定事項出典 [1]

公表されているのは手口・プロセス系列・侵害指標・推奨対策である（出典1）。公表されていないのは、被害組織の名称と業種・国〈未確定2〉、ネットワークへの初期侵入経路と PPB コンソールへの到達手段〈未確定1〉、攻撃者の帰属〈未確定3〉、侵害の時期、データ持ち出しの有無〈未確定4〉である。 「既知の弱点（既定パスワード・ハードコード資格情報・アップロードのパストラバーサル）が使われた」とは書かれておらず、可能性の列挙にとどまる（出典1）—— 本記録はこれを原因として断定しない。

  • 「管理ソフト」の棚卸しに、電源・空調・監視といった設備系ソフトを入れる
    **本件で入口になったのは UPS 管理ソフトである**（出典1）〈重要〉—— **遠隔管理ツール（RMM）やバックアップ製品は資産管理の対象になっていても、 UPS 管理ソフトは「設備の付属品」として台帳から漏れやすい**（本記録の評価）。 **しかも停電時にサーバを止める役目のため、最も重要な機器に同居している**（出典1）。
    取るべき行動 電源・空調・物理監視などの設備系管理ソフトについて、 ①どのホストに入っているか ②管理画面のポートがどこから到達できるか ③スクリプト実行機能を持つか の3点を棚卸しする。 ドメインコントローラ上に設備系ソフトが同居していないかを特に確認する。
  • 「パッチで閉じられない機能」の扱いを決めておく
    **悪用されたのは脆弱性ではなく、製品の正規機能である**（出典1）〈重要〉—— **脆弱性管理の仕組みは CVE 番号が付いたものを追うが、 本件の芯である「任意スクリプトを SYSTEM で実行する設定機能」には番号が付かない**（本記録の評価）。 **閉じられるのは到達経路と権限の側だけである。**
    取るべき行動 製品が備える「スクリプト・コマンド実行機能」を一覧にし、 機能ごとに実行権限・到達できる経路・変更の監視があるかを記録する。 閉じられないものは、到達制限と監視を代替策として明文化する。
  • ドメインコントローラの同居物を、権限の観点で見直す
    **本件は「UPS 管理ソフトの一機能」が「ドメインコントローラ上の SYSTEM 実行」に 直結した**（出典1）〈重要〉—— **ドメインコントローラ上で SYSTEM を取られれば、AD の資格情報データベース全体が 射程に入る。実際に ntds.dit と SYSTEM ハイブが複製された**（出典1）。
    取るべき行動 ドメインコントローラ上で動いている非 AD のソフトウェアを列挙し、 SYSTEM 権限で動くもの・外部から管理画面に到達できるものを別ホストへ移す計画を立てる。 移せないものは、管理アクセスの発信元を限定する。
  • 「持ち出しは確認されていない」で資格情報の入れ替えを見送らない
    **Symantec は持ち出しを観測していないが、指標が出た組織には krbtgt のリセットと広範な資格情報の入れ替えを勧めている**（出典1）〈重要〉—— **ntds.dit が複製された時点で、資格情報は「露出した」と扱うのが前提である**（本記録の評価）。 **krbtgt のリセットは業務影響があるため、事後に判断すると先送りされやすい。**
    取るべき行動 AD データベースの複製の痕跡が見つかった場合の手順（krbtgt の二段リセット・ 特権アカウントの入れ替え・影響範囲と停止時間）を、事案が起きる前に文書化し、 実施の判断者を決めておく。
セキュリティ技術者への示唆
  • PPB の管理ポート（TCP 3052）の到達範囲を今日確認する
    **攻撃者はこのポートの REST ファイルアップロードからスクリプトを投入した**（出典1）〈重要〉—— **Symantec の第一の推奨は「全インスタンスを洗い出し、TCP 3052 を指定した 管理ホストのみに制限する」である**（出典1）。
    取るべき行動 ネットワーク内で TCP 3052 を待ち受けているホストを走査し、 インターネット・利用者ネットワーク・他サーバから到達できないよう絞る。 既定の管理者パスワードが残っていないかも併せて確認する。
  • extcmd フォルダの中身を製品既定と突き合わせる
    **投入されたスクリプトは extcmd フォルダ（および temp\profile\extcmd）に `pp?????.cmd` の名前で保存された**（出典1）〈重要〉—— **Symantec は「製品既定と比べ、見覚えのないスクリプトは悪性とみなせ」と書いている**（出典1）。
    取るべき行動 PPB の全ホストで extcmd と temp\profile\extcmd の一覧を取得し、 意図して置いたスクリプト以外が無いかを確認する。 イベントとコマンドの紐づけ設定も点検し、設定の差分を定期的に取る仕組みにする。
  • ppbed.exe を親とするプロセス生成を検知対象に加える
    **スクリプトは ppbed.exe の子として SYSTEM で動き、インプラント由来のプロセスも ppbed.exe と services.exe に遡れた**（出典1）〈重要〉—— **電源イベントは実際には年に数回しか起きないため、 この親子関係は誤検知の少ない手掛かりになる**（本記録の評価）。
    取るべき行動 EDR / Sysmon で ppbed.exe を親とする cmd.exe・powershell.exe・certutil.exe の プロセス生成を検知ルールにし、電源イベントの実績と照合する運用を決める。
  • ドメインコントローラ上の ntdsutil / esentutl / vssadmin / reg save を即時警報にする
    **攻撃者は ntdsutil ifm → esentutl /vss と手を変えて ntds.dit を複製し、 reg save で SYSTEM ハイブも取った**（出典1）〈重要〉—— **同じ目的のスクリプトが4版以上書き換えられており、 検知の機会は一度ではなく複数回あった**（出典1。本記録の読み）。
    取るべき行動 ドメインコントローラ上での ntdsutil・esentutl・vssadmin・reg save の実行を 変更管理の記録と突き合わせ、計画外の実行を即時に当番へ上げるルールを作る。
  • 正規名の実行ファイルが異常なパスから動く事象（DLL サイドローディング）を見る
    **永続化は SYSTEM プロファイル配下の upnpcont.exe が悪性 atl.dll を読み込む形だった**（出典1）。 **ファイル名だけを見ていると正規のものに見える**（本記録の評価）。
    取るべき行動 実行ファイル名と実行パスの組み合わせを基準化し、 正規名が本来と違うパスから起動する事象を検知する。 ドメインコントローラではアプリケーション制御（許可リスト）の導入を検討する。
