**本件の「攻撃」は、侵入の手口ではなく常駐の手口である**（本記録の整理）〈重要〉。 **Rapid7 が示したのは、正規のオープンソース製品を 検知されない形に作り直す作業の内容である**（出典1）。 **攻撃者は SoftEther の検知表面を6か所に分けて潰している**（出典1。整理は本記録）—— **①ファイルとしての見た目（PE メタデータ）、 ②ホスト内の文字列（デバッグ表示・サービス名・レジストリ・ HTTP 401 のエラーページ・ファイアウォール規則名）、 ③プロトコルの HTTP 端点、 ④ハンドシェイクの透かし、 ⑤付属の資源ファイル（hamcore.se2）の存在、 ⑥平文の設定ファイル。** **①〜④は外から見た姿、⑤⑥はホスト上の痕跡である**（本記録の整理）。 **一方で、③④の改変には副作用がある**（出典1）〈重要〉—— **素の SoftEther のクライアントとサーバは、この版とハンドシェイクできない。** **逆に言えば、この版の端点同士しかつながらない閉じた網になっている。** **Rapid7 は追加のマルウェア機能を1つも見つけていない**（出典1）—— **バックドアを探したが無かった。**

  • **Rapid7 は、検知の指針とともに「その指針の限界」を公表した** （出典1。事実）〈重要〉—— **「samples we have seen all use the same NtMonitor branding internally (despite the PE metadata differing across samples), this is the easiest change for the threat actor to implement next. Similarly, the HTTP endpoints and watermark can be swapped out trivially.」** （原文英語。本記録が訳した: 「我々が見てきた試料はすべて 内部的に同じ NtMonitor の名称を使っているが（PE メタデータは 試料間で異なるにもかかわらず）、これは攻撃者が次に実装するのが 最も容易な変更である。同様に、HTTP の端点と透かしも 簡単に差し替えられる。」）
    トレードオフ: **限界を明示すれば、防御側が指標を入れて安心する事故を防げる** （本記録の評価）——**一方、攻撃者に「どこを変えれば外れるか」を 教えることにもなる。** **ただし本件では後者の損失は小さい**（本記録の評価）〈重要〉—— **攻撃者は既にこれらを変える判断をしてこの版を作っており、 次に何を変えればよいかを Rapid7 から教わる必要が無い。**
  • **Rapid7 は、顧客の環境に由来する情報（復号済み設定の個々の IP・件数）を 公表しなかった**（出典1。本記録の確認。事実）—— **公表したのは「AS 20473 の内側だった」という粒度までである。**
