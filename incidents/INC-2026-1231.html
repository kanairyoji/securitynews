制御プレーンへの露出は無く、これはデータプレーンのみの問題である（出典1〜5。原文英語を訳出）

境界機器の脆弱性に対する定番の緩和は 「管理インターフェースへの到達元を絞る」 である。ところが本件はその対策が効かない（本記録の整理）。攻撃は仮想サーバが処理する通常のトラフィックとして届く——つまりサービスを提供している経路そのものが攻撃面になる。

公開サービスを載せている仮想サーバでは、到達元を絞ることもできない。そして F5 は 「これらの脆弱性に緩和策は無い」 としている（出典6）〈重要〉。

本記録として押さえるのは、「示していない」は「悪用されていない」とは違うという1点である（本記録の明示）。同じ製品の同じコンポーネントで、2か月前には修正前から悪用が起きていた。

「公表されていない要求」とされるため、自前の検知規則が作れない未確定事項

F5 の記述は6件すべてについて、「公表されていない要求（undisclosed requests）が TMM を停止させうる」である（出典1〜5。原文英語を訳出）〈重要〉。

要求の形・プロトコル・必要な前提の詳細は示されていない。悪用の手がかりを渡さないための記述とみられるが、F5 は理由を説明していない（本記録の推定）。

この書き方には実務上の帰結がある（本記録の整理）。

  • WAF・IDS で独自の検知規則を作れない。遮断すべきパターンが分からないため、「パッチが当たるまで WAF で凌ぐ」という選択肢が取れない
  • 過去ログを遡って「既に試行されていたか」を調べられない。探すべき痕跡が無い
  • したがって F5 の「緩和策は無い」という記述と整合する（出典6）

対比として、同じ日に公表された PHP の脆弱性群（INC-2026-1230）では、Cloudflare が既知の攻撃パターンに対する WAF ルールを提供し、さらに「WAF では見えない範囲」まで明示していた。本件にはその層が無い〈重要〉。

加えて、修正バージョンの対応表を本記録は取得できていない〈差異3〉—— F5 の K 記事本体（my.f5.com）は JavaScript 描画のため取得できなかった。適用対象の特定には K 記事の確認が必須である（K000163946・K000163940・K000163939・K000163941・K000163937・K000163942。出典1〜5）。

システム構成□ BIG-IP（21.1.0 系・17.5.0 系・17.1.0 系）、 BIG-IP Next for Kubernetes、または BIG-IP Next CNF を運用している。**これが本件の対象製品である**（出典1〜5）〈重要〉—— **ただし BIG-IP Next CNF の扱いは資料間で一致していない**〈差異2〉。 **技術サポート終了（EoTS）のバージョンは F5 の評価対象外である** （出典1・2）——**該当する場合、評価も修正も提供されない。**
システム構成□ iRule の中で `PEM::subscriber`・`MR::message route`・ `PSC::ip_address`・`GENERICMESSAGE::route` のいずれかを使っており、 その iRule が仮想サーバに適用されている。**これがクリティカル4件（CVE-2026-121805・120292・120285・116953）の 成立条件である**（出典1〜4）〈重要〉—— **CVSSv4.0 のベクタは `AT:N`（攻撃前提条件なし）であり、 構成の該当性はスコアに表れない**（本記録の整理）。 **該当する場合、認証なしの TMM 停止とコード実行に至りうる。**
認証・認可□ BIG-IP APM を使っており、Client Information エージェントと Endpoint Security エージェントを含む毎要求ポリシーを 仮想サーバに適用している。**これが CVE-2026-123637（CVSSv3.1 9.8）の成立条件である**（出典5） 〈重要〉—— **端末の状態を検査してアクセスを判断する構成であり、 リモートアクセスの用途で広く使われる**（本記録の評価）。 **該当する場合、認証の入口が攻撃面になる。**
認証・認可□ BIG-IP APM の Access Profile を SAML サービスプロバイダ（SP）として 設定し、仮想サーバに適用している。**これが CVE-2026-126822（CVSSv3.1 7.5）の成立条件である**（出典5）—— **影響はサービス拒否までで、コード実行は挙げられていない**（出典5）。 **該当する場合、フェデレーション認証の経路が止まり、 連携先アプリケーションへのログインが一斉に失敗する** （本記録の評価）〈重要〉。
運用・監視□ BIG-IP の TMM の異常終了・再起動を監視しておらず、 原因不明の再起動をセキュリティ事象として扱う手順が無い。**F5 は要求の内容を「公表されていない」としており、 通信の側に探すべきパターンが無い**（出典1〜5）〈重要〉—— **結果としての TMM 再起動が現実的な唯一の観測点になる** （本記録の評価）。 **該当する場合、成立しても障害として処理され気づけない。**
体制・契約□ Engineering Hotfix を適用した機器の台帳を持たず、 標準リリースへの移行計画を管理していない。**6件のオーバーフローについて F5 は標準リリースではなく Engineering Hotfix を挙げている**（出典6）〈重要〉—— **該当する場合、Hotfix のまま運用が固定され、 次の脆弱性で適用可能な修正を特定できなくなる**（本記録の評価）。
