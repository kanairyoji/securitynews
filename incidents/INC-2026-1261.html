公告の第4項は「預計可能損失或影響:目前評估對公司營運尚無重大影響。」（予想される損失または影響:現時点の評価では当社の営運に重大な影響は無い。原文中国語）である（出典1）。本記録の作成者が2026年11月23日に3サービスを直接確認した結果は、次の通りである（本記録の観測）〈重要〉—— ①iPair 愛情公寓（i-part.com.tw）は HTTP 200 を返し、「iPair 愛情公寓官方公告」として「より安定し安全な利用体験を提供するため、愛情公寓は全面的なシステムアーキテクチャの最適化を行い、情報セキュリティ防護を強化する」「今回のアップグレードの範囲が広いため、作業全体に多くの時間を要する」と掲出していた（出典3）。②SweetRing（sweetring.com）は HTTP 503 とともに「系統維護公告」を返し、「プラットフォームの情報セキュリティを強化しサービス品質を確保するため、ウェブサイトおよびアプリは現在システムの安全検査と維護作業を行っている。維護期間中はログイン・チャットおよびその他のプラットフォーム機能を停止する」と説明していた（出典4）。③weTouch（wetouch.me）は内容を伴わない HTTP 503（564バイト）のみを返した（出典5）。つまり、主力3サービスのいずれも通常提供されていない（本記録の観測）。 報道（出典2）も同日正午時点で同様の状態を確認しており、weTouch については HTTP 403 だったと伝える（齟齬3）。ここが本件の読みどころである（本記録の評価）〈重要〉—— 「営運に重大な影響は無い」という記述は、会計上・業績上の影響を指しているとも読めるが、公告はその限定を書いていない。 交友サービスの事業者にとって、ログインとチャットが止まることはサービスの全停止に等しい（本記録の読み）。 本記録は停止が本件に起因すると断定していない——維護公告はいずれも11月21日の侵入に言及していない（齟齬4）〈未確定3〉。断定できるのは、時期と理由（情報セキュリティの強化・安全検査）が重なっていることだけである。

「営運への影響」を業績の言葉で書くと、利用者の体験とずれる評価・解釈出典 [1] [3] [4]

本記録の評価として、日本の読者が自組織に移せる論点はここにある。 適時開示の文面は、投資家向けの枠組みで書かれる（本記録の読み）〈重要〉—— 「営運に重大な影響は無い」は、売上・損益・継続企業の前提への影響が当面大きくないという意味で使われることが多い。 ところが同じ文は、利用者には「サービスは普通に使える」と読める。 本件では、公告の2日後に主力3サービスのログインとチャットが止まっていた（本記録の観測）。 この乖離は、嘘をついたから生じたのではなく、同じ言葉が二つの読者に別の意味で届くから生じる（本記録の評価）。 自組織で確かめるべきことは三つある（本記録の評価）—— ①適時開示の「影響」の記述に、何の影響を指しているか（財務／サービス提供／データ）を明示する欄があるか。②市場向けの開示と、利用者向けの告知・ステータスページを、同じ事案について相互に参照させる手順があるか。③サービスを止めるときに、停止の理由を「メンテナンス」と書くか「セキュリティ事案」と書くかの判断基準を、事案の前に決めてあるか。 ③は難しい判断である（本記録の評価）——事案と明記すれば利用者は自衛できるが、影響範囲が未確定のまま不安を広げる。メンテナンスと書けば混乱は小さいが、後から事案と分かったときに信頼を失う。 決めるべきは「どちらを選ぶか」ではなく「どの事実が揃ったらどちらに切り替えるか」である（本記録の評価）。

判断評価評価の根拠と留保
侵入を発見した当日（土曜日）の18時15分に重大訊息を提出した。 侵入された設備・経路・流出の有無がいずれも未確定のままの開示である機能した**本記録の作成者の評価である。** **事實發生日と同日、 それも土曜日の夕刻に出している点は速い**（出典1）〈重要〉—— **「疑い」ではなく「侵入を発見した」と断定で書き、自社の情報セキュリティチームが 当日に検知したことまで示している（本記録の評価）。** **ただし、速さの代償として内容は薄い——7項目のうち実質的な情報は 「不明なIPの侵入を発見した」「緊急対応機構を起動した」「営運に重大な影響は無い」の3点のみである。**
侵入された情報設備の種類・侵入の経路・データ流出の有無のいずれにも触れず、 「営運に重大な影響は無い」という評価を示した。「其他應敘明事項」は「無」とした不十分**本記録の作成者の評価である。** **交友サービスは、年齢・性別・位置情報・顔写真・ チャットの内容という最も機微な情報を扱う事業である（本記録の読み）**〈重要〉—— **その事業者が「不明なIPの侵入」を公告しながら、会員情報への言及を一切置かないことは、 利用者が自衛の判断（パスワードの変更・利用の停止）を下す材料を欠いた状態を作る（本記録の評価）。** **「流出は無かった」と書かれているのではなく、論点に触れていない**（齟齬2）。 **さらに、本記録の確認時点で主力3サービスが揃って通常提供されていないことは、 「営運に重大な影響は無い」という記述と整合しない**（齟齬1）。
重大訊息ではサービスの停止に触れないまま、各サービスの側で個別に維護公告を掲出した。 iPairは「システムアーキテクチャの最適化と情報セキュリティ防護の強化」、 SweetRingは「システムの安全検査と維護」とし、weTouchは説明のないHTTP 503を返している不十分**本記録の作成者の評価である。** **市場向けの開示（重大訊息）には停止の記述が無く、 利用者向けの維護公告には事案の記述が無い**（出典1・3・4。齟齬4）〈重要〉—— **両方を読んだ者だけが、11月21日の侵入と3サービスの停止が同じ時期に起きていると分かる（本記録の読み）。** **weTouch は説明を伴わない HTTP 503 であり、利用者に対する告知が存在しない**（出典5）。 **評価できる点もある——SweetRing は「VIP会員の有効期間をサービス停止日数ぶん自動延長し、 別途の申請は不要」と明記しており、有料会員の権益への配慮を先に示している（本記録の評価）。**
CISO・経営層への示唆
  • 適時開示の「影響」の記述に、何の影響を指しているかを明示する
    **本件の公告は「目前評估對公司營運尚無重大影響」（現時点の評価では営運に重大な影響は無い）と 書いたが、本記録が2日後に確認した時点で主力3サービスは揃って通常提供されていなかった** （出典1。本記録の観測）〈重要〉—— **「営運への影響」は投資家向けには業績の話として読まれ、 利用者には「普通に使える」と読まれる（本記録の評価）。** **同じ言葉が二つの読者に別の意味で届く。**
    取るべき行動 適時開示の雛形に「財務への影響」「サービス提供への影響」「データへの影響」を 別の欄として設け、それぞれに「未確定」も選べるようにする。 開示の原稿を、利用者の立場で読む担当者に通してから出す。
  • 市場向けの開示と利用者向けの告知を、同じ事案として相互に参照させる
    **本件では、重大訊息にサービス停止の記述が無く、 各サービスの維護公告に事案の記述が無い**（出典1・3・4。齟齬4）〈重要〉—— **両方を読んだ者だけが、同じ時期の出来事だと分かる（本記録の読み）。** **weTouch には説明を伴わない HTTP 503 が返るだけで、告知自体が存在しない**（出典5）。
    取るべき行動 事案の公表時に、市場向け開示・サービスの告知・ステータスページ・問い合わせ窓口の 文面を同時に差し替える手順を作り、互いへのリンクを含める。 停止中のサービスについて、告知の無いドメインが残らないことを確認する項目を手順に入れる。
  • 停止の理由を「メンテナンス」と書くか「セキュリティ事案」と書くかの切り替え基準を、事案の前に決める
    **本件の維護公告は「情報セキュリティ防護の強化」「システムの安全検査と維護」という 表現を用い、侵入には言及していない**（出典3・4）〈重要〉—— **事案と明記すれば利用者は自衛できるが、影響範囲が未確定のまま不安が広がる。 メンテナンスと書けば混乱は小さいが、後から事案と分かったときに信頼を失う（本記録の評価）。**
    取るべき行動 「どの事実が揃ったら、メンテナンス表記から事案の明示に切り替えるか」を 平時に決めておく（例: 個人データへの到達が否定できないと判明した時点）。 判断者と切り替えの文面を事前に用意し、切り替えの記録を残す。
  • 有料会員への補償方針を、再開前に、申請を要しない形で示す
    **SweetRing の維護公告は「VIP会員の権益を保障するため、維護完了後、 影響を受けたVIP会員の有効期間はサービス停止日数に応じて自動的に延長され、 別途の申請は不要である」と明記している**（出典4）〈重要〉—— **停止の長さが読めない状況で、利用者が最初に心配するのは「払った分はどうなるのか」であり、 そこに先に答えている（本記録の評価）。**
    取るべき行動 有料サービスの停止時に適用する補償（期間の自動延長・返金・代替手段）を 平時に決め、告知の雛形に含める。申請を要しない自動適用を既定とし、 適用の範囲（有料会員のみか、無料会員を含むか）も明記する。
  • 自社検知であることを開示に書く
    **本件の公告は「本公司資安團隊於當日偵測發現後」と明記し、 自社の情報セキュリティチームが当日に検知したことを示している**（出典1）〈重要〉—— **外部からの指摘で気づいたのか自社で気づいたのかは、同種の開示でしばしば省かれる（本記録の評価）。** **書かれていれば、読者は検知能力の有無を判断できる。**
    取るべき行動 インシデントの第一報の雛形に「検知の主体（自社監視／外部からの指摘／取引先からの連絡）」の 欄を設ける。書けない場合は「検知の経緯は調査中」と明記する。
セキュリティ技術者への示唆
  • 会員データへの到達の有無を短時間で判定できるよう、参照記録を分けて保存する
    **本件は侵入の発見から2日が経った時点でも、データ流出の有無に言及が無い**（出典1）〈未確定2〉〈重要〉—— **「不明なIP」を特定できていることから到達元を識別できる記録はあったと読めるが、 会員データへの到達を否定できる記録が揃っているかは分からない（本記録の推定）。** **SweetRing が「安全検査」を継続していることは、確定が終わっていないことを示唆する。**
    取るべき行動 会員データのデータストアへの参照記録を、アプリケーションのログとは別に保存し、 「誰が・いつ・何件参照したか」を単独で検索できる状態にする。 侵害の想定下で「会員データへの到達を否定できるか」を机上で試し、足りない項目を追加する。
  • 会員向けサービスの基盤と社内の情報設備の境界を、切り離せる形にしておく
    **公告は「資訊設備」への侵入とのみ書き、会員向けサービスの基盤との関係に触れていない**（出典1）〈未確定1〉〈重要〉—— **一方で、本記録の確認時点で3サービスはいずれも通常提供されていなかった（本記録の観測）。** **境界が切り離せない構成では、どちらが侵害されたかの説明そのものができない（本記録の評価）。**
    取るべき行動 社内の情報設備と会員向けサービスの基盤の通信経路を図にし、 どこを閉じれば会員向けサービスを守れるかを決めておく。 閉じる操作の手順と所要時間を実測し、復旧の条件も併せて記録する。
  • 停止中のドメインすべてに、説明のある応答を返す
    **本記録が2026年11月23日に確認した時点で、weTouch（wetouch.me）は 内容を伴わない HTTP 503（「503 Service Temporarily Unavailable」・564バイト）を返していた**（出典5）〈重要〉—— **同じグループの SweetRing は HTTP 503 とともに維護公告を返しており、対応が分かれている（本記録の観測）。** **報道は同日正午時点で weTouch が HTTP 403 だったと伝えており、応答も安定していない**（齟齬3）。
    取るべき行動 停止時に全パスへ告知を返す構成（静的ページ＋適切なHTTPステータス）を、 運営するすべてのドメイン・アプリについて用意する。 停止の切り替え手順にドメインの一覧を含め、告知の無い応答が残らないことを確認する。
  • 到達元アドレスを識別できる監視を常時稼働させ、検知から封じ込めまでを手順にする
    **本件は自社の情報セキュリティチームが当日に検知し、同日に緊急対応機構を起動している**（出典1）〈重要〉—— **「不明なIP」と特定できていることは、到達元を識別できる監視があったことを示す（本記録の読み）。** **ただし検知の手段・時刻は公表されていない**〈未確定2〉。
    取るべき行動 外部からの到達を到達元アドレス単位で記録・警報化し、 検知から遮断までの操作を手順にして所要時間を実測する。 緊急対応の起動条件（誰が、どの事実で起動を宣言するか）を文書にする。

自組織に当てはまるか

該当する項目があれば、この事案と同じ構図が自組織でも成立しうることを意味します。
観点自社に当てはまるか該当する場合に何が起きうるか
体制・契約□ 適時開示の文面に「財務への影響」「サービス提供への影響」「データへの影響」を 分けて書く欄が無く、「影響は無い」が何の影響を指すか読者に委ねている本件は「営運に重大な影響は無い」と公告した2日後に、主力3サービスが揃って 通常提供されていなかった（出典1。本記録の観測）。 同じ言葉が投資家と利用者に別の意味で届く（本記録の評価）。
運用・監視□ 市場向けの開示と、利用者向けの告知・ステータスページを同時に差し替える手順が無く、 互いを参照させていない本件では重大訊息に停止の記述が無く、維護公告に事案の記述が無い（齟齬4）。 両方を読んだ者だけが同じ事案だと分かる（本記録の読み）。
データの保持□ 扱うデータに機微な属性（位置情報・顔写真・交際の希望・チャットの内容）を含み、 侵害時に「会員データへの到達を否定できる記録」が揃っていない本件は交友サービスの事業者が、会員情報に一言も触れずに開示を終えている（出典1。齟齬2）。 利用者が自衛の判断を下すにはこの一点が要る（本記録の評価）。
システム構成□ 社内の情報設備と会員向けサービスの基盤が同じネットワーク・同じ認証基盤を共有しており、 一方の侵害時に他方を切り離す手順が無い本件は「資訊設備」への侵入とのみ開示され、会員向けサービスとの関係が示されていない〈未確定1〉。 切り離せない構成では、影響範囲の説明そのものができない（本記録の評価）。
運用・監視□ 複数のドメイン・アプリでサービスを提供しており、停止時に説明のある応答を すべてのドメインで返せる構成になっていない本件では SweetRing は維護公告つきの503、weTouch は説明のない503を返していた（出典4・5）。 告知の無いドメインは、利用者にとって障害と事案の区別がつかない（本記録の読み）。
体制・契約□ 有料会員を抱えるサービスで、停止時の補償（期間の延長・返金）の方針を 事案の前に決めていない本件では SweetRing が「VIP会員の有効期間を停止日数ぶん自動延長・申請不要」と 再開前に明記した（出典4）。 停止の長さが読めない状況で、利用者が最初に心配するのは支払った分の扱いである（本記録の評価）。
