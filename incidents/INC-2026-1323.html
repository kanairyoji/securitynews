Accenture APEX Labs が、確認された被害組織1社の侵入を分単位で公開した（出典6）。最初の要求からの経過はこうである（出典6）〈重要〉—— T+0 にバージョン確認。T+1分で認証バイパス（セッションなしでコンテンツが返る）。T+9分で AWV コンポーネントへのファイルアップロード2件が受理。T+12分で Webシェル経由の最初のコマンド実行（Webサービスアカウントの権限）。T+15〜30分で root へ昇格——このとき副作用としてシステムログがリセットされた。T+32分で MiCollab の LDAP コネクタに保存されていた資格情報を取得し、LDAPS でドメインコントローラへ認証。T+36分で Webシェルの要求が Webサーバ・エラー・管理の各ログから除去。T+40分から攻撃者サーバへの HTTPS アップロードが約7時間。T+53分でディレクトリアカウントによる初回のネットワークログオン。T+1.5時間で Kerberoasting スクリプトを複数回実行。T+2時間で約2分のうちにフォレスト内の複数のドメインコントローラへ認証し、ユーザーレコードを書き出し。T+2.5〜4.5時間でファイル共有からデータベースの資格情報と平文の認証情報ファイルを取得し、サービスアカウントの資格情報を大量に試験。T+20〜23時間でバックアップサーバと業務データベースサーバへ移動し、ダンプして持ち出した。 この並びで最も重いのは32分の段である（本記録の評価）〈重要〉—— MiCollab は電話・Web・ビデオ会議の製品である。 しかしディレクトリ連携のためにドメインの資格情報を保持しており、root を取られた直後にそれが読み出された。 製品の侵害が、そのままドメインの侵害になっている。 本記録はこれを「ユニファイドコミュニケーション製品の資産区分の問題」として読む（本記録の評価）—— 電話システムは「業務システム」の台帳に載りにくく、ディレクトリ連携アカウントの権限設計も後回しになりやすい。 しかし本件では、そこが Active Directory への入口になった。 検知の機会は MiCollab の外側にあった（本記録の整理）〈重要〉—— 権限昇格でシステムログがリセットされ、36分後には Webシェルの要求が3種のログから除去されている（出典6）。Accenture の推奨も「上流のプロキシ・WAF・ネットワークログで調査すること。ローカルログだけに頼らないこと」である（出典6）。あわせて「パッチ適用や再構築の前に、MiCollab と Border Gateway サーバのフォレンジックイメージを取得すること」も挙げている（出典6）—— パッチを当てた瞬間に、侵害の証拠が消える順序になっているためである（本記録の読み）。 報道は侵入に使われた脆弱性を CVE-2026-133275・133303・133311・133323・133324 の5件として名指ししているが（出典7・8）、Accenture のレポート自身は CVE 番号を付けておらず、Mitel の MTLVULN 番号で参照している（出典6。齟齬6）〈重要〉—— 本記録は段と CVE を1対1で結ばない。

    **勧告は修正手順をナレッジベース記事 KB000129195 に置き、 参照できない場合は Mitel 正規パートナーへ問い合わせるよう案内している** （出典1）〈重要〉—— **本記録も KB の本文を確認できていない**〈自己未確認1〉。 **一方、KEV の是正期限は4件が収載から3日である**（出典3）。 **緊急時に初めてパートナーへ連絡する組織は、 手順を入手する段階で期限を超える**（本記録の評価）。
    取るべき行動 **保守契約のある製品について、 ①セキュリティ情報の通知先、②ナレッジベースへのアクセス権、 ③緊急時の連絡窓口と応答時間、を平時に確認し記録する** （本記録の推奨）—— **年1回、実際に KB へアクセスできるかを試す。**
セキュリティ技術者への示唆
  • 「最新版に上げた」で終わらせない。影響範囲に最新版そのものが含まれることがある。
    **影響を受けるのは MiCollab 10.3（10.3.0.18）以前であり、 10.3.0.18 自体も影響を受ける**（出典1・4）〈重要〉—— **対応は「10.3.0.18 へ更新した上で Mitel のパッチを適用する」か 「それ以降のリリースへ上げる」のいずれかである**（出典1）。 **バージョン番号の比較だけで判定すると、 10.3.0.18 の機器を対象外に分類してしまう**（本記録の評価）。
    取るべき行動 **影響範囲の記述が「X 以前（X を含む）」の形になっている勧告では、 版数の比較ではなくパッチの適用記録で判定する**（本記録の推奨）〈重要〉—— **本件なら、10.3.0.18 の機器について 「MISA-2026-0012 のパッチを適用したか」を個体ごとに記録する。**
  • ブラインド型のコマンドインジェクションは、要求と応答を見ていても成否が分からない。
    **CVE-2026-133323 は「ブラインド」型のコマンドインジェクションである** （出典1・2）〈重要〉—— **応答に実行結果が出ないため、 アクセスログの応答コードを見ていても悪用の成否が判別できない** （本記録の整理）。 **CVSS の内訳も機密性 N・完全性 H・可用性 H で、 「読み取られる」より「実行され、壊される」型である**（出典2）。
    取るべき行動 **AWV が動作するサーバについて、 ①プロセス生成の記録、②外向きの通信の記録、 ③アップロードされたファイルの差分、の3つを取得できる状態にする** （本記録の推奨）〈重要〉—— **侵害指標は公表されていない**〈未確定1〉—— **指標が出てから遡れるかは、いま記録を残しているかだけで決まる。**
  • ベンダー勧告に悪用が書かれていないことは、悪用されていない証拠ではない。
    **本記録が2026年11月26日に確認した時点で、 MISA-2026-0012 には実環境での悪用の記載が無い**（出典1）〈齟齬1〉〈重要〉—— **日本語の報道も同じ点を明記している**（出典4）。 **一方 CISA は5件すべてを悪用済みとして収載した**（出典3）。 **ベンダー勧告の購読だけでは、この緊急性は伝わらない**（本記録の評価）。
    取るべき行動 **外部公開している製品について、 ベンダー勧告とは別に悪用情報の経路（CISA KEV の更新など）を購読し、 資産台帳の製品名・CVE 番号で突き合わせる**（本記録の推奨）〈重要〉—— **突き合わせはベンダー名ではなく製品名と CVE 番号で行う （買収・改称で表記が変わる）。**
  • 【続報】ユニファイドコミュニケーション製品のディレクトリ連携アカウントを、 ドメイン管理の対象として扱う
    **確認された被害組織では、root を取られた2分後（T+32分）に MiCollab の LDAP コネクタに保存されていた資格情報が読み出され、 LDAPS でドメインコントローラへの認証が成立している**（出典6）〈重要〉—— **その後 T+1.5時間で Kerberoasting、T+2時間で複数のドメインコントローラからの ユーザーレコード書き出しに至った**（出典6）。 **MiCollab は電話・会議の製品であり、「業務システム」の台帳に載りにくい（本記録の評価）—— しかしディレクトリ連携のためにドメインの資格情報を持っているため、 製品の侵害がそのままドメインの侵害になる。** **Accenture も「侵害が疑われる場合はディレクトリ侵害として対応する」ことを推奨している**（出典6）。
    取るべき行動 電話・会議・UC 製品、複合機、資産管理、監視ツールなど「業務システム扱いされない機器」の ディレクトリ連携アカウントを棚卸しする。 それぞれについて、読み取り範囲を必要最小限に絞り、対話ログオンとネットワークログオンを禁止し、 連携アカウントが複数のドメインコントローラへ連続認証したときに警報が出るようにする。 侵害が疑われた場合の手順に「当該アカウントとサービスアカウントの資格情報のリセット」を入れておく。
  • 【続報】パッチを当てる前にフォレンジックイメージを取り、 調査は上流のログで行う
    **確認された被害組織では、権限昇格の副作用としてシステムログがリセットされ、 T+36分で Webシェルの要求が Webサーバ・エラー・管理の各ログから除去されている**（出典6）〈重要〉—— **ローカルのログだけでは侵害を再構成できない（本記録の整理）。** **Accenture の推奨は「パッチ適用や再構築の前に MiCollab と Border Gateway サーバの フォレンジックイメージを取得すること」「上流のプロキシ・WAF・ネットワークログで調査し、 ローカルログだけに頼らないこと」である**（出典6）。 **是正期限に追われてパッチを当てると、証拠が先に消える順序になっている（本記録の評価）。**
    取るべき行動 インターネットに面した装置・アプライアンスについて、 緊急パッチの手順の先頭に「イメージの取得」を入れる（取得先と所要時間を事前に決めておく）。 装置の Web アクセスを上流のプロキシまたは WAF 経由に限定し、 要求のログを装置の外に保存する。 外向き通信については、常時の HTTPS 接続・大量の短い HTTPS アップロード・ sslip.io 等の IP 埋め込みホスト名・trycloudflare.com 等の一時トンネルへのアクセスを 検知対象にする（本件の IoC はこの形だった）。
