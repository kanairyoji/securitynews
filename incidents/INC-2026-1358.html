INC-2026-1358米空軍 Cloud One が侵害か

**米空軍の基幹クラウド基盤 Cloud One** が侵害されたと Reuters が2026年11月27日に報じた。 更改作業中の直近1か月ほどの間に発見され、米サイバー軍が被害評価に加わったとされる。 移行の停止・アプリケーション更新の停止・管理者権限の剥奪が行われ、 空軍は「特定のネットワークについてコメントしない」として事実を確認していない

不正アクセス・侵害初報のみ有名事象として記録（日本と直接の関係は薄い）既知の脆弱性の悪用
初報: 2026年11月27日（Reuters の報道） 最終更新: 2026年11月27日

米空軍の基幹クラウド基盤「Cloud One」が侵害されたと、 Reuters が3人の関係者の話として2026年11月27日に報じた（出典1）。 侵入は「直近1か月ほど」の間に、システムの更改作業中に発見されたとされ、 Reuters は攻撃者の身元・侵入の全体像・データが窃取されたかを いずれも確認できていないと明記している（出典1）。 Cloud One は2017年に始まった空軍の IT 基盤で、 Microsoft・Amazon・Oracle・Alphabet の4社の資源を組み合わせ、 人事データ・給与・補給・整備のアプリケーション群を動かしている（出典1）。 その中には、北米全域の防空レーダー等のデータを集約する Cloud-Based Command and Control と、 世界200か所超の空軍施設で爆弾・ミサイルを追跡する Theater Integrated Combat Munitions System が含まれる（出典1）。 発覚後、空軍は基幹業務アプリケーションの Cloud One への移行を停止し、 すでに稼働しているアプリケーションの更新を止め、 一部の利用者の管理者権限を剥奪した（出典1）。 米サイバー軍（Cyber Command）が被害評価に招請されたともされる。 空軍は Reuters への声明で「特定のネットワークおよびシステムの セキュリティ態勢・脆弱性・稼働状況についてコメントしない」と述べ、 事実関係を確認していない（出典1。原文英語）。 本記録が本件の読みどころと見るのは、封じ込めの副作用である—— 更新を止めたことで、業界各所で新たな重大脆弱性が公表された まさにその時期に、空軍の担当者は修正を適用できない状態に置かれた（出典1）。 侵害の封じ込めが、別の侵害の入口を開けたままにする構図である（本記録の評価）。

封じ込めのために更新を止めたことが、別の無防備を生んだ評価・解釈

本記録が本件で最も学ぶべきと見るのは、封じ込めの副作用である （本記録の判断）。

報じられた対応は3つである（出典1。事実としての報道内容）。

  • 基幹業務アプリケーションの Cloud One への移行を停止した（長年の軍の優先事項だったとされる）。

  • すでに Cloud One 上で稼働しているアプリケーションの更新をブロックした。その結果、空軍の担当者は、業界全体で新たな重大脆弱性の一群が公表されたまさにその時期に、修正を適用できなくなった。

  • 一部の利用者の管理者権限を剥奪した。

1つ目と3つ目は、侵害対応として理解できる（本記録の評価）。 汚染が疑われる基盤に新しい資産を載せない判断であり、 権限の剥奪は横移動の抑制に直結する。

問題は2つ目である。 更新のブロックは、 攻撃者が正規の配信経路を使って変更を押し込むことを防ぐ措置として 理解できる。しかし同時に、既知の脆弱性に対する修正の適用も止まる。 つまり「既に入っている相手を封じる」ために、 「まだ入っていない相手に対する防御」を下げている（本記録の評価）。 この二律背反は、クラウド基盤に多数のアプリケーションを集約した 構成では避けにくい——配信の経路が共通であれば、 止めるときも共通で止まる。

本記録の評価では、ここが設計段階で考慮されるべき点である。 「侵害時に更新を止める」という判断があり得る前提に立つなら、 更新経路を基盤全体で1本に束ねず、 緊急の修正だけを別経路で通せる仕組みを用意しておく必要がある。

コントロールプレーンに届いたという証言が意味すること原因・手口

情報源1人は、侵入者がソフトウェアの脆弱性を悪用して コントロールプレーンに到達したと述べ、これを「万能リモコン」に 例えた（出典1）。理論上は、そのアクセスを足がかりに 軍用機の稼働状況や予備部品の動きを確認できるとされる。 実際にそうしたかは不明である。

本記録はこの証言の意味を、次のように整理する（本記録の評価）。 クラウド基盤のコントロールプレーンは、 個々のアプリケーションやデータではなく、 「アプリケーションやデータを配置・起動・複製・取得する権限」を扱う層である。 ここに届かれると、個別のアプリケーションの堅牢さは意味を失う—— 鍵のかかった部屋をいくつ作っても、 建物の管理室を取られれば順に開けられる。

さらに本件で重いのは、Cloud One が集約型であることである（出典1）。 人事データ・給与・補給・整備のアプリケーション群に加え、 北米全域の防空レーダー等のデータを集約する Cloud-Based Command and Control と、 世界200か所超で弾薬を追跡する Theater Integrated Combat Munitions System が同じ基盤にある。 「ワンストップ」として設計された利点が、 そのまま影響範囲の広さとして現れる構造である（本記録の評価）。

ただし繰り返すが、コントロールプレーンへの到達は匿名の情報源1人の 説明であり、空軍の確認はない（本記録の明記）。

「100%の成功率」という自己評価が残っていた背景・過去事例

Reuters は、Cloud One が長くハッカーの標的であり続けたことに触れ、 2023年にオンライン媒体 FedScoop に掲載された Cloud One 運営側の論考を 引用している（出典1）。 そこでは「驚くべき数」の侵入試行に対して「100%の成功率」で 撃退してきたと述べられ、「セキュリティに関して誤りの余地はない」と 書かれていた。

本記録はこの引用を、本件の教訓として読むべきものと評価する （本記録の判断）。 「これまで一度も破られていない」は、将来の安全の根拠にならない。 むしろ、侵入試行の撃退を成果指標に置くと、 「破られた後にどれだけ早く気づき、どこまでで止められるか」という 指標が組織の関心から外れる（本記録の評価）。 本件で侵入が見つかったのは監視によってではなく、 更改作業の最中であったと報じられている（出典1）—— この事実は、撃退の実績と検知の能力が別物であることを示している （本記録の読み）。

米政府は同時期に少なくとも6件の別の事案を抱えていた背景・過去事例

Reuters は本件の文脈として、AI を用いた侵入への懸念の高まりと、 米政府が抱える他の事案に触れている（出典1）。

  • AI を用いた侵入への懸念が高まっており、AI モデルが広い攻撃面にわたって弱点を素早く見つけられるため、クラウド基盤のネットワークではとくに深刻な問題になるとされる。

  • 米政府は、最近公表された少なくとも6件の他のサイバー事案の後始末にすでに追われている——FBI の2件、国防省データの過去の侵害、国土安全保障省の職員情報の漏えい、少なくとも2つの情報機関に影響した侵害、財務省の侵害。

本記録はこれらを本件と結びつけない（本記録の明記）。 記録する理由は、「同時に複数の事案を抱えている状態」そのものが 対応能力の制約になるためである（本記録の評価）。 本件で米サイバー軍が被害評価に招請されたと報じられている（出典1）が、 同じ組織が並行して複数の政府事案を見ている状況では、 1件に割ける資源は当然限られる。

    取るべき行動 **アプリケーションの配信経路と、 OS・ミドルウェアの修正の適用経路を分離する。** 少なくとも、①通常のリリース、②緊急の修正、 ③基盤の構成変更の3系統を別の仕組み・別の承認で通せるようにし、 **それぞれを個別に停止できることを実際に試す。**
  • 集約型基盤では、横断的な参照を「業務単位」で検知する
    **本件で懸念されたのは、戦術・人事・補給という 性質の異なるデータが同じ基盤にあることである**（出典1）。 **集約型では、1つの権限が複数の任務のデータに触れられる** （本記録の評価）。利用者単位の監視では、 「本来その人が見ない領域を見た」ことが浮かび上がらない。
    取るべき行動 **基盤上のデータを業務・任務の単位でタグ付けし、 利用者（またはワークロード）ごとに 「通常触る業務」の範囲を定義する。** 範囲外への参照を警報にする。 **タグ付けができていない領域を先に洗い出す** ——そこが最も見えていない場所である。
