INC-2026-1360WP connectの6プラグインに後門

フランスのプラグイン開発元 **WP connect** の WordPress プラグイン6本に、 2026年11月22日、遠隔操作のバックドア（`includes/airwp-online.php`）を 仕込んだ版が WordPress.org へ投入された—— **悪性版は WordPress.org の公開保留（Protect The Shire）と自動審査 Gandalf に 止められ、一度も利用者へ配布されないまま同日夜に6本すべてが閉鎖された。** **Wordfence が CVE-2026-135202（CVSS 9.8）として登録し、11月23日に公表した。** **一方、WP connect 自身は後に「入口は WordPress.org のアカウントではなく、 開発パートナーが持つ GitHub の個人アクセストークンだった」と訂正している** ——**盗まれたトークンでリポジトリに不正なコミットが入り、 自動リリースのワークフローがそれをそのまま WordPress.org へ投入した。** **推定3,600サイト超の利用があるが、悪性版は配布されていないため 被害サイトは報告されていない。**

委託先・再委託先起因で委託元多数に波及不正アクセス・侵害初報のみ有名事象として記録（日本と直接の関係は薄い）委託先・供給元起因認証情報の悪用（使い回し・推測可能・窃取）設計・実装上の不備権限管理の不備
初報: 2026年11月23日（Wordfence の公表。17:12 UTC） 最終更新: 2026年11月28日

2026年11月22日、WordPress プラグイン開発元 WP connect（フランス）の 6本の無料プラグインに、遠隔操作のバックドアを仕込んだ新版が WordPress.org のプラグインリポジトリへ投入された（出典1・出典2）。 追加されたのは includes/airwp-online.php という1ファイルと、 それを読み込む require_once 1行だけである（出典2）。 このモジュールは「分析と自動更新（Analytics & Auto-Update）」を装いながら、 実際には開発元と無関係のドメイン tascredit-pay.com へ サイトURL・PHP・WordPress・OS のバージョン・PHP の実行ユーザを送り、 返ってきた PHP コードを eval() で実行する（出典2）。 さらにシェルコマンドの実行、任意ファイルの読み書き・削除、 任意テーブルの照会、wp_users のパスワードハッシュの吐き出し、 アップロード配下へのウェブシェル設置、毎時のコード実行の永続化までを コマンドとして備えていた（出典2）。 Wordfence は CVE-2026-135202・CVSS 9.8 として登録した（出典2）。

本事案の中心は、被害ではなく「止まった」ことである。 2026年6月に WordPress.org が始めた Protect The Shire の公開保留（新版は 一定時間、自動更新で配られる前に留め置かれる）と、 自動審査 Gandalf が独立に悪性コードを検出し、 6本すべてが同日夜に閉鎖された。悪性版は一度も利用者へ配布されていない （出典1・出典2。開発元・WordPress.org・Wordfence の三者が一致）。 推定3,600サイト超の利用があるが、被害サイトは報告されていない。

もう一つの核心は、入口の訂正である。 Wordfence の初報は「開発者の WordPress.org アカウントが侵害された」と推定し、 本事案を伝えた報道もそう書いた（出典2・出典4）。 WP connect は自社の調査結果として、入口は WordPress.org の認証情報ではなく 開発パートナーが持つ GitHub の個人アクセストークンだったと訂正し、 「最初の仮説を残しておくより、自分たちで訂正したい」と明記した（出典1）。 盗まれたトークンで main ブランチへ不正なコミットが入り、 自動リリースのワークフローが、ワークフロー内に置かれたデプロイ用認証情報で WordPress.org へ新版を投入した。 誰も WordPress.org のトークンを持たないまま、 6本のプラグインに新版が付いた理由はこれである（出典1）。

攻撃の経過

公表された範囲の事実のみ。公表されていない段階は補完せず明示しています。

**本事案は、委託先の認証情報1本から配布基盤の投入までが自動で通った 供給網汚染である**（出典1・出典2）。 **段階は4つに整理する——盗まれた GitHub トークンによる初期侵入、 「分析と自動更新」を装った検知回避、C2 への定期チェックインと `eval` 実行、 そして配布直前での阻止。** **重要な区別——永続化・認証情報窃取・ウェブシェルは 「仕込まれた機能」として確認されているが、 悪性版が配布されていないため、稼働したサイトは報告されていない** （本記録の明記）。

  1. 1. 初期侵入確認済
    **開発パートナーが持つ GitHub の個人アクセストークンが悪用され、 WP connect の GitHub リポジトリへ権限のないコミットが押し込まれた** （出典1）。 **トークンの盗取の経路・時期は公表されていない。** **WP connect の WordPress.org 認証情報は使われていない。**
    根拠: WP connect の説明「The entry point was a GitHub personal access token belonging to one of our development partners, not a WordPress.org credential. The token was used to push unauthorized commits to our GitHub repositories.」（出典1。原文英語）。
  2. 2. 検知回避確認済
    **追加されたのは1ファイル（`includes/airwp-online.php`）と 読み込み1行だけで、ファイルヘッダは自身を 「Online module (Analytics & Auto-Update)」と説明し、 開発元の `wpconnect.co` へ報告すると書いていた**（出典2）。 **実際の宛先は `tascredit-pay.com` にハードコードされていた。** **管理画面には何も表示されず、権限確認・nonce も無い。** **5本は同一バイト列、Air WP Sync 2.9.1 のみ同じモジュールの古い草稿。**
    根拠: Wordfence の解析——モジュールのヘッダ記述と、 `AIRWP_API_URL` に `https://tascredit-pay.com/api` を既定値として 埋め込むコードの引用（出典2）。
  3. 3. C2通信確認済
    **モジュールは `init` フック（未認証のリクエストを含む全リクエストで発火）と 30分ごとの WP-Cron でチェックインし、サイトURL・PHP・WordPress・OS の バージョン・PHP の実行ユーザ・直前のコマンド結果を `tascredit-pay.com` へ POST する**（出典2）。 **TLS の証明書検証を明示的に無効化しており、経路上の第三者も応答を 改変できる。** **応答の `code` は base64 復号・XOR 復号を経て `eval()` で実行され、`api_url` と `interval` の書き換えで 基盤の移転もできる。** **ただしこれは仕込まれた動作であり、 配布されていないため実際の通信は報告されていない**（本記録の明記）。
    根拠: Wordfence の解析——`sync()` が送る項目の列挙、 `CURLOPT_SSL_VERIFYPEER => false` / `CURLOPT_SSL_VERIFYHOST => 0` の指摘、`exec_code()` のコード引用（出典2）。
  4. 4. 影響（暗号化・破壊・改ざん）確認済
    **影響は「配布前に止まった」という形で確定している**（出典1・出典2）。 **WordPress.org の公開保留が新版を留め、自動審査 Gandalf が 悪性コードを検出してリリースを無期限に停止し、 同日夜に6本が閉鎖された。** **悪性版はダウンロード可能になったことも、更新として配られたことも無い。** **仕込まれていた機能としては、OS コマンドの実行、任意ファイルの読み書き・削除、 任意テーブルの照会、全利用者のパスワードハッシュの吐き出し、 アップロード配下へのウェブシェル設置、毎時のコード実行の永続化があった** （出典2）。 **これらが実行されたサイトは報告されていない。**
    根拠: WP connect「No malicious version was ever distributed through WordPress.org.」（出典1）、 Wordfence「the backdoored versions were never released to sites, and all six plugins were closed on WordPress.org the same evening.」 （出典2。いずれも原文英語）。 および本記録による WordPress.org プラグインページの現況確認（出典3）。

仕込まれたのは「分析と自動更新」を装う遠隔操作モジュールだった被害規模・影響範囲

Wordfence の解析による（出典2。事実。引用は原文英語を本記録が訳した）。

偽装——ファイル冒頭のヘッダは、自身を 「Online module (Analytics & Auto-Update)」と説明し、 「wpconnect.co のオンライン・エンドポイント」へ報告し、 「完全なプラグインのリリースを待たずに、 修正や小さな機能更新を全インストールへ届けるため」と書いていた。 実際のエンドポイントは tascredit-pay.com にハードコードされており、 開発元とは無関係のドメインである。 Wordfence はこの偽装について 「WordPress.org のリリース工程の外でコードを届けることを目的と称するモジュールは、 まさに WordPress.org のガイドラインが禁じているものであり、 同時に、任意のリモートコード実行を うっかり見た審査者に『製品の機能』として読ませる作り話でもある」と評している。

動作——
- init フック（未認証の表示を含むすべてのリクエストで発火）に登録し、30分ごとの WP-Cron も予備として仕掛ける。ログイン・権限確認・nonce はどこにも無く、管理画面に何も表示されない。

  • チェックインごとに、サイトURL・PHP・WordPress・OS のバージョン・PHP の実行ユーザ・直前のコマンドの実行結果を C2 へ POST する。

  • 通信は TLS の証明書検証を明示的に無効化している（CURLOPT_SSL_VERIFYPEER を false、CURLOPT_SSL_VERIFYHOST を 0）。C2 の運用者だけでなく、経路上に位置した者も応答を改変できる。

  • 応答の code を base64 復号し、サーバが渡す鍵で XOR 復号したうえでeval() で実行する。「無害化」は PHP の開始・終了タグを取り除くだけで、意味を持たない。

  • api_url と interval を書き換えられるため、元のドメインが停止されても運用者は別の基盤へ移れる。

コマンド群（Wordfence は「侵害後の道具箱そのものだ」と評している）—— sh（OS コマンドの実行）／file（任意ファイルの読み・書き・削除）／ db（任意テーブルの吐き出し）／dump_wp_users（全利用者のログイン名・ メールアドレス・パスワードハッシュ）／webshell（任意パスへ単独動作の ウェブシェルを設置。プラグインを削除しても動き続ける）／ persist（毎時の WP-Cron フックで攻撃者のコードを eval する）／ set_api_url・set_interval。

本記録は、ここで事実と可能性を厳密に分ける。 上記は「仕込まれた版が持っていた機能」であり、 実際に稼働したサイトは報告されていない ——悪性版は配布されていないためである（出典1・出典2）。 Wordfence が述べているのは「これらの版を動かしたサイトがあれば、 サイトとサーバの完全な制御が tascredit-pay.com の運用者に渡っていた」という 条件つきの評価である。

WP connect は認証情報の作り直しだけでなく、リリース経路そのものを変えた再発防止

同社が公表している対応（出典1。事実。原文英語を本記録が訳した）。

済んだこと——
- 侵害されたトークンを失効させ、当該パートナーの自社システムへのアクセスを解除した。

  • WordPress.org アカウントへのアクセスを、自社・協力者のぶんを含めてすべて削除した。

  • 関与しえたアクセス・トークン・認証情報をすべて削除し、権限を制限して作り直した。

  • アカウントのパスワードを変更した（多要素認証は以前から強制しており、現在も有効）。

  • 自社インフラから配布している有料版を監査した。影響は無く、悪性コードは配布されていない。

変えること——
- merge されたコミットだけでは WordPress.org への投入が起きないようにし、リリースには人による明示的な確認を要する。

  • デプロイ用の認証情報を必要最小限に絞り、順次入れ替える。

  • リリースを告知し記録に残す（想定外の版が、後から発見されるのではなくその場で見えるように）。

  • リポジトリへの書き込み権限を実際に必要な人だけに縮め、可能な箇所では長命のトークンではなく短命の認証情報にする。

本記録の評価。 「告知して記録に残す」は地味だが、本事案の文脈では効く。 本事案で WP connect 側は、WordPress.org に止められるまで 自社から新版が9本出たことを把握していた形跡が無い（本記録の読み。 同社は「誰にも気づかれずに到達しうる」と自ら書いている）。 出荷の事実が人の目に触れる経路を作ることは、 検知の仕組みを新規に買うより安く、本事案と同型の事故には直接効く。
