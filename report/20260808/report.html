本日の中心は、米国の脆弱性管理を「固定期限」から「リスク階層」に切り替える CISA の拘束的運用指令 BOD 26-04 と、それを裏打ちするファイブアイズ共同声明である。悪用までのタイムラインが年単位から月単位へ縮んでいるという認識が、政府調達側の規範として明文化された点が大きい。実際、本日 KEV に収載された Progress Kemp LoadMaster の脆弱性には BOD 26-04 に基づく8月10日の期限が付いている。米議会では12月11日までのつなぎ予算が上院を通過したが、下院案（12月4日まで）との調整が残り、国防総省予算は2026会計年度水準に据え置かれ新規プログラムは禁じられる。ホワイトハウス ONCD の国家サイバー戦略については、重要インフラ保護・新興技術での主導権維持・サイバー人材育成という第4〜6の柱の解説が出ている。中国側では CNCERT が「銀狐」トロイの木馬に対する専項打撃行動を組織し、脅威情報の線索を社会から公募する枠組みを立ち上げた。政府が民間・技術コミュニティから IoC を吸い上げる仕組みを制度として運用している点は、日本の政策担当者にとって比較対象になる。

1. CISA BOD 26-04 — 固定期限からリスク階層型へ、最上位は3日以内

出典: トレンドマイクロ セキュリティブログ（取得日 2026-08-08）

BOD 26-04 は連邦文民機関に対し、一律のパッチ適用期限をリスク階層型の優先順位付けに置き換えることを求める。最もリスクの高い脆弱性は3日以内の修復が必要となる。あわせてファイブアイズ各国のサイバーセキュリティ機関が共同声明を出し、AI が攻撃者の偵察とリサーチを加速させることで、脆弱性発見から悪用までのタイムラインが年単位から月単位へ縮んでいると警告した。

拘束力は連邦文民機関に限られるが、記事は州・地方・部族・準州の政府、教育機関、重要インフラも同じ猶予の短縮に直面しており、しかも人員と予算はより厳しいと指摘する。日本の組織にとっても「固定スケジュールのパッチ適用は成立しない」という前提の共有が要点で、SLA を CVSS の一律しきい値ではなく悪用状況（KEV 収載・PoC 公開・実観測）で組み替える議論の材料になる。

3. 米国家サイバー戦略 第4〜6の柱 — 重要インフラ・新興技術・人材

1. VMware ESX のシェルコマンド難読化 — キーワード検知が成立しない21手法

出典: CrowdStrike Blog（取得日 2026-08-08）

ESX 7.0.3 build-20036589 と VMware 提供の BusyBox（/usr/lib/vmware/busybox/bin/busybox、awk の GNU 数学拡張 xor/and/or が有効）で検証。核心は次の点にある。

ESX のシェルログはコマンドをパース段階で記録する。展開が行われる前の文字列が残るため、難読化された形のままログに保存される。

たとえば $(printf "\x65\x73\x78\x63\x6c\x69") system syslog config get は esxcli system syslog config get と同一に実行されるが、ログには esxcli の文字列が現れない。検証された6カテゴリは次のとおり。

カテゴリ 内容
1. エスケープシーケンス符号化 8進（\145）・16進（\x65）を printf / echo -e / ANSI-C クォート（$'...'）で復元。引数を含む全体の符号化も可能
2. 文字生成・文字列操作 awk/python による ASCII 値からの文字生成、sed/od/awk を使った文字列反転、$TERM・$SHELL からの1文字ずつの抽出（符号化文字を一切含まない）
3. 不可視 Unicode 注入 ゼロ幅スペース／非結合子／結合子／Word Joiner を可視文字の間に挟み、実行時に gsub() で除去。PUA（U+E000〜U+F8FF、6,400字）や SPUA-A/B（13万字超）まで拡張可能
4〜6 暗号的な暗号化、インフラを鍵にしたペイロード、代替符号化系

環境変数からの抽出（$(echo $TERM | cut -c 3)...）は、コマンドラインにエスケープシーケンスも符号化値も不審な構文も残らないため特に回避性が高い。CrowdStrike は正規表現ベースの CQL 検知パターンを作成し、Falcon Next-Gen SIEM の相関ルールとして ESX シェルテレメトリに展開できる形で公開している。

実務上の含意: ESX の検知を「既知の悪性コマンド文字列の一致」で組んでいる組織は、その前提を今日中に見直す必要がある。難読化の各クラス（printf 系、awk 系、非 ASCII バイトの存在、環境変数の切り出し）に対する構文的な特徴で検知を組み替える。syslog config set --reset=loghost のようなログ転送停止操作は、それ自体を単独の高優先度アラートにしておく。

利用者が、どの権限が危険か、どのファイルを守るべきか、ツールが本来すべきでないことをしていないかを十分に理解できると期待すべきではない。だからこそ、ツール側にセキュリティを組み込み、利用者がセキュリティ専門家であることに依存しない安全な既定値と保護機構を持たせることが重要になる。

推奨は6点。適切なセキュリティ・プライバシー統制の実装、アーキテクチャレベルでのガードレール強制、生成コードを基準に照らして検証する層の組み込み、サードパーティツールの信頼性評価の正式なプロトコル整備、機微ファイル保護の統合、厳格なセキュリティの既定化。開発者は既にこれらを場当たり的に実践しており、いくつかはツール側に組み込んで既定で有効にすべきというのが結論である。
