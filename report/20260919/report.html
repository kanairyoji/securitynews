日本が直接の当事者になる動きが二つあった。九州に展開した米軍の Typhon にロシアが正式な抗議と撤去要求を出し、10月中旬以降は在日米軍施設で保管される見通しとなった。もう一つは北朝鮮 WaterPlum への共同勧告で、日本国内で初めて「ラップトップ・ファーム」が解体され、日本の暗号資産交換業者が標的として名指しされた。欧州ではドイツの空軍基地付近で再びドローン残骸が見つかり、GRU 関与の線で連邦検察が捜査を引き取っている。米軍内部では AI が作った虚偽の情報報告が作戦の直前中止を招いていた。

1. AI の虚偽報告で米中衝突の寸前まで進み、作戦直前に中止

出典: 보안뉴스 boannews（2026-09-19）

CNN の報道によれば、イランとの戦争が続いていた今年春、「中東海域の中国船舶が核兵器計画の部品を運搬中」とする情報報告が米軍内に回覧された。作成者は特殊作戦司令部の分析官で、米軍は直ちに船舶阻止計画に着手し、武装兵員が乗船を準備し軍用機も上げた。しかし作戦直前の精査で、分析官が使った AI チャットボットが積載物質を誤認識していたと判明した。分析官はハワイの米太平洋特殊作戦司令部から得た積荷目録の情報をボットに問い、ボットは公開情報と政府保有の機密信号情報を融合して結論を出していた。分析官はさらに AI で標準的な報告形式へ整えて配布した。関係者は「報告は全面的に虚偽で、あわや戦争を引き起こしかけた」と述べている。

米軍と情報機関は生情報の分析から目標選定、予算・軍需の管理まで AI を広く使うが、導入が分散したため部門ごとに道具と安全基準が異なり、AI 生成情報を検証する単一の基準が無い。若い分析官が道具を無批判に信頼する傾向も指摘されている。

日本の安全保障担当者には二重の含意がある。同盟国の意思決定に AI 由来の誤情報が混入しうる前提で情報を受け取ること。そして防衛・海保・警察が AI を分析に取り込む際、出所の階層と検証責任を明示する規程を先に作ることである。

2. ロシア、九州の Typhon 撤去を正式に要求——10月中旬から在日施設で保管

出典: The Insider（2026-09-18）

ロシア外務省は、九州に展開中の米軍 Typhon ミサイルシステムの撤去を日本に要求したと発表した。9月3日に正式な抗議文書を送っており、「いかなる口実でも受け入れられない」として、駐留期間や条件にかかわらず国外への撤去を求めている。Typhon は6月の Valiant Shield 2026 に先立ち鹿児島県の海上自衛隊鹿屋航空基地に展開され、9月8日から24日まで日米豪の陸上部隊が参加する Orient Shield 26 でも使われている。統合幕僚監部によれば、演習終了後の10月中旬ごろから在日米軍施設へ保管のため移動する見通しで、国外へは出ない。自衛隊施設への直接展開と九州への展開はいずれも初である。同システムは射程約1,600kmの Tomahawk と SM-6 を発射でき、南九州からは中国東岸の広い範囲が射程に入る。

ロシアは配備前の5月から「極東国境への直接の脅威」と主張しており、8月のプーチン大統領の択捉島訪問で日露関係は一層悪化している。抗議の実質的な効果は薄いが、「日本国内の米軍アセット」を継続的な外交争点に据える意図がうかがえる。

含意は、日本の安全保障判断がミサイル配備の是非にとどまらないことである。この種の争点は偽情報作戦や重要インフラへの威圧的なサイバー活動の口実に使われやすく、鹿児島県内の自治体・港湾・空港関係者は、配備報道に連動した標的型攻撃と世論操作の双方を想定した警戒が要る。

3. 北朝鮮 WaterPlum、日本で初のラップトップ・ファーム解体——313総局に帰属

出典: CyberScoop（2026-09-18）

前回の共同名指しに続き、帰属と国内対応が明らかになった。各国機関は WaterPlum（Contagious Interview）を朝鮮労働党中央委員会軍需工業部傘下の「第313総局」の下で活動する組織と特定した。感染は100か国以上で3万台超、7,000超のウォレットから約1,071万ドル相当が北朝鮮へ移された。一部の関係者は北朝鮮 IT 労働者として企業のウェブ開発も請け負い、ラップトップ・ファームへの接続・クラウドソーシング利用・日本の暗号資産交換業者への応募で同一の IP アドレスを使っていた。勧告は「日本で初めて、当局が国内の協力者が運営するラップトップ・ファームを特定・捜査・解体した」と記し、数億円相当の暗号資産が国外へ移された証拠を得たとしている。

インシデントレスポンス・フォレンジック

カテゴリ: カテゴリ7「インシデントレスポンス・フォレンジック（DFIR）」
対象日: 2026年09月19日
生成日時: 2026-09-20

総評

「既存の検査が通ってしまう」侵害が並んだ日だった。Brevo の続報では、攻撃者がエッジで応答を書き換えたため配信元のファイルは無改変で、完全性検査が何も検知しなかった経緯が明らかになった。GhostCode は正規の OAuth デバイス認可を使い、認証から78秒で3台を登録している。検知側では CISA が重要インフラ向けに初のサイバー誘餌ガイドを出し、環境寄生する侵入者を可視化する手段を体系化した。パッチ適用の前提が崩れつつあることも、SOC の設計課題として示された。

1. Brevo 続報——エッジでの応答書き換えが完全性検査を無効にした

出典: Security Affairs（2026-09-18）

前回の「約10万サイトへ ClickFix 注入」に続き、検知できなかった理由が判明した。Brevo は9月10日に SAML SSO の脆弱性を突かれ138アカウント（Trezor を含む）が侵害され、43アカウントから連絡先が持ち出された。4日後、攻撃者は全権限を持つ長期有効な Cloudflare API キー（ソースコード内に保管）で復帰し、悪性の Cloudflare Worker を投入した。同社の説明では「Worker がエッジで応答を書き換え、Content-Security-Policy 等のヘッダを除去したため、配信元サーバとファイルは無改変で、標準的な完全性検査では検知できなかった」。悪性の WordPress プラグインは「Web Media Optimizer」を装い、must-use フォルダで存続して一覧から隠れた。

ファイル改ざん検知とサブリソース完全性は、配信元が無改変でエッジだけ書き換わる構成では効かない。クローラと検査ツールを避け管理者だけを狙う選別も、能動的な検査を空振りさせる。

国内でも CDN のエッジ関数を使うサイトは増え、MA ツールのタグを外部から読み込む構成はほぼ標準である。応答ヘッダの外形監視（CSP が消えていないか）と、長期有効な API キーのソース混入の洗い出しを点検項目に加えたい。

2. GhostCode——正規のデバイス認可で、78秒に9回のAPI呼び出し

出典: CSO Online（2026-09-18）

eSentire は8月下旬、Microsoft の OAuth 2.0 デバイス認可グラントを悪用するフィッシングキット GhostCode を確認した。キットが自ら「デバイス」として振る舞いコードを発行させ、被害者に正規の認証ページで入力させる。被害者は通常どおりサインインし多要素認証も完了するが、認証されるのは攻撃者側の端末で、トークンが攻撃者に渡る。入口は調達担当を装った問い合わせフォームで、NDA を装う HTML ファイルを開くとデバイスコードのフィッシングページに遷移する。認可後、eSentire は78秒間に9回の成功したAPI呼び出しを記録した。Intune 登録、Device Registration Service、Azure AD、Microsoft Graph にまたがり、認証から28秒・53秒・77秒の時点で3台が登録された。

多要素認証が「正しく」成功するため、認証ログだけでは異常に見えない。検知点は認証直後の端末登録の連続で、時間窓が極端に短いことが手がかりになる。

国内も Microsoft 365 の利用率が高く、デバイスコード認証は多くのテナントで既定で有効である。業務上不要なら条件付きアクセスで遮断し、Intune の端末登録イベントへの即時アラートを設定するのが最短の対策になる。

3. CISA、重要インフラ向けに初のサイバー誘餌ガイドを公表

出典: iThome Security（台湾）（2026-09-18）

CISA は「サイバー誘餌（Cyber Decoys）を用いた検知と対応の強化」ガイドを公表した。同機関が欺瞞技術に言及するのは初めてではないが、防御的な誘餌の配備・運用について体系的な指針を出したのは今回が初となる。CISA は、正規の資格情報を得て OS 標準ツールや環境寄生（LOTL）で動く攻撃者は正常な操作と区別しにくい点を課題として挙げ、正常に見える偽のシステム・アカウント・データを置いて攻撃者に触れさせることで侵入済みの活動を露出させるとしている。ガイドは誘餌の種類、計画と配備、検証と調整までを扱い、MITRE Engage と ATT&CK を引いて攻撃者の行動と防御目標に沿った設計を促す。ゼロトラストとの関係にも触れ、ゼロトラストを採る組織も攻撃者が一定の到達権を得る前提を置くべきだとし、誘餌は高信頼度の警告を作って警報疲れを下げると位置づけている。

実装の敷居は低い。低複雑度の Honeytoken には偽の資格情報、偽の API キーや証明書、偽の文書、偽のデータ記録、誘餌URLが挙げられており、本来業務で使わない資産なので読み取り・ログイン・使用が観測された時点でほぼ不正である。

国内では誘餌技術は「高度な組織のもの」と見られがちだが、Honeytoken は費用がほぼかからない。Active Directory に使われない管理者風アカウントを1つ置き、その認証試行を最優先アラートにするだけで、横展開の検知が一段上がる。

4. パッチ適用の遅れは構造的——修正済みは1%未満

出典: Halcyon（2026-09-18）

SOC と攻撃面管理を運用する立場からの評価として、Anthropic の Glasswing 開示が SOC にとって何を意味するかが整理された。同開示では、公開前の試験で主要 OS とブラウザにわたる数千件の未知の脆弱性が見つかり、10年以上前から存在し過去の広範な試験を生き延びた欠陥や、低権限から完全な侵害へ連鎖しうるものが含まれていた。そして公表時点で修正済みだったのは1%未満だった。筆者はこれを当該組織の問題ではなく、AI による発見が生む量に対してパッチのエコシステムが設計されていない構造的な事実だと述べる。

寄与が大きいのはレガシーである。パッチが存在しても適用できない資産（古すぎる、業務に埋め込まれている、ベンダーが更新をやめた）に加え、管理外端末・OT 環境・シャドーITが問題を積み増す。発見から悪用までの窓が縮む一方で、適用の窓は伸びる方向にある。

国内の実務では、この非対称性を「補償的統制の設計」として引き受けるしかない。パッチ不能資産の一覧を持ち、ネットワーク分離・許可リスト・監視強化のどれで代替しているかを資産ごとに書き切ること。脆弱性管理を適用率だけで測る運用は、来年には意味を失う。

5. アイデンティティの可視化——IAM の意図と実行のあいだ

出典: The Hacker News（2026-09-19）

資格情報の窃取・悪用は侵害研究で最も頻繁に報告される初期侵入経路であり、その対策の出発点としてアイデンティティの可視化が整理された。可視化とは、環境内のすべてのアイデンティティ、それが何にアクセスできるか、実行時に実際どう使われているかを見られる状態を指す。棚卸し、権限の対応付け、挙動のテレメトリを一枚の継続的な像にまとめるもので、定期的なスナップショットとは異なる。重要な区別は意図と実行の間にある。IAM は「誰がどの条件でいつまでアクセスすべきか」という方針の意図を表現し、アプリケーションとインフラは「どの資格情報が認証され、どの権限が行使され、どの経路が通ったか」という実行を示す。

この2層の隙間に「アイデンティティのダークマター」が存在する。アプリ固有のローカルアカウント、埋め込まれたサービス資格情報、レガシーな認証フロー、中央のIdPに一度も載せられなかった連携である。SaaS 導入とクラウド移行の10年が生んだ副産物で、例外ではなく常態である。

国内でも基幹システムのバッチ用アカウント、ベンダー保守用アカウント、退職者のトークンがIdPの外に残っている例は多い。IdP のアカウント数と、実際に認証ログに現れるアイデンティティの数を突き合わせれば、差分がそのまま優先課題になる。

総評

Linux カーネルが二方向から圧力を受けた日だった。CISA が実際の悪用を根拠に3件を KEV へ収載し、別の研究者が root 昇格につながる4件の実証コードを公開した。いずれもローカル昇格だが、共用サーバとコンテナ基盤では前提条件が揃いやすい。加えて libheif/libde265 の「HEIF Heist」は、上流が番号を付けずに直した修正がディストリビューションと配布イメージから抜け落ちる構造を露わにした。CVE を待つ運用の盲点そのものである。SolarWinds ARM の固定鍵、WordPress 7.1.1 の強制テーマ導入、Microsoft の972件と、修正対象は広い。

1. CISA、Linux カーネルの3件を悪用確認として KEV に収載

出典: The Hacker News（2026-09-19） / Security NEXT（2026-09-19）

前回は「2件が追加」としていたが、9月18日付の追加は3件で CVE も判明した。CVE-2025-39682（CVSS 9.8）は kTLS の受信経路で、長さゼロの TLS レコードが適切に処理されず後続レコードが誤った前提で扱われ、メモリ開示やサービス停止に至る。CVE-2026-53266（8.8）は ebtables の SNAT ARP 書き換え経路の領域外書き込みで、権限昇格やDoSが可能。CVE-2025-39964（7.8）は AF_ALG ソケットへの同時書き込みの競合状態で、暗号処理結果の破壊やDoSを招く。Red Hat は9月19日に3件すべての勧告を更新し、公開エクスプロイトの存在と高優先の対応を明記した。

悪用の具体的な手口と、3件が単一の攻撃連鎖かは公表されていない。CISA は BOD 26-04 に基づき修正適用だけでなく侵害痕跡の調査も求めており、既に足場を得た攻撃者の昇格に使われている可能性が高い。

国内でも Linux はクラウド基盤・コンテナホスト・ネットワーク機器の土台であり、ebtables と kTLS はブリッジ構成や TLS オフロードで有効になっている環境がある。カーネル更新を今週のうちに配布し、共用ホストのログを併せて確認したい。

2. Linux カーネルの root 昇格4件に実証コードが公開

出典: The Hacker News（2026-09-18）

研究者 Asim Manizada が、いずれもローカル root を取れるカーネル4件の動作するエクスプロイトを9月18日に公開した。DirtyAH6（CVE-2026-80844、IPsec AH6）、TUNderflow（CVE-2026-81000、TUN/TAP）、PPPoEject（CVE-2026-68121、PPPoE）、DiagSpill（CVE-2026-74469、SCTP の sctp_diag）で、7月中旬に報告され数週間のうちに修正済み。前者3件は非特権ユーザ名前空間が有効な場合に一般ユーザから到達でき、多くのディストリビューションは既定で有効にしている。DiagSpill は名前空間も特権も不要で、SCTP モジュールがあれば足りる。実環境での悪用報告はまだない。

危険なのは共用環境である。低権限アカウントを持つ多人数サーバや、コンテナからの脱出（理論上可能と研究者は述べる）が現実的な脅威になる。DirtyAH6 と DiagSpill は限定条件下でネットワーク経由のクラッシュも起こせる。

3. HEIF Heist——番号の付かない上流修正が配布網から抜け落ちた

出典: CyberScoop（2026-09-18）

Hacktron の研究チームは、画像デコーダ libheif と libde265 の処理経路にメモリ破壊を起こせる欠陥群「HEIF Heist」を公開した。HEIF/HEIC/AVIF を細工してアップロードするだけでアプリ層の防御を越え、多くの場合リモートコード実行に至る。RCE に至らない場合でもヒープの任意開示が可能で、他利用者のデータや環境変数を抜ける。影響先として Discourse、GitHub Enterprise サーバ、Meta の主要製品群、AWS 連携サービスが挙げられている。libheif の最新版では修正済みだが、上流の修正は1年前にセキュリティ修正として扱われず CVE も取得されなかったため、Debian 12 ベースの配布イメージには欠陥が残り続けていた。

CVE とベンダー勧告を起点にした脆弱性管理では、この種の「番号の無い修正」は原理的に見えない。1度配布網から漏れると、本番環境が1年間そのまま動く。

国内でもフォーラム、社内Wiki、画像投稿機能を持つ自社サービスは ImageMagick 経由で libheif を呼ぶことが多く、iPhone 既定の HEIC を受け付ける実装は特に該当する。コンテナイメージ内のライブラリ版を SBOM で洗い出し、上流の最新版へ追随しているかを確認したい。

4. SolarWinds Access Rights Manager、固定鍵で認証なしのコード実行

出典: The Hacker News（2026-09-19）

5. WordPress 7.1.1 の Click2Shell——管理者がリンクを開くだけでテーマが入る

出典: The Hacker News（2026-09-18）

前回は 7.1.1 の公開のみを伝えたが、手口が明らかになった。pwn.ai が報告した本件は、ログイン中の管理者が細工されたURLを開くと、WordPress.org 公式ディレクトリのテーマが「Install」を押さずに導入されるというもの。ディレクトリ側はリンク中の値を通常のテーマ名として扱う一方、管理画面側は同じ文字列を記号ごと再利用してページ要素の選択に渡すため、攻撃者が加えた文字が Install ボタンを指し、WordPress 自身のスクリプトがクリックする。導入されたテーマは無効のままなので見た目は変わらない。単体は CVSS 7.1 だが、研究チームは Mobile Repair Zone テーマの検証を欠いたハンドラと連鎖させ CVSS 9.6 のコード実行を実証した。修正は9月17日の 7.1.1 で、4.7 系まで配布されている。CVE は未割当。

2. Shai-Hulud から1年——自己増殖する npm ワームが常態になった

3. CrowdStrike、エンドポイントで悪性パッケージを実行前に止める

1. 「エージェンティックセキュリティは10億ドル規模の課題」

出典: The Register（2026-09-19）

AI モデルではセキュリティが後付けになっており、エージェントが組織や個人を侵害する事例や制御を外れた不具合が増えていることがその証拠だと、投資家・アクセラレータの幹部は指摘する。Merlin Group の Matt Hartman は「能力が上がるエージェントが創造的で時に予想外の方法を見つけることに驚くべきではない。一方で、有害な振る舞いを避けられないものとして受け入れることもできない」と述べた。Microsoft の M12 の Todd Graham は「ノートPCが既定で安全なら CrowdStrike は無かった。クラウドが既定で安全なら Wiz は無かった」と説明した。従来と違うのはモデルの進化速度で、クラウドは数年かけて採用されたが、組織はエージェントの取り込みを全速で進めている。

投資家の見立ては市場形成の予測として整合的だが、購入側には注意が要る。採用の速度が速い分、製品カテゴリの定義が固まる前に調達が始まる。

日本の企業にとっての含意は調達手順である。AI セキュリティ製品は比較軸が未成熟なため、ベンダーの分類名で選ばず、自社のエージェント利用の工程（どの権限で、どのデータに、どう到達するか）を先に書き出し、それに対する可視化と制御の要件で評価するほうが確実である。

2. Vectra AI、AI 駆動の攻撃に対応する Ascent を投入

出典: Dark Reading（2026-09-18）

Vectra AI は、AI 駆動の攻撃という新たな局面に対応するための製品 Ascent を発表した。同社はネットワークと同一性の挙動検知を主戦場としており、攻撃側の自動化が進む前提で検知と対応の速度を上げる位置づけである。

同日には CrowdStrike が Falcon Guardian とエージェンティックIDプロバイダを、TigerByte がエッジ機器の強化製品を発表している。各社の処方は「攻撃側の自動化に、防御側の自動化で追いつく」という同じ形で、差は検証可能性に出る。

日本の組織にとっては、製品数を増やす前に評価軸を決めるほうが先である。既存の EDR・NDR・IdP と役割が重複していないかを整理し、PoC では「同一環境での反復試行における検知の安定性」を条件に書き込みたい。単発の演習で高い検知率が出ても、運用時の安定性は別問題である。

3. CrowdStrike、外部脅威インテリジェンスの評価でリーダーに

出典: CrowdStrike Blog（2026-09-18）

CrowdStrike は、Forrester Wave の外部脅威インテリジェンスサービス提供者（2026年第3四半期）でリーダーに位置づけられたと発表した。同社は同時期に、エージェンティック SOC の次段階、AI エージェント向けのIDプロバイダ、エンドポイントでの供給網攻撃対策、AI セキュリティの Falcon Guardian を相次いで公表している。

アナリスト評価は調達の社内説明には使えるが、評価基準は各調査会社の定義に依存する。同日に複数の新カテゴリを打ち出す動きは、脅威インテリジェンスの提供価値を「情報」から「行動の自動化」へ移そうとしていることを示す。

日本の組織が脅威インテリジェンスを調達する際の要点は、情報の網羅性ではなく自社環境への接続性である。国内の脅威情報の取り込み、日本語の一次情報の扱い、そして自社の資産台帳と突き合わせられるかを評価軸に入れたい。評価がリーダーであることは、日本での実効性を保証しない。

4. TigerByte Cyber、300万ドルを調達しエッジ機器の強化へ

出典: SecurityWeek（2026-09-19）

TigerByte Cyber がステルスを脱し、Hale Capital Partners 主導のシードで300万ドルを調達した。ニューハンプシャー州ハノーバーに本拠を置き、AI 機器とエッジ機器の強化を稼働場所で行う。製品 Cyber Protection Suite は超小型の据え置き型で、データ検証、深層パケット検査、ネットワーク分割、耐量子暗号といったハードウェアで強制される保護をレガシーを含む重要なエッジ機器に提供する。中核技術は単一チップのネットワークセキュリティ製品を手がけた WebSensing 由来である。資金は軍用・商用の航空機、ドローン、衛星、車両の通信・航法システムの近代化と米国内製造の拡張に充てる。既に米宇宙軍、米海軍、DARPA を含む政府機関と700万ドル超の契約を得ている。

シード300万ドルに対して契約700万ドル超という比率は、技術の実証が先行していることを示す。パッチを当てられないレガシー機器に外付けで保護を足す発想は、OT と装備品の現実に合っている。

日本でも鉄道、電力、防衛装備で更新不能な機器が多数残る。外付けの保護装置はパッチ不能資産に対する補償的統制の選択肢になるが、装置自体の供給網と更新経路の信頼性を評価対象に含める必要がある。

5. 「決定を出力するモデル」が安価に登場

出典: Daniel Miessler（Unsupervised Learning）（2026-09-19）

Jev は大規模言語モデルではなく、テキストではなく決定を出力する仕組みだと評された。決定の型は概ね選択、採点、可否の3種で、これらの判断については Sol や Opus と同程度の知能水準にあるという。注目される理由の第一は、AI で実際に行う作業の多くがこの種の決定であることだ。企業業務や AI の実行機構では分類とラベル付けを絶えず行っており、あるメールが迷惑メールか、ある利用者が解約しそうかといった判断がその例である。実行機構の内部では、特定の作業にどのモデルを使うかの選定もこれに当たる。サイバーセキュリティでは、入力の種類と分類、危険である可能性の判定など、用途は無数にある。第二の理由は価格で、入力10億トークンあたり42ドル、出力は課金されない。顧客対応の全データベースや数万通のメールを処理しても請求は0.12ドル程度になりうる。

セキュリティ運用への含意は明確である。アラートの分類、ログの選別、フィッシング判定といった大量の二値・多値判断は、これまで費用の制約で人手か単純な規則に任されてきた領域である。

日本の SOC でも、一次トリアージの負荷は人員不足の主因である。安価な決定モデルが使えるなら、判定の根拠を保全し誤判定率を継続的に測る仕組みを先に用意したうえで、規則ベースの前処理を置き換える検討に値する。判定を外部サービスに出す場合のデータ取扱いは、別に評価が必要である。
