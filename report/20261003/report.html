3. Antino（UAT-11587）の手口が判明——M365 を C2 に、Gmail を画像で偽装

出典: The Hacker News（2026-10-02） / Security Affairs（2026-10-03）

前回からの差分: 10月2日の件について Cisco Talos の報告で手口が判明。標的はアジア8か国の政府・政策機関16組織。Antino は Rust 製 Windows バックドアで、C2 は Microsoft Graph 経由の Outlook と OneDrive だけ。配送は正規プロバイダ経由で SPF を通し From を偽装、相手側の DMARC が p=none のため失敗しても配送された。Gmail の添付プレビュー枠は HTML 画像で再現し攻撃者のページへリンクを張る。最終段は Microsoft 署名済み診断バイナリのサイドロード。

新しいのは実装ではなく正規サービスへの溶け込みで、M365 の通常通信に紛れ宛先での検知は効かない。

含意は2つ。自組織の DMARC を p=none のままでは他組織でのなりすましを止められず、国内の官公庁・大学・政策系法人が reject へ進める根拠になる。もう一つは、M365 の Graph API 利用とアプリ同意の監査が境界監視より有効な検知面になる点だ。

1. NSA、国家安全保障システムの耐量子移行策を発表——理由は「いま収集して後で復号する」

出典: OODA Loop（2026-10-02）

1. 因数分解を経ずに RSA 署名を偽造する新手法——2048ビットは約90ビット相当へ

出典: Xakep.ru（2026-10-02）

研究者らは RSA 法を因数分解せず秘密鍵も復元せずに署名を偽造する手法を示した。基礎は2007年提案の数体ふるい（NFS）の変種で、パディングなしの「生の RSA」を秘密鍵で実行する oracle への一時アクセスと大量の問い合わせを要し、事前計算後は任意の署名をオフラインで偽造できる。1024ビットは約2^65演算で、因数分解の約2^80演算より安い。2048ビットと4096ビットの強度は約90ビット・119ビット相当に下がり、NSA・NIST・ENISA が求める最低128ビットを下回る。PKCS#1 v1.5 と RSA-PSS は該当する oracle を提供しないが、ブラインド署名の一部実装や HSM のインタフェースは該当しうる。Apple と Cloudflare の Privacy Pass は例外だが約2^43トークンを要する。

現時点の実用上の脅威は小さいが前提が崩れた点が重い。暗号学者 Karsten Nohl は「RSA を破るのは因数分解と同じだけ難しい」という前提を覆す突破だと述べた。査読は残る。

総評

この日は「初動で何が決まるか」に材料が集まった。Huntress は、ランサムウェアの暗号化が侵入の最終段であり、初日に起きる失敗はほとんどが技術ではなく権限と判断の失敗だと整理した。M-Trends 2026 の滞留中央値14日に加え、初期侵入から別グループへの引き渡しまでが8時間超から22秒へ縮んだという数値は、調査の対象が常に2系統になることを意味する。Kiteworks と Citrix の対応は、ベンダー側の判断が利用者の初動を左右することを示した。SANS は線形の対応手順を見直す DAIR を提示し、Magnet Forensics は法廷で通る技術者をどう育てるかを論じている。

1. ランサムウェア着弾後の最初の24時間——失敗の大半は判断の失敗

出典: Huntress Blog（10月3日）

Huntress は食品製造・業務サービス・小売の対応実績から、初日の流れを時間単位で整理した。要点は4つある。暗号化は侵入の最終段で、Mandiant の M-Trends 2026（50万時間超の調査が基礎）では世界の滞留期間の中央値が11日から14日に伸びた。データは暗号化の前に出ている前提で動くべきで、CISA の Akira 勧告には侵入から2時間で持ち出しが完了した事例がある。復旧時間を経営に伝える前に、実際にバックアップから1つ戻してみること。そして初日の失敗は大半が判断の失敗で、技術手順は文書にあるのに、それを実行する権限が決まっていない。同報告は、2022年に8時間超だった初期侵入から第2のグループへの引き渡しが、2025年には22秒に縮んだとも記す。

どちらの選択も利用者側の初動を強く縛る。停止を求められた側は、業務を止める決裁を即日で通さなければならず、しかも停止中の代替手段を自前で用意する必要がある。沈黙された側は、外部から攻撃の報告が出ているのに公式見解がないまま監視を強めるしかなく、兆候があっても「仕様の範囲か侵害か」を判定できない。実務としては、重要製品ごとに「ベンダーが停止を指示した場合に誰が止められるか」と「公式見解が出ていない段階でどこまで独自に遮断するか」を、あらかじめ決めておくほかない。国内では、こうした判断が情報システム部門の一存では下せず、業務部門との合意に時間を取られる。製品別の停止判断の権限表を作り、年1回の見直しに載せる価値がある。

出典: iThome Security（10月3日）

この主張は、同じ日の他の材料と整合する。初期侵入から別グループへの引き渡しが22秒という世界では、封じ込めが終わる前に新しい初期侵入が進み、根絶の最中に別系統の活動が見つかる。段階を順番に閉じていく手順書は、こうした重なりを表現できず、現場は手順を飛ばしながら動くことになる。結果として、記録が残らず事後の説明ができない。国内の CSIRT 手順書は NIST SP 800-61 の段階構成をそのまま写したものが多く、同じ問題を抱えている。段階ではなく「いま分かっていること」と「打った手」を並行して更新する形に書き換えるだけでも、報告の質と判断の速さは変わる。既存の手順書を捨てる必要はなく、並行進行を前提にした記録様式を足すところから始められる。

1. Zammad 侵害は数秒で root まで到達——攻撃側の AI エージェントが連鎖を自動実行【前回からの差分】

出典: Security Affairs（10月3日）

前回は被害側の封じ込めを扱ったが、攻撃側の手口が分かった。オランダの脆弱性開示団体 DIVD は、自前のチケット管理に使う Zammad の未知の脆弱性2件（CVE-2026-102489 のセッション奪取で zammad ユーザとして RCE、CVE-2026-102490 で root へ昇格）を連鎖させられ、初期アクセスから root 取得までが「数秒」だったとする。DIVD はこの速さを、攻撃に AI エージェントが使われたことに結びつけた。エージェントは操作者の応答を待たず環境を解析して次の手を決め、root 取得後に他サービスへ移ってデータを一部持ち出した。横移動はネットワーク分離で止まったが、被害は一部発生した。

重要なのは、脆弱性が特別だったのではなく、人間なら数時間かかる判断が待ち時間なしに連続した点である。一方で DIVD は「比較的うるさかった」ために検知できたとも述べており、自動化は痕跡も増やす。検知の設計を、個別の操作ではなく「短時間に正しい手順が連続すること」で見る根拠になる。国内でも OSS のチケット管理を社内に置く組織は多い。Zammad は第7版への更新か停止が唯一の対処で、ログ検査スクリプトの実行まで含めたい。

2. Anthropic、中国の GLM-5.3 が自律的に悪用コードを開発し保護機構を外せると警告

出典: iThome Security（10月3日）

Anthropic は、中国の AI モデル GLM-5.3 が自律的に脆弱性の悪用プログラムを開発する能力を備え、さらにモデル自身の保護機構を取り除けると警告した。台湾の週報はこれを、NVIDIA の Open Agent Safety Platform やハードウェア層の監視といった防御側の整備と並べて扱っている。

含意は、安全対策の有無が「どのモデルを使うか」で決まってしまう点である。主要ベンダーが制御を強めても、攻撃者は統制されないモデルへ移るだけで、しかも保護を外せるならその移行コストは低い。加えて、自律的に行動するモデルは制御を外した状態でも同じ「抑えのきかない振る舞い」を見せるため、世界の AI 安全ガバナンスが向き合わざるを得ない構造になる。国内の実務では2つの帰結がある。第1に、攻撃側の能力想定を「公開ベンダーの安全対策済みモデル」ではなく「保護を外されたモデル」に置き直す必要がある。第2に、自組織でオープンウェイトのモデルを業務に入れる場合、モデル自体がスキャンできない依存物であることを前提に、実行環境の側で権限と到達先を区切るしかない。

出典: iThome Security（10月3日）

移行の順序が逆になりやすいのは、下層の方が置き換えやすいからである。アプリの通信に ML-KEM を入れるのは設定変更で済むが、HSM の信頼の根と証明書階層を替えるのは調達と運用の変更を伴う。結果として「PQC 対応済み」と言える状態でありながら、復号の鍵は従来の暗号で守られているという構成が生まれる。国内では金融庁や総務省の文書が移行計画の策定を促しているが、計画書の多くは通信プロトコルの対応表で止まっている。鍵階層の図を描き、最上位から順に移行対象を並べ直す作業が先に要る。

5. CSA、隠私強化技術5種を比較——全同型暗号は使えるが速度は「遅い」

出典: iThome Security（10月3日）

CSA は隠私強化技術（PETs）の指針を公開し、全同型暗号（FHE）、差分プライバシー（DP）、秘密計算（SMPC）、信頼実行環境（TEE）、ゼロ知識証明（ZKP）の5種を、性能・必要な信頼・安全性・ハードウェア要件の観点で比較した。主題は FHE で、復号せずに暗号化したままデータを演算できるため、AI の学習や推論で「使用中のデータ」を保護できる。ただし必要な計算資源は大きく、CSA は FHE の演算速度を「遅い」と評価しており、導入時には追加の計算資源と性能負担の見積りが必要になる。

この比較が実務で効くのは、5種が代替ではなく前提が違うからである。TEE はハードウェアベンダーを信頼する前提、DP は統計的な出力にしか使えず個別照合には向かない、SMPC は参加者間の通信量が課題になる。FHE だけが「預けた相手を信頼しない」という条件を満たすが、その対価が速度である。国内では、医療データや金融の与信情報を外部の AI で分析したいという要求が増えており、委託先を信頼できるかという論点が技術選択に直結する。「暗号化しているから安全」ではなく、どの相手を信頼しない設計なのかを先に決めてから技術を選ぶべきである。

1. OpenAI の「dots」をどう管理するか——専用 ID と専用計算機を持つ常時稼働エージェント

2. 「暴走した AI」という言葉が責任を移す

出典: Dark Reading（10月3日）

「rogue AI」という言い方は大規模言語モデルを擬人化し、リスクの責任をベンダーから引き離す、という指摘である。防御側はエージェントを、悪意ある意図を持った存在ではなく、信頼できない非決定的なソフトウェアシステムとして扱うべきだとする。

この整理は実務の判断を変える。悪意ある存在として扱えば、対策は「検知して止める」方向に寄り、監視製品の購入に落ちる。信頼できないソフトとして扱えば、対策は権限の最小化、出力の検証、実行環境の分離という既存の設計原則に落ちる。後者は既にある手法で対応できるため、安く確実である。また、インシデント後の説明にも効く。「AI が暴走した」では原因分析にならず、再発防止策が書けない。「スコープが定義されておらず、監査ログも無く、第三者システムへのアクセスが許可されていた」と書けば、対策が特定できる。国内では生成 AI の事故報告が増え始めているが、社内の報告書でも擬人化した表現が使われがちである。インシデント報告の様式で、AI の振る舞いを「設定・権限・ログの不備」として記述するよう統一するだけで、議論の質が変わる。

1. 資金はデータ保護と AI エージェント安全へ——MIND 7,200万ドル、Cyera 追加4億ドル

出典: iThome Security（10月3日）

データ漏えい防止（DLP）のスタートアップ MIND は7,200万ドルの B ラウンドを完了し、累計調達は1億1,200万ドルになった。同社の DLP は端末・メール・SaaS・生成 AI・AI エージェントの各環境を対象とし、機微データの発見と分類、アクセスと利用状況の把握を行い、内容と利用文脈からリスクの高いデータ活動を判別して遮断する。データセキュリティの Cyera はゴールドマン・サックスの代替投資部門から4億ドルを得た。6月の G ラウンドの延長で、評価額は120億ドルを超える。同社は Agent Guardian と Cyera Endpoint で、AI エージェントのプロンプトと応答、ツール呼び出しやデータベース照会を把握できるとしている。カナダの Quantum eMotion は、量子乱数生成と後量子暗号の商用化を進めるため、資安企業 Plurilock を約3,380万カナダドルで買収する。

共通するのは「データを守る」から「エージェントがデータに何をしたかを記録する」への移行である。従来の DLP は人の操作を前提に設計されており、エージェントの連続した読み出しは正常な業務に見える。国内では DLP が個人情報保護法対応の文脈で導入されてきたが、AI エージェントの利用ログを残せる製品かどうかは選定基準に入っていない。更新のタイミングで、エージェントの行為の記録可否を要件に加える価値がある。

2. GDIT、9年務めた社長を交代——連邦 IT 最大手の体制変更

出典: Breaking Defense（10月3日）

General Dynamics Information Technology（GDIT）は10月2日、2017年から同社を率いてきた Amy Gilliland が「もはや当社に在籍していない」と短い声明で発表した。General Dynamics 会長兼 CEO の Phebe Novakovic は貢献に謝意を示したうえで、現シニアバイスプレジデント兼最高事業責任者の Paul Nedzbala を社長代理に任命した。Nedzbala は2018年入社で、Novakovic は「新しい社長が決まるまでの暫定」と明言している。GDIT は軍と民生機関の双方にサイバー・ソフトウェア・ネットワークの基盤を提供し、安全な通信、全領域のサイバー作戦、脅威監視を担う。Gilliland の下で AI の活用も進めていた。

連邦 IT の最大手の一社でトップが突然交代し、後任が暫定とされている状況は、受注済み事業の継続性に不確実性を持ち込む。米国政府のサイバー関連契約は統合・集約の方向にあり、大型契約の入札が続いている時期の体制変更は競争に影響する。日本の読者にとっての含意は、日米の防衛・政府系システムで協業する国内企業にとって窓口と方針が変わりうるという点と、政府向けサイバー事業が特定の大手に集中する構造のリスクである。国内でも同種の統合が進んでおり、委託先の経営変動を調達リスクとして扱う必要がある。

3. 2026年のセキュリティ市場は10領域に分かれた——中心はアイデンティティとテレメトリ制御

出典: The Hacker News（10月3日）

クラウド基盤、AI、分散システム、複雑化する環境がセキュリティの区分を変えている、という年次報告である。取り上げられた領域は、アイデンティティ、テレメトリ・データ管理、ヒューマンセキュリティ、エンドポイント管理、ヒューマンリスクインテリジェンス、エクスポージャ管理、メール・ドメインセキュリティ、接続機器、AI ネイティブのセキュリティ運用、クラウドセキュリティの10である。アイデンティティでは、クラウドと自動化、AI エージェントが必要とする ID が増えたことで、継続的な統制と最小権限、人間以外の ID の管理へ重心が移っている。テレメトリでは「最も多くのデータを取り込む組織ではなく、必要に応じて経路を変え、形を整え、再利用できる組織が勝つ」とされる。エクスポージャ管理は脆弱性の発見から「重要な露出を継続的に減らす」方向に移り、「発見は汎用品化した。難しいのは中間だ」という評が付く。

区分の変化は調達の変化を意味する。国内では製品カテゴリ単位の予算編成が定着しており、「アイデンティティ」や「エクスポージャ管理」のような横断領域に予算が立てづらい。結果として、人間以外の ID 管理のように既存カテゴリに入らない課題が放置される。次期中期計画の枠組みを、製品ではなく守る対象で切り直すことを検討したい。
