含意。国内でもクラウド上の検証環境や踏み台が22番を開けたまま放置される例は多い。自前で囮を置く場合は本件の制約——ポート転送の禁止、取得物の非実行、転送量上限——を必ず踏襲すること。囮が踏み台に転用されれば加害側になる。GPU を積んだ学習環境は計算資源そのものが標的である前提で、認証を鍵のみに限りたい。

総評

本日の論点は「一度出した許可を、後から取り消せるか」である。ゼロトラストは個々のアクセスを評価する設計だが、発行済みのトークンやセッションクッキーの前提が途中で変わった場合に追随できない。OpenID Foundation の Shared Signals Framework と CAEP は、この穴を標準化された非同期の信号配送で埋めようとしており、Apple・CrowdStrike・Google・Okta・Zscaler などが実装している。もうひとつは信頼の起点を物理に置く設計の解説で、iPhone の起動が BootROM からの段階的な署名検証として組まれている構造を追っている。

1. 発行済みトークンを後から失効させる——Shared Signals と CAEP

出典: CrowdStrike（10/25）

ゼロトラストの穴は、判断の前提が変わったときに追随できない点である。退職やエージェントの暴走で即時に全アクセスを止めたい、発行時の条件が期限内に変わった、権限の範囲が変わった——いずれも「トークンの有効性を見る」方式では扱えない。毎回 IdP へ再検証する方式は、1日有効のトークンが平均千回使われるため IdP に1,000倍の負荷をかけ成立しない。短命トークン化は約24倍に収まるが体験を損なう。

解法は、判断に要るデータを非同期で配送し、アクセス時点では手元のデータだけで評価する構成である。OpenID Foundation が6年以上かけた Shared Signals Framework は、Security Event Token（IETF 標準の JWT）を到達確認しながら配送する。その上の CAEP が「セッション失効」「デバイス準拠状態の変化」「資格情報の変更」「リスク水準の変化」を定義する。Apple・Google・Okta・Zscaler などが実装済みである。

含意。判断材料は IdP（アカウント）、XDR（端末の侵害）、MDM（準拠状態）、人事（休職）、当番表に分散しており、国内企業でもこの分断が残る。調達・更新の場面で IdP・SaaS・MSP に SSF／CAEP の対応状況を確認項目として入れたい。クッキー窃取に技術的な答えを持つのはこの層である。

2. モデルは「どう」、ハーネスは「何を」——統制はハーネス側に置く

出典: Daniel Miessler（10/25）

Daniel Miessler が、モデルとハーネス（エージェントを包む枠組み）の役割を整理している。主張は単純で、モデルは「どうやるか」を担い、ハーネスは「何をしてほしいか」を担う。モデルは急速に良くなるが、利用者自身と作業の文脈は知らない。したがってハーネスの仕事は手順を細かく指示することではなく、利用者が何者で、何を目指し、何を「完了」と見なすかを記述することである。手順を微細に管理するハーネスはモデルの能力に上限を課し、モデルが賢くなるほど早く陳腐化する——Richard Sutton の「苦い教訓」をハーネスに当てはめた議論である。

評価。セキュリティの観点でこの整理が効くのは、統制の置き場所を決める点である。モデルの振る舞いを安全側に寄せる努力はベンダー側の仕事で、利用者が制御できるのはハーネス——どの道具を渡すか、どのデータを参照させるか、何を完了条件とするか——である。本日の OpenAI の事例が示したのも、モデルの意図を推し量るのではなく境界の設計で封じるという方針だった。

含意。国内企業が社内にエージェントを導入する際、議論はモデルの選定に集中しがちである。だが監査可能性と事故の抑止はハーネス側の設計——与える権限、参照できるデータ、承認を要する操作、行動の記録——で決まる。モデル差し替えに耐える形でこの層を自前に持つことが、乗り換えの自由と統制の両方を確保する最短路になる。

2. 「SOC 24/7」の宣伝文句を1件ずつ検証した事例

出典: Habr（10/24）

事実。あるクラウドストレージ事業者（Aroshka Cloud）の実態を追った連載の第4回で、同社が「24時間の SOC」などを掲げる一方、執筆者らに対して5本の投稿を出し、DDoS 攻撃を仕掛けられたと主張した経緯が整理されている。執筆者は各主張を文単位で分解し、同社が7か月間に自ら公表してきた内容と並べ、アーカイブへのリンクを添えて提訴前通知を送った。発端は10月22日、クラウドのファイル名を取得するパーサーの作成依頼がフリーランス市場に出され、執筆者が自腹（299ルーブル）で契約した直後に依頼者の口座が凍結された経緯である。好意的なコメントを書いた利用者が、実は同社名義で発注を出していたことも示されている。

評価。個別の係争の当否はここでは判断しない。注目すべきは手法である。公開情報のアーカイブを時系列に並べ、主張と実績を突き合わせるという検証は、ベンダー選定でそのまま使える。「SOC 24/7」「監視体制」という語は定義が共有されておらず、人員数・当番体制・エスカレーション先・応答時間が明示されない限り、意味を持たない宣伝文句にとどまる。

含意。国内でも中小企業向けのクラウドや MDR サービスで同種の表示が増えている。調達側は、①当番の人員数と所在地、②応答時間の定義（受付か着手か復旧か）、③エスカレーション先と権限、④過去12か月の実績の提示、を文書で求めること。これらに答えられない事業者を外すだけで、選定の質は上がる。SNS 上の評判は発注された投稿と区別できないという前提も必要である。
