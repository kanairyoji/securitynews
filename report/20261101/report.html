1. VAPOR PANDA の ARTEX 運用、11日間で14か国・200組織超——EDR 未導入ホストの棚卸しまで工程化

出典: CrowdStrike Blog（2026-11-01）

前回（10/31）は「約140組織」までだったが、一次報告で範囲が確定した。10月17日から11日間、単一の ARTEX コントローラが14か国・200超の組織へ向き、中南米・欧州・アジア・中東の外務省、米国の製薬・半導体・防衛・原子力・金融19組織、米国・ベルギー・フィリピンの通信事業者が対象。9組織で BLOODALCHEMY 設置と資格情報スプレーを確認、別に12組織へパスワードスプレーが及んだ。LLM は中国製 DeepSeek 主軸に商用 LLM を併用し、単一侵入の計画エージェントだけで約14億入力トークンを消費した。

手口は既存技法の自動化である。未署名 SAML と XXE を連鎖させてクラウドのメタデータサービスから数千インスタンスへ管理命令を出せるロールを取得、別案件では LAPS 読み出しと RBCD による権限なりすまし、ギリシャ政府では2022年のエクスポートに残る未ローテーションの鍵で管理者トークンを偽造した。人間は中国語で要所のみ指示し、Falcon センサ未導入ホストを探す指示まで含んでいた。

名指しされた業種は国内の同業にそのまま当てはまる。今日打てる手は、EDR 未導入ホストの棚卸し、過去のディレクトリ・メールエクスポートに残る鍵と証明書の失効、SAML 署名検証と XXE 対策の再確認の三つである。

2. FBI が Binance の64.3億ドル窃取を TraderTraitor に正式帰属、約28億ドルを凍結

出典: The Hacker News（2026-11-01） / 보안뉴스（2026-11-01）

前回（10/31）は FBI の捜査開始までだったが、FBI はシークレットサービス・IRS-CI とともに計64.3億ドルの窃取を北朝鮮系 TraderTraitor（Jade Sleet／UNC4899 ほか3別称）に正式帰属させた。Chainalysis によると攻撃は米東部時間10月29日16:20頃に開始。Tornado Cash で初期資金を用立て、有効な署名データを提出してホットウォレットに攻撃者のコードを実行させ、複数チェーンへ移転した。最初の20分で凍結可能なステーブルコイン3.25億ドル分を ETH 2.85億ドル分へ交換したが、17:14頃から先制凍結が始まり約28億ドルが固着している。

帰属の決め手は、先月の Bitget 事案の窃取資金と本件の資金がリアルタイムに混ざったオンチェーンの融合だった。業界側の凍結着手が1時間を切ったことが被害額を左右している。

国内の取引所・カストディが同じ速度で動けるかは、ステーブルコイン発行者・分析ベンダー・捜査機関への連絡経路を平時に持っているかで決まる。署名データの提出でコードが実行された経緯は、署名検証と出金フローの権限分離の点検項目になる。

3. WARP PANDA が ESXi のゼロデイ CVE-2026-41709 を悪用、TITAN PANDA は法務専用ソフトを狙う

出典: CrowdStrike Blog（2026-11-01）

前回（10/31）は法務セクターへの侵入が3年でほぼ倍増・金銭目的82%という統計を扱ったが、同報告の中国系に関する部分には悪用済みの脆弱性が含まれている。WARP PANDA は米国の法務セクターを含む複数の侵入で被害組織の VMware vCenter 環境にマルウェアを設置し、一部では2026年初頭に至るまで ESXi のコマンドログ回避の脆弱性 CVE-2026-41709 をゼロデイとして悪用していた。TITAN PANDA は2026年4月、法務セクター専用ソフトウェアを狙った初の事例を実行。ほかに MURKY PANDA・OVERCAST PANDA が主要アクターに挙がる。

企業インフラのゼロデイ、クラウド環境の侵害、業種専用ソフトの悪用という三方向で手口が進んでおり、仮想化層のログ回避はフォレンジックの前提を崩す点が重い。

4. アジアの政府専用 Windows 10 ビルドを狙う NetamLoader、.NET アセンブリ読み込みで展開

出典: The Hacker News（2026-11-01）

Kaspersky が今週公表した分析によると、アジアの政府機関だけが使うカスタム版 Windows 10 を標的とする「高度に洗練された感染チェーン」が確認された。中核は未文書の .NET アセンブリ読み込みフレームワークで、NetamLoader と命名されている。

標的が政府専用ビルドに限られるため裾野は狭いが、攻撃者がその環境構成を事前に把握していたことを意味する。アクターの帰属は示されておらず断定は避けるべき段階である。.NET アセンブリをメモリ上で読み込む構成はディスク上の検体が残りにくく、ファイルベースの検知だけでは取り逃す。

日本では政府・自治体の標準イメージや専用ビルドが同種の事前調査の対象になりうる。標準イメージの構成情報（導入ソフト一覧・エージェント構成）が委託先経由で流出していないかの確認と、.NET の動的アセンブリ読み込みに対する AMSI・スクリプトブロックログの有効化が実務上の対応になる。

5. CSIS「No Front Lines」——紛争に巻き込まれる企業のための意思決定枠組み

出典: CSIS（戦略国際問題研究所）（2026-11-01）

CSIS が、武力紛争に巻き込まれる企業向けの意思決定ガイドを公表した。前提として挙げるのは2026年3〜4月のイランの行動で、軍事基地だけでなく湾岸地域のデータセンターを脅威対象に含めた点を「企業が前線に立つ」事例として扱う。報告書は経営層と取締役会に知識の欠落を洗い出す問いを置き、リスク評価の枠組みと緩和策を示し、最後に企業のリスクを政府がどう低減すべきかを米大統領への提言としてまとめた。赤十字国際委員会の支援による成果物である。

日本では通信・データセンター・海運・半導体材料の各社が台湾海峡や朝鮮半島の情勢で同じ問いに直面する。取締役会レベルで引き受ける支援の範囲と政府に求める保護を事前に合意しておく材料で、経済安全保障推進法の基幹インフラ審査と重なる論点でもある。

3. Repeat-After-Me——モデルが「実行できません」と答えてもツールは呼ばれている

出典: 阿里云先知（2026-10-30）

1. LXD と MicroCloud に CVSS 10.0——公開証明書だけで信頼済みクライアントになりすませる

出典: The Hacker News（2026-11-01）

重いのは前提条件の軽さである。秘密鍵の漏洩は侵害として扱われるが、公開証明書は設計上秘匿されず、構成管理リポジトリやバックアップ、運用手順書に平然と残る。本件は秘密情報を守れていたかではなく、API をどこまで露出させていたかで被害が決まる。

2. PHP2Shell の根本原因が公開——匿名 POST 1回でシェル起動、実環境の悪用は未確認

出典: CrowdStrike Blog（2026-11-01）

前回（10/31）は「修正は揃ったが武器化の障壁は高い」までだったが、根本原因と実証結果が具体化した。10月21日公開の CVE-2026-109618／109619 は 8.2.35／8.3.36／8.4.27／8.5.12 より前が対象（EOL 版も影響しうる）。致命的エラー時に PHP が longjmp() で実行文脈を巻き戻さず放棄するため、構築途中の構造や解放済みメモリを指す状態が残る。CrowdStrike は認証不要の匿名 POST 1回で mod_php ワーカーがシェルを起動することを検証し、ARM では HTTP だけで ASLR を回避した。

国内は PHP の CMS・会員サイト・申請系が厚く mod_php 構成も残る。公開系を優先した更新と、更新後のコンテナ再構築・ワーカー再起動が要る。不要なら session.upload_progress.enabled = Off と file_uploads = Off も設定したい。

1. LiteLLM 1.107.0 に情報窃取コード——Claude Code の応答ログ経由でトークン露出の疑い

1. 管理型脅威ハンティングを AI アプリとエージェント活動、Google Cloud へ拡張

出典: CrowdStrike Blog（2026-11-01）

CrowdStrike は Falcon Adversary OverWatch に、Falcon Guardian を通じた AI アプリと自律エージェント活動の24時間管理型ハンティングと、Google Cloud のテレメトリ駆動ハンティングを追加した。OverWatch Cross-Domain を土台に ID・クラウド・SaaS・他社データを横断でき、モジュールごとの SKU 購入は不要になる。

2. 自前と他社の IOC を SIEM へ取り込む——STIX/TAXII と有効期限管理

出典: CrowdStrike Blog（2026-11-01）

Falcon Next-Gen SIEM に Third-Party IOC Management が追加された。商用の脅威情報、業界 ISAC、政府機関、OSS 調査、自組織のハンティングや IR で得た IP・ドメイン・URL・ファイルハッシュを、STIX/TAXII・API・直接アップロードで取り込み、重複を自動統合する。取り込んだ指標は自動更新される精査済みリストとして相関ルールやハンティング検索に使える。有効期限設定による失効管理で、古い指標が誤検知を生み続けるのを抑える。

評価として新しいのは機能そのものではなく、指標の寿命を運用対象として扱う設計である。IOC は表計算やチケットに散在し、更新されないまま参照され続けると、検知が遅れるうえ無駄なアラートを生む。失効と重複統合を仕組みで持つかどうかが、脅威情報の購読費が検知に変わるかどうかを分ける。

国内では ISAC や JPCERT/CC から受け取る指標を手作業で各製品に投入している組織が少なくない。ベンダーの採用可否とは別に、自組織で確認すべき点は三つある。受領した指標の投入先と投入者が記録されているか、失効の基準（日数・情報源の更新）が決まっているか、同じ指標が複数の経路から来たときに1つに畳めるか。これらは製品を替えなくても手順として整えられる。

3. Kubernetes のランタイムを3層で見る——制御面と短命ワークロードの死角

出典: Darktrace（旧 Cado Security）（2026-11-01）

Darktrace 7.2 の HYBRID NETWORK が Kubernetes のランタイムに対応した。監視は3層で、ポッド間・ノード間・外向きのネットワーク層、コンテナ内の実行を見るプロセス層、Kubernetes API への操作（コマンド投入、RBAC 変更、管理操作）を見る制御面である。特権コンテナや過大権限のサービスアカウントも検出し、イメージの CVE を稼働ワークロードへ紐づける。コンテナが消える前に証跡を取得する調査機能も加わった。

1. プロンプトから実行までを1本の因果鎖で——AI 層と OS 実行層をつなぐ

出典: CrowdStrike Blog（2026-11-01）

AI エージェントは質問に答えるだけでなく、ファイルを開き、資格情報を使い、コードを実行し、ソフトウェアを導入し、ローカルでモデルを動かす。これらはすべて OS 上の操作である。CrowdStrike の Agent Graph は、エンドポイントのセンサが既に見ているプロセス・ファイル・通信に、プロンプト・モデル・ツール・スキルという AI 層を結びつけ、プロンプトから影響までを追跡する。提供される視点はエージェント一覧、セッションのグラフ、脅威スコアの3つ。

評価の軸は死角の位置にある。ネットワークのゲートウェイからやり取りの内容は見えるが、機械の内側で何が起きたかは見えない。Web ゲートウェイには、信頼済みサイトへ接続した事実しか残らない。この隙間で埋め込まれた指示がシェルコマンドに変わり、取得したファイルが利用者の権限で実行される。「何を頼んだか」ではなく「何をしたか」を記録できるかが分かれ目である。

国内でも開発部門のコーディングエージェントと業務部門の MCP 連携が先に広がり、監査は後追いになっている。確認すべき点は三つ。エージェントが使う資格情報を人の資格情報と区別できるか、起動したプロセスを人の操作と区別できるか、プロンプトを保存する場合に機密情報が残らない設定か。いずれも AI 利用規程に書ける項目である。

2. 良い防御エージェントの条件——未承認 MCP サーバ1,710台、MFA リセット調査を70秒へ

出典: CrowdStrike Blog（2026-11-01）

CrowdStrike が NVIDIA と実施したハッカソンに、50か国以上から約100件の自作セキュリティエージェントが集まった。優勝例の一つはエンドポイント上の MCP サーバを探して承認リストと突き合わせるもので、ある企業は1日で未承認の MCP サーバが1,710台のホストで動いていることを把握した。別の例は多要素認証のリセット悪用を検知し、20〜30分の調査が実データに対して約70秒、封じ込めが数時間から数分になった。例外管理のエージェントは、USB の例外が25,000台以上に付き2年以上有効な承認記録が無いことを見つけた。

設計上の共通点が整理されている。モデルには判断が要る部分だけを任せ、ルーティングや検索、固定計算は決定論的な道具に寄せる。前段の SIEM クエリで承認リストの照合と機密情報の除去を済ませてから渡す。スコアリングは関数側で計算し、同じ証拠からは同じ判定が出るようにする。封じ込めは人の承認を要し、承認者の名前を記録に残す。

日本の組織にとっての含意は着手点の選び方である。成果が出ているのは、重要だが緊急でないために後回しになる作業——未承認ツールの棚卸し、例外の期限確認、USB 経由の持ち出し確認——で、誤判定の影響が小さく投資効率が高い。導入時は人の承認を要する操作の線引きと、モデルに渡す前の機密情報の除去を先に決めたい。

1. 「LLM に良いコードを書かせる仕事」へ——宣言への反発と、残る受け入れ責任
