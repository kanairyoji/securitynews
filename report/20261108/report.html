1. APT28 が NATO 加盟国の海軍造船所に侵入——艦艇とエンジンの製造基盤が的

出典: 보안뉴스 boannews（2026-11-08）

Symantec（Broadcom 傘下）の Threat Hunter Team が、ロシア政府系 APT28（Fancy Bear／Forest Blizzard、追跡名 Swallowtail）の侵害を報告した。標的は NATO 加盟2か国の法執行機関、海軍の艦艇造船所、軍用機エンジン製造企業。造船所への攻撃は7月下旬で、攻撃者は約1週間、侵入済みの1台に繰り返し入り手作業で操作した。道具は HOOKEDGE——画面外に隠した Microsoft Edge の窓で命令を受け取るバッチ型バックドアで、APT28 が2023年4月から外交官に使ってきた HEADLACE とコードが重なる。資格情報は SSH 秘密鍵の逆接続トンネルと、NTLM 認証を横取りする PowerShell の2経路で奪った。

初期侵入経路、持ち出したデータ、残り2標的が実際に抜かれたかは非公開である。新規の脆弱性は使われておらず、手口は既存の検知対象に収まる。HOOKEDGE は Recorded Future の Insikt Group が8月末に初報告し、2025年9月以降のルーマニア・スペイン・トルコの政府機関への攻撃で確認されていた。

日本にも艦艇と航空エンジンの元請・下請が同じ構図で存在する。GCAP や日米共同開発に関わる企業は、外向き SSH の許可範囲、NTLM の無効化、ブラウザのヘッドレス起動の検知を点検したい。

2. ウクライナとロシアで緊急警報アプリが偽の核警報を配信

出典: The Guardian - Security（2026-11-08） / Security Affairs（2026-11-08）

11月1日、攻撃者がウクライナの緊急警報アプリを狙い、キーウの住民へ核攻撃の偽警報を送った。同種の偽警報はロシア側の市民にも届いたと報じられ、双方の警報系が同時期に突かれた。帰属は確定していないが、ウクライナ側の件はロシアが当然の容疑対象に挙げられている。

被害は金銭ではなく、住民が避難を判断する唯一の経路を汚染した点にある。警報配信は迅速さを優先して認証や二重確認が薄くなりがちで、攻撃側の費用は小さく効果は大きい。技術的な新規性はなく、配信基盤か事業者の管理系を取れば成立する。

日本は J アラート、L アラート、自治体の防災アプリ、緊急速報メールという多層の配信経路を持つ。民間事業者を含め、配信権限の分離、配信前の人による確認、誤配信を同じ経路で何分で訂正できるかを、攻撃を前提に演習しておきたい。

3. ロシア連邦統計局が攻撃を受け23TBが持ち出されたとの主張

出典: Security Affairs（2026-11-08）

ロシア連邦国家統計局（Rosstat）が大規模なサイバー攻撃を受け、ウクライナ戦争の死傷者数を含む23TBのデータが持ち出されたと報じられた。攻撃者の身元は明らかになっておらず、公表は被害側ではなく攻撃側と報道の経路から出ている。

評価には二重の割引が要る。持ち出し量と中身が攻撃側の申告であること、そして「公式統計が実態を記録していた」という前提自体が確かでないことである。それでも、国家が伏せている数字が外部から出る経路ができた点で情報戦の材料になる。同じ手口は人口・医療・徴兵の登録簿を持つあらゆる政府に向く。

日本の含意は、政府統計の基盤が流出と改ざんの両方に耐えるかという点にある。原票や個票は漏えいすれば企業と個人の機微に触れ、改ざんされれば政策の根拠が崩れる。公開系の e-Stat ではなく収集・集計の内側で、誰がいつ値を書き換えたかを後から証明できるか（監査ログと改ざん検知）を確認しておきたい。

1. 2027年度国防予算は「選別」の年になる——つなぎ予算なら新規生産が止まる

出典: Defense One（2026-11-08）

前回は「中間選挙で調整法案が消え、1兆ドル上限の攻防になる」までを扱った。差分は、上限が下がった場合に何が止まるかが具体化した点である。CSIS の Mark Cancian は、3,500億ドルの調整法案の成立は「怪しい」が約1.1兆ドルの基本予算は「十分可能」と見る。1.5兆ドルなら旧来システムと新規をともに賄えたが、1.1兆ドルでは取捨選択が要る。Forecast International の Shaun McDougall によれば、長期のつなぎ予算（CR）になれば陸軍は UH-60 後継の MV-75 とブラッドレー後継の XM-30 の生産を開始できず、海軍は新型潜水艦母艦と新型フリゲート、空軍はミサイル計画と CCA（協調戦闘機）が削られる。

弾薬は党派を超えて補充せざるを得ず優先される一方、新規開発の立ち上がりが後ろへずれる。中止ではなく「開始の遅延」が主な形になるため、供給側には読みにくい。政府閉鎖の可能性も残る。

日本の防衛産業と、GCAP や日米共同開発に関わる企業は、FY27 の発注時期が前提どおり来ない可能性を織り込む必要がある。弾薬の共同生産のように米側が優先する分野と、新規プラットフォームのように後ろへずれる分野で、投資と人員の張り方を分けたい。

2. 新議会は調達と取引の反腐敗調査へ——米国と商いをする企業の記録管理が論点

1. コーディングエージェントが残した秘密 — 1,994リポジトリに2,539件

出典: DataBreaches.net（2026-11-07）

1. 採用を人材紹介会社に任せても、雇用主の責任は残る

出典: Habr（情報セキュリティHUB）（2026-11-08）

ロシアの個人情報保護法（152-ФЗ）に沿って、人材紹介会社を使った採用の責任分担を整理した解説である。同じ案件の中で紹介会社は委託処理者・独立した運営者・雇用主という3つの立場を行き来する。例として、300人規模の物流会社が新倉庫の責任者と期間雇用30人を紹介会社経由で採用し、3か月後に「この紹介会社に登録していないのに、なぜ当社の履歴書を持っているのか」という候補者の申立てを受けて監督機関（Роскомнадзор）から照会が届く。法的根拠のない取扱いは法人に15万〜30万ルーブルの過料（行政違反法13.11条1項）が科される。

論点は「候補者の同意を誰がいつ取ったのかを雇用主が示せるか」である。紹介会社の立場が工程の途中で変わるため、契約書に委託と紹介会社自身の取扱いの境目を書き分けていないと、自社の取扱い部分を自社で説明できない。申立てが来るのは採用から数か月後で、その時点で記録が残っているかが決まる。

日本も構図は同じである。個人情報保護法の第三者提供（27条）と委託先の監督（25条）の区別に加え、職業安定法が求職者情報の目的外利用を制限する。人材紹介・ダイレクトリクルーティング・スカウト代行を使っているなら、①候補者への取得元の表示、②同意の記録の所在、③委託契約が覆う範囲——の3点を今期の点検項目に入れたい。応募者データの保存期間と、不採用者の削除手順も同じ束で確認できる。

2. サポート終了機器の責任が問われている — 既定パスワードはマニュアルに載っていた

出典: The Guardian - Security（2026-11-08）

欧州の冷蔵設備攻撃で、制御システムを提供する Danfoss は「影響を受けた機器の多くは古く、セキュリティ更新の対象外」「更新か旧ソフトの置き換えを以前から推奨してきた」と説明した。一方、英 NCSC の運用部長は、攻撃者は脆弱性探索に AI を使う必要すらなく、ある冷蔵機器メーカーのマニュアルに既定のアクセスパスワードが掲載されていたと指摘している。

争点は2つある。「サポート終了」と「現に稼働している」の差は誰の責任か、そして既定パスワードをマニュアルに掲載する設計は更新の有無とは別の瑕疵ではないか。前者は契約で、後者は製品仕様で決まる。

1. 出荷前に50種類の攻撃を当て、出荷後に判断経路を追う

2. Vibe Coding の定義は「AI の使用量」ではない

出典: Daniel Miessler（Unsupervised Learning）（2026-11-07）

Daniel Miessler は、Vibe Coding を「AI を使って作ること」と混同するなと書いた。Vibe Coding とは、裏側の動きが本人にとって完全な謎である状態を指す。Andrej Karpathy が2025年2月に「自分の理解を超えて育つコード」として作った語である。コードの100%を AI が書き、月に数十から数百の機能を出していても、どう動くかを把握していればそれは工学である。逆に、どのスタックか、どの言語か、セキュリティをどう実装したかを知らないままサイトを公開すれば Vibe Coding になる。

区別の軸が「理解の有無」であることのセキュリティ上の意味は明確である。脆弱性が出たときに修正できるか、インシデント時に影響範囲を言えるか、監査で設計根拠を説明できるかは、AI の使用比率では決まらない。

国内でも社内規程が「生成 AI でのコード生成の禁止／許可」を軸に書かれている例が多いが、それでは管理できない。書くべき条件は、出荷前に誰が構成（言語・依存・認証と認可の実装）を説明できるかである。受託開発の契約でも、成果物の要件として「引き継ぎ時に構成を説明できること」を入れておけば、同じ線引きが使える。

1. 検知の抜けを探す新興が1,500万ドル調達 — 自動化の前段に検証を置く

出典: SecurityWeek（2026-11-08）

売りの核は「AI エージェントは、自分のシステムが検知できなかった攻撃を調査できない」という指摘である。証明されていない証跡に基づく判断は自動化できないという論理で、検知基盤が見えているかを確かめる層が商品になりつつある。

国内では SIEM を導入したが検知ルールの妥当性を測っていない組織が多い。製品を買う前にできるのは、主要な侵入経路（RDP・VPN・管理画面・コーディングエージェント）が自社のどのログに現れるかを1枚に書き出すことである。ログが入っていない経路は、どの製品でも検知できない。

2. AI 機能の課金が契約を複雑にする — 買い手の6割はベンダーを減らしたい

日本のユーザ企業に効くのは交渉条件である。統合契約には「使用量の可視化」「上限の設定」「利用権の一覧化」を入れる。AI 機能の従量課金は年度予算の読みを壊すため、監査可能な使用量レポートと、上限到達時に止まるのか超過課金になるのかを契約書に明記しておきたい。
