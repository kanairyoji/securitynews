1. 中国系の自律AIエージェントが医療画像ソフトのゼロデイを11分で見つけ、root を奪った

出典: SecurityWeek（2026-11-21）

Amazon Threat Intelligence は9月、認証のない自律ペネトレーションテスト基盤 Cairn の公開インスタンスから、9月8日以降約48時間の作戦記録を観測した。プロンプトは簡体字、タイムスタンプは中国標準時、標的は中国本土以外の東アジアの大学。エージェントは医療画像AI「MONAI Label」0.8.5以前のパストラバーサル（既定で認証が無効）を自力で見つけ、APIの把握から任意ファイル書き込みまで約11分、のちに root でリバースシェルを得た。

Amazon は中程度の確度で中国系に帰属した。成功は3件目で、先行して Redis に16時間・148手、GPUサーバに実在80ユーザ名の資格情報試行を仕掛けいずれも失敗している。休憩も就業時間もなく丸1日適応を続ける速度が、SOCのアラート選別を上回るという指摘が核心である。MONAI Label 側は今週アドバイザリを出した。

日本の大学・医療機関は研究用のオープンソースAI基盤を学内網に素のまま置いていることが多い。認証のない管理画面やアップロード機能が外部から到達できないか、まず到達性を切るべきだ。公開から悪用までの猶予が数日から数時間へ縮む前提で、境界の棚卸しを急ぎたい。

2. 台湾、地方選を前に中国系とみられる Threads アカウント約2,700件を Meta に通報

出典: OODA Loop（2026-11-20）

台湾当局は、11月28日の市長・県長選挙を前に、Meta のテキスト型SNS「Threads」上で協調した中国の情報戦と疑われるアカウント約2,700件を同社に通報した。Threads が選ばれたのは台湾での利用が多いためで、同一の兆候は Instagram 側では確認されていない。通報対象のほぼ全てが直近に開設されたアカウントだという。

プラットフォームを1つに絞って大量開設するやり方は、検知される前に選挙期間を走り切る前提の運用である。アカウント開設時期という単純な指標で2,700件が束ねられている点は、投稿内容ではなく登録・行動のパターンで判定できることを示す。他方、通報は削除を保証しないため、実際にどれだけ落ちたかは選挙後の検証を待つ必要がある。

日本でも統一地方選や国政選挙の前に同じ構図が起こり得る。要点は、政府とプラットフォームの間に「選挙前の大量通報を処理する」常設の窓口があるかどうかで、台湾は実務として回している。企業側でも、自社名や役員名を騙る新規アカウントの監視を選挙期・決算期に合わせて強める運用が現実的だ。

3. ロシアが交渉の場に「NATO1997年国境」を持ち出し、米国は制裁を緩めた

出典: Atlantic Council（2026-11-20）

元駐ウクライナ米大使の John Herbst は、11月19日の米中露3首脳会談に至る6週間を一連の譲歩として整理した。10月9日に米国が対露制裁方針を曲げてロシア産ディーゼルを購入し、署名済みの対露・対イラン制裁法の制裁を全面免除、会談後はロシア側が「世界の消費者向けの石油増産で協力する」との声明を出した。ロシアはウクライナ領土の追加割譲に加え、NATO が1997年の加盟範囲に戻ることを要求している。

要求が領土から「欧州の安全保障の枠組み」へ広がった点が、これまでとの違いである。1997年の線に戻れば中東欧のNATO加盟国が常時圧力下に置かれるため、個別の停戦条件ではなく同盟の設計そのものが交渉材料になった。評価はウクライナ支援を続ける側の立場からのものだが、制裁免除と声明という2つの事実は確認できる。

6. ウクライナ戦4年の教訓は、ドローンとAIではなく「戦役・territory・消耗」だという指摘

出典: War on the Rocks（2026-11-20）

1. 中国 NVDB が Linux カーネルの RCE を警告、CVE-2026-98432 は 4.4 以降ほぼ全主線

出典: 安全客（2026-11-20）

出典: CrowdStrike Blog（2026-11-21）

前回からの差分は、被害者の特定から攻撃者側の道具の作り方へ分析が及んだ点である。CrowdStrike は2026年2月、イラン系 STATIC KITTEN が管理する IP アドレス 157.20.182[.]49 上の開ディレクトリに 1.9GB・2万ファイル超を発見した。その中に、FortiOS と FortiProxy の認証回避 CVE-2024-55591 向けに2025年1月27日公開された PoC の改造版があった。公開版は1コマンドを実行するだけだが、改造版は13の固定ペイロードを持ち、標的の列挙、FortiWiFi という名のバックドア管理者（パスワード FortiWiFi123、super_admin）の作成、SSL-VPN グループへの追加までを自動で行う。

要点は、公開 PoC が「検証用の道具」から「運用可能な攻撃部品」へ数日で変換されることである。PoC の公開を悪用の目安として扱うなら、変換に要る時間は想定より短い。

国内でも Fortinet の SSL-VPN は中堅企業と自治体に広く入り、CVE-2024-55591 は旧いが未適用の機器が残る。管理者一覧から FortiWiFi のような見覚えのない super_admin を探し、SSL-VPN のグループに無断で追加されたユーザーがいないか点検したい。

5. 台湾の詐欺集団が専用機器から一般の Android 端末へ — 1〜9月で38拠点・111台を押収

出典: iThome Security（2026-11-20）

専用機器の取締りが効いた結果、犯罪側が「どこでも買える道具」へ移った構図である。摘発の指標として機器の押収台数を使うと、この移行は見えなくなる。詐欺集団が一般市民を「機器の預かり役」として在宅副業名目で募っている点も、被害者が加害側の一部になる経路を作っている。

日本でも国際電話の表示や発信規制で同種の対策が進み、同じ回避圧力がかかる。国内事業者と警察にとっての含意は、異常な通話量の監視を機器の種類に依存させないことである。企業側では、自社名義の回線や SIM が社外で使われていないか、解約漏れの回線が残っていないかを棚卸する価値がある。

カテゴリ: カテゴリ9「脆弱性・ライフサイクル管理」
対象日: 2026年11月21日
生成日時: 2026-11-22

総評

CISA が Apache Roller・Cisco Expressway・SAP NetWeaver・VMware vCenter の4件を KEV に追加し、11月に名前のついた脆弱性が「公開」から「悪用確認」の段に移った。F5 は BIG-IP APM と iRule に CVSS 9.8 を5件含む帯域外修正を出した。Java4Shell はディストリビューションのパッケージが版数上は新しく見えても脆弱という罠が明らかになり、NGINX2Root は root 取得と Docker 脱出まで実証された。同じ CVE-2026-123007 が Synology の Application Portal Manager にも影響し、修正が版によって未提供である点は国内に直結する。11月の Patch Tuesday は 1,252 件で、プレビューペインで起動する RCE が3か月連続の主戦場である。

1. CISA KEV に4件追加 — Apache Roller・Cisco Expressway・SAP NetWeaver・VMware vCenter

出典: The Hacker News（2026-11-21）

CISA は11月20日、実際の悪用の証拠があるとして4件を KEV に追加した。Apache Roller のデシリアライズ CVE-2026-129448（CVSS 9.8）、Cisco Expressway の CVE-2026-76466、SAP NetWeaver、VMware vCenter の認証回避 CVE-2026-123890 である。対象は vCenter 8.0 U3m 未満と 7.0、VCF/vSphere Foundation の 9.1.1.0200／9.0.2.0200 未満、Telco Cloud 系を含む。

前回からの差分は、vCenter が「修正版が出た」段階から「悪用が公的に確認された」段階へ移ったことである。vCenter には代替緩和策がなく更新の適用だけが対策になる。Expressway と NetWeaver は外部公開されることの多い入口で、Roller のデシリアライズは認証前に到達し得る。

国内では VMware の仮想化基盤が金融・製造・自治体に広く残り、NetWeaver は大企業の基幹系、Expressway は在宅勤務の通話の入口に入る。優先順は「外から触れる Expressway と Roller」→「vCenter」→「NetWeaver」。KEV 収載は国内でも悪用の事実確定として使える。

2. F5 が BIG-IP APM と iRule に帯域外修正 — CVSS 9.8 が5件、認証前の RCE に至り得る

出典: CSO Online（2026-11-21）

F5 は BIG-IP Access Policy Manager（APM）と iRule 向けに帯域外パッチを公開し、5件が CVSS 9.8 である。いずれもスタックベースのバッファオーバーフローで、未認証の攻撃者が Traffic Management Microkernel（TMM）を停止させ遠隔でコードを実行し得る。条件は iRule の構成に依存し、CVE-2026-121805 は PEM:subscriber、CVE-2026-120292 は HTTP プロファイルと MR:message route、CVE-2026-120285 は PSC 系コマンドを含む iRule が仮想サーバに設定されている場合である。

前回からの差分は、傾向の話から具体的な悪用条件の列挙に進んだ点である。影響は BIG-IP の有無ではなく、どの iRule を書いているかで決まる。TMM が落ちればその機器が捌く全サービスが止まるため、RCE に至らなくても可用性の被害は確定する。

国内では BIG-IP が金融・通信・大企業のリモートアクセスとロードバランサに広く入り、APM は VPN 代替に使われる。自組織の iRule で該当コマンドを文字列検索し、見つかれば計画外で当てる判断に進むべきである。該当がなければ通常のパッチ周期でよい。

3. Java4Shell は版数で判断できない — ディストロのパッケージは「新しく見えて脆弱」

出典: Qualys Security Blog（2026-11-20）

前回からの差分は、適用判定に使える表が出たことである。Java4Shell（CVE-2026-114938）は HotSpot の AVX-512 Base64 デコーダのヒープ領域外書き込みで、Oracle は11月17日に修正を公開した。対象は Java SE / OpenJDK の 17.0.21.1・21.0.13.1・25.0.5.1・27.0.1.1 より前、Java SE 8 EPP（8u513-perf で修正）、GraalVM ほかで、EOL 系列に修正はない。重要なのは、修正前にビルドされたディストロのパッケージは版数が現行に見えても脆弱な点で、Ubuntu の 17.0.21.0.3 と Oracle Linux の 17.0.21 が実例である（評価は Oracle が 8.1、Red Hat が 9.8）。

悪用には対象の Java 版、AVX-512 VBMI 対応の x86-64 CPU、攻撃者が与えた Base64 を復号するアプリケーションの3条件が要る（ARM64 は影響しない）。発見者は Keycloak・Jira・Confluence ほかで認証前 RCE を示したが、11月17日時点で実環境の悪用報告はない。

国内では Base64 を使う HTTP Basic 認証・JWT・SAML が至る所にあり、脆弱な経路は入力検証より手前で踏まれる。即時に当てるのは外部に面した Java サービスで、当てられない場合は -XX:-UseBASE64Intrinsics を付けて再起動する。確認は java -version ではなくベンダーのビルド番号と JDK-8393212 の取り込みで行うこと。

4. NGINX2Root は root 取得と Docker 脱出まで実証 — 同じ CVE が Synology にも

出典: CrowdStrike Blog（2026-11-21）

前回からの差分は、PoC 公開の報から攻撃連鎖の全体像に進んだ点である。11月18日公開の nginx の重大な脆弱性5件が NGINX2Root と総称され、CVE-2026-123007 と CVE-2026-123633 は CVSS 4.0 で 9.2。前者は HTTP/2 の整数アンダーフローで、認証も利用者操作もなしにワーカープロセスで任意コマンドを実行できる。ワーカーは非特権だが、Linux カーネル SCTP の欠陥で root へ昇格し、Docker コンテナからホストへの脱出まで実証された。Synology も同じ CVE-2026-123007 が DSM・BeeStation OS・Application Portal Manager に影響すると公告したが、提供されたのは一部版のみである。

HTTP/2 は本番の nginx でほぼ既定で有効なため「特殊な設定をしていない」ことは免責にならず、コンテナ化も緩和にならない。Synology の件は、同梱部品の脆弱性が機器の管理画面に降りてくる典型である。

Synology は国内の中小企業・部門サーバで広く使われ、専任管理者のいないまま外部公開されている設置が多い。公開 nginx の版と HTTP/2 の有効無効を洗い出して当て、DSM は提供済み更新を当てて APM の外部公開を止め、未提供の版は管理 UI の到達元を社内 IP に限りたい。

5. 11月の Patch Tuesday は 1,252 件 — プレビューペイン起動の RCE が3か月連続の主戦場

出典: CrowdStrike Blog（2026-11-21）

2026年11月の Patch Tuesday は 1,252 件の CVE を含み、68 件が Critical、ゼロデイは1件。目立つのは Office 系の Critical RCE 8件で、Outlook の CVE-2026-110043 と CVE-2026-110068 は閲覧ウィンドウで悪性メッセージを選択するか添付をプレビューするだけで、クリックもマクロ確認もなくコードが実行される。ID 基盤では LDAP の RCE（CVE-2026-119958）と AD DS の RCE・権限昇格（CVE-2026-118146／118148）が Critical、Hyper-V の権限昇格は8件、認証不要で到達可能な RCE は14件ある。

国内の実務では、月次のパッチ適用を「全部そろえる」から「配信経路とID基盤を先に閉じる」へ組み替えるのが合理的である。Outlook と Office を最優先、次に AD DS・LDAP を抱えるドメインコントローラ、その後に Hyper-V。Hyper-V は仮想化ホストだけでなく、Windows Sandbox や Credential Guard を有効にした一般端末も対象になる。

1. PLAID の KARTE が侵害され、JINS・DHC・三菱UFJ銀行など数十社が連鎖公表

出典: iThome Security（2026-11-20）

日本のマーケティングテクノロジー事業者 PLAID の CX プラットフォーム「KARTE」が侵入を受け、これを利用する JINS・DHC・三菱UFJ銀行など数十社が、個人情報の流出または流出の可能性を順次公表する事態になっている。台湾の iThome は11月16〜20日の週次総括で、愛爾蘭の銀行 IT 事業者 Wellington IT（信用組合約40社に波及）と並ぶ代表例として本件を挙げた。KARTE は顧客の行動データを収集・解析して接客を最適化する基盤で、導入企業のウェブサイトやアプリに組み込まれて動く。

連鎖の規模は、委託先の事業規模ではなくタグが埋め込まれたサイトの数で決まる。計測・接客系の SaaS は IT 部門ではなくマーケティング部門が選定・契約することが多く、資産台帳にもベンダー評価にも載らない。流出の有無を各社が独自に確認できない点も重く、公表が順次になるのは調査が委託先の報告待ちになるためである。

国内の読者が今日できることは3つある。自社サイトとアプリに入っている外部タグ・SDK の一覧を作ること、その選定・契約がどの部門にあるかを明らかにすること、そして各タグがどの個人情報に触れるかを整理することである。KARTE 利用企業は、自社が受け取る報告を待つだけでなく、取得項目の範囲を自分の側の設定から確認したい。

1. Cloudflare が ruby2shell と phpAfterShell を無料プランまで遮断 — ただし「代償制御」と明記

出典: Cloudflare Blog（2026-11-20）

Cloudflare は11月19日公開の ruby2shell（CVE-2026-132825、Ruby の文字列大小変換のヒープバッファオーバーフロー）に対し、Free Managed Ruleset と Managed Ruleset の両方に2規則を既定動作 Block で追加した。1つは ruby2shell 向け、もう1つは同じリリースで修正された整数オーバーフロー GHSA-87fm-7w84-j2px 向けである。phpAfterShell（CVE-2026-126714、CVSS 4.0 で 9.2）は、10月に php2shell 向けに展開した PHP の RCE 規則が公開前から攻撃パターンの一部を検知していたため、11月19日に検知ロジックを更新した。有料プラン向けには PHP-FPM の CVE-2026-129289 と SOAP 拡張2件の規則も追加された。

5. MITRE ATLAS を検知カバレッジの採点に取り込む — ATT&CK には混ぜない

出典: Elastic Security Labs（2026-11-20）

出典: iThome Security（2026-11-20）

AI がもたらす課題に対し、業界団体と当局の文書が相次いだ。クラウドセキュリティアライアンス（CSA）は自律的なペネトレーションテストの保証標準 APAS 1.0 を公表し、英国の NCSC は企業の取締役会に能動的な脅威ハンティングを重視するよう呼びかけた。OWASP は AI データセンターの10大セキュリティリスクを公表し、RSAC は2027年に企業が GRC（統治・リスク・コンプライアンス）とインシデント対応の能力をより重視する必要があると予測した。

4つの文書の方向は揃っている。AI による検証の自動化を認めるが、その品質を測る基準を作る。そして検知の受け身の運用から、能動的な探索へ重心を移す。取締役会に名指しで求めている点が重要で、脅威ハンティングは人員と時間を要するため、現場の工夫では始まらない。

日本企業の実務では、脅威ハンティングは「予算が付かない活動」の代表である。検知件数や遮断件数では成果が示しにくく、投資判断に乗らない。NCSC の提言を使うなら、報告の単位を「探索した仮説の数と、その結果として変えた設定の数」に置き換えるのが現実的である。あわせて、AI を使った診断サービスを調達する際に APAS 1.0 への適合を要件に入れられるかを確認したい。

3. セキュリティでは言葉が道具と同じくらい重要になる

出典: Dark Reading（2026-11-20）

クラウドセキュリティの説明から AI の利用まで、セキュリティ部門の責任者たちは、明確で規律のある意思疎通が全社にわたる最前線の防御能力になっていることに気づきつつある、という指摘である。道具の導入ではなく、伝え方の質が防御の成否を左右する局面が増えている。

この論点は測りにくいが、具体的な場面は想像しやすい。AI の利用規程が曖昧なために現場が独自判断で持ち込む、脆弱性の緊急度が事業部門に伝わらず適用が遅れる、インシデントの初報が不正確で経営の判断を誤らせる。いずれも道具では解けない。

国内では、セキュリティ部門の文書が「対策の実施状況」の記述に寄り、事業への影響と選択肢を提示する形になっていないことが多い。改善の出発点は、報告の冒頭に「この件で経営が決めるべきことは何か」を1行で置くことである。用語の統一も効く。社内で「インシデント」「侵害」「漏えい」の使い分けが揃っていない組織では、同じ事象が部門ごとに違う重さで扱われる。

総評

Nvidia が拡散型 LLM の新興企業 Inception を5億ドル超で買収する交渉に入った。経営体制が揺れる最中にも技術の囲い込みは続いている。人材の側では IDC が通説を否定する調査を出し、AI 投資で高い投資効果を得ている組織ほど今後の増員を見込んでいることが示された。製品市場では SIEM と ID セキュリティの評価機関レポートが相次ぎ、攻撃ツールの側でも Flipper Zero の後継機が公開直後に巨額を集めている。資格試験では AI による不正の検知が追いつかず、技能の証明という前提が揺らいでいる。

1. Nvidia が拡散型 LLM の Inception を5億ドル超で買収交渉

出典: OODA Loop（2026-11-20）

Nvidia が、設立から約2年・従業員30名超のカリフォルニア州パロアルトの新興企業 Inception を、最低5億ドルで買収する交渉の最終段階に入った。従業員向けには業績連動の追加報酬が上積みされる可能性がある。交渉は Jensen Huang 氏が CEO を退く前に始まっており、同社にはそれ以前に Microsoft からの買収関心もあった。Inception は従来の自己回帰型とは異なる拡散型の言語モデルを手がける。

買収の対象が「別の生成方式」である点が読みどころである。自己回帰型が主流の中で拡散型を押さえる動きは、推論の速度と費用の構造を変える賭けと見える。セキュリティの観点では、生成方式が変わればプロンプトインジェクションや出力の制御の前提も変わるため、既存の防御手法がそのまま通用するとは限らない。

国内企業にとっての含意は、AI の調達判断を「どのモデルを使うか」ではなく「生成方式が変わっても残る統制は何か」で考えることである。入出力の監査ログ、権限の分離、外部データの取り込み経路の制限は方式に依存しない。逆にモデル固有の安全性設定に依存した統制は、基盤の切り替えで作り直しになる。

2. IDC の調査 — AI で成果を出している組織ほど増員を見込む

出典: ITmedia エンタープライズ（2026-11-21）

IDC は11月17日、「AI が普及すれば企業の人員は減る」という過去1年の通説と食い違う調査結果を公表した。AI 投資で50%以上の投資収益率（ROI）を得ていると回答した組織を「リーダー」と位置づけたところ、その過半数が今後18か月で人員が増えると見込んでいた。今後18か月でエントリーレベルの人員が増えると見込む割合は、リーダーが68%、ROI がまだプラスでない「ラガード」が40%、中間の「アチーバー」が51%だった。中間管理職と上級管理職でも同じ傾向で、3分類のいずれも一部の人員削減を見込んでいる点は共通する。

削減と増員が同時に起きるという構図である。AI の影響を受けやすい職種で初級の採用が鈍る一方、成果を出している組織は別の職種で採っている。セキュリティ人材の採用計画にそのまま読み替えると、AI で自動化が進むほど採用が止まる、という想定は成り立たない。

国内のセキュリティ部門にとっての実務的な意味は、投資の説明の仕方である。AI による自動化を「人員削減の根拠」として説明すると、効果が出た後に増員を要求しにくくなる。説明の軸は、同じ人数で扱える事案の範囲と深さを広げること、そして自動化で空いた時間を脅威ハンティングや設計のレビューに振り向けることに置くべきである。

3. SIEM と ID セキュリティで評価機関レポートが相次ぐ

出典: Microsoft Security Blog（2026-11-20）

Microsoft が2026年の Gartner Magic Quadrant for SIEM でリーダーに位置づけられたと発表し、CrowdStrike も2026年の IDC MarketScape（世界の拡張 ID セキュリティソリューション）でリーダーに選出されたと公表した。CrowdStrike は同時に、Falcon Next-Gen SIEM を「エージェント型 SOC の基盤」と位置づける方針も示している。SIEM と ID セキュリティという、SOC の中核2領域で評価の更新が重なった。

評価機関のレポートは製品選定の出発点にはなるが、判断材料としては粗い。SIEM の優劣は取り込めるログの種類と保持費用で決まり、ID セキュリティは既存のディレクトリ構成との相性で決まる。両社がいずれも「エージェント型 SOC」を前面に出していることは、評価軸自体が AI の活用度に移りつつあることを示す。

国内企業が調達で確認すべきは、AI 機能の有無ではなく自社のログが実際に取り込めるかである。国産の業務パッケージ、オンプレの認証基盤、閉域網の機器は標準のコネクタに無いことが多い。評価機関の位置づけを根拠に選定し、取り込みの開発費が本体費用を上回る例は珍しくない。見積の段階でログ源の一覧を提示して確認したい。

4. Flipper Zero の後継機 Flipper One が公開直後に巨額を集める

出典: CNews（2026-11-18）

Flipper Zero を作った開発陣が、新しい携帯機器 Flipper One を Kickstarter に公開した。開始から10分で8,000万ルーブル超、1日でおよそ10億ルーブルを集めた。前機種が「ハッカーのたまごっち」と位置づけられたのに対し、Flipper One は Linux を動かす本格的な携帯型コンピュータとして位置づけられるが、外観は前機種に似た設計である。

Flipper Zero は無線信号の記録・再生やカード読み取りの検証に使える道具として普及し、犯罪への悪用を理由に一部の国で規制が議論された。後継機が汎用の Linux 機になることで、できることの幅は広がる。調達の容易さと価格が下がり続けている点が、防御側にとっての実質的な変化である。

国内の企業が備えるべきは、物理と無線の接点である。入退館カード、車両の無線錠、無線式のセンサー、USB 経由の入力は、いずれも「専門機器が要る」という前提で保護水準が決められてきた。前提が崩れるなら、カードの方式（レガシーな 125kHz など）の更新、USB の入力制御、無線機器の在庫把握を優先度の高い課題として扱う必要がある。

5. 資格試験での AI 利用による不正 — 検知が追いつかない

出典: Dark Reading（2026-11-13）

IT 資格試験の受験者が人工知能を使って不正を行っているかを検知することは難しいが、信頼を高めるための新しい道具と手順が現れつつあるという報告である。試験の実施側が、監視と出題の両面で対応を模索している段階である。

影響は資格の価値に直接及ぶ。採用と要員配置で資格を技能の代理指標として使っている組織は、その指標の信頼度が下がることを前提にしなければならない。とくに在宅での遠隔受験が一般化した領域で、検知の難しさが大きい。

国内では、セキュリティ人材の採用・配置・入札資格で情報処理安全確保支援士や各種ベンダー資格が使われている。実務としては、資格の有無だけで配置を決めず、実機の演習や過去の対応事例の説明を選考に入れることが現実的である。社内の教育でも、修了試験の結果より「実際に設定を変えられたか」を到達点に置く設計へ寄せたい。
