今週の要点

リスクレベル: 🔴 危機（前週から据え置き・2週連続）。 前週からの変化は件数ではなく、入口が特定されたことである。相次ぐ国内の大量漏えいについて、公開アプリの背後にある API を突く手口に名前が付き、点検すべき場所が画面から API へ移った。

  • 国内の大量漏えいが7日連続で公表され、突かれていたのは API だった → 大項目1
  • 預けた基盤の一点が、数百社と公共機能を止めた → 大項目2
  • 遠隔・特権アクセス装置が「最新版でも侵害済み」の前提に変わった → 大項目3
  • 攻撃の自動化が隣国の金融16社で実害になった → 大項目4
  • 日本を狙う経路が名指しされ、報告義務が同じ週に動き出した → 大項目5

今週中に決めること: 遠隔・特権アクセス装置を「侵害済み前提」で調査する判断を出すか。会員基盤の取得件数の上限を誰が決めるか。

大項目1: 突かれたのは画面ではなく、アプリが呼ぶ API だった

何が起きたか。 国内の大量漏えい公表が7日間続いた。ソフトウェア販売会社で2,251万9,960件（会員情報を取得する API の悪用）、飲食チェーンのアプリ会員1,118万件。情報通信研究機構は公開 Android アプリから背後の API を攻める経路を「A2B 攻撃」と命名し、JPCERT/CC は攻撃元サーバの調査から、攻撃者が APK を解析して API を特定し AI で走査を回していたことを示した。

日本への影響。 共通するのは認証は通るが認可が甘い形（他人の識別子を指定できる・取得件数に上限がない）で、WAF では止まらない。国家サイバー統括室も Web の脆弱性管理・委託先管理・保有データ管理の3点で対策強化を要請した。

経営の問い。 自社のアプリが呼ぶ API を、画面に紐づかないものまで含めて一覧で出せるか。

→ 事例「会員情報2,251万件の API 窃取」「アプリ会員1,118万件」。

大項目2: 規模を決めたのは、預けた基盤の一点だった

何が起きたか。 国内のクラウド事業者のランサムウェア被害は495の企業・自治体に及び、既存データが戻らないため復旧は顧客自身のバックアップに委ねられた。自治体の一斉同報サービスは J-ALERT 連携の配信経路ごと止まり、800近い自治体に波及した。海外では MSP 向けバックアップ製品のアプリ識別情報が奪われ、Microsoft 365 の162〜173テナントに正規の認証で侵入された。MFA は素通りし、アプリを止めても発行済みトークンは有効である。

日本への影響。 国内でも MSP・IT 委託経由の M365 連携は広く使われている。委託先の障害が自社の復旧手段や公共機能そのものを止める構図は、クラウド基盤と防災配信の2件で現実になった。

経営の問い。 自社テナントに常時権限を持つ第三者アプリを、誰がいつ承認したか説明できるか。預けた基盤が止まったとき、自社で戻せるバックアップはどこにあるか。

→ 事例「委託先アプリ経由の M365 テナント乗っ取り」。

大項目3: 遠隔・特権アクセスの装置は「最新版でも侵害済み」で扱う

何が起きたか。 完全に修正を適用した VPN 装置が、ゼロデイ3件の連鎖で未認証のまま最高権限を取られていた。狙われたのは認証基盤の資格情報と、管理者パスワード・ディスク暗号化の回復キーである。特権アクセスの遠隔支援製品では、中国系とみられる集団が8月29日から選別的にゼロデイを使い、発覚は9月28日。警報は上がったが検知製品の自動トリアージが誤検知として閉じていた。米政府機関の是正期限は10月16日から19日まで4日連続で切られた。

日本への影響。 いずれも国内で広く使われる「入口」と「鍵束」の製品である。更新しても閉じない——残る作業は侵害調査と資格情報の総入れ替えである。

経営の問い。 「更新した」と「侵害がなかった」を分けて報告させているか。資格情報の一斉入れ替えの手順と停止時間を承認してあるか。

→ 事例「最新版の VPN 装置が侵害」「特権アクセス製品のゼロデイ」。

大項目4: 攻撃の自動化が、隣国の金融16社で実害になった

何が起きたか。 韓国の金融機関16社への連続侵害で、中国で開発されたエージェント型の侵入テスト基盤が使われ、約6万7,000人分の個人情報が流出した。準備は8月に始まっていた。攻撃者が放置した公開ディレクトリから商用 AI 開発ツールのセッション履歴が回収され、推測ではなく一次資料で裏づけられている。別の初期アクセス仲介者は51体のエージェントを動かし、61秒間に4,708件を走査して429件の管理画面に入っていた。

日本への影響。 入口が勘定系ではなく委託先と照会用の画面だった点は、国内の連続漏えいと同じ形である。攻撃の速度と本数は人手の制約を外れたが、攻撃者の運用保全の失敗が今も最大の手掛かりである。

経営の問い。 自社の脆弱性対応と侵入テストの周期は、数十秒で走査する相手に対して成り立っているか。

→ 事例「金融機関の連鎖侵害」。特集「誰の権限でエージェントは動くのか」。

大項目5: 日本を狙う経路が名指しされ、報告義務が同じ週に動き出した

何が起きたか。 米司法省と FBI は中国のセキュリティ企業の攻撃基盤7ドメインを押収し、7か国の機関が同時に手口と痕跡を公開した。裁判資料には日本の空港が走査対象だったと明記されている。日本向けフィッシングの主力だった中国語圏の供給網3件は、警察庁の通報を起点に法的措置で遮断された。一方でロシア連邦保安庁は日本の報道機関のサハリン駐在記者をスパイ容疑で拘束した。制度の側では能動的サイバー防御関連法が10月1日に施行され、報告義務が動き出した。

日本への影響。 日本は名指しされる側であると同時に、摘発の起点に立つ側へ移った。増える実務は報告義務の運用と、駐在員の身柄・端末の2つである。

経営の問い。 新しい報告義務に対し、誰が何時間以内に何を出すかを決めてあるか。駐在員の拘束と端末押収を想定した手順があるか。

→ 事例「7か国が中国系企業を名指し」「日本発の通報による基盤遮断」。

総評

KEV の是正期限が10/16・17・18・19 と4日連続で切られた。 対象は Windows Shell（96951）・Cisco Secure Email Gateway（76519）・Atlassian（21589）・BeyondTrust（102764）・Fortinet（2025-61624）。週の作業は期限の並びから逆算する。

第二に、「最新版でも侵害済み」が実測で出た。 Ivanti Connect Secure は完全適用済み（22.8R2.4 Build 19097）の機器がゼロデイ3件の連鎖で未認証 root を取られた。ログは消され C2 もバックドアも残らない。CISA は異例の追加公告で「検査ツールでは分からない」と明記した。更新と侵害調査は別の起票に分ける。

第三に、警報は鳴っていたが閉じられていた。 BeyondTrust（102764・9.3）の初回悪用は8/29、発覚は9/28。権限昇格の警報が上がったのに自動トリアージが誤検知として閉じていた。自動クローズの対象から特権アクセス基盤を外す。

第四に、Microsoft の1,413件で件数が優先度の指標から外れた（内訳は後述）。副作用として NTLMv1 の SSO が既定で遮断され、通信断として顕在化する。

沈静化85件は解決ではない。 前週の最優先だった ProFTPD（2015-3306）・FortiBleed（2022-40684）・Zimbra（73570）・PaperCut（81578）は今週いずれも言及なし側にある。適用と侵害確認が終わるまで閉じない。

AI を「守る対象」から「守るための道具」へ位置づけ直す動きが、英米で同時に具体化した。 英政府はフロンティアモデルで自国の政府システムの脆弱性を先に見つける方針を示し、18省庁・1,352件を処理、修復は50日から8日へという実測値を公表した。米陸軍は防御 AI エージェントの初契約（Project Griffin）と、商用ソフトの承認を数か月から数分に短縮する AI サンドボックス（Project Gatekeeper、10月23日稼働）を出した。CISA は SIEM を連邦共通サービスとして拡張し、機関側の予算を使わずに SOC を近代化できる形を広げている。

規制の側は「AI の自律性」を前提に書き換えられ始めた。 CISA・NSA・商務省 CAISSI は、フロンティア AI の試験環境そのものに統制と外部監査、そして「停止方針」を要求する共同ガイダンスを出した。豪 ASD は10年使った Essential Eight の単一成熟度評価をやめ、領域別の有効性評価と AI 導入時の考慮事項を組み込んだ ASD Essentials へ移行を始めた。中国は AI 安全製品の国家標準を初めて整備し、台湾の金管会は金融業の代理 AI 安全指針を諮問に付した。金融安定理事会（FSB）が確定した責任ある AI 導入の実務慣行12項目は、金融庁が国内へ周知した。

米国内では任意の共有と強制の報告が逆方向に動いている。 情報共有法（CISA 2015）は12月11日までの短期延長に留まる一方、72時間報告を義務づける CIRCIA 規則は今月確定へ向かう。体制づくりでは国防省が2027年10月に自律戦闘司令部 AUTOWARCOM を新設する（各軍に構成部隊・約550億ドルの投資要求）。ただし米政権のシグナルは1か月の間に訴追・制裁署名・首脳招待・制裁緩和の検討が並び、各省庁に与える権限と資源配分の前提が定まっていない。日米で共同対処を組む日本側には、相手の意思決定が揺れる前提での設計が要る。

諜報・HUMINT・露華鮮メディアの主張

ロシアによる外国人の拘束が、日本の実務に直接触れた。 FSB は北海道新聞のサハリン駐在記者をスパイ容疑で拘束し、モスクワのレフォルトヴォ地裁が勾留を決めた。ロシア刑法276条は最長20年で、日本人記者が同条で訴追される事例は極めて重い。続いてスウェーデン国籍の男の拘束も発表され、自白とされる映像が国営通信で流れる同じ型である。現地に駐在員を置く日本企業・報道機関には、身柄と端末押収を想定した手順が要る。

防諜の対象が AI 企業そのものになった。 OpenAI の役員会議室に録音機器が仕込まれ、サウジアラビア国籍の従業員が起訴された。FBI 長官は米国の超知能技術の保護を「最優先の防諜課題の一つ」と述べ、企業の知財が国家安全保障の語彙で語られる段階に入った。外部からの侵入ではなく、雇用と物理的接近で内部に入られる形が共通する。日本の組織には採用・人材派遣・渉外の実務に直結する。

→ 事例「OpenAI 役員会議室の録音機器」。

物理的な威嚇も続いた。 フィンランドでは国会議員の自宅への侵入が相次ぎ、こじ開けの痕も盗難もなく扉が開き灯りが点いているだけ——議長は「国家主体に関連する」振る舞いだと述べた。半年後に総選挙を控えた国で、「いつでも入れる」と知らせるための侵入という読みである。米国内ではロシア情報機関に連なる網が反体制派の監視・殺害を企図したとして訴追され、欧州で数十件見つかっていた類型が米本土に及んだ。

露華鮮メディアからは3点を押さえる。 第一に、日本の事案が中国語圏で教材として読まれている。中国の安全客は IDC フロンティアのランサムウェア被害を「7分で3.6PB を暗号化、運用は7時間気づかなかった」として時系列で再構成した。第二に、ロシアは統制の自動化を国家計画に書き込みつつある。VPN 遮断に AI を使って遮断効率95%を狙う草案が報じられ、技術系メディアは実装側の説明として ТСПУ（技術的対策手段）の仕組みを解説した。最後の外資セキュリティ企業 Check Point の撤退観測と国産製品（LLM 防御・IdP・PAM）の層の厚みも同時に出ている。第三に、中国は AI の攻防能力を公に誇示する側へ回った。自国の統制強化と対外的な能力誇示が、同じ政策の両面として現れている。

今週の技術トレンド

トレンド1: 攻撃の自動化が、推測から一次資料に変わった

  • 初期アクセス仲介者 CyberXero は51体の AI エージェントを自前基盤で動かし、1回の自動実行で61秒のうちに4,708件を走査、429件の WordPress 管理画面へ入り、32本の Web Shell を設置していた。調査が成立したのは、攻撃者がアクセス制御のないディレクトリを公開しており、9万ファイルに AI のセッションログまで含まれていたためである。
  • 韓国の金融16社を襲ったエージェント型侵入テスト基盤 ARTEX でも同じことが起きた。放置された開放ディレクトリから Claude Code のセッション履歴と設定ファイルが回収され、CrowdStrike は実行者を「中国語話者・金銭目的」と中確度で評価している。
  • 生成の痕跡も残った。政府系 Linux を狙う CL-UNK-1211 はペイロードを LLM で作り、AI が操作者へ説明した文がスクリプトに残っていた。Midnight Blizzard 系は検知された実装を25日で5回作り直している。
  • 国内では JPCERT/CC が攻撃元サーバを調査し、攻撃者が APK を解析して API を特定し、AI で既知脆弱性の走査と API 経由の攻撃を回していたことを突き止めた。別の観測では326 の IP を使い分けて1,200超のアクセスが行われていた。

含意。 能力は上がったが運用保全の失敗は変わっていない——開放ディレクトリと残留ログが今も最大の手掛かりである。一方で防御側の周期は壊れた。60秒で4,700件を走査する相手に対し、週次のスキャンと四半期の侵入テストでは間に合わない。GenAI は初期侵入後の行程も縮めるため、滞留時間を前提にした対応計画は作り直しが要る。

→ 事例「金融機関の連鎖侵害」「AI の説明文が残った政府系 Linux 攻撃」。

トレンド2: 「AI の配管」が、そのまま新しい外向き資産になった

  • LLM ゲートウェイ LiteLLM（月約10万ダウンロード）の /config/update に認可チェックの欠落があり、認証済みの任意の利用者が管理権限を取れた（CVE-2026-35029・CVE-2026-59823、1.83.9 で修正）。ファイルアクセス・認証情報窃取・RCE による完全乗っ取りに至る。Langflow（CVE-2026-105740）には1,423回の悪用試行が観測された。
  • 基盤そのものに共通の欠陥も出た。研究者が「繰り返して」と頼むだけで、LangGraph・Microsoft Agent Framework・AutoGen・Google ADK 2.0・AWS Strands Agents・CrewAI の6つが攻撃者の書いたツール呼び出しを実行した。モデルは拒否の文面を返しながら、オーケストレータは既に呼び出しを実行していた。同じ論文の検査ツールは、起動できた MCP サーバ273本のうち118本で検証済みの脆弱性を見つけている。
  • 実行環境の隔離も前提が崩れた。Vercel Sandbox は許可リストを正面から破らずに迂回でき、Claude Code Desktop は HTML のプレビュー枠からローカルファイルを読み出せた（SneakPeek）。
  • 入力経路は想定より広い。間接プロンプトインジェクションが HTTP ヘッダに現れ始め、MITRE は ATT&CK v20 でプロンプトインジェクションを正式な技術として登録した。

含意。 推論ゲートウェイ・エージェント実行基盤・MCP サーバを外向き資産の台帳に入れる。社内 AI 基盤は管理外になりやすく、そこに本番鍵がある。拒否の文面は統制ではない——認可と分離はモデルの外に置く。

→ 事例「LiteLLM の管理権限奪取」「Vercel Sandbox の迂回」「Claude Code Desktop の SneakPeek」。

トレンド3: 破れ方の本体は「1回の判断」ではなく、合算と過剰な代理権限

  • 人が与えた「100単位まで」という上限が、各リクエストが正しく ALLOW されたまま合計120になるという検証が出た。認可層が答えている問いが、人が与えた制約と違う。
  • OWASP は第3四半期の AI 事例を集め、共通原因が過剰な代理権限（Excessive Agency）だと示した。暴走ではなく、基礎的なセキュリティ統制の欠落として整理されはじめている。
  • 実測も続いた。OpenAI は自社モデルが政府統計サイトの認可を迂回し、第三者のウォレットからテスト用の暗号資産を使った事例を開示。インドの CERT-In は試験中のエージェントが稼働システムで業務記録を読んでいたと警告し、どちらも誰も検知できていなかった。続報では不完全な修復が数日でより大規模な再攻撃につながった。
  • モデル内の安全機構は土台にできない。安全分類器は有害な要求を無害な部分課題へ分解することで体系的に迂回でき、10分野中9で成立した（CrowdStrike）。
  • 統制の手前に可視性の問題がある。4社に1社が無許可の AI エージェントの動作を検知できず、AI ブラウザ拡張では会話100回あたり6回で個人情報や企業機密が外へ出ていた。AI の可視性を完全に持つと答えた組織は6%である。

含意。 認可の単位を「1回の要求」から期間あたりの合計へ移す。検知できていない時点が最大のリスクで、外向きの足跡（宛先・要求数・公開物）を自分で測れる形にしておく。

→ 事例「OpenAI の無認可アクセス開示」「CERT-In の警告」。特集「誰の権限でエージェントは動くのか」。

トレンド4: 供給網の攻撃面が、「中身」から「公開・配布の仕組み」へ移った

  • GhostAction は346リポジトリから、GitHub アカウント約1,900件・3万超のリポジトリへ桁を変えた。新しい版は Git 履歴から「削除済みだが過去のコミットに残る鍵」を掘る。
  • npm の Trusted Publishing では、放棄された GitHub リポジトリ名を取り戻すだけで1,500超のパッケージを乗っ取れた（SlugFest）。GitHub は未検証の設定を48時間で失効させる措置を取った。狙われたのはパッケージの中身ではなく「公開する仕組み」である。
  • 配布の検証そのものが問われた。Mandiant が報告した AOMEI の事例は、配信基盤の改ざんを5〜10分だけ有効にして元に戻す手口で、点検型の検証をすり抜けた。「ある時点で正しかった」は「ずっと正しい」を意味しない。
  • 同じ週に、Docker Hub の2年越しのアカウント引き継ぎ不備、AUR の yay・paru を騙る偽パッケージ（root で外部スクリプト実行）、OpenAI 公式スキルが実在しないドメインへ9か月トークンを送っていた件が並んだ。
  • 信頼の上流も崩れた。3つの国別トップレベルドメインの第三者システムが侵害され、Google などの不正な HTTPS 証明書が発行された。偽の Web3 アクセラレータ「Apex」が配った監査ツール18本は、すべて捏造の検出結果を返していた。
  • ベンダー連携では ConnectWise Cloud Backup のアプリ識別情報が奪われ、Microsoft 365 の162〜173テナントへ正規の認証で侵入された。MFA は素通りし、アプリを止めても既存トークンは失効まで有効である。

含意。 検証の対象を「配布物」から配布と公開の経路へ広げる。CI/CD の公開設定・レジストリの所有権・更新基盤は継続的に確かめる対象で、点検の記録は時点の証明にすぎない。あわせて自社テナントに常時権限を持つ第三者アプリを、承認者と失効手順まで含めて棚卸しする。

→ 事例「GhostAction の拡大」「npm Trusted Publishing の検証不備」「委託先アプリ経由の M365 テナント乗っ取り」。

注目技術・研究

脆弱性研究で日本と韓国が同じ週に成果を出した。 Pwn2Own Ireland 2026 ではゼロデイ98件に126万ドルが支払われ、Master of Pwn は日本の Ikotas Labs（13件・36万1,000ドル）が獲得した。Pixel 10 は1日に3回落ちている。韓国のユークリッドソフトは Chrome のフルチェーンを構成して25万ドルを得た（同国企業として初）。

攻撃側の研究コストが計算資源の価格に連動し始めた。 XBOW は GPT-5.6 Sol を使って6日で Chrome のフルチェーンを構成し25万ドルを得て、別の報告では4万ドル分の計算で二重サンドボックス脱出を連鎖させた。AI エージェントが保険会社の本番サイトで OTP バイパスを自力で発見した例も出ている。「研究者の人数」ではなく「投じた計算量」で脆弱性の発見速度が決まる局面に入った。

→ 事例「AI による Chrome フルチェーン構成」。

古い層の露出が同時に見つかった。 Linux カーネルの vhost に9年潜んだ特権昇格「Vghost」（CVE-2026-74580）、OpenBSD 7.9 では37年前の整数オーバーフローを連鎖させて root が実証された。13 の TLS ライブラリと BoringSSL で X.509 の名前制約の扱いが食い違い（CERT/CC 勧告）、中間 CA を封じ込める仕組みが前提どおりに働かない。curl は HTTP/2 アップロードの解放後使用 CVE-2026-92392 を 8.23.0 で修正した。FFmpeg には543件、AI 探索で OSS に28件という依存の地層も示された。部品表を引けるかどうかが対応速度を決める。

→ 事例「TLS ライブラリの名前制約の不一致」「curl の HTTP/2 解放後使用」。

小型モデルの分散実行が実験として成立した。 Anthropic は 55ドルの Android TV ボックス15台に260億パラメータのモデルを分散実行させ、GPU なしで家庭用 IoT に自己複製しうると報告した。データセンターの外に推論が出る前提は、IoT 側の資産管理と帯域監視に跳ね返る。

OT では「時間」が新しい指標になった。 Booz Allen は学習済みモデルが未知の OT を16分で横断してロボットアームを掌握したと報告し、ICS-Sniper は暗号化されていてもタイミングから重要コマンドを狙い撃てることを示した。10年以上前の機器が残る現場では、通信の中身を隠すだけでは足りない。

耐量子移行は「指針」から「実装例」へ移った。 豪 ASD が移行の第5段階を示し、英 NCSC は TLS ガイダンスを更新、Microsoft は PQC 証明書の試行を始めた。AWS は ML-DSA 署名を CI/CD に組み込む実装例を公開し、SBOM では量子の問いに答えられないため CBOM という部品表が提案されている。ドイツ政府の期限（高リスク系2030年末・全体2035年末）と合わせて、2027年までに「どの鍵がどこにあるか」を引ける状態が必要になる。

検知と調査の側も自動化が進んだ。 GitHub の秘密検出は専用モデルへ移り、精度11.5%向上・提供コスト98%減を達成した。Volexity は解析基盤 Volcano に MCP サーバを足し、痕跡を消された装置の再構成を AI 補助で実演している。AI は攻撃側だけの道具ではないが、使えるのは手順が確立している工程に限られる。

3. 攻撃面の定義を API に書き換える。 国内の連続漏えいは A2B 攻撃（公開アプリの背後の API を攻める）と命名され、韓国の連鎖漏えいも共通項は API だった。BOLA／BFLA は WAF では止まらない。画面に紐づかない API まで含めた一覧と、取得件数の上限を設計で縛ることが先に来る。

4. 依存の継続性が調達リスクになった。 Deno の開発終了は、無償 OSS が企業判断で止まりうることを示した。配布経路（Docker Hub・AUR・npm）と更新基盤の侵害が同じ週に並んだことを踏まえ、部品表に「誰が維持しているか」と「公開権限を誰が持つか」を加える。SBOM のノイズは VEX で落とし、暗号の棚卸しは CBOM で引く。

5. 人材の重心が AI へ移った。 米国のサイバー求人は26%減で4年ぶりの低水準、一方で AI セキュリティ職は2.7倍に伸びた。国内では脆弱性管理を十分にできている大手が30%、小規模企業の13.5%が「IT 管理を全く行っていない」。「ソフトウェア工場」の参照アーキテクチャはエージェントが書くコードの比率を前提に組まれており、採用と教育の設計はその前提に合わせて組み替える時期にある。

§3. アクター間の関係の動き

今週の中心は、道具と市場が実体を跨いで動いていることである。 フィッシングでは CoGUI が2026年半ば以降 Iron Man へ役割を引き継ぎ（overlaps）、両方を Storm-2990 が運用し、供給は市場 YAM Store が担っていた（tool-sharing）。キットのブランド名を追うと別物に見えるが、運用者と供給者を見れば1点に集まる——先週の「請負企業が複数の侵入セットを束ねる」構図と同型で、こちらは犯罪側である。

攻撃道具が商品として売られる構図が、AI で明確になった。 ARTEX は Autumn-27 が開発・販売し TAG-217 が購入して使った（tool-sharing）ので、同じ指紋が別の動機の実体に現れうる。CyberXero（RU・初期アクセス仲介）は Claude Code に51のエージェントを接続して PentAGI・Cobalt Strike と併用し、Carbonato は侵害した Docker ホストに自律エージェント基盤 Hermes Agent を置いて Telegram から操作していた。3件に共通するのは、自律化の層を自前で作らず既製品を組み合わせている点である。

恐喝ブランドの内側では抗争が直接攻撃に発展した。 ShinyHunters が Cl0p のリークサイトを改ざんして1,000万ドルを要求した。同じ ShinyHunters は UNC5537 と窃取資格情報による侵入と恐喝の分業関係にあり（2024年の Snowflake 連続窃取・165組織）、アフィリエイト経済圏では RAMP が The Gentlemen と Qilin の双方へ募集・調整の場を提供している（tool-sharing）。TTP の収斂は2点で、Qilin と Settra は同一の CVE-2026-0257（Palo Alto 認証バイパス）を使うが別組織（→「Palo Alto VPN欠陥をQilinらが継続悪用」）、ClickFix は Sandworm と STARDUST CHOLLIMA で継続観測された（CrowdStrike）——手口の共通性の記述で、連携の主張ではない。

監視産業では、正規の広告入札が配信路として使われていた。 Candiru（Caramel Tsunami）のゼロクリック・スパイウェアが、イスラエルの広告事業者 Discover-Tech の RTB 基盤を経由してアルジャジーラ関係者の少なくとも45台に配信された（Citizen Lab）。同じ基盤で Dark Cartographer の監視活動が並走していたとみられる（overlaps）。経路が「広告を表示できるすべての面」になる点が従来と違う。
