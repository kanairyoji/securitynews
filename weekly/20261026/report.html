今週中に決めること: 「1点で落ちると複数事業が止まる共通基盤」を誰が洗い出すか。開発者端末への拡張機能の導入を誰が統制するか。

大項目1: AIが攻撃の実行主体になり、標的リストの中心に日本が置かれた

何が起きたか。 国内の調査会社が日本を標的とする攻撃基盤3件を解析し、1件は44個のAIエージェントが偵察から報告書作成までを分担していた。標的19組織のうち16組織が日本である。中国系の攻撃者は自前のエージェント型基盤と中国製モデルを組み合わせ、11日間で14か国・200組織超へ並行侵入し、約140組織の侵害が確認された。同じ基盤を悪用した韓国の元技術者も43日で60社・820万件を奪い摘発された。

日本への影響。 標的業種に日本の外務・防衛・半導体・通信・金融が名指しされた。業種単位の前提として読む必要がある。相手は数秒単位で動き、防御製品が未導入のホストの棚卸しまで工程化している。

経営の問い。 検知から遮断の承認までに自社は何分かかるか。社内で動くAIエージェントとその権限を棚卸しして示せるか。

→ 事例「AI主導の攻撃3件」「200組織超への並行侵入」。特集「誰の権限でエージェントは動くのか」。

大項目2: 国家系は修正公開の直後に未修正機器を選別し、日本を名指しで攻めた

何が起きたか。 前週に緊急修正が出たWeb実行基盤の欠陥で、北朝鮮系とみられる集団が未修正・部分緩和の216ホストを列挙し、標的国に日本を挙げた。中国系とみられる別の集団は同じ欠陥とサーバ基盤の権限昇格を連鎖させ、1万9,000台のファイアウォールから米国・日本・台湾・韓国を選別して25台を管理者権限で掌握し、うち1件は米政府系組織の認証基盤まで到達した。中国国家系が3年運用してきた使い捨ての中継網も公開され、4件の未知の欠陥が隠されていた。

日本への影響。 「パッチが出たら直す」の前に選別が終わる。更新できない基盤に乗った事業は、止める以外の手を持たない。

経営の問い。 外部から到達できる機器の一覧を、何時間で出せるか。更新できない基盤に乗る事業を、いつ誰が畳むか。

→ 事例「Web 実行基盤の未認証RCE」「使い捨て中継網の4件のゼロデイ」。

大項目3: 委託先と共通基盤の1点が、同じ週に複数の委託元を落とした

何が起きたか。 旅客サービスの共通基盤1社の侵害が、日本航空・日本トランスオーシャン航空の約9万2,000人（約2,000人はパスポート番号）と全日本空輸・韓国2社へ同時に波及し、日韓4社が1つの委託先に収束した。国内では、EC構築サービスの最終報2,335万6,000人（うち209万6,900人はカード情報）、通信系214万件、生命保険38.5万件、外食238万件、旅行予約354万件が同じ週に並んだ。

日本への影響。 被害規模を決めたのは攻撃の巧拙ではなく、委託先の設計と保存件数という自社の調達判断である。

経営の問い。 1点で落ちると複数事業が止まる委託先・共通基盤を一覧化しているか。

→ 事例「共通予約基盤経由で航空4社へ波及」「So-net 会員データベースの侵害」。

大項目4: 史上最大の暗号資産窃取は、技術者1人の端末から始まった

何が起きたか。 大手暗号資産取引所から約64億ドル（約1兆円）が流出し、暗号資産史上最大の窃取となった。起点は鍵の流出ではなく、開発運用担当者のノートPCから出金権限を持つ実行環境へ到達されたことである。米捜査機関が北朝鮮系の攻撃者に正式帰属させ、約28億ドルを凍結した。同じ週に、開発者向けエディタの拡張機能ストアで正規拡張を装う改ざん版が約11時間配布され、最大5,000人に遠隔接続の裏口が仕込まれた。削除しても痕跡は残る。

日本への影響。 守る対象が「本番サーバ」から「技術者の端末と手元の道具」へ移った。盗まれた資金は北朝鮮の兵器開発原資になる。

経営の問い。 特権作業を行う端末に、どの業務外ソフトの導入を許しているか。開発環境の秘密情報を一斉失効するのに何時間かかるか。

→ 事例「取引所からの63億ドル流出」「拡張機能の改ざん版配布」。

大項目5: 制度は動いたが、起動は被害企業の求めでは決まらないと示された

何が起きたか。 国内の大型事案で被害企業が能動的サイバー防御の初適用を政府に求めたが、官房長官は要請の有無にかかわらず法定要件に照らして警察・防衛省が判断すると述べた。総務省は攻撃者が情報を公開したサイトの遮断を通信各社に要請したが、発動されないまま論点だけが残った。政府調達の暗号リストの耐量子化は意見募集が11月11日まで、米国の標準は従来の公開鍵方式を2030年以降は非推奨・2035年以降は禁止とした。大手クラウドの認証では2027年2月にSMS・音声の多要素認証が廃止される。

日本への影響。 被害時に国が代わりに動く前提は置けない。一方で暗号と認証の移行には動かせない期限が入った。

経営の問い。 自社の対抗手段（公表・遮断依頼・法的措置）を誰が選ぶ決まりか。暗号・認証の移行計画は2030年の期限に間に合う工程か。

総評

今週の作業はKEVの期限で決まる。 10/29 PHP（109618／109619）→ 10/31 Linux カーネル Fragnesia（46300） → 11/2 と 11/13 Ivanti Connect Secure（111357／118527） → 11/10 Brotli（111497）。10/26 期限の 114625・110447 は期限を過ぎたまま言及が続く。

第二に、被害を決めたのは「修正の有無」ではなく「更新の有無」だった。 Synology NAS を暗号化したのは2024年12月に修正済みの3件、Plex は公開翌日からの連鎖、Drupal Commerce（118539）は公告と同時に実攻撃で4万2,000サイトが対象。Qualys の計測では約300万の Node.js のうち修正済みは4.2万、170万は修正が来ないEOL系列である。

第三に、PHP2Shell の局面は「無差別の走査」から「国家系による標的選別」へ移った。 北朝鮮系とみられる集団が未修正・部分緩和の216ホストを列挙し標的国に日本を挙げ、中国系とみられる集団は Fragnesia（46300）と連鎖させて1万9,000台のファイアウォールから米日台韓を選別し25台をroot化した（10/31 に Unit 42 が追認）。汎用的な武器化の障壁は高いという評価も出ている。試行・選別・侵害を分けて起票する。

第四に、エージェント型の攻撃基盤がIR現場の常態になった。 Mandiant／GTIG は8月下旬以降の対応現場で ARTEX・CAIRN ほかを確認し、痕跡の違いを「23秒で27事象」という人の操作では説明できないバーストと、試行錯誤による大量のログに見た。検知原理より速度とログの残り方が手がかりになる。

第五に、前週「沈静化」と判定した104935（Citrix NetScaler）・111357（Ivanti）・97229（GitLab）が、今週 KEV・悪用確認で戻った。 沈静化は解決ではない。適用と侵害確認が終わるまで起票を閉じない。

諜報・HUMINT・露華鮮メディアの主張

今週の諜報事案は、技術的侵入ではなく正規の権限と正規の記録が芯にある。 英 GCHQ は調査権限法に基づくデータを含む可能性のある数千台の可搬記録媒体の所在を把握できていないと監督機関 IPCO に指摘された（数年前の指摘が未解消）。ロシアでは FSB 経済安全保障局（K局）の職員が政府・中央銀行・国有銀行幹部の弱みを集めた機密データベースを売りに出して有罪となり、暗号資産取引所が捜査機関へ提出した取引履歴が13年の実刑の根拠になった。米国では元政府請負業者が国防情報を SNS へ投稿した疑いで逮捕されている。クリアランス保持者の継続管理は、日本でも制度整備が進む領域に直接かかる。

監視の側では、イスラエルの広告技術企業が広告入札データで Starlink 利用者の位置を追っていた疑いが名指しされ、米欧の議員が規制を求めている。セルビアでは総選挙前に Pegasus の標的15件（検察官・大学教授を含む）が確認され、ロシアの国家機関は1,250万件の SNS プロファイルを日次監視し600万件を「戦争批判」に分類していた。ポーランドでは鉄道インフラを撮影していたロシア人の端末から数十万枚の交通施設画像が見つかっている。事前偵察・工作・統制のいずれも、物理と論理が同じ計画で動いている。

露華鮮メディアからは、日本の事案が攻撃者視点の材料として流通している点を見ておくべきである。 ロシアの技術メディアは GMO インターネットの事案を詳報し、報奨金100万ドル・身代金80億円・影響26,739台という数字を伝えた。ロシア側の自画像は防御的で、ヤンデックスは無人機攻撃を受けた計算基盤の移設を発表しつつ、10月に3拠点を同時に失った障害は「戦時の不可抗力ではなく設計と経営の失敗」と自国媒体に検証されている。統制の実装は進み、海外トラフィックを ТСПУ 経由に義務づける案、QUIC v2 の遮断、非正規持込み端末の IMEI 登録義務化、国家認証局への移行とルート CA の扱いが同じ週に並んだ。中国側は、学校・病院・研究機関を含む「事業単位」の党統制を行政法規に明記し、国産 DB と安全防護を束ねた「信創」方案を押し出す一方、STAR50 指数が4か月で40%下落して AI 相場の反転が意識されている。北朝鮮はクラスター弾頭を試験し、2026年末までに4系統の部隊運用へ進むとされる。

今週の技術トレンド

1. AI は「攻撃の道具」から「攻撃の実行主体」へ——ただし変わったのは速度と記録であって手口ではない

今週は、エージェント型の攻撃基盤が単発の事例報告から複数ベンダーのインシデント対応現場での常態へ移った。Mandiant／GTIG は8月下旬以降の対応現場で ARTEX・PentAGI・CAIRN を確認し、識別点を「23秒で27事象」という人の操作では説明できないバーストと、試行錯誤による大量のログに置いた。CrowdStrike は開放ディレクトリから4組織の攻撃用基盤を回収し、VAPOR PANDA が ARTEX と DeepSeek を組み合わせて11日間で200組織超へ並行侵入した運用を公開した。SOCRadar はランサムウェア群の Phantom フレームワーク（7,158台を走査）、Symantec は人の承認なしに10万ステップ走る Skynet を押さえている。

重要なのは、AI が足されているのは侵入技術ではなく選別と開発の工程だという点である。韓国企業への攻撃で年間首位になった新興ランサム n0n は、9月だけで有料 LLM の API に7,216ドルを使いながら、侵入経路は RDP の総当たりと FortiGate の資格情報詰め込みで、脆弱性の悪用は1件も確認されていない。Cisco Talos が解析した VOLTA は盗んだ資料を LLM に渡して被害者の資産価値を順位付けさせ、モデルが拒否すると3段の別モデルへ切り替える。NIK C2 は OpenAI の Chat Completions API を実装に組み込んだ C2 である。設計上の含意は単純で、検知原理を作り直すより、初期段階の警報を落とさない運用と、秒単位の時系列を残せるログ設計のほうが効く（Halcyon の四半期報告では警報の約99%が攻撃連鎖の初期段階で止まっている）。
→ 事例「IR 現場で確認されたエージェント型基盤」「200組織超への並行侵入」「LLM に被害者を値付けさせる窃取型」。特集「誰の権限でエージェントは動くのか」。

2. AI が脆弱性を見つける側に回り、「古い土台」から順に露出し始めた

今週の重大脆弱性は、発見者が AI だったもの／10年以上放置されていたものが重なった。Anthropic は未公開モデルの助けで Chrome・Safari・Android・Windows・Linux の欠陥を連鎖させ、Linux カーネル IPv4 TCP の use-after-free（CVE-2026-98432／CVSS 9.8）で認証不要のリモート root 実行を実証した。EPICS Base の4件（CVE-2026-114595〜114598）は AI エージェントが3時間49分で発見し、うち最古は31.5年前から残っていた。EDK II の UEFI 欠陥（CVE-2026-97631）は16年前から、GitLab の CVSS 10.0（CVE-2026-110264／97229）は2014年の 7.0 以降12年分に及び、根は Ruby の正規表現エンジン Onigmo だった。

能力の計測も進んだ。Gemini 4 Carbon は安全装置を切った状態で脆弱性の発見88.2%・悪用54.8%・修正71.0%を示し、Project Zero は AI エージェントと従来型ファザーを実測比較して V8 で45対37、重複は4分の1という結果を出した（置き換えではなく補完である）。CrowdStrike はモデルがコードの説明を拒むこと自体が脆弱性の在処を示す手法（GbVD）で86シナリオ中73を的中させた。安全機構の改善が探索精度も上げるという非対称がここにある。

CTO 側の含意は、資産台帳の軸を「深刻度」から「いつ作られたコードが、いまどこで動いているか」へ寄せることである。今週の対象は組み込み UEFI・制御系ミドルウェア・自己管理の開発基盤で、いずれも更新計画を持たない領域に集中している。Qualys の計測では約300万の Node.js のうち修正済みは4.2万、170万は修正が来ない EOL 系列だった。

3. 供給網の重心が「依存の中身」から「配布経路と開発者端末」へ移った

今週の供給網事案は、依存ライブラリの改ざんではなく正規の配布経路と正規の設定ファイルを通った。Cursor の拡張マーケットプレイスで Claude Code の公式拡張を装う改ざん版が約11時間配布され、最大5,000人に SSH バックドアが入った——アンインストールしても鍵と永続化は残る。AI ゲートウェイ LiteLLM は、5月に公開して失効させなかったマスターキーが起点となり、公式の PyPI・Docker Hub に情報窃取機能を持つ 1.107.0 が並んだ。Polymarket は自社コードではなく外部の表示速度計測スクリプトを差し替えられ、約270万ドルが抜かれた。npm ワーム「testmetest」は実害なしという評価が覆り42リポジトリが実際に武装化されていた。

経路としては CI/CD の周辺機能が狙われている。Gheist は盗んだ GitHub トークンで850超のアカウントに1.35万の悪性ブランチを仕込み（GitHub の承認保留で止まった）、Radware は GitHub の issue に HTML コメントで隠した命令で CI/CD を実行させる攻撃を61リポジトリ・83件確認した。Gitee の公開リポジトリには有効なクラウド・AI 向け鍵が26,400件あった。制度側では ENISA が CRA を見据えた SBOM 技術指針（生成・検証・署名・保管・利用・維持の6段階を CI/CD に統合）を出したが、同じ週に「SBOM は最終成果物の目録にすぎず、侵害時の影響範囲は即時に答えられない」という指摘も揃っている。GitHub は npm のインストール時に遮断するパッケージファイアウォールをプレビュー公開した。
→ 事例「偽 Claude Code 拡張の配布」「Polymarket の外部スクリプト差し替え」「GitHub issue からの CI/CD 実行」。

4. AI 実行基盤が新しい資産クラスになり、通知の文面が「全部復号された前提で」に変わった

Railway（約10万ワークスペース）・Northflank・Warp・Chainalysis と、環境変数とエージェントの判断ログの侵害が同じ週に並んだ。Northflank の通知は「影響は一部」ではなく「すべての環境変数は復号されたものと想定し、全ての鍵を無効化・再発行せよ」で、これが事実上の標準対応になった。Wiz は10月中に AI 開発プラットフォームで9件の事故を数えている。盗まれた資格情報の用途が顧客データではなく AI API の不正利用に寄るのが、従来の資格情報流出との性質の違いである。

AI 固有の攻撃面も実装レベルで出そろった。Unsloth のモデルローダは trust_remote_code=False でも任意 Python 実行を防げず（CVE-2026-93348）、Cloudflare Workers AI では長文プロンプトの KV キャッシュがリクエスト間で漏れ（155件）、ChatGPT の共有リンクを開くとセッション内で攻撃者コードが動く欠陥が8日で修正された。ベクタ DB Qdrant は内部ポート6335に偽ノードを peer として加えると本物のベクタデータが流れ込む（CVE は未割当で GHSA でしか追えない）。設計の指針としては、資産台帳に「AI 開発ツールの認証ファイル」「MCP の接続先」「エージェントの判断ログの保管先」を載せることが先決である（ある組織では未承認の MCP サーバが1,710台見つかっている）。
→ 事例「Northflank の環境変数侵害」「Warp の判断ログ流出」「ChatGPT 共有リンクのセッション内コード実行」。

注目技術・研究

  • プロンプトインジェクションの重心が「入力」から「計画」へ。 CrowdStrike の分類は222手法に拡張され、新規は入出力フィルタの回避ではなくエージェントが目標を分解して手順を選ぶ過程に偽の文脈を混ぜる型である。各手順は単体では正常に見えるため、手順ごとの検査では捕まらない。
  • 指示ファイルが攻撃面になった。 ダウンロードフォルダに置かれた AGENTS.md／CLAUDE.md に従ってエージェントが自らの設定を書き換え、悪性パッケージ導入やトークン漏えいに至る経路が実環境で確認された（実証では90%超が従った）。
  • 能力評価の前提が崩れる可能性。 学術側から「モデルは任意の能力を証明可能に隠せる」という結果が出て、OpenAI は8月に塞いだ推論トレースの漏えいを compaction smuggling で回り込まれた。能力試験で引き出せるという前提に依存した安全性評価は再設計が必要になる。
  • 人を狙う側の効率も測られた。 AI が個別最適化したフィッシングはクリック率2.7倍（7,741人で実証）、AI 音声のなりすまし電話には6人に1人が応じた（4,100人で検証）。一方、Anthropic を装うフィッシングは業界主要のセキュアメールゲートウェイを素通りしている。
  • 開発生産性の裏側。 Linux Foundation の調査では生成 AI が OSS の開発時間を半減させる一方、受け取る PR の25%が「AI スロップ」と見積もられた。AI の粗悪な脆弱性報告でバグバウンティの運用見直しが始まり（Intel・Google は見直し、curl は終了）、検証可能な所見を出す技能の価値が上がっている。
  • 自己評価の枠組みが出てきた。 OWASP 関係者による RAID-AI は AI システムのランサムウェア耐性を手作業で自己評価する枠組みで、NIST CSF 2.0 と CISA CPG 2.0 に対応づけられている。WAAP の AMTSO 認証試験では同一候補群で防御スコアが61%から100%まで開いた。

中長期に効く変化（CTO 向け示唆）

① 暗号移行の時刻表が確定した。 NIST IR 8547 は RSA・ECDSA・EdDSA・Diffie-Hellman を2030年以降「非推奨」・2035年以降「禁止」とし、連邦の高価値資産は鍵確立が2030年末・署名が2031年末とさらに早い。国内では CRYPTREC 暗号リストの PQC 対応改定が11月11日まで意見募集中で、政府調達で選べる暗号が決まる段階である。ICANN CTO は DNS の量子耐性化も「10年ではない」と前倒しを示した。攻撃側も既に使っており、Lazarus の新作戦は通信に耐量子暗号を用いている。公開鍵の棚卸しは、証明書の有効期限ではなくアルゴリズムと鍵長で引けるようにしておく。

② エンドポイント防御の実装前提が変わる。 EDR がカーネル外へ出ることで、可用性事故のリスクは下がるが検知の深さとドライバ依存の設計は見直しになる。同じ週に、2011年製の Defender ドライバを使って保護プロセスを止める手法（DefenderKiller）が公開されており、持ち込みドライバ対策は移行期の宿題として残る。

③ ID の境界が「人」から「エージェント」へ移る。 Entra ID は2027年2月に SMS・音声 MFA を廃止する。だが今週の実測はもっと手前の問題を示した——Microsoft 365 の侵害企業の約9割は MFA を導入済みで、効いたのは設定の継続管理の欠落である。本番環境で「野良エージェント」に遭遇した担当者は約3割、禁止しても個人アカウントの生成 AI を使う担当者は77.3%。サービスアカウントとエージェント ID を人間の ID と同じ台帳・同じ失効手順に載せることが、次の1年の中核作業になる。

④ 「更新できない構成」は技術的負債ではなく調達の問題。 Node.js の EOL 170万、Android 12・13 に修正が来ない SMS of Death（CVE-2026-58882）、ネットワーク機器のファームウェアに埋め込まれて利用者が直せない PHP、2024年12月に修正済みの欠陥で暗号化された Synology NAS——いずれも適用の速度では解けない。ガートナーは「異常検知を前提にした設計はフロンティア AI の前では通用しなくなる」と警告しているが、今週の被害はその手前の、置き換え計画の不在で決まっている。

⑤ コストの前提が動いた。 メモリ価格の高騰（2025年比で10倍以上という指摘）と PCB・IC サブストレートの不足が、セキュリティ製品のハードウェア原価と機器更新の予算に直接効く。更新計画を「技術的に必要な時期」だけで引くと、調達できない年に当たる。

§3. アクター間の関係の動き

ARTEX が3つの陣営を横断した。 今週の観測で同じ基盤を実運用に取り込んでいたのは、①中国系 VAPOR PANDA と Storm-0940（CrowdStrike は両者を別運用と明記）、②北朝鮮系 Onyx Sleet と Pearl Sleet（Microsoft が「同時期に取り込んだ」と報告）、③韓国で90社・個人情報820万件を破った営利の個人犯（→「韓国でAI侵入ツール使用90社侵害7人検挙」）である。TTP の収斂は帰属の手がかりにならない——動機も規模も違う3者が同じ指紋を残す。犯罪側では INC と The Gentlemen が自律型キルチェーン基盤 Phantom を共同で構築・運用しており、国家系がオープンソース基盤を使い、犯罪系が自製基盤を作るという逆転も起きている。

防弾ホスティングの押収で、アフィリエイト横断の基盤共有が露出した。 10/29、司法省が Virtualine のドメインを押収し、TRM Labs の分析で Qilin・DragonForce・Inc Ransom・Coinbase Cartel が同事業者への直接支払い者に含まれていたと判明した（事実）。群の名前は違っても資金と基盤は1か所に集まる。 なお押収後も当該サイトは稼働しているとの報道があり、ドメイン押収＝停止ではない。

ネットワーク基盤の重なりは「断定しない」形で記録された。 Volt Typhoon の Silent Train と UAT-11473（KeyDrift）・UAT-8616 は Cisco SD-WAN 管理基盤で重なるが、Talos は同一組織との断定を避けている（§2-2）。UAT-#### は未帰属のクラスタで、公開プロファイルが無いのが正常である。
